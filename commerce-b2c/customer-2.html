B2C Commerce でのアカウントパスワードの変更

パスワードは 90 日ごとに変更する必要があります。既存のパスワードの有効期限が切れている場合でも、新しいパスワードを定義します。パスワードの有効期限が切れた後は、新しいパスワードの設定を 6 回まで試みることができます。その後は、アカウントが一時的にロックされます。有効期限が切れているパスワードで正常にログインしたら、ただちにパスワードをリセットしてください。

所有している Salesforce Commerce 製品

メモ セキュリティ強化のため、ユーザーがログインしてパスワードをリセットすると、そのセッションは自動的に無効になります。セッションを続行するには、ユーザーは再度ログインする必要があります。

この手順は、Account Manager アカウントが Salesforce Identity アカウントにリンクされていない場合にのみ使用できます。

  1. Account Manager にログインします。
  2. Password (パスワード) をクリックします。
  3. Current Password (現在のパスワード) フィールドに、現在のパスワードを再度入力します。
  4. New Password (新しいパスワード) フィールドに、新しいパスワードを入力します。
    パスワードの要件:
    • 7 文字以上。一部の組織ではその他の要件を設定しています。
    • アルファベット 1 文字
    • 大文字 1 文字
    • 数字 1 文字
    • 特殊文字 1 文字

    文字を入力すると、パスワードのセキュリティ強度が表示されます。

  5. Confirm Password (パスワードの確認入力) フィールドに、新しいパスワードを再度入力します。
  6. 「パスワードの変更」をクリックします。

B2C Commerce でのユーザーアカウントのリセット

アカウント管理者は、Account Manager を使用してユーザーのアカウントをリセットできます。この操作は、ユーザーがパスワードを忘れた場合や、Salesforce アカウントから Account Manager アカウントのリンクを解除する場合に有用です。ユーザーのアカウントをリセットすると、そのアカウントは最初に作成されたときと同じ状態になります。ユーザーはアカウントを再度アクティベートする必要があります。

所有している Salesforce Commerce 製品

メモ ユーザーがログイン中にそのユーザーのアカウントをリセットすると、ユーザーセッションは自動的に無効になります。セッションを続行するには、ユーザーは再度ログインする必要があります。
  1. Account Manager にログインします。
  2. User (ユーザー) をクリックします。

    「Users (ユーザー)」ページが開き、アカウントのリストが表示されます。

  3. リセットするアカウントのユーザーの横にある Reset (リセット) をクリックします。

    ダイアログボックスが開き、ユーザーのアカウントのリセットを確認するメッセージが表示されます。[ キャンセル ] をクリックすると、リセット操作はキャンセルされ、ユーザーのアカウントは変更されません。

  4. OK をクリックします。

    ユーザーのアカウントがリセットされます。アカウントが Salesforce アカウントにリンクされている場合、Account Manager によってリンクがキャンセルされます。Account Manager からユーザーの Eメールアドレスにメッセージが送信されます。この Eメールメッセージにはアクティベーション URL が含まれており、ユーザーはこの URL を使用して、アカウントのアクティベートを開始できます。また、Users (ユーザー) ページには、ユーザーのアカウントの横にテキストメッセージが表示されます。このテキストメッセージは、ユーザーのアカウントが正常にリセットされたことを示します。また、ユーザーの Eメールアドレスに送信されたアクティベーション URL も含まれています。

    メモ ユーザーが再度アクティブになった場合は、Account Manager で多要素認証 (MFA) の検証メソッドを 1 度登録して、リンクを完了する必要があります。

OKTA の設定と Salesforce Identity との連携

このガイドは、B2C Commerce の一般的な統合の概要を説明します。正確な手順については、Okta などの ID プロバイダー (IDP) に固有の最新の統合ドキュメントを参照することをお勧めします。

所有している Salesforce Commerce 製品

B2C Commerce の SSO サポートはコアライセンス商品を介して行われ、3 つの接続が必要です。

  • Account Manager
  • Salesforce Platform
  • OKTA(オクタ)

手順 1: Salesforce SSOを有効にし、OKTAでSalesforceプロビジョニングを有効にするには、OKTAのドキュメントを使用してください。

このドキュメントには、Salesforce用のSecurity Assertion Markup Language(SAML)2.0を構成する手順( SAMLの構成を参照)と、SalesforceとOktaの間でSP-Initiated SAMLを構成する方法およびSalesforceで委任認証を構成する方法 (オプション)に関するその他の有用な情報が含まれています。

手順 2: 認証されたユーザーがOKTAからSalesforceにフローできるようにするには、Salesforceをサービスプロバイダーとして構成します。

SAML は、サードパーティ ID プロバイダから Salesforce 組織への SSO に Salesforce が使用するオープンスタンダードの認証プロトコルです。また、SAML を使用して、ジャストインタイム (JIT) ユーザー プロビジョニングでユーザー アカウントを自動的に作成することもできます。

SAML を使用して Salesforce をサービスプロバイダーとして構成すると、認証されたユーザーはサードパーティの ID プロバイダーから Salesforce にフローできます。

SAML を使用すると、ID プロバイダはユーザ情報を Salesforce と交換できます。ユーザがログインしようとすると、ID プロバイダはユーザに関するファクトを含む SAML アサーションを Salesforce に送信します。Salesforce がアサーションを受信し、Salesforce 構成に照らして検証し、ユーザに組織へのアクセスを許可します。

ユーザーがログインできない場合は、SAML ログイン履歴を確認して原因を特定します。SAML アサーション バリデーターを使用して、SAML アサーションのエラーをトラブルシューティングします。

構成ヘルプ

組織に SSO を設定するには、SAML ID プロバイダを確立し、次の一般的な手順に従います。

  • ID プロバイダーからの情報の収集
    • Salesforce への SSO の SAML 設定を構成する前に、ID プロバイダと協力して SAML 情報とアサーションパラメータを収集します。
  • SAMLの開始、ログイン、ログアウト、およびエラーページのカスタマイズ
    • Salesforce への SAML シングルサインオンを設定する場合は、SSO フロー全体でユーザに表示されるページの URL を定義します。ID プロバイダーは、開始ページ、ログイン ページ、およびログアウト ページの URL を提供できます。または、これらのページに独自の URL を指定することもできます。また、カスタムエラーページを指定することもできます。
  • SAML シングルサインオンを使用したサービスプロバイダーとしての Salesforce の設定
    • Salesforce を SAML シングルサインオンを使用するサービスプロバイダとして設定する。
  • シングルサインオン設定の表示と編集
    • SAML を使用するように Salesforce Org を構成したら、[Single Sign-On Settings (シングルサインオン設定)] ページから SAML 設定を管理できます。
  • ログイン履歴の確認
    • ユーザが SSO を使用した組織へのログインに失敗した場合は、ログイン履歴を検索して原因を突き止めます。たとえば、ログインの失敗が SAML アサーションと Salesforce の設定のどちらに関連しているかを確認します。
  • SAML アサーション エラーのトラブルシューティング
    • SAML Assertion Validator を使用して、SSO ログインの問題をトラブルシューティングし、ID プロバイダーから送信された SAML アサーションのエラーを特定します。
  • SAML ログインエラー
    • ユーザが SSO を使用して組織にアクセスできない場合は、ログイン履歴を使用して、SAML アサーションエラーか設定の問題かを判断します。アサーション関連のエラーの場合は、SAML Assertion Validator を使用して特定のアサーションの問題を特定します。ID プロバイダーと協力して、SAML アサーションと SSO 構成の両方が有効であることを確認してください。
  • ID プロバイダとしての Microsoft AD FS を使用した Salesforce への SSO の設定
    • ユーザは、Microsoft Active Directory フェデレーションサービス (AD FS) 2.0 を使用して Microsoft 環境から Salesforce 組織にログインできます。Microsoft AD FS は、シングル サインオン認証の ID プロバイダーとして機能します。
  • SAML 用のジャストインタイムプロビジョニング
    • JIT プロビジョニングを使用すると、ユーザがシングル SSO で初めてログインしたときに、Salesforce 組織にユーザアカウントが自動的に作成されます。JITプロビジョニングにより、ワークロードが軽減され、時間を節約できます。また、JIT プロビジョニングは、企業ネットワークのパスワードポリシーを組織に自動的に適用するため、セキュリティが向上する可能性があります。

B2C Commerce でのアカウント削除の取り消し

アカウントが削除されると、削除されたユーザーは、Account Manager 認証情報を必要とするいずれのシステムにもログインできなくなります。アカウントを間違って削除した場合、あるいはセキュリティ対策として削除した場合は、そのアカウントの削除を取り消すことができます。アカウントの削除の取り消しは、アカウント管理者のみが行えます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. User (ユーザー) をクリックします。
    「Users (ユーザー)」ページが開き、アカウントのリストが表示されます。
  3. Filter by status (ステータスでフィルター) リストで、Deleted Users only (削除されたユーザーのみ) を選択します。
  4. 削除を取り消すアカウントのユーザーの横にある [ Undelete (削除の取り消し )] をクリックします。
    ユーザーのアカウントの削除取り消しを確認するメッセージが表示されます。[キャンセル ] をクリックすると、削除取り消しの処理はキャンセルされ、ユーザーのアカウントは削除されたままになります。
  5. OK をクリックします。
    Account Manager によってアカウントが復元されます。削除したアカウントが Salesforce Identity (SSO) にリンクされていた場合、Account Manager は Salesforce Identity へのリンクをキャンセルします。アカウントをリンクするには、ユーザーは Account Manager で多要素認証 (MFA) の検証メソッドを登録する必要があります。この操作は、アカウントで 1 回実行します。

B2C Commerce でのアカウントのロック解除

アカウントへのログインを 6 回失敗すると、Account Manager によってアカウントが一時的に 30 分間ロックされます。アカウント管理者は、管理者の組織内でロックされたアカウントを明示的にロック解除できます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. Users (ユーザー) をクリックします。

    「Users (ユーザー)」ページが開き、組織の全ユーザーの Eメールアドレスのリストが表示されます。

  3. ユーザーリストで Unlock (ロック解除) の操作をクリックします。
  4. Organization User (組織のユーザー) セクションのユーザーリストで、Unlock (ロック解除) 操作をクリックします。

Account Manager と B2C Commerce での ID フェデレーションによるユーザー管理

Account Manager ユーザーアカウントが自動的に作成、プロビジョニングされ、Salesforce 組織の Salesforce Identity にリンクされるように、組織の ID フェデレーション設定を構成できます (Salesforce Identity Management (SFIDM))。

所有している Salesforce Commerce 製品

ジャストインタイムユーザープロビジョニングが有効になっている場合、新規ユーザーとアカウントは自動的にプロビジョニングされ、SFIDM で管理されている Salesforce のアカウントにリンクされます。SFIDM にリンクされていない既存ユーザーのアカウントは、SFIDM で管理されている Salesforce のアカウントに自動的にリンクされます。どちらのオプションでも、ID フェデレーションを強制または許可に設定する必要があります。

必要に応じて、既存の Identity and Access Management (IAM) アカウントにリンクされる前に、Account Manager でユーザーアカウントを引き続き手動でプロビジョニングできます。

  • B2C Commerce での Salesforce Identity との ID フェデレーション
    ID フェデレーションにより、ユーザーは単一の認証情報セットで複数のアプリケーションやシステムにアクセスできるようになります。Account Manager は ID フェデレーションを使用して、セキュリティとアプリケーションのログインプロセスを向上させます。

B2C Commerce での TOTP 認証アプリによる本人確認

Microsoft Authenticator や Google Authenticator などのサードパーティ認証アプリを、多要素認証 (MFA) ログインの検証メソッドとして登録します。このアプリは、時間ベースの一度限りのパスワード (TOTP) と呼ばれる検証コードを生成します。

所有している Salesforce Commerce 製品

  1. お使いのデバイスタイプでサポートされている認証アプリをダウンロードします。

    TOTP アルゴリズム (IETF (Internet Engineering Task Force) RFC 6238) をサポートする認証アプリであれば、どれでも使用できます。

    組織の MFA 検証メソッド設定に応じて、以下のようになります:

    • 次回のログイン時に TOTP 認証アプリとの接続が要求され、これが唯一の許可されている (MFA) 検証メソッドである場合: 次のステップに進みます。
    • 次回のログイン時に TOTP 認証アプリまたは別の検証メソッドとの接続が要求される場合: One-Time Password Generator (一度限りのパスワード生成ツール) をクリックして、次のステップに進みます。
    • Account Manager にログインする際に、複数の MFA 検証メソッドの登録が可能であり、「Account Information (アカウント情報)」から TOTP Authenticator アプリに接続できる場合: Multi-Factor Verification (多要素検証) の横にある Add (追加) をクリックし、One-Time Password Generator (一度限りのパスワード生成ツール) を選択します。
  2. モバイルデバイスの認証アプリを使用して QR コードをスキャンします。または、ブラウザーで、I Can’t Scan the QR Code (QR コードをスキャンできません) をクリックします。ブラウザーにセキュリティキーが表示されます。認証アプリに、ユーザー名と、表示されたキーを入力します。
  3. ブラウザーで、認証アプリで生成されたコードを、Verification Code (検証コード) フィールドに入力します。
    認証アプリでは、新しい検証コードが定期的に生成されます。
  4. 現在のコードを入力してください。
  5. Connect (接続) をクリックします。
    アカウントのセキュリティを守るため、Account Manager アカウントに新しい本人確認メソッドを追加するたびに、Eメール通知が送信されます。

B2C Commerce での多要素認証による本人確認

多要素認証 (MFA) は、ログインセキュリティを向上させ、ユーザーアカウントをセキュリティの脅威から保護するための、シンプルで効率的なメカニズムです。MFA は B2C Commerce のログイン体験の一部で、オフにすることはできません。

所有している Salesforce Commerce 製品

MFA では、ユーザーが 2 つ以上の証拠 (要素) を提供して、実際に登録しているユーザーであることを証明することが要求されます。1 つの要素は、ユーザー名とパスワードの組み合わせなど、ユーザーが知っている情報です。その他の要素は、認証アプリやセキュリティキーなど、ユーザーが所有している検証メソッドです。ユーザーアクセスを複数の異なるタイプの ID 検証機能にリンクすることで、アカウントが侵害されるリスクが軽減されます。

Account Manager によって、サポートされている検証メソッドを使用して本人確認を行うように求められます。複数の検証メソッドが登録されている場合は、最後に使用されたメソッドが開きます。別の登録済み検証メソッドで本人確認を行いたい場合は、別の検証メソッドを選択できます。

組織の MFA 検証メソッド設定によって、次のタイプのメソッドを選択できます: Salesforce Authenticator、セキュリティキー、またはサードパーティーの認証アプリ。

Salesforce Authenticator アプリ

Salesforce Authenticator アプリ (バージョン 3 以降) をアカウントに接続している場合は、そのアプリを使用して B2C Commerce アプリケーションにログインします。Account Manager からモバイルデバイスにプッシュ通知が送信されます。通知を受け取ったら、アプリを開き、アクティビティの詳細を確認し、モバイルデバイスで、Approve (承認) をタップします。Salesforce Authenticator でも TOTP がサポートされています。

メモ Salesforce Authenticator アプリケーションは安全なモバイルデバイスに保管します。モバイルデバイスを保護するには、モバイルデバイスでサポートされている PIN/FaceID/TouchID を使用します。

セキュリティキー

Fast Identity Online (FIDO) U2F または WebAuthn (FIDO2) と互換性のあるセキュリティキーをアカウントに登録した場合は、そのセキュリティキーを使用して B2C Commerce アプリケーションにログインします。プロンプトが表示されたら、コンピューターまたはモバイルデバイスの適切なポートにセキュリティキーを挿入します。ボタンがある場合は、ボタンをタッチします。デバイスを起動するためにタッチを必要とするボタンが付いているセキュリティキーもありますが、セキュリティキーは生体認証デバイスではありません。

一度限りのパスワード生成ツールアプリ

サードパーティーの認証アプリ (Google Authenticator や Microsoft Authenticator など) をアカウントに接続している場合は、そのアプリを使用して B2C Commerce アプリケーションにログインします。時間ベースの一度限りのパスワード (TOTP) と呼ばれる一時的なコードを生成する任意の認証アプリを使用します。コードの値は定期的に変更されます。Account Manager で一時コードの入力を求められたら、コードを入力して、Verify (検証) をクリックします。

買い物客プロフィールの同期のための属性マッピングの構成

属性マッピングでは、B2C Commerce と Salesforce Org の間で同期する買い物客の属性を定義します。

姓、名、メールアドレス、電話番号を含む 12 のデフォルトマッピングが常にアクティブです。これらのデフォルトのマッピングを編集または削除することはできません。

デフォルトのマッピングの後に、追加の標準またはカスタムの買い物客属性のカスタムマッピングを最大 20 個追加します。

カスタム属性マッピングを追加するには、自動同期がオフの状態で属性マッピングセクションに移動します。マッピングする B2C Commerce 買い物客属性と、対応する Salesforce 個人取引先フィールドを選択します。目的の個人取引先属性が表示されない場合は、接続されている Salesforce 組織でその属性を作成したことを確認してください。属性マッピングでは、ブール型、倍精度浮動小数点数型、整数型、長整数型、およびテキスト型の属性がサポートされます。

重要 B2C Commerce では、バージョン 26.7 以降、買い物客のプロフィールでカスタム属性の同期をサポートする予定です。このリリースまで、Shopper Profile Sync はデフォルトのシステム属性マッピングのみを同期します。提供状況に関する最新情報については、B2C Commerce リリースノートを確認してください。

自動同期をオンにする前に、カスタムマッピングを設定します。自動同期がオンのときにマッピングを更新すると、変更は次回にスケジュールされている同期時に有効になります。ただし、時間のかかる既存の買い物客データの再同期を避けるために、マッピングの更新は制限してください。

重要 属性マッピングを更新するたびに、それらの変更を本番環境と非本番環境の両方に反映して、同期を維持します。

    メモ 別のサービスのために B2C Commerce の買い物客データを Salesforce Org に接続すると、そのサービスに適用される信頼性とコンプライアンスに関するドキュメントが適用されます。
  • Business Manager と関連付けられている Salesforce Org の両方で管理者権限があることを確認します。
  • Salesforce 組織で個人取引先を有効にします。詳細については、「個人取引先の有効化」を参照してください。
    メモ 個人取引先のカスタム項目を対応付けるには、Salesforce 組織で作成済みであることを確認してください。
  • Salesforce 組織で一致ルールと重複ルールを構成します。詳細については、「買い物客プロフィールの同期のための個人取引先の重複ルールの設定」を参照してください。
  • 既存の買い物客データを移行する場合は、先に進む前に、買い物客プロフィールの同期フィールドへの管理者アクセス権を付与します。詳細については、「買い物客プロフィールの同期フィールドへの管理者アクセス権の付与」を参照してください。
警告 買い物客プロフィールの同期を有効にすると、組織に同期されたすべての買い物客プロフィールに対して、取引先変更データキャプチャと連絡先変更データキャプチャ (CDC) イベントが生成されます。これらのイベントを消費するダウンストリーム システムとの既存の CDC 統合がある場合、初期同期によって、毎日の CDC イベント資格を大幅に超える大量のイベントが生成される可能性があります。

たとえば、1 日あたり 150,000 件のイベント割り当てに対して 1,000 万人の買い物客を同期すると、下流の消費者が完全に処理するまでに約 60 日間のバックログが作成されます。これにより、タイムリーな CDC 更新に依存するシステム(Shopper Profile Sync 外部の統合を含む)へのイベント配信に大幅な遅延が生じる可能性があります。先に進む前に、現在の CDC 利用資格を確認し、買い物客のデータセットのサイズを評価して、ダウンストリームシステムが結果として生じる処理の遅延を許容できるかどうかを確認します。予測されるバックログが許容できない場合は、アカウントチームに連絡して、CDC イベントの割り当てを増やすか、段階的な有効化を調整するかについて話し合ってから続行してください。

Production (本番) に変更を加える前に、Production (本番) 以外の B2C Commerce インスタンスで Shopper Profile Sync を設定します。このプラクティスを、関連するSalesforce Sandbox 環境にも適用します。たとえば、個人取引先スキーマを変更する場合は、まず下位の環境で変更をテストしてから、本番に昇格させます。

警告 接続の問題を防ぐために、接続されている Salesforce Sandbox 環境の更新は避けてください。接続されている Salesforce Sandbox 環境を更新し、接続の修復についてサポートが必要な場合は、Salesforce カスタマーサポートにお問い合わせください。

買い物客プロフィールの同期を有効にする

記載されている順序で各ステップを完了して、買い物客プロフィールの同期を設定します。手順をスキップしたり、順不同で完了したりすると、設定ミスの原因になります。

  1. Business Manager で、アプリケーションランチャーから管理 | グローバル環境設定 | Salesforce 接続の順に移動します。
  2. [Shopper Profile Sync (買い物客プロフィールの同期)] タイルで [ Get Started (開始する )] をクリックします。
  3. B2C Commerce インスタンスをまだ Salesforce Org に接続していない場合は、設定フローに従ってください。詳細については、「B2C Commerce インスタンスの Salesforce への接続」を参照してください。
  4. [Shopper Profile Sync (買い物客プロフィールの同期 )] をオンにします。
  5. 属性マッピングを確認して構成します。詳細については、「Shopper Profile Sync の属性マッピングの構成」を参照してください。
    重要 6 月のリリースでは、既存の個人取引先の CustomerUnifiedProfile テーブルの accountId 項目は入力されません。今後のリリースでは、すべての顧客プロファイルを更新して、対応する個人取引先 ID を含める予定です。統合のユースケースでは、代わりに連絡先 ID を使用します。
  6. 重複するルールを確認して構成します。詳細については、「買い物客プロフィールの同期のための個人取引先の重複ルールの設定」を参照してください。
  7. 属性マッピングが完了したら、自動同期トグルをオンにします。

自動同期を初めてオンにすると、システムによって初期同期が実行され、既存の登録済み買い物客全員が Salesforce 組織に移行されます。初期同期はバックグラウンドのバッチ操作です。そのため、個人取引先はすべてのレコードの Salesforce にすぐには表示されません。この初期同期の合計時間は、既存の B2C Commerce 買い物客データベースのサイズによって異なります。

初期同期が完了した後、システムは差分同期を通じて同期を維持します。既存の買い物客のマッピングされた属性に対する更新は、スケジュールに基づいて双方向で同期されます。

  • B2C Commerce から Salesforce 組織へ:同期は約 1 時間ごとに実行されます。
  • Salesforce 組織から B2C Commerce へ:同期は約 5 分ごとに実行されます。

自動同期をオンにすると、[データ同期] セクションに、最後に完了した同期と次回にスケジュールされている同期のタイムスタンプを含む同期ステータスが表示されます。

この機能をオフにする必要がある場合は、[ 自動同期 ] トグルをオフにしてから、買い物客プロフィールの同期をオフにします。この機能をオフにしても、以前に同期されたデータは削除されませんが、新しい更新は取引先レコードと同期されなくなります。買い物客プロフィールの同期はいつでもオンにして、機能を再度有効にすることができます。

B2C Commerce での CDP Connector セグメントによる顧客グループの作成

毎日、セグメントのアクティブ化によって統合プロフィールが CDP から B2C Commerce に移動されます。統合プロフィールから顧客グループを作成するには、顧客グループ機能を使用します。このトピックは、B2C Commerce に該当します。

    ベストプラクティス: この 2 つの条件のいずれかを追加する場合は、「および」の方が「または」よりも意味のあるものになります。
  9. (任意) セッションカスタム属性の条件を作成します。
    1. 追加をクリックします。
    2. 属性の選択をクリックし、セッションカスタム属性を選択します。
    3. 属性に名前を付けます。たとえば、Release_Number などです。
    4. Enter を押します。
    5. リストから演算子を選択します。
    6. 値の選択をクリックし、値を入力して、追加をクリックします。
    7. 値を入力して、Enter を押します。

B2C Commerce での顧客グループの作成

顧客グループを作成および編集して、マーケティングのために顧客を割り当てます。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーの順にクリックし、サイト名 | マーチャントツール | 顧客 | 顧客グループを選択します。
  2. 顧客グループのページで、顧客グループを作成または編集します。

    グリッドには、ID、説明、タイプ、静的グループの顧客数が表示されます。

    このグリッドでリンクを右クリックすると、選択内容を新しいタブやウィンドウで開くなど、標準的な操作を実行できます。
    1. フィルターのアイコンをクリックし、フィルタータイプを選択します。
    2. フィールド別に並べ替えるには、ID または説明の列のヘッダーをクリックします。
  3. 顧客グループを作成するには:
    1. 顧客グループのページで、新規をクリックします。
    2. 新規顧客グループの作成ウィンドウで、ID と説明を入力します (例: USA_CA_Customers)。
      このフィールドはいったん作成すると、読み取り専用となります。
    3. 以下のいずれかのタイプを選択します:
      • 静的: マーチャント定義。Business Manager またはインポートを使用して、これらのグループに顧客を手動で割り当てます。
      • 動的: マーチャント定義。顧客データを使用して、どの顧客がグループに所属するか、所属しないかはグループメンバーシップルールによって決定します。これらのグループに明示的に顧客を割り当てることはできません。

      システム タイプは事前定義された Salesforce B2C Commerce グループです。顧客は、これらのグループに自動的に割り当てられます。これらのグループは編集も削除もできません。以下のグループが含まれます。

      • Everyone (すべての顧客): 未登録か登録済みかに関わらず、サイトのすべての顧客。
      • Registered (登録済み): サイトに登録されたすべての顧客。
      • Unregistered (未登録): サイトに登録されていないすべての顧客。
    4. 保存をクリックします。
    5. 動的顧客グループについては、動的顧客グループの作成を参照してください。
    6. 静的顧客グループについては、引き続きこれらの指示に従ってください。
  4. 静的顧客グループを作成するには:
    1. 顧客グループのページで、顧客グループ ID をクリックします。
    2. 顧客グループ「顧客グループ名」の編集ページの全般タブで、説明を入力または編集します。
    3. メンバータブをクリックします。
      顧客がすでに割り当てられている場合は、顧客ナンバー、姓名、ログイン ID、Eメールアドレス、および有効/無効がグリッドに表示されます。
    4. すでにメンバーである顧客をログイン ID で検索します。
      メモ Business Manager で Elastic Search を無効にすると、姓とログイン ID で顧客を検索できます。
    5. フィルターアイコンをクリックします。

      顧客ナンバー、姓、名、Eメール、または有効かどうかでフィルターできます。

      フィルターの詳細を入力します。たとえば、検索する特定の姓を入力します。フィルターはサブ文字列にも使用できます。たとえば、名で Mar を検索すると、Maria、Martin、および Martha が返されます。

    6. 割り当てるをクリックして、顧客を割り当てます。
      グループに割り当てられている顧客がいない場合は、「メンバーをこの顧客グループに割り当てる」のリンクが、空のグリッドの下に表示されます (グリッドのヘッダーのみが表示されます)。
    7. 「顧客を割り当てる」ウィンドウで、前述の検索またはフィルターを行います。

      このウィンドウを使用して、顧客の詳細と、顧客が有効かどうかを確認できます。

    8. グループに追加する顧客を選択して割り当てるをクリックします。
      顧客グループの編集 - 顧客グループ名のページが開き、顧客グループに割り当てた顧客が表示されます。
    9. メンバーの割り当てを解除するには、顧客グループの編集のページで 1 人または複数のメンバーを選択して、割り当て解除をクリックします。また、各行の最後にある割り当て解除アイコンをクリックすることもできます。
    10. 保存をクリックします。
  5. 顧客グループに基づいて商品をプレビューします。
  6. 顧客グループをキャンペーンまたは A/B テストに割り当てます。

B2C Commerce での動的顧客グループの作成

動的顧客グループとは、メンバーシップが変化するグループのことです。メンバーシップは購入履歴、プロフィール、住所、またはアクティブデータに基づきます。また、システムおよび静的顧客グループのメンバーシップを基にすることができます。メンバーシップを動的顧客グループに基づくようにすることはできません。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce

ターゲットを絞ったキャンペーン、マイクロサイト、および商品ラインのために動的顧客グループを作成します。

  1. アプリケーションランチャーの順にクリックし、 サイト名 | マーチャントツール | 顧客 | 顧客グループを選択します
  2. 新規をクリックします。
  3. ID を入力します (必須)。
  4. 動的を選択します。
  5. 保存をクリックします。
  6. 全般タブで、説明を入力または編集します。
    たとえば、「1 回の注文につき平均 100 ドル以上を費やした米国とカナダからの女性顧客」などです。
  7. 条件を追加するには、メンバーシップルールのセクションで次のようにします。
    1. 追加をクリックします。
    2. 属性の選択をクリックして、リストから選択します。
      属性をすばやく見つけるには、「自動検索候補」機能を使用します。
    3. 演算子を選択します。
    4. 値を選択します。
  8. 左側にある四角のアイコンを使用して、条件を別の位置にドラッグします。
    含めるリストまたは除外リストの内部で、または含めるリストと除外リストの間でドラッグアンドドロップします。
  9. 条件間の関係を変更するには、「および」あるいは「または」を選択します。

    ベストプラクティス: 以下の 2 つの条件のいずれかを追加した場合、「および」の方が「または」よりも意味のあるものになります。

    • 平均注文金額が $50 以上 および 国がイタリア
    • 平均注文金額が $50 以上 または 国がイタリア

    「または」条件としては、次の場合が適切です。

    • 市区町村がデンバー または 市区町村がボールダー
  10. (任意) セッションカスタム属性の条件を作成します。
    1. 追加をクリックしてルールを追加します。
    2. 属性の選択をクリックし、セッションカスタム属性を選択します。
    3. たとえば、Release_Number など、セッションカスタム属性の名前を入力します。
    4. Enter を押します。
    5. リストから演算子を選択します。
    6. 値の選択をクリックし、値を入力して、追加をクリックします。
    7. 値を入力して、Enter を押します。
    セッションカスタム属性を変更するには、セルをクリックしてテキストフィールドを開きます。条件タイプを変更しますが (たとえば、セッションカスタム属性から誕生日に変更)、既存の演算子と値はクリアされます。条件を削除して、条件を作成します。
  11. 条件を削除するには、右側にある削除アイコンをクリックします。
  12. 保存をクリックします。
  13. 既存の動的顧客グループを編集するには:
    1. サイト名 | マーチャントツール | 顧客 | 顧客グループの順に選択します。
    2. グループの ID をクリックします。
    3. 全般タブで、説明を入力するか、変更します。
    4. 条件を編集するには、クリックします。
    5. 前述の手順に従います。

B2C Commerce での顧客リストの作成

顧客リストは Staging (ステージング) インスタンスで作成します。

必要なエディション

使用可能なソリューション: B2C Commerce

顧客リストを作成するには、管理 | サイト | 顧客リストモジュールへのアクセス許可が必要です。

  1. アプリケーションランチャーの順にクリックし、管理 | サイト | 顧客リストの順に選択します。
  2. 新規をクリックします。
  3. 新規顧客リストページで、新しいリストの ID を入力します。
  4. 適用をクリックして、新規顧客リストを作成します。
  5. 顧客リストページの全般タブで、次の操作を実行します。
    1. 説明を入力するか、変更します。
    2. 顧客ナンバーシーケンスを指定します。
      組織ごとに一意を選択することをお勧めします。このシーケンス番号に使用される形式は、グローバル環境設定のシーケンス番号ページで設定します。
    3. 顧客プロフィールの保持を構成します。
      顧客プロフィールの保持とは、Salesforce B2C Commerce が顧客プロフィールを保管する日数です (1 ～ 99,999)。指定した日数以内にサイトを訪問しなかった顧客のプロフィールは自動的に削除されます。顧客プロフィールが B2C Commerce から削除されないようにするには、ここを空白のままにします。
    4. 顧客のログイン設定を構成します。
      • 顧客のロックアウトの有効化: 指定のログイン失敗回数に達したときに、顧客の自動ロックアウトを有効または無効にします。
      • 最大無効ログイン試行回数:顧客のアカウントが一時的に無効になるまでのログインの連続失敗回数 (1 ～ 200)。
      • ロックアウト有効期間: ロックアウトされた顧客が再びログインできるまでの時間。
      • ログイン試行リセット時間: 無効なログイン試行回数のカウントが 0 にリセットされるまでの時間。
      • 最小パスワード長: 有効なパスワードに必要な最小文字数。
      • 最小パスワード特殊文字数: 有効なパスワードに必要な特殊文字 ($%/()[]{}=?!.,-_*|+~#) の最小数。
      • パスワードに文字を含める: パスワードで文字の使用を必須にします。また、任意で、大文字と小文字の使用を必須にすることもできます。
      • パスワードに数字を含める: 「はい」または「いいえ」。
      • パスワードの期限: パスワードの有効期間。デフォルトはなし です。
      • パスワードリセットのトークンの有効期限: パスワードリセットのトークンの有効期間。この期間は、ヘッダー属性 max-password-reset-token-age を通じて、顧客リストのインポートで構成することもできます。
        メモ この設定への変更は、SiteGenesis アプリケーションの顧客パスワードリセットのEメールのテキストには自動的には反映されません。この Eメールには、30 分の有効期間がハードコードされています。Eメールテンプレートを手動で更新します。
    5. 適用をクリックします。
  6. 顧客リストページのサイトの割り当てタブで、次の操作を行います。
    1. 顧客リストを構成するサイトを選択します。
    2. 適用をクリックします。
  7. 顧客リストページの顧客タブで、リストから顧客を削除できます。
  8. 適用と << リストに戻るをクリックします。
  9. 顧客リストページで、新規リストを表示します。

B2C Commerce での統合プロフィールの作成

CDP セグメントを作成する際には、顧客を共通の興味、消費習慣、検索の傾向などでセグメント化した属性を指定します。たとえば、過去 30 日間に 5 千円以上を消費し、ロイヤリティプログラムに所属しているすべての顧客のセグメントを作成します。

セグメントの属性に基づいて、属性の条件を満たすすべてのユーザーで構成される統合プロフィールを生成します。統合プロフィール属性を使用し、その統合プロフィールに属する顧客をターゲットとした、プロモーションや Eメールキャンペーンなどの意味のあるコマース体験を作り上げます。

B2C Commerce の顧客グループ機能では、レコードフィールドを使用して顧客を識別し、統合プロフィールに接続します。

セッションカスタム属性を使用した動的顧客グループ

B2C Commerce では、以下の方法で動的顧客グループをインポートする際に特別な変換が適用されます:

  • セッションカスタム属性を評価するルール条件
  • ルール条件の演算子が「が次の値に等しい」
  • 条件の値とセッションカスタム属性が数値またはブール値のようなデータである

数値条件では、以下のインポートが:


 <condition>
	 <attribute-path>session.custom.myAttribute</attribute-path>
	 <operator>is-equal</operator>
	 <string>1.0</string>
	 <string>2.0</string>
	 <string>3.0</string>
 </condition>

エクスポートで以下に変換:


 <condition>
	 <attribute-path>session.custom.myAttribute</attribute-path>
	 <operator>is-equal</operator>
	 <number>1.0</number>
	 <number>2.0</number>
	 <number>3.0</number>
 </condition>

ブール 条件では以下のインポートが:


 <condition>
	 <attribute-path>session.custom.myAttribute</attribute-path>
	 <operator>is-equal</operator>
	 <string>true</string>
 </condition>

エクスポートで以下に変換:


 <condition>
	 <attribute-path>session.custom.myAttribute</attribute-path>
	 <operator>is-true</operator>
 </condition>

データグループ: 顧客リスト

サイトのインポート/エクスポートでは、データグループの顧客リストがサポートされます。B2C Commerce では、カタログ、在庫リスト、および価格表の割り当てと同様に、サイトの割り当てをサイト環境設定として顧客リストにインポートします。B2C Commerce では、同じ顧客リストに割り当てられたすべてのサイトに対して、同じ顧客がエクスポートされます。

要素: Gender (性別)

インポートファイルに gender 要素がない場合、性別はデータベースで更新されません。性別が空白の場合、性別はデータベースで null に設定されます。インポートファイルの gender 要素に男性または女性の値が含まれている場合、B2C Commerce はデータベースで男性を 1 として、女性を 2 として保存します。gender 属性に数値が含まれている場合、B2C Commerce はその値をデータベースにそのまま保存します。

要素: Country-Code (国コード)

address コンプレックスタイプの下位要素 country-code を使用すると、1 文字または 2 文字の国コードをインポートまたはエクスポートできます。バージョン 12.2 より前のバージョンまでは、B2C Commerce でインポートまたはエクスポートすることができたのは 2 文字の国コードのみでした。

メモ 国コードに空白しか含まれていない場合、その国コードはエクスポートされません。ただし、エクスポートされた XML ファイルに国コードが含まれていない場合でも、住所はエクスポートされます。

住所 ID を含む顧客住所の前または後にスペースが含まれている場合でも、その住所は正しくエクスポートされます。バージョン 12.2 より前のバージョンまでは、前または後にスペースを含む顧客住所をエクスポートすることはできませんでした。

B2C Commerce での動的顧客グループのインポート/エクスポート

動的顧客グループは、(既存の) 顧客グループ のインポート/エクスポートを使用して、インポートおよびエクスポートすることができます。このトピックは、B2C Commerce に該当します。

メモ 動的顧客グループのエクスポートには、グループのルールが含まれますが、実際の顧客の割り当ては含まれません。同様に、インポートには、ルールは含まれますが、実際のメンバーシップデータは含まれません。そのため、動的顧客グループのインポートでは、その後実行されるバックグランドのセグメンテーション処理に依存して、新しくインポートされたグループの顧客メンバーシップを確立します。

顧客のインポートでは、現在のところ、明示的な顧客グループの割り当てをインポートします。動的顧客グループのメンバーシップは動的に計算されるため、顧客のインポートでは動的顧客グループへの割り当ては拒否され、エクスポートではそのような割り当ては省略されます。

customergroup.xsd スキーマには、次のルール要素があります:

<xsd:complexType name="complexType.CustomerGroup" mixed="false">
    <xsd:sequence>
        <xsd:element name="description" type="xsd:string" minOccurs="0" maxOccurs="1" />
        <!--- new element capturing the membership rule; if defined the customer group becomes a dynamic customer group.If not defined it becomes a customer group with explicit assignments--->
        <xsd:element name="rule" type="Rule" minOccurs="0" maxOccurs="1" />
        <xsd:element name="custom-attributes" type="sharedType.CustomAttributes" minOccurs="0" maxOccurs="1" />
    </xsd:sequence>
    <xsd:attribute name="group-id" type="simpleType.Generic.NonEmptyString.256" use="required" />
</xsd:complexType>

また、スキーマには、動的グループに関連する次のような複雑なタイプがあります:

<xsd:complexType name="Rule" mixed="false">
<xsd:complexType name="ConditionGroups" mixed="false">
<xsd:complexType name="ConditionGroup" mixed="false">
<xsd:complexType name="DateCondition" mixed="false">
<xsd:complexType name="DateRange" mixed="false">
<xsd:complexType name="RelativeDateRange" mixed="false">
<xsd:complexType name="StringCondition" mixed="false">

B2C Commerce によって提供されていないアクティブデータは、インポートする必要があります。アクティブマーチャンダイジングのデータには、スキーマがありません。代わりに、マーチャントがフィードの形式を定義して、Business Manager で .csv ファイルを手動でインポートするか、または新しい ImportActiveData パイプレットを使用してインポートを自動化することができます。

アクティブデータ属性のインポートを有効にするには、その属性をフィードに割り当てます。1 つの属性は、1 つのフィードにのみ割り当てることができます。マーチャントは、システム用に確保されているフィード数をフィードの最大数 5 から差し引いた数のインポートフィードを ProductActiveData オブジェクトまたは CustomerActiveData オブジェクトに設定できます。フィードには、インポートモードはありません。

/Sites/Impex/src/activedata/a-product-active-data-file.csv

B2C Commerce の顧客リスト

顧客リストにより、1 つまたは複数のサイトに割り当てられた顧客のセットが特定されます。このトピックは、B2C Commerce に該当します。

A/B テストに含めたり、顧客グループに追加したり、アクティブマーチャンダイジングを使用して管理したりすることができるのは、サイトの顧客リストに含まれている顧客のみです。ストアフロントで登録した顧客はすべて、そのサイトの顧客リストに追加されます。顧客リストは、複数のサイトに割り当てることができます。ただし、1 つのサイトで使用できる顧客リストは 1 つだけです。顧客リストは、Business Manager 管理モジュールの「サイト」で組織ごとに定義して管理します。

Business Manager は次の目的で使用します:

  • 顧客リストの作成
  • 顧客リストの削除
  • 顧客リストからの顧客の削除
  • 顧客リストのインポートとエクスポート

共有顧客プロフィールの利点

すべてのサイトで 1 つの顧客リストを管理する場合、顧客はサイトごとに個別のプロフィールを作成する必要がありません。共有プロフィールでは、保持、検証、管理するデータがより少なくなります。

共有プロフィールには、一意の顧客ナンバーおよびログインが必要になるため、サイト間で信頼のおけるデータ集計が可能になります。集計された顧客データでは、顧客についてのより包括的な情報を得ることができるため、顧客関係の管理にとってはより優れたオプションです。

共有顧客プロフィールの制限

共有顧客プロフィールでは、シングルサインオンが許可されていません。顧客は各サイトにログインする必要があります。注文手続き、注文履歴、およびアクティブデータは、サイト固有です。重複するアカウントを所有している顧客が、異なるサイトで異なる支払方法を使用した場合、顧客は支払方法情報を失うことになります。

サイト間で共有される顧客データ

顧客リストが複数サイトに割り当てられた場合、次の顧客データがサイト間で共有されます:

  • 顧客ナンバー: 顧客ナンバーシーケンスを含む
  • 認証情報: ログインとパスワード
  • プロフィールデータ: すべてのプロフィールのカスタム属性を含む
  • 保存されている支払手段: すべての支払手段のカスタム属性を含む
  • データ保持の環境設定: 支払データが保管される日数は、サイトではなく顧客リストによって異なります。

サイト固有の顧客データ

次の顧客データは各サイトで個別に管理する必要があります:

  • 顧客
    • ほしい物リストとギフト登録
    • 買い物カゴ - チェックアウト処理はサイト固有です
    • アクティブデータ - データはサイトごとに収集されます
    • 注文 - 顧客は各サイトごとに個別に注文履歴を表示する必要があります
  • 顧客グループと、顧客から顧客グループへの割り当て
  • ストアフロントセッションと Cookie - 登録済み顧客の「このアカウントを記憶する」のステータスを含む。

顧客リストを共有するサイト内の顧客グループ

顧客グループは引き続きサイト固有です。つまり、グループは各サイトごとに作成して管理する必要があります。ただし、共有顧客リストに含まれる顧客は、その顧客リストを共有しているサイト内のどのグループのメンバーにも属することができます。このため、作成可能なグループの合計数の制限も保持されます。

顧客リストを共有するサイトのアクティブデータ

アクティブデータはサイト固有です。サイト間で顧客に関するデータを収集する場合は、データをエクスポートして集計し、それをアクティブデータフィードに追加する必要があります。共有プロフィールには、一意の顧客 ID が必要になるため、サイト間で信頼のおけるデータ集計が可能になります。

B2C Commerce の顧客リストの環境設定

顧客のサイト環境設定を使用して、顧客がログインに失敗した場合にストアフロントがどのように対応するかを制御します。失敗した試行回数が指定の回数を超えた場合、任意で顧客のアカウントをロックアウトすることで、顧客のパスワードを解読しようとする総当り 試行を防止することができます。

    • 組織ごとに一意
    • 顧客リストごとに一意: 開始値を選択して、書式パターンを入力します。
  5. 顧客プロフィールの保持を構成します。
    顧客のプロフィールを Salesforce B2C Commerce に保存する日数を入力します (1 ～ 99.999)。顧客が指定日数以内にサイトを訪問しないと、その顧客のプロフィールは自動的に削除されます。顧客のプロフィールを削除したくない場合は空白にします。
    メモ データのクリーンアップジョブを使用して、有効期限切れの顧客を削除します。
    1. Business Manager で、アプリケーションランチャーをクリックし、次に管理 | オペレーション | ジョブの順に選択します
    2. ssfcc-data-cleanup ジョブを使用します。
      このジョブには CleanupExpiredCustomers ジョブステップが含まれています。このステップでは顧客の保持期間の値が、LASTVISITTIME、LASTLOGINTIME、および CREATIONDATE に対してこの順番で確認されます。顧客は、定義されている保持日数を超えて非アクティブになると、有効期限切れとしてマークされ、削除の処理が行われます。
      メモ Production (本番) 環境では、顧客の保持日数は 730 日に構成されています。
  6. 顧客のログイン設定を構成します。
    1. 指定の試行回数に達したときに、顧客のロックアウトを有効/無効にします。
      このフィールドはすべての顧客に対してデフォルトで True に設定されています。これは、顧客のパスワードを解読しようとする「総当り」試行を防止するためです。顧客は、ロックアウト期間の有効期限が切れるまで 30 分間待機するか、または即座にパスワードをリセットすることができます。パスワードをリセットすると、アカウントへのアクセスが許可され、買い物を続行することができます。サイト管理者がこのセキュリティ機能を無効にしたい場合は、このフィールドを False に設定できます。
    2. 最大無効ログイン試行回数に 1 から 200 の値を入力します。
    3. ロックアウト有効期間に「1 分」から「10 日」の値を選択します (デフォルトは 2 時間)。
    4. ログイン試行リセット時間に「なし」から「1 日」の値を選択します (デフォルトは 1 日)。
    5. 最小パスワード長を選択します。
    6. 有効なパスワードに必要な特殊文字 ($%/()[]{}=?!.,-_*|+~#) の最小数を入力します。
    7. パスワードに文字が必要かどうかを選択します。True に設定する場合は、大文字または小文字、あるいは大文字と小文字の両方の使用を必須にするかどうか選択します。
    8. パスワードに数字が必要かどうかを選択します。
    9. パスワードの期限で、パスワードの有効期間として「なし」から「90 日」の値を選択します (デフォルトは「なし」)。
  7. 適用をクリックして変更を保存するか、リセットをクリックして変更を拒否します。
