B2C Commerce での B2C Commerce アカウントのアクティベート

アカウントをアクティブにするには、まず、アカウント管理者がアカウントを作成する必要があります。管理者がアカウントを作成すると、Account Manager からユーザーの Eメールアドレスにメッセージが送信されます。この Eメールメッセージを使用して、アカウントのアクティベートを開始します。

所有している Salesforce Commerce 製品

  1. アクティベーションの Eメールメッセージに記載されているアクティベーションリンクをクリックします。

    このリンクから Account Manager の「Change Your Password (パスワードの変更)」ページにリダイレクトされます。

  2. Password (パスワード) フィールドにパスワードを入力します。

    文字を入力すると、パスワードのセキュリティ強度が表示されます。

  3. Confirm Password (パスワードの確認入力) フィールドに、パスワードを再度入力します。
  4. Change Password (パスワードの変更) ボタンをクリックします。

    パスワードが正常に変更されたというメッセージが表示されます。

  5. 続行をクリックします。

    2 通目のメッセージ (パスワードが変更されたという内容) がユーザーの Eメールアドレスに届きます。このメッセージの目的は、アクティベーションが正常に完了したことを確認する、または別の人がパスワードを変更しようとしたことを警告することです。別の人がパスワードを変更しようとした場合は、アカウント管理者またはヘルプデスクまで連絡してください。

B2C Commerce での Account Manager と Salesforce 間の連携のアクティブ化

ID フェデレーションを有効にした後に、Account Manager を Salesforce Org にリンクします。

所有している Salesforce Commerce 製品

  1. Web ブラウザーで、https://account.demandware.com を開きます。
  2. Login with SSO (SSO によるログイン) を選択します。
  3. Salesforce 認証情報を入力します。
    これで、Account Manager にリダイレクトされます。
  4. Account Manager のユーザー名 (Eメールアドレス) を入力します。

    Account Manager と Salesforce CRM Core の Eメールアドレスは同一です。

  5. LOG IN (ログイン) をクリックし、パスワードを入力します。
  6. LINK ACCOUNT (アカウントのリンク) をクリックします。
  7. 登録済みの多要素認証 (MFA) メソッドを使用して、Account Manager へのログインが許可されていることを確認します。
    これで Account Manager にログインできます。
  8. 履歴詳細を確認し、自分のアカウントが Salesforce Identity にリンクされていることを確認します。

次に、Account Manager を接続アプリケーションとしてインストールし、Salesforce プラットフォームを構成します。

B2C Commerce での API クライアントの追加

アカウント管理者は、Account Manager を使用して API クライアントを作成できます。Salesforce Commerce API (Shopper Commerce API (SCAPI)) または Open Commerce API (OCAPI) にアクセスするには、API クライアントを使用する必要があります。これらの API へのアクセスに使用する URL に API クライアント ID を追加します。API クライアントは、On-Demand Sandbox API を使用する場合にも必要です。

B2C Commerce API (SCAPI) と OCAPI の両方に同じクライアント ID を使用することはできません。各 API フレームワークには、独自のクライアント ID が必要です。OCAPI 用の API クライアントID には、 "Salesforce Commerce API" の役割を割り当てることはできません。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. API Client (API クライアント) をクリックします。

    API Clients (API クライアント) ページが開き、API クライアントのリストが表示されます。ページには、各クライアントの API クライアント ID、表示名、ステータスが表示されます。API クライアントが複数の組織で共有されている場合、表示名にはインジケータアイコン (1) が表示されます。共有 API クライアントについては、API クライアントの詳細ページと変更の保存時にも警告が表示されます。Account Manager では、API クライアントを 1 つの組織に制限することを推奨しています。詳細については、「B2C Commerce で複数の組織に割り当てられた Account Manager API クライアントのセキュリティ更新」を参照してください。

  3. [ Add API Client (API クライアントを追加 )] (2) をクリックして [Add API Client (API クライアントを追加)] ページを開きます。
  4. Display Name (表示名) フィールドに、クライアントの表示名を入力します。
  5. Password (パスワード) フィールドに、パスワードを入力します。
    パスワードの最小要件:
    • 12 文字以上で指定します。(必要な文字数は組織レベルで設定できます。12 文字以上にする必要があります)。
    • 数字、記号、小文字、大文字の 4 つのうち 3 つを含める必要があります。
    • 名前、ユーザー名、または汎用一意識別子 (UUID) の一部を含めることはできません。
  6. Confirm Password (パスワードの確認入力) フィールドに、パスワードを再度入力します。

    Access Control (アクセス制御) セクションには、API クライアントのステータスが表示されます。

  7. 「クライアント認証タイプ」セクションで、認証タイプを選択します。
    • 社外秘 :クライアント シークレットを安全に格納できるサーバーまたはプラットフォーム上で実行されるアプリケーションに適しています。
    • パブリック:単一ページの Web アプリやネイティブのモバイルおよびデスクトップアプリケーションなど、シークレットを非表示にできない環境に適しています。Proof Key for Code Exchange (PKCE) を使用して、OAuth トークンを安全に交換します。公開 API クライアントでは、ロールの割り当て、パスワードの設定、JWT 公開鍵の使用はできません。
  8. Organizations (組織) セクションで、Add (追加) をクリックします。

    Assign Organizations (組織の割り当て) ページが開きます。

  9. Assign Organizations (組織の割り当て) ページで、次の操作を行います:
    1. 組織を検索します。
    2. API クライアントを組織に追加するには、組織のチェックボックスにチェックを付けます (各 API クライアントは 1 つ以上の組織に所属させる必要があります)。
    3. 追加をクリックします。
  10. (オプション)API クライアントに役割を割り当てるには、[ Roles (役割 )] セクションで[Add (追加 )] をクリックします。
    1. Account Manager の役割の割り当て:アカウント管理者や API 管理者などの役割を検索して選択します。
    2. Salesforce Commerce API の役割の割り当て:API クライアントが Salesforce Commerce API (SCAPI) にアクセスできるようにするには、Salesforce Commerce API ロールを検索して選択します。フィルター アイコンを選択して、必要なロールの範囲を指定します。Add Instance Filters (インスタンスフィルターの追加) タブで、組織を選択します。アクセスするインスタンスの名前を入力して選択します。追加をクリックします。
  11. (オプション) パスワードの代わりに JSON Web Token (JWT) を使用して API クライアントを認証するには、JWT フィールドに、クライアント JWT ベアラー公開鍵を入力します。PEM 形式の証明書または Base64 でエンコードされた RSA 公開鍵を、ヘッダー付きまたはヘッダーなしで入力します。システムは正しいフォーマットと有効な暗号化素材をチェックします。アクセストークンの形式を使用するには、JWT を追加します。
  12. (オプション)API クライアントで OAuth2 を使用して B2C Commerce リソースにアクセスするには、OpenID Connectセクションに値を入力します。
    JWT アクセストークンフォーマットは必須です。UUID には対応していません。
  13. 保存をクリックします。
    Account Manager によって API クライアントが作成されます。

B2C Commerce API クライアントのパージ

Account Manager 管理者は、Account Manager のパージ機能を使用して API クライアントをパージできます。

所有している Salesforce Commerce 製品

パージオプションは、API クライアントが無効ステータスに設定されてから 7 日間が経過した後にのみ使用できます。この待機期間により、ビジネスに影響を与える可能性のある偶発的なパージが防止されます。パージオプションはグレー表示され、無効になってから 7 日未満の API クライアントではアクティブになりません。

メモ パージ機能を有効にする前に無効にされた API クライアントは、7 日間の待機期間の対象とならず、パージできます。

Account Manager API クライアントの詳細ページには、API クライアントの最終認証日が表示されます。この日付は、API クライアントが最後に有効な認証情報を使用してアクセストークンを取得した日時を示します。最終認証日を使用して、API クライアントのアクティビティをモニタリングし、非アクティブな API クライアントを特定します。セキュリティ上の理由から、使用されていない API クライアントを無効にして消去することをお勧めします。

B2C Commerce は、2024 年 8 月 14 日に API クライアントの最終認証値の追跡を開始しました。API クライアントの最後の認証値が空の場合、2024 年 8 月 14 日より前に使用されていません。

その他の参照項目:

  • 最終認証日による API クライアントアクティビティの追跡
  • Account Manager からの API クライアントのパージ
    B2C Commerce Account Manager 管理者は、7 日以上無効ステータスに設定されている API クライアントをパージできます。

監査ログイベント

Account Manager B2C Commerce の監査ログイベントは Log Center で利用でき、ユーザー、API クライアント、組織に対する変更を可視化できます。

所有している Salesforce Commerce 製品

Log Center は、ユーザーアカウント、API クライアント構成、組織の設定、ロールの割り当てへの変更を含む、すべての Account Manager アクティビティの監査ログイベントを発行します。

監査イベントには、次の情報が含まれます。

  • 変更されたエンティティ (ターゲット)
  • 誰が変更したか (俳優)
  • 発生したアクションの種類 (作成、更新、削除、ロールの割り当て)
  • 変更が行われた日時
  • 変更が関連付けられている組織

フィルタリングオプション、一般的なユースケース、Log Center クエリ言語 (LCQL) の例など、Account Manager 監査ログイベントへのアクセスと使用の詳細については、Log Center ドキュメンテーションの「Account Manager 監査ログイベント」を参照してください。

Account Manager と B2C Commerce でのリンクされていないアカウントの自動リンク

ジャストインタイムプロビジョニングを有効にしない場合でも、Account Manager でユーザーアカウントを作成すると、新規ユーザーアカウントの自動有効化とリンクを利用できます。

所有している Salesforce Commerce 製品

新規ユーザーが最初に SSO を実行すると、Account Manager アカウントが有効化され、Salesforce Identity アカウントまたは Salesforce Identity を使用するサードパーティの Identity and Access Management (IAM) にリンクされます。

このアプローチは、既存の Account Manager ユーザーにも使用できます。ユーザーが SSO を実行すると、Account Manager によってユーザーのアカウントが Salesforce Identity アカウントにリンクされます。セキュリティ上の理由から、既存のユーザーは Account Manager によってアカウントをリンクされる前に、Account Manager の認証情報で認証を受ける必要があります。ユーザーが多要素認証 (MFA) 検証者として登録済みの場合は、MFA 検証を送信してアカウントをリンクする必要があります。

Account Manager がユーザの Account Manager アカウントを Salesforce Identity アカウントにリンクした後、Account Manager ユーザのユーザ名を Salesforce Identity アカウントのメールアドレスに変更します。

B2C Commerce でのアカウント情報の変更

Account Manager でアカウント情報を変更します。Eメールアドレスは変更できませんが、勤務先の電話番号など、他のアカウント情報を変更できます。また、組織の多要素認証 (MFA) の検証メソッド設定によっては、B2C Commerce アプリケーションにログインする際に ID を検証するメソッドを登録できます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. Account Details (アカウント詳細) をクリックします。

    「Account Details (アカウント詳細)」ページが開き、変更可能な次のフィールドが表示されます: First Name (名)、Last Name (姓)、Business Phone (勤務先電話番号)、Mobile Phone (携帯電話番号)、Home Phone (自宅電話番号)、Preferred Language (優先する言語)。

  3. フィールド値を変更したら、[ 更新 ] をクリックします。

    アカウント詳細が正常に更新されたという内容のメッセージが表示されます。

  4. 続行をクリックします。

B2C Commerce での ID フェデレーション用の Account Manager の構成

ID フェデレーションにより、ユーザーは単一の認証情報セットで複数のアプリケーションやシステムにアクセスできるようになります。ID フェデレーションと Salesforce の [私のドメイン] を組み合わせると、ユーザーは Salesforce ID またはサードパーティの ID とアクセス管理 (IAM) の認証情報を Account Manager にリンクできます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. Organization (組織) をクリックし、ID フェデレーションを追加する組織を選択します。
  3. [Identity Federation with Salesforce Identity] (Salesforce Identity との ID フェデレーション) で、ID フェデレーションを有効にする方法を選択します。
    1. Allowed (許可): ユーザーは Account Manager アカウントと Salesforce Identity のリンクを拒否しても、Account Manager アカウントを使用して B2C Commerce にログインできます。
    2. Enforced (強制): ユーザーが Account Manager アカウントと Salesforce Identity のリンクを拒否した場合、そのユーザーは Account Manager アカウントを使用して B2C Commerce にログインできなくなります。
    3. Disabled (無効): ユーザーは、Account Manager のアカウントを Salesforce Identity にリンクできません。
  4. (オプション) ジャストインタイムユーザープロビジョニングを選択します。
    このオプションを使用すると、Account Manager で新規ユーザーが自動的にプロビジョニングされます。この設定は、ID フェデレーションが有効であり、Salesforce の [私のドメイン] が検証済みの場合にのみ適用されます。
  5. Salesforce Core 内の組織の My Domain (私のドメイン) サブドメインを指定する必要があります。
    1. 接尾辞を変更するには、ドロップダウンメニューを使用します。
      デフォルトのドメイン接尾辞は my.salesforce.com です。ID フェデレーションが許可または強制されている場合は、値を変更できます。たとえば、Salesforce Core の Sandbox を使用している場合、sandbox.my.salesforce.com をドメイン接尾辞として使用できます。

      サポートされている Salesforce Core ドメイン接尾辞は次のとおりです。

      • my.salesforce.com
      • sandbox.my.salesforce.com
      • develop.my.salesforce.com
      • trailblaze.my.salesforce.com
      • scratch.my.salesforce.com
      • sfdctest.my.salesforce.com
      メモ ユーザーが間違ったパスワードを 6 回入力すると、アカウントは 30 分間ロックされます。Account Manager のユーザーリストでは、アカウントは temporary locked (一時的にロックされています) とマークされます。
  6. ジャストインタイムのオプションを選択した場合は、Salesforce Org で認証します。Start verification (認証の開始) をクリックします。
    [Start verification] リンクが表示されない場合は、構成を保存してからページを更新してください。
    メモ ID フェデレーションを無効にしたものの、後ほどまた有効にする場合は、「私のドメイン」を再度検証する必要があります。

B2C Commerce での本人確認を目的とした Salesforce Authenticator (バージョン 3 以降) のアカウントへの接続

Salesforce Authenticator モバイルアプリは、多要素認証 (MFA) ログインのための素早く簡単な検証メソッドです。アプリを登録して Account Manager アカウントに接続します。Salesforce Authenticator では、自分のモバイルデバイスに送信されたプッシュ通知を受信して承認するには、セキュリティ PIN と Face ID を使用してモバイルデバイスをセキュリティ保護する必要があります。

所有している Salesforce Commerce 製品

  1. 使用しているモバイルデバイスのタイプ用の Salesforce Authenticator アプリ (バージョン 3 以降) をダウンロードしてインストールします。

    iPhone の場合は、App Store からアプリをダウンロードできます。

    Android デバイスの場合は、Google Play からアプリをダウンロードできます。

    お使いのモバイルデバイスに Salesforce Authenticator バージョン 1 をすでにインストールしている場合は、App Store または Google Play からアプリをバーション 3 に更新できます。更新の場合は、アプリにすでに保存されている接続済みアカウントが保持されます。これらのアカウントは、検証コードを生成しますが、プッシュ通知の受信や位置情報ベースの自動検証の許可を行わない、コード専用アカウントです。Salesforce への現在のログインで使用したユーザー名でコード専用アカウントをお持ちの場合は、アプリ内で左にスワイプしてそのユーザー名を削除してから先に進んでください。以降の手順で、アカウントをそのユーザー名に再度接続します。新しく接続されたアカウントでは、Salesforce Authenticator バージョン 3 の機能をすべて使用できます。バージョン 2 がすでにインストールされている場合は、バージョン 3 の更新がプッシュアウトされます。

    組織の MFA 検証メソッド設定に応じて、以下のようになります:

    • 次回のログイン時に Salesforce Authenticator との接続が要求され、これが許可される唯一の検証メソッドである場合: REGISTER DEVICE (デバイスの登録) をクリックして続行します。
    • 次回のログイン時に Salesforce Authenticator または別の検証メソッドとの接続が要求される場合: Salesforce Authenticator をクリックして続行します。
    • Account Manager にログインする際に、複数の MFA 検証メソッドの登録が可能であり、「Account Information (アカウント情報)」から Salesforce Authenticator に接続できる場合: Multi-Factor Verification (多要素検証) の横にある Add (追加) をクリックし、Salesforce Authenticator を選択します。
  2. モバイルデバイスで Salesforce Authenticator アプリを開きます。アプリを初めて開く場合は、アプリの機能を紹介するツアーが表示されます。ツアーを見るか、または Account Manager アカウントをアプリに追加する手順に直接進みます。
  3. アプリで、Add (追加) をタップしてアカウントを追加します。
    2 単語で構成される一意のフレーズがアプリで生成されます。
  4. SALESFORCE AUTHENTICATOR の接続ウィンドウで、そのフレーズを Two-Word Phrase (2 単語のフレーズ) フィールドに入力します。
  5. Connect (接続) をクリックします。
    以前に検証コードを生成する認証アプリをアカウントに接続している場合は、警告が表示されることがあります。Salesforce Authenticator モバイルアプリの新バージョンを接続すると、古いアプリのコードが無効になります。検証コードが必要な場合は Salesforce Authenticator から取得してください。モバイルデバイスの Salesforce Authenticator アプリに、接続するアカウントの詳細が表示されます。
  6. アカウント接続を完了するには、アプリで Connect (接続) をタップします。

    アカウントのセキュリティを守るため、お使いの Account Manager アカウントに新しい本人確認メソッドが追加されるたびに、Eメール通知が送信されます。

    アプリを接続した後は、本人確認が必要な操作をしようとすると、モバイルデバイスに通知が届きます。通知を受け取ったら、モバイルデバイスのアプリを開き、アクティビティ詳細を確認した上で、モバイルデバイスで返答して検証します。覚えのないアクティビティについて通知を受け取った場合は、アプリを使用してそのアクティビティをブロックします。ブロックしたアクティビティは、アカウント管理者ためにフラグを立てることができます。アプリには、本人確認の代替メソッドとして使用できる検証コードもあります。

アカウントの作成は、アカウント管理者のみが行えます。各アカウントは 1 つ以上の組織に割り当てる必要があります。また、作成できるのは、アカウント管理者がメンバーになっている組織のアカウントのみです。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. User (ユーザー) をクリックします。

    「Users (ユーザー)」ページが開き、組織の全ユーザーの Eメールアドレスのリストが表示されます。

  3. 「ユーザーの追加」をクリックします。

    Eメール検証ページが開きます。

  4. Eメールアドレスを入力してから、Add (追加) をクリックします。
    Account Manager で、指定した Eメールアドレスを使用してアカウントが見つかった場合は、そのユーザーを組織に追加できます。( 「B2C Commerce でのアカウントの組織への追加」を参照してください。)Account Manager でアカウントが見つからない場合は、「Add User (ユーザーの追加)」ページが開き、追加情報を入力するよう求められます。
  5. 「Add User (ユーザーの追加)」ページに、以下のフィールドの値を入力します:
    • 電子メール アドレス。メールプロバイダーがサブアドレス指定をサポートしている場合は、メールアドレスフィールドに「+」を使用できます。
    • 名
    • 姓
  6. (オプション) 次のフィールドに値を入力または選択します:
    • Business Phone (勤務先電話番号)
    • Mobile Phone (携帯電話番号)
    • Home Phone (自宅電話番号)
    • Preferred Language (優先する言語)
  7. 事前に選択されている組織を変更する場合は、Organizations (組織) セクションで、Add (追加) をクリックして、Assign Organizations (組織の割り当て) ウィンドウを開きます。
    1. 組織を検索し、アカウントが所属する各組織のボックスにチェックを付けます (各アカウントは 1 つ以上の組織に割り当てる必要があります)。
    2. ユーザーに組織を適用するには、「追加」をクリックします。
  8. Primary Organization (プライマリ組織) リストから、ユーザーのプライマリ組織を選択します。
    ユーザーのアカウントを管理できるのは、プライマリ組織のアカウント管理者のみです。
  9. 「Roles (役割)」セクションで、Add (追加) をクリックして Assign Roles (役割の割り当て) ウィンドウを開きます。
    ユーザーが Business Manager のインスタンスにアクセスする必要がある場合は、「eCommerce Platform (eコマースプラットフォーム)」セクションの Business Manager User (Business Manager ユーザー) または Business Manager Administrator (Business Manager 管理者) のどちらかを選択します。
    1. 役割を検索し、ユーザーに割り当てる各役割のボックスにチェックを付けます。
    2. ユーザーに役割を割り当てるには、「追加」をクリックします。
      Business Manager User (Business Manager ユーザー) や Business Manager Administrator (Business Manager 管理者) など一部の役割は、特定の Sandbox (サンドボックス) や PIG のインスタンスにアクセスする必要があり、役割の範囲が要求されます。
  10. 役割がインスタンスにアクセスする必要がある場合は、役割の範囲を追加します。
    1. フィルターのアイコンを選択します。
    2. Add Instance Filters (インスタンスフィルターの追加) タブで、組織を選択します。
    3. ユーザーへのアクセスを許可するインスタンスの名前を入力します。
    4. インスタンスを選択します。
    5. 追加をクリックします。
  11. 追加をクリックします。

    ユーザーの Eメールアドレスにメッセージが送信されるので、ユーザーはこのメッセージを使用してアカウントを有効にします。「B2C Commerce アカウントのアクティベート」を参照してください。ユーザーの Eメールアドレスが、ただちにユーザーのリストに表示されます。

    ユーザーに別の役割を割り当てる必要がある場合は、「Users (ユーザー)」タブから役割を変更できます。

B2C Commerce でのアカウントの削除

アカウントを削除できるのはアカウント管理者のみであり、そのアカウントがアカウント管理者の組織に割り当てられている必要があります。アカウント管理者がアカウントを無効にすると、そのユーザーは自分の認証情報を使用してサービスにログインすることができなくなります。アカウントを削除しても、セキュリティ上の理由から、Account Manager は引き続きそのユーザーをデータベースに保存します。

所有している Salesforce Commerce 製品

メモ セキュリティ強化のため、ユーザーがログイン中にそのユーザーのアカウントを削除すると、ユーザーセッションは自動的に無効になります。

アカウントを削除するには:

  1. Account Manager にログインします。
  2. Users (ユーザー) をクリックします。
    「Users (ユーザー)」ページが開き、アカウントのリストが表示されます。
  3. 削除するアカウントのユーザーの横にある[削除 ] をクリックします。
    ダイアログボックスが開き、ユーザーのアカウントの削除を確認するメッセージが表示されます。[ キャンセル ] をクリックすると、削除処理はキャンセルされ、ユーザーのアカウントは削除されません。
  4. OK をクリックします。
    これでアカウントは削除されます。アカウントが Salesforce アカウントにリンクされている場合、Account Manager はそのリンクをキャンセルします。
メモ
  • 180 日を超えて Deleted (削除済み) ステータスにあるユーザーは自動的に除去されます。
  • ログイン後、ユーザー組織が 90 日を超えて[削除済み]状態にある場合、管理者には警告バナーが表示されます。
  • ユーザーリストページで「削除済みユーザーのみ」のフィルターが選択されている場合、削除済みの状態が 90 日を超えているユーザーの横に警告ツールチップが表示されます。ツールチップメッセージには、Account Manager がユーザーをパージするまでの日数が表示されます。
  • ユーザーが自動的に除去される前に、その削除を取り消す。アカウントの削除の取り消しを参照してください。

Account Manager での廃止予定のロールの削除

B2C Commerce のユーザーに廃止予定のロールを割り当てることは避けてください。これらのロールは B2C サービスへのアクセスを提供しなくなり、Salesforce は Account Manager 3.9 (2026 年 6 月) 以降に削除する予定です。廃止予定のロールをユーザーから削除しても、機能やアクセスが失われることはありません。

所有している Salesforce Commerce 製品

Account Manager 3.9 以降、Account Manager では、すべてのユーザーから廃止予定のロールの割り当てが段階的に解除されます。割り当て解除プロセスは数か月にわたってスケジュールされ、その後 Account Manager は役割を完全に削除する予定です。

これらの役割は、以前 Account Manager 1.46.0で廃止予定とアナウンスされていました。Account Manager 3.7 以降、Account Manager では、ユーザーの詳細ページで廃止予定のロールに適切なラベルが付けられます。ユーザーにロールを割り当てるときは、DEPRECATED とマークされているロールは選択しないでください。

  • AppDynamics ユーザ
  • CQuotient Configurator Administrator (CQuotient Configurator 管理者)
    • この役割は Einstein へのアクセスには必要ありません。Einstein のログインに必要なのは Account Manager アカウントだけです。Configurator アプリ自体の権限を制御します。
  • ドキュメンテーション ユーザー
  • Business Manager Partner (Business Manager パートナー)
  • Order Management Admin (Order Management 管理者)
    • この役割は、2022 年 7 月 31 日に廃止されたレガシーの Commerce Cloud Order Management 製品に適用されました。
  • Order Management User (Order Management ユーザー)
    • この役割は、2022 年 7 月 31 日に廃止されたレガシーの Commerce Cloud Order Management 製品に適用されました。
  • Shopper Login and API Access Service (SLAS) 組織管理者 (API クライアント用)
    • このロールは API クライアントにのみ割り当てることができ、ユーザーには割り当てず、追加のアクセス権は付与されません。ユーザーのアクティブなロールである SLAS 組織管理者 は非推奨ではありません。
  • SLAS Trusted Agent Read Only (SLAS 信頼できるエージェントの読み取り専用)
  • SLAS Trusted Agent Read Write (SLAS 信頼できるエージェントの読み取りと書き込み)
  • XChange ユーザー
  • statuspage.io User (statuspage.io ユーザー)

カスタム実装と自動化スクリプトでは、円滑な移行を確実にするために、非推奨のロールの割り当てを事前に削除することをお勧めします。ただし、非推奨のロールの使用状況を監査する必要はありません。

B2C Commerce での組織の編集

アカウント管理者は、組織を編集してパスワードポリシーを指定したり、ユーザーが自分の Account Manager アカウントを Salesforce Platform の組織内の既存のアカウントにリンクできるようにしたり、ユーザーが B2C Commerce B2C アプリケーションにログインする際に ID を検証するために使用できる多要素認証 (MFA) 検証メソッドを指定したりできます。セキュリティを向上させ、不正なアクセスやアカウントへの被害を削減するために、MFA はすべての Account Manager ユーザーに対して必須になっています。

組織を編集するには:

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. Organization (組織) をクリックします。
  3. 編集する組織をクリックします。
    組織情報のページが開きます。
  4. Organization Name (組織名) フィールドで、名前を変更します。
  5. (オプション) ユーザーに連絡します。セキュリティ通知 Eメールを受信するユーザーの選択を参照してください。
  6. (オプション) Password Policy (パスワードポリシー) セクションで、次のフィールドの値を設定します。
    Minimum Password Length (最小パスワード長) パスワードに必要な最小の長さを指定します。一般的に、パスワードが長くなるほど、セキュリティが強くなります。
    Length of Password History (パスワード履歴の長さ) パスワード履歴の長さを指定します。すでに使用されたパスワードは許可されません。パスワード履歴によって、Account Manager が記憶する過去のパスワードの個数が決まります。
    Days Until Password Expires (パスワードの有効期限が切れるまでの日数) パスワードの有効期限が切れてリセットが必要になるまでの保持期間を指定します。
    このパスワードポリシーは、Account Manager のローカルユーザーにのみ適用されます。シングルサインオンユーザーには適用されません。

    Password Policy (パスワードポリシー) の設定に加えて、次のポリシーを適用できます。

    • 最低限の複雑さをもたせるために、次のうちの 3 つを含める必要があります
      • 数字
      • 記号
      • 小文字
      • 大文字
    • ログイン試行の最大失敗回数 (この回数を超えるとアカウントは 30 分間ロックされます): 6
  7. (オプション)非アクティブなユーザーを自動的に無効にします。
    1. Account Manager バージョン 3.1 では、この設定はデフォルトでオンになっています。
    2. ユーザーが無効化されるまでの日数を指定します。デフォルトは 90 日です。
      有効化または無効化の設定、または削除までの日数の設定を変更すると、「連絡先ユーザー」リストに記載されているアドレスに Account Manager から Eメール通知が送信されます。この Eメールは、アカウントが無効になる 10 日前と 1 日前に送信されます。ユーザーは任意の B2C Commerce アプリケーションにログインすることで、アカウントをアクティブに保つことができます。
      メモ 有効にすると、ユーザーは無効または削除済みのステータスになってから 180 日後に自動的に除去されます。B2C Commerce でのアカウントの削除を参照してください。
  8. Salesforce Core 内の組織の My Domain (私のドメイン) サブドメインを指定する必要があります。ID フェデレーション用の Account Manager の構成を参照してください。
    1. 接尾辞を変更するには、ドロップダウンメニューを使用します。
      デフォルトのドメイン接尾辞は my.salesforce.com です。ID フェデレーションが許可または強制されている場合は、値を変更できます。たとえば、Salesforce Core の Sandbox を使用している場合、sandbox.my.salesforce.com をドメイン接尾辞として使用できます。

      サポートされている Salesforce Core ドメイン接尾辞は次のとおりです。

      • my.salesforce.com
      • sandbox.my.salesforce.com
      • develop.my.salesforce.com
      • trailblaze.my.salesforce.com
      • scratch.my.salesforce.com
      • sfdctest.my.salesforce.com
      メモ ユーザーが間違ったパスワードを 6 回入力すると、アカウントは 30 分間ロックされます。Account Manager のユーザーリストでは、アカウントは temporary locked (一時的にロックされています) とマークされます。
  9. MFA Verification Method Settings (MFA 検証メソッドの設定) セクションで、ユーザーが選択可能な多要素認証メソッドを定義します。Salesforce Authenticator、時間ベースの一度限りのパスワード (TOTP) 認証アプリ、または Fast Identity Online (FIDO) U2F/WebAuthn (FIDO2) 互換のセキュリティキー。
  10. 保存をクリックします。

  6. Primary Organization (プライマリ組織) リストで、ユーザーのプライマリ組織を変更します。
  7. Roles (役割) セクションで、Add (追加) をクリックして Assign Roles (役割の割り当て) ウィンドウを開きます。

    1. 役割を検索し、ユーザーに割り当てる各役割のボックスにチェックを付けます。

  8. 役割がインスタンスにアクセスする必要がある場合は、役割の範囲を追加します。ユーザーは、Account Manager のアカウント情報ページで、インスタンスフィルターを含め、割り当てられた役割を確認できます。
    1. フィルターのアイコンを選択します。
    2. Add Instance Filters (インスタンスフィルターの追加) タブで、組織を選択します。
    3. ユーザーへのアクセスを許可するインスタンスの名前を入力します。
    4. インスタンスを選択します。

  • 管理者が Salesforce Identity Management (SFIDM) を使用してユーザーアカウントを作成またはリセットし、ID フェデレーションが許可または強制される場合
  • ユーザーが自分のアカウントを SFIDM にリンクする場合

B2C Commerce での API クライアント ID の有効化と無効化

アカウント管理者は、Account Manager を使用して、API クライアントの有効/無効を切り替えることができます。Open Commerce API には、API クライアントからアクセスする必要があります。API クライアント ID は、Open Commerce API とのインタラクションを行うために使用する URL に付加します。API クライアントは、On-Demand Sandbox API を使用する場合にも必要です。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. API Client (API クライアント) をクリックします。

    API Clients (API クライアント) ページが開き、API クライアントのリストが表示されます。ページには、各クライアントの API クライアント ID、表示名、ステータスが表示されます。

  3. 有効/無効にする API クライアントの ID をクリックします。

    API Client (API クライアント) ページが開きます。

  4. Access Control (アクセス制御) セクションの Enabled (有効) フィールドの値を変更します。ボックスにチェックを付けると API クライアントが有効になり、チェックを外すと API クライアントが無効になります。
  5. 保存をクリックします。

B2C Commerce での B2C Commerce アカウントについての FAQ

B2C Commerce では、統一アカウント管理システムである Account Manager を使用します。このトピックでは、Account Manager を使用してアカウントを設定し、アクセスする際の一般的な質問に回答します。

所有している Salesforce Commerce 製品

質問: Account Manager では多要素認証が必須ですか。

回答: はい。すべての Account Manager ユーザーは B2C Commerce にアクセスするために MFA を使用する必要があります。詳細はこちらを参照してください。

質問: Account Manager はサードパーティーの ID プロバイダーと統合できますか。

回答: Account Manager はサードパーティーの ID プロバイダーと直接統合することはできませんが、Salesforce Identity を使用して SSO/フェデレーションを行うように Account Manager を構成し、Salesforce Identity をサードパーティーの ID プロバイダーと連携するように構成できます。詳細については、こちらをご覧ください。

質問: Account Manager は英語以外の文字に対応していますか。

回答: はい。Account Manager は英語以外の文字に対応しています。ただし、パスワードと Eメールの値には標準の ASCII 文字しか使用できません。その他の数値以外の入力フィールドには、標準の ASCII 文字セット以外の他国語の文字を使用できます。

質問: B2C Commerce Eメールが届きません (または間違って削除してしまいました)。B2C Commerce アカウントにはどのようにアクセスしたらよいでしょうか。

回答: アカウント管理者に連絡し、B2C Commerce 招待 Eメールの再送信をリクエストしてください。アカウント管理者が自分のアカウントにアクセスできない場合は、Salesforce ヘルプでサポートケースを開いてください。

質問: 私のアカウントデータは誰が管理していますか。

回答: アカウントをお持ちの方はどなたでも自分の個人アカウント情報を管理できます。B2C Commerce のお客様またはパートナーの組織には、それぞれにアカウント管理者が割り当てられています。アカウント管理者は、自分の組織に所属する全メンバーのアカウントを管理する役割を担います。役割、許可、メンバーシップを変更する場合は、アカウント管理者に問い合わせてください。アカウント管理者は、自分の組織に新規ユーザーアカウントを追加することもできます。

質問: ログインを何度か試みた後で「Forgot Password (パスワードを忘れた場合)」の操作を行いましたが、パスワードをリセットできませんでした。

回答: ログインの試行回数が多すぎると、アカウントは一時的に 30 分間ロックされます。セキュリティ上の理由により、「Forgot Password (パスワードを忘れた場合)」の操作は、ロックされたアカウントでは無効になります。

質問: Account Manager はサブアドレス指定をサポートしていますか。

回答: はい。Account Manager は、アカウントの Eメールアドレスのサブアドレス指定 (プラスアドレス指定とも呼ばれます) をサポートしています。サブアドレス指定では、+記号とタグ付きのプライマリメールアドレスのバリエーションを使用できます。これらのサブアドレスに送信されたメールは、プライマリメールアドレスに配信されます。Eメールプロバイダーがサブアドレスをサポートしている場合は、Account Manager でそのサブアドレスを使用して、1 つの E メール受信トレイに複数のユーザーアカウントを作成できます。また、サブアドレスに基づいて正確な役割を割り当てることもできます。B2C Commerce でのアカウントの組織への追加を参照してください。

B2C Commerce での Salesforce Identity との ID フェデレーション

ID フェデレーションにより、ユーザーは単一の認証情報セットで複数のアプリケーションやシステムにアクセスできるようになります。Account Manager は ID フェデレーションを使用して、セキュリティとアプリケーションのログインプロセスを向上させます。

所有している Salesforce Commerce 製品

Account Manager で ID フェデレーションを有効にする前に、利用可能なオプションと、フェデレーションユーザー体験に対するそれらのオプションの影響を確認してください。Account Manager の ID フェデレーションによるユーザー管理を参照してください。

Salesforce の [私のドメイン]

Account Manager は、Salesforce の [私のドメイン] を使用して Salesforce 内のユーザーの Org のサブドメインを識別します (Salesforce Identity Management (SFIDM))。組織の Salesforce の [私のドメイン] が複数の Account Manager 組織で使用されている場合、ユーザーは SSO プロセス中に自分の Account Manager 組織を選択します。これはアカウントのリンクに必要な 1 回限りの選択です。[私のドメイン] を検証するには、ユーザーの Account Manager と Salesforce Org の Eメールアドレスが一致する必要があります。[私のドメイン] を検証し、ジャストインタイムユーザプロビジョニングを使用するには、ユーザは Salesforce の [私のドメイン] にログインし、Salesforce Identity またはサードパーティの Identity and Access Management (IAM) で認証を行います。Account Manager とサードパーティ IAM の ID フェデレーションは、Salesforce Identity を通じて行われます。Account Manager は、サードパーティ IAM と直接連携はしません。

Account Manager の有効化とユーザーのアカウントリンクは、アカウントの設定方法によって異なります。

  • リンクされていないユーザーアカウント ― アカウントを SFIDM にリンクする際、ユーザーの主要な組織の [私のドメイン] が、SFIDM での SSO に使用したものと一致することが検証されます。
  • 既存のアカウント ― [私のドメイン] の検証は必要ありませんが、ユーザーの主要な組織の [私のドメイン] は、SFIDM による SSO に使用されたものと一致している必要があります。
  • ジャストインタイムユーザープロビジョニング ― Salesforce の [私のドメイン] は、ジャストインタイムユーザープロビジョニング中に検証されます。
  • B2C Commerce での ID フェデレーション用の Account Manager の構成
    ID フェデレーションにより、ユーザーは単一の認証情報セットで複数のアプリケーションやシステムにアクセスできるようになります。ID フェデレーションと Salesforce の [私のドメイン] を組み合わせると、ユーザーは Salesforce ID またはサードパーティの ID とアクセス管理 (IAM) の認証情報を Account Manager にリンクできます。
  • B2C Commerce での Account Manager と Salesforce 間の連携のアクティブ化
    ID フェデレーションを有効にした後に、Account Manager を Salesforce Org にリンクします。
  • B2C Commerce での Salesforce Org への Account Manager のインストール
    ID フェデレーションを使用する Salesforce Org を構成します。

FAQ と ID フェデレーションのトラブルシューティング

B2C Commerce のフェデレーションの識別に関するよくある質問に対する回答を示します。

所有している Salesforce Commerce 製品

さまざまなSSOおよびIDフェデレーションシナリオのログインフローの詳細はどこで確認できますか?

Salesforce Identity を使用したログインフローの詳細な概要については、「Account Manager ワークフロー」を参照してください。

コア組織で Account Manager が接続アプリケーションとして表示されないのはなぜですか?

コア組織で Account Manager が接続アプリケーションとして表示されない場合は、アカウントを一度リンクします。この最初の試行は成功しませんが、必要なプロセスがトリガーされます。この後、Account Manager が Salesforce Core 組織に接続アプリケーションとして表示され、インストールを続行できます。

ユーザーが複数の組織に割り当てられている場合はどうなりますか?

複数の組織に割り当てられている場合、認証に Salesforce Identity と Account Manager のどちらを使用するかは、プライマリ組織の設定によって決まります。

Salesforce Identity を有効にした後も、Account Manager でユーザーを作成する必要がありますか。

Account Manager でジャストインタイムユーザープロビジョニングが構成されている場合、Account Manager でユーザーを作成する必要はありません。それ以外の場合は、Account Manager でユーザーを作成する必要があります。詳細については、ジャストインタイムユーザープロビジョニング。

Salesforce のユーザーアカウントのメールアドレスが Account Manager のユーザーアカウントと異なる場合はどうなりますか。

Account Manager アカウントを Salesforce アカウントにリンクすると、Account Manager のユーザー名が Salesforce アカウントの Eメールアドレスと一致するように更新されます。

Salesforce Identity からユーザーのリンクを解除できますか?

Account Manager UI のユーザーリストページで、Salesforce Identity からユーザーのリンクを解除します。ユーザーテーブルでリセットリンクをクリックすると、アカウントのリンクが解除され、アクティベーションメールがユーザーに送信されます。

Salesforce Identity を再度オフにするとどうなりますか?

Account Manager でユーザーをリセットします。Account Manager 管理者は、ユーザーのアカウントをリセットします。ユーザーアカウントがリセットされると、アカウントを再アクティベートする手順が記載されたアクティベーションメールがユーザーに送信されます。有効化すると、ユーザーは Account Manager に直接ログインします。

AM 組織の設定で ID フェデレーションの強制があり、顧客 ID プロバイダー (IDP) (Ping など) がダウンしている場合、B2C Commerce にログインする際にどのように強制から無効に切り替えることができますか。

AM 組織の設定で ID フェデレーションの強制があり、顧客 IDP (Ping など) がダウンしている場合、強制から無効に切り替えるには 2 つのオプションがあります。

  1. この組織へのアクセス管理ロールを持つ招待されたユーザーは、プライマリ組織が影響を受ける IDP を使用していない限り、設定を変更できます。
  2. または、Salesforce サポートに連絡して ID フェデレーションの設定を変更することもできます。

    切り替え後、すべてのユーザーをリセットして、アカウントを新しい設定にリンクするか、Account Manager の認証情報を使用してログインできるようにします。

Salesforce Identity でユーザーのメールアドレスが変更されるとどうなりますか?

この変更は、次回のログイン時に Account Manager にも反映されます。これにより、両方のシステムが正しい電子メールアドレスで同期されたままになります。

「Salesforce の [私のドメイン] のサブドメイン名」を変更できますか?

はい。「Salesforce の [私のドメイン] のサブドメイン名」は変更できますが、Salesforce Identity 統合のリセットが必要です。手順は次のとおりです。

  1. 組織の ID フェデレーションを無効にします。
  2. ページを保存します。
  3. Salesforce Identity フェデレーションを再度有効にします。
  4. 新しい「Salesforce の [私のドメイン] のサブドメイン名」を設定します。
  5. ユーザーをリセットして、アカウントを新しいサブドメインにリンクするか、Account Manager 認証情報でログインします。

アカウントを Salesforce Identity にリンクした後で、WebDav、カートリッジアップロード、パイプラインデバッガ、スクリプトデバッガ、保護されたストアフロントにアクセスできないのはなぜですか。

WebDav、カートリッジアップロード、パイプラインデバッガー、スクリプトデバッガー、または保護されたストアフロントは、SSO/フェデレーションをサポートしていません。これらの外部クライアントは、ログインの代わりにアクセスキーを使用できます。アクセスキーは 1 年で有効期限が切れます。6 回誤って入力すると、その認証範囲でそのアクセスキーを使用することはできません。API キーは Business Manager によって生成され、その特定の Business Manager インスタンスに対してのみ有効です。アカウントを Salesforce Identity にリンクした後、Business Manager でアクセスキーを生成します。ユーザープロフィール | アクセスキーの管理 | アクセスキーの生成の順に選択します。詳細については、Business Manager でアクセスキーを生成します。

これらのアクセスキーは、WebDav、カートリッジアップロード、パイプラインデバッガー、スクリプトデバッガー、または保護されたストアフロントにアクセスするためのパスワードとして使用します。「WebDAV ファイル、UX Studio エージェント、ユーザーログイン、Open Commerce API (OCAPI)、および保護されたストアフロントアクセスでのアクセスキーの使用」を参照してください

B2C Commerce での Salesforce Org への Account Manager のインストール

ID フェデレーションを使用する Salesforce Org を構成します。

所有している Salesforce Commerce 製品

  1. Salesforce Org にログインし、設定 | アプリケーション | 接続アプリケーション | 接続アプリケーションの OAuth の利用状況の順に選択します。
  2. 接続アプリケーションのリストから、B2C Commerce Account Manager を見つけて、[インストール ] をクリックします。
    Account Manager が接続アプリケーションとしてリストされていない場合、Account Manager は構成されていません。ID フェデレーション用の Account Manager の構成を参照してください。

  3. ポリシーを編集をクリックします。
  4. IP 緩和については、IP 制限を緩和を選択し、変更を保存します。

  6. [私のドメイン] の詳細で、[私のドメイン] の名前に設定されている値を確認します。この値は、Account Manager の設定を構成するときに使用します。

B2C Commerce でのアカウントの組織への追加

アカウント管理者は、ユーザーアカウントを組織に追加できます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. User (ユーザー) をクリックします。

    「Users (ユーザー)」ページが開き、アカウントのリストが表示されます。

  3. 「ユーザーの追加」をクリックします。
    Eメール検証ページが開きます。
  4. Email Address (Eメールアドレス) フィールドに、組織に追加するアカウントの Eメールアドレスを入力します。メールプロバイダーがサブアドレス指定をサポートしている場合は、メールアドレスに + 記号を付けたサブアドレスを入力できます。サブアドレス指定は、メールアドレスのバリエーションを 1 つの受信トレイに転送します。たとえば、開発などの特定の機能のユーザー アカウントを作成する場合は、username+development@sample.com などのサブアドレスを入力できます。サブアドレスを使用すると、きめ細かなレベルで役割を管理できます。B2C Commerce でのパートナーアカウントのアクセスの管理を参照してください。
  5. 追加をクリックします。

    Account Manager でアカウントが見つからない場合は、「Add User (ユーザーの追加)」ページが開き、アカウントを作成できます (「ユーザーアカウントの作成」を参照)。Account Manager でアカウントが見つかった場合は、Add (追加) をクリックして、アカウントを組織に追加します。

    ユーザーアカウントが別の組織のものである場合 (パートナーアカウントの場合など)、追加されたアカウントは、組織のユーザーリストの Invited Users (招待されたユーザー) の下に表示されます。組織のメンバーシップについて通知するメッセージがユーザーの Eメールアドレスに送信されます。

    ユーザーアカウントが組織に追加された後は、さまざまな B2C Commerce アプリケーションへのアカウントのアクセスを管理できます。

Account Manager と B2C Commerce のジャストインタイムユーザープロビジョニング

ジャストインタイムユーザープロビジョニングを使用すると、Account Manager でのユーザーアカウント作成が自動化されるため、管理者がユーザーを手動で追加する手間を省けます。また、このプロビジョニングによって、ユーザーアカウントはシングルサインオン (SSO) に使用される Salesforce Identity のアカウントにリンクされます。

所有している Salesforce Commerce 製品

ジャストインタイムユーザープロビジョニングでは、ID フェデレーションを [Allowed (許可)] または [Enforce (強制)] に設定する必要があります。加えて、ユーザーは Salesforce の [私のドメイン] を確認する必要があります。ジャストインタイムユーザープロビジョニングは、Salesforce Identity を使用したサードパーティの Identity and Access Management (IAM) でサポートされています。このためには、Salesforce Identity もジャストインタイムプロビジョニング用に構成されている必要があります。

ユーザーが自動的にプロビジョニングされた後で、管理者は役割を割り当てることができます。デフォルトでは、役割はジャストインタイムユーザープロビジョニングの一部として割り当てられません。

その他の参照項目:

  • B2C Commerce での ID フェデレーション用の Account Manager の構成
  • Security Assertion Markup Language (SAML) のジャストインタイムプロビジョニング

B2C Commerce での Account Manager アカウントの Salesforce Identity (SSO) へのリンク

組織の設定によっては、Account Manager アカウントを Salesforce Identity で管理されている Salesforce アカウントにリンクできます。組織がこの機能を有効にすると、Account Manager にログインしたときに、Account Manager アカウントを Salesforce アカウントにリンクできます。アカウントのリンクを解除する場合は、アカウント管理者に問い合わせてください。

所有している Salesforce Commerce 製品

  1. Web ブラウザーで https://account.demandware.com/ を開きます。
  2. ユーザー名 (Eメールアドレス) を入力します。
  3. LOG IN (ログイン) をクリックします。
    メモ 組織の構成の一部として Identity Federation with Salesforce Identity (Salesforce Identity との ID フェデレーション) が[Enforced (強制 )] に設定されている場合は、パスワードを入力するために Salesforce Identity にリダイレクトされます。
  4. パスワードを入力します。
  5. LOG IN (ログイン) をクリックします。
  6. (オプション) 組織の設定によっては、多要素認証 (MFA) を使用して本人確認を行うことが必要になる場合があります。すでに MFA 検証メソッドを登録してある場合は、そのメソッドを指定してログインを完了します。メソッドをまだ登録していない場合は、ログインする前にメソッドを登録するように求められます。
  7. LINK WITH A SALESFORCE ACCOUNT (Salesforce アカウントとリンク) をクリックします。
    Salesforce にリダイレクトされます。Salesforce に正常にログインしたら、Account Manager に戻ります。
    警告 Account Manager アカウントを Salesforce アカウントにリンクすると、Account Manager のユーザー名が Salesforce アカウントの Eメールアドレスに変更される場合があります。確認ページに新しいユーザー名が表示されます。Account Manager のユーザー名を変更したくない場合は、この手順をキャンセルし、アカウント管理者に問い合わせてください。
  8. CONFIRM (確認) をクリックしてアカウントのリンクを完了するか、CANCEL (キャンセル) をクリックしてこの手順をキャンセルします。
メモ 組織の構成により、Identity Federation with Salesforce Identity (Salesforce Identity との ID フェデレーション) が Allowed (許可) に設定されている場合は:
  • 新規ユーザーは、MFA を使用して Account Manager にログインし、Account Manager アカウントを Salesforce Identity にリンクする必要があります。詳細については、多要素認証の検証メソッドの登録を参照してください。
  • ユーザーがリセットまたは削除された場合、そのユーザーの Account Manager と Salesforce Identity 間のリンクは削除されます。ユーザーが再度アクティブになった場合、または復元された場合は、MFA を使用して Account Manager にログインし、Salesforce Identity へのリンクを復元する必要があります。
Identity Federation with Salesforce Identity (Salesforce Identity との ID フェデレーション) が Enforced (強制) に設定されている場合は、Account Manager アカウントを Salesforce Identity にリンクにする際に Account Manager で MFA を使用する必要はありません。

Account Manager 監査ログイベント

Log Center は、ユーザー、API クライアント、組織への変更を含む、Account Manager の監査ログイベントを発行します。フィルターとキーワード検索を使用して、選択した期間内の特定のフィールドの変更またはアクションイベントを追跡します。

監査イベントは Log Center で 90 日間使用でき、その後は自動的に削除されます。

メモ 監査ログは、2026 年 9 月 23 日リリースまで、以前の Account Manager の場所でも使用できます。履歴データを保持するには、その日付より前に Account Manager ログをダウンロードします。

はじめに

監査イベントへのアクセスは、役割によって異なります。

  • Log Center 外部管理者の役割 :所属する組織全体のすべての監査イベントを表示します。
  • その他のすべてのユーザー :自分がターゲットまたはアクターであるイベントを含む、自分のアカウントに関連する監査イベントを表示します。

監査イベントからリンクされたエンティティの詳細を表示するには、Account Manager のアカウント管理者または読み取り専用アカウント管理者の役割も必要です。

Account Manager 監査ログイベントへのアクセス

メモ Account Manager 監査ログイベントは、南北アメリカ (AMER) リージョンでのみ使用できます。イベントタブにAccount Manager 監査が表示されない場合は、Log Center の右上隅にあるリージョンセレクタを確認し、AMERを選択します。

Account Manager の監査ログイベントページに直接アクセスするには、Account Manager でLog Center に移動リンクを選択します。または、ブラウザーまたは Business Manager から以下の手順に従います。

  1. ブラウザーまたは Business Manager から Log Center を開きます。詳細については、Log Center の表示を参照してください。
  2. 右上隅で、リージョンが[AMER]に設定されていることを確認します。そうでない場合は、領域セレクターからAMERを選択します。
  3. 「イベント」タブから「Account Manager 監査」を選択します。

キー項目の理解

ターゲット ID

ターゲット ID は、変更された Account Manager エンティティを識別します。ターゲットには、ユーザー、API クライアント、または組織を指定できます。

セキュリティ上の理由から、Log Center には ID のみが表示され、Eメールアドレスは表示されません。表示されたリンクを選択すると、Account Manager で詳細が表示されます。

Actor ID

アクター ID は、アクションを実行したエンティティを識別します。アクターは、ユーザーまたは API クライアントです。表示されたリンクを選択すると、Account Manager で詳細が表示されます。

SystemUserは、スケジュールされたプロセスやシステムによってトリガーされる更新など、ユーザーが直接介入せずに発生する自動化されたバックグラウンド アクションを表す特別なアクターです。

組織のコンテキスト

組織名でフィルタリングして、その組織に属するエンティティへの変更と、組織自体への変更を表示します。このフィルターは、複数の組織の管理者である場合に最も便利です。

イベントアトリビューション

  • ユーザーの変更 :ユーザーに対する変更は、変更がどの組織コンテキストで行われたかにかかわらず、ユーザーのプライマリ組織に起因します。
  • API クライアントの変更 :API クライアントが関係する変更は、API クライアントが属する各組織に起因します。API クライアントが複数の組織に属している場合、同じイベントが複数の組織の監査ログに表示されることがあります。

監査イベントのフィルター

フィルター 用途
ターゲット・タイプ エンティティタイプ(ユーザー、API クライアント、または組織)でフィルタリングします。
Actor Type アクターの種類 (ユーザーまたは API クライアント) でフィルター処理します。
イベントの種類 作成、更新、削除、ロールの割り当てなどのアクションの種類でフィルター処理します。
役割の割り当て 役割の割り当てまたは役割テナントのフィルター変更に関与する役割でフィルター処理します。
所属組織 メンバーシップの変更に関与する組織でフィルターします。

テナントでフィルタリングしたり、イベントメッセージ内のテキストを検索したりするには、キーワード検索バーを使用します。専用のテナント フィルターはないため、テナント レベルのクエリにはキーワード検索が推奨されるアプローチです。

ユーザーの役割の変更を監査する

特定の組織内のユーザーのすべての役割の割り当てを追跡するには、次のようにします。

  1. 組織名でフィルタリングし、組織を選択します。
  2. ターゲット・タイプでフィルタし、「ユーザー」を選択します。
  3. [ロールの割り当て ] でフィルター処理し、追跡するロールを選択します。

結果には、選択したロールに割り当てられた、または選択したロールから削除されたすべてのユーザーが表示されます。

特定の API クライアントによって実行されたアクションを確認するには:

  1. アクター IDでフィルター処理し、API クライアント ID を選択します。
  2. 必要に応じて、組織名でフィルタリングして、結果の範囲を特定の組織に絞り込みます。

「イベント・タイプ」フィルターを確認して、実行されたアクションを確認します。

組織レベルの変更を監査する

組織の設定への変更を監視するには:

  1. ターゲット・タイプでフィルタし、「組織」を選択します。
  2. 組織名でフィルタリングし、組織を選択します。

結果には、組織の構成に対するすべての変更が表示されます。

特定のテナントのイベントを検索する

キーワードまたはフィールド値で検索

  1. ページの上部にある[LCQL ] を選択します。
  2. フィールドを選択し、検索する値を括弧内に入力します。
  3. ロール名には、Account Manager の役割のドキュメントに記載されている各ロール名を入力します。
  4. さらにフィールド条件を追加するには、スペースを入力し、「AND」または「OR」を選択してから、次のフィールドを選択します。
  5. [ 検索]を選択します。

B2C Commerce での Account Manager へのログイン

Account Manager では、シングルサインオン (SSO) 用のリンクまたはユーザー名でのログインという 2 つのログインオプションを用意しています。

所有している Salesforce Commerce 製品

  1. (オプション) シングルサインオン (SSO) 用のリンクを使用して Account Manager にログインします。
    1. Web ブラウザーで https://account.demandware.com/ を開きます。
    2. Link for Single Sign-on (シングルサインオン用のリンク) をクリックします。
      ログインするために Salesforce にリダイレクトされます。Salesforce に正常にログインすると、リダイレクトされて Account Manager に戻ります。この時点ですでに Account Manager にログインしており、追加の操作は必要ありません。

      メモ 複数の Salesforce アカウントにログインしている場合は、Account Manager アカウントがリンクされている正しいユーザー名を選択してください。リストにご自分のユーザー名が表示されない場合は、「Log in with Different Username」(別のユーザー名でログイン) を選択し、表示される手順に従います。
    3. Use Custom Domain (カスタムドメインを使用) をクリックし、使用する Salesforce のドメインを入力します。
    4. 認証に使用する ID プロバイダーを選択します。たとえば、Okta などです。
  2. (オプション) ユーザー名を使用して Account Manager にログインする場合は、以下の手順に従います。
    1. Web ブラウザーで https://account.demandware.com/ を開きます。
    2. ユーザー名 (Eメールアドレス) を入力し、LOG IN (ログイン) をクリックします。
    3. パスワードを入力し、LOG IN (ログイン) をクリックします。
    4. 多要素認証 (MFA) を使用して本人確認を行います。
      すでに MFA 検証メソッドを登録してある場合は、そのメソッドを指定してログインを完了します。メソッドをまだ登録していない場合は、ログインする前にメソッドを登録するように求められます。サービスの問題で MFA を使用できない場合は、登録済みの認証アプリから時間ベースのワンタイムパスワード (TOTP) を使用してログインできます。ユーザー名(メールアドレス)を入力すると、ログイン画面に登録済みの認証アプリが表示されます。アプリを選択し、TOTP を入力します。MFA が停止している間は、新しい認証器を登録できません。このフォールバックオプションを使用するには、TOTP をサポートする認証アプリを少なくとも 1 つ登録しておく必要があります。
  3. (オプション) SSO を使用するように設定されているものの、ユーザー名でログインしたい場合は、以下の手順に従います。
    1. Web ブラウザーで https://account.demandware.com/ を開きます。
    2. ユーザー名 (Eメールアドレス) を入力し、LOG IN (ログイン) をクリックします。
    3. 認証に使用する ID プロバイダーを選択します。たとえば、Okta などです。
    4. 資格情報を入力してログインします。

Account Manager セキュリティ通知メールを受信する連絡先ユーザーの選択

B2C Commerce Account Manager の変更に関するセキュリティ Eメールアラートを受信する連絡先ユーザーを最大 5 人選択します。

所有している Salesforce Commerce 製品

  1. Account Manager で、Organization (組織) をクリックし、組織を選択します。
  2. 「Contact Users (連絡先ユーザー)」フィールドに、ユーザーを最大 5 人追加します。
    ユーザーは、あなたの組織をプライマリ組織として設定している必要があります。組織からユーザーを削除すると、そのユーザーは連絡先リストからも削除されます。
  3. 変更内容を保存します。

連絡先ユーザを設定すると、次のいずれかのイベントが発生すると、そのユーザに電子メール通知が届きます。

  • ユーザーの招待と削除
    • 管理者権限を持つユーザーが組織に招待されます。
    • メモ これらのロールは管理ロールと見なされ、ユーザーイベントに基づいて通知メールをトリガーします。
      • Account Administrator (アカウント管理者)
      • API Administrator (API 管理者)
      • ユーザー管理者
      • グローバルアクセス管理者
      • 読み取り専用アカウント管理者 (Account Manager 3.6 以降)
    • 管理者権限を持つユーザーは、組織から招待解除 (削除) されます。
    • 招待されたユーザーには管理者権限が割り当てられ、自動的に招待が取り消されます (通常、共有パートナー アカウントの競合が原因です)。
    • 招待されたユーザーには管理者権限が割り当てられ、自動的に招待が解除されることはありません (例外の場合)。
      メモ 共有の管理者権限をもつパートナーアカウントはあなたの組織で管理者権限を保持するため、あなたの組織から自動的に削除されます。この削除に対する唯一の例外は、パートナーアカウントがあなたの組織の管理者でもある場合です。ユーザーが削除されたかどうかにかかわらず、セキュリティ連絡先は Eメールを受信します。削除したユーザーに対しては新しいアカウントを作成することをお勧めします。
  • APIとシステムアクセス
    • 管理者権限をもつ API クライアントが組織に割り当てられます。
  • 設定と構成
    • 重要な組織設定が変更された場合。たとえば、ジャストインタイムユーザープロビジョニングや非アクティブなユーザー設定などです。

B2C Commerce でのパートナーアカウントのアクセスの管理

アカウント管理者は、Account Manager を使用して、管理者の組織 (パートナーアカウントなど) に招待されたユーザーアカウントのアクセスを管理できます。招待されたアカウントがどの B2C Commerce アプリケーションにアクセスできるかを制御できます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. User (ユーザー) をクリックします。

    「Users (ユーザー)」ページが開き、アカウントのリストが表示されます。

  3. 「招待されたユーザー」フィールドで、アクセスを管理するアカウントの Eメールアドレスまたはサブアドレスをクリックします。アカウントにアカウント管理者の役割があるが、組織内でそのアカウントにアカウント管理者のアクセス権を付与したくない場合は、サブアドレスに基づいて新しいアカウントを作成します。次に、より限定された役割をそのアカウントに割り当てます。B2C Commerce でのアカウントの組織への追加を参照してください。
    「組織」セクションで、組織へのアカウントのアクセスを取り消すには、ゴミ箱アイコンをクリックします。Roles (役割) セクションで、組織の Sandbox (サンドボックス) または PIG のインスタンスへのアカウントのアクセスを管理できます。
  4. Roles (役割) セクションで、Add (追加) をクリックして Assign Roles (役割の割り当て) ウィンドウを開きます。
  5. Assign Roles (役割の割り当て) ウィンドウで役割を検索し、アカウントからアクセスできるようにする各役割を選択します。
  6. Add (追加) をクリックします。
  7. インスタンスへのアクセスが必要なすべての役割について、役割の範囲を指定します。
    1. フィルターのアイコンを選択します。
    2. Add Instance Filters (インスタンスフィルターの追加) タブで、組織を選択します。
    3. ユーザーへのアクセスを許可するインスタンスの名前を入力します。
    4. インスタンスを選択します。
    5. 追加をクリックします。

B2C Commerce アカウントのパージ (完全な削除)

アカウントをパージ (完全に削除) できるのはアカウント管理者のみです。なお、当該アカウントはアカウント管理者の組織に割り当てられている必要があります。アカウントをパージすると、そのユーザーレコードは Account Manager のデータベースから削除されます。

所有している Salesforce Commerce 製品

メモ パージされたアカウントは復元できません。

パージする前に、パージするアカウントが削除済みになっていることを確認してください。削除済みのアカウントのみパージ可能です。

アカウントを削除するには:

  1. Account Manager にログインします。
  2. Users (ユーザー) をクリックします。
    「Users (ユーザー)」ページが開き、アカウントのリストが表示されます。
  3. Filter by status (ステータスで絞り込み) を Deleted Users only (削除されたユーザーのみ) に設定します。
  4. パージするアカウントユーザーの横にある Purge (パージ) をクリックします。
    ダイアログボックスが開き、ユーザーアカウントのパージを確認するメッセージが表示されます。[キャンセル ] をクリックすると、パージ処理はキャンセルされ、ユーザーのアカウントはパージされません。
  5. 「パージ」をクリックします。
    これでアカウントはパージされ、復元できなくなります。
メモ ユーザーがパージされた後に同じログインユーザー名でユーザーを復元する場合は、次のいずれかのオプションを実行します。ユーザーが Business Manager にログインする際に問題が発生するため、両方のオプションを実行することはしないでください。
  • オプション 1: ユーザーは必ず Business Manager で削除してください。
  • オプション 2: 管理者に依頼して、Account Manager でユーザーを再作成し、Business Manager ユーザープロフィールでユーザーの汎用一意識別子 (UUID) を更新するよう依頼します。Business Manager のユーザープロフィールを更新する手順は次のとおりです。
    1. Business Manager で管理 | 組織 | ユーザーの順に選択します。
    2. ユーザーを選択します。
    3. ユーザーの Account Manager ユーザー ID を見つけて、Account Manager の [User Details」(ユーザーの詳細) ページにあるユーザー ID と比較します。値が一致する必要があります。
    4. 必要に応じて、Account Manager の値と一致するように Business Manager の値を更新します。

Account Manager からの API クライアントのパージ

B2C Commerce Account Manager 管理者は、7 日以上無効ステータスに設定されている API クライアントをパージできます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. API Client (API クライアント) をクリックします。
  3. API クライアントをパージします。
    1. 「アクション」列で、「パージ」をクリックします。
      削除オプションを使用できない場合は、API クライアントを無効にします。7 日間の待機期間を考慮して、再試行してください。「B2C Commerce での API クライアント ID の有効化と無効化」を参照してください。

B2C Commerce での WebAuthn 本人確認用のセキュリティキーの登録

多要素認証 (MFA) ログインの検証メソッドとして、Fast Identity Online (FIDO) U2F または WebAuthn (FIDO2) と互換性のあるセキュリティキーを登録します。自分の身元を検証するには、コンピューターやモバイルデバイスの適切なポートにセキュリティキーを挿入して検証を完了します。同じセキュリティキーを複数のサービスプロバイダー、および複数の Salesforce Org とアカウントに登録できます。また、アカウントごとにキーを 1 つ登録できます。

所有している Salesforce Commerce 製品

セキュリティキーを手元に置き、指示が表示されたときにすぐに挿入できるようにしておきます。時間がかかりすぎると、登録の試行がタイムアウトします。

  1. 組織の MFA 検証メソッド設定に応じて、以下の手順を使用できます:
    • 次回のログイン時にセキュリティキーの接続が要求され、これが許可されている唯一の検証メソッドタイプである場合: 次のステップに進みます。
    • 次回のログイン時にセキュリティキーの接続または別の検証メソッドが要求される場合: Security Key (セキュリティキー) をクリックして次のステップに進みます。
    • Account Manager にログインする際に、複数の MFA 検証メソッドの登録が可能である場合は、「Account Information (アカウント情報)」でセキュリティキーを接続します。Multi-Factor Verification (多要素検証) の横にある Add (追加) をクリックし、Security Key (セキュリティキー) を選択してから、次のステップに進みます。
  2. プロンプトが表示されたら、コンピューターまたはモバイルデバイスの適切なポートにセキュリティキーを挿入します。ボタンがある場合は、ボタンをタッチします。
    デバイスを起動するためにタッチを必要とするボタンが付いているセキュリティキーもありますが、セキュリティキーは生体認証デバイスではありません。
  3. Continue (続行) をクリックして確認メッセージを閉じます。

    これで、この本人確認メソッドを使用する準備が整いました。必要な認証情報がセキュリティキーによって生成され、ブラウザーによって、その情報が Salesforce に渡されて、検証が完了します。アカウントのセキュリティを守るため、お使いの Account Manager アカウントに新しい本人確認メソッドが追加されるたびに、Eメール通知が送信されます。

B2C Commerce での多要素認証の検証メソッドの登録

多要素認証 (MFA) は、単一のパスワードによる保護を超える追加の保護レイヤーです。

所有している Salesforce Commerce 製品

MFA では、2 つ以上の証拠 (要素) を提供して、実際に登録しているユーザーであることを証明します。最初の要素は、ユーザー名とパスワードの組み合わせ (自分が知っている情報) です。追加の要素は、認証アプリやセキュリティキーなど、自分が所有している検証メソッドです。MFA はすべての Account Manager ユーザーに要求され、オフにすることはできません。最初にログインする際に、MFA の検証メソッドを登録するように求められます。登録プロセスでは、選択したメソッドを Account Manager アカウントに接続します。ログインするたびに、登録した検証メソッドを指定する必要があります。Account Manager のアカウント情報から、追加のメソッドをいつでも登録できます。

メモ 主要なメソッドを忘れてしまった場合や紛失した場合にバックアップがあるように、複数のメソッドを登録することを強くお勧めします。異なるタイプのメソッド (Salesforce Authenticator とセキュリティキーなど) や、同じメソッドタイプの 2 つのインスタンス (2 つのセキュリティキーや、2 つの異なるサードパーティの時間ベースのワンタイムパスワード (TOTP) 認証アプリなど) を登録します。
  • B2C Commerce での本人確認を目的とした Salesforce Authenticator (バージョン 3 以降) のアカウントへの接続
    Salesforce Authenticator モバイルアプリは、多要素認証 (MFA) ログインのための素早く簡単な検証メソッドです。アプリを登録して Account Manager アカウントに接続します。Salesforce Authenticator では、自分のモバイルデバイスに送信されたプッシュ通知を受信して承認するには、セキュリティ PIN と Face ID を使用してモバイルデバイスをセキュリティ保護する必要があります。
  • B2C Commerce での TOTP 認証アプリによる本人確認
    Microsoft Authenticator や Google Authenticator などのサードパーティ認証アプリを、多要素認証 (MFA) ログインの検証メソッドとして登録します。このアプリは、時間ベースの一度限りのパスワード (TOTP) と呼ばれる検証コードを生成します。
  • B2C Commerce での WebAuthn 本人確認用のセキュリティキーの登録
    多要素認証 (MFA) ログインの検証メソッドとして、Fast Identity Online (FIDO) U2F または WebAuthn (FIDO2) と互換性のあるセキュリティキーを登録します。自分の身元を検証するには、コンピューターやモバイルデバイスの適切なポートにセキュリティキーを挿入して検証を完了します。同じセキュリティキーを複数のサービスプロバイダー、および複数の Salesforce Org とアカウントに登録できます。また、アカウントごとにキーを 1 つ登録できます。

B2C Commerce での多要素認証の検証メソッドの削除

多要素認証 (MFA) 検証メソッドを置き換える場合は、登録済みの検証メソッドを Account Manager アカウントから削除できます。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. Account Information (アカウント情報) をクリックします。
  3. Multi-Factor Verification (多要素検証) の下で、削除するメソッドの横にあるゴミ箱アイコンをクリックします。
    メソッドの削除を確認するメッセージが表示されます。
  4. Remove (削除) をクリックします。
    メモ 検証メソッドを紛失した際に、登録済みのバックアップのメソッドがない場合は、アカウント管理者に連絡してアカウントへのアクセスを復元してください。

B2C Commerce でのパスワードを忘れた場合のリセット

パスワードを忘れてしまった場合はリセットできます。ただし、この手順は、アカウントを正常にアクティベートした場合にのみ使用できます。既存のパスワードの有効期限が切れている場合でも、新しいパスワードを定義します。パスワードの有効期限が切れた後は、新しいパスワードの設定を 6 回まで試みることができます。その後は、アカウントが一時的にロックされます。有効期限が切れているパスワードで正常にログインしたら、ただちにパスワードをリセットしてください。

所有している Salesforce Commerce 製品

この手順は、Account Manager アカウントが Salesforce Identity アカウントにリンクされていない場合にのみ使用できます。

  1. Web ブラウザーで https://account.demandware.com/ を開きます。
  2. ユーザー名 (Eメールアドレス) を入力します。
  3. LOG IN (ログイン) をクリックします。
  4. [ Forgot Password? (パスワードを忘れましたか? )] リンクをクリックします。

    「Forgot Your Password? (パスワードを忘れましたか?)」ページが開きます。

  5. Email Address (Eメールアドレス) フィールドに、Eメールアドレスを入力します。
  6. 送信をクリックします。

    ユーザーの Eメールアドレスにメッセージが送信されます。メッセージにはアクティベーションコードが含まれており、パスワードのリセットに使用できます。「Forgot Your Password? (パスワードを忘れましたか?)」ページには、「Code (コード)」フィールドもあり、アクティベーションコードを入力できます。

  7. Eメールアカウントにアクセスし、Eメールメッセージを開き、アクティベーションコードをコピーします。
  8. 「Code (コード)」フィールドに、Eメールからコピーしたアクティベーションコードを貼り付けます。
  9. [ Submit Code ] をクリックします。
  10. New Password (新しいパスワード) フィールドに、新しいパスワードを入力します。
    パスワードの要件:
    • 12 文字以上。一部の組織ではその他の要件を設定しています。
    • 以下の文字を 3 種類以上使用してください。大文字 (A から Z)、小文字 (a から z)、数字 (0 から 9)、および記号 (!、#、$ など)
    • 名前やユーザー名の一部を含まない
    • 以前の 4 つのパスワードのいずれも再利用できません

    文字を入力すると、パスワードのセキュリティ強度が表示されます。

  11. Confirm Password (パスワードの確認入力) フィールドに、新しいパスワードを再度入力します。
  12. 「パスワードの変更」をクリックします。

    2 通目のメッセージ (パスワードが変更されたという内容) がユーザーの Eメールアドレスに届きます。このメッセージの目的は、アクティベーションが正常に完了したことを確認する、または別の人がパスワードを変更しようとしたことを警告することです。別の人がパスワードを変更しようとした場合は、アカウント管理者またはヘルプデスクまで連絡してください。
