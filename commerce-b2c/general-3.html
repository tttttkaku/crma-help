B2C Commerce での Cookie の SameSite 属性の変更のサポート

Google Chrome などの多くのブラウザーベンダーは、SameSite=Lax という新しいデフォルトの Cookie 属性設定を導入しました。以前には SameSite Cookie 属性のデフォルトは SameSite=None でした。SameSite が None に設定されている場合、Cookie には暗号化された HTTPS 接続が必要であることを示す Secure 属性が必要です。このトピックは、B2C Commerce に該当します。

新しい Cookie の動作で自分のストアフロントが確実に機能するように、次の作業を行います。

  • Business Manager のグローバルセキュリティ環境設定で「HTTPS を強制する」を有効にします。
  • クライアント側の JavaScript コードで、Cookie 属性の変更に対応するためにコードの調整が必要でないかどうかを判定します。
  • クロスサイトのシナリオをテストして、サードパーティの統合が Cookie 属性の変更後も予期したとおりに機能することを確認します。

HTTPS の強制の有効化

新しい Cookie 設定がアクティブになった後に Cookie が期待どおりに動作するように、変更を実装しました。グローバルセキュリティ環境設定の「HTTPS を強制する」を有効にして、サーバーが Secure 属性で Cookie をマークし、SameSite=None を指定できるようにします。「HTTPS を強制する」を有効にしないと、サーバーで SameSite 属性は指定されません。この場合、ブラウザーは独自のデフォルト SiteSame 設定を使用し、クロスサイトコンテキストで Cookie の送信に失敗する可能性があります。Cookie の重要性によっては、送信しないことでサイトの重要な機能が動作しないことがあります。

グローバルセキュリティ環境設定「HTTPS を強制する」を有効にするには、Business Manager でアプリケーションランチャーをクリックし、管理 | グローバル環境設定 | セキュリティの順に選択します。アクセス制限タブで、HTTPS を強制するを選択して、適用をクリックします。

重要

グローバルセキュリティ環境設定の「HTTPS を強制する」の有効化サイト環境設定として「HTTPS を強制する」を有効にしても、必要な機能は有効になりません。HTTPS をグローバルに、またはサイトごとに強制した場合の影響については、B2C Commerce での HTTPS の強制を参照してください。

HTTPS の強制は、Production (本番) インスタンスで変更を行う前に、Production (本番) 以外のインスタンスでテストすることをお勧めします。

クライアント側コードのテスト

カスタムのクライアント側の JavaScript を使用してCookie を設定する場合は、テストを行って、Cookie 属性の変更に対応するためにコードの調整が必要かどうかを判定します。

クロスサイトシナリオのテスト

クロスサイトシナリオとは、サイトのユーザーがブラウザーを使用して、異なるドメイン名のサイトとコンテンツをやり取るする場合を指します。一般的なクロスサイトシナリオは、以下の場合に SameSite Cookie 属性の影響を受けます。

  • 別のサイトのコンテンツが iframe に表示される。
  • 自分のサイトが POST リクエストを使用してユーザーを別のサイトに導いている。
  • ブラウザーが XMLHttpRequests (XHR) を使用して別のサイトからコンテンツを取得する。他のサイトが Cookie に依存して応答をパーソナル化している。

Chrome を使用してテストする場合は、作成されてから 2 分間未満の Cookie で SameSite 属性が設定されていない場合、クロスサイト POST リクエストで SameSite=None がデフォルトになることに注意してください。この機能をオフにするには、コマンドラインからフラグ--enable-features=SameSiteDefaultMethodRigorouslyを使用して Chrome を実行します。詳細については、SameSite の更新を参照してください。

Firefox ブラウザーでテストするには、about:config 環境設定で、次の両方の環境設定を true に設定します:

  • network.cookie.sameSite.laxByDefault
  • network.cookie.sameSite.noneRequiresSecure

Page Designer ページのコピー

Page Designer ページのコピーを作成できます。コピーしたページは元のページと同じページ設定とコンテンツをもち、ページ ID だけが異なります。既存のページをコピーすると、毎回ゼロからページを作成する必要がなくなるため、効率が向上します。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce

Page Designer ビジュアルエディターを使用してページを作成および管理するには、組織のコンテキストで機能の許可Manage_All_Libraries、またはページを作成する対象のサイトのコンテキストでManage_Site_Libraryする機能の許可がユーザーの役割に含まれています。

重要 コピーしたページの名前は、元のページの名前の末尾に 10 桁のタイムスタンプを追加したものになります。ページ名は 100 文字を超えることはできません。コピーしたページの名前は、タイムスタンプが追加されることで、100 文字を超える場合があります。この場合は、元のページの名前の末尾が切り取られ、10 桁のタイムスタンプが追加されます。
  1. ビジュアルエディターから、コピーするページの横にあるドロップダウンメニューをクリックします。
  2. 複製を選択します。
    ページのリストで元のページのすぐ下ににページの新しいコピーが表示されます。
  3. コピーしたページを編集するには、ページを複製した際に画面の上に表示される通知メッセージをクリックします。
    また、ページ名の横にあるドロップダウンメニューから編集を選択することもできます。
  4. 説明や ID nadonoページ設定を更新するには、ページ設定アイコンをクリックします。

B2C Commerce での 1 つまたは複数のカテゴリのコピー

カテゴリをコピーして、同じ商品のセットを使用して、または使用せずに、複数のカタログ、およびカタログ内の複数のカテゴリに割り当てます。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーをクリックし、次にマーチャントツール | サイト | 商品とカタログの順に選択します。
  2. カタログページで、コピーしたいカテゴリが含まれているカタログ ID をクリックします。
  3. コピーするカテゴリを選択し、コピーをクリックします。
  4. コピー後のカテゴリに含めたいオプションを選択します。
  5. ドロップダウンリストで、コピーしたカテゴリの割り当て先のカタログを選択します。
  6. カテゴリツリーで、コピーしたカテゴリの追加先のカテゴリを選択します。コピーしたカテゴリは、選択したカテゴリのサブカテゴリとして追加されます。変更を適用する前に、リストされているカタログとカテゴリの割り当てを確認します。とカテゴリの割り当てを行ってから変更を適用してください。
  7. カテゴリのカタログへの割り当てが完了したら、OKをクリックします。

B2C Commerce の分類ルールセットの作成

分類ルールセットは、商品の整理と分類に使用される一連の条件のことです。これらの条件は、特定の属性、演算子、値に基づいて商品をフィルタリングおよび分離し、適切なカテゴリに自動的に割り当てます。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | 商品とカタログ | カタログの順に選択します。
  2. ID をクリックしてカタログに移動します。
  3. カテゴリに移動し、編集をクリックします。
  4. 分類ルールタブを開きます。
  5. 新規をクリックします。
  6. ルールセットの初期パラメータを設定します。
    1. 地域情報の選択ドロップダウンから地域情報を選択するか、またはデフォルトのままにしておきます。
    2. サイトのコンテキストの選択ドロップダウンから、商品を割り当てるサイトを選択します。
    3. カテゴリを、ルールセットによって割り当てられた商品の分類カテゴリまたは主要カテゴリとして指定します。分類カテゴリと主要カテゴリのを参照してください。
  7. ルールセットを作成します。
    1. ルールの追加をクリックします。
    2. ルールの属性を選択します。
    3. ルールセットのロジックを構成するには、演算子を選択します。B2C Commerce のルールベースの分類を参照してください。
    4. 選択した属性に関連する値を設定します。
    5. 別のルールをセットに追加するには、条件の追加をクリックします。

      各ルールセットには、最大 5 つの条件を設定できます。デフォルトでは、ルールセット内のすべての条件で AND が使用されます。

    6. 別のルールセットを追加するには、ルールの追加をクリックします

      デフォルトでは、特定のカテゴリのすべてのルールセットで「または」が使用されます。

    7. 変更内容を保存します。
  8. ルールセットのプレビューと実行:
    1. ルールセットをプレビューするには、プレビューをクリックします。
    2. ルールセットを手動で実行するには、実行をクリックします。

    ルールセットが一括ジョブとして実行されるように構成されている場合は、一括ジョブが実行された後で結果を確認します。

Log Center アラートの作成

状態を監視し、通知を送信します。動作の異常を早期にキャッチしたり、ログ配信パイプラインが失敗したときに通知を受け取ったり、特定のインシデントのアラートを作成したりできます。

  1. Log Center の [Alerts] (アラート) タブで、[ Alert Management] (アラート管理 ) に移動します。
  2. [ アラートの作成 ] をクリックします。
  3. アラートモードを選択します。[New Alert]、[Saved Search]、[Log Streaming]、または [Anomaly Detector ] を選択し、情報を入力します。
    最大 50 個のアラートを作成できます。通知は、アラート作成者のメールアドレスに自動的にメールで送信されます。アラートごとに最大 5 人のメール受信者を追加できます。
    新しいアラートを作成する場合は、アラートを適用するレルムを選択します。ユーザーは、アラートの作成者に関係なく、レルムへのアクセス権があればアラートを表示できます。アラートに適用されるレルムを変更する必要がある場合は、アラートを削除して新しいアラートを作成します。
    ログストリーミングアラートを作成している場合、ログストリームの編集権限リスト内のすべてのユーザーがアラートを編集または削除できます。
  4. 作成をクリックします。

インシデント発生時にチームの足並みを揃えるために、Slack や PagerDuty のチャンネルを設定できます。

Log Center アラート用の PagerDuty チャネルの作成

オンコールエスカレーションとインシデント管理のために、B2C Commerce で PagerDuty 通知を設定します。B2C Commerce の Log Center 通知を PagerDuty にルーティングすると、アラートの状態のライフサイクルが特定の PagerDuty のアクションと重大度にマッピングされます。各アラート モニターは一意の重複排除キーを使用するため、トリガーを繰り返すと、重複するインシデントが作成されるのではなく、既存のオープン インシデントが更新されます。

  1. PagerDutyを設定します。
    1. 「サービス」から、ターゲット・サービスを選択します。
    1. [統合] を選択します。
    1. Events API v2を追加します。
    1. インテグレーションキーをコピーします。
  2. Log Center で通知チャネルを作成します。
    1. [アラート] タブで、[ 通知チャネル ] に移動します。
  3. 「チャンネルを作成」をクリックします。
  4. [タイプ] で [PagerDuty]を選択します。
  5. 該当するレルムを選択するか、フィールドを空のままにして、管理者とサポートの役割にのみ表示されるチャネルを作成します。
  6. ルーティングキーを入力します。
    PagerDuty エンドポイントは自動的に構成されます。
  7. 「チャンネルを作成」をクリックします。

Log Center 通知用の Slack チャンネルの作成

インシデント発生時にチームの足並みを揃えるには、B2C Commerce で Slack 通知を設定します。

  1. Slack ワークスペースで、受信 Webhook を作成し、URL をコピーします。「受信 Webhook を使用したメッセージの送信」を参照してください。
  2. Log Center の [Alerts] (アラート) タブで、[ Notification Channels] (通知チャネル ) に移動します。
  3. 「チャンネルを作成」をクリックします。
  4. [タイプ] で[Slack ] を選択します。
  5. 該当するレルムを選択するか、フィールドを空のままにして、管理者とサポートの役割にのみ表示されるチャネルを作成します。
  6. Webhook URL を入力します。「チャンネルを作成」をクリックします。

    並べ替えルールを定義して、カテゴリでの検索結果の表示順序をコントロールします。並べ替えルールを開発する際には、顧客が探している商品をすばやく見つけることができるようなストアフロント戦略を採用するのが最適です。このトピックは、B2C Commerce に該当します。
  • B2C Commerce のページのメタタグルール
    ページのメタタグは、HTML ドキュメントで使用され、Web ページに関する構造化されたデータを提供します。一般的なタグとしては、タイトル、ロボット、説明、Open Graph のタグなどのソーシャルタグがあります。このトピックは、B2C Commerce に該当します。

ブーストルールとベリールールの作成

検索用語、カテゴリ、またはサイト全体のコンテキストに一致する商品をブーストまたは埋めるルールを作成します。

必要なエディション

使用可能なソリューション: B2C Commerce

まず、ブーストルールとベリールールの属性の準備でセットアップ手順を完了します。

  1. Business Manager でアプリケーションランチャーをクリックし、マーチャントツール | サイト名 | 商品とカタログ | ビジュアルマーチャンダイジングの順に選択します。
  2. ルールを適用する検索またはカテゴリのコンテキストを開きます。
  3. 新規ルールをクリックします。
  4. ルール名を入力し、商品属性や ID などのターゲット条件と限定子を構成します。
    サイト全体の動作のために、限定子を空白のままにします。
  5. ルールの条件を定義します。
    ルールごとに最大 10 個の条件を入力します。
  6. 「ブースト」または「ベリー」を選択し、0 から 100 までの係数値を設定します。
    値が大きいほど、ランキングの調整が強くなります。この係数は、他の商品と比較して、商品が検索結果でどの程度積極的に移動するかを決定します。因子が大きいほど影響が強く、因子が小さいほど微妙な調整が適用されます。ブーストとベリーのルールの仕組みの詳細については、B2C Commerce のブーストとベリーのルールを参照してください。
  7. [ 適用 ] をクリックしてルールを保存します。
    ビジュアルマーチャンダイジングのプレビューが更新され、一致する商品のランキングへの影響が表示されます。

Page Designer ビジュアルエディターを使用したページの作成

ページ作成ウィザードでは、ビジュアルエディターで Page Designer ページを作成するための手順をガイドします。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce

Page Designerビジュアルエディターを使用してページを作成および管理するために、ユーザーの役割には組織のコンテキストで機能的な許可Manage_All_Librariesが含まれます。または、ページを作成する対象のサイトのコンテキストでユーザーの役割に Manage_Site_Library を含めることもできます。

  1. アプリケーションランチャーをクリックし、次にマーチャントツール | サイト | コンテンツ | Page Designerの順に選択します。
  2. 新規をクリックします。
  3. ページレイアウトを選択します。
  4. 必要であれば、このページの使用方法を指定します。
    たとえば、商品一覧ページと商品詳細ページに適用する動的レイアウトを使用している場合は、作成するページの種類を選択します。
  5. 商品一覧または商品詳細のテンプレートページを作成する場合は、ページに割り当てるカテゴリを選択します。
    ページにカテゴリを割り当てると、サブカテゴリの割り当てを明示的に変更しない限り、すべてのサブカテゴリは暗黙的に同じページに割り当てられます。カテゴリは 1 つの商品一覧ページのみと 1 つの商品詳細ページのみに割り当てることができます。ページの作成時にカテゴリの割り当てを省略して、後からページ設定でカテゴリの割り当てまたは変更を行うこともできます。商品一覧ページまたは商品詳細ページのテンプレートの作成の詳細については、Page Designer の商品一覧ページまたは商品詳細ページのテンプレートの作成を参照してください。
  6. ページ言語を選択します。
    ベストプラクティスは、基本言語 (一般的にはデフォルト) で作成することです。Page Designer によって、Business Manager で定義されているフォールバック階層に、各地域情報のページのバリエーションが追加されます。次に、ページバリアントを使用し、必要に応じてコンポーネントを各地域情報用にローカライズします。ローカライズされていないコンポーネントは、Business Manager に定義されているフォールバック階層に従って表示されます。
  7. ページの名前と ID を入力します。
  8. (オプション) ページの説明を入力します。
  9. 入力した情報を確認します。
    変更を行うには、変更する情報の横にある編集をクリックします。
  10. すべての情報を正しく入力したら、保存して作成をクリックします。
    ビジュアルエディターに新しいページが表示されます。一部の動的ページでは、レンダリングするカテゴリや商品に基づいて情報が表示されます。通常は、ページに割り当てられている最初のカテゴリからの情報が表示されます。ページにカテゴリまたは商品が表示されない場合、または別のカテゴリや商品を表示するには、ページの上部でプレビュー設定アイコンをクリックします。動的属性でカテゴリを選択するか、商品 SKU を入力して、適用をクリックします。選択したカテゴリまたは商品固有の画像とテキストがページに表示されます。
  11. ページにコンポーネントを追加するには、アイコンをクリックしてコンポーネントメニューを開きます。
    デベロッパーによって領域にデフォルトのコンポーネントが割り当てられている場合は、これらのコンポーネントがページに読み込まれます。デフォルトのコンポーネントを変更または削除します。また、一度に10 個までのコンポーネントをコピーして、複数のページに貼り付けることができます (ターゲットの領域またはコンポーネントがコンポーネントを受け入れる場合)。
  12. コンポーネントタイプを選択して、ページの領域にドラッグします。
    コンポーネントがページに追加されますが、属性は構成されません。
  13. 右側のペインで、コンポーネント属性を構成します。
    リッチテキストエディターを使用する際には、Heading1、Heading2、Heading3、Heading4、および Paragraph のタグを使用してテキストの書式を設定できます。ストアフロントにページが表示されると、テキストの書式設定はブラウザーの CSS のスタイルに対応します。テキストを編集するために大きなウィンドウを開くには、アイコンをクリックします。
    一部のコンポーネントは、デフォルトでレンダリングするカテゴリや商品を使用して表示するコンテンツを決定する、動的属性をもっています。ページに渡されたカテゴリや商品を上書きするには、ページに割り当てられた値の横にある編集をクリックします。別のカテゴリを選択します。
    コンポーネントはコンテンツアセットのバインドをサポートします。コンテンツを直接入力する代わりに、コンポーネントの属性をコンテンツアセット属性にバインドするには、コンテンツアセットの選択をクリックします。詳細については、コンテンツアセットへのコンポーネント属性のバインドを参照してください。
  14. コンポーネントがどの顧客にいつ表示されるかを指定するには、右側のパネルのコンポーネント名の横にあるドロップダウンメニューをクリックします。
    表示を制御することによって、領域に複数のコンポーネントを追加できます。
    1. コンポーネントを特定の顧客グループに表示するには、顧客グループを選択します。
    2. コンポーネントを表示する日時を指定するには、スケジュールをクリックします。
    3. コンポーネントを表示する対象の顧客グループと日時を選択して、適用をクリックします。
      時刻はサイトのタイムゾーンに対応します。
  15. 保存をクリックします。
  16. ページの各領域に 1 つまたは複数のコンポーネントを追加します。
    一部のコンポーネントは領域をもち、この領域にもコンポーネントを追加することが必要です。
  17. さまざまなソースコードや動的属性で、特定の日時に特定の顧客にページがどのように表示されるかを確認するには、表示アイコンをクリックします。設定を調整して、プレビューをクリックします。
  18. 異なるデバイスでページがどのように表示されるかを確認するには、ビューポートアイコンをクリックします。
  19. プレビューのサイズを調整するには、編集アイコンをクリックし、幅と高さをピクセル数で入力します。
    使用している画面サイズより大きいピクセル数を入力した場合、幅と高さが正しくスケーリングされないことがあります。サイズにカスタムの値を入力した場合、コンポーネントをページ上に正しく配置できないことがあります。ピクセル値を自動で計算するには、編集アイコンを再度クリックします。
  20. 縦表示と横表示を切り替えるには、回転アイコンをクリックします。
  21. ページの表示内容に満足したら、公開をクリックしてページをオンラインにします。

顧客グループまたはスケジュールに基づく Page Designer ページの表示の指定

特定の顧客または特定の日時にのみ表示されるように Page Designer ページを構成します。ページをキャンペーンまたはプロモーションの一部とするようにターゲット設定した場合は、この機能は使用できません。この場合は、キャンペーンまたはプロモーションを割り当てていれば、それによって顧客グループとスケジュールが決まります。また、顧客グループを作成して、特定の地域や地域情報を含めたり除外したりします。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. ビジュアルエディターからページを開きます。
  2. ページ設定アイコンをクリックします。
  3. ターゲット設定をクリックします。
  4. ページを表示する対象の顧客グループ、日時、あるいはその両方を選択します。
    時刻はサイトのタイムゾーンに対応します。
  5. 保存をクリックします。

B2C Commerce での代替パスを使用した 404 エラーページの作成

顧客が有効期限の切れたページにリンクしていたり、URL が壊れていたために 404 エラーに遭遇した場合でも、サイトのホームページにたどり着けるように、エラーページを作成します。

必要なエディション

使用可能なソリューション: B2C Commerce

代替パスは、ランディングページやプロモーションページを削除した場合に非常に便利です。404 エラーページを用意して、顧客を新しいページに移動したり、プロモーションが終了したことを知らせることができます。

Business Manager内に、アプリケーションサーバーがダウンした場合、または時間内に応答しない場合に使用されるすべてのエラーページを含むテンプレート.zipファイルをダウンロードします。この zip ファイルをダウンロードしてから、ページをカスタマイズし、再圧縮してアップロードします。

  1. 管理 | サイトの開発 | カスタムエラーページの順に選択します。
  2. ダウンロードをクリックします。
  3. ダウンロードしたエラーページを解凍してカスタマイズします。
  4. 管理 | サイトの開発 | カスタムエラーページの順に選択します。
  5. 参照をクリックして、カスタマイズしたエラーページの zip ファイルに移動します。アップロードした.zipファイルに errorpages.zip という名前を付けます。myCustomErrorPages.zip といった名前は使用しないでください。アップロードを終えると、zip ファイルは自動的に解凍されて、コンテンツが Web サーバーに保存されます。
  6. アップロードをクリックします。
  7. カスタマイズしたエラーページをテストするには、無効な URL を入力して 404 エラーを起こすか、アプリケーションサーバーを停止して転送エラーを引き起こします。
メモ これは自動アップロードではありません。ファイルが Web アダプターと同期されるまで、最長 2 時間かかる場合があります。

B2C Commerce でのライブラリフォルダーの作成

Business Manager を使用して、コンテンツアセットフォルダーの階層構造を定義または編集します。

必要なエディション

使用可能なソリューション: B2C Commerce

ライブラリフォルダーのページには、サイトライブラリに存在するサブフォルダーが表示されます。サイトライブラリは、非公開ライブラリまたは共有ライブラリのいずれかです。

メモ ライブラリフォルダーから、並べ替えられたコンテンツアセットのリストを含むページを作成します。この場合は、ライブラリフォルダーページで取得できるViewContentList-Listの並べ替えられたアセットのリストを使用します。この並べ替えられたリストは、プロジェクトでコンテンツ領域を作成するときにも役立ちます。
  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | コンテンツ | ライブラリの順に選択します。ライブラリのリンクをクリックします。

    薄く表示されているフィールドがある場合は、読み取り専用許可が付与されています。ライブラリを参照し、コンテンツアセットを検索し、コンテンツアセットデータを読み込みます。ただし、これらのモジュールのデータを変更することはできません。異なる役割を通じて 1 つのモジュールに複数の許可が与えられている場合は、最も高いレベルのアクセスが付与されます。書き込みアクセスが必要な場合は、管理者に連絡してください。

    ライブラリ、ライブラリフォルダー、およびコンテンツアセットは、階層状に整理されています。この階層によって、ライブラリ、ライブラリフォルダー、コンテンツアセットの読み取りまたは書き込みのアクセスをもつ役割には同じレベルのアクセスが必要であることが規定されます。

  2. ライブラリフォルダーのページで、新規またはライブラリフォルダーの編集リンクをクリックします。
  3. 全般タブで情報を入力または編集して、適用をクリックします。
    コンテンツアセットがコンテンツ検索の一部として返されると、ライブラリフォルダー (またはそのサブフォルダー) 内のすべてのコンテンツアセットのカスタム CSS ファイルが読み込まれます。
  4. コンテンツ属性グループタブで、ライブラリフォルダーにバインドされているすべてのアセットに対してコンテンツ属性を定義します。
    たとえば、この機能を使用して、一部のサイトによる使用から一部のコンテンツアセットを除外します。カスタムオブジェクトタイプの作成を参照してください。
  5. 検索絞り込み定義タブで、検索の絞り込みを指定します。
  6. ページのメタタグルールタブで、ページのメタタグを作成および管理します。
  7. リストに戻るをクリックして、ライブラリフォルダーのページに戻ります。
  8. サブフォルダーを作成するには:
    1. サブフォルダーを作成したいフォルダーの ID リンクをクリックします。
    2. ライブラリフォルダーセクションにある新規をクリックします。
    3. 新規ライブラリフォルダーのページで、新規フォルダーの定義を指定して適用をクリックします。
    4. ライブラリフォルダーのページで、<< リストに戻るをクリックして、新規サブフォルダーがリストされている上位フォルダーのページを表示します。

    すべてのフォルダーにコンテンツアセットを含めることができます。コンテンツアセットは、複数のフォルダーまたはサブフォルダーで体系化することができます。

B2C Commerce での共有ライブラリの作成

ライブラリの作成と削除、またはライブラリの割り当ての変更は、Staging (ステージング) インスタンスと Sandbox (サンドボックス) インスタンスでのみ行えます。

必要なエディション

使用可能なソリューション: B2C Commerce

共有ライブラリを作成および削除するには、適切な許可が必要です。コンテンツライブラリの許可 セクションを参照してください。この機能は Development (開発) インスタンスと Production (本番) インスタンスでは使用できません。Staging (ステージング) インスタンスでライブラリを変更した場合は、データレプリケーションを使用して Development (開発) インスタンスまたは Production (本番) インスタンスに変更を転送できます。

  1. アプリケーションランチャーをクリックし、管理 | サイト | コンテンツライブラリの順に選択します。

    薄く表示されているフィールドがある場合は、読み取り専用許可が付与されています。ライブラリを閲覧し、コンテンツアセットを検索し、コンテンツアセットデータを読み込むことができます。ただし、これらのモジュールのデータを変更することはできません。異なる役割を通じて 1 つのモジュールに複数の許可が与えられている場合は、最も高いレベルのアクセスが付与されます。書き込みアクセスが必要な場合は、管理者に連絡してください。

    ライブラリ、ライブラリフォルダー、およびコンテンツアセットは、階層状に整理されています。この階層によって、ライブラリ、ライブラリフォルダー、コンテンツアセットの読み取りまたは書き込みのアクセスをもつ役割には同じレベルのアクセスが必要であることが規定されます。

  2. ライブラリページで、新規またはライブラリの編集リンクをクリックします。
  3. ライブラリページの全般タブで、情報を入力または編集して適用をクリックします。
    共有ライブラリとサイトには、同じ ID を使用しないでください。同じ ID を使用すると、予想外のエラーが発生します。

ライブラリページの全般タブに、サイトの割り当てセクションが再表示されたら、ライブラリにサイトを割り当てることができます。

B2C Commerce でのゾーンの作成

CDN 構成は、ゾーンを使用して整理されています。ゾーンはルートドメイン、または Apex ドメイン (例: example.com) を表します。ホスト名は特定のゾーンのサブドメインです (例: www.example.com)。

必要なエディション

使用可能なソリューション: B2C Commerce

Salesforce B2C Commerce ではお客様のすべてのレルムで、Development (開発)、Staging (ステージング)、Production (本番) インスタンスのすべてのホスト名エイリアスファイルが確認されます。B2C Commerce はこの情報を集約し、エイリアスファイルのホスト名エントリからゾーン名を導き出します。

メモ 埋め込み CDN 設定は各インスタンス (Development (開発)、Staging (ステージング)、Production (本番)) に固有なもので、インスタンスごとに個別に管理します。

たとえば、Production (本番) インスタンスのホスト名エイリアスファイルに www.example.com のエントリが含まれる場合、B2C Commerce によってゾーン example.com が作成されます。

メモ

作成したゾーンは、ユーザーインターフェイスで削除することはできません。ゾーンを削除するには、Salesforce サポートにお問い合わせください。

ゾーンを作成する前に、DNS プロバイダーでドメイン名を登録します。たとえば、ゾーン example.comを作成する前にドメインwww.example.comを登録します。

B2C Commerce がプロキシゾーンを作成して検証するまで最高 24 時間かかることがあります。

  1. Business Manager で、アプリケーションランチャーをクリックし、管理 | サイト | 埋め込み CDN 設定の順に選択します。
  2. ホスト名の追加をクリックします。
    埋め込み CDN 設定ページには、デフォルトゾーンと既存のホスト名が表示されます。
  3. リスト内の追加したいホスト名ごとにゾーンの追加をクリックします。
    ゾーンを作成および構成し、ゾーンのステータスを検証済みに設定すると、B2C Commerce で自動的にホスト名が追加されます。

  4. 新しいゾーンを作成する場合は、ゾーンの作成中に「ステータスの更新」リンクを使用して個々のゾーンのステータスを更新します。ホスト名検証のステータスを確認するには、構成の検証をクリックします。この検証には最大で 24 時間かかります。
    メモ 次に、eCDN ゾーンに SSL 証明書を追加します。eCDN ゾーンへの SSL 証明書の追加と DNS マッピングの構成を参照してください。
  5. ゾーンが検証され、証明書がアクティブになったら、バニティホスト名が eCDN ホスト名を直接指すように DNS CNAME を更新します。
    CNAME をdx.commercecloud.salesforce.comにポイントしないでください。eCDN ゾーンのホスト名を直接ポイントします。
  6. ゾーンのセキュリティルール、Web アプリケーション ファイアウォール (WAF)、分析、ホスト ヘッダーの上書きルール、およびページ シールド ポリシーを管理するには、[ ゾーンの構成 ] をクリックし、ドロップダウンからゾーンを選択します。
    重要 標準の本番インスタンスとは異なり、On-Demand Sandboxes (ODS) ゾーン (開発ODSと本番を含む) には、デフォルトの [すべてブロック] ファイアウォール規則はありません。Salesforce では、ゾーンの作成後に少なくとも 1 つのカスタムルールを追加することを推奨しています。まず、AI クローラーをブロックするルールを追加して、Sandbox での不要な自動トラフィックを防止します。

ODSバニティ・ドメインの移行

ODS でバニティホスト名 (CNAME からdx.commercecloud.salesforce.com ) を使用する場合は、26.7 のロールアウトの前に、以下の該当するシナリオに従ってください。

前提条件 (開始する前に):

  • ゾーンを作成する前に、DNS プロバイダーにドメイン名を登録します。たとえば、ゾーン example.comを作成する前に www.example.com を登録する必要があります。
  • ODS レルムが eCDN 用にプロビジョニングされていることを確認します。Business Manager で、埋め込み CDN 設定にレルムがデフォルトゾーンを使用したプロビジョニングと表示されていることを確認します。
  • バニティホスト名がインスタンス (Development (開発)、Staging (ステージング)、または Production (本番) ) のホスト名エイリアスファイルにリストされていることを確認します。B2C Commerce は、これらのエイリアスファイルからゾーン名を導き出します。

シナリオ 1:入力トランスポート層セキュリティ(TLS)ターミネーションを備えたバニティ ホスト名(26.5 パイロット カスタマーのみ):

ODS のセルフサービス・バニティ・ホスト名の完全なサポートは、26.7 リリースを予定しています。26.5 パイロットのお客様は、暫定的な手動パスを利用できます。Salesforce サポートに連絡して、eCDN チームの関与を調整してください。

シナリオ 2 — バニティ ホスト名 CNAMEd を dx.commercecloud.salesforce.com (証明書ODSなし):

Salesforce は、この状態のホスト名のインベントリと移行パスを確定していません。バニティホスト名に、ODSインフラストラクチャを介した既存のLet's Encrypt証明書があることを確認します。そうでない場合 (シナリオ 3)、この移行パスは使用できません。Salesforce サポートにお問い合わせください。

重要な注意事項:

  • eCDN 設定はインスタンスごとです。Dev、Staging (ステージング)、Production (本番) の各インスタンスを個別に管理します。各インスタンスタイプのゾーンを個別に作成および検証します。
  • ゾーンの削除には Salesforce サポートが必要です。ゾーンは、いったん作成すると UI から削除することはできません。
  • ゾーンの作成の検証には最大で 24 時間かかることがあります。
  • ゾーンの作成を成功させるには、ODS レルムで eCDN が有効になっている必要があります。Storefront Fast Setup ジョブでCDN-API default-domain/hostnames call failed (CDN-API のデフォルトドメイン/ホスト名の呼び出しに失敗しました ) と表示される場合は、レルムがまだプロビジョニングされていません。Salesforce サポートに問い合わせてください。

必要なエディション

使用可能なソリューション: B2C Commerce

  • 環境設定グループの定義

カスタマイズした機能をシステムに実装する際に高い柔軟性を実現する 1 つの方法として、特定の機能やプロパティを構成可能にすることができます。こういった機能では、将来要件が変化した場合に、システムの機能を簡単に調整することができます。

カスタム環境設定を作成して、設定を構成可能にします。グローバルカスタム環境設定は、OrganizationPreference システムオブジェクトのコンテキストで定義します。

メモ グローバルカスタム環境設定を構成するには、書き込み許可が必要です。読み取り専用 権限では、設定を表示できますが、変更はできません。この変更は、B2C Commerce API 呼び出しを経由する変更にも該当します。
メモ 環境設定とグループのリストが、システムオブジェクト定義で構成した順番に表示されます。

      以下の値を入力または選択します。

      • ID: processingDays
      • 表示名: カスタム環境設定の例
      • ヘルプテキスト: これは注文の処理日数です
      • 値タイプ: 文字列の列挙
    4. 適用をクリックします。
    5. 次に、以下を選択します。
      • 必須: フィールドが選択されているか、テキストが含まれています。

      • 複数選択: (文字列の列挙のみに適用。)ユーザーは、リストの要素として表示される選択肢から複数を選択できます。複数の要素を選択するには、Windows のCtrlキーやMac の Commandキーなどの標準キーボード要素が必要です。
        メモ カスタマイズ可能なオプションは、以前に選択した値タイプによって異なります。
    6. 適用をクリックします。
    7. 以下の値 | 表示値の定義を入力して、各エントリの後に適用をクリックします。
      • 5 | orderProcessing (これをデフォルトにします)
      • 6 | shipDays
      • 11 | totalDays

    1. 属性グループ化タブをクリックし、<< 戻るをクリックします。

      名前: totalProcessTime

    2. グローバルカスタム環境設定のページでインスタンスタイプを選択します。
    3. 環境設定の値を選択します。
    4. 適用をクリックします。

B2C Commerce の Page Designer

Page Designer は B2C Commerce の機能で、再利用可能なページタイプとコンポーネントタイプを作成するための、標準的な開発プロセスとツールをサポートしています。マーチャントは Business Manager のビジュアルエディターを使用し、ページタイプやコンポーネントタイプをドラッグすることで、ストアフロントのカスタムページをデザイン、スケジュール、公開できます。

マーチャントは、デベロッパーに更新を依頼する必要なしに、同じページタイプやコンポーネントタイプを使用してさまざまなページを独自に作成できます。一般的な Page Designer の実装プロセスには、以下のステップが含まれます。

  • eコマースマーケティングディレクターがデベロッパーと協力して、ストアフロントで必要なページ、コンポーネント、レイアウト、アセットについて話し合います。
  • デベロッパーが、eコマースマーケティングディレクターの要件をサポートする再利用可能なページタイプとコンポーネントタイプを作成します。
  • デベロッパーが、これらのページタイプとコンポーネントタイプを含むカスタムカートリッジと、サポートのための UI アーチファクトを含む別のカスタムカートリッジをサイトにアップロードします。
  • マーチャントが Business Manager の Page Designer ビジュアルエディターを使用し、デベロッパーが実装したページタイプとコンポーネントタイプを使用して、ストアフロントページを作成します。

Page Designer はコンテンツアセットのデータバインディングもサポートしており、コンポーネントがコンテンツアセットからコンテンツを動的に取り込むことができます。つまり、同じコンテンツを複数のページで再利用し、1 か所から更新することができます。詳細については、コンテンツアセットへのコンポーネントのバインドを参照してください。

  • Page Designer ビジュアルエディターを使用したページの作成
    ページ作成ウィザードでは、ビジュアルエディターで Page Designer ページを作成するための手順をガイドします。このトピックは、B2C Commerce に該当します。

    以下のヒントは顧客のフィードバックから集められたもので、ビジュアルエディターを使用して Page Designer ページを作成する場合に知っておくと便利です。このトピックは、B2C Commerce に該当します。

    商品一覧ページまたは商品詳細ページのテンプレートを作成して、複数のカテゴリや商品で再利用します。使用したい構造とコンポーネントを使用してテンプレートページを作成し、そのページを 1 つまたは複数のカテゴリに割り当てます。ストアフロントで商品一覧ページまたは商品詳細ページが必要な場合は、カテゴリに割り当てられたテンプレートページが表示され、適切な商品情報が読み込まれます。このトピックは、B2C Commerce に該当します。

マスターカタログの CSV ファイル

B2C Commerce Business Manager では、XML 形式および CSV 形式によるカタログのインポートとエクスポートがサポートされています。読みやすく編集が簡単なバージョンが必要な場合は、CSV ファイルとしてエクスポートします。

CSV プロセスは XML のプロセスのサブセットなので、XML のエクスポートでサポートされていない機能は CSV のエクスポートでもサポートされません。また、CSV プロセスはサブセットであるため、XML プロセスで使用可能なすべての機能を CSV プロセスで使用できるとは限りません。たとえば、CSV エクスポートには商品属性のみが含まれ、商品バンドルや商品オプションの列は含まれていません。

エクスポートした CSV ファイルの読み方

列ヘッダーには商品の属性が含まれています。ヘッダーの形式は属性のタイプによって異なります。

  • 標準的な属性は属性の名前のみを含みます。
  • カスタム属性は c__ で始まります。たとえば、c__fabric などです。
  • サイト固有属性は __siteID で終わります。たとえば、fragrance__globalsite などです。
  • ローカライズされた属性は __locale で終わります。たとえば、color__en などです。

エクスポートプロセスで複数の値をもつセルが処理される場合、サイトに存在しない句読点が表示されることがあります。インポートプロセスでは、インポートする際にこれらの文字が元の値に変換されます。このため、新しい該当値を追加する場合は、必ず句読点を追加してください。

  • 当社の CSV ファイルでは、セミコロンを使ってセル内の複数の値を区切っています。値にセミコロンが含まれる場合、B2C Commerce ではセミコロンの前にバックスラッシュが追加されます。たとえば、バリエーション商品 "a"、"b"、および "c" を含む標準的なセルは "a;b;c" と表示されます。商品が "a;1"、"a;2"、および "a;3" の値をもつ場合、セル内の値は "a\;1;a\;2;a\;3" になります。
  • 複数値セルの値にバックスラッシュが含まれる場合、B2C Commerce では別のバックスラッシュが追加されます。たとえば、バリエーション商品値 "a\1"、"a\2"、および "a\3" をもつセルは、"a\\1;a\\2;a\\3" と表示されます。

Microsoft Excel では、一部の値の形式が変更されます。Excel によってセル内の先頭のゼロが削除されるため、商品 ID などのゼロで始まる一部の値が正しく表示されないことがあります。また、一部の長い数値が指数表記で保存されることがあります。CSV を Excel で開いた後にインポートする場合は、これらの点に注意してください。

サイトをインジェクション攻撃から守るために、B2C Commerce では、=、+、-、または @ で始まるすべての値の前にゼロ幅接合子 (ZWJ) が挿入されます。ZWJ は表示されず、ファイルをインポートすると B2C Commerce によって削除されます。

CSV のインポートのための準備

ファイルをインポートのために準備する際には、次の点に注意してください。

CSV ファイルがインポートの基準を確実に満たすように、まずカタログをエクスポートして、変更を行います。新しい CSV ファイルを作成することもできますが、これはベストプラクティスではありません。

CSV ファイルはカタログのみを更新できます。インポートプロセスでは CSV ファイルから新規カタログを作成することはできません。インポートプロセス中に更新したいカタログを選択します。

Business Manager では UTF-8 形式の CSV ファイルのみがサポートされています。Business Manager からダウンロードしたすべての CSV は、自動的に UTF-8 形式でエクスポートされるため、ファイルタイプを変更しなければそのまま使用できます。

属性では大文字と子文字が区別されるので、属性 ID を編集した場合は大文字と小文字が一致することを確認してください。

インポート処理では、空のセルは無視されます。カタログをエクスポートして、セルの値を削除し、このカタログをインポートすると、そのセルは元の値を維持します。インポートプロセスによって、値が無効の値で置き換えられることはありません。

インポートプロセスを開始する前に、すべての属性が有効であることを確認してください。以前に定義された接尾辞がないすべてのサイト固有値またはローカライズされた属性は、インポートプロセス中に省略されます。また、接尾辞をもつ、サイトに固有でない属性、またはローカライズされていない属性も省略されます。インポートプロセスの完了後、すべての無効な属性を示すログが表示されます。新しくインポートしたカタログにすべての属性が表示されない場合は、ログを確認してください。

CSV はマージモードでのみインポートし、プロセスを開始する前にインポートするカタログを指定します。

CSV の制限事項

CSV プロセスでは、システムオブジェクトタイプ | Product (商品) で利用可能で、XML カタログスキーマでサポートされている、すべてのシステム属性とカスタム属性がサポートされています。また、マスターのバリエーション商品、バリエーショングループ、および商品セットに含まれる商品を参照できるように、このプロセスではその他の追加の要素がいくつかサポートされています。XML で廃止された要素はサポートされていません。

CSV プロセスでサポートされていない要素

  • Bundled-products
  • Category-assignment
  • Classification-category
  • 画像とすべての下位要素
  • オプション
  • Product-detail-page-meta-tag-rules とすべての下位要素
  • Product-links
  • バリエーション > 属性
  • バリエーション > 属性値

利用可能な日数

利用可能な日数は、B2C Commerce で品目が作成されてからの経過時間を表す商品属性です。

B2C Commerce では、現在の日付と商品の availableDate (利用可能な日付) を基にして属性が計算されます。availableDate がインポートされない場合は、代わりに B2C Commerce で商品の creationDate (作成日) が自動的に判断され、使用されます。これは、商品がオンラインになった日付や利用可能になった日付を基にしていません。利用可能な日数はグローバル属性です。したがって、この値は商品を共有するすべての B2C Commerce サイトで同じです。

利用可能な日数:

  • B2C Commerce では、この値がリアルタイムで計算されます (以下の計算手順を参照)
  • インポートまたはエクスポートできません。
  • ステージングされていないため、値はインスタンスに固有です。
  • バリエーションマスターや商品セットで特別な処理が必要ありません。B2C Commerce では、マスター商品レコードの availableDate または creationDate に基づいて、商品マスター商品の利用可能な日数が計算されます。商品セットも同様に処理されます。

商品 (p) に利用可能な日付がある場合、その商品の利用可能な日数は、現在の日付から利用可能な日付を差し引いた値と等しくなります。

DaysAvailable(p) = Current Date - Available Date(p)

商品 (p) に利用可能な日付がない場合、その商品の利用可能な日数は、現在の日付から作成日を差し引いた値と等しくなります。

DaysAvailable(p) = Current Date - Creation Date(p)

利用可能な日付がある場合の例

  • 利用可能な日付: 2008/08/05
  • 作成日: 2008/08/04
  • 現在の日付: 2008/08/25

利用可能な日数 (日): 20

利用可能な日数 (時間): 480

利用可能な日付がない場合の例

  • 利用可能な日付: n/a
  • 作成日: 2008/08/04
  • 現在の日付: 2008/08/25

利用可能な日数 (日): 21

利用可能な日数 (時間): 504

B2C Commerce のデフォルトドメインのサポート

デフォルトドメインは、各インスタンス (Development (開発)、Staging (ステージング)、Production (本番)) に対して、Salesforce が管理する eCDN 有効化済みのホスト名を提供します。これにより、手動の DNS 設定、カスタムドメイン登録、証明書管理を行うことなくチームでテストできます。

デフォルトドメインとは?

デフォルトドメインは、eCDN 機能が有効になっている B2C Commerce インスタンス (Development (開発)、Staging (ステージング)、Production (本番)) 用に事前構成された Salesforce 所有のホスト名です。

デフォルトドメイン形式の例:<realm>-<stg>.my.commercecloud.salesforce.com ( 例: abcd-stg.my.commercecloud.salesforce.com )。

このドメインは、カスタムブランドのドメイン (www.example.com など) と共存し、開発者によるテスト、負荷テスト、本番前レビュー、およびカスタムドメインをまだ持っていない、または使用したくない場合に eCDN を有効化する目的で使用します。

1. デフォルトドメインへのアクセス

新しいレルムをプロビジョニングした後 (またはパイロット中に既存のレルムに対して機能を有効にした後)、デフォルトドメインはすぐに利用可能になります。

  1. ドメインの場所: Business Manager で「埋め込み CDN 設定」ページを開きます。デフォルトドメインは、ホスト名の 1 つとしてリストされます。
  2. アクセス方法: 提供された URL をブラウザーで開きます。
    • Development (開発) または Staging (ステージング): これらの環境は、通常は保護サイトのため、ユーザ認証情報で認証してアクセスします。Development (開発) または Staging (ステージング) に「すべてブロック」の eCDN ルールを追加して、アクセスをブロックします。
    • Production (本番): カスタムドメインを使用しない場合は、デフォルトドメインを公開することができますが、これは主に下位環境でのテスト用です。

      バニティー・ドメインがない場合、Page Designer および Preview 機能でのナビゲートで問題が発生する可能性があります。たとえば、開発機能はプレビューで失敗します。

      この場合:

      1. Page Designer および Preview 機能のバニティホスト名を作成します。
      2. このトラフィックに対してデフォルトゾーンの IP またはユーザーエージェントを許可するカスタムルールを作成します。
      3. Production (本番) で [Block All] ルールを無効にします。
        メモ 基本的な「すべてブロック」ルールを削除すると、本番環境のすべてのサイトでデフォルトドメインが完全に公開されるため、追加のセキュリティルールやレート制限ルールがないと推奨されるオプションではありません。
      • デフォルトの Production (本番) セキュリティ構成: セキュリティを維持するため、Production (本番) のデフォルトドメインには、eCDN レイヤーで最終的な「Block All」ルールがあります。
      • デフォルトドメイン経由でパブリックにアクセスできるようにするコンテンツの「すべてブロック」ルールの上に、明示的な「許可」ルール(サイト/パス用)を追加します。
      • 基盤となる「Block All」ルールを削除すると、本番環境のすべてのサイトでデフォルトドメインが完全に公開され、明示的な通知がトリガーされます。

2. デフォルトドメインでの eCDN 構成

デフォルトドメインは、カスタムドメインと同様に、Business Manager (BM) UI と CDN API の両方を使用して完全に構成できます。また、デフォルトドメインの前面に外部 CDN を配置することもできます。詳細については、外部 CDN またはサードパーティプロキシの構成を参照してください。

メモ 信頼済み IP については、信頼済み IP 機能を使用して IP アクセス制限を構成している場合、Production (本番) デフォルトドメインの既定の「Block All」セキュリティルールは、送信元がこれらの信頼済み IP アドレスのトラフィックには適用されません。推奨アプローチは、セキュリティルールを使用することです。

3. カスタムドメインへの影響

デフォルトドメインでは、既存のカスタムドメインの機能や動作は変更されません。

  • 共存: デフォルトドメインとカスタムドメインは、同じインスタンス上で存在できます。
  • ブランディング: カスタムドメインは、外部に公開するブランド付きストアフロントで引き続き推奨されます。
  • 一貫性: デフォルトドメインを変更しても、カスタムドメインの構成には影響しません。

B2C Commerce の DKIM の構成

Google、Microsoft、Yahooなどの主要なメールプロバイダーは、DomainKeys Identified Mail(DKIM)認証を必要とするようになりました。DKIMの設定は、Eメールが顧客の受信箱に届き、拒否されたり、スパムとしてフラグが立てられたりしないようにするために不可欠です。DKIM を設定して、メールが送信元であると主張するドメインから送信されたことを確認します。

所有している Salesforce Commerce 製品

  1. DKIM の秘密鍵と公開鍵のペア (.p12 鍵) を生成します。秘密鍵と公開鍵のペアの生成を参照してください。
  2. DKIM の .p12 鍵をインポートします。
    1. Business Manager で、アプリケーションランチャーをクリックし、次に管理 | オペレーション | 秘密鍵と証明書の順に選択します。
    2. [ インポート ] をクリックし、p12 キーを選択します。
    3. エイリアスと、必要に応じてパスワードを入力します。キーを保存します。
  3. DKIM を有効にし、メール設定で DKIM セレクタを指定します。

    DKIMセレクタは、DKIMメール署名内の一意のユーザー定義の文字列で、DNSレコード内の特定の公開鍵を参照します。これは、同じドメイン上の複数のDKIMキーを区別するために使用されます。セレクタは、DNS TXT レコードのプレフィックスを形成し、<selector>._domainkey.< という形式になります。domain>です。

    たとえば、E メールアドレスがnoreply@notifications.example.com で、セレクタがmyselectorの場合、DNS TXT レコードラベルはmyselector._domainkey.notifications.example.comになります。

    1. 管理 | オペレーション | Eメール設定で、「DKIM を有効にする」を選択します。
    2. [Private RSA key (秘密 RSA キー)] で、インポートした .p12 キーを選択します。
    3. DKIM セレクタの名前を入力します。
    4. 適用をクリックします。
      次の点に留意してください。
      • ドメインは手動では構成されません。代わりに、メールの送信時に使用されるのと同じドメインです。たとえば、noreply@notifications.example.com などです。
      • 1 つのインスタンスは 1 つの秘密鍵とセレクタのみを持つことができますが、同じ公開鍵とセレクタを複数のインスタンスで使用できます。
      • 同じ秘密鍵と公開鍵のペアは、同じインスタンスであっても、複数のドメインで使用できます。

      この図は、1 つのインスタンスが DKIM 用に一度に 1 つのアクティブな秘密鍵とセレクタしか持たないことを示しています。ただし、この 1 つの秘密鍵は、ホスト名の管理インターフェイスを介して複数のホスト名に関連付けることができます。

      この画像は、すべてのストアフロントが、同じインスタンスで構成された同じ基礎となる秘密鍵を共有していることを示しています。同じ本番インスタンスで複数のストアフロントをホストする場合は、一意のサブドメインごとにパブリック DNS TXT レコードを複製する必要があります。

  4. DNS ホスティング プロバイダーまたはドメイン レジストラーで、メール ドメインの DNS レコードを構成します。
    DNS レコードの DKIM TXT レコード エントリの値を更新します。

    たとえば、ドメインnotifications.example.comにmyselectorという名前のセレクタがある場合、レコードに TXT エントリを入力しますmyselector._domainkey.notifications.example.com

    TXT エントリのコンテンツは long 変数です。

    たとえば、"v=DKIM1; k=rsa;" "p=MIIBIjANBgkqhk…です。

    TXT レコードは公開鍵を保存するために必須です。

    メモ DNS TXT レコード内の 1 つの文字列は 255 文字を超えることはできません。TXT レコードは複数の文字列を保持できます。DKIMレコードが255文字を超える場合は、同じレコード内で複数の引用符で囲まれた文字列に分割します。文字列を分割するには、二重引用符で囲まれた文字を使用します。メールサーバーがDNSに問い合わせると、引用符で囲まれた文字列が自動的に1つの長くて壊れていない公開鍵に連結されます。1024 ビットの RSA キーでは分割は必要ありませんが、2048 ビットの RSA キーでは分割が必要です。

B2C Commerce での攻撃のブロック方法の決定

Salesforce B2C Commerce ではセキュリティ保護を提供していますが、セキュリティコントロールの構成と、デフォルトで有効になっているセキュリティコントロールを維持することはお客様の責任です。お使いの B2C Commerce インスタンスのセキュリティを維持するために、次のすべての面を考慮する必要があります。

Salesforce B2C Commerce で作業する際には、次のセキュリティに関する質問を念頭においてください。

  • 攻撃者をどのようにエッジでブロックし、ネットワークを介してインスタンスにアクセスできないようにしますか。
  • クレジットカードデータや個人を特定できる情報 (PII) など、買い物客と自分のサイトの間、またはユーザーと Business Manager の間で交換された機密情報を攻撃者が読み取りまたは変更できないようにするにはどうすればよいでしょうか。
  • 買い物客やユーザーは実際にそれぞれが名乗っている人物ですか。
  • 買い物客やユーザーが、実行しようとしている操作に対し、実行する承認を受けていますか。
  • 攻撃者が正規の買い物客やユーザーに対しアクセスを制限または拒否できますか。
  • 攻撃が発生した場合、監査ログを使用して何が起こったのかを特定できますか。

B2C Commerce のセキュリティの概念をより良く理解するには、プラットフォームアーキテクチャを理解することが役立ちます。詳細については、Salesforce B2C Commerce (デベロッパー向け) のトレイルを参照してください。

B2C Commerce での HTTP Strict Transport Security (HSTS) の無効化

HSTS の無効化は 2 つのステップによる処理です。まず買い物客に保護されていない接続を使用してサイトにアクセスさせ、次にサイトのヘッダーで HSTS の送信を中止します。

必要なエディション

使用可能なソリューション: B2C Commerce

単にサイトで HSTS ヘッダーを無効にすると、サイトからブラウザーへの HSTS 要件の送信は中止されますが、多くのブラウザーはすでにサイトから最大期間を受信していると考えられます。最大期間が経過するまで、ブラウザーではサイトのヘッダーは再度確認されません。ブラウザーがヘッダーを確認するのは、最大期間を変更した場合のみです。このため、サイトの HSTS ヘッダーを無効にする前に、最大期間を 0 に設定して、顧客が保護されていない接続を使用してサイトにアクセスするようにします。

2 番目のステップでは、HSTS ヘッダーを無効にします。無効にする前に、過去に設定した最大の最大期間だけ待つことをお勧めします。たとえば、4 月 1 日に最大期間を 1 か月に設定したとします。4 月 5 日には、最大期間を 1 週間に変更しました。この場合は、5 月 1 日、つまり 4 月 1 日から 1 か月間待って、ヘッダーを無効にします。

  1. Business Manager で、アプリケーションランチャーをクリックし、次に管理 | サイト | 埋め込み CDN 設定の順に選択します。
  2. ゾーンの構成をクリックします。
  3. 暗号化タブで最大期間を 0 に設定します。最大期間が 0 の場合、ブラウザーでは保護された接続を通じて接続を行うという要件が破棄されます。
  4. HSTS ヘッダーを無効にする前に、過去に設定した最大の最大期間だけ待機します。
  5. HSTS ヘッダーを無効にするには、有効をクリックします。
  6. 確認をクリックします。

B2C Commerce の分類ルールセット

分類ルールセットは、自動的に商品を特定のカテゴリに割り当てます。ルールセットを作成するには、属性、演算子、値を使用して、商品が特定のカテゴリに含まれるために満たす必要のある条件を定義します。このトピックは、B2C Commerce に該当します。

演算子

演算子をフィルターの条件として使用して、商品をカテゴリに正確に割り当てます。

演算子 説明 例
が次の値と等しい フィールド値は、指定した値と完全に一致する必要があります。これにより、色が「赤」に一致する商品のみが選択されます。 商品の色が「赤」と等しい
が次の値と等しくない フィールド値は、指定した値と一致してはなりません。これにより、色が「赤」でない商品が選択されます。 商品の色が「赤」と等しくない
が次の値を含む フィールド値には、指定した値 (フィールド内の任意の場所) が含まれている必要があります。これにより、名前に「電話」という単語が含まれる商品が選択されます。たとえば、スマートフォン、携帯電話などです。 商品名に「電話」が含まれる
が次の値で始まる フィールド値は、指定した値で始まる必要があります。これにより、名前が「スマート」で始まる商品が選択されます。たとえば、スマートフォン、スマートウォッチなどです。 商品名が「スマート」で始まる
が定義されている フィールドには値が必要です。たとえば、空または null であってはなりません。これにより、説明が入力されている商品のみが選択されます。 商品説明が定義されている
が定義されていない フィールドに値を含めることはできません。たとえば、空または null です。これにより、説明が入力されていない商品が選択されます。 商品説明が定義されていない

ルールセット

ルールセットは、商品がカテゴリに割り当てられるために満たさなければならない分類条件の集合です。これらのルールでは、商品全体に適用できる事前定義された特性である標準属性が使用されます。すべての標準属性が、ルールセットを作成し、商品を分類するための条件を定義するためのオプションとして使用できるわけではありません。ルールセットを実行して、カテゴリに割り当てる商品の範囲を狭めたり広げたりします。

ルールセットロジックは、「および」「または」の演算子で構成します。特定のルールセット内におけるすべての条件で、デフォルトで「および」が使用されます。また、特定のカテゴリのすべてのルールセットでは、デフォルトで「または」が使用されます。1 つのルールセットに、「および」を使用するルールセットを最大 5 つ設定できます。1 つのカテゴリに、「または」を使用するルールセットを最大 5 つ設定できます。

たとえば、商品名に「レトロ」が含まれるすべての XYZ ブランドの商品を「クリアランス」カテゴリに追加したいとします。また、2019/1/1 までオンラインで購入可能なすべての XYZ ブランドの商品を同じ「クリアランス」カテゴリに追加するとします。このカテゴリを作成するには、次の 2 つのルールセットが必要です。

ルールセット 1
属性 演算子 値
ブランド が次の値と等しい XYZ
商品名 が次の値を含む レトロ

または

ルールセット 2
属性 演算子 値
オンライン終了 不等号 (より小さい) 2019/1/1

ルールセットを作成して検証したら、ルールセットを手動で実行するか、一括ジョブとして実行します。一括ジョブの作成方法については、ジョブの作成を参照してください。ルールセットを一括ジョブとして実行するには、「分類ルール」タブで「実行」を選択します。

条件に該当する新規商品は、自動的には割り当てられません。ジョブを再度実行して、カテゴリを更新します。ルールベースの分類は、商品以外のインスタンスのユーザーを対象としており、商品の処理はカテゴリあたり 10 万件までに制限されています。

1 つの商品に割り当てられるのは、1 つの主要カテゴリと 1 つの分類カテゴリのみです。いずれかのチェックボックスがオンの状態で複数の分類ルールが適用される場合は、最後に実行された分類ジョブによって主要カテゴリと分類が決定されます。Salesforce では、2 つのExecuteCategorizationRulesジョブを順番に実行することをお勧めします。最初のジョブはカテゴリの割り当てを決定し、2 番目のジョブはどのカテゴリを主要または分類として設定するかを制御します。
