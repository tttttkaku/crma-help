Script API でのバリエーショングループのサポート

B2C Commerce Script API では、バリエーショングループがサポートされています。

Script API をバリエーショングループとともに使用するには、次のようにします。属性値を読み取る場合、バリアントで属性値が定義されていないと、バリエーション商品からマスター商品へのフォールバックが行われます。バリエーション商品に属性値が定義されていない場合は、バリエーション商品からバリエーショングループへのフォールバックは行われません。ただし、バリエーショングループに属性値が定義されていない場合は、バリエーショングループからマスター商品へのフォールバックが行われます。

  • dw.catalog.Variant クラスの属性フォールバック動作では、まず (1 つまたは複数の) 割り当てられているバリエーショングループから属性が取得され、次にマスター商品から取得されます。
  • dw.catalog.VariationGroup クラスの属性フォールバック動作では、属性がバリエーショングループで指定されていない場合、マスター商品から属性が取得されます。
  • dw.catalog.Product クラスでは、公開の isVariationGroup(); ブールメソッドを使用して、商品がバリエーショングループのタイプであるかどうかがチェックされます。
  • dw.catalog.Product クラスでは、公開の getVariationGroups(); コレクションメソッドを使用して、マスター商品のすべての割り当てられたバリエーショングループが返されます。
  • dw.catalog.ProductVariationModel クラスでは、公開の getVariationGroups(); コレクションメソッドを使用して、対応するマスター商品のすべての割り当てられたバリエーショングループとオンラインバリエーショングループが返されます。
  • dw.catalog.ProductVariationModel クラスでは、公開の ProductVariationAttributeValue getVariationValue( Product variantOrVariationGroup, ProductVariationAttribute attribute ); メソッドを使用して、バリエーショングループ商品の構成されているバリエーション値が返されます。

B2C Commerce での Dos 攻撃に対する保護

DoS 攻撃では、攻撃者がネットワークのユーザーに対してコンピューターリソースを拒否することを試みます。攻撃者は通常、ターゲットのコンピューターシステムのリソースに大量の未承認のリクエストを送信し、一般のユーザーがネットワークにアクセスできないようにします。

DDoS 攻撃では、攻撃は 1 人の侵入者ではなく、複数のソースから行われます。DoS 攻撃の影響を緩和するために使用される主なメカニズムは eCDN で、DoS と DDoS に対する保護を提供します。eCDN は、SYN、UDP、および ICMP の攻撃を含む、一連の TCP での過剰負荷による攻撃に対し自動的な保護を提供します。また、eCDN は DoS 攻撃の影響を緩和できます。これを行うには、次のように構成します。 - IP ファイアウォールルール - Web アプリケーションファイアウォール (WAF) ルール - eCDN セキュリティレベル - CAPTCHA (Computers and Humans Apart) チャレンジを見分けるための完全自動公開チューリングテスト

リスト型攻撃は、顧客とユーザーのログインロックアウトポリシーを使用して緩和できます。Web サービスの開発に使用するカスタムコードに対し、洗練されたレート制限機能を使用できます。

アカウントレベルの信頼できる IP リストが eCDN ゾーンに対して構成されている場合、Salesforce はこれらのゾーンに DDoS レイヤー 7 上書きを自動的に適用して、信頼できるソースからの大量のトラフィックに対する誤検知チャレンジを防止します。これらのオーバーライドにより、特定の Cloudflare DDoS マネージドルールに対して機密性レベルが引き下げられ、ログのみのアクションが設定されます。追加の設定は必要ありません。詳細については、「DDoS レイヤー 7 オーバーライドの詳細」を参照してください。

ショートコードの生成と API クライアント ID の作成

Salesforce Commerce API を使用するには、以下のものが必要です。

  • ショートコード (構成値を参照)
  • API クライアント ID と、CDN Zones API の認証トークン (CDN ゾーン ⁻ コンテンツ配信ネットワークを参照)

API 認証トークンを取得するときは、<tenant_id>がインスタンスと一致することを確認してください。

  • eCDN Development (開発) プロセスには、 <realm>_dev を使用
  • eCDN Staging (ステージング) プロセスには、 <realm>_stg を使用
  • eCDN Production (本番) プロセスには、 <realm>_prd を使用

ショートコードと API の認証が完了したら、返された値を使用してプロセスで必要なさまざまなエンドポイントを呼び出します。

  • {shortcode}
  • {organizationId} - f_ecom_<realm>_stg

Tableau コネクタの API クライアント ID の生成

Tableau コネクタにアクセスするには、B2C Commerce で API クライアント ID を設定します。

所有している Salesforce Commerce 製品

  1. Account Manager にログインします。
  2. API Client (API クライアント) をクリックします。
    API クライアントページには、各クライアントの ID、表示名、状態が表示されます。
  3. Add API Client (API クライアントの追加) をクリックします。
  4. API Client (API クライアント) の情報を入力します。
    1. Display Name (表示名) フィールドに、クライアントの表示名を入力します。
    2. 必要に応じて、API クライアントの説明を入力します。
    3. 安全なパスワードを入力します。
    4. Confirm Password (パスワードの確認入力) フィールドに、パスワードを再度入力します。
    5. Organizations (組織) で、自分の組織を選択します。
    6. Roles (役割) で Salesforce Commerce API を選択し、自分の Production (本番) インスタンスをフィルターとして追加します。
      メモ データ抽出は、Production (本番) インスタンスでのみ可能です。
    7. OpenID Connect (OpenID 接続) の Default Scopes (デフォルトの範囲) フィールドに、tenantFilter (1) とroles (2) のリテラル文字列を別々の行に入力します。tenantFilter (テナントフィルター) と roles (役割) のエントリは、Authorization Code Flow (認証コードフロー) または OpenID Connect (OpenID 接続) を使用する場合に必要です。[既定のスコープ] フィールドは、クライアント アプリがスコープを明示的に指定せずに承認要求を行った場合に付与されるベースライン アクセス許可を定義します。詳細については、B2C Commerce の役割と許可を参照してください。
    8. 「トークン・エンドポイント認証方法」から、「client_secret_post」を選択します。
    9. 保存をクリックします。
      新しい API クライアントが、組織の API クライアントリストに表示されます。
  5. API クライアント ID を表示するには、API Client (API クライアント) をクリックします。
    Tableau Data Connector にログインするには、新しいクライアント ID とパスワードを使用します。

B2C Commerce API (Shopper Commerce API (SCAPI)) メトリクス

SCAPI メトリクスは、Web サイト管理者と DevOps チームが API 呼び出しのパフォーマンスを監視および分析するのに役立ちます。また、実行時間の長い API 呼び出しや不正なキャッシュヒット率など、API の問題を特定するのに役立ちます。SCAPI メトリクスは、最大 10 分の遅延でメトリクスダッシュボードに表示されます。

フィルターを使用して、特定の API にメトリクスを絞り込んでください。

  • API ファミリー:API ファミリーに属するすべての API をフィルター処理します。
  • API 名1 つの API をフィルター処理します。

リクエストレイテンシ

リクエストレイテンシメトリクスは、外部ネットワークを除いた SCAPI 側での API リクエストの処理にかかる合計時間をミリ秒単位で測定します。

使用事例:

  • 実行時間の長い API と、パフォーマンスが低下している API を特定します。

リクエスト数

リクエスト数は、B2C Commerce API に対して行われたリクエストの合計数を測定します。

使用事例:

  • 予期せぬトラフィック量を受信する API を特定します。リクエスト数が異常に多いまたは少ない場合は、呼び出し元の実装が間違っているか、効果がない、呼び出し元システムの停止、または DDoS 攻撃を示している可能性があります。

キャッシュヒット率

SCAPI キャッシュヒット率メトリクスは、応答が SCAPI キャッシュから提供された呼び出し (HIT)、キャッシュから提供されなかった呼び出し (MISS)、またはキャッシュから提供された部分と提供されなかった部分から構成された呼び出し (PARTIAL) の数を測定します。

使用事例:

  • どの API 呼び出しがキャッシュから確実に提供されるか、およびキャッシュヒット率を高めるためにどの呼び出しを改善できるかを特定します。

その他の SCAPI メトリクスについては、Commerce Analytics Center (CCAC) の SCAPI ダッシュボードをご覧ください。『B2C Commerce ガイド』の「Salesforce B2C Commerce パフォーマンスのトラブルシューティング」を参照してください。

B2C Commerce API (Shopper Commerce API (SCAPI)) フックメトリクス

SCAPI フックメトリクスは、Web サイト管理者と DevOps チームが SCAPI フックのパフォーマンスを監視および分析するのに役立ちます。これらのメトリクスは、パフォーマンスの低下や SCAPI フックの失敗に関する問題を特定するのに役立ちます。SCAPI フックメトリクスは、最大 10 分の遅延でメトリクスダッシュボードに表示されます。

特定の API にメトリクスを絞り込むには、フィルターを使用してください。

  • API ファミリー:API ファミリーに属するすべての API をフィルター処理します。
  • API 名1 つの API をフィルター処理します。

フック実行時間

フック実行時間メトリクスは、フックスクリプトの実行にかかる時間をミリ秒単位で測定します。

使用事例:

  • フックの実装が不十分であると引き起こす可能性のあるパフォーマンスの問題を特定します。

フック実行エラー

フック実行エラーメトリクスは、SCAPI フックの実行中に発生したエラーの数を測定します。

使用事例:

  • 頻繁に失敗するフックを特定。

その他の SCAPI メトリクスについては、Commerce Analytics Center (CCAC) の SCAPI ダッシュボードをご覧ください。『B2C Commerce ガイド』の「Salesforce B2C Commerce パフォーマンスのトラブルシューティング」を参照してください。

Technical Open Commerce API (OCAPI) ダッシュボード

B2C Commerce Reports & Dashboards の Technical (テクニカル) OCAPI ダッシュボードは、サイトの OCAPI リクエストに関するインサイトを提供します。レポートのメトリクスは毎日更新されます。すべての時刻はグリニッジ標準時 (GMT) です。

Average Response Time (平均応答時間)

平均応答時間レポートは、リクエストあたりの平均応答時間のトレンドを表示します。応答時間はミリ秒単位で表示されます。グラフには、選択した期間内の毎日の応答時間が点としてプロットされます。応答時間を表示するには、マウスをプロットラインに合わせます。コントローラーの応答時間を追跡して、トラブルシューティングを行い、リソースの最適化を特定します。

Request Report (リクエストレポート)

1 日あたりのフィルターされた OCAPI リソースのリクエスト数。

Non200-Level Responses (200 レベル以外の応答)

200 レベル以外の応答レポートは、選択した期間中に 200 レベル以外の応答コードとなったリクエストの頻度のトレンドを合計に対するパーセントとしてプロットします。特定の日の 200 レベル以外の応答の数とタイプを表示するには、グラフの点をマウスでポイントします。

Response Time Distribution (応答時間の分布)

このレポートは、応答時間 500 ミリ秒の範囲ごとのリクエスト数を表示します。たとえば、ダッシュボードの期間中、サイトで 1000 万件のリクエストが受信されました。このうち、700 万件のリクエストは応答時間が 0 ~ 400 ミリ秒の範囲でした。また、300 万件のリクエストは応答時間が 500 ~ 999 ミリ秒の範囲でした。棒グラフには、各応答時間の範囲に該当するリクエスト数と、表されている応答の合計の割合が表示されます。システムとコントローラーのパフォーマンスを確認します。応答時間が長く、コントローラーリクエストの数が多くなっている場合は、コントローラーで問題が発生していることが考えられます。

このレポートには、ダッシュボードの期間中の OCAPI API リクエストがリストされます。このレポートを使用して、OCAPI API の使用と応答時間を追跡します。

Cache Hit Ratio (キャッシュヒット率)

キャッシュヒット率レポートには、選択した期間におけるキャッシュヒット、キャッシュミスと保存、キャッシュミスの 3 つの率が表示されます。

  • キャッシュヒットレポートは、Web アダプターページキャッシュから取得された応答の割合です。
  • キャッシュミスと保存は、アプリケーションサーバーで作成されて、キャッシュ可能としてマークされ、Web アダプターページキャッシュに保存された応答の割合です。
  • キャッシュミスは、Web アダプターページキャッシュから取得されなかった応答の割合です。

CDN Zones API を使用した eCDN 構成

Development (開発)、Staging (ステージング)、Production (本番) のいずれかのゾーンを設定するには、開発チームが CDN Zones API を使用して顧客の証明書をアップロードして、Shopper Commerce API (SCAPI) の実装をテストし、eCDN の Development (開発)、Staging (ステージング)、Production (本番) の各インスタンスのバニティホスト名を構成します。

CDN-API を使用すると、Business Manager で作成するゾーンを表示できます。(24.4 リリースで利用可能) Business Manager は、Development (開発)、Staging (ステージング)、Production (本番) 用の eCDN の設定と管理をサポートします。B2C Commerce でのゾーンの作成を参照してください。

Salesforce Commerce APIの CDN ゾーンコンポーネントを使用して、Development (開発)、Staging (ステージング)、Production (本番) の eCDN ゾーンを構成して管理します。

メモ 選択的発信元遮断と発信元遮断の導入以降、eCDN を介するすべてのトラフィックに発信元遮断が強制されます。構成されたすべてのインスタンスも同様です。
  1. ショートコードの生成と API クライアント ID の作成
    Salesforce Commerce API を使用するには、以下のものが必要です。
  2. eCDN ゾーンとホスト名の作成
    Development (開発)、Staging (ステージング)、Produation (本番) のいずれかのインスタンス POD にカスタム SSL 証明書がインストールされていない場合、または POD にインストールされているカスタム SSL 証明書にホスト名が含まれていない場合は、eCDN ゾーンを作成し、各ドメイン名の証明書をアップロードします。
  3. B2C Commerce のサイトトラフィックの移行
    eCDN にトラフィックを移動するために、トラフィック移行を構成します。
  4. B2C Commerce での移行後のタスク
    移行後のタスクでは、eCDN トラフィックの流れと設定を検証します。移行後のプロセスを完了するには、B2C Commerce エンジニアリングと調整します。B2C Commerce Engineering は、Business Managerホスト名のみを通過するBusiness Managerトラフィックを処理するために、Staging (ステージング) Business Managerゾーンを作成して有効にします (例: staging-<realm>-<customer>.demandware.net)。 Business Manager は Staging (ステージング) インスタンスの eCDN をサポートします。
  5. eCDN 管理
    Business Manager または CDN Zones API を使用して、Development (開発)、Staging (ステージング)、および Production (本番) インスタンスの eCDN をサポートするために作成したゾーンを管理します。
