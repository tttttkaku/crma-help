B2C Commerce の注文

Business Manager を使用して、B2C Commerce サイトの注文処理に関する要件の多くを管理できます。たとえば、注文情報と支払情報の変更、注文属性の編集、注文レコードへのメモの追加、注文のステータスを確認するための Eメールの送信、注文のキャンセル、注文のエクスポートが可能です。

  • B2C Commerce での注文の管理
    注文の処理に別のシステムを使用する一方で、B2C Commerce で最初に注文を作成する場合や、注文に関連する処理を管理する場合に Business Manager を使用することもできます。
  • B2C Commerce での支払方法の管理
    Business Manager を使用して支払方法の作成と管理を行えます。作成できる支払方法は、作成済みの支払処理業者によって異なります。このトピックは、B2C Commerce に該当します。
  • B2C Commerce でのクレジットカードとデビットカードの管理
    Business Manager を使用してクレジットカードとデビットカードの作成と管理を行えます。デフォルトのクレジットカードとデビットカードには以下が含まれます。Visa、Master (Master Card)、Discover、Diners Club (Diners Club International)。このトピックは、B2C Commerce に該当します。
  • B2C Commerce での配送方法の管理
    Business Manager を使用して、税区分や通貨、注文金額、配送料を含めた、サイトで利用可能な配送方法を作成し、管理します。このトピックは、B2C Commerce に該当します。
  • B2C Commerce でのサイトの税金の管理
    サイト課税方針は、サイトで商品およびその他の価格をグロス価格で扱うか、ネット価格で扱うかを規定するものです。このトピックは、B2C Commerce に該当します。
  • B2C Commerce の税区分 ID 属性

B2C Commerce の支払カードのキャプチャのタイミング

キャプチャのタイミングは、B2C ストアフロントのために支払がキャプチャされ、支払のイシュアーからマーチャントのアクワイアラーに支払が行われた時点になります。

インスタンスのステータスは Business Manager で設定します。マーチャントツール | 注文 | Salesforce Payments の順に選択し、設定をクリックします。Salesforce Payments では次の 2 つのキャプチャ設定がサポートされています。

  • 支払カードに対して即時にキャプチャ– Salesforce Payments では、承認後すぐに支払がキャプチャされます。キャプチャされた支払の資金は、ただちに支払われます。資金は他のビジネス固有のロジックのために保留されることはありません。
  • 支払カードに対して後でキャプチャ– Salesforce Payments は支払のみを承認します。キャプチャと支払は後で行います。

B2C Commerce の支払カードの認証情報ストレージ

保存されている認証情報の使用を買い物客が承認した場合、支払カードの認証情報ストレージによって、保存されたクレジットカードの認証情報をどのように使用できるかが示されます。この機能は、B2C Commerce に該当します。

インスタンスのステータスは Business Manager で設定します。マーチャントツール | 注文 | Salesforce Payments の順に選択し、設定をクリックします。次の 2 つの設定があります。

  • 今後のセッション外使用のために保存– アクティブにすると、チェックアウト時に買い物客のクレジットカード認証情報が Salesforce Payments によって保存され、セッション外で使用するときに再度承認できます。たとえば、セッション外設定と Script API を使用して、定期サブスクリプションの支払いを承認したり、注文のフルフィルメントが遅れた場合に支払いを再度承認したりできます。
  • 今後のセッション内使用のために保存– アクティブにすると、Salesforce Payments は買い物客のクレジットカードを保存して、現在の注文手続きセッションでのみ使用します。

Order Management への注文の再送信

B2C Commerce で Order Management への注文の送信が失敗した場合、または送信した注文で情報が欠落している場合は、手動で再送信できます。再送信できるのは、ステータスが送信中または承認済みで、まだ割り当てが行われていない注文のみです。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリランチャーをクリックし、次にマーチャントツール | サイト 注文 | 注文の順に選択します。
  2. 再送信したい注文を見つけます。
    • 検索機能を使用します。
    • すべての注文のリストを表示するには、検索をクリックします。
  3. 1 つの注文を再送信するか、再送信可能な注文すべてを再送信します。
    • 1 つの注文を再送信するには、注文の行にある再送信をクリックします。
    • 失敗した注文をすべて再送信するには、失敗したすべての注文を再送信をクリックします。リンクは、再送信可能な注文の数を示しています。

Salesforce Order Management (OMS) と買い物客プロフィールの同期の互換性

買い物客プロフィールの同期は、Salesforce Order Management システム (OMS) と標準で互換性があります。両方の機能を有効にすると、これらの機能が連携して、買い物客の ID に関する信頼できる唯一の情報源が維持されます。

  • 共有重複ルール:Salesforce 組織で個人取引先を作成する場合は、買い物客プロフィールの同期と OMS の両方で同じ重複ルールが使用されます。OMS ロジックでは、明示的な B2C Commerce 識別子 (CommerceCustomerReference および CommerceOrganizationReference) に基づいて照合の優先順位が付けられます。完全に一致するシステムが見つからない場合、システムは標準の重複ルール (メールや名前による照合など) にフォールバックし、両方のシステムが同じ個人取引先レコードに対して一貫して重複排除されるようにします。

OMS買い物客のプロビジョニング

注文の取り込み中に、Salesforce 組織に買い物客がいない場合、OMS によって新しい個人取引先がプロビジョニングされます。このプロビジョニングの一環として、OMSは、CommerceCustomerReference、CommerceOrganizationReferenceおよびCommerceGroupReferenceに直接マップされる、必要な同期参照フィールド(customerId、realmIdおよびcustomerListId)を自動的に移入します。これにより、OMS によって作成された買い物客は、後で変更データキャプチャ (CDC) イベントを介して B2C Commerce に認識され、同期されます。

  • B2C Commerce 向け Salesforce Payments のセットアップ
    Salesforce Payments は、Adyen、Stripe、PayPal などの複数の支払方法と支払ゲートウェイをサポートするネイティブのチェックアウトソリューションです。Salesforce Payments は、Storefront Reference Architecture (SFRA) またはコンポーザブルストアフロントで使用できます。
  • B2C Commerce Salesforce Reference Architecture (SFRA) サイト用の Salesforce Payments プラグインのインストール
    Salesforce Payments プラグインは複数の支払方法とサードパーティの支払ゲートウェイをサポートしているため、買い物客の注文手続き体験が効率化されます。B2C Commerce Storefront Reference Architecture (SFRA) サイト用に Salesforce Payments プラグインを設定するには、GitHub の Salesforce B2C Commerce リポジトリにアクセスできることを確認してください。
  • B2C Commerce の Salesforce Payments プラットフォームの構成
    B2C Commerce の Storefront Reference Architecture (Salesforce Reference Architecture (SFRA)) サイトで Salesforce Payments プラグインを使用するには、Adyen、Stripe、および PayPal でサイトを構成します。
  • Salesforce Payments B2C Commerce ストアフロント設定

  • B2C Commerce の Salesforce Payments 設定
    B2C Commerce Salesforce Payments 設定を使用して、インスタンスのステータス、支払カードのキャプチャのタイミング、サイトの支払カードの認証情報ストレージを構成します。

  • B2C Commerce での Payments の Customer オブジェクトのインポートとエクスポート
    B2C Commerce の Payments では、Customer オブジェクト (customer.xsd) を使用して、支払顧客に関するサイト固有データをインポートおよびエクスポートします。Customer オブジェクトの詳細については、「Customer オブジェクトのインポートとエクスポート」を参照してください。

Call Center API - 注文のエクスポート

Call Center API を使用するアプリケーションでは、注文のエクスポートで以下のステータスコードがレポートされます:

  • EXPORT_STATUS_NOTEXPORTED: 注文をエクスポートできるオプションの日付 (exportAfter)。

    このステータスコードは、注文作成後の初期ステータスです。エクスポートできる日付はあらかじめ定義でき、注文ステータスが「準備完了」に変わったときに使用されます。

    結果: このステータスのときは注文をエクスポートできません。

  • EXPORT_STATUS_READY: 注文をエクスポートできるオプションの日付 (exportAfter)。

    このステータスコードは、注文が検証されて外部システムにエクスポートできる状態になっていることを示します。注文の exportAfter 属性が将来の日付になっていない限り、エクスポートを実行できます。この属性が将来の日付になっている場合は、注文は基本的に保留中 です。注文の変更中にexportAfterを使用することで、注文が途中でエクスポートされるのを防ぎます。

    結果: 注文はこのステータスでエクスポートできます。
  • EXPORT_STATUS_EXPORTED: このステータスコードは、注文がエクスポートされた後の最終ステータスです。

    結果: このステータスは、注文がエクスポートされたことを示します。

  • EXPORT_STATUS_FAILED: サードパーティシステムへの注文のエクスポートが失敗したことを示します。このステータスは、この注文のエクスポートが失敗したことを示します。問題を手動で修正してから、注文を再度エクスポートしてください。

    結果: このステータスは、注文エクスポートの試行に失敗したことを示します。

exportAfter ステータスが EXPORT_STATUS_NOTEXPORTED または EXPORT_STATUS_READY のときにのみ時刻を設定できます。ただし、時刻の評価はステータスが EXPORT_STATUS_READY のときにのみ行われます。この時間によって、エクスポートの準備ができている注文の実際のエクスポートが遅れます。

B2C ストアフロントと買い物客エージェントのための信頼できる URL の追加

エージェントで URL を使用するには、その URL を信頼済み URL に追加します。信頼できる URL とコンテンツセキュリティポリシー (CSP) ディレクティブにより、B2C ストアフロントと Shopper Agent が買い物客と安全にやり取りできるようになります。Agentforce は信頼済み URL の許可リストを適用し、エージェントが悪意のあるリンクを呼び出したり生成したりすることを防ぎ、機密データを保護します。

信頼済み URL には、自社ストアフロント、買い物カゴ、商品詳細ページ、画像などのリソースを含めることができます。エージェントは、買い物客との会話でこれらのリソースを参照したり、ストアフロントまたは他の外部サイトへリダイレクトしたりできます。

メモ 末尾が .salesforce.com の URL は追加しないでください。
  1. Salesforce 組織で、ページ上部のをクリックし、設定を選択します。
  2. 「クイック検索」ボックスで、信頼済み URL を見つけて選択します
  3. 新規信頼済み URL をクリックします。
  4. API 参照名を入力します。
  5. URL を編集または入力します。
    PWA ストアとハイブリッド認証ストアの場合は、Shopper Commerce API (SCAPI) URL のエントリを作成します。たとえば、www.yoursitename などです。
    すべてのストアタイプで、ストアフロント URL のエントリを作成します。たとえば、www.yoursitename などです。
    適切な URL 構文 (例: https://www.examplestorefront.com) に従います。複数のサブドメインがある場合は、ワイルドカード文字 * (アスタリスク) を使用します。たとえば、https//*.examplestorefront.com などです。URL を含めない場合、エージェントは「URL Redacted」と応答します。エージェントにこの URL を共有させるには、リストに追加してください。
  6. 必要に応じて、説明を入力します。
  7. URL を選択し、「CSP ディレクティブ」でconnect-src、frame-src、img-src のリソースのみを選択します。
  8. 変更内容を保存します。
  9. 各 URL について、このプロセスを繰り返します。

エージェントの応答に「URL Redacted」が含まれている場合、その URL のドメインは信頼済み URL に追加されていません。エージェントにこの URL を共有させたい場合は、そのドメインを信頼済み URL に追加してください。

重要 ストアフロント URL が組織の CORS 許可リストにも追加されていることを確認します。[クイック検索] ボックスで、[ CORS]を見つけて選択します。

Salesforce は、処理されたレコードの数に基づいて使用量を計算します。

処理されるレコードの数は、クエリの構造と、クエリ対象のオブジェクト内のレコードの合計数など、その他の関連要因によって異なります。

  
データサービスクレジット 処理された非構造化データ

Salesforce は、処理された非構造化データの量に基づいて使用量を計算します。たとえば、検索インデックスでそれぞれ 1 MB の PDF ドキュメントが 100 件処理される場合、Salesforce は使用量を 100 MB と計算します。検索インデックスで、それぞれ平均 100 MB のオーディオ/動画ファイルが 5 つ処理される場合、Salesforce は使用量を 500 MB と計算します。

Data 360では、埋め込みモデルを使用して非構造化データをチャンク化およびベクトル化できます。Salesforce は、この両方のアクティビティで使用量を 1 回だけ計算します。たとえば、1 つの 100 MB の PDF ドキュメントがチャンク化され、ベクトル化されている場合、使用量は 200 MB ではなく 100 MB として計算されます。

  
データストレージ 割り当てを超えたストレージ Salesforce は、割り当てられた量を超えて使用されたストレージの量に基づいて使用量を計算します。 ストレージとは、Data 360 に保存されているデータの量を指します。Salesforce Lightning Platform に保存されているデータなど、Data 360 の外部で使用されるストレージは、この制限にカウントされません。B2C Shopper Agent の会話のためにData 360に取り込んだデータは、ストレージ割り当てにカウントされます。割り当てられたデータ量よりも多くのデータを使用した場合は、使用量が課金されます。

    TOOL-CALLING POLICY (HIGH PRIORITY):
1. Hard constraint on rejections
   - When the user declines or rejects a confirmation (e.g. “no”, “nope”, “not this”, or changes the options),
     you MUST NOT call B2CCommerceProductSearch in that turn. In this case you MUST call CommerceGuidedShoppingB2C__GetB2CConvContextQuestionAction to rebuild or update convContext using the user’s latest message and set the value contextSwitchType="exploratory".
2. General product search rule
   - Only call B2CCommerceProductSearch when:
     a) convContext is complete (all required options are chosen or confirmed), AND
     b) you are not in a “user just declined” situation.
3. Fallback rule
   - If CommerceGuidedShoppingB2C__GetB2CConvContextQuestionAction fails or returns an error, you MAY call B2CCommerceProductSearch as a fallback, unless you are handling a user rejection as in rule 1.

CONTEXT BUILDING FLOW:
- Always invoke CommerceGuidedShoppingB2C__GetB2CConvContextQuestionAction using the user query as input to build or refine convContext, before calling B2CCommerceProductSearch.
- After receiving the user’s response, update convContext accordingly while preserving existing context if the category remains unchanged.
- If the user query indicates a different category/product, you MUST invoke GetB2CConvContextQuestionAction again to generate a new convContext by passing user query and an empty convContext.
- Maintain convContext in this format:
  convContext: "category/product-name, attribute1:value1, attribute2:value2, attributeN:valueN" e.g. convContext: "mens-clothing, color:blue, size:M"

STEP-BY-STEP FLOW:
Step 1: When the user switches to a different product/category (switch) or returns to a previous one (repeat), MUST call GetB2CConvContextQuestionAction first with the new user query as input and set the contextSwitchType to "switch" or "repeat" accordingly.
Step 2: Show generatedQuestions in plain text (no quotes, no extra formatting).
Step 3: Let the user choose options and form convContext in the specified format.
Step 4: Confirmation handling:
   - If you ask the user to confirm pre-selected options (repeat question scenario):
     * If the user CONFIRMS (yes/yeah/yep/sure/okay etc.):
       - If convContext is complete → call B2CCommerceProductSearch with current convContext.
       - If more details are needed → call GetB2CConvContextQuestionAction to continue refining convContext.
     * If the user DECLINES or changes options (no/nope/not really/different color/another size etc.):
       - Reset convContext to empty string and MUST be passed to GetB2CConvContextQuestionAction as input, along with contextSwitchType="exploratory".
       - Call GetB2CConvContextQuestionAction with no convContext (empty) and contextSwitchType="exploratory" in order to generate a new set of questions.
       - DO NOT call B2CCommerceProductSearch in this turn.
Step 5: If convContext is missing or empty, rebuild it by calling GetB2CConvContextQuestionAction with the user query as input.
Step 6: If GetB2CConvContextQuestionAction fails or returns an error:
   - Call B2CCommerceProductSearch as fallback, unless this is a user-decline situation (see rule 1).

IMPORTANT RULES FOR contextSwitchType:
1. On every new GetB2CConvContextQuestionAction call, pass the value of contextSwitchType as either "exploratory", "repeat", or "switch" as following:
   - Pass "exploratory" if this is the first search utterance and no convContext set yet.
   - Pass "repeat" when same type of product is asked again (like user came back to previous searched product in the current session).
   - Pass "switch" when user query is switched to another product/category.
2. When the category or product changes and you call GetB2CConvContextQuestionAction:
   - pass the current convContext as convContext, and
   - pass the "repeat" or "switch" as contextSwitchType. Empty / "exploratory" in case of first question.

SLAS認証用の指定ログイン情報の作成

SLAS は、ヘッドレス B2C Commerce API にアクセスするための Salesforce B2C Commerce の ID およびトークンサービスです。安全に保存されている SLAS クライアント ID とパスワードにアクセスするには、Salesforce が SLAS サービスに対して認証できるよう、指定ログイン情報を設定します。パブリックA PI にアクセスし、パブリックエンドポイントをテストするには、認証を必要としない指定ログイン情報も構成します。指定ログイン情報を構成する前に、まず関連付けられた外部ログイン情報を構成します。

  1. Salesforce 組織で、ページ上部のをクリックし、設定を選択します。
  2. 「クイック検索」ボックスに、「指定ログイン情報」と入力し、選択します。
  3. 外部ログイン情報タブで、新規をクリックします。
  4. 認証用の外部ログイン情報を作成します。
    1. ラベルと名前を入力します。たとえば、「GuidedShoppingAuth」のように入力します。

      後でエージェントを作成する際に使用するため、この名前をコピーしておきます。

    2. 「認証プロトコル」で、基本認証を選択します。
    3. ログイン情報を保存します。
  5. 認証用の外部ログイン情報にユーザーコンテキストを割り当てます。
    1. 作成したログイン情報のプリンシパルセクションで、新規をクリックします。
    2. パラメーター名を入力します (例: GuidedShoppingAuth Principal)。
    3. 「ID 種別」で、指定プリンシパルを選択します。
    4. 「シーケンス番号」に「1」と入力します。
    5. ユーザー名とパスワードには、Shopper Login and API Access Service (SLAS) のクライアント ID とクライアント ID シークレットを入力します。
    6. 作業内容を保存します。
  6. ゲスト用の外部ログイン情報を作成します。
    1. ラベルと名前を入力します。たとえば、「GuidedShoppingGuest」のように入力します。
    2. 「認証プロトコル」で、認証なしを選択します。
    3. 作業内容を保存します。
    4. 「プリンシパル」セクションで、新規をクリックします。
    5. パラメーター名に「Guest」と入力します。
    6. 作業内容を保存します。
  7. 認証用の指定ログイン情報を作成します。
    1. 指定ログイン情報タブで、新規をクリックします。
    2. ラベルと名前を入力します。たとえば、「GuidedShoppingAuthAPI」です。
      後でエージェントを作成する際に使用するため、この名前をコピーしておきます。
    3. URL には、「https://short_code.api.commercecloud.salesforce.com/shopper/auth/v1/organizations/commerce_org_id/oauth2/token」と入力します。
      たとえば、「https://sandbox-001.api.commercecloud.salesforce.com/shopper/auth/v1/organizations/f_ecom_zyom_006/oauth2/token」です。
    4. 外部ログイン情報フィールドで、以前に作成した認証用の外部ログイン情報を選択します。
    5. 作業内容を保存します。
  8. ゲスト用の指定ログイン情報を作成します。
    1. ラベルと名前を入力します。たとえば、「GuidedShoppingAPI」です。
      後でエージェントを作成する際に使用するため、この名前をコピーしておきます。
    2. URL に「https://short_code.api.commercecloud.salesforce.com」と入力します。たとえば、「https://sandbox-001.api.commercecloud.salesforce.com」です。
    3. 外部ログイン情報フィールドで、以前に作成したゲスト用の外部ログイン情報を選択します。
    4. 作業内容を保存します。
  9. SFRA ストアの場合は、SFRA ストアを指す新しい名前付きログイン情報を作成します。この指定ログイン情報は、SFRA API コールに使用されます。
    1. 指定ログイン情報タブで、新規をクリックします。
    2. ラベルと名前を入力します。たとえば、SFRA_Guest_Named_Credential などです。
    3. URL には、B2C Commerce SFRA ストアフロント URL を入力します。たとえば、www.yoursitename などです。
    4. [外部クレデンシャル(External Credential)] フィールドで、以前に作成した認証なしの外部クレデンシャルを選択します。たとえば、「GuidedShoppingGuest」のように入力します。
    5. 作業内容を保存します。
  10. SFRA ストアの場合は、B2C Commerce から送信されたトークンの復号化に使用する共有秘密鍵を保存するための新しい外部認証情報を作成します。
    1. [External Credentials ] タブで、[ New ] をクリックします。
    2. ラベルSFRA Shopper Agent Secret Key (買い物客エージェントの秘密鍵 ) を、名前にsfra_shopper_agent_secret_keyを入力します。
    3. 「認証プロトコル」で、「カスタム」を選択します。
    4. 保存をクリックします。
    5. 「プリンシパル」セクションで、新規をクリックします。
    6. パラメーター名として「SharedSecretKeys」と入力します。
    7. [ 追加(Add )] をクリックして、認証パラメータを追加します。
    8. 名前として「SharedKey」と入力します。
    9. 値フィールドで、新しい共有秘密鍵を生成します。ターミナルウィンドウで、コマンドopenssl rand -base64 32を実行し、出力をコピーします。これが秘密鍵です。
    10. Principal の value フィールドに、秘密鍵を貼り付けます。
    11. 保存をクリックします。
  11. SFRA ストアの場合は、B2C Commerce のサービス認証情報に秘密鍵を追加します。
    1. Business Manager で、アプリケーションランチャーをクリックし、管理 | オペレーション | サービス | 認証情報の順に選択します。
    2. 新規をクリックします。
    3. 名前として「sfra_agent_secret_key」と入力します。
    4. パスワードフィールドに、秘密鍵を貼り付けます。
    5. 適用をクリックします。
    6. 「プロファイル」タブで、「新規」をクリックします。
    7. sfra_agent_secret_keyという名前のプロファイルを追加します。
    8. 適用をクリックします。
    9. 「サービス」タブで、「新規」をクリックします。
    10. sfra_agent_secret_keyという名前のサービスを追加します。
    11. 「タイプ」ドロップダウンで、「汎用」を選択します。
    12. [プロファイルと資格情報] ドロップダウンで、[ sfra_agent_secret_key ] を選択します。
    13. 適用をクリックします。
重要 90 日ごとに新しい秘密鍵を作成して保存することをお勧めします。

詳細については、外部ログイン情報プリンシパルの有効化を参照してください。

B2C 買い物客エージェントのプリンシパルアクセスの割り当て

プリンシパルアクセスを含むエージェント用の権限セットを作成します。このアクセス権により、Shopper Agent は SCAPI で認証を行い、作成した接続を使用できます。

  1. Salesforce 組織で、ページ上部のをクリックし、設定を選択します。
  2. 「クイック検索」ボックスに「権限セット」と入力し、選択します。
  3. [ 新規 ] をクリックし、次のフィールドを構成します。
    1. 表示ラベル —B2C Shopper Agent Permissions (B2C 買い物客エージェントの許可 ) と入力します。
    2. 説明 —「Grant principal access to the B2C Shopper Agent (B2C 買い物客エージェントへのプリンシパルアクセスの付与 )」と入力します。
    3. [ライセンス] - [ なし ] を選択します。
  4. 作業内容を保存します。
  5. ページの「アプリケーション」セクションで、外部ログイン情報プリンシパルアクセスを選択します。
    1. 編集をクリックします。
    2. 作成した認証とゲストの外部プリンシパルを [Enabled External Credential Principals] 列に追加します。たとえば、GuidedShoppingAuthプリンシパルとGuidedShoppingGuestプリンシパルです。
    3. 作業内容を保存します。
  6. ページの「アプリケーション」セクションで、オブジェクト設定を選択します。
    1. ユーザー外部ログイン情報オブジェクトを選択します。
    2. 編集をクリックします。
    3. [読み取り ] を選択し、作業内容を保存します。
  7. エージェントユーザに権限セットを割り当てるには、[ 割り当ての管理 ] を選択します。

SLAS クライアントの作成

B2C Commerce API にアクセスするための認可トークンをエージェントが取得できるように、SLAS クライアントとシークレットを作成します。

  1. Business Manager に移動し、B2C Commerce インスタンスの組織 ID を取得します。
  2. 「Shopper Login and API Access Service (SLAS) の概要」に移動し、手順に従って状況に適したクライアントタイプを作成します。

Business Manager での組織 ID とショートコードの確認

組織 ID とショートコードを見つけて、メモしておきます。これらの値は、一部のエージェントのセットアップおよびテストタスクに必要です。

  1. Business Manager にログインします。
  2. 管理 | サイトの開発 | Salesforce Commerce API 設定の順に移動します。
  3. 後の構成およびテストで使用するため、組織 ID とショートコードをコピーします。

PWA Kit ストアフロントのエクスプレス支払方法の無効化

メッセージングセッションで「注文手続き」ボタンのみを表示するには、エクスプレス支払方法を無効にします。

  1. Salesforce 組織で、ページ上部のをクリックし、設定を選択します。
  2. 「クイック検索」ボックスに、「Agentforce エージェント」と入力し、選択します。
  3. Shopper Agent を選択し、Agentforce Builder を開きます。
  4. エージェントを非アクティブ化します。
  5. Commerce Cart Management とB2C Commerce Order Assistantサブエージェントの手順を更新します。
    1. 新規バージョンをクリックします。
    2. expressPaymentURL パラメーターの指示を、次の正確なテキストに置き換えます: expressPaymentUrl 入力パラメーターには、ハードコードされた値 'null' を常に使用してください。
    3. 変更内容を保存します。

ガイド付きショッピング向け Agentforce の有効化

B2C Commerce のガイド付きショッピングに Agentforce を有効にします。

  1. Salesforce 組織で、ページ上部のをクリックし、設定を選択します。
  2. クイック検索ボックスに「Commerce Agentforce 設定」と入力し、選択します。
  3. ガイド付きショッピング向け Agentforce — B2Cを有効にしてから、ブラウザーを更新します。
  4. 「クイック検索」ボックスに、「Agentforce エージェント」と入力し、選択します。
    このオプションが表示されない場合は、Einstein 生成 AI がオンになっているかどうかを確認してください。エージェントタイプに適したライセンスと必要なユーザー権限があることを確認します。
  5. Agentforce を有効にし、ページを更新します。
  6. 新規エージェントボタンが表示されることを確認します。

    このボタンが表示されない場合は、Agentforce (デフォルト) 以外の少なくとも 1 つのエージェントタイプに対する権限があることを確認してください。

PWA Kit ストアフロントでの会話コンテキストの有効化

PWA KIT ストアフロントで会話コンテキストを有効にするには、MRT プロジェクトを修正して、会話コンテキスト用の環境変数を追加します。

  1. 拡張チャットの組み込みサービスリリースから、チャットコードスニペットを JSON 形式のファイルにコピーします。
  2. enableConversationalContext 変数をファイルに追加し、値を true に設定します。
  3. conversationContext 変数をファイルに追加し、メッセージングの会話が開始されたときに買い物客に表示されるピルを定義する文字列を最大 3 つ指定します。
  4. 変更が完了したら、JSON ファイルを圧縮 (縮小) します。
  5. Managed Runtime コンソールにログインします。
  6. Projects (プロジェクト) から、関連する既存のプロジェクトを選択し、作業する環境 (ステージングなど) を選択します。
  7. 対象のリリースで環境変数を選択し、COMMERCE_AGENT_SETTINGS に、更新された JSON テキストを貼り付けます。
  8. 変更内容を保存します。
    環境変数を変更するたびに、プロジェクトが自動的にデプロイされます。
