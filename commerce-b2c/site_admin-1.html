B2C Commerce サイト通知へのアクセス

すべてのタスクと通知は、Business Manager ホームページの通知セクションで確認できます。サイトに関するすべてのタスクと通知を通知モジュールで確認できます。通知は Business Manager のホームページまたはヘッダーに表示するか、Slack チャンネルに直接送信できます。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. Business Manager で、右上隅にあるベルのアイコンをクリックし、すべて表示を選択します。
  2. 通知を検索するには、モジュールと優先度を選択します。
  3. 通知で要求されるモジュールに素早くアクセスするには、通知のテキストをクリックします。
  4. 通知が有効かどうかを確認するには、操作の選択をクリックして、再確認を選択します。
  5. 通知を閉じるには、操作の選択をクリックして閉じるを選択します。
    必要な条件が満たされていない場合は、閉じた通知が再度表示されることがあります。

通知の表示方法と表示場所を構成するには、Business Manager と Slack での B2C Commerce 通知の構成 を参照してください。個々のユーザーは、通知設定の編集によって独自の通知をカスタマイズできます。

B2C Commerce の組織管理

管理者は、ユーザーおよび許可を制御します。インポートおよびエクスポート、サードパーティとの統合、バッチ処理、およびデータのレプリケーションは管理者が行います。インスタンスの管理には Control Center を使用します。また、管理者自身の環境内でクライアント証明書を管理することもできます。このトピックは、B2C Commerce に該当します。

  • B2C Commerce の WebDAV ファイルへのアクセス
    Business Manager のフォルダーブラウザーを使用すると、WebDAV ファイルを簡単に表示してダウンロードできます。また、サードパーティの WebDAV クライアントを使用して、WebDAV ファイルを表示、ダウンロード、アップロード、削除できます。
  • Business Manager ユーザーインターフェイスの地域情報の変更
    Business Manager ユーザーインターフェイスでは複数の言語がサポートされています。
  • B2C Commerce の許可、ユーザー、および役割
    B2C Commerce を使用する際のオペレーションとセキュリティの効率を向上させるために、定義した役割に応じてアクセスを割り当てて制限します。ユーザーと許可は、管理者役割をもつユーザーのみがコントロールできます。
  • B2C Commerce のクロスサイトリクエストフォージェリ (CSRF) 環境設定
    CSRF 攻撃からページを保護するために、Business Manager はリクエストにトークンを挿入し、失敗した検証をログに記録します。ログエントリを使用して、失敗したリクエストのトラブルシューティングを行います。
  • Business Manager の Eメール構成
    オプションの Eメール設定を使用して、顧客とプラットフォームの Eメール配信のための独自の SMTP サーバーを定義します。このトピックは、B2C Commerce に該当します。
  • B2C Commerce の HTML 属性内の JavaScript とオブジェクト
    セキュリティ上の理由から、Account Manager の多要素認証などの強力な認証をもつ Business Manager ユーザーのみが、データベースオブジェクトの HTML 属性に JavaScript および iframe、object、applet、embed タグで埋め込まれているオブジェクトを含めることができます。このトピックは、B2C Commerce に該当します。
  • B2C Commerce のグローバル環境設定
    組織全体に対してグローバル環境設定を構成し、場合によってはサイトレベルでこれらの環境設定を上書きします。グローバル環境設定には、サイトのタイムゾーン、地域情報、およびシーケンス番号の設定が含まれます。このトピックは、B2C Commerce に該当します。
  • B2C Commerce のサイト環境設定
    サイト環境設定を使用して、Salesforce B2C Commerce の個々のサイトの動作を制御します。さまざまなサイト環境設定を構成します。
  • Business Manager でのサイトの管理
    Business Manager では、ストアフロントサイト、Business Manager サイト自体、グローバル静的キャッシュなど、サイトのさまざまな面を管理できます。
  • B2C Commerce でのインスタンスバックアップのスケジュール設定
    インスタンスのバックアップをスケジュールします。
  • B2C Commerce インスタンスの Salesforce への接続
    B2C Commerce と Salesforce Org 間で信頼できるデータ交換を作成します。B2C Commerce インスタンスを Salesforce に接続することで、Shopper Agent、マーチャントエージェント、Shopper Profile Sync、Shopper Notifications などのエージェント体験やクロスクラウド体験にアクセスできます。
  • 買い物客プロフィール同期
    Shopper Profile Sync は、B2C Commerce の買い物客データを Salesforce Org のレコードに接続します。このインテグレーションにより、登録済みの買い物客が個人取引先として自動的に同期され、コマース、サービス、その他の Salesforce アプリケーション全体で各顧客の統一されたビューが提供されます。
  • B2C Commerce でのイベント処理の設定 (パイロット)
    B2C Commerce のイベントを使用すると、Commerce Cloud 環境で特定のデータイベントや処理イベントが発生したときに通知を受け取ることができます。イベントタイプを有効にし、コネクターを構成するには、Business Manager を使用します。B2C Commerce は、構成済みのコネクターにイベントを直接ルーティングします。
  • B2C Commerce のジョブ
    ジョブを使用して、データのインポートとエクスポート、データやコードのレプリケート、検索インデックスの作成などの、日常業務や実行時間の長いプロセスを自動化します。ジョブでは、事前構成済みのシステムステップを使用するか、デベロッパーがカスタムジョブステップを作成できます。ジョブは必要に応じて手動で実行するか、特定の日時または定期的に実行するようにスケジュールします。
  • B2C Commerce のレプリケーション
    レプリケーションでは、プライマリインスタンスグループ (PIG) の Staging (ステージング) インスタンスから Development (開発) または Production (本番) インスタンスへ、選択したストアフロントのデータまたはコードバージョンを安全にコピーします。これは 2 つのステップで構成される手順で、まずデータまたはコードバージョンを転送し、次にデータを公開するか、コードバージョンをアクティブにします。このトピックは、B2C Commerce に該当します。

B2C Commerce でのライブラリへのサイトの割り当て

ライブラリを作成したら、そのライブラリをサイトに割り当てます。コンテンツライブラリを参照してください。ライブラリの作成と削除、またはライブラリの割り当ての変更は、Staging (ステージング) インスタンスと Sandbox (サンドボックス) インスタンスでのみ実行できます。

必要なエディション

使用可能なソリューション: B2C Commerce

この機能は Development (開発) インスタンスと Production (本番) インスタンスでは使用できません。Staging (ステージング) インスタンスでライブラリを変更した場合は、データレプリケーションを使用して Development (開発) インスタンスまたは Production (本番) インスタンスに変更を転送できます。

  1. 組織のライブラリを表示するには、アプリケーションランチャーをクリックし、次に管理 | サイト | コンテンツライブラリの順に選択します。
  2. ライブラリページで、新規をクリックするか、ライブラリの編集リンクをクリックして、ライブラリを作成または選択します。
  3. ライブラリの全般タブで、
    1. 言語を選択します。
    2. ライブラリ ID を入力します。ID はいったん作成すると、変更できません。
    3. ライブラリ名を入力するか、変更します。
    4. 説明を入力するか、変更します。
    5. 適用をクリックします。
      新規の共有ライブラリを作成すると、ライブラリページの全般タブに、サイトの割り当てセクションが再表示されます。
  4. サイトの割り当てを変更するには、サイトの割り当てセクションで追加ボタンをクリックします。
    このボタンは、1 つまたは複数の他のサイトにライブラリを割り当てることができる場合にのみ表示されます。コンテンツライブラリの共有ライブラリ セクションを参照してください。
  5. サイトの再割り当てウィンドウで、ライブラリの割り当て先となるサイトを選択して、OK をクリックします。
    割り当てられたサイトがサイトの割り当てセクションに表示されます。
  6. ライブラリページに戻るには、<< リストに戻るをクリックします。
    新しいライブラリがグリッドに表示されます。

B2C Commerce ダッシュボードのレルムの通貨の変更

B2C Commerce Reports & Dashboards では、レルムの通貨を設定して、すべてのサイトの集計レルムデータを、選択した通貨で表示できます。

メモ 設定の構成は、ライブに移行した日から 60 日以内に行う必要があります。この 60 日間が終了すると、お使いの Reports & Dashboard インスタンスでは通貨の設定を変更できるオプションが使用できなくなります。

通貨設定の変更は、サイトの集計表示にのみ影響を与えます。個々のサイトでは、設定したサイトの通貨が引き続き使用されます。

  1. Business Manager で、アプリケーションランチャーをクリックし、次にマーチャントツール | Analytics | Reports & Dashboards の順に選択します。
  2. Settings (設定) アイコンをクリックします。
  3. Manage Realm (レルムの管理) タブをクリックします。
  4. Default currency (デフォルト通貨) ドロップダウンをクリックして、通貨を選択します。
  5. Save (保存) をクリックします。
    通貨の変更が保留中であることがページに表示されます。保留中の通貨の変更は、適用されるまで 24 時間かかります。
  6. 24 時間が経過したら、レルムの管理ページに戻って新しい設定を確認し、保留中の変更がないことを確認します。
    通貨設定が適用されると、すべてのサイトの集計されたレルムデータで選択した通貨が使用されます。

URL の文字制限

URL で使用される文字のほとんどをエンコードします。URL の特殊文字、予約された文字、ウムラウトは自動でエンコードされますが、削除はされません。

メモ "h"、"_h"、"n"、"_n" の文字は予約されており、スタンドアロンの URL 接頭辞として使用する場合は削除されます。たとえば、カテゴリ URL "/h/womens は /womens に変更されます。

商品名やカテゴリ名を使用して URL を作成する場合は、名前の間のスペースを '%20' でエンコードするか、またはハイフンなどの他の文字で置き換えるかどうかを指定できます。また、すべての文字を小文字に変換するかどうかや、すべての URL の最後にスラッシュを付けるかどうかも構成できます。URL で使用できる文字または使用できない文字は、標準の構文、検索しやすい URL 構文、または URL ルールの URL 構文を使用しているかどうかにかかわらず、すべての B2C Commerce URL に適用されます。

マーケティングテキストにおける B2C Commerce URL のエンコード

SEO URL での禁止文字:

  • & - アンパサンド
  • ASCII 制御文字 (ASCII コード: 0x00-0x1F, 0xF7)。たとえば、NULL、タブ、またはその他の非表示の制御文字は SEO URL で使用できません。

文字エンコードルール:

B2C Commerce では UTF-8 および ISO-8859-1 エンコードがサポートされています。Java 仮想マシンでサポートされている他のエンコードもすべて機能するはずですが、正式にサポートしているわけではありません。URL の一部として ISO またはその他のエンコードを指定する方法については、URL 構文を参照してください。

B2C Commerce では、SEO URL の文字をエンコードする際に以下のルールを使用します。

  • 禁止文字以外の表示可能な ASCII 特殊文字すべて。禁止文字が表示されている場合は、空白置換文字 ('+' または %20) に置き換えられます。
  • マーケティングテキストの最初と最後のスペースは削除され、複数のスペースは 1 つに圧縮されます。
  • 構成された空白置換 (%20, +) を使用して、標準の UTF8 URL エンコードが適用されます。
  • フォワードスラッシュ (/) はエンコードされず、生成された URL にクリアテキストとして残されます。
  • プラス記号 (+) は、現在の空白置換文字のシステム構成にしたがってエンコードされます。

eCDN ゾーンのレルムセキュリティルール

レルムセキュリティルールでは、eCDN ゾーン全体で信頼できる IP トラフィックの処理方法を制御する管理 IP アドレスリストとカスタムファイアウォールルールを定義できます。これらのルールは、従来の信頼できる IP 構成を置き換えます。

概要

メモ レルムセキュリティルールタブは、組織で「eCDN の信頼できる IP 移行を有効にする」機能スイッチが有効になっている場合にのみ使用できます。このタブが Business Manager に表示されない場合は、Salesforce アカウントチームにお問い合わせください。

レルム・セキュリティ・ルールは、信頼できるIPトラフィックを管理するために連携する2つのコンポーネントを提供します。

管理対象 IP アドレスリスト

重要 レルムセキュリティルールは、ゾーン設定スライダーのファイアウォールタブで以前に構成されていたレガシーの信頼できるIPリストグループを置き換えます。既存の信頼できる IP 構成がある場合は、Salesforce によって自動的に移行されます。詳細については、「Web アプリケーション ファイアウォール (WAF) への信頼できる IP 移行のカスタム ルールについて」を参照してください。

B2C Commerce でのレガシー URL 用の 301 HTTP リダイレクトの構成

301 リダイレクトは永久的な URL リダイレクトに使用され、ユーザーがブラウザーに入力した URL、または検索エンジンの結果から選択した URL とは別の URL にユーザーを移動します。301 リダイレクトは、ユーザーを HTTP から HTTPS にアップグレードするためのベストプラクティスであると考えられています。

必要なエディション

使用可能なソリューション: B2C Commerce

SEO のベストプラクティスでは、他の URL がポイントする優先ドメイン名を 1 つだけ設定します。たとえば、顧客がブラウザーに company.com と直接入力した場合、永久 "301" リダイレクトを介して www.company.com に移動することができます。リダイレクトは、すべてのバージョンのサイト URL のページランキングとオーソリティスコアを集計して取得し、オーガニック検索エンジンのランキングを上げるのに役立つため、重要です。

  1. ストアフロントにある B2C Commerce が生成したすべての URL が、www.company.comなどの単一のホスト名を使用していることを確認します。これを実現するには、ホスト名エイリアスファイルでサイトのHTTPホスト名とHTTPSホスト名を適切に設定します。これは、運用開始時に行います。早めに行うことはできませんし、後で行うべきではありません。
  2. company.com から www.company.com へリダイレクトします。
    1. URL をリダイレクトするカスタムパイプラインを作成します (たとえば、RedirectURL-Domain または RedirectSiteURL などの名前が付いたもの)。SiteGenesis アプリケーションには、RedirectURL という名前のサンプルのリダイレクトパイプラインが含まれています。
    2. レガシー URL とカスタムパイプライン間の静的マッピングを指定します。アプリケーションランチャーの順にクリックし、マーチャントツール | サイト | SEO & 検出可能性 | 静的マッピングの順に選択します。静的マッピングの形式は、 <レガシー URL> [i] p,[<protocol>], [<host>], <pipeline>, [<locale>], [<parameter name>, <parameter value>]* です。
    3. コンテンツのデフォルトページ URL:何も指定されていない場合、デフォルトは ${pageURL||name} です。デフォルト URL を構築するために、ページ URL とコンテンツ名属性が使用されます。カスタム URL を作成するためにサポートされるコンテンツ属性は、pageURL、pageTitle、ID、name です。リリース 2.6.4 以降をお使いの場合、ホスト名をパイプラインのパラメーターとして指定する必要はありません。パイプラインは、インスタンスのホスト名へのフォールバックとともに HTTP ホスト名をサイト構成から読み込めるようになりした。
    4. 301 リダイレクトが設定されていることを確認するには、リダイレクトパイプラインテンプレートで使用されるInternet Store Markup Language (ISML) タグ ( isredirect ) 内でpermanent属性を true に設定するように指定します: <isredirect location="${pdict.Location}" permanent="true">です。SiteGenesis アプリケーションでは、このコードは redirectpermanent テンプレートに含まれています。
  3. リダイレクトをサポートするように外部検索エンジン設定を定義します。たとえば、Google ウェブマスターツールでは、優先するドメインを www.company.com に設定します。Google があなたを両方のドメインの所有者として認識していることを確認するには、Google のオーナーシップ認証方法のいずれかに従ってください。

B2C Commerce の組織の地域情報の構成

Salesforce B2C Commerce は、1 つ以上のサイト (ストアフロント) を含む組織として設定されます。この両方の構成要素に対し、ローカライゼーション設定を定義します。

必要なエディション

使用可能なソリューション: B2C Commerce

新しいデータ地域情報を追加し、サイトのインポート/エクスポートを使用して、地域設定を転送、追加、削除、更新します。

組織の地域情報を構成後、サイトの地域情報を構成します。

  1. 組織のデフォルト言語を割り当てるには、[アプリケーションランチャー] > [ ] をクリックし、[ 管理] > [組織] > [組織プロファイル ] の順に選択します。
    1. デフォルトの UI 言語を選択します。
    2. デフォルトのデータ言語を選択します。
    3. 適用をクリックします。
  2. インスタンスで使用可能な地域情報をアクティブ化または非アクティブ化するには、[アプリケーションランチャー] [ ] をクリックし、[ 管理] > [グローバル環境設定] > [地域情報 ] の順に選択します。

    アクティブにした地域情報のみがストアフロントで使用でき、Business Manager の言語選択ボックスに表示されます。デフォルト地域情報は必須で無効にできません。

    3. 地域情報 ID をクリックします。

      • 日付/時刻
      • 番号書式
      • 通貨書式

      • https://docs.oracle.com/javase/8/docs/api/java/text/SimpleDateFormat.html

    デフォルトでは、国の地域情報 (たとえば、en_US) はそれぞれの言語の地域情報 (en) からのデータを継承します。また、言語の地域情報 (en) は地域情報のデフォルト を継承します。地域情報の継承を設定します。

    各地域情報のフォールバック動作を無効にします。

B2C Commerce の SEO URL の構成

検索エンジンのためにサイト URL を最適化すると、ユーザー体験、ランキング、リンクの機能が向上され、サイトのトラフィックが大幅に増加します。

必要なエディション

使用可能なソリューション: B2C Commerce

サイトを作成する場合、URL ルールは自動的に有効になり、URL ルールモジュールへの許可があればURL ルールを構成できます。Salesforce では、URL ルールを Staging (ステージング) にエクスポートして Production (本番) にレプリケートする前に Sandbox 上で構成およびテストすることをお勧めします。

メモ URL ルールを無効にすることで、廃止予定の SEO サポートを使用できます。ただし、Salesforce では URL ルールモジュールを使用することをお勧めします。この URL ルールモジュールと (廃止予定の) SEO サポートモジュールを同時に有効にすることはできません。

ストアフロント URL の長さは 1800 文字までです。この制限を超える URL は短くされますが、有効性と一意性は保たれます。具体的に言うと、商品 URL やコンテンツ URL には商品 ID や コンテンツ ID が保持されます。

構成可能な有効な URL 検索の絞り込みの最大数は 30 です。カテゴリ/フォルダーの有効な URL 検索の絞り込みの最大数は 5 です。

異なる地域情報に対して異なる絞り込みの順序を提供するために、特定の地域情報で URL 検索の絞り込みを有効にすることができます。検索エンジンが特定の URL 検索絞り込みをクロールしないようにするには、地域情報固有の定数を URL パスに追加するように設定します。この定数をロボットファイルで使用して、クロールが続行されないようにします。

  1. ストアフロント URL の環境設定で SEO URL を有効にします。
    URL ルールモジュールと (廃止予定の) SEO サポートモジュールを同時に有効にすることはできません。
  2. サイトのホスト名のエイリアスを構成します。

    そうしないと、ストアフロントに URL が正しく表示されません。ホスト名のエイリアスを参照してください。

    ホスト名のエイリアスの構成を参照してください。

  3. URL ルールモジュール ( マーチャントツール | サイト | SEO & 見つけやすさ | URL ルールの全般タブを選択) でステータスを表示し、競合を解決するための情報を入手できます。
    URL ルールページの全般タブではなく検索サポート環境設定ページが表示される場合は、サイト環境設定 | ストアフロント URLの順に移動して URL ルールモジュールを有効にします。
  4. 設定タブをクリックして、地域情報マッピングの設定を構成します。

    または、地域情報 と if-site-path の構文を使用して、ホスト名のエイリアスの構成内で地域情報を構成できます。

  5. カタログまたはライブラリを使用して SEO URL を作成する方法を構成します。URL の作成方法と、有効な検索の絞り込みをパラメーターではなく URL パスにマッピングする方法に関するルールを定義します。対応するタブをクリックして、以下を構成します。
    • カタログ | コンテンツの URL: カテゴリ | フォルダーの URL、カテゴリ | フォルダーの検索絞り込み URL、および商品 | コンテンツアセットの URL 用。
    • パイプライン URL: パイプラインの検索しやすい URL マッピング用。
  6. URL 文字置換の設定を構成します。

    小文字と空白の文字置換を構成し、カスタム置換はカテゴリ、フォルダー、および有効な検索絞り込み URL のマッピングに適用されます。

    商品とコンテンツの URL に対して作成されたルールベースの部分はクリーンアップされます。この URL の必須の ID の部分は変更されません。

    URL: 予約文字または特殊文字の置換を参照してください。

  7. 検索絞り込みの設定を使用して、URL に検索の絞り込みを表示する方法を構成します。
  8. Production (本番) インスタンスでストアフロント URL が有効な場合、URL マッピングの一部が変更される場合があります。この場合は、顧客や検索エンジンが予期したページを表示できるように、古いマッピングから新しいマッピングへのリダイレクトが必要です。
    1. 古くなったカテゴリ、フォルダー、パイプラインの URL マッピングの自動リダイレクトは、URL アーカイブ機能によって実行されます。

      この機能は Staging (ステージング) インスタンスと Production (本番) インスタンスで有効にし、カテゴリ、フォルダー、パイプラインの URL マッピングが古くなった際に自動的に保存して、新しいマッピングにリダイレクトすることができます。

      アーカイブに不要なマッピングがある場合は、URL アーカイブタブをクリックします。このタブは Staging (ステージング) インスタンスのみで表示され、これらのマッピングを削除または表示することができます。

メモ Staging (ステージング) から Production (本番) に URL リダイレクトをレプリケートします。
ヒント リンク元のページからリンク先のページへのリダイレクトは、常に 1 回使用することをお勧めします。リダイレクトチェーンを無差別に使用すると、検索エンジンがページまたはサイトの一部のインデックスを解除する恐れがあります。サイトを訪れる顧客は、すでに 1 回以上のオフサイトリダイレクトを経験している可能性があり、これについては管理できないため、単一のリダイレクトを使用する方が安全です。
メモ デフォルト設定を構成するには、マーチャントツールサイト | サイト | 環境設定 | ストアフロント URLの順に選択します。
  1. アプリケーションランチャーの順にクリックし、マーチャントツール | サイト | SEO & 検出可能性 | URL Redirectsの順に選択します。
  2. 以下の操作のうち 1 つまたは複数を実行します:
    1. 新規をクリックして URL リダイレクトを作成します。
    2. 既存の URL リダイレクトを見つけるには、検索用語を入力して検索をクリックします。
    3. 既存の URL リダイレクトをより詳しく検索するには、詳細をクリックします。
      URI 検索用語ボックスに、リダイレクトしたい URI を識別する単語を 1 語以上入力します。リダイレクトがすでにその URI に設定されていないことをチェックすることで、重複したリダイレクトの作成を防ぐことができます。
    4. すべてのリダイレクトが既存のカテゴリ、商品、またはコンテンツの項目にリダイレクトするように構成されているかどうかを検証するには、無効なリダイレクトの検索をクリックします。
    5. 編集をクリックして、既存の URL リダイレクトを編集します。
  3. URL リダイレクトの編集ページで、ソース URI を直接特定するか、ソースタイプと ID を指定します。
    当社ではソースタイプと ID を入力することをお勧めします。その理由は 2 つあります。まず、標準 URL から検索しやすい URL に切り替えた場合、リダイレクトがすべて保持されます。2 つ目に、ソース ID を直接選択できるため、データ入力エラーの可能性が下がります。
  4. ソースタイプを指定します。選択項目に応じて次のフィールドが変わります。
    URI | URI URI を入力します。大文字 C[0-9] のパターンは、ソース URI でサポートされていません。
    カテゴリ | カテゴリ ID カテゴリ ID を入力するか、参照ボタンをクリックして選択します。
    商品 | 商品 ID 商品 ID を入力するか、参照ボタンをクリックして選択します。
    フォルダー | フォルダー ID フォルダー ID を入力するか、リストから選択します。
    コンテンツ | コンテンツ ID コンテンツ ID を入力するか、参照ボタンをクリックして選択します。

    URI では、ホスト名とサイト ID、および冗長なクエリ文字列をすべて削除します。B2C Commerce は、古い URL と共通するパラメーターが最も多い、新規 URL を自動で選択します。

    たとえば、レディースカテゴリの商品をリダイレクトするには、次のようにします: 

    http://www.mystore.com/on/demandware.store/Sites-YourShopHere-Site/EN_US/Search-Show?_ie=iso-8859-1&cgid=womens

    次を削除します: 

    http://www.mystore.com/on/demandware.store/​Sites-YourShopHere-Site

    次を削除します: 

    _ie=iso-8859-1

    次を入力します:

    /​EN_US/Search-Show?cgid=womens

    URI では、アスタリスクをワイルドカードとして使用します。ワイルドカードをもつリダイレクトは、ワイルドカードのないリダイレクトの後で処理されます。

    ワイルドカードに関するその他の例については、URL リダイレクトの処理および例を参照してください。

  5. 有効ボックスにチェックを入れます。
  6. 宛先タイプを指定します。選択項目に応じて次のフィールドが変わります。
    URL | URL URL を入力します。
    カテゴリ | カテゴリ ID カテゴリ ID を入力するか、参照ボタンをクリックして選択します。
    商品 | 商品 ID 商品 ID を入力するか、参照ボタンをクリックして選択します。
    フォルダー | フォルダー ID フォルダー ID を入力するか、リストから選択します。
    コンテンツ | コンテンツ ID コンテンツ ID を入力するか、参照ボタンをクリックして選択します。
  7. リダイレクトしたい URL を、絶対 URL または相対 URL として指定します:
    • 絶対 URL: URL はプロトコルで始まります (例: http://www.example.com)。
      メモ サポートされているプロトコルは HTTP と HTTPS のみです。追加のパラメーターは、このフィールドではなく、追加パラメーターフィールドに入力します。
    • 相対 URL: URI フィールドに入力する URL と同様、URL のホスト名とクエリ文字列の間の部分のみ入力します。[追加] このフィールドではなく、追加パラメーターを [追加パラメーター ] フィールドに指定します。
  8. ソース URL パラメーターを宛先 URL にコピーするかどうかを制御します。
    デフォルト サイト環境設定が使用されます。Business Manager で、サイト名 | マーチャントツール | サイト環境設定 | ストアフロント URL | ソースパラメーターをコピーするを参照してください。
    いいえ これにより、サイト環境設定が上書きされます。

    ソース URL パラメーターは、宛先 URL にコピーされません。宛先 URL パラメーターは指定どおりに使用されます。
    はい

    これにより、サイト環境設定が上書きされます。

    リクエストからのパラメーターが宛先 URL に追加されます。たとえばソース URL が /mens/shoes?affiliate_code=123 で、宛先 URL が /gents/shoes であり、「ソース URL パラメーターをコピーする」の設定がそのリダイレクトで有効になっている場合、実際の宛先 URL は /gents/shoes?affiliate_code=123 となります。

    リクエストパラメーターがすでに宛先にあってはなりません。

    ID 識別子が対応している必要があります。たとえば、Productがソースとして構成され、Categoryが宛先として構成されている場合、pidとcgidは元の要求からコピーされません。代わりに、宛先 URL パラメーターが使用されます。

    ストアフロント URL 環境設定の有効化を参照してください。

  9. リダイレクトを一時的にするか、永久にするかを選択します。
    永久 (301) リダイレクト リダイレクトソースの SEO の信頼性およびランキングが保持されます。検索エンジンがリダイレクトを認識するまでに時間がかかることもありますが、通常、ランキングが下がってもすぐに回復します。永久リダイレクトは削除されません。
    検出/一時的 (302) リダイレクト 302 リダイレクトは、新しい URL に永久的に移動されたコンテンツの SEO ランキングを保持するために使用します。302 リダイレクトでは、リダイレクトソースの SEO の信頼性およびランキングが保持されません。新しいページで同じランキングと信頼が蓄積されるまで、そのページのSEOランキングは下がることが予想されます。302 リダイレクトは、新しい URL が元の URL と同じランキングと信頼を蓄積した時点で削除されるため、一時的となります。古い URL がコンテンツへのアクセスに再び使用されることは想定されていません。たとえば、302 リダイレクトは、カテゴリ名を変更した場合に使用します。B2C Commerce では一時的なリダイレクトがキャッシュされますが、ブラウザーではキャッシュされません。
    一時的 (307) リダイレクト 307 リダイレクトは、現在メンテナンス中だが間もなく利用可能になる URL の、本当に一時的なリダイレクトとして使用されます。307 リダイレクトでは、リダイレクトソースの SEO の信頼性およびランキングが保持されません。新しいページで同じランキングと信頼が蓄積されるまで、そのページのSEOランキングは下がることが予想されます。一時的なリダイレクトは、後で削除されることを意図しています。B2C Commerce では一時的なリダイレクトがキャッシュされますが、ブラウザーではキャッシュされません。元のコンテンツを一時的に削除して古い URL に戻す場合は、307 リダイレクトを使用します。たとえば、記事やマイクロサイトを編集または更新のために削除し、すぐに利用できるようにする場合が考えられます。
  10. 追加 URL パラメーター (URL 宛先タイプを選択した場合) に URL の最後に追加したいパラメーターを、表示したい形式で入力します。例:
    &cgid=womens-accessories-scarves&prefn1=displaySiz
    特殊文字は、URL に付加される前にエンコードされます。エントリの始めに ? または & を追加しないでください。これらの文字は自動的に追加されます。
  11. 適用をクリックします。
メモ 有効な宛先が設定されていないリダイレクトがないか定期的にチェックすることをお勧めします。これを行うには、URL リダイレクトページの詳細検索で無効な URL を検索をクリックします。

B2C Commerce の URL 正規化タグの作成

正規 URL は、検索エンジン最適化の一環として Web ページの「正規の」または「優先する」バージョンを指定することで、重複するコンテンツの問題を防止します。検索エンジンは通常、重複していると見られるページのランキングを下げます。ページに正規 URL が設定されていると示すことは、ランキングの保持に役立ちます。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce SiteGenesis と Salesforce リファレンスアーキテクチャ (SFRA)

  • 複数の URL から 正規 URL への 301 リダイレクト。たとえば、www.test.com、test.com、および www.example.com/index.html に example.com/home.asp への 301 リダイレクトが設定されている場合、example.com/home.asp は正規 URL になります。
  • URL 正規化タグを、複数のページのヘッダーに含める。たとえば、test.com および www.example.com/index.html のヘッダーに example.com/home.asp への URL 正規化タグが設定されている場合、example.com/home.asp は正規 URL になります。

パイプライン URL の作成

パイプラインによって生成された URL に最大 500 のエイリアスを作成します。

必要なエディション

使用可能なソリューション: B2C Commerce

"/" 文字を使用して、customer/accountやconsumers/cartなど、複数のパス要素をもつパイプラインエイリアスを作成します。新規エイリアスフィールドに、たとえばCart-Show パイプラインの consumers/cartを入力します。このパイプラインが呼び出され、選択された地域情報の地域情報マッピングがus の場合は .../us/consumers/cartになります。

パイプラインエイリアスには、予約されたキーワードは使用できません。

メモ 予約されたキーワードには dw、_dw、h、_h、n、または _n が含まれます。

SEO URL の構成を参照してください。

カテゴリ ID と検索の絞り込みなしに Search-Show パイプラインに対して作成された URL は、検索絞り込み URL でのみサポートされています。たとえば、search/abrand/blue などです。この機能は Search-ShowContent パイプラインでも使用できます。たとえば、searchcontent/history などです。

カテゴリ (またはフォルダー) の ID がない場合は、パイプラインのエイリアスSearch-Show (またはSearch-ShowContent ) を URL パスから除外します。これにより、www.my-host.com/search/brand/black|blue/ の代わりに www.my-host.com/brand/black|blue/ のような URL を作成できるようになります

SEO URL の設定タブの使用を参照してください。

  1. アプリケーションランチャーの順にクリックし、マーチャントツール | サイト | SEO & 検出可能性 | URL ルールの順に選択します。
    URL ルールページの全般タブではなく、検索のサポートの環境設定ページが表示される場合は、マーチャントツール | サイト | サイト環境設定 | ストアフロント URLの順に選択して、URL ルールモジュールを有効にします。
  2. パイプライン URL タブをクリックします。
  3. エイリアスにスラッシュが含まれている場合に末尾にスラッシュを付加するには、パイプライン URL の最後にスラッシュを付加するを有効にします。
    これは、自動リダイレクトが発生するかどうかに関係なく構成します。末尾のスラッシュと自動リダイレクトはデフォルトで無効になっています。

B2C Commerce でのクロスサイトリクエストフォージェリ (CSRF)

各ストアフロントには、高レベルのセキュリティ保護を必要とする、保護されたリクエストがいくつかあります。通常これらのリクエストは、認証済みの買い物客がアカウントを変更する場合や、操作を完了するためにサーバーに個人データを送信する場合に実行されます。ユーザーは、これらのリクエストは自分がリクエストを開始した場合にのみ行われると考えています。

クロスサイトリクエストフォージェリ (CSRF) は、その期待を裏切ります。これは、ユーザーのブラウザを騙して、本人が知らないうちに、ユーザーの認証を得て、この保護されたリクエストを行うように仕向けます。Salesforce B2C Commerce には CSRF 保護ソフトウェアライブラリがあり、デベロッパーはこの攻撃からリクエストを保護できます。

CSRF 保護 API は、ユーザーの現在のセッションに関連付けられたランダムなチャレンジトークンを要求する Synchronizer Token パターンを使用します。ユーザーがページからコンテンツを送信すると、サーバーはそのトークンを検索して検証します。トークンの検証に失敗すると、サーバーは要求を拒否します。

機密な業務では、必要なセキュリティトークンを HTTP リクエストに含めることで、CSRF 攻撃を緩和できます。これは、攻撃に成功するには、特定のセッションに対しランダムに生成されたトークンを攻撃者が把握する必要があるからです。

dw.web.CSRFProtectionクラスはこの API を公開し、以下のメソッドを含みます。

  • getTokenName(): CSRF トークンにマッピングする文字列として、予想されるパラメーター名を返します。
  • generateToken(): 現在のユーザーに対してトークン文字列を安全に生成します。トークンは generateToken の呼び出しごとに一意になります。
  • validateRequest(): ユーザーの現在のリクエストを検討して、有効な CSRF トークンがリクエストに含まれているかどうかを判定します。トークンは、このユーザーのセッションに対して過去 60 分間以内に生成された場合に有効です。

次に、Internet Store Markup Language (ISML) 内のフォームの例を示します。このフォームでは、CSRF フレームワークを使用してトークン パラメーター名と対応する値が挿入されます。 

<form action="/submit" method="post">
  ...
   <input name="${dw.web.CSRFProtection.getTokenName()}" value="${dw.web.CSRFProtection.generateToken()"> 
</form>

次に、関数のボディで直接 CSRFProtection.validateRequest() を呼び出すか、ミドルウェアの実装を使用して CSRF トークンを検証します。

SiteGenesis JavaScript コントローラーでの CSRF のベストプラクティスは、特定のフォームアクションを処理する際に CSRFProtection.validateRequest() を含めることです。すべてのアクションでデータが送信され、CSRF 保護が必要とされるわけではないので、これはアクションに特定になります。

B2C Commerce でのクロスサイトスクリプティング

クロスサイトスクリプティング (XSS) を使用すると、攻撃者は、ターゲットとなるユーザーが表示している Web ページにクライアント側の JavaScript を注入できます。コンテンツの操作による悪意をもった攻撃を防止するには、すべてのユーザーが提供するコンテンツを適切にエンコードする必要があります。

たとえば、ユーザーが入力したデータを処理する際には、Salesforce B2C Commerce Internet Store Markup Language (ISML) テンプレートとスクリプト API の使用方法に注意します。

ISML テンプレートには、変数値を表示する方法が 2 つあります。${...} を使用し、省略記号を表示する変数に置き換えることができます。または <isprint> タグを使用できます。

ISML テンプレートで ${pdict.ProductSearchResult.searchPhrase} などのスクリプト式を使用して、コンテンツタイプを以下のように設定すると、スクリプトの結果は自動的に HTML エンコードされます。

<iscontent type="text/html" charset="UTF-8" compact="true">...</iscontent>

ただし、同じ式を <isinclude template="> によって含められた ISML テンプレートで使用し、含められた ISML スニペットでコンテンツタイプを設定しないと、B2C Commerce ではコンテンツタイプが text/plain だとみなされ、HTML エンコードは行われません。これは一貫性がなく、XSS の問題につながる可能性があります。

これを修正するには、コンテンツタイプを明示的に設定するか、<isprint value="{}"/>を使用して、結果の HTML がエンコードされるようにする必要があります。

以下に、安全ではない <isprint> タグの例を示します。

<isprint value="${pdict.ProductSearchResult.searchPhrase}"/>

シナリオでは HTML エンコードは使用しないでください。isprint タグは、ユーザーが入力したデータをエンコードするエンコード属性をもっています。以下に、<isprint> タグを安全に使用する例をあげます。

<isprint value="${pdict.ProductSearchResult.searchPhrase}" encoding="jshtml"/>

まとめていうと、それぞれの設計された状況に適したエンコードを使用してください。

サイト速度の向上

顧客により良いオンラインショッピング体験を提供したいとお考えの場合は、Web ストアの速度向上をご検討ください。これらの速度最適化機能により、ストアフロントの読み込みが速くなるため、顧客は待ち時間を減らして閲覧する時間を増やすことができます。

最初のバイトまでの時間 (TTFB)

最初のバイトまでの時間 (TTFB) は、リソースのリクエストからレスポンスの最初のバイトが到着し始めるまでの時間を測定するメトリクスです。これらのリクエストフェーズは TTFB を表します。

  • リダイレクト時間
  • Service Worker の起動時間 (該当する場合)
  • DNS ルックアップ
  • 接続とトランスポート層セキュリティ (TLS) ネゴシエーション
  • レスポンスの最初のバイトが到着するまでのリクエスト

接続のセットアップ時間とバックエンドのレイテンシーを短縮することで、TTFB を短縮できます。

Argo

コンテンツ配信ネットワーク (CDN) 機能である Argo は、ルーティングの決定を分析および最適化します。顧客がストアフロントを訪問する場合、顧客のマシンと eCDN、そして最終的にはオリジンサーバーとの間に多くのホップが存在します。Argo は、eCDN に到達するための最適なルートを見つけるのに役立ちます。ARGO を導入して以来、顧客は平均 20〜30% の改善を経験しています。Argo Smart Routing は、CDN ネットワークを通過する各リクエストから収集されたレイテンシーとパケットロスデータを使用し、インターネット上の最適なパスを特定します。Argo は B2C Commerce CDN の一部として実装されています。

Early Hints

Early Hints は、Web サイトの読み込みを高速化するのに役立つ HTTP ステータスコード (103 Early Hints) です。読み込み速度を上げるために、アーリーヒントは、最終的なコンテンツの準備が整う前に、ページのプレビューをブラウザーに送信します。これにより、ブラウザーは、サーバーが残りの部分を生成するのを待っている間に、ページのプリロードを開始できます。Early Hints は、ページの読み込み時間を短縮し、ユーザーが感じる遅延を軽減するのに役立ちます。

B2C Commerce の eCDN はエンドユーザーの近くに配置されているため、アーリーヒントを迅速に配信できます。早期配信により、サーバーがページを生成するのにかかる時間が大幅に短縮されます。eCDN は、顧客のブラウザーがリクエストを行った時点からブラウザーが早期ヒントを受信するまで、Time to First Byte を追跡します。TTFB が速くなると、パフォーマンスが最適化され、ユーザーの満足度が向上します。

Early Hints を使用すると、Web ストアのパフォーマンスを向上させ、ユーザーのエクスペリエンスを向上させることができます。

HTTP/2 からオリジン

HTTP/2 からオリジンは、eCDN とオリジン間で HTTP/2 プロトコルを使用し、両者間のパフォーマンスを向上させます。HTTP は、時間の経過とともに進化してきた一般的なプロトコルです。各バージョンには、パフォーマンスを向上させる新機能が追加されています。HTTP/1.1 と HTTP/2 は、どちらも今日のインターネットで広く使用されています。HTTP/1.1 は以前から存在していましたが、2015 年に Internet Engineering Task Force がページの読み込み時間を短縮する HTTP/2 を導入しました。

この設定は、オリジンが HTTP/2 をサポートしている場合にのみ有効です。HTTP/2 には下位互換性があります。サポートされていない場合、eCDN は HTTP/1 を使用します。

HTTP/3

HTTP/3 は、トランスポートプロトコルとして Quick UPD Internet Connections (QUIC) を使用するハイパーテキスト転送プロトコルのバージョンです。QUIC は、伝送制御プロトコル (TCP) よりも高速で、迅速なネットワーク切り替えをサポートするユーザーデータグラムプロトコル (UDP) を使用します。このアプローチにより、高トランザクション接続の速度を低下させる可能性のあるヘッドオブラインブロッキングが軽減されます。また、QUIC はレイヤー 4 のトランスポート接続をレイヤー 3 の IP フローから分離し、ネットワーク間の移行を改善します。ネットワークパケットの損失や順序変更により、多くのトランザクションがある接続が遅くなる可能性があります。

QUIC は、今日のインターネットの使用方法に適しています。これは、ネットワーク間を頻繁に切り替える電話やその他のモバイルデバイス向けに設計されています。元のインターネットプロトコルは、デバイスの携帯性がそれほど高くなく、ネットワークの切り替えもそれほど頻繁に行われなかった時代に開発されました。

Brotli

Brotli 圧縮は、HTML、CSS、JS、JSON などの静的テキストベースの Web アセットの配信を改善します。これを実現するために、ペイロードサイズを縮小し、より迅速な配送を実現します。

Brotliは推奨される圧縮アルゴリズムであり、HTTPリクエストヘッダー「Accept-Encoding」に「br」が存在する場合に使用されます。gzip レスポンスを保証するには、「Accept-Encoding」ヘッダーを「gzip」に設定します。ヘッダーにすべてのオプション (gzip、br、zstd) が含まれている場合、eCDN は Brotli を優先します。

Brotli が無効になっている場合、eCDN はデフォルトで自動圧縮を使用します。このモードでは、訪問者のブラウザーサポートと CDN プロバイダーの変化する設定に基づいて、最適なアルゴリズムが選択されます。

B2C Commerce では、ページ専用値、カテゴリ値、またはデフォルト値で設定できる継承 URL 属性値を複数レイヤーで使用できます。URL ルールモジュールが有効な場合、URL が割り当てられます。

画像変換 URL の構造、検証、および操作の順序

画像変換要求では、/dw/image/v2/ パスとクエリ文字列が使用されます。B2C Commerce Dynamic Imaging Service では、これらのパラメーターが一定の順序で適用されます。

変換タイプ、パラメーター名、JavaScript 変換オブジェクト、および検証の詳細については、サポートされている変換の表を使用してください。このトピックでは、パスの形状、操作の順序、および出力形式と URL の関係についてのみ説明します。

パスマーカー

変換された画像 URL では、パスセグメント/dw/image/v2/と通常の静的コンテンツパスが使用されます (例: on/demandware.static/... )。ハブのDynamic Imaging Service トピック にあるように、Dynamic Imaging Service のURLUtilsクラスとMediaFileクラスを使用して URL を作成します。

出力形式とファイル拡張子

生成された URL のファイル拡張子 ( .webpや.avifなど) によって、出力形式が選択されます。sfrmパラメーターは、必要に応じて、ソース・イメージ・フォーマットを指定できます。「サポートされている変換」の「形式」行を参照してください。

操作の順序

1 つの要求に複数の変換の種類が適用される場合、Dynamic Imaging Service はそれらを次の順序で処理します。切り抜きと拡大縮小を組み合わせる場合は、サービスが最初に切り抜きを適用してから結果を拡大縮小するため、元のソース画像で切り抜きを計画します。

  1. 形式 (指定されている場合)
  2. 背景色 ( bgcolor )、使用されている場所で透明度を平坦化します。
  3. クロップ( cx、cy、cw、ch )
  4. サイズ変更/拡大縮小モード( sw、sh、sm )
  5. オーバーレイ( ox、oy、oimg )
  6. 品質 ( q )
  7. メタデータ ストリップ ( strip)

400 応答の一般的な原因

  • 同じ URL に重複するパラメーター ( ?sw=100&sw=200 )。最後の値が優先され、論理エラーをマスクできます。

コンテンツアセット ストアフロントのコンテンツアセットを追加したり、削除したりします。コンテンツアセットは、ストアフロント向けの画像および非商品ページです。
キャンペーンおよびプロモーション 売上を増加させるために、特定の顧客を対象としたキャンペーンおよびプロモーションを作成します。キャンペーンとプロモーションによってサイトのストアフロントの画像と割引を結び付けます。
コンテンツスロット コンテンツスロットを設定して、画像やテキストをスケジュールに基づいて表示したり、永続的に表示したりします。コンテンツスロットは、特定のコンテンツアセット専用のサイトのレルムです。たとえば、すべてのカテゴリページに、そのカテゴリのお買い得商品専用のコンテンツスロットを設定できます。
B2C Commerce Einstein 人工知能を採用した商品のおすすめと予測型並べ替えのためのツールを設定します。このツールによって、買い物客の興味に関するデータに基づいて、検索結果をカスタマイズし、並べ替えることができます。
ギフト券 ギフト券を発行したり、ギフト券のレポートを表示したりします。
顧客 キャンペーンおよびプロモーションの対象となる顧客グループを特定します。
検索 ストアフロントのカテゴリナビゲーションを設定します。ストアフロントのキーワード検索の作成やトラブルシューティングを行います。Google や Yahoo といった主要な検索エンジンの検索ランクにおいて、自社商品の位置を最適化します。
検索エンジンの最適化 (SEO) サイトを最適化するために、検索エンジンの最適化設定を構成します。外部検索エンジンでのオーガニック (無料の) 検索結果を最適化するために、サイトマップ設定を構成します。
注文 支払処理業者、支払方法、配送方法、および買い物カゴの持続性のオプションを構成します。
店舗の位置情報 店舗の位置情報の機能用に、店舗の郵便番号データを読み込みテストします。
Analytics 顧客がどのようにストアフロントを使用しているかを測定し、トラフィックパターン、顧客の購入、およびその他のレポートを分析します。
アクティブマーチャンダイジング 商品の傾向と収益性を測定します。
A/B テスト 最適なプロモーションとストアフロントレイアウトの戦略を決定します。

サイトをマーチャンダイジングする際の最優先事項は、カタログとカテゴリ構造を作成することです。これを決定するには、その他の考慮点に加え、ストアフロントのナビゲーションについて戦略的に考える必要があります。カテゴリ構造を構築すると、商品を設定できます。カテゴリ構造の構築については、サイト構造の構築を参照してください。

  • カタログ
    このトピックは、B2C Commerce に該当します。B2C Commerce では、商品データがカタログに保存されます。カタログとは、販売する商品を集め、異なるカテゴリに整理したものです。
  • B2C Commerce のカテゴリ
    カテゴリとサブカテゴリを作成および整理して、カタログとストアフロントで商品を整理およびグループ化します。たとえば、アウトドア用品のサイトでは、ブーツ、クライミング用品、アウターウェアのカテゴリを使用して、ストアフロントで商品を整理できます。このトピックは、B2C Commerce に該当します。
  • B2C Commerce の商品
    商品とは、販売する品目やサービスです。B2C Commerce では、すべての商品データがマスターカタログに保存されます。マスターカタログはストアフロントカタログとすることもできます。または、独立したストアフロントカタログを作成することもできます。カタログはカテゴリで編成します。カテゴリは、ストアフロントでの商品へのナビゲーションとしての役割を果たします。ストアフロントに商品やサービスを表示するには、カテゴリに割り当てます。ビジネスニーズに合わせて、カタログ、カテゴリ、および商品シナリオをいくつでも作成できます。このトピックは、B2C Commerce に該当します。
  • B2C Commerce の推奨項目
    B2C Commerce を使用し、さまざまなアプローチで推奨項目を実装します。
  • B2C Commerce の Page Designer
    Page Designer は B2C Commerce の機能で、再利用可能なページタイプとコンポーネントタイプを作成するための、標準的な開発プロセスとツールをサポートしています。マーチャントは Business Manager のビジュアルエディターを使用し、ページタイプやコンポーネントタイプをドラッグすることで、ストアフロントのカスタムページをデザイン、スケジュール、公開できます。
  • コンテンツブロック
    コンテンツブロックは、Page Designer で作成し、Business Manager のコンテンツブロックモジュールを使用して一元管理する、モジュール式の再利用可能なコンテンツ単位です。
  • B2C Commerce のキャンペーンとプロモーション
    Business Manager のオンラインマーケティングモジュールで、プロモーション、コンテンツスロット、並べ替えルールなどの体験を含むラッパーの役割を果たすキャンペーンと A/B テストを作成します。ただし、スロットの設定と並べ替えルールを有効にするために、キャンペーンや A/B テストへの割り当ては必要ありません。スロットの設定は、A/B テストの範囲外でスケジュールできます。デフォルトの並べ替えルールは、キャンペーンまたは A/B テストの範囲外で、ストアフロントカタログのカテゴリに設定できます。このトピックは、B2C Commerce に該当します。
  • ギフト券
    買い物客がストアフロントで使用するギフト券を作成します。買い物客は、ギフト券を購入して受取人に Eメールで送信したり、ギフト券を支払方法として使用したり、ギフト券の残高を確認したりできます。ギフトカードの作成、ギフト券の統計のレポート、およびギフト券のインポートとエクスポートを行います。ギフトカードはプログラムによって処理することもできます。詳細については、B2C Commerce API のドキュメンテーションを参照してください。
  • B2C Commerce の検索とナビゲーション
    B2C Commerce を使用して、サイト内や Google などの外部検索エンジンから顧客による商品の検索方法を制御できます。
  • B2C Commerce の注文
    Business Manager を使用して、B2C Commerce サイトの注文処理に関する要件の多くを管理できます。たとえば、注文情報と支払情報の変更、注文属性の編集、注文レコードへのメモの追加、注文のステータスを確認するための Eメールの送信、注文のキャンセル、注文のエクスポートが可能です。
  • B2C Commerce の複数通貨のサイト
    Salesforce B2C Commerce の複数通貨のサイト機能によって、複数の国や地域で商品を販売できます。この機能を利用することで、顧客が好みの通貨で商品の検索や注文手続きを行うことが可能になります。
  • Analytics
    B2C Commerce Reports & Dashboards アプリは、レルムのデータを収集、分析してまとめ、ダッシュボードという論理的なデータセットに整理します。Reports & Dashboards ポータルを使用して、サイトの売上、商品、プロモーション、テクニカル、トラフィックなどのデータを確認します。各ダッシュボードには、経時的なトレンドを特定する助けとなるアナリティクスが表示されます。
  • B2C Commerce でのバッチ処理
    カタログ、カテゴリ、顧客、商品に関する特定の Business Manager タスクでは、バッチ処理を使用します。
