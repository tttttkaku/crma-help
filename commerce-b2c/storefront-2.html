B2C Commerce でのコンテンツのプレビュー

ストアフロントのコンテンツをプレビューするには、Storefront Toolkit を使用します。Sandbox (サンドボックス)、Development (開発)、Staging (ステージング) の各インスタンスでは、ストアフロントの左上隅にこのツールが表示されます。このトピックは、B2C Commerce に該当します。

Storefront Toolkit を使用して、コンテンツスロット内のコンテンツをプレビューします。ただし、どのコンテンツが表示されるかを判断するために、Salesforce B2C Commerce ではコンテンツスロットのアクティブなスロットの設定がチェックされます。1 つのコンテンツスロットに複数のスロットの設定を適応したり、それぞれのスロットの設定で異なるコンテンツを指定したりできるため、コンテンツをプレビューする前に、アクティブにする構成を変更しておくことをお勧めします。

アクティブにするスロット設定を制御するには、Storefront Toolkit の Site Preview Controls (サイトプレビューコントロール) ウィンドウを使用します。このウィンドウを使用して、ストアフロントセッションの有効な日付/時刻を変更します。スロットの設定はスケジュールに基づいており、ストアフロントのセッションの日時がスロットの設定のスケジュール範囲内にない限り、B2C Commerce ではスロットの設定が無視されるため、これは重要です。

メモ

各コンテンツスロットに任意でデフォルトのスロット設定を設定できます。デフォルトは他のスロット設定がスケジュールされていない間に使用されます。

Site Preview Controls ウィンドウで、アクティブなソースコードを変更または削除するには、Source code フィールドの値を編集します。この値によって、ストアフロントセッションのアクティブなソースコードが決まります。この値を設定すると、ページタイトルが、上書きされた日付と時刻で書き換えられます。

  • 無効にされたソースコードで、サイトをプレビューすることはできません。
  • サイトのプレビューの日付/時刻をソースコードのアクティブ期間に適合するように設定して、非アクティブなソースコードでサイトをプレビューします。

必要なエディション

Salesforce Payments B2C Commerce ストアフロント設定

ストアフロントの支払体験を構成するには、Business Manager で B2C Commerce 用の Payments モジュールを使用します。エクスプレスチェックアウトと複数ステップ支払方法、および各方法の支払サービスを選択します。

  • B2C Commerce の支払方法
    Salesforce Payments では、ストアフロントで買い物客にチェックアウト、エクスプレスチェックアウト、またはその両方の支払方法を提供できます。チェックアウトを提供すると、買い物客は Afterpay、Amazon Pay、Bancontact、クレジットカード、EPS、iDEAL、Klarna、PayPal、SEPA Debit、TWINT、Venmo を使用して商品を購入できます。エクスプレスチェックアウトを提供する場合、買い物客はAmazon Pay、Apple Pay、Google Pay、PayPal、Venmoを使用して商品を購入できます。
  • B2C Commerce における PayPal での Venmo の使用
    Salesforce Payments は、エクスプレスおよび複数ステップチェックアウト方法として、Venmo をサポートします。Venmo では、クレジットカード、デビットカード、銀行振替、または Venmo の資金銀行にリンクしたデジタルウォレットの支払オプションを買い物客に提供できます。Salesforce Reference Architecture (SFRA) ストアフロントで Venmo を使用するには、Salesforce Payments で PayPal インテグレーションが行わていることが必要です。この機能は、B2C Commerce に該当します。
  • B2C Commerce の「今すぐ購入」と「今すぐ支払う」の注文手続き方法
    Salesforce Payments にはエクスプレスチェックアウトの体験として、2 つの方法が用意されています。「今すぐ購入」と「今すぐ支払う」です。「今すぐ支払う」では現在の買い物客の買い物カゴが必要であるのに対し、「今すぐ購入」では現在の買い物カゴは無視されます。
  • B2C Commerce の後払い決済サービス
    B2C Commerce の後払い決済 (Buy Now, Pay Later) の支払オプションを使用すると、買い物客はすべての価格帯の商品を便利に購入できるようになります。Salesforce Payments では、Klarna と AfterPay を通じて後払い決済サービスを提供しています。
  • 保存された支払方法を使用した注文の自動作成
    トークンに保存された支払情報を再使用して、セッション外トランザクションで自動的に注文を作成するようにサイトを設定します。セッション外トランザクションでは、購入者が購入を完了するためにオンラインである必要はありません。サイトではセッション外トークンを使用して、サブスクリプションや分割払いといった定期的な支払いが発生する注文や、ワンクリックによる再注文などを自動化できます。
  • B2C Commerce 向け Adyen 支払の検証
    B2C Commerce インスタンスのテストまたはライブの Adyen マーチャントアカウントで、テスト支払を設定して検証します。B2C Commerce インスタンスに関連付けられている Adyen マーチャントアカウントを使用して、テスト支払を作成します。
  • B2C Commerce 向け Stripe 支払の検証
    B2C Commerce インスタンスのテストまたはライブの Stripe マーチャントアカウントで、テスト支払を設定して検証します。B2C Commerce インスタンスに関連付けられている Stripe マーチャントアカウントを使用して、テスト支払を作成します。
  • PayPal 構成のテスト
    PayPal マーチャントアカウントを Salesforce Payments に統合し、PayPal マーチャントアカウントをサイトに追加したら、Sandbox で構成をテストします。
  • PayPal 資金の支払
    PayPal が実装された Salesforce Payments では、キャプチャと資金の支払が即時に行われます。たとえば、買い物客が買い物カゴの注文手続きを完了し、注文が承認されると、その買い物客の支払は即時にキャプチャされ、マーチャントに支払われます。

拡張チャットへのメッセージングコンポーネントの追加

Commerce Messaging Components (CMC) は、チャットウィンドウ内の JSON 出力を変換して、買い物客とエージェント間のインタラクションを円滑にします。メッセージングバブルコンポーネントを追加するには、必要なコンポーネントを Salesforce 組織にアップロードします。

アダプティブレスポンスを無効にして、エージェントがこのメッセージングコンポーネントを使用するようにします。メッセージングコンポーネントのアダプティブレスポンスの無効化を参照してください。

  1. GitHub で、commerce-on-lightning-components リポジトリをシステム上のローカルディレクトリにクローンします。
  2. コマンドウィンドウを開き、ローカルディレクトリに移動して、miaw-messaging-release ブランチに切り替えます。
  3. メッセージングコンポーネントを Salesforce 組織にデプロイします。Lightning Web コンポーネントのデプロイを参照してください。
  4. CMC を使用するように拡張チャットを構成します。
    1. Salesforce 組織で、ページ上部のをクリックし、設定を選択します。
    2. 「クイック検索」ボックスで、組み込みサービスリリースを見つけて選択します。
    3. リリースのリストから、変更したいリリースを選択します。
    4. 「カスタム UI コンポーネント」タイルで、カスタムコンポーネントを追加をクリックします。
    5. 「ヘッダー」で commerceHeader を選択します。
    6. 「テキストメッセージバブル」で dynamicContentRenderer を選択します。
  5. 変更内容を保存します。
  6. リリースを公開します。

Salesforce Reference Architecture (SFRA) ストアフロントの会話コンテキストの有効化

SFRA ストアフロントで会話コンテキストを有効にするには、カスタムショッパーエージェント変数を修正して、会話コンテキスト用の環境変数を含めます。

  1. Business Manager で、マーチャントツール | カスタム環境設定 | サイト環境設定 | ショッパーエージェントの順に移動します。
  2. 会話コンテキストの有効化がはいに設定されていることを確認します。
  3. 会話コンテキストに、メッセージングの会話が開始されたときに買い物客に表示されるピルを定義する文字列を最大 3 つ入力します。
    最大 3 つの文字列を指定すると、メッセージングウィンドウで最も見やすい結果が得られます。
  4. 変更内容を保存します。

SFRA ストアフロント向けショッパーエージェントカートリッジのインストール

SFRA (Storefront Reference Architecture) を使用してストアフロントを開発する場合は、エージェントの実行に必要な SFRA カートリッジをインストールします。

  1. GitHub のSalesforce Commerce リポジトリにアクセスできることを確認します。
  2. plugin_shopper_agent リポジトリをクローンします。
  3. plugin_shopper_agent ディレクトリから、コマンド npm install を使用して Node Package Manager (NPM) の依存関係をインストールします。
    SFRA は npm によって管理されるモジュールに依存します。
  4. plugin_shopper_agent ディレクトリに戻り、dw.json 構成ファイルを開きます。
  5. dw.json 構成ファイルで、ホスト名、ユーザー名、パスワード、およびコードのバージョンを編集します。ファイルが存在しない場合は、作成します。
    dw.json ファイルはサーバー接続と、カートリッジをアップロードするコードのバージョンを確立します。コードのバージョンは、Business Manager の SFRA デプロイメントと一致している必要があります。確認するには、管理 | サイトの開発 | コードのデプロイの順に選択します。
    "hostname": "HOST.salesforce.com",
"username": "USERNAME",
"password": "WEBDAV_ACCESS_KEY",
"code-version": "CODE_VERSION"
  6. npm run uploadCartridge コマンドを使用してカートリッジをアップロードします。
  7. Business Manager でカートリッジのパスを設定します。
    1. app_storefront_base カートリッジをインストールします。
    2. 管理 | サイト | サイトの管理の順に選択し、自分のサイトを選択します。
    3. 「設定」タブで、カートリッジのパス名を更新します。たとえば、plugin_shopper_agent:app_storefront_base です。
    4. 変更内容を保存します。

SFRA ストアフロントで Shopper Agent を起動する場所を選択します

訪問者が SFRA ストアフロントで Shopper Agent にアクセスできる場所を調整します。複数の起動場所を有効にすることで、買い物客はサイトを閲覧、検索、またはナビゲートするときに AI を活用したサポートに簡単にアクセスできます。

  1. SFRA ストアフロントの plugin-shopper-agent カートリッジを再デプロイし、Salesforce Commerce リポジトリに移動して、SFRA ストアフロントの plugin-shopper-agent カートリッジを再デプロイします。
  2. Business Manager にログインします。
  3. マーチャントツール | サイト環境設定 | カスタム環境設定の順に移動します。
  4. カスタムグループリストから、Shopper Agent を選択します。
  5. 「買い物客エージェントを有効にする」をオンにして、Commerce 組織 ID を入力します。
  6. 使用する起動場所を選択します。
    サイトのヘッダーナビゲーションにアイコンを追加します (1)。買い物客が検索中にエージェントにアクセスできるようにします (2)。各ストアフロントページの下部にフローティングアイコンを表示します (3)。このストアフロントページの例には、3 つのオプションがすべて表示されています。
  7. 変更内容を保存します。

カスタムメッセージングコンポーネントへの地域情報の追加

カスタム・メッセージング・コンポーネントの翻訳サポートを拡張するには、独自の地域情報を追加します。地域情報を追加すると、静的テキストが買い物客の優先言語で表示されます。

コンポーネントの labels.js ファイルに地域情報を追加します

  1. force-app/main/default/lwc/yourComponent/labels.js に移動します。
  2. labels.js ファイルを開き、新しい言語コードと翻訳をそれぞれ追加します。
    LABEL_DATA オブジェクトの各ラベルについて、新しい地域情報コードと対応する翻訳を含めます。

    ドイツ語 (de) を追加する方法の例を次に示します。

     export const LABEL_DATA = {
  YourComponent_buttonLabel: {
   'en_US': 'Submit',
   'en_GB': 'Submit',
   'es': 'Enviar',
   'fr': 'Soumettre',
   'de': 'Einreichen', // Added new language
  },
  YourComponent_cancelLabel: {
   'en_US': 'Cancel',
   'en_GB': 'Cancel',
   'es': 'Cancelar',
   'fr': 
    'Annuler',
   'de': 'Abbrechen', // Added new language
  },
  // Continue for all labels
 };
  3. すべてのラベルに、新しい言語コードのエントリが含まれていることを確認します。
    欠落している翻訳は en_US に戻ります。
  4. コンポーネントをデプロイし、メッセージングチャネル用の組み込みサービスリリースを公開します。

Salesforce Reference Architecture (SFRA) ストアフロントの地域情報の追加

Shopper Agent でまだサポートされていない地域情報と通貨を追加するには、地域情報と通貨を追加し、関連するカスタムメッセージング設定を追加します。会話コンテキストを有効にすると、静的会話コンテキストピルに、ストアフロントのアクティブな地域情報に対応するローカライズされたラベルが表示されます。

  1. Business Manager で、サイト環境設定 | 地域情報の順に選択します。
  2. 新しい地域情報を構成し、エージェントでサポートする利用可能な地域情報のリストに追加します。
  3. 通貨で、新しい地域情報の通貨を選択します。

SFRA ストアフロントの買い物客エージェントの設定

B2C SFRA ストアフロント用に Shopper Agent を設定するには、plugin_shopper_agentカートリッジを取り付け、Shopper Agent 機能を構成します。これらのタスクは Git と B2C Commerce インスタンスの両方で行います。

プラグインカートリッジを取り付ける前に、以下を行います。

  • Salesforce 組織で拡張チャットをセットアップし、チャネルをショッピングエージェントに接続します。
  • ハイブリッド認証 (ハイブリッド認証) を設定します。手順については、ハイブリッド認証を参照してください。[Site Settings (サイトの設定)] で、[Hybrid Auth (ハイブリッド認証)]、[Shopper Context (買い物客のコンテキスト)]、[Do-Not-Track Synchronization (追跡拒否の同期)]、および [HttpOnly True] を有効にします。

    B2C Commerce バージョン 25.3 以降、ハイブリッド認証はプラグイン SLAS カートリッジオプションに置き換わり、パフォーマンスが向上しています。

  • SFRA ストアフロント向けショッパーエージェントカートリッジのインストール
    SFRA (Storefront Reference Architecture) を使用してストアフロントを開発する場合は、エージェントの実行に必要な SFRA カートリッジをインストールします。
  • SFRA ストアの買い物客エージェントに対する Apple Pay と Google Pay の設定
    B2C Commerce の買い物客が Shopper Agent で直接購入を完了できるようにします。Adyen は Salesforce Payments で Apple Pay と Google Pay をサポートしています。
  • SFRA 店舗での買い物客エージェントのアクションの入力と出力

  • Salesforce Reference Architecture (SFRA) ストアフロントのカスタムメタデータのインポート
    SFRA ストアフロントでは、サイト固有の商品属性に対して特定のインポートとエクスポート処理が必要です。最良の結果を得るため、このデータは手動でインポートします。

    ストアフロントの商品ページにライブチャットボタンを表示するには、組み込みサービスリリースのコードスニペットをサイト環境設定に追加します。コードスニペットは、メッセージングチャネルを設定すると自動的に生成されます。
  • SFRA ストアフロントで Shopper Agent を起動する場所を選択します
    訪問者が SFRA ストアフロントで Shopper Agent にアクセスできる場所を調整します。複数の起動場所を有効にすることで、買い物客はサイトを閲覧、検索、またはナビゲートするときに AI を活用したサポートに簡単にアクセスできます。
  • SFRA ストアフロントの買い物客エージェント分析の収集
    Commerce Reports & Dashboards では、B2C Shopper Agent に直接起因する SFRA ストアフロントの収益と注文を視覚的に追跡できます。これらのメトリクスは、エージェントの投資収益率を見積もるのに役立ちます。ダッシュボードのエージェントフィルターを使用すると、ホームページ、売上、商品、プロモーションの各ビューで、買い物客エージェントの関与がある場合と関与していない場合にメトリクスを比較できます。

B2C Commerce のサイトとストアフロント

B2C Commerce では、サイトとは、ストアフロントを実行するアプリケーションと関連するコードです。ストアフロントとは、ユーザーのオンライン体験のことです。サイトは、異なるブランド、地域情報 (通貨と税金が異なる)、または複数のチャネルに応じて、異なる URL をもつ複数のストアフロントをもつことができます。特定の URL を指す場合は、B2C Commerce ではストアフロントという用語を使用します。

サイトアーキテクチャのシナリオ

サイトを設計する際には、以下を考慮することが必要です。

  • ストアフロントと、ストアフロントを維持するチームの地理的関係
  • 商品データ、税金と支払いの情報、ユーザーの役割と許可、プロモーション、アプリケーションのコードなど、サイト間で共有されるデータ
  • 異なる市場の地域情報に合わせてストアフロントをローカライズまたは再構築する必要があるかどうか
  • 企業の構造や法的義務のために別々に管理されたままのデータ
  • 顧客、買い物カゴ、またはトランザクションデータを 1 つのストアフロントから次のストアフロントに引き継ぐかどうか。

    例: アパレルのリテーラーでは、顧客が大人用のサイトと子供用のサイトで同時にショッピングできるようにします。ただし、2 つの非常に異なる顧客ベースをもつリテーラー (たとえば、宗教関係の本とファンタジーフィクションの本を出版している出版会社の場合など) では、2 つのサイトで混同がないようにします。

1 つのサイト、1 つのストアフロント

もっともシンプルなシナリオでは、サイトが 1 つあり、このサイトで 1 つのストアフロントをサポートします。

1 つのサイト、複数のストアフロント

多数のストアフロントがあり、そのすべてのストアフロントを 1 つのチームで維持している場合、各サイトで商品が異なる場合でも、1 つのサイトとして管理した方が簡単です。同様に、複数のストアフロント間で買い物カゴを共有するには、これらのストアフロントが 1 つのサイトの一部であることが必要です。同様のブランディングと商品を含むローカライズされたサイトを多数デプロイする場合、新しいストアフロントを既存のサイトの拡張として管理した方が、管理の時間を節約でき簡単に管理できます。

複数のサイト、複数のストアフロント

複数のサイトがあり、各サイトが複数のストアフロントをサポートする場合です。また、顧客データなどのサイトデータを、サイト間で共有することもできます。

サイトの定義

ライブサイトとは、マーチャントの Business Manager の Production (本番) インスタンスで「サイトの管理」画面にリストされているサイトのうち、ステータスが「オンライン」に設定されているサイトのことです。他のステータスのサイトや削除されたサイトは含まれません。

B2C Commerce でのストアフロントのネットワークアクセス

ストアフロントへのネットワークアクセスを制限するために、B2C Commerce に付属の埋め込みコンテンツ配信ネットワーク (eCDN) を有効にします。組織で eCDN を有効にするには、Salesforce カスタマーサポートにお問い合わせください。

eCDN には、DoS 攻撃に対する保護を提供するために、Web アプリケーションファイアウォール (WAF) と IP ファイアウォールの機能が含まれています。eCDN は、ゾーンを使用して構成を整理します。eCDN を特定のゾーンに対して構成するか、すべてのゾーンに対してグローバルに構成します。

いずれの場合も、特定の IP アドレスと IP 範囲に対してファイアウォールの許可リストとブロックリストを構成できます。また、内部アルゴリズムを使用して計算される、訪問者の IP 評価を使用する IP セキュリティレベルを構成して、ユーザーがログインする前に Completely Automated Public Turing Test to tell Computers and Humans Apart (CAPTCHA) チャレンジへの回答を要求するかどうかを決定できます。CAPTCHA チャレンジは、特に自動化された攻撃に対して有用です。最高レベルのセキュリティでは、すべての訪問者は続行する前に CAPTCHA チャレンジに回答する必要があります。

eCDN WAF は HTTP/S トラフィックを分析および解釈して、ストアフロントを保護します。WAF は、コードレベルの脆弱性を悪用するアプリケーションレベルの攻撃を防止します。これらのタイプの攻撃には、クロスサイトスクリプティング (XSS) と SQL インジェクションがあります。

シミュレーション、チャレンジ、およびブロックのアクションモードを構成して、OWASP の脅威にどのように対応するかを決定できます。IP ファイアウォールの設定と同様、チャレンジアクションでは攻撃者であることが疑われるユーザーにストアフロントに進む前に CAPTCHA チャレンジが表示されます。

ストアフロントパスワードの保護とログイン

開発とテスト中に買い物客がストアフロントを見つけられないようにするには、アクセスを制限します。ストアフロントへのアクセスを、プロジェクトに関与しているマーチャントとその他の担当者に制限します。この制限によって、クローラーと検索エンジンロボットがストアフロントをインデックスできなくなり、検索エンジンからアクセスできなくなります。ページなどの動的コンテンツと画像などの静的コンテンツの両方が保護されます。このトピックは、B2C Commerce に該当します。

Business Manager で、ストアフロントにアクセスしようとするユーザーの認証を要求するストアフロントパスワードを設定します。この機能により、動的ページと静的ページの両方へのアクセスがブロックされます。サイトのストアフロントが保護されており、ストアフロントのユーザーが適切な認証情報を提示しない場合、B2C Commerce はこれらの HTTP エラーを返します。

  • 401 – 共有パスワードを使用したアクセス
  • 401 – ユーザーパスワードまたはアクセスキーを使用したアクセス
  • 403 – Storefront Toolkit を使用したアクセス
  • 403 – 機能の許可なしで Storefront Toolkit を使用したアクセス

買い物客またはユーザーが開発段階のストアフロントへのアクセスを試み、パスワードによる保護が有効になっている場合、認証要求ウィンドウが開きます。ストアフロントのパスワード保護を有効または無効にする方法については、保護フラグの設定とパスワードの割り当てを参照してください。

機能許可 'Access_Protected_Storefront' をもつ Business Manager ユーザーは、ストアフロントに常にログオンできます。その他のユーザーがストアフロントにアクセスできるようにするには、共有ログインを作成します。デフォルトのユーザー名は storefront ですが、自分独自のパスワード (認証要求時に入力) を割り当てる必要があります。ストアフロントの管理者は、Business Manager を使用してフラグとパスワードを設定します。

メモ ストアフロントの保護を有効にする際には、静的コンテンツの保護を強制するために、静的コンテンツキャッシュを無効にします。無効にしないと、配信済みの保護されていないコンテンツが期限切れになるまで有効のままになってしまいます。パスワードが変更された場合は、新規パスワードの使用を強制するために静的コンテンツのキャッシュを無効にします。無効にしないと、配信されたコンテンツが期限切れになるまで使用されてしまいます。

買い物客がパスワードを忘れて、リセットをリクエストした場合、パスワードリセットのトークンの有効期間は 30 分間です。

メモ Business Manager ユーザーのパスワードリセットのトークンの有効期間は 120 分間です。

Storefront Toolkit のヒントと制限事項

最良の結果を得るには、Storefront Toolkit のパフォーマンスが最適になるようにシステムを構成し、ツールキットの制限事項について理解します。このトピックは、B2C Commerce に該当します。

  • 検索情報ツールは商品の検索にのみ機能します。コンテンツの検索結果は分析されません。
  • 暗号化されていない HTTP バージョンのページを使用するようにブラウザーをリダイレクトすると、Storefront Toolkit は適切に機能しないことがあります。ベストプラクティスは、HTTP を使用するようにブラウザーをリダイレクトしないことです。暗号化されていないページに関する潜在的な問題を完全に排除するために、グローバルセキュリティ環境設定の「HTTPS を強制する」を有効にします。Business Manager で、アプリケーションランチャーをクリックし、管理 | グローバル環境設定 | セキュリティの順に選択します。アクセス制限タブで、HTTPS を強制するを選択して、適用をクリックします。
  • HTTPS ホストが適切に構成されていることと、DNS を使用してホスト名エイリアスが正しいインスタンスを指していることを確認します。
  • Page Designer ページは、新旧いずれの Storefront Toolkit でもコンテンツプレビューに接続されていません。
  • すべての証明書が有効であることを確認します。無効な証明書がある場合は、まずストアフロントを開いて、例外を許可します。次に、Storefront Toolkit を開きます。
  • Cookie に対し、Secure 属性を使用し、SameSite 属性を None に設定します。
  • Storefront Toolkit は iframe を使用してストアフロントを表示します。iframe のwindow.top 要素または window.parent 要素にアクセスする JavaScript は避けてください。コードで範囲がグローバルの parent に書き込みが行われないことを確認してください。
  • クリックジャック攻撃の防止、またはクリックジャック攻撃防止スクリプトは使用しないでください。エラーが発生することがあります。代わりに、適切な HTTP ヘッダーを使用します。詳細については、B2C Commerce での Storefront Toolkit のトラブルシューティングを参照してください。

B2C Commerce での Storefront Toolkit のトラブルシューティング

Storefront Toolkit に関する一般的な問題のトラブルシューティングを行います。このトピックは、B2C Commerce に該当します。

Storefront Toolkit の JavaScript は、ストアフロントの HTML <head> セクションにある最初の JavaScript タグの前に挿入されます。HTML <head> セクションに JavaScript がない場合、Storefront Toolkit の JavaScript は、<head> セクションの最後に挿入されます。

次の表は、Storefront Toolkit を使用する際に一般的に発生する問題の一部と、その解決策をリストしています。

問題 解決策
Storefront Toolkit でページを開こうとすると、ツールキットを初期化できなかったというメッセージが表示される。
  • HTTPS ホストが適切に構成されていることと、DNS を使用してホスト名エイリアスが正しいインスタンスを指していることを確認します。ホスト名のエイリアスを参照してください。
  • ストアフロントを開くには、ストアフロントをクリックします。ストアフロントでは URL に必ず HTTPS を使用します。ブラウザーに無効な証明書に関するエラーが表示される場合は、証明書の例外を許可します。
  • ストアフロントの HTML コードから CDATA セクションを削除します。Storefront Toolkit は CDATA をサポートしていません。
コンテンツ情報ツールでコンテンツと商品タグが表示されない。

HTML にページマーカーがない可能性があります。コンテンツアセットを表示する場合には <!-- dwMarker="content" dwContentID="${pdict.Content.UUID}" --> を、商品を表示する場合には <!-- dwMarker="product" dwContentID="${Product.UUID}" --> を追加します。
検索結果ウィンドウまたは商品検索モデルウィンドウを使用できない。 isobject タグが正しく実装されていることを確認します。B2C Commerce の Storefront Toolkit 検索情報ツールの有効化を参照してください。
Storefront Toolkit のツールに何も情報が表示されない。 コンテンツ配信ネットワーク (CDN) で HTML のコメントが削除されている可能性があります。CDN でこの機能を無効にします。Cloudflare を使用している場合は、How do I minify HTML, CSS, and JavaScript to optimize my site? (HTML、CSS、および JavaScript をミニファイしてサイトを最適化する方法) を参照してください。
Toolkit に空のストアフロントが表示される。

コードにクリックジャック対策が含まれている場合は、iframe で開いたときにページのコンテンツが非表示になることがあります。この問題を解決するには、Staging (ステージング) インスタンスまたは Sandbox (サンドボックス) インスタンスで、クリックジャックの防止を無効にするカスタムのサイト環境設定を追加することをお勧めします。詳細については、Clickjacking を参照してください。

以下の dw.web.URLUtils のメソッドを使用して作成した URL が予想通りに機能しない。

  • url
  • http
  • https
  • abs

Storefront Toolkit は、URL にキャッシュバスティングパラメーターを追加します。たとえば、URLUtils.url を使用して、次のようなパラメーターを使って URL を作成します: URLUtils.url(”Pipeline-Start”) + “?param=value”。

この結果の URL は https://example.com/on/demandware.store/Sites-MySite-Site/default/Pipeline-Start?__sftkCacheBuster=1593615552718?param=value です。

この URL は予想通りに機能せず、使用する場所によってはストアフロントで問題を引き起こす可能性があります。

次の例にしめすように、URLUtils を使用して URL パラメーターを渡します: URLUtils.url("Pipeline-Start", "param", "value")。

Storefront Toolkit を使用する場合、結果の URL は https://example.com/on/demandware.store/Sites-MySite-Site/default/Pipeline-Start?__sftkCacheBuster=1593615552718&param=value です。この URL では、パラメーターの前に ? の代わりに & 文字があります。Storefront Toolkit を使用しない場合は、結果の URL は https://example.com/on/demandware.store/Sites-MySite-Site/default/Pipeline-Start?param=value です。
リンクをクリックすると、Storefront Toolkit が見えなくなる。

次の例に示すように、target=”_top” 属性を含むリンクを使用していることを確認します:

<a href="/example/link" target="_top">An example link</a>

target=”_top” 属性によって、ブラウザーでリンクが最前面のフレームに開き、Storefront Toolkit が見えなくなります。
ストアフロントが Storefront Toolkit に表示されないか、Storefront Toolkit のツールバーが表示されない。

このエラーは、クリックジャック攻撃の防止、またはクリックジャック攻撃防止スクリプトによって発生します。クリックジャック攻撃では、悪意をもつユーザーによって、攻撃者がコントロールする iframe に Web サイトが表示されます。攻撃者は入力イベントを傍受して、ユーザーが入力するパスワードやクレジットカード番号などの情報を取得します。

スクリプトを使用する代わりに、クリックジャック攻撃を防止するために次の HTTP ヘッダーをストアフロントに含めます: X-Frame-Options: DENY および Content-Security-Policy: frame-ancestors ‘none’。

以下のコードをストアフロントで使用して、これらのヘッダーを設定します。

response.setHttpHeader("X-Frame-Options", "DENY");
response.setHttpHeader("Content-Security-Policy", "frame-ancestors 'none');
Storefront Toolkit からリンクをクリックすると、インスタンスにログインするように求められ、ログインに失敗する。 新しい Storefront Toolkit を使用しているかどうかを確認します。廃止予定バージョンの Storefront Toolkit は、統合認証とともに使用すると適切に機能しない場合があります。

カスタムコードでページマーカーを探します。

dwContentIDに使用される式は異なっていてもかまいません。式が実際にコンテンツアセットの汎用一意識別子 (UUID) に評価されることを確認します。
