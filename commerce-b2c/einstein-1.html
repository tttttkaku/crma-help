Commerce Einstein

Commerce Einstein は人工知能を利用したマーチャンダイジングツールを提供し、実用的なインサイトとカスタマイズされた顧客体験を提供します。このトピックは、B2C Commerce に該当します。

B2C Commerce Einstein のデプロイのためのカタログと注文フィードの構成

Einstein へのカタログと注文のデータフィードを構成、スケジュール、デプロイします。

必要なエディション

使用可能なソリューション: B2C Commerce

Einstein 機能を使用するには、まず B2C Commerce Einstein のカタログフィードと注文フィードを構成する必要があります。マスターカタログの商品と買い物客の注文に関するデータは、これらのフィードを経由して送信されます。これらのフィードでは、マスターカタログと注文に関する重要なプロパティが B2C Commerce Einstein にエクスポートされます。

Einstein はこのデータを使用して、ストアフロントで有効にした B2C Commerce Einstein 機能のための結果の生成に使用される機械学習モデルのトレーニングを行います。また、データは Einstein Configurator ツールにもフィードされます。Einstein Configurator を使用して、システムで推奨が生成される方法を調整するビジネスルールを構成します。

これらのフィードを構成することで、カタログと注文のデータをエクスポートする頻度を制御します。

メモ カタログと注文のフィードは Production (本番) インスタンスでのみ構成します。

カタログと注文のフィードを構成するには:

  1. Business Manager で、アプリケーションランチャーをクリックし、次に管理 | オペレーション | Einstein ステータスダッシュボードの順に選択します。
  2. 各サイトの右側にあるドロップダウンメニューを使用して、構成を選択します。
    メモ ホストフィールドは、空の場合以外はそのままにして次のステップに進みます。
  3. ホストフィールドが空の場合は、現在のサイトのホスト URL を指定します。
    たとえば、www.myCompanyName.com などです。
    メモ ホスト URL を指定する場合は、'https://' は含めないでください。
  4. デプロイ構成セクションで、地域を選択します。
    地域はサイトごとに 1 回のみ選択します。この設定では、主な業務地域に対応する地域を指定します。システムはこの情報を使用して、予測データを保管および処理する場所を決定します。Production (本番) インスタンスと Staging (ステージング) インスタンスで地域設定が構成されていることを確認してください。
  5. 以下の表を使用して、特定の操作を定義します。
    操作 選択する項目...
    現在在庫切れのページに対し、商品詳細ページで商品の推奨項目を生成する。

    在庫切れ商品

    メモ このオプションでは、Einstein が在庫切れ商品のカタログ情報を保存し、買い物客が表示する在庫切れ商品の ID を引き続き認識し、適用された Recommender ルールを使用することができます。
    商品タイプを利用するストアフロントカタログ: バリエーショングループ。 バリエーショングループの商品
    デフォルトの地域情報以外の商品のデータを含むマスターカタログ。 複数地域情報
  6. 特定の日付以降に作成された注文をエクスポートするには、「次の日時以降に作成された注文をエクスポート」フィールドで値を指定します。
    メモ この値を指定する場合は、サイトが B2C Commerce でライブになった日付、または 2 年間のうち、短い方を指定します。
  7. 実行あたりの最大注文数を定義します。
    この値は、ピーク日に予想される注文数です。デフォルト値は 10,000 です。参考までに、注文数を 100,000 件に設定すると、注文フィードの処理には約 30 分間かかります。
    メモ 大規模な注文履歴をもつ新しいサイトに対して実行あたりの最大注文数を構成する際には、注文数を 10,000 件を超えるように増やすことを推奨します。この設定では、現在の日付に追いつくまで何日もかかるのではなく、注文フィードがもっとも最近の日付から注文をインポートできます。注文フィードが最新でないと、Commerce Insights が生成されない場合があります。Commerce Insights には、過去 7 日間の買い物客の買い物カゴのビジュアル化が表示されます。
  8. (オプション) カタログフィードと注文フィードをすぐに実行するには、保存をクリックします。
  9. カタログと注文フィードのスケジュールのスイッチをオンに設定します。
    スイッチが無効の場合は、カタログと注文のフィードはサイトに対してスケジュールされません。
  10. カタログフィードのスケジュールを定義します。
    フィールド 推奨
    開始日時

    Einstein が確実に最新の商品情報や新製品の立ち上げを受け取るように、Staging (ステージング) から Production (本番) へのレプリケーションが完了した直後に実行するようにジョブをスケジュールします。

    Staging (ステージング) から Production (本番) へのレプリケーションジョブの完了時刻は、Staging (ステージング) インスタンス | アプリケーションランチャー | 管理 | レプリケーション | データレプリケーション処理 | 次のタイプの終了時刻を表示: 転送 & 公開の順に選択して確認できます。
    時間単位 日
    頻度

    1

    メモ Einstein がすべての変更に関して最新の状態を保てるように、カタログフィードは毎日実行することをお勧めします。Einstein では、最初の実行時にのみカタログ全体がエクスポートされます。毎日のランタイムを短くするために、その後の実行には差分のみが含まれます。
  11. 注文フィードのスケジュールを定義します。
    フィールド 推奨
    開始日時 注文がピークでない時間帯にジョブをスケジュールします。
    時間単位 日
    頻度

    1

    メモ 過去 7 日間の注文が使用されるため、Commerce Insights 機能を最新の状態に保つには毎日の注文フィードの構成が重要になります。また注文フィードは、Product Recommendations 戦略の商品アフィニティアルゴリズムでも使用されます。
  12. 保存をクリックします。
    Business Manager で構成が保存されます。
  13. デプロイが完了するまで、少なくとも 24 時間から 48 時間待ちます。
  14. Salesforce サポートにチケットを記録し、Configurator に最初のサイト管理者を追加するよう依頼します。
  15. サイト管理者として追加されたら、Einstein Configurator を開き、管理 | ユーザー管理に移動します。必要に応じてユーザーを追加します。
    ユーザーは関連する組織の Account Manager アカウントを持っている必要がありますが、特定の Account Manager 役割は必要ありません。

B2C Commerce Einstein Recommender の構成

B2C Commerce Einstein のデプロイ後、商品詳細ページ (PDP) と最近見た商品の Recommender はそのまますぐに使用できます。またマーチャントは、Einstein の戦略とルールを利用して、カスタムの Recommender を作成できます。このトピックは、B2C Commerce に該当します。

Recommender の目的は次のとおりです。

  • 商品 ID のリストの生成に使用するアプローチ、またはアルゴリズムを制御する。
  • 商品 ID のリストを操作するには、リストをストアフロントに渡す前に商品 ID を削除するか、順番を変更します。

Recommender の構成では、1 つまたは複数の戦略 を指定して、商品 ID のリストを生成するためにシステムで使用するアプローチを決定します。必要ではありませんが、構成の際に 1 つまたは複数のルール を指定して、推奨項目のリストを調整し、リストの内容や順番を制御できます。

Recommender を構成する際には、固有の名前を付ける必要があります。この名前は、Recommender によって生成された推奨項目に対してコンテンツスロット設定を作成する際に、Business Manager に表示されます。

Recommender タイプと戦略の詳細については、B2C Commerce Einstein Product Recommendationsを参照してください。

B2C Commerce Einstein での Product Recommendations のコンテンツスロットの設定

コンテンツスロットを使用して、ストアフロントで Product Recommendations を表示します。このトピックは、B2C Commerce に該当します。

推奨商品は、コンテンツスロットを使用してストアフロントページに表示されます。コンテンツスロットの設定の詳細については、スロット設定の管理と作成を参照してください。

Product Recommendations のためにコンテンツスロットを設定する際には、以下の作業を行います。

  • コンテキストがグローバルであるコンテンツスロットを選択します。
  • コンテンツタイプフィールドを推奨項目に設定します。
  • Recommender フィールドの値を選択します。
  • slots/recommendation フォルダーから適切なレンダリングテンプレートを選択します。

Recommender フィールドには、Einstein Configurator ツールで定義するRecommenderと呼ばれるビジネスルールの名前付きリストが含まれています。これらのルールによって、B2C Commerce Einstein が推奨商品を出力する方法を制御します。

買い物客通知の Salesforce Personalization の有効化

パーソナライゼーションを使用すると、買い物客の通知で関連性の高いパーソナライズされた体験を提供できます。買い物客への通知を使用するためにパーソナル化は必要ありません。

買い物客への通知にパーソナライズされたおすすめ商品を追加するには、パーソナライゼーションライセンスが必要です ( 「パーソナライゼーション」を参照)。また、B2C Commerce ドメインデータを Data 360 に取り込むには、Apache Iceberg Connectorを設定する必要があります。

  1. B2C Commerce のナビゲーションサイドバーで、マーチャントツール | サイト | サイト環境設定 | Salesforce Data Cloud | 機能構成 | パーソナライゼーションの順に選択します。
  2. 「パーソナライゼーションを有効にする」をクリックします。
重要 パーソナル化 Recommender のトレーニングが終了するのを待ってから、買い物客への通知にパーソナライズされた推奨項目を追加します。「個人用設定が有効になりました」と表示されるまで、このページを更新します。このプロセスには最大 30 分かかることがあり、トレーニングは 24 時間ごとに更新されます。「パーソナル化 Recommender のトレーニング」を参照してください。

明示的な推奨の作成

明示的な推奨機能を使用して、B2C Commerce で明示的な推奨を作成および管理します。

必要なエディション

使用可能なソリューション: B2C Commerce

明示的な推奨を使用すると、次の操作が可能です:

  • 明示的な推奨を作成、更新、並べ替え、削除する。
  • 追加機能に標準またはカスタム属性を使用する。
  • カタログを使用して推奨項目をインポートおよびエクスポートする。

Business Manager では、明示的な推奨項目がソースオブジェクトごとに整理されます。これは、ソースオブジェクト内で並べ替え順が設定されているためです。明示的な推奨機能を拡張します。推奨項目タイプはシステム属性です。構成するには、管理 | サイトの開発 | システムオブジェクトタイプ の順に選択します。たとえば、タイプを追加して、ラベルを構成します。

メモ 以下の手順は明示的な推奨にのみ使用でき、Product Recommendations には使用できません。
  1. 推奨項目を作成するには、アプリケーションランチャーをクリックし、マーチャントツール | サイト | 商品とカタログ | 推奨項目を選択 (または商品エディターから商品の推奨項目タブにアクセス) します。
    1. カタログの選択ページで、推奨項目を追加するカタログを選択します。
    2. 商品の推奨項目タブで、新規をクリックします。
    3. 推奨項目ソースの選択ページで、推奨項目を作成する商品の有効な商品 ID を入力するか、商品リストを参照します。
    4. 省略記号をクリックして商品を参照します。
    5. 商品の選択ページで、商品を検索するか、検索フィールドに商品 ID を入力します。

      商品 ID が入力された状態で、推奨項目ソースの選択ページが再度開きます。

    6. 次へ >> をクリックします。
    7. 推奨項目タイプの選択ページで、作成する推奨項目タイプを選択します。

      1 (商品詳細ページ – クロスセル): SiteGenesis。商品は、商品詳細ページの「類似商品」セクションに表示されます。通常はこれを選択します。

      2 (カテゴリのランディングページ - おすすめの商品): SiteGenesis では実装されていません。新しいテンプレートが必要です。

      3 (その他): SiteGenesis では実装されていません。新しいテンプレートが必要です。

    8. 推奨する商品をリストから選択します。
    9. 推奨項目のターゲットの選択ページで、完了をクリックします。
  2. カテゴリ推奨項目を作成するには、アプリケーションランチャーをクリックし、マーチャントツール | サイト | 商品とカタログ | 推奨項目の順に選択 (または商品エディターから商品の推奨項目タブにアクセス) します。
    1. 必要なカタログを選択します。
    2. カテゴリ推奨項目タブで、新規をクリックします。
    3. 推奨項目を作成するカテゴリの有効なカテゴリ ID を入力するか、カテゴリリストを参照します。
    4. 省略記号をクリックしてカテゴリを参照します。
    5. カテゴリの選択ページで、カテゴリを検索するか、検索フィールドにカテゴリ ID を入力します。
    6. 選択をクリックします。

      カテゴリ ID が入力された状態で、推奨項目ソースの選択ページが再度開きます。

    7. 次へ >> をクリックします。
    8. 推奨項目タイプを選択します。
    9. 推奨する商品をリストから選択します。
    10. 完了をクリックします。
  3. 既存の推奨項目を編集するには、アプリケーションランチャーをクリックし、マーチャントツール | サイト | 商品とカタログ | 推奨項目の順に選択します。
    1. カタログを選択します。
    2. 商品の推奨項目タブ、またはカテゴリ推奨項目タブで編集をクリックします。
      ターゲット商品のプロパティ (推奨項目タイプ、説明、コールアウトメッセージ、画像の仕様など) を変更します。
    3. 商品の推奨項目の詳細ページ、またはカテゴリ推奨項目の詳細ページで並べ替えをクリックします。
      商品の推奨項目ページ、またはカテゴリの推奨項目ページで、ターゲット商品がストアフロントで表示される順序を変更できます。必要であれば、まず推奨項目タイプを選択し、並べ替えの矢印を使用して位置を変更します。
    4. 推奨商品をリストから削除するには、商品の推奨項目タブ、またはカテゴリ推奨項目タブで、1 つ以上の商品またはカテゴリを選択し、削除をクリックします。

Einstein アクティビティ追跡:必須フィールド

ハイブリッドストアフロントまたはカスタムストアフロントに Einstein アクティビティ追跡を実装する場合は、各アクティビティタイプに特定のフィールドを含めます。このトピックでは、適切なデータ収集とアトリビューションのために Einstein API で想定される必須フィールドの一覧を示します。

Storefront Reference Architecture (SFRA) または SiteGenesis を使用している場合、ストアフロントはisobjectタグを使用して必要なアクティビティフィールドを追跡します。ただし、ハイブリッドストアフロントまたはカスタムストアフロントを作成する場合は、必須項目を必ず追跡してください。必須フィールドを追跡することで、Einstein でデータを処理できるようになります。

項目が欠落していたり、形式が正しくなかったりすると、Einstien が重要なアクティビティを誤って除外し、Einstein ダッシュボードと推奨項目のデータが不完全になる可能性があります。

トラブルシューティング

Einstein ダッシュボードにアクティビティが表示されない場合は、以下の一般的な問題を確認してください。

  • 非本番インスタンスタイプ— Einstein では、prd以外のinstanceType値をもつアクティビティのレポートは生成されません。
  • 欠落または空のアクティビティタイプ— Einstein では、有効なactivityTypeがないアクティビティはレポートされません。
  • Recommender 名の欠落—viewReco、clickReco、およびレコメンデーションから買い物カゴへのアクティビティでは、recommenderNameがないと適切なアトリビューションが行われません。
  • 無効な商品 ID - 商品 ID が商品カタログの ID と一致していることを確認します。

B2C Commerce Einstein とデータ

B2C Commerce Einstein では、買い物客の行動から収集される入力データが必要です。Einstein はこのデータを使用して、ベンチマーキングと分析を行い、データ駆動型のインテリジェントなパーソナル化を可能にします。このトピックは、B2C Commerce に該当します。

収集したデータを使用して、Einstein は以下を実行できます。

  • 推奨項目をパーソナル化する。
  • 検索結果とカテゴリグリッドの並べ替えをパーソナル化する。
  • 新しい検索同義語を識別する。
  • 買い物客の買い物カゴを分析して、同時購入される頻度の高い商品を識別する。
  • 予測入力検索ガイダンス、買い物客が最近行った検索、および、よく使用されるストアフロント検索を買い物客に提供する。

このレベルの買い物客のパーソナル化を提供するために、Einstein は以下の 3 つのソースからデータを収集して使用します。

データソース 説明
Catalog

カタログから商品情報を収集するには、Production (本番) インスタンスに対してカタログフィードを実行します。
注文数

ストアフロントから注文情報を収集するには、Production (本番) インスタンスに対して注文フィードを実行します。
クリックストリーム

クリックストリームのデータは、ピクセル追跡を使用してリアルタイムでサイトから自動収集されます。このデータを収集するためにアクションを実行する必要はありません。

次のアクティビティが自動的に追跡されます。

  • 商品のビュー数
  • 買い物カゴへの追加
  • 注文手続きの完了
  • おすすめ商品の表示

B2C Commerce Einstein の同意管理

Einstein では、クリックのたびに買い物客の閲覧イベントが収集され、買い物客の予測モデルがリアルタイムで更新されて、買い物客に対して最も関連性の高い体験が計算されます。このトピックは、B2C Commerce に該当します。

  • 同意管理のしくみ

Einstein ダッシュボード

B2C Commerce Reports & Dashboards Einstein ダッシュボードを使用して、Einstein Recommendations のパフォーマンスを確認します。このデータは、コンバージョンと収益を向上させるための推奨項目の戦略策定に役立ちます。

このダッシュボードには、平均注文金額、買い物カゴへの追加数、および買い物カゴのコンバージョンのメトリクスがあり、Einstein Recommendations を経時的に表示します。

デフォルトでは、すべてのサイトの概要がダッシュボードに表示されますが、サイトごとの詳細を見ることもできます。また、サイトや日付範囲でフィルターすることもできます。

メモ Einstein ダッシュボードのデータは 48 時間の遅延期間がありますが、他のダッシュボードレポートの遅延期間は 24 時間です。Einstein のパフォーマンスデータは量が多いために処理時間が長くなり、通常 2 日間遅れで提供されます。
メモ Einstein ダッシュボードは Production (本番) インスタンスでのみ使用できます。On-Demand Sandbox (ODS)、Development (開発) インスタンス、Staging (ステージング) インスタンスなどの非 Production (本番) インスタンスでは使用できません。
ダッシュボードの定義
用語 定義
Recommendation Name (推奨項目名) 推奨項目ゾーン、または Einstein データの Recommender と呼ばれます。Recommender は常に 1 つまたは複数のコンテンツスロットに関連付けられています。
Views (ビュー数) 指定した期間中に、Recommender に関連付けられたコンテンツスロットがサイトの訪問者に表示された回数。画面をスクロールしなければ見えない場所にスロットが表示されたかどうかは関係ありません。サイトの訪問者が表示したページにコンテンツスロットが含まれていれば、そのコンテンツスロットは表示されたとみなされます。
Clicks (クリック数) Recommender に関連付けられたコンテンツスロットに表示された任意の商品を、ユーザーがクリックした回数。
CTR 「クリック数/ビュー数」として測定されるクリックスルー率。
Adds To Cart (買い物カゴへの追加数) 買い物客が Recommender 内で最初にクリックした商品で、買い物カゴに追加された個別の商品の数。買い物カゴへの追加は、同じセッション内、またはクリックイベントから 7 日以内に発生することが必要です。買い物客がクリックして、連続して 7 日以内に買い物カゴに追加した商品のみが、その Recommender によるものと考慮されます。
ATC Rate (買い物カゴへの追加率) 買い物カゴへの追加率は、「買い物カゴへの追加数/クリック数」として計算されます。
Conversions or products purchased (コンバージョン数または購入された商品数) 商品が Recommender 内でクリックされた最初のものである場合に、購入された一意の商品の数 (確定した注文ではありません)。購入は、同じセッション内、またはクリックイベントから 7 日以内に発生することが必要です。
Conversion Rate (コンバージョン率) 「コンバージョン数/買い物カゴへの追加数」として計算されます。
Attributed Revenue (起因する収益)

コンバージョンされた商品の金額。

メモ B2C Commerce は、以下の場合に収益を Recommender に帰属させます。       
  • 買い物カゴへの追加イベントが、同じセッション内、または関連する Recommender のクリックイベントから 7 日以内に発生した場合。
  • 注文手続きイベントが、関連付けられている買い物カゴへの追加イベントと同じセッション内、または買い物カゴへの追加イベントから 7 日以内に発生した場合。
Recommender に関連付けられた収益は、Recommender のクリックイベントから最長 14 日間発生する場合があります。

Attributed Revenue (起因する収益)

起因する収益のレポートでは、ページの推奨項目スロットから直接買い物カゴに追加されて購入された商品が毎日の収益に与える影響を通貨レベルで追跡します。プラスのトレンドは、推奨項目が収益に影響を与えていることを示します。マイナスのトレンドは、推奨項目の戦略を変更する必要があることを示します。

収益を追跡するために、メトリクスでは Einstein を起因とする 4 つの 買い物客イベントが監視されます。Recommender の表示、Recommender の商品のクリック、買い物カゴへの追加、および注文手続きです。B2C Commerce では、買い物客が前回の Einstein Recommender のクリックから 7 日以内に品目を買い物カゴに追加し、買い物カゴへの追加のアクションから 7 日以内に注文手続きが行われた場合にのみ、収益が Einstein に帰属します。

以下に例を示します:

  • 1 日目 Recommender の表示 – 買い物客 A が XYZ T⁻シャツの Recommender からサイトのページを訪問します。
  • 1 日目 Recommender の商品のクリック – 買い物客 A が XYT T-シャツの同じ Recommender をクリックします。
  • 7 日目 買い物カゴに追加 – 買い物客 A が XYZ T⁻シャツを買い物カゴに追加します。
  • 14 日目 注文手続き – 買い物客 A が T⁻シャツの注文手続きを完了します。

このシナリオでは、B2C Commerce は、買い物客が最後に XYZ T-シャツの Recommender をクリックした、1 日目に完了した注文の収益を Einstein に起因させます。B2C Commerce では、買い物客が前回の Einstein Recommender のクリックから 7 日以内に品目を買い物カゴに追加し、買い物カゴへの追加のアクションから 7 日以内に注文手続きが行われた場合にのみ、収益が Einstein に帰属します。Recommender に関連付けられた収益は、Recommender のクリックイベントから最長 14 日間発生する場合があります。

Click Through Rate (クリックスルー率)

クリックスルー率レポートは、クリックスルーにつながった Einstein 推奨項目の割合をプロットします。クリックスルー率は、買い物客が推奨項目にどのように反応しているかに関するインサイトを提供します。たとえば、プラスのトレンドは、推奨項目が商品に対する興味を生み出していることを示唆します。

Adds To Cart (買い物カゴへの追加数)

買い物カゴへの追加数のレポートは、Einstein 推奨項目のクリックスルーの結果、買い物客の買い物カゴに追加された品目の数をプロットします。買い物カゴへの追加数のデータを使用して、推奨項目の全般的な成功を経時的に評価します。たとえば、推奨項目の戦略が成功している場合は、買い物カゴへの追加数がプラスのトレンドを示しています。

Cart Conversion Rate (買い物カゴコンバージョン率)

買い物カゴコンバージョン率レポートには、注文による購入につながった推奨項目のクリックの割合が表示されます。コンバージョン率が高い場合は、買い物客が推奨項目の戦略に肯定的に反応していることを示唆します。

Performance by Recommendation (推奨項目別パフォーマンス)

推奨項目別パフォーマンスレポートを使用して、個々の Einstein 推奨項目のパフォーマンスを評価します。このレポートには、各推奨項目に対して以下のメトリクスがリストされます。

  • Clicks (クリック数)
  • CTR
  • Adds To Cart (買い物カゴへの追加数)
  • Conversions (コンバージョン)
  • Attributed Revenue (起因する収益)

このレポートを使用して、顧客が特定の推奨項目にどのように反応しているかを評価します。たとえば、クリック数が多くてもコンバージョン率が低い推奨項目は、推奨項目のターゲットを変更する必要がある可能性を示しています。

Value of Conversion (コンバージョンの価値)

Performance by Recommendation (推奨項目別パフォーマンス) テーブルにリストされている推奨項目を選択し、その推奨項目のコンバージョンデータを確認します。選択した推奨項目に対し、テーブルに推奨項目名と以下のメトリクスがリストされます。

  • Views (ビュー数)
  • Clicks (クリック数)
  • Cart Adds (買い物カゴへの追加数)
  • Products purchased (購入された商品)
  • Attributed Revenue (起因する収益)

推奨項目の対象となる商品のコンバージョンメトリクスを確認します。テーブルには、各商品に対して以下のメトリクスがリストされます。

  • ID
  • Product Name (商品名)
  • Views (ビュー数)
  • Clicks (クリック数)
  • CTR
  • Cart Adds (買い物カゴへの追加数)
  • ATC Rate (買い物カゴへの追加率)
  • Products purchased (購入された商品)
  • Cart Conversion (買い物カゴコンバージョン)
  • Revenue Attributed (起因となった収益)

この表には、主要サービス契約 (MSA) で定義されているとおりに、顧客が Salesforce サービスに送信した顧客データがリストされます。また、この表には、顧客データでトレーニングされたグローバルモデルを使用する機能と、使用される使用状況データ (Salesforce とのユーザインタラクションに関連するデータ) も示されています。

Einstein 機能に送信されたデータは、AI モデルのトレーニング、サービスや機能の改善、追加コストなしでアクセスできる新機能の開発に使用される場合があります。このモデルでは、複数の Salesforce 顧客間で集計されたトレンドが検索されます。

グローバルモデルタイプ

カタロググローバルモデル :さまざまな顧客のカタログ間で機能する機械学習モデル。カタログをプールして、商品または商品の属性をより適切に分類します。カタロググローバルモデルでは、マスターカタログのフィールド (名前、説明、主要カテゴリ、カテゴリリスト、価格、カスタム属性など) を使用し、画像などのリンクアセットも使用します。このモデルは、カタログのグローバルモデリングをオプトアウトしていない顧客間でトレーニングされます。カタログ グローバル モデルは、オプトアウトした顧客に使用されますが、そのデータはモデルのトレーニングには使用されません。

マーチャントグローバルモデル :検索辞書など、顧客間でマーチャントのアクティビティ/設定を共有する機械学習モデル – Einstein は、マーチャント間の検索アクティビティに基づいて、一般的な商品名の同義語を提案します。

カスタマーコントロール

お客様は、自分のデータがグローバルモデルに寄与するかどうかを制御できます。Einstein 機能でグローバルモデルを使用する場合、顧客はオプトアウトできます。データの使用方法を管理については、コマースサポートチームにお問い合わせください。

B2C Commerce Einstein Product Recommendations の実装

B2C Commerce Einstein Product Recommendations を実装するには、さまざまなコンポーネントの構成、実行、および変更が必要です。これらの各タスクは、さまざまな役割が実行されます。このトピックは、B2C Commerce に該当します。

以下の表は、Product Recommendations を使用する前に必要な一般的なステップを説明しています。また、各ステップを実行する担当者の役割も示してあります。

ステップ ステップの担当者
Production (本番) インスタンスに対してカタログと注文のフィードを構成する。

管理者
Einstein Configurator ツールを使用して Recommender を構成する。 マーチャント
Internet Store Markup Language (ISML) テンプレートを変更して、推奨コンテンツスロットを作成し、Product Recommendations を表示する。 デベロッパー
コンテンツスロットを設定して、Product Recommendations の表示に使用するテンプレートと Recommender を制御する。 マーチャント

Product Recommendations は、商品 ID (推奨商品の ID) のリストの形で提供されます。このリストがストアフロントに渡される前に、システムによってビジネスルール (Einstein Configurator ツールを使用して定義する Recommender ) が適用されます。これらのルールは商品 ID のリストの構成を制御し、一部の ID を削除したり、ID の順番を変更したりできます。つまり、このルールでは、どの商品を表示、非表示、昇格、および降格するかを制御できます。

ストアフロントで推奨商品の最終的なリストが表示される際には、ルールの定義にしたがった最適な順番になっています。

Product Recommendations はコンテンツスロットに表示されます。デベロッパーは ISML テンプレート内でコンテンツスロットを定義する必要があります。コンテンツスロットを作成したら、スロットの設定を作成できます。コンテンツスロットの設定 (コンテンツタイプを必ず推奨項目に設定) で、推奨商品の表示に使用するテンプレートを制御します。また、推奨商品 ID のリストに適用するビジネスルールも制御します。

必要なエディション

使用可能なソリューション: B2C Commerce

特定の買い物客に対して設定が明示的に変更された場合を除き、Einstein はこの設定を使用して、ブラウザーベースのアクティビティの追跡を可能にします。これにより、サイトでの買い物客のアクティビティがリアルタイムで追跡されます。

メモ Einstein はデフォルトのプライバシー設定を使用する唯一のサービスではありません。

デフォルトのプライバシー環境設定を設定するには、以下の手順に従います。

  1. Business Manager で、アプリケーションランチャーをクリックし、マーチャントツール | サイト | サイト環境設定 | プライバシー設定の順に選択します。
  2. 新規ストアフロントセッションの顧客追跡に関するデフォルトアクションを選択します。

    無効 - 追跡はデフォルトで無効になり、カスタムコードを使用してセッションごとに有効にできます。

    有効 - 追跡はデフォルトで有効になり、カスタムコードを使用してセッションごとに無効にできます。

  3. 「クリックストリームでセッションの DNT を使用」の設定を選択します。

    買い物客のセッションでは、その買い物客の最後の 50 件のトップレベルリクエスト (パイプラインの呼び出しなど) を含むクリックストリームオブジェクトが保持されます。SiteGenesis ではこの機能を使用して、買い物客が最後に訪問した商品を判定し、買い物客の便宜のために履歴を表示します。現在のセッションからクリックストリームエントリを取得するスクリプト API があります。

    メモ この設定はクリックストリーム API dw.web.Clickstreamのみに関連するもので、B2C Commerce の他のクリックストリーム機能を制御することはありません。

    はい – クリックストリームでストアフロントの DNT (追跡拒否) セッションステータスが使用されます。

    セッションで DNT が true の場合、クリックストリームイベントは収集されません。

    セッションで DNT が false の場合、クリックストリームイベントは収集されます。

    いいえ – セッションの DNT ステータスに関わらず、クリックストリームイベントは収集されます。
