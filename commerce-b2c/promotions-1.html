B2C Commerce の A/B テスト: プロモーションの比較

プロモーションと A/B テストを比較します。

新規キャンペーンの一環として、マーケティングマネージャーは、対照群と比較して最も効果が高いプロモーションは次のうちどれかを知りたいと考えています:

  • 注文金額が $100 を超えると送料無料
  • 注文金額が $100 を超えると 10% 割引
  • 注文金額が $200 を超えると $25 割引

マーケティングマネージャーは次の操作を実行します:

  1. アプリケーションランチャーをクリックし、次にマーチャントツール | サイト | オンラインマーケティング | プロモーションの順に選択します。3 種類のプロモーションが存在していることを確認して、欠落しているプロモーションがあれば追加します。
    • 注文金額が $100 を超えると送料無料
    • 注文金額が $100 を超えると 10% 割引
    • 注文金額が $200 を超えると $25 割引
  2. アプリケーションランチャーをクリックし、次にマーチャントツール | サイト | オンラインマーケティング | A/B テストの順に選択して、コンテンツプロモーションテストという ID でテストを作成します。
  3. テストを有効にして、テストで使用する任意の説明を入力します。
  4. キーメトリクスについて統計的に有意な結果が出た場合に通知を受信できるように、Eメールアドレスを指定します。
  5. キーメトリクスとして注文を選択しますが、結果を見る際に他のメトリクスも考慮します。(このテストは、最高のコンバージョン率につながるプロモーションを探しています。また、平均注文金額を最大化して、平均割引額を最小化するプロモーションも探しています。)
  6. 「顧客ごと」または「ブラウザーごと」のいずれかを選択して、より詳細な対照群を提供します。マーケティングマネージャーは、テスト中に繰り返しサイトに戻ってきた顧客には同じプロモーションを提示したいと考えています。
    メモ 顧客ごと 顧客プロファイルで追跡されるため、顧客が認識されると、同じテストセグメントに参加できます。「ブラウザーごと」の追跡は、参加がブラウザーの履歴と Cookie に関連付けられることを除けば「顧客ごと」と同様です。
  7. 顧客全員が参加できるように、Everyone (すべての顧客) グループからの参加者を含むようにテストを構成します。
  8. 3 つのテストセグメントを以下のように設定します:
    • 注文金額が $100 を超えると送料無料 に 30% 割り当て
    • 注文金額が $100 を超えると 10% 割引 に 30% 割り当て
    • 注文金額が $200 を超えると $25 割引 に 30% 割り当て
      メモ Business Manager は、自動的に残りの 10% を対照群に割り当てます。
  9. アプリケーションランチャーをクリックし、次にマーチャントツール | サイト | オンラインマーケティング | コンテンツスロットの順に選択してます。サイト上でヘッダーバナーという名前のスロットを探し、含まれる各プロモーションのバナーを表示します。次に、Header Banner に 3 つのスロット設定 (3 つのプロモーションのコンテンツに対し 1 つずつ) を作成します。
  10. テストに戻って、対照群以外の各テストグループに、対応するスロットの設定を体験として含めます。
  11. 開始日を次の日の真夜中に、終了日を土曜日の午後 9 時に設定します。(マーケティングマネージャーは、翌週月曜日に夏物クリアランスセールが始まる前に回答を得たいと考えています。)

Staging (ステージング) でテストを作成した後、そのテストを Production (本番) にレプリケートします。テストは真夜中に有効となります。次の朝には結果はまだありませんが、翌日には結果が出始めます。土曜日の朝に、結果が出たという Eメール通知を受信し、次のような結果を結果ページでレビューできます。

  • 注文: 注文金額が $100 を超えると送料無料 のセグメントでは、注文率 5% で統計的に有意な差が見られます。その他のセグメントでは、ほぼ同等の注文率 4% が示されています。
  • 平均注文金額: 注文金額が $200 を超えると $25% 割合 のセグメントでは、$59.50 で統計的に有意な差があります。その他のセグメントでは、ほぼ同等の平均注文金額の約 $47 が示されています。
  • 訪問ごとの平均収益: 注文金額が $100 を超えると送料無料 のセグメントの方が高いですが、その差異は統計的に有意ではありません。

マーケティングマネージャーは、注文金額が $100 を超えると送料無料 および注文金額が $200 を超えると $25 割引 のプロモーションの両方の効果が対照群より優れていると結論付けました。これらのプロモーションがサイトで使用されることになりました。

B2C Commerce でのソースコードをもつ 2 つ目の URL の追加

B2C ストアフロントの 2 つのセットの受信 URL を同じターゲットにマッピングします。

必要なエディション

使用可能なソリューション: B2C Commerce
メモ B2C Commerce で同時にアクティブにできるソースコードグループは 1 つのみです。
  1. サイト | オンラインマーケティング | ソースコードグループを選択します。
    1. 検索をクリックしてソースコードグループのリストを表示します。
    2. 選択したソースコードグループを開きます。
    3. コードタブで、ソースコード仕様フィールドに SpringSale と入力し、追加をクリックします。
    4. リダイレクトタブで、アクティブ: カテゴリオプションを選択します。
    5. カテゴリコードとして JA を入力して適用をクリックします。
  2. サイト名 | マーチャントツール | サイト環境設定 | ソースコードの順に選択します。
    1. ソースコード環境設定ページで、URL パラメーター名に src と入力します。
    2. 適用をクリックします。
  3. サイト名 | マーチャントツール | サイト URL | エイリアスの順に選択します。
    1. エイリアスページで、www.yourstore.com と入力します。
    2. 保存をクリックします。
  4. サイト名 | マーチャントツール | サイト URL | 動的マッピングの順に選択します。
  5. 動的マッピングページで、以下の 2 行のマッピングコードを入力します:
    • / specials /?src=* p,,,SourceCodeRedirect-Start,,src,{0}
    • / seasonal /?src=* p,,,SourceCodeRedirect-Start,,src,{0}
  6. 保存をクリックします。

    顧客は以下のいずれかを使用して移動できます:

    www.yourstore.com/specials/?src=SpringSale
www.yourstore.com/seasonal/?src=SpringSale

    受信 URL に関わらず、結果は同じになります。JA コードに対応するカテゴリページが表示されます。

B2C Commerce のプロモーションのアナリティクスとレポート

Salesforce B2C Commerce では、アナリティクスレポート、デバッグロガー、およびシステムログによってプロモーションのレポート作成を行います。

レポートの処理

多くの実装でプロモーションの処理にパイプラインが使用されるため、プロモーションのテストとトラブルシューティングを行う際には、パイプラインの使用状況レポートおよびパイプラインエラーレポートから役に立つ情報を入手できます。

Reports & Dashboards の Technical ダッシュボードを参照してください。またパイプラインデバッガーを使用することもできます。

コンバージョンレポート

プロモーションコンバージョンダッシュボードでは、プロモーションのコンバージョンを追跡します。Reports & Dashboards Promotion Conversion ダッシュボードを参照してください。

システムログ

システムログでは、API 処理、データステージング、およびエラーハンドリングに関連する情報を取得します。これらのログは、プロモーション関連の問題をトラブルシューティングする際に役立つことがあります。

B2C Commerce のソースコード対象プロモーションレポート

Promotions Source Code (プロモーションソースコード) ダッシュボードは、ソースコードによって対象となるユーザーが決定されるプロモーションの効果を理解するうえで役に立ちます。このトピックは、B2C Commerce に該当します。

Promotions Source Code (プロモーションソースコード) ダッシュボードにアクセスするには、マーチャントツール | サイト名 | Analytics | Reports & Dashboards の順に選択します。Promotions (プロモーション) タブを選択し、Source Code (ソースコード) タブを選択します。

このダッシュボードを使用して、ソースコードのコンバージョンアクティビティを表示し、ストアフロントでどのキャンペーンが注文と収益につながっているかを分析できます。以下の表に、Promosions ダッシュボードの 3 つのレポートを説明します。

レポート 提供される情報
Source Code Activations (ソースコードのアクティブ化) 注文コンバージョンがソースコードごとに分類されます。
Order Conversion Results (注文コンバージョン結果) ソースコードが少なくとも 1 つあるすべての訪問。
Conversion of Source Codes (ソースコードのコンバージョン) 少なくとも 1 つの注文を作成したソースコードのアクティブ化。

クーポン用の B2C Commerce API

B2C Commerce API を使用して、同じクーポンの複数のクーポンコードを買い物カゴに追加します。

この設定によって制御される動作は、クーポンが買い物カゴにどのように追加されるかに関係なく、強制されます。B2C Commerce Script API、SHOP API、AddCouponToBasket、またはAddCouponToBasket2パイプレット。

買い物カゴに一意のコードが追加されるたびに、一意のCouponLineItemが追加されます。逆に、すべてのCouponLineItemは 1 つのクーポンコードを表します。

注文が作成されると、その注文に関連付けられているすべてのクーポンコードが使用済みとしてマークされます。

アクティブな顧客のプロモーションを取得するロジックは、他のプロモーションの場合と同じです。たとえば、PromotionMgr.getActiveCustomerPromotions()は、プロモーションが 1 つのクーポンコードによってトリガーされたか、複数のクーポンコードによってトリガーされたかにかかわらず、同じ情報を返します。

このクーポンタイプを「ボーナス商品の選択」とともに使用する場合、B2C Commerce によって作成されたBonusDiscountLineItemはトリガーとなるクーポンコードに関連付けられます。トリガーとなるクーポンコードは、買い物カゴ内のクーポンコードとボーナス割引品目の位置によって決まります。この関連付けには B2C Commerce Script API 経由でアクセスできるため、ボーナス商品が特定のクーポンコードに関連していることをストアフロントアプリケーションで表示できます。買い物カゴからクーポンコードが削除されると、関連するボーナス商品のみが買い物カゴから削除されます。

B2C Commerce キャンペーンへのクーポンの割り当て

プロモーションを追跡および整理するには、1 つまたは複数の B2C Commerce キャンペーンにクーポンを割り当てます。クーポンのレポートと整理を行い、クーポンの有効期間をキャンペーンやプロモーションのスケジュールに関連付けることができます。プロモーションごとに同じ設定を繰り返す代わりに、キャンペーンのすべてのプロモーションにクーポンを適用します。プロモーションごとに例外を構成することは可能です。

  1. 関連するサイトで、オンラインマーケティング | クーポンを選択します。
  2. クーポンページで、クーポン ID を選択します。
    クーポンの編集ページが開きます。
  3. 「割り当て」タブに移動し、「割り当て」をクリックします。
  4. キャンペーンのリストから 1 つまたは複数を選択し、[ 割り当てる ] をクリックします。
    リストに表示されない場合は、特定のキャンペーンを検索します。
  5. 割り当てを保存します。
  6. キャンペーンからクーポンの割り当てを解除するには、1 つまたは複数のキャンペーンを選択して [ 割り当て解除 ] をクリックします。
  7. 変更内容を保存します。

B2C Commerce の「X を購入すると合計金額が」プロモーション

同じ小売価格または異なる価格の商品に「X を購入すると合計金額が」プロモーションタイプを使用します。このトピックは、B2C Commerce に該当します。

同じ小売価格の商品の例は、「各 $5 の任意のギフト 2 点を購入すると合計金額がたった $8」($2 割引) などです。一方、異なる価格の商品の例は、「商品 A は $6、商品 B は $5、商品 C は $5.50 で、買い物客は任意の商品 2 点を $8 で購入」 ($2 ～ $4 割引) などです。

メモ 対象商品と割引商品を区別することはサポートされていません。階層化は、対象商品ではなく割引商品でサポートされています。

割引処理

Salesforce B2C Commerce では、複数の商品の間で割引金額を比例配分し、すべての割引商品に均等に配分します。

  • 商品割引では、価格調整は商品品目の下に表示され、特定の割引のために算出された負の金額を表します。
  • 注文割引では、価格調整は注文割引の金額であり、個別ユニット、機能、その他の数量の各フィールドに基いて計算されます。

実際の割引は、元の価格とプロモーションで定義される価格の差額になります。

  • 標準の定額割引では、定額が商品品目ごとに適用されます。

    たとえば商品単価が $10 で定額割引額が $8 の場合、価格調整はこの 2 つの価格の差額である $2 です。

  • 価格が複数に分かれる場合の「X を購入すると合計金額が」プロモーションでは、複数の商品に基いて割引が計算されます。次に、その割引金額がすべての割引商品に均等に配分されます。

商品グループ内の割引されていない価格の合計が割引価格よりも低い場合、その価格が引き上げられて割引価格になることはありません。

例

「シャツ 3 枚を購入すると合計金額が $22」というプロモーションを提示しているとします。

買い物客の買い物カゴには以下の商品が入っています。

シャツの色 注文個数 単価
レッド 2 $13
ブルー 2 $12

価格調整は次のようになります:

シャツの色 注文個数 単価 調整価格 商品ごとの割引
レッド 2 $13 $10.95 $5.47
ブルー 1 $12 $5.05 $5.05

割引計算の明細は以下のとおりです。

  1. 割引定額: $22
  2. 該当する割引商品: レッドシャツ x 2、ブルーシャツ x 1
  3. 該当する割引商品の合計価格: 2 x $13 + 1 x $12 = $38
  4. 合計割引金額: $38 - $22 = $16
  5. 割引率 (%): 16/38 = 0.421 (42.1%)
  6. レッドシャツ 1 点ごとの価格調整: $13 x 0.421 = -$5.47
  7. ブルーシャツ 1 点ごとの価格調整: $12 x 0.421 = -$5.05

プロモーションはレッドシャツ 2 枚に適用されますが、ブルーシャツは 1 枚だけにしか適用されません。これは、レッドシャツの方が高いため、割引金額が大きくなるからです。

階層の例

「X を購入すると合計金額が」プロモーションの階層化は、他の階層化プロモーションタイプとは異なります。通常は、該当する最高の階層のみが適用されます。たとえば、2 点以上購入すると、それぞれ 1 点が $10 になります。4 点以上購入すると、それぞれ 1 点が $9 になります。

「X を購入すると合計金額が」プロモーションでは、買い物カゴの中にある商品の数に応じてすべての階層が適用されることがあります。

たとえばマーチャントが、「シャツ 2 枚を購入すると合計金額が $20、シャツ 3 枚を購入すると合計金額が $22 」(適用制限なし) というプロモーションを提示しているとします。買い物カゴには割引商品が 5 点入っています。

B2C Commerce の「X の購入で Y をゲット」プロモーション

「X の購入で Y をゲット」プロモーションは、もっとも標準的なプロモーションタイプの 1 つです。このトピックは、B2C Commerce に該当します。

「X の購入で Y をゲット」プロモーションでは対象商品は割引できません。同じ商品が対象商品にも条件商品にもなれる場合、価格がもっとも高い商品が条件を満たし、価格が同じかそれより低い商品に割引が適用されます。

メモ クラス除外の「X の購入で Y をゲット」の商品プロモーションでは、割引商品と対象商品のどちらも、それ以上は割引対象になりません。

割引の適用を制御するには、サイト環境設定を使用します。どの商品に割引を適用するか、および割引適用商品の価格が対象商品よりも高くてもよいかどうかを決定します。

「X の購入で Y をゲット」プロモーションの階層化

「X の購入で Y をゲット」プロモーションの階層を作成するには、プロモーションが適用される正確な数の割引商品が必要です。割引対象となるかどうかの判定には、買い物カゴ内の合計数量が使用されます。たとえば、買い物カゴに 4 つの商品があり、このうち 3 つが「商品 3 点の購入で商品 2 点が無料」の割引の対象となるとします。割引には 2 つの無料商品が必要なため、残りの商品は割引の対象となりません。

買い物カゴに「X の購入で Y をゲット」割引の対象となる商品が複数ある場合、B2C Commerce では割引適用商品グループで数量のもっとも多い「X の購入で Y をゲット」プロモーションが最初に考慮されます。数量の最も高い「X の購入で Y をゲット」プロモーションを最初に適用すると、「X の購入で Y をゲット」割引は余分に適用されずに、買い物客にとっての価値が最大化されます。

買い物カゴ内の数量が複数の「X の購入で Y をゲット」階層プロモーションのしきい値を超える場合、B2C Commerce ではもっともメリットの大きいプロモーションのみが適用されます。たとえば、買い物カゴに 6 点の商品が入っているとします。この場合、買い物カゴには「商品 2 点の購入で商品 1 点が無料」ではなく、「商品 3 点の購入で商品 2 点が無料」のプロモーションが適用されます。これは、後者の方が買い物客にとってメリットが大きいためです。

1 つの「X の購入で Y をゲット」プロモーションが適用された商品は、同じ買い物カゴ内で同じ階層の別の「X の購入で Y をゲット」プロモーションに考慮されることはありません。ただし、別の「X の購入で Y をゲット」など、他のプロモーションに考慮されることはあります。たとえば、買い物カゴに商品が 4 点入ってる場合です。B2C Commerce では最初の 3 点の商品に「商品 3 点の購入で商品 2 点が無料」プロモーションが適用された後に、4 つ目の商品に「商品 2 点の購入で商品 1 点が無料」プロモーションが適用されます。

例

同じ商品に対して 2 つのプロモーションがあります。「商品 3 点の購入で商品 2 点が無料」と「商品 2 点の購入で商品 2 点が無料」です。買い物カゴが商品が 4 点入っています。最善の割引は「商品 2 点の購入で商品 2 点が無料」で、2 回の適用で 4 点の商品が無料になります。「商品 3 点の購入で商品 2 点が無料」では 2 点の商品しか無料になりません。

結果は設定の金額に基づいて決まります。プロモーションが適用されるには、正確な数の割引商品が必要です。

この設定が有効な場合、割引が適用されるには 3 点の対象商品と 2 点の無料となる商品が必要なため、2 回目の割引は適用されません。

B2C Commerce のキャンペーンとプロモーション

Business Manager のオンラインマーケティングモジュールで、プロモーション、コンテンツスロット、並べ替えルールなどの体験を含むラッパーの役割を果たすキャンペーンと A/B テストを作成します。ただし、スロットの設定と並べ替えルールを有効にするために、キャンペーンや A/B テストへの割り当ては必要ありません。スロットの設定は、A/B テストの範囲外でスケジュールできます。デフォルトの並べ替えルールは、キャンペーンまたは A/B テストの範囲外で、ストアフロントカタログのカテゴリに設定できます。このトピックは、B2C Commerce に該当します。

キャンペーンを使用して複数の体験用にスケジュールを定義し、複数のプロモーションや並べ替えルールに限定子 (クーポンなど) を定義できます。体験がキャンペーンに割り当てられているときは、そのスケジュールと限定子で絞り込めるのは、キャンペーンに含まれている体験だけになります。キャンペーンは、特定のサイト内で定義し、複数サイト間で共有できません。キャンペーンは有効または無効にできます。無効なキャンペーンは非アクティブです。消費者はそのキャンペーンを利用できません。無効なキャンペーンに含まれる有効なプロモーションも非アクティブです。固有のビジネス要件を満たすために、カスタム属性でキャンペーンを拡張します。

プロモーションのタイプ、条件、割引を定義するルールはプロモーションに含まれます。また、各自のビジネス要件に対応するカスタム属性で拡張することもできます。プロモーションに関連付けられている商品、カテゴリ、配送方法を削除しても、そのプロモーション (およびそのルール) は削除されません。

B2C Commerce には、商品、注文、配送の 3 つのプロモーションクラス、つまりプロモーションの割引を定義する方法があります。

B2C Commerce の注文処理では、特定のタイミング、特定の優先順位で、プロモーションの処理が行われます。利用可能なプロモーションのアナリティクスとレポートには、処理レポート、コンバージョンレポート、システムログなどがあります。

B2C Commerce のプロモーション環境設定の構成

プロモーション設定の多くをサイト環境設定で構成すると、プロモーションの処理方法を非常に柔軟に調整できます。これらの設定には、「X の購入で Y をゲット」のプロモーション処理、割引精度、割引適用品目の課税基準の計算方法などがあります。

必要なエディション

使用可能なソリューション: B2C Commerce

次のステップでは各環境設定について、動作の仕組みとオプションの差異について説明します。

  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | サイト環境設定 | 価格設定とプロモーションの順に選択します。
  2. 「X の購入で Y をゲット」プロモーションの動作を構成します。
    価格が次に高い商品に割引を適用 (デフォルト)
    • 対象商品は、プロモーションの対象商品ルールを満たす商品のうち価格が最も高い商品 (X) です。
    • 割引が適用される商品は、プロモーションの割引商品ルールを満たす残りの商品のうち価格が次に高い (または価格が同じ) 商品 (Y) です。
    • 割引商品の価格は、関連する対象商品の価格より低くする必要があります。
    価格が最も低い商品に割引を適用
    • 対象商品は、プロモーションの対象商品ルールを満たす商品のうち価格が最も高い商品 (X) です。
    • 割引が適用される商品は、プロモーションの割引商品ルールを満たす残りの商品のうち価格が最も低い商品 (Y) です。
    • 割引商品の価格は、関連する対象商品の価格よりも安くなります。
  3. 「X の購入で Y をゲット」の割引対象を構成します。
    この設定は「X の購入で Y をゲット」のプロモーションにのみ適用され、「X と Y の購入で Z をゲット」やその他のプロモーションタイプには適用されません。これらのプロモーションでは、プロモーション割引処理は常に「割引商品の最高価格」の設定で定義します。
    割引商品の最高価格 (デフォルト) 対象商品のうち価格が最も低いものと同じかそれより低い価格が設定されている商品にのみ割引が適用されます。この設定により、割引商品の価格が増加するようなプロモーションが作成されることがないようにします。
    割引の対象となるすべての商品 プロモーションの割引ルールを満たす商品が、割引対象となります。この設定は、対象商品と同一ではない割引商品のプロモーションにのみ該当します。
  4. 価格表の割引の動作を構成します。
    割引による品目価格の増加を許可する (デフォルト) 割引によって、買い物カゴ内の品目の価格が増加することがあります。これは望ましくありません。
    割引による品目価格の増加を許可しない 価格表からの価格の割引によって、買い物カゴ内の品目の価格が増加するのを防ぎます。たとえば、プロモーションで 2 つの価格表を使用している場合に、1 つの価格表での商品のセール価格が、他方の価格表での標準価格よりも高いような場合です。
  5. 「ボーナス商品の位置」を構成します。
    この設定を使用して、買い物カゴ内のボーナス商品の表示位置を制御します。「対象商品の数に基づく 」プロモーションで、ボーナス 商品割引が付与されている商品プロモーションにのみ適用されます。
    常に買い物カゴの最後 (デフォルト) ボーナス商品は数量 1 で買い物カゴの一番下に移動します。
    対象商品の後 ボーナス商品は、対象商品の後に表示され、数量が 1 より大きい場合はまとめて表示されます。
  6. 「割引精度」を構成します。
    中間地点の値は、プラスの場合とマイナスの場合の両方で切り上げられることが多くなります。この慣行は四捨五入といい、一般的に使用されます。たとえば、値 23.5 は 24 に丸められ、値 −23.5 は −23 に丸められます。
    サイト通貨の精度 (デフォルト) 割引はサイト通貨の精度に基づいて計算されます。丸めモードは四捨五入です。
    小数点以下なし 割引は常に整数値に丸められ、小数点以下は含まれません (精度=0)。丸めモードは四捨五入です。
  7. 「割引課税」を構成します。
    価格に基づいて商品、送料、割引に課税 (デフォルト) すべての品目は、ネットまたはグロス価格を課税基準として使い、個別に課税されます。商品および配送料への課税金額はプラスになり、価格調整への課税はマイナスになります。
    調整価格に基づいて商品および送料のみに課税 価格調整は課税されません。その代わり、課税基準として、商品の品目では比例配分された価格が、送料の項目では調整価格がそれぞれ使用されます。課税金額はゼロ以上です。
  8. 注文ごとの複数クーポンコードを設定します。
    クーポンコードの併用を防止 (デフォルト) 1 つの注文プロモーションで複数のクーポンコードを使用できないようにします。
    クーポンコードの併用を許可 1 つの注文プロモーションで複数のクーポンコードを使用できるようにします。クーポンでこの設定が有効になっている場合、クーポンの追加時にのみ検証されます。
  9. 「現時点以降の購入」を設定します。
    無効 (デフォルト) 今後のプロモーションについては、買い物客は注文手続き中に利用できません。
    有効 買い物客は、今後の日付でアクティブなプロモーションを使用できます。特定の期間内にアクティブなプロモーションを取得するには、有効日を設定します。現時点以降の購入を参照してください。

B2C Commerce でのプロモーションの管理

Salesforce B2C Commerce で、プロモーションの適用方法を制御します。

  • B2C Commerce のプロモーション環境設定の構成
    プロモーション設定の多くをサイト環境設定で構成すると、プロモーションの処理方法を非常に柔軟に調整できます。これらの設定には、「X の購入で Y をゲット」のプロモーション処理、割引精度、割引適用品目の課税基準の計算方法などがあります。
  • B2C Commerce での特定の店舗への価格表またはプロモーションの割り当て
    店舗固有の価格設定とプロモーションでは、最大 2,000 の店舗に価格表を選択します。この割り当てフレームワークにより、マーチャントとデベロッパーは、プロモーションなどの特定の体験をアクティブにする限定子 (店舗など) を設定できます。また、特定の店舗にプロモーションを割り当てることもできます。この機能は、XML のインポートを通じてのみサポートされています。サイト割り当てを使用するには、まずデベロッパーが、店舗割り当てを含むように割り当ての XML を編集する必要があります。現在、割り当てとしてリストできるのは店舗のみです。
  • B2C Commerce のプロモーションスケジュール
    B2C Commerce でキャンペーン、A/B テスト、プロモーション、コンテンツスロットをスケジュールします。スケジュールされた体験 (プロモーションまたはコンテンツスロット) は、コンテナ (キャンペーンまたは A/B テスト) と同時に行う必要があります。一致させないと、実行できません。
  • B2C Commerce での階層割引
    割引を階層化して、買い物客が購入する商品または金額が増加するほど割引金額が増加するようにします。条件パラメーターに複数のしきい値レベルがあるプロモーションでは、割引がしきい値によって異なり、組み合わせることができない階層割引を構成します。
  • B2C Commerce のプロモーション互換性
    互換性ルールを使用して、プロモーションの適用をコントロールします。互換性ルールでは、買い物客が可能なすべてのプロモーションの対象となることを防止できます。ランクおよび除外のシステム属性を使用して、プロモーションの互換性を管理します。
  • B2C Commerce のプロモーションの最大適用数
    最大適用数の制限を使用して、注文ごとに適用できるプロモーションの回数を制限します。
  • B2C Commerce での体験の対象者の指定
    限定子を使用して、体験の対象者とプロモーションの利用方法を指定します。限定子には、顧客グループ、クーポン、またはソースコードがあります。プロモーションに限定子を追加するには、キャンペーンに限定子を割り当てる (すべての対象のプロモーションに影響) か、特定のプロモーションに限定子を割り当てるかの 2 つの方法があります。
  • B2C Commerce の対象商品と割引商品
    対象商品、買い物客が購入する商品、および割引の対象となる金額を指定するプロモーションを定義します。また、どの商品が割引されるかも指定します。
  • 同一商品のみのプロモーション制限
    制約を設定すると、商品の選択が同一商品に制限されます。商品プロモーションルールで制約を設定すると、複数の商品に適用される単一商品プロモーションを構成することになります。
  • アクティブな価格表に基づくプロモーションの対象資格
    価格表の条件を使用して、商品をプロモーションに含めたり、プロモーションから除外したりします。

B2C Commerce のクーポンの使用

使用制限を設定して割引オファーを制御し、プロモーションキャンペーンを予算内に収めます。顧客別または時間制限別にクーポンの使用状況を管理します。

プロモーションの対象となるには、買い物客は注文手続きでクーポンを使用します。デフォルトでは、商品ごとに 1 つのクーポンコードがデフォルトですが、買い物客は複数のクーポンコードを入力できます。また、配送用および注文全体のクーポンを提供することもできます。

ローリング使用では、買い物客は 7 日間に 1 回クーポンを使用できます。顧客が月曜日の午前 11:00 に注文にクーポンを適用した場合、顧客は次週月曜日の午前 11:00 までクーポンを再度使用することはできません。

クーポン使用データは、インポートおよびエクスポートできます。

クーポンの使用の処理

B2C Commerce では、顧客が買い物カゴにクーポンを追加するたびに、および買い物カゴが再計算されるたびに、使用制限が評価されます。

1 回のみ使用できるクーポン

クーポンは 1 人の買い物客が 1 回しか使用できません。その人がゲストとしてチェックアウトしてクーポンを 2 回使用しようとすると、B2C Commerce は買い物客の Eメールアドレスに対して検証を行います。登録済みの買い物客の場合、買い物客がクーポンを買い物カゴに追加すると、B2C Commerce で使用制限が検証されます。未登録の買い物客の場合、買い物客が請求ページで Eメールアドレスを入力すると、B2C Commerce によって使用制限が検証されます。

注文ごとの複数回使用クーポン (ベータ)

同じ買い物カゴ内の注文ごとにクーポンの使用回数を指定します。

  • 1 つ (デフォルト) — 買い物客は特定のクーポンに対して 1 つのコードを買い物カゴに適用できます。
  • 複数 (ベータ) — 買い物客はクーポンを 1 つの買い物カゴに複数回適用できます (一意のクーポンコード 1 つにつき 1 回)。

買い物客が注文すると、すべてのクーポンコードが使用済みとしてマークされます。複数回使用できるクーポンでは、同じプロモーションを複数の対象商品またはトランザクションに複数回適用できます。これは、買い物客が同じ商品に対して複数の割引を受けるという意味ではありません。

商品プロモーションには、複数のクーポンコードを複数回適用できます。たとえば、割引商品を 10% 割引にするプロモーションがあります。最大使用回数は 2 回ですが、買い物カゴには 3 つの異なるクーポンコードが含まれています。したがって、プロモーションは最大 6 回まで適用できます。

重要 注文レベルの割引は、複数回使用できるクーポンコードではサポートされていません。この制限により、買い物客がクーポンコードを繰り返し適用して、注文全体を無料で取得することを防ぐことができます。B2C Commerce では商品ごとにプロモーションごとに 1 つの割引が適用されるため、商品レベルの割引は問題になりません。

デベロッパーの注意事項

買い物カゴ内に同じクーポンからのコードが複数ある場合、コードは別々の CouponLineItems として表示されます。

B2C Commerce では、どのクーポンコードがボーナス商品の選択割引をトリガーするかを追跡します。買い物客が買い物カゴからクーポンコードを削除すると、対応する BonusDiscountLineItem とすべての関連するボーナス商品が削除されます。クーポンコードと割引商品の関係は、他のタイプのプロモーションでは保持されず、B2C Commerce の将来のアプリケーションには影響しません。

  • B2C ストアフロントのクーポン使用の追跡と管理
    クーポンの使用データを表示して、誰がいつクーポンを使用するかを追跡および管理します。すべてのクーポンの使用データを検索および分析したり、クーポン固有の使用データを表示したりできます。また、使用されたクーポンから買い物客の Eメールアドレスを削除できます。使用は注文に関連付けられています。買い物客が注文を削除すると、使用済みクーポンは削除されます。クーポンとコードを削除しても、使用済みのクーポンには影響しません。
  • 同じ B2C Commerce 注文での複数クーポンの使用制限
    買い物客は 1 回の B2C Commerce 注文で複数のクーポンコードを適用できます。

クーポンのインポート

クーポンのインポートと Business Manager のクーポンのユーザーインターフェイスでは、同じ制約が検証に使用されます。使用される制約は以下のとおりです。

許可されないもの：

  • コードごとの使用制限、顧客ごとの使用制限、期間ごとの使用制限 > 制限、または期間ごとの使用制限 > 期間、およびシステムにより生成されるクーポンコードのコードの最大数における負の数値。

  • クーポンのタイプの変更 (置換モードを除く)。
  • コードの最大数なしのシステムコードクーポンの作成。

許可されるもの：

  • システムにより生成されるクーポンコードの接頭辞が空白の文字列に設定されている場合の、接頭辞の削除。
  • システムにより生成されるコードの設定の更新 (クーポンがまだ使用または発行されていない場合に限る)。
  • 単一コードのクーポンの更新 (未変更のコードが xml ファイルにある場合を含む)。

次の XML サンプルは、クーポンコードの使用データを含む注文エクスポートを示しています。クーポンの使用状況を表示するには、サイト | 名マーチャントツール | オンラインマーケティング | クーポン | 使用済みクーポンの表示の順に選択します。

クーポン使用データは XML 形式で、または一度に 1 コードずつ CSV 形式でインポートおよびエクスポートします。ただし、クーポン使用データのインポートは稀なケースでしか行わないでください。クーポン使用データを 1 つのインスタンスからエクスポートして、別のインスタンスにインポートする場合、すべての適切なクーポンと注文の情報が事前にインポートされていることを確認してください。これを怠ると、インポートが期待どおりに動作しない可能性があります。

B2C Commerce のクーポン XML ファイルのサンプル

Business Manager を使用して、または XML 形式でクーポン定義をインポートすることにより、クーポンを作成することができます。以下の XML の例は、クーポンのインポート形式の主な要素を示しています。このトピックは、B2C Commerce に該当します。

<coupons>

このクーポン定義は、1 人の顧客につき週に 5 回まで、1 人の顧客につき 1 つ、最高 500 回使用できることを示しています。

	<coupon coupon-id="myCoupon">
		<description>クーポンの説明</description>
		<enabled-flag>true</enabled-flag>
		<redemption-limits>
			<limit-per-code>500</limit-per-code>
			<limit-per-customer>1</limit-per-customer>
			<limit-per-timeframe time-frame="week">5</limit-per-timeframe>
		</redemption-limits>

デフォルトでは、すべてのクーポンで大文字と小文字が区別されます。クーポンコードで大文字と小文字を区別しない場合は、ここで定義します。この定義は、既存のコードがないクーポンでのみ機能します。

		<case-insensitive>true</case-insensitive>

クーポンが単一コードの場合、ここで定義します。

		<single-code>DRR94IGB49S</single-code>

クーポンがシステム生成コードの場合、この例では、接頭辞が「ABC」で 1000 回まで発行されます。

		<virtual-codes>
			<code-prefix>ABC</code-prefix>
			<code-limit>1000</code-limit>
		<virtual-codes>

クーポンが複数コードの場合、ここに表示されます。コードが多数あるクーポンでは、システムで生成されたクーポンを使用します。「システムにより生成されたクーポンコード」を参照してください。

		</coupon>
		 <coupon-codes coupon-id="myCoupon">
			<code>ABEEO48HD4C</code>
			<code>ABRREO48H7F</code>
		</coupon-codes>
	...
</coupons>

B2C Commerce でのキャンペーンの作成

キャンペーンはプロモーションと限定子のラッパーとして機能します。キャンペーンを作成する際は、プロモーションやスロット設定のグループ全体に対してスケジュールと限定子を定義します。

必要なエディション

使用可能なソリューション: B2C Commerce

プロモーション、スロットの設定、および並べ替えルールなど、キャンペーン内のすべての体験は、キャンペーンに定義されている情報を継承します。これらの継承した情報は、有効化のステータスを除き、上書きまたは調整することができます。

ヒント 同様のスケジュールをもつプロモーションは、同じキャンペーンに含めることをお勧めします。他のプロモーションと共通点のないプロモーションがある場合は、別のキャンペーンに含めることを検討してください。
  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | オンラインマーケティング | キャンペーンの順に選択します。
    プロモーションとコンテンツスロットの割り当て、およびスケジュールタイムラインのグラフを表示するには、プラスのアイコンをクリックします。
  2. 新規をクリックします。
  3. 全般情報を定義します。
    キャンペーンを無効にすると、そのキャンペーン内のすべてのプロモーションも無効になります。
  4. キャンペーンの日付を指定するか、開始日なしまたは終了日なしを選択します。
    日付を設定しない場合、キャンペーンは無期限で実行されます。
  5. キャンペーンの対象者とトリガー方法を調整するには、限定子を割り当てます。
  6. 体験の追加をクリックし、含めたい体験を選択して、適用をクリックします。
    1. スロットの設定を追加した場合は、スケジュールに変更を加えて、顧客グループを割り当てます。
    2. プロモーションを追加した場合は、スケジュールに変更を加えて、キャンペーンページから限定子を割り当てます。プロモーションとソースコードを有効または無効にしたり、プロモーションの除外を体験内から変更したりできます。
    3. 並べ替えルールを追加した場合は、並べ替えルールが影響を与えるカテゴリを選択します。
  7. 適用をクリックします。

B2C Commerce でのプロモーションの作成

すべてのプロモーション (商品、配送、注文) は同じ方法で作成します。ただし、ルールの仕様は異なります。

必要なエディション

使用可能なソリューション: B2C Commerce

以下の基本的な指示に従って、プロモーションを作成します。プロモーション環境設定を構成し、開始前に注文手続きを行うことをお勧めします。プロモーションを完成したら、キャンペーンまたは A/B テストに追加します。プロモーションを表示する際には、無効なキャンペーンに属するプロモーションには引き続き有効のフラグが表示されることに注意してください。複数のプロモーションを同時に実行する場合は、互換性とランキングを使用して、望ましくない組み合わせを避けるようにします。

  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | オンラインマーケティング | プロモーションの順に選択します。
    選択内容を新しいタブやウィンドウで開くなど、標準的な操作を実行するには、このグリッドのリンクを右クリックします。
    プロモーションを削除するには、削除するプロモーションを選択して削除をクリックします。商品を有効化または無効化する、またはグローバルに除外された商品を有効化または無効化するには、その他をクリックします。
  2. 新規をクリックします。
  3. 全般情報を定義または編集します。

    検索可能フィールドでは、Salesforce B2C Commerce API を介して、商品プロモーションに関連付けられているすべての対象商品と割引商品を検索できます。このフィールドでは、ストアフロントの 1 か所にすべての対象商品と割引商品を表示し、購入者に対してより良い決定を行うための情報や選択肢を提供できます。

  4. 除外ルールを使用して、プロモーションの一般的な互換性を設定します。このルールに対する例外を、組み合わせと相互排他性を使用して構成できます。プロモーション互換性の「相互排他的なプロモーションと組み合わせ可能なプロモーション」のセクションを参照してください。適用をクリックします。
  5. プロモーションルールセクションで、プロモーションクラスを指定して、必要な情報を入力します。
  6. プロモーションクラスセクションの下で適用をクリックします。

プロモーションに割引を追加する方法については、このビデオをご覧ください。

動画を全画面表示で視聴できない場合は、次のリンクを新しいタブで開きます。プロモーションに割引を追加します。

B2C Commerce でのキャンペーンとプロモーションの作成

完全なマーケティングとプロモーションのキャンペーンの作成は手間のかかる作業に思えるかもしれませんが、そのようなことはありません。まず全体的な目標を決め、次に必要なタスクに分割していきます。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. まず体験の作成から始めます。体験には、プロモーション、スロットの設定、および並べ替えルールの 3 つのタイプがあります。たとえば、以下のものを作成できます:
    • アカウントを 5 年以上もっている顧客を対象とした販売を提供するプロモーション
    • ストアフロントで未登録の顧客が見るコンテンツをターゲットとしたスロット設定
    • 検索結果の表示順序の並べ替えルール
  2. プロモーションを作成します。プロモーションはサイト全体を対象とするか、限定子でトリガーすることができます。プロモーションは商品、注文全体、または配送に適用できます。以下がその例です:
    • シャツ 2 枚の購入で 1 枚が無料
    • 10,000 円以上の買い物で 20% 割引
    • 注文にネクタイを追加すると配送料無料
    クーポン、顧客グループ、またはソースコードなどの限定子を定義することで、プロモーションをさらに制御できます。
  3. スロット設定を作成します。スロット設定は特定の顧客をターゲットにします。たとえば、ホームページのコンテンツスロットは、上位買い物客をターゲットとします。
  4. 並べ替えルールを作成します。並べ替えルールでは、ストアフロントで商品が表示される順番を定義します。たとえば、売れ筋商品で並べ替えて、顧客が販売数の多い商品を最初に見ることができるようにします。
  5. キャンペーンを作成して設定します。たとえば春物キャンペーンに、サンダルを割引するプロモーションと、グリーンの商品を最初に表示する並べ替えルールを含めます。顧客はクーポン SPRINGFUN を使用して、プロモーションをトリガーします。このキャンペーンは春の最初の 1 か月間実行されます。
    1. キャンペーンに体験を追加します。
    2. キャンペーンに限定子を追加します。
    3. キャンペーンをスケジュールします。
  6. 各体験で、以下を実行します:
    • プロモーション: スケジュールに変更を加えて、顧客グループ、ソースコード、クーポン、ランクを割り当てます。
    • スロットの設定: スケジュールに変更を加えて、顧客グループとランクを割り当てます。
    • 並べ替えルール: 1 つ以上のカテゴリを割り当てます。
  7. 全体的なマーケティングの目標に照らして、プロモーション、コンテンツスロット、並べ替えルールの効果を判断するために、A/B テストを作成して実行します。
  8. キャンペーンとプロモーションをストアフロントでテストします。
  9. キャンペーンに満足したら、オンラインに設定します。

B2C Commerce での顧客の位置情報に基づく顧客プロモーションの作成

顧客の IP アドレスを決定し、その IP アドレスに基づいて顧客の地理的位置情報を検索します。

位置情報に基いて動的顧客グループを作成する場合は、プロモーションとストアフロント体験を、顧客の一般的な地理的位置情報に基づいてカスタマイズします。

Salesforce B2C Commerce では、すべてのインスタンスで共有される MaxMind の IP 地理位置情報データベースを提供しています。このデータベースは、グローバルリリースの際に必要に応じてアップデートされます。

メモ このデータベースから取得した情報はエクスポートできません。位置情報インポート/エクスポートスキーマは、IP アドレス情報に基いていない店舗位置情報データベースにのみ使用してください。

顧客グループを限定子として使用するプロモーションを作成します。顧客グループをキャンペーンまたはプロモーションに割り当てる方法については、キャンペーンの作成およびプロモーションの作成を参照してください。

メモ ストアフロント体験のカスタマイズの詳細については、アクティブマーチャンダイジングでの動的顧客グループの使用を参照してください。顧客がログインしなくても、IP アドレスを判断して地理的位置情報の判定に使用することが可能です。

顧客グループを Web サイトでテストするには、現在の位置情報をもつグループを含めます。これにより、ストアフロントにログインして機能をテストできます。作成した顧客グループをテストするには、ストアフロントツールキットのサイトプレビューツールを使用します。

ルールデータのテスト

市区町村や地域に依存する顧客グループを使用している場合は、ルールを作成する前にサンプル IP アドレスをデータベースでテストすることをお勧めします。データベースの地域情報の精度が予想よりも低い場合に、作成した顧客グループのルールが正しくトリガーされない可能性があるからです。このトピックを開始する前に、IP アドレスの位置情報データモジュールを使用するための許可を受けていることを確認してください。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーをクリックし、管理 | オペレーション | IP アドレスの位置情報データの順に選択します。
  2. IP アドレスの位置情報データページで、IP アドレスを入力してから検索をクリックします。

    データベースに登録されている IP アドレスの市区町村、地域、国、郵便番号、メトロコード、緯度、経度が表示されます。予想と異なる結果を書き留めておき、顧客グループメンバーシップルールを作成するときに、この情報を使用してください。

地域顧客グループの作成

ルールを使用して、顧客がログインしたときの IP アドレスの位置情報データによって顧客グループを定義します。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーをクリックし、次にマーチャントツール | サイト | 顧客 | 顧客グループの順に選択します。
  2. 顧客グループの管理ページで、新規をクリックして顧客グループを作成します。
  3. 新規顧客グループページで、ID (必須) を入力します (例: USA_NY_Customers)。
  4. タイプに動的を選択します。セッション中は顧客の位置情報が存在しますが、B2C Commerce に保存されることはないため、地域顧客グループが静的になることはありません。
  5. 説明 (例: ニューヨークの顧客) を入力し、適用をクリックします。メンバシップルールフィールドが表示されます。
  6. 編集をクリックします。
  7. 含める/含めない顧客グループのウィンドウで、属性フィールドをクリックします。使用可能なルールの詳細については、動的顧客グループの属性を参照してください。
  8. 位置情報の属性を使用するルールを作成します。顧客グループをテストするには、現在の位置情報を持つグループを必ず含めてください。これにより、ログインして機能をテストできます。

ギフト券の作成

Business Manager を使って、ギフト券を個々に作成します。ギフト券はステージングできないため、Production (本番) 環境で作成および管理します。このトピックは、B2C Commerce に該当します。

必要なエディション

使用可能なソリューション: B2C Commerce

ギフト券が使用できるかどうかは、ギフト券のステータス、およびギフト券が有効になっているかどうかによって異なります。ギフト券の作成後に額面を編集することはできません。実行可能な操作はギフト券を使用することのみです。

ステータス 説明 有効=True 有効=False
保留中 既存の、使用できないギフト券 使用不可 使用不可
発行済み 既存の、未使用のギフト券 使用可能 使用不可
一部使用済み 金額の一部を使用したギフト券 使用可能 使用不可
使用済み 残高のないギフト券 使用不可 使用不可
  1. マーチャントツール | サイト名 | オンラインマーケティング | ギフト券の順に選択します。
    クーポンを編集または削除するには、行の最後にあるメニューを使用します。
  2. 新規をクリックします。
  3. 必要な情報を入力して、適用をクリックします。

    システムが生成したギフト券コードは 16 文字の英数字です。Salesforce B2C Commerce では、後方互換性を保つためにレガシーの 10 文字のコードをサポートしています。

  4. ギフト券のリストを表示するには、検索をクリックします。

B2C Commerce での注文プロモーションルールの作成

注文プロモーションルールは、注文全体に適用されます (例: 4 月のすべての注文に 20% の割引)。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | オンラインマーケティング | プロモーションの順に選択します。
  2. 新規をクリックします。
  3. 一般的なプロモーション情報を入力または選択して、適用をクリックします。
  4. プロモーションクラスに注文を選択します。
  5. プロモーションタイプを選択します。
  6. 割引を指定します。階層割引を行うことができます。
    ボーナス商品割引は独特の動作をもつことに注意してください。この動作はプロモーション環境設定で構成できます。
    割引として「ボーナス商品の選択」を選択した場合は、ストアフロントアプリケーションを変更する必要があります。
  7. 商品を除外するには、編集をクリックし、除外商品を選択して、適用をクリックします。
    「商品レベルの割引を受けた商品や品目も除外する。」を選択できます。商品プロモーションのクラス除外の環境設定値に基づいて、買い物カゴまたは注文のすべての SKU または個々の商品が除外されます。
    ルールで注文の合計金額から割引が行われる場合は、プロモーションでは合計割引対象金額に除外商品のコストは含まれません。
  8. 対象商品を指定するには、編集をクリックします。
    対象商品を設定しないと、注文内のすべての商品が商品合計額に含められます。
  9. 支払方法に基づいて注文の割引が行われるプロモーションの場合は、支払方法で編集をクリックし、支払方法を選択します。
    「ボーナス商品」と「ボーナス商品の選択」の注文プロモーションクラスには、支払方法の割引を作成することはできません。支払方法による割引は、注文が確定した時点で、ボーナス商品が選択される前に計算されます。
    顧客が対象となる支払方法を複数使用する場合は、分割支払が発生する場合があります。分割支払の注文にプロモーションが適用されるのを防ぐには、Salesforce のカスタマーサポートまでお問い合わせください。
  10. 注文が割引プロモーションに近づいていることを顧客に知らせるには、通知を選択します。条件をトリガーするのに必要な商品合計金額を入力します。
  11. 適用をクリックします。

B2C Commerce での配送プロモーションルールの作成

配送プロモーションは、配送料に適用されます (例: 注文金額が $100 を超えると送料無料)。買い物カゴには複数の配送が含まれることがあるので、商品の配送プロモーションは各配送に個々に適用されます。

必要なエディション

使用可能なソリューション: B2C Commerce
  1. アプリケーションランチャーをクリックし、マーチャントツール | サイト | オンラインマーケティング | プロモーションの順に選択します。
  2. 新規をクリックします。
  3. 一般的なプロモーション情報を入力または選択して、適用をクリックします。
    プロモーションルールセクションが表示されます。
  4. プロモーションクラスに配送を選択します。
  5. プロモーションタイプを選択します。
  6. 割引を指定します。金額を入力する際には、通貨記号は含めないでください。
  7. 階層割引を設定するには、追加をクリックして別の割引を追加します。これは、「配送対象商品の組み合わせに基づく」のルールとは互換性をもちません。
    階層には必ず一意のしきい値を指定してください。たとえば、両方とも $100 でトリガーされる 2 つの階層割引を作成することはできません。
  8. 対象商品を指定するには:
    • 「配送対象商品の金額に基づく」または「配送対象商品の数に基づく」のルールでは、編集を選択し、限定子、演算子、値、カタログを選択して、保存をクリックします。
    • 「配送対象商品の組み合わせに基づく」のルールでは、追加をクリックして、必要とする対象商品の数を指定します。次に編集をクリックして商品グループを定義します。商品を追加しても、商品グループを定義しないと、プロモーションがトリガーされることはありません。

    対象商品を指定すると、指定した商品のみが割引されます。指定しないと、注文に含まれるすべての商品が対象商品と見なされ、割引されます。

  9. 適用対象の配送方法を指定するには、編集をクリックし、配送タイプを選択し、割り当てるをクリックし、保存をクリックします。
  10. 注文が割引プロモーションに近づいていることを顧客に知らせるには、通知を選択します。通知をトリガーするのに必要な商品合計金額を入力します。
  11. 制約を指定します (「配送対象商品の数に基づく」の場合)。
    制約を指定しないと、配送に対象外の商品が含まれている場合でも、プロモーションが適用されます。
  12. 複数の配送を含む注文でプロモーションの適用回数を制限するには、最大適用数を設定します。これは、「配送対象商品の組み合わせに基づく」のルールとは互換性をもちません。

    最大適用数を設定すると、金額が最も大きいものから順に、指定した数の配送にプロモーションが適用されます。設定しないと、プロモーションはすべての配送に適用されます。

    たとえば、最大適用数を 2 に指定し、配送の合計が $130、$170、$250 であったとします。この場合、$250 および $170 の注文だけにプロモーションが適用されます。

  13. 適用をクリックします。

  5. ソースコード仕様をグループに追加するには、コードタブをクリックします。
  6. ソースコード仕様を入力し、追加をクリックします。ソースコード仕様はリテラルソースコード (英数字のみでスペースなし) である場合や、以下のようなワイルドカードを含む場合があります:
    ? 任意の 1 文字の英数字と一致します。たとえば、仕様 'ABC?' は ABCD や ABC3 と一致しますが、ABCDE とは一致しません。
    * 英数字の任意のシーケンスと一致します。たとえば、仕様 'ABC*' は、ABCD、ABCDE、および ABC123 と一致します。
    [n1...n2] n1 から n2 までの任意の数値 (両端を含む) に一致します。たとえば、仕様 ' ABC[3..22] ' は、ABC3、ABC4、ABC22 と一致しますが、ABC33 や ABCD とは一致しません。
  7. ソースコードを使用して特定の商品やカテゴリ、URL に顧客をリダイレクトするには、リダイレクトタブをクリックします。
  8. カスタム商品属性にソースコードを関連付けるには、属性タブをクリックします。
  9. ソースコードグループを特定の価格表に関連付けるには、価格表タブをクリックします。

B2C Commerce クーポンの一般設定の指定

全般タブで、クーポンの説明、ステータス、使用制限を構成します。

メモ システムでクーポンが生成された後は、クーポン ID、大文字と小文字の区別、クーポンタイプを変更することはできません。
  1. 関連するサイトで、オンラインマーケティング | クーポンを選択します。
  2. クーポンページで、クーポン ID をクリックします。

  3. 全般タブで、説明を追加します。
  4. クーポンを有効にします。
  5. 使用制限を次のように指定します:
    • クーポンコードごとの使用 — 買い物客がクーポンコードを使用できる合計回数。単一コードのクーポンの場合は、クーポンコードに十分な大きさの数字を入力します。単一コードのクーポンの場合は、ビジネス要件に見合った大きさの数字を入力します。複数コードのクーポンの場合は、1 つ入力します。

    • Redemption per Order (注文ごとの使用) - 注文ごとに使用されたクーポンの数。
      • 各注文で 1 回: 買い物客は、特定のクーポンのコードを 1 つだけ買い物カゴに追加できます。
      • 各注文で複数回: 買い物客はクーポンを買い物カゴに複数回追加できます (個々のクーポンコード 1 つにつき 1 回)。「同じ B2C Commerce 注文での複数クーポンの使用」を参照してください。

Products Gift Certificate ダッシュボード

このトピックは、B2C Commerce に該当します。Gift Certificate (ギフト券) ダッシュボードを使用すると、ギフト券の販売を通じてサイトがどのように収益をあげているかを分析できます。

このダッシュボードには、ギフト券の購入と使用に関するメトリクスが表示されます。これらのメトリクスは、ギフト券の販売収益によって生み出された収益、平均販売金額、使用回数、使用金額、および特定の金額範囲内におけるアクティブ化の回数などに関するインサイトを提供します。ダッシュボードを開くには、商品ダッシュボードでギフト券タブを選択します。

Activations (アクティブ化)

アクティブ化は、期間中にアクティブにされたギフト券の数です。このレポートを使用して、アクティブ化の履歴を監視し、アクティブ化の増減を評価します。このデータを使用して、アクティベーションによる収益を向上させます。たとえば、これまでアクティブ化が少なかった時期にギフト券のプロモーションを計画します。

Gift Certificate Revenue (ギフト券の収益)

このレポートは、ギフト券の販売からの収益をプロットします。この日付を使用して、収益のトレンドを追跡し、収益を他のメトリクスと比較します。たとえば、同じ期間中に収益が低く、アクティブ化率が高い場合は、顧客が金額の少ないギフト券をアクティブ化する傾向にあることを示しています。

Average Gift Certificate Value (ギフト券の平均金額)

このレポートは、販売されたギフト券の平均金額をプロットします。

Redemptions (使用)

このレポートは、使用されたギフト券の金額をプロットします。使用されたギフト券の金額は、いくつかの評価で役に立ちます。たとえば、ギフト券の償還率に関するインサイトを取得します。メトリクスは 1 対 1 で比較することはできませんが、使用回数を、販売されたギフト券の平均金額レポートのデータと比較します。

Number of Redemptions (使用回数)

このレポートは、期間中におけるギフト券の使用回数をプロットします。

このレポートのデータはレルムの通貨で表示されます。チャートは、通貨の範囲に対するギフト券の合計アクティブ化回数を表示します。たとえば、$25.00 から $49.99 のギフト券を確認します。このグラフは、通貨の範囲の分布を示します。グラフの棒にマウスを置くと、通貨の範囲に対するギフト券のアクティブ化回数が表示されます。

買い物客の同意書の作成

同意リクエストで概説した条件に従ってマーケティングコミュニケーションを送信する許可を得ることで、買い物客と直接つながります。

  1. B2C Commerce のナビゲーションサイドバーで、マーチャントツール | サイト | オンラインマーケティング | 同意管理の順に選択します。
  2. [同意] ページで、[ 新しい同意 ] をクリックします。
  3. 同意書の一意の名前をスペースなしで入力します。

    英数字、ハイフン、アンダースコアを使用できます。

    名前を保存した後は、変更できません。

  4. 「デフォルトのチェックボックスステータス」を「チェック」または「オフ」に設定し、同意を「必須」または「不要」に設定します。

    同意を保存した後は、これらの選択を変更することはできません。

  5. 同意を有効または無効に設定します。
  6. 地域情報を選択し、同意を説明するテキストを入力します。

    このテキストは、同意チェックボックスの横に表示されます。また、同意チェックボックスのテキストの下に表示されるサブテキストを入力することもできます。

    重要 各同意要求には、その同意に関連付けられているチャネルの数に関係なく、チェックボックスが 1 つだけ表示されます。買い物客がチェックボックスをオンにすると、関連付けられているすべてのチャネルに同意が適用されます。チェックボックスのテキストに、同意が適用されるチャネルが示されていることを確認します。たとえば、「メールと SMS で最新情報を受け取ることに同意します」などです。チャネルタイプごとに個別のチェックボックスが必要な場合は、チャネルごとに同意書を作成します。

    同意書に一致する地域情報テキストが定義されていない場合は、デフォルトのテキストがサイトに表示されます。デフォルトまたは地域情報固有のチェックボックステキストがない場合、同意はサイトに表示されません。

  7. この同意に関連付けるサイトページを選択します。
  8. この同意がサポートする通信チャネルを選択します。
  9. 保存をクリックします。

買い物客通知チャネルフローとテンプレートのカスタマイズ

テンプレートをサイトのロゴと色で更新して、ブランド化された体験を提供できます。通知では、Salesforce フローを使用して買い物客への通知をトリガーします。買い物客への通知に必要なフローは、通知用のフローとテンプレートをインストールすると自動的に作成されます。通知の送信を開始するには、Salesforce 組織で該当するフローを有効化します。

まず、「買い物客通知チャネルフローとテンプレートのインストール」の手順を完了します。

重要 買い物客に重複して通知が送信されないようにするには、通知フローをアクティブにする前に、外部またはサードパーティのメッセージングサービスを無効にします。
  1. B2C Commerce のナビゲーションサイドバーで、マーチャントツール | サイト | オンラインマーケティング | 通知の順に選択します。
  2. 通知タイルで、[ 設定 ] をクリックします。
  3. チャネル タイルの [エクスペリエンス] で、[ テンプレート ] をクリックします。
  4. Content Builder で、変更を行って保存します。
  5. チャネル タイルの [エクスペリエンス] で、[ フロー ] をクリックします。
  6. Flow Builder で、[メールメッセージを送信]、[SMS メッセージを送信]、または [WhatsApp メッセージを送信] アクションを選択します。

    アクション設定の [通信サブスクリプションの選択] で、正しいサブスクリプションが選択されていることを確認します。

  7. 省略可能: フローを拡張して、他の要素、アクション、コンポーネントを含めます。
  8. 保存をクリックします。
  9. 通知の送信を開始する準備ができたら、[ アクティブ化 ] をクリックします。
重要 チャネルフローをアクティブ化した後、Business Manager でマーチャントツール | サイト | オンラインマーケティング | 通知の順に選択します。通知タイルでフローの状態が更新されるまで、ページを更新します。このプロセスには最大で 30 分かかります。

買い物客の同意を得るためのチャネルの定義

Salesforce で、メール、SMS、WhatsApp など、買い物客への通知の送信に使用するチャネルタイプを選択します。エンゲージメントチャネルを使用するには、B2C Commerce インスタンスで属性定義を作成し、それをチャネルの Salesforce レコード ID にマッピングします。

  1. 使用するチャネル種別の Salesforce レコード ID を取得します。
    1. 接続されている Salesforce 組織で、Data 360 に移動し、「エンゲージメントチャネル種別」を検索します。
    2. [All Engagement Channel Types (すべてのエンゲージメントチャネルタイプ )] を選択します。
    3. エンゲージメントチャネルタイプのリストで、チャネルを見つけて選択します。
    4. URL では、レコード ID の最初の 15 文字のみをコピーして保存します。

      レコード ID は、EngagementChannelType/の後、/viewの前に表示されます。たとえば、電子メールの URL がwww.salesforce.com/lightning/r/EngagementChannelType/0eFSG000000R5hx2AC/viewの場合は、0eFSG000000R5hxをコピーします。

    5. メール、SMS、WhatsApp など、使用するチャネルの種類ごとにこれらの手順を繰り返します。
  2. チャネル・タイプごとに属性定義を作成します。
    1. 接続している B2C Commerce インスタンスのナビゲーションサイドバーで、マーチャントツール | サイト サイト | 環境設定 | サイトのカスタム環境設定の順に選択します。
    2. 新規をクリックします。
    3. [属性定義 ] をクリックし、[ 新規 ] をクリックします。
    4. 表に示すように、チャネル ID を入力します。
      Channel (チャネル) ID
      Eメール uma-email-id (英語)
      SMS UMA-SMS-ID
      WhatsApp uma-whatsapp-ID
  3. チャネル属性定義を属性グループに追加します。
    1. 「属性グループ化」をクリックします。
    2. 「新規属性グループ」で、ID に「uma」と入力し、「追加」をクリックします。
    3. uma 属性の行で、「編集」をクリックします。
    4. [...]アイコンをクリックし、使用しているチャネルの属性定義 ID を選択して、[ 選択 ] をクリックします。
  4. チャネル属性定義に Salesforce レコード ID を追加します。
    1. ナビゲーションサイドバーで、マーチャントツール | サイト | サイト環境設定 | サイトカスタム環境設定の順に選択します。
    2. uma グループを選択します。
    3. 各属性定義の横にある値フィールドに、チャネル タイプに対応するレコード ID を入力します。
    4. 保存をクリックします。

同意の有効化または無効化

同意を有効にすると、サイトの構成した同意コンポーネントにその同意が表示されます。

重要 同意を削除すると、その同意はストアフロントから削除され、復元することはできません。Agentforce Marketing のサブスクリプションも削除されるため、同意によってサブスクライブした買い物客に通知することはできません。同意サブスクライバー向けのキャンペーンを引き続き実行するには、代わりに同意を無効にします。
  1. B2C Commerce のナビゲーションサイドバーで、マーチャントツール | サイト | オンラインマーケティング | 同意管理の順に選択します。
  2. 同意を選択します。
  3. 「有効」オプションを選択または選択解除します。
  4. 保存をクリックします。

買い物客通知チャネルフローとテンプレートのインストール

チャネルの設定は、通知の種類によって異なります。たとえば、カゴ落ち通知のチャネル設定は、注文後通知の設定とは異なります。使用するチャネルを指定します。

  1. B2C Commerce のナビゲーションサイドバーで、マーチャントツール | サイト名 | オンラインマーケティング | 通知の順に選択します。
  2. 通知タイルで、[ 開始する]をクリックします。
  3. 「カゴ落ち」通知を設定する場合は、「詳細を追加」をクリックします。
    1. サイトのショッピング カートの URL を入力します。

      チャネルを有効にした後、この URL を変更する場合は、チャネル テンプレートで変更する必要があります。

    2. 個人用設定を有効にしていて、パーソナライズされたレコメンデーションを通知に含める場合は、[ メール通知にレコメンデーションを含める]を選択します。
    3. 「チャネルの有効化」をクリックします。
  4. 使用するチャネルごとに、フローとテンプレートのインストールを選択します。
  5. 各チャンネルの設定を行います。
  6. 保存をクリックします。

Agentforce Marketing を使用した B2C Commerce

B2C Commerce を Salesforce 組織に接続すると、Agentforce Marketing、Data 360、Personalization によって得られる買い物客の同意と通知を使用できます。B2C Commerce ストアフロントに同意リクエストを追加して、メールアドレスを収集し、Agentforce Marketing オーディエンスを構築します。カゴ落ち通知をメール、SMS、WhatsAppで自動化します。また、買い物客が購入を完了したときにトリガーされる、パーソナライズされたおすすめ情報を含む注文後のマーケティング通知を作成することもできます。

  • B2C Commerce と Agentforce Marketing の前提条件
    Agentforce Marketing で B2C Commerce を使用する前に、必要な Salesforce アプリと機能を構成します。
  • B2C Commerce の買い物客の同意の設定
    同意リクエストをサイトに追加して買い物客の Eメールをキャプチャし、マーケティングキャンペーンを成長させます。同意要求は Data 360 クレジットを消費します。クレジットの使用状況の詳細については、アカウントエグゼクティブにお問い合わせください。
  • B2C Commerce の買い物客通知の設定
    放棄された買い物カゴのリマインダーや注文後のマーケティング通知など、買い物客に通知を送信します。通知には、Salesforce Flow、Agentforce Marketing、Data 360 が必要です。Data 360 クレジットは、送信される通知ごとに消費されます。クレジットの使用状況については、アカウントエグゼクティブにお問い合わせください。また、パーソナル化を有効にして、特定の買い物客のニーズや好みに合わせてマーケティングコミュニケーションをカスタマイズすることもできます。

B2C Commerce の買い物客の同意の設定

同意リクエストをサイトに追加して買い物客の Eメールをキャプチャし、マーケティングキャンペーンを成長させます。同意要求は Data 360 クレジットを消費します。クレジットの使用状況の詳細については、アカウントエグゼクティブにお問い合わせください。

同意を設定する前に、前提条件を満たしていることを確認してください。「B2C Commerce と Agentforce Marketing の前提条件」を参照してください。

  • PWA ストアフロントで買い物客の同意を得るための SLAS クライアントの設定
    PWA ストアフロントがある場合は、B2C Commerce インスタンスに Shopper Login and API Access Service (SLAS) クライアントを設定してアクセストークンをリクエストします。
  • 買い物客の同意を得るためのチャネルの定義
    Salesforce で、メール、SMS、WhatsApp など、買い物客への通知の送信に使用するチャネルタイプを選択します。エンゲージメントチャネルを使用するには、B2C Commerce インスタンスで属性定義を作成し、それをチャネルの Salesforce レコード ID にマッピングします。
  • 買い物客の同意書の作成
    同意リクエストで概説した条件に従ってマーケティングコミュニケーションを送信する許可を得ることで、買い物客と直接つながります。
  • 同意の有効化または無効化
    同意を有効にすると、サイトの構成した同意コンポーネントにその同意が表示されます。
  • PWA または SFRA ストアフロントでの買い物客の同意の表示
    買い物客の同意は、Progressive Web App (PWA) サイトのマーケティング同意フッターコンポーネント、またはStorefront Reference Architecture (SFRA) サイトのフッターと登録コンポーネントに表示できます。
