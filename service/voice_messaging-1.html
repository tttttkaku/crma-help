Connect REST API を使用した会話データの取得

このメソッドは、プログラムで一度に 1 つの特定のトランスクリプトを取得するためのもので、主に開発者が使用します。会話エントリ Connect REST API を使用して、個々の会話とそれに関連付けられた会話エントリにアクセスできます。ケースページにチャット履歴を表示するカスタムコンポーネントを作成したり、外部ポータルで顧客に過去の会話を表示したりする場合に最適です。一括データ抽出には適していません。

詳細は、「会話データへのアクセス」を参照してください。

Connect API の使用に関する考慮事項

  • レート制限: API は、1 時間あたりのユーザーあたりの特定のコール数に制限されます。何千ものレコードを取り込むと、すぐにこの制限に達します。デフォルトのレート制限は、アプリケーションあたり 1 ユーザーあたり 1 時間あたり 1,000 コールです。この制限の増加を要求できます。制限を増やすと、1 時間あたりの制限はなくなり、コールは組織の 1 日あたりの API 制限よりも大幅に多くなるだけで制限されます。
  • 有効なセッション制限: Connect REST API へのコールごとに会話が有効とマークされます。これは、組織の同時有効な会話の制限に含まれます。この制限を超えると、エラーや中断が発生する可能性があります。これを回避するには、不必要または過剰なコールを最小限に抑えることが重要です。
  • テキストのみ: API はテキストのみのトランスクリプトを返します。画像やボタンなどのリッチメディアは含まれません。
  • ボット メッセージなし:ボットが送信したメッセージは API 応答に含まれません。
  • 音声通話エントリは、通話が終了するまで音声通話レコードに関連付けられません。
メモ 会話データ GET 会話エントリ API は、制限の少ない Connect REST API の代替機能です。会話データ GET API を使用して、リッチコンテンツ、URL、ボットメッセージなど、すべての ConversationEntry 種別からトランスクリプトを取得します。

チャネルオブジェクトリンクのサポート担当者環境 (ベータ)

サポート担当者がユーザーとのセッション中に、ルールが適用されると、Lightning コンソールに通知が表示されます。サポート担当は、通知のリンクをクリックして詳細を取得したり、他のアクションを実行したりできます。

必要なエディション

サポートされているエディションを表示する。
重要 最新の柔軟なソリューションについては、「個人オブジェクトリンク」を参照してください。個人オブジェクトのリンクにより、リード、取引先責任者、従業員、および個人取引先レコードを音声通話、メール-to-ケースのケース、およびすべてのチャネルのメッセージングセッションに関連付けます。

たとえば、テキストメッセージ用に、会話を取引先責任者レコードにリンクするルールを作成します。そして、一致するものがあった場合は、リンクは自動的に適用されると指定します。取引先責任者の電話番号と一致する電話番号の人とサポート担当者が会話すると、その取引先責任者に会話が自動的にリンクされたことがサポート担当者に通知されます。サポート担当者は変更を確認し、必要に応じて新しいリンクをキャンセルできます。

次の表に、可能性のあるすべてのシナリオと各シナリオのデフォルト動作を示します。

見つかった一致の数 リンクロジック (ルールの設定中に指定) デフォルトの動作 追加オプション
0 レコードとリンクを作成 レコードが自動的に作成され、チャネルインタラクションにリンクされます。 サポート担当者は、別のレコードにリンクしたり、自動リンクされたレコードのリンクを解除したりできます。
サポート担当者に確認 サポート担当者は、リンク先のレコードを検索または作成するように促されます。 サポート担当者はアクションをキャンセルできます。
1 レコードを自動リンク レコードが自動的にチャネルインタラクションにリンクされます。 サポート担当者は、別のレコードにリンクしたり、自動リンクされたレコードのリンクを解除したりできます。
サポート担当者に確認 サポート担当者は推奨レコードを促され、リンク先の別のレコードを検索または作成できます。 サポート担当者はアクションをキャンセルできます。
2 以上 なし サポート担当者は推奨レコードを促され、リンク先の別のレコードを検索または作成できます。 サポート担当者はアクションをキャンセルできます。

一致ロジックでは、[電話番号] 項目の値が通話者の電話番号のほとんどの桁に対応する取引先責任者レコードが検索されます。国コードは無視され、残りの桁が照合されます。

たとえば、米国の電話番号 415-555-1234 を持つ顧客がコンタクトセンターに電話をかけたとします。組織にはこの顧客の 3 個の取引先責任者レコードがあり、各レコードに顧客の電話番号のバリエーションが含まれます。

  • 取引先責任者レコード 1 の電話番号は 415-555-1234 です。

  • 取引先責任者レコード 2 の電話番号は 1-415-555-1234 です。

  • 取引先責任者レコード 3 の電話番号は +1-415-555-1234 です。

一致ロジックでは、これらのレコードが通話者の番号と一致すると認識されるため、一致として提案され、サポート担当者に通話を取引先責任者レコードにリンクするように促されます。取引先責任者が音声通話レコードと一致すると、通話種別に応じて音声通話レコードの [通話者] 項目または [受信者] 項目が更新されます。着信通話と転送通話の場合は、通話者項目が更新されます。発信通話と返信通話の場合は、受信者項目が更新されます。

  5. [新規フロー] をクリックします。
  6. [すべて + テンプレート] をクリックします。
  7. [個人-オブジェクトリンクフロー] をクリックします。
  8. フローテンプレート「Find Contact Associated with Voice Call (音声通話に関連付けられている取引先責任者を見つける)」を選択します。

  12. ビジネスニーズに合わせてフローをテストおよび更新してから、有効化します。

音声通話用のチャネルオブジェクトリンクルールの追加

顧客からの着信音声通話のオブジェクトリンクルールを作成します。サポート担当者がワークスペースで電話を受け入れると、推奨される取引先責任者レコードから選択するか、レコードを検索するか、新しいレコードを追加するように求められます。電話チャネルでは、取引先責任者レコードへのリンクのみがサポートされます。

必要なエディション

サポートされているエディションを表示する。

Lightning Experience での設定手順:

  1. チャネルオブジェクトリンクルールを作成する前に、Voice を設定します。
  2. [設定] で、[クイック検索] ボックスに「Channel-Object」と入力します。[チャネルオブジェクトリンク] 設定ページから、[新規リンクルール] をクリックしてガイド付きフローを開始します。
  3. 電話チャネル種別と、リンク先のオブジェクト (取引先責任者など) を選択します。ルール名と説明を作成します。レコードが見つからなかった場合のアクションと 1 件のレコードが見つかった場合のアクションの 2 つのシナリオのルールアクションを設定します。作業を保存します。

    たとえば、一致する取引先責任者が見つからない場合、自動的にレコードを作成してリンクするルールを含めることができます。または、サポート担当者にレコードの検索または作成を促すこともできます。1 件の一致するレコードが見つかった場合、自動的にレコードをリンクするか、プロンプトを表示するルールを設定できます。このプロンプトでは、推奨レコードの選択、レコードの検索、またはレコードの作成がサポート担当者に求められます。

  4. 電話の設定を完了したら、Lightning アプリケーションビルダーでオブジェクトリンク通知バックグラウンドユーティリティを追加して、サービスコンソールにプロンプトをトーストメッセージとして表示します。

ガイド付き設定フローを使用したチャネルオブジェクトリンクルールの作成 (ベータ)

簡単なガイド付き設定フローを使用して、チャネルオブジェクトリンクルールを組織に追加します。

必要なエディション

サポートされているエディションを表示する。
重要 最新の柔軟なソリューションについては、「個人オブジェクトリンク」を参照してください。個人オブジェクトのリンクにより、リード、取引先責任者、従業員、および個人取引先レコードを音声通話、メール-to-ケースのケース、およびすべてのチャネルのメッセージングセッションに関連付けます。

設定フローにアクセスできる場所

このフローは、Lightning Experience のサービスの設定から使用できます。歯車アイコンをクリックし [サービスの設定] を選択することで、[サービスの設定] にアクセスできます。Spring '26 以降に作成された組織では、[サービスの設定] を使用できません。

[サービスの設定] から、[クイック検索] ボックスに「チャネルオブジェクト」と入力し、[チャネルオブジェクトリンク] を選択します。[チャネルオブジェクトリンク] 設定ページから、[新規リンクルール] をクリックします。

このフローの機能

このフローでは、チャネルインタラクションを取引先責任者などのオブジェクトにリンクするルールを作成できます。チャネル種別 (Facebook Messenger など) とリンク先のオブジェクト種別 (取引先責任者など) を選択したら、リンクロジックを定義できます。ロジックは、何件の一致が見つかったかによって異なります。

一致が見つからない場合は、ルールで自動的にレコードを作成してリンクするか、サービス担当者にレコードを検索または作成するように要求できます。

一致するレコードが 1 件見つかった場合、ルールで自動的にレコードをリンクするか、サービス担当者に推奨レコードの選択、レコードの検索、またはレコードの作成を促すことができます。

複数の一致がある場合、サービス担当者は常に推奨レコードのリストから選択するか、レコードを検索するか、レコードを作成するように求められます。

一致は、次の情報を使用してチャネルごとに判断されます。

チャネル種別 照合に使用される情報
Facebook Messenger ユーザー名
電話 電話番号
テキスト (SMS) 電話番号
メモ [チャネルオブジェクトリンク] と [通話者をエンドユーザーレコードと照合] は併用できません。使用できるのはいずれか 1 つのみです。

会話データの保存とアクセス

会話データに関する必要な情報をすべて見つけることができます。

必要なエディション

Voice でサポートされているエディションを表示する。
メッセージングでサポートされているエディションを表示する。

要件に適したツールの選択を支援します。たとえば、日次パフォーマンスレポートを作成したり、トランスクリプトをアプリケーションに追加したり、データを保存して会社のルールに従ったり、会話を分析してインサイトを得たりすることができます。データを保存する場所は、拡張チャットやメール-to-ケースなど、使用するチャネルによって決まります。

ここでは、2 つのストレージシステムについて説明し、どの会話がどこに転送されるかを示し、データを取得するために使用できるさまざまなツールを比較します。また、メッセージングセッションや音声通話から会話トランスクリプトをダウンロード、削除、縮小、レポート、操作する方法も説明します。

  • 会話データが存在する場所
    会話データは、使用しているチャネルに応じて、Salesforce コアストレージまたは Amazon Web Service Database (AWS) にあります。
  • AWS での会話へのアクセス
    Amazon Web Services Database (AWS) から会話データの全体像を把握するには、会話データを Data 360 に同期するか、Connect REST API を使用するか、一括エクスポートツールを使用して会話データをダウンロードします。
  • Data 360 での会話トランスクリプトデータの分析
    会話データを確認および分析するには、Data 360 を使用して拡張メッセージングチャネル、音声通話、統合メッセージングからトランスクリプトにアクセスします。Data 360 のレポートとダッシュボードを使用してトランスクリプトを分析し、Data Cloud API を使用してデータにズームインし、Salesforce Object Query Language (SOQL) クエリを使用して特定の情報を検索します。
  • 会話トランスクリプトのエクスポート
    Salesforce ユーザーは、任意の本番組織で Voice、拡張チャット、拡張 Facebook Messenger、拡張 WhatsApp の会話トランスクリプトをエクスポートできます。Sandbox では会話のエクスポートはサポートされていません。また、会話トランスクリプトは Salesforce 組織のストレージ制限と使用量の計算に含まれません。
  • メッセージングセッションと音声通話トランスクリプトでの機密データのブロック
    拡張メッセージングセッション、拡張チャット、音声通話トランスクリプトで、クレジットカード番号や冒涜的な言葉など、特定のパターンをブロックする機密データルールを作成します。テキストを削除するか、好ましい文字に置き換えることができます。この方法はデータマスキングとも呼ばれ、顧客のデータを保護するのに役立ちます。

Salesforce コアストレージの会話データ

Salesforce コアストレージはメインデータベースであり、処理速度を重視して構築されています。情報にすばやくアクセスできるため、日々のレポートの実行に最適です。

次のチャネルからのデータはコアストレージに直接送信されます。

  • 従来のチャット (2026 年 2 月 14 日に廃止)
  • 標準メッセージング: WhatsApp、SMS、Facebook Messenger (2026 年 2 月 14 日に廃止)

標準メッセージングチャネルでは、エンドユーザー、サービス担当者、ボット、またはオートメーションから送信されたメッセージごとに ConversationEntry レコードが作成されます。ConversationEntry レコード (最初のメッセージを除く) は、メッセージングセッションが終了し、サービス担当者がセッションタブを閉じるまで作成されません。各 ConversationEntry レコードは MessagingSession レコードに関連付けられます。このレコードは、エンドユーザーと企業間のメッセージのやり取りを表します。

ConversationEntry レコードには、標準オブジェクトと同様にアクセスして操作できます。メッセージング活動に関するレポートを作成し、会話ワークフローを追跡できます。また、ConversationEntry オブジェクト上に構築されたソリューションを使用して、トランスクリプトのダウンロードまたは削除、機密テキストの削減、ワークフローのカスタマイズを行うこともできます。

Salesforce Object Query Language (SOQL) を使用して、特定の質問を行ったり、トランスクリプトデータを関連レコード (取引先責任者のメールなど) に関連付けたり、情報を要約したりできます。

データローダーまたは Salesforce Bulk および REST API を使用して、トランスクリプトをダウンロードできます。

会話トランスクリプトのデータストリームの作成

会話トランスクリプトを分析するには、Data 360 に会話関連のデータがあることが重要です。このデータをインポートするには、会話、会話関係者、関係者、メッセージングセッション、音声通話、会話エントリ、関連レコードオブジェクトを使用してデータストリームを作成できます。以下のメソッドでは、これらのオブジェクトにアクセスして会話関連のデータを取得し、データストリームを作成する方法について説明します。

方法 1: データキットを使用したデータストリームの作成

拡張チャネルを使用していない場合は、次のタスクを使用してデータを取得します。会話関連のデータは、Conversation、ConversationParticipant、Participant、MessagingSession、VoiceCall オブジェクトにあります。データストリームを作成するには、次のオブジェクトを使用します。

メモ この機能を使用するには、必要な権限が必要です。問題が発生している場合は、次を参照してください。
  • 権限がありません。Voice Call Object Unavailable (音声通話オブジェクトが使用できません)。
  • 既知の問題とその回避策。
  • セールスおよびサービスバンドルデータマッピング。
  1. Data Cloud で、[データストリーム] タブに移動します。
  2. [新規] をクリックし、[Salesforce CRM] を選択します。
  3. [次へ] をクリックします。
  4. [Digital Engagement Bundle (デジタルエンゲージメントバンドル)] をクリックし、[次へ] をクリックします。
  5. 必要に応じて、デジタルエンゲージメントオブジェクトの項目を選択します。必要なフィールドは、会話、会話関係者、関係者、メッセージングセッション、または音声通話です。
  6. [次へ] をクリックします。
  7. データストリーム名にマウスポインターを置いて鉛筆アイコンをクリックすると、名前を変更できます。デフォルトでは、選択したデジタルエンゲージメントオブジェクトの末尾に _home が付けられ、データストリーム名になります。
  8. [リリース] をクリックします。
    選択したオブジェクトのデータストリームがリリースされ、[データストリーム] タブに表示されます。データストリームごとに、データの対応付けが正しいことを確認できます。

方法 2: 会話エントリと関連レコードのデータストリームを作成する

すでに拡張チャネルを使用している場合、会話で交換された実際のメッセージは会話エントリオブジェクトに保存されます。データストリームを作成するには、会話エントリオブジェクトと関連レコードオブジェクトを使用して会話関連のデータを取得します。

メモ Data 360 を使用するホーム組織に接続されたコンパニオン組織を使用している場合は、「コンパニオン組織を使用した会話トランスクリプトへのアクセス」を参照してください。
  1. [設定] から、[クイック検索] ボックスに「会話トランスクリプト」と入力し、[Data Cloud] の [会話トランスクリプト] を選択します。
  2. ドロップダウンから、会話トランスクリプトを共有するために Data 360 のデータストリームを関連付ける適切なデータスペースを選択します。データスペースについての詳細は、「データスペース」を参照してください。
    ドロップダウンから値を選択しない場合、デフォルトのデータスペースが自動的に選択されます。
  3. [有効化] をクリックします。
    会話トランスクリプトアクセスが有効になっており、必要なデータストリームが Data 360 で正常に作成されたことを示すメッセージが表示されます。

データの検証と表示

  1. アプリケーションランチャーで、[Data Cloud] を見つけて選択します。
  2. [データストリーム] タブをクリックして、作成されたデータストリームを表示します。
  3. CONVERSATION_ENTRY_<your_org_id> と Related_RECORDS_<your_org_id> という名前の 2 つのデータストリームが表示されていることを確認します。

トランスクリプトは、CONVERSATION_ENTRY_<your_org_id> データレイクオブジェクト (DLO) の entry_payload 項目/列の一部として、または文字列化された JSON が含まれる会話データモデルオブジェクト (DMO) のペイロード項目/列として使用できます。この JSON 内の Object["abstractMessage"]["staticContent"]["text"] キーには、トランスクリプトが含まれます。次の例では、I AM THE TRANSCRIPT はトランスクリプトを表します。

{"entryType":"Message","id":"b2a140c2-a50f-426b-92ae-aafd3faf2d68","abstractMessage":{"messageType":"StaticContentMessage","inReplyToMessageId":null,"id":"b2a140c2-a50f-426b-92ae-aafd3faf2d68","references":null,"staticContent":{"formatType":"Text","text":"I AM THE TRANSCRIPT"}},"messageReason":null}

Data 360 で会話トランスクリプトを表示するには、次のいずれかの方法を使用できます。

  • データエクスプローラー
  • クエリエディター
  • Data 360 公開 API を使用した会話トランスクリプトの分析
  • Data 360 レポートを使用した会話トランスクリプトの分析

会話トランスクリプトオブジェクトのデータガバナンス権限の有効化

会話トランスクリプトで使用する Data 360 オブジェクトへのアクセスをカスタマイズするには、選択したデータガバナンスポリシーに従ってオブジェクトにアクセス権を付与します。

属性ベースのアクセス制御 (ABAC) またはロールベースのアクセス制御 (RBAC) のいずれかを選択できます。これにより、データへのユーザーアクセスをより詳細に制御できます。「Grant Access to Data 360 Objects (Data 360 オブジェクトへのアクセス権の付与)」の手順に従って、これらのオブジェクトを使用可能なポリシーに割り当てます。

Data 360 レポートを使用した会話トランスクリプトの分析

会話トランスクリプトを分析するには、Data 360 レポートを活用します。

  1. 「Analyze Conversation Transcripts in Data 360 (Data 360 での会話トランスクリプトの分析)」に記載されている前提条件を満たし、会話データのデータストリームを作成したことを確認します。
  2. アプリケーションランチャーで、[Data Cloud] を見つけて選択します。
  3. [レポート] タブをクリックします。[レポート] タブが表示されない場合は、アプリケーションランチャーから、[レポート] を見つけて選択し、Data Cloud で [レポート] タブを作成します。[レポート] タブを表示するには、Data 360 レポート権限が必要です。
  4. [新規レポート] をクリックします。
  5. [カテゴリ] で、[Data Cloud] をクリックし、レポートタイプとして [ConversationEntry] を選択します。
  6. [レポートを開始] をクリックします。
  7. [列を追加] をクリックして、レポートに表示する列を追加します。
  8. [実行] をクリックします。結果は表形式で表示されます。レポートを目的の名前で保存できます。また、いくつかの文字コード形式を使用して .xls、.csv、.xlsx 形式でエクスポートすることもできます。

Amazon Web Services データベースの会話データ

Amazon Web Services Database (AWS データベース) は、最新の大容量通信チャネル用に設計された個別の大容量データベースです。これにより、メインの Salesforce 環境でのパフォーマンスの低下を回避できます。新規のお客様は、デフォルトでこのシステムを使用するように設定されます。Lightning Webコンポーネントを使用して、サービス担当者と顧客のメッセージをリアルタイムで監視することもできます。

これらのチャネルからのデータはここに保存されます。

  • テレフォニープロバイダーを使用した Salesforce Voice (旧称 Service Cloud Voice)
  • 拡張メッセージング: WhatsApp、Facebook Messenger、SMS、Apple Business Messaging、LINE
  • 拡張チャット
  • 拡張ボットと Bring Your Own Bot (BYOB)
  • Bring Your Own Channel (BYOC)
  • Agentforce

これらのチャネルでは、受信メッセージと送信メッセージは 2 つの方法のいずれかで処理されます。ConversationEntry レコードは作成されるが Message 項目が空白の場合、または ConversationEntry レコードがまったく作成されない場合です。

これらのチャネルでの会話の全体像を把握するには、次のいずれかの方法を使用する必要があります。

  • 会話データの Data 360 への同期。
  • 会話エントリ Connect REST API を使用して会話データにアクセスします。
  • Bulk Export Tool を使用した会話データのダウンロード

一括エクスポートツールを使用した会話データのダウンロード

これは、すべての会話データの完全な履歴アーカイブをダウンロードできるように設計されたユーティリティです。

このツールは、法令遵守要求の履行、履歴データの新しいデータウェアハウスへの移行、データ保持ポリシーの長期バックアップの作成など、データのフルオフラインコピーが必要なタスクに使用します。

このツールは、頻繁なレポートや分析には適していません。完全なエクスポートは 7 日に 1 回のみ実行できます。この制限により、通常のレポートユーティリティではなく、アーカイブツールとしての目的が強化されます。

詳細は、「会話トランスクリプトのエクスポート」を参照してください。

一括エクスポートツールに関する考慮事項

  • Sandbox では、会話のエクスポートはサポートされていません。
  • 会話トランスクリプトは、Salesforce 組織のストレージ制限に含まれません。

チャネルメニュー設定で設定されるコード設定は、静的リソースファイルを使用してメニュー項目を変更する場合に便利です。画像を変更したり、よくある情報を事前チャットの項目に渡したり、非表示の項目に入力したりするには、静的リソースファイルを作成して Salesforce にアップロードします。

メモ WhatsApp、SMS テキスト、または電話チャネルへのコード変更はサポートされません。

設定は最初にコードスニペットまたはエクスペリエンスビルダーでチャネルメニューコンポーネント設定から Web サイトまたはエクスペリエンスビルダーサイトに適用されます。次に、設定はアップロードした JavaScript ファイルから適用され、その後 [設定] から適用されます。

コード設定が Web サイトまたはエクスペリエンスビルダーサイトに適用されると、関連する JavaScript ファイルが読み込まれます。複数の JavaScript 静的リソースを異なるコード設定に関連付けて、設定を Web サイトまたはエクスペリエンスビルダーサイトに読み込むことができます。

ステップ 3: コード設定へのリソースの追加

  1. [設定] から、[クイック検索] ボックスに「チャネルメニュー」と入力し、[チャネルメニュー] を選択します。

  6. 説明を追加して、リソース種別を選択します。

ステップ 5: コード設定の実装 (Web サイト)

コード設定名をチャネルメニューのコードスニペットに追加します。

  1. チャネルメニューコードスニペットをまだ適用していない場合は適用します。
  2. Web サイトに追加したコードスニペットを開きます。
  3. スニペットの embedded_svc.menu.init() コールに新しいパラメーターをオブジェクトとして追加します。例については、このセクションの終わりを参照してください。
  4. オブジェクトが embedded_svc.menu.init() に渡された最後のパラメーターであることを確認します。
  5. Web ページマークアップでコードスニペットが変更されることを確認します。
  6. 10 分後に Web ページを更新して、[チャネルメニュー] ボタンが表示されることを確認します。静的リソースが読み込まれ、項目が Web ページで動作することを確認します。

チャネルメニューのコードスニペットへのパラメーターの追加

embedded_svc.menu.init(
	...existing parameters,
	{
		pageName: "InsertName"
	}
);

チャネルメニューのコードスニペットの適用

必要なエディション

重要

チャネルメニューへの項目の追加

Salesforce サイトまたは Experience Cloud サイトのチャネルメニューに表示される顧客チャネルを選択してカスタマイズします。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
チャネルメニューを設定する 「アプリケーションのカスタマイズ」および「メタデータの編集」

メニュー項目を追加する前に、[設定] の [チャネルメニュー] ページでチャネルメニューリリースを作成します。

  1. [設定] から、[クイック検索] ボックスに「チャネルメニュー」と入力し、[チャネルメニュー] を選択します。
  2. 編集するチャネルメニューの名前をクリックします。
  3. [メニューの設定] セクションで、[編集] をクリックします。
  4. [項目を追加] ボタンをクリックすると、Web サイトに最大 6 個のチャネルを追加できます。各項目を追加するときに、詳細を入力します。
    1. 顧客には表示されないメニュー項目名を追加します。
    2. チャネル種別 (通話、SMS、Apple Messages for Business、拡張 Web チャット、Facebook、WhatsApp、Web URL) を選択します。
    3. メニュー項目をリンクする電話番号、URL、または有効なメッセージングチャネルを指定します。外国の顧客がいる場合は、電話チャネルを追加するときに + 記号と電話番号の国コードを使用します。
    4. 必要に応じて、カスタムアイコンを追加します。
    5. [詳細設定] で、Channel Menu Reordering API を使用している場合は、[このメニュー項目を表示] を選択解除します。それ以外の場合は、選択したままにします。
    6. 必要に応じて、特定のユーザーオペレーティングシステムのメニュー項目を非表示にします。たとえば、モバイルプラットフォームの拡張 Web チャットを非表示にして、WhatsApp や SMS などのモバイル対応チャネルの使用を促します。
    7. 上下矢印ボタンを使用して、メニュー項目の順序を変更します。
  5. すべてのチャネルをメニューに追加したら、[保存] をクリックします。

メニュー項目はいつでも編集できます。

チャネルメニューに関する考慮事項と制限

チャネルメニューを設定するときは、次の制限と考慮事項に留意してください。

必要なエディション

サポートされているエディションを表示する。
重要 チャネルメニューの設定を変更すると、キャッシュされるため、結果が Web サイトに表示されるまで最大 10 分かかることがあります。

拡張 Web チャット

  • チャネルメニューでは 1 つの拡張 Web チャットチャネルをサポートできます。また、チャネルのリリースが現在または以前のリリースで公開されている必要があります。機能、セキュリティ修正、アクセシビリティの更新などの最新バージョンを取得するには、Salesforce のリリースごとに拡張 Web チャットリリースを再公開します。
  • チャネルメニューが拡張 Web チャットチャネルに接続されている場合、Experience Cloud サイトのフッター領域にのみ追加できます。

従来の Web チャット

  • 同じチャネルメニューで選択できる組み込みサービスチャット種別は 1 つのみです。チャットチャネルが複数あると、重複するチャットメッセージが作成され、JavaScript ライブラリが繰り返し読み込まれます。
  • Web チャットのみを表示するようにチャネルメニューを設定すると、サービス担当者が対応できない場合、ボタンは顧客に表示されません。ボタンを表示するには、この種別の設定で検証前に担当者をオンラインにするための追加手順が必要です。

電話チャネル

チャネルメニュー設定で電話番号を入力する場合、検証は提供されません。外国の顧客の電話番号を使用する場合は、+ 記号と国コードを含めます。たとえば、+012125551212 などです。

WhatsApp

より堅牢な環境を実現するには、顧客が whatsapp.com からダウンロードした WhatsApp ネイティブクライアントバージョンをインストールする必要があります。クライアントがインストールされていない場合、Microsoft Store が開き、Windows 顧客向けに「No apps named WhatsApp (WhatsApp という名前のアプリケーションがありません)」というメッセージが表示されます。

静的リソース

  • 最新の静的ファイルを使用するには、キャッシュをハード再読み込みまたはクリアして Web ページを更新します。設定を完了した後にチャネルメニューボタンが表示されない場合は、ブラウザーコンソールでエラーを確認してください。通常、ボタンがないのはスクリプトのダウンロードに問題があることを示します。
  • Experience Cloud サイトの静的リソースファイルを読み込む場合は、ビルダーでフロー全体をテストして CSP エラーがないか確認します。このステップを使用すると、静的リソースの読み込みで指定された他のドメインの画像 URL とアセットが適切なタイミングで確実に読み込まれます。欠落が見られる場合は、まずコンソールで CSP エラーがないか確認します。
