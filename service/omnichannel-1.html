インシデントのルーティング設定の定義

サポート担当者をインシデントに転送します。

必要なエディション

サポートされているエディションを表示する。
  1. [設定] から、[クイック検索] ボックスに「ルーティング」と入力し、[ルーティング設定] を選択します。
  2. [新規] をクリックします。
  3. ルーティング設定名と API 参照名を入力します。
  4. オーバーフロー割り当て先としてオムニチャネルインシデント権限セットを持つユーザーを追加します。
  5. ルーティングの優先度を設定します。たとえば、ケースよりもインシデントを優先するには、インシデントのルーティング設定を 1、ケースのルーティング設定を 2 にします。
  6. インシデントルーティングモデルを選択します。
  7. サポート担当者が作業を受け入れる時間を入力します。
  8. 省略可能: スキルベースのルーティングを使用している場合は、[スキルベースのルーティングルールで使用] を選択して、インシデントスキルを選択します。
  9. インシデントの業務量要件を決定します。
  10. 変更内容を保存します。

キーボードショートカットの設定

拡張オムニチャネルユーティリティ内でクイックコントロール用の独自のキーボードショートカットを設定します。

  1. オムニチャネルユーティリティの [設定] で、[Configure Keyboard Controls] オプションを有効にします。
  2. [Configure Keyboard Controls (キーボードコントロールを設定)] オプションを選択します。
  3. 関数ごとに、一意のキーボードショートカット値を入力します。
  4. 変更内容を保存します。カスタムショートカットはすぐに有効になります。

クイックコントロールのキーボードショートカット

作業項目の受け入れ、拒否、終了など、オムニチャネルのクイックアクション用にカスタマイズされたキーボードショートカットを設定して使用します。営業担当は、拡張オムニチャネルユーティリティ内で直接、主要なアクションの独自のショートカットを設定できます。キーボードショートカットは、営業担当の電話種別が卓上電話であっても設定および使用できます。

キーボードショートカット 機能
承諾/切断 音声通話、メッセージなどの作業項目を受け入れます。このショートカットは、有効な音声通話を終了するためにも使用されます。
Decline 音声通話やメッセージなどの作業項目を拒否します。
ミュート/ミュート解除 このショートカットは、有効な音声通話のミュートとミュート解除を切り替えます。
  • キーボードショートカットの設定
    拡張オムニチャネルユーティリティ内でクイックコントロール用の独自のキーボードショートカットを設定します。
  • キーボードショートカットの制限
    クイックコントロールのショートカットを有効にして使用する場合は、キーボードショートカットの制限を考慮してください。

作業の再割り当ての設定

担当者とスーパーバイザーがルーティング可能な Salesforce 標準オブジェクトとカスタムオブジェクト (ケースなど) を再割り当てできるようにするには、[再割り当て] アクションをオブジェクトページレイアウトに追加します。

必要なエディション

サポートされているエディションを表示する。
メモ 標準オムニチャネルと拡張オムニチャネルの両方で異なるスキルセットに作業を転送できますが、このトピックは拡張オムニチャネルのみに適用されます。標準オムニチャネルを使用して作業を転送するには、「異なるスキルセットへの作業項目の転送」を参照してください。
ヒント [再割り当て] アクションを使用できるユーザーとそのユーザーを制御するには、ここで説明されているように、ページレイアウトに追加するのではなく、Lightning Builder で動的アクションとして追加します。Lightning ビルダーでは、表示ルールを追加できます。「Lightning アプリケーションビルダーでの動的アクションの作成」を参照してください。

作業の再割り当てを設定する前に、次の前提条件を完了します。

  • 拡張オムニチャネルルーティングが有効になっていることを確認します。含まれていない場合、[再割り当て] アクションは使用できません。
  • ルーティング設定のない作業項目をスキルまたは特定の担当者に再割り当てするには、サービスチャネル設定でデフォルトのルーティング設定を選択します。たとえば、元々オムニチャネルによってルーティングされなかった作業には、ルーティング設定がありません。
  1. オブジェクトマネージャーで、ケースなどのオブジェクトを開きます。
  2. [再割り当て] アクションを追加するページレイアウトを開くには、オブジェクトの [ページレイアウト] をクリックし、レイアウトを選択します。
  3. [モバイルおよび Lightning のアクション] セクションで、[再割り当て] アクションをページレイアウトの [Salesforce モバイルおよび Lightning Experience アクション] セクションにドラッグします。
  4. ページレイアウトを保存します。

[再割り当て] アクションがオブジェクトページに表示されます。

キーボードショートカットの制限

クイックコントロールのショートカットを有効にして使用する場合は、キーボードショートカットの制限を考慮してください。

  • キーボードショートカットは、拡張オムニチャネルレイアウトでのみサポートされ、標準オムニでは使用できません。
  • カスタムショートカットがオペレーティングシステム、ブラウザー、またはその他のアプリケーションで使用されるショートカットと競合していないことを確認します。「Salesforce のキーボードショートカット」を参照してください。
  • 進行中の音声通話中にキーボードショートカット機能を有効にすると、通話中アクションは現在の通話では機能しませんが、ページを更新せずに後続のすべての通話で有効になります。ライブコール中にショートカットの対応付けを更新できます。
  • キーボードショートカットは、QWERTY、AZERTY、QWERTZ キーボードレイアウトでのみサポートされています。
  • 絵文字などの非 ASCII 文字はショートカットとして機能しませんが、これらの文字はショートカットとして保存できます。
  • < などの特殊文字を生成するために Shift キーが必要なショートカットはサポートされていません。
  • キーボードショートカットは、常に Inbox の最上位の作業項目に適用されます。タブナビゲーションの使用に重点を置いた作業項目では機能しません。
  • 有効な通話中のショートカットの有効化や対応付けの更新はサポートされていません。変更は、作業項目の処理の前または後に行う必要があります。
  • 通話が [接続中] 状態の場合、切断などの通話中ショートカットは機能しません。
  • キーボードショートカットは、マルチパーティ通話ではサポートされません。
  • 誤って切断されないように、通話を受け入れてから切断ショートカットを使用できるようになるまで 2 秒の遅延があります。この間は、ソフトフォンまたは卓上電話からの切断オプションを使用する必要があります。Inbox の複数の作業項目を誤って受け入れたり却下したりしないように、受け入れと却下のショートカットにも同様の 2 秒の遅延があります。
  • 卓上電話を使用する場合、キーボードショートカットはサポートされません。

中止された顧客とのやりとりの分析

放棄された顧客とのやりとりとは、顧客がサービス担当者に応答する前に終了する通話またはメッセージングセッションです。放棄された顧客とのやりとりとその分類方法を理解することで、レポートとサービス管理を改善できます。

必要なエディション

サポートされているエディションを表示する。

顧客が特定の顧客と営業担当のインタラクション条件で通話を切断すると、通話は放棄されたとみなされます。次のいずれかの条件を満たした場合、顧客とのやりとりは放棄されたとみなされます。

重要 [エージェントの作業を中止] 状況は、拡張オムニチャネルでのみ使用できます。
  • 顧客が会話を開始する。作業がサービス担当者に割り当てられたが、サービス担当者が作業を受け入れる前に顧客が切断 (チャットを終了する/電話を切る) した。
  • 顧客が会話を開始したが、対応可能なサービス担当者またはエージェントがおらず、顧客が切断した。
  • 顧客が会話を開始する。作業はサービス担当者に割り当てられます。サービス担当者は作業を受け入れますが、通話は別のサービス担当者に転送されます。2 番目のサービス担当者が電話を受け入れる前に顧客が切断した。
  • サービス担当者が作業を拒否し、作業が別のサービス担当者に再転送された。2 番目のサービス担当者が電話に出る前に顧客が切断すると、通話は放棄されたとみなされます。

次のいずれかの条件を満たす場合、通話は放棄されたとみなされません。

  • サービス担当者が作業を受け入れ、顧客が切断する。
  • サービス担当者が作業を受け入れます。会話中に技術的な問題がある (音声ストリーミングの問題やネットワークの問題など)。サービス担当者または顧客には互いの声が聞こえず、通話が切断されます。サービス担当者が作業を受け入れたため、放棄されたインタラクションとはみなされません。
  • 顧客がボイスメールを残すか、キューで待機している間にコールバックを選択して切断した。これらのシナリオは、ボットが回答した場合と同様に処理されます。
メモ 放棄された音声通話ログは、テレフォニーベンダーが音声 API コール操作を更新したタイミングに応じて非同期で更新されます。

放棄された通話の数はオムニチャネルウォールボードで確認できます。オムニチャネルウォールボードに [Agent Work Status] 項目を含めます。放棄された通話は、[放棄] 行に表示されます。

メッセージングセッションまたは音声レコードをエージェント作業レコードと組み合わせることで、放棄された通話に関する包括的なレポートを作成できます。これらのレポートでは、メッセージングセッションまたは音声インタラクションに関して放棄されたインタラクションが発生した状況に関するインサイトが提供されます。

Command Center for Service タブへのカスタムアクションの追加

スーパーバイザー設定を編集して、カスタムアクションを表示するタブを指定します。スーパーバイザー設定に割り当てられているすべてのスーパーバイザーにアクションが表示されます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Command Center for Service でカスタムアクションを設定する Salesforce Voice コンタクトセンター管理者
  1. [設定] から、[クイック検索] ボックスに「スーパーバイザー構成」と入力し、[スーパーバイザー構成] を選択します。
  2. 既存のスーパーバイザー設定を選択するか、アカウントを作成します。
  3. スーパーバイザー設定の [アクションを定義] セクションで、タブを選択し、カスタムアクションを [選択済みのアクション] ボックスに移動します。
    カスタムアクションボタン名は、基盤となる画面フロー名と同じです。各タブに最大 10 個のアクションを追加できます。
  4. スーパーバイザー設定を保存します。

システムアクションと同様に、カスタムアクションは [Command Center for Service] タブにボタンとして表示されます。システムアクションは、デフォルトで提供されるアクションです。カスタムアクションは、[Command Center for Service] タブに追加できるアクションです。

アプリケーションへの Command Center for Service の追加

スーパーバイザーが Command Center for Service に簡単にアクセスできるようにするには、作業する場所に Lightning アプリケーションに追加します。

必要なエディション

サポートされているエディションを表示する。
メモ Command Center for Service を従来の Classic サービスコンソールに追加することもできます。ただし、オムニチャネルは Lightning アプリケーションで最適に機能します。
  • Lightning アプリケーションへの Command Center for Service の追加
    Lightning Experience のアプリケーションに Command Center for Service を追加して、スーパーバイザーを稼働させます。
  • オムニスーパーバイザーの Classic コンソールへの追加
    オムニスーパーバイザーを Salesforce Classic コンソールに追加して、スーパーバイザーを稼働させます。

[作業を転送] アクションの追加

オムニチャネルフローを使用して、特定のスキルを持つサービス担当者に作業項目を転送します。

サポートされているエディションを表示する。

スキルベースのルーティングを使用して作業を転送するには、事前に [設定] の [オムニチャネル設定] で [スキルベースのルーティングとエージェントへの直接転送を有効化] オプションを有効にしておく必要があります。

  1. [作業を転送] アクションをキャンバスにドラッグします。
  2. アクションに表示ラベルと API 参照名を付与し、必要に応じて [説明] を指定します。
  3. [入力値を設定] で、作業を転送する項目の数を選択します。
    1 つの項目を転送するには、[単一] を選択し、作業を転送するレコード ID が含まれるテキスト型のフロー変数を選択します。最大 100 件の項目を転送するには、[複数] を選択し、転送するレコード ID のリストが含まれるテキスト型のコレクション変数であるフロー変数を指定します。
    レコードのコレクションを指定し、フローでいずれかのレコードが見つからなかった場合、変更はロールバックされ、どのレコードも転送されません。
  4. [サービスチャネル] で、チャネルを選択します。
  5. [ルーティング先] で、[スキル] を選択します。
  6. [スキル要件] で、次のいずれかのオプションを選択します。
    1. スキル要件の定義
    2. スキルベースのルーティングルールの実行
    3. 両方
  7. フローの [スキル要件を追加] アクションでスキル要件を定義する場合は、[作業を転送] アクションのスキル要件リストとしてそのアクションの出力を指定します。
    たとえば、[スキル要件を追加] アクションの API 参照名が AddSkill の場合、そのアクションの出力 {!AddSkill.skillRequirements} を指定します。または、skillList 変数を使用してスキルを集計する場合は、[スキル要件を追加] アクションの出力と RouteWork アクションのスキル要件リストで、その変数を出力として指定します。
  8. [ルーティング設定] で、次のいずれかのオプションを選択します。
    1. ルーティング設定の選択 — [スキルベースのルーティングルールで使用] オプションが無効になっているルーティング設定を指定します。
    2. 変数を使用 — 変数を使用して適切なスキルリストを検索します。たとえば、変数を使用して、顧客の取引先責任者レコードに関連付けられている言語スキルを判断します。

デバッグログは、[作業を転送] アクションが呼び出されたときに作成されません。

会話に関するコンテキストをより多く営業担当に提供する画面ポップの追加

デフォルトでは、サービス担当者が作業項目を受け入れると、主作業レコードのみが開きます。ただし、コンテキストが増えると、サービス担当者は顧客ごとによりパーソナライズされたサービスを提供できます。音声通話、メッセージ、またはチャットが担当者に転送されたときに、サービス担当者の画面でレコードまたは画面フローを自動的に開くには、オムニチャネルフローに [画面ポップを追加] アクションを含めます。レコードまたは画面フローを合計 3 つまで開くことができます。たとえば、顧客のケースレコードと取引先責任者レコードを表示し、[チャネルオブジェクトリンク] 画面フローをサブタブとして開くことができます。

サポートされているエディションを表示する。
メモ [画面ポップを追加] アクションでは、サービス担当者が転送された作業を受け入れるときにレコードまたは画面フローは開きません。たとえば、サービス担当者 1 がチャットを受け入れるとします。このアクションにより、担当者の画面にレコードが開きます。サービス担当者 1 はチャットをサービス担当者 2 に転送します。 サービス担当者 2 がチャットを受け入れると、アクションはサービス担当者 2 の画面でレコードや画面フローを開きません。

画面ポップは、標準ナビゲーションを使用するアプリケーションでは機能しません。画面ポップは、サービス担当者がコンソールナビゲーションを使用してアプリケーションから作業を受け入れている場合にのみ機能します。

オムニチャネルフローをサポートしていないテレフォニーパートナーからの音声通話の画面ポップを設定するには、テレフォニーパートナーにお問い合わせください。

  1. Flow Builder の [要素] タブで、[画面ポップを追加] アクションをキャンバスにドラッグします。
  2. アクションに表示ラベルと API 参照名を付け、必要に応じて説明を指定します。
  3. [コレクション変数を設定] で、必要に応じて前の [画面ポップを追加] アクションの出力を選択し、これらの画面ポップの指示をこのアクションによって作成される指示と組み合わせます。
    詳細は、「オムニチャネルフローでの複数の [画面ポップを追加] アクションの使用」を参照してください。
  4. レコードの [画面ポップタイプ] で、開くレコードの ID 項目を選択します。または、特定のレコード ID 値を入力します。サービス担当者の画面で複数のレコードが開いている場合、[フォーカス] を切り替えて、このレコードをサービス担当者のフォーカスに合わせます。
    たとえば、取引先責任者レコードを開くには、取引先責任者レコード変数 ([取引先責任者を取得] 要素からの出力が含まれる) を選択してから、取引先責任者 ID 項目を選択します。
    メモ レコードを定義する順序は、サービス担当者の画面で開く順序です。フォーカスを設定しない場合、すべてのレコードが開きますが、サービス担当者の画面では主作業レコードにフォーカスが置かれます。
  5. 画面フローの [画面ポップタイプ] で、[タイプ] として [画面フロー] を選択し、有効な画面フローのリストから選択します。または、[タイプ] として [リソース] を選択し、独自のフロー変数を選択します。
    • 有効な画面フローのリストには最大 5 個のフローが表示されますが、[画面フロー名] 項目に入力して他のフローを検索できます。
    • 有効な画面フローと完全修飾画面フロー API 参照名 (名前空間プレフィックスを含む) の場合のみリソースが表示されます。
  6. 別のレコードまたは画面フローを開くには、[画面ポップを追加] をクリックします。レコードまたは画面フローを 3 つまで開くことができます。
  7. [完了] をクリックします。

忘れずに、画面ポップの指示 (このアクションからの出力) を [作業を転送] アクションの入力として渡します。[作業を転送] アクションに渡される画面ポップの指示のみが、作業がサービス担当者に転送されるときにレコードを開くために使用されます。

画面ポップの指示を [作業を転送] アクションへの入力として追加するには、[作業を転送] アクションを開きます。[コレクション変数を画面ポップ] 項目で、[画面ポップを追加] アクションからの出力を選択し、[routingInteractionInfoList] を選択します。

ヒント Flow Builder の [デバッグ] オプションを使用して、この [画面ポップを追加] アクションをオムニチャネルフローの他の要素と一緒に検証します。
  • オムニチャネルフローでの複数の [画面ポップを追加] アクションの使用
    同じフローで複数の [画面ポップを追加] アクションをチェーニングできます。たとえば、作業の転送先となるキューやサポート担当者に関係なく、レコードを開くアクションを 1 つ追加します。次に、作業の転送先に応じて追加レコードを開く別のアクションを追加します。
  • 変数での画面ポップの指示の保存
    複数の [画面ポップを追加] アクションをフローに追加する場合、すべての画面ポップの指示を集計して保存するためにコレクション変数を定義します。変数にすべての指示を保存することで、[画面ポップを追加] アクションがフローに追加される順序を気にする必要がなくなります。

[スキル要件を追加] アクション

スキル要件を作業項目に追加して、作業が顧客の問題に最適なサービス担当者に転送されるようにします。[スキル要件を追加] アクションで最大 10 件のスキルを追加でき、個々の作業項目を転送するときにフロー全体で 20 件のスキルを定義できます。

サポートされているエディションを表示する。
  1. オムニチャネルフローを作成する手順を実行します。
  2. [スキル要件を追加] アクションをキャンバスにドラッグします。
  3. アクションに表示ラベルと API 参照名を付与し、必要に応じて [説明] を指定します。
  4. [入力値を設定] で、作成した skillList 変数を必要に応じて選択します。この変数は、フローの実行中にスキルを保存して集計します。
  5. [スキル要件を追加] で、サービス担当者に必要なスキルまたはスキル ID を持つ変数を入力します。スキルレベル、補助的なスキルであるかどうか、そして優先度を指定できます。

    まず、オムニチャネルは要求されたすべてのスキルを持つサービス担当者に作業を転送しようとします。すべてのスキルを持つサービス担当者が対応できず、追加のスキルを削除するように設定されている場合、オムニチャネルはタイムアウト後に追加のスキルを削除します。ルータは、残りのスキルを持つサービス担当者が対応可能になるまでスキルを削除します。その他のスキルが削除される順序を指定できます。優先度の高いスキルが最初に削除されます。たとえば、優先度 5 のスキルは、優先度 4 のスキルの前に削除されます。 優先度 0 のスキル (優先度のないスキル) が最後に削除されます。その後、サービス担当者がすべての追加スキルを持っていなくても、最も適したエージェントに作業項目が転送されます。

    サービス担当者が作業を拒否したりオフラインになったりすると、必須スキルが元の状態に戻り、タイマーがリセットされます。ルータは、すべての追加スキルを持つサービス担当者の検索に戻り、追加スキルを削除するプロセスを最初からやり直します。

  6. フローの実行中に skillList 変数でスキルを集計する場合は、[詳細] セクションで、[スキル要件を追加] アクションの出力としてその変数を設定します。

後続の [作業を転送] アクションでは、[スキル要件を追加] アクションの出力を使用して、サービス担当者が作業項目に対して必要とするスキルを定義できます。たとえば、[スキル要件を追加] アクションの API 参照名が AddSkill の場合、[作業を転送] アクションでそのアクションの出力 {!AddSkill.skillRequirements} を指定します。skillList 変数でスキルを集計する場合は、[スキル要件を追加] アクションの出力および [作業を転送] アクションのスキル要件リストとして指定します。[スキル要件を追加] アクションは、オムニチャネルフローを使用して Sandbox から本番組織に手動操作なしで移行できます。[スキル要件を追加] アクションを移行するには、[アクションバージョン] をバージョン 2.0.0 に変更します。 スキルは移行できません。[スキル要件を追加] アクションを正常に移行するには、必要なスキルが対象組織に存在することを確認する必要があります。スキルへの参照は移行できません。

作業の手動再割り当て

音声通話やメッセージングセッションの転送と同様に、オムニチャネルを使用してルーティング可能な標準オブジェクトとカスタムオブジェクトを新しいルーティング先に再割り当てできます。たとえば、ケースまたはリードを再割り当てできます。作業レコードの [所有者] 項目を変更する代わりに、作業項目を別のキュー、サービス担当者、スキル、またはオムニチャネルフローに再割り当てできます。作業項目が再割り当てされると、その作業項目はオムニチャネルによって新しい対象に転送されます。解決時間を短縮し、SLA の目標を達成するために、再割り当てされた作業項目のキュー内での優先度は保持されます。この機能は、拡張オムニチャネルでのみ使用できます。

必要なエディション

サポートされているエディションを表示する。

作業項目を再割り当てする前に、オムニチャネル設定で [拡張オムニチャネルを有効化] を有効にします。作業を担当者に再割り当てするには、[スキルベースのルーティングとエージェントへの直接転送も有効化] も有効にします。

メモ 作業を担当者に直接再割り当てするには、「すべてのユーザーの参照」権限が必要です。

  2. 作業項目をキューに再割り当てするには、キューを選択します。
    作業をキューに再割り当てする場合、キューにルーティング設定が必要です。設定がない場合、そのキューは作業の再割り当てが可能なキューのリストに表示されません。

スキルベースのルーティングルールを使用した転送

スキルベースのルーティングルールを作成して、作業をサービス担当者に転送するときに特定のスキルを必要とするタイミングを定義します。たとえば、商品の返品に関する問い合わせを、返品の処理方法を熟知しているサービス担当者に転送するルールを定義します。

必要なエディション

サポートされているエディションを表示する。

スキルベースのルーティングルールを作成する前に、すべてのスキルベースのルーティングの前提条件を満たしてください。

スキルベースのルーティングルールでは、ケース、リード、注文、カスタムオブジェクトがサポートされます。

ルーティングロジックは、作業が所有者に割り当てられた場合に適用されます。作業項目が転送された後にその項目の項目値が変更された場合、ルーティングロジックは再適用されません。

  • ルーティング設定からのスキルベースのルーティングルールの有効化
    スキルベースのルーティングルールを使用するには、作業項目の転送時に経由するキューで使用されるルーティング設定を有効にする必要があります。
  • スキルへの作業項目値の対応付け
    スキルベースのルーティングルールを使用して特定のスキルを持つサービス担当者に作業を転送するには、作業項目項目値とスキルの対応付けを定義します。たとえば、商品返品の電話を適切なサービス担当者に転送するには、ケース種別項目値 [商品返品] を返品処理スキルに対応付けます。

関連項目:

  • サービス担当者のサービスリソースの作成
  • スキルに転送するための準備

ルーティング設定からのスキルベースのルーティングルールの有効化

スキルベースのルーティングルールを使用するには、作業項目の転送時に経由するキューで使用されるルーティング設定を有効にする必要があります。

必要なエディション

オムニチャネルを設定する 「アプリケーションのカスタマイズ」

    1. [設定] から、[クイック検索] ボックスに「キュー」と入力し、[キュー] を選択します。
    2. キューを編集し、[オムニチャネルルーティングを使用する設定] セクションでルーティング設定名を探します。

  3. 作業項目の転送時に経由するキューで使用されるルーティング設定を編集します。
  4. [スキルベースのルーティングルールで使用(Use with Skills-Based Routing Rules)] を選択します。

  6. 必要に応じて、ルーティング設定にスキルを追加します。

    作業を適切なサービス担当者に転送するために、オムニチャネルはこれら 2 つのソースのスキルの組み合わせを適用します。

    そのルーティング設定を使用して転送されるすべての作業項目にスキルを追加するには、スキルをルーティング設定に追加します。
    オムニチャネルフローまたはスキルベースのルーティングルールから追加された動的スキル
    条件に基づいて特定の作業項目にスキルを動的に追加するには、オムニチャネルフローまたはスキルベースのルーティングルールを使用してロジックを作成します。条件が満たされると、スキルが作業項目に適用されます。

スキルへの作業項目値の対応付け

スキルベースのルーティングルールを使用して特定のスキルを持つサービス担当者に作業を転送するには、作業項目項目値とスキルの対応付けを定義します。たとえば、商品返品の電話を適切なサービス担当者に転送するには、ケース種別項目値 [商品返品] を返品処理スキルに対応付けます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」

オブジェクトごとに 1 つのスキルの対応付けセットを作成します。各対応付けで、オブジェクトの選択リスト、Boolean、および参照項目値を、作業項目を適切なサービス担当者に転送するために必要なスキルに関連付けます。最大 10 個の項目と 100 個の項目値を対応付けることができます。スキルレベルを指定することもできます。作業項目をより迅速に転送するには、スキルがその他であり、必要に応じて削除できるかどうかを指定します。

  1. [設定] から、[クイック検索] ボックスに「スキルベースのルーティングルール」と入力し、[スキルベースのルーティングルール] を選択します。
  2. [スキルの新しいマッピングセット] をクリックします。
  3. マッピングセットの名前と API 参照名を入力し、転送されるオブジェクト種別を選択します。続いて、[次へ] をクリックします。
  4. ケースを転送するための項目を選択します。続いて、[次へ] をクリックします。
    種別が選択リスト、Boolean、参照の標準およびカスタム項目値を対応付けることができます。
    メモ オブジェクトのカスタム項目値は、どの方法で設定しても構いません。たとえば、事前チャットフォーム、トリガー、カスタム Apex コードなどを使用できます。
  5. 項目ごとに、項目値と対応するスキルを選択します。スキルレベルを指定したり、スキルをその他のスキルに設定したりすることもできます。その他のスキルでは、指定されたタイムアウト後にそのスキルを持つサービス担当者が対応できない場合にスキルを削除する順序を指定できます。

    まず、オムニチャネルは要求されたすべてのスキルを持つサービス担当者に作業を転送しようとします。すべてのスキルを持つサービス担当者が対応できず、追加のスキルを削除するように設定されている場合、オムニチャネルはタイムアウト後に追加のスキルを削除します。ルータは、残りのスキルを持つサービス担当者が対応可能になるまでスキルを削除します。その他のスキルが削除される順序を指定できます。優先度の高いスキルが最初に削除されます。たとえば、優先度 5 のスキルは、優先度 4 のスキルの前に削除されます。 優先度 0 のスキル (優先度のないスキル) が最後に削除されます。その後、サービス担当者がすべての追加スキルを持っていなくても、最も適したエージェントに作業項目が転送されます。

    サービス担当者が作業を拒否したりオフラインになったりすると、必須スキルが元の状態に戻り、タイマーがリセットされます。ルータは、すべての追加スキルを持つサービス担当者の検索に戻り、追加スキルを削除するプロセスを最初からやり直します。

    たとえば、次の必須スキルとその他のスキルを設定できます。

    • 言語: 英語とフランス語は必須です。その他ではありません。
    • 問題種別: ソフトウェアとハードウェアは最高優先度 0 のその他のスキルです。
    • 商品: スピーカー、マウス、キーボードは優先度 1 のその他のスキルです。
    • 場所: 米国、英国、カナダ、フランスは優先度 2 のその他のスキルです。

    この例では、言語スキルはその他ではないため削除されません。[問題種別] 項目に関連付けられているスキルには最高優先度が設定されているため、オムニチャネルはこのスキルを最後に削除します。[場所] 項目に関連付けられているスキルは最初に削除されます。

    メモ スキルベースのルーティングルール設定メソッドまたは Apex コードから生成された同じ優先度値を持つスキルは、同じグループに属し、同時に削除されます。
  6. 項目ごとに項目値をスキルに対応付けたら、[完了] をクリックします。

    マッピングセットを作成するには、[新規] (1) をクリックします。マッピングセットを編集または削除するには、ドロップダウンメニュー (2) を使用します。オブジェクトのルーティングを停止するには、[無効化] をクリックします。オブジェクトのルーティングを開始するには、[有効化] をクリックします。

    ルーティング設定をテストするには、アプリケーションに移動して、適切なスキルを持つサービス担当者をオンラインにします。対応するスキルに対応付ける項目値を使用して、作業項目を作成します。スキルベースのルーティングルールで設定したルーティング設定を使用して、作業項目の所有者をキューに変更します。オムニチャネルコンポーネントに作業項目が表示されます。転送された作業は、Command Center for Service の [キューのバックログ] と [スキルのバックログ] に表示されます。

対応付けは、レコードの値が更新されるときではなく、作業が転送されるときにのみ行われます。

  • Available Interruptible: サービス担当者が新しい中断可能な作業項目に対応しなければならない中断可能な残りの業務量。

評価指標の絞り込みと調整

スーパーバイザーはカードを動的に調整して、重要なチーム総計値を分離できます。すべての検索条件の状態は、手動でクリアされるまでセッション間で保持され、自動的に保存されます。該当する場合、総計値は、関連付けられたスーパーバイザ設定で選択されたサービス担当者、キュー、スキルに基づきます。

検索条件は次のロジックに従います。

  • 1 つのフィルタ タイプ (OR): 同じフィルタ内で複数のオプション (2 つ以上のスキルなど) を選択すると、それらの選択のいずれかに一致する作業がカードに表示されます。たとえば、スキル A とスキル B を選択すると、スキル A またはスキル B を介して転送された作業が返されます。
  • Across different filter types (AND): さまざまなフィルタ タイプ (スキルと担当者の選択など) で選択した場合、カードはすべての有効なフィルタ グループを満たす作業に結果を絞り込みます。たとえば、スキル A と担当者 1 を選択すると、スキル A を介して担当者 1 に転送された作業が返されます。

特定のレコードを分離するには、カードの検索条件アイコンをクリックし、条件を選択します。

  • キュー: 1 つ以上の特定のワーク キューのデータを表示します。
  • スキル: 作業項目に割り当てられたスキルで絞り込みます。
  • チャネル: 組織で設定されている特定のサービスチャネルで絞り込みます。
  • サービス担当者: 1 人以上の特定のエージェントにデータを転送します。
  • サービス担当者種別:AIが所有する作業または人が所有する作業のみに基づいて評価指標で絞り込みます。

検索条件を管理者の元のレイアウト設定にリセットするには、選択した検索条件をクリアします。

サービス担当者の対応可能状況の確認によるよりスマートなルーティングの決定

新しい作業要求を処理するための組織の業務量に関して収集された情報を使用して、ルーティングを最適化します。[ルーティングの対応可能状況を確認] アクションをオムニチャネルフローに追加して、サービス担当者の対応可能状況と推定待機時間を決定します。このアクションでは、指定されたルーティング要件 (ルーティング種別とパラメーターを含む) に基づいて、オンラインサービス担当者の数と受け取りを待機している作業項目の数を返すことができます。また、顧客がサービス担当者に到達するまでに待機する必要がある時間を推定することもできます。その後、結果に基づいてルーティングロジックを作成できます。たとえば、サービス担当者のキューに 5 個を超える作業項目がある場合、代わりに作業を別のキューに転送できます。

  2. アクションに表示ラベルと API 参照名を付け、必要に応じて説明を指定します。
  3. サービスチャネルを選択します。
  4. [対応可能状況の確認対象] 項目で、確認する場所を選択します。
    1. キューに転送するときに対応可能状況を確認するには、[キュー] を選択し、キューを保存するキューまたは変数を選択して、次のいずれかの出力オプションを返します。

      予想待機時間 予想待機時間を返します。

    出力値 説明
    予想待機時間 (秒)

    このアクションは、指定されたルーティングパラメーターで作業をキューまたはスキルに転送するときの予想待機時間 (秒) を返します。たとえば、作業をキューに転送する場合、このパラメーターには、営業担当が作業を受け入れるまで作業がキューに残される推定時間が表示されます。

    オムニチャネルは、過去 10 分間に受け入れられた最新の 1 ～ 10 個の作業項目に基づいて予想待機時間を計算します。過去 10 分間に受け入れられた作業項目がない場合、[ルーティングの対応可能状況を確認] アクションは -1 を返します。計算の詳細については、Knowledge Article: Estimated Wait Time Calculation When Routing Work with Omni-Channel (オムニチャネルを使用して作業を転送する場合の予想待機時間の計算) を参照してください。

    待機時間は、キュー内の主 (中断不可能) 作業項目に基づいて計算されます。中断可能な作業は計算に含まれません。

    キューに入っている作業項目の数

    このアクションは、受け取りを待機している品目の数を返します。これには、サービス担当者に割り当てられた品目またはサービス担当者によって受け入れられた品目は含まれません。サービス担当者に転送する場合、この値は代替キューなしでサービス担当者に直接割り当てられた PSR の数です。キューに転送する場合、この値はキューに割り当てられた PSR の数 (このキューを代替キューとして特定のサービス担当者に割り当てられた PSR を含む) です。スキルに転送する場合、この値はアクションで使用される必須のスキル要件 (スキルとスキルレベルの両方) のまったく同じセットを共有する PSR の数です。

    キューのサイズは、キュー内の主 (中断不可能) 作業項目に基づいて計算されます。中断可能な作業は計算に含まれません。

このアクションの結果に基づいてルーティングに関する意思決定を行うには、決定要素をオムニチャネルフローに追加します。決定要素で、さまざまな条件の予測されるルーティングを定義します。たとえば、少なくとも 1 人のサービス担当者がオンラインであり、キューサイズが 10 以下の場合、[作業を転送] アクションを使用してケースをキューに転送します。

予想待機時間に基づいて作業を転送するには、オムニチャネルフローの [ルーティングに対応可能かを確認] アクションで時間を出力し、その出力を [作業を転送] アクションでルーティングロジックの入力として使用します。

[ルーティングの対応可能状況を確認] アクションは、オムニチャネルフローを使用して、手動操作なしで Sandbox から本番組織に移行できます。[ルーティングの対応可能状況を確認] アクションを移行するには、[アクションバージョン] をバージョン 2.0.0 に変更します。

エージェントとキューへの参照は、移行する回避策が必要です。User Entity - Agent への参照の回避策

  • [レコードを取得] フローアクションを使用してエージェント ID を取得する (例: ユーザー名またはメール)
  • [オムニチャネル] アクション項目で、前のステップから取得したユーザー ID を使用します。

キューエンティティへの参照の回避策

  • [レコードを取得] フローアクションを使用してキュー ID を取得する (例: キュー名別)
  • [オムニチャネル] アクション項目で、キューを参照する項目に前のステップから取得したキュー ID を使用します。

  2. ルーティングサービスを選択します。[ルート先] 値が [キュー]、[スキル]、または [エージェント] に設定されていることを確認します。

コールバックでカスタム要求日時を使用する場合のベストプラクティス

音声およびコールバックシナリオの主な課題は、順番待ちの順番を失うことです。通常、コールバックの再試行が失敗し、項目が再キューに入れられた場合、項目は新しいエントリ時間に基づいてキューの最後尾に移動します。[要求日] オプションを使用すると、通話が最初にキューに入れられたタイミングに基づいてコールバックを転送できます。

顧客とエージェントにシームレスな環境を提供するには、次の主要な実装戦略に従います。

  • Use Original Creation Dates (元の作成日を使用): コールバックの [作業を転送] アクションを設定するときに、要求されたカスタム項目をケースや音声通話などのレコードの元の作成日にマッピングします。この対応付けでは、バックログでの顧客の元の位置が保持されます。
  • 再試行全体の優先度の維持: 複数回の再試行を伴うコールバックシナリオでは、フローロジックで最初の要求タイムスタンプが新しい [作業を転送] の各実行に一貫して渡されるようにします。
  • システムログの監視: 将来の日付は無視されるため、作業項目がカスタム入力ではなく現在のキュー時間に基づいてルーティングされているようであれば、イベントログを確認します。
  • KPI への影響: 元の要求時間を使用すると、報告される待機時間と応答速度の総計値が増加する可能性があります。これらの総計値はダッシュボードでは異なりますが、顧客満足度 (CSAT) と実際の待機時間をより正確に表すことができます。

Flow Builder でのスケジュール済みルーティングの設定

スケジュール済み作業を使用して作業のルーティングを遅らせます。作業を転送する特定の将来の日時を定義します。

必要なエディション

サポートされているエディションを表示する。

スケジュール済み作業を使用して作業のルーティングを遅らせます。作業を転送する特定の将来の日時を定義します。

  1. Flow Builder でフローを開き、[作業を転送] アクションを追加または編集します。
  2. ルーティングサービスを選択します。[ルート先] 値が [キュー]、[スキル]、または [エージェント] に設定されていることを確認します。
  3. [Set Additional Input Values (追加入力値の設定)] を展開し、ルーティング開始オプションを見つけます。
  4. [Schedule work time routing (作業時間ルーティングをスケジュール)] チェックボックスをオンにします。[Schedule a date and time (日時をスケジュール)] オプションを選択し、[Scheduled Date and Time (スケジュール済み日時)] フィールドに作業項目を転送する日時を入力します。
  5. フローを保存して有効化します。フローが実行されると、scheduledDateTime 項目が入力された待機中のサービスルーティング (PSR) レコードが作成されます。項目と値は、作成されたエージェント作業にも継承されます。

メモ Agentforce エージェントまたは Einstein ボットでは、スケジュール済みルーティングはサポートされていません。

スケジュール時刻がフローの実行時に過去の時刻に評価された場合、その値は無視され、項目がすぐに転送されます。

オムニチャネルセッションの有効期限の設定

オムニチャネルユーザーがコンピューターから離れたときのネットワークへの公開を制限するには、セッションセキュリティを設定します。デフォルトでは、Salesforce セッションがタイムアウトしても、サービス担当者はオムニチャネルから自動的にログアウトされません。タイムアウト中に同じオムニチャネルページでアイドル状態が続くと、オムニチャネルにもオンラインと表示され、転送された作業を見逃す可能性があります。オムニチャネルセッションは、サービス担当者がログインページにリダイレクトされるまで終了しません。

必要なエディション

サポートされているエディションを表示する。

サービス担当者をログインページにリダイレクトし、オムニチャネルセッションが対応する Salesforce セッションと同時に終了するようにするには、Salesforce セッションセキュリティ設定で [セッションタイムアウト時に強制的にログアウト] を選択します。このオプションを有効にしない場合、サービス担当が Salesforce に再ログインすると、[新しいウィンドウまたはタブのオムニチャネルでエージェントを自動的にログインしない] 設定に関係なく、オムニチャネルにもログインします。

メモ 担当者が Salesforce から手動でログアウトしてもオムニチャネルでオンラインのままの場合、ルーティングセッションは 2 分間有効なままであるため、割り当てられた項目は他の対応可能な担当者にすぐに再転送されません。この 2 分のタイムアウトが切れると、品目は他の対応可能な担当者に再転送されます。

主または中断可能な作業項目の設定

チャットなどの中断不可能な作業は、処理できる業務量があるサービス担当者のみに任せてください。中断不可能な作業を主として定義し、ケースやリードといった長期にわたる作業や緊急度の低い作業を中断可能として定義します。

必要なエディション

サポートされているエディションを表示する。

サービス担当者が時間的制約のある作業と長時間の作業の両方を処理する場合、オムニチャネルは顧客が応答時間を短縮できるように時間的制約のある作業項目を転送できます。オムニチャネルで緊急度の高い作業をサービス担当者にすぐに転送できるように、緊急度の低い作業項目を中断可能として定義できます。

メモ LiveChatTranscript レコードは中断不可能で、常に主業務量を使用します。

作業項目の項目 (待機中のサービスルーティングまたはエージェント作業レコードの [中断可能] 項目) によって、作業項目が中断可能かどうかが決まります。

作業項目は、サービスチャネル、ルーティング設定、または Apex といういずれかの方法で中断可能に設定できます。

  • サービスチャネル設定を使用して、作業項目を中断可能に設定する。

    [設定] のオムニチャネルの [サービスチャネル] で、[中断可能] を選択します。たとえば、ケースサービスチャネルの作業を中断可能に設定し、チャットサービスチャネルからの作業を主に設定します。

  • ルーティング設定を使用して、作業項目を中断可能に設定する。

    [設定] のオムニチャネルの [ルーティング設定] で、転送される作業項目の [業務量種別] を指定します。この項目は、中断可能、主、またはサービスチャネルからの継承に設定できます。

  • Apex を使用して、業務量種別を設定する。

    Apex で、作業項目の待機中のサービスルーティングレコードまたはエージェント作業レコードで IsInterruptible 項目を明示的に設定します。

[作業を転送] アクションを使用するオムニチャネルフローを定義する場合は、フローでサービスチャネルまたはルーティング設定を指定します。サービスチャネルまたはルーティング設定で中断可能性を設定します。それに従って、オムニチャネルは待機中のサービスルーティングレコードの [中断可能] 項目を設定できます。

例 Tier 1 サービス担当は、主に優先度の高いケースを処理します。時間に余裕があれば、優先度が低いケースも処理します。キューを定義し、ケースの種別ごとにルーティング設定を作成します。各ルーティング設定で、業務量種別を高いケースの場合は [中断不可能]、優先度の低いケースの場合は [中断可能] に設定します。オムニチャネルフローは、受信したケースの優先度を確認し、ケースを適切なキューに転送します。次に、オムニチャネルは待機中のサービスルーティングレコードの [中断可能] 項目を確認し、業務量ルールを満たすサービス担当者に作業を転送します。

作業項目の業務量の設定

オムニチャネルは、中断可能性と作業項目サイズの両方に従って転送します。作業項目を主または中断可能に設定した後に業務量を設定します。

作業項目の業務量は、ルーティング設定と Apex という 2 通りの方法で設定できます。

重要 作業項目のサイズを定義するときは、主業務量と中断可能業務量に設定された値より小さくするようにしてください。そうしないと、オムニチャネルはその作業項目を転送できません。

  • ルーティング設定で作業項目の業務量を設定します。

    [設定] のオムニチャネルの [ルーティング設定] で、作業項目のサイズを指定します。サイズを作業単位またはサービス担当者の業務量に対する割合として定義します。たとえば、サービス担当者の業務量が 6 作業単位であり、すべてのケースの業務量が 2 の場合、エージェントは最大 3 件のケースを処理できます。または、作業項目の必須業務量をパーセントとして指定します。

    メモ 音声通話では、[業務量単位] または [業務量に対する割合] のどちらで指定された場合でも、サービス担当者の業務量の 100% が必要です。

    オムニチャネルは、ルーティングの決定を行うときに、使用可能な主業務量と中断可能な業務量のパーセントを確認します。作業単位を使用して作業項目のサイズを指定すると、対応可能な業務量がパーセントに変換され、サービス担当者がルールを満たす対応可能状況であるかどうかが確認されます。

  • または、Apex で、PendingServiceRouting、AgentWork、QueueRoutingConfig レコードの [Capacity Weight (業務量)] または [Capacity Percentage (業務量 (%))] 項目を明示的に設定します。

これで、主業務量と中断可能な業務量を使用してルーティングの決定を行うオムニチャネルの準備ができました。

オムニチャネルフローの作成

フローを最初から作成します。または、オムニチャネルフローテンプレートからフローを作成して作成時間を短縮します。テンプレートは、チャット、音声通話、メッセージをサービス担当者、キュー、スキルに転送するフローの作成方法を示しています。テンプレートを使用して各着信通話のケースを作成することもできます。ビジネスニーズに合わせてテンプレートから作成されたフローをカスタマイズできます。

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「フロー」と入力し、[プロセスの自動化] の [フロー] を選択します。
  2. [新規フロー] をクリックします。
  3. [すべて + テンプレート] をクリックします。
  4. フロー種別をオムニチャネルフローに絞り込むには、[新規フロー] 画面の左ペインで [オムニチャネルフロー] を選択します。
  5. テンプレートからフローを作成するには、次のいずれかのテンプレートを選択します。
    オムニチャネルフローテンプレート 説明
    Basic Routing with Case Creation (基本ルーティングとケース作成) 着信通話ごとにケースを作成します。
    Chats Routed to Agents and Queues (エージェントおよびキューにチャットを転送) 定義した条件に基づいて各チャットをサービス担当者またはキューに転送します。
    Chats Routed to Agents with the Right Skills (適切なスキルを持つエージェントにチャットを転送) 定義した条件に基づいて、必要なスキルを持つサービス担当者に各チャットを転送します。
    Voice Calls Routed to Agents and Queues (エージェントおよびキューに音声通話を転送) 定義した条件に基づいて各通話をサービス担当者またはキューに転送します。
    Messages Routed to Agents and Queues (エージェントおよびキューにメッセージを転送) 定義した条件に基づいて各メッセージをサービス担当者またはキューに転送します。
  6. フローを最初から作成するには、[オムニチャネルフロー] をクリックします。
  7. [次へ] をクリックします。
  8. 次の変数を作成して、フローの値を保存します。
    変数 リソース種別 説明
    recordId 変数 転送される作業レコードを一意に識別する ID を保存します。たとえば、フローで音声通話が転送される場合、音声通話 ID が保存されます。
    input_record レコード (単一) 変数 すべての項目と入力値を含めて転送される作業レコードを保存します。たとえば、フローでチャットが転送される場合、チャットトランスクリプトオブジェクトのチャットレコード全体が保存されます。
  9. 作業を転送するには、少なくとも 1 つの [作業を転送] アクションを追加します。
    [作業を転送] アクションは、フローの最後のオブジェクトです。
  10. [保存] をクリックします。
  • フロー変数について
    フローの値を保存するには、recordId、skillList、prechat、input_record の各変数を作成します。recordId は必須です。フローロジックによっては skillList、prechat、input_record は省略可能です。
  • 会話に関するコンテキストをより多く営業担当に提供する画面ポップの追加
    デフォルトでは、サービス担当者が作業項目を受け入れると、主作業レコードのみが開きます。ただし、コンテキストが増えると、サービス担当者は顧客ごとによりパーソナライズされたサービスを提供できます。音声通話、メッセージ、またはチャットが担当者に転送されたときに、サービス担当者の画面でレコードまたは画面フローを自動的に開くには、オムニチャネルフローに [画面ポップを追加] アクションを含めます。レコードまたは画面フローを合計 3 つまで開くことができます。たとえば、顧客のケースレコードと取引先責任者レコードを表示し、[チャネルオブジェクトリンク] 画面フローをサブタブとして開くことができます。
  • サービス担当者の対応可能状況の確認によるよりスマートなルーティングの決定
    新しい作業要求を処理するための組織の業務量に関して収集された情報を使用して、ルーティングを最適化します。[ルーティングの対応可能状況を確認] アクションをオムニチャネルフローに追加して、サービス担当者の対応可能状況と推定待機時間を決定します。このアクションでは、指定されたルーティング要件 (ルーティング種別とパラメーターを含む) に基づいて、オンラインサービス担当者の数と受け取りを待機している作業項目の数を返すことができます。また、顧客がサービス担当者に到達するまでに待機する必要がある時間を推定することもできます。その後、結果に基づいてルーティングロジックを作成できます。たとえば、サービス担当者のキューに 5 個を超える作業項目がある場合、代わりに作業を別のキューに転送できます。
  • キューへの作業項目の転送
    変数を使用して作業を特定のキューに自動的に転送します。
  • スキルへの作業項目の転送
    特定のスキルに基づいて作業項目を適格なサポート担当者に自動的に転送します。これを実現するには、スキルベースのルーティングルール、オムニチャネルフロー、またはその両方を組み合わせて使用します。たとえば、オムニチャネルフローを使用して特定のスキル要件を作業項目に条件付きで割り当てるには、[決定] アクションを追加して各作業項目に適用されるスキルセットを決定する条件を設定し、[スキル要件] アクションを追加してスキルセットを定義します。
  • 特定のサポート担当者への作業項目の直接転送
    エージェントへの直接転送を使用して、作業項目をサポート担当者に直接自動的に転送します。
  • 拡張ボットへの作業項目の転送
    拡張メッセージングチャネルを使用してビジネス条件に基づいて会話を拡張ボットに自動的に転送します。
