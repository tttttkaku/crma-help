  1. グローバルウィンドウオブジェクトに _snapinsSnippetSettingsFile を指定します。 
    window._snapinsSnippetSettingsFile = (function() {})();
  2. マージする embedded_svc.menu.snippetSettingsFile の設定をチャネルメニューに保存します。 
    window._snapinsSnippetSettingsFile = (function() {
    console.log("Code settings file loaded");

        TestChatChannel: {

メッセージングセッションと音声通話トランスクリプトでの機密データのブロック

拡張メッセージングセッション、拡張チャット、音声通話トランスクリプトで、クレジットカード番号や冒涜的な言葉など、特定のパターンをブロックする機密データルールを作成します。テキストを削除するか、好ましい文字に置き換えることができます。この方法はデータマスキングとも呼ばれ、顧客のデータを保護するのに役立ちます。

必要なエディション

Voice でサポートされているエディションを表示する。
メッセージングでサポートされているエディションを表示する。
この記事の対象: Voice、拡張アプリケーション内チャット、拡張 Web チャット、拡張 WhatsApp、拡張 Facebook Messenger、拡張 SMS、拡張 Apple Messages for Business、拡張 LINE、Bring Your Own チャネル
必要なユーザー権限
機密データルールを作成する

「アプリケーションのカスタマイズ」

および

システム管理者

機密データルールは、メッセージングセッションで送信されたテキストや、クイックテキストを含め音声通話で話されたすべてのプレーンテキストに適用されます。ささやきメッセージ、メッセージングコンポーネント、添付ファイル内のテキスト、サービス担当者名、またはメッセージングウィンドウに表示されるその他の標準テキストには適用されません。

  1. [設定] で、[クイック検索] ボックスに「機密データ」と入力します。
  2. 拡張メッセージングチャネル、拡張チャット、および音声トランスクリプトのルールを作成するには、[Sensitive Data Rules for Enhanced Channels (拡張チャネルの機密データルール)] というページを選択します。
  3. [新規] または [新規機密データルール] をクリックします。
  4. 名前と説明を入力し、保存後にルールの適用を開始するには、[有効] を選択します。
  5. 非表示にするテキストパターンを入力します。各パターンを JavaScript 正規表現 (regex) として記述し、必要な設定を選択します。regex では、大文字と小文字は区別されます。
  6. 検出されたときにテキストパターンを削除するか置き換えるかを選択します。置き換える場合は、置き換えるテキストを入力します。
  7. プレビューセクションを展開して、ルールをテストします。
    1. 社会保障番号の場合は 123-45-6789 など、非表示にするデータの形式でテキストを入力します。
    2. プレビューでテキストが削除または置き換えられることを確認します。
  8. 1 つ以上のロールを選択済み列に移動して、そのロールが送信したメッセージまたは発言した単語にルールを適用します。たとえば、顧客が送信したメッセージに含まれる次のパターンのデータを非表示にするには、[訪問者] を [選択されたロール] 列に移動します。
  9. ルールに優先度を割り当てます (0、1 など)。 数値の低いルールが先に適用されます。
  10. ルールを保存します。
  11. 有効なルールの適用を開始する準備ができたら、ページ上部の [機密データルール] 設定をオンにします。
    この設定を有効にすると、[拡張メッセージングの機密データルール] ページに表示されるすべての有効なデータルールが適用されます。この設定が無効になっている場合、ルールは適用されませんが、そのページでルールを作成して有効化することはできます。

メッセージングセッションまたは音声トランスクリプトで機密データが検出されると、次の 1 つ以上の会話トランスクリプトイベントが記録されます。

  • ブロックされた機密データ (エージェント) — サービス担当者またはボットによって送信された機密テキストが非表示になりました。
  • Sensitive data blocked (Supervisor) — スーパーバイザーから送信された機密テキストが非表示になりました。
  • Sensitive data blocked (Visitor) (ブロックされた機密データ (訪問者)) — 顧客が送信した機密テキストが非表示になりました。

ルールを有効にすると、今後のすべての音声通話、拡張メッセージングセッション、および拡張チャットセッションで、選択したロールに自動的に適用されます。Voice のみに適用するなど、選択的に適用することはできません。一度に最大 10 個の有効な機密データルールを設定できます。

ルールはリアルタイムで適用され、営業担当とデータベースに保存されているトランスクリプトの両方で機密テキストが非表示になります。機密データルールを作成または更新すると、変更は 1 時間以内に有効になります。機密データは Voice の録音では編集されず、トランスクリプトのみで編集されます。

個人をメッセージングセッションにリンクするフローの作成

メッセージングの相手についての詳細を参照します。フローテンプレートを使用して、取引先責任者、リード、従業員、または個人取引先をメッセージングセッションに自動リンクします。

フローを自動起動するように設定するか、サポート担当者がアクション & おすすめコンポーネントから実行できるようにします。

  1. チャネルオブジェクトリンクを使用していない場合は、ステップ 3 までスキップします。 チャネルオブジェクトリンクを使用している場合は、無効にしてから個人オブジェクトリンクを追加してください。[設定] の [クイック検索] ボックスに「チャネルオブジェクトリンク」と入力し、[チャネルオブジェクトリンク] を選択します。
  2. [チャネルオブジェクトリンク] を無効にします。
  3. [設定] で、[クイック検索] ボックスに「フロー」と入力して、[プロセスの自動化] の下にある [フロー] を選択します。
  4. [新規フロー] をクリックします。
  5. [すべて + テンプレート] をクリックします。
  6. [個人-オブジェクトリンクフロー] をクリックします。
  7. フローテンプレート「Find Contact Associated with Messaging Session (メッセージングセッションに関連付けられている取引先責任者を見つける)」を選択します。
  8. [作成] をクリックします。
  9. 取引先責任者ではなくリード、従業員、または個人取引先を検索するには、[Find Matching Contacts Flow (一致する取引先責任者フローを検索)] フローアクションをクリックし、[アクションを編集] を選択します。[オブジェクトを検索] ドロップダウンで選択します。
  10. 個々のレコードの特定の項目に検索を絞り込むには、[項目を検索] ドロップダウンメニューから選択します。
  11. 特定の用語または変数を検索するには、[検索語] 項目の内容を置き換えます。
  12. [完了] をクリックします。
  13. [保存] をクリックします。
  14. フローをテストして更新し、有効化します。

サポート担当者がフローを実行すると、ケースの [Web メール] 項目と同じメールアドレスの取引先責任者が表示されます。取引先責任者をケースにリンクするには、サポート担当者が一致する取引先責任者を選択します。

クイックチャットと Flex クレジット

Quick Chat で Agentforce Action Framework と Flex Credits を使用してリアルタイムをサポートする方法について説明します。

必要なエディション

使用可能なインターフェース: Salesforce Classic および Lightning Experience
使用可能なサイト: Aura および LWR Experience Cloud サイト
使用可能な機能: Einstein for Service、Einstein Platform、Community、Community Plus、または Agentforce for Service アドオンを使用した拡張チャット
使用可能なエディション: Foundations Edition または Agentforce 1 Edition が付属する Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition で使用できます。一部の標準エージェントアクションにアクセスするには、追加のアドオンライセンスが必要です。

クイックチャットでは、Agentforce アクションフレームワークを使用して対話型の支援が提供されます。ログイン数に応じて拡張されるKnowledge Article SummaryやDynamic Q&Aとは異なり、Quick ChatではFlex Creditsのプールが使用されます。

クイックチャットは Data 360 を操作し、顧客の問い合わせを解決するためのアクションをトリガーします。Agentforce アクションフレームワークを介して開始されたインタラクションまたはアクションごとにクレジットが消費されます。

柔軟なクレジットプロビジョニング

  • 基盤: Salesforce は、基盤または特定の製品エディションを通じてクレジットをプロビジョニングします。
  • Agentforce 1 Edition: このエディションには、チャット機能のクレジット数が設定されています。
  • 追加購入: 現在の残高が 0 になった場合にクイックチャットを引き続き使用するには、追加の Flex Credit を購入します。

Digital Walletでクレジット消費を追跡します。Digital Walletでは、クイック チャットのやりとりがクレジット残高にどのように影響するかを可視化できます。

Data 360 への会話データの同期

Data 360は、すべての異なるシステムの顧客データを統合し、1つの包括的な顧客ビューを作成するSalesforceプラットフォームです。ここで会話データを同期すると、データが分析可能なアセットに変換されます。

このデータを使用して、詳細な分析を実行したり、トレンドを特定したり、高度なビジネスインテリジェンスダッシュボードを構築したりできます。

  1. Data 360 で会話トランスクリプトへのアクセスを有効にします。
  2. 会話トランスクリプトのデータストリームを作成します。

会話インテリジェンスを使用したサポート担当者の処理時間の短縮

テレフォニーシステムからのインテリジェンスシグナルや、サポート担当者または顧客がメンションしたキーワードに基づいてアクションを自動的にトリガーします。顧客との会話中にサポート担当者を支援するために、スーパーバイザーとサポート担当者に通知を送信したり、サポート担当者におすすめを表示したり、バックグラウンドでプロセスを実行したりするルールを作成できます。たとえば、カスタマーエクスペリエンスが悪いために顧客がサービスのキャンセルを要求した場合に、サポート担当者が割引を提供することを推奨するアクションを作成します。

必要なエディション

サポートされているエディションを表示する。

この例では、顧客との現在の会話に基づいてサービスを 20% 割引する提案がサポート担当者に表示されます。

  • 検出されたキーワードに基づいたアクションの自動的なトリガー
    サポート担当者または顧客が電話またはメッセージで発言またはキーワードを入力したときにアクションをトリガーする会話インテリジェンスルールを作成します。サンプルアクションには、スーパーバイザーとサポート担当者への通知の送信、サポート担当者へのおすすめの表示、バックグラウンドでのプロセスの実行などがあります。たとえば、サポート担当者が「サービスをキャンセルしてください」と言った場合に、サポート担当者が割引を提供することを推奨するアクションを作成します。
  • インテリジェンスシグナルに基づいたアクションの実行
    テレフォニーシステムによって検出されたインテリジェンスシグナルに基づいてアクションを自動化します。たとえば、テレフォニーシステムでサポートコール中に顧客が不満を抱いていることが検出された場合、Salesforce Voice に Next Best Action のおすすめを表示できます。このおすすめでは、検出されたシグナルと顧客ロイヤルティ情報に基づいて、サポート担当者が 20% の割引を提供することを提案できます。
  • Next Best Action の設定
    Next Best Action をトリガーするルールを作成した場合は、会話中の キーワードまたはテレフォニーシステムからのインテリジェンスシグナルに基づいてサポート担当者におすすめを表示するように Einstein Next Best Action コンポーネントを設定します。サポート担当者に表示するおすすめを決定するために、Next Best Action コンポーネントは定義済みのアクション戦略を使用して受信シグナルを評価します。
  • 自動起動フローの設定
    自動起動フローを使用してビジネスプロセスを実行します。この場合はトリガーなしの自動起動フローを使用します。これはバックグラウンドで実行され、イベントによってトリガーする必要がありません。自動起動フローを実行するタイミングを指定するには、フローの条件を定義します。

    おすすめ戦略フローがリストに表示されていない場合は、フローを有効化したことを確認します。

    • データ型: Text
    • 複数の値を許可 (コレクション): false
    • 入力で使用可能: true
    • 出力で使用可能: false

  3. recordId 変数を追加するには、ツールボックスで [新規リソース] をクリックし、リソース種別として [変数] を選択します。API 参照名として「recordId」と入力し、データ型として [テキスト] を選択して、[入力で使用可能] を選択し、[完了] をクリックします。
  4. 必要に応じて、他の変数を追加します。

    変数の API 参照名は intelligenceSignals、recordId、または ruleDevName である必要があります。

    変数の適切なデータ型を選択します。intelligenceSignals 変数の場合、Apex クラスを EnhancedChannel__IntelligenceSignals に設定します。

    複数のシグナルを同時に渡すことができるコレクション変数の場合、[複数の値を許可 (コレクション)] を選択します。intelligenceSignals 変数で、[Available for input (入力で使用可能)] を選択します。これらの値はフローへの必須の入力パラメーターです。

  5. [アクション] 要素をフローに追加します。たとえば、ケースを登録するアクションを追加します。
  6. フローを保存して有効化します。

必要なエディション

サポートされているエディションを表示する。

Flow Builder は、Strategy Builder よりも柔軟性と機能が向上しています。Flow Builder を使用すると、Salesforce の顧客データとの統合も改善できます。Flow Builder の制限事項について理解するには、フローの制限を確認します。

おすすめ戦略フローを作成すると、recordId 変数と outputRecommendations 変数が事前設定されます。入力をフローに渡すには、変数をフローに追加します。詳細は、「おすすめ戦略フローの入力変数」を参照してください。

  5. トリガーされた会話インテリジェンスルールを確認し、通話を適切な NBA に転送するには、決定要素をフローに追加します。表示する NBA ごとに、次の設定を使用して結果ブランチを追加します。
    1. [表示ラベル] 項目に、NBA を識別する名前を入力します。
    2. ［Condition Requirements］ フィールドで、［All Conditions Are Met （AND）］ を選択します。
    3. ［Resource］ フィールドで、ruleDevName を選択します。

  6. おすすめレコードを取得するには、各決定ブランチの下に [レコードを取得] 要素を追加します。取得するおすすめを絞り込むには、条件を追加します。

  8. フローを保存して有効化します。

アクションをトリガーするには、テレフォニープロバイダーの検出されたシグナルを Salesforce で定義されたアクションに対応付けるフローを作成します。このアクションでは、スーパーバイザーとサポート担当者に通知を送信したり、スクリプトを表示したり、戦略を推奨したり、会話中にサポート担当者をサポートするその他のアクションを完了したりできます。アクションを定義するには、Einstein Next Best Action または自動起動フローを使用します。

Next Best Action のおすすめを使用して、顧客との現在の会話に基づいて次に何をするかをサポート担当者に表示します。おすすめは、テレフォニーシステムで定義されたインテリジェンスシグナル、またはメッセージングの会話で検出されたキーワードに基づくことができます。インテリジェンスシグナルに基づいておすすめを表示するには、最初に各シグナルを識別するテレフォニーシステムのルールを定義します。次に、Salesforce の会話インテリジェンスルールにトリガーを追加します。次に、対応するおすすめ戦略とおすすめを Salesforce で定義します。最後に、サポート担当者におすすめを表示するには、サポート担当者が作業するレコードページに Next Best Action コンポーネントを追加します。

自動起動フローを使用すると、小規模なものから複雑なものまでビジネスプロセスを実行し、メールの送信、ToDo の作成、取引先の作成などのアクションをすばやく実行できます。これらのフローは、Salesforce の会話インテリジェンスルールで定義した条件に基づいてバックグラウンドで自動的に実行されます。会話インテリジェンスでは、フロートリガーのない自動起動フローがサポートされています。
