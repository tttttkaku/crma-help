ケースコメントの作成と編集

ケースコメントを使用すると、ケースを参照または編集するときに、サポート担当者が公開および非公開のケースメモを追加、編集、削除できます。すべてのコメントは、[ケースコメント] 関連リストに表示されます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
ケースコメントを参照する ケースに対する「参照」
ケースコメントを追加し、公開する ケースに対する「編集」または「作成」
他のユーザーによって追加されたケースコメントを編集または削除する ケースに対する「すべてのレコードの編集」
既存のケースコメントを編集、削除、または公開する 「ケースコメントの編集」
ケースコメントのメール通知を送信する 「活動へのアクセス」

コメントは非公開のままにするか、公開して、カスタマーポータル、セルフサービスポータル、または Chatter アンサーでケースの取引先責任者が使用できるようにすることができます。顧客がケースにコメントできるようにポータルまたは Experience Cloud サイトを設定することもできます。ポータルユーザーがコメントを追加すると、ケースの所有者にメールが送信されます。ケースの所有者が確認するまで、ケースヘッダーのコメントアイコン () は表示されたままになります。

ポータルおよび Experience Cloud サイトへの顧客のコメントは常に公開されるため、ケースコメントの [公開] チェックボックスは冗長になり、顧客を困惑させます。顧客のこのチェックボックスをオフにするには、組織レベルで設定を有効にします。

  1. [設定] に移動して、[クイック検索] ボックスを使用して [サポート設定] を検索します。
  2. [サポート設定] を選択し、[編集] をクリックします。
  3. [ケースコメントを非表示にする] [コミュニティユーザーに公開] チェックボックスをオンにします。
  4. [保存] をクリックします。
メモ Spring '12 以降、新しい Salesforce 組織ではセルフサービスポータルを利用できません。既存の組織は、引き続きセルフサービスポータルを使用できます。

ケースの詳細ページ

[ケース] タブまたは関連リストからケースを開くと表示されるケースの詳細ページで、ケースコメントを作成および編集できます。

  1. ケースの詳細ページで、[ケースコメント] 関連リストの [新規] または [編集] をクリックします。
  2. 必要に応じて、[公開] を選択すると、ケースの取引先責任者へのコメント通知を有効にし、取引先責任者がカスタマーポータルまたはセルフサービスでコメントを参照できるようになります。
  3. [コメント] にコメントを入力します。
  4. [保存] をクリックします。

Salesforce to Salesforce から外部の取引先責任者に対しケースおよびケースコメントを公開すると、ケースを共有するときに、接続先と、すべての公開ケースコメントを自動的に共有します。コメントの共有を停止するには、[非公開] をオンにします。

[ケースコメント] 関連リストから、次の操作を実行できます。

  • 既存のコメントを削除するには、[削除] をクリックします。
  • カスタマーポータルまたはセルフサービスポータルのコメントの公開状態を変更するには、[公開] または [非公開] をクリックします。[公開] とマークされたケースコメントは、Chatter アンサーにカスタマーサポートからの非公開メッセージとして表示されます。サイト全体には表示されません。たとえば、サポート担当者が公開ケースコメントを追加すると、Chatter アンサーのケースの取引先責任者の非公開メッセージにのみ表示されます。サポート担当者は、すべての非公開ケースコメントと公開ケースコメントを参照できます。

ケース編集ページ

ケース編集ページでケースコメントを作成および編集できます。

  1. ケースを作成するには、[ケース] タブの [新規] をクリックします。または、既存のケースを選択して [編集] をクリックします。
  2. [社内コメント] にコメントを入力します。
  3. 必要に応じて、[通知メールを送信する] を選択すると、ケースの取引先責任者に新規の公開コメントが送信されます。
  4. [保存] をクリックします。ケースコメントが作成されると常に、ケース所有者にメールが送信されます。

[通知メールを送信する] は、次の場合にケース編集ページに表示されます。

  • システム管理者が、[サポート設定] または [セルフサービスポータル設定] ページで取引先責任者へのケースコメントの通知を有効にしている。
  • コメントが [公開] に設定されている。
  • ケースに取引先責任者が存在する。
  • ケースの取引先責任者が有効なメールアドレスを持っている。

ケース履歴

ケース詳細ページの [ケース履歴] 関連リストでは、ケースに対する変更を追跡します。ケースの履歴を追跡するように設定した任意の標準項目またはカスタム項目をユーザーが編集すると、常に新しい履歴が [ケース履歴] 関連リストに追加されます。すべてのエントリには、日付、時間、変更内容、変更者が含まれます。ケースの関連リストに対する変更は、ケース履歴では追跡されません。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
ケースを参照する ケースに対する「参照」
メモ [作成時にクローズ] 項目への変更は、Lightning プラットフォーム API を使用して項目が更新された場合にのみ追跡されます。

Professional Edition、Enterprise Edition、Unlimited Edition、Performance Edition、および Developer Edition の組織では、Web-to-ケースやケース割り当てルールまたはエスカレーションルールによってケースが自動的に変更された場合、履歴に表示されるユーザーは、[サポート設定] で選択した [自動ケース更新ユーザー] です。

Salesforce Classic ケースフィードのメールドラフトの確認と承認

システム管理者が組織のドラフトメールと承認プロセスをどのように設定しているかに応じて、監視するサポート担当者が作成したメッセージを顧客に送信する前に確認および承認する必要があります。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
メールドラフトを確認して承認する

「メールの送信」

および

メール承認プロセスに含まれている

サポート担当者が承認申請すると、メッセージを含むケースへのリンクが記載されたメール通知が送信されます。通知は、[メール] をクリックするとパブリッシャーの上部に表示されます。[メールを参照] をクリックすると、メッセージの詳細ページに移動します。そのページでは、次の操作を実行できます。

  • [レコードのロック解除] をクリックして、メッセージを編集可能にする。
  • [削除] をクリックして、ドラフトを破棄する。
  • [承認履歴] 関連リストにある [承認/却下] をクリックして、メッセージを承認または却下する。
  • [再割り当て] をクリックして、他のスーパーバイザーに承認を割り当てる。

メッセージを承認すると、そのメッセージは顧客に送信されます。却下すると、理由を説明するメモを作成するオプションが表示されます。このメモは、サポート担当者が [メール] をクリックすると、ドラフトが却下されたことを示す通知と共にケースページのパブリッシャーの上に表示されます。

Salesforce Classic ケースフィードでのメールへの画像とファイルの添付

メールメッセージにファイルを添付し、インライン画像を追加して画像でテキストを拡張することで、ユーザーに包括的な情報を提供し、問題をより迅速に解決できるようにします。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
添付ファイルまたはインライン画像を含むメールを送信する 「メールの送信」

たとえば、問題を解決するために顧客がいくつかの異なるソリューションを試さなければならないケースに取り組む場合、ハウツー動画や、複数の詳細なトラブルシューティング手順を含むドキュメントを添付します。顧客が特定のトラブルシューティングステップセットに慎重に従う必要がある場合、メッセージ本文の各ステップの後にインライン画像を使用します。

  • インライン画像を追加するには、ケースフィードメールパブリッシャーのツールバーで [] をクリックし、必要な画像をアップロードまたはリンクします。埋め込む画像はそれぞれ 1 MB 以下で、.png、.jpg、.jpeg、.jpe、.jfif、.pjpeg、.bmp、.gif のいずれかの形式にする必要があります。画像とテキストを含むメールメッセージの合計サイズは、12 MB 以下にする必要があります。
    メモ メールパブリッシャーのリッチテキストエディターを使用して、画像を埋め込みます。プレーンテキストメッセージに画像を埋め込むことはできません。
  • ファイルをメールに添付するには、[ファイルをアップロード] をクリックしてコンピューターまたは Salesforce からファイルを選択するか、すでにケースに添付されているファイルを使用するか、メールパブリッシャー下部にある添付ファイル領域にファイルをドラッグします。各メールメッセージには、合計で最大 10 MB まで添付できます。Salesforce では、すべての種類のファイルがサポートされます。ドラッグアンドドロップ機能は Microsoft Edge ではサポートされておらず、HTML5 をサポートするブラウザーでのみ使用できます。
  • 追加した添付ファイルのリストを表示するには、[ファイル:] をクリックします。
  • 添付ファイルを削除するには、添付ファイルの横にある をクリックします。

メールの受信者がメッセージを表示すると、埋め込み済みの画像がメールの本文に表示されます。メッセージに添付したすべてのファイルの合計サイズが 3 MB を超えると、添付ファイルはすべてリンクとして表示され、受信者はそのリンクを使用してファイルをダウンロードできます。添付ファイルの合計サイズが 3 MB 未満の場合、各ファイルは添付ファイルとして表示されます。

例 あなたは家電会社のサービス担当者で、冷蔵庫の製氷機に問題がある顧客のケースを担当するとします。顧客に、製氷機のトラブルシューティング手順をステップごとに説明したメール (各ステップの後に画像を挿入) を、冷蔵庫のユーザーマニュアルの PDF (2 MB のファイル) と冷蔵庫の正常な動作を維持するための保守ヒントの一覧 (10 KB のファイル) の 2 つのドキュメントを添付して送信します。顧客が受信したメールには、次のファイルとドキュメントが表示されます。
  • 顧客がトラブルシューティング手順を実行しながら 1 ステップごとに画像を参照できるようにメールの本文に埋め込まれた画像
  • メッセージに添付されたユーザーマニュアルと保守ヒントの一覧 (合計サイズが 3 MB 未満であるため)

トラブルシューティングビデオ (2.5 MB のファイル) も添付した場合、すべての添付ファイルの合計サイズが 3 MB を超えるため、3 つの添付ファイルはすべてリンクとして顧客に表示されます。

ケースフィードへのカスタムアクションの追加

ケースフィードパブリッシャーにカスタムアクションを含めると、サポート担当者はケースを使用するときに必要となる追加のツールや機能に簡単にアクセスできます。

ケースフィードのアクションを使用すると、サポート担当者は顧客へのメール送信、ケースメモの作成、ケースの状況の変更などのタスクを実行できます。Visualforce ページを使用して、サポート担当者により多くの機能を提供するカスタムアクションを作成できます。たとえば、サポート担当者が顧客のロケーションを検索して近隣のサービスセンターを検索できる [地図とローカル検索] アクションを作成します。標準ケースコントローラーを使用する Visualforce ページをカスタムアクションとして使用できます。

高度なページレイアウトエディタを使用してケースフィードレイアウトのパブリッシャーを設定するように選択した場合、アクションを追加する手順については、「Salesforce Classic のケースフィードページレイアウト」を参照してください。

  1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. [ケースフィードの設定] ページへのアクセス方法は、使用しているページレイアウトの種類に応じて異なります。
    1. [ケースページレイアウト] セクションのレイアウトの場合、[編集] をクリックし、ページレイアウトエディターで [フィードビュー] をクリックします。
    2. [ケースフィードユーザーのページレイアウト] セクションのレイアウトの場合、 をクリックし、[フィードビューを編集] を選択します。(このセクションは、Spring '14 より前に作成された組織にのみ表示されます)。
  3. カスタムアクションのリストで [+ Visualforce ページを追加] をクリックします。
  4. アクションとして追加するページを選択します。
  5. アクションの高さをピクセル単位で指定し、[保存] をクリックします。

ケースフィードへのカスタムコンポーネントの追加

Visualforceページをケースフィードのカスタムコンポーネントとして使用し、サポート担当者がケースの操作中に特別なツールや機能に簡単にアクセスできるようにします。

たとえば、サポート担当者が顧客がどこにいるかを確認できる地図コンポーネントを作成したり、サポート担当者が作業中のケースに関連する商品を検索するために使用できるツールを作成したりします。標準ケースコントローラーを含む Visualforce ページは、カスタムコンポーネントとして使用できます。

カスタムコンポーネントとして使用する Visualforce ページを作成したら、ケースフィードレイアウトにそれを追加します。

  1. [ケースフィードの設定] ページへのアクセス方法は、使用しているページレイアウトの種類に応じて異なります。
    • [ケースページレイアウト] セクションのレイアウトの場合、[編集] をクリックし、ページレイアウトエディターで [フィードビュー] をクリックします。
    • [ケースフィードユーザーのページレイアウト] セクションのレイアウトの場合、 をクリックし、[フィードビューを編集] を選択します。(このセクションは、Spring '14 より前に作成された組織にのみ表示されます)。
  2. [その他のツールおよびコンポーネント] セクションで、[+ Visualforce ページを追加] をクリックし、目的のページを選択します。コンポーネントの幅は、コンポーネントが含まれる列の幅によって決まります。コンポーネントを最適に見せるために、幅を 100% に設定することをお勧めします。
  3. コンポーネントの高さを設定します。
  4. ページ上のコンポーネントを表示する場所を選択します。

サポート担当者が [ケースの詳細] ページを表示すると、右列のコンポーネントは非表示になるため、常にアクセスできるようにするコンポーネントには左列を使用します。

コンソールサイドバーへのグローバルアクションとカスタムクイックアクションのコンポーネントとしての追加

グローバルアクションとカスタムクイックアクションをコンポーネントとしてサービスコンソールサイドバーに追加できるため、サポート担当者は現在のタブから離れることなく、レコードの作成、ケース情報の更新、関連情報の検索、親レコードへのリンクをすべて行うことができます。クイックアクションを使用してケースの詳細ページを置き換えることで、サポート担当者はメインワークフローで取引先責任者や納入商品などのケース関連情報を確認できます。

  1. グローバルアクション (作成アクション用) とカスタムクイックアクション (更新アクション用) を作成します。
    作成アクションは、グローバルクイックアクションである必要があります。更新アクションは、参照項目オブジェクト種別に基づくオブジェクト固有のクイックアクションである必要があります。たとえば、取引先責任者の参照項目を更新するには、取引先責任者固有の更新アクションが必要です。
  2. クイックアクションをサポート担当者が使用できるように、アクションをコンポーネントとしてケースページレイアウトに追加します。
    1. [設定] から、[クイック検索] ボックスに「ケース」と入力し、[ページレイアウト] を選択します。
    2. クイックアクションを追加するページを選択し、[編集] をクリックします。
    3. [ケースレイアウト] ページで、[カスタムコンソールコンポーネント] を選択します。
    4. コンポーネントを追加するサイドバーセクション ([左サイドバー] セクションなど) に移動します。
    5. [種別] で [ルックアップ] を選択します。
    6. [項目] で、クイックアクションが実行される関連項目を選択します。
    7. サポート担当者がレコードを検索して関連レコードにリンクできるようにするには、[リンクを有効化] を選択します。たとえば、サポート担当者は取引先責任者名をケースにリンクできます。
    8. [作成アクション] で、レコードを作成するグローバルアクションを選択します。たとえば、グローバルアクションで取引先責任者を作成できます。
    9. [更新アクション] で、レコードを更新するクイックアクションを選択します。たとえば、クイックアクションで取引先責任者の項目を更新できます。
    10. [保存] をクリックします。

ケースのメールドラフトの有効化

ドラフトメールを使用すると、ケースフィードを使用するサポート担当者は、すぐにメッセージを送信することなくメッセージを作成して保存できます。このオプションでは、承認プロセスを実装できるため、スーパーバイザーやシニアサポート担当者がメッセージをレビューしてから顧客に送信できます。

メールドラフトを有効にする前に、メール-to-ケースを設定します。Salesforce Classic では、ケースフィードも有効にする必要があります。

  1. [設定] から、[クイック検索] ボックスに「サポート設定」と入力し、[サポート設定] を選択します。
  2. [編集] をクリックします。
  3. [メールドラフトを有効化] を選択します。
  4. [保存] をクリックします。

次の考慮事項に留意します。

  • Salesforce Classic: メッセージがドラフトとして保存される場合、[メール] アクションの [宛先]、[差出人]、[CC]、[BCC]、[件名] 以外の項目への変更は保存されません。ドラフトメールを使用する場合、[メール] アクションからすべての追加項目を削除することをお勧めします。
  • Lightning Experience: 非公開メールドラフトを使用する場合、[メール] アクションからすべての追加項目を削除することをお勧めします。カスタムメールメッセージ項目への変更は直ちに保存されません。ただし、標準項目が変更されると、以前のカスタム項目の変更も保存されます。メールドラフトを有効化すると、メールコンポーザーのツールバーの [ドッキングビューにポップアウト] ボタンが無効になります。
  • メールドラフトは、ケースの [メールを送信] クイックアクションでのみサポートされ、メールコンポーザーでは使用できません。
  • メールコンポーザーまたは他のオブジェクトから送信するメールには、メール承認の制限は適用されません。
  • ケースでメールドラフトが有効化されている場合、メールコンポーザーには削除アイコン、更新ボタン、ポップアウトアイコンが表示されません。

ケースフィードのデフォルトメールテンプレートの有効化

ケースフィードのデフォルトメールテンプレートを使用して、サポート担当者が作業中のケースの種別に基づいて必要なテンプレートに簡単にアクセスできるようにします。デフォルトのメール テンプレートを有効にする前に、テキスト、HTML、または Visualforce テンプレートを作成し、テンプレート選択ロジックを含む Apex クラスを作成する必要があります。

デフォルトメールテンプレートを使用すると、サポート担当者はより迅速、正確かつ一貫性のある方法で顧客に簡単に応答できます。メールテンプレートは事前に読み込まれているため、サポート担当者はメールを作成する前に必要なテンプレートを参照する必要はありません。テンプレートは必要なだけ作成でき、会社のニーズに基づいて割り当てることができます。たとえば、サポートセンターが複数の製品に関連する問題を処理する場合、製品ごとに固有のテンプレートを作成し、ケースの発生源、件名、またはその他の条件に基づいて適切なテンプレートを事前に読み込むことができます。

  1. [設定] から、[クイック検索] ボックスに「サポート設定」と入力し、[サポート設定] を選択します。
  2. [編集] をクリックします。
  3. [デフォルトメールテンプレートを有効化] を選択します。
  4. テンプレート選択ロジックを含む Apex クラスを選択します。
  5. [保存] をクリックします。

メールドラフトの承認プロセスの作成

承認プロセスでは、どのメッセージに承認が必要か、承認者を自動的に割り当てるかどうかなどを指定して、組織でのドラフトメールメッセージの処理方法を決定します。会社のニーズに基づいてカスタマイズした承認プロセスを作成します。

  1. ドラフトメールを有効化します。
    このステップを実行しなくてもメールメッセージの承認プロセスを作成できますが、このステップを実行しないで作成したプロセスは組織でメールドラフトが使用可能になるまでトリガーされません。
    Experience Cloud サイトのメールドラフトの承認プロセスを使用することはできません。
  2. 送信アクションを作成します。
    送信アクションによりメールメッセージが承認後に確実に送信されます。
  3. 承認プロセスを作成します。
    必ず、[承認プロセスを管理するオブジェクト:] ドロップダウンリストから、メールメッセージを選択してください。
  4. 上級サポート担当者など、特定のユーザーにメール・メッセージの承認申請を行うか、単にメッセージを送信するかを選択できるようにするには、「メール承認をバイパス」権限が選択されているプロファイルに割り当てます。

If you use Apex to create customized approval processes for email message drafts, the from address in the message defaults to the organization-wide address instead of the user’s email address. To set an Email-to-Case routing address as the from address, define an organization-wide address that matches the Email-to-Case routing address.

メールの承認プロセスの送信アクションの作成

送信アクションを使用して、承認プロセスの終了時にメールメッセージが自動的に送信されるようにすることで、サポート担当者の時間を節約します。送信アクションは、メールドラフトを有効化している組織でのみ使用できます。

  1. [設定] から、[クイック検索] ボックスに「送信アクション」と入力し、[送信アクション] を選択します。
  2. [新規送信アクション] をクリックします。
  3. [オブジェクト] ドロップダウンリストから [メールメッセージ] を選択します。
  4. アクションに一意の名前を入力します。
  5. 必要に応じてアクションの説明を入力します。
  6. [保存] をクリックします。

送信アクションを作成したら、そのアクションを含む承認プロセスを作成します。

ケースフィードでの外部に表示されるフィード項目の強調表示

ケースフィードで外部ユーザーに表示されるフィード項目をマークできます。これにより、サポート担当者は、顧客に表示されるフィード項目と、サポート担当者などの内部ユーザーのみに表示されるフィード項目を簡単に区別できます。

デフォルトでは、ケースフィードで誰に表示されるかによってフィード項目が区別されることはありません。

この区別をマークするには、[外部から参照可能なフィード項目を強調表示] および [エクスペリエンスケースフィードを有効化] 設定を両方とも有効にします。設定を有効にすると、次の種別の投稿がケースフィードでの一般公開としてマークされます。

  • ケース取引先責任者のメールアドレスとの間で送受信された公開メール
  • 公開ケースコメント
  • すべてのソーシャル投稿 (Facebook 投稿など)
  • Experience Cloud サイトからエスカレーションされた質問
  • [アクセス権があるすべてのユーザー] または [公開] が設定された ToDo
  • [アクセス権があるすべてのユーザー] または [公開] が設定された行動
  • [アクセス権があるすべてのユーザー] または [公開] が設定された Chatter 投稿
  • 記録された活動

[外部から参照可能なフィード項目を強調表示] のみを有効にすると、ケース取引先責任者のメールアドレスとの間で送受信されたメールフィード項目のみがマークされます。

ケースフィード項目をマークするには、次の手順を実行します。

  1. [外部から参照可能なフィード項目を強調表示] 設定を有効にします。
    1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
    2. 編集するフィードベースのページレイアウトを選択し、[編集] をクリックします。
    3. [フィードビュー] 設定までスクロールし、[外部から参照可能なフィード項目を強調表示] を選択します。
  2. [エクスペリエンスケースフィードを有効化] 設定を有効にします。
    1. [設定] から、[クイック検索] ボックスに「サポート設定」と入力し、[サービス] | [サポート設定] をクリックします。
    2. [エクスペリエンスケースフィードを有効化] を選択します。

ケースフィードのポータル返信メール通知の有効化

組織でポータルまたは Experience Cloud サイトを使用している場合、サポート担当者はケースフィードのアクションを使用して顧客に応答できます。返信メール通知を有効にすると、サポート担当者は [メールを送信] オプションにアクセスできます。

  1. [設定] から、[クイック検索] ボックスに「サポート設定」と入力し、[サポート設定] を選択します。
  2. [編集] をクリックします。
  3. [取引先責任者へのケースコメント通知を有効化] を選択します。
  4. メール通知のテンプレートを選択します。
  5. [保存] をクリックします。

Emails sent to external users include a link to the site. If the user receiving the email is a member of multiple active Experience Cloud sites, the link goes to the oldest active site. If the user is already logged in to a site and clicks the link in the email, the link goes to that site. If the user isn't a member of any site, the link goes to the internal org. If the user is a member of a portal and a site, the link goes to the site.

Salesforce Classic ケースフィードのドラフトメールの使用

ドラフトメールを使用すると、サポート担当は顧客に作成したメッセージをすぐに送信せずに保存でき、システム管理者はメールメッセージの承認プロセスを作成できます。

必要なエディション

サポートされているエディションを表示する。

ドラフトは、システム管理者がドラフトを有効化している場合にのみサポートされます。

サポート担当者は、解決している問題に関する追加情報を収集したり、同僚とトラブルシューティング手順を確認したり、休憩して Salesforce からログアウトしたりするときに、メッセージをドラフトとして保存できます。メールをドラフトとして保存するには、メールを書いているテキストボックスの下にある [保存] をクリックします。

ケースフィードの権限セットの作成

組織のケースフィードを有効にした後、ユーザーにケースフィードのアクセス権を付与する権限セットを作成します。

  3. [ケースフィードを使用] を選択します。必要に応じて、セットに含める他の権限を設定します。
  4. [保存] をクリックします。

「ケースフィードの使用」権限は、フィードベースのレイアウトを有効にしていない、Winter '14 より前に作成された組織でのみ使用できます。Winter '14 リリース以降に作成される Salesforce 組織では、ケースフィードが自動的に有効化され、すべての標準プロファイルに割り当てられます。

既存の権限セットがある場合は、編集して「ケースフィードを使用」権限を含めることができます。ただし、[印刷用に表示] ページでの項目の表示に影響します。この権限が有効になっている場合、すべてのレコード項目を表示できません。すべてのレコード項目を表示するには、この権限を無効にします。

ユーザーへのケースフィードの割り当て

組織のケースフィードを有効にして、そのケースフィードを含む権限セットを作成した後、その権限セットをユーザーに割り当てます。

  1. [Setup (設定)] から、[Quick Find (クイック検索)] ボックスに「Users (ユーザー)」と入力し、[User (ユーザー)] を選択します。
  2. ユーザーの名前を選択します。
  3. [権限セットの割り当て] リストで、[割り当ての編集] をクリックします。
  4. [利用可能な権限セット] リストの権限セットを選択して、[追加] をクリックします。
  5. [保存] をクリックします。

カスタムプロファイルを使用した、ユーザーへのケースフィードのアクセス権の付与

権限セットを使用してユーザーにケースフィードのアクセス権を付与する代わりに、[ケースフィードを使用] ユーザー権限を含むカスタムプロファイルを作成できます。

  2. プロファイルページで [編集] をクリックします。
  3. [一般ユーザー権限] で、[ケースフィードを使用] を選択します。
  4. [保存] をクリックします。
  5. ユーザーをプロファイルに割り当てます。

ケースフィードでのフィード条件の使用

フィード検索条件を使用すると、サポート担当者はケースフィードでケースを操作するときに、すべての通話ログやすべてのメールメッセージなど、1 つの種別のすべての更新を簡単に確認できます。検索条件を使用することで、サポート担当者はケースイベントごとに参照することなく、必要な情報をよりすばやく見つけることができます。

必要なエディション

サポートされているエディションを表示する。

システム管理者は、フィードレイアウトの作成または編集時に使用する条件を指定できます。

  • [すべての更新] のみを選択すると、ケースのすべてのイベントが自動的に表示され、個別のフィード条件のリストは表示されません。このオプションは、サポート担当者がケースの完全な履歴を参照できるようにする場合に使用します。
  • 1 つの種別のみのフィード条件を選択すると、その種別のケースイベントのみが自動的に表示され、個別のフィード条件のリストは表示されません。たとえば、[すべてのメール] のみを選択した場合、各ケースのフィードにはケースに関連するメールメッセージは表示されますが、ケースメモ、ポータルの返信、またはその他の活動は表示されません。このオプションは、主に 1 つのチャネル (電話、メール、ポータル) でサポートを提供し、そのチャネルのケースイベントのみを表示する必要があるサポート担当者に役立ちます。
  • 複数の種別のフィード条件を選択すると、ケースフィードページの左のサイドバーまたはこのページの中央のフィードの上に、使用可能な条件のリストが表示されます。最初の条件がデフォルトで選択されます。たとえば、[すべてのメール]、[状況の変更]、[ポータルアンサー] を使用可能にしている場合、各ケースのフィードには、デフォルトで、ケースに関連するメールメッセージが表示されます。他の条件をクリックすると、他の種別のケースイベントを表示できます。このオプションは、サポート担当者が 1 つのチャネルでサポートを提供する傾向があるが、他の種別のケース更新も確認する必要がある場合に使用します。

また、システム管理者はフィード条件のリストが表示される位置と方法を次から指定できます。

  • 左列に固定リストとして表示。
  • 左列にフロート表示リストとして表示。このオプションを使用すると、フィード条件リストはページをスクロールダウンしても常に表示されます。このオプションを使用すると、サポート担当者はページ上部までスクロールすることなく、ページのどこからでもケース活動をすばやく絞り込むことができるため、フィードが長い場合に便利です。
  • 中央列にドロップダウンリストとして表示。
  • コンパクトフィードビュー内のインラインリンクとして表示。このオプションは、コンパクトフィードビューでのみ使用できます。

Salesforce Classic でのケースフィードの使用

ケースフィードによって、ケースを作成、管理、表示する方法が合理化されます。ケースフィードには、ケースメモの作成、活動の記録、ケース状況の変更、Chatter フィードでの顧客とのやりとりなどのケースアクションが用意されています。ケースフィードには、重要なケースイベントが時系列に表示されるため、各ケースの進捗状況を簡単に確認できます。

必要なエディション

サポートされているエディションを表示する。

ケースフィードページレイアウトに割り当てられた営業担当には、スクリーンショットに示されているページに似たページが表示されます。システム管理者はケースページレイアウトをカスタマイズできるため、組織のページレイアウトは異なる可能性があります。

  • 強調表示パネル (1) — 取引先責任者情報、ケース名、ケースの説明、状況、優先度、ケース所有者など、ケースの最も重要な情報の概要が表示されます。サポート担当者は、列の区切り文字を使用して強調表示パネルのセクションのサイズを変更し、最も関連性の高い情報をより多く表示できます。
  • フィードビューと詳細ビュー (2) — サポート担当者は、パブリッシャーとフィードを含むフィードビューから、ケースの詳細ビューに簡単に切り替えて、詳細情報を表示したり、関連リストを操作したりできます。
  • パブリッシャー (3) — [メール]、[ケースメモ]、[状況の変更] アクションなど、ケースを操作するために営業担当が使用するアクションが含まれます。
  • 記事ツール (4) — サポート担当者は、ケースの解決に役立つ Knowledge 記事を見つけて、ケースに添付したり、顧客にメールで送信したりできます。
  • フィード検索条件 (5) — 表示されるフィード項目を制限することで、サポート担当者がフィード内の特定の情報をすばやく見つけることができます。
  • フィード (6) — ケースの履歴が時系列に表示されます。フィード項目は以下を対象に作成されます。
    • ケースレコード作成
    • ケースに関連する受信メールおよび送信メール
    • カスタマーポータルまたは Chatter アンサーのケースに関連するコメント
    • ケースについて記録された活動
    • ケースの状況に対する変更
    • ケースに対して作成されたコメント
    • ケースに追加されたリンクまたはファイル
    • ケースに関連するマイルストーン活動
    • ワークフローイベントによるケースアクション
    • ケースに関連する新規 ToDo および行動
  • [フォロー] ボタンおよび [フォローされている人] リスト (7):サポート担当者がケースをフォローして、Chatter でケースの更新が通知されるようにし、他のフォローされている人を表示できるようにします。
  • カスタムボタンとカスタムリンク (8) — サポート担当者がより多くのツールと機能にアクセスできるようにします。

システム管理者は、ケースフィードの大部分の要素 (以下を含む) をカスタマイズできます。

  • 強調表示パネルの項目
  • 表示されるアクション、およびアクションに含まれる項目
  • 使用可能なフィード条件、およびページ上のそのリストの表示場所
  • フィードの幅
  • 使用可能なツール、カスタムボタン、カスタムリンク、およびページ上のこれらの表示場所

ケースフィードの使用について、もう少し詳しく説明します。

  • ケースフィードのアクションを使用したケースの操作
    ケースフィードアクションを使用すると、サポート担当者はメールの送信、ポータルや Experience Cloud サイトへの投稿、活動の記録、ケース状況の変更、ケースメモの作成などをすべて同じページで簡単に行うことができます。
  • ケースフィードでのフィード条件の使用
    フィード検索条件を使用すると、サポート担当者はケースフィードでケースを操作するときに、すべての通話ログやすべてのメールメッセージなど、1 つの種別のすべての更新を簡単に確認できます。検索条件を使用することで、サポート担当者はケースイベントごとに参照することなく、必要な情報をよりすばやく見つけることができます。
  • ケースフィードと関連リスト
    従来のケースインターフェースでは、サポート担当は主に関連リストを使用して、通話の記録やメールの送信などのタスクを実行します。ケースフィードでは、サポート担当はフィードでこれらのタスクをいくつか直接実行できます。
  • ケースフィード記事ツールを使用した、記事の検索、添付、およびメール送信
    ナレッジ記事は、詳細なトラブルシューティング手順やその他の詳細情報が記載されているため、ケースをすばやく解決するのに役立ちます。ケースフィードの記事ツールを使用して、作業しているケースに関連する記事を検索したり、ケースに記事を添付したり、記事を顧客にメールで送信したりします。
  • ケースフィードのケースの詳細ページからのケースの参照と編集
    ケースの詳細ページを使用して、ケースに関する詳細情報を参照および更新し、関連リストを操作します。
  • ケースフィードの [エクスペリエンス] アクションによるケースおよび Experience Cloud サイトの質問への投稿
    Experience Cloud サイトまたはカスタマーポータルから作成されたケースの場合、ケースフィードの [エクスペリエンス] アクションが、顧客に回答するデフォルトオプションです。
  • ケースフィードの [印刷用に表示]
    [印刷用に表示] オプションを使用すると、ケースに関連する情報の完全な一覧を表示して印刷できます。

Salesforce Classic のケースフィードページレイアウト

サービス担当者がケースフィードでケースを操作する場合、ケースページレイアウトを使用します。担当者がオープンケースを操作するときに表示される項目、ツール、機能を指定するには、ケースページのフィードビュー、詳細ビュー、強調表示パネルをカスタマイズします。

必要なエディション

サポートされているエディションを表示する。

Salesforce Classic のケースフィードでは、ケースページレイアウトのさまざまな部分をカスタマイズできます。

  • 強調表示パネルは、フィードとケースの詳細ページの両方の上部に表示されます。強調表示パネルにはケースに関する重要な情報が表示されるため、担当者は最も重要な詳細をすばやく確認できます。
  • フィード ビューには、Chatterのようなフィードを使用してケース履歴が表示されるため、担当者はコンテキスト内でケースで何が起きたかを確認できます。
  • 詳細ビューは、営業担当が [View Case Details (ケースの詳細を表示)] をクリックしたときに表示されます。詳細ビューには、取引先責任者の会社の説明、取引先の住所、および関連リストなどのケースに関する有益な情報が表示されます。

ケースフィードでクローズケースページレイアウトをカスタマイズすることもできます。このレイアウトでは、担当者がケースの解決に関する情報を入力します。また、[設定] のオブジェクトマネージャーのケースオブジェクト設定で、すべてのケースページ種別を作成、編集、割り当てることができます。

  • ケースフィードユーザーのページレイアウトのケースページレイアウトへの変換
    Spring '14 では、ケースレイアウトの作成とカスタマイズを容易にするために、ケースフィードユーザーのページレイアウトがフィードベースのケースページレイアウトに置き換えられました。
  • ケースフィードの強調表示パネルのカスタマイズ
    強調表示パネルはフィードの詳細ビューの最上部に表示されます。このパネルには、ケースに関する最も重要な情報が表示されます。
  • 高度なページレイアウトエディターを使用したケースフィードパブリッシャーの設定
    組織でパブリッシャーのアクション機能を使用している場合、高度なページレイアウトエディターを使用してケースフィードパブリッシャーに表示されるアクションを選択できます。
  • ケースフィードのフィードレイアウトの作成と編集
    フィードビューのページレイアウトでは、ケースフィードでユーザーがケースを使用するときに表示されるアクション、項目、ツールを決定します。
  • ケースフィードのフィードビューの設定
    ケースフィード設定を使用して、サポート部門のプロセスおよびビジネスニーズに合わせて機能をカスタマイズします。
  • ケースフィードへの添付ファイルコンポーネントの追加
    ケースフィードページに添付ファイルコンポーネントを追加して、営業担当がケースに関連付けられたすべてのファイルをすばやく表示して管理できるようにします。
  • ケースフィードへのケースのエキスパートコンポーネントの追加
    ケーストピックのエキスパートを簡単に特定して、サービス担当者が協力して顧客の問題を迅速に解決できるようにします。
  • ケースフィードのアクションおよびフィード条件の名称変更
    会社が使用する用語に一致するようにケースフィードのアクションとフィード条件の名前を変更します。
  • ケースフィードのカスタムフィード条件の作成
    カスタムフィード検索条件を使用すると、サポート担当者は自分に最も関連する項目に集中できます。

ケースフィードユーザーのページレイアウトのケースページレイアウトへの変換

Spring '14 では、ケースレイアウトの作成とカスタマイズを容易にするために、ケースフィードユーザーのページレイアウトがフィードベースのケースページレイアウトに置き換えられました。

必要なエディション

必要なユーザー権限
ページレイアウトを作成および編集する 「アプリケーションのカスタマイズ」
ページレイアウトを割り当てる 「ユーザーの管理」

古いページレイアウトを変換することで、高度なページレイアウトエディターを使用してページレイアウトを管理し、ケースフィードをより簡単にユーザーに割り当てることができます。ケースフィードユーザーのページレイアウトは、Spring '14 より前に作成された組織でのみ使用できます。

フィードベースのケースレイアウトには、ケースフィードユーザーのページレイアウトと同じ機能、つまり、フィード (アクションを含むパブリッシャー、フィード条件、記事ツールなどのツール、カスタムボタンやリンクなどのサイドバーコンポーネントを含む)、強調表示パネル、詳細ページ (関連リストとケースに関するその他の詳細な情報を含む) が含まれます。標準ページレイアウト割り当てツールを使用して、フィードベースのケースページレイアウトをユーザーに割り当てることができます。ユーザーにケースフィードへのアクセス権を付与するために、権限セットやカスタムプロファイルを使用する必要がなくなります。

ケースフィードユーザーのページレイアウトをフィードベースのケースレイアウトに変換する手順は、次のとおりです。

  1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. [ケースフィードユーザーのページレイアウト] リストのレイアウトの横にある [] をクリックし、[ケースページレイアウトに変換] を選択します。
    元のレイアウトを削除する前に変換されたレイアウトを確認できるように、このオプションを使用することをお勧めします。ただし、時間を節約する場合は、[ページレイアウトに変換して削除] を選択できます。
  3. 変換されたレイアウトが [変換済み:] というプレフィックス付きで [ケースページレイアウト] リストに表示されます。その横にある [編集] をクリックします。
  4. ページレイアウトエディターで、必要な要素がレイアウトに含まれていることを確認します。フィード条件やサイドバーコンポーネントなど、フィードビューに含まれている要素を表示して編集するには、[フィードビュー] をクリックします。
  5. ケースページレイアウトに問題がなければ、[ケースページレイアウト] リストで [ページレイアウトの割り当て] をクリックして、該当するユーザープロファイルに割り当てます。
    メモ 「ケースフィードを使用」権限を持つカスタムプロファイル、または「ケースフィードを使用」を含む権限セットを持つプロファイルの場合、これらのページ割り当ては、権限または権限セットを削除するまで有効になりません。Winter '14 から Spring '14 までの間に作成された組織の場合、標準プロファイルから [ケースフィードを使用] を削除できないため、これらの割り当ては、ケースフィードユーザーのページレイアウトをすべて削除するまで有効になりません。
  6. [ケースフィードユーザーのページレイアウト] リストで古いバージョンのレイアウトの横にある [] をクリックし、[削除] を選択します。確認が表示されたら、[OK] をクリックします。
  7. 削除するレイアウトにユーザーが割り当てられている場合、置き換えとして別のレイアウトを選択するように要求されます。このプロンプトは形式的なもので、ユーザーをケースページレイアウトに割り当てれば、ユーザーにはそのレイアウトが表示されます。

ケースフィードユーザーのレイアウトが複数ある場合、それらすべてを同時に変換して削除することをお勧めします。最後の古いレイアウトを削除すると、[ケースフィードユーザーのページレイアウト] リストが表示されなくなります。

ケースフィードの強調表示パネルのカスタマイズ

強調表示パネルはフィードの詳細ビューの最上部に表示されます。このパネルには、ケースに関する最も重要な情報が表示されます。

必要なエディション

必要なユーザー権限
ページレイアウトを作成および編集する 「アプリケーションのカスタマイズ」
ページレイアウトを割り当てる 「ユーザーの管理」

強調表示パネルを編集して、担当者にとって最も重要な項目を含めます。

  1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. [ケースフィードユーザーのページレイアウト] で、レイアウトの横にある [] をクリックし、[詳細ビューを編集] を選択します。
  3. 強調表示パネルにマウスポインターを置くと、 アイコンが表示されるのでクリックします。
  4. [強調表示パネルのプロパティ] ページで、編集する項目のボックスをクリックします。
  5. ドロップダウンリストを使用して、各項目に含める情報の種別を選択します。項目を空白のままにしておく場合は、[なし] を選択します。[ケース番号] と [作成日] は、移動および削除はできません。
  6. [OK] をクリックします。

高度なページレイアウトエディターを使用したケースフィードパブリッシャーの設定

組織でパブリッシャーのアクション機能を使用している場合、高度なページレイアウトエディターを使用してケースフィードパブリッシャーに表示されるアクションを選択できます。

必要なエディション

必要なユーザー権限
ケースフィードパブリッシャーを設定する 「アプリケーションのカスタマイズ」

ケースフィードを使用する新しい Salesforce 組織および Summer' 13 リリース後にケースフィードを有効化する組織については、デフォルトでこのオプションが選択されます。

  1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. [ケースフィードの設定] ページへのアクセス方法は、使用しているページレイアウトの種類に応じて異なります。
    • [ケースページレイアウト] セクションのレイアウトの場合、[編集] をクリックし、ページレイアウトエディターで [フィードビュー] をクリックします。
    • [ケースフィードユーザーのページレイアウト] セクションのレイアウトの場合、 をクリックし、[フィードビューを編集] を選択します。(このセクションは、Spring '14 より前に作成された組織にのみ表示されます)。
  3. [ページレイアウトエディターを使用してアクションを設定] を選択します。
  4. [保存] をクリックします。
  5. ページレイアウトエディターにアクセスする手順は、次のとおりです。
    • [ケースページレイアウト] セクションのレイアウトの場合、[編集] をクリックします。
    • [ケースフィードユーザーのページレイアウト] セクションのレイアウトの場合、 をクリックし、[詳細ビューを編集] を選択します。(このセクションは、Spring '14 より前に作成された組織にのみ表示されます)。
  6. ページレイアウトエディターの [Salesforce Classic のパブリッシャーのクイックアクション] セクションで、レンチアイコンをクリックします。
  7. パレットで、[クイックアクション] をクリックします。
  8. 必要なアクションを [Salesforce Classic のパブリッシャーのクイックアクション] セクションにドラッグします。アクションをドラッグして表示される順序を変更したり、必要のないアクションをセクション外にドラッグして削除したりできます。
    メモ ケースフィードページのパブリッシャーに表示されるアクションは約 5 ～ 6 個で、残りは [さらに表示] ドロップダウンリストに含まれます。
  9. [保存] をクリックします。

従来の [ケースフィードの設定] ページを使用したパブリッシャーの設定と、高度なページレイアウトエディターに切り替えた後には次の違いがあります。

  • アクションリストがパブリッシャーの上部に表示されます。パブリッシャーの左にアクションリストを表示することはできません。
  • [顧客への回答] アクションは、[メール] と [ポータル] という 2 種類のコンポーネントアクションに分けられます。
  • アクションリストの外観が、他のページの Chatter パブリッシャーに近くなります。
  • [ケースのメモを記入] アクションの代わりに、標準 Chatter アクション ([投稿]、[ファイル]、[リンク]、[アンケート]、[質問]、[感謝]) が自動的にパブリッシャーレイアウトに表示されます。これらのアクションの順序は変更でき、不要なものは削除できます。
  • [ケースの詳細を参照] アクションの代わりに [フィードビュー/詳細] ドロップダウンリストが表示されます。
  • ケースフィードパブリッシャーに過去に追加したカスタムアクションは使用できません。カスタムアクションを作成して、パブリッシャーに追加してください。これらの新しいアクションでは、interaction.js ではなく publisher.js を使用する必要があります。
  • ケースの詳細ページが最大幅まで拡大され、すべての関連リストとその他の情報が見やすくなります。

ケースフィードへの添付ファイルコンポーネントの追加

ケースフィードページに添付ファイルコンポーネントを追加して、営業担当がケースに関連付けられたすべてのファイルをすばやく表示して管理できるようにします。

必要なエディション

必要なユーザー権限
ページレイアウトを作成および編集する 「アプリケーションのカスタマイズ」
ページレイアウトを割り当てる 「ユーザーの管理」

サービス担当者が顧客をサポートする場合、ケースに関連付けられたすべてのファイルへのアクセスは重要です。添付ファイル コンポーネントを使用すると、営業担当はケースのすべての Chatter ファイル、メールからの添付ファイル、ケースのケース添付ファイル関連リスト ファイルをすべてケース フィード ページで表示および管理できます。添付ファイルコンポーネントを使用すると、営業担当はメールにすばやくファイルを添付してファイルをダウンロードできます。

営業担当は、すべてのソースのケースの最新添付ファイルの表示と、ケースに関連付けられたすべてのファイルの作成日で並び替えた表示を切り替えることができます。

  1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. [ケースフィードの設定] ページへのアクセス方法は、使用しているページレイアウトの種類に応じて異なります。
    • [ケースページレイアウト] セクションのレイアウトの場合、[編集] をクリックし、ページレイアウトエディターで [フィードビュー] をクリックします。
    • [ケースフィードユーザーのページレイアウト] セクションのレイアウトの場合、 をクリックし、[フィードビューを編集] を選択します。(このセクションは、Spring '14 より前に作成された組織にのみ表示されます)。
  3. [その他のツールおよびコンポーネント] セクションで、[ファイル] を選択し、ページのどこに表示するかを指定します。
  4. [保存] をクリックします。

Visualforce ページに添付コンポーネントを含めてカスタムページに添付コンポーネントを追加するか、<support:caseUnifiedFiles>コンポーネントを Salesforce コンソールコンポーネントとして追加して、サポート担当者がケースフィードページでスペースを取らずに使用できるようにします。

ケースフィードへのケースのエキスパートコンポーネントの追加

ケーストピックのエキスパートを簡単に特定して、サービス担当者が協力して顧客の問題を迅速に解決できるようにします。

必要なエディション

必要なユーザー権限

ケースのトピックの機能を使用して、サービス担当を特定のトピックのエキスパートとして推薦できます。エキスパートとして推薦された営業担当は、そのトピックに関する知識が少ない他の営業担当を助けることができます。組織でケースのエキスパートを選定するには、Chatter とケースに関するトピックを有効にする必要があります。

ケースのエキスパートを有効にするには、ケースフィードにエキスパートコンポーネントを表示します。

  1. ケースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. [ケースフィードの設定] ページへのアクセス方法は、使用しているページレイアウトの種類に応じて異なります。

Salesforce Classic での顧客へのメール送信

Salesforce Classic でケースフィードのメールを操作します。

必要なエディション

サポートされているエディションを表示する。
  • Salesforce Classic のケースメールの操作
    メール-to-ケースまたはオンデマンドメール-to-ケースを使用して生成されたケースが、[メール関連リスト] に表示されます。[メール] 関連リストには、お客様とお客様の顧客との間のメールスレッドのほか、顧客が送信した特定のケースに関するすべてのメールが表示されます。メールメッセージの最初の 77 文字が関連リストに表示されるため、メールをクリックしなくても、メッセージの内容を確認できます。
  • Salesforce Classic ケースフィードのメールの送信およびメールへの返信
    ケースフィードの [メール] アクションの機能を使用して、メッセージの作成時間を節約したり、顧客に送信するメールをカスタマイズしたりします。
  • Salesforce Classic ケースフィードでのメールへの画像とファイルの添付
    メールメッセージにファイルを添付し、インライン画像を追加して画像でテキストを拡張することで、ユーザーに包括的な情報を提供し、問題をより迅速に解決できるようにします。
  • Salesforce Classic ケースフィードのメールテンプレートの使用
    テンプレートを使用すると、一貫性を保ち時間を節約しながら、顧客名、ケース番号などの基本情報をすべてワンクリックで挿入できます。システム管理者がテキスト、HTML、または Visualforce のメールテンプレートを作成した場合、または独自のテンプレートを作成した場合、ケースフィードで顧客にメールするときに使用できます。
  • Salesforce Classic ケースフィードのドラフトメールの使用
    ドラフトメールを使用すると、サポート担当は顧客に作成したメッセージをすぐに送信せずに保存でき、システム管理者はメールメッセージの承認プロセスを作成できます。
  • Salesforce Classic ケースフィードのメールドラフトの確認と承認
    システム管理者が組織のドラフトメールと承認プロセスをどのように設定しているかに応じて、監視するサポート担当者が作成したメッセージを顧客に送信する前に確認および承認する必要があります。
  • Salesforce Classic ケースフィードのリッチテキストエディターを使用したメールのカスタマイズ
    リッチテキストエディターでは、顧客に送信するメールをカスタマイズできます。リッチテキストエディターを使用して、テキストの書式を設定したり、箇条書きや番号付き箇条書きを追加したり、画像やリンクを追加したりします。

カスタマーポータルまたは Experience Cloud サイトのケースに投稿する

  1. ケースフィードページの [顧客への回答] をクリックします。
  2. をクリックして、[コミュニティ] を選択します。

  • リッチテキストエディターは、[メール] アクションにのみ使用できます。
  • エディターに HTML など他の種類のマークアップを入力しても、メッセージを送信するときに表示されません。
  • メッセージを削除するには、 をクリックします。

ケースの [メールを送信] アクションの考慮事項

ケースの [メールを送信] アクションを使用する前に、次の制限に注意してください。

必要なエディション

サポートされているエディションを表示する。

Spring '17 以降、Lightning メールコンポーザーは、新しい [メールを送信] アクションに置き換わりました。

古い [メールを送信] アクションは、エンドユーザーに表示されなくなりました。既存のページレイアウトには残っていますが、ページレイアウトエディターパレットにはありません。このアクションをページレイアウトから削除すると、追加し直すことができません。

ヒント 新しい [メールを送信] アクションと古い [メールを送信] アクションの違いはどこにあるのでしょうか?ページレイアウトエディターパレットの [メールを送信] アクションにマウスポインターを置きます。新しいアクションは [アクション種別] が [クイックアクション] になっています。

一般情報

  • [メールを送信] アクションでは、カスタム項目を追加したり、既存の項目の名前を変更したりすることはできません。
  • [送信者] 項目は必須です。

    [送信者] 項目が [メールを送信] アクションレイアウトにない場合は、定義済みの値セットが必要です。

  • 本文は HTML 形式である必要があります。テキスト形式はケース固有の [メールを送信] アクションでのみサポートされています。

    [HTML 内容] 項目が [メールを送信] アクションレイアウトにない場合は、定義済みの値セットが必要です。

  • Salesforce Inbox では、組織共有のメールアドレスを使用できません。
  • Experience Cloud サイト内のカスタマーコミュニティユーザーは、メールを送信できません。
  • グローバルの [メールを送信] アクションでは、[関連先] 項目を [ケース] に設定できません。
  • 活動コンポーザーに [メール] タブを表示するには、[メール送信] を [すべてのメール] に設定します。
  • ケースフィードのメールごとに、サポート担当者に返信オプションを含むドロップダウンメニューが表示されます。ケースフィードパブリッシャーに複数のメールアクションがある場合、サポート担当者のドロップダウンメニューに返信アクションのグループが表示されます。
  • メールの返信では、元のメールの本文 (引用符で囲まれた内容) の差し込み項目が自動的に変更され、括弧内にスペースが含まれます。このセキュリティ対策により、差し込み項目が項目値に解決されなくなります。

ケース

  • ケースでケース固有の [メールを送信] アクションを有効にするには、メール-to-ケースを有効にします。
  • ケースに追加できるのはケース固有の [メールを送信] アクションのみです。
  • [返信] メールアクションと [全員に返信] メールアクションを機能させるには、フィードで [メールコンポーザー] タブを選択する必要があります。
  • ケースに関連するメールを [グローバルアクション] メニューから送信することはできません。

定義済みの値

  • [宛先アドレス]、[CC アドレス]、[BCC アドレス] の各項目では、定義済みの値としてメールアドレスのみを使用できます。文字列項目 (例: Contact.custom_email_field) を使用します。
    メモ 指定されたメールアドレスのみを使用して送信されたメールは、Salesforce レコードに関連付けられていません。
  • [宛先受信者]、[CC 受信者]、[BCC 受信者] の各項目は、JUNCTIONIDLIST 関数を使用して Salesforce ID のリストに関連付けることができます。ID 項目 (例: Contact.Id) を使用します。

    これらの定義済み項目を使用して送信されたメールでは、メールが Salesforce レコードに関連付けられます。たとえば、ケースの取引先責任者レコードなどです。[宛先受信者]、[CC 受信者]、および [BCC 受信者] 項目を使用して、メールを複数の取引先責任者やユーザーに送信できます。これらの項目は、ケースの [メール] アクションでのみ機能します。

  • メールコンポーザータブをクリックすると、[全員に返信] は [作成日] 項目に基づいてケースの最新メールに返信します。
  • メールコンポーザータブをクリックすると、現在のケースの最新メールに [すべて返信] します。
  • メールコンポーザータブをクリックするか、特定のメールで [すべて返信] をクリックすると、Salesforce によって [CC] 項目が入力されます。

    受信メッセージに返信する場合、CC 項目はそのメッセージの [宛先(To)] 値と [CC] 値に基づきます。CC 項目は、これには、メール-to-ケースルーティングアドレスや組織の共有アドレスは含まれません。アウトバウンド メッセージに返信する場合、そのアウトバウンド メッセージに CC 項目がある場合にのみ CC 項目が入力されます。

    カスタムコードを使用して新しい [メールを送信] アクションを使用する場合は、アクション種別のデフォルトは [全員に返信] になります。つまり、CC フィールドは事前入力されます。

    • 返信として処理するには、[メールを送信] クイックアクションで CC アドレスを null として事前定義します。これは、そのクイックアクションのすべての使用に影響します。または、API 使用事例専用のカスタム SendEmail クイックアクションを作成し、[CC Address (CC アドレス)] 定義済み値を null に設定することを検討してください。

  • これらの動作は、[全員に返信] アクションにのみ適用され、[返信] には適用されません。

  • [関連先] はエンティティ固有のクイックアクションのみに事前に定義でき、グローバルクイックアクションには事前に定義できません。

  • [宛先受信者] 項目、[CC 受信者] 項目、[BCC 受信者] 項目の定義済み項目値は、最初のメールでのみ入力されます。返信メールや転送メールの場合、これらの項目は事前入力されません。

  • 定義済みの値は、アシスタントまたは商談インサイトから始めたメールではサポートされていません。
  • コンプライアンス BCC が有効である場合、[BCC] 項目の定義済みの値は無視されます。自動 BCC が有効である場合、[BCC] 項目の定義済みの値は自動 BCC アドレスに追加されます。
  • システム管理者によってレイアウトから [BCC] 項目が削除された場合、自動 BCC はユーザーのメールアドレスをメールに入力しません。
  • システム管理者の設定が自動 BCC よりも優先されます。システム管理者が事前定義された BCC 値を指定している場合は、自動 BCC のメールアドレスではなく、事前定義された値がメールに入力されます。

ケースの [メールを送信] クイックアクションの作成

[メールを送信] クイックアクションを作成して、サポート担当者が Lightning Experience および Salesforce モバイルアプリケーションでケースフィードからメールを送信できるようにします。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限

ケースオブジェクトで [メールを送信] クイックアクションを使用するには、メール-to-ケースを有効にしておく必要があります。

新規組織でメール-to-ケースを有効にすると、デフォルトで [メールを送信] クイックアクションが作成されます。組織が Spring '17 より前に作成されたか、Spring '17 より前にメール-to-ケースを有効にした場合は、[メールを送信] クイックアクションを作成します。

  1. [メールを送信] クイックアクションを作成します。
    1. [設定] から、[オブジェクトマネージャー] タブをクリックします。[ケース] を選択して、[ボタン、リンク、およびアクション] 設定ページを開きます。
    2. [新規アクション] をクリックします。
    3. [アクション種別] に、[メールを送信] を選択します。
    4. [標準の表示ラベル種別] 項目で、このアクションの表示ラベルを選択します。アクションをケースページレイアウトに追加すると、この表示ラベルがアクションバーに表示されます。
    5. [名前] 項目は自動入力されます。この名前は API と管理パッケージで使用されます。先頭は英字にする、英数字文字とアンダースコアのみを使用する、末尾をアンダースコアにしない、アンダースコアを 2 つ続けないという制約があります。API の使用に習熟している場合を除き、この項目は編集しないことをお勧めします。
    6. [説明] 項目で、このアクションの機能を説明します。説明は、アクションの詳細ページと、[ボタン、リンク、およびアクション] ページのリストに表示されます。説明はユーザーに表示されません。同じオブジェクトに対して複数のアクションを作成する場合、詳細な説明を使用することをお勧めします。
    7. [保存] をクリックします。
      メモ メールレイアウトページが開き、メールアクションに表示される項目を指定できます。
  2. 必要に応じてメール項目の順序を並び替えます。サポート担当者がクイックアクションを選択すると、メール項目は次の順序で表示されます。
    1. [メールメッセージ 項目] メニューから、項目をメールレイアウトにドラッグします。項目を削除するには、メールレイアウトから [メールメッセージ項目] セクションにドラッグします。
      メモ [宛先アドレス], [差出人] 選択リスト、[件名]、および [HTML 内容] 項目はデフォルトで追加されます。
    2. 項目を参照のみまたは必須にするには、項目にマウスポインターを置いて をクリックし、項目プロパティを指定します。
    3. 項目プロパティを保存するには、[OK] をクリックします。
    4. [保存] をクリックします。
  3. メールを Salesforce レコードに関連付けるには、[宛先受信者]、[CC 受信者]、および [BCC 受信者] 項目の定義済み項目値を作成します。
    重要 新規組織では、メール-to-ケースを有効にすると [宛先受信者] に自動的に定義済み項目値が設定されるため、この手順をスキップできます。

    ただし、組織が Winter '18 より前に作成されたか、Winter '18 より前にメール-to-ケースを有効にした場合は、次の手順を実行して、定義済み項目値を作成します。[宛先受信者] 項目の値を定義することをお勧めします。

    ケースメールアクションによって [宛先] 項目の定義済み項目値 (ケース取引先責任者のメールアドレス) が入力されます。この定義済みデータ型はテキスト (ケース取引先責任者にリンクされていないプレーンメールアドレス) であるため、メールは Salesforce ケース取引先責任者レコードに関連付けられません。デフォルト環境を変更して、メールを Salesforce レコードに関連付けるには、定義済み項目値を作成する必要があります。

    [宛先受信者] 項目、[CC 受信者] 項目、[BCC 受信者] 項目の定義済み項目値は、最初のメールでのみ入力されます。返信メールや転送メールの場合、これらの項目は事前入力されません。

    1. [Predefined Field Values (定義済み項目値)] セクションで、[New (新規)] をクリックします。
    2. [項目名] には、次のいずれかの項目を選択します。
      • 宛先受信者
      • CC 受信者
      • BCC 受信者
    3. 数式エディターで JUNCTIONIDLIST 関数を使用して、選択した項目を Salesforce レコードに関連付けます。
      メモ 1 つの ID のみの値の場合、JUNCTIONIDLIST 関数を使用する必要はありません。次に例を示します。
      • [宛先受信者] 項目をケースの取引先責任者レコードに関連付けるには、次のように入力します。

        JUNCTIONIDLIST(Case.ContactId) または Case.ContactId

      • [BCC 受信者] 項目をケースの所有者と所有者のマネージャーに関連付けるには、次のように入力します。

        JUNCTIONIDLIST(Case.OwnerId, Case.Owner:User.ManagerId)

    1. [保存] をクリックします。

    5. 必要に応じて、[テンプレートの件名を適用しない] を選択してメールテンプレートの件名を無視します。
      デフォルトでは、[メールを送信] クイックアクションは、デフォルトメールテンプレートで指定された件名を適用します。たとえば、テンプレートの件名行が「Thanks for your email」の場合、サポート担当者がメールアクションを使用してメールを作成するときにその件名が適用されます。[テンプレートの件名を適用しない] が選択されている場合、メールテンプレートに定義されている件名はメールに適用されません。
      返信する際に、デフォルトのテンプレートを使用して、顧客の件名行をそのまま残すには、[返信] を選択してドラフトを破棄します。[テンプレートの件名を適用しない] が選択されている場合、テンプレートの件名は適用されません。たとえば、顧客が「Please help」という件名のメールを送信すると、サポート担当はドラフト返信を破棄してメールテンプレートを使用し、顧客の件名行を保持します。
    6. アクションの表示ラベルを指定します。デフォルトの表示ラベルが入力される標準表示ラベル種別を使用するか、[標準の表示ラベル種別] 項目で「なし」を選択し、独自の表示ラベルを指定できます。アクションをケースページレイアウトに追加すると、この表示ラベルがアクションバーに表示されます。
    7. [名前] 項目は自動的に入力されます。この名前は API と管理パッケージで使用されます。先頭は英字にする、英数字文字とアンダースコアのみを使用する、末尾をアンダースコアにしない、アンダースコアを 2 つ続けないという制約があります。API の使用に習熟している場合を除き、この項目は編集しないことをお勧めします。
    8. [説明] 項目で、このアクションの機能を説明します。説明は、アクションの詳細ページと、[ボタン、リンク、およびアクション] ページのリストに表示されます。説明はユーザーに表示されません。同じオブジェクトに対して複数のアクションを作成する場合、「祝祭日用のブランドを設定したメールを顧客に送信」など、詳細な説明を使用することをお勧めします。
    9. [保存] をクリックします。
      メールレイアウトページが開き、メールアクションに表示される項目を指定できます。
  2. テンプレートに適切なメール本文項目があることを確認します。
    [HTML 内容] 項目はデフォルトで [メールを送信] クイックアクションに追加されます。[テキスト内容] 形式が必要であれば、使用できます。
  3. [保存] をクリックします。

ケースフィードの [メール] アクションは、組織でメール-to-ケースを使用していて [ケースフィードアクションおよびフィード項目を有効化] 設定が有効になっている場合にのみ使用できます。

メモ システム管理者によるケースフィードの設定方法によっては、スクリーンショットで説明するオプションの一部が使用できない、または異なって見える可能性があります。

[メール] アクションの使用方法は次のとおりです。

  1. ケースのフィードで、[メール] をクリックします。システム管理者によるケースフィードの設定方法によっては、スクリーンショットで説明するオプションの一部が使用できない、または異なって見える可能性があります。メッセージへの返信を作成するには、フィードのメールメッセージの下にある [返信] または [全員に返信] をクリックします。
  2. 所属部門でメールテンプレートを使用している場合、メッセージに対応するメールテンプレートを選択します。
  3. [差出人] アドレスを選択します。
    メモ この項目が選択リストとして表示されない場合、システム管理者がすでに送信元アドレスを定義しています。
  4. 作成者が既存の取引先責任者である場合、ケースを作成した取引先責任者のメールアドレスは [宛先] 項目に自動的に表示されます。受信者をさらに追加するには、 をクリックしてアドレスを検索するか、メールアドレスまたは名前を [宛先] 項目に入力または貼り付けます。
    • 入力したメールアドレスまたは名前が 1 人の取引先責任者またはユーザーに一致すると、そのアドレスは取引先責任者名の付いたボタンとして表示されます。
    • 一度に複数のアドレスを追加するには、スペースまたはカンマで区切った複数のアドレスをコピーして貼り付けます。これらのメールアドレスはボタンとして表示され、取引先責任者またはユーザーに関連付けられている場合は、取引先責任者の名前が表示されます。
    • 入力したメールアドレスが複数の取引先責任者またはユーザーに一致すると、そのアドレスはボタンとして表示されます。ボタンをクリックすると、そのメールアドレスに関連付けられているユーザーのリストが表示されます。メッセージに関連付ける取引先責任者またはユーザーを選択します。
  5. 他のユーザーにメッセージに送信する場合、[Cc を追加] または [Bcc を追加] をクリックします。
  6. デフォルトでは、メール件名は関連するケースの名前です。件名が含まれているメールテンプレートを適用する場合、テンプレートの件名が表示されます。件名は必要に応じて編集できます。
  7. リッチテキストエディターを使用して、メッセージを書式設定します。
  8. メッセージを作成します。所属部門でクイックテキストメッセージを使用している場合、「;;」と入力して挿入します。
  9. システム管理者がメールドラフトを有効化している場合、[保存] をクリックすると、メッセージを送信することなくそのメッセージのコピーを保存できます。メッセージをドラフトとして保存すると、ケースへのアクセス権を持つすべてのサポート担当者が編集できます。
  10. ファイルをメッセージに追加するには、[ファイル添付] をクリックするか、ファイルを添付ファイルペインにドラッグします。
  11. 必要に応じて、メッセージに記事を添付します。
  12. [メールを送信] をクリックします。
    メモ システム管理者によるケースフィードの設定方法によっては、このボタン名が異なる場合があります。

メッセージペインの高さを変更するには、右下隅で をクリックしてドラッグします。拡大すると、作成している内容の詳細を確認できます。縮小すると、スクロールせずにフィードにより多くのケース履歴を表示できます。メッセージペインのサイズを変更すると、再度サイズを変更するまで、メールを作成するときは常にその新しいサイズで表示されます。

前提条件と基本設定

ケースフィードを有効にしてカスタマイズする前に、必要なアクションとツールを決定します。[メール] アクションを使用するには、メール-to-ケースを設定します。記事ツールを使用するには、Salesforce Knowledge を設定します。

準備ができたら、ケースフィードアクションとフィード項目を有効にします。

メモ Winter '14 より前に作成された組織では、次の操作も必要です。
  • パブリッシャーの Chatter およびアクションを有効化します。
  • ケースのフィード追跡を有効化します。フィード追跡ページで、[状況] 項目の追跡をオフにします。[状況] 項目の追跡を無効にすると、サービス担当者が [状況の変更] アクションを使用してケースの状況を更新するときにフィード項目の重複が回避されます。

  • ケースの詳細ページ、クローズケースページ、強調表示パネルのレイアウトを作成します。
  • フィードビューページのレイアウトを作成して、サービス担当者がケースを操作するときに表示されるアクション、項目、ツールを指定します。

ユーザーにケースフィードへのアクセス権を付与する最も簡単な方法は、作成したフィードベースのケースページレイアウトを使用するプロファイルにユーザーを割り当てることです。

Spring '14 より前に作成された組織では、権限セットを作成してユーザーに割り当てるか、カスタムプロファイルを使用して、ユーザーにアクセス権を付与することもできます。

ケースフィードの設定: その他の機能の追加

ケースフィードに機能を追加するには、次の省略可能な手順に従います。

  • サービス担当者がメールに事前作成済みの短いメッセージを含めることができるようにするには、クイックテキストを設定してクイックテキストメッセージを作成します。
  • ポータルに投稿した質問に回答があったときに顧客にメールで通知するオプションをサービス担当者が使用できるようにするには、ポータルメール通知を有効にします。
  • サービス担当者が送信前にメールメッセージをドラフトとして保存できるようにし、メールの承認アクションを作成できるようにするには、メールドラフトを有効にします。
  • サービス担当者が顧客にメールを送信するときの時間を節約し、一貫性を高めるには、テキスト、HTML、または Visualforce メールテンプレートを作成します。
  • サービス担当者が反復作業を自動化できるようにするには、コンソールにマクロブラウザーを追加し、サービス担当者にマクロを使用する権限を付与します。
  • サービス担当者がより多くの機能にアクセスできるようにするには、カスタムアクションを作成して追加します。
  • Salesforce Classic でのケースフィードのアップグレード結果
    組織のケースフィードを有効にすると、アップグレードプロセスにより、アクティブなケースが新しいインターフェースに変換され、それらのケースの活動に対応するフィード項目が作成されます。
  • Salesforce Classic でのケースフィードアクションおよびフィード項目の有効化
    ケースフィードアクションとフィード項目を有効化すると、ケースを使用するときに必要な一部の標準アクション ([メール] や [状況の変更] など) とそれらのアクションに関連するフィード項目へのアクセス権がユーザーに付与されます。
  • Salesforce Classic のケースフィードページレイアウト
    サービス担当者がケースフィードでケースを操作する場合、ケースページレイアウトを使用します。担当者がオープンケースを操作するときに表示される項目、ツール、機能を指定するには、ケースページのフィードビュー、詳細ビュー、強調表示パネルをカスタマイズします。
  • Salesforce Classic でのケースフィードへの機能の追加
    Salesforce Classic のケースフィードをサポート担当者のニーズに合わせてカスタマイズします。エージェントがクイックテキストのような生産性ツールにアクセスすることや、さらにはメールドラフトや承認プロセスを有効化することができるようにします。

Salesforce Classic でのケースフィードのアップグレード結果

組織のケースフィードを有効にすると、アップグレードプロセスにより、アクティブなケースが新しいインターフェースに変換され、それらのケースの活動に対応するフィード項目が作成されます。

必要なエディション

サポートされているエディションを表示する。

アップグレードプロセス中、ユーザーが何か変わったことに気づくことはありません。プロセスが完了すると、ケースフィードを有効にしたユーザーには、既存のケースも新しいケースも新しいインターフェースで表示されますが、ケースフィードを有効にしていないユーザーには、引き続き従来のケースが表示されます。

ケースが新しいインターフェースにアップグレードされると、次の処理が行われます。

  • 組織のアクティブな最新の 5000 件のケースが、ケースフィードインターフェースに変換される。ケースの変換プロセスは、変換されるケースの数と、ケースに含まれるデータの複雑さに応じて異なります。たとえば、複数のメールメッセージやその他の添付ファイルを含むケースは、変換にかかる時間が他のケースよりも長くなる場合があります。
  • 古いケースも、元の 5000 件の変換されたケースに適用される日付範囲内に、そのケースに追加されたコメント、メール、または活動ログがある場合は、アップグレードされる。現在のコメントが設定されたケース、現在のメールが設定されたケース、現在の活動ログが設定されたケースが、それぞれ最大 500 件の合計 1500 件までのケースが追加で変換されます。
  • 次の項目が、各ケースのフィードに追加される。
    • 最大 60 件のメールメッセージ。
    • 最大 60 件の非公開コメントと公開コメント。アップグレード中に、コメントは Chatter 投稿に変換されます。
    • 最大 60 件の活動ログ。ケースフィードにアップグレードする前に作成された活動ログは、ToDo としてフィードに表示される場合があります。
  • ケースフィードインターフェースはすべての新規ケースに対して有効化され、ユーザーにはパブリッシャーとフィードへのアクセス権が付与される。
  • ケースの詳細ビューが使用可能になり、現在の関連リスト内に表示されている項目も含めて、ケースの追加情報が示される。

アップグレードプロセスが完了すると、メールメッセージで通知されます。

ベストプラクティス

  • アップグレード操作を円滑に進めるために、ケースフィードを本番組織で有効にする前に、フルコピーの Sandbox 組織で有効にすることをお勧めします。フルコピーの Sandbox 組織でケースフィードを有効にすると、ケース変換プロセスにかかる時間を見極め、新しいユーザーインターフェースでいくつかサンプルケースをレビューできます。
  • 本番組織でケースフィードを有効化したら、アップグレードプロセスが完了するまで待ってからユーザーにアクセス権を与えます。最初は、ケースフィードを 1 人のユーザーに割り当て、変換されたケースをいくつかレビューしてアップグレードプロセスが成功したことを確認してから、他のユーザーが利用できるようにすることをお勧めします。

さまざまなレコードタイプに対してクローズケースアクションを作成できます。

  1. [設定] のオブジェクトマネージャーで [ケース] を検索し、[ケース] を選択します。
  2. [ケース] で [ボタン、リンク、アクション] を選択し、[新規アクション] を選択します。
  3. [新規アクション] ウィンドウで、[アクション種別] で [レコードを更新] を選択します。
  4. [標準の表示ラベル種別] で [ケースのクローズ] を選択します。

メモ

  • [ケースのクローズ] ページレイアウトは、Salesforce Classic と Lightning Experience で異なります。Salesforce Classic では、標準のレイアウトであるケースクローズページレイアウトが使用されます。Lightning Experience では、クイックアクションページレイアウトが使用されます。

  • Lightning Experience では、ケースのクローズ後にケースの取引先責任者にメールで通知することはできません。

  • Lightning Experience では、ケースクローズアクションの API 参照名は CloseCaseLightning で、編集可能です。API 参照名を CloseCaseLightning 以外に変更すると、[ケースをクローズ] アクションがカスタムクイックアクションになります。[ケースのクローズ] ページには、すべての選択リスト値が表示されます。

  • Lighting Experience では、[ケースクローズ] アクションを削除できます。API 参照名 CloseCaseLightning で新しいカスタムアクションを作成して、再作成できます。

  • Salesforce Classic では、[ケースをクローズ] クイックアクションはサポートされていません。クイックアクションページレイアウトで使用できますが、お勧めしません。

  • [関連レコード] コンポーネントでは、[ケースをクローズ] クイックアクションはサポートされません。

  • 標準のケースクローズアクションと同様に、すべてのケースクローズクイックアクションが強調表示パネルに表示されます。
  • クローズケースアクションに CloseCaseLighting API 参照名を使用すると、選択リスト値が上書きされます。選択リストには、クローズ動作の状況のみが表示されます。

ケースの割り当て

さまざまな方法でユーザーまたはキューにケースを割り当てることができます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
ケースを参照する ケースに対する「参照」
取引先に関連するケースの所有権を移行する 関連取引先に対する「参照」および「割り当て」
キューからケースの所有権を取得する ケースに対する「編集」
  • Web-to-ケース、メール-to-ケース用割り当てルール、またはオンデマンドメール-to-ケースを使用

    Professional Edition、Enterprise Edition、Unlimited Edition、Performance Edition、および Developer Edition の組織では、Web およびメールで生成されたケースは有効なケース割り当てルールの条件に基づいて、ユーザーまたはキューに自動的に割り当てられます。

    割り当てルールの条件に一致しないケースは、サポートの設定で指定されている [デフォルトのケース所有者] に自動的に割り当てられます。

  • ケースの作成または編集時に割り当てルールを使用

    Professional Edition、Enterprise Edition、Unlimited Edition、Performance Edition、および Developer Edition の組織では、ケースを作成または編集するときに、有効なケース割り当てルールを使用して、ケースを自動的に割り当てることができます。ルール項目に一致したときのメールテンプレートがシステム管理者によって指定されている場合、新しい所有者にメールが自動的に送信されます。このチェックボックスをデフォルトでオンにする場合は、ユーザーのシステム管理者が適切なページレイアウトを変更できます。必要に応じて、システム管理者はページレイアウトを編集して割り当てチェックボックスを非表示にできますが、ケース割り当てルールは引き続き適用できます。

  • 複数ケースの所有権の変更 (システム管理者専用)

    システム管理者、または「ケースの管理」権限を持つユーザーは、1 つ以上のケースをユーザーまたはキューに手動で割り当てることができます。また、ケースが取引先に関連する場合、システム管理者またはユーザーには取引先に対する「参照」および「割り当て」権限が必要です。

  • キューからのケースの取得

    キューにあるケースの所有権を取得するには、キューのリストビューを表示し、1 つ以上のケースの横にあるチェックボックスをオンにして、[承認] をクリックします。

    メモ オブジェクトに対する組織の共有モデルによって、ユーザーがキュー内のそのオブジェクトのレコードに対して持つアクセス権が決まります。
    公開/参照・更新・所有権の移行
    ユーザーは、任意のキューのレコードの所有権を参照し、また、その所有権を得ることができます。
    公開/参照・更新可能または公開/参照のみ
    ユーザーは任意のキューを参照できますが、レコードの所有権が得られるのはユーザーがそのキューのメンバーである場合、または、共有設定に従って、ロール階層またはテリトリー階層でキューメンバーより上位にある場合に限られます。
    非公開
    ユーザーがキューからレコードを参照および引き受けできるのは、ユーザーがそのキューのメンバーである場合、または、共有設定に従って、ロール階層またはテリトリー階層でキューメンバーより上位にある場合に限られます。
    共有モデルに関係なく、ユーザーが自分がメンバーであるキューからレコード所有権を取得するには、「編集」権限を持っている必要があります。Salesforce システム管理者、ケースまたはリードに対してオブジェクトレベルの「すべてのレコードの編集」権限を持つユーザー、および「すべてのデータの編集」権限を持つユーザーは、キュー内のメンバーシップにかかわらず、任意のケースキューまたはリードキューのレコードを参照および取得できます。
  • 単一ケースの所有権の変更

    自分が所有する、または「参照・更新」権限を持っている 1 つのケースの所有権を移行するには、ケースの詳細ページの [ケース所有者] 項目の横にある [変更] をクリックし、ユーザー、パートナーユーザーキューを指定します。新しい所有者が、ケースに対する「参照」権限を持っていることを確認してください。[変更] リンクは詳細ページでのみ表示され、編集ページでは表示されません。

    Group Edition、Professional Edition、Enterprise Edition、Unlimited Edition、Performance Edition、および Developer Edition の組織では、[メールで通知する] チェックボックスをオンにすると、ケースの新しい所有者に自動的にメールが送信されます。

  • 手動によるケースの作成 (デフォルトの割り当て)

    割り当てルールチェックボックスが表示されており、それをオンにして割り当てルールを有効化しない限り、[ケース] タブでケースを作成すると、作成者が自動的にケース所有者として表示されます。チェックボックスがデフォルトでオンになっている場合は、オフにすることで割り当てルールを上書きし、作成者を所有者として割り当てることができます。

メモ レコードリストコンポーネント (ケースに対応付けられている場合) の上部にある [新規] ボタンを使用してケースが作成された場合は、エクスペリエンスビルダーサイトでケース割り当てルールを使用できます。[ケース作成フォーム]、[レコード作成ボタン]、または [カスタマーサポートおよび質問ボタン] コンポーネントを使用して作成されたエクスペリエンスビルダーサイトケースでは、ケース割り当てルールはサポートされません。

Partner Community ライセンスを持つユーザーをケースキューに割り当てることができます。

Experience Cloud の自動ケース割り当てルールの有効化

Experience Cloud サイトで作成されたすべてのレコードに対して、標準ケースルールと割り当てルールを自動的かつ一貫して実行します。自動割り当てにより、標準のルーティング機能を複製するための複雑なカスタムコードやフローが不要になるため、正確で拡張性の高いカスタマーサービスをすぐに提供できます。

必要なエディション

サポートされているエディションを表示する。
  • [設定] から、[クイック検索] ボックスに「ケース割り当てルール」と入力し、[ケース割り当てルール] を選択します。
  • [Apply case assignment rules to cases created via the Community Portal (コミュニティポータルを介して作成されたケースにケース割り当てルールを適用)] チェックボックスをオンにします。

この設定を有効にすると、Experience Cloud サイトメンバーとゲストユーザーが Experience Cloud コンポーネントを介して作成したケースに対して、標準ケース割り当てルールが自動的に実行されます。この機能は、大規模カスタマーポータルライセンスでは使用できません。これらのルールの実行は、メール-to-ケース、Web-to-ケース、または標準の Salesforce UI で作成されたケースと機能的に同じです。

Experience Cloud でのケース割り当てのトラブルシューティング

ケースが割り当てられなかった理由を理解し、動作が標準の Salesforce ルーティングロジックと一致していることを確認します。

  • 組織設定状況の確認: 問い合わせフォームから作成されたケースに対してケースを自動的に割り当てる組織設定が有効になっていることを確認します。この設定が無効になっている場合、ケースは標準ルーティングロジックをスキップします。
  • ルールの適用の一貫性を確認: Experience Cloud の割り当てルールの実行は、メール-to-ケースや標準の Salesforce UI などの標準メソッドと機能的に同じです。ケースが割り当てられていない場合は、標準割り当てルールで定義された特定のルール条件を満たしているかどうかを確認します。
  • 従来の回避策の特定: ルーティングの複製に以前使用されていた既存のカスタムコードまたはフローを確認します。新しい標準動作との競合を回避するために、次の回避策を段階的に実行します。
  • Review case origin (ケースの発生源の確認): Experience Cloud コンポーネントまたは問い合わせフォームを介してケースが作成されたことを確認します。自動トリガーは、次のプラットフォームの変更専用に実装されています。

実装が成功すると、Experience Cloud サイトから発生したケースの最初のエージェント割り当ての時間が短縮されます。

ケース共有設定のカスタマイズ

ケースの共有モデルによって、他のユーザーが所有するケースへのユーザーのアクセス権が決まります。ニーズに合った共有モデルを選択する前に、オプションを確認してください。

必要なエディション

サポートされているエディションを表示する。

最初に、ケースへのアクセスをどの程度制限するかを決定します。たとえば、ユーザーが所有していないケースを表示または更新できるようにしますか?次のいずれかの共有モデルを選択します。

  • 公開/参照・更新・移行: ユーザーは任意のレコードの所有権を表示、編集、移行できます。
  • 公開/参照・更新可能: ユーザーは所有者に関係なく、任意のレコードを表示および編集できますが、レコードの所有者を変更することはできません。
  • 公開/参照のみ: ユーザーは任意のレコードを表示できますが、自分が所有するレコードの編集のみが可能です。
  • 非公開: ケース所有者、そのマネージャー、管理者のみがケースを表示および編集できます。

共有モデルがケースキューに与える影響に注意してください。たとえば、非公開共有モデルでは、キューメンバーとその直属部下のみが、キューが所有するケースを表示または取得できます。「公開/参照・更新可能」または「公開/参照のみ」共有モデルでは、すべてのユーザーはキューが所有するレコードを表示できますが、その所有権を持つことができるのはキューメンバーのみです。

  1. [Setup (設定)] から、[Quick Find (クイック検索)] ボックスに「Sharing Settings (共有設定)」と入力し、[Sharing Settings (共有設定)] を選択します。
  2. [組織の共有設定] の横にある [編集] をクリックします。
  3. ケースオブジェクトの [デフォルトの内部アクセス権] の共有モデルを選択します。
  4. 変更内容を保存します。

ケースとは?

ケースは、顧客の質問、フィードバックまたは問題です。サービス担当者はケースを使用して顧客とやりとりし、問題の解決を追跡します。営業担当は、ケースを使用して営業プロセス中に問題を追跡できます。

必要なエディション

サポートされているエディションを表示する。

コミュニケーションチャネルでは、顧客が希望する連絡方式からケースが収集されます。チャネルには、オンラインフォーラムの Experience Cloud サイト、メールのメール-to-ケース、Web フォームの Web-to-ケース、電話の Salesforce Voice、WhatsApp のメッセージング、SMS、Facebook Messenger などがあります。

[ケース] タブで、ケースの作成、検索、編集に加え、標準およびカスタムリストビューを使用したケースとキューの並び替えや絞り込みもできます。

サポートチームは、Salesforce でケースを解決する 5 つの基本手順に従います。

  • 特定: ケースを持つ顧客を特定し、その顧客が受ける必要があるサポートのレベルを決定します。
  • レコード: 顧客の質問の内容や、どの製品またはバージョンに関心があるかなど、Salesforce でケースの詳細を取得します。サービスコンソールとそのダッシュボードのようなインターフェースを使用して、複数のケースに迅速に返答できます。
  • 解決: お客様の問題に対する回答を見つけます。必要に応じて、ケースにソリューションまたは記事を添付するか、新しい記事を作成します。
  • コミュニケーション: 希望するチャネルで顧客に応答します。
  • Close: ケースにすべての詳細が含まれていることを確認し、ケースをクローズします。

サービスプランテンプレートでのドラフトケースコメントアクションの使用

組織でケースコメント生成用の標準プロンプトテンプレートを設定して、サービス担当者がコメントを生成できるようにします。標準化されたコメント生成をチーム全体にリリースして、会社のコミュニケーション標準に準拠します。

必要なエディション

サポートされているエディションを表示する。
  • Agentforce 従業員エージェントが有効になっていることを確認します。
  • 従業員ケース管理のトピックが上記のAgentforce従業員エージェントに割り当てられていることを確認します。
  • 組織でサービスアシスタントが有効になっていることを確認します。より正確な結果を得るには、ケースのサービスプランを生成します。
  • このアクションは Agentforce 内の標準アクションとして定義されます。
  • エージェントユーザーにケースコメントオブジェクトに対する「作成」権限があることを確認します。
  • ケース ID を入力変数として確実に受信するようにアクションを設定し、コメントが正しいレコードに関連付けられるようにします。

必要なエディション

必要なユーザー権限

ケースの更新

  • 取引先責任者を変更するとき、取引先は、取引先責任者の取引先に更新されませんが、取引先を自分で編集することができます。
  • ポータルユーザーである取引先責任者には、取引先責任者レコードの取引先に関連付けられたケースのみが表示されます。
  • 取引先を変更すると、新しい取引先への参照アクセス権のないユーザーのケースの手動共有は削除されます。
  • サポート担当者がケースの詳細で [エスカレーション済み] を確認すると、件名の前に矢印アイコンが表示されます。このアイコンは強調表示パネル、リストビュー、コンパクトプレビューモーダルに表示されるため、サポート担当者はエスカレーション状況を一目で確認できます。
  • 権限が設定されている場合、[メールで取引先責任者に通知する] を選択すると、ケースを更新したことを取引先責任者に通知できます。メールは、その取引先責任者へのアクセス権がある場合にのみ送信されます。
  • 権限が設定されている場合、[有効な割り当てルールによりケースを割り当てる] を選択すると、割り当てルールを使用してケースを再割り当てできます。ケースがルール条件に一致しない場合、そのケースは組織のデフォルトのケース所有者に再割り当てされます。
  • 権限が設定されている場合、[共有] をクリックするとケースを他のユーザー、グループ、またはロールと共有できます。
  • 権限が設定されている場合、[状況] の下にある [クローズ済み] を選択してケースをクローズできます。または、[ケースのクローズ] をクリックし、必要に応じて項目を変更します。ナレッジ記事の送信が設定されている場合は、[記事の保存および作成] をクリックして他のユーザーが類似のケースをクローズするのに役立つ情報を保存できます。送信したドラフト記事が公開されると、ケースに添付されて知識ベースで利用可能になり、容易に参照できるようになります。
  • 権限が設定されている場合、[Web-to-Case 情報] セクションに、Web サイトのフォームからケースを作成した顧客が入力した情報が一覧表示されます。
  • 「ケースの管理」アプリケーション権限は、ケースの編集、削除、移行、および作成を行うために必要です。この権限には「ケースの編集」、「ケースの削除」、「ケース所有者の移行」、および「ケースの作成」権限が含まれています。プロファイルまたは権限セットからいずれかの個別の権限が削除されると、「ケースの管理」アプリケーション権限が無効になります。

ケース関連リストの使用

  • メール-to-ケースから作成されたケースに返答し、処理するには、[メール] 関連リストを使用します。
  • サポートプロセスの必須手順を表示したり、マイルストーンの完了日を追加したりするには、[ケースマイルストーン] 関連リストを使用します。
  • ケースにファイルを追加するには、[ファイル] または [添付ファイル] 関連リストにファイルをドラッグします。Lightning Experience でのみ、ファイルをドラッグできます。
  • 組織の知識ベースから記事を見つけてケースの解決に役立てるには、[記事] 関連リストを使用します。検索を開始するには、キーワードを入力します。ケースに関連記事を添付してソリューションを追跡し、他のユーザーによる類似ケースの解決に役立てることができます。添付された記事は、関連リストに表示されます。ケースのクローズ中にドラフト記事を作成すると、そのドラフト記事は公開された後、関連リストに表示されます。
  • ソリューション (バージョン 1.0 の記事) を見つけてケースの解決に役立てるには、[ソリューション] 関連リストを使用します。ソリューションカテゴリが設定されている場合、キーワードと一緒にカテゴリを選択して検索を絞り込むことができます。推奨ソリューションが設定されている場合、[推奨ソリューションの参照] をクリックして関連するソリューションを確認できます。ソリューションは、関連性とケースの類似性に基づいて推奨されます。

ケースのレポート

  • [レポート] タブの [サポートレポート] フォルダーには、ケース履歴、作成されたケース、エージェント (サービス担当者) が作成したケース、オープンケースを所有するエージェントなどのケースレポートが含まれます。
  • [レポート] タブで独自のカスタマイズケースレポートを作成することもできます。たとえば、優先度で並び替えられたオープンケースのリストを表示するレポートを作成します。

Chatter アンサーからケースへの返答 (Lightning Experience では使用不可)

  • Web サイトでの質問から変換されたケースに返信するには、Chatter に似たフィードに返答を入力して [顧客への回答] をクリックします。返答は、[ケースコメント] 関連リストで追跡されます。

Salesforce Classic のケースメールの操作

メール-to-ケースまたはオンデマンドメール-to-ケースを使用して生成されたケースが、[メール関連リスト] に表示されます。[メール] 関連リストには、お客様とお客様の顧客との間のメールスレッドのほか、顧客が送信した特定のケースに関するすべてのメールが表示されます。メールメッセージの最初の 77 文字が関連リストに表示されるため、メールをクリックしなくても、メッセージの内容を確認できます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
ケースを参照する ケースに対する「参照」
ケースメールと連携させる ケースに対する「編集」

メール-to-ケースまたはオンデマンドメール-to-ケースを処理する手順は、次のとおりです。

  • [メールを送信] をクリックして、取引先責任者、別のユーザー、またはその他のメールアドレスにメールを送信します。
    メモ パートナーコミュニティユーザー種別では、Classic コミュニティに [メールを送信] ボタンは表示されません。このボタンは [活動] リストで使用できます。 
  • [返信] をクリックして、メールに返答します。返信メールには、お客様から受信したメール本文が自動的に含まれます。返答を入力して、[送信] をクリックします。

    ケースの [メール] 関連リストにあるメールメッセージに返信するとき、受信者には、メールの [差出人:] 項目が「no-reply@salesforce.com」または「support@company.com」と表示される場合があります。これは、受信者のメールアプリケーションが受信メールの [送信者] ヘッダーや [差出人] ヘッダーをどう受信するかによります。デフォルトでは、組織に対し [送信者 ID 準拠を有効化] 設定がオンになっています。そうすることにより、Salesforce から送信されたメールメッセージが、送信に [送信者] ヘッダーを必要とするメールアプリケーションに準拠できます。

  • メールスレッドに参加している人全員に返答する場合は、[全員] をクリックします。
  • メールを表示するには、メールの件名をクリックします。メールから、送信者および全員への返答、メールの転送または削除を行うことができます。
  • [メールメッセージリスト] をクリックすると、メールを表示しながら、そのケースと関連付けられているすべてのメールを表示することができ、[次へ] または [前へ] をクリックすると、そのケースの他のメールに移動できます。
    メモ [メールメッセージリスト]、[次へ]、および [前へ] リンクは、カスタマーポータルおよびパートナーポータルでは利用できません。
  • メールを表示しながら [転送] をクリックすると、そのメールが転送されます。そのメールには、お客様から受信したメール本文が自動的に含まれます。必要に応じて、テキストを入力して、[送信] をクリックします。
  • 元のメールが HTML メールの場合は、「HTML 形式に変換」リンクをクリックすると、HTML バージョンを表示できます。受信メールメッセージでメールのヘッダー全体を表示する場合は、メール詳細ページの [元のメールヘッダーを表示するにはこちらをクリック] リンクをクリックします。
  • 受信メールに添付されているファイルを表示するには、そのメールの [添付ファイル] 関連リストにアクセスします。送信メールに添付されているファイルを表示するには、送信メールの [添付ファイル] 関連リストを表示します。

    添付ファイルの容量制限は 5 MB です。メールのエージェントを構成したユーザーは、添付ファイルが制限サイズを超えたかどうかを調べるために、ログファイルを表示できます。

  • メールを削除するには、[削除] をクリックします。削除されたメールは、ごみ箱から取り出すことができます。ただし、ケースからメールを削除し、ケースを削除した場合は、そのメールをごみ箱から取り出すことはできません。

[メール] 関連リストには、最後に受信したメールを先頭に、受信した順序で表示されます。関連リスト内のメールは、次のいずれかの状況で表示されます。

メール状況 説明

Lightning Experience での顧客へのメール送信

Lightning Experience で、ケースフィードのメールパブリッシャーを使用して顧客の質問に回答し、顧客の問題を解決します。

必要なエディション

サポートされているエディションを表示する。
メモ Lightning Experience のサービスコンソールアプリケーションから顧客にメールを送信するには、メール-to-ケースが組織で有効になっている必要があります。

開始するには、コンソールでケースを開きます。ケースフィードのパブリッシャーセクションで、[メール] をクリックします。メールパブリッシャーから差し込み項目の挿入、取引先責任者の検索、メールのプレビュー、メールのクリアなどを実行できます。さらに、Salesforce Classic および Lightning Experience メールテンプレートを挿入し、ファイルを添付し、気が変わった場合は添付ファイルを削除できます。

Lightning Experience でメールを使用するときには次の点に留意してください。

取引先責任者の検索
取引先責任者のメールアドレスを検索するには、[宛先] 項目、[CC] 項目、[BCC] 項目でルックアップアイコンをクリックします。メールコンポーザーで、取引先の取引先責任者や同僚 (内部ユーザー) によって取引先責任者を絞り込むことができます。取引先責任者をメール受信者として追加するには、取引先責任者を選択して [追加] をクリックします。探している人が表示されない場合は、名前で検索できます。
Safari を使用していない限り、メールアドレスピルをクリックして選択できます。
添付ファイル
コンピューターから複数のファイルを添付するには、ファイルをメールの本文にドラッグします。ファイルは何個でもドラッグできますが、ファイルは 2 GB 以上にはできません。Salesforce にアップロードされたファイルを添付するには、添付ファイルアイコンを使用します。
差し込み項目
差し込み項目は、送信とプレビューでのみ解決されます。パブリッシャーに挿入されたときは、プレーンテキストとして表示されます。
ヒント 取引先または取引先責任者の差し込み項目など、ダイアログボックスに表示されていない差し込み項目を挿入できます。プレーンテキストとして入力し、送信する前にプレビューボタンを使用して確認します。
メールテンプレート
Lightning Experience および Salesforce Classic テンプレートを挿入できます。テンプレートを挿入すると、件名がテンプレートの件名で置き換えられます。
<head>、<meta>、<title>、または <style> HTML タグが含まれる反応型メールテンプレートを挿入する場合、そのテンプレートでメール本文の内容が上書きされます。上書きされる前に確認メッセージが表示されるので、心配いりません。
メールドラフト
メールの作成、返信、転送を行うときにメールの作業中のドラフトが数秒ごとに自動的に保存されます。ドラフトから離れても、いつでも戻ってくることができます。
メモ メールドラフトは非公開で、共有できません。
メール状況
メール履歴には、Salesforce ユーザーから送信された返信が最新順に表示されます。メッセージの詳細にはメールの状況が含まれます。
メール状況説明
New まだ読まれていない受信メール。
既読 読まれたものの、返答されていない受信メール。
Sent 送信メール。
Replied 返答済みのメール。送信されたメールに返答すると、返答済みになります。

メールに直接返信した場合、メールの状況は [返信済み] になります。たとえば、受信メールに対して返信を送信すると、そのメールの状況は [返信済み] になります。その後、同じ受信メールに続けて返信を送信し、最初の返信には直接返信しなかった場合、最初の返信の状況は [送信済み] になります。

メールのプレビュー
プレビューを使用して、送信前にメールとその差し込み項目を確認します。
メールの削除とクリア
ごみ箱アイコンを使用すると、作業中のドラフトを削除し、項目を元の状態にリセットできます。この動作は、メールドラフトが有効化されているかどうかに応じて異なります。
  • メールドラフトが有効になっていない場合、このアクションでは、本文、件名、追加された受信者がクリアされ、メールが元の状態に戻ります。
  • メールドラフトが有効になっている場合は、ドラフトが削除され、元の状態に戻ります。
ポップアップしてドッキングされるメールコンポーザー

メールへの返信時にケースフィードを確認しやすいように、ドッキングされたメールコンポーザーを開きます。このコンポーザーはコンソールの横に表示されます。メールの作成に集中できるように、ドッキングされたコンポーザーからメールコンポーザーを最大化することもできます。

ドッキングされたコンポーザーを開くには、メールコンポーザーツールバーで [ドッキングビューにポップアウト] アイコンをクリックします。

システム管理者がメールドラフトを有効化している場合、[ドッキングビューにポップアウト] ボタンは無効化されています。

ドッキングされたメールコンポーザー

ドッキングされたメールコンポーザーを使用してメールを送信すると、ページの一部のみが更新されます。

画像
画像をメッセージに埋め込むには、コピーして貼り付けるか、画像の URL を指定するか、Salesforce ファイルを参照またはアップロードします。方法によって動作は少し異なります。
  • コピー/貼り付け — すべての画像ファイルの種類がサポートされます。画像は添付ファイルおよびインラインとして追加され、インライン画像はサイズ変更できます。ケースメール内の画像の最大サイズは 1 MB です。その他のメールでは、最大 5 MB です。Microsoft Edge はサポートされません。Internet Explorer 11 以前では画像のサイズ変更ができません。
  • Web URL — 最大ファイルサイズはありません。画像はインラインで追加され、サイズ変更できます。画像は添付ファイルとしては追加されず、Salesforce ファイルに変換されません。画像のデフォルトの説明テキストは「User uploaded image」 (ユーザーがアップロードした画像) に設定されます。
  • Salesforce ファイルの参照またはアップロード — アップロードされたファイルから Salesforce ファイルを作成するか、既存の Salesforce ファイルを挿入します。ファイルサイズ制限は、Salesforce Files の制限に基づきます。メッセージ自体から画像のサイズを変更することはできません。画像は添付ファイルおよびインラインとして追加されます。Salesforce ファイルの内容のバージョンが変更された場合、以前のバージョンの Salesforce ファイルを使用していたメッセージは更新されません。
メモ Lightning Experience でケースメールパブリッシャーを使用している場合のみ、メッセージの転送時にはメール添付ファイルが含まれますが、メッセージへの返信時には含まれません。
テーブル
テーブルをメールに追加するには、メールコンポーザーのアクションメニューでテーブルアイコンをクリックし、テーブル設定を入力します。次に、コンテンツをテーブルに追加します。メールコンポーザーのアクションメニューを使用して、コンテンツのスタイルを設定したり、テーブルに画像を挿入したりします。テーブルのセルのスペーシング、パディング、位置揃えを編集するには、テーブルの境界線でマウスの左ボタンをダブルクリックします。
メモ
  • Lightning メールテンプレートエディターでは、テーブルアクションは使用できません。
  • 他のアプリケーションからメールコンポーザーにテーブルをコピーして貼り付けることはできますが、スタイル設定に影響する可能性があります。
  • Salesforce でテーブルを表示している場所に応じて、テーブルの境界線が 2 つの線で表示される場合と 1 つの線で表示される場合があります。
コードサンプル
コードサンプルアイコンをクリックしてコードをコードウィンドウに貼り付けて、コード書式設定を保持するコードスニペットを挿入します。

Salesforce システム管理者は、ケースのメール環境をカスタマイズできます。「ケースの [メールを送信] クイックアクションの作成」を参照してください。

顧客へのメール送信

ケースレコードページから直接メールを使用して顧客に返答できます。効率的に作業するために、メールテンプレートを挿入および作成したり、クイックテキストや差し込み項目を使用したりできます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
メールを送信する 「活動へのアクセス」
メモ サービスコンソールアプリケーションから顧客にメールを送信するには、メール-to-ケースが組織で有効になっている必要があります。
  • 別のケースへのメールの移動
    顧客が別のケースに関する情報を含むスレッドに返信したときにメールを正しく並び替えます。 
  • Lightning Experience での顧客へのメール送信
    Lightning Experience で、ケースフィードのメールパブリッシャーを使用して顧客の質問に回答し、顧客の問題を解決します。
  • Salesforce Classic での顧客へのメール送信
    Salesforce Classic でケースフィードのメールを操作します。
  • デフォルトの No-Reply メールアドレスの設定
    組織の共有システムメールアドレスを使用して、顧客にケースに関する自動メールを送信します。ケースの詳細を含めてメールテンプレートをカスタマイズするには、検証済みのカスタム No-Reply アドレスを作成します。そうしないと、[ケース通知をシステムアドレスから送信] を有効にしたときに、既存のケースに関する受信メールのメール通知、ケースコメント、ケースエスカレーション、ケース割り当ては、noreply@salesforce.com から送信されます。noreply@salesforce.com から送信するメールは、セキュリティ上の理由によりカスタマイズできません。ケースの詳細や顧客情報は含めないでください。
  • ケースの差し込み項目
    Salesforce Merge Language で使用可能なメールテンプレート差し込み項目のリストは、使用しているデータ型によって異なります。ケースの差し込み項目のほとんどはケース項目に直接対応しています。

ケースのメールテンプレートの作成

メールテンプレートは、送信メールで一貫したメッセージングを使用するのに役立ちます。ケース割り当てルールや自動レスポンスルールで使用したり、問い合わせに応じて顧客に送信したりするためのブランドメールテンプレートを作成します。

必要なエディション

サポートされているエディションを表示する。

メールテンプレートの計画

必要なメールテンプレートの種類を決定します。開始するためのアイデアをいくつか紹介します。

  • 一般的なコミュニケーション: サービス担当者が顧客とコミュニケーションするときに使用する汎用テンプレート。
  • ケースの作成: ケースが作成されたことを取引先責任者に通知します。
  • ケース割り当て通知: ケースがサービス担当者に割り当てられたことをユーザーに通知します。
  • ケースコメントの作成または変更: ケースコメントが追加または変更されたことを取引先責任者に通知します。
  • Web サイトからケースを取得する: 顧客が Web サイトでフォームに入力したときに、問い合わせが受信されたことを通知します。
  • 顧客のメールからケースを取得: 顧客がカスタマーサポートのメールアドレスにメールを送信すると、メールが受信され、ケースが作成されたことが通知されます。
  • ケースクローズ通知: ケースがクローズしたことを顧客に通知します。

メールテンプレートを整理する方法を決定します。適切なユーザーが使用できるように、公開フォルダーまたは非公開フォルダーに保存することもできます。

メールテンプレートの作成

アプリケーションランチャーから移動できる [メールテンプレート] タブからテンプレートを作成および管理します。

メールテンプレートを作成するときは、次のガイドラインに留意してください。

  • 日付や顧客の名前などの特定のデータを含めるには、メールの件名または本文に差し込み項目を挿入します。差し込み項目は、Salesforce レコードのデータに置き換える変数テキストのプレースホルダーです。
  • 必要に応じて、[関連エンティティ種別] 項目でオブジェクトを選択します。選択したオブジェクトは、差し込みピッカーで使用できる差し込み項目に影響します。[取引先責任者] または [リード] を選択するか、項目を空白のままにすると、テンプレートはグローバル差し込み項目のみを使用するグローバルテンプレートになります。

メールおよび Web フォームからのケースの取得

メール-to-ケースと Web-to-ケースを使用すると、顧客のメールと Web フォームの送信を Salesforce のケースレコードに自動的に変換できます。この自動化により、時間を節約し、顧客からの問い合わせに対応せずに済みます。

必要なエディション

サポートされているエディションを表示する。

Web フォーム送信

Web-to-ケースは、Web サイトの問い合わせフォームと Salesforce のケース管理システム間のギャップを埋めます。顧客が Web サイトで問題の報告、質問、フィードバックを行うための Web フォームを作成します。顧客がフォームの応答を送信すると、追跡と解決のために Salesforce の新しいケースレコードにその要求が取り込まれます。

使用を開始するには、「Web-to-ケースを使用した Web フォームの提供」を参照してください。

メールでのお問い合わせ

同様に、メール-to-ケースでは、顧客のメールからケースが自動的に作成され、メール応答が既存のケースにスレッド化されます。1 つ以上のメールルーティングアドレスを選択し、メールの送信先アドレスに応じてケース作成用のカスタムロジックを追加できます。たとえば、ゴールドとプラチナのサポートアカウントがある場合、ルーティングアドレスを設定します (例: goldsupport@acme.com、platinumsupport@acme.com)。

自動レスポンスルールを使用して、異なるメールテンプレートを使用して異なるケースに応答することもできます。使用するメールテンプレートを決定するケース属性を決定します。次に、送信されたケースの種別に固有の情報を提供するようにケースメールテンプレートを設計します。

使用を開始するには、「メール-to-ケースを使用したメールの送受信」を参照してください。
