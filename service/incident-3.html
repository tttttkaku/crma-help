ブロードキャスト Slack メッセージの送信

インシデントが発生したときに、ブロードキャスト Slack メッセージで関係者とリーダーチームに最新情報を提供します。ブロードキャスト Slack メッセージは、関連付けられた Slack チャンネルへのアクセス権を持つすべてのユーザーに表示されます。

必要なエディション

サポートされているエディションを表示する。
  • カスタマーサービスインシデント管理が有効になっている必要があります。
  • ブロードキャスト Slack メッセージが有効である必要があります。
  • ブロードキャストトピックを Slack チャンネルに割り当てる必要があります。
  1. [インシデント] 関連リストに移動し、[ブロードキャスト通信] 関連リストを見つけます。
  2. [新規ブロードキャスト Slack メッセージ] をクリックします。
  3. 関連性の高いブロードキャストトピックとテンプレートを選択して、[次へ] をクリックします。
  4. メッセージを送信する前に、メッセージを送信するチャンネルのリストを確認します。ブロードキャストメッセージを別のチャンネルに送信するには、別のブロードキャストトピックを選択します。
  5. トピックが適切であれば、メッセージプレビューを確認して [送信] をクリックします。
    送信する内容が適切であることを確認できるように、メッセージをテストチャンネルに送信するためのブロードキャストトピックがシステム管理者によって用意されている場合があります。テストブロードキャストトピックと Slack チャンネルを使用することで、共有しても安全なコンテンツであることを確認できます。
  6. コンテンツが適切であることを確認して、[このまま送信] をクリックします。

インシデントのエンタイトルメントプロセスの設定

インシデントのエンタイトルメントを有効にして、サポート担当者が顧客に適切なサービスレベルを提供できるようにします。エンタイトルメントプロセスを設定して、サポート担当者がインシデントを解決するために実行する必要のあるすべてのステップ (マイルストーン) を含むカスタマイズされたタイムラインを作成します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
エンタイトルメントを有効化する 「アプリケーションのカスタマイズ」
エンタイトルメントを参照する エンタイトルメントに対する「参照」
エンタイトルメントを変更する エンタイトルメントに対する「編集」
エンタイトルメントプロセスを作成および更新する 「エンタイトルメントの管理」

インシデントのエンタイトルメントとマイルストーンを使用する前に、エンタイトルメントを有効にしてマイルストーンを作成します。手順については、「エンタイトルメントとマイルストンの設定と管理」を参照してください。

  1. [設定] の [クイック検索] ボックスに「エンタイトルメント」と入力し、[エンタイトルメントプロセス] を選択します。
  2. [新規エンタイトルメントプロセス] をクリックします。
  3. エンタイトルメントプロセス種別として [インシデント] を選択し、[次へ] をクリックします。
  4. プロセスの名前を入力します。
  5. エンタイトルメントプロセスを [有効] に設定します。
  6. 必要に応じて、インシデントでプロセスを開始および終了する条件を設定します。
  7. 変更内容を保存します。
  8. [マイルストーン] で、[新規] をクリックします。
  9. マイルストーンを選択します。エンタイトルメントプロセスの定期的なマイルストーンまたは非定期的なマイルストーンを選択できます。
  10. タイムトリガーの分数を入力します。
  11. マイルストーンを処理する順序を指定します。
  12. 変更内容を保存します。

カスタマーサービスインシデント管理の設定

カスタマーサービスインシデント管理を有効にして、ユーザーにアクセス権を付与する方法を説明します。カスタマーサービスインシデント管理は、Winter '22 リリース以降に作成されたすべての組織で自動的に有効になります。

必要なエディション

サポートされているエディションを表示する。
ヒント Salesforce Go!ガイド付き設定環境の検索、より多くのコンテンツの探索、関連機能の発見、機能の使用状況の監視を行います。「Discover and Set Up Features With Salesforce Go」を参照してください。
  1. カスタマーサービスインシデント管理の有効化
    いくつかのステップを行うことでカスタマーサービスインシデント管理を有効にして、サービスチームがサービスの中断を追跡して診断し、再発を防止できるようにします。これらをすべて Salesforce 内で実行できます。
  2. ユーザーへのカスタマーサービスインシデント管理に対するアクセス権の付与
    ユーザーにカスタマーサービスインシデント管理機能へのアクセス権を付与するには、ユーザープロファイルにインシデント、問題、および変更要求へのアクセス権を割り当てます。
  3. カスタマーサービスインシデント管理を使用した自動化
    カスタマーサービスインシデント管理用のオートメーションツールを使用して問題をシームレスに解決します。
  4. カスタマーサービスインシデント管理のインテグレーションの設定
    カスタマーサービスインシデント管理をパートナーシステムと統合し、潜在的な問題を特定して、致命的な問題になる前に問題に積極的に対応します。
  5. インシデントおよびケースページレイアウトへの関連項目の追加
    ケースレコードからケースに関連したインシデント、問題、変更要求を確認するには、ケースページレイアウトに関連リストを追加します。また、Winter '24 より前にカスタマーサービスインシデント管理が有効化されている組織では、[商品] 項目を追加して、[インシデント] ページレイアウトに関連商品が表示されるようにします。
  6. カスタマーサービスインシデント管理のレポート
    [カスタマーサービスインシデント管理ダッシュボード] 管理パッケージを使用してチームがインシデントを解決する方法を確認します。作成されたインシデント、問題、変更要求の数と、完了したそれらの数を追跡します。また、月次の有効ユーザー数を使用してユーザーの採用を測定します。

ブロードキャストアラートの設定

インシデントが発生したときにユーザーがアプリケーション内アラートを送信できるようにするには、ブロードキャストアラートを有効にして、ブロードキャストトピックを作成し、グループに割り当てます。次に、カスタム Lightning コンソールアプリケーションを使用している場合は、インシデントアラートウィジェットをコンソールに追加します。

必要なエディション

サポートされているエディションを表示する。
  1. ブロードキャストアラートの有効化
    ブロードキャストアラートを有効にすると、インシデントが発生したときにインシデントマネージャーが中断を伴うアプリケーション内通知を送信できます。
  2. インシデントアラートユーティリティの Lightning コンソールアプリケーションへの追加
    インシデントが発生したときにユーザーがブロードキャストアラートを受信できるようにするには、Lightning コンソールアプリケーションにインシデントアラートユーティリティ項目を追加します。このステップは、カスタム Lightning アプリケーションを使用するユーザーにのみ必要で、Lightning サービスコンソールユーザーで自動的に有効になります。
  3. インシデントアラートの [すべて] タブのカスタマイズ
    インシデントアラートユーティリティの [すべて] タブからカスタムインシデントリストビューを表示します。デフォルトでは、標準のすべてのインシデント (デフォルト) リストビューが表示されます。
  4. ブロードキャストアラートのブロードキャストトピックの作成
    インシデントマネージャーがブロードキャストアラートを作成できるようにするには、まずブロードキャストトピックを 1 つ以上作成します。インシデントが発生すると、インシデントマネージャーはブロードキャストトピックに基づいてブロードキャストアラートをグループに送信できます。
  5. グループへのブロードキャストトピックの割り当て
    事前に決められた Salesforce ユーザーセットにブロードキャストアラートを送信するには、ブロードキャストトピックを 1 つ以上のグループに割り当てます。インシデントが発生すると、インシデントマネージャーはブロードキャストトピックに基づいてブロードキャストアラートを Salesforce のグループに送信できます。

ブロードキャストサイトバナーの設定

インシデントが発生したときにユーザーが Aura および LWR サイトにブロードキャストサイトバナーを追加できるようにするには、ブロードキャストサイトバナーを有効化し、ブロードキャストトピックを作成してネットワークサイトに割り当てます。次にエクスペリエンスビルダーでサイトにサイトバナーコンポーネントをサイト追加します。

必要なエディション

サポートされているエディションを表示する。
  1. ブロードキャストサイトバナーの有効化
    ブロードキャストサイトバナーを有効にして、ユーザーが重要な情報を表示するバナーを Aura および LWR サイトに追加できるようにします。
  2. ブロードキャストサイトバナーのブロードキャストトピックの作成
    ユーザーがブロードキャストサイトバナーを作成できるようにするには、まずブロードキャストトピックを 1 つ以上作成します。インシデントが発生すると、ユーザーはブロードキャストトピックに基づいてブロードキャストサイトバナーを Experience Cloud サイトに追加できます。
  3. ネットワークサイトへのブロードキャストトピックの割り当て
    ユーザーが Aura および LWR サイトにブロードキャストサイトバナーを追加できるようにするには、ブロードキャストトピックを 1 つ以上のネットワークサイトに追加します。ブロードキャストトピックをネットワークサイトに割り当てると、ブロードキャストトピックと Experience Cloud サイト間のリンクが作成されます。インシデントが発生すると、ユーザーはブロードキャストトピックに基づいてブロードキャストサイトバナーを Experience Cloud サイトに追加できます。
  4. サイトバナーコンポーネントのサイトへの追加
    ユーザーが Aura および LWR サイトにバナーを追加できるようにするには、エクスペリエンスビルダーでサイトバナーコンポーネントをサイトに追加します。バナーのデザインをカスタマイズすることもできます。

ブロードキャスト通信の設定

インシデント中にチームが大規模に顧客と最新情報を共有できるように、ブロードキャスト通信を設定します。

必要なエディション

サポートされているエディションを表示する。
  1. ブロードキャストサイトバナーの設定
    インシデントが発生したときにユーザーが Aura および LWR サイトにブロードキャストサイトバナーを追加できるようにするには、ブロードキャストサイトバナーを有効化し、ブロードキャストトピックを作成してネットワークサイトに割り当てます。次にエクスペリエンスビルダーでサイトにサイトバナーコンポーネントをサイト追加します。
  2. ブロードキャストメールの設定
    インシデントが発生したときにユーザーがブロードキャストメールを送信できるようにするには、ブロードキャストメールを有効化し、取引先責任者リストビューを作成/管理するか、ユーザーがインシデントに関連するケースまたは商品の取引先責任者にブロードキャストメールを送信できるようにします。
  3. ブロードキャストアラートの設定
    インシデントが発生したときにユーザーがアプリケーション内アラートを送信できるようにするには、ブロードキャストアラートを有効にして、ブロードキャストトピックを作成し、グループに割り当てます。次に、カスタム Lightning コンソールアプリケーションを使用している場合は、インシデントアラートウィジェットをコンソールに追加します。
  4. ブロードキャスト Slack メッセージの設定
    ユーザーが Slack でインシデントの更新を共有できるようにするには、Service for Slack アプリケーションを設定し、ブロードキャスト Slack メッセージを有効にして、ブロードキャストトピックを作成し、Slack チャンネルに割り当てます。
  5. ユーザーへのブロードキャスト通信に対するアクセス権の付与
    ユーザーがさまざまなブロードキャスト種別を作成できるようにするには、ブロードキャスト通信オブジェクト権限へのアクセス権をユーザーに付与します。
  6. インシデントレコードへのブロードキャスト通信の追加
    インシデントの発生時にユーザーがブロードキャスト (ブロードキャストメールやサイトバナーなど) を作成できるようにするには、[ブロードキャスト通信] 関連リストをインシデントページレイアウトに追加します。
  7. ブロードキャスト通信に関する考慮事項
    さまざまなブロードキャスト種別を使用するときに、以下の考慮事項に留意してください。

ブロードキャスト Slack メッセージの設定

ユーザーが Slack でインシデントの更新を共有できるようにするには、Service for Slack アプリケーションを設定し、ブロードキャスト Slack メッセージを有効にして、ブロードキャストトピックを作成し、Slack チャンネルに割り当てます。

必要なエディション

サポートされているエディションを表示する。
  1. ブロードキャスト Slack メッセージの有効化
    ブロードキャストアラートを有効にすると、インシデントが発生したときにインシデントマネージャーが中断を伴うアプリケーション内通知を送信できます。
  2. ブロードキャスト Slack メッセージのブロードキャストトピックの作成
    インシデントチームがブロードキャスト Slack メッセージを送信できるようにするには、まずブロードキャストトピックを 1 つ以上作成します。インシデントが発生すると、ユーザーはブロードキャストトピックに基づいてブロードキャスト Slack メッセージを Slack チャンネルに送信できます。
  3. Slack チャンネルへのブロードキャストトピックの割り当て
    ユーザーが Slack でインシデントの更新を共有できるようにするには、ブロードキャストトピックを 1 つ以上の Slack チャンネルに割り当てます。インシデントが発生すると、インシデントチームはブロードキャストトピックに基づいてブロードキャスト Slack メッセージを Slack チャンネルに送信できます。
  4. カスタムブロードキャスト Slack メッセージテンプレートの作成
    ビジネスニーズに合わせてカスタマイズされたブロードキャスト Slack メッセージを送信するには、カスタムブロードキャスト Slack メッセージテンプレートを作成します。デフォルトでは、テンプレートは [Slack のインシデントの最新情報] (デフォルト) に設定されています。

カスタムブロードキャスト Slack メッセージテンプレートの作成

ビジネスニーズに合わせてカスタマイズされたブロードキャスト Slack メッセージを送信するには、カスタムブロードキャスト Slack メッセージテンプレートを作成します。デフォルトでは、テンプレートは [Slack のインシデントの最新情報] (デフォルト) に設定されています。

必要なエディション

サポートされているエディションを表示する。

ブロードキャスト Slack メッセージテンプレートを作成する前に、Service for Slack アプリケーションの設定を完了し、ブロードキャスト Slack メッセージを有効にします。

  1. [設定] の [クイック検索] ボックスに「カスタマーサービスインシデント管理」と入力し、[カスタマーサービスインシデント管理] をクリックします。
  2. [ブロードキャスト Slack メッセージを設定] で [カスタムテンプレートを作成 (省略可能)] を見つけ、[テンプレートを作成] を選択します。
  3. [カスタム通知種別] で、[新規] を選択します。
  4. 通知種別として [Slack] を選択します。
  5. カスタム通知名と API 参照名を入力します。この名前は、ユーザーがブロードキャスト Slack メッセージを作成するときにテンプレート名として表示されます。
  6. オブジェクトを [インシデント] に設定します。
  7. 必要に応じて説明を入力し、[次へ] をクリックします。
  8. 配信アプリケーションを [Service Cloud for Slack] に設定し、[次へ] を選択します。
  9. タイトルと本文のメッセージを入力します。このテキストは、ブロードキャスト Slack メッセージが作成されたときに Slack チャンネルでユーザーに送信されます。レコードの項目に基づいてブロードキャスト Slack メッセージテンプレートを動的に更新するには、差し込み項目を使用します。「Slack 通知
    の差し込み項目」を参照してください。
  10. 必要に応じて、アクションボタンを追加します。
  11. [完了] をクリックします。

ユーザーはインシデントからブロードキャスト Slack メッセージを作成するときに、カスタムテンプレートを選択できるようになりました。

カスタマーサービスインシデント管理とは?

現在のデジタル環境では、サービスの中断は避けられません。Web の停止が発生したり、コードの変更やデータの破損によりサーバーがダウンしたり、悪天候によって停電や配信の遅延が発生したりします。このようなサービスインシデントがビジネスで発生した場合、原因を分析し、サービス業務を効率化して、ダウンタイムを最小限に抑える必要があります。Agentforce Service(旧称Service Cloud)のカスタマーサービスインシデント管理を使用して、この手順を実行できます。

必要なエディション

サポートされているエディションを表示する。

カスタマーサービスインシデント管理は、チームが大規模な中断を追跡し、適切なエキスパートに ToDo を委任して、ビジネスが顧客の期待に応えられるようにするサービスソリューションです。組み込みの項目、ページレイアウト、ベストプラクティスと共にカスタマーサービスインシデント管理を使用することで、サービスチームは中断に対応し、顧客に最新情報を提供できます。さらに、リリース管理機能を使用すると、チームは変更を実装し、問題の再発を防止できます。

中断に対する会社の対応によって、ブランドが構築されることも、傷つくこともあります。迅速に解決することは素晴らしいことですが、サービス中断中のカスタマーエクスペリエンスのコミュニケーション方法や管理方法も同様に重要です。中断をポジティブな体験に変換することで、顧客ロイヤルティを強化できます。カスタマーサービスインシデント管理により、次のことができます。

  • インシデントをプロアクティブに特定して対処する。
  • サポート担当者と対応チームがインシデントを追跡および管理するための一元化された場所を提供します。
  • インシデント、顧客、ケースのデータを容易に見つけることができる統合されたコンソールを利用する。
  • サービスレベル契約 (SLA) に準拠する。
  • カスタマーサービスインシデント管理のオブジェクトと項目
    カスタマーサービスインシデント管理を使用すると、サービスチームは、可視性の向上と中断への迅速な対応のために必要なツールとワークフローを取得できます。手順は次のとおりです。
  • ケースとインシデント
    ケースとインシデントが、サービスチームがさまざまな規模の顧客の問題を解決するのにどのように役立つかを説明します。
  • インシデントライフサイクルの例: インシデントチームの一日
    Take-Out のインシデントマネージャーは、メール、チャット、メッセージング、電話など、複数のチャネルで、新しいマーケティング割引コードのエラーに関する顧客ケースが急増していることに気が付きます。

  4. スウォーミングサポート担当者用のサービスリソースを作成します。

スウォーミングのプレゼンス状況と権限セットの設定

プレゼンス状況を使用して、ユーザーがオンラインでスウォーム要求を受け入れ可能か、退席中あるいはオフラインかを示します。スウォーミングを使用すると、サポート担当者はプレゼンス状況を使用して、エキスパートファインダーから送信されるスキルベースのスウォーム要求を拡張できます。権限セットを使用して、プロファイルを永続的に変更することなくサポート担当者の機能アクセス権を拡張できます。

サポート担当者は、スウォーミングに 2 つのプレゼンス状況が必要です。

  • 利用可

    スウォーム要求、対応可能ケースなど、使用可能なチャネルが複数ある場合、この状況は特定のチャネルに固有になる可能性があります。または、すべてのチャネルに使用可能など、複数のチャネルをグループ化した 1 つの状況になる可能性もあります。

  • 取り込み中

    この状況は、他の状況を指定しない限り常にすべての使用可能なチャネルに適用されます。

  1. [スウォーミング可能] プレゼンス状況を作成し、チャネルを [スウォームチャネル] に設定します。
  2. 「Unavailable for Swarming」(スウォーミング不可) の [取り込み中] プレゼンス状況を作成します。
  3. [スウォーミング]、[Slack サービスユーザー]、またはカスタム権限セットにプレゼンス状況を追加します。
  4. 変更を保存します。

スウォーミングの制限および考慮事項

必要なエディション

一般的なスウォーミングの制限

  • [スウォーミングを開始] のワークスペースセレクターには、ユーザーがアクセス権を持っていなかったとしても組織に接続されたワークスペースが表示されます。
  • Essentials Edition では、スウォーミングはサポートされていません。
  • ユーザーがコピーしたフローには、一部の最新のスウォーミング機能と Service Cloud for Slack 機能が含まれていない場合があります。最新の機能と更新を取得するには、元のフローを使用します。
  • スウォームレコードをキューが所有することはできません。
  • Slack からスウォームを開始する場合、[スウォームの説明] 項目には最大 625 文字まで入力できます。ただし、Slack チャンネルに投稿すると、255 文字のみが表示されます。項目の完全な 625 文字は、引き続き Salesforce のスウォームレコードに記録されます。
  • Salesforce でフローからスウォームを開始する場合、スウォームの説明の制限は 255 です。
  • Salesforce でスウォームレコードを手動で作成する場合、スウォームの説明の制限は 32,000 文字です。

Slack を使用したスウォーミング

  • ユーザーが Slack でスウォームに参加できるようにするには、スウォームメンバーが次の条件を満たしていることを確認します。
    • スウォームメンバーは Service Cloud ユーザーである必要があります。
    • スウォームメンバーは Salesforce アカウントを Service Cloud for Slack アプリケーションに接続している必要があります。
    • スウォームメンバーは、スウォーム要求者と同じ Slack ワークスペースに属している必要があります。
    • エキスパートファインダーを使用してスウォームメンバーを追加するには、Salesforce 組織でサポート担当者作業トリガーフローをコピーして有効化し、オムニチャネルを有効にする必要があります。
  • Summer '23 リリースより前に Service Cloud for Slack アプリケーションをインストールした場合、チャネルのワークスペース外のユーザー向けに Slack チャネルに参加するための招待メールを送信するには、Service Cloud for Slack アプリケーションを再インストールする必要があります。
    • Slack で、Service Cloud for Slack アプリケーションから [概要] タブに移動します。[設定] をクリックします。アプリケーションの Slack アプリケーションディレクトリページで、[App を削除] をクリックします。次に、アプリケーションを Slack ワークスペースに再度追加します。
  • 既存のチャネルでスウォーミングを開始すると、Slack ワークスペースのすべてのユーザーがチャネルセレクターから公開チャネルにアクセスできます。
  • Slack ユーザーグループをメンションしてそのメンバーをスウォームチャネルに追加できますが、スウォームを終了するときはユーザーグループをスウォームメンバーとして追加できません。
  • 既存のチャネルでスウォームを開始した場合、チャネルセレクターで自分がチャネルのメンバーである最初の 1,000 件の公開チャネルと非公開チャネルからしか選択できません。
  • 「Slack 会話コンポーネントの考慮事項」を参照してください。
  • Slack のナレッジ記事のドラフトでは、最大 2,500 文字のメッセージがサポートされます (英語の場合)。他の言語では文字数制限が異なる場合があります。Slack メッセージは文字制限で切り捨てられます。
  • Slack のレコードで [Salesforce で表示] を選択すると、Slack から Salesforce のレコードに移動します。
  • Slack で検索および編集できるのは、Salesforce の取引先、取引先責任者、ケース、およびカスタマーサービスインシデント管理のレコードのみです。
  • Slack から作成できるのは、Salesforce ケース、ナレッジ記事のドラフト、およびカスタマーサービスインシデント管理のレコードのみです。
  • Slack では、3 文字から 100 文字までを検索できます。
  • Slack でナレッジ記事のドラフトを作成する場合は、リッチテキスト、画像、動画、添付ファイル、絵文字はサポートされません。
  • Slack からナレッジ記事のドラフトを作成するときに、Slack メッセージと Slack メタデータを同じナレッジ項目に対応付けることはできません。
  • Salesforce でナレッジ作成権限を持つユーザーのみが Slack からナレッジ記事を作成できます。
  • 複数のスウォームがある Slack チャンネルでは、/service-swarm-close スラッシュコマンドを使用しても、スウォームメンバーのリストを表示できません。スウォームのメンバーを表示するには、スウォームの [スウォーミングを完了] ボタンをクリックします。

スウォーミングフローの設定

設定後、サポート担当者は事前設定されたスウォーミングフローテンプレートを使用して、Salesforce のレコードからすばやくスウォームを開始してメンバーを追加し、スウォームをクローズできます。

必要なエディション

サポートされているエディションを表示する。

次のようなフローを使用できます。

  • スウォーミングを開始
  • メンバーをスウォームに追加
  • スウォーミングを完了
  • スウォームを再オープン
  • 関連ケースを使用してスウォームをクローズ (自動起動)
  • 関連インシデントを使用してスウォームをクローズ (自動起動)
  • サポート担当者作業トリガー (自動起動)

これらのフローは、アクション & おすすめ、動的アクション、またはクイックアクションを使用して UI で有効にできます。これらのツールのいずれかまたはすべてを使用して、フローを起動できます。

アクション種別 アクション & おすすめ クイックアクション 動的アクション
利点
  • ユーザーに馴染みのあるコンポーネントをレコードページにあらかじめ設定できる
  • フローがレコードのネストされたサブタブで実行される
  • 完了したフローにチェックマークが表示される
  • すべてのスウォーミングインタラクション (スウォーミングリストビューやフローなど) を 1 つのタブで保持する場合に最適
  • ユーザーはレコードページに留まるため、レコードのコンテキストが維持される
  • フローが新しいタブまたはウィンドウではなく [フィード] タブで実行される
  • 特定のルールを満たしている場合にのみユーザーにフローを表示する
  • フローが新しいタブまたはウィンドウではなく [フィード] タブで実行される

自動起動フローを使用するには、フローをコピーして有効化します。自動起動フローはユーザーに表示されず、レコードが保存された後にフロー条件に一致すると実行されます。

スウォーミングフローを最初から作成し、呼び出し可能なアクションを使用して作成したフローから Slack を操作することもできます。あるいは、事前設定されたテンプレートのいずれかをコピーして、ビジネスニーズに合わせて調整します。

ヒント 標準のフローに追加された新機能は、コピーされたフローには表示されず、システム管理者が作成したバージョンに手動で追加する必要があります。
  • アクション & おすすめを使用したスウォーム
    アクション & おすすめコンポーネントを使用すると、ユーザーはコンソールで有効になっているフローに簡単にアクセスできます。このコンポーネントのフローは、レコードのネストされたサブタブで起動されます。レコードを切り替えて、他のタブで使用する情報を表示できます。
  • クイックアクションを使用したスウォーミング
    クイックアクションを使用したスウォーミングでは、タブやウィンドウではなく、フィードコンポーネントのパブリッシャーでフローが実行されます。サポート担当がクイック アクションを使用してフローを実行すると、フローの実行中に外部 Lightning ページ コンポーネントを表示できるため、レコードに関する詳細情報を表示してアクセスできます。
  • 動的アクションを使用したスウォーム
    動的アクションを使用して、サポート担当者のエクスペリエンスを合理化し、エラーの防止に役立つルールでスウォーミングフローを表示します。ルールを追加し、レコード条件に基づいて [編集] ドロップダウンに適切な ToDo のみが表示されるようにします。たとえば、ルールを設定して、ケースの状況が [クローズ] に設定されている場合にのみ [スウォーミングを完了] が表示されるようにします。

    サポート担当者のスウォーミング環境を最適化し、スウォーミングページレイアウト、タブ、および関連リストを使用してスウォーミングを前面中央に配置します。
  4. スウォーミングフローの設定
    設定後、サポート担当者は事前設定されたスウォーミングフローテンプレートを使用して、Salesforce のレコードからすばやくスウォームを開始してメンバーを追加し、スウォームをクローズできます。
  5. スウォーミング用のエキスパートファインダーの設定
    スウォーミングのカギを握る部分であり、オムニチャネルとスキルベースのルーティングを利用するエキスパートファインダーを設定します。
  6. スウォーミングのためのコラボレーションツールの設定
    顧客の問題についてスウォーミングを行うには、Slack などのコラボレーションツールを Salesforce に接続します。スウォームレコードのフィードをコラボレーションに使用する場合、コラボレーションツールは必要なく、スウォームオブジェクトのフィード追跡を有効にするだけで済みます。

Lightning Experience でのスウォーミング

スウォーミングとのコラボレーションは、サポート担当者が問題解決の支援を得るためにスウォーム要求を送信すると開始されます。Salesforce のレコードからスウォームを開始し、スウォームレコードのフィードからエキスパートとコラボレーションします。

必要なエディション

サポートされているエディションを表示する。
  1. [スウォーミングを開始] フローアクションを選択します。クイックアクション、動的アクション、または [アクション & おすすめ] パネルのいずれかになります。
  2. メンバーをスウォームに追加する方法を選択します。特定のチームメンバーを追加するには、対応するオプションを選択し、その名前を入力します。
    エキスパートファインダーではスキルベースのルーティングを使用して適切なスキルを持ち、作業を遂行できるだけの対応可能状況と業務量を備えたメンバーを見つけます。
  3. [別のスウォームメンバーを追加] チェックボックスをオンにして、スウォームに追加する各メンバーの詳細を入力します。次に、[次へ] をクリックしてスウォームレコードを作成します。
  4. 「I need help with a Java and Perl issue」 (Java と Perl の問題について支援を求めています) のように問題の詳細を入力し、[次へ] をクリックします。
  5. Chatter フィードでエキスパートと会話を開始します。

Lightning Experience でのスウォーミングの使用

Salesforce レコードからスウォームを開始したり、スウォームにエキスパートを追加したり、コラボレーションする場所を選択したりします。

必要なエディション

サポートされているエディションを表示する。
  • Lightning Experience でのスウォーミング
    スウォーミングとのコラボレーションは、サポート担当者が問題解決の支援を得るためにスウォーム要求を送信すると開始されます。Salesforce のレコードからスウォームを開始し、スウォームレコードのフィードからエキスパートとコラボレーションします。
  • Slack でのスウォーム
    Service Cloud for Slack アプリケーションで、顧客の問題についてスウォームします。スウォームは、Salesforce のレコードまたは Slack チャネルから開始できます。
  • Lightning Experience でのスウォームへのメンバーの追加
    顧客の問題を解決するときに異なるスキルを持つ他のユーザーから支援が必要な場合、進行中のスウォームにメンバーを追加できます。エキスパートファインダーを使用して、スキル、対応可能状況、業務量の観点から最適なユーザーを検索します。またはユーザーを直接名前で追加します。エキスパートファインダーを使用している場合、オムニチャネルは、対応可能で指定されたスキルを持つ最適なユーザーに招待を転送し、ケースとスウォームのスウォームメンバーレコードを作成します。スウォームメンバーを名前で追加したり、エキスパートファインダーでスキル別に検索したり、スウォームメンバーの追加をスキップして後で追加したりできます。
  • Lightning Experience でのスウォームのクローズ
    Lightning Experience からスウォームを完了としてマークします。スウォーミングを完了すると、終了日時が設定され、状況とすべての関連するスウォームメンバーが [完了] に変更されます。また、サポート担当者がより多くの作業を受け入れることができるように、サポート担当者のオムニチャネルプレゼンス設定の領域も解放されます。また、スウォームに関与しているメンバーがレポートに表示されます。
  • Lightning Experience でのスウォーミングの再オープン
    Lightning Experience から完了したスウォームを再オープンし、会話をシームレスに再開します。スウォームを再オープンすると、状況がクローズ済みからオープンに変更されます。また、スウォームの再オープンを決定した方法に基づいて、同じスウォームメンバーまたは業務量がまだ残っているメンバーのみでスウォームを開くことができます。
  • Slack でのアクションの実行
    スウォーミングを最大限に活用するには、Service Cloud for Slack アプリケーションと簡単に使用できるスラッシュコマンドを使用して Salesforce レコードを作成および検索します。

Slack でのスウォーム

Service Cloud for Slack アプリケーションで、顧客の問題についてスウォームします。スウォームは、Salesforce のレコードまたは Slack チャネルから開始できます。

必要なエディション

サポートされているエディションを表示する。

Service Cloud for Slack アプリケーションで顧客の問題についてスウォームするには、「Slack でのスウォームの開始」を参照してください。

スウォーミングの有効化

顧客の問題についてのスウォーミングを開始して、顧客の解決時間を短縮するには、スウォーミングを有効にします。

必要なエディション

サポートされているエディションを表示する。
  1. [設定] で、[クイック検索] ボックスに「スウォーミング」と入力して、[スウォーミング] を選択します。
  2. 切り替えスイッチを選択してスウォーミングを有効化します。

次に、スウォーミングオブジェクトへのアクセス権をユーザーに付与し、サービスコンソールを設定し、標準のフローを設定して、コラボレーションツールを選択します。
