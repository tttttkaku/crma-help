統合従業員ライセンスを使用した従業員のオンボーディング

移行後: 変更箇所と変更箇所

CCP から UEL への移行は、ID 変換に焦点を絞った従業員ユーザーのモデル化方法の基本的な移行です。

メモ Apexトリガー、Apexクラス、カスタム・フローなどのカスタマイズは、自動的には移行または更新されません。移行が成功したら、これらのコンポーネントをテストして再設定し、期待どおりに動作することを確認します。

What Changes? (変更内容) 変わらないもの
対象プロファイル: 移行時に、対象ユーザープロファイルが統合従業員プロファイルに対応付けられます。移行が成功したら、適切なプロファイルがユーザーに割り当てられていることを確認し、必要に応じてプロファイルベースの設定を再設定します。 権限セットおよび権限セットグループ: 移行中に権限セットおよび権限セットグループは変更されません。ただし、移行が成功したら、UEL 移行のユーザーアクセスポリシーを設定する必要があります。
共有セット: 共有セットは UEL に適用されません。移行後は、代わりに Apex または共有ルールを使用します。 ロール: 既存のロール割り当てとレポート構造は移行時に保持されます。

移行後のチェック

プラットフォームユーザーライセンス (PUL) ユーザーと UEL ユーザーでは、共有動作が異なります。適切なコントロールがないと、PUL ユーザーは所有していないケースを編集したり、内部ケースコメントを表示したりする場合があります。意図しないアクセスを防止するために、次の設定を確認してください。検証は省略可能ですが、移行後にすべての機能が期待どおりに機能するように次の手順を実行することをお勧めします。

コアライセンスと機能の設定の確認

UEL と PUL の両方のライセンス種別で必要なベースライン設定が有効になっていることを確認します。

  • 両方のライセンス種別で [外部組織の共有設定 (OWD)] を [非公開] に設定します。
  • PUL ユーザーの場合は、[内部 OWD] を [非公開] に設定します。
  • 両方のライセンス種別で次の項目が有効 (True) になっていることを確認します。
    • 個人取引先
    • ネットワーク機能 (有効、メンバー、内部ユーザー)
    • 従業員リンク

セキュリティ設定の確認

PUL ユーザーを要求者専用ユーザーとして設定し、意図しないアクセスを防止します。

  • [組織の共有設定 (OWD)] を [非公開] に設定します。
  • 要求者のみのアクセス権を持つ必要がある PUL ユーザーに対して NetworkOnlyInternalUser プロファイル権限を有効にします。
  • カスタム公開グループを使用して、要求者のみの PUL ユーザーを標準の内部ユーザーから分離します。
  • 内部ユーザーグループに関係なく、要求者が適切なレコードにアクセスできるように共有ルールを設定します。
  • Apex を使用して、PUL ユーザーによって作成された Chatter フィードおよびケースコメントが公開/外部のみにマークされるようにします。

従業員レコード権限の確認

表示と編集アクセス権を制限することで、従業員データを保護します。

  • すべてのユーザーが従業員情報にアクセスできる必要がない限り、[従業員ユーザーを表示] ボタンを削除します。
  • 従業員レコードに対する編集アクセス権を管理者のみに制限します。それ以外の場合、ユーザーは自分の従業員状況、開始日、従業員番号を変更できます。

データのインポート方法

Employee2 オブジェクトでは、API または Apex を使用してプログラムで挿入する必要があります。開発者と協力して、カスタムワークフローが次の特定の順序に従うようにします。

  1. Create Person Accounts (個人取引先を作成): まず、従業員データを個人取引先としてアップロードします。これにより、リンクされた取引先責任者レコードが自動的に作成されます。
  2. メモ データインポートウィザードでは、Employee2 はサポートされていません。従業員レコードは、API または Apex を使用してプログラムで作成する必要があります。
    従業員レコードの作成: カスタムインテグレーションで Apex または Salesforce API を使用して従業員レコードを作成し、各レコードを前のステップで作成した取引先責任者にリンクします。
  3. ユーザープロビジョニング: レコードがアップロードされると、従業員ユーザー設定に基づいてユーザーレコードがリンクまたは作成されます。

従業員ユーザー設定の定義

インテグレーションを開始する前に、すべての新規ユーザーに適用されるデフォルト値を定義します。

  1. [設定] から、[クイック検索] ボックスに「従業員ユーザー設定」と入力し、[従業員ユーザー設定] を選択します。
  2. 次の必須項目を設定します。
    • プロファイル: 新規ユーザーのデフォルトプロファイルを選択します。
    • メールの文字コード: メールの文字コード (UTF-8 など) を選択します。
    • 従業員状況: ユーザープロビジョニングをトリガーする状況を選択します。
    • 権限セット: (統合従業員の場合は必須) 割り当てる権限セットを選択します。
  3. [ユーザープロビジョニング] セクションで、[ユーザープロビジョニングを実行] を選択します。
  4. 確認ウィンドウで [実行] をクリックします。
  5. 従業員レコードが作成またはプロビジョニング状況に更新されると、Salesforce は自動的にユーザープロビジョニングジョブを実行します。手動でプロビジョニングを再度実行する (失敗したレコードを再試行するなど)
    1. [ユーザープロビジョニング] セクションで、[ユーザープロビジョニングを実行] を選択します。
    2. 確認ウィンドウで、[実行] をクリックします。

大規模なデータセットの管理

多数の従業員がいる組織では、200 項目の選択肢の制限があるため、リストビューを使用してレコードを同期することは非効率的です。また、自動ユーザー作成はトランザクションあたり 2,000 レコードに制限されます。

このような場合は、バックグラウンドのユーザープロビジョニングプロセスを使用します。カスタムワークフローで API を使用して従業員データを一括インポートしたら、[従業員ユーザー設定] で [ユーザープロビジョニングを実行] をクリックします。これにより、Salesforce はプラットフォームの制限に達することなく、残りのレコードをバックグラウンドで処理できます。

プロビジョニングプロセスの監視

API または手動の [ユーザープロビジョニングを実行] ボタンを使用してトリガーされたかどうかに関係なく、ユーザー作成の進行状況を追跡します。ユーザープロビジョニングプロセスは、プロビジョニングされていない従業員レコードの数によっては時間がかかる場合があります。プロセスが終了するまで待機している間、他のタスクの処理に進むことができます。

ステータスを確認するには、[Employee User Settings (従業員ユーザー設定)] で [View Processes (プロセスの表示)] をクリックします。有効な進行状況を監視したり、完了したプロセスを確認して成功数を確認したりできます。エラーが発生した場合、ログにはトラブルシューティング用の影響を受ける従業員レコードへの直接リンクが表示されます。

機密の問題の報告

従業員が従業員ポータルまたはAgentforceを使用して機密レポートを安全に送信し、問題に自動的にフラグが付けられてHRに転送される方法について説明します。

サポートされているエディションを表示する。
必要なユーザー権限
機密ケースを送信および管理する 機密ケース管理

従業員ポータルでのケースの送信

従業員ポータルを使用して、機密の問題を報告します。

  1. 従業員ポータルで、[ヘルプセンター] タブに移動します。[Cases (ケース)] セクションで、[New Confidential Case (新規機密ケース)] をクリックします。
  2. 必要な詳細を入力し、ケース種別として [社外秘] を選択して、ケースを送信します。
  3. 機密ケースレコードが作成されます。対応する公開苦情レコードが自動的に作成されてケースに添付されるため、問題を適切な担当者に慎重に転送できます。

Agentforce を使用した機密の問題のエスカレーション

Agentforceを使用して、対話型のAIチャットで機密の問題を報告します。Agentforce は機密の表現を検出し、機密ケースを作成するか、人間のエージェントに接続するようにユーザに要求します。機密ケースを作成すると、安全に追跡できるように、レポートにフラグが自動的に付けられ、承認された HR と法務担当者にのみ慎重に転送されます。

Agentforce から HR または法務担当者に機密の問題をエスカレーションするには、事前設定されたフロー テンプレートを使用します。

  1. [設定] の [クイック検索] ボックスで、[フロー] を検索して選択します。
  2. フローリストから、[Escalate Confidential Complaint (社外秘の苦情をエスカレーション)] を選択します。
  3. [Route for Confidential Handling] 要素を選択し、入力値を設定してルーティングロジックをカスタマイズします。
  4. 新しいフローとして保存し、HR サービスエージェントに追加します。

オムニチャネルのキューベースのルーティングユーザーのステップ (ワークフォースエンゲージメントのみ)

  1. [設定] で、[クイック検索] ボックスに「シフト区分種別」と入力して、[シフト区分種別] を選択します。
  2. [新規] をクリックします。
  3. シフト区分種別に名前を付けます。
  4. [シフト区分種別] ドロップダウンメニューにシフト区分が表示されるようにするには、[有効] ボックスをオンにします。
  5. カテゴリを選択します。
    1. [作業] は、メールやチャットなど、顧客対応チャネルでの作業を表します。
    2. [非作業] は、チームミーティングやトレーニングなど、作業に関連する活動を表します。
    3. [休憩] は、昼休みまたはより短い休憩を表します。
  6. サービスプレゼンス状況を選択します。この項目は、このシフト区分中にサポート担当者に割り当てられた作業活動を示します。
  7. 遵守しきい値を選択します。この項目は、割り当てられたシフト区分に関連付けられたサービスプレゼンス状況とは異なるサービスプレゼンス状況でサポート担当者が作業できる分数を示します。サポート担当者が、割り当てられたサービスプレゼンス状況外で遵守しきい値時間を超えて作業すると、サポート担当者は遵守外になります。プランナーにチーム管理ビューで通知されます。
  8. チーム管理ビューのシフト区分種別の色を選択します。遵守外インジケーターは赤で表示されるため、赤は選択しないでください。

シフト区分種別を作成したら、サポート担当者に割り当てることができるシフト区分に追加します。

オムニチャネルを使用しないシフトスケジュールまたはワークフォースエンゲージメントのステップ

  1. [設定] で、[クイック検索] ボックスに「シフト区分種別」と入力して、[シフト区分種別] を選択します。
  2. [新規] をクリックします。
  3. シフト区分種別に名前を付けます。
  4. [シフト区分種別] ドロップダウンメニューにシフト区分が表示されるようにするには、[有効] ボックスをオンにします。
  5. カテゴリを選択します。
    1. [作業] は、メールやチャットなど、顧客対応チャネルでの作業を表します。
    2. [非作業] は、チームミーティングやトレーニングなど、作業に関連する活動を表します。
    3. [休憩] は、昼休みまたはより短い休憩を表します。
  6. (ワークフォースエンゲージメントのみ) 遵守しきい値を選択します。この項目は、ワークフォースエンゲージメントのオムニ以外のユーザーは使用できない [リアルタイム遵守] と連携します。
  7. (ワークフォースエンゲージメントのみ) チーム管理ビューのシフト区分種別の色を選択します。

シフト区分種別を作成したら、サポート担当者に割り当てることができるシフト区分に追加します。

シフトテンプレートは、シフトのスケジュールとサービスリソースへの割り当てのビルディングブロックとして機能します。シフトテンプレートを作成したら、それらを使用してシフトをすばやく作成できます。テンプレートでは、開始時刻と終了時刻、ジョブプロファイル、状況などの情報を入力します。

シフトテンプレートのライブラリを作成して選定し、それらを使用してシフトを作成します。

  1. アプリケーションランチャーで、[シフトテンプレート] を選択します。
  2. [シフトテンプレート] ページから、[新規] をクリックします。
  3. 項目値を入力します。
    各テンプレートには 1 時間以上の期間が必要です。シフトテンプレートは、15 分単位で開始または終了する必要があります。たとえば、10:00、10:15、10:30、10:45 は有効な時間になります。
  4. テンプレートで [非標準] シフトが定義されるかどうかを指定します。
    非標準シフトとは、サポート担当者が不便または望ましくないと考えるシフトです。
  5. [保存] をクリックします。または、シフトテンプレートを保存して引き続き作成するには、[保存 & 新規] をクリックします。

業務量計画からシフトを作成できるのは、ワークフォースエンゲージメントのみです。シフトスケジュールには、業務量計画は含まれません。

業務量計画を作成すると、定義したシフトテンプレートに基づいて予測が分析され、計画が策定されます。計算が完了すると、計画状況が更新されます。短期業務量計画では、[シフトを作成] をクリックして、必要な残りのシフトを計画から直接追加できます。

短期計画で [シフトを作成] をクリックすると、既存のシフトとシフトテンプレートが考慮され、シフトの不足分 (必要なシフト - 出社可能シフト) のみが作成されます。たとえば、100 件のシフトが必要で、同じサービステリトリー、ジョブプロファイル、日付範囲に 10 件のシフトが存在する場合、プロセスで 90 件のシフトが作成されます。

非標準シフト

非標準シフトとは、不都合な時間や作業負荷の増加など、さまざまな理由でコンタクトセンター担当者が要求しないシフトです。シフトを非標準として識別してマークすると、プランナーはより公平でバランスの取れた方法でシフトを割り当てることができるため、サポート担当者の不満や欠員を減らすことができます。

非標準としてのシフトのマーク

プランナーは、シフトとシフトテンプレートを非標準としてマークできます。

  • シフトを非標準としてマークするには、シフトの作成または編集時に [非標準] チェックボックスをオンにします。

  • シフトテンプレートを非標準としてマークするには、シフトテンプレートの作成または編集時に [非標準] チェックボックスをオンにします。

非標準シフトの識別

非標準としてマークされたすべてのシフトは、さまざまなビューでフラグが付けられます。たとえば、スケジュールビューでは、非標準シフトには赤い苦痛アイコンのフラグが設定されます。

テーブルビューの非標準シフトは、[非標準] 列でフラグが付けられ、グループ化してビューの上部に移動できます。

非標準シフトの制限

プランナーは、各サポート担当者に割り当てる非標準シフトの数を制限できます。

  1. 各サービスリソースまたはサービステリトリーのスケジュール制約で、非標準シフトの最大数を指定します。
  2. [非標準シフトの制限] タイプのスケジュールルールを作成します。

サポート担当者を割り当てるときに、スケジュールロジックで非標準シフトの制限に達していないサポート担当者が検索されます。

スケジュール制約の作成

スケジュール制約は、作業が発生する時点や遂行する作業量の境界を設定するものです。サービスリソースまたはサービステリトリーのいずれかでスケジュール制約を設定します。サポート担当者をシフトと照合するために、スケジュールルールでは最初にサービスリソースの制約が参照されます。制約がない場合は、サービステリトリーのスケジュール制約が検索されます。

スケジュールの目的の作成

スケジュールの目的では、ビジネス目標をスケジュールプロセスに適用します。プランナーとシステム管理者は、スケジュールの目的を設定してスケジュールを最適化できます。

必要なエディション

サポートされているエディションを表示する。
メモ ワークフォースエンゲージメントは廃止される予定です。「ワークフォースエンゲージメントの廃止」を参照してください。

スケジュール目標を反映するスケジュールの目的を作成します。プランナーがサポート担当者をシフトと照合すると、スケジュール設定エンジンによって各目標に同じ加重が設定されます。

  1. [設定] の [クイック検索] ボックスに「スケジュール」と入力し、[目的] を選択します。
  2. [新規] をクリックします。
  3. スケジュールの目的に名前を付け、説明を追加します。
  4. スケジュールの目的の種別を選択します。目的種別で項目を使用する場合、表示される項目の値を入力します。
    次の目的種別を事前定義します。

    • Maximized Preferences (最大化された希望設定) — サービス担当者が希望する業務時間を定義してサービスリソース希望設定を作成すると、スケジュールツールでシフトの候補者を特定するときに各サービス担当者の希望が考慮されます。

    • シフトのバランス — スケジュールにより、指定された期間内のシフト数がサービス担当者間でバランスを取ります。

    • Balance Non-Standard Shifts (非標準シフトのバランス調整) — スケジュールにより、指定された期間内の非標準シフト数がサービス担当者間でバランス調整されます。

例 [シフトの均衡] 種別のスケジュールの目的を作成します。この項目では、シフト割り当てを調整するときに考慮する日数を定義します。たとえば、[シフト前の日数] に「10」、[シフト後の日数] に「50」と入力すると、スケジュールツールによって、各シフトの 10 日前から 50 日後までの 60 日間の期間全体で割り当てのバランスが取られます。

スキルを照合

シフトに割り当てるための適切なスキルをサービスリソースが備えているかどうかチェックします。スキルレベルは考慮されません。スケジュールロジックでは、サービスリソースのスキル関連リストを参照して、シフトのジョブプロファイルで指定されたスキル要件とスキル関連リストが比較されます。

スキルレベルを使用してスケジュールする場合、レベルごとに個別のスキルを作成します。たとえば、「Claims Level 1 (請求レベル 1)」、「Claims Level 2 (請求レベル 2)」、「Claims Level 3 (請求レベル 3)」という名前のスキルを定義します。 これらのスキルをさまざまなジョブプロファイルに割り当て、適切なスキルをサポート担当者に追加します。たとえば、3 つのスキルをすべてレベル 3 のサポート担当者に割り当てます。次に、スケジュールでは、レベル 1、2、3 のスキルを必要とするジョブプロファイルを持つシフトのレベル 3 サポート担当者が考慮されます。
キューを照合 (ワークフォースエンゲージメントのみ) サービスリソースレコードのサポート担当者が、シフトのジョブプロファイルに対応付けられたすべてのキューのメンバーであるかどうかをチェックします。オムニチャネル計画を作成する前に、作業割り当てを転送するキューに各ジョブプロファイルを対応付けます。
テリトリーを照合 サービスリソースがシフトのテリトリーに属しているかどうかチェックします。スケジュールロジックでは、サービステリトリーメンバーシップの日付と時間が考慮されます。テリトリーメンバーシップのプライマリ種別とセカンダリ種別も考慮されますが、再配置種別は考慮されません。
休憩時間 (分) サービスリソースの連続するシフト間に最小休憩時間があるかどうかチェックします。分単位の休憩時間でスケジュール制約を定義し、適切なサービスリソースまたはサービステリトリーに割り当てます。
作業制限 サービスリソースが最大作業単位を処理できるかどうかチェックします。最大作業単位を時間で測定するのか、シフトで測定するかを決定します。必要な作業の種別を定義するための特定のスケジュール制約を選択します。最大数の単位 (1 日、1 週間、または 1 か月) を決定します。カスタムのスケジュール制約も作成できます。

スケジュールルールを作成する

テリトリーを照合ルールと他に必要なスケジュールルールを作成します。

  1. [設定] から、[クイック検索] ボックスに「ワークフォースエンゲージメントの管理」と入力し、[スケジュール] を選択して [ルール] を選択します。
  2. [新規] をクリックします。
  3. スケジュールルールに名前を付け、説明を追加します。
  4. ルールタイプを選択します。ルールでスケジュール制約を使用する場合、制約を選択します。カスタム制約を追加するには、オブジェクトマネージャーを使用して、スケジュール制約オブジェクトのカスタム項目を追加します。
  5. [保存] をクリックします。または、ルールを保存してさらに追加するには、[保存 & 新規] をクリックします。

[候補を取得]、[一括割り当て]、[シフトの一括更新] などのシフトスケジュールツールを使用して、サポート担当者をシフトと照合するときにルールを確認します。スケジュールロジックでシフトに割り当てるサポート担当者を検索する場合、すべてのルールに合格したサポート担当者のみが考慮されます。

例

サポート担当者が毎日作業できる時間数を制限するには、[作業制限] 種別のルールを作成します。ルールでは、サービスリソースまたはサービステリトリーのスケジュール制約をチェックして、サポート担当者が 1 日に割り当てられたシフト時間の制限に達しているかどうかを確認できます。

シフトは、手動で作成したり、シフトテンプレートを使用して作成したり、シフトテンプレートとシフトパターンを使用して作成したりできます。シフトテンプレートを使用してシフトを作成する場合、一度に複数のシフトを作成できます。シフトの繰り返しパターンを作成する場合は、シフトテンプレートで使用するシフトパターンを作成します。

シフトを手動で作成する手順は、次のとおりです。

  1. アプリケーションランチャーで [シフト] を開きます。
  2. ドロップダウンメニューからリストビューを選択する。
    [すべてのシフト] リストビューには大量のシフトが表示される可能性があるため、カスタムリストビューを作成することをお勧めします。たとえば、サービステリトリーまたはその他の条件でシフトを絞り込むリストビューを作成します。
  3. スケジュールビューに変更します。
  4. カレンダーで、このシフトを設定する日付の列にマウスポインターを置き、[+ 新規シフト] をクリックします。
  5. シフトの開始時刻と終了時刻を選択します。2 番目の時間のセットには、シフトの開始と終了がサービステリトリーのタイムゾーンで示されます。
  6. シフト状況を選択します。カスタムシフト状況値を指定するか、これらのデフォルトを使用できます。
    • 仮承諾 — シフトが暫定的に定義されています。サービスリソースに割り当てるか、未割り当てにすることができます。
    • 公開済み — シフトがサービスリソースに割り当てられ、公開されています。ワークフォースエンゲージメントでは、サポート担当者はエージェントホームでワークフォースエンゲージメントを表示できます。シフトスケジュールでは、サポート担当者は「シフトスケジュール結果の参照」ユーザー権限でシフトスケジュールを表示できます。
    • 確認済み — シフトの割り当てが確認されています。
  7. 必要に応じて、残りの項目を入力します。
    1. サービステリトリーとジョブプロファイルを追加します。
      サービステリトリーは、作業が実行される場所を示します。ジョブプロファイルは、作業に必要な専門知識を表します。
    2. サービスリソースを選択します。スケジュールツールで割り当て済みのシフトが考慮される場合、最適な一致が検索されます。サービスリソースの選択を保持するか、上書きできます。
  8. [保存] をクリックします。または、別のシフトを作成するには、[保存 & 新規] をクリックします。
  9. カスタムリストビューまたはスケジュールビューで新規シフトを表示します。
  • シフトテンプレートの作成
    テンプレートを使用してシフトをよりすばやく作成します。シフト作成ペインで項目を手動で入力する代わりに、事前入力された項目のテンプレートを挿入します。
  • 業務量計画からのシフトの一括作成
    ワークフォースエンゲージメントでは、必要に応じて短期業務量計画で予測されるシフトを追加できます。シフトを計画から直接作成すると、すばやく正確にスケジュールできます。シフトを 1 つずつコピーしてあと何件が必要かを追跡する必要はもうありません。
  • 非標準シフト
    非標準シフトとは、不都合な時間や作業負荷の増加など、さまざまな理由でコンタクトセンター担当者が要求しないシフトです。シフトを非標準として識別してマークすると、プランナーはより公平でバランスの取れた方法でシフトを割り当てることができるため、サポート担当者の不満や欠員を減らすことができます。

  4. シフト区分の右側で、ドロップダウンメニューをクリックして [編集] を選択します。
  5. 必要な変更を加えます。
  6. 変更内容を保存します。

[イントラデイ管理] タブからシフトを更新する (ワークフォースエンゲージメントのみ)

  1. アプリケーションランチャーから、[イントラデイ管理] を見つけて選択します。
  2. 必要に応じて、イントラデイ管理ダッシュボードのデータを更新します。
  3. チーム管理ビューから、シフト区分をクリックします。
  4. 必要な変更を加えます。
  5. 変更内容を保存します。
  6. サポート担当者のシフトまたはシフト区分を調整すると、チーム管理ビューが自動的に更新されます。データグラフビューを手動で更新して、それが反映されていることを確認します。シフトに割り当てられたサポート担当者に変更に関するメールが送信されます。
