オムニチャネルフローテンプレートを使用した着信通話のケースの作成

基本ルーティングとケース作成時のテンプレートを使用して、このルーティングロジックを自分で設定する時間を節約します。このテンプレートでは、通話者を識別し、通話をキューに転送し、通話のケースを作成して、サービス担当者が通話を受け入れるときに新しいケースレコードを画面ポップします。必要に応じてオムニチャネルフローを変更し、デフォルトのルーティングの動作 (キューなど) を変更します。

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「フロー」と入力し、[プロセスの自動化] の [フロー] を選択します。
  2. [新規フロー] をクリックします。
  3. [すべて + テンプレート] をクリックします。
  4. フロー種別をオムニチャネルフローに絞り込むには、[新規フロー] 画面の左ペインで [オムニチャネルフロー] を選択します。
  5. [Basic Routing with Case Creation (基本ルーティングとケース作成)] テンプレートからフローを作成するには、[Voice Calls Routed to Basic Queue with Case Creation (基本キューとケース作成に音声通話を転送)] を選択して、[作成] をクリックします。
  6. [作業を転送] アクションを開きます。
  7. [サービスチャネル] 項目で、[電話] を削除し、[電話] を検索して再度選択します。
  8. [完了] をクリックします。
  9. オムニチャネルフローを保存します。
  10. フローに対する更新を有効化するには、[有効化] をクリックします。
  11. Amazon Connect で、関連付けられた [Sample SCV Basic Routing with Case Creation (サンプルの SCV 基本ルーティングとケース作成)] 問い合わせフローを開きます。
  12. [Invoke AWS Lambda function (AWS Lambda 関数を呼び出す)] ブロックをダブルクリックし、[flowDevName] および [fallbackQueue] 入力パラメーターを追加します。
  13. flowDevName で、作成した [Voice Calls Routed to Basic Queue with Case Creation (基本キューとケース作成に音声通話を転送)] オムニチャネルフローの API 参照名を指定します。
  14. fallbackQueue で、代替キューの開発者名または ID を指定します。必要に応じて、SCV 基本キューをフォールバックキューとして割り当てます。
  15. Lambda 関数への変更を保存します。
  16. [Sample SCV Basic Routing with Case Creation (サンプルの SCV 基本ルーティングとケース作成)] 問い合わせフローを保存して公開します。
  17. [Sample SCV Inbound (サンプルの SCV 受信)] フローを開きます。
  18. [フローへの転送] ブロックを開き、[Sample SCV Basic Routing with Case Creation (サンプルの SCV 基本ルーティングとケース作成)] を選択します。
  19. 受信問い合わせフローを保存して、変更を公開します。

完了したら、電話チャネルに発信された通話を転送するために、[Sample SCV Basic Routing with Case Creation (サンプルの SCV 基本ルーティングとケース作成)] オムニチャネルフローを電話チャネルに割り当てます。

[チャット] ボタンへのオムニチャネルフローの割り当て

オムニチャネルルーティング種別とオムニチャネルフローを使用して、最適なサービス担当者にチャットを動的に転送します。

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「[チャット] ボタンと招待」と入力し、[[チャット] ボタンと招待] を選択します。
  2. 既存のボタンを編集するか、新しく作成します。
  3. [ルーティング情報] セクションの [ルーティング種別] で、[オムニチャネル] を選択します。
  4. [ルーティング用のフローを使用] を選択します。
  5. [ルーティングフロー] に、チャットを転送するために作成したフローを指定します。
  6. [キュー] で、このチャットボタンのキューを選択します。ルーティングフローを使用していない場合、キューによってチャットが管理され、優先順位が付けられます。ルーティングフローを使用している場合、キューによってチャットボタンを使用できるかどうかが決まります。キューに割り当てられたサービス担当者がオンラインで業務量がある場合、このボタンを使用できます。ボタンの可用性を管理するには、サービス担当者を大まかにグループ化した親キューを [チャット] ボタンに対して設定することを検討してください。

input_record の作成

Salesforce レコードの項目値に基づいて作業を転送するフローを作成する場合は、レコード変数を使用してレコードを保存します。

サポートされているエディションを表示する。
  1. Flow Builder ツールボックスで、[マネージャー] をクリックし、[新規リソース] をクリックします。
  2. [リソース種別] で [変数] を選択します。
  3. [API 参照名] に「input_record」と入力します。
  4. [データ型] では [レコード] を選択します。
  5. [オブジェクト] で、Salesforce オブジェクトを選択します。
    たとえば、チャットトランスクリプトレコードの項目値に基づいてチャットを転送する場合は、[チャットトランスクリプト] を選択します。通話の場合、[音声通話] を選択します。
  6. [フロー外部での可用性] で、[入力で使用可能] を選択します。
  7. [完了] をクリックします。

reasonForNotRouting の作成

フローで作業項目を転送できない理由を説明するには、reasonForNotRouting 変数を作成します。アプリ内および Web のメッセージングチャネルでこの変数を使用して、フローでメッセージング要求を転送できない理由を返すことができます。

サポートされているエディションを表示する。
  1. Flow Builder ツールボックスで、[マネージャー] をクリックし、[新規リソース] をクリックします。
  2. [リソース種別] で、[変数] を選択します。
  3. [API 参照名] に「reasonForNotRouting」と入力します。
  4. [データ型] で [テキスト] を選択します。
  5. [フロー外部での可用性] で、[出力で使用可能] を選択します。
  6. [完了] をクリックします。

オムニチャネルフローに [作業を転送] アクションにならないパスが含まれている場合、フローではこの文字列が返されます。たとえば、フローで割り当て要素を使用して、変数を [Outside business hours (営業時間外)] に設定できます。メッセージング要求が通常の営業時間外に発生したためにサービス担当者が対応できない場合、フローロジックはアプリ内および Web のメッセージングチャネルでこの文字列を返します。

recordId の作成

フローで作業項目の ID を保存するには、recordId 変数を作成します。

サポートされているエディションを表示する。
  1. Flow Builder ツールボックスで、[マネージャー] をクリックし、[新規リソース] をクリックします。
  2. [リソース種別] で [変数] を選択します。
  3. [API 参照名] に「recordId」と入力します。注意: 必ずこの名前を使用してください。
  4. [データ型] で [テキスト] を選択します。
  5. [フロー外部での可用性] で、[入力で使用可能] を選択します。
  6. [完了] をクリックします。

skillList の作成

適切なスキルを持つサービス担当者に作業を転送するには、必要なスキルを特定し、レコードコレクション変数に保存します。

サポートされているエディションを表示する。
メモ 音声通話にはスキルベースのルーティングを使用できません。
  1. Flow Builder ツールボックスで、[マネージャー] をクリックし、[新規リソース] をクリックします。
  2. [リソース種別] で [変数] を選択します。

  6. [オブジェクト] で [スキル要件] を選択します。
  7. [完了] をクリックします。

Command Center for Service でのスーパーバイザーの表示の変更

スーパーバイザー設定を使用して、表示される Command Center for Service タブとその順序を設定し、カスタムタブを追加します。スーパーバイザーのグループが表示できるサービス担当者、キュー、スキル、アクションを指定できます。担当者のプライバシーを強化するには、サービス担当者のタイムラインをこれらのスーパーバイザーに非表示にします。スーパーバイザーのグループごとに個別のスーパーバイザー設定を定義できます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」

ロールまたは [階層を使用したアクセス許可] によってユーザーをスーパーバイザー設定に追加することはできません。スーパーバイザー設定では、公開グループに直接割り当てられたユーザーのみがサポートされます。

  1. [設定] で、[クイック検索] ボックスに「スーパーバイザー構成」と入力し、[スーパーバイザー構成] を選択します。
  2. [新規] をクリックします。
  3. 設定の名前を入力します。[API 参照名] は自動入力されます。
  4. スーパーバイザーを設定に割り当てるには、[影響を受けるスーパーバイザーは?] セクションでユーザーまたはそのプロファイルを選択します。ユーザー設定は、ユーザープロファイル設定よりも優先されます。権限セットまたはプロファイルを介してサービスプレゼンス状況が割り当てられているユーザーのみが [選択可能なユーザー] リストに表示されます。
    メモ この設定によって担当者、キュー、またはスキルへのスーパーバイザーのアクセス権が変更されることはありません。[Command Center for Service (サービス向け Command Center)] タブに表示される内容が絞り込まれます。
  5. これらのスーパーバイザーが Command Center for Service の [Service Reps (サービス担当者)] タブに表示される担当者を絞り込むには、[Select Visible Agents (参照可能なエージェントを選択)] セクションで少なくとも 1 人の担当者または公開グループを追加します。
    公開グループを名前で検索する場合、検索結果には最大 2,000 件の公開グループが表示されます。
    選択した担当者は、Command Center for Service でスーパーバイザーに表示される担当者です。Command Center for Service には、有効な担当者と無効な担当者が表示されます。この選択により、[ウォールボード] タブの指標の計算に使用されるデータも絞り込まれます。
  6. これらのスーパーバイザーが Command Center for Service の [Agentforce Agents] タブに表示される AI エージェントを絞り込むには、[Select Visible Agentforce Agents] セクションで少なくとも 1 人のエージェントを追加します。
    選択した AI エージェントは、Command Center for Service でスーパーバイザーに表示されるエージェントです。
  7. [キューのバックログ] タブと [処理中] タブからキューを絞り込むには、[表示キューを選択] セクションで少なくとも 1 つのキューを選択します。

    たとえば、上位の取引先からのケースからのサポートを強化するには、これらの取引先のみが表示されるように [キューのバックログ] タブを絞り込みます。これらの選択により、[ウォールボード] タブのメトリクスの計算に使用されるデータも絞り込まれます。

    スーパーバイザーが担当者に割り当てられたキューを変更すると、スーパーバイザーの設定で指定されたキューのみが表示されます。そのスーパーバイザーにスーパーバイザー構成がない場合、すべてのキューが表示されます。

  8. [スキルのバックログ] タブでスキルを絞り込むには、[表示スキルの定義] セクションでスキルを選択します。また、指定したスキルが少なくとも 1 つある作業項目を表示するのか、指定したすべての指定スキルがある作業項目を表示するのかを指定する必要があります。
    これらの選択により、[ウォールボード] タブのメトリクスの計算に使用されるデータも絞り込まれます。
    最大 30 個のスキルを選択できます。
  9. [Command Center for Service] タブにアクションを表示するには、[アクションを定義] セクションでタブを選択し、アクションを [選択済みのアクション] 列に移動します。
    [アクションを定義] セクションには、システムアクションとカスタムアクションが表示されます。各タブに最大 10 個のアクションを追加できます。上下矢印を使用して、選択済みのアクションを並び替えます。
    メモ スーパーバイザー設定でカスタムアクションを追加する場合、Command Center for Service でアクションを表示するには、スーパーバイザーに「フローを実行」ユーザー権限か、ユーザーの詳細ページで [フローユーザー] 項目が有効になっている必要があります。または、フローで [デフォルトの動作を上書きし、有効化されたプロファイルまたは権限セットへのアクセスを制限します] が選択されている場合は、フローへのアクセス権が必要です。
  10. Command Center for Service で表示可能なタブを選択するには、[表示可能なタブを定義] セクションまでスクロールし、タブを [選択済みのタブ] リストに移動します。

    Command Center for Service には、[選択済みのタブ] リストに表示される順序でタブが表示されます。Lightning アプリケーションビルダーで、Command Center for Service Page ページ種別を使用してカスタムタブを作成できます。この機能は、拡張オムニチャネルでのみ使用できます。

  11. 担当者のプライバシーをより尊重できるようにするには、[エージェントタイムラインをこれらのスーパーバイザーに非表示] を選択します。
  12. [保存] をクリックします。

事前チャットの作成

事前チャットフォームで取得した情報に基づいてチャットを転送するフローを作成するには、事前チャットレコードコレクション変数を追加します。会話コンテキストの入力オブジェクトから事前チャットの詳細を取り込むように変数を設定します。

サポートされているエディションを表示する。
  1. Flow Builder ツールボックスで、[マネージャー] をクリックし、[新規リソース] をクリックします。
  2. [リソース種別] で [変数] を選択します。
  3. [API 参照名] に「prechatInfo」と入力します。
  4. [データ型] では [レコード] を選択します。
  5. [複数の値を許可 (コレクション)] を選択します。
  6. [オブジェクト] で [会話コンテキストの入力] を選択します。
  7. [フロー外部での可用性] で、[入力で使用可能] を選択します。
  8. [完了] をクリックします。
例

顧客の市区郡に基づいてチャットを転送するとします。顧客がシカゴ在住の場合、シカゴチームにチャットを転送します。それ以外の場合は、デフォルトのキューに転送します。チャットが開始される前にこのプロセスを自動化するには、顧客に事前チャットフォームに記入してもらいます。ここでは、名前とメールアドレスを入力してもらいます。

この事前チャット情報をフローで使用するには、最初に会話コンテキストの入力オブジェクトに基づいて事前チャットコレクション変数を定義します。次に、事前チャットレコードをループして顧客のメールアドレスを取得するフローを作成します。このフローでは、顧客レコードが見つかった場合、指定されたメールアドレスに基づいて取引先責任者オブジェクトから顧客レコードを取得します。最後に、顧客レコードの市区郡がシカゴの場合、フローによってチャットがシカゴチームに転送されます。それ以外の場合、チャットはデフォルトのキューに転送されます。

Command Center for Service カスタムアクションの画面フローの作成

アクションの動作を定義して、スーパーバイザーがアクションボタンをクリックすると表示される画面を設計するには、Flow Builder で画面フローを作成します。たとえば、スーパーバイザーがサービス担当者にメールを送信できる画面を作成できます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Flow Builder でフローを開く、編集または作成する 「フローの管理」
  1. [設定] の [クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  2. [新規フロー] をクリックします。
  3. [画面フロー] | [作成] をクリックします。
  4. 選択したサービス担当者、キュー、または作業項目を画面フローへの入力として受け入れるには、変数リソースを追加します。変数の API 参照名を ids に設定し、データ型を [テキスト] に設定し、[複数の値を許可 (コレクション)] オプションと [入力で使用可能] オプションを選択します。
    この変数には、スーパーバイザーがアクションを実行する Command Center for Service で選択したサービス担当者、キュー、または作業項目が保存されます。
  5. スーパーバイザーが Command Center for Service でアクションボタンをクリックしたときに表示されるページを作成するには、画面要素を追加します。

オムニチャネルの有効化と設定

オムニチャネルを有効にして、サービス担当者が同じアプリケーションからさまざまなサービスチャネルで作業を管理できるようにします。次に、ビジネスニーズに基づいてオムニチャネル機能を有効にします。

必要なエディション

サポートされているエディションを表示する。
重要

標準オムニチャネルは Summer '26 リリースで廃止されます。ユーザーがルーティングワークフローを維持し、最新の機能にアクセスできるように、Summer '26 リリースのロールアウト中に Salesforce によって組織が自動的に拡張オムニチャネルにアップグレードされます。拡張オムニチャネルは、サービス担当者とスーパーバイザー向けの最新の機能を提供します。「標準オムニチャネルから拡張へのアップグレード」を参照してください。

オムニチャネルは、Agentforce Service(旧称Service Cloud)製品ライセンス、またはデジタルエンゲージメント、拡張チャット、Amazon Connectまたはパートナーテレフォニーを使用するSalesforce Voice(旧称Service Cloud Voice)、ワークフォース管理のいずれかのアドオンライセンスで使用できます。

必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」
  1. [設定] から、[クイック検索] ボックスに「オムニチャネル設定」と入力し、[オムニチャネル設定] を選択します。
  2. オムニチャネルとその機能を有効にして、変更内容を保存します。
    設定 使用目的
    オムニチャネルの有効化 さまざまなサービスチャネルから受信した作業項目を、コンタクトセンターの最も適格で対応可能なサポートサービス担当者に転送します。スーパーバイザーが 1 か所 (Command Center for Service) からコンタクトセンター、サービス担当者の作業負荷、作業項目の状況を監視することができるようにします。
    スキルベースのルーティングとエージェントへの直接転送を有効化 作業を特定のサービス担当者または特定のスキルを持つサービス担当者に転送します。「Enable Skills-Based Routing or Route Work Items Directly to a Specific Support Rep (スキルベースのルーティングの有効化または特定のサポート担当者への作業項目の直接転送)」を参照してください。
    セカンダリルーティング優先度の有効化 作業項目をキュー内で古い項目より前に移動したり、キュー間で同じルーティング設定優先度を持つ項目の競合を解決したりします。キューでは、作業項目の待ち時間によって優先度が決まります (先入れ先出し)。しかし、作業項目がキューで待機しているときに、より緊急な作業が飛び込んで来ることもあります。「セカンダリルーティング優先度の設定」を参照してください。
    状況ベースの業務量モデルを有効化 開いているタブやセッションではなく、受け入れられた作業の状況に基づいてサービス担当者の業務量を測定します。サービス担当者が対応できない場合、作業が完了または再割り当てされるまで、作業は割り当てられたままになり、業務量に反映されます。「状況ベースの業務量モデルの設定」を参照してください。
    オムニチャネルを使用するサービス担当者が新しいウィンドウまたはタブを開いたときのログイン動作を定義する

    各サービス担当は、一度に 1 つのオムニチャネルセッションにのみログインできます。たとえば、サービス担当者が 1 つのブラウザータブでオムニチャネルにログインしている場合、2 番目のタブでオムニチャネルにログインすると有効なセッションが終了し、進行中の作業がすべて失われます。

    サービス担当者が別のタブまたはウィンドウでオムニチャネルを開いたときの動作を定義するには、次のいずれかのオプションを選択します。

    • 新しいウィンドウまたはタブでエージェントをオムニチャネルに自動的にログインします。この場合、サービス担当は元のセッションからログアウトされ、進行中の作業を終了します。
    • 開いているタブベースの作業が終了することをポップアップでエージェントに警告します。この場合、サービス担当はログインするオムニチャネルセッションを選択できます。
    • エージェントが新しいウィンドウまたはタブでオムニチャネルに自動的にログインしないようにします (推奨)。この場合、サービス担当は元のセッションにログインしたままになり、進行中の作業が中止されないようにします。サービス担当が新しいセッションにログインしていない。

    オムニチャネル代替モードが有効になっている場合、このログイン設定は無視されます。この場合、[新しいウィンドウまたはタブでエージェントを自動的にオムニチャネルにログインしない] オプションが常に使用されます。

    新しいウィンドウまたはタブにログインしたときに終了する進行中の作業には、有効な音声通話が含まれます。オンコールのサービス担当者が別のタブまたはウィンドウでオムニチャネルを開くと、通話情報は新しいインスタンスに表示されません。
    拡張オムニチャネルルーティング

    拡張オムニチャネルルーティングを有効にして、Agentforceエージェントの監視、オムニモバイル、オムニウォールボード、すべてのチャネル用の1つのInbox、Command Center for Serviceのカスタムタブとアクション、サービス担当者用のオムニサイドバーなどの最新機能にアクセスできるようにします。標準オムニチャネルの新機能は開発されなくなりました。

    このオプションを有効にする前に、「Upgrade Standard Omni-Channel to Enhanced (標準オムニチャネルの拡張へのアップグレード)」の考慮事項と前提条件を確認してください。
    重要 代替モードが有効になっている場合、[拡張オムニチャネルルーティング] オプションが無効になっているため、拡張オムニチャネルを標準オムニチャネルにダウングレードすることはできません。
  3. サービスチャネルから作業を転送するようにサービスチャネルを設定します。
    たとえば、オムニチャネルを使用してメッセージングセッションをサービス担当者に転送するには、メッセージングを有効にする必要があります。

オーディオデバイスと受信した作業通知の設定

間違ったオーディオデバイスで電話を受けた場合は、デバイスを変更します。また、オムニチャネルで受信した作業項目を見逃さないように、音声通知を有効にします。オムニチャネルコンポーネントウィンドウから離れる場合に備えて、視覚的な通知も設定します。

必要なエディション

サポートされているエディションを表示する。
  1. オーディオデバイスを変更するには、オムニチャネルコンポーネントの [設定] アイコンをクリックし、[入力および出力] で目的のデバイスを選択します。
    選択するデバイスは、現在のブラウザーにのみ設定されます。たとえば、Google Chrome 用にデバイスを選択した場合、そのデバイスは Mozilla Firefox には設定されません。この機能は、Apple Safari ブラウザーでは使用できません。デフォルトでは、通話はシステムデバイスで使用されているスピーカーとマイクを介して行われます。
    ヒント オムニチャネル設定でオーディオデバイスを選択しても、その使用は保証されません。オーディオデバイスの出力または入力の問題をトラブルシューティングするには、ブラウザーとコンピューターのオーディオ設定を確認します。詳細は、Salesforce システム管理者、Salesforce Voice テレフォニープロバイダー、または IT 担当者にお問い合わせください。
  2. 新しい作業に関する通知を受け取るには、通知を受信できるように、オペレーティングシステムとブラウザーアプリケーションで設定を有効にします。
  3. 視覚的なアラートを表示するには、オムニチャネルコンポーネントで [設定] アイコンをクリックし、[ブラウザーで新しい作業通知を表示] を有効にします。
    新しい作業項目が割り当てられているが、ブラウザーウィンドウがフォーカスされていない場合、アラートを受信します。
  4. オムニチャネルから通知音を受信するデバイスを選択するには、[設定] アイコンをもう一度クリックし、[リンガー出力] でデバイスを選択します。
    選択したデバイスは、現在のブラウザーのみに設定されます。たとえば、Google Chrome 用にデバイスを選択した場合、そのデバイスは Mozilla Firefox には設定されません。この機能は、Apple の Safari ブラウザーでは使用できません。
  5. 期待されるリンガー出力サウンドを確認するには、[通知音をテスト] をクリックします。

オムニチャネルフローを使用する場合の考慮事項

オムニチャネルフローを使用すると、堅牢なルーティングロジックを実装できます。作業が期待どおりに転送されるようにするには、次のガイドラインを確認してください。

サポートされているエディションを表示する。
  • オムニチャネルフローの実行中にエラーが発生した場合、作業項目はサービスチャネルに指定された代替キューに転送されます。
  • オムニチャネルフローの Apex クラスでは、非同期コールアウトのみがサポートされます。同期コールアウトを追加すると、ボットがメッセージングセッションを拒否したり参加しなかったり、作業が適切に転送されなかったりするなど、予期しない動作が発生する可能性があります。「Apex を使用したコールアウトの呼び出し」を参照してください。

オムニチャネルフローアクションを使用してオムニチャネルフローを移行する場合の考慮事項

Sandbox から本番環境にオムニチャネルフローを容易に移行できるようになりました。以前は、移行後の特定のフローアクションでは手動での更新が必要でした。バージョン 2.0 に更新することで、[ルーティングの対応可能状況を確認]、[スキル要件を追加]、[作業を転送] などのアクションを手動操作なしで移行できるようになりました。

手動操作なしでアクションを移行するには、フローでアクションのバージョンを 2.0 バージョンに更新します。

オムニチャネルフローアクションのバージョンを更新する

  • Flow Builder でオムニチャネルフローを開きます。
  • フローでアクションを選択し、アクションの設定パネルで [詳細オプションを表示] を選択します。
  • [アクションバージョン] ドロップダウンメニューで、バージョン 2.0.0 を選択します。 [保存] を選択します。

オムニチャネルフローが正常に移行されるようにするには、次のガイドラインを確認してください。

  • アクションを含むオムニチャネルフローの移行中、アクションで参照されるスキルは移行されません。対象組織のフローで使用するスキルを作成して、移行を続行できます。
  • フローアクションで参照されるスキルベースのルーティングルールは移行できません。リリース後に再作成できます。代わりに AddSkillRequirement アクションを使用できます。
  • [作業を転送] アクションを移動するときに、ルーティング対象としてエージェントまたはキューを選択すると、アクションの移動後に問題が発生する可能性があります。これを回避するには、値をハードコードする代わりに、変数を使用してフロー内で必要なエージェントまたはキューを動的に検索します。[レコードを取得] フローアクションを使用することもできます。この方法では、移行後に [作業を転送] アクションが正しく機能します。
  • オムニチャネルフローアクションで変数を使用する場合、変数が名前でレコードを取得して対応する ID を取得するようにします。この方法では、フローの移行後に正しい ID が使用されます。
  • サービスチャネルは移行できません。オムニチャネルフローを移行する前に、対象組織で必要なサービスチャネルを作成する必要があります。
  • エージェントとキューへの参照は、移行する回避策が必要です。User Entity - Agent への参照の回避策
    • [レコードを取得] フローアクションを使用してエージェント ID を取得する (例: ユーザー名またはメール)
    • [オムニチャネル] アクション項目で、前のステップから取得したユーザー ID を使用します。
  • キューエンティティへの参照の回避策
    • [レコードを取得] フローアクションを使用してキュー ID を取得する (例: キュー名別)
    • [オムニチャネル] アクション項目で、キューを参照する項目に前のステップから取得したキュー ID を使用します。

オムニチャネルフローを使用した高度なルーティング

オムニチャネルフローにより、Flow Builder 内でオムニチャネルのすべての機能が提供されます。Flow Builder の機能と柔軟性を使用して、ルーティングルールを定義し、作業を最適なサービス担当者に動的に転送します。オムニチャネルフローにより、音声通話、チャット、メッセージングセッション、ケース、リード、カスタムオブジェクトなど、サポートされているすべてのチャネルのルーティング設定が統合されます。

サポートされているエディションを表示する。
  • オムニチャネルフローの仕組み
    顧客がチャット、音声、またはメッセージングの会話を開始したら、オムニチャネルフローを起動して作業項目をキュー、スキル、サービス担当者、またはボットに転送します。
  • オムニチャネルフローの作成
    フローを最初から作成します。または、オムニチャネルフローテンプレートからフローを作成して作成時間を短縮します。テンプレートは、チャット、音声通話、メッセージをサービス担当者、キュー、スキルに転送するフローの作成方法を示しています。テンプレートを使用して各着信通話のケースを作成することもできます。ビジネスニーズに合わせてテンプレートから作成されたフローをカスタマイズできます。
  • オムニチャネルフローテンプレートを使用した着信通話のケースの作成
    基本ルーティングとケース作成時のテンプレートを使用して、このルーティングロジックを自分で設定する時間を節約します。このテンプレートでは、通話者を識別し、通話をキューに転送し、通話のケースを作成して、サービス担当者が通話を受け入れるときに新しいケースレコードを画面ポップします。必要に応じてオムニチャネルフローを変更し、デフォルトのルーティングの動作 (キューなど) を変更します。
  • [チャット] ボタンへのオムニチャネルフローの割り当て
    オムニチャネルルーティング種別とオムニチャネルフローを使用して、最適なサービス担当者にチャットを動的に転送します。
  • 電話チャネルへのオムニチャネルフローの割り当て
    コンタクトセンターには、サポート用とセールス用など、顧客が電話をかけられる複数の電話チャネルを追加できます。各チャネルには独自の電話番号が割り当てられます。電話チャネルで通話を転送するには、コンタクトセンターでチャネルを作成してから、チャネルのルーティング方法を指定します。オムニチャネルフローを使用して通話を動的に転送するには、フローをチャネルに割り当てます。
  • メール-to-ケースからケースを転送するためのオムニチャネルフローの割り当て
    オムニチャネルフローを使用して、カスタマーサポートメールのケースを適格なサポート担当者に転送します。
  • 非リアルタイムオブジェクトを転送するためのオムニチャネルフローの呼び出し

スキルベースのルーティングのしくみ

オムニチャネルのスキルベースのルーティングでは、必須スキルに基づいて作業項目を最も適格なサービス担当者と照合します。作業項目が作成されると、オムニチャネルはルーティング設定、スキルベースのルーティングルール、およびオムニチャネルフローの [作業を転送] アクションに渡されるスキル要件に基づいて、必要なスキルを決定します。次に、オムニチャネルは、必要なスキルと作業に対応できる業務量をすべて持つサービス担当者に項目を転送します。

サポートされているエディションを表示する。

作業項目を適切なサービス担当者に転送するために、オムニチャネルはこれら 2 つのソースのスキルの組み合わせを適用します。

ルーティング設定に含まれる静的スキル。
そのルーティング設定を使用して転送されるすべての作業項目にスキルを追加するには、スキルをルーティング設定に追加します。
スキルベースのルーティングルールまたはオムニチャネルフローから追加された動的スキル。
条件に基づいて特定の作業項目にスキルを動的に追加するには、スキルベースのルーティングルール、オムニチャネルフロー、またはその両方を使用してロジックを作成します。条件が満たされると、スキルが作業項目に適用されます。

オムニチャネルは、すべての必須スキルを持ち、ルーティング種別 (対応可能状況が最大または最小) に基づいて対応可能で、該当する場合は指定された最小スキルレベルを満たすサービス担当者に各作業項目を転送します。

すべての必須スキルを持つサービス担当者がおらず、追加スキルを削除するように設定されている場合、オムニチャネルは、残りのスキルを持つサービス担当者が対応可能になるまで、指定された順序で追加スキルを削除します。優先度の高いスキルが最初に削除され、優先度 0 または優先度のないスキルが最後に削除されます。その後、作業項目は、すべての追加スキルを持っていなくても、最も適した担当者に転送されます。サービス担当者が作業を拒否したりオフラインになったりすると、必須スキルが元の状態に戻り、追加のスキルを削除するプロセスが最初から開始されます。

スキルは、ケースなどのレコードがオムニチャネルキューに追加されると評価されます。オムニチャネルキューにあるレコードを編集した場合、そのレコードを同じキューまたは別のキューに再割り当てするまで、スキルへの変更は反映されません。

作業項目に特定のスキルが必要で、そのスキルを持つサービス担当者がいない場合、作業項目は転送されません。この状況は、オンラインのサービス担当者がいない場合のキュー内の項目の処理方法に似ています。Command Center for Service を使用している場合、スーパーバイザーは [スキルのバックログ] タブを参照して、スキルを必要とする作業項目のうちサービス担当者に割り当てられていないものを確認できます。

中断可能な業務量を使用した優先度の設定

サービス担当者が時間的制約のある作業と長時間の作業の両方を処理する場合、オムニチャネルは顧客が応答時間を短縮できるように時間的制約のある作業項目を転送できます。オムニチャネルで緊急度の高い作業をサービス担当者にすぐに転送できるように、緊急度の低い作業項目を中断可能として定義します。

サポートされているエディションを表示する。

作業項目は主または中断可能のいずれかとして指定できます。主作業項目とは、中断不可能とみなされる作業項目です。音声通話やチャットは、中断されるべきでないタスクの例です。一方、中断可能な作業項目とは、より差し迫った作業を優先するために後回しにできる作業項目です。解決に時間を要するケースは、中断可能な作業項目の一例です。

同様に、サービス担当者の主業務量と中断可能な業務量 (各サービス担当者が一度に処理できる中断不可能な作業と中断可能な作業の量) をそれぞれ定義できます。オムニチャネルは作業を転送するときに、作業項目のサイズと中断可能性を確認し、その作業項目に適した対応可能な業務量があるサービス担当者を検索します。

たとえば、サービス担当者が一度に 1 つの音声通話と 4 つのケースを処理できるとします。各作業項目の業務量を 1 単位として、サービス担当者の主業務量を 1 つの作業項目に設定し、中断可能な業務量を 4 つの作業項目に設定します。音声通話は中断不可能、ケースは中断可能になるように、サービスチャネルを設定します。

オムニチャネルで 1 人のサービス担当者に 4 つのケースが割り当てられた場合、そのサービス担当者は中断可能な作業でフル業務量になり、別のケースは提供されません。ただし、主作業である音声通話が着信すると、オムニチャネルはサービス担当者にまだ主業務量があることを確認し、通話を割り当てます。

主業務量と中断可能な業務量に関するオムニチャネルルーティングルールの概要を次に示します。

次の作業の場合 オムニチャネルが従うルール
主 (中断不可能) オムニチャネルでは、サービス担当者に使用可能な主業務量がある場合にのみ主作業項目が割り当てられます。中断不可能な作業を転送する場合、オムニチャネルではサービス担当者に割り当てられた中断可能な作業は考慮されません。
中断可能 中断可能な作業を転送する場合、オムニチャネルでは主業務量と中断可能な業務量の両方が十分にあるサービス担当者のみが考慮されます。これにより、サービス担当者が電話などの主作業で多忙な場合、オムニチャネルはサービス担当者が対応できない中断可能な作業を割り当てません。

例

次のシナリオでは、サービス担当者が一度に最大 5 件のリードと 5 件のケースを処理できると想定します。そのため、主業務量と中断可能な業務量は、5 つの相対作業単位に設定されます。各リードやケースで消費される作業単位数は 1 です。それぞれのサービスチャネルでは、リードが中断不可能、ケースが中断可能として設定されています。

  • サービス担当の Erika は 5 件のケースに対応しているため、対応可能な中断可能な業務量がありません。ただし、中断不可能なリードについては 100% 対応できます。オムニチャネルでリードが受信されると、Erika に使用可能な主業務量があることが確認され、リードが割り当てられます。
  • サービス担当者の Lucas は 5 件のリードに対応しているため、対応可能な主業務量がありません。ただし、ケースはないため、中断可能な作業については 100% 対応できます。オムニチャネルでケースが受信されると、Lucas に作業項目に対応するための主業務量と中断可能な業務量の両方が十分あるかどうかが確認されます。Lucas には主業務量がないため、オムニチャネルは両方の種別の業務量に対応できる別のサービス担当者を探します。

メモ

ルーティングロジックは、作業が所有者に割り当てられた場合に適用されます。作業項目が転送された後にその項目の項目値が変更された場合、ルーティングロジックは再適用されません。

次の推奨事項を確認してください。

  • オムニチャネルを使用して作業を転送および割り当てます。オムニチャネルは、オムニチャネル設定とサービス担当者の業務量に基づいて最適な割り当て先を見つけます。オムニチャネルフローを使用して、スキルに基づいて作業を転送することもできます。また、営業担当はオムニチャネルウィジェットを使用して、自分に割り当てられた作業を表示および管理できます。
  • 標準オムニチャネルの代わりに拡張を使用します。拡張オムニチャネルは、標準オムニチャネルよりも優れた、担当者とスーパーバイザー向けの広範な環境を備えています。また、今後のオムニチャネル機能は拡張オムニチャネルで開発されます。「標準オムニチャネルと拡張オムニチャネルの比較」および「オムニチャネルの有効化と設定」を参照してください。
  • オムニチャネルによる作業の転送
    オムニチャネルを使用して、作業項目をキュー、サポート担当者、スキル、さらにはEinsteinボット(サポートされるチャネル上)に転送します。ビジネスニーズに応じて、オムニチャネルフローを含め、異なる方法を使用して作業を転送できます。
  • オムニチャネルの設定
    コールセンターで最も適格で対応可能なサポート担当者にあらゆる種別の受信作業項目を転送するようにオムニチャネルを設定します。オムニチャネルは、コンソールと標準アプリケーションの両方にシームレスに統合されます。
  • 標準オムニチャネルから拡張へのアップグレード
    標準オムニチャネルを使用している場合は、拡張オムニチャネルにアップグレードして、すべての高度なオムニチャネル機能をロック解除します。拡張オムニチャネルでは、Voice、ケース、拡張メッセージングなど、より幅広いサービスチャネルがサポートされます。最新のオムニチャネル機能はすべて、拡張オムニチャネル専用に開発されています。たとえば、標準オムニチャネルとは異なり、拡張オムニチャネルでは Agentforce エージェント、オムニモバイル、オムニウォールボード、すべてのチャネル用の 1 つの Inbox、スーパーバイザー用の Command Center for Service のカスタムタブとカスタムアクション、担当者用のオムニサイドバーがサポートされます。
  • オムニチャネル実装のテスト
    オムニチャネルを設定して有効にしたら、実装をテストして正常に動作することを確認します。
  • サポート担当者、キュー、スキルの管理
    組織のサポート担当者、キュー、スキルを管理します。
  • オムニチャネルを使用したリアルタイムチャネルのカスタマーサポートの提供
    標準チャネルと拡張チャネルで、電話、メッセージング、チャットなどの顧客が希望するリアルタイムコミュニケーションの手段を使用して、顧客に対するサービスを行います。オムニチャネルでこれらの種類のサポート要求を受け入れ、管理できます。必要に応じて、顧客をサポートしている間にスーパーバイザーに連絡してサポートを受けることができます。
  • Priority Work By Acceptance Due Date (受け入れ期日別の作業の優先度付け)
    オムニチャネルでは、作業に優先度を付けながら将来の日付を考慮できます。これにより、ルーティングの優先順位付けが強化され、全体的な効率と SLA 管理が改善されます。その結果、スーパーバイザーは SLA コミットメントに関連するチームの作業負荷をより効果的に監視して管理できます。オムニチャネルフローで [承諾期日] を転送作業アクションと共に含めることで、スーパーバイザーが担当者作業の期日を確認できるようにします。システム管理者は、作業項目を送信するときに、目標日を作業項目に割り当てることができます。これは、システム管理者が作業を受け入れる予定日です。システム管理者は、目標日に基づいて、サービス担当者が作業項目を受け入れる必要がある期日を選択できます。
  • 今後のルーティングの作業項目のスケジュール
    [作業項目ルーティングをスケジュール] を使用して、作業項目をすぐにバックログに追加するのではなく、転送する将来の特定の日時を設定します。

サポートされているエディションを表示する。

次の例で、このプロセスの動作について説明します。このサンプルフローは、顧客の注文番号を IVR からの入力として受け入れます。最初の [画面ポップを追加] アクションで、通話者の取引先責任者および取引先レコードが開きます。通話者が注文番号を入力すると、2 番目の [画面ポップを追加] アクションで 3 番目のレコード (注文番号に関連付けられた注文レコード) が開きます。

ヒント フローで複数の [画面ポップを追加] アクションを追加する場合、すべての画面ポップの指示を保存するためにコレクション変数を定義します。

必要なエディション

サポートされているエディションを表示する。

Agentforce エージェントと拡張ボットは、最適化されたルーティングを使用して、ユーザーが会話を開始してから最初の応答を受信するまでの時間を減らします。オムニチャネルは、会話の開始直後にユーザーをエージェントまたはボットに直接接続します。複数のルーティング確認ステップが完了するまで待つ必要はありません。この方法では、接続パスからバックグラウンドステップが削除されるため、より迅速で応答性の高いインタラクションが得られます。

ルーティングのしくみ

以前は、会話をエージェントまたはボットに転送するには、接続を確立する前に一連の確認手順が必要でした。Agentforce エージェントと拡張ボットは常に使用できるため、更新されたルーティング プロセスではこれらの手順がスキップされ、すぐにユーザが接続されます。

更新されたルーティング動作には、次の手順が含まれます。

  • オムニチャネルは待機中のサービスルーティング (PSR) レコードの作成をスキップします。
  • オムニチャネルによって [開封済み (承諾済み)] 状況の AgentWork レコードが作成されます。
  • エージェントまたはボットがすぐに会話に参加します。

ルーティングライフサイクルの詳細の理解

オムニチャネルとルーティングプロセスをさらに掘り下げる場合、2 つの特定のオブジェクト (PendingServiceRouting (PSR) と AgentWork) の理解を深めることをお勧めします。

必要なエディション

サポートされているエディションを表示する。

PSR とは?AgentWork とは?

PSR (PendingServiceRouting) は、オムニチャネルを使用して作業が転送されるときに作成される Salesforce オブジェクトです。PSR は、転送中の作業項目に関するルーティング情報が含まれる一時オブジェクトです。サポート担当者が作業項目を受け入れると、オブジェクトが自動的に作成され、PSR が削除されます。Command Center for Service の [キューのバックログ] タブと [スキルのバックログ] タブに PSR が表示されます。

AgentWork は、ルーティングシステムで作業項目を処理できるサポート担当者が見つかったときに自動的に作成される Salesforce オブジェクトです。これには、作業項目とルーティング状況に関する情報が含まれます。このオブジェクトは自動的に削除されませんが、[状態] 項目が無効な状態になると手動で削除できます。有効な状態は、[割り当て済み] と [オープン済み] です。他のすべての状態は、無効な状態とみなされます。

なぜ気にする必要があるのか?

レコードの所有者がオムニ対応キューに割り当てられた場合、またはレコードがオムニフローの [作業を転送] アクションを使用して転送された場合は、PSR レコードが自動的に作成されます。また、細かい優先度設定など、フローでサポートされていないより複雑な使用事例で、特に作業を再開、転送、または再割り当てするときに、Apex を使用してこのレコードを手動で作成および更新することができます。ただし、絶対に必要でない限り、これを行うことはお勧めしません。

基本的なライフサイクルは?

この最も簡単なシナリオでは、オムニチャネルを使用して作業項目が転送されるときに PSR レコードが作成されます。作業項目を処理できる可能性のあるサポート担当者が見つかると、AgentWork レコードが作成されます。担当者が作業項目を受け入れると、PSR レコードが削除されます。AgentWork レコードが自動的に削除されることはありませんが、無効な状態 ([クローズ済み]、[使用できません]、[却下済み]、[キャンセル]、[移行済み] など) になると手動で削除できます。

PSR と AgentWork の詳細なライフサイクルは?

これらの 2 つのオブジェクトのライフサイクルを完全に理解するには、次の状態図を参照してください。この図には、PSR および AgentWork レコードの作成と削除に加えて、ライフサイクルの別のフェーズの PSR.IsPushed 状態と AgentWork.Status 値も記載されています。

PSR レコードは一時的ですが、AgentWork レコードは明示的に削除されるまで残ります。

AgentWork に同じ作業の複数の作業レコードが含まれる理由は?

作業項目がサポート担当者に割り当てられるたびに、AgentWork でレコードが作成されます。たとえば、担当者が作業項目を別の担当者に転送する場合、各担当者に 1 つずつ、計 2 つのレコードが存在します。作業が新しい担当者に割り当てられ、元の担当者が作業を開いたままにしている場合、AgentWork には作業項目の複数の有効なレコード (担当者ごとに 1 件) が含まれます。作業項目が同じ担当者に複数回転送される場合、AgentWork には同じ担当者と作業項目の複数の作業レコードを含めることができます。

AgentWork レコードが [完了] に設定されるタイミングは?

AgentWork レコードは、次のいずれかのイベントが発生するまで完了しません。

  • タブベースの業務量の場合、割り当てられた営業担当が作業タブを閉じると、レコードが閉じられます。
  • 状況ベースの業務量の場合、作業の状況が [完了] になるか、作業が再割り当てされたときにレコードが完了します。
  • [会話後作業] が有効になっている場合、[会話後作業] 期間が終了したときに作業は完了します。

オムニチャネルでキュー内の作業項目がサポート担当者に割り当てられない理由は?

キューにルーティング設定がない場合、作業はサポート担当者に割り当てられません。キューにルーティング設定が割り当てられていないと、オムニチャネルはキュー内の作業項目を転送しません。

組織での PSR レコードの使用状況と制限は?

組織で現在使用されている待機中のサービスルーティングレコードの数と現在の 1 時間あたりの使用量を表示できます。[設定] から、[クイック検索] ボックスに「オムニチャネル」と入力し、[制限] を選択します。[制限] ページには、現在の待機中のサービスルーティングレコードの使用率と組織の待機中のサービスルーティングレコードの制限も表示されます。

作業業務量について

作業業務量によって、一度に処理できる作業単位が決まります。たとえば、最大 2 つのメッセージングセッションを同時に処理したり、1 つの通話を処理したりできます。システム管理者が業務量を設定します。

必要なエディション

サポートされているエディションを表示する。

システム管理者が設定した業務量がタブベースの業務量か状況ベースの業務量かに応じて、作業の完了方法が異なります。システム管理者がタブベースの業務量モデルを使用するようにサービスチャネルを設定した場合、オムニチャネルは開いているタブに基づいてサポート担当者の業務量を決定します。各タブは、特定の作業項目のセッションです。作業項目を閉じてオムニチャネルインスタンスから削除するには、その項目のタブを閉じます。タブベースの業務量モデルでは、作業タブが閉じられると業務量が解放されます。作業項目がキューに再割り当てされ、別のサポート担当者がその作業項目を受け取った場合、その作業項目はタブを閉じるまでオムニチャネルインスタンスに表示されます。タブベースの業務量モデルは、標準ナビゲーションを使用するアプリケーションでは機能しません。

システム管理者が状況ベースの業務量モデルを使用するようにサービスチャネルを設定した場合、オムニチャネルは、進行中のタブとセッションではなく、受け入れ済み作業の状況に基づいてサポート担当者の業務量を決定します。営業担当がタブを閉じても作業は割り当てられたままです。担当者が対応できない場合でも、その作業はオムニチャネルコンポーネントに表示されます。作業が完了するか、別の担当者に再割り当てされるまで、作業は割り当てられたままで、業務量に反映されます。

サービスレポート

サービスレポートには、Salesforce 組織に直接インストールし、必要に応じてカスタマイズできる事前作成済みのレポートとダッシュボードが用意されています。これらのレポートとダッシュボードには、スーパーバイザーが日常業務に必要とする重要な情報が表示されます。標準のカスタムレポートタイプを使用して、独自のカスタムレポートを作成することもできます。

必要なエディション

サポートされているエディションを表示する。

事前作成済みレポートとダッシュボードには次の利点があります。

パフォーマンス追跡
コンタクトセンターのパフォーマンスを監視して、トップパフォーマーと改善すべき領域を特定します。
効率に関するインサイト
回答速度や平均処理時間など、キューの効率に関するインサイトを取得して、ワークフローを最適化し、待機時間を短縮します。
データ主導の意思決定
リアルタイムデータに基づいて情報に基づいた意思決定を行い、サービス戦略と運用プロセスを強化します。
工数の削減
事前作成済みのレポートとダッシュボードを使用して時間とリソースを節約し、ゼロから作成する必要がなくなります。
サポート要請の削減
カスタムレポートを作成するためのデータモデルを理解するのに役立つサポートの必要性を最小限に抑えます。
  • 事前作成済みレポートおよびダッシュボードのインストール
    コンタクトセンターと担当者のパフォーマンスを追跡するには、Agentforce Service（旧称 Service Cloud）用の事前作成済みレポートとダッシュボードをインストールします。必要に応じて、コピー、変更、削除できます。
  • オムニチャネルのカスタムレポートタイプの作成
    標準のレポートタイプを使用して、エージェントの作業をオムニチャネルでよく使用されるオブジェクトと結合します。ケース種別ごとの作業負荷やチャネル種別ごとの活動時間などのデータに関するカスタムレポートを作成します。

キューへの通話の転送

電話チャネルで通話を転送するには、コンタクトセンターチャネルを編集してから、チャネルのルーティング方法とキューを指定します。

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「Voice」と入力し、使用しているテレフォニーシステムに応じて [Amazon コンタクトセンター] または [パートナーテレフォニーコンタクトセンター] を選択します。
  2. コンタクトセンターを開いて編集します。
  3. このチャネルの通話をキューに転送するには、[ルーティング種別] 項目で [キュー] を選択して、キューを選択します。
  4. [保存] をクリックします。

電話チャネルへのオムニチャネルフローの割り当て

コンタクトセンターには、サポート用とセールス用など、顧客が電話をかけられる複数の電話チャネルを追加できます。各チャネルには独自の電話番号が割り当てられます。電話チャネルで通話を転送するには、コンタクトセンターでチャネルを作成してから、チャネルのルーティング方法を指定します。オムニチャネルフローを使用して通話を動的に転送するには、フローをチャネルに割り当てます。

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「Voice」と入力し、使用しているテレフォニーシステムに応じて [Amazon コンタクトセンター] または [パートナーテレフォニーコンタクトセンター] を選択します。
  2. コンタクトセンターをクリックします。
  3. [コンタクトセンターチャネル] で、[追加] をクリックして電話チャネルを追加します。既存のチャネルを編集することもできます。
  4. チャネルのプロパティを入力します。
    プロパティ 説明
    チャネル名 電話チャネルの名前。
    電話番号 このチャネルで顧客が連絡するために電話をかける電話番号。
    ルーティング種別
    • 通話をキューに転送するには、[キュー] を選択して、キューを選択します。
    • オムニチャネルフローを使用して通話を動的に転送するには、[オムニチャネルフロー] を選択し、フローと代替キューを選択します。フローで通話の転送が失敗すると、通話は代替キューに転送されます。
    • コンタクトセンターチャネルのルーティング方法を指定しないようにするには、[なし] を選択します。このオプションを選択して、Execuite OmniFlow API を使用して通話を転送することもできます。ルーティング手順が指定されていない場合、このチャネルへの通話は失敗します。
  5. [保存] をクリックします。

キューへのチャットの転送

チャットを転送するには、チャットボタンを編集してから、ルーティング方法とキューを指定します。

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「[チャット] ボタンと招待」と入力し、[[チャット] ボタンと招待] を選択します。
  2. 既存のチャットボタンを編集します。
  3. [ルーティング情報] セクションの [ルーティング種別] で [キュー] を選択します。
  4. チャットの転送先となるキューを選択します。キューによってチャットが管理され、優先度が付けられます。キューに割り当てられたサポート担当者がオンラインで業務量がある場合、このボタンを使用できます。
