従業員の管理

HR サービスコンソールを使用して、従業員のレコードと情報にアクセスし、問題を把握して解決します。従業員レコードを作成、更新、削除できます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
従業員を管理する HrServiceWorkspaceHrPsnl

従業員レコードの表示

  1. ナビゲーションメニューから [従業員] ページに移動します。
  2. 従業員の個人取引先レコードページを開いて詳細を確認するには、従業員の名前をクリックします。
    [従業員プロファイルカード] コンポーネントと [従業員の詳細] コンポーネントには従業員情報が表示されます。[従業員の詳細] コンポーネントには、関連オブジェクトのレコードも表示されます。

従業員レコードの作成

従業員レコードを作成するには、まずシステム管理者が組織の個人取引先レコードページで [上司] 項目を設定する必要があります。取引先および取引先責任者オブジェクトに対する「作成」、「参照」、「更新」、および「削除」権限が必要です。

  1. ナビゲーションメニューから [従業員] ページに移動します。
  2. [Create Employee] をクリックします。
  3. [従業員を作成] 画面フローで、プロファイル、取引先責任者、住所、情報、雇用の詳細を入力します。
  4. 変更を保存します。
    従業員レコードと、関連付けられた個人取引先および取引先責任者レコードが作成されます。

従業員レコードの更新

  1. ナビゲーションメニューから [従業員] ページに移動します。
  2. 従業員の個人取引先レコードページを開いて詳細を確認するには、従業員の名前をクリックします。
  3. 従業員プロファイルカードの をクリックし、[更新] をクリックします。
  4. [従業員を更新] 画面フローで、プロファイル、取引先責任者、住所、情報、雇用の詳細を更新します。
    関連付けられた個人取引先レコードと共に従業員レコードが更新されます。

従業員レコードの削除

  1. ナビゲーションメニューから [従業員] ページに移動します。
  2. 従業員の個人取引先レコードページを開いて詳細を確認するには、従業員の名前をクリックします。
  3. 強調表示パネルコンポーネントを従業員の個人取引先レコードページに追加します。
  4. [] をクリックし、[Disable Customer Account] を選択します。
  5. 従業員プロファイルカードの をクリックし、[削除] をクリックします。
  6. 削除アクションを確認します。
    従業員レコード、関連付けられた個人取引先および取引先責任者レコードが削除されます。
    メモ Salesforce で作成した従業員レコードは更新および削除できますが、Workday などの外部人材管理 (HCM) システムに関連レコードがある従業員レコードを変更または削除すると、Salesforce での変更内容が上書きされる可能性があります。関連する従業員レコードが HCM システムで更新されると、Salesforce と HCM システム間の次回のデータ同期で削除済み従業員レコードが復元され、Salesforce で行った変更が上書きされます。

マネージャーによる承認の設定

マネージャーの承認を設定して、会社の意思決定プロセスを合理化します。マネージャーの承認により、構造化された承認システムを実装して説明責任を強化し、すべてのケースアクションが会社のポリシーに従っていることを確認します。

必要なエディション

サポートされているエディションを表示する。

従業員ポータルでは、マネージャーの承認に [Identify Manager (マネージャーを特定)] サブフローと [ケース申請の承認] レコードトリガー承認オーケストレーションが使用されます。

サブフローは、ケースを登録した従業員に関連付けられたマネージャーを識別し、そのマネージャーとケースを共有します。

オーケストレーションは、承認プロセスをトリガーしたケースを作成した従業員のマネージャーに承認申請を送信します。従業員にマネージャーが割り当てられていない場合、要求は送信されません。

  • Identify Manager テンプレートを使用したフローの作成
    ビジネス要件を満たすカスタム ID マネージャーフローを作成します。
  • ケース承認申請テンプレートを使用したオーケストレーションの作成
    ビジネス要件を満たすカスタム承認ケース要求オーケストレーションを作成します。
  • HR サービスの Advanced Approvals の制限
    制限は、それを超えると機能が利用不可になったり、パフォーマンスが調整されたり、使用量の請求料金が適用されたりする境界線です。アカウントエグゼクティブと協力して目標を満たすソリューションを見つけてください。

従業員イネーブルメントプログラムの管理

従業員ポータルで従業員イネーブルメントプログラムを従業員に表示します。サイト開発者と協力して、従業員ポータルで従業員イネーブルメントプログラムと課題を表示する従業員環境を作成します。

必要なエディション

サポートされているエディションを表示する。
  • 従業員イネーブルメントプログラムの作成
    イネーブルメントページとコンポーネントを使用する従業員ポータルテンプレートから従業員ポータルを作成します。その後、プログラムビルダーでプログラムを設定します。
  • テンプレートに基づく従業員イネーブルメントプログラムの作成
    テンプレートでは、課題が定義および整理されます。ビジネスニーズに合わせてテンプレートを選択し、ビジネスプロセスに合わせて変更します。テンプレートの課題にはプレースホルダーがあり、詳細を追加する必要があります。
  • 従業員ポータルのイネーブルメントコンポーネントおよびページ
    エクスペリエンスビルダーの従業員ポータルには、コンポーネントパネルに [イネーブルメント] セクションが含まれ、ページメニューにイネーブルメントページが含まれています。サイト開発者は、これらのコンポーネントとページを使用して、従業員イネーブルメントプログラムと課題を従業員ポータルに表示できます。

Work.com から HR サービスへの移行アプローチ

シナリオと組織のニーズに合った移行方法に従います。

必要なエディション

サポートされているエディションを表示する。

次のいずれかの移行方法を実行します。

  • 方法 1: Work.com から同じ個人取引先レコードを保持し、HR サービスで employee2 レコードと user レコードを作成します。この方法では、Work.com と HR サービスが同じ組織に存在することを確認します。
  • 方法 2: HR サービスで employee2、個人取引先、ユーザーレコードを作成します。このアプローチは、Work.com と HR サービスが同じ組織にあるか異なる組織にあるかに関係なく機能します。

各方法にはプラス面とマイナス面があります。

アプローチの長所と短所 1: 古い個人取引先レコードを保持し、Employee2 およびユーザーレコードを作成する

プラス面 マイナス面

参照の一貫性

同じ個人取引先レコードを保持すると、HR サービスのケースおよびサービスカタログ要求レコードの個人取引先 ID と個人取引先責任者 ID への既存の参照が保持されます。

移行中に既存の個人取引先レコードを使用できない

移行フェーズ中にユーザーが Work.com の既存の個人取引先レコードを使用できない場合があるため、ビジネスプロセスが中断する可能性があります。

連動コンポーネントに対する最小限の変更

個人取引先オブジェクトに依存する標準コンポーネントとカスタムコンポーネントおよびプロセスは、ほとんど変更することなく HR サービスで引き続き動作します。

ダウンタイムの長期化

Employee2 および User オブジェクトの更新中にユーザーが HR サービスの重大なダウンタイムに遭遇し、通常の業務が中断される場合があります。
 

進行中のプロセスを完了するための十分な時間がない

Work.com の進行中のプロセス (サービスカタログの要求や承認など) は、完了までに十分な時間がないために失敗します。これらのプロセスは、HR サービスには存在しないか、異なる可能性があります。

アプローチの長所と短所 2: Employee2、個人取引先、ユーザーレコードの作成

プラス面 マイナス面

既存のワークフローを中断させない

個人取引先、従業員 2、ユーザーレコードを作成すると、Work.com の既存のワークフローに影響が及ばないため、HR サービスを Work.com と共に実行できます。新しいレコードにより、ビジネスプロセスの継続性が確保されます。

オブジェクトの作成と更新の追加作業

この方法では、HR サービスで Employee2、個人取引先、およびユーザーオブジェクトの作成と更新が必要です。これには時間がかかり、リソースを大量に消費する可能性があります。

ダウンタイムの短縮

Work.com と HR サービスを個別に運用することでダウンタイムを最小限に抑え、Work.com の現在の業務への影響を最小限に抑えて移行を進めることができます。

  

進行中のプロセスを完了するための十分な時間

移行によって既存の Work.com の機能に影響が及ぶことはなく、Work.com で進行中の要求またはプロセスを完了するための十分な時間が確保されます。

  

使用事例と Work.com 実装の複雑さを評価した後で、方法を選択してください。

Work.com から HR サービスへの移行 (CCP ユーザー向け)

HR サービスは Work.com の包括的な再設計です。Work.com から HR サービスに切り替えるには、Work.com データモデルから HR サービスデータモデルへのデータの移行が必要です。

必要なエディション

サポートされているエディションを表示する。
  • Work.com と HR サービスのデータモデル
    Work.com と HR サービスのデータ モデルの違いを確認します。
  • Work.com から HR サービスへの移行アプローチ
    シナリオと組織のニーズに合った移行方法に従います。
  • Work.com から HR サービスへの移行アプローチの実装
    既存の Workday またはカスタム MuleSoft インテグレーション、CSV インポート、またはデータ処理エンジン、DBScript、任意のジョブを使用するカスタム実装を使用して、移行アプローチを実装します。
  • Work.com から HR サービスへの移行への従業員の誘導
    従業員に適切なガイダンスを提供し、移行プロセスを適切に進めます。

Salesforce と Workday のインテグレーション

Salesforce を Workday と統合して、従業員名、取引先責任者の詳細、関連付けられたロケーション、組織、 レポートマネージャーなどの従業員データを Workday から直接 Salesforce にインポートします。自動作成設定を有効にしてユーザーをプロビジョニングします。Workday からインポートされたすべての従業員レコードは Salesforce に保存されます。連絡先情報は個人取引先に、従業員の詳細は従業員オブジェクトに保存されます。Workday のロケーションと組織は、Salesforce のロケーションオブジェクトと内部組織単位オブジェクトに保存されます。従業員のレポートマネージャー情報は、従業員の個人取引先の [上司] 項目に保存されます。

必要なエディション

Employee オブジェクトの API 参照名は Employee2 です。

サポートされているエディションを表示する。

Salesforce と Workday のインテグレーションを有効にする前に、次の作業を行う必要があります。

  • MuleSoft Direct インテグレーションへのアクセスを有効化します。
  • 個人取引先を有効化します。次に、[個人取引先] ページで、個人取引先の [上司] 項目を有効化します
  • OAuth 2.0 クライアントログイン情報フローの接続アプリケーションを設定します。
  • Workday からの従業員のインポート
    Workday から Salesforce に従業員の詳細をインポートするには、インテグレーション機能を有効にして 2 つのプラットフォーム間の接続を確立します。
  • Workday からインポートされた従業員レコードの表示
    Workday から従業員をインポートしたら、Salesforce で連絡先情報や直属の上司など、従業員の詳細を表示します。
  • 従業員の経費管理アプリケーションの有効化
    サービスプロセスまたはAgentforceを使用して従業員が従業員ポータルで経費レポートを直接送信できるようにするには、組織でWorkday Expense Management MuleSoftインテグレーションアプリケーションを有効にします。
  • 従業員の休暇管理の有効化
    Agentforce またはサービスプロセスを使用して従業員が従業員ポータルで休暇申請を送信し、休暇残高を直接追跡できるようにするには、組織で Absence Manager インテグレーションアプリケーションを有効にします。
  • 従業員の支払割り当てプロセスの有効化
    従業員は、従業員ポータルのサービスプロセスまたは Agentforce を使用して、複数の口座振替を作成および管理し、給与を口座間で分割できます。
  • 従業員のプロファイル管理の有効化
    Agentforce またはサービスプロセスを使用して従業員が従業員ポータルから直接プロファイルの詳細 (名前や連絡先情報など) を更新できるようにするには、組織で従業員プロファイル更新インテグレーションアプリケーションを有効にします。変更は自動的に Workday と同期されます。
  • ユーザーに必要なプロファイルをプロビジョニングし、ユーザーレコードを自動作成
    必要なプロファイルと権限を割り当てて、インポートされたすべての従業員を一括でプロビジョニングします。最初のプロビジョニングプロセスを完了したら、プロビジョニングを再実行することなく、Salesforce で新規従業員エントリのユーザーレコードを自動的に作成します。
  • 状況別の従業員プロファイルの同期
    Workday と Salesforce 間で従業員プロファイルを従業員の状況別に同期するには、Salesforce 組織で [Employment Status Data Import (雇用状況データインポート)] アプリケーションを有効にします。Workday 従業員の状況を対応する Salesforce の状況にリンクして、正確な同期を確保します。[Employment Status Data Import (雇用状況データインポート)] アプリケーションでは、終了日、レポーティングマネージャー、住所の変更など、Workday の他の従業員詳細も Salesforce プロファイルで更新されます。

  5. [ツールボックス] の [マネージャー] タブで、userId および routableId の入力変数を作成します。
    userId 変数には、フローに渡されるユーザ ID が保存されます。routableId には、現在のメッセージングセッションのメッセージングセッションレコードのルーティング可能 ID が保存されます。

    2. [オブジェクト] ドロップダウンリストから、[ユーザー] を選択します。

    5. [保存するレコード数] セクションで、[最初のレコードのみ] を選択します
    6. [レコードデータの保存方法] セクションで、[すべてのフィールドを自動的に保存] を選択します。
  9. [連絡先を取得] 要素で、[ユーザーを取得] 要素から受信したユーザーレコードを使用して、関連する連絡先レコードを取得します。
    1. [データソース] セクションで、[Salesforce オブジェクト] を選択します。
    2. [オブジェクト] ドロップダウンリストで [取引先責任者] を選択します。

    5. [保存するレコード数] セクションで、[最初のレコードのみ] を選択します
    6. [レコードデータの保存方法] セクションで、[すべてのフィールドを自動的に保存] を選択します。
  10. [メッセージングセッションを取得] 要素で、フローに渡された routableID を使用して現在のメッセージングセッションレコードを取得します。
    1. [データソース] セクションで、[Salesforce オブジェクト] を選択します。
    2. [オブジェクト] ドロップダウンリストから、[メッセージングセッション] を選択します。
    3. [条件の要件] ドロップダウンリストから、[すべての条件に一致 (AND)] を選択します。

    5. [保存するレコード数] セクションで、[最初のレコードのみ] を選択します
    6. [レコードデータの保存方法] セクションで、[すべてのフィールドを自動的に保存] を選択します。
  11. [メッセージングセッションを更新] 要素で、関連する取引先責任者レコードの取引先責任者 ID、氏名、関連取引先 ID を使用して現在のメッセージングセッションレコードを更新します。
    1. [更新するレコードを検索してその値を設定する方法] セクションで、[レコードを識別する条件を指定し、項目を個別に設定] を選択します。

    ドロップダウンリストには、10 人の直属部下のみが表示されます。デフォルトでは、このページの [従業員名] ドロップダウンリストに最初の直属部下の進行状況情報が表示されます。この情報には、プログラム名、説明、期日、完了率が含まれます。特定の詳細を表示するには、完了状況または登録種別でプログラムを絞り込みます。

Web-to-ケースの設定

従業員が会社の Web サイトのフォームからケースを送信できるようにします。Web-to-ケースでは、フォームから送信された情報からケースが自動的に作成されます。Web-to-ケースを使用すると、従業員は従業員ポータルサイトにログインせずにサポートを求めることができます。

必要なエディション

サポートされているエディションを表示する。

Web-to-ケースを設定するには、次の作業を行います。

  • Web フォームに含めるケース項目を選択します。
  • 自動確認通知用の顧客メールテンプレートを作成します。
  • 受信ケースを割り当てるには、1 つ以上のケースキューを作成します。
  • Web フォームを使用して作成されたケースの所有者を特定します。
  • Web-to-ケースを有効にします。
  • Web フォームを生成します。
  • reCAPTCHA を使用してスパムを防止します。

「Web-to-ケースを使用した Web フォームの提供」を参照してください。
