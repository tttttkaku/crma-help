HR サービスコンソールの機能

ホームページは、ログイン後のメインのランディングページです。ホームページでは、サービス担当者に割り当てられたケースの概要をすばやく確認できます。

必要なエディション

サポートされているエディションを表示する。

ホームページの主な機能は次のとおりです。

  • 従業員ポータルダッシュボード (1): サービス担当者に割り当てられたケースの概要が視覚的に表示されます。このダッシュボードには、次のレポートのケース情報が表示されます。
    • My Cases (私のケース): サービス担当者に割り当てられたケースの数。
    • Cases By Priority (優先度別のケース数): 優先度別のケース数。
    • Cases By Type (種別ごとのケース数): 種別ごとのケース数。
    • Average Resolution Time (平均解決時間): ケース発生源別のケースの平均解決時間。
    レポートを表示するには、ダッシュボードタイルの [レポートを表示] をクリックするか、ナビゲーションメニューから [レポート] ページを開いてレポートをクリックします。
    メモ 関連するレポートを表示するようにダッシュボードを編集できるのは管理者のみです。
  • [私のケース] リストビュー (2): リストビューには、自分に割り当てられた最近のケースが表示されます。ケースをクリックすると、ケースレコードページが開きます。

HR サービスカタログライブラリ

需要の高い HR ニーズに対応する標準受入および履行ワークフローのライブラリを従業員に提供することで、価値実現までの時間を短縮します。これらの事前設定済みのサービステンプレートは、給与、休暇申請、給付などの一般的なシナリオを対象としているため、プロセスをゼロから設計することなく、プロフェッショナルなセルフサービス環境をリリースできます。これらのワークフローは、内部履行のスタンドアロンプロセスとして実行することも、事前作成済みコネクタを使用してサードパーティの HR システムにリンクすることもできます。

メモ サービスカタログテンプレートの事前作成済み受入フローと履行フローはローカライズされていません。フロー画面の表示ラベルは、ユーザーのロケールに関係なく英語で表示されます。
  • コネクタベースの HR サービステンプレート
    これらのテンプレートを使用して、コアワークフォースアクションを外部の記録システムに直接自動的に同期します。従業員と HR サービス担当者に、事前設定されたコネクタを介してデータをサードパーティの HR、ID、財務プラットフォームにシームレスに渡す構造化された受入フォームを提供します。これにより、統合された HR 技術スタック全体でデータの一貫性が即座に確保され、手動データ入力エラーが最小限に抑えられ、自動化された下流ワークフローがトリガーされます。
  • 一般的な HR サービステンプレート
    構造化されたサービステンプレートを使用して、標準のワークフォース要求、個人プロファイルの更新、および業務ワークプレイスワークフローを管理します。一貫したデータ収集により、チームは手動履行またはカスタムフローで要求を効率的に転送できます。

CCP から UEL への移行に関する FAQ

CCP から UEL への移行に関するよくある質問 (ロールバック、ダウンタイム、無効なユーザー、段階的なロールアウト、Sandbox テスト、エラー処理、移行後のライセンスの動作など) を確認します。

  • 移行をロールバックできますか?

    いいえ。移行プロセスは意図的に一方向であり、元に戻すことはできません。ユーザーのライセンスと UserType を CCP から UEL に移行すると、元に戻すことはできません。このため、UEL に移行する前に、プロセスを徹底的にテストし、移行前のすべての設定を完了しておくことが重要です。

  • ダウンタイム中の従業員への影響は?

    統合従業員ライセンスの移行を有効にすると、従業員がログインできないシステムダウンタイムが発生します。ビジネスの中断を最小限に抑えるために、管理者は専用の稼働開始期間を慎重に調整してスケジュールする必要があります。さらに、移行が完了すると、すべての有効なユーザーセッションが終了し、UserInfoキャッシュがクリアされます。これにより、更新されたライセンスとアクセス設定をシステムで適用できるように、従業員は再度ログインする必要があります。

  • 移行時に無効なユーザーはどうなるでしょうか。

    プラットフォーム移行ユーティリティでは、無効なユーザーの CCP から UEL への移行はサポートされていません。このジョブは、履歴メタデータを保持しながら有効な ID を変換するために特別に設計されています。

  • 段階的な移行は可能ですか?

    いいえ。段階的または部分的な移行はできません。UEL 移行を有効にすると、組織レベルで適用されます。有効にすると、この設定は永続的になります。つまり、すべての新規ユーザーは UEL モデルを使用する必要があり、従来の CCP 従業員ユーザーの作成や追加はできなくなります。

  • 移行プロセス中にユーザーは無効化されますか?

    いいえ。移行中にユーザーは無効化されません。このツールは、ユーザー種別を外部 (C) から標準内部 (S) に移行するインプレース ID 変換を実行します。このプロセスでは、ユーザーを無効化することなく、UserId、Username、Email、および関連付けられたすべてのレコード所有権または監査証跡 (CreatedById、LastModifiedById など) が意図的に保持されます。

  • 移行ツールは Sandbox で使用できますか?

    はい。移行プロセス全体を本番にリリースする前に Sandbox 組織でテストすることをお勧めします。これにより、カスタムプロファイル、権限、共有ルールを事前に検証できます。

  • エラーが発生した場合はどうすればよいか?

    移行ジョブは、200 件のレコードの制御されたバッチで実行される非同期バックグラウンドプロセスとして動作します。エラーが発生した場合は、次の方法を使用してトラブルシューティングします。

    • Review Track Migration Status (追跡移行状況の確認): 管理者は、リアルタイムの追跡インターフェイスと、実行中に失敗したすべての従業員 (従業員 ID を含む) を表示する専用のリストビューにアクセスできます。
    • 障害のフェーズの特定: 基盤となるロジックはフェーズに分割されています (権限セットの削除、DB の直接更新、グループの再割り当てなど)。プロセスが停止した正確なステップを特定する詳細な失敗理由が表示されます。
    • 修正と再試行: 根本的な操作またはデータの問題が解決されると、管理者は組み込みメカニズムを使用して失敗したレコードを再試行できます。再試行メカニズムは、ワークフロー全体を再開するのではなく、特定の障害点から自動的に再開されます。試行するたびに、簡単に追跡できるように監査済みバージョン履歴が作成されます。
  • 移行後に CCP ライセンスはどうなりますか?

    ライセンスの使用方法によって異なります。従業員プロファイルの場合:

    • 移行が完了したら、従業員プロファイルに割り当てられたすべての CCP ライセンスをキャンセルします。これらは自動的に無効化されません。
    • その他の使用事例: アクションは必要ありません。その他のすべての CCP ライセンスは、中断することなく引き続き正常に機能します。
  • 統合従業員ユーザが Slack での認証や Agentforce Agents for Slack へのアクセスに失敗する理由は?

    Slack 認証および Agentforce Agent アクセスを機能させるには、統合従業員ユーザープロファイルの「API の有効化」システム権限を有効にします。

    この権限を有効にするには、次のいずれかの方法を選択します。

    • 標準プロファイルをコピーします。統合従業員ユーザー標準プロファイルをコピーし、コピーしたプロファイルで「API の有効化」権限を手動で有効にします。
    • 権限セットの作成: API の有効化が有効になっている権限セットを作成し、統合従業員ユーザーに割り当てます。

    移行が成功したら、移行した従業員ユーザーに必要な権限セットを割り当てます。「従業員イネーブルメントプログラム統合従業員ユーザー」権限セットと「従業員ハブ統合従業員ユーザー」権限セットを割り当てることをお勧めします。

Work.com から HR サービスへの移行 (UEL ユーザー向け)

HR サービスは Work.com の包括的な再設計です。Work.com から HR サービスへの移行には、Work.com データモデルから HR サービスデータモデルへのデータの移行が含まれます。移行では、PUL から PUL へのユーザーマッピングが保持されます。PUL (プラットフォームユーザーライセンス) ユーザーは UEL (統合従業員ライセンス) ユーザーに移行されません。

HR サービスへの移行

Work.com 従業員データを HR サービスに移行するためのライセンス、権限、移行ツールを設定します。

  1. 必要なライセンスと権限セットを有効にします。
    1. Data Cloud アドオンライセンスを有効にします: GenieDataPlatformStarter。
    2. SvcCloudEmpHubEmpUsrAddOn、UnifiedEmployeeAddOn、SvcCloudEmpHubHrStdAddOn のライセンスを追加します。
    3. 「Employee Hub Unified Employee User(従業員ハブ統合従業員ユーザー)」権限セットをすべてのWork.com従業員ユーザーに割り当てます。
    4. EmployeeManagement 権限セットライセンスを管理ユーザーに追加します。
    5. [設定] の [クイック検索] ボックスに「権限セット」と入力し、[権限セット] を選択します。
    6. [Data Cloud Salesforce コネクタ] 権限セットを選択します。
  2. 従業員オブジェクトの項目レベルセキュリティを設定します。
    1. [設定] から、[オブジェクトマネージャー] タブに移動します。
    2. オブジェクトのリストから、[従業員] を選択します。
    3. 左ペインから、[Fields & Relationships (項目とリレーション)] を選択します。
    4. [EmployeeNumber] 項目を選択します。
    5. [Set Field Level Security] をクリックします。
    6. [Analytics Cloud Integration User に参照可能] を選択し、[保存] をクリックします。
    7. EmployeeStatus、StatusAsOf、WorkerType 項目に対してステップ d ～ f を繰り返します。
  3. データ処理エンジンを設定します。
    1. [設定] から、[クイック検索] ボックスに「データ処理エンジン」と入力し、[データ処理エンジン] を選択します。
    2. [Migrate Work.com Employees to HR Service (Work.com 従業員の HR サービスへの移行)] を選択します。このテンプレートを編集して、個人取引先または Employee2 レコードの項目を追加および削除できます。
    3. [保存] ドロップダウンから、[別名で保存] を選択します。
    4. テンプレートの名前と説明を入力し、変更を保存します。
    5. データ処理エンジン (DPE) を有効化します。この DPE を編集して項目を追加または削除できます。データ処理エンジンでの DPE のしくみについての詳細を参照してください。
  4. テンプレートからフローをインストールします。
    1. [設定] から、[クイック検索] ボックスに「フロー」と入力し、[プロセスの自動化] で [フロー] を選択します。
    2. [フロー] ページで、[新規フロー] をクリックします。
    3. [新規自動化]ウィンドウの[頻繁に使用]で、[View All Automations]をクリックします。
    4. [Migrate Work.com Employees to HR Service (Work.com 従業員を HR サービスに移行)] テンプレートを検索して選択します。
    5. フローの表示ラベル、API 参照名、ステップ 3.d で作成した DPE API 参照名を入力し、[次へ] をクリックします。
    6. アプリケーション名を入力し、[作成] をクリックします。
  5. [設定] から、[クイック検索] ボックスに「フロー」と入力し、[プロセスの自動化] で [フロー] を選択します。
  6. フローのリストから、ステップ 9.c で作成したフローを開きます。
  7. フローを実行します。このアクションにより、移行プロセスが開始されます。DPE によって Employee_Home という名前のデータストリームが作成されます。
  8. [データストリーム] から、[Employee_Home] を選択します。
  9. [今すぐ更新] をクリックし、[フル更新] を選択して、[今すぐ更新] をクリックします。
  10. 移行の監視とトラブルシューティング:

    2. DPE 実行インスタンスを選択します。[ToDo] タブにはジョブが表示され、[失敗した書き戻しレコード] タブには失敗が表示されます。

移行に関する FAQ

Work.com から HR サービスへの移行に関するよくある質問 (機能の同等性、ライセンス、段階的なロールアウトのサポート、データモデルの動作など) を確認します。

  • なぜ移行する必要があるのですか?

    HR サービスは、Work.com の包括的な再設計を表します。移行することで、コアワークフローの機能と同等の強力な統合従業員エクスペリエンスを実現できます。これには、更新された堅牢なデータ モデルを活用しながら、統合従業員ポータル、HRサービス デスク、Agentforceエージェント、統合サービス カタログなどの最新の機能に移行することも含まれます。

  • Work.comのすべての機能はHRサービスで使用できますか?

    次の表は、現在の Work.com 機能と対応する HR サービス機能を比較したものです。

  • Work.comのお客様は、従業員向けAIエージェントをスタンドアロンSKUとして購入できますか。

    はい。顧客はスタンドアロン SKU として購入できます。ただし、この SKU では Agentforce ユーザーライセンス (AUL) が使用されるため、Work.com の移行はサポートされていません。そのため、新規ユーザーを作成する必要があり、履歴データ (過去のケースなど) は保持されません。移行ツールは、このデータの損失を防止するように設計されているため、LPP または LPS パスが推奨されます。

  • Work.com移行に使用できるSKUを教えてください。

    Work.com の移行は、Lightning Platform Plus (LPP) および Lightning Platform Starter (LPS) SKU でのみ使用できます。HR サービス機能を使用するには、AI Agent for Employee アドオンも購入する必要があります。

  • 従業員を PUL から UEL に移動するパスはありますか?

    いいえ。現在、従業員をプラットフォームユーザーライセンス (PUL) から統合従業員ライセンス (UEL) に移行するための直接のパスはありません。既存の移行ツールは従業員間 2 データモデルの移行を目的として設計されており、ライセンスの移行はサポートされていません。

  • 移行ツールにアクセスするために必要なアドオンライセンスは?

    ビジュアルデータ処理エンジン (DPE) 移行ツールを正常に設定、実行、管理するには、次のライセンスが必要です。

    • Admin Migration License (管理者移行ライセンス): 移行を実行する管理者ユーザーに EmployeeManagement 権限セットライセンス (PSL) が必要です。
    • 前提条件ライセンスチェック: 組織が基盤となる EmployeeManagementAddOn ライセンスをすでに所有していることを確認します。
  • 段階的な移行は可能ですか?

    段階的な移行は完全にサポートされています。移行戦略は、デュアルデータモデル戦略/データ共存モデルに基づいて明示的に構築されます。新しい Employee2 レコードでは、従来の従業員レコードへのバックエンド外部キーの参照が直接維持されるため、下位互換性が保持されます。従来の Work.com オブジェクトは完全にそのままで有効なままであるため、既存のビジネスロジック、レポート、インテグレーションを中断することなく、ユーザーと操作を長期にわたって段階的に安全に移行できます。

  • 既存のマネージャーのデータと割り当てはどうなりますか?

    組織階層は自動的に保持されます。新しい Employee2 レコードに対するマネージャの割り当てと更新は、統合されたマネージャプロビジョニング一括処理ジョブによって完全に処理されます。

  • 既存のWork.comデータモデルはどうなりますか?

    既存のデータアーキテクチャは保持されますが、分離されます。

    • 従来のWork.comオブジェクトは再構成または上書きされません。
    • これらは履歴レコードとしてそのまま残りますが、HR サービスは新しい Employee2 ベースのデータモデルのみを使用します。
  • カスタムコンポーネントは移行後に機能しますか?

    いいえ。カスタムコンポーネントは移行後に自動的に機能しません。非推奨の Work.com 機能をサポートされている HR サービス機能に置き換える必要があります。カスタムコンポーネントの場合、移行後の動作をテストおよび検証する必要があります。場合によっては、同等の代替コンポーネントが使用できないことがあります。
