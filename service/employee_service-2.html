従業員の詳細コンポーネントの設定

従業員ポータルサイトで、従業員情報を表示するように [私のプロファイル] ページの [従業員の詳細] コンポーネントを設定します。User、PersonAccount、Employee2 オブジェクトから項目を追加できます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
従業員の詳細コンポーネントにアクセスする コミュニティユーザーの従業員ハブ

[従業員の詳細] コンポーネントでこれらの項目を従業員に表示するには、項目の項目レベルセキュリティを [参照可能] に設定します。

  • 別メールのアドレス
  • 状況の終了日
  • 従業員種別
  • 雇用種別
  • 内部組織単位

「Set Field-Level Security for a Field on All Profiles (すべてのプロファイルの項目レベルセキュリティの設定)」を参照してください。

  1. [設定] から、[クイック検索] ボックスに「すべてのサイト」と入力し、[すべてのサイト] を選択します。
  2. 従業員ポータルサイトの名前の横にある [ビルダー] をクリックします。
  3. ホームページで、ビルダーページメニューの [ユーザー] を展開します。
  4. [私のプロファイル] をクリックします。
  5. ビルダーのキャンバスで、[Employee Details (従業員の詳細)] をクリックします。
  6. User、PersonAccount、および Employee2 オブジェクトからさらに項目を追加するには、[Employee Details (従業員の詳細)] ウィンドウで [選択] をクリックします。
  7. [私のプロファイル] ページに従業員の円形写真を表示するには、[円形写真を表示] を選択します。
    メモ 円形の写真に変更すると、従業員が写真を再アップロードしなければならない場合があります。

従業員プロファイルカードコンポーネントの設定

HR サービスコンソールの [個人取引先レコード] ページには、従業員プロファイルカードコンポーネントが含まれます。このコンポーネントでは、サービス担当者に従業員情報が表示されます。コンポーネントをケース、メッセージングセッション、音声通話レコードページに追加することもできます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
従業員プロファイルカードコンポーネントを設定する HrServiceWorkspaceHrPsnl

従業員プロファイルカードコンポーネントを設定する前に、個人取引先を有効にします。「Enable Person Accounts (個人取引先の有効化)」を参照してください。

  1. Lightning アプリケーションビルダーで、個人取引先レコードページを編集します。
  2. キャンバスで、[従業員プロファイルカード] コンポーネントを選択します。
  3. コンポーネントのプロパティペインで、個人取引先と従業員のコンパクトレイアウトを指定します。
    コンポーネントにコンパクトレイアウトに含まれる項目が表示されます。デフォルトでは、[個人取引先コンパクトレイアウト] 項目で [従業員ポータルのデフォルト] が選択されています。このコンパクトなレイアウトは、HR サービスコンソールで標準で使用できます。個人取引先が有効になっておらず、Service Cloud Employee Hub アドオンライセンスがプロビジョニングされていない場合、[個人取引先コンパクトレイアウト] 項目でシステムデフォルトのコンパクトレイアウトが選択されます。

ナビゲーションタイルコンポーネントの設定

  3. [ホーム] から、ビルダーのキャンバスで [ナビゲーションタイル] をクリックします。
  4. プロパティエディターで、コンポーネントのプロパティを設定します。
    プロパティ 詳細
    ナビゲーションタイルの編集 ナビゲーションタイルに表示されるアクションをクリックして編集します。
    デフォルトのテーマの色を使用 ナビゲーションタイルのデフォルトのテーマの色を使用する場合に選択します。
    タイル形式 クリックすると展開します。
    背景色 タイルの背景の色を設定します。
    境界線の半径 0 ～ 50 ピクセルの値を入力します。
    フロート表示境界線の色 フロート表示状態のタイルの境界線の色を設定します。
    フォーカスの境界線の色 フォーカス状態のタイルの境界線の色を設定します。
    ドロップシャドウを表示 タイルの下にドロップシャドウを表示する場合に選択します。
    タイルの幅 タイルの幅をピクセル単位で入力します。
    表示ラベル形式 クリックすると展開します。
    表示ラベルの色 表示ラベルのフォントの色を設定します。
    表示ラベルのフォントサイズ 表示ラベルのフォントサイズをピクセル単位で入力します。
    表示ラベルの水平配置 タイル内の表示ラベルの横方向の配置を指定します。
    表示ラベルを上に表示アイコン アイコンの上にタイルの表示ラベルを表示する場合に選択します。
    アイコン形式 クリックすると展開します。
    アイコンの高さ アイコンの高さをピクセル単位で入力します。
    アイコンの幅 アイコンの幅をピクセル単位で入力します。

個人取引先の [レポート先] 項目の設定

マネージャーを従業員に関連付けるには、個人取引先オブジェクトの [上司] 項目を有効にします。これは、HR サービスの設定に必要なステップです。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
個人取引先オブジェクトの [報告先] 項目を設定する HrServiceWorkspaceHrPsnl

前提条件として、個人取引先オブジェクトを有効にして、組織で [上司] 項目を使用可能にします。[個人取引先を有効化] を参照してください。

  1. [個人取引先] ページレイアウトに [レポート先] 項目を追加します。
    「高度なページレイアウトエディターのユーザーインターフェース要素」を参照してください。
  2. [設定] から、[クイック検索] ボックスに「個人取引先」と入力し、[個人取引先] を選択します。
  3. [個人取引先のレポート先フィールド(Reports To Field on Person Account)] を有効にします。

テンプレートに基づく従業員イネーブルメントプログラムの作成

テンプレートでは、課題が定義および整理されます。ビジネスニーズに合わせてテンプレートを選択し、ビジネスプロセスに合わせて変更します。テンプレートの課題にはプレースホルダーがあり、詳細を追加する必要があります。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
従業員イネーブルメントプログラムを作成する

「イネーブルメントプログラムの設計および提供」

および

「エクスペリエンスの作成および設定」または「アプリケーションのカスタマイズ」またはサポート対象 Experience Cloud サイトのメンバー
  1. アプリケーションランチャーから、[イネーブルメントプログラム] を見つけて選択します。
  2. イネーブルメントプログラムページから [新規] をクリックします。
  3. 促されたら、プログラム種別として [Employee Enablement Program (従業員イネーブルメントプログラム)] を選択し、[次へ] をクリックします。

  4. テンプレートをプレビューするには、テンプレートを選択して課題プレースホルダーをスクロールします。
  5. [作成] をクリックします。
  6. 従業員が使用できるようにプログラムをカスタマイズし、公開して従業員が使用できるようにします。
  • 従業員イネーブルメントプログラムテンプレート
    テンプレートを使用して、従業員のオンボーディング、従業員のオフボーディング、医療休暇、職場復帰、再配置などの一般的なトピックの従業員イネーブルメントプログラムを作成します。

テンプレートからの HR サービスエージェントの作成

HRサービスエージェントは、必要に応じてサービス要求を処理し、担当者にエスカレーションすることで、従業員をインテリジェントにサポートします。Agentforce HR サービスエージェントテンプレートを使用して、一般的な従業員サポートケースと要求を解決するように設計されたエージェントを作成します。このテンプレートは、Agentforce Employee Agent（AEA）も必要な場合にのみ使用できます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
HR サービスエージェントを構築および管理する

「Agentforce サービスエージェントを管理」および「AI エージェントの管理」

または

「アプリケーションのカスタマイズ」

開始する前に、Einstein生成AI、Agentforceの有効化、Einstein Trust Layerの設定を行います。

  1. [設定] で、[Agentforce Agents] を見つけて選択します。
  2. [新規エージェント] をクリックします。
  3. [テンプレートから作成] を選択します。エージェントを作成する HR サービスエージェントテンプレートを選択し、[次へ] をクリックします。
  4. テンプレートに付属するトピックを確認します。このトピックとアクションは後でカスタマイズできますが、ユースケースに適用されないトピックやアクションがある場合は削除します。続いて、[次へ] をクリックします。
  5. メモ Agentforce HR サービスの多言語サポートは、パイロットまたはベータサービスです。このサービスには、Agreements - Salesforce.com のベータサービス条件、またはお客様が締結した場合は書面による統合パイロット契約、および製品条件ディレクトリの適用条件が適用されます。このパイロットサービスまたはベータサービスは、お客様ご自身の裁量でご利用ください。
    システムメッセージや言語設定など、エージェントの設定を定義します。
    これらの設定によって、エージェントが会話でどのように振る舞い、どのように自分自身を提示するかが決まります。
  6. [Answer Questions with Knowledge (ナレッジを使用して質問に回答)] アクションでエージェントの応答をグラウンディングするデータソースを選択し、[作成] をクリックします。
    使用可能なデータソースを使用しない場合は、HR サービスエージェントを特定の記事またはアップロードされたフィールドに制限するライブラリを作成できます。「エージェントへのデータライブラリの割り当て」を参照してください。
  7. トピック、アクション、およびその他のエージェントアセットを使用してエージェントを設定します。
    [Get Leave Balance (休暇残高を取得)]、[Submit Leave Request (休暇申請を送信)]、[Update Employee Profile (従業員プロファイルを更新)]、[Get Direct Deposit Details (口座振替の詳細を取得)]、[Submit Direct Deposit Details (口座振替の詳細を送信)] アクションを設定するときに、指定ログイン情報を更新します。
  8. Agentforce Builder でエージェントをテストし、エージェントのパフォーマンスが期待どおりで、セキュリティ標準に準拠していることを確認します。
    HR サービスエージェントは、Agentforce Builder のエージェント ユーザ コンテキストで、メッセージング チャネルにリリースされた場合と同じコンテキストで動作します。そのため、設計時テストには、リリース時の HR サービスエージェントの動作が反映されます。
  9. エージェントを有効化します。

ケース承認申請テンプレートを使用したオーケストレーションの作成

ビジネス要件を満たすカスタム承認ケース要求オーケストレーションを作成します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Flow Builder でフローを開く、編集または作成する 「フローの管理」

  3. [新規フロー] ウィンドウで、[テンプレートを使用] を選択します。

従業員サービス要請オーケストレーションの承認の設定

このオーケストレーションにより、サービス要請の承認申請が従業員のマネージャーに送信されます。マネージャーが承認アクションを実行すると、オーケストレーションは Workday の承認状況を更新し、従業員に通知します。作成した休暇申請およびプロファイルサービスプロセスの更新の設定手順に従います。

  1. [設定] で、[フロー] を見つけて選択します。
  2. [従業員サービス要請を承認] フローをクリックします。
  3. [Save As New Orchestration] をクリックします。
  4. 必要な詳細を入力し、変更を保存します。
  5. 開始要素で、[編集] をクリックします。
  6. サイドバーで、プレースホルダー開発者名を、作成したサービスプロセスの API 参照名に置き換えて [数式] 項目を編集します。
  7. [Update Manager Decision] 要素をクリックし、[Edit Element] をクリックします。
  8. サイドバーの[実行するアクションを選択]セクションで、作成した[従業員サービス要請を処理]フローを選択します。
    次の入力値を設定します。
    • approvalDecision: {!AssignCaseToManager.Outputs.approvalDecision}
    • integrationDefinitionApiName: <インテグレーション定義の名前>
    • rejectionMessage: {!AssignCaseToManager.Outputs.approvalComments}
    • serviceRequestDetails: {!$Record}
  9. [有効化] をクリックします。

従業員ポータルサービスカタログコンポーネントの設定

従業員ポータルサイトで、従業員ポータルサービスカタログコンポーネントを設定して [サービスカタログ] ページをカスタマイズします。従業員はこのコンポーネントを使用してサービス要求を送信します。

  1. [設定] から、[クイック検索] ボックスに「すべてのサイト」と入力し、[すべてのサイト] を選択します。
  2. 従業員ポータルサイトの名前の横にある [ビルダー] をクリックします。
  3. [ホーム] から、ビルダーページメニューの [サービスカタログ] をクリックします。
  4. ビルダーのキャンバスで、[Employee Hub Service Catalog] をクリックします。
  5. [レコード ID] 項目に、先ほどメモした商品カタログ ID を入力します。
    [レコード ID] フィールドには、デフォルトで{!recordId}が入力されます。従業員ポータルサービスカタログコンポーネントをカタログページに追加し、ユーザーが選択したカタログに基づいて実行時に [レコード ID] 値を自動的に入力する場合は、{!recordId}を値として保持します。コンポーネントを他のページに追加する場合は、[レコード ID] 項目にカタログの一意の ID を入力します。「Salesforce での一意のレコード ID の特定」を参照してください。
  6. [従業員ポータルサービスカタログ] ウィンドウで、[コンポーネントタイトル] 項目と [すべてのサービスタブタイトル] 項目にカスタムタイトルを追加します。
    他の項目を設定するには、「商品閲覧環境のカスタマイズ」を参照してください。

経費を管理するためのサービスプロセスの作成

従業員イネーブルメントプログラムと課題を測定するための分析ツールには、いくつかの連動関係と注意事項があります。

プログラムの完了とユーザーの削除

ユーザーを削除しない限り、プログラムを完了した後もユーザーはプログラムに登録されたままになります。この登録は、割り当てられたユーザーとセルフ登録したユーザーのどちらも、プログラムに登録されているユーザーの最大数に含まれます。

登録済みユーザーをプログラムから削除すると、プログラムの分析データにそのユーザーを使用できなくなります。そのユーザーを同じプログラムに後から再割り当てしたり、同じプログラムに再登録したりしても、分析データの一部が保持されません。

ダッシュボードページのカスタマイズ

従業員イネーブルメントプログラムダッシュボードは、イネーブルメント管理者権限を持つ他のユーザーが使用できます。事前作成済みダッシュボードに加えた変更は、他のユーザーにも表示されます。事前作成済みダッシュボードを変更する場合は、最初にダッシュボードをコピーします。コピーしたダッシュボードは、ダッシュボードページからのみ開くことができます。

課題の進行状況

課題の完了はリアルタイムで計算されます。

同じコンテンツリンクを同じプログラム内の複数の課題に含めることができます。ただし、ユーザーが 1 つの課題のリンクをクリックした場合、ページが更新されると、そのリンクを参照するすべての課題が完了とマークされます。

イネーブルメントシステム管理者は公開済みプログラムの課題コンテンツを置き換えることができますが、多くの場合、ユーザーが取り組んでいるプログラムを編集しないことをお勧めします。

従業員を従業員イネーブルメントプログラムに登録する場合の考慮事項と制限

従業員イネーブルメントプログラムにユーザーを割り当てる場合、権限、割り当てや選択の制限、検索条件、ユーザーのタイムゾーンなど、特定の要因によって割り当て動作が左右されます。このような要因はプログラムにセルフ登録するユーザーにも影響する可能性があります。

必要なエディション

サポートされているエディションを表示する。

権限

イネーブルメント管理者が従業員にプログラムを割り当てるか、従業員がプログラムにセルフ登録するには、従業員に「従業員イネーブルメントプログラムコミュニティユーザー」権限セットライセンスが必要です。

登録の制限

  • 従業員ポータルの従業員イネーブルメントプログラムでは、最大 10,000 人の従業員を割り当てるか、セルフ登録できます。この制限を増やす場合は、Salesforce カスタマーサポートケースを送信してください。
  • 従業員をプログラムに割り当てる場合、最大 1,000 人の従業員を個別に選択できます。
  • 従業員はプログラムを完了した後もプログラムに割り当てられたまま、または登録されたままになります。登録の制限に達している場合、何人かの従業員を削除します。
  • プログラムに登録されている従業員にそのプログラムを割り当てることはできません。従業員は、すでに割り当てられているプログラムにセルフ登録することはできません。

プログラムの特定の従業員の登録状況を確認し、必要に応じて登録を管理するには、イネーブルメントプログラムのレコードの詳細ページにある [登録済みユーザー] 関連リストに移動します。

メモ プログラムを開始または完了した従業員を削除すると、プログラムの分析データに影響します。「Considerations for Analyzing Employee Enablement Program Completion (従業員イネーブルメントプログラム完了の分析に関する考慮事項)」を参照してください。

割り当てウィンドウでのイネーブルメントユーザーの絞り込み

プログラムの詳細ページまたは [イネーブルメントプログラム] ページのドロップダウンで「プログラムの割り当て」を選択すると、割り当てウィンドウが表示されます。割り当てウィンドウには、プログラムに割り当て可能な従業員を絞り込むための次のオプションが用意されています。

  • 取引先、プロファイル、ロール、または公開グループで選択可能な従業員を絞り込むことができます。
  • 一度に複数の検索条件を適用できますが、同じ検索条件の複数の値を適用することはできません。たとえば、1 つのプロファイルと 1 つのロールで絞り込むことはできますが、複数のプロファイルで絞り込むことはできません。
  • 絞り込みに使用できる値は表示権限があるもののみです。たとえば、アクセス権がないプロファイルの名前を入力した場合、そのプロファイルは照合されません。
  • 検索条件カテゴリ全体の表示権限がない場合は錠アイコンが示され、検索条件を適用できません。たとえば、ロールの表示権限がない場合は錠アイコンが示されます。
  • 検索条件を適用し、結果から従業員を選択した後で、もう一度検索条件を適用すると、以前に行った選択がクリアされます。同じ検索条件を適用した場合もクリアが実行されます。

割り当てウィンドウでの従業員の選択

割り当てウィンドウには、プログラムに割り当てる従業員を選択するための次のオプションが用意されています。

  • 割り当てウィンドウにはまず、適用した検索条件に一致した最大 200 人の従業員が読み込まれます。それ以上の従業員を 200 人ずつ読み込む場合は、スクロールし続けます。割り当てウィンドウには最大 1,000 人の従業員を表示できます。
  • 従業員を個別に選択することも、複数の従業員を選択することもできます。ウィンドウに表示されているすべての従業員を選択する場合は、ヘッダーのチェックボックスをオンにします (1)。このチェックボックスをクリックしても、次の両方の条件に該当する場合は、1 回のクリック操作で一致する従業員をすべて選択するオプションを示すバナーが表示されます (2)。
    • 検索条件に一致する従業員が他にも存在する。
    • プログラムの登録制限にまだ達していない。
  • 一致する従業員の数が組織の登録制限を超える場合は、一致する従業員をすべて選択するオプションを示すバナーが表示されません。結果から選択可能な従業員数を減らすための検索条件を適用できます。
  • 一部の従業員を選択したら、割り当てウィンドウを簡易ビューに変更して、選択した従業員のみを表示できます (3)。
  • 従業員を選択中に組織の登録制限に達すると、警告メッセージが表示されます。
  • 1,000 人の従業員を個別に選択する場合は、警告メッセージが表示され、選択した従業員の割り当てをこの時点で終了するよう求められます。

割り当てられたプログラムの開始日と期日

プログラムに割り当てる従業員を選択したら、プログラムの開始日を選択します。割り当てウィンドウでは、平日のみを選択できます。呼び出し可能なアクションを使用して従業員を割り当てる場合、週末を選択すると、開始日が自動的に次の平日に調整されます。

プログラムの期日は、割り当てた開始日とプログラムの長さ (土曜日と日曜日を除く) に基づいて計算されます。期日は、ユーザーが個人設定で指定したタイムゾーンに基づいて、従業員の最終日にスケジュールされます。たとえば、開始日が 1 月 1 日 (月曜日) の 20 日間のプログラムをスケジュールした場合、プログラムの期日は 1 月 26 日 (金曜日) です。 この予測では、1 月 1 日 (月曜日) 以降の週末の 6 日間はスキップされます。 土曜日または日曜日に課題またはマイルストーンを完了しても、従業員は功績が認められます。

ヒント 世界中のタイムゾーンの従業員でプログラムを完了するまでの時間が等しくなるように、将来の日付の開始日を選択してください。開始日として現在の日付を選択すると、その日付よりもかなり早く 1 日が始まるタイムゾーンに属する割り当てられた従業員は、プログラムの利用期間が実質的に 1 日少なくなる可能性があります。

従業員には、各自が選択したタイムゾーンに基づいて、プログラムの開始日の午前 5 時頃にメール通知が送信されます。開始日が割り当てられた当日である場合はすぐに通知が送信されます。ただし、スケジュール済みの Apex ジョブなど、リソースを大量に消費する他の活動が組織にある場合は、実際に通知が届く時刻に影響することがあります。従業員は開始日の午前 12 時からプログラムを開くことができます。

開始日と期日によって、他の通知が送信されるタイミングも決まります。「従業員イネーブルメントプログラムの通知の管理」を参照してください。

セルフ登録されたプログラムの開始日と期日

従業員がプログラムにセルフ登録した場合、プログラムの開始日は登録した日 (週末を含む) となります。

プログラムの期日は、開始日とプログラムの長さに基づいて計算されます。従業員が週末に登録した場合、プログラムの 1 日目には、その週末と次の月曜日の両方が含まれます。プログラムの期日を計算する際には、それ以降の土曜日と日曜日は除外されます。

  • 割り当て状況: イネーブルメントシステム管理者が従業員にプログラムを割り当てようとしたときに問題が発生したかどうかを示します。

  • 従業員イネーブルメントプログラムの起動
    Sandbox でプログラムと基準を開発したら、本番にリリースします。プログラムを公開し、従業員にプログラムを直接割り当てて、従業員がセルフ登録できるようにプログラムを共有することで、従業員イネーブルメントプログラムを従業員が利用できるようにします。
  • 従業員イネーブルメントプログラムの進行状況の追跡
    従業員イネーブルメントプログラムの課題に対するユーザーのパフォーマンスを確認します。事前作成済みのダッシュボードとレポートにより、従業員イネーブルメントプログラムでどの程度行動が変化し、ビジネス成果が向上しているかを分析するのに役立つインサイトが得られます。
  • 従業員イネーブルメントプログラムの管理
    従業員イネーブルメントプログラムの品質を経時的に管理するには、既存のプログラムのコピー、ユーザーの削除、プログラムの非公開、またはすでに公開したプログラムの編集を行います。
  • 従業員イネーブルメントプログラムの制限
    従業員イネーブルメントプログラムを作成して従業員が使用できるようにする場合は、プログラムと登録の制限に留意してください。従業員イネーブルメントプログラムでは基準はサポートされません。
  • 従業員イネーブルメントプログラムでサポートされる言語
    従業員イネーブルメントプログラムを作成したり受講したりするためのほとんどの機能は、Salesforce がサポートするすべての言語で利用できます。ただし、一部のレコード、コンテンツ、その他の項目では 1 つの言語のみがサポートされます。
  • [チームイネーブルメントプログラム] タブの設定
    マネージャーは、従業員イネーブルメントプログラムで直属の部下の進行状況を追跡します。このためには、従業員ポータルの [チームイネーブルメントプログラム] タブにアクセスする必要があります。このタブをマネージャーに表示するには、共有セットを使用して、直属の部下の取引先レコードとユーザーレコードへのアクセス権をマネージャーに付与します。

従業員イネーブルメントプログラムに関する考慮事項

従業員イネーブルメントプログラムに関する考慮事項を確認します。

必要なエディション

サポートされているエディションを表示する。

権限

イネーブルメント管理者の場合、「HRServiceWorkspaceUserPSG」権限セットグループには、従業員ポータルで従業員イネーブルメントプログラムを作成するためのアクセス権が付与されます。この権限はデフォルトの「Enablement Essentials の管理」権限セットに含まれます。未公開または公開従業員イネーブルメントプログラムを最大 100 個作成できます。

また、「Enablement Essentials の管理」権限セットをサイト開発者に割り当てることを検討してください。この権限セットを割り当てると、サイト開発者がイネーブルメントコンポーネントとイネーブルメントページを従業員ポータルに追加するときにイネーブルメントオブジェクトにアクセスできるようになります。

従業員の場合、従業員ポータルで従業員イネーブルメントプログラムを受講するための「EmployeeHubUserPSG」権限セットグループを割り当てます。

ユーザーエクスペリエンス

従業員イネーブルメントプログラムは、Experience Cloud で構築された従業員ポータルにログインする従業員に提供されます。従業員ポータルページ内でプログラムを見つけて受講します。通常、これらの従業員は Lightning Experience にアクセスできません。サイト開発者と協力して、従業員イネーブルメントプログラムの情報を従業員ポータルに追加します。いくつかのデフォルトのコンポーネントとページを使用できます。

従業員ポータルの要件

プログラムビルダーでは、従業員イネーブルメントプログラムの作成時にプログラムのプロパティで従業員ポータルを使用できます。

イネーブルメントコンポーネントは、サイト開発者がエクスペリエンスビルダーで編集する従業員ポータルテンプレートでのみ使用できます。

プログラムビルダーでサイトを選択する場合、他の権限が必要です。

権限またはアクセス権 選択可能なサイト
「エクスペリエンスの作成および設定」 無効なサイトまたは有効なサイト
「アプリケーションのカスタマイズ」 無効なサイトまたは有効なサイト
サイトのメンバー 有効なサイトのみ

この権限のいずれかを持っていない場合は、プログラムビルダーでサイトを表示できません。権限のある別のイネーブルメントシステム管理者によって追加されたサイトのプログラムを編集する場合、サイトの表示またはプログラムの保存、公開はできません。

課題

従業員イネーブルメントプログラムには、30 個の課題を含めることができます。

従業員イネーブルメントプログラムの音声録音、ドキュメント、スケジュール済み行動、およびその他の課題では、他のサイトページへの相対 URL がサポートされます。デジタルエクスペリエンスアプリケーションのイネーブルメントワークスペースの対応するリンクコンテンツレコードで、別のサイトページへの相対 URL を指定します。

フィードバック要求、Trailhead 課題は、従業員イネーブルメントプログラムでサポートされていません。

登録

従業員を従業員イネーブルメントプログラムに割り当てる場合、プロファイル、グループ、ロール検索条件に加えて取引先で絞り込むことができます。

割り当てウィンドウには、「従業員イネーブルメントプログラムコミュニティユーザー」権限を持つ従業員のみが表示されます。

最大 10,000 人の従業員を従業員イネーブルメントプログラムに割り当てるか、従業員イネーブルメントプログラムに登録できます。

通知

従業員イネーブルメントプログラムに関連するメール通知は、従業員ポータルのユーザー固有のメール設定に従います。

従業員イネーブルメントプログラムに関連するアプリケーション内通知は、従業員がアクセスできる環境によって異なります。

  • 通知は、従業員イネーブルメントプログラムが公開されている従業員ポータルだけではなく、メンバーになっている、および通知がサポートされているすべてのサイトで受信します。
  • Lightning Experience へのアクセス権がある場合、Lightning Experience で従業員イネーブルメントプログラムに関連する通知を受信します。

分析

従業員イネーブルメントプログラムには、他のプログラム種別の分析とは異なるダッシュボードとレポートが用意されています。

メモ [イネーブルメント設定] で、Salesforce システム管理者は事前作成済みレポートとダッシュボードを更新することで、最新のリリースから更新されたデフォルトレポートを取得できます。これにより、レポートとダッシュボードに加えられたカスタマイズが上書きされます。「従業員イネーブルメントプログラムのレポートおよびダッシュボードの更新」を参照してください。

従業員ポータルのアプリケーション内ガイダンス

従業員イネーブルメントプログラムには、プログラムを公開する従業員ポータルのプロンプトとウォークスルーが含まれます。[イネーブルメント設定] で、サイトでプロンプトとウォークスルーを作成するユーザーにデフォルトの「パートナーのアプリケーション内ガイダンスを管理」権限セットを割り当てることができます。従業員に割り当てる従業員イネーブルメントプログラムコミュニティユーザー権限セットライセンスには、従業員ポータルでプロンプトとウォークスルーを表示する権限が含まれます。

従業員イネーブルメントプログラムのスケジュール済みジョブを削除すると問題が発生する

[プログラム状況] のスケジュール済みジョブは削除しないでください。ジョブを再スケジュールする必要がある場合は、Salesforce カスタマーサポートまでご連絡ください。

従業員ポータル機能

ログインすると、従業員ポータルのホームページに Web サイトの概要が表示され、Web サイトの主要なページに簡単にアクセスできます。

必要なエディション

サポートされているエディションを表示する。

ホームページの主な機能は次のとおりです。

  • カルーセル (4) の項目をクリックすると、その項目が表示されます。および をクリック して、カルーセルの項目間を移動します。
  • グローバル検索ボックス (5) は、ケースおよび ナレッジ記事の検索に役立ちます。
    • 先行入力機能では、部分的な入力に基づいて提案が提供されるため、関連する結果をすばやく見つけることができます。先行入力機能によって提案されるオプションのいずれかを選択します。

必要なユーザー権限

ケースの表示

  1. ナビゲーションメニューで、[ヘルプセンター] をクリックします。

メモ 取り消しアクションは元に戻せません。
  1. ナビゲーションメニューで、[ヘルプセンター] をクリックします。
  2. [My Cases] をクリックします。
  3. [承認を追跡] タブをクリックします。
  4. 承認作業項目名リンクをクリックします。
  5. 承認申請リンクをクリックします。
  6. [取り消し] をクリックし、[次へ] をクリックします。
  7. 承認作業項目を取り消す理由を入力し、[取り消し] をクリックします。
    承認作業項目の状況が [取り消し済み] に変わり、マネージャーはこの承認作業項目を確認できなくなります。
