HR サービスの Advanced Approvals の制限

制限は、それを超えると機能が利用不可になったり、パフォーマンスが調整されたり、使用量の請求料金が適用されたりする境界線です。アカウントエグゼクティブと協力して目標を満たすソリューションを見つけてください。

サポートされているエディションを表示する。

Advanced Approvals with HR Service を使用する場合は、次の制限事項を考慮してください。

  • マネージャーは、メールで従業員の申請を承認できません。申請を承認するには、マネージャーが従業員ポータルにログインする必要があります。

Agentforce HR サービスアクション

Agentforce HR サービスエージェントテンプレートに含まれるアクションについて説明します。まず、実装で MuleSoft for Flow: Integration コネクタモデルを使用しているか、カスタムインテグレーションを使用しているかを特定します。

必要なエディション

サポートされているエディションを表示する。

フローコネクタアクション

これらのアクションは、新しい実装の推奨パスです。ネイティブのノーコード MuleSoft フローコネクタを使用して HCM に直接接続し、サードパーティインテグレーションのメンテナンスを不要にするネイティブ機能を提供します。

  • Create Performance Goal Action:従業員とマネージャはこのツールを使用して、接続された外部 HR システムで新しいパフォーマンス目標を作成します。
  • Update Performance Goal Action: 従業員とマネージャーはこのツールを使用して、詳細、日付、または既存のパフォーマンス目標の状況を変更します。
  • Get Performance Goals Action: 従業員とマネージャーはこのツールを使用して、現在のパフォーマンス目標を取得して表示します。
  • パフォーマンス目標の削除アクション: 従業員とマネージャーはこのツールを使用して、関連性がなくなったパフォーマンス目標や誤って作成されたパフォーマンス目標を削除します。

カスタムインテグレーションアクション

これらのアクションには、カスタム Mule アプリケーションを介して Workday または SAP SuccessFactor とのサードパーティシステムインテグレーションが必要です。

Agentforce HR サービス テンプレートには、従業員の要求に対応するように設計された事前設定済みのサブエージェントとアクションが含まれています。これらのアセットのリリース方法は、フローコネクタモデルとカスタムインテグレーションモデルのどちらを使用しているかによって異なります。

必要なエディション

アセットを設定する前に、HR エコシステムに適合する実装モデルを特定します。

フローコネクタモデル (コードなし)

フローコネクタモデルでは、MuleSoft for Flow を使用して、外部システムへのコードなしのネイティブ接続を提供します。この合理化されたパスにより、カスタムミドルウェア開発が不要になります。外部システムごとにデータの保存方法が異なるため、接続はコネクタの参照ページで使用可能な特定のトリガーとアクションに従って動作します。

メモ

フローコネクタを使用する標準の SCI ワークフローとエージェントツールの場合、フローで Salesforce と外部システム間の従業員識別子を照合する必要がある場合は、常に従業員 ID の対応付けを設定します。たとえば、これは [Create Goal (目標を作成)]、[Update Goals (目標を更新)]、[Get Goals (目標を取得)] エージェントツールを使用する BambooHR コネクタや、外部 ID の対応付けに依存するその他の SCI ワークフローまたはエージェントツールに適用されます。

Salesforce は、Salesforce 内で Salesforce ID を解決できます。Salesforce ID を外部従業員 ID (BambooHR 従業員 ID など) に対応付けるには、システムごとに異なる識別子が使用されるため、ID の対応付けを設定します。

次のいずれかの方法を選択します。

  • Salesforce と外部従業員 ID のペアを外部内部 ID 対応付けオブジェクトに保存します。
  • インテグレーションにカスタム ID 対応付けソリューションを実装します。
  • 標準フローの場合、フローの上書きを使用してコネクタと対応付けロジックを追加します。同じフロー API 参照名を使用し、フローの入力または出力パラメーターを変更しないでください。フローの入力または出力パラメーターを変更すると、関連付けられたエージェントツールの参照が破損する可能性があります。

組み込みメッセージングの設定

卒業生ポータルサイトで組み込みメッセージングを設定し、卒業生がボットまたはサービス担当者とチャットして、すぐにサポートを受けたりケースの状況を確認したりできるようにします。

必要なエディション

サポートされているエディションを表示する。

組み込みメッセージングを設定するには、次の作業を行います。

  • Salesforce 組織を準備します。
  • リリースを設定します。
  • 必要に応じて、事前チャットフォームを設定します。
  • 組み込みメッセージングコンポーネントを卒業生ポータルサイトに追加します。
  • コンポーネントを設定します。
  • ドメインをクロスオリジンリソース共有 (CORS) 許可リストに追加する。

「組み込みメッセージング」を参照してください。

設定時に、Web リリースを設定するときに、<script> タグ内に同様の JavaScript コードを追加して、事前チャット API を使用して卒業生のユーザー ID をオムニチャネルフローに渡します。「エクスペリエンスビルダーサイトまたは Commerce Cloud サイトでの拡張 Web チャットリリースの設定」を参照してください。

<script>
    window.addEventListener("onEmbeddedMessagingReady", e => {
        const userId = $A.get("$SObjectType.CurrentUser.Id");
        console.log("User id is:"+userId);
        embeddedservice_bootstrap.prechatAPI.setHiddenPrechatFields({
            "userId": userId});
    });
</script>

オムニチャネルフローでは、卒業生の取引先 ID、取引先責任者 ID、氏名が取得され、次の詳細でメッセージングセッションレコードが更新されます。更新されたメッセージングセッションレコードを使用すると、サービス担当者はすべての受信チャットメッセージ通知で卒業生の名前を確認できます。

  • 卒業生の詳細を使用したメッセージングセッションの更新
    卒業生がチャットでサービス担当者に連絡すると、サービス担当者は受信チャット通知を受け取ります。通知に卒業生の名前を表示するには、メッセージングセッションレコードに卒業生の取引先 ID、取引先責任者 ID、氏名が含まれている必要があります。これらの詳細でメッセージングセッションレコードを更新するには、自動起動フローを作成し、オムニチャネルフローを更新します。
  • ケース管理ボットの設定
    ケース管理ボットを使用して組み込みメッセージングを設定します。ボットを使用すると、卒業生はケースを作成してケースの状況をすばやく見つけることができます。

  • 通知の設定
