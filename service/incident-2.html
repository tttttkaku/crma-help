インシデントプレゼンス状況の設定

インシデントチャネルに割り当てられたサポート担当者がインシデントを解決できるとマークできるようにします。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」
権限セットを変更する 「プロファイルと権限セットの管理」
  1. [設定] から、[クイック検索] ボックスに「プレゼンス状況」と入力し、[プレゼンス状況] を選択します。
  2. [新規] をクリックします。
  3. 状況と API 参照名を入力します。
  4. 状況を [オンライン] に設定して、サポート担当者が新しいインシデント作業を受けられるようにします。
  5. チャネルとして [インシデント] を選択します。
  6. 変更内容を保存します。
  7. オムニチャネルプレゼンス状況へのアクセス権をユーザーに付与します。
    1. [設定] の [クイック検索] ボックスに「権限セット」と入力し、[権限セット] を選択します。
    2. [新規] をクリックします。
    3. 表示ラベルと API 参照名を入力します。
    4. 変更内容を保存します。
    5. 権限セットの [アプリケーション] セクションで、[サービスプレゼンス状況のアクセス権] を選択します。
    6. [編集] をクリックします。
    7. インシデントのプレゼンス状況を追加して保存します。
    8. [割り当ての管理] を選択します。
    9. [割り当てを追加] をクリックし、Service Cloud ユーザーライセンスを持つユーザーを追加します。[割り当て] をクリックします。
    10. 変更内容を保存します。

問題の作成

インシデントの根本原因を調査し、エキスパートとコラボレーションするには、問題を作成します。

必要なエディション

サポートされているエディションを表示する。
  1. サービスコンソールでドロップダウンをクリックし、[問題] を選択します。
  2. [新規] を選択します。
  3. 情報を入力し、変更を保存します。

問題を作成したら、関係者とコラボレーションして問題を解決できます。

インシデントキューの作成

インシデントを特定のキューに自動的に転送します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」
  1. [設定] から、[クイック検索] ボックスに「キュー」と入力し、[キュー] を選択します。
  2. [新規] をクリックします。
  3. 表示ラベルとキュー名を入力します。
  4. カスタマーサービスインシデント管理ルーティング設定を選択します。
  5. オブジェクトとして [インシデント] を選択します。
  6. インシデントオムニチャネル権限セットを持つユーザーをキューに追加します。
  7. 変更内容を保存します。

インシデントが作成されたら、サポート担当者はインシデントキューにインシデントを割り当てることができます。

スキルベースルーティングのインシデントスキルの作成

適切なスキルを持つサポート担当者がインシデントを解決できるように、スキルに基づいてインシデントをサポート担当者に転送します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」
サービスリソースを作成する サービスリソースに対する「作成」
サービスリソースにスキルを割り当てる サービスリソースに対する「編集」

スキルに基づいてインシデントをサポート担当者に転送する手順は、次のとおりです。

  1. スキルベースのルーティングを有効にします。
  2. インシデントスキルを作成します。
  3. インシデントエージェントのサービスリソースを作成します。
  4. サービスリソースにインシデントスキルを割り当てます。

作業プランの作成

インシデントの問題を特定して変更要求を作成したら、作業プランを作成して解決に必要なステップの概要を決定します。

必要なエディション

サポートされているエディションを表示する。
  1. 指示ステップを使用して作業プランテンプレートから作業プランを作成します。
    1. 変更要求から、ドロップダウンをクリックし、[作業プランを追加] を選択します。
    2. 作業プランテンプレートを選択して、[追加] をクリックします。
  2. テンプレートを使用せずに作業プランを作成します。
    1. 変更要求から、作業プランコンポーネントの横にあるドロップダウンを選択して、[新規] をクリックします。
    2. 情報を入力し、変更を保存します。デフォルトでは、親レコードは現在の変更要求に設定されます。
  3. 既存の作業ステップセットから作業ステップを作業プランに追加するには、作業プランの横にあるドロップダウンをクリックし、[作業ステップを追加] を選択します。
    1. プランに追加する作業ステップを選択し、[追加] をクリックします。
  4. 作業プランに新しい作業ステップを追加するには、変更要求の [関連] タブに移動して [作業ステップ] を見つけて [新規] をクリックします。
    1. 情報を入力し、変更を保存します。

作業プランを変更要求に追加したら、レコードから作業ステップの概要を確認し、進行時にステップを完了としてマークできます。

作業プランテンプレートの作成

作業プランテンプレートを使用して、インシデント管理担当者の作業プランを簡素化します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
作業プランテンプレートを作成する 作業プランテンプレートに対する「作成」および「参照」
作業プランテンプレートを表示する 作業プランテンプレートに対する「参照」
作業プランテンプレートを更新する 作業プランテンプレートに対する「編集」および「参照」
作業プランテンプレートを削除する 作業プランテンプレートに対する「削除」および「参照」
作業ステップテンプレートを作成する 作業ステップテンプレートに対する「作成」および「参照」
作業ステップテンプレートを表示する 作業ステップテンプレートに対する「参照」
作業ステップテンプレートを更新する 作業ステップテンプレートに対する「編集」および「参照」
作業ステップテンプレートを削除する 作業ステップテンプレートに対する「削除」および「参照」
  1. アプリケーションランチャーから、[作業プランテンプレート] を見つけ選択します。
  2. [新規] をクリックします。
  3. 名前を入力してテンプレートを [有効] に設定し、変更を保存します。
  4. 作業ステップのリストの概要を決定するには、[作業ステップ] 関連リストを作業プランテンプレートに追加します。
    1. 作業プランテンプレートで [設定] をクリックし、[オブジェクトを編集] をクリックします。
    2. [ページレイアウト] を選択し、[作業プランテンプレートレイアウト] を選択します。
    3. [関連リスト] で、[作業プランテンプレートエントリ] と [作業プランテンプレート履歴] を [関連リスト] セクションに追加します。
    4. 変更内容を保存します。
  5. 作業プランテンプレートの [関連] タブから、[作業プランテンプレートエントリ] を見つけます。
  6. 既存の作業ステップを作業プランテンプレートに関連付けるには、[管理] をクリックして、[追加] をクリックします。
  7. 作業ステップテンプレートを作成するには、[新規] をクリックして、[新規作業プランステップテンプレート] をクリックします。
    1. 作業ステップテンプレートを必要なだけ追加します。
    2. 変更を保存します。
  8. 作業ステップテンプレートを並び替えるには、[作業プランテンプレートエントリ] から [管理] をクリックし、[並び替え] をクリックします。
  9. 変更内容を保存します。

作業プランテンプレートと作業ステップテンプレートを作成すると、サポート担当は変更要求から標準ステップを使用して作業プランを生成できます。

ブロードキャストサイトバナーの無効化

インシデントが解決したら、バナーを無効にしてサイトから削除します。

必要なエディション

サポートされているエディションを表示する。

ブロードキャストサイトバナーが有効でなければ、無効化することはできません。

  1. [インシデント] 関連リストに移動し、[ブロードキャスト通信] 関連リストを見つけます。
  2. ブロードキャストサイトバナーを見つけて、ブロードキャスト通信レコードを開きます。
  3. ブロードキャスト通信レコードの [関連] タブから、ブロードキャスト通信利用者レコードを見つけます。
  4. レコードのドロップダウンをクリックし、[バナーを無効化] を選択します。
  5. [バナーを無効化] をクリックして、[完了] をクリックします。

ブロードキャスト Slack メッセージの削除

インシデントが解決された場合や関連性がなくなった場合には、サービスコンソールを離れることなく、ブロードキャスト Slack メッセージを Slack チャンネルから削除します。

必要なエディション

サポートされているエディションを表示する。
  • カスタマーサービスインシデント管理が有効になっている必要があります。
  • ブロードキャスト Slack メッセージが有効である必要があります。
  • ブロードキャストトピックを Slack チャンネルに割り当てる必要があります。

削除されていないブロードキャスト Slack メッセージや、以前に送信、更新、削除に失敗していないブロードキャスト Slack メッセージのみを削除できます。

ブロードキャスト Slack メッセージを削除しても、そのブロードキャスト通信レコードは削除されません。

  1. [インシデント] 関連リストに移動し、[ブロードキャスト通信] 関連リストを見つけます。
  2. 削除するブロードキャスト Slack メッセージを見つけます。ブロードキャスト通信のドロップダウンから、[ブロードキャスト Slack メッセージを削除] を選択します。
  3. [次へ] をクリックし、[完了] をクリックします。

ブロードキャストアラートの有効化

ブロードキャストアラートを有効にすると、インシデントが発生したときにインシデントマネージャーが中断を伴うアプリケーション内通知を送信できます。

必要なエディション

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「カスタマーサービスインシデント管理」と入力し、[カスタマーサービスインシデント管理] をクリックします。
  2. [ブロードキャスト設定] タブで、ブロードキャストアラートを有効化します。

ブロードキャストアラートを有効にしたら、カスタムアプリケーションを使用している場合はインシデントアラートウィジェットを追加し、必要に応じてグループを作成または管理して、1 つ以上のブロードキャストトピックを作成し、グループに割り当てます。次に、ブロードキャスト通信に対するアクセス権をユーザーに付与します。

ブロードキャストメールの有効化

ブロードキャストメールを有効にして、ユーザーが重要な情報を影響を受ける顧客に送信できるようにします。

必要なエディション

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「カスタマーサービスインシデント管理」と入力し、[カスタマーサービスインシデント管理] をクリックします。
  2. [ブロードキャスト設定] タブで、ブロードキャストメールを有効化します。

ブロードキャストメールを有効にしたら、必要に応じて取引先責任者リストビューを作成または管理し、ブロードキャスト通信へのアクセス権をユーザーに付与します。ブロードキャストメールを作成するときに、ユーザーはあらかじめ定められた取引先責任者リストビューか、インシデントに関連するケースまたは商品の取引先責任者に送信することを選択できます。

カスタマーサービスインシデント管理の有効化

いくつかのステップを行うことでカスタマーサービスインシデント管理を有効にして、サービスチームがサービスの中断を追跡して診断し、再発を防止できるようにします。これらをすべて Salesforce 内で実行できます。

必要なエディション

サポートされているエディションを表示する。

既存の Salesforce 組織でカスタマーサービスインシデント管理を有効にします。カスタマーサービスインシデント管理が有効になっている場合、オブジェクトマネージャーから、新しいオブジェクト (問題、インシデント、変更要求) に関する詳細情報を参照できます。[カスタマーサービスインシデント管理] 設定ページでこの機能を無効にすることができます。カスタマーサービスインシデント管理を無効にしても、Salesforce によってデータが削除されることはありませんが、関連付けられているすべてのオブジェクトも無効になります。

  1. [設定] の [クイック検索] ボックスに「カスタマーサービスインシデント管理」と入力し、[カスタマーサービスインシデント管理] をクリックします。
  2. カスタマーサービスインシデント管理を有効にします。

カスタマーサービスインシデント管理オブジェクトがユーザーに表示されない場合、ユーザープロファイルオブジェクトのタブが非表示になることがあります。ユーザーにカスタマーサービスインシデント管理オブジェクトへのアクセス権を付与するには、プロファイルレベルで権限を有効にします。

  1. [設定] の [クイック検索] ボックスに「プロファイル」と入力し、[プロファイル] をクリックします。
  2. カスタマーサービスインシデント管理オブジェクトにアクセスできるようにするプロファイルを選択します。
  3. [編集] をクリックします。
  4. [標準オブジェクト権限] セクションで、インシデント、問題、または変更要求オブジェクトを見つけて、オブジェクトへのアクセス権をユーザープロファイルに付与します。ユーザーがカスタマーサービスインシデント管理レコードを表示して編集するには、「編集」以上の権限が必要です。
  5. [タブの設定] で、[デフォルトで表示] を選択します。
  6. 変更内容を保存します。
  7. 他の 2 つのカスタマーサービスインシデント管理オブジェクトに対してステップ 4 ～ 6 を繰り返します。
  8. 必要に応じて、他のユーザープロファイルに対してステップ 1 ～ 8 を繰り返します。

ブロードキャストサイトバナーの有効化

ブロードキャストサイトバナーを有効にして、ユーザーが重要な情報を表示するバナーを Aura および LWR サイトに追加できるようにします。

必要なエディション

サポートされているエディションを表示する。

ブロードキャストサイトバナーを有効化する前に、デジタルエクスペリエンスを有効化します。

  1. [設定] の [クイック検索] ボックスに「カスタマーサービスインシデント管理」と入力し、[カスタマーサービスインシデント管理] をクリックします。
  2. [ブロードキャスト設定] タブで、ブロードキャストサイトバナーを有効化します。

ブロードキャストサイトバナーを有効にしたら、1 つ以上のブロードキャストトピックを作成してネットワークサイトに割り当てます。

ブロードキャスト Slack メッセージの有効化

ブロードキャストアラートを有効にすると、インシデントが発生したときにインシデントマネージャーが中断を伴うアプリケーション内通知を送信できます。

必要なエディション

サポートされているエディションを表示する。
  1. [設定] の [クイック検索] ボックスに「カスタマーサービスインシデント管理」と入力し、[カスタマーサービスインシデント管理] をクリックします。
  2. Service for Slack アプリケーションとスウォーミングの設定を完了します。
  3. カスタマーサービスインシデント管理の [ブロードキャスト設定] タブで、ブロードキャスト Slack メッセージを有効にします。

ブロードキャスト Slack メッセージを有効にしたら、必要に応じてブロードキャストに使用する Slack チャンネルを確認し、1 つ以上のブロードキャストトピックを作成して Slack チャンネルに割り当てます。次に、ブロードキャスト通信に対するアクセス権をユーザーに付与します。

インシデントライフサイクルの例: インシデントチームの一日

Take-Out のインシデントマネージャーは、メール、チャット、メッセージング、電話など、複数のチャネルで、新しいマーケティング割引コードのエラーに関する顧客ケースが急増していることに気が付きます。

必要なエディション

サポートされているエディションを表示する。
  1. インシデントマネージャーが新規ケースとオープンケースを調べると、正常に機能しない割引コードに関するケースが多数あることがわかりました。
  2. インシデントマネージャーがインシデントレコードを作成します。インシデントレコードには、割引コードのエラー、影響を受けるサービステリトリー、緊急度に関する情報が含まれます。
  3. インシデントの調査中に関連ケースを追跡し、サポート担当者キューからインシデント関連の問題を削除するために、インシデントマネージャーが [ケース関連の問題] 関連リストからケースをリンクします。
  4. 割引コードの問題に関する専門知識に基づいて、インシデント解決チームのメンバーに、オムニチャネルを介してインシデントが割り当てられます。
  5. リンクされたすべてのケースを所有するために、インシデント所有者が [アクション & おすすめ] コンポーネントから [ケース所有者をインシデント所有者に変更] フローを起動します。以前のケース所有者は新しい顧客ケースの処理に戻ることができます。これでインシデントに関連するケースに取られることがなくなります。
  6. インシデント所有者は、Knowledgeコンポーネントで関連するKnowledge記事を検索しますが、既知の回避策は見つかりません。
  7. インシデント所有者は、[スウォーミングを開始] フローとエキスパートファインダーを使用して、Slack で他の専門分野エキスパートとスウォームを開始することにします。割引コードのエキスパートがスウォーム内でチームとして協力して問題を突き止め、影響を受けるすべての顧客を特定し、解決策に関するコラボレーションに DevOps チームメンバーを招待します。
  8. DevOps チームのメンバーが Salesforce に問題レコードを作成し、問題の詳細を取得して根本原因を調査します。DevOps チームは、問題のデバッグを行い、影響を受けるアセットを特定し、問題をインシデントにリンクし、インシデント所有者が顧客に最新情報を提供できるようにします。
  9. インシデント所有者は、認証済みユーザーにインシデントを通知して、さらにケースが発生しないように代わりの割引コードを提供するために、ブロードキャストバナーを Take-Out サイトに追加します。
  10. DevOps チームが割引コードエラーの原因となっているバグを特定するとすぐに、チームメンバーが解決へのステップを取得するために変更要求を作成します。
  11. 変更要求から、DevOps メンバーがインシデントを解決して割引コードを修復するために必要なステップをまとめた作業プランを作成します。
  12. すべてのステップを完了して確認したら、変更アドバイザリボードから緊急修正のサインオフを得るために、インシデント対応チームが承認フローを起動します。
  13. 修正が承認され、インシデントが解決されたら、インシデントチームが [アクション & おすすめ] コンポーネントから [変更要求および関連問題をクローズする] フローを起動します。このフローで、変更要求とそれに関連する問題、インシデント、ケースが自動的にクローズされます。
  14. インシデント所有者は Take-Out サイトからバナーを削除し、影響を受けたすべての顧客に割引コードが機能するようになったことを知らせるブロードキャストメールを送信します。
  15. インシデント所有者はスウォームをクローズし、チームは Slack を活用したとっさの判断とコラボレーションをお祝いします。

カスタマーサービスインシデント管理フローに関する考慮事項

カスタマーサービスインシデント管理のサンプルフローを使用するときは、以下の考慮事項に留意してください。

必要なエディション

サポートされているエディションを表示する。
  • フローの制限および考慮事項
  • 実行中のユーザーには「フローを実行」ユーザー権限が必要です。
  • カスタマーサービスインシデント管理フローを使用するには、インシデント管理を有効にする必要があります。
  • [ケース所有者をインシデント所有者に変更] フローはインシデントでのみ機能します。[変更要求および関連問題をクローズする] フローは変更要求でのみ機能します。
  • [変更要求および関連問題をクローズする] フローでクローズされるのは、変更要求とその関連したケース、問題、インシデントのみです。
  • [クローズ済み] 選択リスト値が [状況] 項目から削除されると、[変更要求および関連問題をクローズする] フローは失敗します。
  • [ケース所有者をインシデント所有者に変更] フローはケースがインシデントに関連とマークされている場合のみ機能します。
  • カスタマーサービスインシデント管理フローは、レコード ID が指定されたコンポーネントまたは Lightning ページでのみ機能します。 たとえば、カスタマーサービスインシデント管理フローを Experience Cloud 側またはユーティリティ バーから使用することはできません。
  • [変更要求および関連問題をクローズする] フローでは部分的な更新はサポートされません。たとえば、実行中のユーザーに少なくとも 1 つの関連問題へのアクセス権がない場合、フローは失敗します。
  • [ケース所有者をインシデント所有者に変更] フローで、ケース所有者を変更できるのは実行中のユーザーにそのケースへのアクセス権がある場合のみです。
  • トリガーまたは入力規則エラーのためにフローが失敗する場合があります。フローに関連するすべてのレコードに入力規則エラーがあるかどうかを確認してください。
  • [ケース所有者をインシデント所有者に変更] フローで、ケース所有者を変更できるのはインシデント所有者がユーザーである場合のみです。

MuleSoft Composer によるインテグレーションのインストール

カスタマーサービスインシデント管理を最大限に活用するには、Agentforce Service（旧称Service Cloud）をMuleSoft Composerテンプレートを利用したJiraやServiceNowなどのサードパーティインテグレーションと統合します。

メモ Service Cloud は Agentforce Service になりました。Salesforce アプリケーションおよびドキュメントで Service Cloud を参照することがあります。

ServiceNowのCMDBとカスタマーサービスインシデント管理間で同期されたインシデントを使用して、Agentforceサービスでサポート担当者の生産性を維持します。MuleSoft Composer ServiceNow テンプレート (ベータ) を使用すると、Salesforce のアセットとインシデントを ServiceNow CMDB と同期できます。その逆も同様です。

また、MuleSoft Composer Jira テンプレート (ベータ) を使用することで、エンジニアは Jira のエピック、ストーリー、タスクをカスタマーサービスインシデント管理に合わせて調整し、効率的にインシデントを解決できます。Jira の問題とカスタマーサービスインシデント管理レコード間の接続を作成して、エンジニアリングチームとカスタマーサービスチームが常に同期できるようにします。たとえば、Jira で問題が作成された場合、対応する変更要求が Salesforce で作成され、Jira の問題 ID が添付されます。

MuleSoft Composer を使用するカスタマーサービスインシデント管理インテグレーションの使用を開始するには、MuleSoft Composer テンプレートの使用方法を確認してください。次に、Salesforce アカウントエグゼクティブにお問い合わせください。

サポートされているエディションを表示する。
  • ブロードキャストメールの送信
    インシデントの影響を受けた顧客にメールを送信します。定義済みの取引先責任者リストにメールを送信できます。ケースまたは商品がインシデントに添付されている場合は、ケースまたは商品の取引先責任者にブロードキャストメールを送信できます。
  • ヘルプサイトへのブロードキャストサイトバナーの追加
    バナーを Web サイトに追加して、処理中のインシデントについて事前に顧客に通知します。ブロードキャストサイトバナーは、有効なバナーがないサイトにのみ追加できます。
  • ブロードキャストサイトバナーの無効化
    インシデントが解決したら、バナーを無効にしてサイトから削除します。

ブロードキャスト通信を使用した内部関係者への通知

インシデントチームや内部関係者に進行中のインシデントを通知するには、ブロードキャストアラートまたは Slack メッセージを使用します。

必要なエディション

サポートされているエディションを表示する。
  • ブロードキャストアラートの送信
    インシデントが発生したら、直接アクションを実行して問題をすばやく解決できるように、適切なチームメンバーにアラートを送信します。アラートは、グループに割り当てられたトピックに基づいてチームに転送されます。たとえば、ハードウェアの問題に関連するインシデントが発生した場合、ブロードキャストトピックとして [Hardware Issue (ハードウェアの問題)] を選択します。ハードウェアの問題を処理するインシデントグループに通知されます。
  • ブロードキャストアラートへの応答
    ブロードキャストアラートに対処できるように、インシデントアラートユーティリティで、最近発生したインシデントと現在のインシデントに関連ケースを添付します。インシデントを開いて詳細を確認することもできます。インシデントアラートユーティリティを使用するには、システム管理者がこのユーティリティをサービスアプリケーションに追加する必要があります。
  • ブロードキャスト Slack メッセージの送信
    インシデントが発生したときに、ブロードキャスト Slack メッセージで関係者とリーダーチームに最新情報を提供します。ブロードキャスト Slack メッセージは、関連付けられた Slack チャンネルへのアクセス権を持つすべてのユーザーに表示されます。
  • ブロードキャスト Slack メッセージの更新
    新しいブロードキャスト Slack メッセージを送信せずに関係者に最新情報を通知するには、ブロードキャスト Slack メッセージのインシデント項目を更新して、最新の変更を反映します。
  • ブロードキャスト Slack メッセージの削除
    インシデントが解決された場合や関連性がなくなった場合には、サービスコンソールを離れることなく、ブロードキャスト Slack メッセージを Slack チャンネルから削除します。

インシデントの解決

インシデント管理チームは、問題を診断して解決策を見つけた後に変更要求を使用できます。これにより、サービスチームは必要なステップを簡単に決めることができ、問題またはインシデントが再発生しないようにできます。

  • 変更要求の作成

  • 作業プランを使用した修正のロールアウト
    作業プランとその作業ステップを使用して、変更要求を送信し、インシデントを解決するために必要な一連のステップの概要を決定します。

必要なエディション

インシデントが発生したら、オムニチャネルのキューベースまたはスキルベースのルーティングを使用して、インシデントを適切なチームに転送します。

  1. インシデントチャネルの作成

カスタマーサービスインシデント管理のサンプルフロー

カスタマーサービスインシデント管理には、インシデント解決プロセスを合理化するためにカスタマイズおよび有効化できる一連のサンプルフローが用意されています。

必要なエディション

サポートされているエディションを表示する。

変更要求および関連問題をクローズする

インシデントを解決するときの反復作業を排除するために、変更要求と、ケースや問題、インシデントなどの関連問題を自動的にクローズします。

たとえば、サポート担当者が変更要求を完了とマークする準備ができたら、サポート担当者は変更要求の [アクション & おすすめ] コンポーネントから「変更要求および関連問題をクローズする」フローを使用できます。

フローを起動したら、クローズする関連問題を選択するよう要求する画面が表示されます。

ケース所有者をインシデント所有者に変更

ケースが包括的なインシデントの一部として特定された場合に重複作業を避けるために、ケース所有者を自動的にインシデント所有者に変更します。

たとえば、サポート担当者が、進行中のインシデントに関連するとマークされたケースの流入を確認したが、ケース所有者とインシデント所有者が異なることに気付いたとします。サポート担当者はインシデントの [アクション & おすすめ] コンポーネントから [ケース所有者をインシデント所有者に変更] フローを使用できます。

フローを起動したら、ケースの所有者をインシデント所有者に変更することを確認する画面が表示されます。

ブロードキャストアラートの送信

インシデントが発生したら、直接アクションを実行して問題をすばやく解決できるように、適切なチームメンバーにアラートを送信します。アラートは、グループに割り当てられたトピックに基づいてチームに転送されます。たとえば、ハードウェアの問題に関連するインシデントが発生した場合、ブロードキャストトピックとして [Hardware Issue (ハードウェアの問題)] を選択します。ハードウェアの問題を処理するインシデントグループに通知されます。

必要なエディション

サポートされているエディションを表示する。
  • カスタマーサービスインシデント管理が有効になっている必要があります。
  • ブロードキャストアラートが有効である必要があります。
  • ブロードキャストトピックをグループに割り当てる必要があります。
  1. [インシデント] 関連リストに移動し、[ブロードキャスト通信] 関連リストを見つけます。
  2. [新規ブロードキャストアラート] をクリックします。
  3. 関連性の高いブロードキャストトピックを選択して、[次へ] をクリックします。
  4. アラートを確認して、[送信] をクリックします。

ブロードキャストアラートを送信すると、アラートのグループのチームメンバーのインシデントアラートユーティリティの [最新] タブに表示されます。

  2. ブロードキャストメールの送信方法を選択して、[次へ] をクリックします。
  3. [新規ブロードキャストメール] をクリックします。
  4. メールを作成し、[プレビューして送信] をクリックします。
  5. メールを送信するには、[送信] をクリックします。
