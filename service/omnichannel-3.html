メール-to-ケースからケースを転送するためのオムニチャネルフローの割り当て

オムニチャネルフローを使用して、カスタマーサポートメールのケースを適格なサポート担当者に転送します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
ケースを転送するオムニチャネルフローを割り当てる 「アプリケーションのカスタマイズ」

メール-to-ケースを使用している場合は、レコードトリガーフローではなくオムニチャネルフローを使用して、ケースをキューやサポート担当者などの適切な宛先に転送します。オムニチャネルフローのロジックを使用してメール-to-ケースでケースが転送されるように、他のケース割り当てルールは使用しないでください。

オムニチャネルフロー内では、ケースを転送するロジックを作成することも、ケースを転送しないように選択することもできます。フローの実行中に例外が発生すると、ケースはフォールバックキューにルーティングされます。

  1. 「フローを実行」または「フローの管理」権限を自動ケース更新ユーザーに割り当てます。このユーザーは、[設定] の [サポート設定] で定義されます。
  2. [設定] から、[クイック検索] ボックスに「メール-to-ケース」と入力し、[メール-to-ケース] を選択します。
  3. 顧客がサポートチームに問い合わせを送信するために使用するルーティングアドレスを作成または編集します。
    オムニチャネルフローをルーティングに使用するには、このアドレスを検証する必要があります。
  4. [フロー設定] セクションで、ケースを転送するために作成したフローを指定します。
  5. 代替キューを指定します。
    代替キューでは、ケースをサービスチャネルオブジェクトとして使用し、オムニチャネルルーティング設定を使用する必要があります。
  6. [保存] をクリックします。

顧客がルーティングアドレスにメールを送信すると、メール-to-ケースによってケースが作成されます (存在しない場合)。その後、フローが実行され、ケースが適切なオムニチャネルキューまたはサポート担当者に送信されます。

キューへのメッセージの転送

メッセージングチャネルでメッセージングセッションを転送するには、チャネルを編集してから、チャネルのルーティング方法とキューを指定します。

サポートされているエディションを表示する。
  1. [設定] から、[クイック検索] ボックスに「メッセージング」と入力し、[メッセージング設定] を選択します。
  2. [チャネル] で、既存のメッセージングチャネルを開いて編集します。
  3. [ルーティング] でルーティングのプロパティを入力します。
    プロパティ 説明
    高度なルーティングの有効化 [高度なルーティングを有効化] チェックボックスが表示され、オムニチャネルフローを使用する場合はそのチェックボックスをオンにします。このオプションでは、オムニチャネルフローで定義されたロジックに基づいて、このチャネルのメッセージングセッションを転送します。
    ルーティング種別 [オムニチャネル] を選択します。
    キュー このチャネルのメッセージングセッションを転送するキューを指定します。キューによってこのチャネルへのセッションが管理され、優先度が付けられます。
  4. [自動応答] で、同意設定、会話の応答、ヘルプを入力します。
  5. [保存] をクリックします。

サポート担当者への転送

作業を優先サポート担当者に直接転送します。たとえば、既存の顧客からの営業電話をアカウントエグゼクティブに転送できます。

必要なエディション

サポートされているエディションを表示する。
メモ 外部ルーティングでは、スキルベースのルーティングまたは直接担当者へのルーティングはサポートされません。
  • サービス担当者への転送の準備
    作業をサービス担当者に直接転送するルールを設定する前に、次の前提条件 ToDo が完了していることを確認します。

Agentforce サービスエージェントへのルート

拡張メッセージングと音声通話をAgentforceサービスエージェントに転送します。サービスエージェントは、自律AIを使用して、広範な一般的なサポート タスクを効率的に処理します。このルーティングにより、サービス担当者は複雑な問題解決や顧客とのより深い関係の構築など、戦略的で価値の高い作業に集中できます。

必要なエディション

サポートされているエディションを表示する。

Agentforce サービスエージェントに転送するオムニチャネルフローを作成します。

  • [設定] から、[クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  • 編集する既存のオムニチャネルフローを選択するか、オムニチャネルフローを最初から作成する手順に従います。
  • Flow Builder でフローを開きます。[作業を転送] アクションをキャンバスにドラッグします。
  • アクションの表示ラベル名と API 参照名を入力し、必要に応じて説明を入力します。
  • [入力値を設定] で、レコード ID 変数を設定します。
  • 会話をそれぞれのサービスチャネルに転送する
    • 音声会話の場合、[サービスチャネル] ドロップダウンで [電話] を選択します。
    • メッセージングの会話の場合、[サービスチャネル] ドロップダウンで [メッセージング] を選択します。
  • [ルーティング先] ドロップダウンで、[Agentforce サービスエージェント] を選択します。
  • Agentforce サービスエージェントドロップダウンで、ASA エージェントを選択します。
  • フローを保存して有効化します。

拡張ボットへの作業項目の転送

拡張メッセージングチャネルを使用してビジネス条件に基づいて会話を拡張ボットに自動的に転送します。

必要なエディション

Einstein ボットのサポートされているエディションを表示します。

拡張ボットは、拡張チャットや拡張サードパーティチャネルなどの拡張チャネルでのみ機能します。拡張チャネルにアクセスするには、Salesforce アカウントエグゼクティブにお問い合わせください。チャットのオムニチャネルフローは Einstein ボットでは使用できません。

開始する前に、拡張ボットを作成して有効化します。

  1. 編集する既存のオムニチャネルフローを選択するか、オムニチャネルフローを最初から作成する手順に従います。
  2. [作業を転送] アクションをキャンバスにドラッグします。[作業を転送] アクションは、フローの最後のオブジェクトです。
  3. アクションに表示ラベルと API 参照名を付与し、必要に応じて [説明] を指定します。
  4. [入力値を設定] で、必須項目に入力します。
    • [レコード ID] 項目で、作成したレコード変数を選択します。
    • [サービスチャネル] 項目で、[メッセージング] を選択します。
    • [ルーティング先] 項目で、[ボット] を選択して拡張ボットのリストを入力します。
  5. [ボット] でボットを選択します。使用できるのは有効なボットのみです。ボットがリストに表示されない場合は、ボットを有効化し、Flow Builder を更新してもう一度お試しください。後でボットを無効化しても、そのボットは追加したフローに引き続き関連付けられます。
  6. [キュー] で、ルーティングに失敗した場合にオムニチャネルフローで会話を送信する代替キューを選択します。
  7. 変更内容を保存します。

会話をボットに転送するすべてのオムニチャネルフローが、ボットの [概要] ページの [受信オムニチャネルフロー] セクションに表示されます。

キューへの作業項目の転送

変数を使用して作業を特定のキューに自動的に転送します。

サポートされているエディションを表示する。
  1. オムニチャネルフローを作成する手順を実行します。
  2. [作業を転送] アクションをキャンバスにドラッグします。
  3. アクションに表示ラベルと API 参照名を付与し、必要に応じて [説明] を指定します。
  4. [入力値を設定] で、作業を転送する項目の数を選択します。
    1 つの項目を転送するには、[単一] を選択し、作業を転送するレコード ID が含まれるテキスト型のフロー変数を選択します。最大 100 件の項目を転送するには、[複数] を選択し、転送するレコード ID のリストが含まれるテキスト型のコレクション変数であるフロー変数を指定します。
    レコードのコレクションを指定し、フローでいずれかのレコードが見つからなかった場合、変更はロールバックされ、どのレコードも転送されません。
  5. [サービスチャネル] で、チャネルを選択します。
  6. [ルーティング先] で、[キュー] を選択します。
  7. [キュー] で、次のいずれかのオプションを選択します。
    1. キューを選択 — ルーティング先のキューを指定します。
    2. 変数を使用 — 変数を使用して適切なキューを探します。たとえば、この変数は顧客の取引先責任者レコードに関連する部署キューを表すことができます。オムニアクションを使用してオムニチャネルフローを移行する場合、変数を使用してアクションの移行をより適切にサポートします。

フローでレコードが見つかったが、何らかの理由で指定したキューに転送できない場合、そのレコードは代替キューに転送されます。

特定のサポート担当者への作業項目の直接転送

エージェントへの直接転送を使用して、作業項目をサポート担当者に直接自動的に転送します。

サポートされているエディションを表示する。

音声通話以外のすべての作業項目を転送するには、[設定] の [オムニチャネル設定] で、[スキルベースのルーティングとエージェントへの直接転送を有効化] が有効になっていることを確認します。このオプションを有効にしないと、これらの種別の作業項目を特定のサポート担当者に転送できません。

メモ 音声通話をサポートの特定の担当者に転送するには、オムニチャネル統合ルーティングを使用していない限り、[スキルベースのルーティングとエージェントへの直接転送を有効化] を選択しないでください。他のルーティングモデルでは、このオプションは必要ありません。
  1. オムニチャネルフローを作成する手順を実行します。
  2. [作業を転送] アクションをキャンバスにドラッグします。
  3. アクションに表示ラベルと API 参照名を付与し、必要に応じて [説明] を指定します。
  4. [入力値を設定] | [レコード ID] で、作成した recordId 変数を選択します。
  5. [ルーティング先] で [エージェント] を選択します。
  6. [エージェント] で、次のいずれかのオプションを選択します。
    1. エージェントの選択 — 作業項目の転送先となるサポート担当者を指定します。
    2. 変数を使用 — 変数を使用して、適切なサポート担当者を検索します。たとえば、顧客の取引先責任者レコードに関連付けられた優先営業担当を決定できます。この例では、この取引先責任者の優先担当者を定義する参照項目が取引先責任者レコードにあります。このエージェント ID を変数として渡します。オムニアクションを使用してオムニチャネルフローを移行する場合、変数を使用してアクションの移行をより適切にサポートします。
  7. 希望のサポート担当者のみが利用可能になったときに作業を割り当てる
    1. [Required Agent (必要なエージェント)] をクリックします。
    2. 次に、ルーティング用のパラメーターに使用する [ルーティング設定] を指定します。
    3. 音声通話の場合は、[Required Agent (必要なエージェント)] を選択しないでください。オムニチャネル統合ルーティングを使用していない限り、必要な担当者への音声通話の割り当てはサポートされていません。このオプションが選択されておらず、優先担当者がオンラインで対応できない場合、通話は他のユーザーに転送されます。
    メモ 特定の担当者が必要な場合、ルーティング設定の [プッシュ時間 0ut(Push Time-0ut)] またはプレゼンス設定の [エージェントが作業要求を拒否できるようにする(Allow Agents to Decline Work Requests)] は無視されます。
  8. または、優先担当者が対応できないときに作業をキューに転送するには、[必要なエージェント] チェックボックスをオフにします。その後、作業項目を転送するバックアップキューを指定します。

スキルへの作業項目の転送

特定のスキルに基づいて作業項目を適格なサポート担当者に自動的に転送します。これを実現するには、スキルベースのルーティングルール、オムニチャネルフロー、またはその両方を組み合わせて使用します。たとえば、オムニチャネルフローを使用して特定のスキル要件を作業項目に条件付きで割り当てるには、[決定] アクションを追加して各作業項目に適用されるスキルセットを決定する条件を設定し、[スキル要件] アクションを追加してスキルセットを定義します。

サポートされているエディションを表示する。
メモ 音声通話にはスキルベースのルーティングを使用できません。
  • 作業をスキルに転送するための前提条件
    オムニチャネルフローまたはスキルベースのルーティングルールを使用して作業項目をスキルに転送するには、前提条件を満たしている必要があります。
  • [スキル要件を追加] アクション
    スキル要件を作業項目に追加して、作業が顧客の問題に最適なサービス担当者に転送されるようにします。[スキル要件を追加] アクションで最大 10 件のスキルを追加でき、個々の作業項目を転送するときにフロー全体で 20 件のスキルを定義できます。
  • [作業を転送] アクションの追加
    オムニチャネルフローを使用して、特定のスキルを持つサービス担当者に作業項目を転送します。

オムニチャネルによる作業の転送

オムニチャネルを使用して、作業項目をキュー、サポート担当者、スキル、さらにはEinsteinボット(サポートされるチャネル上)に転送します。ビジネスニーズに応じて、オムニチャネルフローを含め、異なる方法を使用して作業を転送できます。

必要なエディション

サポートされているエディションを表示する。

オムニチャネルは、定義済みのルーティングロジックに基づいて作業を転送します。サポート担当者は、作業項目が割り当てられたら、その作業項目を受け入れて作業を開始するか、拒否できます。作業項目が却下されると、オムニチャネルは作業項目によって消費された担当者の業務量を解放します。ただし、拒否された作業項目は、作業が再度転送されるまで、拒否された営業担当の所有のままです。営業担当が作業項目を拒否した場合、または指定された期間内に作業項目を受け入れなかった場合、オムニチャネルはその作業項目を営業担当に再度転送しません。

営業担当が作業を受け入れると、その作業を別の営業担当に転送できます。

重要 標準オムニチャネルは Summer '26 リリースで廃止されます。ユーザーがルーティングワークフローを維持し、最新の機能にアクセスできるように、Summer '26 リリースのロールアウト中に Salesforce によって組織が自動的に拡張オムニチャネルにアップグレードされます。拡張オムニチャネルは、サービス担当者とスーパーバイザー向けの最新の機能を提供します。「標準オムニチャネルから拡張へのアップグレード」を参照してください。
  • ルーティングライフサイクルの詳細の理解
    オムニチャネルとルーティングプロセスをさらに掘り下げる場合、2 つの特定のオブジェクト (PendingServiceRouting (PSR) と AgentWork) の理解を深めることをお勧めします。
  • ルーティング戦略の選択
    最適なルーティング戦略を選択することは、サービス担当者とその作業負荷を効率的に管理するために不可欠です。Salesforce でサポートされるさまざまなルーティング戦略についての詳細は、このトピックを参照してください。
  • 転送先の選択

RowCount/PARENTGROUPVAL(RowCount, GRAND_SUMMARY)

オムニチャネルは、2 つの異なるプロセスを使用して作業を転送します。

  • まず、新しい作業項目がオムニチャネルキューに割り当てられると、オムニチャネルはその作業項目をサポート担当者に転送しようとします。オムニチャネルでは、作業項目が割り当てられているキューの優先度で転送されるため、最も重要な作業項目が最初に担当者に転送されます。次に、キュー内で待機している時間に基づいて項目が転送されます。最も古い作業項目は、より新しい作業項目の前に担当者に転送されます。(この詳細については後ほど説明します)。

  • 次に、担当者が作業を受け入れる能力が変更された場合 (「退席中」の状況から戻った場合や、別の作業項目を終了した場合など)、オムニチャネルはその担当者に転送できる作業を見つけようとします。

次に、オムニチャネルによって、対応可能な担当者と各担当者が取り組んでいる作業量が判断されます。この情報は、作業項目に対する営業担当の現在の業務量を追跡する UserServicePresence API オブジェクトから取得されます。

セカンダリルーティング優先度の設定

サポート担当者がセカンダリルーティングの優先度を使用して最初に適切なケースに対応できるようにします。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
オムニチャネルを設定する 「アプリケーションのカスタマイズ」

キューでは、作業項目の待ち時間によって優先度が決まります (先入れ先出し)。しかし、作業項目がキューで待機しているときに、より緊急な作業が飛び込んで来ることもあります。たとえば、転送されて来た作業、誰かの応答を待っている作業、またはサービス契約の締め切りが迫っている作業などです。作業項目を別のキューに移すこともできますが、そのキューでは、すでに待機している項目の後に配置されてしまいます。また、複数のキューが同じ優先度を持つ場合もあります。セカンダリルーティング優先度は、作業項目をキュー内で他の項目より前に移動したり、キュー間で同じルーティング設定優先度を持つ項目の競合を解決したりすることで、この問題に対応します。

メモ セカンダリルーティングを有効にしても、既存の作業は再評価されません。セカンダリルーティングは、この機能を有効にした後に開かれた新しい作業に適用されます。
  1. [設定] から、[クイック検索] ボックスに「オムニチャネル」と入力し、[オムニチャネル設定] を選択します。
  2. [セカンダリルーティング優先度の有効化] を選択します。
    これで、各チャネルのセカンダリルーティング優先度の対応付けを設定できるようになります。
  3. [設定] から、[クイック検索] ボックスに「サービスチャネル」と入力し、[サービスチャネル] を選択します。
  4. 既存のサービスチャネルを編集するか、新しいサービスチャネルを作成します。
  5. [セカンダリルーティング優先度] セクションで、優先度項目を選択します。そして、項目値を優先度に対応付けます。
例

エスカレーションされたケースを第一優先、新しいケースを次に優先するには [状況] を優先項目として選択します。次に [エスカレーション済み] 項目値を優先度 1、[新規] 項目値を優先度 2 に設定します。 最も高い優先度は 0 です。

メモ セカンダリルーティング優先度は、スキルベースでルーティングされたチャットチャネルやメッセージチャネルでは自動的には更新されません。PendingServiceRouting オブジェクトの SecondaryRoutingPriority 項目を更新するには、API を使用してください。

サポート担当者の業務量の設定

サポート担当者が複数のタスクに柔軟に対応できるようにします。主作業と中断可能な作業の業務量を設定します。

必要なエディション

サポートされているエディションを表示する。

サポート担当者の作業は、音声通話のように主 (つまり、中断されない) である場合もあれば、ケースのように中断可能な場合もあります。サポート担当者の主業務量と中断可能な業務量を設定することで、サポート担当者は長年の作業や緊急度の低い作業を一時停止して、緊急度の高い作業に取り組むことができます。

単純な設定、特にチャネルが 1 つの設定の場合、通常は担当者の主業務量で十分です。より複雑な設定、特にリアルタイムチャネルと非同期チャネルをブレンドする場合は、中断可能な業務量を検討してください。中断可能な業務量についての詳細は、「中断可能な業務量を使用した優先度の設定」を参照してください。

[設定] の [プレゼンス設定] で、主業務量と中断可能な業務量を定義します。これらの値は、担当者が一度に処理できる主作業と中断可能な作業の最大量を表します。使用可能な業務量は、相対的な作業単位値またはパーセントを使用して指定できます。

[業務量] 項目の主業務量には値が必要です。主業務量のみを定義すると、デフォルトで中断可能な業務量は同じ値に設定されます。

これで、担当者の作業項目に主業務量と中断可能な業務量を作成する準備が整いました。「作業項目の主または中断可能としての設定」を参照してください。

スキルベースのルーティングとキューベースのルーティングの違い

スキルベースのルーティングでは、キューベースのルーティングより高度で動的な条件を使用して作業項目を転送できます。

サポートされているエディションを表示する。

一般的に、キューは 1 つのスキルを表すようになっています。たとえば、スペイン語を話すサービス担当者用のキューと、レベル 3 のテクニカルサポートコール用のキューを作成できます。キューベースのルーティングでは、オムニチャネルは各作業項目をキューのメンバーであるサービス担当者に転送します。

スキルベースルーティングのスキルの作成

オムニチャネルで作業項目を最も適格なサービス担当者に転送するために使用でき、サービス担当者が作業項目を移行するときに検索できるサービス担当者スキルを定義します。スキルによって、サービス担当者の専門分野が識別されます。たとえば、言語 (スペイン語、フランス語、英語)、製品知識 (ソフトウェアおよびハードウェア)、資格 (CompTIA および CCNP) のスキルを定義できます。

  4. 必要に応じて、スキルの説明を入力します。
  5. 標準オムニチャネルを使用している場合、[ユーザーの割り当て] および [プロファイルの割り当て] セクションでスキルをユーザーとプロファイルに割り当てます。

  7. [保存] をクリックします。

スキルへの転送

各作業項目をその作業に最適なサービス担当者に自動的に転送することで、カスタマーサービスの品質を向上させます。スキルベースのルーティングでは、問題を解決する適切なスキルを持つサービス担当者にすべての作業項目を転送します。

サポートされているエディションを表示する。

スキルベースのルーティングを実装するには、作業項目の転送に必要なスキルを決定し、各サービス担当者のスキルを識別するロジックを定義します。

作業項目の転送に必要なスキルを決定するロジックを定義するには、次のいずれかの方法を使用します。

  • オムニチャネルフローを使用して作業を転送する。オムニチャネルフローは、スキルベースのルーティングルールにはない優れた柔軟性と機能を備えています。フローでは、作業項目ごとにスキル要件を動的に定義して、スキルベースのルーティングルールを実行できます。「スキルへの作業項目の転送」を参照してください。
  • スキルベースのルーティングルールを使用して作業を転送する。「スキルベースのルーティングルールを使用した転送」を参照してください。

スキルをサービス担当者に割り当てるには、各サービス担当者のスキルを定義して、サービス担当者に割り当てます。スキルをサービス担当者に割り当てるには、スキルをサービスリソースに割り当ててから、サービスリソースをサービス担当者に割り当てます。サービスリソースが割り当てられていない場合、サービス担当者はオフライン時に Command Center for Service に表示されません。

メモ 外部ルーティングでは、スキルベースのルーティングまたは直接担当者へのルーティングはサポートされません。
  1. スキルベースのルーティングのしくみ
    オムニチャネルのスキルベースのルーティングでは、必須スキルに基づいて作業項目を最も適格なサービス担当者と照合します。作業項目が作成されると、オムニチャネルはルーティング設定、スキルベースのルーティングルール、およびオムニチャネルフローの [作業を転送] アクションに渡されるスキル要件に基づいて、必要なスキルを決定します。次に、オムニチャネルは、必要なスキルと作業に対応できる業務量をすべて持つサービス担当者に項目を転送します。
  2. スキルベースのルーティングとキューベースのルーティングの違い
    スキルベースのルーティングでは、キューベースのルーティングより高度で動的な条件を使用して作業項目を転送できます。
  3. スキルに転送するための準備
    スキルへのルーティングを設定する前に、スキルベースのルーティングの制限を確認し、オムニチャネルを設定して、次の前提条件タスクを完了してください。
  4. スキルベースのルーティングの制限事項
    スキルベースのルーティングを実装する前に、その制限を確認してください。

  3. 作業項目にスキルを追加するには、スキルを選択します。

  4. [転送] をクリックします。
    メモ スキルベースでルーティングされるチャットの場合、[転送] アイコンはオムニチャネルコンポーネントの [私の作業] タブの作業項目にあります。

状況ベースの業務量モデルの設定

状況ベースの業務量モデルを使用して、サービス担当者の業務量をより正確に測定します。このモデルでは、オムニチャネルは進行中のタブとセッションではなく、受け入れ済み作業の状況に基づいてサービス担当者の業務量を決定します。サービス担当者が対応できない場合や作業タブを閉じた場合、作業が完了または再割り当てされるまで、作業は割り当てられたままで業務量に適用されます。サービス担当者は、作業を一時停止して後で完了することもできます。一方、タブベースの業務量モデルでは、サービスコンソールで作業タブが閉じられたときにサービス担当者の業務量が解放されます。

状況ベースの業務量モデルに関する考慮事項

状況ベースの業務量モデルを使用するときには、次の点に留意してください。

状況ベースの業務量を使用する前に、次の考慮事項を確認してください。

  • 状況ベースの業務量モデルでは、オムニチャネルで合計 100 個の作業項目をサービス担当者に割り当てることができます。オムニチャネルコンポーネントには、割り当てられた最初の 20 個の作業項目が表示されます。追加の 20 個の作業項目を開いたままにして割り当てることができますが、サービス担当者の業務量には影響しません。他の作業項目を表示するには、サービス担当者が他の作業項目を閉じてオフラインになり、オンラインに戻る必要があります。
  • オムニチャネルで最初にキューまたはスキルを使用して作業を割り当てた場合にのみ、作業項目でサービス担当者の業務量が消費されます。状況ベースの業務量が有効になる前に作成された作業項目は、サービス担当者の業務量には適用されません。
  • サービス担当者が管理可能な作業負荷を確保できるように、オムニチャネルからのみ割り当てを処理する必要があります。
  • サービス担当者が最優先の作業に取り組めるように、オムニチャネルでは作業に優先順位を付けます。
  • 状況ベースの業務量を設定するときに業務量チェックボックスをオンにしない場合、自動化ルールはトリガーされません。
  • 会話後作業 (ACW) は、状況ベースの業務量モデルと互換性がありません。
  • 状況ベースの業務量モデルで Voice を使用している場合、営業担当は自分のオムニチャネル状況を設定できません。
  • 連絡要求は状況ベースの業務量と互換性がないため、状況ベースの業務量モデルでは、オムニチャネル統合ルーティングで転送される音声通話のコールバックはサポートされません。
