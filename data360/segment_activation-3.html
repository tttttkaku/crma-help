Data 360 データアクションとフローの統合

Data 360データ アクションは、ストリーミング イベントとインサイトをSalesforceフローに送信してオーケストレーションを促進できます。オーケストレーションでは、フェーズ、ステップ、決定を使用して複雑なビジネスプロセスを整理します。

データアクションをフローに統合する前に、完了する必要があるタスクを確認します。

  • Data 360 でのカスタムオブジェクトの作成
    データアクションをフローと統合するカスタムオブジェクトを作成します。カスタムオブジェクトには、会社または業種に固有の情報が保存されます。ビジネスに関連するすべての情報を 1 か所で追跡できます。
  • プラットフォームイベントトリガーフローの作成
    ビジネスプロセスを自動化し、データレコードが変更されたときにフローを内部で起動します。フローは、Salesforce または外部システム内でデータを収集し、アクションを実行します。

セグメント属性の循環パスの使用に関する問題

関連属性を選択しているときに DMO を複数回選択する場合は、循環パスを作成します。循環パスとは、循環動作 (a →b →a) を使用するリレーションです。循環パスによって、セグメントのパフォーマンスが低下し、計数や公開が失敗する可能性があります。この問題を回避するために、Data 360 ではデフォルトでセグメントビルダーを使用して循環パスを作成できません。

メールエンゲージメントが 2 回使用される次の循環パスの例について考えてみましょう。

次に、関連属性で [セグメント対象] エンティティが使用される別の例を示します。パスは、取引先 ([セグメント対象] エンティティ) からケースに進み、その後、取引先に戻ります。

メモ Data 360 では、以前に作成した循環パスがセグメントに保持されます。
メモ 特定の状況で循環パスを使用する必要がある場合は、組織の循環パスを有効にするようにサポートに依頼してください。

Data 360 セグメントスケジュールの管理

セグメントスケジュールオプションを使用すると、セグメントの公開頻度を詳細に制御できます。セグメントをスケジュールして、ニーズに最適な頻度で実行できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要な権限セット
公開をスケジュールする

次の権限セットのいずれか:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト

Data 360 での標準セグメントの作成。次に、ニーズに基づいてスケジュールします。

標準公開のスケジュール

  1. セグメントの詳細を入力したら、公開種別として [標準公開] を選択します。
  2. [実行モード] で、[スケジュール] を選択します。
  3. [頻度] で、セグメントを公開する頻度を選択します。毎日、毎週、または毎月公開できます。
  4. [毎日の頻度] を選択した場合は、次のサブステップを実行します。
    1. ドロップダウンから [12 時間] または [24 時間] を選択して期間を設定します。
    2. [開始日] と [開始時刻] を入力してスケジュールを開始します。
    3. 公開を実行する曜日を選択します。
    4. (省略可能) 終了日を設定するには、[一度に] を選択し、終了日と終了時刻を入力します。
  5. [頻度を毎週] を選択した場合は、次のサブステップを実行します。
    1. 公開を実行する頻度を決定する週数を入力します。
    2. [開始日] と [開始時刻] を入力してスケジュールを開始します。
    3. 公開を実行する曜日を選択します。
    4. (省略可能) 終了日を設定するには、[終了] ドロップダウンから [ある時点で] を選択し、終了日と終了時刻を入力します。
  6. [頻度] [毎月] を選択した場合は、次のサブステップを実行します。
    1. 公開を実行する頻度を決定する月数を入力します (最大 24 か月)。
    2. [On day (オン)] を選択して特定の日付を入力するか、[On last day (最終日)] を選択して月の最終日にスケジュールします。
    3. [開始日] と [開始時刻] を入力してスケジュールを開始します。
    4. (省略可能) 終了日を設定するには、[一度に] を選択し、終了日と終了時刻を入力します。
    メモ スケジュールに 29、30、または 31 日を選択し、選択した月にその日が含まれない場合 (2 月や 30 日が含まれる月など)、その月のセグメント公開はスキップされます。
  7. セグメントを保存します。

高速公開のスケジュール

  1. セグメントの詳細を入力したら、公開種別として [高速公開] を選択します。
  2. [実行モード] で、[スケジュール] を選択します。
  3. [頻度] は、デフォルトで [毎日] が選択されています。 
  4. ドロップダウンから 1 時間または 4 時間を選択して間隔を設定します。
  5. [開始時間] と [終了時間] を入力して、公開を実行するその日の期間を決定します。
  6. [開始日] と [開始時刻] を入力してスケジュールを開始します。
  7. 公開を実行する曜日を選択します。
  8. (省略可能) 終了日を設定するには、[一度に] を選択し、終了日と終了時刻を入力します。
  9. セグメントを保存します。
メモ セグメントの最終更新を確実に実行するには、[終了時刻] を計算された最終更新時刻より後に設定します。スケジュールの [終了時刻] が更新時刻 (T15:00Z で終了する 24 時間更新で [終了時刻] が T15:00Z など) と同じ場合、有効期限が優先され、最終更新はスキップされます。
メモ スケジュール済み公開日時を更新しても、セグメントレコードページの [次の公開日時] 項目はすぐに更新されません。この値は、次の公開が完了した後にのみ再計算および更新されます。

このスケジュールは、セグメントの詳細ページで表示できます。 

パラメーターへのコミュニケーション制限の有効化対象の対応付け

コミュニケーション制限を有効化対象に適用するには、対象をパラメーターにマッピングする必要があります。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要な権限セット
有効化対象を作成してコミュニケーション制限を使用する

次の権限セットのいずれか:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  1. Data Cloud で、[有効化対象] をクリックします。
  2. 有効化対象を選択します。
  3. [Map Target to Parameters (対象をパラメータに対応付け)] セクションで、[追加] をクリックします。
  4. チャネル、部署、市区郡などのパラメーターを選択します。
  5. [保存] をクリックします。

コミュニケーション上限の有効化対象の有効化を作成すると、対応付けられたパラメーターが有効化概要に表示されます。

目標をパラメーターに対応付けたら、顧客セグメントを作成してコミュニケーション上限の有効化対象に有効化します。

JSON ベースの外部有効化対象のデジタル識別子の取り込みとモデル化

標準 ContactPointDigitalId データモデルオブジェクト (DMO) を使用して、デジタル識別子データを取り込んでモデル化します。独立系ソフトウェアベンダー (ISV) は、有効化ツールキットを使用して、この DMO を照会し、デジタルメディアプラットフォーム全体でデジタル ID を解決する有効化を構築します。

必要なエディション

使用可能なインターフェース: Lightning Experience 使用可能なエディション: Developer Edition、Enterprise Edition、および Unlimited Edition
メモ 匿名デジタル識別子を有効化するには、デジタル識別子を個人 DMO のカスタム項目に対応付ける代わりに ContactPointDigitalID DMO を使用することをお勧めします。

データをマッピングする前に、ターゲットブループリントを理解することが重要です。ソース識別子を ContactPointDigitalId DMO に対応付けます。有効化が機能するには、この DMO が個人 DMO と多対一 (N:1) リレーションを確立している必要があります (ContactPointDigitalId.ssot__IndividualId__c を Individual.ssot__Id__c にリンク)。[データモデル] タブでこのリレーションを確認または作成できます。特定のデジタル識別子 (UID2、RampID など) に依存する JSON ベースの外部有効化プラットフォームで有効化ツールキットを使用する場合、この対応付けは必須です。

メモ

有効化の対象がメールまたは電話ベースの宛先 (ContactPointEmailまたはContactPointPhoneを使用) のみの場合、この DMO は省略可能ですが、すべてのデジタル ID をここで一元化することをお勧めします。

ソースデータの準備

CSV/ファイルの取り込み、取り込み API、WebSDK など、複数の方法でデータを取得できます。取り込み方法 (バッチまたはストリーミング) に関係なく、ソースデータ構造で DMO に必要な詳細なマッピングがサポートされている必要があります。ソースデータをピボットして、識別子の種別に 1 つの列、値に別の列を設定します。

メモ [デジタル ID 種別] と [デジタル ID 値] は ContactPointDigitalId DMO の特定の項目です。ソースデータは、これらの項目に明示的にマッピングされて取り込まれる必要があります。

ID 種別の対応付けの設定

データストリームのマッピングを開始する前に、ソースデータの識別子種別が Data 360 の [設定] ページの設定と完全に一致していることを確認します。

Data 360 管理者ユーザーとして、[Data 360 Setup]> [External Activation Target]> [[Target Name]]> [ID Type Mapping] に移動して、ID タイプの対応付けを設定します。

ソースデータの Digital_ID_Type 列の正確な文字列値 (「TD ID」など) は、Data 360 管理者が [ID 種別] 列で設定した文字列と完全に一致する必要があります。Data 360 は有効化時にこの文字列を厳格な検索条件として使用するため、大文字と小文字が一致しない場合 (たとえば、データの値が「TDID」と表示されるのに対し、Data 360 の設定では「TD ID」と表示される)、有効化されたレコードは 0 になります。

メモ

有効化時に、最終的な計算には、左列にパートナーがサポートする ID 種別 (Google など) と右列にマッピングされたすべての別名 (GID、gid、GAid など) の両方が含まれます。この例では、DigitalIdType値が Google、GID、gid、または GAid の ContactPointDigitalId DMO のレコードは、対応する対象に対してアクティブ化されます。

データストリームの作成とマッピング

ソースファイルを準備したら、データストリームを作成して標準 DMO に対応付けます。

メモ Data 360 では、新しい DMO は自動的にリンクされません。これらの対応付け手順を完了したら、ContactPointDigitalIdとIndividualの関係を手動で作成する必要があります。
  1. データストリームを作成し、データソースを参照します。
  2. マッピングキャンバスで、プロファイルデータを個人 DMO にマッピングします。
    • Map Individual_ID -> Individual.IndividualId
    • Map FirstName -> Individual.FirstName
    • 匿名ユーザーを有効化する場合、名や既知の顧客 ID などの標準プロファイルデータがありません。 この場合、デバイスの ID や Cookie ID などの永続的なデジタル識別子を使用して、個人のプロファイル ID として動作する必要があります。 この値を [ssot__IndividualId__c] フィールドにマッピングして、データモデルで匿名個人を表します。
  3. マッピングキャンバスで、データレイクオブジェクト (DLO) のソース項目を ContactPointDigitalId DMO の特定の項目に対応付けます。有効化時に母集団エラーがゼロにならないようにするには、項目レベルの適切な対応付けが不可欠です。
    対象項目 (ContactPointDigitalId DMO) ソース項目の説明 備考
    ssot__Id__c (プライマリキー) 一意のレコード ID (デバイス ID、イベント ID、UUID など) これは、レコード自体の一意のキーである必要があります (device_id や event_id など)。ここでデジタル ID 値を対応付けないでください。
    ssot__IndividualId__c 個人 ID このデジタル ID を特定のプロファイルにリンクします。
    ssot__DigitalIdType__c 種別文字列 (「TDID」、「GoogleID」など) これは、それがどのような ID であるかを識別します。この ID では、大文字と小文字が区別されます。
    ssot__DigitalIdValueText__c 実際の ID トークン プラットフォームで使用される英数字文字列 (UID2 トークンなど)。
  4. 2 つのオブジェクトをリンクするリレーション項目を対応付けます。このステップは重要です。
    • Map Individual_ID -> ContactPointDigitalId.IndividualId__c
    • データモデルリレーションを確認または作成します。[データモデル] タブに移動し、ContactPointDigitalId と Individual の間に多対一 (N:1) リレーションが存在することを確認します。存在しない場合は、ContactPointDigitalId.ssot__IndividualId__cをIndividual.ssot__Id__cにリンクして手動で作成します。

この対応付けにより、有効化に必要な適切な関連データ構造が作成されます。

Marketing Cloud Engagement データアクションターゲット

データとインサイトを使用してビジネス評価指標を向上させ、Marketing Cloud Engagement で Journey Builder API イベントと取引メールを送信することによって顧客とのやりとりの遅延を減らします。Data 360とエンゲージメントを組み合わせて、トランザクションを自動化およびパーソナライズします。データトリガーのメールメッセージとジャーニーを使用して単純な運用タスクを自動化したり、取引開始数を最大化したり、顧客の離脱率を最小限に抑えたりすることが可能です。

必要なエディション

使用可能なエディション: Data Cloud でサポートされているすべてのエディション。Data Cloud エディションの使用可能状況を参照してください。

Engagement データアクションターゲットには次の利点があります。

  • レイテンシの削減 — Engagementを通じてData 360データ アクションを使用することで、データをほぼリアルタイムでアクションにできます。
  • 単純な設定と使用 — 直観的な UI により、誰でも簡単にデータアクション作成できます。
  • 柔軟性 — 会社の規模に関係なく、ほぼリアルタイムのオーケストレーションをあらゆる使用事例に適用できます。

顧客の行動またはアクションに基づいて、Data Cloud データモデルオブジェクトや計算済みインサイトから顧客へのメールやジャーニーをトリガーします。

  • Marketing Cloud Engagement データアクションターゲットの作成
    Data 360から転送された行動またはトランザクションイベントデータに基づいて、顧客に自動メールとジャーニーを送信します。データモデルオブジェクト (DMO) と計算済みインサイトから顧客へのメールとジャーニーをトリガーします。たとえば、顧客が商品を購入し、Web サイトで「インストールマニュアル」を検索するとします。ハウツー動画またはインストール手順が記載されたメールを顧客に送信するイベントをトリガーします。
  • Data 360 でのデータエクステンションの作成
    Data 360 で直接、データアクションの Journey Builder API イベントのデータエクステンションをすばやく作成します。この自動化プロセスにより、Marketing Cloud Engagement にアクセスする必要がなくなります。

パッケージマネージャーを使用した配布用外部有効化プラットフォームのパッケージ化

警告 未管理パッケージを配布すると、Amazon S3 ログイン情報が公開され、新しいパッケージバージョンをシステム管理者に転送できない可能性があります。
  1. パッケージマネージャーに移動します。
  2. パッケージを作成する前に、[名前空間設定] で既存の名前空間がないかを確認します。ない場合には、[編集] をクリックして作成します。

    重要 各組織でサポートされる管理パッケージは 1 つのみです。この組織に既存の管理パッケージがある場合は、新しいパッケージを作成するのではなく、そのパッケージを選択して新しいバージョンをアップロードします。新しいバージョンを追加しても、以前に公開されたバージョンには影響しません。
  4. 新規パッケージの場合は、パッケージに関する情報を入力します。[パッケージ名] は、Data 360 管理者にインストール先として表示されます。
  5. [管理] チェックボックスをオンにします。
    メモ [管理] チェックボックスは、新規パッケージを作成する場合にのみ使用できます。チェックボックスがグレー表示になっている場合、組織にはすでに管理パッケージがあります。その場合は、既存の管理パッケージを選択して新しいバージョンをアップロードします。
  6. [保存] をクリックします。
  7. [コンポーネント] で、[追加] をクリックします。
  8. [コンポーネントの種類] で、[有効化プラットフォーム] を選択します。
  9. [外部有効化プラットフォーム] を選択します。
  10. [パッケージに追加] をクリックします。
  11. [コンポーネント] タブで、もう一度 [追加] をクリックします。
  12. [コンポーネントの種類] で、ドロップダウンリストをクリックし、[ActivationPlatformCredential] を選択します。
  13. 自動作成されたカスタムメタデータの横にあるチェックボックスをオンにします。JSON ベースの外部有効化プラットフォームの場合、表示されるプラットフォームログイン情報は、JSON 設定で指定されたプラットフォームの開発者名と一致します。
  14. [パッケージに追加] をクリックします。
  15. [アップロード] をクリックします。パッケージマネージャーによってパッケージの URL が生成されます。
  16. バージョン名やバージョン番号など、パッケージの詳細に関する情報を入力します。
  17. [リリース種別] で、[管理-リリース済み] の商品配分を選択します。
    ヒント 商品配分の前に本番以外の環境でテストするには [管理 - ベータ] を選択します。
  18. [アップロード] をクリックします。
  19. アップロードが完了したら、システム管理者とインストール URL を直接共有するか、ISV パートナーになって AppExchange のアプリケーションとしてパッケージをリストします。

外部有効化プラットフォームがパッケージ化され、Data 360 管理者がインストールして使用できる状態になっています。

メモ 外部有効化プラットフォームバージョンに対する一部の変更では、システム管理者が以前に作成した有効化対象を再保存する必要があります。新しいバージョンのパッケージの配布時に問題が発生しないように、次のようにすることをお勧めします。
  • 今後のバージョンアップグレードで既存の識別子種別 (ハッシュされたメールなど) を削除しない。
  • 項目で同じ省略可能または必須の設定を維持し、非表示の項目で同じデフォルト値を維持する。
  • 有効化プラットフォームパッケージのテスト
    アクティベーション プラットフォーム パッケージを、Data 360 ライセンスがプロビジョニングされた Enterprise Edition または Developer Edition 組織にインストールしてテストします。アプリケーションの開発時にファイル出力をより迅速にテストして検査するには、Developer 組織を使用して手動での有効化の公開をトリガーします。Enterprise 組織で有効化プラットフォームアプリケーションをテストする場合、有効化出力がユーザー識別子 (PER_USER) でグループ化されていれば、有効化ファイルは 24 時間ごとに公開されます。有効化の出力がセグメント (PER_SEGMENT) でグループ化されている場合、更新スケジュールはセグメント公開スケジュールに関連付けられます。

クラウドファイルストレージでの外部有効化プラットフォームセグメントの検索

システム管理者が外部有効化プラットフォームをインストールすると、クラウドファイルストレージ (Amazon S3) へのセグメントを受信できます。有効化対象ごとに、ユーザー識別子で出力がグループ化されている場合 (PER_USER)、ID 種別ごとに 1 日 1 回、成功ファイル、メタデータファイル、有効化出力ファイルを受け取ります。ファイルは1日に1回しか到着しないため、Data 360のお客様がセグメントを更新してからその変更がS3に到着するまでに遅延が生じます。

  1. クラウドファイルストレージにログインします。
  2. 外部有効化プラットフォームを作成したときに [バケット名] 項目で指定したバケットに移動します。
  3. s3://{Bucket-Name}/{Date}/{Account-ID}/{Activation-Run-ID}/type={ID-Type}/ に移動します。
    セグメントは 24 時間ごとに複数の CSV、NSVSON、Parquet ファイルとして公開されます。出力がユーザー識別子 (PER_USER) でグループ化されている場合、識別子種別ごとに複数の部分ファイルが配信され、各部分ファイルは個別に圧縮された GZIP ファイルになります。有効化の出力がセグメント (PER_SEGMENT) でグループ化されている場合、更新スケジュールはセグメント公開スケジュールに関連付けられます。
  • クラウドファイルストレージの外部有効化プラットフォームファイル

管理パッケージ

AppExchange にアプリケーションを表示する場合は、管理パッケージを使用します。管理パッケージでは、開発者に固有のコンテンツを作成する名前空間が使用されます。また、登録者組織にインストールされているパッケージをアップグレードできるバージョン管理とプッシュアップグレードもサポートされています。

一部の Salesforce ユーザーは、アプリケーションライフサイクル管理の一部としてパッケージを使用します。

未管理パッケージ

未管理パッケージは、任意の Salesforce エディション (Enterprise、Unlimited、Performance、Developer) で作成できます。未管理パッケージはアップグレードできませんが、インストール後、パッケージ内のすべてのコンテンツを編集できます。インストールしたコンテンツを新しいバージョンに置き換えるには、アンインストールしてから新しい未管理パッケージを再インストールします。

専用 Data 360 パッケージ

Data 360 メタデータを使用して管理パッケージを作成する場合、Data 360 メタデータのみを含む個別のパッケージを作成して、Data 360 メタデータを他の Salesforce メタデータから分離する必要があります。次に、専用の Data 360 パッケージと関連パッケージ間のパッケージ連動関係を作成します。

ロック解除済みパッケージ

ロック解除済みパッケージは、Salesforce メタデータのコンテナです。組織全体でカスタマイズを追加、編集、削除、リリースするための追跡可能な方法が提供され、社内のビジネスアプリケーションの管理とアップグレードが容易になります。Data 360 オブジェクトでは、ロック解除済みパッケージはサポートされていません。

Data 360 の第二世代管理パッケージ

Salesforce には、第一世代管理パッケージ (1GP) と第二世代管理パッケージ (2GP) があります。今後、すべての新規パッケージは第二世代管理パッケージを使用して作成することをお勧めします。管理 2GP パッケージを使用して、ソースを整理し、小さなモジュール型パッケージを作成し、バージョン管理システムと統合して、カスタム Apex コードをより適切に使用できます。バージョン管理が情報源であるため、パッケージ化組織やパッチ組織はありません。

管理パッケージでのメタデータのロックとロック解除

管理パッケージのすべての Data 360 機能メタデータはロックされます。パッケージ所有者は、データキットメタデータを制御および未承認の変更から保護できます。パッケージをインストールしてデータキットコンポーネントをリリースすると、コンポーネントはロックされます。登録者はエンティティを追加できますが、リリースされた対応付けやエンティティを変更または削除することはできません。リリースされたメタデータエンティティに変更が加えられると、データキットが再リリースされるときに上書きされます。

バージョン設定

パッケージバージョンを使用して後続のパッケージバージョンをリリースすることにより、管理パッケージのコンポーネントを適切にアップグレードできます。そのパッケージを使用する既存のユーザーに影響を与えることもありません。

転送アップグレード

登録者を新しいバージョンのパッケージに自動的にアップグレードします。この機能は、すべての組織がパッケージの同一バージョンまたは最新バージョンを使用していることを確認するために使用できます。

AppExchange

パッケージを配布するために AppExchange で公開するには、パッケージが「管理-リリース済み」状態である必要があります。

セグメントの有効化と関連属性の追加および絞り込み

セグメントが完了したら、次のステップはセグメントの有効化と関連属性の追加です。このキャンペーンは特定の日付範囲内の新規自動車保険契約を持つユーザーに固有のものであるため、他の契約が Marketing Cloud に送信されないように検索条件を追加します。

Marketing Cloud の有効化対象を設定してから、有効化を作成します。

  1. [Data 360 Segment] タブで、[New Auto Policy Holders] タブを選択します。
  2. セグメントレコードの [有効化] セクションで、[新規] をクリックします。
  3. 有効化対象 (セグメントデータの送信先) として、[Marketing Cloud Engagement-Cumulus BU] を選択します。
  4. 有効化メンバーシップを確認し、[続行] をクリックします。
  5. 次に、キャンペーンの連絡先 (チャネル) として [メール] をクリックし、[次へ] をクリックします。
  6. Cumulus のメールには、パーソナライズ目的で顧客の名、保険契約タイプ、保険契約番号を含めるためのプレースホルダーがあります。この情報が Marketing Cloud に送信されるようにするには、有効化に属性を追加します。[属性を追加] をクリックします。
  7. 個人 ID とメールアドレスに加えて、直接属性リストから [名] を選択してキャンバスにドラッグします。
  8. 関連属性リストから、次の操作を実行します。
    1. [RA_PolicyInformation_02] から、[保険契約番号]、[開始日]、[商品種別] を選択します。
    2. [RA_PolicyProducts] から、[商品種別 1] と [商品 ID] を選択します。
    3. [RA_Account02] から、[メンバーの名前] を選択します。
  9. [保存] をクリックします。
  10. [RA_PolicyInformation_02] の横にある [検索条件を追加] をクリックします。
  11. [商品種別] 属性を選択し、[演算子] を [次の値と等しい] に設定して、「Auto」(自動車) の値を追加します。
  12. [開始日] 属性を選択し、[演算子] を [最後の月数] に設定して、「1」の値を追加します。
  13. [完了] をクリックして [保存] をクリックします。
  14. このマーケティングキャンペーンに関連する適用可能な属性の制限を設定する場合は、[属性値の最大数] 項目を「2」に設定します。
  15. このキャンペーンは新規自動車保険契約の開始日に基づくため、[並び替え] ドロップダウンから [開始日] を選択し、[最新] を選択してデータの並び替え方法を定義します。
  16. RA_PolicyProducts は、商品 ID を降順で並び替えます。

セグメント利用者のグループ化、ランク付け、制限

Data 360 セグメンテーションのグルーピング、ランキング、制限ルールにより、セグメントビルダーに高度な複数レベルの絞り込みが追加されます。標準検索条件を適用したら、順次ロジックを使用してセグメント母集団のグループ化、ランク付け、制限を行い、より構造化されたバランスの取れた利用者を作成できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

グルーピングルール、ランキングルール、制限ルールには、次の高度な絞り込みオプションがあります。

  • データをグループ化: 共有属性に基づいてレコードをバンドルします (たとえば、同じ取引先 ID に属するすべての取引先責任者をグループ化します)。
  • Sort Data (Rank) (データの並び替え (ランク): 特定の属性に基づいて各グループ内のレコードを並び替えます (適合スコアの降順で取引先を並び替えるなど)。
  • データを制限: ランク付けされた各グループから選択するレコード数を制限します (たとえば、上位 10 件の取引先のみを保持)。

たとえば、次のような操作が可能です。

  • 地域内の取引先をランク付けし、地域ごとに上位 3 つの取引先を対象にします。
  • 候補に挙げられた各取引先内で、取引先責任者を権限レベルでランク付けし、取引先ごとに上位 3 件の取引先責任者を対象にします。
メモ ランク付けルールと制限ルールは、包含条件と除外条件に合格した適格なプロファイル内でのみ適用されます。データセット全体でグローバルランキングは実行されません。

考慮事項

  • グループ化、ランキング、制限は、プロファイル DMO とエンゲージメント DMO に基づくセグメントで使用できます。ルールを作成する場合、直接属性と集計可能な計算済みインサイトのみを使用できます。ランキングと制限は、関連属性ではサポートされません。
  • グルーピング、ランキング、制限ルールを使用するセグメントは、最終メンバーシップモードでのみ別のセグメント内にネストできます。これらのセグメントでは、[セグメント条件] オプションを使用できません。DBT、リアルタイム、または動的セグメントでは、グループ化、ランキング、制限はサポートされていません。ウォーターフォールセグメントでは、これらのルールは子セグメントにのみ適用でき、これらのルールを使用するセグメントは概算数の対象になりません。
  • 各ルールセット (またはコンテナ) に制限ルールを含めます。制限ルールを含むルールセットを単独で作成することも、1 つ以上の並び替えルールやグループルールと組み合わせることもできます。
  • 1 つのルールセット内で最大 3 つのグループルールと 3 つの並び替えルールを使用できます。
  • 絞り込みロジックを保持するために、順序の最後のルールセットのみを削除できます。前のコンテナに [グループ化単位] ルールが含まれている場合のみ、新しいルールセットを追加できます。
  • これらのルールで除外されたレコードは、セグメントの「除外母集団」数に追加されます。
  • ルールセットに属性を追加すると、Data 360 によってメインセグメントエンティティ (個人や取引先責任者など) へのリレーションパスが決まります。同じデータへの複数のリレーションパスが存在する場合があります。一貫性を保つために、ルールセット内のオブジェクトごとに 1 回のみコンテナパスを選択できます。このパスは、同じオブジェクトから追加した他の属性で自動的に再利用されます。
  • グルーピング、ランキング、制限を使用したセグメントの絞り込み
    Data 360 セグメンテーションでは、[包含] タブと [除外] タブで初期条件を設定したら、[ランクと制限] タブに移動してセグメントをさらに絞り込みます。最初のコンテナは自動的に作成され、セグメントの主エンティティにロックされます。このコンテナは、最も内側の絞り込みルールを定義します。

Data 360 から有効化対象へのセグメント更新の増加

Rapid Publish を使用して、セグメントの更新頻度を増やし、Data 360 から有効化対象への有効化の公開時間を短縮します。セグメントを作成するときに、1 時間または 4 時間間隔で日次スケジュールで実行するには、[高速公開] を選択します。

高速公開を使用するセグメントは、公開キューで優先されます。両方の公開種別でルックバック期間を設定できます。セグメントを作成したら、標準公開を高速公開に変更することはできません。次に、Marketing Cloud Engagement、Data Cloud、または Amazon S3、Microsoft Azure、SFTP、Google Cloud Storage (GCS) などのファイルストレージターゲットに対して有効化します。高速公開では、最大 20 個のセグメントを作成できます。

増分更新モードで高速公開を使用できます。詳細は、「有効化の更新種別」を参照してください

Marketing Cloud Engagement では、標準セグメントと高速セグメントがデータエクステンションとして有効化されます。登録者キーに対応付けられたプロファイル ID に基づく増分高速有効化インデックス。

例

ある金融サービス会社は、過去 30 日間にローン商品ページを参照した顧客を対象とする標準セグメントを作成します。迅速な公開を選択し、30 日間のルックバック期間を設定し、有効化データが営業日全体にわたってマーケティングチームに届くように月曜日から金曜日までの 1 時間の間隔を設定します。

セグメントキャンバス

Data 360 のセグメントキャンバスを使用して、直接属性と関連属性を選択し、作成したセグメントを対象利用者に絞り込みます。

ステップ

[属性] をライブラリからキャンバスにドラッグし、セグメントの検索条件を設定します。属性を独自のコンテナにドラッグするか、同じコンテナ内の他の属性と組み合わせて、属性間の AND または OR リレーションを作成できます。[直接] タブから、セグメント対象オブジェクトから (何らかのパスで) 1:1 または N:1 のリレーションを持つデータモデルオブジェクト (DMO) を選択できます。[関連] タブでは、任意のパス上のセグメント対象オブジェクトから 1:N リレーションを持つ DMO を選択できます。ライブラリには、オブジェクトがマッピングされている限り、標準オブジェクトまたはカスタムオブジェクトを含むすべてのオブジェクト種別が表示されます。

リレーション

ライブラリの属性には、他のオブジェクトへの複数のリレーションがある場合があります。オブジェクトに同じオブジェクトへのリレーションが複数ある場合、セグメントを作成するときに区別しやすくなるように、ライブラリにはオブジェクト名と関連する項目名の両方が表示されます。

オブジェクトにネストによる自身への複数のリレーションがある場合、属性ライブラリにはネストされたオブジェクトのみが 1 回表示されます。

一致ルールと調整ルールに基づいて、DMO グラフをガイドし、属性ライブラリに表示される DMO を決定します。個人 DMO に対して一致ルールと調整ルールが設定されている場合、対象エンティティ DMO と統合個人 DMO の間にリレーションが派生します。次の派生したリレーションはトラバース可能であり、個人 DMO は派生したリレーションのあるパスと共に属性ライブラリに表示されます。

コンテナパス内のオブジェクトリレーションは、大文字と小文字を区別して適用されます。Data 360 では、大文字と小文字を区別する 1 つの方法でデータテーブルを結合できます。この方法は設定できません。リンクされたレコードの値は完全に一致する必要があります。たとえば、SalesOrder.SoldToCustomer の値が c12d3、Individual.IndividualId の値が C12D3 の場合、この 2 つの値の大文字と小文字が一致しないため、レコードはリンクされません。

直接属性

直接属性は、セグメント化されるエンティティに関する 1 つのデータポイントまたは情報 (郵便番号、名、誕生日など) です。直接属性は、多くの場合デモグラフィック属性です。

例

1:1 リレーション

  • First Name (名): 各顧客に 1 つの名があります。
  • 誕生日: 各顧客の誕生日は 1 つです。

N:1 リレーション

  • 従業員から部門: 複数の従業員が 1 つの部門に属することができます。
  • Orders to Customer (顧客への注文): 1 人の顧客が複数の注文を行うことができます。

関連属性

関連属性は、複数のデータポイント、またはセグメント化されるエンティティに関連付けられた情報 (購入履歴、商品番号、メールのやり取りなど) のコレクションです。多くの場合、関連属性は行動またはエンゲージメントイベントです。

値項目

属性値が条件を満たしているかどうかを判断するために属性値と比較する値。クエリは特殊文字とアクセントに対して完全一致を適用し、大文字と小文字を区別しません。たとえば、「市区郡 | 次の値と等しい | Canon City」のクエリでは、市区郡 Cañon City は検索されません。「市区郡 | 次の値と等しい | Canon City」のクエリでは、canon city は検索されます。また、クエリではデータ型の完全一致が適用されます。たとえば、「購入注文番号」の項目のデータ型が文字列の場合、「購入注文番号 | 次の値と等しい | 0852」のクエリでは 0852 の購入注文番号が検索されます。 先頭に 0 がない購入注文番号 852 や引用符が付いた “0852” は検出されません。

セグメント数

セグメント数には、適用された検索条件に基づくエンティティ数が表示されます。セグメント対象が [個人] または [統合個人] の場合、データ削除または処理の制限要求が送信された個人プロファイルもカウントから除外されます。詳細は、「データ主体の権利」を参照してください。

パラメーター化された値が有効になっている場合、セグメント数は動的セグメントには適用されません。パラメーター化された値が有効になっている属性を持つ動的セグメントのセグメント母集団は空です。

検索条件レベル数は、直接属性検索条件で使用できます。そのフィルタに関連付けられたセグメント母集団が表示されます (たとえば、[Segment On Individual (個人のセグメント)] の [Gender = Female (性別 = 女性)] というフィルタは、性別が女性の個人の個別の数を示します)。フィルタを初めて追加するときには、件数は表示されません。リボンに [Calculate population (母集団の計算)] が表示されます。更新して計数を実行します。件数は明示的であり、このオプションが有効になっている場合、区分件数と同じおおよその母集団の動作に従います。

コンテナレベルの数は、関連属性検索条件 (コンテナ) で使用できます。そのコンテナに関連付けられたセグメント母集団が表示されます (たとえば、[セグメント対象個人] で、「1 つ以上の販売注文に Product Line = Luxury watch AND Shipping City = California (商品品目 = 高級時計と納入先市区郡 = カリフォルニア)」というコンテナは、そのような注文を少なくとも 1 つ持つ個人の個別の数を示します)。コンテナを初めて追加するときには、件数は表示されません。リボンには [Calculate population (母集団の計算)] が表示されます。更新して計数を実行します。件数は明示的であり、このオプションが有効になっている場合、区分件数と同じおおよその母集団の動作に従います。

主キーと外部キー

主キーは、顧客のメールアドレスや商品 SKU など、オブジェクトのレコードの一意の識別子です。外部キーは、別のテーブルの主キーを参照するテーブル内の項目です。外部キーは、データポイント (顧客 ID など) に基づいて 2 つのデータテーブルをリンクします。

主キーと外部キーの属性はセグメントキャンバスには表示されません。これらの属性を属性ライブラリで使用できるようにするには、主キーまたは外部キーとして割り当てずにカスタム属性を作成します。セグメントを作成するときに、このカスタム属性を使用します。

  • 属性によるデータのセグメント化
    セグメントを作成したら、セグメントキャンバスインターフェースで関連属性または直接属性に基づいてデータを絞り込みます。絞り込まれたオーディエンスから母集団のサブセットを絞り込んで、含まれる人と除外される人を確認します。セグメントの除外は省略可能です。
  • コンテナと属性を使用した絞り込み
    セグメンテーションキャンバスで、母集団を対象グループに絞り込むルールを定義できます。検索条件は、結果ごとにさまざまな方法で作成、組み合わせることができます。関連属性を使用して検索条件を定義すると、該当するルールオプションと共にコンテナがキャンバスに追加されます。関連属性のデータモデルオブジェクト (DMO) がコンテナオブジェクトになります。
  • セグメントの母集団の概算
    Data 360 でセグメントを作成するときに、[セグメントの母集団の概算] 項目を使用して、セグメント数が期待値を満たしていることをすばやく確認します。概算数は、95% の信頼性で可能な値の範囲として表される推定区分母集団を提供します。セグメントの母集団が小さい場合、またはセグメントのレコード件数が少ない場合、実際の母集団が推定範囲と異なる場合があります。その後、セグメントルールを調整してセグメントを保存すれば、最終的なセグメントの母集団を取得できます。この機能を使用するには、機能マネージャーで [セグメントの母集団の概算] を有効にします。
  • Data 360 のセグメンテーション演算子
    属性ライブラリからセグメントキャンバスにドラッグされた属性ごとに、その属性を変更する演算子を選択し、選択されたレコードを制限します。使用可能な演算子は、属性のデータ型によって異なります。
  • セグメントのタイムゾーン
    セグメント公開スケジュールはユーザーのタイムゾーンで解釈されます。Data 360 組織は、セグメントの初期保存およびセグメントキャンバスで公開タイムゾーンを設定します。セグメント項目と有効化項目には、ユーザーのタイムゾーンで公開スケジュールの開始日時が表示されます。
  • セグメンテーションでの値の提案の使用
    データ型が [テキスト] の場合、データモデルオブジェクト (DMO) 項目の値の提案を有効にできます。DMO レコードホームでこの機能を有効化または無効化します。値の提案は組織全体で最大 500 個の属性に対して有効にできます。提案された値が表示されるまで最大 24 時間かかる場合があります。
  • セグメント内の複数の ID 解決ルールセット
    同じエンティティに対して、異なる ID 解決ルールセットを適用した場合にセグメント母集団の件数に与える影響を比較します。ID 解決を使用して同じエンティティに対して別のルールセットを作成すると、両方のルールセットで作成されたエンティティと属性をセグメンテーションで使用できます。両方のルールセットの属性を使用して、異なる母集団を検証するか、A/B テストを行います。セグメント対象とするエンティティを選択しているか、属性を属性ライブラリに追加している場合、エンティティおよび属性名の末尾にはルールセット ID が含まれます。
  • セグメント内の複数の Marketing Cloud Engagement ビジネスユニット
    キャンペーン計画のセグメントの真のサイズを判断するには、ビジネスユニット (BU) でセグメントを絞り込みます。セグメントがビジネス ユニットで絞り込まれていない場合、Data 360セグメントの母集団とMarketing Cloud Engagementデータエクステンション数の差が大きくなる可能性があります。

セグメント基準

セグメント基準は、セグメントを作成するために使用される対象オブジェクトを定義します。取り込み時にプロファイルまたはエンゲージメント種別としてマークされたオブジェクトを選択できます。たとえば、統合個人、統合世帯、取引先、予約、販売注文などでセグメントを作成できます。

選択した対象オブジェクトによって、区分条件として使用できる属性ライブラリで使用可能な属性が決まります。

統合個人または個人

ID 解決を活用するには、セグメント対象として統合個人を使用します。ID 解決では、さまざまなデータソースのプロファイルデータ、行動データ、トランザクションデータを 1 つの統合個人としてセグメント化できます。

Data 360 の複数のデータソースからのデータがある場合、統合個人の ID 解決とセグメント化をお勧めします。ID 解決を使用していない場合、個人をセグメント対象として使用します。

統合個人は、世帯と呼ばれる個人のグループに統合できます。統合世帯でセグメント化して、特定の条件で世帯を特定します。

メモ 統合個人ではなく個人でセグメント化すると、件数内のエンティティが重複したりスキップされたりする可能性があります。

セグメントエラーのトラブルシューティング

Data 360 で最も一般的なセグメントエラーを解決するためのヒントを紹介します。

エラー トラブルシューティングの提案
セグメントが参照するデータレークオブジェクト (DLO) が多すぎる。
  • 計算済みインサイト (CI) を使用してセグメントが参照する DLO の数を減らします。
  • セグメントを複数の小さなセグメントに分割します。
セグメントが複雑すぎる。
  • 多数の属性とネストされた演算子の代わりに CI を使用します。
  • 多くのリレーションがある属性 (データモデルオブジェクト) の代わりに CI を使用します。
  • テキスト値を 1 つの Is In テキスト演算子に結合します。
セグメントで歪んだデータが返される。
  • データを Data 360 に取り込む前に、0 や Unknown などのプレースホルダー値をソースデータから削除してください。
セグメントが無効。
  • 無効なセグメントをコピーして、同じ母集団を持つセグメントを作成します。
同時に公開しようとしているセグメントが多すぎる。
  • 一部のセグメントの公開が完了するまで待ってから、もう一度試します。
  • 一部のセグメントの公開スケジュールを変更します。
セグメントの母集団の再カウントが処理中。
  • 再カウントが完了するまで待ってから、セグメントを再度公開します。
セグメントが処理されなかった。
  • Salesforce カスタマーサポートにお問い合わせください。
複数の母集団の計数が処理中。
  • 計数が完了するまで待ってから、もう一度試します。
  • 可能な場合は、セグメントを簡略化したり、ネストされたセグメントを使用したり、コンテナをマージしたりして、セグメントを改善します。
セグメントの母集団の計数に失敗した。
  • 可能な場合は、同じ結合パスを持つコンテナを特定し、ネストされた演算子を使用してマージします。
  • 長いパスを回避し、最も短い結合パスを使用して必要な属性にアクセスします。
  • セグメント内の循環パスを回避します。循環パスとは、循環動作 (a →b →a) を使用するリレーションです。セグメントの計数は失敗する可能性がありますが、セグメントジョブは正常に実行される可能性があります。
セグメントを公開できません。
  • 可能な場合は、コンテナをマージしてセグメントを簡略化します。ネストされた演算子を使用してコンテナをマージします。
  • 特にエンゲージメント種別データの場合、DMO 種別が正しいことを確認します。誤った DMO 種別ではタイムアウトが発生して失敗する可能性があります。
セグメント数/母集団が不一致。
  • セグメンテーションでは、エンゲージメント日に検索条件が適用されます (標準セグメントの場合は 24 か月、高速セグメントの場合は 7 日)。データエクスプローラーで、エンゲージメントイベント日付に必ず検索条件を適用します。
  • 日付演算子がテナントのタイムゾーンと一致することを確認します。
  • ソースデータが大きく変わったかどうか (大幅な追加、更新、削除) を確認します。
  • 計算済みインサイトをセグメントで使用しており、セグメント数またはセグメント母集団の予期しない増加または減少に気付いた場合、CI とセグメント実行間で ID 解決ルールが処理されたかどうかを確認します。
  • Data 360 のセグメンテーションでは、一意のプロファイル ID のリストが出力として生成されます。ただし、Marketing Cloud ではセグメンテーションに登録者キー属性が使用されるため、Data 360 と Marketing Cloud では母集団数が異なる可能性があります。
セグメントを編集できないか、セグメントエディター UI がタイムアウトする。
  • DMO レベルで [セグメント対象] で定義された不要なリレーションを削除します。問題が続く場合は、Salesforce カスタマーサポートにお問い合わせください。

メモ

2025 年 10 月 14 日以降、Data Cloud は Data 360 にブランド変更されました。 この移行中に、アプリケーションやドキュメントで Data Cloud への参照が見られることがあります。名前は新しくなりますが、機能とコンテンツに変更はありません。

データモデルのオブジェクトでセグメントを作成し、選択したスケジュールでまたは必要に応じて公開することができます。基本的なセグメントでも複雑なセグメントでも、Data 360 を使用する上で重要です。属性ライブラリを使用したセグメントの作成、計算済みインサイトのセグメントの拡張、およびセグメントデータの絞り込みについて説明します。

複合キーの制限事項:

  • セグメントキャンバスは、定義済みのリレーションを使用してデータを結合します。現在、これらのリレーションでは 1 つの項目のみがサポートされているため、Data 360 では複合キーのすべての項目を使用してデータを自動的に結合することはできません。これにより、母集団の数が不正確になったり、結合で 1 つの項目のみがランダムに選択されるセグメントになったりする可能性があります。
  • 複合キーは、複合キーのすべての項目が結合ロジックで明示的に定義されている手動クエリをユーザーが記述した場合にのみ正しく機能します。
  • セグメンテーションで一貫した正確な結果を得るには、1 つの一意の主キーでデータモデルオブジェクト (DMO) を使用します。
  • Data 360 での標準セグメントの作成
    データモデルオブジェクトに基づいて標準セグメントを作成し、セグメントを有効化対象に公開します。
  • リアルタイムセグメントの作成
    オンデマンドでミリ秒で完了するリアルタイムセグメントを作成します。セグメントをリアルタイムデータグラフで使用できるようにするには、セグメントメンバーシップ DMO オブジェクトの [セグメント ID] 項目と [タイムスタンプ] 項目をリアルタイムデータグラフに追加します。除外条件とネストされたバッチセグメントが含まれるリアルタイムセグメントは使用できません。リアルタイムセグメントでは、セグメント数と手動公開も使用できません。
  • ウォーターフォールセグメントの作成
    複数のオファーがあるキャンペーンを実行している場合、ウォーターフォールセグメントを使用して既存のセグメントのリストを優先度順に処理します。主な目標は、複数のセグメントの対象となる個人を、一致する優先度が最も高いセグメントにのみ配置することです。これにより、相互に排他的な一連のオーディエンスが作成されます。これは、顧客に最も関連性の高いオファーを 1 つだけ送信したいキャンペーンに最適です。
  • 動的セグメントの作成
    データモデルオブジェクト (DMO) に基づいて動的セグメントを作成し、セグメントメンバーシップ DMO にデータを保持せずにセグメントクエリを実行します。実行時に動的値を受け入れるプレースホルダーを使用して属性検索条件を定義します。
  • データキットからのセグメントの作成
    Data 360 でセグメントを最初から作成する代わりに、データキットの定義済みセグメントを使用します。セグメントを編集して微調整できます。
  • セグメントキャンバス
    Data 360 のセグメントキャンバスを使用して、直接属性と関連属性を選択し、作成したセグメントを対象利用者に絞り込みます。
  • セグメントエラーのトラブルシューティング
    Data 360 で最も一般的なセグメントエラーを解決するためのヒントを紹介します。
  • セグメンテーション検索条件の例
    さまざまな種類のセグメンテーション使用事例の検索条件の例を確認します。セグメントの開始点として次の例を使用し、キャンペーンに合わせて検索条件を追加して調整できます。
  • Data 360 の Einstein セグメント
    Einsteinセグメント作成生成AIを使用してセグメントを作成します。セグメントの概要説明を入力し、推奨セグメントとそのすべての属性を受け取ります。説明を変更して別のセグメントのドラフトを作成したり、セグメントの属性を編集して調整したりします。セグメントに問題がなければ、公開して有効化します。
  • セグメンテーションの請求に関する考慮事項
    セグメンテーションでは、セグメントデータの処理と公開に Data 360 が使用されます。セグメンテーションの使用は、次の使用量種別のクレジットの消費に影響します。

Marketing Cloud Engagement での Data Cloud セグメントの検索

Marketing Cloud Engagement に対してセグメントを作成および有効化したら、Contact Builder でセグメントを表示します。Data 360 セグメント サブフォルダは、最初のアクティベーションを公開するときに作成されます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

エンゲージメントフォルダーには、エンゲージメントユーザーが関連付けられているビジネスユニット (BU) でのみアクセスできます。Engagement では、Contact Builder でその BU の Data 360 セグメントを確認できます。

  1. Marketing Cloud で、[Contact Builder] をクリックします。
  2. [データエクステンション] をクリックします。
    1. [共有アイテム] をクリックします。
    2. [共有データエクステンション] をクリックします。
    3. [Customer 360 Segments (Customer 360 セグメント)] をクリックします。

セグメントが複数の BU に対して有効化されている場合、有効化されたセグメントは Data 360 サブフォルダに共有データエクステンションとして作成されます。共有データエクステンションの命名形式は segmentName_activationName_segmentID_activationID です。有効化対象の場合、共有データエクステンションフォルダーは選択した BU に基づきます。子ビジネスユニット (MID) では、デフォルトで親ビジネスユニット (EID) への権限が付与されます。MID で作成された共有データエクステンションには、EID でアクセスできます。MID が複数ある場合、特定の MID で作成された共有データエクステンションに他の MID のユーザーがアクセスすることはできません。

エンゲージメントセグメントの個人の数が Data 360 のセグメント母集団よりも少ない場合は、ナレッジ記事「 Data 360 segment counts don't match activation counts for a Marketing Cloud activation target (Data 360 セ グメント数が Marketing Cloud 有効化対象の有効化数と一致しない)」のヒントを参考にトラブルシューティングをお試しください。
