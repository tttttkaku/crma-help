Apex での予測の取得

Apex コードを使用して、モデルビルダーのコードなしモデルから予測、上位の要素、処方箋を取得します。

呼び出し可能なアクション

Apex で予測モデルを使用するには、このメソッドを使用して呼び出し可能なアクションを作成します。このメソッドは、予測モデルに入力データを提供する呼び出し可能なアクションを作成します。モデル要求をトリガーし、返された出力 (予測、上位の要素、処方箋 (推奨アクション) など) を処理します。

Invocable.Action.createCustomAction

REST 要求

モデルが有効化されると、呼び出し可能なアクションが自動的に作成され、フローまたは Apex で使用できます。Apex でこの呼び出し可能なアクションを使用する場合、この REST エンドポイントを使用して入力パラメータを取得する必要がある場合があります。

GET /services/data/v63.0/actions/custom/cdpMlPrediction/{ModelIdOrName}
メモ 予測モデル名 (この例では) またはモデル ID (API 参照名) を使用できます。一部の API では、モデル API 参照名「{ModelIdOrName}」も必要です。モデルの API 参照名は、モデルビルダーのモデルの詳細ページで確認できます。

Google Cloud Vertex AI ノートブックで Salesforce データにアクセスするには、Python コネクタを使用します。使いやすいインターフェースにより、Data 360 のデータをすばやく照会できるため、必要なデータを Python に抽出できます。

  1. Vertex AIワークベンチで、CDP Pythonコネクタをインストールして、Data 360オブジェクトにアクセスし、SalesforceデータをVertex AIに取り込みます。
  2. Python コネクタ設定の一環として、外部クライアントアプリケーションまたは接続アプリケーションを作成します。
    重要 Spring '26 以降、接続アプリケーションの作成は制限されます。 Spring '26 中およびそれ以降も、既存の接続アプリケーションを使用できます。 ただし、代わりに外部クライアントアプリケーションを使用することをお勧めします。引き続き接続アプリケーションを作成する必要がある場合は、Salesforce サポートにお問い合わせください。

    詳細については、「Spring '26 で新しい接続アプリケーションを作成できなくなりました」を参照してください。

  3. データに安全にアクセスするために、次のいずれかの方法で認証します。
    • Google サービスアカウントのログイン情報
    • API キー
  4. Data 360で、Vertex AIのSalesforceデータソースに接続してデータセットを照会します。たとえば、メールエンゲージメントデータを取得するには、Marketing Cloud Engagement のメールエンゲージメントオブジェクトにアクセスします。
  5. Data 360 で推測を使用するには、Python ファイルをノートブックにアップロードします。
  6. モデルエンドポイントを取得するには、[オンライン予測] セクションの Vertex AI ダッシュボードに移動します。モデルを Salesforce に接続するには次の詳細が必要なため、URL をメモします。

Google Cloud Vertex AI モデルの使用

Google Cloud Vertex AI と Salesforce のデータを使用して、高度なカスタム機械学習 (ML) モデルを作成、トレーニングして、リリースできます。Vertex AIでモデルを登録したら、予測条件を定義し、モデルをData 360に接続して、使用事例の予測とインサイトを取得します。このインサイトを使用して、顧客プロファイルの強化、セグメントの作成、さまざまなチャネルのエクスペリエンスのカスタマイズを行うことができます。

必要なエディション

使用可能なエディション: Developer Edition、Enterprise Edition、Performance Edition、および Unlimited Edition。

Salesforce のデータで Vertex AI モデルを使用すると、次のような利点があります。

  • Customer 360 全体で、厳選され、ハーモナイズされたほぼリアルタイムのデータにアクセスできます。 この機能により、よりインテリジェントな予測を提供するエキスパートモデルが創出されます。
  • Vertex AIでモデルを作成し、Data 360に簡単に接続して、ビジネスプロセスを最適化するための予測インサイトを利用します。使用事例には、購入傾向、リードの取引開始、商品の関心などが含まれます。
  • Salesforceでモデルと推測を簡単に運用できます。Data 360は、ビジネスプロセスからの結果の消費をシンプルにし、価値を高めます。
  • データへのゼロコピーの方法により、Google Cloud の複雑で、コストのかかる、ミスが発生しやすい抽出、変換、読み込み (ETL) ジョブが排除されます。この方法では、ビジネスの効率も向上します。
  • Vertex AI モデルを統合し、Salesforce で予測を取得します。ワークフロー自動化スイートであるフローを使用して、データに対するリアルタイムの更新に基づいて進化できる AI 主導の意思決定を可能にします。

Salesforce で Vertex AI モデルを使用する

  • Vertex AIでData 360データにアクセスして、モデルを作成、トレーニング、リリースします。
  • Data 360でVertex AIモデルを接続し、Salesforce全体のさまざまなワークフローで予測とインサイトの推測を消費します。
  • Vertex AI でのデータの設定
    Google Cloud Vertex AI ノートブックで Salesforce データにアクセスするには、Python コネクタを使用します。使いやすいインターフェースにより、Data 360 のデータをすばやく照会できるため、必要なデータを Python に抽出できます。
  • Vertex AI モデルの接続
    SalesforceでVertex AIモデルからの予測を使用するには、Data 360に接続して、使用事例の予測条件を定義します。

アクション可能な変数と処方箋

Data 360 からのデータを使用する AI モデル (旧 Einstein Studio) モデルビルダーでは、アクション可能変数はゼロから作成された (AI によって作成された) モデル内の項目であり、予測結果に影響を与えるために変更できます。他の項目 (顧客のロケーション、性別、年齢など) は変更できませんが、アクション可能変数は変更できます。これらの変数は、より適切な結果を得るためにユーザーが実行できる推奨アクション (処方箋) を提供するため重要です。

アクション可能な変数とその調整方法を次に示します。

  • Credit Limit (クレジット限度): 限度の引き上げを提案
  • 利率: さまざまな顧客グループの利率を設定します。
  • Product Price (商品価格): 商品の単価を引き上げる
  • 配送オプション: 送料無料または迅速な配送を提供

予測モデルのアクション可能変数を設定したら、次の Salesforce インテグレーションを使用して処方箋を取得できます。

一括処理データ変換

一括処理データ変換を使用して、大規模なデータセットでモデルを実行します。モデルでは、モデルビルダーで設定したアクション可能変数に基づいて、各データポイントの予測が生成されます。一括処理データ変換では、アクション可能変数を使用して処方箋を処理します。これらの処方箋は、データセットの各予測の横にある列に追加され、ダッシュボードなどの決定ツールに役立ちます。

例

[変数名]: [新しい値] - Discount_Offered: 10%

[影響値] - 20 (この値は、割引を 5% から 10% に変更すると、予測コンバージョンスコアが 20 ポイント増加することを意味します)。

フロー

自動フローを使用して、予測インサイトを価格の更新や提案の開始など、自動化されたパーソナライズされた指示的なアクションに変換します。これにより、意思決定の説明可能性と信頼性が向上します。アクション可能変数の設定後:

  • モデルは予測スコアを返すだけではありません。
  • モデルでは、結果を改善するために実行するアクションを提案する処方箋を返すこともできます。プロンプトビルダーを使用して、「提供期間を 7 日間延長」などのわかりやすい出力にすることをお勧めします。

これらの処方箋は、フローの呼び出し可能なアクション (cdpMlPrediction) の出力項目になります。特定の顧客、商品、または地域で何を変更するかを示す画面を作成できます。フローでは次のこともできます。

  • メッセージング、割引、ルーティングを規定の値に基づいて動的に調整します。
  • 最も影響する可能性の高いアクションに基づいて顧客をセグメント化します。たとえば、割引を提供したり、サービス担当者にエスカレーションしたりします。

フローに、担当者向けに作成された画面フローなどの画面要素がある場合、次の操作を実行できます。

  • 処方箋について詳細に説明します。
  • ユーザーに有効期限を提供します。例: 購入の可能性が 20% 高くなる可能性があるため、10% の割引を提供します。
例

新しいリードがシステムに追加されたときのフローロジックを見てみましょう。

  • トリガー: 新規リード
  • 予測: 取引開始の可能性が低い
  • 処方箋: 24 時間以内のフォローアップを提案
  • フロー結果: リードをトップサービス担当者に割り当て、同じ日に通話をスケジュールします。

このフローはループを閉じます。リードをスコアリングするだけでなく、営業担当がリードをフォローアップできるようにアクションを指示および自動化します。

  • アクション可能変数の設定
    モデルビルダーのアクション可能変数は、モデルの予測結果に影響を与えるために変更できる項目です。アクション可能変数を設定すると、モデルで処方箋 (結果を改善するためにユーザーが実行できる推奨アクション) を提供できます。

バイナリ分類総計値

バイナリ分類の総計値は、データを 2 つのクラスに分類するモデルのパフォーマンスを評価するのに役立ちます。

精度

AUC を使用する全体的な精度スコアに加えて、バイナリ分類モデルの精度を把握するための 2 つの追加の総計値があります。

モデルが正しい予測と誤った予測を行う頻度を表示します (1)。クラス間で予測が分類される方法のしきい値切り捨てポイントを表示します (2)。

混同行列

混同行列は、しきい値に基づいてさまざまなエラーの種類間のトレードオフを評価する場合に使用します。関連付けられたしきい値で、モデルが観察を正しく分類した回数と誤って分類した回数が表示されます。

ROC 曲線

受信者動作特性 (ROC) 曲線には、さまざまなしきい値設定でのパフォーマンス測定値が表示されます。ROC は確率曲線であり、AUC (曲線下面積) は分離可能性の程度を定量化します。グラフを使用して、モデルがどのくらい効果的にクラスを区別できるかを確認します。

ゲインおよびリフト

ゲイングラフとリフトグラフには、モデルの利点が示されます。これらのグラフは分析のためにスコアリングされランク付けされたデータの一部を使用して、モデルを使用して取得した結果とモデルを使用しないランダムな推測の比較を測定します。ゲインが大きくリフトが高いほど、モデルはより効果的です。

グラフ 説明
ゲイン

ゲイングラフでは、データのパーセント別に合計陽性率、つまりゲインが描画されます。モデルの線が理論的正確さ (完全なモデル) に近く、ランダムな推測 (モデルなし) から遠いほど、ゲインは大きくなります。ゲインは、組織のリソースに優先度を付けるために使用できます。

たとえば、あるモデルのゲインがデータの 20% で 80% であれば、上位 20% のデータで目標の 80% に到達できます。
リフト

リフトグラフでは、データのパーセント別に改善率、つまりリフトが描画されます。モデルが適切であるほどリフトが高くなります。

たとえば、モデルで 20% のデータでリフトが 2.5 の場合、モデルの結果はモデルなしと比べて上位 20% のデータが 2.5 倍優れていることになります。

4 回の交差検証の結果

4 回の交差検証のアプローチは、モデルの検証プロセスのサンプリングバイアスを減らします。この方法では、データをランダムに 4 つの同じサイズのパーティションに分割し、モデルは 4 つのテストパス (分割) を通ります。各パスでは 3 つのパーティションがトレーニングデータ、残りのパーティションがテストデータとして機能します。4 つのテストパスが完了すると、各パーティションは検証セットとして 1 回機能し、トレーニングセットの一部として 3 回機能したことになり、包括的な評価が保証されます。検証結果のテーブルを参照して、データの各分割に対応する総計値を調べます。

指標 説明
レコード数

観測の合計数。値の意味は、列ごとに異なります。

  • [トレーニングデータ] 列と [検証データ] 列では、この数値は同じです。この値は、モデルの作成で使用されるデータ全体の観測の合計数を表します。
  • [分割 #1] ～ [分割 #4] 列の場合、この値はその分割に含まれる観測数 (データ全体の約 25%) を表します。
AUC

曲線下面積 (AUC) は、ロジスティックモデルによる正分類率を表します。

  • 0.5 は、モデルのパフォーマンスがランダムな推測と同等であることを意味します。
  • 1.0 は、モデルで 100% の確率でデータが正しく分類されることを意味します。これは、データ漏洩を示している可能性があります。
GINI ジニインデックスは、このロジスティックモデルのパフォーマンスが、理論的に最適なモデルにどれほど近いのかを測定します。

その他の評価指標

モデル品質の評価によく使用される他の評価指標を検討します。

指標 説明
精度

精度は、モデルで正しく予測された結果の割合 (真陽性と真陰性) を測定します。

  • モデルの全体的な分類パフォーマンスを評価する場合に使用します。
  • 範囲は 0 ～ 1 で、値が大きいほどパフォーマンスが高くなります。
  • 次のように計算されます: (True Negative+True Positive)/(True Negative+False Negative+True Positive+False Positive).
F1 スコア

F1 スコアは、陽性予測値 (精度) と真陽性率 (リコール) の調和平均です。

  • バイナリ分類モデルの全体的なパフォーマンスを評価する場合に使用します。特に、偽陽性と偽陰性を最小限に抑えることが同様に重要な場合に使用します。
  • 範囲は 0 ～ 1 で、値が大きいほどパフォーマンスが高くなります。
  • 2*(Positive Predicted Value*True Positive Rate)/(Positive Predicted Value+True Positive Rate) として計算されます。
偽陰性 実際に陽性である予測陰性の数。
偽陰性率

偽陰性率 (FNR、タイプ II エラーまたはミス率とも呼ばれる) は、すべての実際の陽性に対する予測偽陰性の割合です。

  • 分類モデルで陽性が陰性として誤って分類される頻度や、偽陰性エラーを最小限に抑えることが重要である場合に使用します。
  • 指定できる範囲は 0 ～ 1 です。値が低いほどパフォーマンスが高くなります。
  • 次のように計算されます: False Negative/(False Negative+True Positive)
偽陽性 実際に負の予測陽性の数。
偽陽性率

偽陽性率 (FPR。タイプ I エラー、偽アラーム率、フォールアウトとも呼ばれる) は、すべての実際の陰性のうちの予測偽陽性の数です。

  • 分類モデルで陰性を陽性として誤って分類する頻度や、偽陽性エラーを最小限に抑えることが重要である場合に使用します。
  • 指定できる範囲は 0 ～ 1 です。値が低いほどパフォーマンスが高くなります。
  • 次のように計算されます: False Positive/(False Positive+True Negative)
情報性

情報性 (Youden の J 統計とも呼ばれる) は、モデルが肯定と否定の両方をどの程度適切に予測しているかを測定します。

  • バイナリ分類モデルの全体的なパフォーマンスを評価する場合に使用します。特に、真陽性と真陰性の分類が同様に重要な場合に使用します。
  • 範囲は -1 ～ 1 で、1 は完全なパフォーマンス、0 はランダムなパフォーマンス、-1 は完全な逆パフォーマンスを示します。
  • 次のように計算されます: True Positive Rate+True Negative Rate-1
有標性

有標性は、モデルによる陽性予測と陰性予測の信頼性を測定します。

  • バイナリ分類モデルの全体的なパフォーマンスを評価する場合に使用します。特に、肯定と否定のパフォーマンスを個別に評価することが重要です。
  • 範囲は -1 ～ 1 で、1 は完全なパフォーマンス、0 はランダムなパフォーマンス、-1 は完全な逆パフォーマンスを示します。
  • 次のように計算されます: Positive Predicted Value+Negative Predicted Value-1
MCC

Matthews Correlation Coefficient (MCC) は混同行列の 4 つの部分が他の分類評価指標よりも均等になっている表現を提供します。

  • 特にデータが不均衡な場合に、全体的なパフォーマンスを評価する場合に使用します。
  • 範囲は -1 ～ 1 で、1 は完全なパフォーマンス、0 はランダムなパフォーマンス、-1 は完全な逆パフォーマンスを示します。
  • 次のように計算されます: (True Positive*True Negative-False Positive*False Negative )/square root((True Positive+False Positive)*(True Positive+False Negative)*(True Negative+False Positive)*(True Negative+False Negative))
陰性的中率

陰性予測値 (NPV) は、すべての予測陰性に対する実際の陰性の比率です。

  • 分類モデルで陰性インスタンスがどの程度適切に予測されているかを評価する場合や、偽陰性を最小限に抑えることが重要である場合に使用します。
  • 範囲は 0 ～ 1 で、値が大きいほどパフォーマンスが高くなります。
  • 次のように計算されます: True Negative/(True Negative+False Negative)
正の予測値 (精度)

陽性予測値 (PPV、精度ともいう) は、すべての予測陽性に対する実際の陽性の割合です。

  • 分類モデルで陽性インスタンスがどの程度適切に予測されているかを評価する場合や、偽陽性を最小限に抑えることが重要である場合に使用します。
  • 範囲は 0 ～ 1 で、値が大きいほどパフォーマンスが高くなります。
  • 次のように計算されます: True Positive/(True Positive+False Positive)
True Negatives 実際に陰性である予測陰性の数。
真陰性率 (特異性)

真陰性率 (TNR、特異度ともいう) は、すべての実際の陰性に対する予測陰性の割合です。

  • 分類モデルで陰性を正しく分類する頻度や、陰性インスタンスを正しく識別することが重要である場合に使用します。
  • 範囲は 0 ～ 1 で、値が大きいほどパフォーマンスが高くなります。
  • 次のように計算されます: True Negative/(True Negative+False Positive)
真陽性 実際に陽性である予測陽性の数。
真陽性率 (感度、リコール)

真陽性率 (TPR、感度または想起とも呼ばれる) は、すべての実際の陽性に対する予測陽性の割合です。

  • 分類モデルで陽性が正しく分類される頻度や、陽性インスタンスを正しく識別することが重要である場合に使用します。
  • 範囲は 0 ～ 1 で、値が大きいほどパフォーマンスが高くなります。
  • 次のように計算されます: True Positive/(True Positive+False Negative)

データの問題の解決

モデル作成用のデータの準備時やモデルのトレーニング後に発生する可能性がある一般的な問題に対処します。

問題 アプローチ
極値と異常値 異常値は統計的に有意な計算で平均と標準偏差に影響するため、予測アルゴリズムは異常値に対して敏感です。異常値が見つかった場合、そのデータポイントは関連性があり、実在するかどうかを確認します。多くの場合、異常値はエラーです。極端なデータポイントが正確かつ予測可能で、繰り返し発生する場合、そのポイントが重要でなければ削除しないでください。
不正値 予測アルゴリズムは、入力情報が正しいと想定します。数行のみに不正値が含まれている場合は、何を行うかを決定します。つまり、分析からそれらの行を削除するか、不正値をより正確な値または平均値に置き換えます。多数の不正値がある場合、不正が発生した理由を調べ、修正可能かどうかを判断します。エラーの原因となる可能性が高い変数は、分析に含めるよりも削除した方がよい場合があります。
カテゴリ値の標準化 カテゴリ値では、一貫したカテゴリ名を使用してください。スペルのバリエーション (複数形や省略形など) を削除します。入力ミスやその他のエラーを修正します。また、意味のある、わかりやすい表示ラベルを使用します。
高カーディナリティ項目 高カーディナリティ項目は、多数の個別値を含むカテゴリ属性です。例として、名前、郵便番号、取引先番号などがあります。これらの変数は多数の情報を提供しますが、高カーディナリティ属性は予測モデリングではほとんど使用されません。この属性を含めるとデータの次元が大幅に増加し、ほとんどのアルゴリズムで正確な予測モデルを構築することが困難になる可能性があります。
順序変数 順序変数は、予測モデルでは問題となることがあります。順序データは、セット内の項目のランクを表すカテゴリデータの一種ですが、値の間隔が均一でなく、意味のあるものではありません。たとえば、1 位、2 位、3 位というように、販売金額に基づく営業担当者のランキングについて考えてみます。順位は明確ですが、ランク 1 位とランク 2 位の営業担当者の金額の差は、ランク 2 位とランク 3 位の差とは異なります。その他の例としては、教育レベル、満足度評価、評価スケールを用いた回答などがあります。順序値を使用する場合は、演算子をテキスト (カテゴリ) と数値 (連続) のどちらとして処理するかを検討してください。順序データが数値であれば、1 と 2 の評価は低く、3 は中間、4 と 5 は良いというように、意味のあるビンにグループ化しましょう。定数データがテキストの場合は、各値が個別に分析およびモデル化されます。
重複変数、冗長な変数、または高度に相関する変数 同じ情報が格納される重複変数、冗長な変数、その他の高度に相関する変数は最小限に抑えます。予測アルゴリズムは、このような共線変数がない場合にパフォーマンスが向上します。共線性は、2 つ以上の予測変数が高度に相関する場合に発生します。その結果、一方を他方からかなりの精度で線形的に予測できます。共線性を回避するには、高度に相関する複数の変数、または同じレポート階層のデータを含めないようにします。たとえば、タンパ市に住む顧客はフロリダ州にも住んでいます。2 つの連続変数間の高度な相関を識別するには、散布図を確認します。散布図のパターンで、変数間のリレーションが示されます。リレーションは線形または非線形です。リレーションの強度を調べるには、相関関係を計算します。相関関係は –1 ～ +1 の間で変動します。
欠損値 欠損値の最も一般的な修正は、分布の平均または計算値を使用して期待値を代入することです。平均値を使用する場合、標準偏差が低減される可能性があります。したがって、分布の代入方法の方が信頼性が高くなります。別の方法は、欠損値のあるレコードを削除することです。だだし、欠損値を安易に除外しないでください。欠損データ内にパターンが存在する場合があります。また、削除するレコード数が多すぎると、分析で実環境の側面が低減します。

モデリングデータのバイアス

データのバイアスは、不公正または不正確な予測につながり、意図せずに特定のグループに不利益を与えたり、ビジネス結果を歪めたりする可能性があります。AIモデル(旧称Einstein Studio)では、倫理的なモデルの構築は、まずデータのどこにバイアスがあるかを理解し、モデル ライフサイクル全体にわたってその影響を最小限に抑えるためのプロアクティブなアクションを実行することから始まります。

過去のデータには、客観的ではない既存の不平等や人間の決定が反映されます。

たとえば、顧客の優先順位付けを予測するモデルでは、既存の顧客プロファイルを継続的に優先することでサービス品質の不均衡を永続化できます。過去のサポートデータでは、重要度や支出パワーによって特定の顧客がより迅速に解決できたことが示されています。

モデルのトレーニングに使用される入力変数は、予測に不当に影響したり、隠れたバイアスを明らかにしたりする。これらは、選択によって導入されるか、データ内の変数の表現です。バイアスは、場所、年齢、性別など、特定の属性が予測に偏りがある場合に発生します。

たとえば、顧客満足度を予測するモデルでは、「優先されるコミュニケーションチャネル」変数を使用します。一部の顧客セグメントは、年齢、アクセシビリティ、文化的な要因により、特定のチャネル (チャット、電話、メール) を好みます。このモデルでは、エンゲージメントが優勢でないチャネルを使用しているグループの満足度が誤って判断されます。

表示ラベル

データの結果は、一貫性がない、不正確、または主観的な判断のために、一貫性がない、または不当にラベル付けされています。

たとえば、離脱を予測するモデルでは、「90 日以内に購入なし」という離脱表示ラベルが使用されます。ただし、季節性のある買い物客など、購入サイクルが長い顧客もいます。このモデルでは、セグメントの消費者行動は正常であっても、これらの顧客は「離脱」したと予測されます。

表示ラベルを監査して、実際の結果を正確に反映していることを確認します。

表示ラベルが明らかに矛盾している、または主観的であるデータポイントを除外します。誤って表示されたセグメントに、正しい表示ラベルが付いている十分な例があることを確認します。
サンプリング

トレーニングデータは、顧客や使用事例を表すほど多様ではありません。

たとえば、購入の可能性を予測するモデルでは、エンゲージメントスコアや満足度スコアが過大評価されます。無効な顧客や離脱した顧客は過小評価されているため、モデルは活動の少ない顧客セグメントから学習していません。

トレーニングデータを監査して、顧客ベースまたは使用事例のどのセグメントが過小評価されているかを特定します。また、異なるセグメント間でモデルのパフォーマンスを比較して、格差を特定します。

モデル品質の評価

トレーニング総計値を使用して、モデルで結果を予測する能力を評価し、有効化する準備ができているかどうかを判断します。トレーニング総計値は、モデルがトレーニングデータに含まれるパターンと関係をどれだけ効果的に理解しているかについての情報を提供し、その予測効果を示します。

モデル品質を評価する前に、主要概念を確認しておくと役に立ちます。

  • 結果変数とはモデルの目標であり、求められる予測あるいは結果です。
  • 変数とは、モデルが予測を行うために分析する入力データです。
  • トレーニングとは、モデルがパターンや関係を学習し、新しい未知のデータに対して予測を行うためのプロセスです。
ヒント どのモデルも完璧ではないため、予測には限界や不確実性があります。機械学習モデルの結果を解釈する際には、常に注意を払い、常識に基づいて判断してください。

精度

Einstein は、回帰の決定係数 R2 と 2 値分類の曲線下面積 (AUC) を使用して精度を測定します。Einstein は、パフォーマンスに関する標準的なしきい値に基づいて、モデルの全体的な精度が適切か、低すぎるか、高すぎるかを教えてくれます。

  • 「適切」は、モデルが全般的に正確であることを意味します。
  • 「低すぎる」は、ランダムな推測とほとんど同じであることを意味します。
  • 「高すぎる」は、場合は、モデルが (ほぼ) 完全であり、データ漏洩や過学習の可能性があることを意味します。

上位の予測因子

上位の予測因子は、結果の予測に最も影響する入力 (変数) です。

変数の分布

結果変数のデータの実際の値または観測された値の分布。

  • 回帰総計値
    回帰の総計値は、連続データの数値を予測するモデルの性能を評価するのに役立ちます。
  • バイナリ分類総計値
    バイナリ分類の総計値は、データを 2 つのクラスに分類するモデルのパフォーマンスを評価するのに役立ちます。

  2. 変数アラートを表示するには、[変数を準備] をクリックします。
  3. モデルに影響する問題についての詳細は、ページの右側に移動してアクションを選択します。たとえば、モデルのトレーニングの前に特定の変数を除外することで、多重共線性アラートを解決できます。

  1. モデルをクリックすると、その詳細が表示されます。

  1. モデルをクリックして、その設定を表示します。ここで、アラート種別や郡など、モデルアラートの詳細を確認できます。

曲線下面積 (AUC) 品質アラート

曲線下面積 (AUC) は、バイナリ分類のパフォーマンス指標です。2 つのクラス (肯定と否定、true と false、yes と no など) を区別するモデルの能力を測定します。AUC は、さまざまなしきい値設定で偽陽性率 (FPR) に対する真陽性率 (TPR) をプロットする受信者動作特性 (ROC) 曲線から取得されます。

考慮すべきアクション

  • AUC が低い場合は、モデルのパフォーマンスが低いことを示します。モデルを有効化する前に、モデルを改善することを検討してください。
  • 高い AUC は、モデルのパフォーマンスが非常に高いため、データ漏洩が発生している可能性があることを示します。データ漏洩の原因となる変数を調査してモデルから削除します。

検出方法

モデルビルダーでは、次の値に基づいて AUC が高いまたは低いことが検出されるとアラートが表示されます。

  • 0.6 を下回る (低)
  • 0.95 を上回る (高)

例

ある通信会社は、顧客が 1 か月以内に離脱する可能性を予測したいと考えています。会社はこれらの入力変数を使用してバイナリモデルを作成します。

  • 顧客在職期間
  • 月額料金
  • internet service type (インターネットサービス種別)
  • 苦情の数
  • コール数
  • データ使用量

モデルのトレーニング後、AUC スコアが想定よりも低かったため、アラートが表示されます (トレーニング AUC=0.58)。スコアはランダムな推測 (AUC=0.5) よりもわずかに優れています。これは、モデルが顧客を離脱させるか、サービスを続行させるかを区別できないことを示しています。この問題を解決するには、次の点を考慮してください。

  • 「顧客満足度スコア」、「顧客とのやりとり」、「競合他社のプレゼンス」などの追加変数を使用して、予測精度を向上させます。
  • 小さいグループ (チャーン) をオーバーサンプリングして不均衡なデータを改善するか、モデルのトレーニング中にクラスの加重を使用してチャーンデータの重要性を高めます。
  • データベースをクリーンアップして、不一致、異常値、欠損値を削除します。
  • ビジネス目標に基づいて精度と取り消しのバランスを取るように AUC しきい値を調整します。
  • 線形モデルのパフォーマンスが低い場合は、ランダムフォレストや勾配ブースティングなど、より複雑なモデリングアルゴリズムを使用します。
  • 更新されたデータセットを使用してモデルを再トレーニングします。

多重共線性アラート

多重共線性は、データセットの複数の変数 (「市区郡」と「郵便番号」など) の相関関係が高いことを示します。これらの変数は結果に重複の影響を及ぼす可能性があるため、高い共線性は過学習につながる可能性があります。つまり、モデルはトレーニングデータでは適切に機能しますが、モデルがまだ公開されていないデータでは適切に機能しない可能性があります。

考慮すべきアクション

結果を改善するには、1 つの変数のみを選択します。最もわかりやすい項目 (「city」など) を使用して、インサイトをよりわかりやすくします。

検出方法

モデルビルダーでは、多重共線性をテストする Cramér の V アルゴリズムが 2 つの変数で 0.5 以上の値を返すと、データアラートが表示されます。

例

ある不動産会社が新規物件の住宅価格を予測したいと考えています。これを実現するために、代理店は次の入力変数を使用して回帰モデルを作成します。

  • 住宅の規模 (平方フィート)ft)
  • ベッドルームの数
  • バスルームの数
  • 家屋の年数
  • 収入中央値
  • 改築状況

モデルのトレーニング後にアラートが表示されるのは、「家のサイズ」、「寝室の数」、「バスルームの数」変数の相関関係が高いためです。その結果、モデルでは各変数の重要度を判断できず、係数の信頼性が低下します。この問題を解決するには、次の点を考慮してください。

  • 相関変数のいずれかを除外して、まだトレーニングされていないデータの汎化を改善します。たとえば、データセットから「house size (家のサイズ)」を含めて「number ofbedrooms (ベッドルームの数)」を除外します。
  • 主成分分析 (PCA) や放物線回帰などの変数選択手法を使用して、冗長性を減らします。
  • 更新されたデータセットを使用してモデルを再トレーニングします。

交差検証失敗アラート

交差検証では、データセットを複数の部分に分割し、ある部分でモデルをトレーニングし、別の部分で検証することで、モデルがどの程度目に見えないデータに一般化されるかを評価します。失敗は、トレーニングデータが十分に大きくない場合、使用する例が少なすぎる場合、無効な形式、欠損値、異常値がある場合に発生します。

考慮すべきアクション

K 分割交差検証の 1 つの分割のパフォーマンスが他の分割とは大きく異なっています。トレーニングデータで異常値または異常データを調査し、それに応じて絞り込んでください。

検出方法

モデルビルダーでは、いずれかの分割でパフォーマンスの大きな違いが検出されるとアラートが表示されます。

例

ある小売ブランドは、在庫を最適化して在庫の補充を改善できるように、さまざまな店舗での商品の週次需要を予測したいと考えています。これを実現するために、小売業者は次の入力変数を使用して回帰モデルを作成してトレーニングします。

  • ストア ID
  • 商品 ID
  • price
  • 昇格
  • 在庫数
  • 季節
  • 週次売上

モデルのトレーニング後、交差検証に失敗したためアラートが表示されます。データセットに商品データ、店舗データ、または販売履歴データがない場合や、交差検証用のデータ分割が失敗する可能性があります。この問題を解決するには、次の点を考慮してください。

  • 「商品種別」や「店舗種別」など、属性が豊富な入力変数を使用してモデルを再トレーニングします。「商品 ID」や「ストア ID」は使用しないでください。
  • 将来の情報が漏洩する可能性がある「週末在庫数」などの変数を削除すると、モデルの信頼性が低下します。
  • データセットが小さすぎる (行数、列数、またはその両方が少なすぎる) 場合は、より多くのデータを使用します。

データ漏洩アラート

データ漏洩は、モデルのトレーニングデータに予測しようとしている情報が含まれている場合に発生します。漏洩により、モデルのトレーニングでスコアが楽観的に高くなりますが、ライブデータでの精度が低下します。実際には使用できない学習パターンにモデルを誘導し、予測を損なう可能性があります。

考慮すべきアクション

変数のデータ漏洩を調査します。検出された場合、モデルからこの変数を除外します。

検出方法

モデルビルダーでは、常に同じ結果の説明変数が検出されるとアラートが表示されます。

例

貸し手は、顧客がローンを不履行にするかどうかを予測したいと考えています。これを実現するために、貸し手は次の入力変数を使用してバイナリモデルを作成します。

  • 経過時間
  • 収入
  • クレジットスコア
  • 貸付金額
  • loan status (ローン状況)
  • 支払履歴
  • ローン最終支払日

トレーニング後、データ漏洩が検出されたため、モデルにアラートが表示されます。「ローン状況」変数と「支払履歴」変数の値は、ローンが承認され、一部が返済された後にのみ決定されます。このような情報を含めると、モデルが予測を行うときに現実的に使用できない将来のデータが漏洩します。この問題を解決するには、次の点を考慮してください。

  • トレーニングセットから「ローン状況」、「支払履歴」、「ローン最終支払日」入力変数を除外します。
  • 「経過時間」、「収入」、「クレジットスコア」、「ローン金額」の代わりに、ローン承認時に把握された変数を使用します。
  • 更新されたデータセットを使用してモデルを再トレーニングします。

高頻度値アラート

頻度が高い値は、変数のほとんどの値が同じカテゴリにあることを示します。これは、変数で提供される予測値が少なく、モデルへの貢献度が制限される可能性があることを示します。

考慮すべきアクション

データ値のより均等な分布で変数を更新します。または、モデルから変数を削除することを検討します。

検出方法

データセットの 1 つの値が 90% 以上の確率で出現する (相対頻度 0.9 以上) と、モデルビルダーに変数のアラートが表示されます。

例

E コマース小売業者は、さまざまな地域でブランドを購入する顧客の傾向を予測したいと考えています。これを実現するために、小売業者は次の入力変数を使用して回帰モデルを作成します。

  • 商品 ID
  • 顧客 ID
  • 販売チャネル
  • 購入頻度
  • region

モデルトレーニング後にアラートが表示されるのは、このデータによると、ブランドを購入する可能性の高い顧客の 95% が米国にいて、カナダにはわずか 5% しかいないためです。このモデルは、USA がブランドの顧客にとって最適な地域であることを前提としています。ただし、「地域」変数は変動性が低いため、この変数は予測には意味がありません。この問題を解決するには、次の点を考慮してください。

  • 1 つの値を使用して、支配的でない値を削除します。たとえば、カナダではなく米国の顧客データがあるとします。または、データセットから「region」変数を削除します。
  • USA 以外の地域のデータ値をより適切に表現した更新されたデータセットを使用してモデルを再トレーニングします。

不均衡な分布アラート

不均衡な分布は、トレーニングデータの各クラスの観測の不均衡な比率を示します。

考慮すべきアクション

不均衡なデータセットでモデルをトレーニングすると、予測にバイアスがかかってモデルの信頼性が低下する可能性があります。モデルバージョンを作成すると、Einstein は次の処理を実行します。

  • データのアップサンプリングにより、小数クラスの頻度を増やす。
  • 異常なイベント、定期的でないイベント、または頻繁ではないイベントを反映する正しい値。

検出方法

不均衡な分布が検出されると、モデルビルダーによって自動的にアラートが表示されます。

例

ある E コマース会社は、顧客がサブスクリプションをキャンセルするか離脱するかを予測したいと考えています。これを実現するために、会社は次の入力変数を使用してバイナリ分類モデルを作成します。

  • 顧客 ID
  • 月間コスト
  • 毎月のログイン頻度
  • サブスクリプション種別
  • 在職期間
  • 離脱

モデルのトレーニング後、変数「離脱」のクラス分布が不均衡で、顧客の 95% が有効、5% のみが離脱と表示されているため、アラートが表示されます。この不均衡により、モデルは「有効な」顧客を優先的に予測し、離脱した顧客を正確に識別する能力が低下する可能性があります (偽陰性率高)。この問題を解決するには、次の点を考慮してください。

  • アラートで提供される推奨事項に従って、データセットのバランスを取ります。
  • 更新されたデータセットを使用してモデルを再トレーニングします。

異常値アラート

異常値とは、データセットの大部分と大きく異なるデータポイントのことです。このアラートは、少なくとも 1 つの異常値が検出され、異常に小さいまたは大きい数値が存在することを示します。異常値は、モデルのパフォーマンスを歪めたり、精度を低下させたり、販売予測を誤ったものにしたりする可能性があります。

考慮すべきアクション

異常値には 2 種類があります。

  • データ入力エラー、処理エラー、またはその他の問題により、不正な値。
  • 異常なイベント、定期的でないイベント、または頻繁ではないイベントを反映する正しい値。

調査して、保持する異常値とモデルから除外する異常値を決定します。モデルのトレーニングの前に、誤った値を除外して修正することを検討してください。

検出方法

変数の場合、モデルビルダーは次のようになります。

  • は、その値のグローバル平均とグローバル標準偏差を計算します。
  • は、グローバル平均から 5 標準偏差以上離れた値として異常値を指定します。

例

小売業者がさまざまな商品の販売台数を予測したいと考えているとします。これを実現するために、小売業者は次の入力変数を使用して回帰モデルを作成します。

  • 商品 ID
  • 単価
  • 曜日
  • 店舗ロケーション
  • 在庫状況
  • 競合他社の単価
  • プロモーションイベント

モデルのトレーニング後、商品の高い異常値スコアが検出されたため、アラートが表示されます。ほとんどの商品は 1 日あたり 10 ～ 100 個を販売しますが、レコードでは 1 日あたり 1000 個以上を販売しています。この問題を解決するには、次の点を考慮してください。

  • エラーによって発生した可能性があるデータポイントを削除します。
  • トレーニング中に異常値スコアを含めて、モデルが通常の販売金額を示すパターンを学習できるようにします。次に、データを使用して、標準から大幅に逸脱する取引を特定します。
  • 更新されたデータセットを使用してモデルを再トレーニングします。

R2 品質アラート

R2 (R 二乗)、つまり決定係数は、回帰モデルがどの程度データに適合するかを評価するパフォーマンス評価指標です。

考慮すべきアクション

  • 低い R2 は、モデルのパフォーマンスが低いことを示します。有効化する前にモデルを改善します。
  • 高い R2 は、モデルのパフォーマンスが非常に高いため、データ漏洩が発生している可能性があることを示します。データ漏洩の原因となっている変数を調査して削除します。

検出方法

モデルビルダーでは、これらの値に基づいて高または低の R2 スコアが検出されるとアラートが表示されます。

  • 0.3 未満 (低)
  • 0.95 を上回る (高)

例

ある小売ブランドは、各店舗の月間売上を予測したいと考えています。これを実現するために、小売業者は次の入力変数を使用して回帰モデルを作成します。

  • 店舗サイズ (sq.ft)
  • 従業員数
  • 1 日あたりの平均顧客占有面積
  • 1 か月あたりの広告費
  • 地域の個体群密度

モデルのトレーニング後、R 二乗スコアが 0.45 で低いとみなされるため、アラートが表示されます。このスコアは、モデルが「月次売上」目標変数の変動の 45% のみを説明しており、売上に影響する他の要素は把握していないことを示しています。したがって、予測は信頼できない可能性があります。この問題を解決するには、次の点を考慮してください。

  • 「店舗プロモーション」や「競合他社の近接性」などの追加変数を使用して、モデルのパフォーマンスを向上させます。
  • データ品質をチェックして、欠損値、異常値、矛盾を特定します。
  • より多くの販売履歴データを使用して、データの品質を向上させます。
  • 線形モデルのパフォーマンスが低い場合は、ランダムフォレストや勾配ブースティングなど、より複雑なモデリングアルゴリズムを使用します。
  • 実際の売上と予測売上の差を比較して、パターンや矛盾を明らかにします。
  • 更新されたデータセットを使用してモデルを再トレーニングします。

回帰総計値

回帰の総計値は、連続データの数値を予測するモデルの性能を評価するのに役立ちます。

予測 vs 実際

予測された散布図と実際の散布図は、モデルの予測結果と実際のデータ結果を対比させます。対角線に対する点の近さはモデルの精度を示し、点が近いほど精度が高いことを表します。

残差

残差の散布図は、予測値に対する実際の値と予測値の間の分散 (残差と呼ばれます) を示します。点がランダムに分布しているように見えることが理想です。Y 軸の正の値は予測が低すぎたことを示し、負の値は予測が高すぎたことを示し、ゼロの値は予測が正確に正しかったことを示します。

4 回の交差検証の結果

4 回の交差検証のアプローチは、モデルの検証プロセスのサンプリングバイアスを減らします。この方法では、データをランダムに 4 つの同じサイズのパーティションに分割し、モデルは 4 つのテストパス (分割) を通ります。各パスでは 3 つのパーティションがトレーニングデータ、残りのパーティションがテストデータとして機能します。4 つのテストパスが完了すると、各パーティションは検証セットとして 1 回機能し、トレーニングセットの一部として 3 回機能したことになり、包括的な評価が保証されます。検証結果のテーブルを参照して、データの各分割に対応する総計値を調べます。

指標 説明
レコード数

観測の合計数。値の意味は、列ごとに異なります。

  • [Training Data (トレーニングデータ)] 列と [Validation Data (検証データ)] 列の場合、数値はそれぞれトレーニングと検証のモデルの作成で使用されるデータ全体の観測の合計数を表します。
  • [分割 #1] ～ [分割 #4] 列の場合、この値はその分割に含まれる観測数 (データ全体の約 25%) を表します。
R2

R2 は、モデルでどれくらい結果の変動を説明できるのかを測定します。これはモデルの予測能力を示す指標になります。

範囲:

  • 0 は、モデルで結果のどの変動も説明できないことを意味します (偶然)。
  • 1 は、モデルですべての変動を説明できることを意味します (完全モデル)。
MAE 平均絶対誤差。実際の値と予測値の絶対差を測定します。この平均では、すべての差が均等に荷重されるため、MSE ほど異常値に対する感度は高くありません。
MSE 平均二乗誤差。モデルの予測の平均二乗誤差を測定します。MSE は、観測された (実際の) 結果と予測値の平方差を計算して平均します。
RMSE 二乗平均平方根誤差。MSE の平方根を表します。RMSE は、モデルの予測値と観測された (実際の) 値の差を測定します。この値は、「誤差の標準偏差」と考えることができます。

モデル設定の作成

基盤モデルを追加したら、特定の使用事例に関連付けられたモデル設定を作成できます。

  1. AIモデル(旧称Einstein Studio)で、[新規設定]をクリックします。
  2. モデル Playground で、[Create model] を選択します。
  3. 使用する基盤モデルを選択します。
  4. [高度な設定] で、モデルの学習プロセスを制御するハイパーパラメーターを定義します。
    これらの値は、トレーニングで重要であり、プロンプトの応答に影響します。

    • 温度

      0 ～ 2 の値で応答の創造性を決定します。 値が低いほど、応答の一貫性が高まります。値が大きいほど (0.7 ～ 0.9 など)、ランダムな応答が生成されます。生成するテキストの一貫性やクリエイティブ性に基づいて、値を指定します。

      この設定をテストに使用できるのは Anthropic モデルのみです。

    • 頻度ペナルティ

      応答での同じトークン (単語、語句、コード) を頻繁に使用しないようにします。-2.0 ～ 2.0 の値を指定します。 生成されるテキストの繰り返しを減らすには、より高い値を使用します。

    • プレゼンスペナルティ

      応答でさまざまなトークンの使用を促します。-2.0 ～ 2.0 の値を指定します。 生成されたテキストで使用されていないトークンを含めるには、より高い値を使用します。

  5. プロンプト設定を定義します。
    • [プロンプト] セクションに移動して、[設定] をクリックします。
    • 入力するプロンプトごとに停止シーケンスとデータマスキングを指定します。
  6. モデル構成設定を最初から定義する場合は、[デフォルトに戻す] をクリックします。
  7. モデル Playground を終了し、[生成] タブでモデルを表示するには、[閉じる] をクリックします。

モデル設定の編集

さまざまなプロンプトを試してハイパーパラメーターを調整し、モデルがプロンプトにどの程度適切に応答するかを評価します。ただし、モデルがすでにプロンプトに関連付けられている場合は、代わりに新しいモデルを作成します。モデル設定を更新すると、関連付けられたプロンプトのパフォーマンスに影響する可能性があります。

  1. AI モデル (旧 Einstein Studio) の [生成] タブで、モデルをクリックして設定を編集します。
  2. モデル Playground で、[モデルを編集] をクリックします。
  3. プロンプト、プロンプト設定、ハイパーパラメーターを変更します。次に、[更新] をクリックします。

モデル活動の監視

ダッシュボードでモデル推測の使用状況とエラーを表示します。重要なインジケーターを使用して、モデルのパフォーマンスを追跡、調整、および改善できます。

推測

基礎モデルは、大規模なデータセットで事前にトレーニングされていますが、人間のようなテキストを生成したり、特定の言語関連タスクを実行したりする際には、推論中のプロンプトからも学習します。モデルを調整し、ドメイン固有の要件に合わせてハイパーパラメーターを微調整することも重要です。モデルの効率、リリースインフラストラクチャ、および倫理的な影響も考慮する必要があります。

モデル活動は、特定の期間に使用されたすべての設定済みモデルからのすべての推測のスナップショットを提供します。

エラー

モデルの操作およびリリース中にエラーが発生する可能性があります。これらのエラーは、実世界のアプリケーションにおける LLM のパフォーマンス、信頼性、およびセキュリティに影響を与える可能性があります。一般的な問題としては、不正確な応答やバイアスのかかった応答、待ち時間やスケーラビリティの問題などがあります。

  2. [設定] をクリックします。

    これらのプロンプト設定は、テスト中にのみ使用されます。モデル設定には保存されません。

  5. プロンプト応答を取得するには、［Generate］ をクリックします。

  7. テストプロンプトの品質に満足したら、作業を保存してモデル Playground を終了します。

基盤モデルの追加

AIモデル(旧称Einstein Studio)に基盤モデルを追加すると、外部モデル プロバイダーとSalesforce間のエンドポイント接続が確立されます。モデルを接続したら、新しいモデル設定を作成し、カスタムプロンプトに対するモデルの応答を評価します。

Bring Your Own LLM (BYOLLM) は、基盤モデルプロバイダーとして Google の Amazon Bedrock、Azure OpenAI、OpenAI、Vertex AI をサポートしています。LLM Open Connectorを使用するには、[Connect to your LLM]オプションを使用します。これにより、主要なクラウド プラットフォームでホストされている、または自分でホストしている任意の言語モデルにEinstein AI Platformを接続できます。

基盤モデルを追加するには、Einstein生成AIが組織で有効になっている必要があります。詳細は、Salesforce ヘルプの「Einstein 生成 AI の設定」を参照してください。

モデルエンドポイントに接続するには、その URL と認証情報が必要です。プロバイダーのダッシュボードで次の詳細を確認してください。

LLM Open Connector の場合、URL は /chat/completions で終わる必要があります。URL パスがこの要件を満たしていない場合、Open Connector は URL パスに /chat/completions を自動的に追加します。

  1. AI モデルで、[生成] タブに移動します。
  2. [基盤モデルを追加] をクリックします。
  3. 接続する基盤モデルの種別を選択し、[次へ] をクリックします。
  4. モデルエンドポイントに接続します。
    1. エンドポイント名と URL を入力します。
      メモ リモートモデルエンドポイントに接続するには、標準 HTTPS 443 ポートが必要です。
    2. 認証の詳細を入力します。
      独自の Azure Open AI モデルを使用する場合は、[OAuth] を選択して指定ログイン情報を選択できます。詳細は、Salesforce ヘルプの「指定ログイン情報と外部ログイン情報の作成」を参照してください
    3. モデル情報を入力します。
      Azure Open AI モデルを接続する場合は、Azure リリースを入力します。この情報は、[リリース] の Azure OpenAI ダッシュボードにあります。OpenAI で微調整されたモデルを接続する場合は、設定時に促されたら [Yes] を選択します。
      サポートされるモデルについての詳細は、「大規模言語モデルのサポート」を参照してください。
    4. [保存 & テスト] をクリックします。
    5. 接続するモデルの正確な名前を入力します。
    6. [接続] をクリックします。
    7. モデルの名前を入力し、[名前と接続] をクリックします。
    8. モデルバージョンを選択します。

      プロンプトに対するモデルで生成されたテキスト応答に「朗読」への参照が表示されることがあります。詳細は、『Google Gemini API Reference』を参照してください。

    9. モデル種別を選択します。
      Amazon Bedrock の場合は、Anthropic を使用します。モデルのリストについては、「Large Language Model Support (大言語モデルのサポート)」を参照してください。
  5. 基盤モデルを使用するには、[基盤モデル] タブに移動して設定します。

予測 AI の用語集

AIモデル(旧Einstein Studio)での予測AIによく関連する用語を理解しておきましょう。

アクション可能な変数
アクション可能な変数とは、特定の顧客に使用するマーケティングキャンペーンの決定など、ユーザーが制御または影響を及ぼすことができる説明変数です。この変数を、顧客の住所や個人の年齢など、制御できない説明変数と対比します。変数がアクション可能として指定されている場合、モデルは指示的分析を使用して、予測結果を改善するためにユーザーが実行できるアクションを推奨します 。
実際の結果
実際の結果とは、結果が発生した後の観測の結果変数の実際の値です。モデルのパフォーマンスは、予測結果が実際の結果にどれほど近いかを比較することで計算します。実際の結果は、観測された結果と呼ばれることもあります。
アルゴリズム
アルゴリズムは、予測モデリングでモデルを作成するために使用されます。AIモデルで作成されたモデルは、いくつかのアルゴリズムのいずれかを使用します。GLM(一般化された線形モデル)は回帰ベースのアルゴリズムですが、GBM(勾配ブースティング マシン)とXGBoostはディシジョン ツリー ベースの機械学習アルゴリズムです。
属性
「変数」を参照してください。
認証ヘッダー
認証ヘッダーは、API 要求の実行時にクライアントからサーバーに送信される HTTP 要求の一部です。要求されたリソースにアクセスするためのクライアント ID および権限を検証するためにサーバーが使用する情報を提供します。
バイナリ分類
バイナリ分類の使用事例は、バイナリであるビジネス結果、つまり成立/不成立、合格/失敗、公開/非公開、維持/離脱などの 2 つの値のみを含むカテゴリ (テキスト) 項目に適用されます。これらの結果により、データが 2 つの個別のグループに分類されます。Einstein は分析目的で 2 つの値を Boolean 値の true と false に変換します。ロジスティック回帰は、バイナリ結果を分析するために使用されます。バイナリ分類は、AI モデルで作成されたモデルがサポートする主要な使用事例の 1 つです。回帰と比較してください。
カーディナリティ
カーディナリティとは、カテゴリ内の個別値の数です。カーディナリティの高い (個別値が非常に多い) 変数では、解釈が難しい複雑さをもたらすことがあります。AI モデルで作成されたモデルは、変数ごとに最大 100 個のカテゴリをサポートします。必要に応じて、残りのカテゴリ (観測数が 25 個未満のカテゴリ) を [その他] というカテゴリに統合できます。null 値は、[未定義] というカテゴリに配置されます。
カテゴリ変数
カテゴリ変数は、定性的な値 (カテゴリ) を表す変数の種別です。バイナリ分類の使用事例を表すモデルには、その結果としてカテゴリ変数が含まれます。「カテゴリ」を参照してください。
カテゴリ
カテゴリは、通常は商品カテゴリ、リード状況、ケース件名などのカテゴリ (テキスト) データを含む、定性的な値です。カテゴリは、データのグループ化や絞り込みに便利です。数値変数とは異なり、カテゴリで計算を行うことはできません。
因果関係
因果関係は、状況の原因と結果の関係を説明します。予測モデリングでは、因果関係は、たとえば、変数と結果変数間で変数がどの程度相互に影響している (または影響していない) かを表します。一部の変数は、明白で直接的な影響を相互に及ぼしている可能性があります (価格と割引が販売利益に及ぼす影響など)。また、それほど明白ではない、弱い影響を及ぼしている可能性がある変数もあります (天候が、時間どおりの配送に及ぼす影響など)。多くの変数は相互に影響しません。変数は独立しており、相互に排他的です (サッカーチームの勝敗記録や通貨換算レートなど)。変数間の因果関係を、単に変数間の統計的相関のみに基づいて想定できないことに注意してください。実際には、相関関係では、該当の変数間の関連付けをさらに調査するためのヒントが提供されます。詳細な探索を行ってのみ、これらの項目間に因果関係が実際に存在するかどうかを判断でき、存在する場合は、その影響の重要度を判断できます。
係数
係数とは、結果変数に対する変数 (または変数のペア) の影響を表す数値です。係数は、変数に 1 単位の変化があったときの結果変数の平均の変化を定量化します。モデルの他のすべての変数はそのまま維持されることを前提としています。
相関関係
相関関係とは、2 つ以上の状況間の単なる関連付け、つまり「相互関係」です。予測モデリングでは、相関関係は変数間 (通常は変数と結果変数間) の統計的な関連付けを説明します。相関関係の強度はパーセントとして定量化されます。パーセントが高いほど、相関関係が強くなります。ただし、相関関係は因果関係ではありません。相関関係は、単に変数間の関連付けの強度を説明します。変数が互いに因果的な影響を及ぼしているかどうかを説明するものではありません。
件数
件数は、モデルのトレーニングに関連付けられている観測 (行) の数です。件数は、データ内のすべての観測、または関連付けられた検索条件を満たす観測のサブセットを表すことができます。
日付変数
日付変数は、日付/時間 (一時) データを含む変数の種別です。
連動変数
「結果変数」を参照してください。
ドリフト
時間が経つにつれて、リリース済みモデルのパフォーマンスがドリフトし、結果の予測精度が低下する可能性があります。ドリフトは、データやビジネス環境の要素が変化することにより発生する可能性があります。また、ドリフトは、モデルの基盤となっているデータに組み込まれている、使用されなくなった仮定により発生することもあります。モデルがドリフトした場合は、データ設定を調整したり、モデルを新しいデータで再トレーニングしたりすることで、モデルを更新して修復できます。
エンドポイント URL
特定の API またはサービスにアクセスできる場所を表す URL。API のエンドポイントを操作する要求を実行できる場所です。
倫理的な使用
倫理的な使用とは、AI と機械学習を公正で偏りのない目的に応用することを意味します。AI モデルを使用すると、倫理的で説明可能なモデル、インサイト、予測を作成できます。概要については、Trailhead モジュールの「人工知能の責任ある作成」を受講してください。
機能
「予測変数」を参照してください。
機能の選択
機能の選択では、モデルの最適な機能 (予測変数) のセットを選択します。モデルには、結果変数の変動を最適に説明する変数の数を含めることをお勧めします。変数が少なすぎるモデルはデータの基本パターンを検出するにはあいまいすぎて、学習不足のモデルが生成される可能性があります。変数が多すぎるモデルはデータ内の不要な情報を除外するには過度に具体的かつ複雑であり、過学習のモデルが生成される可能性があります。成功する特徴の選択には、有意な潜伏変数 (モデルにない重要な変数) がなく、最も影響力のある変数が含まれます。
一般化された線形モデル (GLM)
一般線形モデルは、モデルを作成するために使用される等式ベースのモデリングアルゴリズムです。
目標
目標では、モデルの目的の結果を指定します。モデルの目標には、その結果変数と、目的とする結果の方向 (最小化または最大化) が含まれます。たとえば、目標として、利益率の最大化やコストの最小化が考えられます。予測モデリングでは、モデルの目標を使用して分析とトレーニングをガイドします。「結果変数」を参照してください。
勾配ブースティング
勾配ブースティングは、モデルを構築するために使用するディシジョンツリーベースのアンサンブル機械学習アルゴリズムです。勾配ブースティングマシン (GBM) とも呼ばれます。
重要性
重要度は、モデルの予測結果に対する変数の相対的な影響度です。AI モデルで作成されたモデルの場合、重要度は、結果を予測するときにモデルが変数を使用する量を示します。重要度のレベルはパーセントとして定量化されます。パーセントが高いほど、影響が大きくなります。重要度は、変数間のインタラクションを考慮する高度な評価指標です。2 つの変数に高い相関関係があり、類似する情報が含まれている場合、モデルはより適切な変数を選択して使用します。たとえば、エネルギー使用量を予測する場合、温度とエアコンの稼働時間の変数は両方とも高度に相関していますが、重要度スコアが高くなるのはいずれか一方の変数のみです。
独立変数
「予測変数」を参照してください。
推測
推測とは、AIモデルのAIモデルによって生成されるあらゆるタイプのデータ出力です。
k 分割交差検証
データのすべての観測を 4 つの同じサイズの個別のパーティションにランダムに分割するモデル検証プロセス。次に、4 つのテストパス (分割) を実行します。3 つのパーティションはトレーニングセットとして機能し、1 つのパーティションはテストセットとして機能します。総計値は 4 つすべての分割で平均されます。
キーベースの認証
API エンドポイントへのアクセスを承認するために API キーを使用する認証。API キーは、API を保護し、特定のリソースへのアクセスを制御する一般的な方法です。
漏洩
漏洩は、モデルのトレーニングに使用したデータに、予測しようとしている情報を含む変数が 1 つ以上含まれている場合に発生します。これにより、実際にはモデルに問題がある場合でも、非常に正確なモデルになる可能性があります。データ漏洩を修復するには、漏洩の原因となっている変数をモデルからすべて削除します。
線形回帰
線形回帰は、数値の使用事例で使用される分析手法です。
ロジスティック回帰
ロジスティック回帰は、バイナリ分類の使用事例で使用される分析手法です。
潜伏変数
潜伏変数とは、モデルにはないが、結果変数の変動を有意に説明する変数です。
平均値
平均は、すべての項目を項目数で除算した統計的な平均です。
モデル
モデルは、将来の結果を予測するために使用された過去の結果に関する包括的かつ統計的な理解に基づく高度なカスタム表現です。モデルは、1 つ以上の予測変数の値を入力として受け入れて、予測結果を出力として生成します。要求に応じて、上位の要素と改善も生成されます。
モデルビルダー
モデルビルダーは、モデルの作成、接続、編集に使用される AI モデルのツールです。
モデリングアルゴリズム
モデリング アルゴリズムは、AIモデルがモデルの作成に使用するものです。Einstein ではいくつかのアルゴリズムのいずれかが使用されます。一般化された線形モデル (GLM) は線形アルゴリズムです。勾配ブースティングマシン (GBM) と XGBoost はディシジョンツリーベースの機械学習アルゴリズムです。
モデルのパフォーマンス
モデルのパフォーマンスは、予測モデルのパフォーマンスを説明するために使用される評価指標です。これらの評価指標 (適合度統計とも呼ばれる品質インジケーター) は、モデルの予測がデータセットのトレーニングデータにどの程度適合しているかを示します。Model Performance に表示される品質インジケーターの定義については、「モデル品質の評価」を参照してください。
ノイズ
ノイズは、結果変数の変動を有意義に説明できないデータです。「シグナル」を参照してください。
数値変数
数値変数は、収益や価格など、定量的な値 (数値) を表す変数の種別です。総収益や平均価格の計算など、数値変数に対して算術処理ができます。数値には常に測定単位 (通貨、量、重量など) が関連付けられています。数値の使用事例を表すモデルには、数値の結果変数が含まれます。
観測
観測は、データのインスタンスを表します。観測は、テーブルデータの行、または Salesforce のレコードに似ています。たとえば、モデルの目標が商談成立の最大化である場合、各観測は商談を表します。
結果
結果はビジネスの結果です。結果は通常、販売利益や商談の成立などの重要業績評価指標 (KPI) です。
結果変数
予測モデリングでは、結果変数は分析および予測の 1 つの主な焦点として使用される項目です。モデルの目標は、結果変数を最大化または最小化することです。結果変数は、応答、対象変数、または従属変数と呼ばれることもあります。「目標」参照。
異常値
Einstein でデータの異常値が検出された場合、変数に平均値から異常に離れた (その変数の平均からの標準偏差の 5 倍以上の) データポイントが含まれることを意味します。データエントリエラーまたはまれなイベントにより発生する可能性がある異常に大きいまたは小さい数値は、平均および標準偏差に影響し、インサイトまたは予測の精度が低下する可能性があります。異常値は、モデルから選択的に除外できます。
過学習
予測モデリングでは、データのトレーニングデータでモデルが結果を適切に予測し、新しい未経験のデータ (本番データなど) でモデルが結果を適切に予測しない場合、過学習が発生します。使用する変数が多すぎると、データ内の不要な情報が取得される過度に複雑な予測モデルが生成される可能性があります。過学習を軽減するために、AI モデルで作成されたモデルはリッジ回帰と正規化を使用します。「学習不足」も参照してください。
パフォーマンス
予測モデルの場合、パフォーマンスはモデルがどの程度正確に結果を予測するかの定性的測定で表されます。AIモデルで作成されたモデルの場合、モデルのトレーニング評価指標を使用してパフォーマンスを評価します。
予測結果
予測結果は、予測モデルが入力データと学習したパターンに基づいて推定または予測する結果です。対象変数に対するモデルの最適な推測を表します。
予測
AIモデルでは、予測は、予測結果を表す派生値(モデルによって生成される)です。予測は、予測モデルの出力として考えることができます。
予測モデル
「モデル」を参照してください。
予測モデリング
予測モデリングは、AI、機械学習、予測モデリング、統計的手法に基づいて履歴データと現在のデータを分析し、パターンを特定し、将来の結果を確率的に予測する手法です。予測モデリングは、予測分析または予測 AI と呼ばれることもあります。
予測因子または予測変数
モデルで入力として想定される変数。予測要求では、モデルで必要な各予測変数の値を渡します。指定された入力値に基づいて、モデルの等式によって予測が出力として生成されます。予測因子は機能および独立変数とも呼ばれます。
指示
指示は、求められる結果の可能性を高めることができる推奨アクションです。指示は、アクション可能な変数に関連付けられます。アクション可能な変数は、ユーザーが制御できる説明変数です。推奨アクションを実行すると、予測結果が改善される可能性があります。
R2
R2 は、回帰のモデルで結果の変動を説明する能力を測定します。これは、1 つ以上の変数から予測できる結果変数の分散の比率を表します。一般に、R2 が大きいほど、モデルで結果を予測する精度が高くなります。R2 は、数値を予測する回帰の使用事例で一般的に使用される総計値です。
ランク付けされたデータ
ランク付けされたデータは、確度でデータを分散するために使用されます。ランク付けされたデータは、累積分数とも呼ばれ、多くの場合、十分位数または四分位数として表示されます。AI モデルで作成されたモデルのトレーニング総計値では、ランク付けされたデータの割合の X 軸にゲイングラフとリフトグラフが描画されます。たとえば、ランク付けされたデータが 0.1 の場合、最上位の十分位数 (スコアが最も高いレコードの 10%) になります。
回帰
回帰は、数値結果変数に適用されます。数値項目の予測は、モデル品質を測定する総計値の独自のセットを使用する回帰問題です。予測モデリングでは、線形回帰を数値の結果の予測に使用します。数値の使用事例は、AIモデルで作成されたモデルがサポートする主な使用事例の1つです。
要求
エンドポイント要求は、クライアントから特定の URL またはサーバー上のエンドポイントへの要求です。この要求には、HTTP メソッド、ヘッダー、パラメーター、およびリクエストボディ (該当する場合) が含まれます。
残差
残差とは、観測値 (実際の値) と予測値との数学的な差です。次のように計算されます: residual=observed value-predicted value。残差は誤差とも呼ばれ、モデルの品質と精度を評価するために使用されます。正の残差は予測が低すぎることを意味し、負の残差は予測が高すぎることを意味します。
応答
エンドポイント応答は、クライアントの要求に対するサーバーの応答です。要求には、要求の成功または失敗を示す HTTP 状況コード、応答に関するメタデータを提供するヘッダー、および要求されたデータまたは追加情報を記載するリクエストボディ (該当する場合) が含まれます。
Retriever
取得者は、大規模言語モデル (LLM) プロンプトを増強するために、ベクトルデータベースでインデックス付けされたテキストデータから関連する事実を返します。取得者は、プロンプトに正確で最新の関連情報を追加することで、ユーザーの LLM 応答の価値と関連性を向上させます。
リッジ回帰
リッジ回帰は、AIモデルで作成されたモデルが係数が大きくなりすぎないようにすることでモデルの過学習を軽減するために使用される正規化アプローチです。
サンプリング
データの分析に必要な時間の短縮を目的として、分析する観測のサブセットをランダムに選択する手法。サンプルは、データの変動を十分に表すことができる大きさにする必要があります。
スコア
(名詞) 観測に関連付けられた予測。スコアリングする (動詞): 観測セットの結果を予測するプロセス。
秘密鍵
API エンドポイントに関連付けられた秘密の暗号鍵。この鍵によってエンドポイント要求が認証および承認されます。
区分
区分は、区分条件で指定された条件を満たす観測 (行) のサブセットです。「セグメンテーション」を参照してください。
セグメンテーション
セグメンテーションには、特定のグループ (顧客種別や地域など) に予測の焦点を絞るためのデータの絞り込みが含まれます。
機密変数
機密変数には、不平等な扱いに関連付けられる可能性のあるデータが含まれます。いくつかの例として、人種、性別、宗教、出身国、性的指向、障害、年齢に関連付けられた変数があります。それほど明白ではない例として、差別的慣行を反映する可能性があるプロキシ変数 (住所や郵便番号など) があります。
シグナル
シグナルは、統計的に有意で潜在的に意味のあるデータのパターンを示します。たとえば、インサイトで変数と結果変数間の高い相関関係を説明できます。リレーションをさらに調査することで、相関関係が結果の変動を説明するのに役立つか (潜在的シグナル)、否か (潜在的ノイズ) を確認できます。ヒントと呼ばれることもあります。
同期種別
さまざまなシステム、デバイス、またはアプリケーション間のデータを同期するために使用される方法。同期は、2 つ以上のデータセット間の一貫性を維持するプロセスです。
最終状態
最終決定されて、変更が期待されないデータ。最終的なデータの例として注文の発送日があります。最終状態に達したレコードは、実際の結果 (または観測された結果) を表します。モデルの結果変数が最終状態を達成した条件を定義します。
テキスト変数
「カテゴリ変数」、「バイナリ結果」を参照してください。
しきい値
バイナリ分類モデルでは、バイナリ結果を分類する方法がしきい値によりモデルに指示されます。AIモデルで作成されたモデルでは、計算された確度がしきい値を上回る場合、Einsteinは結果を一方向(TrueやPositiveなど)で分類します。計算された確度がしきい値を下回る場合、Einstein は逆の方向 (False や Negative など) で結果を分類します。デフォルトのしきい値は 0.5 ですが、使用事例に合わせてこの値を上下に調整できます。しきい値は、分類しきい値または決定しきい値と呼ばれることもあります。
トークン
大きな言語モデル (LLM) で処理および生成されるテキストの単位。トークンは、未処理のテキストデータと LLM が扱うことのできる数値表現との橋渡しとしての役割を果たします。単位としては、個別の文字、単語、熟語、さらに大きな言語単位などがあります。
上位の予測因子
上位の予測因子は、予測結果に最も大きな影響を与える条件です (規模の降順)。条件は、列に関連付けられたデータ値です。AI モデルで作成されたモデルでは、予測因子は 1 つまたは 2 つの条件で構成されます。「予測変数」を参照してください。
トレーニングセット
予測モデリングでは、トレーニングセットは、予測を行うためのモデルをトレーニングするために使用するデータの部分です。「検証セット」も参照してください。
学習不足
予測モデリングでは、データセットのトレーニングデータでモデルが結果を適切に予測しない場合、学習不足が発生します。学習不足は多くの場合、十分な変数がないために統計アルゴリズムでデータの基本パターンを取得できない過度にシンプルなモデルが原因で発生します。「過学習」も参照してください。
非構造化テキスト
コンテンツと長さが異なる自由形式のテキスト。例として、顧客のコメント、アンケートのフィードバック、ソーシャルメディア投稿、テキストメッセージ、メールがあります。「カテゴリ変数」とは対照的です。
検証セット
予測モデリングでは、検証セットは、トレーニングされたモデルが生成した予測を検証するために使用されるデータの部分です。「トレーニングセット」も参照してください。
変数
変数は、分析するデータの特性を表します。変数は、テーブルの列または Salesforce オブジェクトの項目に似ています。たとえば、商談には、各商談に関連付けられるプロパティを説明する変数 (商談種別、リードソース、会計年度、リードソース、期待収益など) があります。各変数には 1 つのデータ型 (数値、テキスト、または日付) があります。予測モデリングでは、2 つの種別の変数 (結果変数と変数) 間のリレーションが分析されます。データサイエンティストは、変数を属性または機能と呼ぶことがあります。
XGBoost
XGBoost (極端な勾配ブースティング) は、効率化を目的として最適化された GBM の拡張アルゴリズムです。XGBoost ツリーベースのアンサンブル機械学習アルゴリズムで、ディシジョンツリーのグループを順次作成してデータの適合性を高める一方で、過学習を回避します。

モデルの有効化

予測モデル設定を保存すると、モデルを有効化できます。予測を消費するには、まずモデルを有効化する必要があります。

重要 一度に有効化できるモデルのバージョンは 1 つのみです。最新バージョンを有効化すると、モデルの以前のバージョンが自動的に無効化されます。

モデルの管理

予測モデルを作成したら、編集して設定を更新したり、不要になった場合は削除したりできます。

モデルを有効化する前にその設定を更新できるため、モデルの作成にかかる時間と労力を節約できます。

  1. [モデルの詳細] に移動し、編集するモデルバージョンをクリックします。
  2. [編集] をクリックして、設定を確認して更新します。モデルバージョンを編集すると、新しいバージョンのモデルが作成されます。
  3. 作業内容を保存します。

モデルを削除すると、モデルまたはその予測ジョブのバージョンを復元できなくなります。

設定の非表示による大規模言語モデル (LLM) アクセスの管理

プロンプトビルダーのユーザーがプロンプトテンプレートで別のモデルに変更する場合は、LLM 設定を非表示にします。新しい LLM バージョンまたは別のプロバイダーの別の LLM を選択できます。テストが完了するまで、新しい LLM へのアクセスを一時停止できます。必要に応じて、非表示の LLM 設定を後で表示して選択できるようにすることもできます。

  1. モデルライブラリで、非表示にする LLM 設定をクリックします。
    [モデルの表示] 列には、プロンプトビルダーでモデルを表示または非表示にするかどうかが表示されます。
  2. [設定済みモデル] タブをクリックします。
  3. 非表示にする LLM 設定の場合、ドロップダウンメニューから [Hide Model (モデルを非表示)] を選択します。

    [モデル表示] 列には、モデル設定が [非表示] として表示されます。モデル設定名の前にテキスト (使用不可) が表示されます。

  4. 非表示のモデルを表示するには、ドロップダウンメニューから [Hide Model (モデルを非表示)] を選択します。

現在非表示モデルを使用しているプロンプトテンプレートは、以前と同じように実行されます。プロンプトビルダーでは、プロンプトテンプレートはモデルが非表示であることを示します。別のモデルに変更するには、[モデル] リストから使用可能なモデルを選択します。非表示のモデルを使用してプロンプトテンプレートをコピーする場合、コピーを保存する前に別のモデルを選択する必要があります。
