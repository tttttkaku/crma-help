個人または取引先の統合

Data 360 の ID 解決では、レコードを統合するいくつかの異なる方法が提供されます。選択した統合種別によって、統合プロファイルのベースとなるオブジェクトの種別、ルールセットによって作成される出力オブジェクト、レコードの統合速度が決まります。

  • 個人オブジェクトのデータモデリングの要件
    データモデリング時に次の項目をマッピングして、ID 解決プロセス用に個人に関するデータを準備します。
  • 取引先オブジェクトのデータモデリングの要件
    データモデリング時に次の項目をマッピングして、ID 解決プロセス用に取引先に関するデータを準備します。
  • 関係者識別子に基づく個人または取引先の統合
    関係者識別子は、関係者 ID オブジェクトの [ID 番号]、[ID 名]、[関係者 ID 種別] 項目の完全一致を参照します。この種別の一致は、政府 ID、ファーストパーティ Cookie、外部 MDM システム、ベンダー固有の ID などの一意の識別子を照合する場合に役立ちます。
  • 外部リンクを使用した個人または取引先の統合
    外部リンクの一致により、外部データソースで一致として識別されたプロファイルを統合できます。ソースデータには、一致するレコードを識別する ID が含まれている必要があります。
  • リアルタイムでの個人プロファイルの統合
    リアルタイムプロファイル統合では、プロファイル情報がすぐに確認され、ミリ秒でリアルタイムプロファイルの照合が完了します。リアルタイム照合では、有効なエンドユーザーに関する情報を統合プロファイルと照合するため、ミリ秒以内にアプリケーションまたは Web サイトをパーソナライズできます。

関係者識別子に基づく個人または取引先の統合

関係者識別子は、関係者 ID オブジェクトの [ID 番号]、[ID 名]、[関係者 ID 種別] 項目の完全一致を参照します。この種別の一致は、政府 ID、ファーストパーティ Cookie、外部 MDM システム、ベンダー固有の ID などの一意の識別子を照合する場合に役立ちます。

Salesforce CRM と Marketing Cloud Engagement を統合するときは、MC 登録者キーを関係者識別子として使用します。MobilePush を使用する場合、Mobile SDK 共有識別子と照合する追加のカスタム一致ルールを作成します。

関係者識別子に基づく一致ルールでは、[空白の一致] オプションを使用できません。

ID 解決で関係者 ID オブジェクトを使用するには、次の項目をマッピングする必要があります。

Party Identification ID (関係者 ID)
関係者 ID は、顧客データのプライマリキーまたはプライマリ識別子です。任意の一意の ID を使用できます。
Party (関係者)
この ID 項目は、取引先または個人の外部キーです。取引先 ID または個人 ID とこの項目間でリレーションが存在している必要があります。
Party Identification Type (関係者 ID 種別)
この項目は、ソーシャルや取引先識別子などの識別子に関する追加情報を提供します。一致ルールの設定に使用されるため、わかりやすくしてください。
Identification Number (識別番号)
ID 解決の比較に使用する ID。たとえば、運転免許証番号、登録者 ID 番号、外部 MDM ID 番号です。空白の識別番号は照合できません。
Identification Name (識別名)
関係者 ID 種別と同様に、この項目で ID スペースの名前を指定します。たとえば、モバイル ID、D-U-N-S Number、LinkedIn ID です。 この名前は、一致ルールの設定にも使用されます。

リアルタイムでの個人プロファイルの統合

リアルタイムプロファイル統合では、プロファイル情報がすぐに確認され、ミリ秒でリアルタイムプロファイルの照合が完了します。リアルタイム照合では、有効なエンドユーザーに関する情報を統合プロファイルと照合するため、ミリ秒以内にアプリケーションまたは Web サイトをパーソナライズできます。

リアルタイム統合は、次の条件が満たされている場合にのみ使用できます。

  • ID 解決ルールセットは、個人オブジェクトに基づいています。
  • ルールセットの出力統合個人オブジェクトは、リアルタイムデータグラフの基礎として使用されます。

リアルタイムパーソナライズプロセスから顧客 ID 情報を受信すると、1 つの個人プロファイルがリアルタイム速度ですぐに照合されます。

リアルタイム照合を使用している場合、ID 解決によって入力値がルールセットの関連リアルタイムデータグラフの統合プロファイルレコードと比較されます。既存の顧客が識別されると、次の 2 つのアクションがトリガーされます。

  • 統合プロファイルに基づくリアルタイムインサイトが計算されます。結果はリアルタイムデータグラフレコードに保存されます。
  • 統合プロファイルに基づくリアルタイムセグメントが作成されます。セグメントデータは、リアルタイムデータグラフレコードに保存されます。

また、同じルールセットを使用して、リアルタイムパーソナライズプロセスから受信したプロファイルを、他のデータソースから取り込まれたプロファイルや統合プロファイルと共に増分処理します。

ID 解決一致ルール

一致ルールは、ID解決プロセス中にどのプロファイルを統合するかをData 360に指示します。各一致ルールに 1 つ以上の条件が含まれています。一致ルールのすべての条件を満たすと、プロファイルが一致します。

複数の一致ルールを作成して、一致オプションを拡張します。1 つの一致ルールが有効化されている場合、統合プロファイルが作成されます。

一致ルールは特定のオブジェクトでのみ作成できます。使用可能なオブジェクトは、個人と取引先のどちらを照合しているかによって異なります。次のオブジェクトが適切にマッピングされていることを確認し、ID 解決で使用できるようにします。

  • 取引先を照合する場合 — 取引先、連絡先住所、連絡先電話、連絡先メール、関係者 ID
  • 個人を照合する場合 — 個人、連絡先住所、連絡先アプリケーション、連絡先メール、連絡先電話、連絡先ソーシャル、関係者 ID

条件を使用して、各一致ルールの厳格度を決定します。正確性を最優先する場合は、条件を追加することを検討してください。一致ルールの条件が多いほど、一意の統合プロファイルを作成する可能性が高くなります。統合の強化を優先する場合は、条件の数を減らして、プロファイルをより簡単に照合できるようにします。

  • ID 解決一致ルールの用語
    ID 解決ルールセットでの一致ルール、一致条件、一致方法の役割を理解します。一致ルール、一致条件、一致方法を追加、調整、および削除すると、ルールセット全体の統合率が変わる可能性があります。
  • ID 解決一致ルールの設定
    ID 解決で Data 360 の一致するレコードを識別する方法を指定します。
  • ID 解決の照合方法
    一致ルールの照合方法により、照合時に比較対象のソースデータをどのように変換するかが決定されます。項目の照合方法を変更すると、通常、その項目に基づいて統合率が変更されます。
  • 高度な一致条件設定
    各一致ルールの [高度な一致条件設定] で一致ルール修飾子設定にアクセスします。
  • デフォルトおよびカスタムの一致ルール
    ID 解決では、さまざまな照合種別に対応する標準のデフォルトの一致ルールが提供されます。カスタム一致ルールは、デフォルトルールでは対処できない使用事例の解決に使用します。さまざまな種別の条件にわたってバランスの取れた効果的な一致ルールセットを作成することで、個人と取引先の統合率が向上します。

高度な一致条件設定

各一致ルールの [高度な一致条件設定] で一致ルール修飾子設定にアクセスします。

大文字と小文字を区別する一致を使用するか、空白値を照合するルールを設定できます。

大文字と小文字を区別

一致ルールで [大文字と小文字を区別する] が選択されている場合、大文字は小文字と一致しません。たとえば、「Maryanne」と「MaryAnne」は、大文字と小文字を区別する一致では異なる名前として扱われます。

新しいルールセットを作成するときに、[大文字と小文字を区別する 一致を使用して個人 ID と完全修飾鍵をリンク する] オプションをルールセット全体に設定できます。選択すると、ID 解決は、個人 ID と完全修飾鍵の両方が同じレコードに一致します。

空白に対する一致

選択すると、空の項目値が一致とみなされます。この設定は、重複しないように慎重に選択してください。たとえば、ミドルネームなど、頻繁に空になる項目で [空白を照合] を選択すると、不完全なレコードが同じ統合プロファイルにリンクされる可能性があります。

ルールセットがリアルタイムで更新される場合、[空白を照合] は無視されます。

エラー「一部のソースプロファイルが 50,000 件以上の他のプロファイルと一致したため、統合されませんでした。一致するレコード数を減らすには、データをクリーンアップするか、一致ルールを絞り込みます」ルールセットの実行は、頻繁に空になる項目で [空白で照合] を選択することで発生する可能性があります。

  8. [保存] をクリックします。

デフォルトおよびカスタムの一致ルール

ID 解決では、さまざまな照合種別に対応する標準のデフォルトの一致ルールが提供されます。カスタム一致ルールは、デフォルトルールでは対処できない使用事例の解決に使用します。さまざまな種別の条件にわたってバランスの取れた効果的な一致ルールセットを作成することで、個人と取引先の統合率が向上します。

  • 取引先の一致ルール
    ID 解決では、取引先名と他の一般的なデータの組み合わせに基づく 2 つの事前設定済みのデフォルトの一致ルールが提供されます。デフォルトの一致ルールでは、4 つの一般的な一致ルール設定のいずれかをすばやく選択できます。ルールセットでデフォルトルールとカスタムルールを組み合わせて、レコードの照合方法を複数作成できます。取引先の照合から最良の結果を得るには、取引先名と地理的位置で照合する一致ルールを使用することをお勧めします。選択した特定の住所データは、一致の品質と精度に影響します。
  • 個人の一致ルール
    ID 解決には、個人の名と個人の姓を他の共通データと組み合わせた 4 つのデフォルトの一致ルールが事前設定されています。ルールセットでデフォルトルールとカスタムルールを組み合わせて、レコードの照合方法を複数作成できます。
  • 世帯の一致ルール
    Data 360 ID 解決で世帯照合を設定する場合、ルールセットに追加できる一致ルールは 1 つのみです。各統合世帯には 1 人以上の個人が含まれます。姓と住所、または関係者 ID に基づいて個人を世帯に一致させることをお勧めします。

ID 解決の照合方法

一致ルールの照合方法により、照合時に比較対象のソースデータをどのように変換するかが決定されます。項目の照合方法を変更すると、通常、その項目に基づいて統合率が変更されます。

警告 [あいまい] と [完全 (標準化)] の照合方法が選択されている場合は、照合の目的でデータが変換されます。ただし、書式が変更されたデータは統合プロファイルに保存されません。統合プロファイルに保存される値の書式はソースデータに基づき、調整ルールで判断されます。

照合方法は、ID 解決時にデータが一致する精度を表します。精度の高い照合を必要とする場合は、予測される統合率が低くなります。通常、精度の低い照合方法を選択すると統合率が高まりますが、望ましくない照合が発生する可能性があります。

カスタム一致ルールの条件を作成する際には、最大 5 つの照合方法を使用できます。各オブジェクトおよび項目で使用できる照合方法は異なります。あいまい一致方法は、取引先オブジェクトの項目では使用できません。

  • 完全
  • 完全 (標準化)
  • あいまい - 精度高
  • あいまい - 精度中
  • あいまい - 精度低

空白の項目間の照合を許可することで、カスタム一致条件をさらに絞り込むことができます。

ヒント 各自のデータに最適な照合方法を判断するには、条件が異なる数通りのルールセットを設定します。統合率を比較して、各自の統合プロファイルに最適な照合方法を決定します。

ID 解決調整ルール

調整ルールでは、ID 解決プロセス中に、複数の値を含めることができない統合項目 (個人の名前など) に保存する 1 つの値を選択する方法を指定します。調整ルールはオブジェクトレベルで設定され、項目固有の調整ルールで上書きできます。調整プロセスでは、ソースプロファイルデータの削除や変更、接続済みソースシステムの更新、顧客との作業時に使用するソースデータの通知は行われません。

メモ 調整ルールは、メールや電話番号などの連絡先には適用されません。すべての連絡先は統合プロファイルの一部のままであるため、統合プロファイルのセグメントの有効化を作成するときにすべての連絡先を使用できます。有効化でソースの優先順序を使用して、目的のソースの連絡先を有効化対象に確実に提供します。

調整プロセスでは、統合プロファイルに表示される情報のみが決まります。これは、すべてのアプリケーションで項目の「最適」値を決定するものではありません。調整された値は、Customer 360 プロファイルの要約と表示ラベル付けに簡単に使用されます。

統合リンクオブジェクトは、統合プロファイルをすべてのソースデータに関連付けるため、使用する顧客のビューを選択できます。統合プロファイルを使用して、使用事例で使用する最適なソースデータを確認します。

最終更新

このルールでは、最近更新されたレコードから値を選択して統合プロファイルに含める必要があることを指定します。

[最終更新日] レコードは、プライマリデータモデルオブジェクトの [最終更新日] 項目によって決まります。この調整ルールは、[最終更新日] 項目がデータストリームからマッピングされている場合にのみ使用できます。

最も頻繁

このルールでは、最も頻繁に発生する値を選択して統合プロファイルに含める必要があることを指定します。

ID 項目でサポートされる調整ルールを選択してください。 [ソースの優先度] 調整ルールを選択してソースデータレークオブジェクトを優先度で並び替えることにより、ID 項目値の変更頻度を減らします。

ID 解決ルールセット処理エラーのトラブルシューティング

ルールセット処理エラーの意味と解決方法を理解します。

エラー 解決のヒント
同じ ID、データソース ID、データソースオブジェクト ID、キー修飾子が含まれていたため、一部の連絡先レコードがスキップされました。

一致およびマージプロセス中、ID 解決では、すべての連絡先レコードにレコード ID、データソース ID、データソースオブジェクト ID、キー修飾子の一意の組み合わせが必要です。プロセスがこれら 4 つの項目の同じ組み合わせのレコードに遭遇した場合、一致中に最初に見つかった連絡先レコードのみが考慮されます。属性が一致する他の連絡先レコードはスキップされます。照合に使用されるレコードが任意に選択されるため、照合に影響する可能性があります。

このエラーを解決するには、データソースでデータをグルーミングするか、データ変換を使用して品質の低いデータを削除または修復します。
一部の一致ルールまたは調整ルールには、アクセスできない外部データレイクオブジェクトが含まれます。

ルールセットを実行しようとしたときに、外部データレイクオブジェクトにアクセスできませんでした。

認証エラーやその他の問題のために外部データレイクオブジェクトにアクセスできない場合は、修正を試みます。それ以外の場合は、ルールセットの一致ルールと調整ルールを編集して、外部データレイクオブジェクトへの参照を削除します。
一部の連絡先レコードは、プライマリデータモデルオブジェクトにリンクされていません。 連絡先レコードが存在し、プライマリデータモデルオブジェクトに対応するレコードがない。ID 解決では、一致と調整で孤立した連絡先レコードを使用できないため、一致中にレコードが削除されました。孤立した連絡先レコードは、ルールセットから作成された統合プロファイルに含まれません。
レコードサイズが 15 KB を超えているため、一部のレコードがスキップされました。 入力レコードは、主データモデルオブジェクトレコードと、対応するすべての連絡先データモデルオブジェクトレコードの組み合わせとして定義されます。入力レコードの最大許容サイズは 15 KB です。このサイズを超える入力レコードは、一致時に統合の対象として考慮されません。
照合される値の合計の長さが 500 文字を超えていたため、一部のレコードが照合中に変更されました。

一致時に、一致ルールに含まれるすべての項目のすべての値の合計文字数制限は 500 文字を超えることはできません。照合プロセス中に、照合する項目の合計値が 500 文字を超える場合、一部の値または値の一部が切り捨てられます。一致は切り捨てられた値に基づいているため、不一致が生じる可能性があります。

たとえば、一致ルールで [完全一致]、[完全一致名]、[標準化されたメールアドレス] 項目が使用されている場合、レコードの電話番号、名、メールアドレスの組み合わせの長さは 500 文字を超えることはできません。

ロング値は通常、ソースデータの書式設定エラーが原因で発生します。CSV ファイルからデータをインポートした場合、誤った形式で複数のレコードが一緒に実行されると、長いストリームが作成される可能性があります。
一部のソースプロファイルが 50,000 件以上の他のプロファイルと一致したため、統合されませんでした。一致レコード数を減らすには、データをクリーンアップするか、一致ルールを絞り込みます。

ID 解決では、50,000 件を超えるレコードを 1 つの統合プロファイルにまとめることはできません。50,000 件を超えるレコードがあるクラスターは、複数の統合プロファイルレコードに分割されます。大きなプロファイルが作成される理由を判断するには、次の点を考慮してください。

  • 空白項目の一致を許可する一致ルール条件がありますか?その場合は、一致ルール条件を変更して空白値の照合を禁止することを検討してください。または、データソースでデータをグルーミングするか、データ変換を使用して品質の低いデータを除去または修復します。
  • データソースの項目にデフォルト値が入力されていますか?たとえば、電話番号がない場合、ユーザーまたはプロセスは 000-0000 などのプレースホルダー値を入力していますか?
  • 一致ルールが広すぎますか?一致ルールは、条件を追加するか、より厳格な一致方法を使用して絞り込むことができます。
1 つ以上のソースデータレイクオブジェクトがエラー状態です。 ID 解決ルールセットで使用されるデータモデルオブジェクトに対応付けられているデータレイクオブジェクトの状況を確認します。データモデルオブジェクトを修正するか、ルールセットを再設定します。

Data Cloud 用語集

  • ユーザーの設定と Sales Cloud データバンドルのインストール
    Data Cloud ユーザーを設定し、適切な権限セットを追加して、Sales Cloud データバンドルをインストールします。これらの手順はすべて Data Cloud の [設定] 内で実行します。
  • Sales Cloud からのデータの取り込みとマッピング
    Data Cloud では、多くのデータソースに接続できます。Salesforce コネクタの多くには、データストリームの設定、データレイクオブジェクトの作成、データモデルへの自動マッピングをすばやく行うのに役立つスターターデータバンドルがあります。ただし、ID 解決を使用するには、カスタムオブジェクトと一部の必須項目を Customer 360 データモデルにマッピングする必要があります。
  • ID 解決を使用したセールスデータの統合
    ID 解決ルールセットを使用して、複数のデータソースを統合プロファイルにリンクします。ルールセットには、取引先データモデルオブジェクトまたは個人データモデルオブジェクトに基づく一致ルールと調整ルールが含まれます。
  • 計算済みインサイトを使用したセールスデータの分析
    Data Cloud 内のデータの複数ディメンション評価指標を計算します。評価指標はプロファイル、セグメント、母集団レベルで作成できます。たとえば、チャネルレベルでパフォーマンスを評価したり、商品評価指標を使用して購入行動や閲覧行動を把握したりできます。

プロファイルエクスプローラーでの統合プロファイルの表示

統合取引先プロファイルと統合個人プロファイルがプロファイルエクスプローラーに表示されます。これは属性または関連属性で検索できます。

  1. Data 360 で、[プロファイルエクスプローラー] をクリックします。
  2. プロファイルを検索するには、属性を選択して完全に一致する語句を入力します。
    結果を取得するには、完全に一致する語句で検索する必要があります。
