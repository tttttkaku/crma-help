データ統合方法の比較

データは、ライブ クエリ、ローカル データ キャッシュへの高速クエリ、またはファイルフェデレーションを介して統合できます。各オプションは異なる使用事例をサポートします。パフォーマンス、データの新鮮度、クレジット消費に関する考慮事項は異なります。

3 種類のデータ統合の違いを理解しておくと、使用事例に適した方法を選択できます。

ライブクエリ統合

ライブクエリはリアルタイムで実行され、データソースから最新の結果を返します。

  • 使用事例: ライブクエリデータ統合は、対話型の分析とリアルタイムダッシュボードに最適です。頻繁ではないクエリに最適化されています。ライブクエリデータ統合では、リアルタイムのパーソナライズと動的ワークフローがサポートされます。
  • データソースの場所: 外部データレイクハウス
  • データ新鮮度: クエリはリアルタイムで実行されます。全体的なデータの更新頻度は、ソースデータの更新頻度によって異なります。ライブクエリデータ統合では、1 秒未満の決定がサポートされます。
  • パフォーマンスドライバ: 外部ソースシステムのパフォーマンスに大きく依存します。述語と集計をソースにプッシュできる場合に最適化されます。
  • クレジット消費に関する考慮事項:
    • クレジットは、アクセスされた行数に基づいてクエリごとに消費されます。クレジットは主に [データ統合] および [データ共有アクセス] 利用状況種別で消費されます。
    • ライブクエリは、頻度の低いクエリではコスト効率が高くなります。ただし、変更頻度の低いデータに対するクエリを頻繁に実行すると、同じデータを照会するために繰り返しクレジットが消費される可能性があるため、このオプションは高速化クエリよりもコストがかかります。

Accelerated Query Federation (高速化されたクエリ統合)

クエリ統合でアクセラレーションが有効になっている場合、Data 360 は設定された間隔で更新されるローカルデータキャッシュを保持します。高速クエリでは、データソースを直接照会するのではなく、ローカルデータキャッシュにアクセスします。

  • 使用事例:クエリが頻繁に実行され、データが頻繁に変更されない場合、データ統合の高速化が最適です。高速化を有効にすると、スケジュールされた間隔で更新されるローカルキャッシュを保持できるため、頻繁なアクセスパターンのパフォーマンスが向上します。高速化されたデータ統合は、ダッシュボードとセグメンテーションに適しています。キャッシュの更新頻度よりもデータの変更頻度の方が高い場合、高速化は秒未満の決定には適していません。
  • データソースの場所: 外部データレイク
  • Data Freshness:Freshness は、選択したキャッシュ間隔によって異なります。キャッシュ間隔は 15 分から 7 日まで設定できます。
  • パフォーマンスドライバ: 繰り返されるライブクエリと比較して遅延を削減します。
  • クレジット消費に関する考慮事項:
    • クレジットは、キャッシュに追加または更新されたデータの行ごとに消費されます。キャッシュが更新されると、クレジットは一括処理データパイプライン利用状況種別で消費されます。
    • キャッシュが照会されるときにデータクエリを使用してクレジットも消費されます。
    • クエリキャッシュの高速化は、組織の Data 360 ストレージの使用に寄与する可能性があります。
    • 高速クエリのクレジット消費は、一括処理データ取り込みによる同じバッチデータのクレジット消費に似ています。

ファイルフェデレーション

ファイルフェデレーションでは、Data 360 はデータソースのメタデータを使用して仮想テーブルを作成します。仮想テーブルは、データソースのファイルへのアクセスと参照に使用されます。

  • 使用事例:ファイルフェデレーションは、大規模なバッチ処理や、AIおよび機械学習モデルのトレーニングに最適です。ファイルフェデレーションは、履歴分析やペタバイト規模のレポート作成に最適です。リアルタイムダッシュボードには適していません。
  • データソースの場所: クラウドオブジェクトストアまたはクラウドデータレイク
  • データ新鮮度: 新鮮度はソースファイルの更新頻度によって異なります。
  • パフォーマンスドライバ: パフォーマンスは、オブジェクトの形式、パーティショニング、および外部システムのスループットに大きく依存します。パーティション分割された列形式 (Parquet) を使用します。
  • クレジット消費に関する考慮事項:
    • Data 360 テナントと同じリージョンにある AWS 設定を使用している場合、アクセスされた行に対してクレジットは消費されません。たとえば、顧客のデータが US-East-1 の S3 にあり、Data 360 テナントも US-East-1 にある場合、Data 360 によって顧客のデータソースからアクセスされる行に対してクレジットは消費されません。
    • Data 360 テナントとは異なるリージョンで AWS を設定している場合、または Azure などの異なるクラウドを使用している場合、アクセスする行数に応じてクレジットを消費します。

ストリーミング変換対象オブジェクトの再構築

ストリーミング変換対象オブジェクトを再構築して、データの一貫性を確保します。

ストリーミング変換では、ソースオブジェクトからデータを取得して変換し、出力を新しいオブジェクトに書き込みます。処理中にシステムエラーが発生した場合、出力オブジェクトのデータが不完全である可能性があります。変換対象オブジェクトを再構築すると、すべての変換元データが再処理され、変換先に対して新しい結果が生成されます。

再構築が役立つもう 1 つの状況は、ストリーミング変換が編集されている場合です。変換の編集は、新規レコードに適用されます。出力の既存のレコードは影響を受けません。すべてのレコードに変更を適用する場合は、変換対象オブジェクトを再構築する必要があります。

  1. データ変換レコードページで、ドロップダウンメニューから [再構築] を選択します。データ変換で書き込む対象オブジェクトを再構築します。
  2. 再構築を実行します。
    • 対象オブジェクトへの変換書き込みしかない場合は、再構築を確認し、[実行] をクリックします。
    • 同じ対象オブジェクトに複数の変換書き込みがある場合、[続行] をクリックして、対象オブジェクトを再構築する変換順序を選択するように求められます。1 つの変換を実行すると、前の変換ですでに書き込まれたデータが上書きされる可能性があるため、変換の順序は重要です。順序を選択したら、[実行] をクリックします。
  3. [更新履歴] ページを表示して、データの再構築の進行状況を追跡します。データ量によっては時間がかかる場合があります。再構築プロセス中に、[最終実行状況] が [再構築待機中] に変更され、[再構築] に変更されます。
    再構築では、対象オブジェクトの既存のレコードが削除され、ソースオブジェクトのレコードが再処理されます。対象オブジェクトは、再構築プロセス全体で変更されません。この間、対象オブジェクトに書き込む変換は作成または削除できません。

Google BigQuery とのデータの共有

データ共有を作成することで、Google BigQueryのデータセットとしてData 360オブジェクトにアクセスできます。ゼロコピーインテグレーションでは、データを Google BigQuery にコピーすることなく、直接共有および照会できます。Google BigQuery でデータにアクセスできる場合、Data 360 のハーモナイズされた統合データを操作できます。データの共有には、次の概要手順が含まれます。

作業を開始する前に

  • 「Supported Regions for Google BigQuery Integration (Google BigQuery インテグレーションでサポートされる地域)」を参照してください。
  • VPC サービスコントロールを使用していて、Analytics Hub API が制限されている場合は、VPC サービスコントロール境界で出力ルールを作成し、Salesforce Analytics Hub Producer プロジェクトを含めます。詳細は、「Analytics Hub VPC Service Controls rules」を参照してください。
  1. アクセスする Data 360 オブジェクトを特定します。
  2. Data 360 でデータ共有を作成します。
    「データ共有の作成」を参照してください。
  3. Data 360 でデータ共有対象を作成して、Google BigQuery との接続を確立します。
    「Create a Data Share Target to Connect with Google BigQuery」を参照してください。
  4. データ共有をデータ共有ターゲットにリンクして、BigQueryでData 360オブジェクトにアクセスできるようにします。
    「データ共有とデータ共有対象のリンクまたはリンク解除」を参照してください。
  5. Google BigQuery で、Analytics ハブを使用して Data 360 データ共有を登録します。
  • Google BigQuery に接続するためのデータ共有対象の作成
    Google BigQueryアカウントとの接続を確立するには、Data 360でデータ共有対象を作成します。
  • Google アナリティクスハブでのデータ共有の登録
    Google Cloud ユーザーは Analytics ハブを使用してデータを登録できます。
  • Google BigQuery インテグレーションでサポートされる地域
    Data Cloud では、Google BigQuery とのクロスクラウドデータ共有がサポートされています。クロスクラウドデータ共有では、Google BigQuery はデータ共有を使用できる任意の場所に配置できます。

Amazon SageMaker とのデータの共有

Amazon SageMaker には、Amazon Redshift、Athena、または Elastic MapReduce (EMR) を使用してクエリを実行するための AWS Glue データカタログビュー、AWS Lake Formation、AWS エンジンが含まれています。データ共有を使用して、データレイクオブジェクト、データモデルオブジェクト、計算済みインサイトオブジェクトなどの Data 360 オブジェクトを Amazon Redshift アカウントと共有します。

  • 必要な手順とリンクの一部は、Salesforce コンテンツ外部にあります。Salesforce ではこれらのリンクは維持されません。
  • 「Harness Zero Copy Data Sharing from Salesforce Data Cloud to Amazon Redshift for Unified Analytics – Part 1 (統合分析で Salesforce Data Cloud から Amazon Redshift へのゼロコピーデータ共有を利用 – パート 1)」の前提条件を確認してください。

Amazon SageMaker とデータを共有すると、Athena および Redshift SQL 方言を使用して Amazon Redshift、Athena、EMR から Salesforce Data 360 オブジェクトにアクセスできます。データ共有を Amazon SageMaker データ共有対象にリンクして、Data 360 オブジェクトを Amazon Redshift アカウントで使用できるようにします。その後、Amazon Redshift からライブ、ハーモナイズ、統合データを照会できます。

  1. アクセスする Data 360 オブジェクトを特定し、Data 360 でデータ共有を作成します。「データ共有の作成」を参照してください。
  2. Data 360 でデータ共有対象を作成し、Amazon Redshift アカウントとの接続を確立します。「Amazon SageMaker に接続するためのデータ共有対象の作成」を参照してください。
  3. データ共有をデータ共有対象にリンクして、Amazon Redshift で Data 360 オブジェクトにアクセスできるようにします。「データ共有とデータ共有対象のリンクまたはリンク解除」を参照してください。
    データ共有とデータ共有対象をリンクすると、AWS で使用できるようになります。
  4. 顧客の AWS アカウントで、Lake Formation コンソールでデータ共有を受け入れ、対象リージョンへのリソースリンクを作成し、Salesforce Data 360 オブジェクトをデータカタログビューとしてマウントして、Amazon Redshift でライブデータと統合データを照会する権限を付与します。「Harness Zero Copy Data Sharing from Salesforce Data Cloud to Amazon Redshift for Unified Analytics – Part 1 (統合分析で Salesforce Data Cloud から Amazon Redshift へのゼロコピーデータ共有を利用 – パート 1)」を参照してください。

Data 360 では、Amazon Redshift Serverless クラスターとプロビジョニング済み RA3 クラスターの両方で同じリージョンでのデータ共有がサポートされています。リージョン間で共有オブジェクトにアクセスするには、Data 360 と同じリージョンで Amazon Redshift Serverless をプロビジョニングします。 プロビジョニングされた RA3 クラスターでは、リージョン間の共有オブジェクトへのアクセスはサポートされていません。「Harness Zero Copy Data Sharing from Salesforce Data Cloud to Amazon Redshift for Unified Analytics – Part 1 (統合分析で Salesforce Data Cloud から Amazon Redshift へのゼロコピーデータ共有を利用 – パート 2)」を参照してください。

  • Amazon SageMaker に接続するためのデータ共有対象の作成
    Amazon Redshift アカウントとの接続を確立するには、Data 360 で Amazon SageMaker データ共有対象を作成します。
  • Amazon Redshift インテグレーションでサポートされるリージョン
    Data Cloud では、同じ地域および地域間のデータ共有がサポートされています。

Snowflake とのデータの共有

Data 360 データにアクセスするには、Data 360 オブジェクトを含むデータ共有を作成します。Data 360 オブジェクトには Snowflake アカウントのビューとしてアクセスできます。Snowflake でデータが使用可能な場合、ハーモナイズされた統合データを照会できます。

作業を開始する前に

  • Snowflake システム管理者が Data 360 IP アドレスを許可リストに追加していることを確認します。
  • Snowflake インテグレーションでサポートされる Data 360 リージョンを確認します。
  1. アクセスする Data 360 オブジェクトを特定し、Data 360 でデータ共有を作成します。
    詳細は、「データ共有の作成」を参照してください。
  2. Snowflake でユーザーを作成し、ユーザーのログイン情報を取得します。
    詳細は、「Get User Credentials from Snowflake (Snowflake からのユーザーログイン情報の取得)」を参照してください。
  3. Snowflake アカウントとの接続を確立するには、Data 360 でデータ共有対象を作成します。
    詳細は、「Create Data Share Target and Connect with Snowflake」を参照してください。
  4. Snowflake で Data 360 オブジェクトにアクセスできるようにするには、データ共有をデータ共有ターゲットにリンクします。
    詳細は、「データ共有とデータ共有対象のリンクまたはリンク解除」を参照してください。
  5. Snowflake でデータ共有を表示します。
    1. Snowflake アカウントでデータ共有の非公開共有を選択します。
    2. データ共有のデータベースを作成します。
      データベースの Data 360 オブジェクトを表示するには、ACCOUNTADMIN としてログインします。データを照会し、Data 360 テーブルと Snowflake テーブルにまたがる結合を作成できます。Classic コンソールを使用している場合、データ共有は [インバウンド] タブで使用できます。
  • Snowflake からのユーザーログイン情報の取得
    Snowflake でユーザー情報と認証の詳細を収集し、データ共有対象を作成します。
  • Snowflake に接続するためのデータ共有対象の作成
    Data 360 でデータ共有対象を作成し、Snowflake アカウントとの接続を確立します。
  • Snowflake インテグレーションでサポートされる Data 360 リージョン
    Data 360 では、次の地域で Snowflake との統合がサポートされています。
  • Snowflake インテグレーションでサポートされる Data 360 Government Cloud リージョン
    Government Cloud の Data 360 は、次の Snowflake リージョンとの統合をサポートしています。

Data 360 のデータストリーム同期の有効化

Simple Start で Salesforce CRM メタデータを Data 360 に追加したら、データストリームを有効化してデータを取り込むことができます。Simple Start は、無効な状態のストリームを取り込み、クレジット消費をすぐに回避します。

必要なエディション

開始する前に、次のことを確認してください。

  • 組織が 2026 年 6 月以降に Data 360 がプロビジョニングされている。
  • ホーム組織の接続で [シンプルスタート] が有効になっている。
使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限セット
Simple Start のデータストリームを有効化する

権限セット

  • Data Cloud アーキテクト
  1. [設定] から、[クイック検索] ボックスに「Data Cloud 設定」と入力し、[Data Cloud 設定] を選択します。
  2. [データストリーム] をクリックします。
  3. 有効化するデータストリームを見つけます。
  4. 1 つ以上の無効なデータストリームの横にあるチェックボックスをオンにします。
  5. [有効化] をクリックします。

Data 360 では、データストリームの状況が [有効] に変更されます。Data 360 はソースオブジェクトからデータの取り込みを開始します。このデータは標準データレイクオブジェクトに入力され、定義済みの対応付けを使用して対応するデータモデルオブジェクトに入力されます。このデータは、セグメント、分析、その他のプロセスで使用できます。

モデルの接続

Salesforce の外部で作成された予測および生成 AI モデルを接続し、Salesforce のデータを使用して将来の結果を予測します。データソースを選択して予測条件を定義し、AI と機械学習を使用して予測推測とインサイトを明らかにするモデルをトレーニングします。

  • Bring Your Own Large Language Model (独自の大規模言語モデル)
    BYOLLM(Bring Your Own Large Language Model)機能を使用すると、外部プラットフォームでホストされる基盤モデルを追加して、AIモデル(旧称Einstein Studio)に接続できます。基盤モデルを使用して、生成 AI を強化するモデル設定を作成できます。モデルを本番にリリースする前に、モデル Playground でさまざまな設定を使用してプロンプトに対するモデルの応答を評価します。
  • モデル Playground でのモデルの設定とテスト
    モデル Playground でモデル設定を作成、編集、評価します。設定や専門的な専門知識は必要ありません。Playgroundモデルでは、データのプライバシーとセキュリティを確保するTrustレイヤーを使用します。

Databricks AI モデルの使用

Databricks とデータを使用して、Salesforce でカスタム機械学習モデルを構築、トレーニングして、リリースできます。Databricksでモデルを登録したら、予測条件を定義し、モデルをData 360に接続して、使用事例の予測とインサイトを取得します。このインサイトを使用して、顧客プロファイルの強化、セグメントの作成、さまざまなチャネルのエクスペリエンスのパーソナライズを行うことができます。

Salesforce のデータで Databricks モデルを使用すると、次のような利点があります。

  • Customer 360 全体で、厳選され、ハーモナイズされたほぼリアルタイムのデータにアクセスできます。 この機能により、よりインテリジェントな予測を提供するエキスパートモデルが創出されます。
  • Databricksでモデルを作成し、Data 360に簡単に接続して、ビジネス プロセスの最適化と予測インサイトを取得し、価値を高めます。使用事例には、購入の傾向、リードの取引開始、離脱の傾向などがあります。
  • Salesforceでモデルと推測を簡単に運用できます。Data 360は、ビジネスプロセスからの結果の消費をシンプルにし、価値を高めます。
  • データへのゼロコピーの方法により、Databricks の複雑で、コストのかかる、ミスが発生しやすい抽出、変換、読み込み (ETL) ジョブが排除されます。この方法では、コストが削減され、効率が向上します。
  • Vertex AI モデルを統合し、Salesforce で予測を取得します。ワークフロー自動化スイートであるフローを使用して、データに対するリアルタイムの更新に基づいて進化できる AI 主導の意思決定を可能にします。

モデルの作成、接続、有効化

コーディングせずに数クリックの操作で独自の予測モデルを作成できます。Salesforce 外のモデルから生成 AI と予測 AI を活用できるように接続を確立します。次に、データで明らかにされた推測とインサイトを使用するようにモデルを有効化します。

  • モデルランタイム設定へのアクセス
    新しいデフォルトランタイムは、Data 360 の [AI モデル] タブですべての新しい予測モデルを作成するための基盤です。 この機能強化により、従来のランタイムが、拡張予測モデリング機能の長期的なプラットフォームに置き換えられます。
  • ゼロからの予測 AI モデルの作成
    モデルを作成してデータを分析し、機械学習に基づいて AI を活用した予測を取得します。サポートされる使用事例と倫理的なモデル構築について説明します。そして、手順に従ってモデルを作成し、モデル品質を評価します。
  • 構造化クラスタリング
    Data 360 のクラスタリングを使用して、隠れたパターンを明らかにし、選択した項目の類似点に基づいて構造化データの自然なグルーピングを検出します。クラスター化では、新しい顧客プロファイル、定期的なサポートパターン、予期しない行動トレンドを特定します。
  • 売上予測
    Data 360 の売上予測を使用して、履歴データから将来の値を予測します。売上予測モデルでは、データサイエンスの専門知識がなくても、トレンドと季節のパターンを自動的に特定して予測を生成します。
  • センチメント分析
    Data 360 のセンチメント分析を使用して、構造化されていないテキストを評価し、顧客がブランド、商品、サービスについてどのように感じているかを確認します。モデルでは、顧客レビューやアンケートへの回答などのレコードごとに、肯定的、否定的、または中立的な表示ラベルと信頼スコアが割り当てられます。利用者を絞り込み、ダッシュボードを作成し、自動化をトリガーするには、モデル出力を適用します。
  • トピック分類
    Data 360 のトピック分類を使用して、レビュー、ケースコメント、アンケートへの回答などの非構造化テキストを意味のあるカテゴリに整理します。分類するレコードを評価するために、モデルではトレーニング済み言語モデルが選択した項目に適用されます。モデルでは、レコードごとにトピックの表示ラベルと信頼度スコアが割り当てられます。Data 360 では、次の出力がデータセットに追加されます。レポートとクエリでトピック分類を適用します。
  • 予測モデル監視
    AIモデル(旧称Einstein Studio)のモデル監視を使用して、リリースされた予測モデルの精度、安定性、信頼性を維持します。この継続的なプロセスにより、モデルのパフォーマンスに関する詳細なインサイトが得られ、データ品質や接続の問題を特定できます。Data 360 で一貫した監視を行わないと、モデルのパフォーマンスが低下し、不正確な予測、予期しない結果、結果の信頼性の低下を招く可能性があります。
  • モデルの接続
    Salesforce の外部で作成された予測および生成 AI モデルを接続し、Salesforce のデータを使用して将来の結果を予測します。データソースを選択して予測条件を定義し、AI と機械学習を使用して予測推測とインサイトを明らかにするモデルをトレーニングします。
  • モデルの有効化
    予測モデル設定を保存すると、モデルを有効化できます。予測を消費するには、まずモデルを有効化する必要があります。
  • コンパニオン組織の予測モデル
    Data Cloud One コンパニオン組織から、ホーム組織でトレーニングおよび有効化された予測モデルにアクセスします。Data Cloud One ではマルチ組織アクセスがサポートされるため、さまざまなチーム、国、またはブランドにビジネスが分散している場合に最適です。また、ホーム組織のモデルガバナンスにより、モデル管理が簡素化され、エコシステム全体で予測 AI を拡張できます。
  • AI モデルのモデル系統
    モデルの系統により、トレーニングデータ、バージョン管理、リリース、ライブデータでの使用に至るまで、AI モデルのライフサイクルの追跡可能な履歴が提供されます。Data 360は、この機能をAIモデル(旧Einstein Studio)とガバナンスに統合しています。
  • 設定の非表示による大規模言語モデル (LLM) アクセスの管理
    プロンプトビルダーのユーザーがプロンプトテンプレートで別のモデルに変更する場合は、LLM 設定を非表示にします。新しい LLM バージョンまたは別のプロバイダーの別の LLM を選択できます。テストが完了するまで、新しい LLM へのアクセスを一時停止できます。必要に応じて、非表示の LLM 設定を後で表示して選択できるようにすることもできます。

Zero Copy Data Federation (ゼロコピーデータ統合)

Data 360のゼロ コピー データ統合は、物理的に異なる複数のデータソースからデータを照会するプロセスです。このアプローチにより、ユーザーは、異なるシステムを統合と呼ばれる 1 つの論理システムとして扱い、各システムの自律性を維持できます。重要なのは、データ統合により、システム境界を越えてデータが重複することを回避できることです。Data 360。

データ統合に関連する各システムは、ストレージコンポーネントとコンピューティングコンポーネントの2つの主要コンポーネントで構成されます。ストレージ コンポーネントはデータの保存を担当し、コンピューティング コンポーネントはストレージ コンポーネントに保存されているデータのクエリを担当します。一部のシステムでは、基礎となるデータはオープンテーブル形式を使用して編成されます。

Data 360 では、次の 2 つの方法でデータ統合がサポートされます。

  • クエリ統合 (コンピューティング): 外部システムのデータを必要とするワークフローを起動すると、Data 360 は SQL クエリを外部システムのコンピューティングエンジンに送信します。外部システムはクエリを実行し、Data 360 のワークフローに関連レコードを返します。 ワークフローの完了後、レコードは保持されません。
  • ファイルフェデレーション(ストレージ): サポートされているオープンテーブル形式でデータが構成されている場合、Data 360は外部ストレージシステムを直接照会します。Data 360 は独自のクエリエンジン (および計算) を使用して、ワークフローに必要なレコードを取得します。クエリ統合と同様に、ワークフローの完了後はレコードは保持されません。

データが取り込まれているか統合されているかに関係なく、Data 360 はデータレークオブジェクト (DLO) を作成します。ただし、ゼロコピーコネクタを使用する場合、DLO には実際のデータが含まれず、外部物理テーブルへのポインターとして機能します。そのため、ゼロコピーコネクタを介して作成された DLO は、外部 DLO または仮想 DLO と呼ばれます。

  • データフェデレーションでのキャッシュまたはアクセラレーション
    キャッシュでは、外部ソースからデータを取得し、Data 360 のデータレークオブジェクトに一時的に保存します。データストリームの作成時にアクセラレーションを有効にすると、キャッシュが有効になります。大きなデータセットにアクセスする場合や、データが頻繁に変更される場合は、キャッシュすることをお勧めします。キャッシュされたデータは、任意の頻度で更新できます。
  • データ統合方法の比較
    データは、ライブ クエリ、ローカル データ キャッシュへの高速クエリ、またはファイルフェデレーションを介して統合できます。各オプションは異なる使用事例をサポートします。パフォーマンス、データの新鮮度、クレジット消費に関する考慮事項は異なります。
  • データ統合の請求に関する考慮事項
    データフェデレーションを使用すると、Data Cloud ライセンスで Data 360 を運用している組織の請求に使用するクレジットの消費に影響します。

コンパニオン接続がどのように機能しているかを示す像を理解します。

接続状況

Data 360 ホーム組織とコンパニオン組織の接続状況を示します。

  • 接続中 — 初期接続が進行中です。後でもう一度確認して、更新された状況を確認します。
  • Incomplete — 接続が設定されましたが、データスペースが共有されていません。データスペースが共有されるまで、接続は有効化されません。
  • Active — 接続が完了して機能しています。
  • 無効 — ホーム組織の Data 360 ライセンスが期限切れになったか、コンパニオン組織が有効でなくなったため、接続が機能しなくなりました。たとえば、コンパニオン組織が期限切れのトライアル組織の場合、接続は無効になります。この状況を解決するには、ホーム組織の Data 360 ライセンスを更新するか、コンパニオン組織を再有効化するか、コンパニオン組織を切断します。

初期化状況

初期化状況は、コンパニオン組織と共有されているデータスペースに固有です。この状況は、Data 360 ホーム組織がコンパニオン組織にデータスペースを正常に作成し、初期同期を完了したかどうかを示します。

  • 有効化 — Data 360 とコンパニオン組織間の初期同期が進行中です。初回同期には時間がかかる場合があります。
  • Active — 初回同期が正常に完了しました。
  • エラー — 最初の同期中にエラーが発生しました。そのため、同期が完了していません。サポート用のサポートチケットを作成します。
  • 共有の削除 — データスペースがコンパニオン組織から削除されています。データスペースの共有を解除すると、そのデータスペースのデータはコンパニオン組織からも削除されます。データスペースの削除には最大 30 分かかります。

メタデータ同期状況

Data 360 ホーム組織とコンパニオン組織間の定期的なメタデータ同期の状況を示します。

  • エラー — 前回の同期が失敗し、メタデータの同期が一時停止しています。同期を再開するには、エラーログをダウンロードしてエラーを解決します。メタデータの競合がある場合は、競合を解決してもう一度お試しください。
  • 進行中 — ページが読み込まれたときに同期が進行中でした。
  • Succeeded — 最後の同期セットが正常に完了しました。
  • 待機中 — 次の同期ラウンドで同期される変更の数。この状況は、メタデータの変更後に表示され、同期が完了するまで保持されます。同期のタイミングは異なります。

Data Cloud One コンパニオン接続

Data 360 コンパニオン接続では、1 つの Data 360 と 1 つ以上の Salesforce 組織間の双方向接続を作成できます。コンパニオン接続は標準接続の機能に基づいて構築され、統合データをコンパニオン Salesforce 組織に同期します。コンパニオン接続を使用すると、Salesforce 組織は、会社のすべてのデータのデータを使用して構築された顧客の全体像を把握できます。

Data 360 コンパニオン接続を作成すると、標準の Salesforce CRM 組織接続も作成されます。接続先の組織への標準 CRM 接続がすでにある場合は、標準接続の名前がコンパニオン接続の名前と一致するように更新されます。

  • Data Cloud ホーム組織から Data Cloud One コンパニオン組織への変換
    ホーム組織をコンパニオン組織に変換するには、まず組織からすべての Data Cloud データを削除してから、コンパニオン組織として別の Data Cloud インスタンスに接続します。Data Cloud が有効になっている組織を変換することはできません。
  • Data Cloud One コンパニオン接続の設定
    Data 360 と別の Salesforce 組織間の双方向接続を確立します。すでにコンパニオン接続を介して別の Data 360 に接続されている Salesforce 組織へのコンパニオン接続を作成することはできません。Sandbox 組織を本番組織に接続することはできません。
  • Data 360 コンパニオン接続の監視
    Data 360 の接続状況を確認し、各コンパニオン組織と共有されているデータスペースを確認します。
  • コンパニオン接続の削除
    コンパニオン組織のエラーを回避するには、コンパニオン接続を削除する前にマルチ組織のデータの連動関係に対処します。連動関係のあるコンパニオン組織を切断しようとすると、Data 360 に既存の連動関係が表示されます。
  • Sandbox 組織の Data 360 One に関する考慮事項
    Data 360 One クラスタを設定する前に次の考慮事項を確認して、よくある間違いを回避します。Data 360 One 接続を確立する前に本番組織から Sandbox 組織を作成するか、Data 360 One クラスタを再作成する前に Data 360 メタデータをクリーンアップします。Data 360 One を使用して Sandbox 組織を本番組織に接続することはできません。
  • コンパニオン組織からの Data Cloud One へのアクセス
    コンパニオン組織では、Data 360 アプリケーションの代わりに Data Cloud One アプリケーションを使用できます。これを使用して、プロファイルエクスプローラーなどの Data 360 機能にアクセスします。

タスク 3: データのマッピング

データの取り込み時に、データはそのまま取り込まれます。つまり、項目とそのデータ型は変換されずにインポートされます。前のタスクでは、Data 360 にデータを取り込むための Salesforce CRM データストリームを作成しました。すべてのデータストリームによって取り込まれたデータは、データレークオブジェクト (DLO) に書き込まれます。データバンドルでは標準項目を対応付けますが、電話番号項目など、ID 解決に必要な項目を手動で作成して対応付ける必要がある場合があります。この項目は、同じ名前と電話番号を持つ複数の取引先または個人に一致します。Data Cloud アーキテクトは、次の手順を実行します。

  1. Data Cloud の [データストリーム] タブで、[取引先責任者] データストリームを選択します。
  2. [データマッピング] セクションで、[確認] をクリックします。
    選択したデータレイクオブジェクト (DLO) とオブジェクトが画面の片側に表示されます。検索可能なデータモデルオブジェクト (DMO) が反対側に表示されます。
  3. [Data Lake Objects] で、[Business Phone] フィールドをクリックします。
  4. [データモデルエンティティ] で、検索ボックスを使用して連絡先電話オブジェクトの [書式設定された E164 電話番号] 項目を見つけます。セクションを展開するには、［Unmapped］ をクリックします。
  5. [Formatted E164 Phone Number] フィールドをクリックして、左側の [Business Phone] に対応付けます。
    実線は 2 つの項目を接続します。
  6. [保存] をクリックします。
    ビジネスの使用事例とその他の必須項目に基づいて、この手順を続行します。
    メモ [データストリーム] タブからデータストリームの状況を表示します。状況が表示されない場合は、ドロップダウンをクリックし、[今すぐ更新] を選択します。

これで、Data 360 を Salesforce CRM 組織に接続し、標準バンドルをインストールして、データを取り込んでマッピングできました。この取り込まれたデータを使用して、パーソナライズとエンゲージメントを促進し、Salesforce Customer 360アプリケーション全体およびそれ以降のインサイトを引き出すことができます。

  • パッケージのアップグレード中に ISV パートナーが識別子のサポートを終了した場合、アップグレード中に ISV パートナーが行った変更を反映するように有効化を更新する必要があります。
  • ISV パートナーでサポートされている ID の可能なすべての値を対応付けていて、追加の連絡先デジタル ID 検索条件が適用されていない場合、サポートされている識別子にリンクされている連絡先デジタル ID DMO のすべてのレコードが有効になります。ただし、検索条件を適用すると、有効化に含めるレコードをより詳細に制御できます。
  • メモ デジタル識別子をモデル化して ContactPointDigitalId DMO にマッピングし、外部プラットフォーム用の有効化ツールキットを正常に使用する方法については、「JSON ベースの外部有効化対象のデジタル識別子の取り込みとモデル」を参照してください。

Data 360 への Salesforce CRM 組織の接続

Salesforce 組織を Data 360 に接続して、Data 360 で処理と統合するために Salesforce オブジェクトからデータを取り込みます。選択した接続の種別に応じて、データアクションまたはハーモナイズされた Data 360 データのみを送信できます。Salesforce CRM 組織の Data 360 のデータと機能にアクセスするには、Salesforce コンパニオン接続を設定します。フロー、Apex、CRM、データ強化などのプラットフォーム コンポーネントも、コンパニオン組織全体のData 360データにアクセスできます。

標準 CRM 接続を使用する組織と Data Cloud One コンパニオン接続を使用する組織を同じアーキテクチャで接続できます。プロファイルの統合と統合データ共有に関する会社のニーズに最適な接続種別を選択します。

例

NTO Sales は組織で Data 360 をプロビジョニングしました。NTO カスタマーサービス組織と NTO Sporting Goods Retail 組織はコンパニオン接続を介して Data 360 に接続され、これらの組織と Data 360 間で選択したデータスペースの双方向データ共有が可能になります。Data 360 を利用した機能と Data Cloud One アプリケーションへのアクセスを設定できます。NTO Materials Research は、標準の Salesforce CRM 接続を介して接続されます。そのデータはData 360に取り込まれ、NTOのサービス組織や小売組織のデータと共に統合されますが、資料調査組織はデータアクションのみを受け取ることができます。

自宅組織

ホーム組織は、Data 360 がプロビジョニングされている Salesforce 組織です。Data 360 に自動的に接続されます。

コンパニオン組織

コンパニオン組織とは、Data 360 コンパニオン接続を介して Data 360 に接続されている組織です。ホーム組織はデフォルトで接続されているため、コンパニオン組織にすることはできません。コンパニオン組織のユーザーは、Data Cloud One アプリケーションの Data 360 機能のサブセットにアクセスできます。Data 360 データは、フローや強化などのプラットフォーム機能を強化するコンパニオン組織で使用できます。

標準 Salesforce CRM コネクタ

Data 360 から Salesforce 組織への標準の Salesforce CRM 接続により、Data 360 でデータを取り込んでデータアクションを送信できます。標準接続では、メタデータは接続組織に同期されず、接続組織に Data 360 の機能またはデータへのアクセス権は付与されません。組織が標準接続を介してのみ Data 360 に接続されている場合、Data 360 の機能を設定することはできません。

Data 360 コンパニオン接続

Data 360 コンパニオン接続を使用して、1 つの Data 360 と 1 つ以上の Salesforce 組織間の双方向接続を作成します。コンパニオン接続は、統合メタデータをコンパニオン組織に同期し直すことで、標準の Salesforce CRM 接続の機能に基づいて構築されます。組織がコンパニオン接続を介して Data 360 に接続されている場合、Data 360 の機能を設定できます。

Data Cloud One アプリケーション

Data Cloud One アプリケーションは、任意のコンパニオン組織で使用できます。Data Cloud One アプリケーションでは、コンパニオン組織のユーザーが Data 360 の一部の機能にアクセスできます。Data Cloud One では、一部の Data 360 機能にアクセスできません。

Data 360 のデータソース

データ ソースは、データ ストリームを作成する前に管理者が設定する特定の要件とステップを使用して、さまざまな方法で Data 360 に取り込まれるか、Data 360 に接続されます。

データソースは、Marketing Cloud Engagement コネクタや CRM コネクタなどの Salesforce コネクタになります。Salesforce コネクタには、データストリームをすばやく設定できるようにオブジェクトとマッピングを事前定義するスターターデータバンドルが用意されています。

他のサービスで SDK や取り込み API を使用してデータソースを接続することもできます。MuleSoft Anypoint コネクタまたはサードパーティインテグレーションを使用して、データソースの可能性を拡大することもできます。新しいコネクタは定期的に追加され、Data 360 に取り込めるデータが拡張されるため、データを統合する際の価値が高まります。

  • Data Cloud 用 Salesforce コネクタ
    Data Cloud では、他の Salesforce データソースに接続できます。これらのデータソースの多くのコネクタには、データストリームをすばやく設定するためのスターターデータバンドルがあります。スターターデータバンドルは、Salesforce で定義された、Data Cloud DMO 構造へのマッピングを含むデータストリーム定義です。バンドルをカスタマイズすることもできます。一部のコネクタでは、複数のデータバンドルオプションが提供されます。
  • Web およびモバイルアプリケーションコネクタ
    Web およびモバイルアプリケーションを Data Cloud に接続して、顧客エンゲージメントデータを収集します。このデータは、メッセージのカスタマイズ、オートメーションの作成、AI プロジェクトのサポートなどに役立ちます。接続したら、データを Data Cloud に取り込むようにデータストリームを設定することで、さまざまな用途でこのデータにアクセスおよび照会できるようになります。
  • Zero Copy Data Federation (ゼロコピーデータ統合)
    Data 360のゼロ コピー データ統合は、物理的に異なる複数のデータソースからデータを照会するプロセスです。このアプローチにより、ユーザーは、異なるシステムを統合と呼ばれる 1 つの論理システムとして扱い、各システムの自律性を維持できます。重要なのは、データ統合により、システム境界を越えてデータが重複することを回避できることです。Data 360。

SQL を使用したストリーミングインサイトの作成

SQL 式を記述して、ほぼリアルタイムのデータソースからディメンション全体のストリーミング評価指標を計算します。ストリーミングインサイトでは、特定の時点のデータが分析されます。ストリーミング インサイトは、ほぼリアルタイムで時系列集計を作成し、Data 360内のデータをオーケストレーションして最適化するのに役立ちます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限セット
ストリーミングインサイトを作成する

権限セット

  • Data Cloud アーキテクト

ストリーミングインサイトを設定するには、いくつかの前提条件と手順が必要です。最適な結果を得るには、次のアクションフローに従います。

  • データソース — Web および Mobile SDK、取り込み API、Marketing Cloud Personalization データストリームからさまざまなオブジェクトにソースをマッピングします。
  • ID解決とデータ マッピング — データをData 360に取り込み、ID解決を使用して統合個人を作成します。
  • インサイト — ストリーミングインサイトは計算済みインサイトに似ていますが、ストリーミングデータを管理するための専用の関数があります。
  • 一致ルール — 顧客からの統合個人データで強化します。
  • 強化 — プロファイル関連の属性でデータアクションを拡張します。
  • データアクション — ストリーミングインサイトにデータアクションを適用し、そのアクションが必要かどうかを評価します。
  • DMO — ストリーミングインサイトでは、エンゲージメント DMO のみをプライマリ DMO として使用できます。プロファイルとその他の DMO は、右テーブル結合として使用できます。
  • ウィンドウ関数 — ストリーミングインサイトには、ウィンドウ関数集計が必要です。window.start と window.end を使用して、 SELECT ステートメントでウィンドウ枠を定義します 。
  1. Data Cloud で、[計算済みインサイト] タブに移動し、[新規] をクリックします。
  2. [データスペース] ドロップダウンから、データスペースを選択します。
    使用できるのは、アクセスできるデータスペースのみです。
  3. [ストリーミングインサイト] をクリックします。
  4. [Use SQL Authoring (SQL オーサリングを使用)] をクリックし、[次へ] をクリックします。
  5. ストリーミングインサイト名を入力し、[次へ] をクリックします。
    [ストリーミングインサイト API 参照名] 項目は自動入力されます。
  6. 最大 131,021 文字の SQL クエリ式を入力します。
  7. インサイトに通貨基準が含まれる場合、TRY_CONVERT_CURRENCY 関数を使用する必要があります。
  8. SQL 式が有効かどうかを確認するには、[構文を確認] をクリックします。
    無効な場合、続行できません。
  9. [保存して実行] をクリックします。

ストリーミングインサイトがレコードホームページに表示されます。ストリーミングインサイトの最終実行状況は常に [処理中] です。
