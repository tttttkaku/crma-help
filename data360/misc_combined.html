計算済みインサイトを使用したセールスデータの分析

Data Cloud 内のデータの複数ディメンション評価指標を計算します。評価指標はプロファイル、セグメント、母集団レベルで作成できます。たとえば、チャネルレベルでパフォーマンスを評価したり、商品評価指標を使用して購入行動や閲覧行動を把握したりできます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

Data Cloud アーキテクトは、SQL 式を作成したり、SQL インサイトビルダーを使用して、マッピングされたオブジェクトや項目から評価指標やディメンションを作成したりできます。その後、データエクスプローラーを使用して、データレークオブジェクト (DLO)、データモデルオブジェクト (DMO)、または計算済みインサイトオブジェクト (CIO) から Data Cloud データを表示できます。

計算済みインサイトの作成

計算済みインサイトを作成する前に、ID 解決を使用して統合プロファイルを生成します。

  1. Data Cloud の [計算済みインサイト] タブで、[新規] をクリックします。
  2. [データスペース] ドロップダウンから、データスペースを選択します (デフォルトに設定することもできます)。
  3. [Create with SQL (SQL で作成)] をクリックし、[次へ] をクリックします。
  4. 計算済みインサイトの名前と説明 (省略可能) を入力します。[API 参照名] 項目は自動入力されます。
  5. この例の式を SQL クエリの例「Unified Individual Counts by Sales Object」に置き換えます。 
    SELECT UnifiedIndividual__dlm.ssot__Id__c AS Customer_Id__c
    ,approx_count_distinct(iil.Contact_Id__c) AS Contact_Count__c
    ,approx_count_distinct(iil.Lead_Id__c) AS Lead_Count__c
    ,approx_count_distinct(iil.ssot__AccountId__c) AS Account_Contact_Count__c
    ,approx_count_distinct(iil.ssot__DataSourceId__c) AS Salesforce_Org_Count__c
FROM UnifiedIndividual__dlm
/* The sub-query is required to perform case statements prior to aggregating */
LEFT JOIN (
    SELECT IndividualIdentityLink__dlm.UnifiedRecordId__c AS UnifiedRecordId__c
   	 ,IndividualIdentityLink__dlm.SourceRecordId__c AS SourceRecordId__c
   	 ,IndividualIdentityLink__dlm.ssot__DataSourceId__c AS ssot__DataSourceId__c
   	 ,CASE
   		 WHEN IndividualIdentityLink__dlm.ssot__DataSourceObjectId__c = 'Contact'
   			 THEN IndividualIdentityLink__dlm.SourceRecordId__c
   		 ELSE NULL
   		 END Contact_Id__c
   	 ,CASE
   		 WHEN IndividualIdentityLink__dlm.ssot__DataSourceObjectId__c = 'Lead'
   			 THEN IndividualIdentityLink__dlm.SourceRecordId__c
   		 ELSE NULL
   		 END Lead_Id__c
   	 ,AccountContact.ssot__AccountId__c AS ssot__AccountId__c
    FROM IndividualIdentityLink__dlm
    LEFT JOIN (
   	 SELECT DISTINCT ssot__AccountContact__dlm.ssot__IndividualId__c AS ssot__IndividualId__c
   		 ,ssot__AccountContact__dlm.ssot__AccountId__c AS ssot__AccountId__c
   	 FROM ssot__AccountContact__dlm
   	 ) AccountContact ON IndividualIdentityLink__dlm.SourceRecordId__c = AccountContact.ssot__IndividualId__c
    WHERE IndividualIdentityLink__dlm.ssot__DataSourceId__c LIKE 'Salesforce_00D%'
    ) iil
    /* "Data Source ID like Salesforce_00D%" identifies Salesforce CRM sources. 00D is the prefix for the Org ID object type.
     * This is optional but it adds greater certainty that this is a Salesforce Org source ID from the connector.*/
    ON UnifiedIndividual__dlm.ssot__Id__c = iil.UnifiedRecordId__c
GROUP BY Customer_Id__c

  6. SQL 式が有効かどうかを確認するには、[構文を確認] をクリックします。無効な場合、続行できません。式を再確認して、もう一度お試しください。
  7. [有効化] をクリックします。
  8. [スケジュール] ドロップダウンから、[スケジュールされていません] を選択します。
  9. [有効化] をクリックします。

Salesforce CRM 接続の別名の使用

July '24 以降、Salesforce CRM 接続を設定するときに別名が必要になります。既存の接続には別名が割り当てられません。データストリームとデータレイクオブジェクトの名前は別名から取得されます。

Salesforce CRM 接続の別名を作成すると、デフォルトのデータストリーム名とデータレイクオブジェクト名に、作成した別名が追加されます。たとえば、組織 MyCompany への接続で別名が SourceOrg の場合、取引先のデータストリーム名とデータレークオブジェクトの表示ラベルは Account_SourceOrg になります。

別名機能が使用可能になる前に作成された接続の場合、別名は割り当てられず、デフォルトのデータストリーム名とデータレイクオブジェクト API 参照名にデータソースの組織 ID が追加されます。たとえば、組織 MyCompany への接続で組織 ID が 00DOK00129XWZ の場合、Account のデータストリーム名とデータレイクオブジェクト名は Account_00DOK00129XWZ になります。

デフォルトでは、Data Cloud を使用して組織がプロビジョニングされると、ホーム組織の接続にエイリアス Home が付与されます。

別名は、接続の作成プロセス中に定義します。接続が確立されると別名を変更できなくなるため、名前は慎重に選択してください。

抽出のデータ更新プロセス

データ更新には 2 つのフェーズがあります。すべての対象データを置き換えるフル更新と、フル更新の実行間でデータを更新する増分更新です。オンデマンドでフル更新と増分更新の両方を実行できます。さまざまな更新シナリオと、ContentVersion および Knowledge＿kav オブジェクトの特殊な動作について説明します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

データ更新フェーズ

データ更新 (またはデータ同期) には 2 つのフェーズがあります。

  • フル更新: 取得元データ全体が取得先データ全体を置き換えます。
  • 増分更新: フル更新サイクルの間に更新されます。増分更新ごとに、以前の抽出の開始時刻から現在の時刻までのデータが抽出されます。

すべてのデータ更新フェーズには 2 つのフェーズがあります。

  • ソース組織からのデータの抽出。
  • Data 360 対象組織へのデータの取り込み。

取り込みを開始する前に、抽出が成功する必要があります。[Data stream History (データストリーム履歴)] パネルには、抽出エラーと取り込みエラー、または成功した取り込みが表示されます。データレイクオブジェクト (DLO) に抽出されたデータが含まれている場合、Data 360 では取り込みが成功したとみなされます。履歴パネルには、後続の取り込みフローが成功メッセージにカプセル化されるため、成功した抽出は表示されません。

メモ まれに、抽出時にデータストリームが失敗すると、データストリームの状態が不良になる可能性があります。たとえば、ソース組織と対象組織間の接続が中断された場合、更新によって中断がエラーとして表示される可能性があります。問題が一時的で、抽出する新しいデータがない場合、メッセージは送信されません。

Knowledge Articles and Content Version Objects Unique Refresh Behavior (ナレッジ記事およびコンテンツバージョンオブジェクトの一意の更新動作)

ContentVersion オブジェクトを介したコンテンツ バージョンのストリーミングと Knowledge＿Kav オブジェクトを介した Knowledge 記事のストリーミングは、独自の更新パターンに従います。

Content Version Special Day- Zero Behavior: 他のオブジェクトの初期データ同期動作とは異なり、Data 360 では、初期同期時に CRM 組織からすべての ContentVersion オブジェクトデータが取り込まれません。代わりに、フル更新の一環として、データストリームが作成された後に作成または更新されたデータが取り込まれます。

ドキュメント AI

Data 360のドキュメントAIは、LLM(大規模言語モデル)を使用して、請求書、履歴書、ラボ レポート、購入注文などの非構造化ドキュメントから構造化データを抽出します。

ドキュメント AI では、2 つの処理モードがサポートされています。

  • リアルタイム (トランザクション) モード: Salesforce のドキュメントに対して直接ドキュメント AI API を呼び出すか、実行時に送信します。このモードでは、非構造化データモデルオブジェクトを作成する必要はありません。
  • バッチモード: 外部ソースから大量のドキュメントを処理するには、ファイルを参照する非構造化データモデルオブジェクト (UDMO) を作成します。Data 360 には、サードパーティソースから非構造化データを取り込むために構築されたコネクタがいくつかあります。ドキュメント AI はドキュメントからデータをデータレークオブジェクト (DLO) に抽出します。DLO は抽出されたデータのスキーマを表します。これ以降、データは検索インデックス処理や自動化フローまたはAIエージェント アクションからの取得に使用できます。

AI 要件の文書化

  • Einstein生成AIを有効にし、AgentforceがData 360でドキュメントAIを使用できるようにします。
  • Data 360 で Document AI を使用するには、Data 360 ライセンスが必要です。Customer Data Platform ライセンスではドキュメント AI を使用できません。

ドキュメント AI の使用事例

さまざまなクラウドで作業しているチームが Document AI を使用して設定のドラフトを作成し、ドキュメントスキーマを調整して本番用に公開する方法を探索します。

Sales Cloud 契約ドキュメントを取り込んで顧客プロファイルにリンクし、すべての契約データを一元化します。
Sales Cloud 請求書を取り込み、関連するローン申込から抽出されたデータとプログラムで比較します。
Service Cloud ゲストアンケートデータの取り込み、顧客レコードの作成、将来の商談のフォローアップを行います。
従業員サービス 確定申告ドキュメントを取り込み、従業員レコードにリンクします。
Health Cloud 手書きまたはシステムで生成された患者ラボレポートからデータを抽出します。

ドキュメント AI の請求に関する考慮事項

ドキュメント AI の使用は請求に影響します。詳細は、「Billing Considerations for Document AI (ドキュメント AI の請求に関する考慮事項)」を参照してください。

  • 自動抽出を使用したドキュメントスキーマ設定の作成
    ソースファイルからデータレークオブジェクト (DLO) に抽出されたデータを表すドキュメントスキーマを設定します。ドキュメントスキーマビルダーの自動抽出オプションを使用して、LLM でドキュメントスキーマの構造を定義します。ビルダーでは、すべての項目、テーブル、列が自動入力されます。
  • ドキュメントスキーマ設定の手動作成
    ソースファイルからデータレークオブジェクト (DLO) に抽出されたデータを表すドキュメントスキーマを設定します。ドキュメントスキーマビルダーを使用して、項目とテーブルを追加してドキュメントスキーマの構造を手動で定義します。
  • ソースオブジェクトを使用しないドキュメントスキーマ設定の作成
    プログラム API ワークフローで使用するドキュメントスキーマを設定します。ドキュメントスキーマビルダーを使用して、新しいドキュメントスキーマを定義します。
  • ドキュメントの AI 設定の管理
    ドキュメント AI 設定を表示、編集、公開、エクスポート、再構築します。ドキュメント AI 設定をデータキットにパッケージ化します。ドキュメント AI 設定をドラフトとして保存し、複数のセッションで抽出スキーマを調整します。
  • ドキュメント AI スキーマの例
    次のプロンプトは、Data 360 でドキュメント AI 設定を作成するときに使用できる JSON 形式のスキーマです。これらの例を出発点として使用したり、特定の使用事例に合わせて変更したりします。
  • ドキュメント AI の請求に関する考慮事項
    ドキュメントAIは、Data 360を使用して非構造化ドキュメントから構造化データを抽出し、Flex Creditsを使用して生成AIをコールします。ドキュメント AI の使用は、次の利用状況種別のクレジットの消費に影響します。

ドキュメントの AI 設定の管理

ドキュメント AI 設定を表示、編集、公開、エクスポート、再構築します。ドキュメント AI 設定をデータキットにパッケージ化します。ドキュメント AI 設定をドラフトとして保存し、複数のセッションで抽出スキーマを調整します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
ドキュメント AI 設定を管理する

権限セット

  • Data Cloud アーキテクト

ドキュメント AI 要件

  • Data Cloud 360でドキュメントAIを使用するには、Einstein生成AIとAgentforceを有効にします。
  • Data 360 ライセンスがあることを確認します。Customer Data Platform ではドキュメント AI を使用できません。

ドキュメントの AI 設定の詳細の表示

ドキュメントAI構成の詳細ページには、[ドラフト]状態または[有効]状態のいずれであるか、ランタイム ステータス、ソース、出力データ、その他の情報が表示されます。

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [Process Content | Document AI (コンテンツドキュメント AI を処理)] をクリックします。
  3. ドキュメント AI 設定を選択し、詳細を確認します。
  4. 出力スキーマを確認するには、[出力] をクリックします。

ドラフト設定の編集

ドラフト設定を公開する前に変更および調整します。

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [Process Content | Document AI (コンテンツドキュメント AI を処理)] をクリックします。
  3. 編集するドラフト設定を選択します。
  4. [編集] をクリックします。
  5. 項目、テーブル、またはその他の設定を変更します。
  6. [Test (テスト)] をクリックして、抽出結果を確認します。
  7. [ドラフトを保存] を選択して、変更を保存します。

ドキュメントの AI 設定の公開

スキーマが必要な精度を満たしたら、ドラフト設定を公開してドキュメント処理用に有効化します。

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [Process Content | Document AI (コンテンツドキュメント AI を処理)] をクリックします。
  3. 公開するドラフトを選択します。
  4. 詳細とテスト結果を確認します。
  5. [公開] をクリックします。

ドキュメントの AI 設定の削除

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [Process Content | Document AI (コンテンツドキュメント AI を処理)] をクリックします。
  3. 削除するドキュメント AI 設定を選択します。
  4. オブジェクトビューで、[削除] をクリックします。

ドキュメントの AI 設定の再構築

ドキュメントスキーマ設定が正しく処理されない場合は、設定を再構築します。

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [Process Content | Document AI (コンテンツドキュメント AI を処理)] をクリックします。
  3. 再構築するドキュメントスキーマ設定をクリックします。
  4. 詳細ページで、[再構築] を選択します。

再構築が完了すると、[最終実行状況] 項目が [準備完了] に変更されます。

ドキュメントの AI 設定を JSON としてエクスポート

ドキュメント AI 設定を JSON ファイルとしてエクスポートして再利用します。

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [Process Content | Document AI (コンテンツドキュメント AI を処理)] をクリックします。
  3. ドロップダウンメニューを選択して、ドキュメント AI 設定をエクスポートします。
  4. [Export JSON (JSON をエクスポート)] を選択します。

設定は、別の組織または環境にインポートできる JSON ファイルとしてダウンロードされます。

データキットへのドキュメントスキーマ設定の追加

ドキュメントスキーマ設定をデータキットに追加して、ユーザーや環境で機能を共有します。

  1. Data Cloud の [設定] に移動します。
  2. [ツール] で、[データキット] | 新規] をクリックします。
  3. データキットに名前を付け、必要に応じて説明を追加します。
  4. [保存] をクリックします。
  5. [ドキュメントスキーマ] で、[追加] をクリックします。
  6. データキットに追加するドキュメントスキーマを選択し、[次へ] をクリックします。
  7. [保存] をクリックして、[公開] をクリックします。

データキットが作成されます。これで、パッケージマネージャーで公開できます。

Einstein 生成 AI の有効化

使用を開始する前に、ドキュメントAIで生成AI機能を使用するようにEinsteinを有効にします。Einsteinを有効にした後、EinsteinとData Cloudを同期するまで数分かかります。

  1. システム管理者:[設定] から、[クイック検索] ボックスに「Einstein 設定」と入力し、[Einstein 設定] を選択します。
    メモ Einstein設定が見つからない場合は、使用する生成AI機能の前提条件を組織が満たしていることを確認してください。詳細は、Salesforce アカウントエグゼクティブ (AE) にお問い合わせください。
  2. Einstein を有効にします。

出力 DLO の作成

ソースファイルから抽出されたデータのスキーマ定義を表す出力 DLO を設定します。

  1. アプリケーションランチャーで、[Data Cloud] を選択します。
  2. [Process Content (コンテンツを処理)] | [Document AI (ドキュメント AI)] | [新規] をクリックします
  3. [From a Source Object (ソースオブジェクトから)] をクリックします。
  4. 処理するドキュメントが含まれる UDMO を選択し、[次へ] をクリックします。
  5. 切り替えを使用して、ドキュメントスキーマ設定で使用できるファイルの種類を選択し、[次へ] をクリックします。
  6. 使用する LLM を選択し、[次へ] をクリックします。
  7. [データレークオブジェクトの設定] ページで、[追加] をクリックします。
  8. [From Scratch]をクリックし、[New Data Lake Object]ダイアログで、[DLO Name]と[API Name]の値を入力し、[Next]をクリックします。

ドキュメントスキーマの自動抽出

ドキュメントスキーマビルダーを使用して、項目、テーブル、列などのドキュメントスキーマを自動抽出します。

  1. ドキュメントスキーマビルダーで、[自動抽出を使用] をクリックし、[次へ] をクリックします。
    Document Al は、ソースからすべてのデータを自動抽出し、ドキュメントスキーマに自動入力します。
  2. [Test (テスト)] をクリックし、抽出の結果を確認します。
  3. [ドラフトを保存] を選択して後で設定を再確認するか、[公開] を選択して設定を有効化します。

詳細ページでドキュメントスキーマ設定を表示できます。代わりに JSON ファイルからスキーマを入力するには、「Import a Document Schema Configuration from JSON」を参照してください。

抽出する項目の追加

ドキュメントスキーマの構造を抽出して定義するための項目を設定します。

  1. ドキュメントスキーマビルダーで、[手動で作成] をクリックし、[確認] をクリックします。
  2. [出力] パネルで、[項目] タブを選択し、[項目を追加] をクリックします。
  3. 項目の名前、API 参照名、カテゴリを入力します。
  4. フィールドをさらに追加するには、［Add］ をクリックします。
  5. [Test (テスト)] をクリックし、抽出の結果を確認します。
  6. [ドラフトを保存] を選択して後で設定を再確認するか、[公開] を選択して設定を有効化します。

抽出するテーブルの追加

抽出するテーブルを設定します。

  1. [出力] パネルで、[テーブル] タブを選択します。
  2. [テーブルを追加] をクリックします。
  3. テーブルの名前、API 参照名、カテゴリを入力します。
  4. [列] タブをクリックし、[新規列を追加] をクリックして、列の名前、API 参照名、カテゴリを指定します。
  5. テーブルが完了するまで列の追加を続行します。
  6. さらにテーブルを設定するには、[新規追加] をクリックし、この手順を繰り返してテーブル列を追加します。
  7. [Test (テスト)] をクリックし、抽出の結果を確認します。
  8. [ドラフトを保存] を選択して後で設定を再確認するか、[公開] を選択して設定を有効化します。
