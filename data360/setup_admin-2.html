CRM ストリーミングの権限の有効化

CRM ストリーミングの場合、次のシステム権限とユーザー権限を設定します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
オブジェクトと項目を取り込む

権限セット

  • Data 360 アーキテクト

特定のシナリオでは、ストリーミング処理モードがバッチに変更される場合があります。「CRM コネクタストリーミング」を参照してください。

  1. [設定] の [クイック検索] ボックスに「権限」と入力し、[権限セット] を選択します。
  2. [Data 360 Salesforce Connector (Data 360 Salesforce コネクタ)] 権限セットを選択します。
  3. [システム権限] をクリックします。
  4. [View Setup and Configuration (設定・定義の参照)]、[Customize Application (アプリケーションのカスタマイズ)]、[Modify Metadata Through Metadata API Functions (メタデータ API 関数を使用したメタデータの変更)] を有効にします。
  5. ユーザーデータストリームの「ユーザー」にある「すべてのユーザーの参照」権限を有効化
  6. 変更内容を保存します。

Salesforce CRM 権限

組織に接続すると、Data 360 オブジェクトおよび項目へのアクセスを許可する「Data 360 Salesforce コネクタ」権限セットが作成されます。組織のニーズに合わせて「Data 360 Salesforce コネクタ」権限セットを編集できます。

  • 「すべてのレコードの参照」、「すべてのレコードの編集」、および「すべての項目の表示」権限はオブジェクト権限です。データを取り込むには、オブジェクトおよび項目に対して「すべてのレコードの参照」および「すべての項目の表示」が付与されている必要があります。［View All Fields］ はデフォルトで有効になっています。「すべてのフィールドの参照」ユーザー権限を持つユーザーは、割り当てられたフィールド権限に関係なく、すべてのオブジェクトのすべてのフィールドとフィールドデータを表示できます。
  • [View All Records (すべてのレコードの参照)] は、デフォルトでは有効になっていません。この権限は、「Query All Fields (すべてのフィールドのクエリ)」権限を有効にするために必要です。この権限は、コンテンツファイルとオブジェクトへのアクセス権をユーザーに付与します。
  • 「すべてのデータの参照」または「すべてのデータの編集」ユーザー権限を持つユーザーは、アプリケーションとデータが自分と共有されていない場合でも、すべてのアプリケーションとデータを参照または変更できます。
  • Data 360 では、プラットフォームインテグレーションユーザーと呼ばれるシステムユーザーが使用されます。このユーザーに権限セットを介して付与された権限によって、Data 360 から取得するデータが決まります。
  • 関連オブジェクトを Data 360 に取り込まない場合でも、関連オブジェクトに対する権限を付与します。 関連オブジェクトを参照する取り込みオブジェクトには、関連オブジェクト情報にアクセスしてデータストリームを作成する権限が必要です。
  • Winter '25 リリース以降:
    • Data 360 Salesforce コネクタ権限セットには、新しい組織でデフォルトで有効になっている「すべてのデータの参照」権限が含まれます。既存の Data 360 Salesforce コネクタ権限セットの場合、「すべてのデータの参照」権限を手動で適用するか、オブジェクト権限を一度に 1 つずつ設定できます。
    • sfdc_c360a_sfdctrust_permSet API の名前が sfdc_a360_sfcrm_data_extract に変更されました。これは内部 API ですが、Data 360 Salesforce コネクタ権限セットの詳細ページに表示されます。Winter '25 にアップグレードすると、廃止された sfdc_c360a_sfdctrust_permSet API 参照名を使用するスクリプトは 0 を返します。
  • SurveyQuestionResponse オブジェクトへのアクセスは、SurveyResponse オブジェクトによって制御されます。Survey オブジェクトのデータの取り込みを有効にするには、SurveyResponse オブジェクトに「すべてのレコードの参照」または「すべてのレコードの編集」権限を付与します。
  • Salesforce CRM 組織で権限セットを変更すると、Data 360 のデータバンドルのデフォルトの動作に影響する可能性があります。
  • ユーザーが ToDo と行動にアクセスできるようにするには、「Data 360 Salesforce コネクタ」権限セットで「活動にアクセス」システム権限を有効にします。
  • CRM 接続のオブジェクトおよび項目権限の有効化
    「Data Cloud Salesforce コネクタ」権限セットを編集して、オブジェクトと項目を Data 360 に取り込むことができます。
  • CRM ストリーミングの権限の有効化

  • データストリームが編集されたとき (ソース項目や数式項目が追加されたときなど)。

Customer Data Platform ライセンスから Data Cloud ライセンスへのユーザーの移行

以前に Customer Data Platform ライセンスで Data 360 を運用していた組織に Data Cloud ライセンスを追加すると、Customer Data Platform ライセンスで付与された権限セットによって Data 360 へのアクセスは許可されなくなります。ユーザーに Data 360 への継続的なアクセスを提供するには、Data Cloud ライセンスに関連付けられた権限セットをユーザーに割り当てる必要があります。

必要なエディション

必要なユーザー権限
権限セットを割り当てる

「権限セットの割り当て」

および

「設定・定義を参照する」
  1. Data Cloud ライセンスに関連付けられている Data Cloud 権限セットを特定します。
  2. 必要に応じて、Data Cloud ライセンスで付与される標準権限セットをカスタマイズするか、標準権限セットからカスタム権限セットを作成します。
  3. Data Cloud ライセンスで付与された権限セットをユーザーに割り当てます。
    このプロセスを自動化するには、ユーザーアクセスポリシーを使用してユーザーグループの権限セットを移行します。
  4. Customer Data Platform ライセンスで付与された権限セットを削除します。
    このプロセスを自動化するには、ユーザーアクセスポリシーを使用してユーザーグループの権限セットを移行します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

必要なユーザー権限
データスペースを管理する データスペース範囲の管理

複数のデータスペースにアクセスする必要がある Data Cloud ユーザーがいる場合、機能アクセス専用の権限セットを作成します。この専用の権限セットでは、ユーザーを特定のデータスペースに接続して、そのスペース内の機能レベルのアクセス権のみを付与します。オブジェクト権限は含まれません。標準 Data Cloud 権限セットを使用して、ユーザーにロールベースのオブジェクト権限を付与します。専用権限セットは、データスペースを認識する機能に適用できます。

  1. 特定のアクセス権が必要なデータスペースごとに専用の権限セットを作成します。
  2. Data Cloud データスペース管理設定で、専用の権限セットをデータスペースに接続します。
  3. ユーザーにロール権限とオブジェクト権限を付与するには、標準の Data Cloud 権限セット (「Data Cloud データアウェアスペシャリスト」など) を割り当てます。
  4. 特定のデータスペースの機能へのアクセス権をユーザーに付与するには、専用の権限セットを割り当てます。
  5. レコードレベルでユーザーアクセスを制御するには、[Data Cloud Feature Permissions (Data Cloud 機能権限)] で、各機能の [表示] または [カスタマイズ] を有効にします。

データスペースのデータレークオブジェクト (DLO) とデータモデルオブジェクト (DMO) の間の接続を作成します。セグメンテーションと有効化のリレーションではマッピングされた項目とオブジェクトのみを使用できます。

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
アドオンライセンスで使用可能な機能: データスペース
必要なユーザー権限
データオブジェクトをマッピングする

権限セット

  • Data Cloud アーキテクト

データオブジェクトをデータスペースにマッピングする前に、「データマッピング」を参照して要件と DMO リレーションを理解します。

  1. Data 360 で、[データストリーム] タブに移動します。
  2. マッピングするデータストリームを開きます。[データマッピング] セクションには、DLO が関連付けられているすべてのデータスペースが表示されます。
  3. ［Start］ をクリックします。
  4. [データモデル] エンティティで、[オブジェクトを選択] をクリックします。
    キャンバスの左側にソース DLO、右側に対象 DMO が表示されます。マッピングではすべての標準 DMO を使用できます。
  5. カスタムデータモデルを選択するには、[カスタムデータモデル] タブに移動し、[新規カスタムオブジェクト] をクリックします。
  6. オブジェクトの表示ラベル、オブジェクト API 参照名、項目を確認します。
  7. [保存] をクリックします。
  8. マッピングを確立するには、DLO で項目を選択し、DMO で関連項目をクリックします。項目を接続する矢印と共に確認メッセージが表示されます。
  9. [保存] をクリックします。

Data 360 のデータオブジェクトの概念とスキーマ

取り込み時に、Data 360はデータのサンプルを取得し、ソース スキーマを推奨します。その後、推奨されるスキーマを確認して変更できます。

スキーマでは、編集不可のヘッダーの表示ラベルで未加工データのソースが識別されます。その他の表示ラベルは変更できます。

  • 項目の表示ラベル — 各ソースヘッダー列の提案された Data 360 の表示名。
  • 項目 API 参照名 — 各ソースヘッダー列の提案された Data 360 API 参照名。
  • データ型 — 各ソースヘッダー列の提案されたデータ型。サポートされるデータ型についての詳細は、「Data 360 のデータ型」を参照してください。
    警告 誤ったデータ型を選択した場合、データストリームを削除して再作成する必要があります。データストリームの作成後にデータ型を変更することはできません。
  • ソース、オブジェクト名、オブジェクト API 参照名
    データセットを Data 360 に取り込むときに、データセットに source という名前を付けます。
  • カテゴリ
    データストリームを作成するときに、そのデータストリームで見つかったデータのカテゴリまたはタイプを選択します。
  • 主キー
    Data Cloud でデータストリームを作成するには、そのソースのプライマリキーまたは一意の識別子を選択します。データソースに主キーとして使用できる項目がない場合は、数式項目を使用して 2 つ以上のソース項目を組み合わせて複合キーを作成します。
  • 匿名プロファイルと既知のプロファイルの分類
    ソースプロファイルは、取り込み時にデータストリームの個人 DMO の [匿名] 項目の値に基づいて匿名または既知に分類されます。この項目がマッピングされていないソースプロファイルは常に既知とみなされます。既知のプロファイルと匿名プロファイルを分類できるように、このマッピングを追加してください。
  • 組織単位識別子
    Organization Unit Identifier (組織単位識別子) は、Data 360 データでビジネスユニットを指定できる省略可能なフィールドです。
  • データ系統項目
    Data 360 は、データオブジェクトに項目を追加して、データソースの詳細を取得します。
  • ソースオブジェクトスキーマの変更
    Data 360 ソースオブジェクトスキーマは、データストリームの詳細ページで変更できます。すべての変更は、以降のデータインポートに適用されます。ロジックを遡って適用するには、ソースから取得して Data 360 に取り込みます。
  • 完全修飾キー
    Data 360 データモデルでさまざまなソースからのデータがハーモナイズされるときに、完全修飾キー (FQK) を使用してキーの競合を回避します。
  • 数式項目の作成

    FSC オブジェクトを取り込むための権限とライセンス要件を Salesforce CRM 組織に追加します。
  • データキットにより提供される標準データバンドルのインストール
    Data 360 インスタンスを作成して Salesforce CRM 接続を設定したら、データキットによって提供される標準データバンドルをインストールして、Data 360 内にデータをリリースできます。
  • Salesforce CRM のオブジェクト共有アクセス権の設定
    QuickTextUsage や MacroUsage などの特定のオブジェクトの共有アクセス権は、デフォルトで [非公開] に設定されます。これらのオブジェクトを Data 360 に取り込むには、組織の共有アクセス権を公開に変更します。
  • Salesforce CRM 接続の切断
    接続が必要なくなったら、削除できます。標準のSalesforce CRM接続を削除すると、Data 360は接続組織からのデータの取り込みを停止し、Trustファイルを除く、その組織から取り込んだすべてのデータを削除できます。組織から取り込まれたデータは、次に ID 解決が実行されるときに統合プロファイルから削除されます。
  • Salesforce CRM 接続の確認と再認証
    Salesforce CRM Connection Trustを確認し、中断がSandboxの更新によって発生した場合は再認証します。Salesforce 組織に Sandbox 組織への CRM 接続があり、その Sandbox が最近更新された場合、更新プロセスで既存の接続に関連付けられている組織 ID と競合する Sandbox 組織の新しい組織 ID が生成されます。Data 360は更新されたSandboxでTrustを確立できないため、Data 360への接続が中断され、再認証が必要になります。接続が切断されると、新しいストリームのリリースの失敗やストリームの更新履歴内のエラーなど、接続に関連付けられているデータストリームでエラーが発生する可能性があります。

Data 360 のプラットフォーム暗号化の設定

プラットフォームの暗号化を有効にすると、最初の Data 360 ルート鍵が自動的に生成されます。この鍵は、Data 360 に以前取り込まれたすべてのデータを暗号化します。 初期設定後、生成されたルート鍵を引き続き使用するか、外部鍵管理 (EKM) を使用して外部鍵を設定するか、Salesforce UI で Bring Your Own Key (BYOK) を使用して独自の鍵素材を活用し、Data 360 のデータを暗号化できます。ルート鍵を定期的に循環し、[設定] で作成日時や作成者などの鍵メタデータを表示できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
アドオンライセンスで使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。Salesforce ShieldまたはShield Platform Encryption、Platform Encryption for Data Cloudを購入する必要があります。また、オプションの外部鍵管理を使用するには、Platform Encryption for Consumption ライセンスを購入する必要があります。

主な移行オプションを次に示します。

  • 顧客が管理する鍵 (CMK) から EKM: 既存の CMK ユーザーは、[設定] の [鍵の在庫と管理] ページから新しい EKM 鍵を設定できます。この変更は、今後の新しいデータの暗号化にのみ影響します。以前に暗号化されたデータは、既存の CMK 鍵で暗号化されたままになります。
  • EKM から CMK へ: 既存の EKM ユーザーは、[鍵の在庫と管理] ページで新しい鍵を生成して CMK に切り替えることができます。このアクションでは、新しく生成された CMK 鍵を使用して既存の Data 360 データを再暗号化します。
  • CMK または EKM から BYOK へ: [設定] の [Bring Your Own Key (独自の鍵を使用)] オプションを使用して独自の鍵素材をアップロードします。以前の鍵で暗号化されたデータに引き続きアクセスできます。新しいデータは、新しい BYOK ルート鍵を使用して暗号化されます。
    • 顧客は Salesforce UI を使用して、CMK から BYOK および BYOK から CMK に移行できます。この移行時に、以前に取り込まれたデータが新しい鍵に再暗号化されることはありません。以前の鍵で暗号化されたままになります。
    • 顧客は EKM から BYOK、BYOK から EKM に移行することもできます。
      • EKM から BYOK: 以前に取り込まれたすべてのデータを新しい鍵に再暗号化します。
      • BYOK から EKM: この移行時に、以前に取り込まれたデータを新しい鍵に再暗号化しません。以前の鍵で暗号化されたままになります。
