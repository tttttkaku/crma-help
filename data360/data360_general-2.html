Data 360 のインテリジェントなコンテキスト

インテリジェント コンテキストは、プロンプトを操作して非構造化データを処理し、特定のビジネス コンテキストに合わせて調整された検索インデックス構成を作成するAI機能を備えたワークスペースです。

完全な検索インデックスを作成する前に、少数の非構造化データ セットで検索設定をテストします。まず、インテリジェントコンテキストワークスペースでサポートされるファイルをいくつか追加します。一連のプロンプトに応答して、非構造化データの処理方法をチェックし、期待した結果が返されていることを確認します。インテリジェントコンテキストでは、作業中に設定が自動的に保存され、設定がリストビューに表示されます。

設定をテストしたら、非構造化データモデルオブジェクトに適用して、正確で関連性の高い検索インデックスを作成します。

主なメリットは次のとおりです。

  • 検索精度の向上: LLMを利用したコンテンツ理解、ドメイン固有のインテリジェンス、ユーザーフィードバックループにより、チームとユーザーが正確な情報にすばやくアクセスできます。
  • 複数のファイルタイプをサポート: .docx、.html、.jpeg、.jpg、.pdf、.png、.pptx、.txt など、さまざまな種類のファイルをアップロードできます。
  • カスタマイズ可能なビュー: 1 つのドキュメントから複数のビジネスの視点を取得できます。チームが未加工データをマイニングすることなく関連情報にアクセスできるように、各レンズを設計して、特定のビジネス機能に不可欠な情報に優先順位を付けます。
  • ローコード環境: 使いやすいインターフェースを使用して、広範な技術的専門知識がなくても、非構造化データを設定可能な消費可能な検索インデックスに変換できます。
  • 効率的な問題解決: 検索結果の誤った形式のテーブルなどの一般的な問題に対処し、迅速な診断と問題解決を可能にします。

インテリジェントなコンテキストの要件

  • インテリジェント コンテキストには、Agentforceで使用可能な生成AI機能が必要です。Agentforce を有効にしていない場合は有効にします。
  • インテリジェントなコンテキストで生成 AI 機能を使用するには、Data 360 で Einstein 生成 AI を有効にする必要があります。

インテリジェントコンテキストの使用方法

インテリジェントなコンテキストの次の重要な使用事例を考慮してください。

使用事例 説明
コンテンツの理解とエンドツーエンドの検証 本番システムでコンテンツを使用する前に、いくつかのサンプル・ドキュメントをアップロードして、検索インデックスで重要な情報を検出できるかどうかをすばやく確認します。
プロンプトベースのカスタマイズ 検索インデックス全体を再構築せずに単純なプロンプトを追加することで、不正な形式のテーブルなどの抽出の問題を修正します。たとえば、「ドライブトレインテーブルをマークダウンとして抽出」などです。
テストから本番環境へのリリース サンプルファイルの検索品質を検証し、設定を非構造化データモデルオブジェクト (UDMO) に適用して数千のドキュメントに拡張します。

例: 商品仕様書の調整

Salesforce Platform 内のインテリジェントコンテキストの実用性を理解するために、2 つの異なるチームが商品仕様書を使用する独自のレンズを作成する方法を検討します。

  • セールス: 営業担当にとって価値のある情報 (競争優位性、価格設定構造、顧客の価値提案など) を自動的に抽出するようにセールスレンズを設定します。これにより、営業チームは商品のメリットをすばやく特定して明確化できます。
  • サービス: サービスレンズを設定して、サポートの前提条件、トラブルシューティング手順、メンテナンスガイドラインなど、サービスチームとサポートチームの重要な詳細を強調します。これにより、サービスチームは顧客の成功に必要な情報にすばやくアクセスできます。

このインテリジェントなコンテキストフレームワークにより、ビジネス部門ごとに異なるドキュメントワークフローが不要になります。インテリジェントコンテキストでは、同じ基礎となるデータのカスタマイズされたビューが提供されるため、すべてのユーザーに目的に沿ったインサイトが提供されます。

  • インテリジェントなコンテキスト設定の作成
    インテリジェント・コンテキスト構成の作成には、評価用のサンプル・ドキュメントのアップロード、インテリジェント・コンテキスト構成の設定、結果のテスト、構成の反復、検索インデックスへの公開という重要なステップが含まれます。
  • インテリジェントなコンテキストの請求に関する考慮事項
    インテリジェントなコンテキストの使用は、次の利用状況種別のクレジットの消費に影響します。

Agentforce の有効化

インテリジェント コンテキストには、Agentforceで使用可能な生成AI機能が必要です。組織で Agentforce を有効にしていない場合は有効にします。

新しいインテリジェントコンテキスト設定の作成

新しいインテリジェントコンテキスト設定の使用を開始するには、いくつかのドキュメントをアップロードする必要があります。最大 5 個のドキュメントをアップロードできます。

  1. Data Cloud | Process Content | Intelligent Context に移動して、[新規設定] をクリックします。
  2. [新規検索設定] ダイアログで、 のデータスペースと名前を選択し、[保存] をクリックします。
  3. [インテリジェントなコンテキスト] ページから、新しいプロジェクトを選択します。
  4. [ファイルをアップロード] をクリックするか、ファイルをコンテンツスペースにドロップします。
  5. 設定プレビューでコンテンツを確認するファイルを選択します。

AI スマートデフォルトを使用した設定

AI スマートのデフォルト設定を使用して設定を生成します。

  1. エージェントのチャットで、[スマートデフォルトを使用して設定をセットアップする(Set up my configuration using smart defaults)] をクリックします。
  2. 設定の概要を確認し、受け入れるか変更するかを選択します。
    1. 設定を受け入れた場合は、「インテリジェントなコンテキスト設定に対するテストと反復」に進みます。
    2. 設定を変更する場合は、「Modify an Intelligent Context Configuration」に進みます。

インテリジェントなコンテキスト設定の変更

設定プレビューには、ソースドキュメントから作成された生成されたチャンクが表示されます。必要に応じて、次の設定を変更します。

  1. [Edit Configuration (設定を編集)] タブをクリックします。
  2. 検索タイプを変更するには、[検索インデックス タイプを選択] をクリックし、ベクトル検索またはハイブリッド検索を選択します。
    ベクトル 意味に基づいてコンテンツのインデックスを作成します。
    ハイブリッド セマンティックな意味とキーワードに基づいてコンテンツのインデックスを作成します。
  3. コンテンツの解析方法を変更するには、［Set Parsing Options］ をクリックします。
    LLM ベースの解析オプションと LLM ベースのビジュアルデータ前処理オプションの両方を選択することはできません。これらのオプションの詳細については、「LLM ベースの解析および前処理」を参照してください。
  4. 次のいずれかのオプションを選択します。
    デフォルトパーサー 組み込み設定でテキストを抽出します。
    LLM ベースのパーサー LLM を使用して、すべてのテキスト、画像、その他の視覚要素を抽出します。
    Docling Parser Docling Parser を使用して、画像、テーブル、ドキュメントレイアウトからテキストを抽出します。
  5. 画像やテーブルなどのマルチモーダル要素をチャンクするためのコンテンツの前処理方法を変更するには、[Set Preprocessing Options (前処理オプションの設定)] をクリックします。

    前処理では、テーブルデータ内のコンテキストとリレーションを維持しながら、画像からコンテキストを抽出し、テーブルからデータを抽出します。

  6. [前処理] ドロップダウンリストから、次のいずれかを選択します。
    前処理なし デフォルト設定。
    LLM ベースの前処理 デフォルトのプロンプトをそのまま使用するか、特定の使用事例に合わせて編集します。
  7. テーブル、フォーム、および画像のキャプションからテキストを抽出するには、画像処理の切り替えを有効にします。
  8. [Select an Embedding Model (埋め込みモデルを選択)] をクリックし、リストから埋め込みモデルを選択します。
  9. コンテンツのチャンク方法を変更するには、[Set Data Chunking Rules (データチャンクルールの設定)] をクリックし、チャンク戦略を選択します。
  10. 必要に応じて、トークン設定を調整します。
    チャンク戦略 説明
    セクション対応チャンク

    title 要素と heading 要素を使用してドキュメントをチャンクします。追加設定:

    • Max Tokens (最大トークン): トークンサイズを調整して、隣接する小さなセクションを大きなチャンクに結合します。
    • 重複トークン: 1 つのセクションから複数のチャンクを作成する場合にのみ使用します。各チャンクの末尾から次のチャンクの先頭までに追加するトークン数を指定します。
    通過抽出

    HTML タグに固有のセマンティックな意味を使用して、文書を複数の通路に分割します。追加設定:

    • Max Tokens (最大トークン): トークンサイズを調整して、隣接する小さなセクションを大きなチャンクに結合します。
  11. [Apply Changes (変更を適用)] をクリックします。

    設定を変更すると、Data Cloud によって設定プレビューに新しいコンテンツチャンクのセットが生成されます。

  12. 引き続き設定をテストして評価します。

インテリジェントなコンテキスト設定のテストと反復

エージェントのチャットウィンドウで質問をして設定をテストしたり、生成されたチャンクをソース文書と比較したりします。生成された各チャンクには、信頼性スコア、ソースファイル参照、引用が含まれます。

  1. エージェントのチャットで、提案された質問を選択するか、独自の質問をチャットボックスに書き込みます。
  2. プレビューでソースファイルを開くには、生成されたチャンクをクリックします。チャンクを検索して絞り込むこともできます。
  3. 生成されたチャンクをソースドキュメントと比較するには、[Compare with Source (ソースと比較)] をクリックします。
  4. 設定をさらに変更するには、「インテリジェントコンテキスト設定の変更」の手順に従います。
  5. 引き続き検索インデックス設定を公開します。

検索インデックス設定の公開

設定を公開する前に、ソースファイルを取り込むための非構造化データ接続を設定する必要があります。Data Cloud の非構造化データレイクオブジェクト (UDLO) にソースファイルを取り込むように非構造化データコネクタを設定します。コネクタのリストについては、「非構造化データ ファイル形式とコネクタ」を参照してください。

設定をテストおよび変更したら、最後に公開して組織で使用できるようにします。

  1. [インテリジェントなコンテキスト] で、[公開] をクリックします。
  2. [非構造化データモデルオブジェクトを選択] ダイアログで、設定を適用する非構造化データモデルオブジェクト (UDMO) を選択します。
  3. [次へ] をクリックします。
  4. [検索インデックスを作成] ダイアログで、インデックス名を確認または変更し、[公開] をクリックします。
  5. [コンテンツのインデックス付け] ページまたは [検索インデックス] ページに移動して、結果を確認します。

Data 360 ライフサイクル管理

Data 360のライフサイクルを管理するには、ライセンスを更新するか、Data 360インスタンスを削除して組織をリセットします。Data 360 インスタンスを保持するには、120 日の猶予期間内にライセンスを更新します。有効なライセンスを使用して新しい Data 360 インスタンスを設定するには、Data 360 クリーンアッププロセスを使用して、関連付けられたデータ、メタデータ、設定を削除します。クリーンアップ プロセスを使用して、Data Cloud Oneコンパニオンとして組織を既存のData 360インスタンスに接続することもできます。

組織をクリーンアップしたら、次の 2 つの方法でリセットできます。

  • 有効なライセンスが必要な新しい Data 360 インスタンスを設定します。
  • 組織を Data Cloud One コンパニオンとして既存の Data 360 インスタンスに接続します。

既存の Data 360 インスタンスの更新

Data 360 ライセンスの有効期限が切れると、120 日の猶予期間に入ります。この期間中は、Data 360 サービスは無効化されますが、データは残ります。このシナリオでは、ライセンスを更新して現在の組織を復元できます。すべての Data 360 データを削除することもできます。

Data 360 のクリーンアップとリセット

猶予期間が終了し、ライセンスの有効期限が切れると、Data 360テナントは削除されますが、そのデータ、メタデータ、設定は残ります。新しい Data 360 インスタンスを作成するか、Data Cloud One コンパニオン組織として使用するには、そのデータを削除します。

これらは、組織から関連付けられたすべての Data 360 データを削除する別のシナリオです。

  • 同じリージョンまたは異なるリージョンで新しい Data 360 ホーム組織インスタンスを作成するには、
  • 既存のホーム組織を Data Cloud One コンパニオン組織に変換する。
  • 組織を Data Cloud One コンパニオン組織として既存の Data 360 ホーム組織に接続する。
  • 既存の Sandbox を接続された Sandbox のコンパニオン組織として設定する。

Data 360 のデータとメタデータのクリーンアップは、その Data 360 インスタンスに直接接続されている組織にのみ影響します。Sandbox で Data 360 ホーム組織をクリーンアップしてコンパニオン組織に変換する場合、親は別の Data 360 インスタンスに接続されているため、このアクションは親本番組織の Data 360 の機能、データ、メタデータ、パッケージには影響しません。

Data 360 データ削除プロセス

組織の管理者は、Data Cloud の [設定] の画面の指示に従って、すべての Data 360 データとメタデータが組織から完全に削除されるようにします。組織の有効期限が切れているか、組織に Data 360 メタデータが含まれており、Data 360 テナントがない場合、[ライフサイクル管理] 画面が表示されます。

期限切れのライセンスと、切断された Data 360 テナントと残りのメタデータがある組織の通知が表示されている Data Cloud の設定画面。

120 日の猶予期間内の期限切れライセンスの通知が表示されている Data Cloud の設定画面。

外部連動関係の削除

外部連動関係とは、Data 360 の外部でその機能に依存する設定または機能です。これには、Data 360トリガー フロー、コピー フィールド強化、Agentforceデータ ライブラリが含まれます。データ削除プロセスを続行するには、まず外部連動関係を削除します。各連動関係に移動して削除します。すべての外部連動関係を削除したら、引き続き未管理パッケージの連動関係と残りのデータの削除を承認します。

削除するフロー定義が表示されている [外部連動関係を削除] 画面。

未管理パッケージ連動関係の確認

未管理パッケージには、Data 360 オブジェクトと Data 360 以外のオブジェクトの両方を含めることができます。Salesforce で Data 360 オブジェクトを削除できるようにしても、未管理パッケージと、未管理パッケージに含まれる Data 360 以外のオブジェクトには影響しません。オブジェクトの使用方法を確認して、ビジネスニーズとプロセスに影響がないことを確認します。Data 360 管理パッケージは、Data 360 クリーンアップの一環として自動的に削除されます。

削除を承認する前に確認する Data 360 オブジェクトのリストが表示されている [パッケージ化された連動関係を確認] 画面。

データ削除

未管理パッケージのリストを確認したら、Data 360 の承認を得て残りのデータを削除します。すべての Data 360 データの削除は永続的なプロセスです。完了すると、以下にアクセスできなくなります。

  • Data 360 の機能、データ、メタデータ、データスペース、パッケージ
  • 接続されたコンパニオン組織の Data 360 機能

Salesforceでは、顧客データのバックアップやData 360インスタンスのリストアを行うことはできません。

承認すると、データの削除が開始されます。このプロセスには最大 50 分かかります。完了すると、Data Cloud の [設定] 画面が更新されます。

進行中の Data 360 クリーンアッププロセスが表示されている画面。

DevOps データキットを使用した Data 360 Governance マージバック

Sandbox を使用してデータガバナンス戦略を開発および検証し、マージバックで本番にリリースします。マージバックは、検証済みのメタデータを Sandbox 組織からリンクされた本番組織または別のリンクされた Sandbox 組織に戻すプロセスです。DevOps データキットは、ガバナンスメタデータを環境間で移動し、一貫したセキュリティ体制を維持します。

ガバナンスのデータキットタイプ

Data 360 には 2 つのデータキットタイプがあります。

  • DevOps データキット: リンクされた環境間の Sandbox から本番へのマージバックに使用されます。
  • 標準データキット: 組織全体のパッケージ化とリリースに使用されます。

マージバックのガバナンスメタデータ

マージバックは、データへのアクセスを制御するメタデータを移動します。

  • タグの割り当てにより、データモデルオブジェクト (DMO)、データレークオブジェクト (DLO)、計算済みインサイトオブジェクト (CIO) が識別および分類されます。
  • ガバナンスポリシーは、データへのアクセスを制御して保護します。
    • レコードレベルセキュリティ (RLS) は、レコードへのアクセスを制御します。DevOps データキットを使用して、ガバナンスコンポーネントを対象組織にリリースします。
    • 項目レベルセキュリティ (FLS) は、項目へのアクセスを制御します。
    • オブジェクトレベルセキュリティ (OLS) は、オブジェクトへのアクセスを制御します。
    • 構造化マスキングポリシーは、機密データを保護します。

マージバックのデータガバナンスのサポート

マージバックでは、次のデータガバナンス機能がサポートされています。

  • Data 360 オブジェクトへの標準タグの割り当て
  • 次のような標準タグに基づくガバナンスポリシーの適用
    • RLS ポリシー
    • FLS ポリシー
    • オブジェクトレベルの構造化マスキングポリシー

ガバナンスの DevOps データキットリリースモデル

DevOps データキットは、ガバナンスコンポーネントをグループ化して対象組織にリリースします。

  • ガバナンスポリシーと Data 360 オブジェクト間のリレーションを取得します。
  • 変更セットなどの組み込みのリリースメカニズムを使用します。

ガバナンスマージバックリリースに関する考慮事項

移行を計画するときは、次の具体的な動作を考慮してください。

  • サポートされるリリースパス: マージバックでは、Sandbox から本番環境、Sandbox から Sandbox など、関連する Data 360 環境間のリリースのみがサポートされます。
  • 削除はサポートされていません: Sandbox でポリシーまたはタグの割り当てを削除しても、対象組織からは削除されません。
  • CLI はサポートされていません。Salesforce CLI はガバナンス ポリシーのリリースをサポートしていません。
  • システム定義タグ: Salesforce は、システム定義タグの分類を提供および管理します。ガバナンスポリシーはこれらのタグに依存するため、これらのタグの名前変更、削除、再割り当てを行わないでください。プラットフォームの更新時に変更が元に戻されます。
  • トランザクションの制限: 大規模なリリースではバッチ処理が必要になる場合があります。
  • DevOps データキットを使用した Data 360 ガバナンスポリシーのリリース
    DevOps データキットを使用して、Sandbox から本番組織にデータガバナンスポリシーを移行します。この方法では、一貫性が維持され、手動エラーが減少します。
  • Data 360 Governance マージバックリリースのトラブルシューティング
    データガバナンスメタデータを移行するときに、リリースエラーが発生することがあります。さまざまな環境でリリースを正常に完了できるように、一般的なマージバックの問題の症状と解決策を確認します。

複雑な計算済みインサイト (CI) SQL データを論理ステップに整理して、強力なワークフローを作成します。Metrics on Metrics を使用すると、複数のシナリオで評価指標を改善して再利用できます。

  COUNT(ssot_EmailEngagement_dlm.ssot_Id_c) as email_open_count_c,
 ssot_Individual_dlm.ssot_Id_c as customer_id_c
FROM 
ssot_Individual_dlm
JOIN ssot_EmailEngagement_dlm
   on (ssot_Individual_dlm.ssot_Id_c = ssot_EmailEngagement_dlm.ssot_IndividualId_c)
WHERE ssot_EmailEngagement_dlm.ssot_EngagementChannelActionId_c = ‘Open’
GROUP BY customer_id__c

Data Cloud では、Salesforce CRM 組織で設定された通貨と静的為替レートを使用して、データ変換、計算済みインサイト、セグメンテーション、レポート、その他のプロセスに適用します。

単一通貨組織では、Data Cloud はこのプロセスを使用して Salesforce 組織から通貨データを同期します。

  • Data Cloud への Salesforce CRM コネクタが自動的に設定されると、Salesforce は通貨データの静的レートデータレークオブジェクト (DLO) を Static_Currency_Rates_<CRM orgID> という名前で作成し、静的レート変換データモデルオブジェクト (DMO) を Static_Currency_Rates_<CRM orgID> という名前で作成します。CRM コネクタに別名がある場合、名前の<CRM orgID>は別名に置き換えられます。

  • Salesforce システム管理者が Salesforce CRM 組織で通貨を追加または換算レートを更新すると、Data Cloud でこれらの変更が同期され、静的換算 DMO が数分で更新されます。

正規化および非正規化されたデータ

データは複数のソースから取得され、正規化または非正規化できます。Data 360 標準データモデルは正規化されているため、受信データをデータモデルにマッピングする前に正規化する必要があります。すべてのソースシステムが正規化してエクスポートするオプションを備えていたり、データを正規化したりするわけではないため、項目レベルでデータを評価し、ソースデータを変換して標準データモデルにマッピングする方法を確立します。

正規化されたデータは、冗長や不整合を軽減するために、リレーションが確立された複数のテーブルに分割されます。

非正規化されたデータは、すばやく取得できるように 1 つのテーブルにまとめられます。行にはリレーショナルデータが列属性として記載されます。一般にこの形式をスプレッドシートビューといい、Marketing Cloud Engagement データエクステンションも同じ形式です。

Data 360 の親子階層

親子タグ階層では、タグが論理的な複数レベルの構造で整理され、より広範な汎用タグ (親) がより具体的な詳細なタグ (子) にリンクされます。

この階層型アプローチでは、タグ付けが標準化され、明確さが向上し、関連するデータ要素全体に拡張性の高いポリシーを適用できます。次に例を示します。

  • 個人情報 (親タグ)
    • メールアドレス (子タグ
    • 電話番号 (子タグ)
    • 自宅住所 (子タグ)

タグ階層は、組織全体でデータの表示ラベルを標準化し、継承をサポートします。親タグをオブジェクトに割り当てると、関連する子タグを分類の一部として含めることができるため、大規模なポリシーの適用が容易になります。オブジェクトに子タグを割り当てると、対応する親タグが自動的に適用され、親タグにリンクされているポリシーが適用されます。ただし、親タグのみを割り当てると、子タグに関連付けられたポリシーは、明示的にオブジェクトに追加しない限り適用されません。

Data Cloud でのコンテンツの処理

Data Cloud の生成 AI ベースのツールを使用して、AI、自動化、分析ワークフローで使用する非構造化データを処理します。

Data Cloud で使用できる処理機能は次のとおりです。

  • プロンプトベースのカスタマイズ: カスタムプロンプトまたはエージェント提供のプロンプトを使用して、非構造化データを分割し、さらに処理して検索インデックスを最適化します。また、プロンプトを使用して、検索インデックス全体を再構築することなく、不正な形式のテーブルなどの抽出の問題を修正することもできます。
  • インデックス付けされた音声および動画の文字起こし: Data Cloud でコンテンツを自動的に文字起こししてインデックス付けすることで、音声および動画データからの音声の検索と取得を簡素化します。その後、テキスト起こしを照会して、テキストに基づいて関連情報や類似項目を取得できます。
  • 強化されたインデックス: AI を使用して、インデックス付けされたコンテンツからメタデータを抽出します。抽出されたメタデータには、キーワード、エンティティ、トピックの概要、コンテンツによって回答された質問、コンテンツの概要が含まれます。
  • コンテンツの解析と前処理: プロンプトを使用してドキュメント構造を識別し、非構造化ドキュメントのテキストとメタデータを構造化表現または半構造化表現に変換します (解析)。または、画像やテーブルから抽出されたデータでソースのコンテキストとリレーションが維持されるようにします (前処理)。
  • ドキュメントスキーマの抽出: 非構造化コンテンツから構造化出力を生成します。プロンプトを使用するか、Data Cloud Connect API を使用してプログラムで項目とテーブルを抽出、分類、生成するスキーマを定義します。

Data Cloud でのコンテンツ処理の主な使用事例を次に示します。

  • RAG(取得拡張生成):非構造化データを処理し、コンテンツをData Cloud検索インデックスに追加することで、AIが正確なコンテキストを取得し、その応答を特定のデータにグラウンディングして、より正確で関連性の高い出力を得ることができます。これは RAG の基盤です。
  • Service Cloudの場合:コンテンツ処理は、Knowledge記事、メール、サポート チケット、チャット ログから重要な情報とトピックを抽出します。この構造化された出力により、AI エージェントは正確な回答を見つけ、より適切な回答を作成し、顧客の問題に積極的に解決策を提案できます。
  • Sales Cloud の場合: メール、通話トランスクリプト、メモなどの非構造化セールスデータを処理することで、主要な詳細とセンチメントを抽出します。AI エージェントはこの情報を使用して、関連性の高いミーティングブリーフィングや概要を生成し、エンゲージメントを高めるパーソナライズされたコンテンツのおすすめを促進します。
  • 自動化フローの場合: コンテンツ処理では、ケースなどのレコードをその説明に基づいて比較するために必要なセマンティックな理解が提供されます。これにより、AI エージェントは重複を自動的に特定し、類似する過去の例を見つけて解決時間を短縮し、受信したレコードを正確に分類できます。
  • 分析の場合: 非構造化データを処理することで、Tableau での詳細な分析に備えることができます。テーマを抽出し、コンテンツ内のトピックを分類することで、従来の分析方法では見逃されがちなパターンを明らかにし、インサイトを得ることができます。

Data Cloud で次のツールを使用してコンテンツを処理します。

  • 非構造化データ
    Data 360の非構造化データを使用して、Agentforceエージェント、生成AI、分析、自動化の使用事例をビジネス固有のデータでグラウンディングし、ユーザーと顧客に深いインサイトを提供します。
  • チャンクデータ
    Data 360 の検索インデックスにデータを追加するには、最初にチャンクする必要があります。チャンクを使用すると、データが意味のあるチャンクに分割され、Data 360 はそのチャンクを機械で読み取り可能なベクトル埋め込みに変換します。
  • Data 360 のインテリジェントなコンテキスト
    インテリジェント コンテキストは、プロンプトを操作して非構造化データを処理し、特定のビジネス コンテキストに合わせて調整された検索インデックス構成を作成するAI機能を備えたワークスペースです。
  • ドキュメント AI
    Data 360のドキュメントAIは、LLM(大規模言語モデル)を使用して、請求書、履歴書、ラボ レポート、購入注文などの非構造化ドキュメントから構造化データを抽出します。
  • コンテンツの解析と前処理
    Data 360のコンテンツ解析および前処理方法を使用して、チャンク用の非構造化データを準備します。解析と前処理では、ヘッダー、段落、テーブルなどのドキュメント構造を識別し、無関係のコンテンツを削除して、チャンクやインデックス付けのためにテキストを準備します。
  • Data 360 検索インデックス
    Data 360では、検索インデックスを使用して、構造化コンテンツと非構造化コンテンツを検索に最適化された方法で管理します。検索インデックス設定を作成して、コンテンツをチャンク化してベクトル化します。チャンクでは、元のコンテンツ (文章や段落など) の文章を反映して、テキストを小さな単位に分割します。ベクトル化では、チャンクがテキストの数値表現に変換され、セマンティックの類似性が取得されます。
  • コンテンツとKnowledgeのハーモナイゼーション
    ハーモナイゼーションを使用して、取り込まれたKnowledge記事と非構造化コンテンツを Data 360 に変換します。 ハーモナイゼーションにより、コンテンツが正規化および強化され、コンテンツビューアーでの一貫した表示に適した 1 つのハーモナイゼーションスキーマが作成されます。ビューアには、Data 360 のデータエクスプローラーまたは Service Cloud の Enterprise Knowledge コンポーネントからアクセスします。

関連属性の関連用語

次の例で使用されている用語を確認してください。

  • 有効化: セグメントを有効化プラットフォーム (対象) に公開するプロセス。
  • 有効化メンバーシップ: 有効化に含める、さまざまなデータモデルオブジェクト (DMO) の項目のグルーピング。
  • 有効化対象: 有効化プロセス中にセグメントのデータが送信される場所 (広告プラットフォームや Marketing Cloud Engagement など)。
  • 属性: データモデルオブジェクト (DMO) などのオブジェクトにある情報またはデータ。Data 360 には、セグメンテーションの 2 種類の属性があります。
    • 直接属性 (1:1) — この属性では、DMO のユーザーに 1 つの値のみが設定されます (便番号や名など)。 
    • 関連属性 (1:N) — この属性には、特定のユーザーの属性ごとに複数の値を設定できます (購入、メールイベントなど)。 
  • データエクステンション: Marketing Cloud Engagement にデータを保存するテーブル。データエクステンションは、データストレージや顧客へのメッセージ送信に使用できます。 
  • データモデルオブジェクト (DMO): データストリーム、インサイト、他のソースから作成された属性で構成されるデータのグルーピング。 
  • 絞り込み: 結果を減らすまたは絞り込むプロセス。絞り込みは、セグメンテーションと有効化内で実行できます。 
  • ガイド付きテンプレート言語 (GTL): 指定されたデータソースからデータを取得し、コンテンツの表示に使用されるテンプレート内に適用する Marketing Cloud Engagement プログラム言語。GTL は Mustache.js または Handlebars.js のテンプレートをサポートし、Engagement 内のデータエクステンションに保存されている JSON データにアクセスできます。 
  • JavaScript オブジェクト表記 (JSON): JSON は、JavaScript 構文に基づいて構造化されたデータを表すための標準のテキストベースの形式です。Data 360 から Engagement に関連属性データを送信するために使用されます。 
  • 演算子: 検索条件が相互にどのように関連するかを指定するために使用される方向を表す語句。検索条件内の演算子はセンテンス内の動詞に似ています (「次の文字列と一致する」、「次の値より大きい」、「次の文字列を含む」など)。 
  • セグメント: 一連の特性を共有するデータグルーピング (誕生日が同じ顧客など)。
  • ショートメッセージサービス (SMS): 最大文字数が 160 文字のテキストのみのメッセージ。

Data 360 のリアルタイム機能

Data 360 のリアルタイム機能を使用すると、すべてのプラットフォームで一貫性のある同期された顧客データを有効にできます。リアルタイム機能では、複数の顧客とのやりとりで 1 秒未満のデータ処理が提供されます。

たとえば、E コマース小売業者は、ユーザーの行動に基づいてリアルタイムでパーソナライズされたおすすめや Next Best Action を提供することで、ショッピングエクスペリエンスを向上させることができます。プラットフォームは、顧客の過去の購入と現在の閲覧活動に基づいて上位のオファーを対象にできます。

リアルタイム機能を使用するには、まずリアルタイムデータグラフを作成する必要があります。

データグラフ データグラフは、データモデルオブジェクト (DMO) の正規化されたテーブルデータを結合し、新しいデータのマテリアライズドビューに変換します。
リアルタイム ID 解決 デバイス間で顧客プロファイルをマージし、不明なユーザーと既知のユーザーをリアルタイムで統合します。
リアルタイムデータアクション 事前設定されたルールに基づいてアラートまたはイベントを送信し、リアルタイムで応答を取得するリアルタイムデータアクションを作成します。
リアルタイムセグメント オンデマンドでミリ秒で完了するリアルタイムセグメントを作成します。
インサイトによるデータの拡張 リアルタイムインサイトを使用して、Web サイトのより複雑なパーソナライズロジックを作成します。
Flow Builder でのリアルタイムの予測 有効化されたモデルからの出力を使用して自動化を作成し、意思決定に役立てます。
Salesforce クラウド全体でパーソナライズされた環境を提供します。

CRM 接続のトラブルシューティング

Salesforce CRM データストリームの作成に問題がある場合は、次の一般的な問題を確認してください。

更新履歴オブジェクト権限エラー

データストリームの [更新履歴] タブには、発生したエラーを含む、各データストリームの最新の 50 件の更新操作の概要が表示されます。このタブを使用して、エラーをトラブルシューティングします。

失敗した状況の理由:

  • Data 360 の設定時にオブジェクトおよび項目権限を有効にしないと、データストリームの更新に失敗する可能性があります。Salesforce CRM にアクセスするためのオブジェクトと項目の権限を有効にします。
  • カスタム項目を削除してから再度追加した場合、スケジュール済みまたは手動のデータストリーム更新でレコードまたは状況を更新できないことがあります。項目を再度追加する場合は、その項目に対する「参照アクセス権」を再度有効にします。
  • DLO から DMO へのマッピングの制限を超えた場合、データストリームの更新が完了できないことがあります。DMO リレーションの制限を確認してください。
  • 増分更新またはフル更新が実行されているときに、フル更新をトリガーする数式項目を追加すると、最初の更新がキャンセルされます。更新は失敗として表示されます。
  • 次のエラーメッセージが表示された場合、権限設定が不適切であることを示します。
    The following fields are missing in the CRM object
or you do not have permissions to read from these fields.

    「Enable Object and Field Permissions for CRM Connections (CRM 接続のオブジェクトおよび項目権限の有効化)」を参照してください。

ストリーミングエラー

ストリーミングを実行するには、必要な権限を設定し、検証チェックを満たしていることを確認します。

次のシナリオでは、ストリーミングは使用できず、処理モードはバッチに変更されます。

  • オブジェクト、オブジェクト種別、または派生項目ではストリーミングはサポートされません。「CRM データストリームのオブジェクトサポート」を参照してください。
  • 一括で取り込まれた標準項目またはカスタム項目をデータストリームに含めます。
  • Salesforce CRM コネクタの絞り込みパイロットに参加し、ストリームの検索条件を定義している。
  • ユーザーを追加して、「Data 360 Salesforce コネクタ」権限セットを変更しました。組織に接続すると、「Data 360 Salesforce コネクタ」権限セットが作成され、Data 360 オブジェクトおよび項目へのアクセスが許可されます。この権限セットは、プラットフォームインテグレーションユーザーを対象としています。この権限セットに他のユーザーを追加すると、Data 360 でストリーミングに必要な権限を割り当てることができなくなります。
  • リリース状況が [リリース済み] ではなく [開発中] のデータストリームにカスタムエンティティを含めます。データストリームは、リリース状況が [リリース済み] になった後にのみ作成することをお勧めします。状況が [開発中] のエンティティをデータストリームに含めると、データストリームは自動的にストリーミングモードに切り替わりますが、更新は受信されません。データの取り込みを有効にするには、オブジェクトマネージャーでエンティティの状況を [リリース済み] に変更します。エンティティの開発中に更新されたレコードは適切に同期されない可能性があるため、データが不正確になる可能性があります。この不正確さを回避するには、データストリームを削除してから再作成します。

「CRM コネクタストリーミング」および「Salesforce CRM データストリームの作成」を参照してください。

SurveyQuestionResponse オブジェクトの取り込みに失敗しました

SurveyQuestionResponseオブジェクトへのアクセスは、SurveyResponseオブジェクトによって制御されます。アンケートオブジェクトのデータを確実に取り込むには、SurveyResponseオブジェクトに「すべてのレコードの参照」または「すべてのレコードの編集」権限を付与します。

「Enable Object and Field Permissions for CRM Connections (CRM 接続のオブジェクトおよび項目権限の有効化)」を参照してください。

OPERATION＿TOO＿LARGE エラー

次のエラーメッセージが表示された場合、いずれかの項目が CRM コネクタがアクセス権を持たないエンティティを参照していることを示します。これを解決するには、すべての関連オブジェクトに「参照」および「すべて表示」アクセス権が付与されていることを確認します。

"[{"message":"exceeded 100000 distinct
          ids","errorCode":"OPERATION_TOO_LARGE"}]"

権限が付与された 100,000 件を超えるレコードがエンティティにある場合、すべてのレコードを問題なく取得できます。ただし、エンティティが別のエンティティに関連付けられている場合、行を返す前に関連レコードにも権限が付与されているかどうかが確認されます。元のクエリが関連エンティティごとに展開され、この追加クエリによって操作が過負荷になる可能性があります。パフォーマンスを維持するために、ハードリミットが設定されます。

Data 360 データストリームの場合、このクエリは常にプラットフォームインテグレーションユーザーとして実行されます。システム内の他のユーザーとしてログインすると、失敗ではない結果が表示される場合がありますが、問題は権限に関連するものであり、続行するには Data 360 Salesforce コネクタ権限セットで対処する必要があります。

「Enable Object and Field Permissions for CRM Connections」を参照してください。

抽出時にデータストリームが失敗する

取り込みを開始する前に、抽出が成功する必要があります。データストリーム履歴パネルには、抽出エラーと取り込みエラーがある場合、または取り込みが成功した場合が表示されます。

「抽出のデータ更新プロセス」を参照してください。

Salesforce CRM と Data 360 のデータの不一致

Salesforce CRM を Data 360 と統合する場合、アクセス権限が正しく設定されていないとデータの不一致が発生する可能性があります。

「Addressing Salesforce CRM to Data 360 Data Mismatches」を参照してください。

Salesforce CRM ソースのレコード数が Data 360 データストリームの数と一致しない場合、または最近変更されたレコードが Data 360 に反映されない場合は、ストリーミングモードデータストリームの定期的なフル更新間隔を設定している可能性があります。ストリーミングモードでは、定期的なフル更新間隔を設定できません。データを同期するには、[データストリーム] タブでそのストリームの [今すぐ更新] ボタンをクリックして、オンデマンドでフル更新を設定できます。

「Configure Periodic Full Refresh Interval and CRM Connector Streaming」を参照してください。

Salesforce CRM 接続が切断されない

Salesforce CRM 接続を削除できない場合は、システムデータストリームを確認してください。PF （ProvisionedFeature）、TET （TenantEntitlementTransaction）、TUTM （TenantUsageTypeMultiplier） などの Digital Wallet システム データ ストリームなど、他のアプリケーションで使用する Salesforce システム データ ストリームは編集または削除できません。それらを含む接続を削除することもできません。接続を削除するには、Salesforce カスタマーサポートにお問い合わせください。

「Salesforce CRM 接続の切断」を参照してください。

Salesforce CRM ソースのレコード数が Data 360 データストリームの数と一致しない場合、または最近変更されたレコードが Data 360 に反映されない場合は、ストリーミングモードデータストリームの定期的なフル更新間隔を設定している可能性があります。ストリーミングモードでは、定期的なフル更新間隔を設定できません。データを同期するには、[データストリーム] タブでそのストリームの [今すぐ更新] ボタンをクリックして、オンデマンドでフル更新を設定できます。

「Configure Periodic Full Refresh Interval and CRM Connector Streaming」を参照してください。

一般的な考慮事項

Salesforce CRM データストリームを作成するときは、次の考慮事項に留意してください。

  • Salesforce CRM コネクタでは、Salesforce CRM からの Big Object の取り込みはサポートされません。
  • Salesforce CRM コネクタストリーミングプロセスでは、Bring Your Own Key (BYOK) を使用したデータ暗号化はサポートされていません。
  • Salesforce は、1 年以上経過した ToDo と行動をアーカイブします。データを取り込む場合、これらのアーカイブ済みレコードは含まれません。
  • 項目およびオブジェクト権限がないため、Salesforce CRM データストリームが失敗する可能性があります。エラーをダウンロードするには、データストリームの [更新履歴] タブに移動し、エラーをクリックして、エラーメッセージファイルをダウンロードします。
  • 項目と値の数は更新時間に影響し、タイムアウトが発生する可能性があります。
  • 関連オブジェクトを Data 360 に取り込まない場合でも、関連オブジェクトに対する「参照」権限を有効にします。 関連オブジェクトを参照する取り込みオブジェクトには、関連オブジェクト情報にアクセスしてデータストリームを作成する権限が必要です。
  • 接続された CRM から項目を削除するには、まず Data 360 からその項目を無効にして、データストリームの取り込みエラーを回避します。「データストリーム項目の無効化に関する考慮事項」を参照してください。
  • DMO はカスタムオブジェクトの場合にのみ削除できます。  「Manage Data 360 Objects and Field Mappings (Data 360 オブジェクトと項目の対応付けの管理)」を参照してください。

データエクステンションデータストリームの更新

更新モードが更新/挿入のデータエクステンションデータストリームでは、増分更新またはフルデータ更新のいずれかを実行できます。

データ更新を実行するには、[データストリーム] タブに移動してデータストリームを選択し、[今すぐ更新] をクリックします。2 つの更新モードがあります。

増分更新: 増分更新ごとに、新しい情報が挿入され、古い情報が保持されます。増分更新は、新しい数式項目が作成され、データストリームに入力する必要があるシナリオで使用できます。

フル更新: フル更新ごとに、数式や削除を含め、Marketing Cloud Engagement のすべてのデータが同期されます。現在 Data 360 DLO に存在し、Marketing Cloud で使用できないレコードは、DLO から完全に削除されます。Marketing Cloud から削除されたデータが Data 360 DLO に確実に反映されるようにするには、フル更新を使用できます。

メモ

特定のデータエクステンションでは、24 時間に 1 回のみデータ更新を実行できます。更新の進行中にデータストリームを変更していないことを確認します。データ更新プロセス中、更新が完了するまで新しいデータは取り込まれません。

処理の制限の要求

Data 360 で処理制限要求を送信する方法について説明します。

Data 360 で、個人プロファイルと統合個人プロファイルの処理の制限要求を送信できます。同意 API を使用して、すべての要求を送信する必要があります。

処理の制限要求では、指定した個人プロファイルおよび統合個人プロファイルの 24 時間以内のすべてのデータ処理が制限されます。

メモ 要求の処理には最大 90 日かかります。その間、削除申請された一部のレコードは引き続き表示されます。

個人および統合個人以外のオブジェクトに基づいてセグメントを作成する場合、消費者の権利と期待を慎重に検討してください。

処理の制限要求は、すべての接続済みシステムおよび Salesforce クラウドで送信する必要があります。

ルート鍵ライフサイクル

プラットフォームの暗号化のルート鍵の状況では、データの暗号化と復号化の各鍵の使用を定義します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
アドオンライセンスで使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。Salesforce ShieldまたはShield Platform Encryption、Platform Encryption for Data Cloudを購入する必要があります。また、オプションの外部鍵管理を使用するには、Platform Encryption for Consumption ライセンスを購入する必要があります。

各状況は、暗号化ライフサイクル内の鍵の可用性と機能に影響します。

  • 有効: ルート鍵は Salesforce Platform Encryption UI に表示され、新しいデータを暗号化します。すべての書き込みオプションでは、このキーを使用して、これ以降の新しいデータを取得します。一度に有効化できるルート鍵は 1 つのみです。
  • Archived (アーカイブ済み): 新しいルート鍵が生成されると、以前の鍵がアーカイブされます。アーカイブ済み鍵は、既存のデータの復号化には引き続き使用できますが、新しいデータの暗号化には使用されません。
  • 無効: ルート鍵は、Salesforce Platform Encryption UI で手動で無効化すると無効になります。この状態では、ルート鍵は暗号化または復号化に使用できなくなります。この鍵で暗号化されたデータは、Salesforce UI で鍵が再有効化されるまでアクセスできません。
  • 使用不可 (EKM のみ): この状況は、外部鍵管理 (EKM) を使用している場合にのみ適用されます。ルート鍵は、AWS KMS などの外部鍵マネージャーで無効化されると使用できなくなります。この状況は、[無効] と同様に動作します。Data 360 プロセスが失敗し始める前に、顧客にメールで通知されます。
  • キャンセル: 鍵は明示的に破棄されます。これにより、顧客は別の鍵を生成できます。

無効な鍵または使用できない鍵を再有効化するには、「Reactivate an EKM Key (EKM 鍵の再有効化)」を参照してください。Data 360 でデータが失われないように、48 時間以内に鍵を再有効化します。

BYOK の主要な状態

  • 設定の完了待機中: Salesforce が AWS KMS で空の鍵ラッパーを作成し、ラップされた鍵素材とトークンのアップロードを待機しています。
  • Active (有効): キーが有効で、その識別子が UI に表示されます。
  • Archived (アーカイブ済み): 新しいルート鍵を生成した後に鍵がアーカイブされます。アーカイブ済み鍵では、既存のデータを復号化できますが、新しいデータを暗号化することはできません。鍵がアーカイブ済み状態になると、復号化は引き続き機能します。
  • 無効: Salesforce UI でキーを無効にすると、キーは無効になります。無効な鍵では、データを暗号化または復号化できません。この鍵で暗号化されたデータは、再有効化するまでアクセスできなくなります。
  • キャンセル: 鍵を明示的にキャンセルしました。キャンセル後、新しい鍵を生成できます。

  • Salesforce ヘルプ: EKM キーの再有効化
  • Salesforce ヘルプ: EKM キーへの接続の確認

ユーザーの設定とデータバンドルのインストール

データの取り込みとマッピング

スターターデータバンドルを使用して、Service Cloud のデータストリームを作成します。次に、ID 解決の必須項目を対応付けます。

ID 解決を使用したサービスデータの統合

個人データモデルオブジェクトに基づく一致ルールと調整ルールを含む ID 解決ルールセットを使用して、複数のデータソースを統合プロファイルにリンクします。次に、プロファイルエクスプローラーでプロファイルを表示します。

  • ユーザーの設定と Service Cloud データバンドルのインストール
    Data Cloud ユーザーを設定し、適切な権限セットを追加して、Service Cloud データバンドルをインストールします。これらの手順はすべて Data Cloud の [設定] 内で実行します。
  • Service Cloud からのデータの取り込みとマッピング
    Data Cloud では、多くのデータソースに接続できます。Salesforce コネクタの多くには、データストリームの設定、データレイクオブジェクトの作成、データモデルへの自動マッピングをすばやく行うのに役立つスターターデータバンドルがあります。ただし、ID 解決を使用するには、カスタムオブジェクトと一部の必須項目を Customer 360 データモデルにマッピングする必要があります。
  • ID 解決を使用したサービスデータの統合
    ID 解決ルールセットを使用して、複数のデータソースを統合プロファイルにリンクします。ルールセットには、取引先データモデルオブジェクトまたは個人データモデルオブジェクトに基づく一致ルールと調整ルールが含まれます。
  • 計算済みインサイトを使用したサービスデータの分析
    Data Cloud 内のデータの複数ディメンション評価指標を計算します。評価指標はプロファイル、セグメント、母集団レベルで作成できます。たとえば、チャネルレベルでパフォーマンスを評価したり、商品評価指標を使用して購入行動や閲覧行動を把握したりできます。
  • Data Cloud を使用した次のステップ
    このガイドで詳しく説明している使用事例では、Data Cloudを使用して統合Customer 360を強化する方法を垣間見ることができます。より多くのデータ ソースを接続して統合すればするほど、統合、インサイト、分析がより役立ちます。

必要なエディション

  2. 共有する Data 360 オブジェクトを特定し、Data 360 でデータ共有を作成します。 詳細は、「データ共有の作成」を参照してください。
  3. 別の Data 360 組織との接続を確立するには、Data 360 でデータ共有対象を作成します。詳細は、「Data 360 組織と接続するためのデータ共有対象の作成」を参照してください。
  4. 他の Data 360 組織で Data 360 オブジェクトにアクセスできるようにするには、データ共有をデータ共有対象にリンクします。詳細は、「データ共有とデータ共有対象のリンクまたはリンク解除」を参照してください。ソース組織で共有される Data 360 オブジェクトの種別に関係なく、対象 Data Cloud 組織では DLO としてモデル化されます。

  • Data 360 組織に接続するためのデータ共有対象の作成

Data 360 での簡単な開始

シンプルスタートで Data 360 の初期設定を合理化します。メタデータを同期し、Salesforce CRM データの標準化されたデータ構造を数分で作成することで、手動のバンドル設定と項目の対応付けをスキップします。最初はメタデータのみが同期されるため、クレジットは関連データストリームとダウンストリームプロセスを有効化した後にのみ消費します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

主なメリット

  • 自動設定: プラットフォームは、接続されたホームの Salesforce 組織のメタデータに基づいて CRM データストリームとデータレイクオブジェクト (DLO) を自動的に作成します。
  • Review before ingestion: Simple Start では、無効な状態でデータストリームが作成されるため、取り込みを開始する前にスキーマを確認できます。

メタデータ同期

Data 360 では、メタデータ同期を実行するためにホーム組織への接続が必要です。この同期プロセスにより、必要なデータストリーム、データレークオブジェクト (DLO)、データモデルオブジェクト (DMO) のマッピングが自動的に作成されます。Data 360 ではメタデータがスキーマに直接追加されるため、標準バンドルやパッケージをインストールする必要がありません。

Simple Start では、次のアクションが自動的に実行されます。

  • 無効な状況のデータストリームを作成して、すぐにクレジットが消費されないようにします。
  • Salesforce 標準オブジェクトの標準対応付けを生成します。『Data 360 DMO Mapping Guide』を参照してください。
  • 制限事項と主要な考慮事項
    シンプルスタートを使用する前に、次の制限事項を確認してください。
  • Data 360 のデータストリーム同期の有効化
    Simple Start で Salesforce CRM メタデータを Data 360 に追加したら、データストリームを有効化してデータを取り込むことができます。Simple Start は、無効な状態のストリームを取り込み、クレジット消費をすぐに回避します。
  • 単純な開始エラーのトラブルシューティング
    最も一般的な Simple Start エラーを解決するためのヒントを紹介します。
