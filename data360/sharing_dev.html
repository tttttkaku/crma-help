Data 360 でのデータ共有要求の受け入れ

Data 360 組織間でデータを共有するには、対象組織がソース組織からの共有要求を受け入れる必要があります。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
ソース組織からの共有要求を受け入れる システム管理者プロファイル
  1. Data Cloud で、[通知] をクリックします。
  2. ソース組織からデータ共有を受信するには、データ共有を受け入れます。

    デフォルトでは、対象組織はデフォルトのデータスペースにデータ共有を保存します。データ共有のオブジェクトを目的のデータスペースに移動するには、「データレークオブジェクトを使用したデータスペースへのデータの追加」を参照してください。

    データ共有の受信を停止するには、取得元組織の管理者に、組織をデータ共有対象から削除するように依頼してください。

プラットフォームイベントトリガーフローの作成

ビジネスプロセスを自動化し、データレコードが変更されたときにフローを内部で起動します。フローは、Salesforce または外部システム内でデータを収集し、アクションを実行します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
  1. [設定] の [クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  2. [新規フロー] をクリックします。
  3. [Start From Scratch (ゼロから開始)] を選択し、[Platform Event - Triggered Flow (プラットフォームイベント - トリガーフロー)] をクリックして、[作成] をクリックします。
    イベントメッセージを受信したときに、プラットフォームイベントトリガーフローが実行されます。
  4. プラットフォームイベントの場合、[データオブジェクトデータ変更イベント] を選択します。
  5. [要素を追加] をクリックし、[レコードを作成] をクリックします。
  6. レコードの表示ラベル、API 参照名、説明を入力します。
  7. [レコードフィールド値の設定方法] で、[手動] を選択します。
  8. [オブジェクト] ドロップダウンから、カスタムオブジェクトを選択します。
  9. カスタムオブジェクトの項目値を設定します。
  10. 重複レコードを回避するには、[一致するレコードを確認] を有効にします。
  11. 条件を追加して、一致するレコードが見つかった場合の処理を指定します。
  12. [保存] をクリックします。
  13. フローの表示ラベルとフローの API 参照名を入力します。
  14. [保存] をクリックします。

フローを作成した後に有効化するには、［Activate］ をクリックします。

データ共有のコピー

既存のデータ共有をコピーしてデータ共有を作成できます。コピー時にデータオブジェクトを追加または削除できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
データ共有をコピーする

権限セット

  • Data Cloud アーキテクト
  1. Data 360 で、[データ共有] タブに移動します。
  2. コピーするデータ共有をクリックします。
  3. データ共有オブジェクトのホームページで、[コピー] をクリックします。
  4. [表示ラベル] に、データ共有の表示名と説明 (省略可能) を入力します。
    API 参照名は表示ラベルと一致するように自動入力されますが、変更することもできます。
  5. 関連するデータスペースを選択します。複数のデータスペースがプロビジョニングされている場合は、[デフォルト] を選択します。
  6. [次へ] をクリックします。
  7. データオブジェクトを選択または選択解除します。
  8. [保存] をクリックします。

コード拡張

カスタム Python コードを Data 360 に取り込み、コードエクステンションを使用して Data 360 のネイティブ機能を拡張します。ネイティブの Data 360 機能がビジネス要件を満たしていない場合は、サポートされる Data 360 機能にカスタムロジックをリリースします。

コードエクステンションでは、実行方法が異なる 2 種類のカスタムコードがサポートされます。

  • スクリプトは、一括処理データ変換 (オンデマンドまたはスケジュールに従って実行するジョブ) として実行されます。
  • 関数は検索インデックス パイプラインの一部として実行され、検索および AI 取得のためにコンテンツがどのようにチャンクされるかを制御します。

コード拡張ワークフローには、開発者と「Data Cloud アーキテクト」権限セットを持つユーザーとのコラボレーションが含まれます。開発者は、Salesforce CLIとCode ExtensionプラグインおよびData Custom Code Python SDKをツールチェーンとして使用し、カスタムPythonコードをローカルで作成および検証します。次に、リリースの準備をします。

Data 360 ユーザーは、コードの実行、監視、Sandbox から本番への移行を管理します。Sandboxで、カスタム コード パッケージをアップロードし、関連するData 360機能(スクリプトの一括処理データ変換や関数の検索インデックス)でカスタム コードを使用してから実行します。リリース状況、実行履歴、ログを監視します。検証後、カスタムコードと連動関係をデータキットにパッケージ化します。本番環境では、データキットをインストールし、カスタムコードを実行して本番データを処理し、実行を監視します。

  • コード拡張の請求に関する考慮事項
    Data 360 でコードエクステンションを使用すると、Data Cloud ライセンスで Data 360 を運用している組織の請求に使用するクレジットの消費に影響します。

関連項目:

  • Salesforce 開発者ヘルプ: Data 360 でのコード拡張

Data 360 でのカスタムオブジェクトの作成

データアクションをフローと統合するカスタムオブジェクトを作成します。カスタムオブジェクトには、会社または業種に固有の情報が保存されます。ビジネスに関連するすべての情報を 1 か所で追跡できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
  1. [設定] をクリックします。
  2. [オブジェクトマネージャー] タブで、[作成] をクリックし、[カスタムオブジェクト] をクリックします。
  3. 表示ラベルと複数形の表示ラベルを入力します。
    [オブジェクト名] 項目と [レコード名] 項目は自動入力されます。
  4. [このカスタムオブジェクトの保存後、新規カスタムタブウィザードを起動する] を選択します。
  5. [保存] をクリックします。
  6. [新規カスタムオブジェクトタブ] ページで、[タブスタイル] をクリックし、アイコンの外観を選択します。
  7. [次へ] をクリックし、再度 [次へ] をクリックします。
  8. [保存] をクリックします。
  • Data Cloud でのカスタムオブジェクトのカスタム項目の作成
    カスタムオブジェクトにカスタム項目を追加します。カスタム項目に固有のビジネスデータを保持できます。カスタム項目の作成時にその表示場所を設定し、項目レベルのセキュリティを制御できます (省略可能)。

Data Cloud でのレコードトリガーフローの作成

Data 360 アクションのプラットフォームイベントを公開するレコードトリガーフローを作成します。公開されたプラットフォームイベントを使用し、一時停止した自動起動フローを再開できます。レコードトリガーフローを使用して、別のレコードの更新、通知の送信、プロセスの開始、データの一貫性の維持を行うことができます。レコードトリガーフローは、レコードの作成時または更新時にのみ実行されます。レコード変更プロセスよりも 10 倍速くレコードを更新できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
レコードトリガーフローを作成する

権限セット

  • Data Cloud アーキテクト
  1. Data 360 で、[] をクリックし、[設定] を選択します。
  2. [クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  3. [新規フロー] をクリックします。
  4. [Start From Scratch]を選択し、[Record-Triggered Flow]をクリックして、[Create]をクリックします。
  5. [オブジェクト] ドロップダウンから、カスタムイベントを公開する Data Cloud アクションを選択します。
  6. [レコードが作成または更新された] を選択します。
  7. [条件の要件] ドロップダウンから [すべての条件に一致 (AND)] を選択します。
  8. 条件を定義します。必要に応じて、他の条件を追加できます。
  9. [条件の要件に一致するようにレコードを更新したときのみ] と [アクションと関連レコード] を選択します。
  10. [完了] をクリックします。
  11. キャンバスで、[要素を追加] をクリックし、[レコードを作成] をクリックします。
  12. 表示ラベル名を入力し、[個別のリソースおよびリテラル値を使用] を選択します。
  13. [オブジェクト] ドロップダウンから、公開するカスタムプラットフォームイベントを選択します。
  14. 項目を選択し、カスタムプラットフォームイベントの値を設定します。
  15. [完了] をクリックして [保存] をクリックします。
  16. フローの表示ラベルを入力し、[保存] をクリックして [有効化] をクリックします。
    レコードトリガーフローは、レコードが更新され、条件が満たされるたびにトリガーされます。

フローがトリガーされると、カスタムプラットフォームイベントが公開されます。公開されたプラットフォームイベントを使用して、一時停止した自動起動フローを再開します。

Data 360 組織に接続するためのデータ共有対象の作成

Data 360 でデータ共有対象を作成し、別の Data 360 組織との接続を確立します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
  1. Data Cloud の [データ共有対象] タブで、[新規] をクリックします。
  2. [接続種別]で[Salesforce Data Cloud]を選択し、[次へ]をクリックします。
  3. 次の詳細情報を入力します。
    • Data Share Target Name (データ共有対象名) - データ共有対象の表示名。文字制限はありません。
    • API 参照名 - この項目は対象名と一致するように自動入力されますが、別の名前を使用できます。
    • 対象組織の [私のドメイン] の URL - 対象組織の [私のドメイン] の URL を入力します。対象組織の [設定] の [組織設定] -> [私のドメイン] で URL を見つけます。例: https://mycompany.my.salesforce.com または https://mycompany.my.site.com
    • 対象組織 ID - 対象組織 ID を入力します。
  4. 組織 ID、オフコアテナント ID、および [私のドメイン] の URL をコピーして対象組織の管理者と共有し、組織とデータを共有できるようにします。
  5. [保存] をクリックします。

    要求を受け入れるための通知が対象の Data 360 組織に送信されます。通知が表示されない場合は、ソース組織のデータ共有対象に移動し、[再送信招待] をクリックします。

Google BigQuery に接続するためのデータ共有対象の作成

Google BigQueryアカウントとの接続を確立するには、Data 360でデータ共有対象を作成します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
  1. Data 360 の [データ共有対象] タブで、[新規] をクリックします。
  2. [接続種別]で[Google BigQuery]を選択し、[次へ]をクリックします。
  3. 次の詳細情報を入力します。
    1. [表示ラベル] に、データ共有対象の表示名を入力します (最大 20 文字)。
      API 参照名は表示ラベル名と一致するように自動的に入力されますが、別の名前を使用することもできます。
    2. [Google Cloud プリンシパル] に、検証済みのユーザーまたはグループのメールアドレスを入力します。
      各プリンシパルには識別子があり、通常はメールアドレスです。プリンシパルは有効な Google ワークスペースドメインである必要があります。
    3. 認証せずに接続するには、[認証をスキップ] チェックボックスをオンにするか、[種別] でユーザーまたはグループを選択します。

      サービスアカウントベースの認証の場合、サービスアカウントをグループに追加し、グループベースの認証を使用します。

    メモ 同じ Google Cloud プリンシパルと種別で複数のデータ共有対象を作成することはできません。
  4. [保存] をクリックします。
    Google サインオンページが表示されます。
  5. Google Cloud プリンシパルを認証します。
    Data 360にリダイレクトされ、データ共有対象が有効になります。

データ共有の作成

外部システムと共有するためにデータ共有に含める Data 360 オブジェクトを選択します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
データスペースを作成する

権限セット

  • Data Cloud アーキテクト

データポリシーと規制に準拠するために、データ共有には同意情報を個人に提供する IndividualGDPRState__dll オブジェクトが含まれます。個人 ID を使用して、データ共有対象で個人の同意データをリンクし、尊重できます。

  1. Data 360 の [データ共有] タブで、[新規] をクリックします。
  2. 次の詳細を入力し、[次へ] をクリックします。
    • 表示ラベル - データ共有の表示名。Google BigQuery の場合、文字数制限は 20 文字ですが、[説明] で詳細を追加できます。Snowflake の場合、文字数制限はありません。
    • Name (名前) - Data 360 でのデータ共有の API 参照名。この名前は、表示ラベル名と一致するように自動的に入力されます。異なる名前を使用することもできます。
    • データスペース - データスペースは、Data 360 でプロファイルの統合、インサイト、マーケティングを行うためのデータを整理する論理パーティションです。組織でプロビジョニングされている他のデータスペースがない場合は、データスペースに「デフォルト」を選択します。
    • Salesforce Data Cloud 以外の受け入れ組織のシステム管理者または特権ユーザーが、データ共有のデータモデルオブジェクト (DMO) に対応付けられたデータレイクオブジェクト (DLO) のすべてのレコードを表示および照会することに同意します。
    • 説明 - データ共有に関する関連する詳細。
  3. データ共有に含める Data 360 オブジェクトを選択します。
    外部データレイクオブジェクト (DLO) または外部 DLO にマッピングされたデータモデルオブジェクト (DMO) を外部データレイクと共有することはできません。
  4. [保存] をクリックします。

Data 360 の管理パッケージの作成とインストール

管理パッケージを使用して、Data 360 アプリケーションを作成し、AgentExchange で配布します。パッケージはメタデータを入力するコンテナであり、アプリケーションを構成する関連機能、カスタマイズ、スキーマのセットを保持します。パッケージにはさまざまなメタデータコンポーネントを含めることができ、1 つのコンポーネント、アプリケーション、またはライブラリをパッケージ化できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限セット
パッケージを作成する 「AgentExchange パッケージの作成」権限
パッケージをアップロードする 「AgentExchange パッケージのアップロード」権限
データキットを作成する 「Data Cloud アーキテクト」権限セット

管理パッケージを使用して、AgentExchange で Data 360 ソリューションを配布したり、複数の顧客組織で設定を共有したりできます。管理パッケージは、バージョン管理、アップグレード管理、知的財産保護を提供するため、Data 360 機能を製品化したい ISV やパートナーに最適です。

パッケージを作成するには Salesforce Developer Edition 組織、パッケージをインストールするには登録者組織が必要です。Salesforce では、第二世代管理パッケージ (管理 2GP) と第一世代管理パッケージ (管理 1GP) を提供しています。このトピックでは、管理 1GP パッケージの作成方法について説明します。管理 2GP パッケージでの Data 360 のパッケージ化についての詳細は、「Workflow for Data Cloud Second-Generation Managed Packages (Data Cloud 第二世代管理パッケージのワークフロー)」を参照してください。

  1. Data 360 で、[設定] に移動し、パッケージマネージャーを使用してパッケージを作成します。「第一世代管理パッケージの作成およびアップロード」を参照してください。
  2. 管理パッケージの一意の名前空間を定義します。
  3. 必要なコンポーネントを追加するには、[コンポーネント] で [追加] をクリックします。
  4. [コンポーネントの種類] で、 [データパッケージキット定義] を選択します。
  5. 標準データキットを作成するか、既存のデータキットを選択して、[パッケージに追加] をクリックします。
    データキットメタデータに関連するすべてのエンティティが自動的にパッケージに追加されます。
  6. パッケージバージョンの詳細を追加します。
  7. パッケージインストール URL を生成するには、[アップロード] をクリックします。
  8. インストール URL をコピーして対象組織に移動し、パッケージのインストール URL を使用してパッケージをインストールします。

    パッケージをインストールするには、管理者ユーザー権限が必要です。

パッケージを対象組織にインストールしたら、データキットを使用して Data 360 でデータストリームや他のコンポーネントをリリースできるようになります。

データフロー

Data 360 のデータの機能を Data 360 内外で活用します。データはData 360に取り込んで保存することも、メタデータを介して接続してストレージなしで照会することもできます。

データソース

データソースは、さまざまな方法で Data 360 に取り込まれるか、Data 360 に接続されます。取り込まれるデータソースを次に示します。

  • Salesforce コネクタ
  • コネクタサービス
  • コネクタとインテグレーション

これらのソースからのデータは、ストリーミングデータまたはバッチデータとして取り込まれます。ほぼリアルタイムの Web エンゲージメントデータは、ストリーミングデータの一例です。

データターゲットとデータ共有

Data 360 でデータを操作、ハーモナイズ、またはセグメント化したら、データを SFTP (2) などの対象 (1) に送信したり、Snowflake などのインテグレーションと共有したりできます。

ターゲットは次の目的で使用されます。

  • Marketing Cloud Engagement、Amazon S3、SFTP、Google Cloud Storage (GCS)、Microsoft Azure Blob Storage に対してセグメントを有効化する。
  • Meta などの広告プラットフォームに対してセグメントを有効化する
  • データアクションを使用して Sales Cloud または Service Cloud で ToDo を実行する
  • Tableau や CRM Analytics などのツール内でデータを分析する

特定の機能はターゲットに関連付けられています。有効化対象はオーディエンスセグメントを共有するために作成され、データアクションターゲットはデータに基づいてアクションを開始するために作成されます。

データ共有では、Salesforce 以外の外部プラットフォーム (Snowflake など) と Data 360 データを共有できます。

データキット

Data 360 のデータキットを使用して、パッケージの作成とインストールを合理化します。データキットでパッケージ化可能なすべての Data 360 機能を管理できます。データストリームバンドルを作成できます。データモデルのカスタマイズとリレーションも含まれています。

データキットを作成してアップロードする方法については、次の動画をご覧ください。

データキットは、パッケージ化可能なすべてのData 360メタデータをラップするため、Data 360で完全なソリューションを作成してリリースできます。

データキットの種別

Data 360 には、メタデータとプロセス定義をリリースするための 2 種類のデータキットが用意されています。適切なデータキットの選択は、使用事例とリリース環境によって異なります。ガイドラインを使用して、ニーズに最適なオプションを決定します。

  • 標準データキット: 標準データキットを作成して、Data 360 の機能とソリューションをパッケージ化し、顧客と共有します。デフォルトのデータスペースからデータキットを作成し、対象組織の任意のデータスペースにリリースできます。標準データキットを使用すると、顧客のニーズに合わせて調整された Data 360 ソリューションを配布できます。
  • DevOps データキット: DevOps データキットを使用して、Sandbox 組織から本番組織に Data 360 メタデータを移行しますが、Data 360 メタデータをパッケージ化しません。DevOps データキットは任意のデータスペースから作成できますが、対象組織の同じデータスペースにリリースします。DevOps データキットを使用すると、メタデータ管理プロセスの一貫性を維持できます。

管理パッケージのデータキットのワークフロー

  • データキットにパッケージ化するデータストリームを作成します。
  • Data 360 からデータキットを作成します。
  • データキットパッケージのデータストリームとデータストリーム定義を選択して追加します。
  • データキットコンポーネントのリリース順序を定義します。
  • Data 360 でデータキットパッケージをアップロードします。
  • パッケージマネージャーでデータキットを公開します。
  • データキットを使用してパッケージマネージャーでパッケージを作成します。
  • 作成したパッケージを Salesforce 組織にインストールします。

パッケージ化されたデータストリームをリリースすると、パッケージに含まれるリレーションが自動的にマッピングされます。

Data 360 のパッケージ化とデータキット

  • Data 360 のデータキットに関する考慮事項
    データキットの作成、公開、リリースに関する次の考慮事項を確認して、実装を正常に行い、一般的な問題を回避します。
  • 標準データキットの作成と公開
    メタデータとリレーションを標準データキットにラップすることで、Data 360 オブジェクトのパッケージ作成とインストール環境を合理化します。管理パッケージをサポートする Developer Edition 組織を使用して、標準データ キットを作成および公開します。DevOps データキットを使用して、組織間でメタデータを移行します。
  • パッケージへのデータキットの追加
    Data 360 ソース組織でデータキットを作成して公開したら、データキットをパッケージに追加し、Salesforce 組織のパッケージマネージャーを使用してアップロードします。
  • Data 360 でのデータキットコンポーネントのリリース
    標準データキットを作成して管理パッケージにインストールしたら、パッケージマネージャーを使用して、データストリーム、一括処理データ変換、計算済みインサイト、データグラフなどのパッケージコンポーネントをData 360から対象組織にリリースできます。
  • Data 360 でのデータキットの更新
    Salesforce CRM と B2C Commerce のデータストリーム、データモデル、マッピング、リレーションを変更するときに、既存のデータキットを更新できます。また、Salesforce 組織のパッケージマネージャーを使用して、Data 360 から更新されたデータキットを取得してリリースすることもできます。
  • Data 360 でのリリース済みデータキットのアンインストール
    未使用のデータキットや古くなったデータキットを削除すると、組織の整理と効率が維持されます。管理パッケージからリリースされたデータキットをアンインストールするには、最初にすべてのデータスペースからリリースされたデータキットコンポーネントとその連動関係をリリース解除します。次に、管理パッケージをアンインストールします。

データ共有

データ共有により、外部システムで Data 360 のデータに簡単にアクセスできます。データレークオブジェクト (DLO)、データモデルオブジェクト (DMO)、計算済みインサイトオブジェクト (CIO) へのアクセス権を使用して、強力な分析インサイトと機械学習モデルを作成できます。データ共有を使用したゼロ コピー データ共有により、データを外部システムに読み込むことなくData 360オブジェクトを共有でき、ほぼリアルタイムでデータにアクセスできます。

データ共有で Data 360 オブジェクトを結合し、データ共有対象を介して外部システムに接続します。データ共有対象は、外部システムとの接続を設定します。

重要
  • データ共有では、Data 360 によって適用されるデータガバナンスポリシーが適用されません。 データ共有対象でこれらのポリシーを適用します。
  • Salesforce Data 360 以外の受け入れ側組織のシステム管理者または特権ユーザーは、データ共有のデータモデルオブジェクト (DMO) に対応付けられたデータレイクオブジェクト (DLO) のすべてのレコードを表示および照会できます。これは、外部システムで定義されたセキュリティ構造によって異なります。
  • データ共有の管理
    Data 360 でのデータ共有の作成、編集、コピー、削除。データ共有をデータ共有対象にリンクまたはリンク解除することもできます。
  • Snowflake とのデータの共有
    Data 360 データにアクセスするには、Data 360 オブジェクトを含むデータ共有を作成します。Data 360 オブジェクトには Snowflake アカウントのビューとしてアクセスできます。Snowflake でデータが使用可能な場合、ハーモナイズされた統合データを照会できます。
  • Google BigQuery とのデータの共有
    データ共有を作成することで、Google BigQueryのデータセットとしてData 360オブジェクトにアクセスできます。ゼロコピーインテグレーションでは、データを Google BigQuery にコピーすることなく、直接共有および照会できます。Google BigQuery でデータにアクセスできる場合、Data 360 のハーモナイズされた統合データを操作できます。データの共有には、次の概要手順が含まれます。
  • Amazon SageMaker とのデータの共有
    Amazon SageMaker には、Amazon Redshift、Athena、または Elastic MapReduce (EMR) を使用してクエリを実行するための AWS Glue データカタログビュー、AWS Lake Formation、AWS エンジンが含まれています。データ共有を使用して、データレイクオブジェクト、データモデルオブジェクト、計算済みインサイトオブジェクトなどの Data 360 オブジェクトを Amazon Redshift アカウントと共有します。
  • Databricks とのデータの共有
    データ共有を使用して、Data 360オブジェクトをDatabricksアカウントと共有します。データ共有をDatabricksデータ共有ターゲットにリンクして、DatabricksアカウントでData 360オブジェクトを利用できるようにします。
  • クエリ統合を使用した Databricks とのデータの共有
    Zero Copy Data Federation を使用して統合クエリを実行することで、データを Data 360 から Databricks に移行することなく、Data 360 データを Databricks と安全に共有できます。Databricks の Unity Catalog を使用して、ワークスペース内のデータレイク、データモデル、計算済みインサイトの各オブジェクトにアクセスできます。
  • Data 360 組織間でのデータの共有
    データ共有を使用して、異なるリージョンのData 360インスタンス間、または他のData 360組織とData 360オブジェクト(DLO)、データモデルオブジェクト(DMO)、計算済みインサイトオブジェクト(CIO)を共有します。Data 360 組織間で外部高速化 DLO を共有することもできます。
  • データ共有エラーのトラブルシューティング
    よくあるデータ共有およびデータ共有ターゲットのエラーを解決するためのヒントを紹介します。

データ共有の管理

Data 360 でのデータ共有の作成、編集、コピー、削除。データ共有をデータ共有対象にリンクまたはリンク解除することもできます。

  • データ共有の作成
    外部システムと共有するためにデータ共有に含める Data 360 オブジェクトを選択します。
  • データ共有のコピー
    既存のデータ共有をコピーしてデータ共有を作成できます。コピー時にデータオブジェクトを追加または削除できます。
  • データ共有の編集
    データ共有のすべてのデータレークオブジェクト、データモデルオブジェクト、計算済みインサイトオブジェクトを追加または削除できます。Data 360オブジェクトをデータ共有に追加すると、リンクされたデータ共有ターゲットからアクセスできます。同様に、Data 360オブジェクトを削除すると、リンクされたデータ共有対象からはアクセスできなくなります。
  • データ共有とデータ共有対象のリンクまたはリンク解除
    データ共有をデータ共有対象にリンクして、外部システムで使用できるようにします。データ共有をデータ共有対象からリンク解除することもできます。
  • データ共有の削除
    Data Cloud では、不要になったリンクされていないデータ共有を削除できます。
  • データ共有対象の削除
    リンクが解除され、不要になったデータ共有対象は削除できます。

Data 360 でのフローの自動化

自動化を定義し、取り込み(Salesforce CRMおよびAmazon S3データストリーム)、セグメンテーションと有効化、ID解決、計算済みインサイトを含むData 360プロセスをチェーニングします。スケジュールした時刻にプロセスが実行されるのを待つのではなく、必要に応じてを順番に実行できます。たとえば、プロセスをチェーニングして、データの取り込みが完了した場合に計算済みインサイトを更新したり、セグメンテーションを実行したりできます。自動化を定義して、フローの実行を監視したり、進行状況を確認したりできます。Flow Builder を使用して、Data 360 フローを作成します。Flow Builder では、自動化されたトリガー、再利用可能なビルディングブロック、事前作成済みソリューションを使用して、複雑なエンタープライズ規模のオートメーションを作成できます。

必要なエディション

自動起動フローを作成する

権限セット

  • Data Cloud アーキテクト

Data 360 プロセスの完全なワークフローを定義する自動起動フローを作成します。

  1. Data 360 で、[設定] を選択します。
  2. [クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  3. [新規フロー] をクリックします。
  4. [Start From Scratch (ゼロから開始)] を選択し、[Autolaunch Flow (No Trigger) (自動起動フロー (トリガーなし))] をクリックして、[作成] をクリックします。
    ボタンがクリックされると、自動起動フローが実行されます。ユーザー操作は不要です。
  5. キャンバスで、[要素を追加] をクリックし、[アクション] をクリックします。
  6. 左ペインで、[Data 360] をクリックし、Data 360 アクションを選択します。
  7. 表示ラベルと入力値を入力して、[完了] をクリックします。
  8. キャンバスで、[要素を追加] をクリックし、[条件を待機] をクリックします。
    一時停止したフローは、1 つ以上の再開イベントを待機します。指定したプラットフォームイベントが公開されたときに、フローを再開します。
  9. 表示ラベルと待機設定の表示ラベルを入力します。
  10. [イベントを再開] タブに移動して、[プラットフォームイベントメッセージを受信したとき] を選択します。
  11. [プラットフォームイベント] ドロップダウンからイベントを選択し、[完了] をクリックします。

Data 360 でプラットフォームイベントを公開するレコードトリガーフローを作成します。

  • Data Cloud でのレコードトリガーフローの作成
    Data 360 アクションのプラットフォームイベントを公開するレコードトリガーフローを作成します。公開されたプラットフォームイベントを使用し、一時停止した自動起動フローを再開できます。レコードトリガーフローを使用して、別のレコードの更新、通知の送信、プロセスの開始、データの一貫性の維持を行うことができます。レコードトリガーフローは、レコードの作成時または更新時にのみ実行されます。レコード変更プロセスよりも 10 倍速くレコードを更新できます。
  • 自動化に関するガイドラインと制限
    Data 360 アクションを使用して、要件に基づいて自動化を設定できます。自動化を計画するときは、ガイドラインと制限を確認してください。スロットリング (調整) では、指定した期間内にトリガーされる API 要求の最大数が制限されます。

Sandbox でのデータキットの作成

  1. Sandbox 組織で、[Data Cloud 設定] を選択します。
  2. [Developer Tools (開発者ツール)] で、[Data Kits (データキット)] をクリックします。
  3. [Data Kits (データキット)] タブで、[新規] をクリックします。
  4. [Standard Data Kit type (標準データキットタイプ)] を選択します。
  5. データキット名と開発者名を入力します。
  6. ソースデータスペースがデフォルトのデータスペースに設定されていることを確認します。
  7. [関連] タブの [データキットコンポーネント] セクションで、[追加] をクリックします。
  8. データモデルオブジェクト (DMO)、計算済みインサイト、セグメントなど、含めるメタデータ型を選択します。
    「Data 360 Extensibility Readiness Matrix」を参照してください。
  9. 特定のコンポーネントを選択し、[データキットに追加] をクリックします。
  10. [保存] をクリックします。

ローカルデータスペースへのデータキットのリリース

  1. [データキットの詳細] ページで、標準データキットを選択します。
  2. [Local Data Kit Deploy] をクリックします。
  3. 対象データスペースと組織 ID の詳細を選択し、コネクタ種別を選択します。
  4. [リリース] をクリックします。
  5. [Local Deployment History (ローカルリリース履歴)] タブで、リリースログを確認してリリースの状況を確認します。
