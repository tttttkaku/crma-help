コミュニケーション制限設定の作成

コミュニケーションの上限設定を作成し、Data Cloud のデータスペースに関連付けます。すべての設定済みパラメーターまたは特定のサブセットに適用できます。各組織は、有効なコミュニケーション制限設定を 1 つに制限されています。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要な権限セット
コミュニケーション制限を使用する

次のいずれかの権限セット:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  1. Data Cloud で、[Communication Capping (コミュニケーション制限)] をクリックし、[新規] をクリックします。
  2. 制限ルールを作成するパラメータを選択します。
  3. コミュニケーション制限インスタンスが適用されている 1 つ以上のデータスペースを選択します。
  4. コミュニケーションの上限の名前と説明 (省略可能) を入力します。
  5. [保存] をクリックします。

通信制限設定を作成したら、制限ルールを作成します。

Data 360 では、既存のセグメントをコピーして、既存のセグメントと同じ検索条件とカスタマイズを入力できます。

必要なエディション

使用可能なエディション: Data Cloud でサポートされているすべてのエディション。「Data 360 Edition の可用性」を参照してください。
アドオンライセンスで使用可能な機能: セグメンテーションと有効化
必要な権限セット
セグメントを削除する

次の権限セットのいずれか:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト
  1. [Segments] に移動します。
  2. コピーするセグメントを選択します。
  3. [コピー] をクリックします。
  4. 新しいセグメントに名前を付け、公開スケジュールを選択します。
  5. [保存] をクリックします。

Data 360 でのデータアクションの作成

データアクションを使用して、Salesforce Platform、Webhook、Marketing Cloud Engagement などの対象にアラートまたはイベントを送信します。チャネル、商品、取引先、サービス、個人など、さまざまなレベルでほぼリアルタイムのイベントとインサイトに焦点を当てるデータアクションを作成します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限セット
データアクションを作成する

次のいずれかの権限セット:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト
  1. Data 360 で、[データアクション] タブに移動し、[新規] をクリックします。
  2. データアクションを最初から作成するか、データキットおよびパッケージからインポートするかを選択します。
  3. データアクションターゲットを選択し、[次へ] をクリックします。選択したデータアクション対象がドラフト状態の場合、データアクションもドラフト状況に移行します。
  4. データスペースを選択します。
  5. データモデルオブジェクト (DMO) または計算済みインサイトオブジェクト (CIO) 種別を選択します。Marketing Cloud Engagement 対象の場合、選択したオブジェクト種別は Marketing Cloud データストリームから取得されている必要があります。
    Marketing Cloud Engagement インスタンス (EID) が複数あり、登録者キーが CIO から取得されている場合、CIO の作成時に項目 API 参照名「DataSource__c」を式に追加します。
  6. 主オブジェクトを選択し、[次へ] をクリックします。
    変更イベントが特定されたときにデータアクションをトリガーするには、Amazon Redshift、Google BigQuery、Snowflake、Databricks などの外部データレイクオブジェクト (DLO) にリンクされている DMO、CIO、または加速 DMO を選択します。高速化 DMO を選択した場合は、高速化プロセスが完了していることを確認します。DMO を選択する場合は、DLO の主キー項目が DMO にマッピングされていることを確認します。
  7. データアクションを強化するには、関連オブジェクトを選択します。
    外部 DLO に対応付けられた DMO またはデータグラフを関連オブジェクトとして使用できます。オブジェクトがデータアクションで関連オブジェクトとして表示されるには、主オブジェクトが関連オブジェクトと多対一または一対一のリレーションを持っている必要があります。
    1. 関連オブジェクトとして DMO を使用する場合:
      • データアクションに最大 10 個の関連属性を追加します。
      • 登録者キー値を選択します。登録者キーは、エンゲージメントのメッセージ受信者の一意の識別子です。コミュニケーションに使用するメールアドレスを決定します。
      • 通貨データ型を選択するときに cdp_sys_record_currency 項目を含めます。このフィールドがない場合、Data 360 は通貨属性を数値として扱います。
    2. 関連オブジェクトとしてデータグラフを使用する場合:
      • データを使用できる関連オブジェクトのルックアップパスを選択します。ペイロード全体がデータアクション対象に送信されるため、属性を個別に選択することはできません。
      • Marketing Cloud Engagement データアクションターゲットの場合、データアクションペイロードを保存するようにデータエクステンションを設定します。「データアクションペイロードを保存するためのデータエクステンションの設定」を参照してください。を参照してください。
  8. イベントルールとアクションルールを選択します。
    イベントルールを使用して、レコードの変更に基づいてアクションを作成します。アクションルールはデータアクションを評価し、OR 条件と AND 条件を含めることができます。
  9. さらに条件を追加するには、[条件を追加] をクリックします。
  10. オブジェクト、属性、演算子を選択し、データアクションをトリガーできる値を入力します。
  11. マルチ通貨オプションが有効になっている組織では、データアクション対象の通貨を選択します。出力データには、選択した通貨が反映されます。
  12. [レコードが更新されました] イベントルールのデータアクションをいつトリガーするかを選択します。
    [更新済みレコードのデータアクションをトリガー] オプションは、[レコードが更新されました] イベントルールを選択した場合にのみ使用できます。アクションルール条件で [増加した] や [変更済み] などの変更演算子を使用している場合、[更新済みレコードのデータアクションをトリガー] 設定は変更できません。この設定を変更するには、条件からすべての変更演算子を削除します。
  13. [次へ] をクリックします。
  14. アクション名を入力します。
    [アクション API 参照名] 項目は自動的に入力されます。
  15. [保存して公開] をクリックします。データアクションはレコードホームページに表示できます。
    データアクションの作成後、設定が完了するまで約 15 分かかります。その後、ほぼリアルタイムでイベントが送信され、主オブジェクトの行が追加、更新、削除された場合にのみトリガーされます。それ以降の変更では、イベントがすぐにトリガーされます。
    Flow Builder を使用して項目をコピー強化フローや Data Cloud トリガーフローなど、インテグレーションユーザーが作成したデータアクションは参照のみです。これらのデータアクションは削除、無効化、または編集できません。
  • イベントルール条件とアクションルール条件でサポートされる演算子
    データアクションをトリガーするには、レコードアクションに基づいて 1 つ以上のイベントルールを選択し、OR 条件と AND 条件を使用してデータを公開するタイミングを指定できます。
  • データアクションのイベント活動の監視
    Event Activity ダッシュボードで、識別、処理、公開、失敗したイベントなど、データアクションの主要な総計値を追跡します。データアクションパイプライン内をほぼリアルタイムで移動するデータをより詳細に把握できます。これにより、イベントの量とデータ配信に関する透明性が確保されます。

Web フックデータアクションターゲットの作成

データアクションイベントを Web フックターゲットに送信し、Salesforce によって生成された秘密鍵を使用してメッセージの整合性を保護します。Web フックは、要求駆動型ではなくイベント駆動型の API です。秘密鍵は、Salesforce から送信されたペイロード要求を検証します。Web フックは、DataObjectDataChgEvent 形式のイベントを含む HTTP ペイロードを転送します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限セット
Web フックデータアクションターゲットを作成する

次のいずれかの権限セット:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト
  1. Data 360 で、[データアクション対象] タブに移動し、[新規] をクリックします。
  2. アクションターゲット名を入力します。
    [アクションターゲットの API 参照名] 項目は自動入力されます。
  3. [Web フック] を選択します。
  4. Web フック イベントを公開する URL を入力し、[保存] をクリックします。
  5. 秘密鍵を生成します。
    有効または無効なデータアクションターゲットの秘密鍵のみを生成できます。
  6. 秘密鍵をコピーして、Web フックシステムを設定します。 
    {
   "creationDateTime": "DateTime: Payload creation time at the service calling webhook",
   "count": "Number: Count of events in this payload",
   "schemas": [ { "schemaId": "Action Name of schema", schema : "Schema of Event Payload in Action" } ], //Array of Schemas for different event payload
   "events": [Array of Data Object Data Change Event],
}

動的セグメントの作成

データモデルオブジェクト (DMO) に基づいて動的セグメントを作成し、セグメントメンバーシップ DMO にデータを保持せずにセグメントクエリを実行します。実行時に動的値を受け入れるプレースホルダーを使用して属性検索条件を定義します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要な権限セット
セグメントを作成する

次の権限セットのいずれか:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト
メモ Data 360 ユーザーインターフェースまたは接続 API を使用して動的セグメントをスケジュールまたは公開することはできません。ブロードキャスト フローを介した API コールを使用して動的セグメントを実行し、実行時に動的値を指定します。
  1. Data 360 で、[セグメント] をクリックします。
  2. [新規] をクリックします。
  3. [ビジュアルビルダーを使用] を選択します。
  4. [動的セグメント]を選択し、[次へ]をクリックします。
  5. セグメントの詳細を入力します。
    1. データスペースを選択します。
    2. [セグメント対象] で、セグメントの構築の基盤となる DMO を選択します。
    3. セグメントに識別しやすい一意の名前を付けます。
    4. セグメントのルックバック期間を入力します。
      デフォルトは 90 日です。ルックバックは最大で 2 年まで設定できます。  ドロップダウンから [Days (日数)] を選択した場合、最大 360 日の期間を設定できます。
      セグメントを作成するときのルックバックオプションは、組織の最大許容期間 (最大 2 年など) に基づきます。この設定では、選択可能な初期のデータ範囲を定義します。セグメントでは、コンテナで特定の条件を適用できます。これは、デフォルトのルックバック期間とは異なる場合があります。そのため、セグメントレベルのルックバックが 90 日に設定され、コンテナ条件が 60 日に設定されている場合、コンテナ条件が優先され、データは 60 日間のみ取り込まれます。
  6. [保存] をクリックします。

Marketing Cloud Engagement データアクションターゲットの作成

Data 360から転送された行動またはトランザクションイベントデータに基づいて、顧客に自動メールとジャーニーを送信します。データモデルオブジェクト (DMO) と計算済みインサイトから顧客へのメールとジャーニーをトリガーします。たとえば、顧客が商品を購入し、Web サイトで「インストールマニュアル」を検索するとします。ハウツー動画またはインストール手順が記載されたメールを顧客に送信するイベントをトリガーします。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限セット
Marketing Cloud Engagement データアクションターゲットを作成する

次のいずれかの権限セット:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー

データアクションターゲットを作成する前に、次の前提条件を完了します。

  • Data 360 で Marketing Cloud Engagement 接続を設定します。
  • Email Studio から Content Builder でメールテンプレートを作成し、すべての必須項目を入力します。テンプレートベース、テキストのみ、または HTML メール種別を使用します。
  • Marketing Cloud Engagement の登録者リストには、登録者キー、名と姓、メールアドレスが含まれます。
  • Marketing Cloud に移動しなくても、Data 360 で 1 回のクリックでデータアクションの Journey Builder API イベントのデータエクステンションを作成できます。詳細は、「Create a Data Extension in Data 360」を参照してください。または、Marketing Cloud でデータエクステンションを手動で作成するには、まず API イベントの Journey Builder で目的のジャーニーを作成します。
    メモ ジャーニーエントリソースが API イベント種別であり、そのデータエクステンションのすべての項目が null 可能である必要があります。主オブジェクトと関連オブジェクトのデータエクステンション属性名は、Data 360 で選択したデータモデルオブジェクトのオブジェクト API 参照名で始まり、アンダースコア、属性 API 参照名が続く必要があります。たとえば、Shopping_Events__dlm_deviceId__c や Individual_deviceId__c などです。主オブジェクトと関連オブジェクトに同じデータエクステンションを使用できます。これらのオブジェクトを使用する複数のデータアクションがある場合、データエクステンションを再利用します。
  • ビジネスユニットを選択し、Data 360 でマッピングを有効にします。
  1. Data 360 で、[データアクション対象] タブに移動し、[新規] をクリックします。
  2. データアクション対象名を入力します。
    [API 参照名] 項目は自動的に入力されます。
  3. データアクションターゲット種別として、[Marketing Cloud] を選択します。
  4. 登録者が存在するビジネスユニットを選択します。

    複数のMarketing Cloud Engagementインスタンス(EID)がData 360組織に接続されている場合、ビジネスユニットリストには、関連付けられているすべてのビジネスユニットが表示されます。

  5. 対象として [メール] または [Journey Builder API イベント] を選択します。
  6. データアクション条件を満たしたときに送信するメールテンプレートまたは Journey Builder API イベントを選択します。

    [Journey Builder API Event (Journey Builder API イベント)] を選択しない場合、データアクションターゲットおよび対応するデータアクションの状況はドラフトに設定されます。有効に設定するには、Data 360 内でデータアクションの自動的なデータエクステンション作成方法を使用し、データアクションターゲットの Journey Builder API イベントを選択します。

  7. 登録者を絞り込むには、[選択したビジネスユニットの登録者にのみイベントを送信] を選択します。
    選択したビジネスユニットに登録者キーが対応付けられていないが、エンゲージメントの親ビジネスユニットで使用できる登録者にメールテンプレートまたはジャーニーを送信しない場合、このオプションを選択します。
  8. [保存] をクリックします。

既存のメールテンプレートを変更して別のメールを送信する場合は、更新されたメールテンプレートを使用して別のデータアクションターゲットを作成します。

Data 360 でのリアルタイムデータアクションの作成

Data 360 での標準セグメントの作成

データモデルオブジェクトに基づいて標準セグメントを作成し、セグメントを有効化対象に公開します。

必要なエディション

次の権限セットのいずれか:

選択したデータモデルオブジェクト (DMO) に基づいて特定の利用者を定義するように統合データを絞り込みます。セグメントを作成したら、定義したスケジュールに従って有効化対象に公開します。セグメントスケジュールを設定するときに、標準公開と高速公開のいずれかを選択できます。

  2. [新規] をクリックします。
  3. [ビジュアルビルダーを使用] を選択します。
  4. [標準セグメント]を選択し、[次へ]をクリックします。

      メモ [ルックバック期間] オプションは、組織の最大許容期間に基づきます。この設定では、選択可能な初期のデータ範囲を定義します。セグメントでは、セグメントレベルの [ルックバックウィンドウ] とは異なる可能性があるコンテナで特定の条件を適用できます。たとえば、セグメントレベルの [ルックバック期間] が 90 日に設定され、コンテナが 60 日を指定した場合、コンテナの条件が優先され、データは 60 日間のみ取り込まれます。
  6. [次へ] をクリックします。
  7. セグメントの公開方法を選択します。

例

ある小売会社は、過去 60 日間に購入した顧客を対象とする標準セグメントを作成します。統合個人 DMO を選択し、60 日のルックバック期間を設定し、月曜日から金曜日まで 1 時間の間隔で高速公開を選択して、更新されたオーディエンスデータを Marketing Cloud Engagement の有効化対象にすばやく転送します。

セグメントを作成したら、有効化対象に公開して有効化します。同じ DMO を使用して追加のセグメントを作成したり、コンテナ条件を使用してセグメントルールを絞り込んだりすることもできます。

  • セグメント基準
    セグメント基準は、セグメントを作成するために使用される対象オブジェクトを定義します。取り込み時にプロファイルまたはエンゲージメント種別としてマークされたオブジェクトを選択できます。たとえば、統合個人、統合世帯、取引先、予約、販売注文などでセグメントを作成できます。
  • Data 360 セグメントスケジュールの管理
    セグメントスケジュールオプションを使用すると、セグメントの公開頻度を詳細に制御できます。セグメントをスケジュールして、ニーズに最適な頻度で実行できます。
  • Data 360 でのセグメントの公開
    Data 360 でセグメントを定義したら、いつでも有効化対象に公開したり、セグメントの作成時のスケジュールに基づいて公開したりできます。標準の公開スケジュールは 12 時間または 24 時間です。セグメントスケジュールはそのプロパティを編集して変更することもできます。セグメント公開の同時実行制限に達すると、Data 360は他のセグメントの公開を延期します。この延期は、同時に実行されるセグメント数が制限を下回るまで続行されます。つまり、特定の時間にスケジュールされたセグメントは、そのスケジュールされた時間に公開が開始されない場合があります。
  • セグメントメンバーシップデータモデルオブジェクト
    セグメントを公開するたびに、セグメントメンバーシップ情報を保存するデータモデルオブジェクト (DMO) が作成または更新されます。セグメントに含まれるユーザーを識別するには、セグメントメンバーシップ DMO (種別は Segment_Membership) を使用します。DMO に連動関係がない場合は、セグメントメンバーシップ DMO を手動で削除できます。
  • セグメントの編集
    Data 360 でセグメントを作成したら、そのルールやプロパティを編集して更新を提供したり、目的を変更したりできます。セグメント名を変更しても、セグメント API 参照名は変更されません。

ウォーターフォールセグメントの作成

複数のオファーがあるキャンペーンを実行している場合、ウォーターフォールセグメントを使用して既存のセグメントのリストを優先度順に処理します。主な目標は、複数のセグメントの対象となる個人を、一致する優先度が最も高いセグメントにのみ配置することです。これにより、相互に排他的な一連のオーディエンスが作成されます。これは、顧客に最も関連性の高いオファーを 1 つだけ送信したいキャンペーンに最適です。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要な権限セット
ウォーターフォールセグメントを作成する

次の権限セットのいずれか:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト
  1. Data 360 で、[セグメント] をクリックします。
  2. [新規] をクリックします。
  3. [ビジュアルビルダーを使用] を選択します。
  4. [Waterfall Segment (ウォーターフォールセグメント)] を選択し、[Next (次へ)] をクリックします。
  5. セグメントの詳細を入力します。
    1. データスペースを選択します。
    2. [セグメント対象] で、セグメントの作成元となるデータモデルオブジェクト (DMO) を選択します。リストには、取り込み時にプロファイル種別としてマークされたオブジェクトが表示されます。
    3. ウォーターフォールセグメントに識別しやすい一意の名前を付けます。
  6. [次へ] をクリックします。
  7. 有効化対象にウォーターフォールセグメントを公開するタイミングと頻度を定義します。
    セグメント・フィルタを追加する場合は、「更新しない」を選択して後でスケジュールを追加することもできます。処理スケジュールはウォーターフォール全体に適用されます。高速セグメント公開は、ウォーターフォールセグメントでは使用できません。
  8. [保存] をクリックします。
  9. セグメントをキャンバスにドラッグし、優先度に従って並び替えて、ウォーターフォールを作成します。
    最大 20 個のセグメントを追加できます。選択した DMO に基づいており、まだウォーターフォールになっていない有効なセグメントのみが表示されます。セグメントは 1 つのウォーターフォールにのみ存在できます。ネストされたセグメントをウォーターフォールセグメントに含めることはできません。相互に排他的な各セグメントの数は、ウォーターフォールセグメントを保存して公開すると表示されます。

例

この例では、ウォーターフォールセグメントで相互に排他的な利用者を作成し、顧客が 1 つの提案のみを受信する方法を示します。

3 つの個別のプロモーションオファーと、対象とする顧客の 3 つのセグメントがあります。

  • オファー 1 (最良のオファー): 価値の高い顧客には 25% 割引
  • オファー2(中間オファー):新規顧客の場合は15%割引(過去90日間に参加)
  • オファー 3 (一般オファー): すべての有効なお客様の 10% 割引

顧客は一度に複数のセグメントに存在できます。たとえば、価値の高い顧客 (オファー 1) は新規顧客 (オファー 2) でもあり、間違いなくすべての有効な顧客 (オファー 3) でもあります。このユーザーに 3 つの異なる提案をメールで送信するのではなく、対象になる最適な提案 (25% 割引) のみを送信するとします。

ウォーターフォールセグメントを作成し、既存のセグメントを次の優先度でキャンバスにドラッグします。

  1. 価値の高い顧客 (優先度 1)
  2. 新規顧客 (優先度 2)
  3. すべての有効な顧客 (優先度 3)

ウォーターフォールセグメントが実行されると、リストに対して各顧客が順番に評価され、一致が見つかるとすぐに停止します。

  • 顧客 A (Sarah): Sarah は価値の高い顧客であり、新規顧客です。
    • 優先度 1 (高価値) と一致するか?はい。
    • 結果: Sarah は High-Value Customers グループに配置されます。ウォーターフォールは彼女の処理を停止します。技術的には対象であっても、新規顧客グループまたはすべての有効顧客グループには配置されません。彼女は 25% の割引オファーのみを受けています。
  • 顧客 B (David): David は価値の高い顧客ではありませんが、新規顧客です。
    • 優先度 1 (高価値) と一致するか?いいえ。
    • 優先度 2 (新規顧客) と一致しますか?はい。
    • 結果: David は New Customers グループに配置されます。ウォーターフォールは彼の処理を停止します。彼は 15% の割引オファーのみを受けています。
  • 顧客 C (Maria): Maria は重要顧客でも新規顧客でもないが、有効な顧客である。
    • 優先度 1 (高価値) と一致するか?いいえ。
    • 優先度 2 (新規顧客) と一致しますか?いいえ。
    • 優先度 3 (すべての有効な顧客) と一致しますか?はい。
    • 結果: Maria は [すべての有効顧客] グループに入れられ、10% 割引のオファーを受け取ります。

ウォーターフォールセグメントの最終出力は、重複しない 3 つの個別の顧客リストで、誰も複数のプロモーションを受け取らないようにします。

セグメンテーションの通貨データ型

セグメンテーション検索条件で集計を実行して必要なグループを作成するときに、通貨データ型を使用して通貨を変換できます。

デフォルトの通貨換算データモデルオブジェクト (DMO) に必要なすべての換算レートが含まれていることを確認します。これにより、正確な結果を得ることができます。換算レートが通貨換算 DMO にない場合、誤った結果になる可能性があります。

メモ

現在、API を使用して作成されたセグメントでは通貨データ型はサポートされていません。

検索条件の通貨属性

通貨データ型属性を使用してデータをセグメント化できます。検索条件を作成するときに、[通貨] ドロップダウンメニューから通貨コードを選択します。この通貨コードは、データを正規化するために使用されます。

例

検索条件が [注文合計] = $500 で、[収入] 属性にマルチ通貨の値が含まれている場合、通貨換算 DMO を使用してすべての値が米ドル (検索条件で選択した通貨) に変換されます。変換後、検索条件がセグメントに適用されます。

メモ

条件通貨項目が使用されている場合、セグメント数とセグメント公開結果に不一致が生じる可能性があります。

集計の通貨属性

通貨属性を使用して合計や平均などの集計操作を実行する場合、[通貨] ドロップダウンメニューから通貨コードを選択します。この通貨コードは、集計を実行する前にデータを正規化するために使用されます。

メモ
  • 他の操作の一部として暗黙的な通貨変換は行われません。
  • 通貨変換中に丸めエラーが発生すると、セグメンテーションで結果が不正確になることがあります。

Data 360 のデータアクションターゲット

データアクションの結果は、データアクションターゲットでトリガーされます。ターゲットはデータアクションをほぼリアルタイムで受信します。データアクションをターゲットに送信して、イベントベースのオーケストレーションを促進できます。

必要なエディション

使用可能なインターフェース: Lightning Experience

サポートされるターゲットは次のとおりです。

  • Salesforce Platform イベント — データアクションをコアイベントバスに送信し、Data 360 で生成されたほぼリアルタイムのインサイトに基づいてフローアプリケーションを構築します。
  • Web フック — データアクションを Web フックターゲットに送信し、Salesforce によって生成された秘密鍵を使用してメッセージの整合性を保護します。Web フックは、要求駆動型ではなくイベント駆動型の API です。
  • Marketing Cloud Engagement — エンゲージメントメッセージングおよびジャーニー機能を使用して、イベントやインサイトに基づいたシナリオを管理します。

インテグレーションユーザーが作成したデータアクションターゲット ([項目をコピー] 強化、Salesforce CRM 強化、Flow Builder を使用した Data Cloud トリガーフローなど) は参照のみです。これらのターゲットは削除、無効化、または編集できません。

例

データアクションによってほぼリアルタイムのイベント駆動型の使用事例をいくつか紹介します。

  • アクション情報に基づいたエンゲージメント

    インストールが複雑な品目を購入した顧客が、Web サイトで「インストールマニュアル」を検索したとします。顧客にハウツー動画やインストール手順を記載したメールを送信できます。

  • サービスとサポート

    顧客が特定の期間に複数のトラブルシューティングページにアクセスした。顧客のケースを自動的に登録できます。

  • 金融サービス

    顧客が Web サイトで $1,000 を超える商品を購入すると、カスタマージャーニーイベントをトリガーできます。

  • Account engagement (取引先エンゲージメント)

    顧客が複数の品目を選択してカートに入れますが、購入はしません。顧客に購入の完了を促すジャーニーをトリガーできます。

  • ロケーションベースのエンゲージメント

    顧客がホテルにチェックインする。ホテルのバーを訪れたり、豪華な休暇やアクティビティを確認したりするためのプロンプトを含むジャーニーを顧客に送信できます。

  • Salesforce Platform イベントデータアクションターゲットの作成
    データアクションをコアイベントバスに送信し、Data 360 で生成されたトリガーに基づいてフローアプリケーションを作成します。
  • Web フックデータアクションターゲットの作成
    データアクションイベントを Web フックターゲットに送信し、Salesforce によって生成された秘密鍵を使用してメッセージの整合性を保護します。Web フックは、要求駆動型ではなくイベント駆動型の API です。秘密鍵は、Salesforce から送信されたペイロード要求を検証します。Web フックは、DataObjectDataChgEvent 形式のイベントを含む HTTP ペイロードを転送します。
  • Marketing Cloud Engagement データアクションターゲット
    データとインサイトを使用してビジネス評価指標を向上させ、Marketing Cloud Engagement で Journey Builder API イベントと取引メールを送信することによって顧客とのやりとりの遅延を減らします。Data 360とエンゲージメントを組み合わせて、トランザクションを自動化およびパーソナライズします。データトリガーのメールメッセージとジャーニーを使用して単純な運用タスクを自動化したり、取引開始数を最大化したり、顧客の離脱率を最小限に抑えたりすることが可能です。

データアクションエラーのトラブルシューティング

よくあるデータアクションおよびデータアクションターゲットのエラーを解決するためのヒントを紹介します。

エラー トラブルシューティングの提案
Web フックデータアクションターゲット経由でイベントが来ない。
  • Web フックデータアクションターゲットに秘密鍵があることを確認します。
  • 秘密鍵がない場合は、署名の検証のために秘密鍵を生成します。
イベントが Marketing Cloud Engagement データアクションターゲットで生成されない。
  • Journey Builder のデータエクステンション属性名で正しい命名形式が使用されているかどうかを確認します。名前は、Data Cloud で選択されたデータモデルオブジェクトのオブジェクト API 参照名で始まり、その後にアンダースコアと属性 API 参照名が続く必要があります。例: Shopping_Events__dlm_deviceId__c。
  • イベントペイロードに必須項目があることを確認します。
  • イベントペイロードの取り込み中に、データアクションの作成時に選択した購読者キー値が null でないことを確認します。
  • Engagement と Data Cloud で設定されている項目のデータ型が一致する必要があります。
  • 属性の長さは、Journey Builder のデータエクステンションで定義した値を超えることはできません。

Data 360 のデータアクション

Data 360 のデータモデルオブジェクトと計算済みインサイトオブジェクトのデータ変更を監視し、変更データイベントを Salesforce Platform イベント、Marketing Cloud Engagement、または Web フックに送信します。

豊富なペイロードが含まれるデータアクションは、特定の条件に基づいてトリガーできます。また、このデータアクションにより、ダウンストリームシステムでアクションやオーケストレーションを促進できます。

データアクションを使用すると、チャネル、商品、取引先、サービス、販売、履行、エンゲージメント、支払、個人レベルなど、さまざまなレベルでほぼリアルタイムのイベントとインサイトに焦点を絞ることができます。

データアクションでは、さまざまな種別のイベント駆動型インテグレーションおよびオーケストレーションを有効にできます。

  • Data 360からのインサイトとデータ イベントを使用して、Salesforce CRMワークフローを調整します。
  • 条件に基づいて集計イベントデータを外部パートナーと共有することで、Mulesoft Anypoint のデータアクションを統合します。
  • Data 360からのシグナルを使用してSaaSアプリケーションと統合します。
  • Data 360 のインサイトに基づいて Web フックと連携するサーバーレス関数をトリガーします。
  • Data 360で便利なイベントが発生したら、マルチクラウド ワークフローまたはサービスを接続します。
  • 絞り込まれていないインサイトとエンゲージメントをデータレークに転送し、分析および保存できます。

データアクションを使用してイベントを Salesforce Platform に公開すると、Salesforce は標準イベントDataObjectDataChgEventを使用してメッセージを公開します。

イベントがホーム組織またはコンパニオン組織に公開されている場合、Data 360 では特にプラットフォームで (フローなどを介して) イベントが消費されるときに、公開制限や割り当て制限が適用されません。ただし、イベントがプラットフォームの外部 (Mulesoft や AWS Lambda など) 登録者に配信される場合、Data 360 では配信割り当て制限が適用されます。

Data Cloud トリガーフローを介してイベントを Salesforce Platform イベントに公開すると、データアクション機能が使用されます。データアクションレコードホームページの [管理対象] 列に公開済みレコードが [フローインテグレーション] として表示されます。

データアクションを使用するには、まず結果を受信するデータアクションターゲットを作成します。

  • Data 360 のデータアクションターゲット
    データアクションの結果は、データアクションターゲットでトリガーされます。ターゲットはデータアクションをほぼリアルタイムで受信します。データアクションをターゲットに送信して、イベントベースのオーケストレーションを促進できます。
  • データグラフを使用した Data 360 のデータアクションの強化
    データグラフを関連オブジェクトとして含めることで、Data 360 のデータアクションを関連データグラフ属性で強化できます。
  • Data 360 でのデータアクションの作成
    データアクションを使用して、Salesforce Platform、Webhook、Marketing Cloud Engagement などの対象にアラートまたはイベントを送信します。チャネル、商品、取引先、サービス、個人など、さまざまなレベルでほぼリアルタイムのイベントとインサイトに焦点を当てるデータアクションを作成します。
  • Data 360 でのベクトル検索データアクションの作成
    非構造化データに対してほぼリアルタイムでアクションを実行し、アラートまたはイベントを送信するベクトル検索データアクションを作成します。
  • Data 360 でのリアルタイムデータアクションの作成
    アラートまたはイベントを送信し、リアルタイムで応答を取得するリアルタイムデータアクションを作成します。リアルタイムデータアクションを使用して、チャネル、商品、取引先、サービス、個人レベルなど、さまざまなレベルのリアルタイムイベントとインサイトに焦点を絞ります。
  • Data 360 データアクションとフローの統合
    Data 360データ アクションは、ストリーミング イベントとインサイトをSalesforceフローに送信してオーケストレーションを促進できます。オーケストレーションでは、フェーズ、ステップ、決定を使用して複雑なビジネスプロセスを整理します。
  • データアクションエラーのトラブルシューティング
    よくあるデータアクションおよびデータアクションターゲットのエラーを解決するためのヒントを紹介します。
  • データアクションの請求に関する考慮事項
    データアクションの使用は、次の使用量種別のクレジットの消費に影響します。

セグメントの削除

不要になったセグメントを削除します。セグメントが有効化に関連付けられている場合は、有効化を先に削除します。

セグメントを再度使用する場合は、代わりに公開スケジュールを停止します。セグメントを削除するには、セグメント名の横にあるドロップダウンメニューを使用して [削除] を選択します。

セグメントを削除すると、再度有効にすることはできません。削除したセグメントをごみ箱から復元した場合、編集または削除を再び行うことはできません。セグメントを新たに作成する必要があります。

無効化されたセグメント

セグメントが不要になった場合は、Data 360で無効化でき、選択したすべてのターゲットに適用されます。無効になったセグメントは公開されなくなり、有効化の選択と再有効化はできなくなります。セグメントを再度使用する場合は、代わりに公開スケジュールを停止します。

セグメント名の横にあるドロップダウンメニューを使用してセグメントを無効化し、[無効化] をクリックします。

メモ セグメントを無効化すると、再度有効にすることはできません。無効化でエラーが発生した場合、セグメントを再作成する必要があります。

外部有効化プラットフォームのカスタムメタデータの作成

Data 360 管理者が使用するためにプラットフォームをパッケージ化する前に、外部有効化プラットフォームのカスタムメタデータを作成します。これは、手動ワークフローを使用して作成されたプラットフォームにのみ適用されます。

メモ 有効化スケジュールでは、24 時間ごとの公開がサポートされます。
  1. 歯車アイコンをクリックし、[設定] をクリックします。
  2. [設定] で、[カスタムメタデータ型] に移動します。
  3. [新規カスタムメタデータ型] をクリックします。
  4. [表示ラベル] に「ActivationPlatformCredential」と入力し、[表示ラベル(複数形)] に「ActivationPlatformCredentials」と入力します。
  5. [表示] で、[同じ管理パッケージ内の Apex コードのみがこの種別を参照できます。この種別の名前とレコードは数式で参照されている場合に表示できます。
    メモ 別のオプションを選択すると、パッケージをインストールするユーザーに Amazon S3 バケットのログイン情報が公開される可能性があります。
  6. [保存] をクリックします。
  7. [ActivationPlatformCredential] をクリックします。
  8. [カスタム項目] で、[新規] をクリックします。
    1. [テキスト] を選択して、[次へ] をクリックします。

      ヒント [長さ] の値は 150 にすることをお勧めしますが、他の任意の制限値も設定できます。
    3. [ActivationPlatformCredential ページレイアウト] が選択されていることを確認します。
    4. [保存 & 新規] をクリックします。

    6. [項目の表示ラベル] と [項目名] に「SecretKey」と入力し、[次へ] をクリックします。

      ヒント Data 360 で外部有効化プラットフォームを作成したときに入力した S3 バケット名のログイン情報を使用します。
