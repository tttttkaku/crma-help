取得者のテストに関する請求の考慮事項

検索インデックスを照会して取得者をテストする場合、データは Data 360 で処理されます。 取得者テストの主な使用種別はデータクエリです。retriever playground の使用は、次の使用量種別の請求に使用されるクレジットの消費に影響します。

Digital Walletを使用して、組織で有効な消費カードを確認し、各カードで使用可能なクレジット数を確認し、各使用量種別で消費されたクレジット数を確認する

Data 360 ProfilesライセンスやAgentforce 1 Editionなど、特定のライセンスまたはエディションでは測定されない使用量タイプもあります。詳細は、ライセンスとライセンスドキュメントを参照してください。

Customer Data Platform(CDP)ライセンスでData 360を運用している組織では、検索インデックスなどの非構造化データ処理機能は使用できません。

Data 360 の利用状況

データ収集と処理に Data 360 を使用する場合、組織は Data Services 消費カードまたは Flex Credits 消費カードからクレジットを消費します。有効なデータサービス消費カードがある場合、それらのクレジットが最初に消費されます。データサービスクレジットが不足していたり、まったくクレジットがなかったりした場合、組織は Data 360 Flex Credits for Data 360 サービスを消費します。

データ サービスの使用量タイプについての詳細は、「Data 360 Billable Usage Types and Flex Credits Usage Types for Data 360」を参照してください。使用量種別ごとの乗数を確認するには、「Multipliers for Data Services Rate Card」または「Agentforce & Data 360 Flex Credits Rate Card」を参照してください。各クレジットのコストは契約によって決まります。

予測 AI の請求に関する考慮事項

AIモデル(旧Einstein Studio)の予測モデルでは、Data 360を使用してデータの取り込み、クエリ、保存、推測の作成を行います。Data 360 サービスを使用すると、次の使用量種別の請求に使用されるクレジットの消費に影響する可能性があります。

Customer Data Platform の請求可能な使用量の計算

旧 Customer Data Platform 組織への請求は、契約上のエンタイトルメントに基づいて行われます。請求の対象となる使用量を理解しておくと、データ管理に関する決定を下しやすくなります。

重要 これらの請求使用量の計算は、Customer Data Platform ライセンスを持つ Data 360 組織にのみ適用されます。Data 360 組織に Data Cloud ライセンスがある場合は、代わりに「Data Services Billable Usage Types for Data 360」を参照してください。

統合プロファイル、セグメント公開、エンゲージメントイベントの領域の使用量に応じて請求されます。上記の領域の最大使用量は、契約のエンタイトルメントスケジュールに定義されています。毎月超過分が契約した料率で請求されます。契約について不明な点がある場合は、取引先チームにお問い合わせください。

Customer Data Platform 組織の請求可能統合プロファイルの計算

請求可能なプロファイル数は、有効な ID 解決ルールセットがあるかどうかに基づきます。請求可能なプロファイル数がエンタイトルメントを超える場合は、追加の統合プロファイル分が請求されます。

ID 解決を使用していない場合の請求可能なプロファイル数は、カテゴリに関係なく、プロファイル種別として分類されているデータモデルオブジェクト (DMO) にマッピングされたすべてのデータレークオブジェクト (DLO) の全レコードの合計です。既知のプロファイルレコードと不明なプロファイルレコードの両方が計数されます。次の DMO にのみマッピングされている DLO は、この数から除外されます。

  • Account Contact (取引先責任者)
  • 連絡先住所
  • 連絡先アプリケーション
  • 連絡先の同意
  • 連絡先メール
  • 連絡先 OTT サービス
  • 連絡先電話
  • 連絡先ソーシャル
  • デバイス
  • 関係者 ID

ID 解決を使用してソースプロファイルを統合プロファイルにリンクしている場合、請求可能な統合プロファイル数は次の両方の合計です。

  • すべての有効な ID ルールセットの既知の統合プロファイルレコード数。所有している統合プロファイルレコード数を確認するには、有効なルールセットごとに [ID 解決の概要] を参照します。概要でルールセットの統合プロファイルの数を見つけます。すべてのルールセットの既知の統合プロファイルの数を追加します。
  • ID 解決に含まれる DMO を除き、[プロファイル] に分類された DMO に対応付けられている、カテゴリに関係なくすべての DLO のすべてのレコードの数。これらのレコードはセグメントの作成に使用できるため、この数に含められます。[その他] 種別の DMO に対応付けられている DLO は、統合プロファイルではなくエンゲージメントイベントとして計数されます。

匿名プロファイルの制限は、Salesforce エディションに基づきます。ID 解決を使用している場合は、請求可能な統合プロファイル数から匿名プロファイルが除外されます。

例

この例では、10,000 件のレコードが含まれる Unified Individual.1 と 8,000 件のレコードが含まれる Unified Individual.2 の 2 つの有効な ID 解決ルールセットがあります。[プロファイル] に分類され、個人に対応付けられていない 2 つの DLO があります。取引先 DLO には 2,000 件のレコードがあり、カスタム DLO には 5,000 件のレコードがあります。この顧客の場合、請求可能な統合プロファイルの合計は 10,000 + 8,000 + 2,000 + 5,000 = 25,000 です。

Customer Data Platform 組織の統合プロファイル数に影響する要素

プロファイル数がビジネスニーズを正確に反映するように、これらの要素に対処します。

複数の ID 解決ルールセット

すべての有効な ID 解決ルールセットの統合プロファイル数を使用して、請求可能なプロファイルの合計を計算します。有効な ID 解決ルールセットの数を検証します。複数の有効なビジネス目的にすべてが必要かどうかを判断します。

データストリームの増加

異なるソースシステムを Data 360 に接続し、新しいデータストリームを介して取り込まれるデータ量を増やすと、プロファイルの数も増えます。プロファイルとして分類されたすべてのデータストリームとソースを確認します。重複するソース、開発ソース、テストソース、ステージングソースが存在するかどうか、およびまだ必要かどうかを判断します。

匿名プロファイル

匿名プロファイルは請求可能な統合プロファイルに含まれませんが、取り込まれるときに匿名としてマークする必要があります。個人 DMO の [匿名] 項目が、匿名レコードを含むデータストリームで正しくマッピングされていることを確認します。

DMO カテゴリ

[プロファイル] として分類された DMO にマッピングされた DLO はセグメント化でき、統合プロファイル数に含まれます。DLO から DMO へのすべてのマッピングを確認します。[プロファイル] に分類された DMO にマッピングされたすべてのデータストリームに、セグメント化の基準となる母集団が含まれているか、セグメントの開始母集団として使用する母集団が含まれているかを判断します。DMO がプロファイルとして誤って分類されていないかどうかを確認します。

DMO がプロファイルとして誤って分類されている場合、そのカテゴリを [その他] に変更できます。DMO のカテゴリは、セグメンテーションまたは有効化で使用されていない場合にのみ変更できます。カテゴリを [プロファイル] から [その他] に変更する前に、DMO を使用するすべてのセグメントと有効化を削除します。「データモデルオブジェクトのカテゴリの変更」を参照してください。

メモ 個人 DMO を変更すると、ID 解決に影響する可能性があります。

Customer Data Platform 組織の統合プロファイル数に関するその他の考慮事項

  • マッピングされていない DMO として出力された変換から作成されたデータは、請求可能な統合プロファイルには含まれません。DLO がマッピングされていない場合、DLO は計数されません。
  • 個人 DMO にマッピングされ、[プロファイル] 種別の DMO にもマッピングされている DLO は 2 回計数されません。
  • プロファイル種別が DMO にマッピングされているすべての DLO は、請求可能な統合プロファイルに含まれます。この数には、次のシナリオが含まれます。
    • ID 解決数外のデータストリーム
    • ID 解決の範囲外の同意 DMO の数
    • ID 解決数外のプロファイル タイプの DMO にマッピングされたデータ変換またはストリーム変換 DLO

Customer Data Platform 組織のセグメント公開の計算

「セグメント公開」エンタイトルメントは、契約期間における請求可能なセグメント公開の最大数です。

セグメントが公開されるたびに、1 つの請求可能セグメント公開とみなされます。セグメントに複数の有効化が関連付けられている場合、または有効化が関連付けられていない場合は、そのセグメントの 1 つの公開が 1 つのセグメント公開操作として計数されます。一定期間に完了したセグメント公開が合計され、エンタイトルメントに反映されます。

請求可能なセグメント公開数を推定するには、全セグメントのすべての公開スケジュールを確認します。

Customer Data Platform 組織のエンゲージメントイベントの計算

エンゲージメントイベントは、[エンゲージメント] または [その他] に分類された DLO のすべてのレコードを合計して計算されるため、統合プロファイルレコードとして数えられないものはすべてエンゲージメントイベントとして計数されます。[その他] 種別 DMO にマッピングされているプロファイル種別 DLO も計数されます。レコード数がエンタイトルメントを超えると請求の対象になります。

請求可能なレコード数を計算するには、データレークオブジェクトのホームページに移動します。プロファイル種別 DMO に対応付けられている DLO 以外のすべての DLO のレコード数を合計します。これらの DLO は統合プロファイルとして計数されるためです。マッピングされていない DLO はエンゲージメントエンタイトルメントに含まれますが、統合プロファイルエンタイトルメントには含まれません。

たとえば、購入に関するレコードがデータ変換を使用してソース DLO から対象 DLO にコピーされた場合、両方の DLO の全レコードが合計に含まれるため、レコードは 2 つのエンゲージメントイベントとして計数されます。

Data 360 での機密データ分類

データを分類することで、規制または内部標準に従って適切かつ安全に処理できます。データの機密性 (機密性) と利用状況 (アクセス方法とアクセス者、使用者) の両方を考慮してデータを分類できます。

機密性に基づくデータの分類

機密性でデータを分類するには、まずデータが共有された場合、誤って使用された場合、または紛失した場合にどの程度の損害が発生する可能性があるかを把握します。データを 4 つの感度レベルにグループ化できます。

  • 公開: このデータは、オープンに共有してもリスクはありません。たとえば、商品パンフレットや公開レポートなどがあります。
  • 内部: チームリストまたは内部ルールを含めることができる会社データ。漏洩しても害はありませんが、一般ユーザーに表示されるものではありません。
  • 社外秘: このデータには、顧客レコードまたは内部財務データが含まれる場合があります。暴露されると、重大な害を引き起こし、より強力な管理が必要になります。
  • 制限付きまたは機密性が高い: このデータには、個人の健康情報、クレジットカード番号、または企業秘密が含まれており、法的リスクまたはビジネスリスクのために最も厳しい保護が要求されます。

機密性分類を定義して指針とするには、一般データ保護規則 (GDPR)、医療保険の相互運用性と説明責任に関する法律 (HIPAA)、または (Payment Card Industry Data Security Standard) PCI-DSS などの規制フレームワークを参照してください。

利用状況に基づくデータの分類

利用状況でデータを分類するには、データを使用するユーザー、頻度、およびその理由を確認します。たとえば、会社全体のレポートのデータは、トランザクションシステムやカスタマーサービスで使用されるデータとは異なります。データが使用中か、アーカイブ済みか、削除可能かを検討します。データを整理すると、誰がどのくらいの期間アクセスできるかなど、適切なセキュリティルールを設定し、目的に基づいてデータが適切に管理されるようになります。

  • Data 360 の分類タグ
    分類により、分類内で追加のコンテキストと意味が提供されます。機密性や使用目的などの定義済みの条件に基づいてデータを分類できるため、データの適切な管理、保護、使用が容易になります。
  • Data 360 での分類の作成
    Data 360 では、機密レベルまたは使用量レベルを定義してデータを分類し、マスキングやアクセス制御などのガバナンスポリシーを促進します。
  • Data 360 での分類の編集または削除
    分類の名前と説明を編集したり、関連付けられたタグを管理したり、不要になった場合は削除したりします。ポリシーで使用されている分類は削除できません。これには、Data 360 によって提供されるデフォルトの分類が含まれます。

Data 360 レポート可能リソース参照

リソース参照は、使用量を生成した機能別にクレジット消費量を表示するための標準使用量タグです。リソース種別に関するカスタム Data 360 レポートを作成し、そのソースで使用量を表示、絞り込み、並び替えることができます。

メモ リソース参照は、2025 年 7 月から 2025 年 9 月の間に段階的にロールアウトされます。 ロールアウト前の特定のリソース種別のデータは使用できません。

リソース参照は機能別に整理されているため、さまざまな使用量種別に含まれる使用量がバンドルされることがあります。たとえば、バッチコネクタとストリーミングコネクタは異なる使用量種別でクレジットを消費しますが、どちらも同じリソース参照によって報告されます。

リソース種別に関するレポートを作成したら、[リソース ID] または [API 参照名] 項目で並び替えて、機能内で何が使用量を生成したかを確認します。たとえば、DataStreamDefinition リソース種別に関するレポートを作成する場合、[リソース ID] 項目または [API 参照名] 項目に保存されているコネクタ API 参照名で並び替えると、各接続の使用量を確認できます。

Data 360 のデータサービス請求可能利用状況種別

特定の Data 360 機能の使用は、クレジット消費に影響します。2026 年 2 月 24 日より前にクレジットを購入した場合、組織は Data 360 サービスのデータサービスクレジットを消費します。2026 年 2 月 24 日以降に購入または更新する組織には、データサービスまたは Flex Credit のいずれかを使用できます。これらのデータ サービス使用状況カテゴリの使用状況を監視するには、組織の Digital Wallet にアクセスします。組織に Data 360 Profiles タイプのライセンスがある場合、一部の使用量種別は消費されません。使用量の請求方法についての詳細は、契約書を参照いただくか、アカウントエグゼクティブにお問い合わせください。

メモ Data 360 組織が Customer Data Platform ライセンスで運用されている場合は、代わりに「Customer Data Platform Billable Usage Calculations」を参照してください。

組織のライセンスとDigital Walletを確認し、組織での請求方法を判断します。

  • 組織で Customer Data Platform ライセンスに基づいて Data 360 を運用している場合は、* 代わりに「Customer Data Platform Billable Usage Calculations (Customer Data Platform の請求可能使用量の計算)」を参照してください。
  • 組織が Data Cloud ライセンスで運用されており、有効なデータサービス消費カードがある場合は、代わりに「Data 360 のデータサービスの請求可能な利用状況種別」を参照してください。Data 360 Profiles ライセンスも持っている場合、一部の使用量は測定されません。詳細は、「Data 360 ライセンスの請求に関する考慮事項」を参照してください。
  • 組織が Data Cloud ライセンスで Data 360 を運用していて、有効なデータサービス消費カードがない場合、この記事ではクレジットがどのように消費されるかを説明します。

消費したクレジット数は、各利用状況の種別の単位数に、その利用状況の種別のレートカードに記載されている乗数を乗算した値に基づきます。

実際の使用量は使用量種別ごとに合計され、単位は小数の割合で減少します。使用量種別から差し引かれるクレジットの最小数は 1 です。この場合、端数の使用量は月次請求期間全体で 1 クレジット以上になります。

Digital Walletでは、データ サービスを使用するお客様のData 360の消費は次の消費カードで追跡されます。

Data 360 Profiles ライセンス

Data 360 組織に Data 360 Profiles または Data 360 Enterprise Profiles ライセンスが追加されると、一部の機能でクレジットが消費されなくなります。詳細は、「Data 360 Profiles ライセンスの請求と制限」を参照するか、機能の「請求に関する考慮事項」の記事を参照してください。

データサービスの利用状況

サービス使用量の計算は、処理、照会、分析されたレコードに基づきます。サービス使用量は、Data 360、Data 360 for Marketing、および Data 360 for Tableau ユーザーに適用されます。

請求カテゴリ 説明
内部データパイプライン

使用量は、Salesforce CRM コネクタ、Marketing Cloud コネクタ、Commerce Cloud コネクタ、Marketing Cloud Personalization コネクタを介して Salesforce から取り込まれた構造化データの行数に基づいて計算されます。

2025 年 8 月 7 日以降、この種別の使用は Data 360 に含まれ、クレジットは消費されません。詳細は、「Data 360 への Salesforce データの無料取り込み」を参照してください。
一括処理データパイプライン (外部データパイプライン) 使用量は、内部データパイプラインを介して取り込まれる構造化データを除き、すべてのコネクタで Data 360 データストリームによって処理されるバッチデータの行数に基づいて計算されます。
ストリーミングデータ変換

使用量は、読み取られた行数と書き込まれた行数のいずれか多い方に基づいて計算されます。

結合を実行する場合、読み込まれる行数は、ストリーミング入力オブジェクトのレコード数に結合オブジェクトの数を乗算して計算されます。
一括処理データ変換

使用量は、読み込まれた行数と書き込まれた行数のいずれか多い方に基づいて計算されます。

増分一括処理データ変換では、変換を初めて実行した後、前回の実行以降に変更された行数に基づいて使用量が使用されます。
ストリーミングデータパイプライン (外部データパイプライン)

使用量は、内部データパイプラインを介して取り込まれる構造化データを除き、ストリーム処理を使用するすべてのデータストリームで Data 360 によって処理されるストリーミングデータの行数に基づいて計算されます。

この利用状況種別の利用状況を報告するデータストリームには、Web サイトおよびモバイルアプリケーションコネクタとストリーミング取り込み API によって作成されたストリームが含まれます。
処理される非構造化データ

使用量は、AI によるコンテンツの処理と抽出を使用せずに処理される非構造化データの量に基づいて計算されます。たとえば、検索インデックスでそれぞれ 1 MB の PDF ドキュメント 100 件を処理する場合、使用量は 100 MB として計算されます。検索インデックスでそれぞれ平均 100 MB の 5 つのオーディオ/ビデオ ファイルが処理される場合、使用量は 500 MB として計算されます。

Data 360 では、埋め込みモデルを使用して非構造化データをチャンク化してベクトル化できます。使用量は、これらの両方の活動で 1 回のみ計算されます。たとえば、100 MB の PDF ドキュメントが 1 つにチャンクされてベクトル化されている場合、使用量は 200 MB ではなく 100 MB として計算されます。

データモデルオブジェクト (DMO) をデータソースとして使用する検索インデックスを作成し、DMO からテキストデータ型項目を選択すると、それらの項目のすべての文字列にインデックスが作成され、処理されたすべてのバイトの合計が [非構造化データ処理済み] として報告されます。
インテリジェントな処理 使用量は、LLM ベースの解析、LLM ベースのビジュアルデータの前処理、画像処理、インテリジェントコンテキストなどの AI 支援機能を使用して処理される非構造化データの量に基づいて計算されます。
データ共有行の共有 (データ出力)

使用量は、最初にデータ共有を作成してデータ共有対象にリンクしたときに処理されたレコードの合計数に基づいて計算されます。これは、最初のフルバッチのデータにのみ適用されます。それ以降の増分変更は、この使用量種別には含まれません。

Data 360 組織間のデータ共有の場合、この利用状況種別はソース組織には適用されません。
アクセスされたデータ統合または共有行

データ統合の場合、使用量はソースから取得したレコード数に基づいて計算されます。データ共有の場合、使用量は外部データレイクの要求を満たすために返された行数に基づいて計算されます。

Data 360 組織間のデータ共有の場合、この利用状況種別はすべてのクエリの対象組織に適用されます。

外部データ共有の場合、この利用状況種別はクロスクラウドクエリとクロスリージョンクエリにのみ適用されます。クエリが同じリージョンおよび同じクラウドから発信された場合、クレジット消費はありません。
処理されるプライベートコネクトデータ 使用量は、プライベートネットワークルートを介して転送されるデータ量 (GB) に基づいて計算されます。これは、Data 360 へのデータの転送と外部データソースへのデータの転送に適用されます。
バッチプロファイル統合

使用量は、ID 解決ルールセットによって処理されたソースプロファイルの数に基づいて計算されます。ルールセットが初めて実行された後は、新規または変更されたソースプロファイルのみが数えられます。ソースプロファイルは、ID ルールセットに含まれる個人とその関連レコード (連絡先、関係者識別子など) です。

たとえば、変更済みとは、削除されたプロファイル、または同意 API 設定を介して抑制済みとしてマークされたプロファイルを意味します。

Data 360 の Flex Credits の請求可能使用量種別

特定の Data 360 機能の使用は、クレジット消費に影響します。Flex Credits使用量カテゴリの使用量を監視するには、組織のDigital Walletにアクセスします。組織に Data 360 Profiles タイプのライセンスがある場合、一部の使用量種別は消費されません。使用量の請求方法についての詳細は、契約書を参照いただくか、アカウントエグゼクティブにお問い合わせください。

組織のライセンスとDigital Walletを確認し、組織での請求方法を判断します。

  • 組織が Customer Data Platform ライセンスで Data 360 を運用している場合は、代わりに「Customer Data Platform Billable Usage Calculations (Customer Data Platform の請求可能使用量の計算)」を参照してください。
  • 組織が Data Cloud ライセンスで運用されており、有効なデータサービス消費カードがある場合は、代わりに「Data 360 のデータサービスの請求可能な利用状況種別」を参照してください。Data 360 Profiles ライセンスも持っている場合、一部の使用量は測定されません。詳細は、「Data 360 ライセンスの請求に関する考慮事項」を参照してください。
  • 組織が Data Cloud ライセンスで Data 360 を運用していて、有効なデータサービス消費カードがない場合、この記事ではクレジットがどのように消費されるかを説明します。

消費したクレジット数は、各使用量種別の単位数に、その使用量種別のレートカードに記載されている乗数を乗算した値に基づきます。

実際の使用量は使用量種別ごとに合計され、単位は小数の割合で減少します。使用量種別から差し引かれるクレジットの最小数は 1 です。この場合、端数の使用量は月次請求期間全体で 1 クレジット以上になります。

有効化でデータグラフが使用されている場合、最終的な計算で処理されるレコード数は 2 倍になります。たとえば、有効化でデータグラフが使用されている場合、DMO で 1 件の新規レコード変更があると、2 件の処理済みレコードとみなされます。
Data 360 リアルタイムパイプライン

使用量は、高速データ取り込み、Web およびモバイル SDK トラフィック、サーバー間 API トラフィック、リアルタイム取り込み API など、1 秒未満のリアルタイムレイヤーで処理されたプロファイルイベント、エンゲージメントイベント、API コールの合計数に基づいて計算されます。プロファイルイベント、エンゲージメントイベント、API コールは、リアルタイムデータグラフに関連付けられている場合、リアルタイムレイヤーで処理されます。

たとえば、特定の請求期間中に 3 つのプロファイルイベント、10 個のエンゲージメントイベント、20 個の API コールが処理された場合、処理される合計は 33 になります。
Data 360 コードエクステンション このタイプの使用量は計算単位で測定されます。1時間あたりに消費されるコンピューティング ユニット数は、選択したコンピューティング サイズによって異なります。計算単位の合計数は、1 時間あたりの消費レートとコードで消費された合計計算時間に基づいて計算されます。

Agentforce および Speech Foundation の Flex Credits の利用状況種別については、「Flex Credits Billable Usage Types for AI」を参照してください。

現在および過去の標準レートと乗数を確認するには、「Data 360 Multipliers」を参照してください。契約を確認して、契約レートを決定します。

データストレージ割り当て

ストレージとは、Data 360 に保存されているデータ量のことです。Salesforce Lightning Platformに保存されているデータなど、Data 360以外で使用されるストレージは、この制限に含まれません。ストレージ使用量は、Data 360、Data 360 for Marketing、および Data 360 for Tableau ユーザーに適用されます。

請求カテゴリ 説明
割り当てを超えるストレージ 使用量は、割り当てられた量を超えて使用されたストレージ量に基づいて計算されます。

データスペース

データスペース使用量は、Data 360、Data 360 for Marketing、および Data 360 for Tableau のユーザーに適用されます。

請求カテゴリ 説明
データスペース 使用量は、デフォルトのデータスペースを超えるデータスペース数に基づいて計算されます。

広告オーディエンスサービス使用量

広告オーディエンスサービス使用量の計算は、オーディエンスの数に基づきます。

請求カテゴリ 説明
広告オーディエンス 使用量は、広告オーディエンスのターゲット数に基づいて計算されます。

Data 360 でのクレジット消費の削減

これらの機能の請求に関する考慮事項を確認して、クレジット消費がどのように行われ、クレジット消費を削減するために設定を調整するかを理解します。
