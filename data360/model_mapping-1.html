データフェデレーションでのキャッシュまたはアクセラレーション

キャッシュでは、外部ソースからデータを取得し、Data 360 のデータレークオブジェクトに一時的に保存します。データストリームの作成時にアクセラレーションを有効にすると、キャッシュが有効になります。大きなデータセットにアクセスする場合や、データが頻繁に変更される場合は、キャッシュすることをお勧めします。キャッシュされたデータは、任意の頻度で更新できます。

データストリームを作成すると、キャッシュはデフォルトで無効になりますが、いつでもデータストリームを編集して有効化または無効化できます。日時項目を使用して、すべてのオブジェクトを 15 分ごとに増分更新できます。増分更新では、前回の更新以降に追加または変更されたデータでキャッシュされたオブジェクトが更新されますが、削除されたデータは更新されません。更新頻度が 24 時間以上の場合、日時を選択できます。

増分更新を有効にするには、[新しいデータストリームをリリースした後にデータストリームを編集] を選択し、増分更新のタイムスタンプを示す目的のレコード変更済みフィールドと目的の頻度を選択します。選択した頻度が 24 時間以上の場合、目的の更新日時を選択できます。現在、増分更新では更新/挿入がサポートされ、削除はサポートされていません。キャッシュされたオブジェクトは、前回の更新以降に追加または変更されたデータで更新されます。データストリームタイプを編集しない場合、キャッシュはそのたびに完全に更新されます。

フル更新モードでデータを取得することもできます。フル更新を選択した場合、更新サイクルごとに既存のキャッシュデータがすべて削除され、新しいデータセットに置き換えられます。データを最新の状態に保ち、データソースと同期させるには、定期的なフル更新を実行します。アクセラレーションを有効にすると、請求に使用されるクレジットの消費に影響します。高速化が有効になっている場合、キャッシュにデータを取り込むと、バッチデータパイプライン利用状況種別のクレジットが消費されます。

加速クエリでは、ライブクエリとは異なるレートと乗数でクレジットを消費します。詳細は、「データ統合の請求に関する考慮事項」を参照してください。

メモ Snowflake コネクタでは、Snowflake が開始するステージングバケットを使用して加速率を高めるアンロード機能がサポートされています。これはデフォルトで有効になっていますが、接続を編集することで無効にできます。

データレークオブジェクトからの CRM Analytics へのアクセス

CRM Analytics には、Data 360 インスタンスの [データレークオブジェクト] タブからアクセスできます。

  1. Data 360 で、[Data Lake Objects] タブに移動し、分析する DLO を選択します。
  2. DLO ページで、[Analytics 内を探索] をクリックし、[Analytics] タブのデータを表示して作業します。

データモデルオブジェクトからの CRM Analytics へのアクセス

CRM Analytics には、Data 360 インスタンスの [データモデル] タブからアクセスできます。

  1. Data 360 で、[データモデル] タブに移動し、分析するデータモデルオブジェクト (DMO) を選択します。
  2. DMO ページで、[Analytics 内を探索] をクリックし、[Analytics] タブのデータを表示して作業します。

キー修飾子項目の設定

データストリームを作成したら、データレークオブジェクト (DLO) 項目にキー修飾子を追加して、完全修飾キー (FQK) を作成します。プライマリキーまたは外部キーのいずれかが含まれるすべての DLO 項目にキー修飾子を設定します。最大 20 個の有効なキー修飾子を追加できます。キー修飾子は、DLO 項目で使用される場合に有効になります。Data 360 では、データモデルオブジェクト (DMO) 項目に対してキー修飾子が自動的に追加および削除されます。これらのシステム項目は編集できません。

必要なエディション

メモ キー修飾子をコンパニオン組織に追加するには、ホーム組織に追加し、コンパニオン組織がホーム組織と同期するまで 10 分以上待ちます。
使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
  1. [データレイクオブジェクト] タブに移動します。

  3. フィールドで、[] をクリックし、[Add Key Qualifier] を選択します。

オーディエンスデータモデルオブジェクト

オーディエンスデータモデルオブジェクト (DMO) を使用して、有効化されたオーディエンスを経時的に理解および分析します。関連 DMO には、オーディエンスとオーディエンス最新 DMO の 2 種類があります。

利用者 DMO は、プロファイルが追加、更新、削除されたとき、または変更されなかったときに表示されます。プロファイルの詳細 (有効化された属性、有効化の発生日、属するセグメントなど) を確認します。

Audience Latest DMO を使用すると、データエクスプローラーまたは API から最新の有効化公開に関する情報をすばやく見つけて取得できます。履歴ベースのクエリで最後に公開されたタイムスタンプで絞り込むことなく、有効化 ID のみを使用して最新の有効化ペイロードを照会できます。ただし、これらの DMO には、 および利用者 DMO でのみ使用できる削除デルタ種別は含まれません。

有効化を作成または編集すると、Marketing Cloud Engagement、Amazon S3、SFTP、Google Cloud Storage (GCS)、Microsoft Azure Blob Storage、Marketing Cloud Personalization、Data Cloud、B2C Commerce の有効化対象ごとに利用者 DMO が作成されます。

たとえば、5 つのエンゲージメント有効化対象を作成すると、10 個のオーディエンス DMO が作成されます。5 件の過去の利用者 DMO と 5 件の最新の利用者 DMO。接続された有効化対象または DMO を削除すると、オーディエンス DMO が削除されます。有効化でオーディエンス DMO を使用している場合は削除できません。有効化対象ごとに有効化を初めて保存すると、オーディエンス DMO が作成されるため、通常よりも時間がかかります。

  • セグメントからの Data 360 オブジェクトの作成
    Data 360 有効化対象に対する有効化では、セグメントと属性を使用してオブジェクトを作成します。各 Data 360 組織には 1 つの Data 360 有効化対象を含めることができ、各有効化対象には複数のオブジェクトを含めることができます。複数のセグメントで同じオブジェクトを選択できます。
  • オーディエンス DMO スキーマ属性
    Data Cloud では、特定の命名規則を使用して利用者 DMO が作成されます。「有効化利用者 - <有効化対象名>」を探します。

Data Cloud のオーディエンスインサイトデータモデルオブジェクト

Audience Insights データモデルオブジェクト (DMO) は、Google 広告プラットフォームで Ad Audiences コネクタを使用して有効化したオーディエンスに関するインサイトを提供します。複数の有効化された利用者からレコードを取得し、類似点と相違点を掘り下げることができます。DMO は 48 時間ごとに更新され、過去 90 日間のオーディエンスインサイトレコードが保存されるため、キャンペーンの長期的な影響とオーディエンスの進化を追跡できます。 

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
アドオンライセンスで使用可能: Ad Audiences

Audience Insights DMO を使用して、オーディエンスの特性を比較し、オーディエンス間で親和性、市場内行動、デモグラフィックがどのように異なるかを把握します。[インサイト] タブのレポートスコアは、オーディエンスメンバーが特定のデモグラフィックまたは行動カテゴリに属している可能性を示します。「有効化での Google オーディエンスインサイト」を参照してください。

オーディエンスインサイト DMO は、Google ターゲットの最初の有効化が保存されるときに作成されます。組織に Google に対する既存の有効化がある場合、新しい有効化を開始するか、既存の有効化を編集して、オーディエンスインサイト DMO を作成できます。DMO には、有効ユーザー数が 1,000 人以上のセグメントのオーディエンスインサイトのみが保存されます。

モデルパフォーマンス基準

集計されたモデルパフォーマンス基準を収集して、モデルの品質を監視、維持、改善します。モデルパフォーマンスは、承認、却下、または変更した自動マッピングのおすすめ数に基づきます。

  • 再現度 = ユーザーが承認したマッピングのおすすめ数 / 正しいマッピングの最終数
  • 精度 = ユーザーが承認したマッピングのおすすめ数 / マッピングのおすすめの合計数
  • 正確度 = 1 – (変更済み + 追加済み) / (マッピングのおすすめの合計数) = 再現度 * (2–1/精度)

すべての評価指標が集計され、匿名化されます。特定のしきい値を超えるマッピングのおすすめのみが表示されます。正確なしきい値は、Winter '24 まで決定されません。

自動マッピング

Data 360 での自動マッピングでは、データレークオブジェクト (DLO) フィールドが正しいデータモデルオブジェクト (DMO) フィールドにマッピングされます。項目のマッピング中に特定の DMO を選択すると、Data 360 によって項目のマッピングが計算されて適用されます。その後、必要な変更を行い、対応付けを保存できます。

Data 360 では、次の考慮事項に基づいてマッピングが推奨されます。

  • 履歴データ - 以前にマッピングされた項目のペアを使用して、マッピングのおすすめを提案します。
  • String Comparisons (文字列の比較) - 名前が似ている DLO 項目と DMO 項目がよく一致します。文字列比較は、完全一致、標準化された一致、あいまい一致の組み合わせを使用して行われます。2 つの文字列が同じ場合は完全一致です。あいまい一致の手法では、類似しているが同一ではない用語が識別され、スペル、形式、構造にわずかな違いが生じます。これは、わずかな変化のある文字列を比較するのに役立ちます。標準化された一致では、文字列を比較する前に一貫した形式または構造が文字列に適用されます。
  • シノニム - DLO 項目名の一般的なシノニムが比較に含まれます。たとえば、DLO 項目 subscriber key のマッピングを提案する場合、そのシノニムである Individual ID も比較とマッピングの対象になります。

対応付けの提案は時間の経過と共に改善されます。データ型の互換性は維持されます。たとえば、DLO の Boolean 項目が DMO の Boolean 項目に対応付けられているとします。

データ キットを使用してデータ変換をリリースする場合、出力データ レイク オブジェクト(DLO)とデータ モデル オブジェクト(DMO)間のマッピングは自動的に含まれません。これらのマッピングを継承するには、出力 DLO をデータキットに明示的に追加します。

データ変換をデータキットに含めると、SQLロジックと入力および出力パラメーターがパッケージ化されます。ただし、出力 DLO と DMO 間のマッピングは、独立した連動関係として機能します。データ変換コンポーネントのみをリリースすると、正常にリリースされ、DLO がマッピングされていないままになることがあります。リリース時に出力 DLO から DMO へのマッピングを確実に継承するには、出力 DLO 自体をデータキット設定に明示的に追加する必要があります。

  1. [データキット] タブに移動し、キットを開きます。
  2. データ変換を追加します。
  3. 出力 DLO を追加します。
    1. データキットの [データレークオブジェクト] セクションに移動します。
    2. [追加] をクリックします。
    3. データ変換で生成されるすべての出力 DLO を手動で選択して含めます。

出力 DLO を明示的に追加することで、データキット連動関係エンジンは DLO から DMO へのマッピングメタデータを認識してバンドルします。このデータ キットがターゲット組織にリリースされると、データ変換はそのダウンストリーム マッピングをすべてそのままの状態で到着し、すぐに使用できます。

データレークオブジェクトの出力ノードへの一括処理データ変換結果の書き込み

  1. 一括処理データ変換の最後に、[ノードを追加] ボタン () をクリックし、[出力] を選択します。
    • 既存の DLO を使用するには、[Use Existing (既存を使用)] を選択します。結果の書き込み先オブジェクトを選択し、[適用] をクリックします。
    • 新しい DLO を作成するには、[新規作成] を選択します。
  2. 出力の [書き込みモード] で、[置換] または [更新/挿入] を選択します。
    • 置換モード:
      • 増分変換の試行を置き換えて、以前の実行の変更のみを出力に読み込みます。
      • 出力オブジェクトの対応付けられていない列を許可します。
      • 変換が実行されると、対応付けられていない列に null 値が含まれます。
    • 更新/挿入モード:
      • すべての実行ですべての入力データを読み込みます。
      • 更新/挿入操作中にレコードのすべての列を置き換えて、入力データを出力にマージします。

    1. 変換結果を出力ノードに対応付けると、変換の通貨 (USD、INR、GBP) が出力の通貨項目に書き込まれます。通貨項目は主キーとして使用できません。

コンテナと属性を使用した絞り込み

セグメンテーションキャンバスで、母集団を対象グループに絞り込むルールを定義できます。検索条件は、結果ごとにさまざまな方法で作成、組み合わせることができます。関連属性を使用して検索条件を定義すると、該当するルールオプションと共にコンテナがキャンバスに追加されます。関連属性のデータモデルオブジェクト (DMO) がコンテナオブジェクトになります。

ただし、別個のコンテナの属性には相互リレーションがなく、セグメントを個別に絞り込みます。

    検索条件を定義する最初のステップは、平均または合計など、結果を定量化する方法を決定することです。この方法は、集計とも呼ばれます。たとえば、5 つの販売注文商品と 5 つの販売注文を検索する場合に異なる条件を使用します。コンテナオブジェクトを使用してデータを集計します。コンテナ内の関連属性のデータモデルオブジェクト (DMO) がコンテナオブジェクトになります。

    よく使用するセグメント検索条件属性をデータモデルパスと共にショートカットとして保存し、セグメントや有効化で再利用します。毎回属性ライブラリ内を移動して適切なデータモデルオブジェクト (DMO)、パス、属性を検索する代わりに、必要な設定を含む保存済みショートカットを選択できます。
  • セグメント利用者のグループ化、ランク付け、制限
    Data 360 セグメンテーションのグルーピング、ランキング、制限ルールにより、セグメントビルダーに高度な複数レベルの絞り込みが追加されます。標準検索条件を適用したら、順次ロジックを使用してセグメント母集団のグループ化、ランク付け、制限を行い、より構造化されたバランスの取れた利用者を作成できます。
  • セグメント検索条件での階層集計
    階層集計では、取引先とその関連子会社の収益を積み上げ集計することで、データを包括的に把握できます。その後、複数のレベルの集計値に基づいて、より正確なセグメント検索条件を定義できます。
  • コンテナパス
    一部のコンテナには、セグメンテーションエンティティに戻るパスが複数あります。コンテナに複数のアクセス パスがある場合、Data 360 がセグメントの作成方法を理解するのに役立つパスを選択できます。最初に検索条件を作成したときに使用できるパスは、後で編集するときに使用できるパスとは異なる場合があります。これは、リレーションカーディナリティルールによって促進される、予期される動作です。
  • セグメント属性の循環パスの使用に関する問題
    関連属性を選択しているときに DMO を複数回選択する場合は、循環パスを作成します。循環パスとは、循環動作 (a →b →a) を使用するリレーションです。循環パスによって、セグメントのパフォーマンスが低下し、計数や公開が失敗する可能性があります。この問題を回避するために、Data 360 ではデフォルトでセグメントビルダーを使用して循環パスを作成できません。
  • Data 360 のイベント時刻
    イベント日は、取り込み時にデータストリームレベルで定義される時間ベースの DMO 属性です。DMO には複数のイベント日が存在する可能性があります。[イベント時刻項目] は、エンゲージメントカテゴリに指定されている DMO にのみ適用されます。
  • セグメンテーション用のコンテナの作成
    関連属性を使用して検索条件を定義すると、キャンバスにコンテナが作成され、必要なルールを定義するためのオプションが表示されます。コンテナ内に最大 20 個の検索条件を含めることができます。
  • Data 360 セグメントでのベクトル検索条件の使用 (ベータ)
    ベクトル検索条件により、キーワードの完全一致や手動のデータ整理への依存が軽減され、正確なセグメントを効率的に作成できます。この機能では、セグメント作成で NLP アルゴリズムを使用して非構造化データを並び替えます。1 つのインターフェースとセグメント内で構造化データと非構造化データの両方を絞り込むことができます。
  • セグメンテーションの通貨データ型
    セグメンテーション検索条件で集計を実行して必要なグループを作成するときに、通貨データ型を使用して通貨を変換できます。

Data 360 のイベント時刻

イベント日は、取り込み時にデータストリームレベルで定義される時間ベースの DMO 属性です。DMO には複数のイベント日が存在する可能性があります。[イベント時刻項目] は、エンゲージメントカテゴリに指定されている DMO にのみ適用されます。

セグメントが処理されると、すべてのシステム日付属性項目の値を持つレコードのみが返されます。エンゲージメント DMO がセグメントに含まれている場合、セグメントでは最大 24 か月のイベント日項目のデータレコードを処理できます。日付範囲が 24 か月を超えると、セグメントは失敗します。セグメントを再度実行するには、イベント日をこの範囲に合わせて調整します。

例 販売注文 DMO では、イベント日項目として購入日属性が指定されます。販売注文 DMO を使用して、過去 X 日以内に $500 以上の購入をした個人のセグメントを作成する場合、X の値が 24 か月を超えることはできません。

コンテナパス

一部のコンテナには、セグメンテーションエンティティに戻るパスが複数あります。コンテナに複数のアクセス パスがある場合、Data 360 がセグメントの作成方法を理解するのに役立つパスを選択できます。最初に検索条件を作成したときに使用できるパスは、後で編集するときに使用できるパスとは異なる場合があります。これは、リレーションカーディナリティルールによって促進される、予期される動作です。

パス選択が重要な理由

関連属性検索条件を設定すると、[コンテナパス] ドロップダウンに、コンテナオブジェクトからセグメント化エンティティに戻るすべての有効なパスが表示されます。選択したパスは、どのリレーションをトラバースするか、つまりセグメントの作成時にどのレコードグループを使用するかをセグメンテーションエンジンに指示します。

たとえば、中古車の注文には、購入者 ID と販売業者 ID があり、どちらも個人に関連します。検索条件として注文属性を使用するときにパスを選択すると、セグメントの作成に使用するグループ (自動車バイヤーと自動車販売業者) が決まります。

ドロップダウンのパスの要因

Data 360 は、データグラフのオブジェクト間のすべてのリレーションのモデルである属性ライブラリメタデータ (ALM) からドロップダウンを取得します。ALM は、コンテナオブジェクトとセグメント化オブジェクト間のすべてのパスを検索し、信頼性の高い一義的な結果セットを生成するパスのみを保持します。

表示されるパス:

  • ホップがすべてセグメント化オブジェクトに向かって狭くなっているパス (各ホップで多数のレコードが 1 つにマッピングされる)
  • すべてのホップがコンテナから離れた場所に展開されているパス (各ホップで 1 つのレコードを多数のレコードに対応付ける)

表示されていないパス:

  • 両方の方向を混在させるパス。あるホップでは絞り込まれ、別のホップでは展開されます。方向を混在させると、行が増殖したり折りたたまれたりし、レコードが重複したりあいまいになったりする可能性があります。
例

マーケティング担当者は、最近キッチン家電を購入した顧客にお礼のオファーを送信したいと考えています。Product コンテナ (Product.Category = Kitchen Appliances) の検索条件を使用して、Individual にセグメントを作成します。

商品はデータモデルの 2 つの異なるリレーションを介して個人に接続されるため、[コンテナパス] ドロップダウンには次の 2 つのパスが表示されます。

  • Product.OrderId > Order.PurchaserId > Individual.Individual ID — キッチン用品を購入した個人。
  • Product.CaseId > Case.SubmittedBy > Individual.Individual ID — キッチン用品について苦情を述べた個人。

どちらのパスも有効ですが、利用者は大きく異なります。お礼キャンペーンの場合、マーケティング担当者は最初のパスを選択します。サービス回復キャンペーンの場合、2 番目のキャンペーンを選択します。

個人取引先のターゲティング

Winter '26 以降、直接 DMO 関連リストの強化を個人取引先オブジェクトにリンクできます。リレーションが正しく効果的に設定されるように、次の考慮事項に従ってください。

一致項目を使用して、DMO と個人取引先などのレコードページ間でデータをリンクできます。個人取引先は、取引先オブジェクトと取引先責任者オブジェクトの項目を 1 つのビューにまとめます。そのため、個人取引先の一致する項目を選択すると、取引先ソースと取引先責任者ソースから使用可能な項目のリストが表示されます。これらの項目を使用して、取得元 DMO と取得先個人取引先オブジェクトのレコードを照合できます。

これにより、リレーションを作成するための柔軟性が向上します。たとえば、ビジネス中心の取引先項目 (AccountNumber など) または個人中心の取引先責任者項目 (PersonEmail など) に基づいてレコードを照合できます。

ソース DMO には、対象個人取引先オブジェクトで選択した一致項目に論理的に対応する項目が含まれている必要があります。たとえば、一致項目を PersonEmail に設定した場合、DMO には顧客のメールアドレスを含む項目が必要です。

一致項目 ソース オブジェクト 使用事例
ContactId 取引先責任者 ソース DMO が個人の Salesforce 連絡先 ID に関連付けられている場合にお勧めします。
AccountId 取引先 ソース DMO が個人取引先レコードの Salesforce 取引先 ID に関連付けられている場合にお勧めします。
PersonEmail 取引先責任者 顧客のメールアドレスに基づいてレコードを照合するための一般的で効果的な選択肢。

外部システムからの顧客の最近のサポートチケットのリストを個人取引先レコードページに表示するとします。サポートチケットデータは、Customer_Email__c 項目を含む外部チケット DMO にあります。次の手順に従って設定します。

Microsoft Azure コンテナ SAS トークンの作成

コンテナの共有アクセス署名 (SAS) トークンによって、Microsoft Azure Storage コンテナのファイルへのアクセス権限が付与されます。

SAS トークンを作成する手順は、次のとおりです。

  1. Microsoft Azure ポータルにサインインし、Microsoft Azure Storage アカウントに移動します。
  2. Microsoft Azure コンテナで、[設定] から [共有アクセストークン] をクリックします。
  3. SAS トークンを下記の設定で作成します。
    • 署名方法—アカウントキー
    • 必須権限—参照、更新、リスト、削除、タグ。タグ権限を追加するには、Azure Storage Explorer アプリケーションを使用してトークンを生成し、「Get the SAS for a blob container (Blob コンテナの SAS の取得)」の手順に従います。各リソース種別でサポートされる権限についての詳細は、「関連トピック」セクションを参照してください。
    • 許可されるプロトコル—HTTPS のみ
  4. Blob SAS トークンおよび Blob SAS Url をコピーします。これらは、「Get the SAS for a blob container (Microsoft Azure Storage サービスの接続の設定)」で使用します。
    Data 360 への接続時に無効なログイン情報エラーを回避するために、期限切れになる前に SAS トークンを再生成することをお勧めします。Data 360 Azure Storage Service コネクタでは、Azure アカウントまたは Azure ファイルトークンはサポートされません。

  1. [データモデル] タブで、[新規] をクリックします。
  2. 作成方法を選択します。ここでは [新規] を選択します。
  3. [次へ] をクリックします。
  4. [オブジェクトの表示ラベル]、[カテゴリ]、[オブジェクトの説明] に詳細を入力します。

    2. プライマリキー項目を選択します。
    3. 必要に応じて、項目の値の提案を有効にします。
  6. [保存] をクリックします。

これでカスタム DMO を使用できます。

Data 360 のデータオブジェクト

Data 360 を使用する場合、データレイクオブジェクト (DLO) やデータモデルオブジェクト (DMO) を含む Data 360 データオブジェクトについて理解すると役立ちます。

オブジェクト 説明 メモ
データレークオブジェクト (DLO) Data 360 に取り込まれるデータのコンテナ。 DLO は Data 360 に取り込まれたデータから自動的に作成されますが、手動で作成することもできます。
非構造化データレイクオブジェクト (UDLO) Data 360 が参照する非構造化データのコンテナ。 UDLO は手動で作成されます。
データモデルオブジェクト (DMO) データストリーム、インサイト、その他のソースから作成されたデータのハーモナイズされたグルーピング。 DLO は DMO にマッピングされます。
非構造化データモデルオブジェクト (UDMO) 非構造化データソースから作成されたデータのグループ。 UDLO は、既存または新規の UDMO に自動的にマッピングされます。
外部データレイクオブジェクト 外部データソースから統合されるデータのメタデータが含まれるストレージコンテナ。 外部 DLO は参照として機能し、外部データソースに物理的に保存されているデータを参照します。

オブジェクトの表示

[データモデル] タブを使用して DMO を表示します。[データレイクオブジェクト] タブを使用して、すべての DLO とマッピングされている DMO を表示したり、DLO を作成したり、DLO に項目を追加したりします。DLO 名を選択すると、そのオブジェクトの最新の状況、以前に更新された日付、DMO に関連付けられているすべてのマッピングが表示されます。オブジェクトで実行されたマッピングを表示することもできます。DLO 項目は削除できません。

DLO がデータストリームに関連付けられている場合、[データレイクオブジェクト] タブから DLO に項目を追加することはできません。このような更新は、[データストリーム] タブで行います。詳細は、「Using an Existing Data Lake Object to Create a Data Stream (既存のデータレークオブジェクトを使用したデータストリームの作成)」を参照してください。

データマッピング

すべてのデータストリームによって取り込まれたデータは、データレークオブジェクト (DLO) に書き込まれます。データストリームを作成したら、DLO をデータモデルオブジェクト (DMO) に関連付ける必要があります。リレーションによりマッピングされた項目およびオブジェクトのみをセグメンテーションと有効化で使用できます。

[データストリーム] 詳細ページか、データストリームをリリースした後に、[データマッピングを開始] をクリックします。

[項目] マッピングキャンバスでは、DLO と DMO の両方を参照できます。これらをマッピングするには、DLO の名前をクリックし、対象 DMO に接続します。たとえば、この方法を使用して、DLO の名を対象の [名] 項目にマッピングすることができます。

  • Data 360 のデータマッピング要件
    マッピングとリレーションは、標準データバンドルを使用してリリースされるデータストリームに対してのみ自動的に設定されます。一方、カスタムデータストリームの場合は必要なマッピングとリレーションが適切に設定されるようにする必要があります。
  • データマッピングのベストプラクティス
    Data 360 での適切なデータマッピングは、成功のための重要なコンポーネントです。セグメンテーション、インサイト、ID 解決のために Data 360 全体でデータを確実に使用するには、データマッピングのベストプラクティスに従います。
  • データマッパービュー
    Data 360 でデータをマッピングするときは、テーブルまたはビジュアルビューを選択します。
  • 項目の対応付けのデータ型
    データレイクオブジェクト (DLO) をデータモデルオブジェクト (DMO) にマッピングする場合、DLO 項目と DMO 項目のデータ型に互換性がある必要があります。
  • データモデルオブジェクトのマッピング
    データマッピングにより、データレークオブジェクト (DLO) 項目がデータモデルオブジェクト (DMO) 項目に関連付けられ、ソースデータを 1 つの標準化された Customer 360 データモデルに統合できます。
  • 自動マッピング
    Data 360 での自動マッピングでは、データレークオブジェクト (DLO) フィールドが正しいデータモデルオブジェクト (DMO) フィールドにマッピングされます。項目のマッピング中に特定の DMO を選択すると、Data 360 によって項目のマッピングが計算されて適用されます。その後、必要な変更を行い、対応付けを保存できます。
  • UDLO と UDMO の対応付け
    非構造化データを消費する Data 360 のワークロードは、非構造化データモデルオブジェクト (UDMO) を介して消費します。UDLO を作成する場合、UDLO を UDMO に対応付けます。
  • Data 360 オブジェクトと項目の対応付けの管理
    データモデルオブジェクト (DMO) またはデータレークオブジェクト (DLO) に関連付けられたオブジェクトと項目の対応付けを編集または削除します。マッピングとオブジェクトを管理して、データの正確性を確保し、データモデルの整合性を維持します。
  • 非構造化データレイクオブジェクトの削除
    非構造化データレイクオブジェクト (UDLO) はいつでも削除できます。
  • Data 360 ページからの項目の削除
    FlexiPage は Lightning ページに関連付けられたメタデータを表します。Lightning ページは、Lightning コンポーネントを含む領域で構成される、カスタマイズ可能な画面です。Lightning ページは、UnifiedIndividual や UnifiedAccount などの統合オブジェクトを含む派生データモデルオブジェクト (DMO) に対してのみ作成されます。Data 360 ページからフィールドを削除して、フィールドの対応付けを削除できます。

データマッピングのベストプラクティス

Data 360 での適切なデータマッピングは、成功のための重要なコンポーネントです。セグメンテーション、インサイト、ID 解決のために Data 360 全体でデータを確実に使用するには、データマッピングのベストプラクティスに従います。

計画に関する考慮事項

Data 360 でデータを DMO にマッピングする前に、事前に計画を立ててください。

  • レポート、オフラインデータ辞書、またはソースシステムインベントリを作成します。
  • 項目レベルのデータを特定し、その精度を分析します。
  • データをマッピングできる使用可能な標準データモデルオブジェクト (DMO) と関連項目を確認します。
    • ギャップが特定された場合は、カスタム項目を追加して標準オブジェクトを拡張するか、[データモデル] タブで新しいカスタム DMO を作成します。カスタムデータモデルオブジェクトの作成に関する手順を参照してください。
  • 各データソースと対応する項目が、統合するオブジェクト (個人オブジェクトや取引先オブジェクトなど) にどのように関連するかを検討します。
    • たとえば、Web エンゲージメントデータを取り込む場合、このデータが個人 DMO、または個人 DMO にマッピングされている属性にマッピングされることを確認して、サイトでのユーザーの消費や動作を確実に理解できるようにします。
    • マッピングの下流の使用事例を考慮します。たとえば、青いシャツを閲覧した個人のセグメントを作成するには、エンゲージメントデータを個人 DMO にマッピングします。
  • インポートするデータセットに対応する DLO またはスキーマを設定するときに、カテゴリまたはデータ型を設定します。DMO は、マッピングされている最初の DLO からカテゴリを継承します。次のカテゴリ間の後続の対応付けを作成できます。
    • プロファイル DLO はプロファイル DMO または他の DMO に対応付けることができますが、エンゲージメント DMO に対応付けることはできません。
    • エンゲージメント DLO はエンゲージメント DMO にのみ対応付けることができます。
    • 他の DLO はプロファイル DMO または他の DMO に対応付けることができますが、エンゲージメント DMO に対応付けることはできません。

個人取引先項目の対応付け

個人取引先では、取引先オブジェクトと取引先責任者オブジェクトの両方の項目が使用されます。個人取引先は人を表すため、個人取引先項目を個人 DMO に対応付けます。

  • 取引先責任者オブジェクトを個人 DMO に対応付け、取引先責任者 ID を個人 ID として使用します。この対応付けにより、有効化時に取引先責任者 ID が Marketing Cloud Engagement の登録者キーになります。また、後処理 SQL が制限され、新しい登録者キーが導入されるリスクが軽減されます。
  • 取引先責任者オブジェクトを取引先責任者 DMO に対応付けます。
  • 取引先オブジェクトを取引先 DMO に対応付けます。

変換とリレーション

モデルを確立したら、数式項目の調整、変換の作成、データリレーションの確認が必要かどうかを確認します。

  • ソースデータを変換して、標準データモデルにマッピングする方法を確立します。すべてのソースシステムが、正規化されたエクスポートオプションを備えていたり、データを同程度に正規化したりするわけではありません。詳細は、正規化および非正規化されたデータに関するヘルプトピックを参照してください。
  • [データモデル] タブのグラフビューで、オブジェクトとリレーションを包括的に視覚化します。多くの場合、1 つのオブジェクトを検査するのではなく、データモデルのマッピングされたすべてのオブジェクトのリレーションや不足を包括的に検査することをお勧めします。詳細は、データモデルオブジェクトの表示に関するヘルプトピックを参照してください。

トラブルシューティング

  • DLO のマッピングを試行中、オブジェクトセレクターに特定の対象 DMO が表示されない場合は、DLO のカテゴリが、対象 DMO のカテゴリのいずれかと一致していることを確認します。UI には、互換性のあるカテゴリで絞り込まれた選択可能な DMO のリストが表示され、互換性のないカテゴリを持つオブジェクトは除外されます。
例 Sales Order (販売注文) は、エンゲージメントカテゴリの Order-Headers (注文ヘッダー) という DLO に最初にマッピングされます。この DLO により、Sales Order (販売注文) がエンゲージメントカテゴリに割り当てられます。その後、Sales Order (販売注文) DMO にマッピングできるのはエンゲージメントカテゴリの DLO のみです。

データマッパービュー

Data 360 でデータをマッピングするときは、テーブルまたはビジュアルビューを選択します。

必要なエディション

使用可能なインターフェース: Starter Edition を除くすべてのエディションの Lightning Experience で

テーブルビューとビジュアルビューを切り替えるには、データマッピングページのビュードロップダウンメニューを使用します。ビューを変更する前に変更内容を保存してください。

テーブルビュー

テーブルビューでは、データソースオブジェクト (DSO) やデータモデルオブジェクト (DMO) を列形式で選択できます。ポインターデバイスやビジュアルフィードバックを使わなくてもマッピングできます。マッピングは、データモデルを 1 つずつ管理します。次のアクションは、キーボードを使用して実行できます。

  • 特定の項目のデータモデルオブジェクトを検索する。
  • データストリームのソース項目とデータモデルのオブジェクト項目間のマッピングを作成する。
  • データストリームソース項目とデータモデルオブジェクト項目間の既存のマッピングを削除する。
  • データモデルオブジェクトのカスタム項目を作成する。

項目のマッピングに追加する新しいデータモデルオブジェクトを選択したり、カスタムモデルオブジェクトを追加したりするには、ビジュアルビューを使用します。

ビジュアルビュー

ビジュアルビューでは、ドラッグ操作で DSO と DMO 間の接続を作成できます。

データモデルオブジェクトのプロパティの編集

データモデルオブジェクト (DMO) のプロパティは、[データモデル] タブまたはデータマッピングページで編集できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
  1. Data 360 で、[データモデル] タブに移動します。
  2. DMO を開いて [編集] をクリックします。
  3. [オブジェクトの表示ラベル]、[オブジェクトの説明]、[項目表示ラベル]、[値の提案を有効化] のいずれかのプロパティを編集します。

    [値の提案を有効化] オプションは、テキストデータ型の項目でのみ使用できます。このオプションを有効にすると、セグメントビルダーで [値] 項目にテキストを入力するときに、ドロップダウンリストで提案された値を選択できます。

    メモ DMO 内で項目の表示ラベルを編集しても、これらの変更は関連リストに自動的に反映されません。関連リストには、作成時の初期設定に基づいてデータが表示されます。更新された DMO 項目の表示ラベルが正しく表示されるようにするには、DMO 項目の表示ラベルを変更した後に、レコード詳細ページで [関連リスト] を再作成または再設定します。
  4. DMO カテゴリを変更するには、「データモデルオブジェクトのカテゴリの変更」を参照してください。
  5. 項目を削除するには、[削除] アイコン をクリックします。
    標準 DMO の標準項目は削除できません。
  6. 変更内容を保存します。
    [プロパティを編集] アイコンをクリックして、データマッピングページから直接 DMO プロパティを編集することもできます。

データモデルオブジェクトリレーション

Data 360 データモデルオブジェクト (DMO) には、他の DMO との標準リレーションまたはカスタムリレーションを設定できます。リレーションは一対一リレーションまたは多対一リレーションとして構成できます。リレーションとその状況は DMO レコードの [リレーション] タブで表示できます。

リレーションのカーディナリティ

リレーションを作成するときは、カーディナリティを慎重に選択します。2 つの DMO 間のカーディナリティは、セグメンテーションと有効化に影響します。リレーションの作成後にカーディナリティを変更することはできません。

たとえば、A と B という 2 つのオブジェクト間のリレーションがあり、オブジェクト A にオブジェクト B の各レコードに対応する複数のレコードが含まれている場合、多対一のリレーションが選択されます。

例 連絡先メール DMO と個人 DMO 間のリレーションは、連絡先メール DMO に各個人 DMO レコードに対応する 1 つ以上のレコードが含まれる可能性があるため、多対一として構成されます。同様に、SalesOrder DMO と個人 DMO 間のリレーションは、各個人レコードに複数の注文レコードが含まれる可能性があるため、多対一として構成されます。

標準リレーション

Data 360 データモデルには、いくつかの標準リレーションが含まれます。関連オブジェクト項目がマッピングされるまで標準リレーションは無効です。リレーションの両方の項目へのマッピングが 1 つ以上あると、有効化されます。リレーションの 1 つ以上の項目のマッピングが削除された場合、リレーションは無効化されます。標準リレーションは無効化できますが、削除することはできません。

標準リレーションは、有効化されている場合にのみ [リレーション] タブに表示されます。

例 Data 360 データモデルには、販売注文 DMO の販売注文.請求先メールと連絡先メール間のリレーションが含まれます。連絡先メール DMO の連絡先メール ID。両方の項目に項目のマッピングが存在する場合にこのリレーションが有効になり、[リレーション] タブに表示されます。

カスタムリレーション

[リレーション] タブで、DMO 間のカスタムリレーションを作成します。

カスタムリレーションを無効にすることや削除することもできます。無効化されたリレーション、いつでも再有効化できます。リレーションを削除すると、完全に削除されます。リレーションの 1 つ以上の項目のマッピングが削除された場合、カスタムリレーションは自動的に削除されます。

DMO リレーション状況

DMO のペア間には 1 つ以上のリレーションを設定できますが、DMO 項目の特定のペア間には 1 つのリレーションのみを設定できます。DMO 項目間のリレーション状況は有効または無効にできます。

[リレーションを編集] ウィンドウでリレーションの状況を表示します。

リレーション状況が有効で、無効にできる場合は (1)、切り替えスイッチを使用して状態を変更します。リレーションが無効化されると、セグメンテーションや有効化などの下流機能領域で使用できなくなります。ただし、計算済みインサイト、セグメンテーション、有効化で使用されているリレーションは無効化できません。

一部のリレーションは有効になっていても無効化できません (2)。ID 解決プロセスで使用されているリレーションは無効化できません。

デフォルトでは、無効化されたリレーション (3) は表示されず、[無効なリレーションを表示] が選択されている場合のみ表示されます。切り替えを使用してリレーションを有効化します。

DMO リレーションの制限

Data 360 では、各 DMO で有効にできるカスタムリレーション数が制限されます。DMO が有効なリレーションの制限に達した場合、カスタムリレーションの追加や無効なリレーションの有効化はできません。標準および無効なリレーションの数に制限はありません。

カスタムリレーションの制限は、DMO に関連付けられた直接リレーションにのみ適用され、間接リレーションには適用されません。カスタムリレーションをさらに追加するには、DMO を複数のレベルに整理し、データモデルにネストされた構造を作成します。たとえば、各 DMO が 25 個のカスタムリレーションに制限されていて、30 個が必要な場合、どの 5 個の DMO をグループ化するかを決定します。親 DMO から、25 個のカスタムリレーションを作成します。5 個のグループ化された DMO の新しい親として、いずれかの子を指定します。

Data 360 は、パッケージ化されたデータバンドルが組織にリリースされるときにリレーションの制限をチェックします。リレーションの制限に達すると、パッケージのインストールが失敗します。

CRM スターターバンドルなどの Salesforce スターターデータバンドルには、標準リレーションのみが含まれます。標準リレーションは DMO リレーションの制限に含まれないため、スターターバンドルのインストールは失敗しません。

データモデルオブジェクトの表示

Data 360 データモデルオブジェクトは、リストビューまたはグラフビューで表示できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

[データモデル] タブでは、リストビューとグラフビューを切り替えることができます。グラフビューには、Data 360 内のマッピングされたデータモデルオブジェクトとそのリレーションのエンティティリレーション図が表示されます。

リストビューを使用すると、データモデルオブジェクト (DMO) および関連する詳細をリストで表示できます。オブジェクトの表示ラベル、オブジェクト API 参照名、そのオブジェクトがマッピングされているデータストリーム、種別、状況をすべて 1 つのビューで確認できます。リストビューには [すべて] と [マッピング済み] の 2 つがあります。[すべて] ではすべての DMO が表示され、[マッピング済み] でマッピングのある DMO のみが表示されます。

グラフビューを使用すると、データを画像形式で表示して、インスタンス内のすべてのデータがどのように接続されているかを簡単に視覚化できます。各データモデルオブジェクトノードの色は、[プロファイル]、[エンゲージメント]、または [その他] カテゴリを表します。リストビューと同じように、各ノードをクリックして詳細を表示したり、編集したりできます。キャンバスまたはミニマップを使用して、ドラッグおよび拡大/縮小できます。マッピングされた DMO のみがこのビューに表示されます。

リレーションを表示、編集、または無効化するには、リストビューまたはグラフビューから DMO を選択します。[リレーション] に移動して、[編集] または [新規] をクリックします。オブジェクトと項目間のリレーションを作成します。
