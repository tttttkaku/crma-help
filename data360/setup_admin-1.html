Azure での Databricks のプライベートネットワークルートの追加

Private Connect for Data 360 を使用して、Databricks データソースと Data 360 テナントを専用のネットワーク接続で接続します。 Data 360 インスタンスの数に関係なく、特定のインスタンスへの 1 つの接続を作成します。Databricks フェデレーション接続またはデータ共有を設定する前に、ネットワークルートを確立します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
Databricks ネットワークルートを作成する 「Data Cloud アーキテクト」権限セットおよび「外部接続の管理」または「アプリケーションのカスタマイズ」権限。
Databricks 環境を管理する Databricks アカウント管理者

前提条件

  • Java Database Connectivity (JDBC) エンドポイントと Azure Blob エンドポイントの仮想プライベートクラウド (VPC) エンドポイントサービス名を作成しました。詳細については、『 Implementation Guide 』を参照してください。

この PNR の Data 360 プリンシパル ID が AWS で許可されるプリンシパルとして設定されている。詳細については、『 Implementation Guide 』を参照してください。

制限事項

  • 特定の Databricks URL のプライベートネットワークルート (PNR) の数は、Data 360 機能ドメインごとに 1 つに制限されます (Data 360 組織ごとではありません)。

このトピックでは、完了する必要がある Salesforce の手順のみを説明します。すべてのソースでエンドツーエンドのプロセスを完了するには、『Private Connect Implementation Reference Guide for Databricks on Azure』を参照してください。

ステップ 1: Databricks プライベート接続の作成

Data 360 で Amazon Web Services (AWS) VPC エンドポイントサービスとの Databricks プライベート接続を設定します。

  1. アプリケーションランチャーから、[Data Cloud] を選択します。
  2. [設定] から、[Data Cloud 設定] を選択します。
  3. Data Cloud の [設定] の [外部インテグレーション] で、[プライベートコネクト] を選択します。
  4. [新規] を選択します。ボタンが表示されない場合は、ライセンス済み PNR の最大数を超えています。
  5. [Add Private Network Route]ページで、[Databricks]タイルを選択します。
  6. [Select a Network (ネットワークを選択)] パネルで、[Azure]、[Add Private Network Route (プライベートネットワークルートを追加)] の順に選択します。
  7. [Databricks プライベートネットワークルートを設定] ページに移動します。
  8. ステップ 2: Account に移動し、次の手順を実行します。
    1. [Databricks Account URL]フィールドに、DatabricksアカウントのURLを入力します。
    2. [VPC Endpoint Service Name] フィールドに、先ほど作成した AWS VPC Endpoint を入力します。例: com.amazonaws.vpce.<region>.<vpc-endpoint-service-name>
  9. 「ステップ 3: 内部フェーズ」に移動し、次の手順を実行します。
    1. [Azure Blob URL] 項目に、Azure アカウントの URL を追加します。例: https://.blob.core.windows.net//<storage-account-name>.blob.core.windows.net/<contatiner-name>/<blob-name>
    2. [VPC Endpoint Service Name] フィールドに、「AWS VPC Endpoint」と入力します。例: com.amazonaws.vpce.<region>.<vpc-endpoint-service-name>
  10. 変更を保存し、このブラウザータブを開いたままにします。ネットワークルートのプロビジョニングには数分かかります。次のステップは、Amazon Virtual Private Cloud で接続要求を確認することです。

ステップ 2: 接続要求の確認と設定の確認

プライベート接続が機能していることを確認します。

ステップ 1 を完了します。

  1. Amazon VPCコンソールにアクセスします。
  2. Databricks のエンドポイントサービスおよび Databricks 内部フェーズに移動します。
  3. [エンドポイント接続]タブで、DatabricksおよびDatabricksの内部フェーズの待機中の接続要求に移動します。次に、次の手順を実行します。
    1. Databricks エンドポイントの横にあるチェックボックスをオンにします。
    2. [Actions (アクション)] ドロップダウンを選択します。
    3. [Accept Endpoint Connection Request (エンドポイント接続要求を受け入れる)] を選択します。Databricks Internal Stage でこの手順を繰り返します。
  4. Data Cloud の [設定] に戻ります。
  5. [Data Cloud Setup Refresh] ボタンを選択して、設定を更新します。ブラウザーページを更新しても効果はありません。
  6. 設定を確認するには、Data Cloud の [設定] に移動し、[プライベートコネクト] を選択します。このダッシュボードには、Databricks と Databricks の内部フェーズの両方の PNR の状況が表示されます。
  7. 両方の PNR が接続済みとしてリストされていることを確認します。個々の PNR レコードを選択して、その詳細を表示できます。

プライベートコネクトの設定が完了しました。Data 360でDatabricks接続を作成するには、Databricksデータ統合接続を設定し、切り替えを有効にしてプライベート ネットワーク ルート(PNR)を表示します。[ネットワークルート] ドロップダウンから作成した PNR を選択します。

Azure での Snowflake のプライベートネットワークルートの追加

Private Connect for Data 360 を使用して Snowflake インスタンスと Data 360 テナントを専用ネットワークルートに接続します。 複数の Data 360 インスタンスがある場合でも、特定のインスタンスへのルートを 1 つ作成します。Snowflake フェデレーション接続またはデータ共有を設定する前に、プライベートネットワークルート (PNR) を確立します。

必要なエディション

使用可能なエディション: Data 360 をサポートするエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
Snowflake ネットワークルートを作成する 「Data Cloud アーキテクトと外部接続の管理」または「アプリケーションのカスタマイズ」権限
Snowflake 環境を管理する Snowflake 管理者

制限事項

  • Snowflake URL のプライベートネットワークルート (PNR) の最大数は、Data 360 機能ドメインごとに 1 つです (Data 360 組織ごとではありません)。
  • Data 360 を Snowflake インスタンスに接続するには、仮想プライベートクラウド (VPC) エンドポイント ID を組織の許可リストに追加する必要があります。
    • VPC ID は、既存のプライベートネットワークルートの詳細ページから取得できます。
    • または、内部 IP アドレス範囲 10.0.0.0/8 を Snowflake ネットワークポリシーの許可リストに追加します。この予約済みアドレス範囲を使用するのはプライベート ネットワークのみです。詳細は、Snowflake ドキュメントの「Controlling network traffic with network policies (ネットワークポリシーを使用したネットワークトラフィックの制御)」を参照してください。

このトピックでは、Salesforce の手順のみを説明します。すべてのソースでエンドツーエンドの手順を完了するには、『 Private Connect Implementation Reference Guide for Snowflake on Azure 』を参照してください。

前提条件:

  • 使用量ベースの Data 360 を使用します。

  • Java Database Connectivity (JDBC) エンドポイントと Azure Blob エンドポイントの VPC エンドポイントサービス名があります。この設定についての詳細は、『 Implementation Guide 』を参照してください。

  • この PNR の Data 360 プリンシパル ID が Amazon Web Services (AWS) で許可されているプリンシパルとして設定されている。この設定についての詳細は、『 Implementation Guide 』を参照してください。
  1. アプリケーション ランチャーで、[Data Cloud]を選択します。
  2. [設定] から、[Data Cloud 設定] を選択します。
  3. Data Cloud の [設定] から、[管理ツール] を展開し、[プライベートコネクト] を選択します。
  4. [新規] を選択します。

    ライセンス済みプライベートネットワークルートの最大数を超えた場合、[新規] ボタンは表示されません。より多くのプライベートネットワークルートを取得するには、Salesforce の営業担当者にお問い合わせください。

  5. [プライベートネットワークルートを追加] ページで、[Snowflake] タイルを選択します。
  6. [Select a network]パネルで、[Azure]を選択し、[Add Private Network Route]を選択します。
  7. [Snowflake プライベートネットワークルートを設定] ページで、次の値を入力します。
    1. Route Name (ルート名): この名前でルートを識別します。
    2. ルート API 参照名: Data 360 は、ルート名に基づいてこの項目に自動入力します。
    3. 説明: 接続の説明を入力します。
  8. 「ステップ 3: アカウント」に移動して、次の手順を実行します。
    1. ［Snowflake Account URL］ フィールドに、Snowflake アカウントの URL を入力します。
    2. [Virtual Private Cloud Endpoint Service Name]フィールドに、先ほど作成したAWS VPCエンドポイントを入力します。例: com.amazonaws.vpce
  9. 「ステップ 4: 内部フェーズ」に移動して、次の手順を実行します。
    1. [Azure Blob URL] 項目に、Azure アカウントの URL を追加します。例: https://.blob.core.windows.net//
    2. [Virtual Private Cloud (VPC) Endpoint Service Name]フィールドに、AWS VPCエンドポイントを入力します。例: com.amazonaws.vpce
  10. 変更を保存し、このブラウザーを開いたままにします。ネットワークルートのプロビジョニングには数分かかります。次のステップは、Amazon Virtual Private Cloud で接続要求を確認することです。
  11. Amazon Virtual Private Cloudコンソールにアクセスします。
  12. Snowflake と Snowflake 内部フェーズの両方のエンドポイントサービスに移動します。
  13. [エンドポイント接続] タブで、待機中の Snowflake の接続要求と Snowflake 内部フェーズに移動します。次に、以下の手順を実行します。
    1. Snowflake エンドポイントの横にあるチェックボックスをオンにします。
    2. ［Actions］ ドロップダウンをクリックします。
    3. [Accept Endpoint Connection Request (エンドポイント接続要求を受け入れる)] をクリックします。要求が表示されない場合は、許可されているプリンシパルとしてプリンシパル ID を追加していることを確認してください。Snowflake 内部フェーズでこの手順を繰り返します。
      30 秒待ってから次のステップに進みます。
  14. Salesforce に戻り、[Data Cloud 設定] に移動します。
  15. 使用する準備が整うまで設定を更新するには、[Data Cloud Setup Refresh] をクリックします。
    ブラウザーを更新しても影響はありません。
  16. 設定を確認するには、Data Cloud の [設定] に移動して、[プライベートコネクト] をクリックします。このダッシュボードには、Snowflake の状況と Snowflake 内部フェーズが表示されます。両方の PNR が接続済みとして表示されることを確認します。個々の PNR レコードをクリックすると、その詳細を表示できます。

プライベートコネクトの設定が完了しました。Data 360 で Snowflake 接続を作成するには、 Snowflake データフェデレーション接続を設定し 、プライベートネットワークルート (PNR) を使用するように切り替えを有効にします。[ネットワークルート] ドロップダウンから作成した PNR を選択します。

メモ ネットワークプロビジョニングが完了したら、Snowflake の統合接続またはデータ共有を作成します。ドメインネームサーバー (DNS) の設定が原因で、統合接続またはデータ共有の作成に進むまでに少し時間がかかる場合があります。

Snowflake on Azure の Salesforce が管理するプライベートネットワークルートの設定

Private Connect Multicloud for Data 360 を使用して、Salesforce が管理するプライベートネットワーク接続を使用して、Data 360 を Snowflake on Azure データソースに接続します。 Data 360 と Snowflake 間のクロスクラウド接続は、Salesforce によって自動的にプロビジョニングおよび維持されます。AWS または Azure での設定は必要ありません。

必要なエディション

使用可能なエディション: Data 360 をサポートするエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
Snowflake ネットワークルートを作成する 「Data Cloud Architect」権限セットおよび「外部接続の管理」または「アプリケーションのカスタマイズ」権限
Snowflake 環境を管理する Snowflake 管理者

  • 各 Snowflake URL は、1 つの Data 360 テナントのみが使用できます。
  • プライベートコネクトマルチクラウドは、一部の Data 360 地域では使用できません。ステップ 1 の「サポートされているリージョン」の表を参照してください。 Snowflake アカウントは、どの Azure リージョンでも実行できます。

ステップ 1: Snowflake 環境の準備

前提条件を確認し、Data 360 でプライベートネットワーク接続を確立するために必要な Snowflake 設定値を収集します。

  1. 次のすべてがあることを確認します。
    1. Business Critical Edition 以降がインストールされた Microsoft Azure で実行されている Snowflake アカウント。
    2. Snowflake アカウントの ACCOUNTADMIN ロール。
    3. サポートされている Data 360 リージョンで実行されている Data 360 テナント。Private Connect Multicloud for Snowflake on Azure は、次の Data 360 リージョンで使用できます。
      サポートされる Data 360 リージョン
      us-west-2 us-east-2 ap-south-1
      us-east-1 ca-central-1 ap-southeast-1
      sa-east-1 eu-west-2 ap-southeast-2
      eu-west-3 eu-central-1 ap-northeast-1
      eu-central-2 eu-north-1 ap-northeast-2
      eu-south-1    
  2. Snowflake で内部フェーズを有効にするかどうかを決定します。

    内部フェーズは、Snowflake がデータステージングに使用する Snowflake 管理ストレージアクセスパスです。Snowflake Internal Stage が非公開のみのアクセス用に設定されている場合 (つまり、ストレージアカウントで公開ネットワークアクセスが無効になっている場合)、有効にします。他のすべての設定で無効のままにします。

    内部フェーズを有効にしている場合は、AccountADMIN として Snowflake で次のコマンドを実行します。

    ALTER ACCOUNT SET ENABLE_INTERNAL_STAGES_PRIVATELINK = TRUE;
  3. Snowflake で ACCOUNTADMIN として次のクエリを実行し、Snowflake プライベートリンク設定を取得します。 
    SELECT KEY, VALUE FROM TABLE(FLATTEN(INPUT => PARSE_JSON(SYSTEM$GET_PRIVATELINK_CONFIG())));

    出力から、次の値を記録します。

    Snowflake の値 Data 360 の値 定義 例
    privatelink-pls-id Snowflake アカウント Azure リソース ID Snowflake アカウントの Azure プライベートリンクサービス名。 sf-pvlinksvc-eastus.00000000-0000-0000-0000-000000000000.eastus.azure.privatelinkservice
    privatelink-account-url Snowflake アカウント URL Snowflake アカウントの非公開 URL。 https://myorg-myaccount.privatelink.snowflakecomputing.com
    privatelink_internal_stage (内部フェーズが有効な場合にのみ表示されます) Snowflake 内部フェーズ Azure リソース ID 内部フェーズをホストする Snowflake 管理ストレージアカウントの完全な Azure リソース ID。 /subscriptions/<subscription-id>/resourceGroups/<resource-group-name>/providers/Microsoft.Storage/storageAccounts/<storage-account-name>
  4. 内部フェーズを有効にした場合は、Snowflake ストレージアカウントの URL を取得します。

    privatelink_internal_stage 出力の <storage-account-name> 値を使用して、URL <storage-account-name>.privatelink.blob.core.windows.net を作成します。この URL を保存します。Data 360 でプライベートネットワークルートを作成するときに必要になります。

ステップ 2: Data 360 でのプライベートネットワークルートの作成

Data 360 で Salesforce が管理するプライベートネットワークルートを作成します。 プロビジョニングには約 10 分かかります。

ステップ 1 を完了します。

  1. アプリケーション ランチャーで、[Data Cloud]を選択します。
  2. [設定] から、[クイック検索] ボックスに「Data Cloud 設定」と入力し、[Data Cloud 設定] を選択します。
  3. [管理ツール] を展開し、[プライベートコネクト] を選択します。
  4. [新規] をクリックします。
  5. [プライベートネットワークルートを追加] ページで、[Snowflake] タイルを選択します。
  6. [Select a Network]パネルで、[Azure]を選択し、[Add Private Network Route]をクリックします。
  7. [Choose Management]メニューから[Salesforce-Managed]を選択し、[Next]をクリックします。
  8. [Snowflake プライベートネットワークルートを設定] ページで、次の値を入力します。
    1. ルート名: ルートを識別する名前を入力します。
    2. ルート API 参照名:Data 360 は、ルート名に基づいてこのフィールドに自動入力します。
    3. 説明: 必要に応じて、接続の説明を入力します。
    4. [ステップ 1: アカウント] で、次の値を入力します。
      • Snowflake アカウント URL: ステップ 1 のprivatelink-account-url値を入力します。
      • Snowflake Account Azure Resource ID: ステップ 1 のprivatelink-pls-id値を入力します。
    5. [ステップ 2: 内部フェーズ] で、内部フェーズの設定を定義します。

      Snowflake ストレージアカウントでパブリックネットワークアクセスが無効になっている場合は、[Internal Stage Enabled (内部フェーズを有効化)] (デフォルト) のままにします。他のすべての設定では [無効] を選択し、このセクションの残りのフィールドをスキップします。

      内部フェーズを有効にした場合は、次の値を入力します。

      • ストレージアカウントの URL: ステップ 1 で取得したストレージアカウントの URL を<storage-account-name>.privatelink.blob.core.windows.net形式で入力します。
      • Snowflake Internal Stage Azure Resource ID: ステップ 1 のprivatelink_internal_stage値を入力します。
  9. 設定を保存します。

    Salesforce は、Snowflake アカウント用と内部フェーズ用の 2 つの Azure プライベートエンドポイントのプロビジョニングを開始します。プロビジョニングには約 10 分かかります。プロビジョニングの処理中は、プライベート ネットワーク ルートの詳細ページに [Waiting for the Azure Resource ID to be provisioned for each Azure Resource ID (Azure リソース ID フィールドごとに Azure リソース ID がプロビジョニングされるのを待機しています)] が表示されます。

ステップ 3: エンドポイントの承認と接続の検証

プロビジョニングが完了したら、Snowflake で非公開エンドポイントを承認し、ネットワークポリシーを更新して、接続を検証します。

ステップ 2 を完了し、プロビジョニングが完了するまで待ちます。プライベートネットワークルートの詳細ページに 2 つの Azure リソース ID 値が表示されたら、プロビジョニングは完了です。

  1. Snowflake アカウントエンドポイントを承認します。
    1. Data 360 のプライベート ネットワーク ルートの詳細ページで、Snowflake アカウント エンドポイントの Azure リソース ID をコピーします。
    2. Snowflake アカウントの非公開エンドポイントの認証を要求するには、Snowflake サポートに連絡し、コピーした Azure リソース ID を入力します。
  2. 内部フェーズエンドポイントを承認します。
    1. Data 360 のプライベート ネットワーク ルートの詳細ページで、Snowflake 内部フェーズ エンドポイントの Azure リソース ID をコピーします。
    2. Snowflake で、ACCOUNTADMIN として次のコマンドを実行します。 
      SELECT SYSTEM$AUTHORIZE_STAGE_PRIVATELINK_ACCESS('<stage-private-endpoint-resource-id>');
  3. Data 360 が接続に使用する Snowflake ユーザーの Snowflake ネットワークポリシーを更新します。

    接続は、ネットワークポリシーで Salesforce が管理する必須の非公開エンドポイントが許可されている場合にのみ成功します。内部フェーズを有効にした場合は、追加するエンドポイントが 2 つ、それ以外の場合は 1 つです。

    1. AZURELINKID タイプのネットワーク規則を作成します。
    2. Snowflake アカウントの非公開エンドポイントの Azure リソース ID をネットワークルールの [VALUE_LIST] プロパティに追加します。
    3. そのネットワーク ルールを ALLOWED_NETWORK_RULE_LIST プロパティに含めるネットワーク ポリシーを作成します。
  4. 接続を検証します。
    1. Snowflake アカウントエンドポイントが認証されていることを確認します。Snowflake サポートに指定した Azure リソース ID が出力に表示されます。 
      SELECT SYSTEM$GET_PRIVATELINK_AUTHORIZED_ENDPOINTS();
    2. 内部フェーズを有効にした場合は、内部フェーズエンドポイントが認証されていることを確認します。 
      SELECT SYSTEM$GET_STAGE_PRIVATELINK_AUTHORIZED_ENDPOINTS();

両方のエンドポイントが認証され、ネットワークポリシーが更新されたら、Snowflake Zero Copy Query Federation 接続を設定します。

Data 360 での一般的な設定タスク

データソースのプロビジョニングと接続に加えて、Data Cloud の [設定] で完了するその他の作業について説明します。

  • Data 360 クエリの会計年度カレンダーオプション
    標準またはカスタムの会計年度カレンダーオプションを使用して、Data 360 クエリで会計年度を処理する方法を設定します。これらの設定により、クエリ結果をカレンダー年ではなく組織の会計期間に合わせることができます。
  • Data Cloud での通貨の使用
    Data Cloud では、Salesforce CRM 組織で設定された通貨と静的為替レートを使用して、データ変換、計算済みインサイト、セグメンテーション、レポート、その他のプロセスに適用します。
  • Data 360 タイムゾーン
    Data 360 では、セグメントと有効化を公開および更新するときに Salesforce で設定されたタイムゾーンが使用されます。セグメントキャンバスでセグメントに追加された日付と時刻でも Salesforce のタイムゾーンが使用されます。Data 360 のタイムゾーンを変更するには、Salesforce でタイムゾーンを変更します。
  • 制御およびメタデータ変更イベント
    Flow Builder で Data 360 データの通知を設定し、Data 360 の状況を表示するレポートを作成します。
  • 許可リスト登録

システムレベルの権限とデータスペースアクセス

「すべてのレコードの参照 (VAR)」や「すべてのレコードの編集 (MAR)」などのシステムレベルの権限では、ユーザーは自動的にデータスペースに関連付けられません。ただし、これらの権限を持つユーザーは、システムレベルの権限によって付与された権限に従ってデータスペース対応オブジェクトを照会できます。データスペースの割り当てでは、引き続きデータスペース範囲の機能と管理操作へのアクセスを制御します。

データスペース範囲の機能とリソースにアクセスするには、Data Cloud データスペース管理を使用してユーザーを明示的に割り当てる必要があります。VAR や MAR などのシステムレベルの権限を持つユーザーは、付与された権限に基づいてデータスペース対応オブジェクトを照会できます。

この動作により、データスペースのアクセス制御は、コンプライアンスを重視するマルチテナント環境で引き続き適用されます。

データスペース対応機能の請求に関する考慮事項

請求目的では、特定のデータスペースに関連付けられたオブジェクトの絞り込まれたバージョンがダウンストリームプロセスで使用されている場合でも、ソースオブジェクトのすべてのレコードがカウントされます。これは、オブジェクトのデータスペース固有のバージョンがそのソースオブジェクトの仮想ビューであるためです。データスペース固有のオブジェクトへのクエリでは、オブジェクトに保存されているすべてのレコードから作成されたソースオブジェクトのデータの絞り込まれたビューが返されます。

例

100 件のレコードを含むデータレイクオブジェクト (DLO) が 2 つの異なるデータスペースに関連付けられているとします。あるデータスペースでは、DLO の絞り込まれたビューに 75 件のレコードが含まれています。2 番目のデータスペースでは、DLO の絞り込まれたビューに 50 件のレコードが含まれています。ただし、請求目的でカウントされるレコード数は 100 レコードです。

データスペース対応 Data Cloud 機能へのアクセスの管理

Data Cloud 標準権限セットのデフォルトでは、事前設定済みのオブジェクト権限を使用して、Data Cloud 機能へのアクセスを制御します。データスペースの機能権限を変更して、権限セットに割り当てられた各データスペースでの機能へのアクセスをさらに制限できます。

機能へのアクセスは、オブジェクト権限を持つ権限セットレベルと、機能権限を持つ権限セット内のデータスペースレベルで管理されます。

オブジェクト権限を使用した権限セットでのデフォルト機能アクセス権の設定

オブジェクト権限は、権限セットに関連付けられているすべてのデータスペースにデフォルトで適用されます。権限セットのオブジェクト権限を更新するには、[設定] で権限セットを選択して [オブジェクト設定] に移動します。

考慮事項

機能のいずれかのオブジェクトに対するオブジェクト権限が「すべてのレコードの参照」または「すべてのレコードの編集」である場合は、機能権限を適用できません。オブジェクト権限が「すべてのレコードの参照」に設定されている場合、機能権限の「参照」アクセス権設定が上書きされます。オブジェクト権限が「すべてのレコードの編集」に設定されている場合、「カスタマイズ」アクセス設定が上書きされます。

オブジェクト権限を変更しても、関連付けられたデータスペースの機能権限は変更されません。たとえば、有効化定義オブジェクトに対するオブジェクト権限を [表示] から [作成] に変更した場合、関連付けられたデータスペースの機能権限の [カスタマイズ] チェックボックスは変更されません。権限セットに割り当てられたユーザーが有効化をカスタマイズできるようにするには、システム管理者が、関連付けられた各データスペースの機能権限で [有効化時にカスタマイズ] を手動で設定する必要があります。

機能権限を使用した権限セットの特定のデータスペース内のアクセスの制限

機能権限はオブジェクト権限を上書きし、特定のデータスペース内のアクセスをさらに制限するために使用されます。機能権限は、設定されているデータスペース内でのみ機能します。権限セットのオブジェクト権限で許可されているアクセス権よりも高い権限を付与するために機能設定を使用することはできません。

機能権限は、[表示] と [カスタマイズ] の 2 つの設定を使用して、アクセスレベルを制御します。これらの設定は、機能の主オブジェクトに対するオブジェクト権限と関連しています。権限セットのオブジェクト権限によって機能の主オブジェクトに対する「参照」アクセス権が付与される場合、関連付けられたデータスペースの機能権限で「参照」を使用できます。[表示] を選択解除すると、データスペース内のその機能の参照アクセス権が削除されます。権限セットに割り当てられたユーザーは、データスペースに関連付けられたデータを表示できません。オブジェクト権限に [作成]、[編集]、または [削除] が含まれている場合、機能権限で [カスタマイズ] を使用できます。[カスタマイズ] をオフにすると、機能内のデータを作成、編集、または削除する権限が削除されます。

コンパニオン組織のデータスペースについて

メタデータがコンパニオン組織と共有されるデータスペースの一部である場合、メタデータは Data 360 ホーム組織とその接続されたコンパニオン組織間でのみ同期されます。メタデータ同期により、コンパニオン組織は共有データスペースで Data 360 オブジェクトのデータを参照できます。

データスペースを共有するとどうなりますか?

コンパニオン組織に同じ名前のデータスペースが作成されます。コンパニオン組織は、データスペースに関連付けられた Data 360 メタデータ、オブジェクト、レコードにアクセスして、Data 360 の機能で使用できます。

どのデータスペースをコンパニオン組織と共有できますか?

データを取り込むために必要なデータスペース、またはコンパニオン組織と共有するメタデータ、オブジェクト、レコードが含まれるデータスペースのみを選択します。不要な処理コストを回避するため、不要なデータスペースは選択しないでください。

データスペースをコンパニオン組織と共有していない場合はどうなりますか?

コンパニオン組織とスペースを共有していない場合、コンパニオン組織の接続は有効ではなく、メタデータは Data 360 と同期されません。 データスペースを共有していない場合、接続状況は [不完全] と表示されます。

データスペースの共有を解除するとどうなりますか?

コンパニオン組織と同期されたデータスペースの共有を解除すると、Data 360 ホーム組織はそのデータスペースに保存されたメタデータを取り込みません。メタデータはコンパニオン組織から削除され、データスペースはコンパニオン組織から削除されます。すべてのデータスペースの共有を解除すると、コンパニオン接続は有効ではなくなります。

ユーザーのサブセットを移行するには、サブグループを定義する条件を追加します。

  1. [設定] から、[クイック検索] ボックスに「ユーザー管理設定」と入力し、[ユーザー管理設定] を選択します。[ユーザーアクセスポリシー] 設定と [ユーザーアクセスポリシーの拡張インターフェース] 設定の両方が有効になっていることを確認します。

  3. [New User Access Policy (新規ユーザーアクセスポリシー)] をクリックします。
  4. [Policy Name (保険契約名)] と [Description (説明)] の値を入力します。
  5. [保存] をクリックします。
  6. ユーザ アクセス ポリシーの詳細ページで、［Edit Criteria］ をクリックしてポリシーのユーザ条件フィルタとアクションを設定します。
  7. [ユーザー条件を定義] で、以下を選択します。
    1. [リソース] で、[権限セット] を選択します。
    2. [演算子] で、[次の文字列と一致する] を選択します。
    3. [値] で、ユーザーが現在持っている権限セットの API 参照名を選択します。
  8. [アクションを定義] で、以下を選択します。
    1. [アクション] で、[助成金] を選択します。
    2. [対象] で、[権限セット] を選択します。
    3. [値] で、ユーザーに付与する権限セットの API 参照名を選択します。権限セット API 参照名のリストについては、「Data Cloud 権限セット移行ガイド」を参照してください。

  10. [Apply Policy] をクリックします。ポリシーを適用するユーザーのサブセットを選択するか、[すべて適用] をクリックします。

データスペースを使用したデータの保護

データスペースを使用してデータを論理的に分離し、異なるブランド、地域、またはビジネスユニットが同じ Salesforce Data 360 インスタンス内で独立して動作できるようにします。この分離により、ユーザーは自分が割り当てられているデータスペースに属するデータのみにアクセスできます。権限セットを使用してデータスペースへのアクセスを制御します。デフォルトでは、標準権限セットを持つユーザーにはデフォルトのデータスペースへのアクセス権が付与されます。追加の権限セットを作成し、どのデータスペースに関連付けるかをカスタマイズすることで、ユーザーが組織のデータスペースのデータを表示、更新、操作する方法を変更できます。

  • データスペースへの権限セットの関連付け
    Data Cloud が有効になっている場合、デフォルトのデータスペースは、Data Cloud アーキテクトを除く標準の Data Cloud 権限セットに関連付けられます。他のデータスペースへのアクセス権を付与するには、関連付けられているデータスペース権限セットを変更するか、権限セットを作成します。
  • データスペース対応 Data Cloud 機能へのアクセスの管理
    Data Cloud 標準権限セットのデフォルトでは、事前設定済みのオブジェクト権限を使用して、Data Cloud 機能へのアクセスを制御します。データスペースの機能権限を変更して、権限セットに割り当てられた各データスペースでの機能へのアクセスをさらに制限できます。

標準消費タグのデータスペース参照

Data 360 の消費利用状況に関するレポートをデータスペースで絞り込んでグループ化します。

データスペース名は、TenantUsageAttrDetail データレイクオブジェクト (DLO) のデータスペース API 項目で取得されます。これを使用するには、テナント請求使用量イベント ID の TenantEnrichedUsageEvent DLO と TenantUsageAttrDetail DLO を結合して、消費をデータスペース別に分割する Data 360 レポートを作成します。

これらの DLO のクエリやレポートを行うときにクレジットを消費しません。消費インサイト拡張データモデルオブジェクト (DMO) に関するレポートを作成したり、Tableau Next Viz を作成したりするなど、他の方法でレポートを作成できます。 一部のレポート方法ではクレジットが消費される場合があります。

データスペース属性は、データスペース対応機能に関連する利用状況種別でのみ使用できます。Data 360 データサービス消費カードでは、次の利用状況種別をデータスペースでグループ化して絞り込むことができます。

  • データクエリ
  • 処理される非構造化データ
  • データモデルオブジェクトのデータ変換
  • バッチプロファイル統合
  • Segments Processed (処理されたセグメント)
  • 計算済みインサイト
  • バッチ有効化
  • DMO の有効化 - ストリーミング
  • ストリーミングアクション
  • 1 秒未満のリアルタイムイベント

Data 360 データスペースを使用した Tableau でのデータの整理

データスペースを使用して、データ、メタデータ、プロセスをブランド、地域、部門などのカテゴリに分類します。ユーザーのブランドまたは地域のコンテキストでのみユーザーがデータを表示して使用できるように権限を設定します。

  2. Salesforce Data Cloud コネクタを選択します。

  4. すでに Data 360 にログインしている場合は、ブラウザーモードを使用して自動的に認証されます。
  5. [データスペース] ドロップダウンから、該当するデータスペースまたはデフォルトのデータスペースを選択します。
