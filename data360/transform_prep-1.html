集計

検索条件を定義する最初のステップは、平均または合計など、結果を定量化する方法を決定することです。この方法は、集計とも呼ばれます。たとえば、5 つの販売注文商品と 5 つの販売注文を検索する場合に異なる条件を使用します。コンテナオブジェクトを使用してデータを集計します。コンテナ内の関連属性のデータモデルオブジェクト (DMO) がコンテナオブジェクトになります。

件数、合計、平均、最大値または最小値に基づいて、コンテナオブジェクトを集計できます。

種別 説明 例
件数 条件を満たす必要がある回数に基づいてセグメントのエンティティを選択します。 「5 回以上の購入」(コンテナオブジェクトが販売注文の場合) または「2 件以内の苦情」(コンテナオブジェクトがケースの場合)。
合計 すべてのデータ値で合計された選択した属性に基づいてエンティティをセグメント化します。 通算販売注文金額が $XX より大きい。
平均 指定属性に基づいてエンティティをセグメント化し、すべてのデータ値を平均します。 個人の平均生涯販売注文金額が $XXX 未満、または顧客満足度の平均が 3.5。
最大 属性の指定最大値に基づいてエンティティを選択します。 最大販売注文金額 < $XX。
最小 属性の指定最小値に基づいてエンティティを選択します。 最小販売注文金額 > $XX。

統合世帯でセグメント化する場合、Aggregate values across世帯 では、世帯に属するすべてのメンバーの値が結合されます。世帯の各メンバーに検索条件を適用するには、[Aggregate values across世帯 (世帯全体の集計値)] を無効にします。

コンテナの追加の属性により、選択した集計で絞り込まれたセグメントがさらに制約されます。たとえば、昨年内の購入日の通算販売注文金額が $XX を超えているとします。

予測と処方箋を使用したデータの変換

出力を使用してデータモデルオブジェクト (DMO) を強化します。データ変換を使用して、予測インテリジェンスと指示的インテリジェンスをデータに追加します。データ変換を実行し、DMO に予測スコアなどの出力を保存します。出力の各行を使用して、派生列を作成し、計算を実行します。また、Tableau、CRM Analytics、アプリケーションテンプレートなど、他の Salesforce アプリケーションで DMO に保存された出力データを使用してデータ視覚化を作成することもできます。

  1. [データ変換] で、[新規] をクリックします。
  2. [一括処理データ変換] を選択します。
  3. [データモデルオブジェクト] をクリックし、出力を保存するデータスペースを選択します。
  4. 入力データを追加する DMO と使用する項目を選択します。

    変換中に DMO を変更すると、データがリセットされ、最初からやり直す必要があります。

  5. 変換ノードを追加するには、DMO で [+] をクリックします。
  6. データ変換ノードを開始するには、[AI モデル] をクリックします。
  7. AI モデルを選択し、[次へ] をクリックして変換エディターでモデルを起動します。
  8. [項目を対応付け] タブで、モデルスキーマ項目を入力項目に対応付けます。
  9. [出力を変更] タブで、各予測に最も影響する要素を含めて、[上位の予測因子] をクリックします。この設定により、データセットに説明と影響の列が追加されます。

    このタブは、Salesforce で作成されたモデルにのみ表示されます。

  10. 最大 3 つの予測因子を選択します。
  11. データをプレビューし、出力 DMO の列を確認します。
  12. DMO に予測出力を保存するには、[適用] をクリックします。

データ入力を視覚化するには、DMO を Salesforce の他のアプリケーション (CRM Analytics など) にアップロードします。

データへの変換の適用

モデリングデータを変換して、予測の信頼性、精度、説明可能性を向上させます。ゼロから作成されたモデルの場合、モデルビルダーによって自動的に非構造化テキストが変換され、欠損データが置き換えられます。バイナリモデルまたは回帰モデルの変数を手動で変換することもできます。

必要なエディション

テキストクラスター変換

テキストクラスター変換では、非構造化テキスト項目を分析し、テキストクラスターを作成します。予測時に、モデルは変換を適用し、指定されたテキストに基づいて事前定義されたテキストクラスターを割り当てます。この変換により、カーディナリティが低くなり、自由形式のテキスト項目が同様のデータで小さなクラスターに結合されます。これにより、モデルはテキストをより効果的に学習して使用できます。

  1. モデルビルダーの設定で、構造化されていないテキストを含むテキスト変数 (Description など) をクリックします。
  2. [設定] タブから、[変換] ドロップダウンメニューに移動します。
  3. [テキストクラスタリング] を選択します。
  4. 変換を適用して、[次へ] をクリックします。引き続きモデルを作成し、準備が整ったら有効化します。

[欠損値を置換] 変換

[欠損値を置換] 変換では、(平均、中央値、最頻値) などの統計的代入を使用して欠損値を入力します。予測時に、モデルはモデルビルダーで定義した設定とデータセットの別の類似変数のデータに基づいて新しい値を計算します。これらの数値を使用して欠損値を置き換えます。この変換により、分析のデータの完全性と一貫性が向上します。

  1. モデルビルダーの設定で、欠損値または null 値を含む数値変数 (Tenure など) をクリックします。
  2. [設定] タブをクリックします。
  3. [変換] ドロップダウンから、[欠損値を置換] を選択します。
  4. [置換後の文字列] ドロップダウンから、[平均]、[中央値]、または [モード] を選択して数値を計算します。
  5. [グループ化単位] ドロップダウンで、代入値を取得する変数を選択します。
  6. 変換を適用して、[次へ] をクリックします。引き続きモデルを作成し、準備が整ったら有効化します。

日付変換

モデルで使用するには、日付変数を変換する必要があります。モデルのトレーニング中または予測時に、モデルはモデルビルダーで定義した変換設定を使用して日付値をグループ化し、解釈します。日付は曜日または月で変換できるため、モデルはこれらの時間ベースのパターンから学習できます。

  1. モデルビルダーの設定で、日付値が含まれる日付変数 (作成日など) をクリックします。
  2. [設定] タブをクリックします。
  3. [変換] ドロップダウンから、日付値を変換する方法 (日別または月別) を選択します。
  4. [次へ] をクリックします。引き続きモデルを作成し、準備が整ったら有効化します。

トレーニングデータの準備

効果的なデータプレップは、予測モデルで優れた結果を得るための鍵です。Data 360 のデータインテグレーション機能を活用します。 1 つ以上のデータソースのデータを読み込み、最適化されたトレーニングデータを使用してデータモデルオブジェクト (DMO) に変換します。データは Salesforce や外部ソースから取得できます。サードパーティのツールとユーティリティを使用して、データの整理と収集タスクをさらに迅速に実行することもできます。

データプレップとは?

データプレップは、AIモデル(旧Einstein Studio)で予測モデルをトレーニングできるようにデータを準備するプロセスです。予測モデルを改善すると、より有益な予測と処方が導き出され、意思決定が改善され、ビジネス成果が向上します。

データプレップでは、調査している結果変数のほか、結果に影響する可能性のある予測変数に関連付けられたデータを集計および最適化します。データプレップは、反復的な調整のプロセスでもあります。データをより深く掘り下げると、新しい手がかりが登場します。発見により、以前の仮定を再評価して必要に応じてデータプレップの実装を調整することができます。

ソリューションのデータプレップへの投資

通常、データサイエンティストは多大な時間と労力を費やしてデータの計画と準備を行います。データサイエンティストは、入力の設計と品質によって出力の品質が決まることがわかっています。データサイエンティストがデータプレッププロセスにもたらす専門家レベルの知識、スキル、およびトレーニングには匹敵しない場合でも、次の条件を満たしていれば成功できます。

  • 最適化しようとしているビジネス結果に関連付けられたデータに関する専門知識がある
  • Data 360 の広範なデータインテグレーション機能を使用して、モデルのトレーニング用に最適化されたデータを DMO で集計、クリーンアップ、入力する
  • 一般的なデータプレップ手法を適用して、正確かつ完全で、業務を表しソリューションに関連する高品質のデータを生成する
  • データサイエンティストでなくても、ソリューションの実装に役立つ基本原則を適用すれば結果を改善できます。

数式の他の関数

ロジックを数式に組み込むには、次の関数をテキスト、数値、日時データ型で使用します。

case

case ステートメントを使用して if/then ロジックを処理します。case ステートメントには、常に where ステートメントと then ステートメントのペアがあります。

構文 

case [primary_expr]
    when condition
    then result_expression
    else 
        default_expression
end

パラメーター

  • primary＿expression：省略可能。一連の式と比較する有効な式。主式は、同等性を得るために各 when 句の式と比較されます。これらの式が等しい場合、then 句の式が返されます。
  • condition — case ステートメントのconditionは、次の 2 つの形式になります。
    • 可能な値のセットと比較する式。
    • true、false、または null に評価される Boolean 式。
  • result＿expression — primary＿expression が条件を満たし、True に評価されたときに返される式。
  • default_expression — 前のどちらの比較も True と評価されなかった場合、この式が返されます。

例

case ShippingState__c
    when 'CA'
    then 'California'
    else 
        'Other'
end
case 
    when "ShippingState__c" = 'CA'
    then 'California'
    else 
        'Other'
end

coalesce

coalesce 関数は case ステートメントの短縮形として使用します。この関数は、null 値を別の値に置き換えます。

構文 

coalesce(expression1, expression2)

パラメーター

  • expression1 — null 以外の値を検索する最初の列またはテキスト文字列。
  • expression2 — null 以外の値を検索する次の列またはテキスト文字列。

例

coalesce(city, null)

Returns

null 以外の最初の値を返します。存在しない場合、この関数は null を返します。

sequence

sequence 関数を使用して、開始値と終了値、および各値間の間隔を定義し、数値または日付のシーケンスを作成します。

構文 

sequence(start,stop,step)

パラメーター

  • start — フィールドまたは数値。
  • stop — フィールドまたは数値。
  • step — 項目、数値、または日付間隔。

例

sequence(start_field, stop_field, interval 1 day)

Returns

値ごとに 1 つの要素を含む配列を返します。

UUID

uuid 関数を使用して、テーブル内の行の一意の識別子を生成します。

構文 

uuid()

パラメーター

  • なし

Returns

テーブルの行ごとに 36 文字の一意の識別子文字列を返します。

集計ノード

集計ノードを使用して、データを積み上げ集計します。より高いレベルの粒度に集計したり、階層データを積み上げ集計したりできます。

  • 集計ノード: より高いレベルへのデータの積み上げ集計
    集計ノードを使用して、データをより高い粒度に積み上げ集計します。集計には、ユニーク、合計、平均、件数、最大、最小を使用できます。任意のディメンションまたは日付列でグループ化できます。ディメンションを列としてピボットすることもできます。たとえば、取引先別に商談をグループ化して、取引先レベルの詳細 (各取引先の合計商談金額、平均ケース数、商談成立までの平均日数など) を取得できます。次に、取引先種別でピボットして、取引先と取引先種別の各組み合わせを分析します。
  • 集計ノード: 階層集計
    複数レベルのデータにまたがる基準を合計するには、階層集計を使用します。たとえば、会社とその子会社の収益、資産、または負債を積み上げ集計できます。または、営業担当のデータを管理チェーンに積み上げ集計して、チーム、地域、分野などでの集計を確認することもできます。階層集計には、ID と親 ID を含む行が必要です。 多くの行に同じ親 ID を含めたり、親 ID を空にすることができます。一部の行では、複数の親があるレコードなどの ID を共有することもできます。また、省略可能な積み上げ集計パーセントを使用してパーセント分割を適用し、営業チームのメンバー間のコミッションなど、異なる親に部分を割り当てることもできます。

集計ノード: 階層集計

複数レベルのデータにまたがる基準を合計するには、階層集計を使用します。たとえば、会社とその子会社の収益、資産、または負債を積み上げ集計できます。または、営業担当のデータを管理チェーンに積み上げ集計して、チーム、地域、分野などでの集計を確認することもできます。階層集計には、ID と親 ID を含む行が必要です。 多くの行に同じ親 ID を含めたり、親 ID を空にすることができます。一部の行では、複数の親があるレコードなどの ID を共有することもできます。また、省略可能な積み上げ集計パーセントを使用してパーセント分割を適用し、営業チームのメンバー間のコミッションなど、異なる親に部分を割り当てることもできます。

  1. すでに 1 つ以上の入力ノードが含まれる一括処理データ変換で、2 つのノード間またはデータ変換の最後にある [ノードを追加] ボタン () を選択します。2 つのノード間に [ノードを追加] ボタンを表示するには、結線にカーソルを置きます。
  2. [ノードを追加] ダイアログボックスで [集計] を選択します。
  3. [Aggregate settings (集計設定)] パネルで、[Hierarchical Aggregation (階層集計)] を有効にします。
  4. 基準の合計や行数など、少なくとも 1 つの集計を追加します。
  5. [レコード ID 列] を選択します。レコード ID には、行を定義するデータ内の任意のディメンション (営業担当や取引先名など) を指定できます。

集計ノード: より高いレベルへのデータの積み上げ集計

集計ノードを使用して、データをより高い粒度に積み上げ集計します。集計には、ユニーク、合計、平均、件数、最大、最小を使用できます。任意のディメンションまたは日付列でグループ化できます。ディメンションを列としてピボットすることもできます。たとえば、取引先別に商談をグループ化して、取引先レベルの詳細 (各取引先の合計商談金額、平均ケース数、商談成立までの平均日数など) を取得できます。次に、取引先種別でピボットして、取引先と取引先種別の各組み合わせを分析します。

  1. すでに 1 つ以上の入力ノードが含まれる一括処理データ変換で、2 つのノード間またはデータ変換の最後にある [ノードを追加] ボタン () を選択します。2 つのノード間に [ノードを追加] ボタンを表示するには、結線にカーソルを置きます。
  2. [ノードを追加] ダイアログボックスで [集計] を選択します。
  3. 集計を少なくとも 1 つ追加します。
    グループ化を追加する前に、集計を追加します。次のいずれかの集計関数を選択できます。

    通貨値に集計関数を適用するには、通貨を設定します。通貨を指定しない場合、ノードではデータの最初の行の通貨が使用されます。

    集計関数 説明
    Unique 選択した列の一意値のみを数えます。
    Sum 選択した列のすべての値を加算して合計を計算します。
    Average 選択した列の平均値を計算します。
    Count 選択した列のすべての値を数えます。
    Maximum 選択した列の最大値を計算します。
    Minimum 選択した列の最小値を計算します。
    Stddevp 母標準偏差を計算します。母標準偏差は、データ分布の広がり、つまり各データポイントと平均間の典型的な距離を測定します。
    Stddev 標本標準偏差を計算します。標本標準偏差は、特定の標本のデータ分布の広がりを測定します。標本標準偏差を使用して、標本に基づいて母標準偏差を推定します。
    Varp 母分散を計算します。母分散は、特定の母集団でデータポイントがどのように広がっているかを示します。
    Var 標本分散を計算します。標本分散は、特定の標本のデータポイントがどのように広がっているかを示します。標本分散を使用して、標本に基づいて母分散を推定します。
  4. 行をグループ化するには、[行をグループ化] 列で 1 つ以上のディメンションまたは日付列を追加します。

    たとえば、取引先名でグループ化できます。

  5. ディメンションを列としてピボットするには、[列をグループ化] で 2 つまでのディメンション列を追加し、各ディメンション列の値を選択して、[適用] をクリックします。入力データソースオブジェクトのすべての値を検索できます。値がリストに表示されない場合は、サンプルサイズを調整するか、検索を絞り込みます。次に、[新しい値を追加] をクリックして、値を入力します。

    たとえば、商談種別ごとに列をグループ化できます。商談種別と集計の各組み合わせは個別の列として表示されます。

  6. データ変換に集計ノードを追加するには、[適用] をクリックします。
  7. 一括処理データ変換を保存します。

追加ノードを使用した異なるデータソースの行の統合

追加ノードを使用して、複数の入力データソースの行を 1 つの結果に結合します。

  1. 1 つ以上の入力ノードが含まれる一括処理データ変換で、2 つのノード間またはデータ変換の最後にある [ノードを追加] ボタン () をクリックします。
  2. [追加] を選択します。
  3. 一括処理データ変換に追加するデータを選択します。
    1. 追加するオブジェクトを選択します (1)。
    2. [選択済みのフィールド] (2) で、追加するデータに含めるオブジェクトの列 (フィールドとも呼ばれる) を選択するか、[名前] をクリックしてすべての列を選択します。
    3. [次へ] をクリックします。
  4. 列の対応付け方法を選択します。
    • 一括処理データ変換が実行されるたびにすべての列を自動的にマッピングするには、[すべての列をマッピング] を有効にします。
    • 2 つの列を手動で対応付けるには、追加行の列名を、対応する一括処理データ変換列の横に入力します。
    一括処理データ変換では、一致する列の API 参照名に基づいて両方のデータ オブジェクトのすべての列がマッピングされます。対応する API 参照名がない列を対応付けるには、[スキーマのマージを許可] を選択します。
    メモ 列が片方の入力元に対応付けられている場合、追加ノードは、列が適用されないすべての入力元行に null 値を挿入します。数値列が入力元に対応付けられておらず、null 数値の処理が有効ではない場合、追加ノードは、それらの入力元行に null ではなく 0 を挿入します。
  5. 一括処理データ変換に存在しない追加行の列を追加するには、[+] をクリックして列を選択します。一括処理データ変換列は空白のままにします。
  6. [適用] をクリックして、ノードを一括処理データ変換に追加します。
  7. [保存] をクリックします。

一括処理データ変換を実行すると、追加ノードによって両方のデータオブジェクトの行が同じソースデータに結合されます。

一括処理データ変換を作成するためのベストプラクティス

処理のパフォーマンスを向上させ、プレビューに表示されるデータの速度を高めるため、次の考慮事項に留意してください。

  • 50 個を超えるノードを一度に使用しないでください。
  • 結合で右または左のソースよりも大幅に多くのレコードが生成される爆発的な結合は避けてください。
  • 入力ノードで必要な列のみを選択してください。必要に応じて、他の列を追加できます。
  • 多数のノードが含まれる一括処理変換は小さいデータ変換に分割してください。前のデータ変換の出力は次の変換への入力になります。これらは順番に実行します。
  • 250 個を超えるノードは含めないでください。150 個を超えるノードを含む一括処理データ変換のプレビューと実行には、長い時間がかかります。

キャンバスを高速化するためのヒント:

  • [クリーンアップ] ボタンを使用して、キャンバス上のデータ変換のサイズを減らします。[クリーンアップ] ボタンは分岐を横方向に整理し、入力を左側、出力を右側に配置します。重複するブランチを最小限に抑え、接続をできるだけ短くします。
  • マウスの代わりにキーボードショートカットを使用して、要素間を移動し、キャンバスに要素を追加します。
  • ノードを見つけるには、スクロールではなく検索またはズームを使用します。

次のガイドラインと推奨事項に留意して、一括処理データ変換を最大限に活用してください。

  • 一括処理データ変換を作成するためのベストプラクティス
    処理のパフォーマンスを向上させ、プレビューに表示されるデータの速度を高めるため、次の考慮事項に留意してください。
  • データキットを使用したデータ変換のリリース時の DMO マッピングの維持
    データ キットを使用してデータ変換をリリースする場合、出力データ レイク オブジェクト(DLO)とデータ モデル オブジェクト(DMO)間のマッピングは自動的に含まれません。これらのマッピングを継承するには、出力 DLO をデータキットに明示的に追加します。
  • 一括処理データ変換の結果のプレビュー
    一括処理データ変換に追加した各ノードと変換の結果を確認し、誤りを早期に見つけます。各ユーザーは 1 時間あたり最大 4,000 件のプレビューを開始できます。プレビューには、最新の使用可能なデータのサンプル (最大 5,000 行) が表示されます。
  • 一括処理データ変換の制限事項
    一括処理データ変換には次の制限があります。
  • 一括処理データ変換の編集
    一括処理データ変換を変更して、結果を保存します。
  • 一括処理データ変換の削除
    不要になった一括処理データ変換を削除します。一括処理データ変換を削除しても、その対象データは削除されません。

データ型変換: 列の型の変換

列のデータ型によって、その列のデータを照会できる方法が決まります。たとえば、テキストまたは日付列で絞り込みやグループ化を行ったり、数値列で計算を実行したりできます。項目のタグ付けが正しくないことがあります。必要に応じて、列の型変換を使用して、列を正しい型に変換します。

  • [テキストから日付] 変換: 列の型の変換
    日付列に予期しない文字列値または異なる形式の日付が含まれている場合、日付列がテキストとしてタグ付けされることがあります。月別にグループ化するなど、日付機能を使用するには、[テキストから日付] 変換を使用して、列の型をテキストから日付に変更します。
  • [テキストから数値] 変換: 列の型の変換
    平均の計算など、列で数学的計算を実行するには、[テキストから数値] 変換を使用して、列の型をテキストから数値に変更します。数学的計算は数値列でのみ実行できます。数値型には、パーセントデータ型が含まれます。
  • [数値からテキスト] 変換: 列の型の変換
    数値列でグループ化および絞り込むには、[数値からテキスト] 変換を使用します。グループ化や絞り込みはテキスト列でのみ行うことができます。

増分実行でのデータドリフト

増分モードで一括処理データ変換を実行すると、データ ドリフトによって、出力オブジェクトから除外または置換される代わりに、変更されたレコードが含まれることがあります。データドリフトは、毎日スケジュールされた「フル実行」で修正されます。

データドリフトは、次の状況で発生します。

  • 値で絞り込んで出力からレコードを削除するときに、変更された値が削除条件を満たしている場合、更新されたレコードは除外されません。更新されたレコードは、次のフル実行で除外されます。
  • プライマリキー列に対応付けられている列の値が変更されると、更新されたレコードの生成されたプライマリキーが元のキーとは異なるため、更新されたレコードは新規レコードと同様に処理されます。このシナリオでは、増分実行の出力では、次のフル実行まで、元の生成されたプライマリキーを持つ 1 つのレコードと更新されたキーを持つ 1 つのレコードが保持されます。

データドリフトを修正するために、フル実行は 24 時間ごとに実行されます。

データプレビューサンプリング

データプレビューサンプリングを使用して、[プレビュー] で各ノードのデータをより正確に表示します。サンプルサイズを拡大して、データをまとめるモードを選択すると、データサンプリングによってプレビューデータなしでの作業を防ぐことができます。特定の値を分離するには、[絞り込まれた行] を選択します。

デフォルトでは、[サンプルサイズ] は 2000 に設定され、[サンプリングモード] は上位 2000 行に設定されます。つまり、プレビューにはデータの最初の 2000 行が表示されます。

  1. 入力ノードの [データプレビューサンプリング] で、[サンプルサイズ] を選択します。これはプレビューに含める行数です。デフォルトでは、サンプルサイズは 2000 に設定されています。 [サンプリングモード] は上位 2000 行に設定されています。
  2. [サンプリングモード] で、データに最も適したモードを選択します。バケットの作成時など、すべての列値を表示する必要がある場合にサンプルを入力するには、[すべての列値] を選択します。特定の値を分離するには、[絞り込まれた行] を選択します。
  3. [絞り込まれた行] サンプリングモードを選択する場合は、[検索条件] の下にある [+] をクリックして絞り込みの基準にする列の値を選択します。絞り込まれた結果に含める値を選択します。検索条件に通貨項目を含めるには、変換の通貨を設定します。変換の作成後に通貨を設定すると、プレビューがリセットされます。
  4. [適用] をクリックします。

日時変換: 日付項目の計算

日付項目は、時間の経過に伴うトレンドを把握したり、今後のマイルストーンと期限をチームに知らせたりするための重要な項目です。日付に基づいて計算したり、分析で日付がより役立つようにしたりするには、日時変換を使用します。[現在] オプションを使用して、指定された形式の現在日時を含む列を挿入します。[日付の差] を使用して、選択した 2 つの日付列間の期間を日数、月数、年数として計算します。また、[日数や月数を加算または減算] 関数を使用して、日付列から日数または月数を加算または減算します。

  • 日数や月数を加算または減算
    指定された日数や月数を追加または削除した列の日付を返します。
  • 日付の差
    選択した 2 つの日付列間の期間を日数、月数、年数として計算します。
  • 現在
    指定された形式の現在日時を表示する列を作成します。この変換は、他の列を操作することなく動作します。

日時関数に関する考慮事項

日時関数を使用するときは、次の点に留意してください。

  • これらの関数は、一括処理データ変換が実行された時間を基準とします。
    • now
    • current_date
    • current_timestamp

  • すべての日付関数と日時関数は UTC タイムゾーンに基づきます。
  • カスタムタイムゾーンのサポートが有効になっている場合、日付関数と日時関数は分離されます。無効になっている場合、関数はグループ化されます。

抽出変換: 日付コンポーネントの取得

抽出変換を使用して、選択したコンポーネントを日付項目から新しい項目に取り込みます。たとえば、[ケースの作成日] 項目から時間コンポーネントを抽出して、時間別にケースの作成を分析します。

  1. 変換ノードで、コンポーネントの抽出元の日付項目を選択します。
  2. 変換ツールバーで、[抽出] ボタン () をクリックして抽出設定を定義します。
  3. 抽出する日付コンポーネントを選択します。
  4. [結果の表示先] で、新しい値を新しい項目に表示するかどうかと、元の項目を保持するかどうかを選択します。
  5. 項目を作成するように選択した場合は、[項目の表示ラベル] で表示ラベルを設定します。
  6. [適用] をクリックして、変換ノードに変換を追加します。[プレビュー] タブに新しい日付コンポーネント項目が表示されます。
  7. キャンバスを表示するには、[折りたたむ] ボタン () をクリックします。
  8. データ変換を保存します。

データ変換を実行すると、選択した日付コンポーネントが、指定したディメンション項目に抽出されます。

日付の差

検索条件ノード

検索条件ノードを使用して、対象内で必要のない行を削除します。たとえば、ケースレコードを絞り込んでエスカレーション済みのケースのみに焦点を絞ることができます。検索条件値では、大文字と小文字が区別されます。

  1. すでに 1 つ以上の入力ノードが含まれる一括処理データ変換で、2 つのノード間または一括処理データ変換の最後にある [ノードを追加] ボタン () を選択します。2 つのノード間に [ノードを追加] ボタンを表示するには、結線にカーソルを置きます。
  2. メモ 検索条件ノードを追加すると、選択リストにはプレビューデータセットに存在する値のみが表示されます。フルデータセットに存在し、プレビューに含まれていなかった値は、検索条件オプションとして表示されません。
    [ノードを追加] ダイアログボックスで [検索条件] を選択します。
  3. [+] をクリックして標準の検索条件を追加します。標準の検索条件では、通常の演算子 (次の文字列と一致する、次の文字列と一致しない、＜、など) を使用します。文字列や算術関数へのアクセスなど、検索条件オプションの粒度を高めるには、[検索条件] の横にあるドロップダウンから [カスタム検索条件式を追加] を選択します。両方のオプションの検索条件値では、大文字と小文字が区別されます。
    1. 通貨値に集計関数を適用するには、通貨を設定します。通貨を指定しない場合、ノードではデータの最初の行の通貨が使用されます。
  4. メモ 列の検索結果には、最大 2,000 個の値が表示されます。
    ディメンション列で検索条件を定義する場合、データの値のリストから検索条件値を選択できます。次に、[新しい値を追加] をクリックして値を入力します。
  5. [適用] をクリックします。
  6. 現在の標準の検索条件ロジックを表示するには、[] および [標準の検索条件ロジックを追加] をクリックします。
    デフォルトのANDロジックが表示され、各検索条件コンポーネントには番号が割り当てられています。
  7. ロジックを編集するには、鉛筆アイコン () をクリックします。
  8. 括弧と AND、OR、および NOT Boolean 演算子を使用して、検索条件ロジックを構築します。
  9. [適用] をクリックします。
  10. データ変換を保存します。

階層データのフラット化

flatten 変換を使用すると、ネストされた階層データをリストに変換して簡略化できます。このリストでは、各ノードとその前に存在するノード (上位ノード) が階層内で表示される場所を追跡します。データをフラット化するには、階層内のすべてのノードが含まれる項目と、それぞれに対応する親が含まれる項目を指定します。変換を実行すると、各レコードには親レコードのリストが含まれます。

データソースにフラット化できる階層レベルの数は、そのデータソースに含まれる行数によって異なります。

  • 100 万行を超える場合は 300 レベル
  • 1500 万行を超える場合は 100 レベル
  • 2000 万行を超える場合は 50 レベル (最大)
  1. 変換ノードで、[フラット化] ボタン () をクリックします。
  2. [レコード ID 列] で、階層内のすべてのノードが含まれる列を選択します。
  3. [親 ID] 列で、階層内の各ノードの親を含む列を選択します。
    階層ノードが含まれる生成された列にレコード ID を含めるには、[レコード ID 列の値を含む] を選択します。
  4. [階層列の表示ラベル] に、生成された階層ノードの列の名前を入力します。
  5. 変換結果をプレビューします。
    プレビューでは、レコード ID とその親のみが階層列に表示されます。データ変換を実行すると、すべての上位ノードが表示されます。
  6. [適用] をクリックします。
    ビューを折りたたんでキャンバスを表示するには、[折りたたむ] ボタン () をクリックします。
  7. 階層列を生成するには、データ変換を実行します。

JSON データのフラット化

JSON 文字列として取り込まれたデータを一括変換で表形式データに変換します。ID 解決やセグメンテーションなどの下流機能でデータを使用するには、データをデータレイクオブジェクトまたはデータモデルオブジェクトの行および列として保存する必要があります。フラット化できる JSON データには、単一オブジェクト、オブジェクトの配列、リテラル (スカラー値) の配列として保存されたものがあります。

ネストされた JSON をフラット化するには、JSON データの構造と内容を記述するスキーマファイルが必要です。このファイルは手動で作成することも、Web ユーティリティを使用して JSON データのサンプルから生成することもできます。

メモ :

スキーマファイルからは、「type」、「properties」、「items」キーワードのみが認識され、その他はすべて無視されます。

JSON データの形式が正しくない場合、行は処理されず、結果に含まれません。

JSON レベルの最大制限は 6 です。 「properties」キーワードの最大制限は 50 です。

  1. 変換ノードで、[JSON をフラット化] 変換を選択します。
  2. [ファイルをアップロード] を選択し、JSON スキーマファイルを選択します。
  3. 変換名を入力します。
  4. 少なくとも 1 つの出力テーブルを追加します。
    1. [新規テーブルを追加] を選択します。
    2. テーブルの名前を入力します。
    3. JSON データから抽出する項目を 1 つ以上選択します。
  5. 設定を保存するには、[適用] をクリックします。
  6. テーブルデータをプレビューするには、そのテーブルの出力の分岐にノードを追加します。
例 データテーブルには、order_id 項目と json_data 項目が含まれます。Order_id には、注文を識別する整数が含まれます。Json_data には、各注文に関する重要な情報を含む JSON データ文字列が含まれます。顧客の生涯価値などのインサイトを計算できるように、注文に関するデータをテーブルに抽出します。
order_id json_data
1 {"customer": "John", "items": [{"id": 101, "name": "Laptop", "price": 1500}, {"id": 102, "name": "Mouse", "price": 20}]}
2 {"customer": "Alice", "items": [{"id": 103, "name": "Keyboard", "price": 50}, {"id": 104, "name": "Monitor", "price": 300}]}

Data 360 で JSON データを適切に解釈できるようにするには、JSON スキーマ仕様に準拠するスキーマファイルをアップロードします。次のサンプルスキーマファイルでは、データテーブルのデータが記述されています。

{
  "type": "object",
  "properties": {
    "customer": {
      "type": "string"
    },
    "items": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "id": {
            "type": "number"
          },
          "name": {
            "type": "string"
          },
          "price": {
            "type": "number"
          }
        },
        "required": ["id", "name", "price"]
      }
    }
  },
  "required": ["customer", "items"]
}

[日付を書式設定] 変換: 列の日付形式の標準化

[日付を書式設定] 変換を使用して、テキスト列内のすべての日付の形式を標準化します。一貫した形式により、月などの特定の日付部分による絞り込みを含め、レコードを日付で正しく絞り込み、グループ化できます。また、一貫した形式により、テキストから日付に列の型を確実に変換することができます。

  1. 変換ノードの [プレビュー] タブで、日付を含むテキスト列を選択します。
  2. 変換ツールバーで [日付を書式設定] ボタン () をクリックします。
  3. 選択した列で元の日付形式を入力します。[日付形式] 変換では、[元の形式] 検索ボックスに表示される最初の一致形式が正しい形式だとみなされます。たとえば、日付が 01/06/2023 の場合、日付形式は dd/MM/yyyy または MM/dd/yyyy になります。
  4. [変更後] 項目で目的の日付形式を選択します。
  5. 日付が入力されているテキスト列の型を日付に変換するには、[列のデータ型を日付に変換] を選択します。
  6. [結果の表示先] で、新しい値を新しい列に表示するかどうかと、元の列を保持するかどうかを選択します。
  7. 列を作成するように選択した場合は、[列の表示ラベル] で表示ラベルを設定します。
  8. [適用] をクリックして、変換ノードに変換を追加します。
  9. キャンバス領域を表示するには、[折りたたむ] ボタン () をクリックします。

一括処理データ変換を実行すると、変換によって既存の列の日付が、指定された形式の日付に置き換えられます。変換で日付の元の形式を判断できない、または日付に特定の日付部分の値がない場合、日付は null に置換されます。たとえば、MM/dd/yyyy:hh:mm:sssz 形式に標準化し、日付値に秒の日付部分 (sssz) がない場合、変換によって日付が null に置換されます。

数式変換: 式に基づく計算列の作成

数式計算に基づいて値を表示する列を作成します。計算には、同じ行や他の行の他の列からの入力を含めることができます。たとえば、[Revenue (収益)] 列と [Cost (コスト)] 列からの入力に基づいて [Profit (利益)] 列を作成できます。SQL で数式を入力します。Data 360 の SQL は、数値、文字列、日付データの標準関数とカスタム関数のコレクションです。

  1. 変換ノードの [プレビュー] タブで列を選択します。
  2. 計算列の数式を作成するには、変換ツールバーで [数式] ボタン () を選択し、[カスタム数式] を選択します。
  3. 数式エディターで、正しい構文を使用して数式を入力し、パラメーターを追加します。
    数式エディターで入力を開始すると、名前に一致する関数と列が表示されるので、それらを選択して数式に追加できます。
    メモ ベストプラクティスは、二重引用符を使用してすべての列名を囲むことです。文字列リテラルの値の場合、単一引用符を使用します。

    予約キーワードと名前を共有するデータセット列を参照する場合は、二重引用符が必要です。

    [関数] および [列] タブですべての関数と列のヘルプを確認できます。関数を数式に追加するには、関数を選択して [+] をクリックします。

    [関数] タブには、[ウィンドウ関数]、[文字列関数]、[数値関数]、[日付/時間関数]、[追加の関数] のカテゴリ別に関数が表示されます。ウィンドウ関数を表示するには、[行数式の数式] を有効にします。

  4. ウィンドウ関数を使用する数式の場合、[パーティションの基準] で行を区分するために使用する列、[並び替えの基準] でデータを並び替えるために使用する列、[並び替えの方向] で並び替え方向を指定します。

    たとえば、[パーティションの基準] を [商談名]、[並び替えの基準] を [最終更新日]、[並び替えの方向] を [昇順] に設定します。変換は、これらの設定に従い、同じ商談名に基づいて、すべてのレコードをパーティション (バケット) に結合します。次に、最終更新日に基づいて昇順で各パーティションのレコードを並び替えます。

  5. 数式内の各列は API 参照名で識別します。API 参照名を入力するか、[列] タブから列を選択します。
  6. [出力種別] で、計算された列のデータがテキスト、数値、日付、日時のどれであるかを選択します。
  7. 出力種別に応じて、次の属性を設定できます。
    属性 説明
    精度 数値列の最大桁数。小数点の右側と左側の両方をあわせたすべての桁数 (ただし小数点自体は含まない) が含まれます。1 ～ 18 の整数 (両端を含む) を入力します。
    スケール 数値列での小数点の右側の桁数。0 ～ 17 の整数 (両端を含む) を入力します。スケールは精度より小さくする必要があります。たとえば、数値が 123456.789 で、スケールを 2 に設定した場合、数値は 123456.78 と表示されます。
    長さ テキスト列の最大文字数。1 ～ 32000 の整数 (両端を含む) を入力します。デフォルトの長さは 255 文字です。
    日付形式 日付列の日付形式。
  8. [デフォルト値] で、式から結果が返されない場合に表示する値を選択します。
  9. 必要に応じて、計算列の表示ラベルを変更できます。
  10. 数式を変換ノードにステップとして追加するには、[適用] をクリックします。計算列が [プレビュー] に表示されます。
  11. キャンバスを表示するには、[折りたたむ] ボタン () をクリックします。
  12. データ変換を保存します。

数式列をバケット化したり、データ変換で定義されている後の数式で参照したりできます。

ヒント 一般的な関数の場合は、列と定義済みの構文で数式を自動入力するためのボタンが変換ツールバーにあります。ツールバーには、選択した列の型と数に基づいて適切な関数が表示されます。関数を使用するには、変換ツールバー (1) で関数のボタンをクリックします。選択した列と関数を使用して、数式が自動的に開始されます (2)。
  • 数式の日付関数
    日付関数を使用して、日付の値を調整または計算します。たとえば、日付項目から時間を追加したり、日付項目までの時間を確認したり、日付項目から曜日を抽出したりできます。日付関数の引数は日付項目です。
  • 数式の数値演算子と数値関数
    数値関数を使用して、基準から値を計算します。たとえば、数値を丸めたり、切り捨てたり、数値の絶対値を決定したりできます。数値関数の引数は、数値または基準項目にすることができます。
  • 数式の文字列関数
    string 関数を使用して、メール、電話、時間、日付値などのテキストデータ型を操作します。たとえば、テキストを大文字から小文字に変更したり、複数の項目の値を連結したり、値を置き換えたりします。
  • 数式のウィンドウ関数
    ウィンドウ関数を使用して行全体の計算を実行します。入力データの行ごとに、関連する行の選択内容 (ウィンドウ) に関する計算を実行します。行をグループ化する集計関数とは異なり、ウィンドウ関数は各行の結果を返します。たとえば、各商談のフェーズ全体の商談金額の変化を計算して、販売目標を達成できるかどうかを確認できます。
  • 数式の複数値関数
    複数値データは、数式での使用に制限されています。CRM Analytics でのレポートなど、Data 360 の一括処理データ変換の下流プロセスで複数値データを操作するには、複数値データを文字列に変換します。
  • 数式の他の関数
    ロジックを数式に組み込むには、次の関数をテキスト、数値、日時データ型で使用します。

入力ノードと出力ノード: 一括処理データ変換へのデータの追加および書き込み

入力ノードを使用して、データを一括処理データ変換に追加します。一括処理データ変換の出力を保存するには、データを 1 つ以上の出力ノードに書き込みます。入力ノードと出力ノードには、データレークオブジェクト、またはプロファイル型またはその他型のデータモデルオブジェクトを使用できます。データレークオブジェクトの入力ノードとデータモデルオブジェクトの出力ノードを使用することはできません。その逆も同様です。通常、データアウェアスペシャリストとエンジニアはデータレークオブジェクトとデータモデルオブジェクトにアクセスできますが、マーケティング担当者とアナリストはデータモデルオブジェクトにしかアクセスできません。

  • 一括処理データ変換への入力ノードの追加
    一括処理データ変換に追加するデータごとに入力ノードを作成します。一括処理データ変換では、入力データを最初に選択したときに入力ノードが自動的に作成されますが、他のデータを追加するには、別のノードを追加する必要があります。
  • データレークオブジェクトの出力ノードへの一括処理データ変換結果の書き込み
    ID解決、計算済みインサイト、またはセグメンテーションへの入力として一括処理データ変換を使用するには、出力ノードの新規または既存のデータ レイク オブジェクト(DLO)に結果を書き込みます。出力が保持されているオブジェクトは、対象データレークオブジェクトと呼ばれます。出力ノードを持たない一括処理データ変換を保存することはできません。
  • データモデルオブジェクトの出力ノードへの一括処理データ変換結果の書き込み
    一括処理データ変換の結果を既存のデータモデルオブジェクトまたは出力ノードを介して作成されたデータモデルオブジェクトに書き込みます。出力が保持されているオブジェクトは、変換データモデルオブジェクトと呼ばれます。データ変換内の変換種別のデータモデルオブジェクトにのみ書き込むことができます。変換種別のデータモデルオブジェクトを別の一括処理データ変換や、ID 解決、計算済みインサイト、セグメンテーションなどのダウンストリームプロセスへの入力として使用できます。
  • 複数定義変換を使用したレコードのマージ
    変換定義では、一括処理データ変換時にデータに適用される操作の順序を指定します。定義は、データフローキャンバスにノードとして表示されます。複数の定義を組み合わせて、1 つの統合出力を生成できます。
  • データプレビューサンプリング
    データプレビューサンプリングを使用して、[プレビュー] で各ノードのデータをより正確に表示します。サンプルサイズを拡大して、データをまとめるモードを選択すると、データサンプリングによってプレビューデータなしでの作業を防ぐことができます。特定の値を分離するには、[絞り込まれた行] を選択します。

一括処理データ変換への入力ノードの追加

一括処理データ変換に追加するデータごとに入力ノードを作成します。一括処理データ変換では、入力データを最初に選択したときに入力ノードが自動的に作成されますが、他のデータを追加するには、別のノードを追加する必要があります。

  1. [データ変換] の [最近参照したデータ] ページで、[新規] をクリックします。
  2. キャンバスで、[入力データを追加] をクリックします。
  3. 変更する一括処理データ変換で、ドロップダウンメニューから [編集] を選択します。
  4. キャンバスで、[データを追加] () ボタンをクリックします。
  5. 入力データを選択し (1)、一括処理データ変換に含める列を選択します (2)。

    複数のオブジェクトを選択した場合、特定のオブジェクトの名前、API 参照名、カテゴリ、または場所をクリックして、そのオブジェクトの列を表示します。すべての列を選択解除するには、[名前] チェックボックスをオフにします。

  6. [次へ] をクリックします。

    選択した入力データごとに入力ノードがキャンバスに追加されます。入力元の列数が 100 を超えている場合、最初の 100 列がプレビューに表示されます。さらに列を追加するには、[列を変更] をクリックします。

一括処理データ変換のオブジェクトの結合

一括処理データ変換キャンバスで、ノードを使用してデータオブジェクト間の結合を作成します。複数のデータオブジェクトのデータを正確に結合し、重複しないようにするには、必ずキー修飾子項目を追加して、結合に完全修飾キー (FQK) を作成します。キー修飾子項目の null 値が正しく一致するようにするには、null 値を null 文字列または空の文字列に置き換えて、null セーフ結合を使用します。

データ変換テーブルの結合で使用されるすべてのデータ レイク オブジェクト(DLO)フィールドには、キー修飾子が関連付けられている必要があります。「 完全修飾キーを使用したデータの解釈 」および「 キー修飾子項目の設定」を参照してください。Data 360 では、キー修飾子がデータモデルオブジェクト (DMO) 項目に自動的に追加されます。

  1. 2 つの入力データソース間、または一括処理データ変換の最後で、[ノードを] をクリックします。
    2 つの入力データソースオブジェクト間に [ノードを追加] ボタンを表示するには、結線にカーソルを置きます。入力ソースを自身に結合するには、[ノードを追加] ボタンを入力ソースにドラッグして、[結合] を選択します。
  2. [結合] を選択します。
  3. 結合するデータを選択し、含めるフィールドを選択して、[次へ] をクリックします。
    結合の両側の通貨項目は一致する必要があります。通貨が選択されていない場合、結合の通貨の左側が使用されます。右外部結合では、通貨の右側が使用されます。
  4. 結合種別を選択します。
    一括処理データ変換では、両方の入力データセットから提案される結合キーが追加されます。結果を改善するには、最大 5 個のキーを使用してレコードを照合します。たとえば、取引先責任者情報をリードデータに追加するときに、名前のみを一致として使用すると、異なるリードの名前が同じ場合に重複する可能性があります。代わりに、2 つのキー (名前と会社で照合するキー) を使用して、適切なデータを一致させます。
    パフォーマンスを向上させるには、結合条件のキーの 1 つとして主キー列を使用します。
  5. FQK を作成し、テーブル結合が正しく機能するように、[結合キー] でプラス記号 (+) をクリックし、キー修飾子項目を追加します。
  6. 変更内容を適用します。
  7. キャンバスの結合の片側のキー修飾子項目列で、すべての null 値を文字列値に置き換えます。
    null 値を相互に比較することはできません。null 値がある場合、テーブル結合は正しく機能しません。
    1. [ノードを追加] をクリックし、[変換] を選択します。
    2. [列] で、キー修飾子項目を選択します。
    3. 変換ツールバーで [置換] アイコンをクリックします。
    4. [null を検索] (1) を選択し、[置換] テキストボックスに「--NULL--」 (2) と入力します。または、空の文字列 ("") を入力するか、結合の反対側と比較して既存のキー修飾子項目の値と競合しない値を入力します。
    5. 変更内容を適用します。
    6. 結合の反対側についてもこの手順を繰り返します。
    7. 変更をプレビューし、結合の両側でキー修飾子項目列に null 値が表示されないことを確認します。
  8. 左側のデータソースの項目と右側のデータソースの項目の間で API 参照名が競合しないように、右側のデータソースの項目に付けるプレフィックスを入力します。
    結合ノードでは、右側のすべての項目の API 参照名プレフィックスが先頭に追加されます。たとえば、プレフィックスとして Case を指定した場合、右側の項目の API 参照名はすべて「Case」で始まります。
  9. 右パネルの列タブで、一括処理データ変換に含める列を選択します。
    [ソース] 列には、各列の取得元のオブジェクトが表示されます。
  10. 列をプレビューするには、[プレビュー] をクリックします。
    プレビュー中の列を非表示にするには、[非表示] ボタン () をクリックします。非表示の列もデータ変換には引き続き含まれます。列を表示するには、[表示] ボタン () をクリックします。プレビューには、最大で 100 列を表示できます。
  11. 変更を適用し、一括処理データ変換を保存します。

クロス結合

クロス結合では、関連のないレコードを組み合わせて、左と右の入力データソースオブジェクトのすべての行を含めます。キーを使用して一致を検索する他の結合とは異なり、クロス結合では、1 つのデータソースのすべての行を別のデータソースのすべての行と組み合わせます。

ヒント クロス結合を設計する場合、大きいオブジェクト (左) を最初に使用してから、小さいオブジェクト (右) を結合します。たとえば、次のように結合します。
  • 10,000 行の入力ソース (左) と 1,000 行の入力ソース (右)
  • 20,000 行の入力ソース (左) と 500 行の入力ソース (右)
  • 40,000 行の入力ソース (左) と 250 行の入力ソース (右)
  • 100,000 行の入力ソース (左) と 100 行の入力ソース (右)
例

会社は、さまざまな場所で商品を販売しています。在庫追跡を支援するために、クロス結合を使用して商品とストアのデータを組み合わせて、考えられる商品とストアのすべてのペアを見つけます。

この結合で関連のないレコードを組み合わせる方法を説明するために、参照用に行番号が含まれていますが、データには必要ありません。

クロス結合の制限事項

クロス結合では、どちらの入力データソースよりも大きな出力が作成されるため、いくつかの制限があります。クロス結合の設計とテストを行う場合は、次の点に留意してください。

  • データ変換あたり 1 つのクロス結合のみ
  • クロス結合の結果の最大数は 1,000 万件
  • 左オブジェクトの項目 (列) は最大 8 件、行は最大 100,000 件
  • 右オブジェクトの項目 (列) は最大 8 件、行は最大 1,000 件
  • 複数値項目はサポートされていません

内部結合

内部結合では、左と右の入力データソースオブジェクトの一致行のみが含まれます。複数行が一致している場合、すべての一致行が出力データに含まれます。

例

会社のマーケティングチームは、Salesforce に保存されている商談の外部データソースのデモグラフィックデータを取得します。顧客の教育レベルで商談を比較するために、まず内部結合を使用して両方のデータセットを結合しましょう。

この一括処理データ変換機能で不一致行と重複キーをどのように処理するのかを説明するために、それらを両方の入力データソースに含めました。

一致のあるすべての行が出力に含まれています。複数の一致のため、Opp_ID 2 ([Amy] と [Bob]) のレコードが 2 つ、Opp_id 1 ([High School (高等学校)] と [Secondary School (中等学校)]) のレコードが 2 つ表示されています。また、Opp_ID 4 と Opp_id 5 は一致がないため対象から除外されています。
