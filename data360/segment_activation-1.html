世帯でのセグメントの有効化

Data Cloud の世帯オブジェクトで作成されたセグメントを有効化して、それらの世帯内の個人を対象にします。

特定の世帯を識別するセグメントを作成する場合、有効化を使用してマーケティングキャンペーンを世帯に送信できます。世帯自体にはメールアドレスなどの連絡先がないため、有効化プロセスは世帯内の個人を対象とします。

世帯オブジェクトに基づいて構築されたセグメントを選択したら、有効化メンバーシップを使用してそのメンバーを対象とする方法を選択できます。これは有効化エンティティです。

世帯で有効化: 世帯あたり 1 個人または統合個人を対象

セグメント内の世帯ごとに、Data Cloud は対象として最適な個人または統合個人を選択します。Data Cloud では、設定されたソースの優先度と連絡先の絞り込みルールを使用して、世帯を表す個人または統合個人と連絡先 (最も信頼性の高いメールアドレスなど) を判断します。これは、カタログや、世帯宛ての 1 つのプロモーションメールなど、各世帯に 1 回しか到達する必要のないキャンペーンに役立ちます。

統合個人または個人で有効化: すべての世帯メンバーを対象とする

セグメント内の世帯ごとに、Data Cloud はその世帯に関連付けられているすべての個人 (または統合個人) を対象とします。有効化により、世帯内の各個人のレコードが宛先対象に送信されます。このオプションは、ファミリーモバイルプランのオファー、地域のイベントのお知らせ、新しいストリーミングサービスに関する情報など、メッセージが各個人に関連するキャンペーンに役立ちます。

有効化メンバーシップの絞り込みによる利用者の絞り込み

世帯の特定のメンバーがキャンペーンメッセージの受信を希望していない場合があります。たとえば、特定のサービスまたは商品をまだ使用していない世帯の個人にのみ特別オファーを送信する場合があります。これは、有効化メンバーシップの絞り込みで実現できます。

この機能は、セグメント対象エンティティ (世帯) が有効化エンティティ (個人または統合個人) と異なる場合に便利です。セグメントですでに選択されている世帯のメンバーに第 2 の絞り込みを適用できます。

たとえば、キャンペーンの目標は、年間パスを持つメンバーが 1 人以上いるすべての世帯にプロモーションオファーを送信し、年間パスを持たない世帯の個人にのみオファーを送信することです。

セグメントで、年間パス所有者が 1 人以上の世帯を識別できます。これらのホームの非登録者にプロモーションオファーを送信するには、最初に個人または統合個人で有効化してすべての世帯メンバーを対象にします。次に、[有効化メンバーシップの絞り込み] を使用して、[年間パス所有者] が「いいえ」など、年間パスのない世帯の個人を対象にします。このアクションは、世帯の目的のメンバーのみを対象にします。

Data 360 滝セグメントのサブセグメントの有効化

ウォーターフォールセグメントの個々のサブセグメントまたはすべてのサブセグメントを同時に有効化できます。ウォーターフォールセグメントのすべてのサブセグメントを 1 つのデータエクステンションに含めることで、複数の有効化や有効化後の追加のステッチが不要になります。データエクステンションを有効化すると、すべてのユーザーがジャーニーに入力されますが、サブセグメントに基づいて異なるパスに転送されます。これにより、マーケティングキャンペーンの効果と効率が向上します。ウォーターフォールセグメントを作成したら、Marketing Cloud Engagement 有効化対象または任意のファイルストレージ対象に対してセグメントを有効化します。

有効化するウォーターフォールセグメント内のサブセグメントを選択するときに、[すべてのセグメント] または個々のサブセグメントを選択できます。有効化の結果は、選択内容によって異なります。

たとえば、ウォーターフォールセグメントにサブセグメント A、B、C が含まれているとします。この 3 つのセグメントをすべて対象に有効化するには、 ［すべてのセグメント］ を選択します。その後、サブセグメント D と E をウォーターフォールセグメントに追加すると、自動的に次の公開で有効化されます。

ただし、サブセグメント A、B、C を個別に有効化した場合、後でウォーターフォールに追加したサブセグメントは次の公開に自動的に含まれません。代わりに、有効化するこれらのサブセグメントを手動で選択する必要があります。

有効化と有効化対象

有効化は、セグメントを有効化プラットフォームに公開するプロセスで、そのデータに対してアクションを実行できます。有効化対象は、Marketing Cloud Engagement や Meta などの特定の有効化プラットフォームの認証および承認情報を保存するために使用されます。

対象を作成したら、連絡先と追加の属性を含むセグメントを有効化対象に公開できます。これにより、パーソナライズされたマーケティングキャンペーンを強化し、効果的な広告キャンペーンを作成し、一貫したカスタマーエクスペリエンスを提供できます。

  • Data 360 の有効化対象
    使用事例に応じて、ファイルを保存したり、外部で有効化したり、Data 360 の他のデータモデルオブジェクト (DMO) に対してデータを有効化できます。 Data 360 のセグメント化されたデータに対してアクションを実行する場所がわかったら、プラットフォームごとに有効化対象を作成します。
  • Data 360 セグメントの有効化
    有効化は、セグメントを Data 360 の有効化プラットフォームに公開するプロセスです。 セグメントを有効化する前に、有効化の概念を確認することが重要です。
  • Data 360 データモデルオブジェクトの有効化
    データモデルオブジェクト (DMO) を有効化して、さまざまなソースのデータを使用して完全な顧客プロファイルを作成します。この機能は、すぐにアクション可能な形式でデータを表示し、パーソナライズされたカスタマーエクスペリエンスを促進します。Data 360 では、ストリーミングとバッチの 2 つの方法で DMO を有効化できます。それぞれは、さまざまな使用事例や対象に合わせて設計されています。
  • 有効化テンプレートを使用した有効化の標準化
    有効化テンプレートを使用して、再利用可能な有効化設定を定義および保存します。これらの設定には、連絡先の選択、ソースの優先度、検索条件、強化データ、メンバーシップの絞り込みの設定が含まれます。これらのテンプレートを使用して、サポートされているすべての有効化プラットフォームで一貫性のある定義済みの設定を使用して有効化を作成します。
  • Data 360 での API 有効化の作成
    API 有効化により、有効化を開始できる場所と方法が広がります。API 有効化では、API コールを使用してフローから Data 360 有効化を柔軟に使用できます。
  • Data 360 を使用した広告
    Data 360 を使用して、ファーストパーティデータを使用した広告戦略を実装します。Data 360で信頼できる情報源を確立し、外部広告プラットフォームに接続して、すべてのチャネルで高度に対象を絞ったパーソナライズされた環境を提供します。
  • B2C エンゲージメントのコミュニケーションの制限
    B2C の顧客、リード、見込み客とのコミュニケーションに上限を設定して、規制要件へのコンプライアンスを確保し、カスタマーエクスペリエンスを向上させ、メッセージの疲労を回避します。部門レベルのしきい値を適用して、部門全体のキャンペーン費用予算を最適化します。対象エンティティへの迷惑で規制されていないコミュニケーションを回避して、規制要件へのコンプライアンスを維持します。
  • 有効化の公開履歴
    Data Cloud で、有効化履歴を表示して、セグメントが公開されたタイミングと方法を確認します。Marketing Cloud Engagement 有効化対象に公開されたセグメントの場合、追加の [承諾済み] 列が有効化履歴に表示され、詳細を表示できます。セグメントレコードで同じ公開履歴の詳細を表示します。
  • 有効化種別と対象の互換性
    有効化種別、公開スケジュール、サポートされる有効化対象の概要。
  • 有効化の更新種別
    有効化を作成するときに、フル更新または増分更新の 2 つの更新種別から選択します。フル更新では、有効化中にセグメントのすべてのレコードが更新されます。増分更新では、前回の成功した更新以降に追加、更新、および削除されたレコードのみが公開されます。
  • 有効化エラーのトラブルシューティング
    Data 360 で一般的な有効化エラーを解決するためのヒントを紹介します。

Marketing Cloud Engagement の有効化での整合性の確保

複数の Marketing Cloud Engagement (MCE) 組織 (EID) が有効化に関与する場合、意図しないデータが混在してしまう可能性があります。これは、異なる EID の登録者キーが同じデータスペースに取り込まれ、後で特定の EID に対して有効化された場合に発生します。これにより、データの整合性の問題が発生する可能性があります。

データの混在が心配な理由は?

  • 登録者キーは、異なる EID 間で一意であるとは限りません。つまり、同じ鍵 (SK1 など) が別々の EID で完全に異なる個人に属する可能性があります。
  • 複数の EID から登録者キーをまとめて有効化すると、誤った個人にメッセージを送信するリスクがあります。たとえば、Tech Gadgets (EID 1) と Home Essentials (EID 2) という別々の EID で 2 つのブランドを運営する会社があるとします。両方の EID の登録者データが誤って有効化に含まれていた場合、Tech Gadgets の顧客は、そのブランドを操作していなくても Home Essentials プロモーションを受信する可能性があります。さらに悪いことに、Home Essentials からオプトアウトした場合、コンプライアンス違反につながる可能性があります。
  • 組織は、ユーザーの同意を尊重し、データを分離することでコンプライアンスを維持する必要があります。同じ個人が EID 間で異なるコミュニケーションチャネルに同意できます。たとえば、EID3 ではメールに同意し、EID4 では WhatsApp に同意することもできます。 データをサイロ化することで、異なる EID 間で意図しない同意設定が使用されないようにします。
例

組織が 3 つの Marketing Cloud 接続 (EID) とさまざまなビジネスユニット (BU) を使用して登録者データを管理しているとします。各 EID には一意の登録者キー (SK) のセットがあります。

  • EID1 は BU1、BU2、BU3 (SK1 ～ SK15) に対応します。
    • BU1 は SK1 ～ SK5 をカバー
    • BU2 は SK6 ～ SK10 をカバー
    • BU3 は SK11 ～ SK15 をカバー
  • EID2 は BU4、BU5、BU6 (SK16 ～ SK30) に対応します。
    • BU4 は SK16 ～ SK20 をカバー
    • BU5 は SK21 ～ SK25 をカバー
    • BU6 は SK26 ～ SK30 をカバー
  • EID3 は BU7、BU8、BU9 (SK31 ～ SK45) に対応します。
    • BU7 は SK31 ～ SK35 をカバー
    • BU8 は SK36 ～ SK40 をカバー
    • BU9 は SK41 ～ SK45 をカバー

整理するために、登録者データはデータスペース (DS) にグループ化されます。

  • DS1 には、EID1 (BU1、BU2、BU3) のデータのみが含まれます。
  • DS2 には、EID2 のデータ (BU4、BU5、BU6) のみが含まれます。
  • DS3 には、EID3 (BU7、BU8、BU9) のデータのみが含まれます。
  • DS-Global にはすべての EID (BU1 ～ BU9) が含まれます。
  • DS5 には、EID1 (BU2、BU3) と EID2 (BU4、BU5) のデータが含まれます。

有効化シナリオ

シナリオ 1: DS1 を使用した有効化

DS1 を使用して有効化対象を作成する場合、EID1 のデータ (BU1、BU2、BU3) のみを使用します。

  • つまり、Marketing Cloud Engagement 対象 (MC1) では、SK1 から SK15 までの登録者キーのみが有効化されます。
  • データの混在が防止されます。DS1 には EID1 データのみが含まれているため、EID2 または EID3 のデータを混在させることはできません。

シナリオ 2: DS-Global を使用した有効化

DS-Global にはすべての EID のデータが含まれますが、(EID1 に属する) BU1 のみを有効化する場合は次のようになります。

  • DS-GlobalにEID2とEID3のデータが含まれている場合でも、SK1~SK15(EID1)のみが有効化されます。[Allow Profile Business Unit Mapping Data (BU-aware) (プロファイルビジネスユニットマッピングデータを許可 (BU-アウェア))]が有効になっている場合、BU1のSKのみが有効化されます。
  • EID2 と EID3 からの SK16 から SK45 は自動的に有効化からブロックされるため、データの混在が防止されます。

シナリオ 3: DS5 を使用した有効化

DS5 は EID1 (BU2、BU3) と EID2 (BU4、BU5) が混在しており、BU4 のデータを有効化する必要があります。 

  • BU4はEID2に属しているため、MC2ではSK16~SK30(EID2)のみが有効化されます。 [Allow Profile Business Unit Mapping Data (BU-aware) (プロファイルビジネスユニットマッピングデータを許可 (BU-アウェア))]が有効になっている場合、SK16~SK20のみが有効化されます。 
  • (EID1 の) SK1 ～ SK15 がブロックされるため、データの混在が防止され、データの整合性が確保されます。

Data Cloud でのオーディエンスセグメントの作成

オーディエンスセグメントは、契約の有効期限が 4 か月以内の意思決定者で構成されます。今後の契約更新に関するリマインダーメールを作成します。

  1. Data 360 の [セグメント] タブで、[新規] をクリックします。
    1. [データスペース] で、[デフォルト] を選択します。
    2. [セグメント対象] で、取引先データモデルオブジェクト (DMO) を選択します。
    3. セグメントに「Upcoming Contract Renewals」 (今後の契約更新) という名前を付け、説明を追加します。
    4. [次へ] をクリックします。
  2. [公開種別] で、[公開スケジュールが 24 時間の標準公開] を選択します。
    この種別によって、セグメントで使用するエンゲージメントデータの量が決まります。スケジュールによって、データを更新する頻度が決まります。
  3. [Publish Schedule (公開スケジュール)] に、開始日時と有効期限を入力し、[保存] をクリックします。

Data 360 セグメントの有効化

有効化は、セグメントを Data 360 の有効化プラットフォームに公開するプロセスです。 セグメントを有効化する前に、有効化の概念を確認することが重要です。

有効化メンバーシップ

有効化メンバーシップは、有効化に含めるさまざまなデータモデルオブジェクト (DMO) の項目のグループ化です。ID 解決ルールセットを使用してデータを統合している場合、統合個人データモデルオブジェクト (DMO) を有効化メンバーシップとして使用する必要があります。

「Unified Individual for Activation Membership」を参照してください。

有効化

既存の有効化をコピーして、さまざまなセグメントで検索条件やその他の選択を再利用します。既存の有効化をコピーして新しいオプションを作成する場合、対象と有効化メンバーシップは変更できません。

連絡先

連絡先は、個人に連絡したりエンゲージしたりするために使用できるデータポイント (メールや電話など) を表す項目または一連の項目です。連絡先を選択することで、有効化に含められ、有効化対象に送信されるオブジェクトと項目が決まります。同意関連の検索条件を連絡先に適用して同意を管理することもできます。

[Contact Points and Source Priority Order (連絡先とソースの優先順序)] に関する詳細を確認します。

関連属性の追加

有効化にカスタム検索条件と属性を追加して、よりパーソナライズされたコミュニケーションを送信します。有効化するときに、有効化対象に送信されるデータに含める属性を選択します。

関連属性を有効化する方法を学習します。

有効化の更新種別

有効化を作成するときに、フル更新または増分更新の 2 つの更新種別から選択します。フル更新では、有効化中にセグメントのすべてのレコードが更新されます。増分更新では、前回の成功した更新以降に追加、更新、および削除されたレコードのみが公開されます。

詳細は、[有効化更新種別] ページを参照してください。

データプライバシー種別

本人のデータのサードパーティへの共有または販売を禁じる権利を消費者に付与するカリフォルニア州プライバシー権法 (CPRA) に準拠するには、有効化でのデータプライバシー種別について理解します。プライバシー種別は、[CPRA サードパーティ] および [CPRA サービスプロバイダー] で、該当しません。これらは、Data Cloud の [設定] で外部有効化プラットフォームを設定するときに設定できます。

各プライバシー タイプについての詳細は、California Privacy Protection Agencyを参照してください。

Data Cloud One での有効化

Data Cloud One は、ブランド、ビジネスユニット、または地理的地域にまたがる複数組織の企業がすべての組織の Data 360 コア機能にアクセスできるプラットフォーム機能です。すべての組織は、ホーム組織にプロビジョニングされた 1 つの Data 360 インスタンスから同期されます。ホーム組織で作成された有効化定義は、企業のエコシステム内のすべての接続済みコンパニオン組織から参照できます。

Data Cloud One とコンパニオン組織の詳細については、「Data Cloud One」を参照してください。

  • Marketing Cloud Engagement 対象の有効化の作成
    Data 360 でセグメントを作成したら、セグメントを有効化対象に公開できます。
  • Data 360 ターゲットの有効化の作成
    Data 360 でセグメントを作成したら、Data 360 有効化対象に公開できます。
  • B2C Commerce ターゲットの有効化の作成
    必須のデータ項目のマッピングを設定し、Data Cloud でセグメントを作成したら、B2C Commerce 有効化を作成してセグメントを公開します。
  • ファイルストレージ対象の有効化の作成
    Data 360 でセグメントを作成したら、セグメントを有効化対象に公開できます。
  • 外部プラットフォームの有効化の作成

  • 有効化への関連属性の追加
    関連属性と検索条件を適用して、よりパーソナライズされたコミュニケーションを送信します。Marketing Cloud Engagement、Data Cloud、および Amazon S3、SFTP、Microsoft Azure Blob Storage、Google Cloud Storage (GCS) などのクラウドファイルストレージプラットフォームに関連属性を送信できます。
  • 連絡先とソースの優先順序
    連絡先を選択することで、有効化に含められ、有効化対象に送信されるオブジェクトと項目が決まります。ソースの優先順序を使用すると、有効化に選択される連絡先値を決定できます。

    Data 360セグメントを有効化するときに、連絡先の絞り込みと並び替えを行って、適切な権限を持つ適切なチャネルの適切な利用者を対象にすることができます。この機能は、顧客の同意を管理し、メッセージの重複を防止し、キャンペーンのパーソナライズを改善するために不可欠です。
  • 有効化メンバーシップへの検索条件の追加
    Data 360 アクティベーション メンバーシップ フィルタを使用すると、カスタム フィルタをアクティベーション メンバーシップに追加して、よりパーソナライズされたコミュニケーションを送信できます。検索条件を追加して、対象利用者のみが対象になるようにします。
  • Data 360 滝セグメントのサブセグメントの有効化
    ウォーターフォールセグメントの個々のサブセグメントまたはすべてのサブセグメントを同時に有効化できます。ウォーターフォールセグメントのすべてのサブセグメントを 1 つのデータエクステンションに含めることで、複数の有効化や有効化後の追加のステッチが不要になります。データエクステンションを有効化すると、すべてのユーザーがジャーニーに入力されますが、サブセグメントに基づいて異なるパスに転送されます。これにより、マーケティングキャンペーンの効果と効率が向上します。ウォーターフォールセグメントを作成したら、Marketing Cloud Engagement 有効化対象または任意のファイルストレージ対象に対してセグメントを有効化します。
  • 有効化の計算済みインサイト
    Data 360の計算済みインサイトを使用して、有効化ジャーニーの意思決定とメッセージのパーソナライズを可能にします。
  • セグメンテーション検索条件と有効化検索条件

有効化の更新種別

有効化を作成するときに、フル更新または増分更新の 2 つの更新種別から選択します。フル更新では、有効化中にセグメントのすべてのレコードが更新されます。増分更新では、前回の成功した更新以降に追加、更新、および削除されたレコードのみが公開されます。

メモ 既存のレコードへの変更は、12 時間に 1 回のみ処理されます。その 12 時間以内の追加の実行には、新しく追加または削除されるレコードのみが含まれます。

増分有効化では、必要な更新の正確な種別を定義できます。不要なデータを処理せずに特定の変更のみを受信するように選択します。たとえば、有効化の実行ごとに新しく追加されたプロファイルのみが必要な場合、次のオプションのいずれかまたは両方を選択して、要件に合わせてデータをカスタマイズできます。

  • Exclude records modified since the last refresh：前回の有効化以降に更新されたレコードが現在の有効化に含まれないようにします。
  • Exclude records deleted since the last refresh：前回の有効化以降に削除されたレコードが現在の有効化に含まれないようにします。
メモ 除外オプションは、Google広告、Meta、LinkedIn、その他の戦略的パートナーの有効化などの外部有効化プラットフォームとAppExchangeのISVエコシステム有効化プラットフォームには適用されません。

有効化を作成する場合、使用可能な更新種別は有効化対象によって異なります。

有効化を編集するときに、有効化対象に応じて、フル更新を増分更新に変更できます。増分更新に切り替えた後に、フル更新に戻すことはできません。

考慮事項

  • すべての有効化対象の最初の公開は、選択した更新種別に関係なく、常にフル更新です。有効化を変更するたびに、フル更新もトリガーされます。どちらの場合も、有効化全体が対象に転送されます。
  • 増分更新の進行中にフル更新がキューに入れられると、公開キューが最適化されます。現在の更新が完了すると、最新の更新を除くすべての待機中の更新がSKIPPEDとしてマークされ、最新の待機中の更新がフル更新 (完全上書き) に変換されて実行されます。
  • エコシステムパートナーの場合、有効化されたオーディエンスは、特定の間隔で有効化されたすべてのセグメントを統合します。
  • 有効化に失敗した場合、次の更新は、公開に最後に成功したセグメントからの増分になります。
  • Marketing Cloud Engagement または Marketing Cloud Personalization に対する新しい有効化の場合は、デフォルトで増分更新が選択されます。24 時間経過するごとに、手動でフル更新をトリガーできます。既存のフル更新有効化を増分に変更できます。
  • 戦略的パートナーまたは Marketing Cloud Personalization の場合、既存の有効化を編集すると、アップグレードされたパッケージでフル更新の有効化を増分に変更できます。
  • Marketing Cloud ターゲットの場合、有効化を編集してフル更新と増分を切り替えると、Data 360 によって Marketing Cloud Engagement に新しいデータエクステンション (DE) が作成されます。増分に切り替えると、最初の実行でフル更新が実行され、セグメント全体が新しい DE に読み込まれます。対象 DE が存在しない場合は、フル更新も自動的に実行されます。後続の実行では、登録者キーをプライマリキーとして使用して増分更新/挿入が実行されます。DE を変更したら、既存のジャーニーを新しい DE に再接続します。
  • 有効化を編集し、更新種別 (フルまたは増分) を切り替えると、有効化ペイロードは Marketing Cloud Engagement の新しいデータエクステンション (DE) に書き込まれます。増分に変更した場合、セグメント全体を新しい DE に移動するためのフル更新が実行されます。それ以降の有効化は、既存の取引先責任者への更新の主キーとして購読者キーを使用してペイロードの変更を DE にマージする増分更新となります。Marketing Cloud Engagement で、既存のジャーニーを新しい DE に接続します。
  • Marketing Cloud Engagement の場合、公開後にセグメント数がゼロになることがあります。たとえば、2 日後に誕生日を迎えるメンバーにプロモーションを提供するセグメントを作成します。現在の日付が誕生日を過ぎると、すべてのメンバーが削除されます。有効化で検索条件を追加すると、ペイロードの一部のセグメント化されたメンバーが除外され、これらのメンバーには削除を意味する D が付けられます。
  • セグメントを有効化する場合、対象が Marketing Cloud Engagement と Amazon S3 の場合では違いがあります。 Marketing Cloud Engagement の場合、Marketing Cloud API は購読者 ID をキーとして更新するように DE に書き込みます。Amazon S3 では、増分ペイロードにはオーディエンス側での追加、削除、更新が含まれます。そして、Amazon S3 がペイロードを消費して処理します。
  • オーディエンス DMO のデフォルトの存続可能時間 (TTL) は 30 日であるため、間隔が 30 日を超えると増分更新で無効な結果になります。データの精度を維持するには、更新サイクルが 30 日以上の有効化にフル更新を使用することを検討してください。

Data 360 の有効化対象

使用事例に応じて、ファイルを保存したり、外部で有効化したり、Data 360 の他のデータモデルオブジェクト (DMO) に対してデータを有効化できます。 Data 360 のセグメント化されたデータに対してアクションを実行する場所がわかったら、プラットフォームごとに有効化対象を作成します。

有効化対象の作成

有効化対象の実装手順は似ていますが、一部の手順は異なる場合があります。作成する特定の目標の ToDo ステップを確認します。より具体的な考慮事項やトラブルシューティング手順については、作成する特定の目標のタスク手順を確認してください。

編集または削除

作成した既存の目標を編集または削除できます。有効化対象の削除は、有効化対象を使用するすべてのセグメントに適用されます。

有効化または無効化

有効化対象名の横にあるドロップダウンメニューを使用して、有効化対象を有効化または一時的に無効化することもできます。

  • Marketing Cloud Engagement 有効化対象の作成
    セグメントと一括処理データモデルオブジェクト(DMO)をMarketing Cloud Engagementビジネスユニットに公開するには、Data 360で有効化対象を作成します。
  • Marketing Cloud Personalization 有効化対象の作成
    Marketing Cloud Personalization (旧称 Interaction Studio) にセグメントを公開するには、Data 360 で有効化対象を作成します。
  • Data 360 有効化対象の作成
    Data 360 で有効化対象を作成し、セグメントと一括処理データモデルオブジェクト (DMO) を利用者 DMO に公開します。オーディエンス DMO にデータを公開することで、内部または外部の対象システムに直接接続することなくセグメントや DMO のデータにアクセスできます。
  • Data 360 ロイヤルティ有効化対象の作成
    Loyalty Cloud で使用するセグメントを公開するには、Data 360 で有効化対象を作成します。Salesforce に対して 1 つの有効化対象を作成できます。
  • B2C Commerce 有効化対象の作成
    セグメントを Commerce Cloud に公開するには、Data 360 で有効化対象を作成します。
  • ファイルストレージ有効化対象の作成
    Data 360 で有効化対象を作成し、セグメントと一括処理データモデルオブジェクト (DMO) を Amazon S3、SFTP、Google Cloud Storage (GCS)、Microsoft Azure Blob Storage などの外部ファイルストレージ有効化プラットフォームに公開します。
  • 外部プラットフォーム有効化対象の作成
    Amazon 広告などの外部広告プラットフォームにセグメントを公開するには、Data 360 で外部プラットフォームの有効化対象を作成します。 外部プラットフォームには複数の有効化対象を設定できますが、外部プラットフォームアカウントに添付できる有効化対象は 1 つのみです。

有効化テンプレートを使用した有効化の標準化

有効化テンプレートを使用して、再利用可能な有効化設定を定義および保存します。これらの設定には、連絡先の選択、ソースの優先度、検索条件、強化データ、メンバーシップの絞り込みの設定が含まれます。これらのテンプレートを使用して、サポートされているすべての有効化プラットフォームで一貫性のある定義済みの設定を使用して有効化を作成します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。

連絡先とメンバーシップの絞り込み、ソースの優先度、強化データなどの有効化機能により、有効化の作成がより複雑になりました。チームは多くの場合、特に同意コンプライアンスと連絡先の選択のために、多くのキャンペーンで同じ絞り込み、優先度、強化ロジックを再利用します。

有効化テンプレートでは、一般的な有効化設定を一度保存して、有効化の作成時に適用することで、この問題を解決できます。有効化ロジックを毎回最初から設定するのではなく、テンプレートを選択すると、Data 360 によってテンプレートの保存済み設定が有効化に事前入力されます。

メモ セグメントトリガーフローでも有効化テンプレートが使用されます。フローエンジンはテンプレートの保存済みロジックを読み取り、セグメント内の各個人の正しい連絡先を選択します。

有効化テンプレートの利点

  • 連絡先選択ロジック、強化データ、検索条件を 1 回定義し、複数の有効化で再利用します。
  • ソース優先度ルール、連絡先検索条件、メンバーシップ検索条件を手動で再設定することなく一貫して適用します。
  • GDPR などの規制要件を満たすために、同意と連絡先フィルターの設定を標準化します。
  • Amazon S3、Marketing Cloud、AppExchange、戦略的パートナー先など、さまざまなプラットフォームでテンプレートを使用します。
  • セグメントトリガーフローでは、有効化 UI 専用の機能である連絡先選択ロジックを使用できます。

有効化テンプレートのしくみ

有効化テンプレートは、連絡先チャネル、ソースの優先度、強化データ、メンバーシップの絞り込みロジックなどのメタデータを保存する再利用可能な設定です。

各テンプレートは、個人や統合個人など、特定のデータスペースとデータモデルオブジェクト (DMO) に関連付けられます。DMO とプラットフォームの関連付けによって、テンプレートを参照できる有効化とフローが決まります。

有効化を作成してテンプレートを選択すると、Data 360 は有効化の設定を事前入力するためのブループリントとしてテンプレートを使用します。その後、保存する前に事前入力された項目を確認して編集できます。テンプレートから有効化を作成すると、Data 360 によってリンクが削除されます。その後テンプレートを変更しても、既存の有効化には影響しません。

テンプレートコンポーネント

有効化テンプレートには、次の設定を含めることができます。

  • 連絡先チャネル: メール、電話 (SMS)、WhatsApp などの事前選択されたチャネル。
  • ソース優先度: 同じチャネルに複数の値が存在する場合の連絡先値の評価順序。ソース優先度テーブルの各行は、ソース、ソースオブジェクト、連絡先種別、有効状況の組み合わせを表します。テーブルの上の行が優先されます。
  • 連絡先検索条件: 連絡先 DMO または同意 DMO に適用される条件を絞り込み、準拠する有効な連絡先のみが選択されるようにします。
  • 強化データ: 有効化出力に含める直接属性と関連属性。
  • 有効化メンバーシップの絞り込み: 有効化に含まれるセグメントメンバーを絞り込む条件。

Data 360有効化ツールキットを使用すると、独立系ソフトウェア ベンダー(ISV)はAppExchangeで有効化プラットフォームを構築できます。これらのプラットフォームにより、登録者組織は ISV 有効化サービスをインストールして使用できます。これにより、Data 360 データと対象データペイロードを照合し、複数キー照合、連絡先の絞り込み、有効化メンバーシップでの追加 DMO のサポートなどの高度な機能を使用できます。

このツールキットを使用すると、マーケティングチーム、営業チーム、データチームは、外部プラットフォーム間で既知のファーストパーティデータと匿名のファーストパーティデータの両方を有効化できます。Data 360 の標準またはカスタムデータモデルオブジェクト (DMO) の属性をマッピングして、キャンペーンの実行を最適化できます。

  • outputGrouping が PER_USER に設定されている場合は、isIdentifier を true に設定して、すべてのアクティベーション属性が ID として設定されていることを確認します。
  • outputGrouping が PER_SEGMENT に設定されている場合、isIdentifier を true‌ に設定して、少なくとも 1 つの属性が識別子であることを確認します。
  • 少なくとも 1 つの属性が "applyHash": true に設定されている場合、activationPlatformAdditionalMetadata でハッシュメソッドを "hashMethod": "SHA256" として指定します。
  • 有効化対象の項目の配列には少なくとも 1 つのエントリが含まれている必要がありますが、5 つを超えるエントリを含めることはできません。AccountId は必須項目です。サンプル JSON で指定されているフィールド "name": "AccountId" を使用します。この項目は更新または削除しないでください。
  • 属性リストに objectName として ContactPointDigitalId を含める場合は、activationPlatformAdditionalMetadata に「PartnerSupportedIds」オブジェクトを指定します。ContactPointDigitalId の destinationName が「partnerSupportedIds」で指定された destinationName と一致することを確認します。Id、ID、または id を有効化アトリビュートの destinationName として使用しないでください。
  • activationAttribute の destinationName が partnerSupportedIds の destinationName と一致する場合、activationAttribute の objectName を "objectName": "ContactPointDigitalId" のように指定します。
  • partnerSupportedIds が定義されている場合は、supportedIdTypes を指定し、destinationName 項目に null を入力しないでください。
  • JSON を更新する場合、少なくとも 1 つの supportedIdType を保持する必要があります。
重要 パッケージを作成して有効化プラットフォームを設定したら、JSON を更新してoutputGrouping、destinationNameを変更したり、有効化属性またはsupportedIdTypesを削除したりしないでください。これらの変更は、これらの設定を使用してすでに有効化を設定している既存のユーザーに影響する可能性があります。

ベストプラクティスと推奨事項

  • メールデータの正規化を機能させるには、メールの優先 destinationName を EmailAddress に設定します（大文字と小文字は区別されます）。
  • email や phone などの属性のユーザー識別子値をハッシュする場合は、各属性レベルで "applyHash" : true を設定します。
  • 有効化後、特定のフォルダーが優先先名で Amazon S3 バケットに自動的に作成されます。ただし、連絡先デジタル ID DMO が使用されている場合、ISV パートナーが supportedIdTypes 項目で指定した値がフォルダー名として使用されます。
  • 最適なパフォーマンスを得るには、maxFileSizeInMBの512 MBを超えないことをお勧めします。この省略可能な項目が設定されていない場合、デフォルトの 128 MB になります。
  • 5,000,000 maxRecordsPerFile を超えないことをお勧めします。この省略可能な項目が設定されていない場合、システムはデフォルトで 1,000,000 件のレコードを使用します。
  • maxFileSizeInMB 値と maxRecordsPerFile 値を含めると、各出力ファイルが指定したサイズとレコード件数の制限内に収まるようになります。
  • minRecordsPerFile が設定されている場合は、maxRecordsPerFile 以下であることを確認します。
  • outputPartitions は、有効化の実行ごとに出力場所で生成されるファイルの数を制御します。出力がセグメントでグループ化されている場合、JSON で定義された outputPartitions はセグメントの公開ごとに適用され、有効化の実行とみなされます。詳細は、「クラウドファイルストレージでの外部有効化プラットフォームセグメントの検索」を参照してください。
  • プラットフォーム出力がユーザー識別子ごとにグループ化されている場合、24 時間の更新頻度は、顧客が作成した有効化対象ごとに有効化の実行とみなされます。詳細は、「クラウドファイルストレージでの外部有効化プラットフォームセグメントの検索」を参照してください。
  • outputPartitions と minRecordsPerFile によって、データのパーティションへの分割方法が決まります。outputPartitions が設定されている場合は、それが優先されます。それ以外の場合、パーティションは minRecordsPerFile とすべての出力ファイルのレコード総数に基づいて計算されます。outputPartitions フィールドが設定されていない場合、合計レコード数を minRecordsPerFile 値で除算してパーティション数を計算します。
  • PartnerSupportedIds セクションで、supportedIdTypes の下に、activationAttributes セクションで ContactPointDigitalId に対応付けられている属性のみを含めます。たとえば、メール属性と電話属性が ContactPointDigitalId に対応付けられていない場合は、supportedIdTypes から除外します。
メモ exportDirectory  を "exportDirectory": "/" に設定すると、アクティベーション ファイルは指定された S3 バケットのルート ディレクトリにアップロードされます。エクスポートされたファイルを整理するために、日付ベースのフォルダー構造が自動的に作成および管理されます。

有効化数とセグメント数の相違

さまざまな要素により、有効化数とセグメント数に違いが生じる可能性があります。

  • 異なるオブジェクトでのセグメント化と有効化: 数が異ならないようにするには、同じオブジェクトで有効化します。
  • 2 つ以上のデータストリームからデータが取得されている: DLO と DMO からのデータマッピングを確認します。

    2 つのデータストリームから取得されている個人 ID に、DMO の異なる項目にマッピングされている属性がある場合、レコードが重複する可能性があります。

    セグメンテーションでは、個人 ID が個別に数えられます。重複する ID がある場合、セグメンテーションではその ID が 1 回数えられます。有効化では、ID と属性内の値が同じである複数のレコードがある場合、重複排除されます。

  • 統合データモデルオブジェクト (DMO) での有効化からの複数のレコード: 統合されていない DMO で有効化するか、N:1 リレーションの属性を選択しないでください。

    統合 DMO で有効化していて、直接属性を選択している場合は、有効化オブジェクトと有効化された DMO のリレーションを確認します。いずれかの DMO に N:1 リレーションがある場合、複数のレコードがある可能性があります。

セグメンテーション検索条件と有効化検索条件

セグメンテーションと有効化では、目的と使用する検索条件が異なります。検索条件をセグメントに適用して、オーディエンスを絞り込みます。有効化検索条件を使用して、メッセージをパーソナライズする関連属性で関連する値を絞り込みます。

たとえば、オンライン小売業者が、過去 2 か月間にビデオゲームを購入した顧客を対象としたメールキャンペーンを実行するとします。顧客が最近購入したビデオゲームの商品名を含めてメッセージをパーソナライズします。

検索条件を適用して、セグメンテーションのプロセスを開始し、過去 2 か月間にビデオゲームを購入した顧客にオーディエンスを絞り込みます。

有効化で、[商品名] 関連属性を追加し、顧客が購入した品目の商品名を含めます。ただし、過去 2 か月間に、顧客はビデオゲーム以外を購入している可能性があります。メールにビデオゲームの購入のみを含めるには、[商品カテゴリ] [次の値と等しい] [ビデオゲーム] などの検索条件を属性に適用します。検索条件を属性に適用しない場合、顧客が購入した他の商品がメールに含まれます。

Conversion API (CAPI) による広告オーディエンスパートナープラットフォームへの有効化

オンラインおよびオフラインのコンバージョンイベントとデータを広告プラットフォームに直接送信します。CAPI インテグレーションは、セグメントの作成をスキップし、イベントシグナルをほぼリアルタイムで配信して、優れたキャンペーンの最適化とより明確な属性分析を実現します。

CAPI 有効化では、次のプラットフォームがサポートされます。

  • LinkedIn CAPI
  • メタ CAPI
  • TikTok CAPI
  • Snapchat CAPI

考慮事項

  • CAPI では、セグメントベースの有効化ではなく、DMO ベースの (ストリーミング) 有効化が使用されます。イベントソースとしてオーディエンスセグメントではなくデータモデルオブジェクトを選択します。
  • 各プラットフォームで API レート制限が適用されます。この制限を超えるイベントや、プラットフォームの最大ルックバック期間を超えるイベントは却下されます。
  • デフォルトでは、CAPI 有効化の公開ごとにバッチあたり最大 30,000 件のレコードが送信されます。30,000 件を超えるレコードのセグメントの場合、残りのレコードは連続する更新サイクルで一括で有効化されるため、最初の公開直後にすべてのオーディエンスがパートナープラットフォームに表示されない可能性があります。この制限は、要求に応じて 200,000 まで増やすことができます。
  • ID 強化のために幅広い顧客レコードセットを提供するには、データグラフを作成して CAPI 有効化に関連付けます。「データグラフ」を参照してください。
  • 名、姓、国コード、外部 ID などの省略可能な属性を対応付けると、パートナープラットフォームでのユーザーの一致率が向上します。

  1. [有効化] タブで、[新規] をクリックします。
  2. [セグメント] を選択します。

  • Amazon Ads
  • Google 広告
  • Google DV360
  • Google 広告マネージャー
  • LinkedIn キャンペーンマネージャー
  • Meta Ads Manager
  • Pinterest Business Manager
  • Snapchat 広告マネージャー
  • TikTok 広告マネージャー

考慮事項

  • プラットフォームプラットフォームでの一致率は、有効化時にマッピングする ID シグナルの品質と完全性によって異なります。ロケーション、電話番号、デバイス ID などの追加属性を対応付けると、一致率が向上します。
  • 各プラットフォームでは、セグメントの最小オーディエンスサイズが適用されます。この最小制限は、セグメントサイズではなく、一致したオーディエンス数に適用されます。一致したオーディエンスがプラットフォームの要件より低い場合、Data 360はセグメントをプラットフォームに送信しますが、プラットフォームはキャンペーンでそのセグメントを対象としません。たとえば、TikTok ではセグメントごとに合計 1000 人以上の一致ユーザーが必要です。そのため、5000 件のレコードを含むセグメントを TikTok に対して有効化する場合、セグメントのメンバーがセグメントの 1000 件以上のレコードをプラットフォームのユーザーと照合できる場合にのみ、TikTok はそのセグメントのメンバーを対象とします。
  • 最初の有効化の後、後続の更新はデフォルトで増分有効化されます。増分セグメントの有効化はセグメントの更新スケジュールに基づいて実行され、追加、更新、削除シグナルが含まれます。「有効化更新種別」を参照してください。
  • フル更新ではセグメント全体が再送信され、存続可能時間 (TTL) 制限が適用されるプラットフォームでの利用者の期限切れを防ぎます。フル更新を使用して、マッピングの大幅な変更やセグメントの更新を処理することもできます。特定のプラットフォームでは、フル更新では削除のみが行われ、その他のプラットフォームでは、何も削除せずに現在のセグメントメンバーシップ全体が再送信されます。
  • 最初の公開後に有効化検索条件を追加すると、検索条件は今後の増分更新にのみ適用されます。つまり、セグメントを有効化した後に有効化検索条件を追加しても、プラットフォームにすでに送信されたプロファイルは除外されません。有効化後にセグメントを更新するには、セグメントメンバーシップを編集するか、有効化を作成して、更新された検索条件がオーディエンスセグメントに反映されるようにします。
  • 複数のプラットフォームに対して有効化するには、同じセグメントを有効化する場合でも、プラットフォームごとに個別の有効化が必要です。
  • オーディエンスを作成して有効化すると、セグメンテーションクレジットと有効化クレジットが消費されます。

セグメントの母集団の概算

Data 360 でセグメントを作成するときに、[セグメントの母集団の概算] 項目を使用して、セグメント数が期待値を満たしていることをすばやく確認します。概算数は、95% の信頼性で可能な値の範囲として表される推定区分母集団を提供します。セグメントの母集団が小さい場合、またはセグメントのレコード件数が少ない場合、実際の母集団が推定範囲と異なる場合があります。その後、セグメントルールを調整してセグメントを保存すれば、最終的なセグメントの母集団を取得できます。この機能を使用するには、機能マネージャーで [セグメントの母集団の概算] を有効にします。

おおよそのセグメント母集団を計算するために、プロファイルデータセットのサブセットを使用し、このデータセットの検索条件を計算して母集団を数え、このデータをサンプリングパーセントに対して正規化します。この計算では、区分母集団の推定が提供されます。区分母集団は、95% の信頼性レベルで考えられる母集団値の範囲です。

  • おおよその数は、セグメント化されるプロファイルデータ自体が外部である場合を除き、ゼロコピーで機能します。この場合、おおよその数ではなく正確な数に戻ります。
  • [近似セグメント母集団] が有効になっている場合、検索条件レベルとコンテナレベルの数も近似数を返します。

セグメントからの Data 360 オブジェクトの作成

Data 360 有効化対象に対する有効化では、セグメントと属性を使用してオブジェクトを作成します。各 Data 360 組織には 1 つの Data 360 有効化対象を含めることができ、各有効化対象には複数のオブジェクトを含めることができます。複数のセグメントで同じオブジェクトを選択できます。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
セグメントからオブジェクトを作成する

次のいずれかの権限セット:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  1. ［Activations］ タブに移動します。
  2. [新規] をクリックします。
  3. セグメントを選択します。
  4. Data 360 有効化対象を選択します。
  5. [有効化メンバーシップ] からデータモデルオブジェクト (DMO) を選択し、[続行] をクリックします。
  6. オブジェクトを作成するには、名前と API 参照名を追加して、[次へ] をクリックします。
    既存のオブジェクトを選択することもできます。
  7. デフォルト属性 (セグメント ID、セグメント ID 名、セグメント ID 最終処理済み) を確認します。
  8. 属性を追加するには、[属性を追加] をクリックします。
    1. 属性をキャンバスにドラッグし、[保存] をクリックします。
  9. [次へ] をクリックします。
    重要 有効化が作成された後に、属性を変更することはできません。
  10. 有効化に名前を付けて [保存] をクリックします。

B2C Commerce ターゲットの有効化の作成

必須のデータ項目のマッピングを設定し、Data Cloud でセグメントを作成したら、B2C Commerce 有効化を作成してセグメントを公開します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要なユーザー権限
有効化を作成する

次のいずれかの権限セット:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト
  1. Data 360 で、[セグメント] をクリックしてセグメントを選択します。
  2. [有効化] で、[新規] をクリックします。
  3. B2C Commerce 有効化対象を選択します。[有効化メンバーシップ] では、デフォルトでデータモデルオブジェクト (DMO) が選択されます。
    統合個人 DMO は、取引先オブジェクトまたは統合取引先オブジェクトに基づいて構築されたセグメントでは使用できません。
  4. [続行] をクリックします。
  5. 有効化データを絞り込むには、1 つ以上のデータソースを選択します。
    B2C Commerce データソースを選択する場合、すべての有効化された属性に有効な値が含まれている必要があります。空白や null のままににすることはできません。B2C Commerce 以外のデータソース (例: Amazon S3) を選択する場合、CustomerNo と CustomerListId の有効化済み属性に有効な値が含まれていることを確認します。
    有効な値は、すべてのデータソースで項目のマッピングが正しく行われている場合にのみ入力されます。
  6. 有効化の名前と説明を入力します。

    名前項目に + ! @ # $ % ^ * ( ) = { } [ ] \ . の文字を含めないでください。< > / " : ?| , _ &

  7. [保存] をクリックします。
    選択した有効化対象に対してスケジュールされた次の公開でセグメントが公開されます。有効化されたデータが B2C Commerce に表示されるまで最大 24 時間かかる場合があります。セグメントメンバーシップは、過去 36 時間の有効化データで 1 日に 1 回更新されます。データが B2C Commerce に対して一貫して有効化されていない場合、セグメントから削除される可能性があります。削除を回避するには、有効化を 24 時間以上の頻度でスケジュールします。

外部有効化プラットフォーム

外部有効化プラットフォームを作成してパッケージ化し、ファイルの書式設定、必要なデータの詳細、または有効化時にファイルを公開する場所を決定します。AppExchange でパッケージを共有するか、Data 360 管理者がインストールできるようにパッケージマネージャーで生成されたパッケージ URL を指定します。

  • 有効化ツールキットを使用した ISV エコシステムの有効化
    Data 360有効化ツールキットを使用すると、独立系ソフトウェア ベンダー(ISV)はAppExchangeで有効化プラットフォームを構築できます。これらのプラットフォームにより、登録者組織は ISV 有効化サービスをインストールして使用できます。これにより、Data 360 データと対象データペイロードを照合し、複数キー照合、連絡先の絞り込み、有効化メンバーシップでの追加 DMO のサポートなどの高度な機能を使用できます。
  • 手動ワークフローを使用した外部有効化プラットフォームの作成
    Data 360 Developer Edition組織で外部有効化プラットフォームを作成し、プラットフォームで顧客にリーチできるようにします。
  • 外部有効化プラットフォームのカスタムメタデータの作成
    Data 360 管理者が使用するためにプラットフォームをパッケージ化する前に、外部有効化プラットフォームのカスタムメタデータを作成します。これは、手動ワークフローを使用して作成されたプラットフォームにのみ適用されます。
  • パッケージマネージャーを使用した配布用外部有効化プラットフォームのパッケージ化
    外部有効化プラットフォームとカスタムメタデータを作成したら、パッケージマネージャーを使用して外部有効化プラットフォームをパッケージ化し、Data 360 管理者に配布します。パッケージに変更があった場合にシステム管理者に更新を提供できるため、管理パッケージを使用することをお勧めします。AppExchange で配布できるのは、管理パッケージのみです。
  • クラウドファイルストレージでの外部有効化プラットフォームセグメントの検索
    システム管理者が外部有効化プラットフォームをインストールすると、クラウドファイルストレージ (Amazon S3) へのセグメントを受信できます。有効化対象ごとに、ユーザー識別子で出力がグループ化されている場合 (PER_USER)、ID 種別ごとに 1 日 1 回、成功ファイル、メタデータファイル、有効化出力ファイルを受け取ります。ファイルは1日に1回しか到着しないため、Data 360のお客様がセグメントを更新してからその変更がS3に到着するまでに遅延が生じます。

属性ショートカットを使用したセグメントの作成

事前設定されたデータモデルパスを使用して検索条件属性を保存する属性ショートカットを使用して、セグメントの作成を高速化します。完全な属性ライブラリを参照する代わりに、チームが設定したショートカットから選択します。

必要なエディション

使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition の可用性」を参照してください。
必要な権限セット
セグメントで属性ショートカットを使用する

次の権限セットのいずれか:

  • Data Cloud アーキテクト
  • Data Cloud 有効化マネージャー
  • Data Cloud 有効化スペシャリスト

開始する前に、組織の属性ショートカットを作成していることを確認します。

属性ショートカットを使用すると、データモデルを操作することなく、よく使用される検索条件属性にすばやくアクセスできます。各ショートカットにはセグメント化オブジェクト、パス、対象属性が設定されているため、検索条件の演算子と値のみを設定する必要があります。ショートカットは同じセグメント内の標準データモデル属性と組み合わせることができます。

  1. Data 360 で、[セグメント] をクリックします。
  2. 既存のセグメントを開いて [Edit Rules (ルールの編集)] をクリックするか、新しいセグメントを作成してセグメントビルダーのキャンバスに移動します。
  3. 属性ライブラリパネルで、［ショートカット］ タブをクリックします。
    このタブには、使用可能なすべての属性ショートカットが表示されます。
  4. 使用するショートカットを見つけます。リストをスクロールするか、名前で検索できます。
  5. ショートカットをパネルからセグメントキャンバスにドラッグします。
    ショートカットをドラッグすると、Data 360 はそのショートカットが現在のコンテナと互換性があるかどうかを確認します。Data 360 では、別のコンテナ内の属性を対象とするショートカットが無効になり、キャンバスにドロップできなくなります。現在のコンテナの設定に一致するショートカットのみが有効になります。
  6. (省略可能) ショートカットの設定を確認するには、[View Configuration (設定を表示)] をクリックします。
    設定ウィンドウにセグメント化オブジェクト、オブジェクトパス、属性名が表示されます。
  7. ショートカットの検索条件を設定します。
    1. 演算子 ([次の文字列と 一致する]、[次の文字列 より大きい]、[次の文字列を 含む] など) を選択します。
    2. 検索条件の値を入力または選択します。
  8. ［Done］ をクリックして検索条件を確認します。
  9. さらにショートカットを追加するには、ステップ 4 ～ 8 を繰り返します。
    [データモデル] タブに切り替えて、ショートカットと共に標準属性を追加することもできます。AND または OR ロジックを使用してショートカットとデータモデル属性を組み合わせ、コンテナ内で検索条件を 3 レベルまでネストできます。
  10. セグメントルールを保存します。

セグメント内の複数の Marketing Cloud Engagement ビジネスユニット

キャンペーン計画のセグメントの真のサイズを判断するには、ビジネスユニット (BU) でセグメントを絞り込みます。セグメントがビジネス ユニットで絞り込まれていない場合、Data 360セグメントの母集団とMarketing Cloud Engagementデータエクステンション数の差が大きくなる可能性があります。

  • Data 360 の [設定] で、[プロファイルビジネスユニットのデータマッピングを許可] が有効になっていることを確認します。
  1. 新規および既存のセグメントでは、別のルールを追加します。
  2. [関連属性] の属性ライブラリから所属エンティティを選択します。
  3. [所属先] 属性をセグメンテーションキャンバスにドラッグします。
  4. [次の値と等しい] 演算子を使用して、セグメントのビジネスユニット値 (MID) を入力します。

B2C エンゲージメントのコミュニケーションの制限

B2C の顧客、リード、見込み客とのコミュニケーションに上限を設定して、規制要件へのコンプライアンスを確保し、カスタマーエクスペリエンスを向上させ、メッセージの疲労を回避します。部門レベルのしきい値を適用して、部門全体のキャンペーン費用予算を最適化します。対象エンティティへの迷惑で規制されていないコミュニケーションを回避して、規制要件へのコンプライアンスを維持します。

Data Cloud コミュニケーション制限機能を使用して、しきい値、頻度、および制限ルールを設定します。

  • コミュニケーション制限のパラメーターと値の設定
    組織やビジネス戦略に関連するチャネルや部署などのコミュニケーション制限パラメーターを定義します。制限ルールを作成する前に、制限のパラメータと値を設定する必要があります。 
  • コミュニケーション制限設定の作成
    コミュニケーションの上限設定を作成し、Data Cloud のデータスペースに関連付けます。すべての設定済みパラメーターまたは特定のサブセットに適用できます。各組織は、有効なコミュニケーション制限設定を 1 つに制限されています。
  • コミュニケーション制限設定の管理
    各組織は、Data Cloud で有効なコミュニケーション制限設定を 1 つに制限されています。コミュニケーション上限設定のディメンションを変更する場合は、別のコミュニケーション上限設定を作成します。別の通信制限を作成するには、有効な通信制限設定を無効にする必要があります。
  • 通信制限ルールの作成
    Data Cloud で通信制限のアクティベーション ターゲットに適用する制限ルールを作成します。上限ルールは、UI で作成するか、ルール条件を含む JSON ファイルをアップロードして作成できます。ルールは各パラメーターレベルで個別に適用することも、エンタープライズレベルで累積的に適用することもできます。
  • コミュニケーション制限の有効化対象の作成
    Data Cloud の有効化時にセグメントメンバーシップの優先度と絞り込みを行う管理対象を作成します。Marketing Cloud Engagement、Microsoft Azure、および SFTP の目標に上限を設定できます。
  • パラメーターへのコミュニケーション制限の有効化対象の対応付け
    コミュニケーション制限を有効化対象に適用するには、対象をパラメーターにマッピングする必要があります。
  • コミュニケーション制限の請求に関する考慮事項
    コミュニケーション制限の使用は、次の使用量種別のクレジットの消費に影響します。
