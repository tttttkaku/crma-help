Optimizer 廃止後 四半期健全性チェックリスト
SOQL 版（Org Check 不使用）

目的: Org Check（Salesforce Labs パッケージ）を導入できない / 導入しない組織向けに、Optimizer 廃止（Winter '26）後の健全性点検を Setup 標準機能 + SOQL（sf CLI）のみで完結させる手順書。
所要時間: 約 40 分（1周）／実施頻度: 四半期に 1 回
対応元評価: サンプル株式会社 健全性評価カバレッジ（Org Check 版）

⚠️ 本書は Optimizer の完全代替ではありません
Optimizer / Org Check が検出する「Hardcoded URLs」「Flow LFS Violations」「Admin-like 自動判定」等の高度な静的解析は SOQL では実用的に再現できません（後述）。可能なら Org Check（Salesforce Labs）の併用を第一選択として再検討してください。本書は AppExchange を導入できない組織向けのベースライン点検を目的とします。
📌 実行前の前提
  • Apex テストカバレッジを取る場合、ApexCodeCoverageAggregate は最後のテスト実行から 24 時間で消えるため、本書実行直前に sf apex run test --wait 10 --target-org <alias> を流しておくこと。さもなくば常に 0% 表示になる
  • 「365日未閲覧」検出は LastViewedDate ベース。閲覧追跡が無効な org（Setup → ユーザインターフェース → 「最近閲覧したリスト」無効）では暴発する
  • 付録 B（大量データオブジェクト一括カウント）は本番 org での実行非推奨。API 24h 上限を消費し、count() が QUERY_TIMEOUT を起こすため、Setup → 組織のディスク使用量で代替できる場合は不要
📋 SOQL 版の使いどころ
  • AppExchange パッケージの導入が セキュリティポリシー等で許可されない組織
  • Trial Org / 権限制約下で Org Check の flows / process-builders recipe が INSUFFICIENT_ACCESS になる場合
  • CI / 定期ジョブで JSON 出力を機械処理したい場合（Org Check は UI 主体）
  • サブスク料金や運用負荷（パッケージ更新追従等）を避けたい場合
使い方
  1. Section ① Setup 標準機能で容量・セキュリティ等を確認
  2. Section ② SOQL クエリを sf CLI で順次実行し、結果を記録欄に転記
  3. Section ③ Org Check 専用機能の代替策を確認（または有償ツール検討）
  4. Section ④ サマリ表で前回値と比較して対応事項を起票
⚠️ Org Check 版との差分（取得できない指標）
  • Hardcoded URLs 検出: Apex/VF/WebLink の本文に対する誤検出フィルタ込み判定は SOQL では再現困難（developer.salesforce.com / OAuth エンドポイント / コメント等の除外ロジックを自前で書く必要がある）
  • LFS Violations: Flow 内の SOQL/DML がループ内にあるかの検出は Metadata retrieve + 解析が必要
  • Admin-like 自動判定: Org Check は ModifyAllData 等の組合せでフラグ立てするが、SOQL では PermissionSet ごとの個別確認が必要
  • Apex Test Coverage: ApexCodeCoverage SOQL は取れるが Org Check のサマリ表示が便利
これらは SOQL では実用的に代替しんどい。必要なら Org Check / 有償ツール（Salto / Elements.cloud / Sonar 等）の併用を検討。

付録 A: sf CLI 一括実行スクリプト

②の SOQL を一括で流して結果を CSV/JSON に保存するスクリプト。CI / 定期ジョブで回す場合に活用。

#!/bin/bash
# health-check-sql.sh — Org Check 不使用版 健全性チェック一括実行
# 使い方: ./health-check-sql.sh <target-org-alias>

set -euo pipefail
ALIAS="${1:-}"
[ -z "$ALIAS" ] && { echo "Usage: $0 <alias>"; exit 1; }
OUT="health-check-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$OUT"

run_q() {
  local label="$1" tooling="$2" query="$3"
  local flags="--target-org $ALIAS --result-format csv"
  [ "$tooling" = "true" ] && flags="$flags --use-tooling-api"
  echo "▶ $label"
  sf data query --query "$query" $flags > "$OUT/$label.csv" 2>&1 || echo "  (失敗) $label"
}

付録 B: 大量データオブジェクト一括カウント（参考実装・本番非推奨）

🚨 本番 org での実行は非推奨
  • 標準オブジェクトだけで 500 個超を count() で順次叩くため、24 時間 API 上限を大量消費（数千コール／run）
  • Event / Task / CaseHistory / LoginHistory 等の数百万件オブジェクトで QUERY_TIMEOUT（120秒制限）を起こす
  • 代替: Setup → データ → 組織のディスク使用量 にレコード数とストレージ容量がオブジェクト別で標準提供されている。まずはこちらを参照すること
  • どうしても本スクリプトを使う場合は、Sandbox / Dev Org で動作確認し、objects.txt を主要オブジェクトのみに手動で絞ってから実行する
#!/bin/bash
# large-data-scan.sh — ⚠ 本番非推奨。Sandbox / Dev Org 用の参考実装
ALIAS="${1:-}"
[ -z "$ALIAS" ] && { echo "Usage: $0 <alias>"; exit 1; }

# クエリ可能なオブジェクト一覧を取得
sf sobject list --target-org "$ALIAS" --sobject all > objects.txt
# ⚠ 推奨: vi objects.txt で監視対象オブジェクトのみに絞り込んでから実行

# 各オブジェクトを count
> results.csv
echo "Object,Count" > results.csv
while read -r obj; do
  cnt=$(sf data query --query "SELECT count() FROM $obj" --target-org "$ALIAS" --json 2>/dev/null | jq -r '.result.totalSize // "ERROR"')
  echo "$obj,$cnt" >> results.csv
done < objects.txt

# 100万超を抽出
echo "=== 100万超 ==="
awk -F, '$2 > 1000000 {print $1": "$2}' results.csv
echo "=== 1000万超 ==="
awk -F, '$2 > 10000000 {print $1": "$2}' results.csv

付録 C: Anonymous Apex によるリミット監視

Apex / Storage 系の組織制限は OrgLimits Apex から取得できる。SOQL より手軽に「使用率」を一括取得可能。

// limits-check.apex
// 実行: sf apex run --file limits-check.apex --target-org <alias>
Map<String, System.OrgLimit> limits = OrgLimits.getMap();
List<String> warnings = new List<String>();
for (String name : limits.keySet()) {
    System.OrgLimit lim = limits.get(name);
    Integer used = lim.getValue();
    Integer max  = lim.getLimit();
    if (max == 0) continue;
    Decimal pct = (Decimal.valueOf(used) / max * 100).setScale(1);
    System.debug(name + ': ' + used + '/' + max + ' = ' + pct + '%');
    if (pct >= 80) {
        warnings.add(name + ' = ' + pct + '% (' + used + '/' + max + ')');
    }
}
System.debug('===== 80% 超過 =====');
for (String w : warnings) System.debug(w);
