フロー画面コンポーネント: サービスリソースの対応可能状況

ユーザーが対応可能なサービスリソース (予定の被招集者) のリストを表示して、サービスリソースを選択できるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

メモ デフォルトでは、予定の配分が無効になっている場合、次の 31 日間に対応できるすべてのサービスリソースが画面に表示されます。この期間に対応可能なリソースがいない場合、次の 31 日間 (最大 93 日間) の検索が続行されます。予定配分が有効になっている場合、表示されるサービスリソース数はデフォルトで 10 に制限されます。これは、[表示するリソースの数 (予定配分)] 属性を有効にして変更できます。

Apex 開発

デフォルトでは、業務量ベースのスケジュールを有効にすると、シフト作業トピックの業務量は 0 に設定されます。 これらのスクリプトを使用してシフト作業トピックに値を入力し、業務量ベースのスケジュールを有効にする前と同じようにスケジュールを機能させます。ビジネス継続性を確保するためにすばやく更新する必要がある既存のシフトレコードがある場合、これらのスクリプトを使用することをお勧めします。または、シフト作業トピックの業務量を手動で設定できます。

  1. 組織の [Scheduler for Health Cloud] 設定に応じて、次のいずれかのスクリプトを使用します。
    • 無効
      //For Health Cloud Disabled
global class InitialiseExistingSWTWithCapacity implements Database.Batchable<SObject> {
  global Database.QueryLocator start(Database.BatchableContext BC) {
    return Database.getQueryLocator([SELECT Id, StartTime, EndTime FROM Shift]);
  }

  global void execute(Database.BatchableContext BC, List<SObject> scope) {
    List<String> shiftIds = new List<String>();

    for (Shift shift : (List<Shift>) scope) {
      shiftIds.add(shift.Id);
    }

    // create maps to avoid queries in the loop
    List<Shift> shiftInfo = [
      SELECT ServiceTerritoryId, Id, StartTime, EndTime
      FROM Shift
      WHERE Id IN :shiftIds
    ];
    List<String> serviceTerriroryIds = new List<String>();
    for (Shift shift : shiftInfo) {
      serviceTerriroryIds.add(shift.ServiceTerritoryId);
    }

    Map<String, String> mapStToServiceAppointmentLimitType = new Map<String, String>();
    List<ServiceTerritory> sts = [
      SELECT ServiceAppointmentLimitType, Id
      FROM ServiceTerritory
      WHERE Id IN :serviceTerriroryIds
    ];
    for (ServiceTerritory st : sts) {
      mapStToServiceAppointmentLimitType.put(
        st.Id,
        st.ServiceAppointmentLimitType
      );
    }
    Map<String, String> mapShiftToServiceTerritory = new Map<String, String>();
    Map<String, Decimal> mapShiftToDuration = new Map<String, Decimal>();

    for (Shift shift : shiftInfo) {
      mapShiftToServiceTerritory.put(shift.Id, shift.ServiceTerritoryId);
      Decimal shiftDuration =
        (shift.EndTime.getTime() - shift.StartTime.getTime()) / (1000 * 60);
      mapShiftToDuration.put(shift.Id, shiftDuration);
    }
    Map<String, Decimal> mapWorkTypeToDuration = new Map<String, Decimal>();

    List<WorkType> wts = [SELECT Id, DurationInMinutes FROM WorkType];
    for (WorkType wt : wts) {
      mapWorkTypeToDuration.put(wt.Id, wt.DurationInMinutes);
    }

    Map<String, List<String>> mapShiftToWorkTypeGroupList = new Map<String, List<String>>();

    List<ShiftWorkTopic> shiftWorkTopics = [
      SELECT Id, WorkTypeGroupId, ShiftId, MaxAppointments
      FROM ShiftWorkTopic
      WHERE ShiftId IN :shiftIds AND WorkTypeGroupId != NULL
    ];

    for (ShiftWorkTopic swt : shiftWorkTopics) {
      List<String> existingSWTList = mapShiftToWorkTypeGroupList.get(
        swt.ShiftId
      );
      if (existingSWTList == null) {
        existingSWTList = new List<String>{ (String) swt.WorkTypeGroupId };
      } else {
        existingSWTList.add(swt.WorkTypeGroupId);
      }
      mapShiftToWorkTypeGroupList.put(swt.ShiftId, existingSWTList);

Salesforce Scheduler での対応可能状況と例外の管理

サービスリソースの対応可能状況、サービステリトリーと作業種別の業務時間、および取引先の訪問時間を指定します。休日、不在、手動で作成したカレンダー行動などの例外を管理します。対応可能な時間枠を決定するために Salesforce Scheduler Engine で使用する必要があるルールを指定するには、スケジュールポリシーと Scheduler 設定を定義します。予定配分、マルチリソーススケジュール、および同時スケジュールを処理する機能を設定します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

対応可能状況の管理

サービスリソースの対応可能状況を指定するには、業務時間またはシフトを使用します。サービスリソースの作業時間が固定されている場合、システム管理者またはサービステリトリーマネージャーは業務時間を使用してサービスリソースの対応可能状況を指定できます。サービスリソースの作業時間が柔軟な場合、シフトを有効にします。その後、サービスリソースやサービステリトリーマネージャーはシフトレコードを作成して管理できます。

業務時間を使用してサービステリトリーの対応可能状況を指定します。必要に応じて、作業種別の業務時間や取引先の訪問時間を指定します。

対応可能状況の例外の管理

サービステリトリーおよびサービスリソースの対応可能状況に例外を追加します。

  • サービステリトリーが稼働していないときに予定が予約されるのを回避するには、休日を使用します。
  • サービスリソースが不在のときに予定が予約されるのを回避するには、リソースの不在を使用します。
  • 他のミーティングや行動があるためにサービスリソースが対応できないときに予約されるのを回避するには、カレンダーを確認して対応可能状況を判断するようにスケジュールポリシールールを設定します。

特別な予定のスケジュールのケースの処理

さまざまな予定のスケジュールシナリオを処理する機能を有効にして設定します。

  • サービスリソース間で予定を均等に配分できるようにするには、予定配分を使用します。
  • ユーザーが 1 つの予定で複数のサービスリソースを予約できるようにするには、マルチリソーススケジュールを使用します。
  • サービスリソースが 1 つの時間枠で複数の予定を実行できるようにするには、同時スケジュールを使用します。
  • Salesforce Scheduler での業務時間の設定
    営業時間は、予定をスケジュールできる時間枠を表します。たとえば、銀行のある支店で住宅ローンの予定 (予約) を月曜日から水曜日の午前 8 時から午後 2 時までに限定している場合、この要件を反映する住宅ローン作業種別の営業時間を作成します。
  • Salesforce Scheduler でのシフトの管理
    シフトにより、サービスリソースは頻繁に変更される勤務時間を設定および更新できます。サービスリソースは、同じサービステリトリーに異なる勤務時間のシフトを設定したり、サービステリトリーの業務時間を超えるシフトを設定したり、複数のサービステリトリーのシフトを設定したりできます。
  • 予定配分の有効化
    予定配分により、予定をサービスリソースの間で均等にすばやく割り当てることができます。予定を公平に配分することで、サービスリソースを効率的に活用でき、生産性が高まります。Salesforce Scheduler は、サービスリソースの使用状況スコアに基づいて、予定が最も空いている適格なリソースを特定して予定の候補として提案します。匿名予約では、予定が最も空いている適格なリソースが自動的に予定に割り当てられます。
  • 同時スケジュールの有効化と設定
    同時スケジュールを使用すると、同じ時間枠に複数の顧客の予定を簡単にスケジュールできます。たとえば、医院では月曜日の午後 1 ～ 2 時の予定を複数の患者が予約できるようにして、空き時間が生じるのを防ぐことができます。予定は、重複する行動として Salesforce カレンダーに表示されます。
  • マルチリソーススケジュールの有効化と設定

  • Salesforce Scheduler でのサービスリソースの不在
    不在を使用して、サービスリソースがサービス予定に対応できない期間を指定します。
  • Salesforce Scheduler での休日の設定

    日または週単位で変わるシフトを作成します。シフトを使用して、柔軟なパターンに従った期間にサービスリソースを割り当てることができます。たとえば、同じサービステリトリーで勤務時間が異なったり、異なるサービステリトリーで同じサービスリソースが対応可能であったりします。
  • シフト設定の定義
    シフトへのエンゲージメントチャネル種別とトピックの追加。関連付けられた各トピックに対して顧客がスケジュールできる最大予定数を定義することもできます。
  • CSV ファイルを使用したシフトの一括作成
    CSV ファイルでシフト情報を取得し、CSV ファイルを JSON ファイルに変換して、Salesforce Scheduler で Bulk API を使用してシフトを作成します。
  • エンゲージメントチャネル種別
    エンゲージメントチャネル種別とは、サービスリソースが顧客との会話に使用するメディア (電話、ビデオ、対面など) です。[エンゲージメントチャネルを使用して予定をスケジュール] 設定を有効にして、テリトリーマネージャーとサービスリソースがエンゲージメントチャネル種別とチャネル種別の連結オブジェクトを使用できるようにします。テリトリーマネージャーやサービスリソースは、1 つ以上のチャネル種別をシフトに追加して、エンゲージメントチャネル種別のリソースの対応可能状況を定義できます。Salesforce Scheduler には、予定の作成時にユーザーが選択したチャネル種別に基づいて、サービスリソースとリソース時間枠が表示されます。
  • シフトの複数のトピック
    1 つ以上のトピック (作業種別グループまたは作業種別) をシフトに追加するには、[シフトの複数のトピック] 設定を有効化します。
  • シフトのロールおよび階層の設定
    ロールおよび階層によって誰が誰の部下になるかが定義され、シフトの承認プロセスを定義できるようになります。さまざまなサービステリトリーで特定のロールを所有するユーザーを割り当てることができます。たとえば、Adam は銀行マネージャー、John はリテールバンカーであるとします。テリトリーマネージャーロールとリテールバンカーロールを作成し、リテールバンカーがテリトリーマネージャーの部下になるようにできます。テリトリーマネージャーロールを Adam に、リテールバンカーロールを John に割り当てます。この階層を使用すると、Adam はシフトを作成し、シフトを承認して John に自分の対応可能状況を確認するよう要求できます。
  • シフト状況のレコードタイプの作成
    必要なシフト状況オプションを作成したロールで使用できるようにするには、レコードタイプを作成します。たとえば、サービステリトリーマネージャーは確認済みのシフトを作成したり、仮承諾のシフトを作成してからサービスリソースに確認を要求したりできます。このプロセスでは、テリトリーマネージャーのロール用にテリトリーマネージャー状況というレコードタイプを作成し、[仮承諾] 状況と [確認済み] 状況を選択できます。テリトリーマネージャーはシフトを作成するときに、[状況] 項目の [仮承諾] オプションおよび [確認済み] オプションのみを参照できます。
  • シフトを使用した予定時間枠の決定
    シフトを使用して時間枠を決定するには、スケジュールポリシーでシフト関連ルールを有効にします。サービステリトリーメンバーの業務時間ではなくサービステリトリーメンバーのシフトを考慮するには、[サービステリトリーメンバーのシフトを使用] オプションを有効にします。ただし、シフトとサービステリトリーの業務時間の交差部分を考慮する場合は、[シフトと共にサービステリトリーの営業時間を使用] オプションを [サービステリトリーメンバーのシフトを使用] オプションと共に有効にします。この交差部分と一緒に取引先の業務時間を考慮するには、[取引先の訪問時間を適用] オプションを有効にします。
  • シフトの承認プロセスの設定
    承認プロセスを有効にして、シフト状況の更新を合理化します。承認プロセスを使用すると、サービスリソースおよびテリトリーマネージャーは、シフトが作成、承認、却下されたときにメールアラートを受信します。
  • Apex トリガーを使用してサービスリソースが 2 週間シフトを変更できないように制限
    サービステリトリーマネージャーはサービスリソースと協力して事前にシフトを計画します。たとえば、今日の日付から 2 週間、予定の予約を可能にする必要があるとします。そのため、その期間中にサービスリソースがシフトを変更できないようにする必要があります。サービスリソースが 2 週間シフトを更新できないようにするには、Apex トリガーを作成します。
  • 勤務時間の選択的な制限
    [シフトと共にサービステリトリーの営業時間を使用] スケジュールポリシーを有効にしている場合、Salesforce Scheduler ではシフトとサービステリトリーの業務時間の交差部分を使用して、すべてのサービスリソースの対応可能状況を決定します。ただし、数人のサービスリソースのみについては勤務時間をサービステリトリーの業務時間に制限する場合は、トリガーを使用します。

Apex トリガーを使用してサービスリソースが 2 週間シフトを変更できないように制限

サービステリトリーマネージャーはサービスリソースと協力して事前にシフトを計画します。たとえば、今日の日付から 2 週間、予定の予約を可能にする必要があるとします。そのため、その期間中にサービスリソースがシフトを変更できないようにする必要があります。サービスリソースが 2 週間シフトを更新できないようにするには、Apex トリガーを作成します。

//Because the next two weeks of time slots are visible to customers and are bookable,
//we want to prevent any updates to those shifts.
//This trigger doesn't allow to create a shift
//where either start time or end time falls under
// 1. Older than today's date
// 2. Two weeks after today's date
 
trigger TwoWeeksLimitTrigger on Shift (before insert,before update) {
    if(trigger.isInsert || trigger.isUpdate){
        if (Trigger.isBefore) {
            for(Shift shift : Trigger.New) {
                Date todayDate = date.today();
                Date twoWeekDate = todayDate.addDays(14);
                if(shift.StartTime < todayDate || shift.StartTime > twoWeekDate){
                    trigger.new[0].StartTime.addError('Customers are already booking slots for this time period and so changing Shifts is not allowed.');
                }
                else if(shift.EndTime < todayDate || shift.EndTime > twoWeekDate){
                    trigger.new[0].EndTime.addError('Customers are already booking slots for this time period and so changing Shifts is not allowed.');
                }
            }
        }
    }
}

マルチリソーススケジュールの有効化と設定

マルチリソーススケジュールを使用すると、ユーザーは複数の必須サービスリソースが含まれる予定を作成できます。予定には、最大 5 つの必須サービスリソースを設定できます (1 つの必須プライマリサービスリソースと、アセットリソースを含む 4 つの必須サービスリソース)。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • マルチリソーススケジュールに関する考慮事項
    マルチリソーススケジュールでは、プライマリサービスリソースによって予定が固定されるため、必須としてマークする必要があります。プライマリサービスリソースは、そのスキルが予定のスキル要件と一致する唯一のサービスリソースです。その他の必須サービスリソースは、対応可能状況とプライマリリソースのサービステリトリーに基づいて予定に一致します。必須としてマークされていないリソースは省略可能とみなされます。
  • マルチリソーススケジュールの有効化
    [マルチリソーススケジュール] を有効にすると、ユーザーは顧客の予定に合わせてリソースおよびアセットのグループをスケジュールできます。
  • マルチリソーススケジュールの項目レベルセキュリティの更新
    マルチリソーススケジュールにアクセスする必要があるすべてのユーザープロファイルに対して、割り当て済みリソースオブジェクトのプライマリリソース項目の項目レベルセキュリティを更新します。

Salesforce Scheduler でのサービスリソースの設定

従業員の被招集者を表すサービスリソースを作成します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • サービスリソースにできるユーザーの設定
    サービスリソースとは、クライアントとの予定に参加できる組織内の個人ユーザーです。サービスリソースを作成するためには、サービスリソースとして使用できるユーザーを事前に作成または識別しておく必要があります。そして、権限セットを使用してこれらのユーザーに Salesforce Scheduler 権限セットライセンスを割り当てることで、予定で使用できるようにします。
  • [メインサービスリソース] 設定の有効化
    Salesforce Scheduler の [エージェント] リソース種別でオムニチャネルサービスリソースを使用するには、[メインサービスリソース] 設定を有効にします。この設定を有効にする場合は、ユーザーごとに 1 つのサービスリソースのみを作成することをお勧めします。
  • Salesforce Scheduler でのアセットのスケジュールの有効化
    部屋や機器 (MRI マシンや透析用チェアなど) の予約がアセットのスケジューリングによりこれまで以上に簡単になりました。
  • Salesforce Scheduler でのサービスリソースの作成
    サービスリソースは、顧客の予定に参加できる個人ユーザーです。サービスリソースを作成し、予定をサービスリソースに割り当てることができるようにします。
  • Salesforce Scheduler でのサービスリソースへのスキルの割り当て
    スキルをサービスリソースに割り当て、リソースの専門分野を示します。サービスリソースには、リソースのスキルに基づいて予定が割り当てられます。
  • サービスリソースへの開始日と終了日が含まれるスキルの割り当て
    開始日と終了日の両方が含まれるスキルをサービスリソースに割り当て、その認定と専門分野を追跡します。
  • Salesforce Scheduler でのサービスリソースへのサービステリトリーの割り当て
    サービステリトリーをサービスリソースに割り当てて、予定の出席者が対応可能なすべてのロケーションに関連付けられるようにします。
  • 割り当て済みサービスリソースとのサービス予定の共有
    [リソースの予定の共有] 設定を有効にすると、Scheduler では新しく作成されたサービス予定がすべての割り当て済みサービスリソースと自動的に共有されます。この設定により、サービス予定を管理するための適切な権限がサービスリソースに付与されます。
  • Salesforce Scheduler でサービスリソースを管理するためのガイドライン
    サービスリソースを管理する方法について説明します。

招待 URL を使用したサービスリソースの対応可能状況の共有

サービスリソースまたはそのアシスタントは、予定の予約でリソースを使用できる期間を共有できます。予定条件を定義し、招待 URL を作成して予定条件をユーザーと共有できます。ユーザーは招待 URL に移動して予定を予約できます。この URL によりユーザーは、サービスリソースが対応可能になる開始週に移動します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

次に例を示します。

  • ウェルスマネージャー (コントラクター) は予定招待 URL を生成して、その URL を署名に追加できます。見込み客はこの URL を使用して予定を予約できます。
  • 株式ポートフォリオマネージャー (コントラクター) が、ポートフォリオレビューに備えて 3 か月間後の対応可能状況を既存の顧客 (認証済みコンシューマー) と共有したいと考えています。株式ポートフォリオマネージャーは、現在の日付から 3 か月後の開始日を持つ URL を生成し、その URL を顧客と共有できます。
メモ アシスタントもコントラクターの代理で予定招待 URL を作成し、その URL を顧客と共有できます。

次のフローを使用して、リソースの対応可能状況の共有機能を有効にします。

Generate Appointment Invitation (予定招待を生成)
このフローを使用すると、サービスリソースまたはそのアシスタントが予定招待 URL を生成できます。顧客はフローをカスタマイズして、予定の予約環境を強化できます。たとえば、顧客はデフォルトの作業種別グループまたはサービステリトリーを選択したり、時間枠のプレビューページをスキップしたりできます。また、Lightning アプリケーションビルダーを使用してこのフローを組み込み、認証済みコンシューマーの取引先ページからフローを起動することもできます。
Book Appointment from Invitation (招待から予定を予約)
この機能を使用すると、ユーザーは予定招待 URL を使用して予定を予約できます。顧客は要件に従ってこのフローをカスタマイズできます。

Salesforce Scheduler でサービステリトリーを管理するためのガイドライン

サービステリトリーを管理する方法について説明します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
Salesforce Scheduler でのサービステリトリーの表示
[サービステリトリー] タブでサービステリトリーを参照します。サービスリソースのテリトリーは、リソースの詳細ページの [サービステリトリー] 関連リストでも表示できます。
Salesforce Scheduler でのサービステリトリーの作成

Salesforce の [サービステリトリー] タブでサービステリトリーを作成します。テリトリーの作成後、[サービステリトリーメンバー] 関連リストからメンバーを追加できます。サービステリトリーメンバーはテリトリー内で作業するリソースで、メンバーをテリトリーと関連付けると、メンバーはホームベースに近い予定に割り当てられます。

Salesforce Scheduler でのサービスリソースへのサービステリトリーの割り当て
サービスリソースを複数のテリトリーに関連付け、リソースが作業可能かどうかを示すことができます。リソースの詳細ページの [サービステリトリー] 関連リスト、またはテリトリーの詳細ページの [サービステリトリーメンバー] 関連リストで、リソースにテリトリーを割り当てます。

リソースにテリトリーを割り当てる場合、[種別] 項目を使用して、テリトリーがリソースのプライマリテリトリーであるかセカンダリテリトリーであるかを指定します。

  • プライマリテリトリーは通常、リソースが最も頻繁に作業するテリトリー (本拠地の周辺など) です。リソースに割り当てることができるプライマリテリトリーは 1 つのみです。
  • セカンダリテリトリーは、リソースを必要に応じて予定に割り当てることができるテリトリーです。リソースに複数のセカンダリテリトリーを割り当てることができます。
Salesforce Scheduler でのサービステリトリーの削除
サービス予定のあるサービステリトリーは削除できません。削除しようとすると、予定を別のテリトリーに割り当てるように促されます。

フロー画面でのサービステリトリータイムゾーンの使用

デフォルトでは、フローをスケジュールしているユーザーのタイムゾーンに基づいて時間が表示されます。ですが、選択したサービステリトリーのタイムゾーンに基づいて時間を表示したほうがよいケースもあります。たとえば、カスタマーサービス担当者が複数のロケーションの予定をスケジュールする場合などです。このようなシナリオでは、DefaultTimeZone 変数の値を設定して、サービステリトリータイムゾーンを使用します。

フローを実行する 「フローの実行」

サービステリトリーのタイムゾーンを使用するようにフローを変更すると、[タイムゾーン] ドロップダウンリストのデフォルト値もサービステリトリーのタイムゾーンに設定されます。たとえば、[サービス予定時間を選択] 画面の [タイムゾーン] ドロップダウンリストなどです。

フロー画面でサービステリトリーのタイムゾーンを使用するための手順は、受信フロー、発信フロー、ゲストフローのいずれでも同じです。

  1. [設定] の [クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  2. サービステリトリーのタイムゾーンを使用するフローをクリックします。
  3. フロービルダーの [マネージャー] タブの [変数] で、[DefaultTimeZone] をクリックします。
  4. [デフォルト値] フィールドに「{!ServiceAppointment.ServiceTerritory.OperatingHours.TimeZone}」と入力します。
  5. [完了] をクリックします。
  6. [別名で保存] をクリックします。
  7. [フローの表示ラベル] と [フローの API 参照名] に値を入力し、変更内容を保存します。
    フローのインスタンスが作成されます。
  8. フローを有効化します。
  9. フローインスタンスを、フローを使用するページレイアウトに追加します。

スケジュールポリシーでのシフトルールの定義

対応可能な時間枠を決定するときに、サービステリトリーメンバーの業務時間の代わりにシフトを使用するには、スケジュールポリシーでシフト固有のルールを有効にします。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. [設定] の [クイック検索] ボックスに「スケジュールポリシー」と入力し、[スケジュールポリシー] を選択します。
  2. 作成したスケジュールポリシーの横にある [編集] をクリックします。
    フローまたは API コールでカスタムスケジュールポリシーを作成して使用しない場合、デフォルトの予定スケジュールポリシーを使用します。
  3. サービステリトリーメンバーの業務時間を使用するのではなくシフトを使用するには、[サービステリトリーメンバーのシフトを使用] を選択します。
    このオプションを選択した場合、サービステリトリーメンバーの業務時間が定義されているかどうかに関係なく、業務時間は考慮されません。
  4. サービステリトリーの業務時間とシフトの交差部分に基づいて時間枠を表示するには、[シフトと共にサービステリトリーの営業時間を使用] を選択します。
    [シフトと共にサービステリトリーの営業時間を使用] オプションを選択できるのは、[サービステリトリーメンバーのシフトを使用] オプションを選択した後のみです。
  5. 変更内容を保存します。
