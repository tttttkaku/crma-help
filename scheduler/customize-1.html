シフト承認プロセスの有効化

承認プロセスを設定したら、必ず承認プロセスを有効化します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. [設定] で、[クイック検索] ボックスに「承認プロセス」と入力して、[承認プロセス] をクリックします。
  2. シフト用に作成した承認プロセスを開きます。
  3. プロセスを有効化します。

承認プロセスへの承認ステップの追加

承認ステップを追加して、そのステップに進むことができるレコードと承認者のほか、代理承認者が申請に返答できるかどうかを決定します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
メモ

承認プロセスが無効な場合のみ、ステップを追加できます。

  1. [設定] で、[クイック検索] ボックスに「承認プロセス」と入力して、[承認プロセス] をクリックします。
  2. 承認ステップを追加する承認プロセスを選択します。
  3. [承認ステップ] で、[新規承認ステップ] をクリックします。
  4. 承認ステップの名前を入力して、[次へ] をクリックします。
  5. [すべてのレコードがこのステップに入ります] ラジオボタンを選択し、[次へ] をクリックします。
  6. [自動的にキューに割り当てる] ラジオボタンを選択し、キューを選択します。
  7. 変更内容を保存します。

承認プロセスへのメールアラートの追加

作成したメールテンプレートを承認プロセスのアクション (申請時のアクション、最終承認時のアクション、最終却下時のアクション、取り消しアクション) にリンクします。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. [設定] で、[クイック検索] ボックスに「承認プロセス」と入力して、[承認プロセス] をクリックします。
  2. メールアラートを追加する承認プロセスを選択します。
  3. 選択したアクションの下で、[新規アクションの追加] をクリックし、[メールアラート] を選択します。
    たとえば、[申請時のアクション] の下で、[新規アクションの追加] をクリックし、[メールアラート] を選択します。
  4. メールアラートの説明を入力します。
  5. 承認プロセスのメールテンプレートを選択します。
  6. [受信者種別] 項目では、[検索] ドロップダウンリストから [ユーザー] を選択します。
  7. [受信者] 項目では、[選択可能なメール受信者] リストでメールアラートの受信者を選択します。
  8. 選択した受信者を [選択済みメール受信者] リストに移動するには、[追加] をクリックします。
  9. 変更内容を保存します。

承認プロセスへの項目自動更新の追加

項目自動更新では、選択した項目が承認プロセスの完了後に変更されます。たとえば、テリトリーマネージャーがシフトを承認すると、シフトの [状況] 項目が [仮承諾] から [確認済み] に更新されます。[申請時のアクション]、[最終却下時のアクション]、[取り消しアクション] で項目自動更新を追加できます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. [設定] で、[クイック検索] ボックスに「承認プロセス」と入力して、[承認プロセス] をクリックします。
  2. 最終承認時のアクションを追加する承認プロセスを選択します。
  3. 選択したアクションの下で、[新規アクションの追加] をクリックし、[項目自動更新] を選択します。
    たとえば、[申請時のアクション] の下で、[新規アクションの追加] をクリックし、[項目自動更新] を選択します。
  4. 項目自動更新の名前を入力します。
  5. [更新する項目] ドロップダウンリストから、[状況] を選択します。
  6. 変更内容を保存します。

サービスリソースレコードページへの AddFlow クイックアクション

サービスリソースレコードページから [Generate Appointment Invitation (予定招待を生成)] フローを起動するには、フロークイックアクションをサービスリソースレコードページに追加します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

クイックアクションを追加する前に、[Generate Appointment Invitation (予定招待を生成)] フローを起動するクイックアクションを作成します。

  1. サービスリソースのオブジェクト管理設定から、[ページレイアウト] に移動します。
  2. クイックアクションを追加するページレイアウトを選択します。
  3. パレットで、[モバイルおよび Lightning のアクション] を選択します。
  4. レイアウトエディターの [Salesforce モバイルおよび Lightning Experience アクション] セクションに [定義済みアクションを上書き] リンクが表示された場合、リンクをクリックします。
  5. クイックアクションを [Salesforce モバイルおよび Lightning Experience のアクション] セクションの上部にドラッグします。
  6. 変更内容を保存します。

業務時間コンポーネントをサービステリトリー、サービステリトリーメンバー、作業種別のレコードページに追加します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
メモ 業務時間コンポーネントを使用して追加できる時間枠の合計数は 200 に制限されています。
  1. [設定] から、[クイック検索] ボックスに「アプリケーションビルダー」と入力し、[Lightning アプリケーションビルダー] を選択します。
  2. [サービステリトリー Lightning レコードページ]、[サービステリトリーメンバー Lightning レコードページ]、または [作業種別 Lightning レコードページ] のいずれかで [編集] をクリックします。

Salesforce Scheduler でのデフォルトの予定種別のカスタマイズ

Salesforce Scheduler でユーザーが予定を作成するときに使用できるデフォルトの予定種別をカスタマイズします。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

Salesforce Scheduler では、予定種別を表示するために、作業種別オブジェクトの [デフォルトの予定種別] 選択リストの値が使用されます。

メモ Lightning Design System では、Lightning ページで使用できるユーティリティアイコンが用意されています。Salesforce Scheduler では、ユーティリティアイコンを使用して予定種別のアイコンが表示されます。

[デフォルトの作業種別] 選択リストに選択リスト値を追加する手順は、次のとおりです。

  1. [Setup (設定)] で [Object Manager (オブジェクトマネージャー)] をクリックします。
  2. [作業種別] を選択します。
  3. [項目とリレーション] を選択し、[デフォルトの予定種別] を選択します。
  4. [デフォルトの予定種別] の [選択リスト値] セクションで、[新規] をクリックします。
  5. 「phone」 (電話)、「at a branch」 (支店)、「video」 (ビデオ) などの値を入力します。各行にそれぞれの値を入力します。
    各行の値に対して選択リスト値が作成されます。デフォルトでは、選択リスト値の API 参照名は選択リスト値と同じです。Salesforce Scheduler によって、選択リスト値の API 参照名が Lightning Design System によって提供されるユーティリティアイコンの名前と一致するかどうかを検証されます。名前が一致する場合、Salesforce Scheduler では同じ名前のアイコンが使用されます。名前が一致しない場合、Salesforce Scheduler ではデフォルトの Lightning アイコンが使用されます。
  6. 予定種別のアイコンを編集するには、API 参照名を編集し、使用するユーティリティアイコンの名前を入力します。
  7. 変更内容を保存します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
必要なユーザー権限
Flow Builder でフローを開く、編集または作成する 「フローの管理」
フローを実行する 「フローの実行」
  1. Flow Builder で、[要素] パネルから、[割り当て] をキャンバスにドラッグします。
  2. 「Add Parent Record as Recipient」 (受信者として親レコードを追加) などの名前と、「Add_Parent_Record_as_Recipient」などの API 参照名を入力します。
  3. [変数] に [recipientIds] を選択します。
  4. [演算子] で [追加] を選択します。
  5. [値] に「{!$Record.ParentRecordId}」と入力し、[完了] をクリックします。
  6. [ループ] 要素 (割り当て済みリソース) を [割り当て] 要素 (Add Parent Record as Recipient (受信者として親レコードを追加)) に接続します。

翻訳言語と翻訳者の追加

翻訳の言語を追加し、各言語の翻訳者を割り当てて、言語の翻訳を有効化または無効化します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

翻訳の言語を追加する前に、必ず組織の言語を選択し、トランスレーションワークベンチを有効にしてください。

  1. [設定] から [クイック検索] ボックスに「翻訳言語設定」と入力し、[翻訳言語設定] を選択します。
  2. 言語を追加するには、[追加] をクリックします。
  3. [言語] ドロップダウンから、言語を選択します。
  4. 翻訳をユーザーが使用できるようにするには、[有効] を選択します。
    トランスレーションワークベンチで言語が有効になっていても、ユーザーはいつでも個人の言語を変更できます。
    メモ 翻訳者がすべての値を翻訳してから言語を有効にすることをお勧めします。
    メモ [無効] 状況では、ユーザーに表示される内容のみが制御され、エクスポートやインポートには影響しません。無効な言語はエクスポートされた翻訳ファイルには引き続き含まれ、翻訳者は引き続き作業できます。
  5. [この言語の翻訳者を選択してください] で、[利用可能なリスト] ボックスからユーザーを選択し、[追加] をクリックして [選択されたリスト] ボックスにユーザーを移動します。
    選択されたユーザーが言語の翻訳を管理します。
    重要 翻訳者が翻訳できるように、「設定・定義を参照する」権限を割り当てます。ユーザーは、割り当てられた言語のみを翻訳できます。
  6. 変更内容を保存します。

  5. 変更内容を保存します。

自動リソース割り当てと匿名スケジュールの有効化

自動サービスリソース割り当てを有効化して、ユーザーがサービスリソースを選択せずに予定をスケジュールできるようにできます。顧客やゲストユーザーは、サービスリソースの名前を常に知っているとは限りません。また、自分がどのリソースに割り当てられているかを気にしない場合もあります。自動リソース割り当てを有効にすると、サービスリソースはユーザーが選択した時間枠に基づいて自動的に割り当てられます。また、予定サマリーページで割り当てられたリソースの名前を非表示にして、そのプライバシーを保護することもできます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

匿名スケジュールでは、選択した作業種別グループ、エンゲージメントチャネル (省略可能)、サービステリトリーで対応可能なサービスリソースの集計された時間枠のリストが表示されます。時間枠を選択すると、Salesforce Scheduler は、その時間枠で対応可能なリソースからサービスリソースをランダムに割り当てます。リソース稼働率を最適化するには、[予定配分] 設定を有効にします。

メモ サービスリソースのランダムな選択は Lightning コンソールにのみ適用されます。API の場合、Salesforce Scheduler は各時間枠で対応可能なサービスリソースのセットを返します。
例 顧客である Bruce は、1 Market St. 支店のリテールバンカーと資産管理の話をするために、午後 2 時～ 5 時の間に面談したいと考えています。この時間帯には、John、Sara、Jane の 3 人のリテールバンカーが対応可能です。John が対応できるのは午後 1 時～ 2 時と午後 2 時～ 3 時の時間枠です。Sara は、午後 2 時～ 3 時、午後 3 時～ 4 時、午後 4 時～ 5 時の時間枠で対応できます。そして Jane は、午後 3 時～ 4 時と午後 4 時～ 5 時の時間枠で対応できます。Bruce は、時間枠画面で午後 1 時～ 2 時、午後 2 時～ 3 時、午後 3 時～ 4 時、午後 4 時～ 5 時の空き時間枠の統合ビューを確認します。午後 3 時～ 4 時の時間枠を選択すると、3 人の対応可能なリテールバンカーのうちの 1 人が、予定にランダムに割り当てられます。
  • ユーザーへの [匿名予約] 項目に対する「編集」アクセス権の付与
    自動サービスリソース割り当てを有効にする前に、ユーザーにサービス予定オブジェクトの [匿名予約] 項目に対する「編集」アクセス権を付与します。
  • 自動サービスリソース割り当ての有効化
    自動サービスリソース割り当てを有効にすると、顧客またはゲストユーザーはサービスリソースを選択せずに予定をすばやくスケジュールできます。選択された時間枠に応じて、適切なサービスリソースが自動的に予定に割り当てられます。また、サービスリソースを手動で選択するオプションや、自動的に割り当てるオプションをユーザーに提供するフローを設定することもできます。
  • 匿名リソーススケジュールの有効化
    匿名スケジュールを有効にすると、ユーザーはスケジュール設定プロセス中にサービスリソースを選択しなくなります。また、割り当てられたリソースの名前が予定サマリーページには表示されなくなります。サービスリソース名をユーザーに表示しないことで、そのプライバシーが保護されます。これにより、最初に割り当てられたリソースが対応できなくなった場合に柔軟に別のリソースを予定に割り当てることができるようになります。

    レコードトリガーフローを使用して、今後の予定をユーザーに通知します。通知を受信者グループにメールで送信することも、各受信者に個別に送信することもできます。
  2. 受信者としての割り当て済みサービスリソースの追加
    サービス予定に割り当てられたサービスリソースのリストを取得し、受信者としてメール通知リストに追加します。
  3. 予定通知メールリストへのサービス予定の親レコードの追加
    サービス予定に関連付けられた親レコードをメール通知リストに追加するには、[割り当て] 要素を作成します。
  4. メール通知用のサービス予定レコードの特定
    メール通知で予定情報を追加するには、サービス予定レコードを特定します。
  5. サービス予定通知を送信するアクションの作成
    割り当てられたサービスリソースおよび関連レコードに予定情報が含まれるメール通知を送信します。

同時スケジュールに関する考慮事項

  • 同時時間枠はサービステリトリーメンバーにのみ適用でき、サービステリトリーまたは作業種別には適用できません。そのため、サービステリトリーまたは作業種別レコードを表示しても、営業時間に同時時間枠は表示されません。また、予定のスケジュール中は、サービステリトリーメンバーの営業時間内の同時時間枠のみを選択できます。作業種別またはサービステリトリーの営業時間内の同時時間枠は使用できません。

Salesforce Scheduler でのパフォーマンス向上に関する考慮事項

スケジュールはパフォーマンス集約的なプロセスです。Salesforce Scheduler を最大限に活用するために、設定では次の点に留意してください。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • 有資格のサービスリソース数が増えると、それぞれの時間枠に対応可能なサービスリソースのリストを取得するのに時間がかかるようになります。

    有資格のサービスリソース数は、14 日間あたり 20 人に制限することをお勧めします。 スキルマッチングとエンゲージメントチャネル種別を有効にする場合は、同じ作業種別グループと同じエンゲージメントチャネル種別に関連付けるサービスリソース数を、サービステリトリーあたり 20 人に制限してください。この制限は、Salesforce Scheduler の標準フローを使用する場合に適用されます。

    メモ 1 つの時間枠に 20 人を超えるサービスリソースが対応可能な場合は、予定配分を使用して有資格のサービスリソース数を制限してください。
  • 時間枠がすばやく読み込まれるようにするには、対応可能な時間枠を取得してキャッシュする日数を減らします。
    • 標準フローを使用する場合、1 回のサーバーコールで時間枠が取得される日数は、[サービス予定の時間枠を選択] 画面コンポーネントの [時間枠の事前読み込みの乗数] 属性の値によって決まります。たとえば、デバイスのページで 7 日間の時間枠を表示でき、この属性値が 2 である場合は、14 (=7x2) 日間の時間枠が取得されます。負荷を減らすには、属性値を 1 に設定して 7 日間の時間枠のみを取得するようにします。
    • API を使用している場合は、API 要求の [開始時刻] 項目と [終了時刻] 項目を使用して、短い期間を指定します。デフォルトの期間は 31 日です。
  • サービスリソースが予定に対応できるかどうかを判断する際に Salesforce カレンダーの行動を考慮しない場合は、スケジュールポリシーの [Salesforce カレンダーでリソースの対応可能状況を確認] オプションをオフにします。

  • Available Territory Slots (使用可能なテリトリー時間枠)

    2. [次へ] をクリックします。
  7. [通知テンプレートの選択] セクションで、[承認割り当てメールテンプレート] 項目で使用するメール通知テンプレートを選択し、[次へ] をクリックします。
  8. [承認ページレイアウトに表示する項目の選択] セクションで、次の手順を実行します。
    1. [選択可能な項目] リストで、シフト承認者に表示する項目を選択します。
    2. 選択した項目を [選択済みの項目] リストに移動するには、[追加] をクリックします。
    3. [承認ページの項目] で、[上で選択した項目に加え、承認履歴情報も表示します] を選択します。
    4. [次へ] をクリックします。
  9. [申請者の指定] セクションで、次の手順を実行します。
    1. [申請者] で、申請者種別の検索ドロップダウンリストから [所有者] を選択します。
    2. [選択可能な申請者] リストで、[シフト所有者] を選択します。
    3. 選択した申請者を [許可される申請者] リストに移動するには、[追加] をクリックします。
    4. [ページレイアウト設定] で、[[承認申請] ボタンと [承認履歴] 関連リストをすべてのシフトページレイアウトに追加] を選択します。
  10. 変更内容を保存します。
  • 承認プロセスへのメールアラートの追加
    作成したメールテンプレートを承認プロセスのアクション (申請時のアクション、最終承認時のアクション、最終却下時のアクション、取り消しアクション) にリンクします。
  • 承認プロセスへの承認ステップの追加
    承認ステップを追加して、そのステップに進むことができるレコードと承認者のほか、代理承認者が申請に返答できるかどうかを決定します。
  • 承認プロセスへの項目自動更新の追加
    項目自動更新では、選択した項目が承認プロセスの完了後に変更されます。たとえば、テリトリーマネージャーがシフトを承認すると、シフトの [状況] 項目が [仮承諾] から [確認済み] に更新されます。[申請時のアクション]、[最終却下時のアクション]、[取り消しアクション] で項目自動更新を追加できます。
  • シフト承認プロセスの有効化
    承認プロセスを設定したら、必ず承認プロセスを有効化します。
