[受信 予定を変更] フローの追加の設定

組織で [行動管理] 設定が有効になっている場合、[受信 予定を変更] フローを機能させるために追加の手順を実行する必要があります。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. 取引先と取引先責任者に対する編集権限をユーザーに付与します。
    1. [設定] の [クイック検索] ボックスに「プロファイル」と入力し、[プロファイル] を選択します。
    2. 権限を割り当てるプロファイルの横にある [編集] をクリックします。
    3. [標準オブジェクト権限] で、取引先と取引先責任者オブジェクトの [編集] を選択します。
  2. パートナーユーザーに、パートナーの取引先レコードの参照および更新アクセス権を付与します。次のいずれかの方法で実行できます。
    • パートナーユーザーと取引先レコードを手動で共有します。
    • 共有セットを作成して、パートナーユーザーに参照および更新アクセス権を付与します。
    • 取引先に共有ルールを使用して、取引先レコードをパートナーユーザーと共有します。
  3. [共有設定] の [組織の共有設定] の [活動] で、デフォルトの内部アクセス権を [親レコードに連動] に設定します。
  4. 行動オブジェクトの [公開] 項目で、項目レベルセキュリティをパートナーのユーザと管理者プロファイルについて [参照可能] に設定します。
  5. パートナーユーザが行動を作成したときに、「公開」フラグを true に設定する行動オブジェクトのワークフロールールを作成します。

権限と階層

Dream Horse の Salesforce システム管理者は次の権限と階層を使用して、すべてのユーザーに必要なアクセス権のみが割り当てられるようにします。

  • ポータルロール階層: パートナー関係者の階層を作成して、各ユーザーが、ロール階層内で自分より下位のユーザーが所有する、またはそれらのユーザーと共有するデータにアクセスできるようにします。
  • 外部取引先階層: パートナー取引先がすべてのサービステリトリー取引先のデータにアクセスできるようにします。
  • 共有の直接設定: Dream Horse のシステム管理者が作成したレコードをポータルロールと共有できるようにします。
  • Apex 共有: それぞれのサービスリソースがシフトレコードにアクセスできるようにします。
  • [リソースの予定の共有] 設定: 予定レコードを対応するサービスリソースと共有できるようにします。
  • 共有ルール: Dream Horse の顧客ケアエージェント (クライアント顧客ケアエージェント)、ゲストユーザー、認証済みユーザーとレコードを共有できるようにします。

ポータルロール階層の設定

ポータルロール階層を使用して、階層の上位のユーザーが、自分より下位のユーザーが所有する、またはそれらのユーザーと共有するデータにアクセスできるようにします。デジタルエクスペリエンスの設定で、パートナーロールの数が 3 に設定されていることを確認します。 Customer Community Plus ライセンスを使用している場合は、カスタマーのロール数の数が 3 に設定されていることを確認します。

デフォルトでは、次のロールが作成されます。

  • エグゼクティブ
  • マネージャー
  • ユーザー

パートナーユーザー、コントラクター、アシスタントが、自分のデータと自分が共有しているデータにのみアクセスできるようにするには、これらのユーザーをポータル階層の最下位レベルに追加します。テリトリーマネージャーが自分のデータとチームのデータのみにアクセスできるようにするには、階層内でチームの上位にテリトリーマネージャーを追加します。パートナー顧客ケアエージェントがサービステリトリー全体のすべての従業員のデータにアクセスできるようにするには、階層内でテリトリーマネージャーの上位に顧客ケアエージェントを追加します。

外部取引先階層の設定

パートナー取引先がすべてのサービステリトリー取引先のデータにアクセスできるようにするには、外部取引先階層を使用します。

外部取引先階層を設定する前に、親会社である Dream Horse の取引先を作成します。

次に、親取引先として Dream Horse を使用して、Chantilly Stables と Versailles Stables のパートナー取引先を作成します。

また、販売店を親レコードとして各支店 (サービステリトリー) の取引先を作成します。

販売店ごとに、販売店を親レコード、支店を子レコードとして外部取引先階層を作成します。たとえば、Chantilly Stables を親レコードとして、Chantilly Stables サンフランシスコ支店と Chantilly Stables サクラメント支店を子レコードとして外部取引先階層を作成します。海藻が有効なことを確認します。

Apex による共有管理の設定

シフトを使用している場合は、テリトリーマネージャーがサービスリソースのシフトを作成するときに、シフトレコードへのアクセス権をそれぞれのサービスリソースに付与する必要があります。アクセス権を付与するには、Apex による共有管理を使用して、共有ルールをプログラムで定義します。

シフトレコードを各サービスリソースと自動的に共有するためのサンプル Apex コードを以下に示します。

trigger Shift_share_with_Contractor on Shift (after insert, after update) {
if (trigger.isinsert) {
for (Shift shift: trigger.new) {
String srId = shift.ServiceResourceId;
// if shift has no ServiceResource, then no need to share shift
if (srId == null) {
continue;
}
ServiceResource sr = [Select Id, RelatedRecordId from ServiceResource Where Id=:srId];
String userId = sr.RelatedRecordId;
// if the user is owner, no need to create share row
if (userId == shift.OwnerId) {
continue;
}
// create a ShiftShare row
ShiftShare shiftShare = new ShiftShare (
ParentId=shift.Id, // Shift Id
AccessLevel='Edit', // AccessLevel - Read/Edit/All
RowCause='Manual', // RowCause - Manual
UserOrGroupId=userId // Id of the user/group
);
insert shiftShare;
}
}
else if (trigger.isupdate) {
for(Shift shift: trigger.new) {
Shift oldShift = trigger.oldMap.get(shift.Id);
String prevSrId = oldShift.ServiceResourceId;
String newSrId = shift.ServiceResourceId;
// if service resource is changed
if (prevSrId != newSrId) {
// if previous Service Resource was present, remove the share row for that
if (prevSrId != null) {
ServiceResource prevSr = [Select Id, RelatedRecordId from ServiceResource Where Id=:prevSrId];
String prevUserId = prevSr.RelatedRecordId;
// delete ShiftShare
List<ShiftShare> shiftShare = [Select Id from ShiftShare Where ParentId=:shift.Id and UserOrGroupId=:prevUserId];
if (shiftShare.size() > 0)
delete shiftShare;
}
// if Service Resource is updated, then create a share row
if(newSrId != null) {
ServiceResource newSr = [Select Id, RelatedRecordId from ServiceResource Where Id=:newSrId];
String userId = newSr.RelatedRecordId;
// if the user is owner, no need to create share row
if (userId == shift.OwnerId) {
continue;
}
// create a ShiftShare row
ShiftShare shiftShare = new ShiftShare (
ParentId=shift.Id, // Shift Id
AccessLevel='Edit', // AccessLevel - Read/Edit/All
RowCause='Manual', // RowCause - Manual
UserOrGroupId=userId // Id of the user/group
);
insert shiftShare;
}
}
}
}
}

[リソースの予定の共有] 設定の有効化

サービスリソースが各自の予定にアクセスできるようにするには、[Salesforce Scheduler の設定] で [リソースの予定の共有] を有効にします。

メモ 階層で割り当てられたサービスリソースより上位のユーザーは、自分より下位のユーザーのサービス予定に自動的にアクセスできます。

設定を有効にする前に作成された予定は、対応するサービスリソースと手動で共有します。

共有ルールの設定

レコードをクライアント顧客ケアエージェントと共有するには、Salesforce でクライアント顧客ケアエージェントのロールを作成します。次に、すべてのレコードを内部ロールと共有するための条件に基づく共有を、各オブジェクトで作成します。

すべてのクライアント顧客ケアエージェントと作業種別グループおよびシフトを共有する方法の例を見てみましょう。共有ルールを作成する前に、「Dream Horse CCA」というロールを作成して、すべてのクライアント顧客ケアエージェントに割り当てます。

すべての有効な作業種別グループを Dream Horse CCA ロールと共有するための共有ルールを作成します。

同様に、すべてのシフトレコードを Dream Horse CCA ロールと共有するための共有ルールを作成します。

共有ルールを使用したゲストユーザーと認証済みユーザーへのエンティティアクセス権の付与

予定を予約するには、すべてのサービステリトリー、作業種別、作業種別グループ、サービスリソース、シフトレコードへのアクセス権をゲストユーザーおよび認証済みユーザーに付与します。

ゲストユーザーにアクセス権を付与するには、Experience Cloud サイトのゲストユーザーとレコードを共有するための [条件に基づくゲストユーザーアクセス] ルールタイプの共有ルールを作成します。認証済みユーザーにアクセス権を付与するには、認証済みの顧客全員を含む公開グループを作成します。次に、[条件に基づく] ルールタイプの共有ルールを作成して、レコードをすべての顧客を含む公開グループと共有します。

重要 新しい認証済みユーザーをグループに追加します。

次にいくつか例を見てみましょう。

すべての有効な作業種別グループをゲストユーザーと共有するための共有ルールを作成します。

同様に、すべてのシフトレコードをゲストユーザーと共有するための共有ルールを作成します。

すべての有効な作業種別グループをすべての顧客が含まれる公開グループと共有するための共有ルールを作成します。

同様に、すべてのシフトレコードをすべての顧客が含まれる公開グループと共有するための共有ルールを作成します。

設定の完了後は、Dream Horse とその関係者に必要なアクセス権が付与されています。また、Dream Horse の各販売店は互いのデータにはアクセスできません。

Salesforce Scheduler 実装ガイドライン

Salesforce Scheduler の制限について学習し、それに従って実装を計画します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

モバイルデバイスでのサポートの制限

  • Salesforce Scheduler 標準フローテンプレートでは、モバイルデバイスでのマルチリソーススケジュールはサポートされません。
  • Salesforce モバイルアプリケーションでは、Salesforce Scheduler を使用できません。モバイルデバイスで Scheduler を操作する場合は、代わりにモバイルブラウザーを使用することをお勧めします。詳細は、「Lightning Experience でサポートされるブラウザーおよびデバイス」を参照してください。
  • 発信フローはモバイルデバイスではサポートされていません。

フロー固有の制限

  • Salesforce Scheduler 標準フローテンプレートでは、中国語、デンマーク語、オランダ語、英語、フィンランド語、フランス語、ドイツ語、イタリア語、日本語、韓国語、ノルウェー語、ポルトガル語、ロシア語、スペイン語、スウェーデン語、タイ語がサポートされています。
  • [名前別] および [以前にスケジュールされたサービス予定別] オプションでは、アセットサービスリソース (またはアセット) は表示されません。[作業種別グループ別、予定種別、またはサービステリトリー別] オプションを選択し、対応可能なサービスリソースのリストが表示されるページでアセットを選択します。
  • サービステリトリーを選択するフロー画面では、営業時間は、ユーザのタイムゾーンではなく、サービステリトリーの営業時間のタイムゾーンで表示されます。
  • アクションボタンを使用してフローを起動した場合、フローフェーズを進めるときに動的フロー進行状況インジケーターは表示されません。インジケーターは、クイックアクションボタンを使用してフローを起動したときに表示されます。

行動管理、同時スケジュール、マルチリソーススケジュールの制限

  • 同時スケジュールとマルチリソーススケジュールは併用できません。
  • マルチリソーススケジュールでは、アセットサービスリソース (またはアセット) を含めて最大 5 つの必須サービスリソースがサポートされます。
  • マルチリソーススケジュールが有効な場合、Salesforce Scheduler フローはレコードページのサイドバーに追加されると機能しません。
  • 匿名スケジュールが有効になっている場合、Salesforce Scheduler では予定のサービスリソースが自動的に選択されます。そのため、マルチリソーススケジュールが有効になっていても、Salesforce Scheduler では複数のリソースを匿名の予定に割り当てることはできません。
  • 受信予定フローで [行動管理] 設定を使用するには、行動オブジェクトへのアクセス権を提供するコミュニティライセンスを常に使用します。

  • [行動管理] が有効な場合に、Salesforce Scheduler サービス予定で作成された Salesforce カレンダーの行動は編集できません。

    サービス予定は常に親オブジェクトである必要があります。Salesforce カレンダーの行動を直接編集しないでください。代わりに、対応するサービス予定レコードを更新します。これにより行動レコードが更新されます。

  • [行動管理] が有効になっている場合、行動オブジェクトの件名項目は 255 文字に制限されます。ただし、[行動管理] と [ブロックリソースの対応可能状況] の両方が有効になっている場合、Scheduler では件名項目に Block time before: または Block time after: が追加されます。したがって、件名項目の制限は 234 文字になります。指定された制限を超える文字は切り捨てられます。
  • Salesforce Scheduler では複数日のスケジュールはサポートされていません。つまり、1 日を超える予定をスケジュールすることはできません。

ケースの予定のスケジュールに関する制限

  • パートナーと顧客ケア担当者のみがケースの予定を予約できます。
  • Salesforce Scheduler では、アセット関連のケースの予定の予約はサポートされていません。
  • 取引先に関連するケースの予定を予約する場合、その取引先の設定と業務時間は考慮されません。
  • 取引先または取引先責任者に関連するケースの予定を予約した場合、予約した予定には、対応する取引先または取引先責任者の詳細は表示されません。
  • サービス予定をケースレコードページの [関連] タブに追加することはできません。

    予定フローに作業種別グループの検索条件を適用して、予定をより迅速に、関連する作業種別グループを使用してスケジュールできるようにします。[作業種別グループを選択] フローページの [作業種別グループ ID 別に絞り込み] 属性で、カンマ区切りの作業種別グループ ID のリストを指定します。Salesforce Scheduler には、作業種別グループのリストで指定した作業種別グループのみが表示されます。たとえば、顧客が資産管理の専門知識を持ち、スペイン語も流暢なバンカーとの予定を予約しようとしているとします。この顧客の場合、条件に一致する作業種別グループ ID のみを指定できます。作業種別グループの選択ページで、作業種別グループがアルファベット順に表示されます。
  • サービスリソースの絞り込みの有効化
    予定フローにサービスリソースの検索条件を適用して、予定をより迅速に、最も適したサービスリソースでスケジュールできるようにします。関連するフローページで [リソース ID 別に絞り込み] 属性を使用して、サービスリソース ID のカンマ区切りリストを指定します。Salesforce Scheduler は、予定のサービスリソースまたはサービステリトリースロットを取得するときに、指定されたリソースのリストのみを検索します。サービスリソース選択ページでは、サービスリソースはカンマ区切りのリストで指定した順序で表示されます。
  • サービステリトリーの選択画面をスキップ
    仮想テリトリーを使用する、またはデフォルトのサービステリトリーを設定する場合は、フローを編集し、デフォルトのサービステリトリーを設定して、サービステリトリーの選択画面をスキップします。[発信 新規予定] フロー、[受信 新規予定] フロー、[受信 新規ゲスト予定] フローとそれらのインスタンスでは、サービステリトリーの選択画面をスキップできます。必要に応じて、レビュー画面にサービステリトリーの住所を表示することもできます。
  • 予定のタイムゾーンの管理
    予定の時間枠ページのデフォルトタイムゾーンを設定するか、またはタイムゾーンを動的に設定します。時間枠ページのタイムゾーンドロップダウンリストを有効化して、ユーザーが希望するタイムゾーンで予定をスケジュールできるようにします。
  • サービス予定項目への入力規則の追加
    入力規則を追加して、ユーザー入力が要件を満たすようにします。入力規則を使用してデフォルトのエラーメッセージを上書きすることもできます。たとえば、ユーザーが件名を入力した後でしか予定を保存できないようにする入力規則を追加できます。
  • 入力を更新するようにフローを更新
    ユーザーが予定のスケジュール中に前のページに戻って変更を加えたら、その変更が後続のページにも反映されるように、Salesforce Scheduler フローを設定します。そうしておかないと、ユーザーが前のページで適切な値を選択しなかった場合は、スケジュール処理をキャンセルして最初からやり直す必要があります。
  • [サービス予定をレビュー] 画面の変更
    ユーザーの [サービス予定をレビュー] 画面レイアウトを変更するには、ユーザーのプロファイルに割り当てられた [サービス予定] レイアウトを変更します。
  • カスタムの [サービス予定をレビュー] 画面の作成に関する考慮事項
    組み込みのカスタマイズオプション以上に [サービス予定をレビュー] 画面をカスタマイズする場合は、独自の画面を作成します。たとえば、ゲストフローの [サービス予定をレビュー] 画面で値を事前入力する場合は、カスタムの [サービス予定をレビュー] 画面を作成します。

予定のタイムゾーンの管理

予定の時間枠ページのデフォルトタイムゾーンを設定するか、またはタイムゾーンを動的に設定します。時間枠ページのタイムゾーンドロップダウンリストを有効化して、ユーザーが希望するタイムゾーンで予定をスケジュールできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • 予定の時間枠ページのタイムゾーンのプリセット
    Salesforce Scheduler フローの [タイムゾーンのデフォルト値] 属性を使用して、予定の時間枠が表示されるすべてのページのデフォルトのタイムゾーンを設定します。または、選択したサービスリソース、サービステリトリー、顧客、またはブラウザーのタイムゾーンに応じて、各ページのタイムゾーンを動的に設定します。
  • 予定の確認ページのタイムゾーンの設定
    スケジュールされている予定時刻は、デフォルトでは、予定の時間枠ページで選択されているタイムゾーンで予定の確認ページに表示されます。ただし、デフォルトの動作を上書きし、[タイムゾーン] 属性を使用して確認ページに別のタイムゾーンを設定できます。
  • 複数のタイムゾーンの選択の有効化
    予定フローで [タイムゾーン選択リストを表示] 属性を [True] に設定すると、Salesforce でサポートされるすべてのタイムゾーンのドロップダウンリストが予定の時間枠ページに表示されます。予定をスケジュールするときに、予定の時間枠を表示するタイムゾーンを選択できます。
  • フロー画面でのサービステリトリータイムゾーンの使用
    デフォルトでは、フローをスケジュールしているユーザーのタイムゾーンに基づいて時間が表示されます。ですが、選択したサービステリトリーのタイムゾーンに基づいて時間を表示したほうがよいケースもあります。たとえば、カスタマーサービス担当者が複数のロケーションの予定をスケジュールする場合などです。このようなシナリオでは、DefaultTimeZone 変数の値を設定して、サービステリトリータイムゾーンを使用します。

待機リストの管理

待機リストとは、予約なしで訪れてロビーで待っている顧客をチェックインして、サービスリソースに通知するためにグリーターが使用する仮想キューです。テリトリーマネージャーは、サービステリトリーごとに待機リストを作成して、作業種別とサービスリソースを関連付けることができます。

  • サービステリトリーの待機リストの作成
    グリーターは、待機リストを使用してドロップインの顧客を適切なサービスリソースに転送できます。

Salesforce Scheduler 標準フローテンプレート

ユーザーや顧客は、Salesforce Scheduler 標準フローテンプレートの手順に従って予定をスケジュール、変更、キャンセルできます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
フロー 目的
サービス予定出席者の追加または変更 グループサービス予定のサービス予定被招集者レコードを追加、変更、または削除する手順を説明します。
Book Appointment from Invitation (招待から予定を予約) ユーザーは、手順に従って、共有された予定招待 URL で選択されたサービスリソース (従業員またはコントラクター) またはアセットが含まれる予定をスケジュールできます。このフローは、[Generate Appointment Invitation (予定招待を生成)] フローを使用して作成された予定招待 URL から起動します。

サービス予定出席者の登録または登録解除 グループサービス予定へのサービス予定の被招集者の登録または登録解除の手順を説明します。
Generate Appointment Invitation (予定招待を生成) ユーザーは、手順に従って 1 人以上のサービスリソース (従業員またはコントラクター) またはアセットが含まれる予定招待を作成できます。サービスリソースレコードページからこのフローを追加して起動します。
受信 予定をキャンセル 認証された顧客は、手順に従って予定をキャンセルできます。Experience Cloud サイトまたは Web サイトからこのフローを追加して起動します。
受信 予定を変更 認証された顧客は、手順に従って予定を変更できます。Experience Cloud サイトまたは Web サイトからこのフローを追加して起動します。
受信 新規予定 認証された顧客は、手順に従って 1 人以上の従業員が含まれる予定を作成できます。Experience Cloud サイトまたは Web サイトからこのフローを追加して起動します。
受信 新規ゲスト予定 認証されていない、またはゲストの顧客 (リードまたは見込み客) は、手順に従って 1 人以上の従業員が含まれる予定を作成できます。Experience Cloud サイトまたは Web サイトからこのフローを追加して起動します。
ゲストサービス予定の変更 認証されていない顧客またはゲスト顧客 (リードまたは見込み客) がサービス予定を変更またはキャンセルできるようにします。メール通知テンプレートのリンクからこのフローを追加して起動します。
発信 変更予定 ユーザーは、手順に従って送信予定を変更できます。サービス予定のレコードページからこのフローを起動します。
発信 新規予定 ユーザーは、手順に従って 1 人以上の従業員 (サービスリソース) と顧客またはプロスペクトが含まれる送信予定を作成できます。このフローは、取引先、ケース、商談、またはリードと紹介のレコードページから起動します。
サービス予定の支払 サービス予定の支払についてユーザーに手順に沿った説明が表示されます。送信予定の場合、支払リンクが生成されます。受信予定の場合、ユーザーが支払の詳細を入力できるように支払ページが表示されます。
Reassign Multiple Service Appointments (複数サービス予定の再割り当て) ユーザーは手順に従って、サービスリソースの複数のサービス予定を他のサービスリソースに再割り当てすることができます。このフローは、[サービス予定] タブまたはサービスリソースのレコードページから起動します。
Send Appointment Invitation to Actionable List Members (アクション可能リストメンバーに予定招待を送信) ユーザーは手順に従って、内部ユーザーとログイン情報が設定された外部ユーザーの予定招待を作成し、その招待をアクション可能リストの選択済みメンバーに送信できます。
支払レートを設定 サービス予定の価格設定についてユーザーに手順に沿った説明が表示されます。このフローを起動して、選択した作業種別とサービステリトリーのレートカードを設定します。

  9. シフトのオブジェクト管理設定から、[トリガー] に移動します。
  10. [新規] をクリックします。
  11. デフォルトコードを次のコードに置き換えます。 
    trigger ShiftValidation on Shift (before insert, before update) {
    List<Shift> shifts = Trigger.new;

    Set<String> sr = new Set<String>();
    for(Shift shift: shifts) {
        sr.add(shift.ServiceResourceId);
    }
    
    List<ServiceResource> extendedSr = [SELECT Id FROM ServiceResource WHERE  OvertimeEnabled__c = False AND Id IN :sr];
    
    Set<String> srIds = new Set<String>();
    for(ServiceResource sr1: extendedSr) {
        srIds.add(sr1.Id);
    }
    
    Set<Shift> confirmedShifts = new Set<Shift>();
    Set<String> territoryIds = new Set<String>();
    //We will only run this validation for Shifts with Status Category = "Confirmed" AND Service Resource can work extended hours
    for(Shift shift: shifts) {
        if(shift.StatusCategory == 'Confirmed' && srIds.contains(shift.ServiceResourceId)) {
            confirmedShifts.add(shift);
            territoryIds.add(shift.ServiceTerritoryId);
        }
    }

    if(confirmedShifts.size() > 0) {
        //Get all Service Territory IDs along with their OperatingHourId
        ServiceTerritory[] territoryIdsWithOperatingHours = [SELECT Id, OperatingHoursId FROM ServiceTerritory WHERE Id IN :territoryIds];

        Set<String> operatingHourIds = new Set<String>();
        for(ServiceTerritory st: territoryIdsWithOperatingHours) {
            //Service Territory may not have Operating Hour defined
            if(st.OperatingHoursId != null) {
                operatingHourIds.add(st.OperatingHoursId);
            }
        }

        //Get Timeslot information for all Operating Hours got in previous step. We disregard all STM level concurrent timeslots (Shifts with MaxAppointments set to 1)
        TimeSlot[] timeSlots = [SELECT Id, DayOfWeek, StartTime, EndTime, OperatingHoursId FROM TimeSlot WHERE MaxAppointments = 1 AND OperatingHoursId IN :operatingHourIds];

        //Complex data structure to store Working hours for all Service territories. We will store empty inner map in case Service Territory does not have Operating Hour defined
        Map<String, Map<String, TimeSlot>> serviceTerritoryWithTimeSlotsPerDay = new Map<String, Map<String, TimeSlot>>();

        for(ServiceTerritory territory: territoryIdsWithOperatingHours) {
            Map<String, TimeSlot> timeSlotsPerDay = new Map<String, TimeSlot>();

            for(TimeSlot timeSlot: timeSlots) {
                if(timeslot.OperatingHoursId == territory.OperatingHoursId) {
                    timeSlotsPerDay.put(TimeSlot.DayOfWeek.substring(0,3), TimeSlot);
                }
            }
            serviceTerritoryWithTimeSlotsPerDay.put(territory.Id, timeSlotsPerDay);
        }

        //Main validation logic for all confirmed shifts
        for(Shift s: confirmedShifts) {
            String dayOfShiftStart = ((Datetime) s.StartTime).format('E').substring(0,3);
            String dayOfShiftEnd = ((Datetime) s.EndTime).format('E').substring(0,3);

            Map<String, TimeSlot> slots = serviceTerritoryWithTimeSlotsPerDay.get(s.ServiceTerritoryId);

            if(dayOfShiftStart != dayOfShiftEnd) {
                s.addError('Shift should be within Service Territory\'s Operating hours ');
            } else if(slots.get(dayOfShiftStart) == null || slots.get(dayOfShiftEnd) == null) {
                s.addError('Operating Hours for Service Territory not set up correctly');
            }else if(s.StartTime.time() < slots.get(dayOfShiftStart).StartTime || s.EndTime.time() > slots.get(dayOfShiftEnd).EndTime) {
                s.addError('Shift should be within Service Territory\'s Operating hours ');
            }
        }
    }
}

アクション可能リストを使用したサービスリソースの対応可能状況の共有

潜在顧客がサービスリソースとの予定を簡単かつ便利に行えるようにします。アクション可能リストを使用して、サービスリソースの対応可能状況が含まれる予定招待 URL を作成し、メールで潜在顧客と共有します。アクション可能リストを使用して、その予定招待 URL を使用して予約された予定を追跡することもできます。

アクション可能リストにアクセスするには、次のライセンスを調達します。

  • Industries Sales Excellence アドオン
  • Analytics Query Service Base アドオン
  • Data Pipelines アドオン
  • Data Processing Engine Platform ライセンス
メモ Salesforce Scheduler では、アクション可能リストのアセットのスケジュールとマルチリソーススケジュールはサポートされていません。
  • [アクション可能リストを使用したリソースの対応可能状況の共有] 設定の有効化
    アクション可能リストを使用して潜在顧客に関するサービスリソースの対応可能状況を生成して共有するには、[アクション可能リストを使用したリソースの対応可能状況の共有] 設定を有効にします。
  • アクション可能リストを使用して対応可能状況を共有するためのメールの項目レベルセキュリティの設定
    アクション可能リストを使用して対応可能状況を共有するための [Send Appointment Invitation to Actionable List Members (アクション可能リストメンバーに予定招待を送信)] 標準フローを呼び出すには、取引先責任者、リード、個人取引先オブジェクトの [メール] 項目で項目レベルセキュリティを設定します。
  • アクション可能リストメンバーを使用したサービスリソースの対応可能状況の共有
    対応可能状況を共有して、潜在顧客が簡単に予定をスケジュールできるようにします。カレンダーへの URL を使用して、顧客に招待メールを送信できます。生成できるのは自分の対応可能状況に関する予定招待のみであり、他のサービスリソースの代理では生成できません。
  • アクション可能リストメンバーの状況の変更と予定の詳細の表示
    サービスリソースがアクション可能リストメンバーと対応可能状況を共有すると、Salesforce Scheduler によって状況が更新されるようになります。状況が自動的に更新されない場合は、手動で更新できます。顧客が予定招待を使用して作成した予定を表示することもできます。

  3. Salesforce Scheduler オブジェクトのページレイアウトの関連リストの設定
    Salesforce Scheduler オブジェクトの関連リストを設定して、Salesforce Scheduler ユーザーがオブジェクトレコードに関連する詳細に簡単にアクセスできるようにします。たとえば、サービステリトリーを作成したら、[サービステリトリーメンバー] 関連リストからサービステリトリーにサービスリソースを割り当てられるようになります。また、[サービステリトリー作業種別] 関連リストからサービステリトリーに作業種別を割り当てることができます。
  4. Salesforce Scheduler でのサービステリトリーの設定

  7. Salesforce Scheduler での作業種別グループと作業種別の設定

予定のスケジュール中に、予定の時間枠の対応可能状況は、サービステリトリー、サービステリトリーメンバー、および作業種別の営業時間内での時間枠の交差部分に基づいて判断されます。同時時間枠 (サービステリトリーメンバーに対してのみ適用) の対応可能状況も同じ方法で判断されます。

例

バンカーの Sara は主に 1 Market St. 支店で作業していますが、近くの 101 Mission St. 支店での予定に割り当てられることがあります。Sara のプライマリサービステリトリーは 1 Market St. 支店、セカンダリサービステリトリーは 101 Mission St. 支店です。

1 Market St. 支店での Sara の営業時間は、月曜日から金曜日までの午前 8 時から午後 5 時までです。Sara は月曜日から木曜日までの特定の時間しか 101 Mission St. 支店をサポートできないため、そのテリトリーでの Sara の営業時間は月曜日から木曜日までの午前 10 時から午後 3 時までになります。両方の支店の営業時間は同一であり、月曜日から金曜日までの午前 6 時から午後 6 時までです。この営業時間を Salesforce に反映するため、Sara の Salesforce システム管理者は次の手順を実行します。

  1. 次の 3 つの営業時間を [営業時間] タブから作成し、それぞれの日に時間枠を追加します。
    • 月曜日から金曜日の午前 6 時から午後 6 時
    • 月曜日から金曜日の午前 8 時から午後 5 時
    • 月曜日から木曜日の午前 10 時から午後 3 時
  2. [営業時間] 項目を使用して、最初の営業時間セットを 1 Market St. と 101 Mission St. のサービステリトリーに追加します。
  3. [営業時間] 項目を使用して、2 番目の営業時間セットを 1 Market St. サービステリトリーの Sara のサービステリトリーメンバーレコードに追加します。
  4. [業務時間] 項目を使用して、3 番目の業務時間セットを 101 Mission St. サービステリトリーの Sara のサービステリトリーメンバーレコードに追加します。
これで、Salesforce Scheduler に各支店で Sara が作業できる時間が表示されるほか、Sara の対応可能状況と各支店の営業時間に基づいて時間枠が表示されます。

    業務時間コンポーネントをサービステリトリー、サービステリトリーメンバー、作業種別のレコードページに追加します。
  2. 業務時間のデフォルトの共有設定の更新
    業務時間の共有設定はデフォルトで [非公開] に設定されます。業務時間にアクセスするには、デフォルトの共有設定を変更します。
  3. Salesforce Scheduler での営業時間の作成
    Salesforce Scheduler 設定アプリケーションの [営業時間] タブで、営業時間と時間枠を表示、作成、変更します。または、作業種別、サービステリトリー、またはサービステリトリーメンバーレコードページで [営業時間] コンポーネントを使用します。
  4. サービステリトリー、サービステリトリーメンバー、作業種別への営業時間の割り当て

シフトのロールおよび階層の設定

ロールおよび階層によって誰が誰の部下になるかが定義され、シフトの承認プロセスを定義できるようになります。さまざまなサービステリトリーで特定のロールを所有するユーザーを割り当てることができます。たとえば、Adam は銀行マネージャー、John はリテールバンカーであるとします。テリトリーマネージャーロールとリテールバンカーロールを作成し、リテールバンカーがテリトリーマネージャーの部下になるようにできます。テリトリーマネージャーロールを Adam に、リテールバンカーロールを John に割り当てます。この階層を使用すると、Adam はシフトを作成し、シフトを承認して John に自分の対応可能状況を確認するよう要求できます。

    シフトを外部ユーザーと共有するには、シフト共有ルールを定義します。たとえばコントラクターとは、サービステリトリーマネージャーが承認を得るためにシフトを共有する外部ユーザーです。シフトを共有するには、コントラクターの公開グループを使用して、そのグループ内のロールを選択し、アクセス権を付与するユーザーを選択します。

サービステリトリーを作成して設定し、サービスリソースを整理して、サービスリソースが、拠点とする支店の周辺の予定に割り当てられるようにします。

    州選択リストと国選択リストを設定することで、都道府県および国のデータをテキスト項目に入力する代わりに、事前定義の標準化されたリストから選択できるようになります。

    ロケーション検索を有効にすると、ユーザーが予定をスケジュールするときに、予定のロケーションを検索して選択できます。

Amazon Chime を使用したビデオ予定の設定

Salesforce Scheduler に Amazon Chime が統合され、ビデオ通話が可能になりました。この機能は Bring Your Own Application (BYOA) モデルで動作し、使用するには Amazon Chime アカウントが必要です。Salesforce Scheduler では、ビデオ通話設定を有効にして設定すると、すべてのビデオ予定に Amazon Chime が使用されます。また、Salesforce Scheduler には仮想の予定のメール予定テンプレートが用意されているため、これを利用して未認証のユーザーに今後のビデオ予定の通知を送信することもできます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • Salesforce Scheduler の仮想通話の設定
    権限セットを割り当てて、仮想通話用の Amazon Chime を接続して設定します。
  • ビデオ通話の設定
    AWS アカウントを設定して Salesforce への接続を設定したら、ビデオ予定を設定します。
  • ユーティリティバーへの [ビデオ通話] ユーティリティ項目の追加
    ビデオ通話コンポーネントを Salesforce ユーティリティバーに追加して、サービスリソースやユーザーがビデオ通話に参加しやすくします。[ビデオ通話] ユーティリティ項目は、モバイル Web ブラウザーではサポートされていません。
  • ユーティリティバーへの [私の予定] マイクロカレンダーコンソールの追加
    [私の予定] マイクロカレンダーコンソールを Salesforce ユーティリティバーに追加して、サービスリソースやユーザーが過去の予定と今後の予定を容易に表示できるようにします。[私の予定] マイクロカレンダーコンソールは、モバイル Web ブラウザーではサポートされていません。
  • エクスペリエンスサイトでの Virtual Calls 用のページの作成
    エクスペリエンスサイトに 2 つの個別のページを追加して、Virtual Calls に必要な 2 つのコンポーネントを追加します。
  • 認証されていないユーザーのメール通知の設定
    認証されていないユーザーに今後のビデオ予定に関する通知を送信するには、サービス予定オブジェクトでレコードトリガーフローを作成します。受信者のメールアドレスと割り当てられたサービスリソース名を取得するようにフローを設定します。次に、サービス予定レコードを更新してサービスリソース名をカスタム項目に追加します。次に、使用可能な仮想の予定のメールテンプレートを使用するメール通知を送信する Apex アクションを作成できます。

Salesforce Scheduler での作業種別グループと作業種別の設定

作業種別グループ (予定のトピック) と作業種別 (予定テンプレート) を作成して、予定のスケジュールを合理化します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. Salesforce Scheduler での作業種別グループの作成
    作業種別グループは、予定のトピック (住宅ローンや投資など) を表します。ユーザーに関連する、予定のトピックを作成します。
  2. Salesforce Scheduler での予定のサブトピックのカスタマイズ
    Salesforce Scheduler で予定を作成するときに予定のトピックの下に表示される予定のサブトピックをカスタマイズします。
  3. Salesforce Scheduler での作業種別の作成
    作業種別は作業種別グループ (予定のトピック) とサービステリトリー (支店の場所) に含まれるテンプレートであり、これにより、予定のスケジュール作業を効率的かつ容易に標準化できます。デフォルトの予定所要時間、予定の前後のバッファ時間、予定の対応可能期間など、各種パラメーターを設定できます。
  4. Salesforce Scheduler での作業種別のスキル要件の追加
    作業種別のスキル要件を定義し、適切なスキルを持つサービスリソースに予定が割り当てられるようにします。サービスリソースは、その予定に関連付けられている作業種別に必要なすべてのスキルをそのリソースが持つ場合にのみ、予定に割り当てることができます。スキル要件を作業種別に追加すると、時間を節約し、ビジネスプロセスの一貫性を保つことができます。
  5. Salesforce Scheduler でのサービステリトリーへの作業種別の割り当て
    各作業種別 (予定テンプレート) をサービステリトリー (ロケーション) に対応付けます。
  6. Salesforce Scheduler での作業種別グループへの作業種別の割り当て
    各作業種別 (予定テンプレート) を作業種別グループ (予定のトピック) に対応付けます。
  7. Salesforce Scheduler での作業種別への作業種別グループの割り当て
    各作業種別グループ (予定のトピック) を作業種別 (予定テンプレート) に対応付けます。

時間枠のトラブルシューティング

ユーザーがフローを実行したときに Salesforce Scheduler で時間枠が表示されない場合に、次の手順を使用します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  1. フロー画面の [次のカレンダーページ] ボタンを使用して、次の 31 日間のカレンダーページを表示します。
  2. シフトを使用していない場合、サービステリトリーの業務時間、サービステリトリーメンバーの業務時間、作業種別の業務時間、および取引先の訪問時間の交差部分に少なくとも 1 つの時間枠があることを確認します。

    次の条件を満たす場合、少なくとも 1 つの時間枠が表示されます。

    Intersection of operating hours > Estimated Duration + Block Time After Appointment + (Block Time Before Appointment or Start Time Interval, whichever is higher) (業務時間の交差部分 > 予想所要時間 + 予定後のブロック時間 + (予定前のブロック時間または開始時間間隔のいずれか大きい方))
    重要 取引先の訪問時間は、[取引先の訪問時間を適用] スケジュールポリシーを有効にしている場合のみ使用されます。

    詳細は、「Salesforce Scheduler での業務時間の設定」および「Salesforce Scheduler による対応可能な時間枠の決定方法」を参照してください。

  3. シフトを使用する場合、少なくとも 1 つのシフトが作成されてサービスリソースに割り当てられ、シフトに少なくとも 1 つの時間枠があることを確認します。

    次の条件を満たす場合、少なくとも 1 つの時間枠が表示されます。

    Availability > Estimated Duration + Block Time After Appointment + (Block Time Before Appointment or Start Time Interval, whichever is higher) (対応可能状況 > 予想所要時間 + 予定後のブロック時間 + (予定前のブロック時間または開始時間間隔のいずれか大きい方))

    詳細は、次を参照してください。

    • シフトを使用した予定時間枠の決定
    • シフトに関する考慮事項
    • Salesforce Scheduler のスケジュールポリシールール
    • スケジュールポリシーでのシフトルールの定義
    • Salesforce Scheduler による対応可能な時間枠の決定方法
  4. 選択した作業種別グループのサービステリトリーメンバーの業務時間に少なくとも 1 つの時間枠があることを確認します。

  5. すべての対応可能な時間枠でサービス予定が予約されていないことを確認します。同時時間枠はサービステリトリーメンバーにのみ適用でき、サービステリトリーまたは作業種別には適用できません。詳細は、「同時スケジュールに関する考慮事項」を参照してください。

    詳細は、「カレンダーの確認によるサービスリソースの対応可能状況の判断」を参照してください。
  7. 選択した作業種別の [時間枠開始] から [時間枠終了] までの間に少なくとも 1 つの時間枠があることを確認します。
    詳細は、「Salesforce Scheduler での作業種別の作成」を参照してください。
  8. フローのカスタマイズですべての時間枠が除外されていないことを確認します。

    • 作業種別
    • 作業種別グループ
    • サービステリトリー
    • 匿名予約選択済み
    • リソース ID 別に絞り込み
    • スケジュールポリシー
    • サービスリソース
    • サービスリソース
    • 開始日
    • 作業種別で必要とされる選択したサービスリソースのスキルの開始日。

    詳細は、「フロー画面コンポーネント: サービス予定時間を選択」および「フロー画面コンポーネント: サービスリソースおよびサービス予定時間を選択」を参照してください。

  9. 匿名予約を使用している場合、少なくとも 1 人のサービスリソースが対応可能です。

仮想テリトリー

システム管理者とテリトリーマネージャーは、顧客とサービスリソースがどこからでも柔軟に予定を予約できるように、仮想テリトリーを作成できます。仮想テリトリーとは、電話やビデオなど、仮想チャネルでの予定に使用できるサービスリソースのグループについて、住所なしで作成されるサービステリトリーです。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

たとえば、リテールバンカーのグループが仮想の予定のみを受け入れるとします。バンカーは、シフトを作成して、対応可能なエンゲージメントチャネルを追加できます。システム管理者は、バンカーの仮想テリトリーを作成して、これらのサービスリソースをその仮想テリトリーに関連付けることができます。

メモ チャネルをシフトに関連付ける前に、エンゲージメントチャネル種別とチャネルの連結エンティティを必ず作成してください。
