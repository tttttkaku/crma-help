Salesforce Scheduler フロー画面へのコンポーネントの追加

フロー画面にコンポーネントを追加して、追加情報を表示したり、追加の入力を取得したりします。たとえば、ブランド設定用の表示ラベルとロゴを追加します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
必要なユーザー権限
フローを変更する 「フローの管理」

Salesforce Scheduler では、入力コンポーネントから取得した情報は自動的に保存されません。ユーザー入力をフロー変数に保存し、次のいずれかの方法を使用して Salesforce レコードにこれらの値を保存する必要があります。

  • [レコードを更新] フロー要素または [レコードを作成] フロー要素を使用する。
  • [予定を保存] アクションに渡される JSON コンテンツに値を含める。
  1. [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。
  2. フローを開きます。
  3. コンポーネントを追加する画面を開きます。
  4. 必要なコンポーネントをキャンバスにドラッグし、コンポーネントを設定します。
  5. 変更内容を保存します。
例

[受信 新規予定] フローの [サービスリソースを選択] 画面に画像と情報を追加する手順は、次のとおりです。

  • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。
  • [受信 新規予定] フローを開きます。
  • [被招集者] 画面を開きます。
  • [表示テキスト] コンポーネントをキャンバスにドラッグします。
  • コンポーネントの API 参照名を入力します。
  • 必要な画像と情報を追加します。
  • 変更内容を保存します。

ユーティリティバーへの [私の予定] マイクロカレンダーコンソールの追加

[私の予定] マイクロカレンダーコンソールを Salesforce ユーティリティバーに追加して、サービスリソースやユーザーが過去の予定と今後の予定を容易に表示できるようにします。[私の予定] マイクロカレンダーコンソールは、モバイル Web ブラウザーではサポートされていません。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
必要なユーザー権限
[私の予定] コンソールにアクセスする Salesforce Scheduler PSL ライセンスでの「ビデオ通話ユーザー」権限。
[私の予定] コンソールで予定を表示する サービス予定オブジェクトの [予定の予約 URL] 項目に対する「参照」。

Salesforce Scheduler では、予定が [私の予定] マイクロカレンダーコンソールに次のように表示されます。

  • [今後] タブには、今後 24 時間以内に開始されるようにスケジュールされていて、状況のカテゴリが [進行中]、[スケジュール済み]、[派遣済み]、または [なし] であるすべてのサービス予定が表示されます。
  • [過去] タブには、その日に終了したすべてのサービス予定と、すでに開始されている予定が表示されます。過去 1 時間以内に終了するようにスケジュールされていた予定も表示されます。
  1. [設定] の [クイック検索] ボックスに「アプリケーションマネージャー」と入力し、[アプリケーションマネージャー] を選択します。
  2. Salesforce Scheduler の [設定] で、[アクションを表示] をクリックして [編集] を選択します。
  3. [ユーティリティ項目 (デスクトップのみ)] をクリックして、[ユーティリティ項目を追加] をクリックします。
  4. 検索項目に「私の予定」と入力し、[私の予定] を選択します。
  5. 変更内容を保存します。

[私の予定] マイクロカレンダーコンソールがユーティリティバーで使用できるようになりました。

  • [私の予定] マイクロカレンダーコンソールに表示される予定の詳細
    [私の予定] マイクロカレンダーコンソールには、今後の予定と過去の予定が表示されます。このコンソールには取引先情報、予定のトピック、予定種別など、予定の基本情報が表示されるため、予定を簡単に把握できます。このコンソールでは、ログインしているサービスリソースのタイムゾーンでサービス予定が表示されます。

サービス予定項目への入力規則の追加

入力規則を追加して、ユーザー入力が要件を満たすようにします。入力規則を使用してデフォルトのエラーメッセージを上書きすることもできます。たとえば、ユーザーが件名を入力した後でしか予定を保存できないようにする入力規則を追加できます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
必要なユーザー権限
項目の入力規則を表示する 「設定・定義の参照」
項目の入力規則を定義または変更する 「アプリケーションのカスタマイズ」

ユーザーが予定を保存すると、Salesforce Scheduler ではすべての入力規則を満たしているかどうかが確認されます。入力規則を満たしていない場合、Salesforce Scheduler では設定済みのエラーメッセージが表示されます。これは、サービスリソースが [私の予定] コンソールで [Start Appointment (予定の開始)]、[End Appointment (予定を終了する)]、または [Accept Appointment (予定を受け入れる)] アクションを実行する場合にも適用されます。

  1. サービス予定のオブジェクト管理設定から、[入力規則] に移動します。
  2. [新規] をクリックします。
  3. ルール名、エラー条件数式、エラーメッセージを入力します。
    メモ [構文を確認] をクリックして、数式にエラーがないか確認します。
  4. 変更内容を保存します。

Agentforce for Scheduler の制限および許容量

Agentforce for Scheduler の次の制限と許容量に注意してください。

  • Agentforce は、デジタルエクスペリエンスサイトのアプリ内および Web のメッセージングでサポートされます。

  • ユーザーが会話で参照するオブジェクトのレコードに一意の名前を付ける。たとえば、ユーザが作業種別を参照する場合、Agentforce で適切な作業種別を選択できるように、すべての作業種別に一意の名前を付ける必要があります。これは、作業種別グループ、サービステリトリー、サービスリソースにも適用されます。

  • 予定の時間枠を表示する場合、Agentforce には 5 つの時間枠が表示されます。特定の時間枠を表示するには、その時間枠の時間範囲を指定します。

  • Agentforce はデフォルトのスケジュールポリシーを使用します。

  • Agentforce では、サービステリトリーのタイムゾーンと時間枠がサポートされます。

  • Agentforce では、次の Scheduler 予定がサポートされています。

    • 一対一だ
    • 匿名
    • ゲスト。

  • Agentforce for Scheduler は、ユーザーおよび顧客のコンシューマー エージェントとして使用することを目的としており、従業員エージェントではありません。

スケジューラーのエージェントの作成

Agentforce テンプレートを使用して、予定を管理するエージェントを作成します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Agentforce が有効になっている Enterprise Edition および Unlimited Edition。

開始する前に、Einstein生成AIを設定し、Agentforceを有効にします。

  1. 「テンプレートからのエージェントの作成」の手順に従います。
  2. [設定] で、「エージェント」を検索して [Agentforce Agents] を選択します。
    1. 新しいエージェントを作成するときは、Agentforce サービスエージェントまたはスケジュールを選択します。
    2. サブエージェントのリストで、[Appointment Management For Scheduler] が追加されていることを確認します。
  3. エージェントを作成したら、顧客検証サブエージェントを更新します。
    1. 作成したエージェントで、[] をクリックし、[ビルダーで開く] をクリックします。
    1. [Customer Verification (顧客検証)] サブエージェントをクリックします。
    2. [新しいバージョン] をクリックします。
    3. [分類の説明] を編集して、最初の文を「Verifies the customer's ID before scheduling an appointment or grant access to sensitive data (予定をスケジュールしたり機密データへのアクセス権を付与したりする前に顧客の ID を検証します)」に更新します。
    4. [範囲] を編集して、最初の文を「予定をスケジュールしたり、機密データへのアクセス権を付与したりする前に、まだ認証されていない顧客を認証するのが仕事です」に更新します。
    5. [保存] をクリックします。
    6. ページを再読み込みしてエージェントをテストします。

予定配分の有効化

予定配分により、予定をサービスリソースの間で均等にすばやく割り当てることができます。予定を公平に配分することで、サービスリソースを効率的に活用でき、生産性が高まります。Salesforce Scheduler は、サービスリソースの使用状況スコアに基づいて、予定が最も空いている適格なリソースを特定して予定の候補として提案します。匿名予約では、予定が最も空いている適格なリソースが自動的に予定に割り当てられます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

予定配分が有効である場合にユーザーが予定をスケジュールしやすくするには:

    新しい「表示するリソース数 (予定配分)」属性をフローで使用します。この属性は、[サービスリソースを選択]、[サービスリソースの対応可能状況]、[サービス予定時間を選択]、そして [サービスリソースとサービス予定時間を選択] 画面コンポーネントで使用できます。API を使用する場合は、resourceLimitApptDistribution パラメーターを使用してください。このパラメーターは getAppointmentCandidates REST API と available-territory-slots Connect API で使用できます。

  • 作業不可に基づいてサービスリソースをリストし、最も予定が空いているリソースを一番上に表示します。

    新しい「対応可能状況別にサービスリソースを表示」属性を False に設定します。この属性は、[サービスリソースを選択]、[サービスリソースの対応可能状況]、そして [サービスリソースとサービス予定時間を選択] 画面コンポーネントで使用できます。デフォルトでは True に設定されており、次に対応可能な日時の早い順にリソースが並び替えられます。

予定配分を実装する際の考慮事項

予定配分の制限について学習し、それに従って実装を計画します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • 予定配分が想定通りに機能するように、[時間枠の事前読み込みの乗数] 属性を 1 に設定します。 詳細は、「フロー画面コンポーネント: サービス予定時間を選択」を参照してください。
  • 必要な設定を有効化したら、予定配分が効果的に機能するように、サービスリソースの使用状況スコアを計算するのに十分なデータを数週間掛けてシステムに取得させます。
  • 不正確な使用状況スコアを防止するため、使用状況の計算ではサービスリソースの不在やリソースが予定に適格となる日付は考慮されません。たとえば、あるリソースが週の前半は不在であり、予定の割り当てポリシーで使用状況の計算頻度が毎週に設定されているとします。この場合は、そのリソースが、その週で最も予定の空いているリソースの 1 人として間違って認識されてしまう可能性があります。週の途中で組織に参加したリソースについても同じ状況が考えられます。
  • 予定の割り当てポリシーでは、[パラメーターベース] オプションでどれほど短い期間を指定しても、使用状況スコアを計算するための最小頻度は 1 日です。毎週または毎月の頻度では、使用状況スコアを計算するために考慮される週や月は、ユーザーロケールに基づいて選択されます。
  • Salesforce Scheduler の他にも、Field Service など複数の Salesforce 製品でサービス予定レコードが作成されます。同じ組織にこれらの製品が 2 つ以上あるとします。サービスリソースが各製品から予定を受けた場合、そのサービスリソースの使用状況スコアの計算ではすべての予定が考慮されます。
  • [予定配分] オプションが有効で、スケジュールポリシーで [サービステリトリーメンバーのシフトを使用] オプションが選択されている場合は、サービスリソースが絞り込まれて表示されます。リソースは、[表示するリソースの数 (予定配分)] フロー属性の値に基づいて絞り込まれます。次に、絞り込まれたサービスリソースの対応可能なシフトが考慮されます。

Salesforce Scheduler の機能

Salesforce Scheduler には、予定のスケジュールに関わるデータを管理するツールが用意されています。予定のスケジュールを標準の Salesforce ワークフロー (リード & 紹介、ケース、商談、取引先など) に埋め込むこともできます。Salesforce Scheduler では、ユーザーが Salesforce Lightning コンソール、Experience Cloud サイト、および Web サイトを使用して予定を予約することもできます。

必要なエディション

使用可能なエディション: Enterprise Edition および Unlimited Edition

Salesforce Scheduler を使用して実行できることを次にいくつか示します。

  • サービステリトリー (作業ロケーション)、ユーザーのサービスリソース (顧客の予定に参加する従業員や請負業者)、アセット (部屋または機器)、作業種別グループ (予定のトピック) などのビジネス情報を管理する。
  • 業務時間を使用することでチームの固定の勤務時間を使用するか、シフトを使用してチームが柔軟に独自の勤務時間を管理できるようにする。
  • 事務所の業務時間、予定のトピック、顧客の希望するミーティング時間、不在、休日などのさまざまな要素に基づいて対応可能状況を指定する。
  • 行動管理を使用して、Salesforce カレンダーに予定を表示する。
  • スキル、スケジュールポリシールール、設定を管理して、適切なタイミングで適切なリソースを見つけられるようにする。
  • 予定配分を使用して、サービスリソース間で予定を均等に配分できるようにする。
  • マルチリソーススケジュールを使用して、ユーザーが 1 つの予定で複数の被招集者を予約できるようにする。
  • 同時スケジュールを使用して、ユーザーが 1 つの時間枠に複数の予定を予約できるようにする。
  • フロー、開発者リソース、またはその両方を使用して、予定の予約環境をパーソナライズする。
  • Salesforce Lightning コンソール、Experience Cloud サイト、および Web サイトから受信予定および送信予定のスケジュールを可能にする。
  • 招待 URL を使用してサービスリソースの対応可能状況を共有する。

ドロップイン予定の受け入れに関する考慮事項

サービスリソースが予約なしの予定を受け入れるときに留意すべき点は次のとおりです。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • 待機リストの先頭に登録されている参加者の予約なしの予定を受け入れるように指示する通知が、待機リストに登録されているすべてのサービスリソースに送られます。
  • サービスリソースが参加者の予約なしの予定要求を受け入れると、待機リストで次の参加者の要求を受け入れるように指示する通知が他のリソースに送信されます。サービスリソースは、予約なしの予定を更新することで、新しい予定要求を確認できます。
  • 待機リストに参加者が残っている状態でグリーターが待機リストを無効化した場合でも、残りの参加者の要求を受け入れるように指示する通知が、登録済みのサービスリソースに引き続き送られます。
  • サービスリソースが予約なしの予定を受け入れると、関連する作業種別の推定所要時間に基づいて、そのリソースの時間がブロックされます。サービスリソースが、スケジュールされた終了時刻より前に予約なしの予定を完了した場合は、時間のブロックが解除されます。そして、そのサービスリソースの対応可能な時間枠が予約可能になり、そのリソースは別の予約なしの予定を受け入れられるようになります。

    たとえば、1 Market St. 支店で勤務するリテールバンカーの John が、その日の予定がスケジュールされていないため、予約なしの顧客に対応できるとします。John は、午前 11 時 00 分から、新しい小切手帳の発行についての説明を希望する参加者の予約なしの予定を受け入れました。この予定の予想所要時間は 40 分です。ですが、John は 20 分以内に予定を完了しました。John と定期的にやりとりしている顧客の Sarah は、同じ日に John との予定をスケジュールしたいと考えています。John は予約なしの予定を早めに完了したため、Sarah が予定を予約しようとすると、午前 11 時 20 分から対応可能な時間枠があることが表示されます。

  • [ドロップイン予定] で [スキルおよびスキルレベルのマッチング] 設定が有効になっている場合は、待機リストでの参加者の順序に関係なく、そのドロップイン予定を受け入れるように指示する通知は、必須スキルと一致する登録済みのサービスリソースにのみ送られます。

    1 Market St. 支店で勤務するリテールバンカーである John と Jane の例を見てみましょう。John は企業合併を専門していて、Jane は公証サービスを専門としています。Bruce と Tim は、それぞれドロップインでこの支店を訪れた顧客です。Bruce は提案されている合併について、Tim は書類の公正証書化について話したいと考えています。グリーターは、John と Jane の両方が登録されている待機リストに Bruce と Tim を追加します。Bruce は待機リストの 2 番目、Tim は先頭の参加者です。Jane は別の顧客に対応中であり、John は Tim の用件に対応できるスキルを持っていないため、Salesforce Scheduler は、Tim がリストの先頭であっても Bruce の予定を受け入れるように John に通知します。

業務量ベースのスケジュールに関する考慮事項

予定は、シフトの対応可能状況と業務量に基づいてシフトとサービスリソースに割り当てられます。特定のシフトまたは作業種別が業務量に達した場合、追加の予定は次のシフトまたは対応可能な業務量がある別のサービスリソースでスケジュールされます。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

業務量ベースのスケジュールを使用する場合は、次の考慮事項に留意してください。

  • シフトが部分的または完全に重複する場合、デフォルトの業務量は重複するシフトの業務量の合計になります。たとえば、シフト A の業務量が 5 で、業務量が 3 のシフト B と重複する場合、重複する期間のデフォルトの業務量は 8 です。 業務量管理を正確に行うには、重複するシフトの業務量を調整します。
  • シフトライフサイクルの途中で業務量制限を有効にすると、既存の予定に影響します。スケジュール済み予定が業務量を満たすように再評価されるようにします。
  • 業務量ベースのスケジュールでは、シフト作業トピックの [すべてのトピック] サポート フィールドはサポートされません。
  • シフト承認プロセスを使用して、シフトの追加や変更など、シフトの変更が正式な承認ワークフローを通過するようにします。
  • 業務量消費量を計算する場合、ドロップイン予定は計算で考慮されません。

グループサービス予定に関する考慮事項

グループサービス予定をスケジュールするときは、次の点に留意してください。

  • グループサービス予定はシフトでのみ作成できます。
  • サービス リソースが被招集者としてリード レコードを追加すると、Salesforce Schedulerからグループ予定に登録されたことを示す確認メールが送信されます。
  • サービスリソースまたはエクスペリエンスサイトユーザーが取引先責任者または個人取引先レコードを被招集者として追加すると、グループ予定に登録されます。登録済みの取引先責任者または個人取引先は、[私の予定] コンソールでグループ予定にアクセスできます。
  • グループサービス予定をスケジュールするときに、サービスリソースが [追加されたユーザー] および [エクスペリエンスサイトユーザー] グループ予定アクセス種別を選択した場合、グループサービス予定に追加されていないエクスペリエンスサイトユーザーは、エクスペリエンスサイトの [今後のイベント] タブからグループ予定にアクセスして登録できます。
  • シフトに関連付けられた作業種別とシフト作業トピック レコードの両方で被招集者制限を指定した場合、Salesforce Scheduler ではグループ予定のシフト作業トピック レコードの被招集者制限が考慮されます。
  • 1 つのグループ予定には、最大 50 人の被招集者を含めることができます。
  • マルチリソース グループ予定をスケジュールしていて、プライマリ リソースとセカンダリ リソースの被招集者の制限が異なる場合、Salesforce Scheduler ではプライマリ リソースの被招集者の制限が考慮されます。
  • 重複するシフトや隣接するシフトの場合、Salesforce Scheduler では最少被招集者制限が考慮されます。
  • 認証されていない (ゲスト) ユーザーは、グループ予定を作成できません。
  • グループ予定の場合、対応するシフトのグループカテゴリを選択する必要があります。
  • グループ予定をサポートするように作業種別を設定するには、適切な予定カテゴリを作業種別に関連付けます。デフォルトでは、すべての作業種別の予定カテゴリは、通常の予定の場合は null です。
  • シフトレコードを適切な予定カテゴリに関連付けます。たとえば、シフトレコードでは、[通常] または [グループ]、あるいはその両方のみが許可されます。[ドロップイン] が有効になっている予定カテゴリは使用できません。
  • カスタマーポータルユーザーが [私の予定] コンソールでグループ予定を管理するには、[状況] 項目でサービス予定出席者にエンティティアクセス権と項目レベルセキュリティ (FLS) を付与します。
  • 必要に応じて、Partner Central を使用してパートナーサイトを作成します。

  • プライマリ以外のサービスリソースに「行動の編集」権限がない場合、Scheduler ではそのサービスリソースは行動には追加されません。
  • 被招集者の出欠確認は、サービス予定にリンクしている行動ではサポートされていません。
  • [複数のサービスリソース行動] 設定を有効にする前にサービス予定が存在している場合、予定に関連付けられた行動は個別の行動のままで、Salesforce Scheduler にその他のサービスリソースは表示されません。サービスリソースの完全なリストを表示するには、この設定を有効にした後に既存のサービス予定を変更します。
    メモ サービス予定を変更し、関連付けられている行動は変更しないことをお勧めします。サービス予定への変更は、行動の詳細に自動的に反映されます。たとえば、サービス予定に他のリソースを追加すると、そのリソースが被招集者として行動に反映されます。行動に被招集者を追加しても、サービス予定の割り当て済みリソースは変更されません。また、サービス予定の変更には Scheduler API を使用することをお勧めします。
  • [複数のサービスリソースイベント] 設定を有効にする場合は、グループ予定モードを使用して予定を作成し、複数のリソースと複数の取引先責任者をグループ予定の被招集者として含めます。この場合、グループサービス予定の [関連] リストには、セカンダリサービスリソースの [割り当て済みリソース] に子行動は表示されません。

予定を Salesforce カレンダーに書き込む際の考慮事項

[行動管理] 設定を有効に設定して Salesforce Scheduler の予定を Salesforce カレンダーに書き込めるようにする場合は、次の点に留意してください。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition
  • Salesforce Scheduler の予定を Salesforce カレンダーに書き込むには、Customer Community Plus または Partner Community ライセンスが必要です。この機能は、Customer Community ライセンスではサポートされていません。
  • Salesforce Scheduler では、予定に開始時刻と終了時刻がスケジュールされている場合にのみ予定の Salesforce カレンダーの行動が作成されます。予定の開始時刻と終了時刻を指定しないと、Salesforce Scheduler ではカレンダーの行動は作成されません。
  • Salesforce Scheduler で作成した行動の開始時刻または終了時刻を更新するには、必ず Salesforce Scheduler で予定を更新してください。Salesforce カレンダーで行動を直接編集しないでください。
    • 予定の開始時刻、終了時刻、または状況項目を変更すると、予定に対応する行動が更新されます。
    • 予定をキャンセルするか、または予定を更新してスケジュール済みの開始時刻と終了時刻を削除すると、対応する行動が Salesforce カレンダーから削除されます。
  • [行動管理] 設定を有効にしたら、[リソースの対応可能時間をブロック] 設定と [複数のサービスリソース行動] 設定も有効に設定できます。
    • [リソースの対応可能時間をブロック] 設定を有効にすると、予定の前後のバッファでカレンダーの行動が作成されます。
    • [複数のサービスリソース行動] 設定を有効にすると、個々の行動がグループ化され、1 つの行動の下にすべてのサービスリソースのリストが表示されます。

Salesforce Scheduler での予定の予約のカスタマイズ

Salesforce Scheduler の標準フローテンプレート、フロー画面、フロー画面コンポーネントをカスタマイズして、ユーザー、顧客、見込み客に合わせて調整された予定の予約環境を提供します。

  • Salesforce Scheduler 標準フローテンプレート
    ユーザーや顧客は、Salesforce Scheduler 標準フローテンプレートの手順に従って予定をスケジュール、変更、キャンセルできます。
  • 標準フローテンプレートのカスタマイズ
    Salesforce Scheduler のフローは、標準フローテンプレートとしてインストールされます。ビジネスニーズに合わせて任意のフローをカスタマイズできます。
  • フロー画面のカスタマイズ
    ビジネスニーズに合わせてフロー画面をカスタマイズできます。たとえば、会社の用語を使用するように表示ラベルを変更したり、事前選択された値を変更したりできます。
  • Salesforce Scheduler に用意されたフロー画面のコンポーネントとアクション
    Salesforce Scheduler には、フローを作成してフローを変更するための追加のフロー画面コンポーネントとアクションが用意されています。
  • 自動リソース割り当てと匿名スケジュールの有効化
    自動サービスリソース割り当てを有効化して、ユーザーがサービスリソースを選択せずに予定をスケジュールできるようにできます。顧客やゲストユーザーは、サービスリソースの名前を常に知っているとは限りません。また、自分がどのリソースに割り当てられているかを気にしない場合もあります。自動リソース割り当てを有効にすると、サービスリソースはユーザーが選択した時間枠に基づいて自動的に割り当てられます。また、予定サマリーページで割り当てられたリソースの名前を非表示にして、そのプライバシーを保護することもできます。
  • Salesforce Scheduler でのフロー画面コンポーネントのカスタマイズ
    フロー画面に表示される情報をカスタマイズします。たとえば、オプションを事前選択し、値を自動入力して、レコードを絞り込みます。
  • Salesforce Scheduler 用 Lightning Web コンポーネント (LWC)
    Spring '26 以降、Salesforce Scheduler ではすべてのフロー画面コンポーネントが Lightning Web コンポーネントとしてサポートされるようになりました。これにより、任意のスケジュールフローを Lightning Web Runtime（LWR）サイトにリリースできます。以前は、一部のフロー画面コンポーネントでは Aura コンポーネントが使用され、Aura ベースのサイトに限られていました。

Salesforce Scheduler のデータインテグレーションルール

Salesforce Scheduler でデータインテグレーションルールを使用して地理位置情報の入力および更新を行う方法について説明します。

必要なエディション

使用可能なインターフェース: Lightning Experience。
使用可能なエディション: Enterprise Edition および Unlimited Edition

特定のレコードタイプに住所を追加する場合、データインテグレーションルールでは Google Maps API を使用して住所の地理位置情報データ (緯度、経度、および位置精度) を計算します。API でのみ表示可能なこのデータを、カスタムの Salesforce Scheduler アプリケーションで参照できます。

地理コードと呼ばれる地理位置情報データ機能は、次のオブジェクトで有効になっています。

  • サービス予定。「サービス予定住所の地理コード」データインテグレーションルールを使用します。
  • サービステリトリー。「サービステリトリー住所の地理コード」データインテグレーションルールを使用します。
  • リソースの不在。「リソースの不在住所の地理コード」データインテグレーションルールを使用します。
  • サービステリトリーメンバー。「サービステリトリーメンバー住所の地理コード」データインテグレーションルールを使用します。

データインテグレーションルールでは、次の項目の値が生成されます。

項目名 説明
Latitude 町名・番地の緯度。
Longitude 町名・番地の経度。
GeocodeAccuracy

緯度および経度の位置精度。サポートされている値 (精度の高い順に表示) は次のとおりです。

  • Address: 建物
  • NearAddress: 住所付近の地点
  • Block: 街区の中間点
  • Street: 番地の中間点
  • ExtendedZip: 拡張郵便番号地域の中心
  • Zip: 郵便番号地域の中心
  • Neighborhood: 近隣の中心
  • City: 市区郡の中心
  • County: 郡の中心
  • State: 都道府県の中心
  • Unknown: 住所の一致なし (無効な住所など)
メモ

Google マップは中国では制限されているため、Google マップに依存する Salesforce 機能は中国では機能しません。中国のユーザー向けにエラーを最小限に抑え、アクセスをカスタマイズするには、「Disable Google Maps-based Field Service features for China users (中国のユーザー向けに Google マップベースの Field Service 機能を無効にする)」を参照してください。

地理コードデータの最新情報の維持

Salesforce では次のときに、データインテグレーションルールを使用して項目を更新します。

  • レコードが作成または更新されたとき。
  • レコードタイプのデータインテグレーションルールが有効化されたとき。

データインテグレーションルールは非同期で実行され、処理には時間がかかります。処理時間は、更新するレコードの数によって異なります。

レコードの地理コードデータの状況を確認するには、レコードの [アクション] メニューから [新規データの確認] を選択します。状況には次の内容が表示されます。

  • レコードの地理コードデータが最後に更新された時間。
  • レコードの地理コード状況。地理コードデータが最新の場合、[同期済み] 状況が表示されます。
  • データを手動で更新できる [更新] ボタン。

地理コードの除外

別の地理コードサービスを使用している場合、そのオブジェクトのデータインテグレーションルールを無効化して Salesforce 地理コードを除外できます。
