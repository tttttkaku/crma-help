マーケティングニーズの管理

Account Engagement管理者は、マーケティング チームが取り組みを最大限に活用できるようにするツールにアクセスできます。

  • サードパーティクッキーのためのトラッキングコードの実装
    まだサードパーティトラッキングを使用している場合は、コードをコピーして Web ページに配置できます。トラッキングコードは、商品リストやランディングページなど、価値の高い Web ページでのみ使用してください。
  • 1 つのメールアドレスに対して複数のプロスペクトを有効化
    プロスペクトの一意の識別子としてメールアドレスまたは CRM ID のどちらを使用するかを選択します。使用される識別子は、プロスペクトのインポート、Salesforce コネクタ、フォーム登録、サードパーティコネクタのどれを使用してレコードが作成されたかに基づいています。2016 年 6 月 14 日以降に作成されたビジネスユニットでは、この機能がデフォルトで有効になっています。
  • [CSV ファイルとしてエクスポート] テーブル
    [CSV ファイルとしてエクスポート] テーブルには、最近のエクスポートに関する詳細とダウンロードリンクが表示されます。
  • 送信 IP アドレスの検索
    Account Engagement管理者は、許可リストに登録する送信IPアドレスをビジネスユニット設定で確認できます。
  • 送信 IP 種別の変更
    Account Engagement Advanced Edition および Premium Edition には、専用の送信 IP が付属します。毎月 250,000 件を超えるメールを送信する場合、専用送信 IP を使用する必要があります。ビジネスユニットの設定でこの IP 種別を変更できます。
  • 編集中セッションの終了
    管理者は、保留中の編集中セッションを終了し、Engagement プログラム、メール、テンプレートのロックを解除できます。
  • 項目への差し込み印刷のデフォルト値の追加
    見込み客項目に使用できる値がない場合に表示されるデフォルトの差し込み印刷値を設定します。たとえば、見込み客レコードに名がない場合に [名] 項目に「重要な顧客」が表示されるように設定します。
  • 通貨の書式の変更
    管理者は、ビジネスユニットのデフォルト通貨を編集できます。通貨は、有料検索とキャンペーンレポートに表示されます。
  • Account Engagement アセットの iframe を制限または限定する
    データを保護できるように、フレーム化された Account Engagement フォームとランディングページを表示できる Web ドメインを指定します。iframing を完全に制限することも、特定のドメインでのみ許可することも、制限なしで使用することもできます。
  • ビジターの絞り込み
    フィルターを使用すると、特定の種類の訪問、クリック、その他のアクションをキャンペーン結果やメール通知から除外できます。一般的な使い方は、会社の IP アドレスを除外して、レポートの内容が偏らないようにすることです。

Account Engagement アセットの iframe を制限または限定する

データを保護できるように、フレーム化された Account Engagement フォームとランディングページを表示できる Web ドメインを指定します。iframing を完全に制限することも、特定のドメインでのみ許可することも、制限なしで使用することもできます。

iframe を完全に制限すると、ランディングページやフォームなどの iframe を使用したアセットが Web ページに表示されなくなります。特定のドメインで iframe を許可すると、iframe を使用したアセットはそのドメインでのみ表示されます。トラッカードメインを追加または編集するときに iframe を許可することもできます。

  1. ビジネスユニットの設定を開きます。
    • Account Engagement で、 をクリックし、[設定] を選択します。
    • Lightning アプリケーションで、[Account Engagement 設定] を選択します。
  2. ［Account］ タブで、［Edit］ をクリックします。
  3. [Iframed Assets (フレーム化されたアセット)] 設定に移動し、制限オプションを選択します。
  4. 特定のドメインにフレーム化を制限するには、許可するドメインを入力します。ドメイン情報は引用符で囲まないでください。
    次のガイドラインに留意してください。
    • オプションの URL スキーム (http:// など) を含めて、ドメインの URL または IP アドレスを入力できます。
    • 許可されるアクセスの範囲を示すには、URL の先頭にワイルドカード (アスタリスク) を使用します。たとえば、http://*.example.com を使用して example.com のサブドメインを許可します。
    • 複数のドメインを追加するには、各ドメインの後に Enter または Return キーを押して、個別のエントリとして書式設定します。
  5. 作業内容を保存します。

データの使用状況と制限

Account Engagement のオブジェクト (メール送信可能な見込み客、メールテンプレート、ランディングページなど) には制限があります。各オブジェクトの制限は、Account Engagement のエディションによって異なります。現在の使用状況を確認し、必要に応じてオブジェクトをごみ箱に移動できます。

  • Account Engagement の制限
    Marketing Cloud Account Engagement の最大使用量の推奨事項と制限を理解します。これらの推奨事項は、パフォーマンスを最適化し、サービスの中断を回避することを目的としています。これらのガイドラインには、超過した場合に警告や例外が発生するものもあれば、高パフォーマンスを維持するための推奨事項もあります。
  • データベースの上限
    メール送信可能な見込み客がデータベース制限にどのように反映されるかについて説明します。
  • ビジネスユニットの使用状況の確認
    管理者は、ビジネスユニットで使用できる機能と使用状況の制限を確認できます。
  • ごみ箱の使用
    アセットを削除しても、アセットは削除されません。代わりにアセットはごみ箱に移動します。ほとんどのアセットはごみ箱から復元できます。ごみ箱を空にすることはできません。
  • 外部アクションの使用状況の確認
    サードパーティアプリケーション拡張では、外部アクションの Account Engagement API を使用して、Account Engagement の自動化を行います。すべてのアカウントには、ビジネスユニットのタイムゾーンに基づいて 12:00 AM から 11:59 PM まで、1 日あたり 100,000 回のサードパーティアプリケーション拡張機能コールのデータベース制限があります。外部の使用状況を確認して、データベースの制限を超えないようにします。
  • 外部アクションエラーの監視
    [External Actions Error Table (外部アクションエラーテーブル)] を使用して、Account Engagement の自動化に関連付けられたサードパーティアプリケーションからのエラーを特定、診断、解決します。

Account Engagement Optimizer を使用したビジネスユニットの健全性の監視

Optimizer を使用して、重大な設定の問題を診断して修正し、推奨事項を確認してビジネスユニットの処理効率を改善します。また、現在処理中のアクションを一時停止して再開したり、プロスペクトレコードに最も多くの変化をもたらしている機能を確認したりすることもできます。

  • Account Engagement Optimizer の使用に関する考慮事項
    Optimizer を使用するときは、次の考慮事項を念頭に置いてください。
  • Account Engagement Optimizer について
    Optimizer ページのテーブルではビジネスユニットの設定の問題とパフォーマンス改善基準が示されます。また、ビジネスユニットの稼働の効率を評価したり改善したりするのに役立つ他のツールにもアクセスできます。
  • Account Engagement Optimizer へのアクセス
    問題を解決し、処理時間を改善するのに役立つアクション可能な推奨事項を取得します。
  • Account Engagement でプロスペクトの変化をもたらした機能を監視
    ビジネスユニットのプロスペクトに最も多くの変化をもたらした機能とオートメーションを理解します。この情報を使用して、オートメーション、インポートの習慣、API インテグレーションなどを調整することができます。
  • Account Engagement での進行中のアクションの一時停止または再開
    ビジネスユニットで処理中のアクションを一時停止および再開します。たとえば、プロスペクトをアーカイブするための進行中のアクションがあることが確認された場合、そのアクションを一時停止して、重要なリストメールの送信を優先することができます。アクションが一時停止されると、残りの有効なジョブに集中するように優先順位が変更されます。アクションをキャンセルすることもできます。
  • 重複する見込み客の検索
    Optimizerで重複する見込み客レコードをマージすることで、Account Engagementビジネス ユニットのデータをクリーンかつ正確に保ちます。

Account Engagement Optimizer の使用に関する考慮事項

Optimizer を使用するときは、次の考慮事項を念頭に置いてください。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション
  • Optimizerは、Account Engagementビジネスユニットの全般的な健全性とパフォーマンスを維持するのに役立ちますが、包括的なツールではありません。Optimizer で監視されていない何かで問題が発生する可能性があります。
  • Optimizerにアクセスするには、ユーザーにAccount Engagementの「View Optimizer」ユーザー権限が必要です。カスタムユーザーロールの場合、Optimizer で報告される機能を管理するには、「Optimizer を表示」、「View Pending Table Actions (保留中のテーブルアクションを表示)」、「Delete Automation Rules (オートメーションルールを削除)」、および「Delete List (リストを削除)」ユーザー権限が必要です。
  • 推奨される変更を行った場合、Optimizer で [Performance Improvement Measures (パフォーマンス改善基準)] テーブルが更新されるまで最大 24 時間かかる場合があります。[Configuration Issues (設定の問題)] テーブルは約 2 時間で更新されます。

ダイナミックリストをスタティックに変換

ダイナミックリストは更新のたびにシステム帯域幅を必要とします。維持する必要があるダイナミックリストのうち自動的に更新する必要がないダイナミックリストを保持するには、そのダイナミックリストをスタティックに変換します。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション
必要なユーザー権限
ダイナミックリストを変換する Account Engagement Administrator ロール、または「Segment: Lists and Administration (セグメンテーション: リストおよび管理)」ユーザー権限を持つカスタム Account Engagement ロール
  1. [リスト] ページを開きます。
    • Account Engagementで、[Marketing | Segmentation | Lists]を選択します。
    • Lightning アプリケーションで、[見込み客]、[セグメンテーション | リスト] の順に選択します。
  2. スタティックリストに変換するリストを選択します。
  3. [ビュー] ドロップダウンメニューをクリックし、[無効なダイナミックリスト] または [使用されていないダイナミックリスト] を選択します。
  4. テーブルアクションドロップダウンメニューをクリックし、[Convert to static (スタティックに変換)] を選択します。
    スタティックに変換するためのオプションは、各ダイナミックリストのレコードホームのアクションメニューから使用することもできます。
  5. 確認ウィンドウで、[Yes, convert dynamic lists to static lists (はい、ダイナミックリストをスタティックリストに変換します)] を選択し、[変換] をクリックします。

ダイナミックリストをスタティックに変換したら、プロスペクトの追加と削除は手動で行う必要があります。リストはルール条件に基づいて更新されなくなります。

Account Engagement Optimizer について

Optimizer ページのテーブルではビジネスユニットの設定の問題とパフォーマンス改善基準が示されます。また、ビジネスユニットの稼働の効率を評価したり改善したりするのに役立つ他のツールにもアクセスできます。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション

メッセージ

通知バナーの [メッセージに移動] をクリックして、[メッセージ] セクションに緊急でないアラートと機能の推奨事項を表示します。

概要レベルの評価

Optimizer にアクセスすると、ビジネスユニットの健全性に関する概要レベルの評価が示されます。

  • 良好 — Optimizer で測定されているもので、対処する必要がある重大な問題や効率基準を示すものはありません。
  • 注意が必要 — ビジネスユニットの全体的なパフォーマンスを改善するためのいくつかのアクションを実行できます。
  • 対応が必要 — ビジネスユニットの重大な問題または基準が Optimizer により検出されました。これに対応して解決する必要があります。

Prospect Change Monitor by Feature (機能別のプロスペクト変化モニター)

円グラフには、過去 24 時間に見込み客レコードに最も多くの変更をもたらした自動化と機能が分類されます。

円グラフをクリックすると、[Prospect Change Monitor (プロスペクト変化モニター)] テーブルにドリルインしてアクセスできます。

Configuration Issues (設定の問題)

[Configuration Issues (設定の問題)] テーブルには、Account Engagement 機能へのフルアクセスを妨げている重要な設定の問題がリストされています。たとえば、検証済みのメール送信ドメインがない場合は、その問題を解決する手順がテーブルに表示されます。

Performance Improvement Measures (パフォーマンス改善基準)

[Performance Improvement Measures (パフォーマンス改善基準)] テーブルには、ビジネスユニットの効率を改善するための推奨事項が表示されます。たとえば、大量のオートメーションルールとダイナミックリストがある場合は、メンテナンスに関する提案と、ビジネスユニットのルールとリストを確認するリンクが Optimizer によって提供されます (1)。また、どの基準が良好な状態であるかも Optimizer によって示されるため、何が適切に機能しているかを知ることができます (2)。十分なデータがある場合は、クリック可能な履歴アイコンで基準の経時的な変化が示されます (3)。

メンテナンスリソース

ビジネスユニットでの処理を管理するのに役立つリソースとツールを使用します。テーブルアクションマネージャーを使用して、現在処理中のアクションを一時停止して再開することで帯域幅を解放します。

Account Engagement でプロスペクトの変化をもたらした機能を監視

ビジネスユニットのプロスペクトに最も多くの変化をもたらした機能とオートメーションを理解します。この情報を使用して、オートメーション、インポートの習慣、API インテグレーションなどを調整することができます。

Account Engagement での進行中のアクションの一時停止または再開

既存のプロスペクトの照合

CRM ID とメールアドレスのどちらで照合するかは、状況によって異なります。

プロスペクトのインポート

プロスペクトのインポートには、レコードの作成と既存のレコードの更新という 2 つの目的があります。プロスペクトのインポート時の一致条件として CRM ID (リード ID、取引先責任者 ID、個人取引先 ID) を必要に応じて使用できるようになりました。CRM ID でのインポートは、新規プロスペクトが作成時に Salesforce に関連付けられるため、Salesforce から新規レコードをインポートするときに最適です。

インポートの際に、可能な限り CRM ID を使用することをお勧めしますが、引き続きメールアドレスをプロスペクトのインポートの一致条件として使用することもできます。メールアドレスが一致する既存のプロスペクトがないレコードでは、プロスペクトレコードが作成されます。メールアドレスが複数の既存のプロスペクトに一致するレコードでは、最新のアクティビティがあるプロスペクトが更新されます。

Salesforce コネクタ

Salesforce の同期で最も重要なことは、プロスペクトと Salesforce のリード、取引先責任者、個人取引先の関係を 1 対 1 に対応付けることです。Salesforce コネクタでは、双方向の同期の一致条件に CRM ID を使用します。

SalesforceからAccount Engagementへの同期 — Salesforceが特定のメールアドレスでレコードを作成し、コネクタユーザーにそのレコードを参照する権限がある場合、Account Engagementは一致するCRM IDを使用して見込み客を作成します。

Account EngagementからSalesforceへの同期 — 新しい見込み客が作成され、レコードが同期を開始する条件に一致すると、コネクタの設定に従ってSalesforceにレコードが作成されます。

コネクタ設定 — コネクタ設定項目の数が少なくなります。コネクタは、新しいリード、取引先責任者、個人取引先を見つけると、プロスペクトを作成し、また、これらのレコード間の変更を同期します。コネクタは Salesforce でマージされたレコードや削除されたレコードを検出すると、該当するプロスペクトを更新します。

フォームの登録

誰かがフォームを送信すると、Account Engagement は訪問者の Cookie を使用して、活動を見込み客に関連付けようとします。ビジターのクッキーがプロスペクトと関連付けられれば、そのアクティビティは該当するプロスペクトのレコードに保存されます。そのプロスペクトのレコードがごみ箱にある場合は、復元されます。

訪問者の cookie が見込み客に関連付けられていない場合、Account Engagement はフォームで送信されたメールアドレスを使用して一致する見込み客を検索します。そのメールアドレスを使用しているプロスペクトが 1 人しかいなければ、そのプロスペクトのレコードにアクティビティが保存されます。そのメールアドレスを使用しているプロスペクトが複数いる場合、最新のアクティビティのあるプロスペクトのレコードにアクティビティが保存されます。そのメールアドレスを使用しているアクティブなプロスペクトが存在しない場合、ごみ箱内のレコードとの照合が試みられ、見つかったときにはそのレコードが復元されます。指定されたメールアドレスのプロスペクトが見つからなければ、プロスペクトが作成され、その新しいレコードにアクティビティが保存されます。

このすべての場合において、プロスペクトのレコードに合わせてビジターのクッキーが更新されます。そのクッキーに関連するその後のアクティビティは、関連付けられたプロスペクトレコードに保存されます。

サードパーティのコネクタ

一部のサードパーティコネクタは、そのメールアドレスを使用して、サードパーティのデータをAccount Engagementに同期します。これらのコネクタからデータを取り込むと、メールアドレスが同一の一致するプロスペクトが検索されます。

そのメールアドレスを使用しているプロスペクトが 1 人しかいなければ、そのプロスペクトのレコードにアクティビティが保存されます。そのメールアドレスを使用しているプロスペクトが複数いる場合、最新のアクティビティのあるプロスペクトのレコードにアクティビティが保存されます。そのメールアドレスを使用しているアクティブなプロスペクトが存在しない場合、ごみ箱内のレコードとの照合が試みられ、見つかったときにはそのレコードが復元されます。指定されたメールアドレスのプロスペクトが見つからなければ、プロスペクトが作成され、その新しいレコードにアクティビティが保存されます。

メールの送信

送信レピュテーションを守るために、同じメールアドレスを使用している複数のプロスペクトに同じリストメールが送信されることはありません。組み込まれた保護機能はありますが、リストを適切にセグメント化することをお勧めします。

リストメールを送信すると、Account EngagementはEメールアドレスで重複排除を行います。リスト送信内に同じメールアドレスを使用しているプロスペクトが複数いる場合、最新のアクティビティがあるプロスペクトにメールが送信されます。リスト送信内に同じメールアドレスを使用しているプロスペクトが複数いるが、アクティビティがない場合、最後に作成されたプロスペクトにメールが送信されます。

除外リストは、メールアドレスではなくプロスペクト ID に基づいて照合されます。同じメールアドレスのプロスペクトが複数あり、その 1 つが除外リストにあっても、そのメールアドレスは除外されません。

ただし、最新性と頻度に基づく動的除外リストは、メールアドレスに基づいて照合されます。あるメールアドレスの 1 人のプロスペクトが、間隔と頻度の除外リストの条件を満たしている場合は、同じメールアドレスを持つすべてのプロスペクトが除外されます。

メールの到達性

希望する受信者にのみメールが配信され、ブランドとメール送信レピュテーションが守られます。1 人のプロスペクトがグローバルにオプトアウトすると、同じメールアドレスを持つすべてのプロスペクトもオプトアウトされます。1 人のプロスペクトが特定のメールリストから登録解除すると、同じメールアドレスを持つすべてのプロスペクトがそのリストから登録解除されます。これにより、目的の受信者が他のプロスペクトである場合でも、メールがスパムとして認識されるリスクを回避できます。

1 人のプロスペクトでハードバウンスが発生するか、ソフトバウンスが 5 回発生すると、同じメールアドレスを持つ他のプロスペクトもメール不可として認識されます。

リードナーチャリング

Engagement プログラムでは、プログラムごとに、1 つのメールアドレスに対して作成できるプロスペクトは 1 人です。この制限により、複数のプロスペクトに関連付けられているメールアドレスに同じメールが複数回送信されることがなくなります。

Engagement Studio プログラムの見込み客にメールアドレスが使用されている場合、そのメールアドレスはその見込み客に関連付けられており、他の見込み客が使用することはできません。Engagement Studio プログラムを完了した見込み客のメールアドレスが変更されると、その見込み客に関連付けられている元のメールアドレスを別の見込み客が使用できなくなります。

プロスペクトのトラッキング

複数のプロスペクトが同じメールアドレスを使用し、その一部のプロスペクトがアーカイブされている場合、アーカイブされたプロスペクトでは [オプトアウト] 項目と [メール送信除外] 項目のみが更新されます。アーカイブされたプロスペクトでその他のアクティビティは更新されません。

Account Engagement API

この機能では、異なるバージョンの Account Engagement API が使用されます。新旧の API は類似していますが、新しい API ではプロスペクトに関連する多くの機能で複数の結果を返せるようになっています。カスタムインテグレーションを使用する場合、この機能を有効にする前に、バージョン 4 の API を使用していることを確認してください。サポートされているコネクタはすでにバージョン 4 と互換性があるため、これ以上の操作は必要ありません。

  • カスタムアプリケーションを使用している場合は、バージョン 4 の API を使用するように更新してください。
  • サードパーティ (Zapier や DataHero など) によって作成されたアプリケーションを使用している場合、バージョン 4 の API と互換性があることを確認してください。

データベースの上限

メール送信可能な見込み客がデータベース制限にどのように反映されるかについて説明します。

メモ プロスペクトは、個人に関連付けられたビジネスレコードの取引先責任者と定義されます。見込み客をメール送信可能として数えるには、すべてのマーケティングメールと運用メールの対象である必要があります。「Prospect Mailability Status」を参照してください。

郵送可能な見込み客の制限は、ビジネスユニット間で共有されます。たとえば、メール送信可能な見込み客が 10,000 人、2 つのビジネスユニット (A と B) に制限されています。ビジネスユニット A に 5,000 件のメール送信可能な見込み客、ビジネスユニット B に 7,000 件のメール送信可能な見込み客がある場合、契約制限を 2,000 件超過しました。

制限とデータベースの使用量を確認するには、アカウント設定に移動し、[Usage and Limits (使用量と制限)] タブをクリックします。1 つのビジネスユニットのデータベース制限に近づくと、アプリケーション内メッセージが表示されます。また、更新通知、使用制限、データベースサイズに関する連絡先と、最近ログインした見込み客のインポート権限を持つユーザーにもメール通知が送信されます。

データベースの規模が大きくなるにつれて、制限を増やすか、データベースをクリーンアップできます。データベースを拡張するには、アカウントエグゼクティブにお問い合わせください。

メールの開封数とメール本文内の登録解除リンクのクリック数は絞り込まれません。

  • ビジターフィルターの作成
    管理者は、IP アドレスまたはホスト名に基づいてビジターフィルターを作成できます。
  • ビジターフィルターの削除
    管理者は、ビジターフィルターを削除できます。ビジターフィルターを削除すると、その変更はすぐに有効になり、フィルターは復元できません。
  • 絞り込んだアクティビティの表示
    システム管理者は、Account Engagementで絞り込まれた活動を表示できます。
