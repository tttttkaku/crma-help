Account Engagement と Marketing Cloud Next 間のメール同意の自動照合

Account EngagementとMarketing Cloud Next間でメールの同意を自動的に調整するには、Account Engagementビジネスユニットで同意照合を有効にします。各見込み客の [オプトアウト] 項目に基づいて、特定のリストまたはすべてのメールの同意を照合できます。

必要なエディション

使用可能なエディション: Account Engagement Growth Edition、Plus Edition、Advanced Edition、Premium Edition、および Data 360 Edition または Marketing Cloud Next Edition が付属する Salesforce Enterprise Edition および Unlimited Edition。
必要なユーザー権限
同意照合を有効にする
  • Marketing Cloud Account Engagement 管理者ロールまたはカスタム Account Engagement ロール。「Manage Email Consent Matching」>「View and Edit」ユーザー権限があります。
  • 「すべてのデータの編集」権限セットまたは
  • 「Marketing Cloud 管理者」権限セット

開始する前に、 Marketing Cloud Next と Data 360 を設定します。

  • Account Engagement と Marketing Cloud Next 間の同意と登録の手動一致
    Marketing Cloud Next同意管理はData 360により提供されるため、登録を使用して複数のマーケティング チャネルを管理できます。デフォルトでは、同意はAccount EngagementとMarketing Cloud Next間で共有されません。Marketing Cloud Nextで見込み客の同意設定を使用するには、Account EngagementまたはAPIからその同意設定をエクスポートし、一度に1つずつサブスクリプションとしてMarketing Cloud Nextにインポートします。結果の出力ファイルには、Marketing Cloud Next の対応する登録が必要な見込み客が含まれます。最初に小規模なシンプルなサブスクリプションを使用することをお勧めします。

同意照合のしくみ

同意の一致により、メールアドレスを共有するレコードのAccount EngagementとMarketing Cloud Next間でメールの同意が保持されます。見込み客が作成、新しいメールアドレスで更新、リストに追加、またはごみ箱から復元されるたびに、Account Engagementは同意ステータスをMarketing Cloud Nextと再同期します。ビジネスユニット間で照合できます。複数のビジネスユニットはサポートされていません。

同意は、[公開リスト] と [除外項目] の 2 つの一致種別のいずれかに基づいて照合できます。

公開リストは、[公開リスト] オプションが有効になっている静的リストです。つまり、メールプリファレンスセンターで使用できます。同意照合の場合、公開リスト オプションでは静的公開リストを Marketing Cloud Next の新しいコミュニケーション登録と照合しますが、引き続き [オプトアウト] フィールドが考慮されます。

公開リストがない場合は、全体的なグローバルメール同意のみを制御する [除外] 項目オプションを使用できます。

どちらの一致種別でも、同意の更新は双方向に行われます。ただし、これはそれぞれで少し異なります。一致種別の概要と同意更新の処理方法を次に示します。

一致種別 説明 仕組み
公開リスト

Account Engagement で選択した静的公開リストを Marketing Cloud Next の新しい一意のコミュニケーション登録と照合します。

この一致タイプは、Account Engagement で公開リストを使用する場合に最適です。

  • 更新はリストまたは登録レベルで行うことができます。見込み客が 1 つのプラットフォームで特定のリストまたはメール登録をオプトインまたはオプトアウトした場合、対応するリストまたはメール登録の状況も更新されます。
  • Account Engagement のグローバルメール同意は引き続き重要です。見込み客が Account Engagement のすべてのメールをオプトアウトすると、Marketing Cloud Next はこれを「すべて登録解除」アクションとして処理し、すべてのメール登録からオプトアウトします。
  • Marketing Cloud Next の登録は、 のリスト同意とグローバル同意の両方に影響します 。見込み客が以前にAccount Engagementのすべてのメールをオプトアウトした後、Marketing Cloud Nextでメール登録にオプトインした場合、その見込み客はAccount Engagementの対応する公開リストとグローバル メールの両方にオプトインし直されます。
除外項目

Marketing Cloud Next で [B2B Email Consent (B2B メール同意)] という 1 つのグローバルメール登録を作成します。

このオプションは、Account Engagement に公開リストがない場合にのみ使用します。
  • 1 つの登録を使用して同意を追跡します。このオプションでは、個々のリストを一意の登録と照合する代わりに、見込み客がすべてのメールをオプトインしたかオプトアウトしたかを追跡する 1 つのメール登録が作成されます。Marketing Cloud Next の B2B メール同意登録の更新は、Account Engagement の [オプトアウト] 項目に影響します。その逆も同様です。
  • オプトアウトとは、[すべて登録解除] という意味ではありません。同意は1つの登録で追跡されるため、見込み客がAccount Engagementのすべてのメールをオプトアウトした場合、Marketing Cloud Nextの[すべて登録解除]アクションとして適用されません。代わりに、メールは B2B メール同意登録からオプトアウトされます。
  • 新しい見込み客の処理は異なります。見込み客が Salesforce コネクタを使用して作成されている場合、その状況はアカウントの標準の [同期動作] ルールと 2 つのシステム間の最新の同意タイムスタンプを組み合わせて計算されます。見込み客が Account Engagement で (フォームやインポート、API、手動などで) 作成された場合、Account Engagement の状況によっていずれかのシステムのメールアドレスの既存の同意履歴が上書きされます。

同意照合に関するその他の考慮事項

Account EngagementとMarketing Cloud Nextの間で同意照合を有効にする準備をするときは、次の考慮事項に留意してください。

  • Account Engagement のデフォルトの [Do Not Email (メール送信拒否)] 項目は同意を追跡しません。この項目を使用して、エンゲージしていない見込み客にメールを送信しないようにします。
  • 見込み客をAccount Engagementのごみ箱に移動したり、ごみ箱から見込み客を完全に削除したりしても、Marketing Cloud Nextのメール同意状況は削除または更新されません。
  • 公開リストに基づいて同意を照合するには、Account Engagementビジネスユニットの有効なオプトアウト済み見込み客が25万人未満である必要があります。制限を超えた場合は、ごみ箱を使用して見込み客の数を減らすか、代わりに [除外] 一致種別を使用できます。
  • 公開リストをごみ箱に移動すると、同意の照合が続行され、Optimizer に設定の問題が表示されます。
  • [オプトアウト] 一致種別を使用する場合、Account Engagement の [Opted Out (オプトアウト)] というデフォルトの見込み客項目の同期動作は、[最後に更新された項目値を使用]、[Account Engagement の値を使用] のいずれかに設定されるか、Salesforce に対応付けられていない必要があります。

同意照合の開始

2 つのアプリケーションで同意データの照合を開始する準備ができたら、[Account Engagement 設定] でこの機能を有効にします。

  1. Lightning アプリケーションで、[Account Engagement Settings] を選択し、[Email Consent Matching] を選択します。
  2. [メール同意照合の設定] ページで、[使用開始] をクリックして [編集] ページを開きます。
  3. [Match Type (一致種別)] で、[Opted Out Field (除外項目)] または [Public List (公開リスト)] を選択します。
  4. [公開リスト] を選択した場合は、コミュニケーション登録を設定します。
    1. 照合する最大 100 件の公開リストを選択します。
    2. リストごとに、Marketing Cloud Next で作成するコミュニケーション登録の一意の名前を入力します。公開リストを既存の登録に対応付けることはできません。
  5. 選択内容を確認し、同意照合のしくみを理解していることを確認して、[同意を照合] をクリックします。

更新が処理されるまで最大 48 時間かかることがありますが、最初のコピーの進行状況が状況項目に表示されます。プロセスが完了するまで、新しい同意レコードを Marketing Cloud Next にインポートしないでください。照合が完了すると、状況は [有効] になり、プロセスを開始したユーザーにメールが送信されます。

同意照合の管理

[メール同意の一致] ページで、各公開リストの同意の一致状況を確認します。有効な同意照合のリストはいつでも追加または削除できます。すべてのリストの同意の照合を停止すると、同意データは引き続き使用可能ですが、Account EngagementとMarketing Cloud Nextの間で一致しなくなります。Marketing Cloud Next では、登録ごとに 1 つの一意の名前のみがサポートされます。同意照合を再開するには、まず Marketing Cloud Next で影響を受ける登録の名前を削除または変更します。

タスク ステップ
新しいリストの照合を開始 [メール同意の一致] ページで、[新規] を選択します。リストを選択して [次へ] をクリックし、登録名を入力して、[同意を照合] をクリックします。
1 つのリストの一致を停止する [Email Consent Matching (メール同意照合)] ページで、使用するリストの横にある [Settings (設定)] ドロップダウンをクリックし、[Stop Matching (一致を停止)] を選択します。1 つのリストのみが同意をアクティブに照合している場合は、代わりに [一致を停止] ボタンを使用します。
すべてのリストの照合を停止 [メール同意の一致] ページのページヘッダーで、[一致を停止] をクリックします。確認ウィンドウを確認し、[停止] をクリックします。

Account Engagement と Marketing Cloud Next 間の同意と登録の手動一致

Marketing Cloud Next同意管理はData 360により提供されるため、登録を使用して複数のマーケティング チャネルを管理できます。デフォルトでは、同意はAccount EngagementとMarketing Cloud Next間で共有されません。Marketing Cloud Nextで見込み客の同意設定を使用するには、Account EngagementまたはAPIからその同意設定をエクスポートし、一度に1つずつサブスクリプションとしてMarketing Cloud Nextにインポートします。結果の出力ファイルには、Marketing Cloud Next の対応する登録が必要な見込み客が含まれます。最初に小規模なシンプルなサブスクリプションを使用することをお勧めします。

必要なエディション

メモ 製品間の全体的なメール同意を自動的に照合するには、Account Engagement ビジネスユニットで同意照合ツールを有効にします。同意の一致では、Marketing Cloud Next のサブスクリプションレベルの同意はサポートされません。
使用可能なエディション: Account Engagement Growth Edition、Plus Edition、Advanced Edition、Premium Edition、および Data 360 Edition または Marketing Cloud Next Edition が付属する Salesforce Enterprise Edition および Unlimited Edition。

同意に関する考慮事項

Marketing Cloud NextでAccount Engagementの同意と登録設定を使用する準備をするときは、次の考慮事項に留意してください。

  • オプトアウト要求を見逃すリスクを最小限に抑えるには、Account EngagementまたはMarketing Cloud Nextのいずれか内のサブスクリプションにマーケティングし、両方にはマーケティングしません。登録は 1 つのシステムにのみ存在しますが、コンプライアンスを確保するために、顧客はシステム間のすべてのマーケティングをオプトアウトできます。
  • Account Engagementからのエクスポートには、Account Engagement登録および設定のオプトインおよびオプトアウト同意信号を登録の1つの同意信号に変換することが含まれます。同意が開始された日付の選択も含まれます。同意した日付は、レコードがシステムにインポートされるため、Account Engagement から取得されません。そのため、同意が開始された日付が [最終更新日] として最適になるように選択します。
  • Marketing Cloud 次に、同意はサブスクリプション設定を介してのみ管理されます。Account Engagementでは、ユーザーがEメールでオプトアウトすると、すべてのEメールコミュニケーションからオプトアウトされます。ただし、ユーザーが設定レベルでオプトアウトした場合、登録メールは次のようにオプトアウトされます。
    • メールがオプトインされていても登録がオプトインされていない場合、そのユーザーはMarketing Cloud Nextにインポートされた登録にオプトインされません。
    • メールがオプトアウトされていても、ユーザーが登録にオプトインしている場合、そのユーザーはMarketing Cloud Nextにインポートされた登録にオプトインされません。

Marketing Cloud Next の同意についての詳細は、「Marketing Cloud Next の同意の概念について」を参照してください。

Account Engagement アプリケーションを使用した登録設定のエクスポート

Marketing Cloud Next にインポートする Account Engagement 登録の設定リストをエクスポートします。

  1. Account Engagement で、[プロスペクト | セグメンテーション | セグメンテーションリスト ] に移動します。
  2. Marketing Cloud Next にインポートする公開設定セグメンテーションリストを選択します。
  3. [ツール] ドロップダウンから [CSV ファイルとしてエクスポート] を選択します。
    式出力が推奨されます。
  4. Marketing Cloud Next のインポート形式に準拠するように CSV 出力ファイルを変更します。
    1. 2 つの個別の CSV ファイルを作成します。1 つは "opt in" 用で、もう 1 つは "opt out." 用です。
    2. [メール] と [更新] 以外のすべての列を削除して、CSV 出力ファイルを編集します。「オプトアウト」および「メール送信しない」エントリを除外します。

    詳細は、「マーケティング同意インポートファイルの形式設定」を参照してください。

REST API を使用した登録設定のエクスポート

開発者は、UI からエクスポートする代わりに、Account Engagement API を使用して設定リストのメンバーをエクスポートできます。

このプロセスにはリストメンバーシップエンドポイントを使用します。「リストメンバーシップオブジェクト」 を参照してください。

  1. 設定リスト ID を使用してリストメンバーシップエンドポイントを照会し、次の項目を要求します。
    • prospect.email
    • prospect.optedOut
    • list.name
    • optedOut
    • isDeleted
    • updatedAt
    • updatedBy.name
  2. Marketing Cloud Next で登録に必要な条件でリストを絞り込みます。
    たとえば、If (optedOut = FALSE & prospect.optedOut = FALSE & isDeleted = FALSE) の場合、リスト メンバーは同じ Marketing Cloud Next サブスクリプションにオプトインしてインポートしても安全であると結論付けることができます。条件によって、プロスペクトのメールがオプトインされていること、プロスペクトがリストからオプトアウトされていないこと、値が最新であることが確認されます。

スコアリング

Marketing Cloud Nextには、追跡されたエンゲージメントに基づいてリードの関心を定量化するデフォルトのスコアカードが用意されています。スコアリングは、Data 360 の計算済みインサイトを使用して実装されます。スコアは、リード、取引先責任者、および取引先レコードに表示されます。

リードと取引先責任者は、マーケティング活動にどの程度エンゲージしているかと、理想的な顧客にどの程度類似しているかに基づいてスコアリングされます。デフォルトのスコアリングルールをカスタマイズし、エンゲージメントスコアと適合スコアをリードまたは取引先責任者の全体的なマーケティングスコアにどのように組み込むかを決定できます。エンゲージメントスコア、適合スコア、全体的なマーケティングスコアを使用して、セグメントを作成し、対象を絞ったコンテンツを作成できます。

テストするときは、スコアリングに時間がかかることがあります。一度に複数のシナリオを検証することをお勧めします。

5. 同意の調整

Account Engagement+を使用して初めてメッセージを送信するときに、マーケティングアプリケーションで元のAccount Engagementツールと次世代のツールセットのいずれかを選択できます。この 2 つのシステムは同意の管理方法が異なるため、一致させる必要があります。これは実装の一部として有効にできます。

B2B メール同意登録は同意データの統合コンテナであり、すべての登録の [見込み客のメールオプトアウト] 状況が保存されます。時間が経つにつれて、いずれかのアプリケーションで同意状況が変更されると、Data 360 は最新のデータを評価して保存します。

進行状況はデータエクスプローラーで監視できます。データエクスプローラーには一度に最大 100 件のレコードが表示されます。可視性を高めるために、管理者は Data Cloud Query API を使用できます。

  • マーケティングキャンペーンに関連付けられていたプロスペクト数を確認できます。
  • ランディングページを作成します。ランディングページを作成してキャンペーンに関連付けると、そのキャンペーンに固有のトラッキングコードが含まれます。

  • Salesforce の [リードソース] 項目を更新します。
