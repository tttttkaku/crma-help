フォーム登録とコンバージョンの違い

フォーム登録は、ビジターまたはプロスペクトがフォームに情報を入力して送信をクリックしたときに実行されます。コンバージョンとは、匿名ビジターがメールアドレスを提供してプロスペクトに変わる、特殊なタイプの登録のことです。

フォームとフォームハンドラーのレポートを参照するときには、総登録数にコンバージョンが含まれていることに注意してください。

[フォームハンドラーの統計情報] テーブルのコンバージョン指標は、個々のレポートページの表示内容よりも高くなることがあります。テーブルのコンバージョン指標には、登録後にアーカイブまたは削除されたプロスペクトが含まれていますが、レポートページの値は有効なプロスペクトのみに基づいています。

レイアウトテンプレートを使用するフォームの送信ボタン画像の変更

フォームおよびランディングページでカスタムレイアウトテンプレートを使用する場合、送信ボタンの画像を挿入できます。カスタム CSS を埋め込むフォームまたはランディングページに関連付けられたレイアウトテンプレートにカスタム CSS を追加します。

必要なエディション

必要なユーザー権限
フォームを編集する Account Engagement の管理者ロールまたはマーケティングロール
  1. [フォーム] ページを開きます。
    • Account Engagementで、[Marketing | Forms | Forms]を選択します。
    • Lightning アプリケーションで、 [ コンテン | ツフォーム]を選択します。
  2. 編集するフォームを開き、[フォームを編集] をクリックします。
  3. [デザイン] タブで、[送信ボタン] 項目のテキストを削除します。
    画像の上にテキストを表示するには、項目内のテキストをそのままにするか編集します。
  4. フォームを保存します。
  5. フォームまたはランディングページに関連付けられたレイアウトテンプレートを開いて編集します。
  6. [レイアウト] タブで、次のコードを <head> タグ内に貼り付けます。 
    <style type="text/css">
  form.form p.submit input {
  margin: 0;
  padding: 0;
  text-align: right;
  border: none;
  background: url(https://www.example.com/example.gif) no-repeat left top;
  width:100px;
  height:100px;
  cursor: pointer; }
</style>
  7. サンプルの URL を、使用する画像の URL に置き換えます。
  8. 幅と高さの属性を編集し、画像のサイズに合わせます。
  9. レイアウトテンプレートを保存します。

ストックテンプレートを使用するランディングページフォームの送信ボタン画像の変更

ストックテンプレートを使用する従来のランディングページでマーケティングフォームを使用する場合、送信ボタンを画像に変更できます。画像ベースのボタンは [私のレイアウトテンプレート] セクションのテンプレートでは使用できません。

必要なエディション

必要なユーザー権限
ランディングページを編集する Account Engagement の管理者ロールまたはマーケティングロール
  1. [ランディングページ] ページを開きます。
    • Account Engagementで、[Marketing | Landing Pages | Landing Pages]を選択します。
    • Lightning アプリケーションで、[コンテンツ]、[ランディングページ] の順に選択します。
  2. 編集するランディングページを開き、[ランディングページを編集] をクリックします。
    [コンテンツレイアウト] セクションで [ストックテンプレート] が選択されていることを確認します。
  3. [ランディングページコンテンツ] タブをクリックします。
  4. [送信] ボタンをダブルクリックします。
  5. [ファイル] から画像を選択するか、画像の URL を入力します。
    メモ 画像ボタンは、元の画像ファイルと同じサイズです。画像ファイルを追加する前にサイズ変更します。
  6. ランディングページを保存します。

フォームの統計表の総計値

[フォーム統計] テーブルには、Account Engagement で作成するホストされるフォームの概要レベルの統計が表示されます。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション

レポートにアクセスするには、[Reports (Lightning アプリケーションでは Account Engagement Reports)]、[Marketing Assets | Forms] の順に選択します。

メモ

フォームが Account Engagement ランディングページにある場合、送信、クリック、エラー、およびその他の総計値がランディングページレポートに表示されます。総計値はフォームレポートには表示されません。

総計値 定義
総ビュー数 フォームが参照された回数の合計数。同一ビジターによる複数の参照が含まれます。
総登録数 フォームが正しく登録された合計数。
登録率 フォーム登録につながった参照の割合。
総エラー数 フォームエラーのために登録が妨げられた合計数。
エラー率 エラーにつながった参照の割合。

フォームのテスト

ホストされたフォームをテストするには、ホストされたフォームをブラウザーで開き、プロスペクトと同様にフォームに入力します。フォームをテストするときは、次の考慮事項を念頭に置いてください。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション
  • フォームがキオスクモードであるか、送信後に常に表示されるように設定されていない限り、Account Engagement は 30 分ごとに重複する見込み客の活動をレコードに記録します。登録はすべて承諾され、完了アクションが登録ごとに実行されます。テスト中にフォームを複数回登録する場合は、プロスペクト監査を確認して、フォームが想定どおりに動作していることを確認します。登録はすべてプロスペクト監査に表示されますが、プロスペクトのアクティビティには、30 分ごとに 1 つの登録のみが表示されます。
  • フォームを再テストするには、ブラウザーのクッキーをクリアしてから、別のメールアドレスを使用して必要事項を入力し、別のプロスペクトレコードを作成します。クッキーをクリアしない場合、または新しいメールアドレスを使用しない場合、フォームの登録は前のテストで作成されたプロスペクトのものとして受け付けられます。
  • 登録の 10 分以内にフォームに戻ると、お礼メッセージが表示されるか、お礼ページにリダイレクトされます。フォームを再表示するには、ブラウザーのクッキーをクリアするか 10 分間待機します。
  • フォームに自動応答メールがある場合、フォームを短時間に繰り返し登録したとしても、そのたびに自動応答メールが送信されるわけではありません。デフォルトでは、プロスペクトが重複メールを受信しないように自動応答メールは制限されています。
  • [常に表示] を有効化せずにプログレッシブプロファイリングを含むフォームをテストするときは、フォームの登録後に 10 分間待機する必要があります。その 10 分の間にフォームを強制的に表示するには、「?PI_ALWAYS_DISPLAY=1」というパラメーターをフォームの URL の末尾に追加します。
  • フォームをテストするときは、[絞り込んだアクティビティを表示] がオンになっていることを確認してください。そうでないと、テストアクティビティが非表示になることがあります。オンにするには、フォームのプロスペクトのテーブルの上にある [ツール] ドロップダウンをクリックして、[絞り込んだアクティビティを表示] をクリックします。

フォーム登録時のメールアドレスの検証

プロスペクトが無効なメールアドレスでフォームを登録することを防止するため、フォームごとにメール検証を設定してください。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション
必要なユーザー権限
フォームを編集する Account Engagement の管理者ロールまたはマーケティングロール
  1. [フォーム] ページを開きます。
    • Account Engagementで、[Marketing | Forms | Forms]を選択します。
    • Lightning アプリケーションで、 [ コンテン | ツフォーム]を選択します。
  2. 編集するフォームを開き、[フォームを編集] をクリックします。
  3. メール項目の横にある鉛筆アイコンをクリックします。
  4. [データ形式] ドロップダウンから検証オプションを選択します。

    [有効なメールサーバーからのメール] の要件

    • 有効なメールアドレス構文
    • 実行中のドメイン名
    • DNS レコードに記載された受信用メールサーバー

    [ISP や無料のメールプロバイダー以外からのメール] の要件

    • 有効なメールアドレス構文
    • 実行中のドメイン名
    • DNS レコードに記載された受信用メールサーバー
    • 一般的な ISP (Comcast、Charter など) からではないこと
    • 無料のメールプロバイダー (Gmail、Hotmail など) からではないこと
  5. [詳細] タブをクリックし、プロスペクトのメールアドレスが有効でないときに表示する、詳細なエラーメッセージを入力します。
  6. 作業を保存します。

ユーザーが変更可能なランディングページコンテンツの制御

マーケティングコンテンツの特定の部分の編集を許可するには、コンテンツリージョンを使用して従来のレイアウトテンプレートの領域をロックします。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション

Pardot の名称が Marketing Cloud Account Engagement に変更されました。あらゆる場所の名称を一括変換できればよいのですがそうもいかないため、変更が完了するまでは以前の名称を目にすることがあるかもしれません (アプリケーション自体も含む)。

レイアウトテンプレートの各部分を編集可能にするには、pardot-region 属性を HTML 要素に追加して名前を付けます。構文が完全であることを確認して、リージョンをネストできない点に注意してください。ランディングページで使用されているリージョンの名前を変更すると、コンテンツが破損するおそれがあるため、変更しないようにしてください。

例 <p pardot-region="text_block2"> により、text_block2 という名前の p 要素と、それに含まれる要素が編集可能になります。

領域を編集するために使用できるエディタの種類を指定するには、要素にpardot-region-type="<type>"を追加します。

次の表に、サポートされているエディターと、コンテンツリージョンになる HTML タグを示します。

エディター HTML タグ

ランディングページ用レイアウトテンプレートの作成

従来のランディングページ環境で、ランディングページ、フォーム、サイトの検索結果を書式設定するレイアウトテンプレートを作成します。レイアウトテンプレートは、サーバーサイドスクリプト言語をサポートしていません。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション
必要なユーザー権限
従来のレイアウトテンプレートを作成する Account Engagement の管理者ロールまたはマーケティングロール
  1. [レイアウトテンプレート] ページを開きます。
    • Account Engagementで、[Marketing | Landing Pages | Layout Templates]を選択します。
    • Lightning アプリケーションで、[コンテンツ]、[レイアウトテンプレート] の順に選択します。
  2. [+ レイアウトテンプレートを追加] をクリックします。
  3. テンプレートに名前を付けます。
  4. 次のいずれかの方法で、スタイル設定を作成するかインポートします。
    • [レイアウト] タブで HTML と CSS を追加します。%%title%%、%%content%%、または %%description%% 変数タグはランディングページのコンテンツに入力されるため、削除しないでください。
    • [レイアウトをインポート] ドロップダウンから [元 URL] を選択し、Web サイトからスタイル設定をインポートします。URL を入力して、[今すぐインポート] をクリックします。%%title%%、%%content%%、および %%description%% 変数タグを追加する必要があります。
    • [レイアウトをインポート] ドロップダウンから反応型テンプレートを選択し、[今すぐインポート] をクリックします。テンプレートをインポートすると、[レイアウト] タブのすべてのコードが上書きされます。
  5. (省略可能) [フォーム] タブと [サイト検索] タブを編集します。多くの場合はデフォルトコードが最適です。
  6. レイアウトテンプレートを保存します。

レイアウトテンプレートを作成したら、それを使用してランディングページのスタイルを設定します。

レイアウトテンプレートを使用したランディングページの作成

レイアウトテンプレートを作成したら、それを使用して従来のランディング環境でランディングページのスタイルを設定できます。

必要なエディション

必要なユーザー権限
従来のランディングページを作成する Account Engagement の管理者ロールまたはマーケティングロール
  1. [ランディングページ] ページを開きます。
    • Account Engagementで、[Marketing | Landing Pages | Landing Pages]を選択します。
    • Lightning アプリケーションで、[コンテンツ]、[ランディングページ] の順に選択します。
  2. [+ ランディングページを追加] をクリックします。
  3. ステップ 1: 名前
    1. ランディングページの名前を付けます。
    2. タイトルを入力します。このタイトルは、ページの表示時にブラウザーのタイトルバーに表示されます。
    3. 説明を入力します。このコンテンツは、ランディングページの <meta> の説明の SEO で使用されます。
    4. キャンペーンを選択します。
    5. (省略可能)。ランディングページが検索エンジンの結果に表示されないようにするには、[検索エンジンのインデックス化から除外] を選択します。
    6. [次へ] をクリックします。
  4. ステップ 2: フォームを選択
    1. フォームオプションを選択します。
    2. (省略可能)。[フォームのお礼メッセージを表示する代わりにプロスペクトをリダイレクト] を選択し、リダイレクト URL を入力します。このオプションを使用すると、お礼メッセージが表示される代わりにプロスペクトがリダイレクトされます。
    3. [次へ] をクリックします。
  5. ステップ 3: コンテンツレイアウト
    1. レイアウトテンプレートを選択します。
    2. [次へ] をクリックします。
  6. ステップ 4: ランディングページコンテンツ
    1. エディターを使用してコンテンツを追加します。このコンテンツにより、レイアウトテンプレートに %%content%% タグが入力されます。
    2. 完了したら、[次へ] をクリックします。
  7. ランディングページを確認して保存します。

ランディングページのリンクは、リード画面で使用したり、[オンラインで表示] をクリックして使用したりできます。

ストックテンプレートを使用したランディングページの作成

書式設定済みストックテンプレートを使用して、従来のランディングページをすばやく作成します。

必要なエディション

必要なユーザー権限
従来のランディングページを作成する Account Engagement の管理者ロールまたはマーケティングロール
メモ
  • ランディングページに Account Engagement フォームを配置した場合、フォームのレイアウトテンプレートはランディングページに表示されません。代わりにレイアウトテンプレートを使用するか、フォームのレイアウト CSS をコピーして、[ページオプション] のスクリプトハンドラーに貼り付けます。
  • ストックテンプレートは、反応型テンプレートではありません。反応型テンプレートが必要な場合、代わりにレイアウトテンプレートまたは拡張ランディングページ環境を使用してください。
  1. [ランディングページ] ページを開きます。
    • Account Engagementで、[Marketing | Landing Pages | Landing Pages]を選択します。
    • Lightning アプリケーションで、[コンテンツ]、[ランディングページ] の順に選択します。
  2. [+ ランディングページを追加] をクリックします。
  3. ステップ 1: 名前
    1. ランディングページの名前を付けます。
    2. タイトルを入力します。このタイトルは、ページの表示時にブラウザーのタイトルバーに表示されます。

拡張ランディングページ環境の考慮事項

拡張ランディングページ環境を使用する前に、以下の考慮事項に留意してください。

必要なエディション

使用可能なエディション: すべての Account Engagement エディション

拡張ランディングページの設定

  • 拡張ランディングページビルダーは、拡張メールと同じ権限およびデジタルエクスペリエンスインテグレーションを使用します。拡張メール環境が設定されている場合、通常はユーザーがランディングページをすぐに開始できます。
  • ランディングページのレコードレイアウトへの更新は通常、自動的に表示されます。ただし、ランディングページの Lightning レコードページまたはページレイアウトがすでにカスタマイズされている場合、管理者が新しい項目とタブを手動で追加する必要があります。

レコードの作成

  • 拡張ランディングページを作成した場合は、接続済みのキャンペーンに関連付ける必要があります。
  • ランディングページのキャンペーンは、1 つのビジネスユニットに関連付ける必要があります。ランディングページを公開するには、ビジネスユニットの割り当てが必要です。複数のビジネスユニットがない場合は、[接続されているキャンペーン] 設定のみによってリレーションが定義されます。

    接続済みキャンペーンとビジネスユニットは、1 対 1 のリレーションを持ちます。このリレーションは、コネクタ設定で制御できます。ビジネスユニットを割り当てるには、レコードタイプ設定を定義してから同期を実行します。

  • [非公開時のリダイレクト URL] 項目など、ランディングページオブジェクトの項目またはタブが見つからない場合は、管理者に最新のリリース更新を確認するよう依頼してください。一部のコンポーネントは手動で追加する必要があります。

コンテンツの作成

  • デジタルエクスペリエンスアプリケーションの Salesforce CMS は、画像リポジトリとして使用できます。また、サードパーティでホストされている公開画像への絶対 URL を含めることもできます。Salesforce Files はサポートされていません。
  • ランディングページのコンテンツを作成すると、HTML 項目に保存されます。HTML 項目のサイズは 384 KB 以下にする必要があります。
  • 拡張ランディングページでは、JavaScript や SVG ファイルなどのアクティブコンテンツはサポートされていません。
  • ランディングページはモバイル対応です。横幅が 480 ピクセルより小さい画面では、ランディングページのデフォルトの横幅は 320 ピクセルです。

iframe の使用

  • HTML コンポーネントでは iframe がサポートされます。ビルダーのキャンバスやレコードホームには iframe コンテンツのプレースホルダーが表示されます。iframe は公開済みのランディングページにのみ表示されます。
  • ランディングページの公開時に iframe が反応するようにするには、埋め込みコードを確認します。
    • 埋め込みコードがすでに反応している場合: iframe タグに style 属性または width 属性がパーセント値で設定されていることを確認します。ビルダーでは埋め込みコードは変更されません。
    • 埋め込みコードが反応しない場合: iframe タグに width 属性と height 属性がピクセル値で設定され、style 属性が設定されていないことを確認します。埋め込みコードが表示されるときにビルダーによって変更が行われ、iframe が反応するようになります。

ランディングページの公開

  • ランディングページをオンラインで使用できるようにするには、公開する必要があります。公開済みのランディングページを編集すると、状況は [公開済み (変更あり)] に更新され、編集がオンラインに表示される前に再度公開する必要があります。
  • ランディングページレコードの公開リンクは、プライマリトラッカードメインを表示します。バニティ URL を入力することで、任意のカスタムトラッカードメインのパスを指定できます。
  • バニティ URL は一度に 1 つのランディングページで使用できます。バニティ URL を使用するランディングページレコードを削除すると、そのバニティ URL を別のレコードで再度使用することはできません。バニティ URL を再利用するには、ランディングページのレコードからクリアして変更を公開します。その後、バニティ URL を新しいレコードに追加できます。元のランディングページのレコードが不要になった場合は削除できます。
  • 拡張ランディングページを公開すると、Account Engagement に関連レコードが作成されます。このレコードは、エンゲージメントアクティビティを追跡して総計値を保存します。これらは、Salesforce のメインランディングページレコードに同期されます。
  • Salesforce の拡張ランディングページを非公開にすると、関連レコードが Account Engagement にアーカイブされます。ランディングページを再び公開すると、関連するレコードがアーカイブ解除され、以前の総計値が保持されます。

割り当て

  • ほとんどの Account Engagement エディションでは、一度に最大 1,000 個の拡張ランディングページがサポートされます。この数には、公開済みと未公開の拡張ランディングページが含まれます。従来のランディングページは無制限です。
  • Account Engagement Growth Edition では、従来のランディングページと公開済みの高度なランディングページを合わせて 50 個のランディングページがサポートされます。

ランディングページレコードには、バニティ URL と非公開時のリダイレクト URL、ヘッダーコードとフッターコードなどの情報が含まれています。ランディングページのフォーム、テキスト、および画像は、拡張ランディングページビルダー内で作成されます。

ランディングページを編集すると、コンテンツと設定は保存されますが、公開されません。その場合、状況が [公開済み (変更待機中)] として表示されます。待機中の変更を Web に転送するには、ランディングページを再公開します。

  1. 編集するランディングページレコードを開きます。
  2. レコード項目を編集するには、[編集] をクリックします。
    1. 変更を入力して保存します。
  3. ランディングページコンテンツを編集するには、[ビルダーで編集] をクリックします。
    1. ランディングページコンテンツを編集して、保存します。
  4. ヘッダーまたはフッターコードブロックを編集するには、ランディングページレコードの [設定] タブをクリックします。
    1. 任意のブロックで、[追加] または [編集] をクリックします。
    2. コードの変更を入力して保存します。
  5. 変更を公開するには、ランディングページレコードに戻り、[公開] をクリックします。

情報

  • ランディングページ名 — ランディングページのわかりやすい名前。この値は、ランディングページのビジターには表示されません。
  • キャンペーン — ランディングページに関連付けられているキャンペーンの名前。
  • コンテンツ — ランディングページの HTML。コンテンツ HTML ファイルはバックグラウンドで保存されますが、[コンテンツ] タブでランディングページのプレビューにアクセスできます。
  • 状況 — ランディングページの状況。使用可能な値は、[ドラフト]、[公開済み]、および [公開 (変更あり)] です。デフォルト値は [ドラフト] です。
  • 公開リンク — プライマリトラッカードメインに基づいてランディングページを使用できる公開 URL。ランディングページを初めて公開するまで、この公開は空白です。ランディングページが非公開になると、URL は削除されます。
  • コンテンツ最終保存 — ランディングページの最新の更新のタイムスタンプ。[ランディングページ名]、[キャンペーン]、[コンテンツ]、[ヘッダーコード]、[フッターコード]、[バニティ URL]、[検索エンジンのインデックス付け]、[非公開時のリダイレクト URL] 項目を変更すると、タイムスタンプが更新されます。
  • コンテンツ最終保存者 — ランディングページを最後に更新したユーザーの名前。[ランディングページ名]、[キャンペーン]、[コンテンツ]、[ヘッダーコード]、[フッターコード]、[バニティ URL]、[検索エンジンのインデックス付け]、[非公開時のリダイレクト URL] 項目を変更すると、タイムスタンプが更新されます。
  • 最終公開日 — ランディングページの最新の公開のタイムスタンプ。
  • 最終公開者 — ランディングページを最後に公開したユーザーのユーザー名。
  • 検索エンジンのインデックス化から除外 — ランディングページが公開検索の対象になるかどうかを示します。デフォルトでは、ランディングページは検索可能であるため、このボックスはオフになっています。
  • バニティ URL — トラッカードメインに追加する優先ランディングページ URL のパスの部分。[バニティ URL] 項目は完全な URL をサポートしていません。
  • 非公開時のリダイレクト URL — ランディングページが非公開のときに使用される URL。デフォルトでは、未公開のランディングページは [Account Engagement Settings (Account Engagement 設定)] の Web サイトにリダイレクトされます。閲覧者を別のサイトにリダイレクトするには、https:// で始まる完全な URL を入力します。

フォームスタイルは、背景、項目の表示ラベル、入力、チェックボックス、ラジオボタン、送信ボタンに適用できます。編集可能なスタイルは、要素種別によって異なります。スタイルは、選択したフォーム自体ではなく、フォームコンポーネントに適用されます。たとえば、フォーム A を追加してスタイルを適用し、それをフォーム B に置き換えた場合、追加したスタイルは引き続きコンポーネントに表示されます。

  2. フォームを追加します。
  3. フォームの編集ペインで、[スタイル] をクリックします。
  4. セクションを展開して、使用可能なスタイル設定をカスタマイズします。
  5. 完了したら、ページを保存します。

最も重要なことは、高度なランディングページビルダーでスタイルを編集する場合でも、Account Engagement フォームレコードに適用されるスタイルはフォームが表示されるすべての場所で使用されるということです。フォームにスタイルを適用する方法はいくつかあります。

  • [デザイン] セクションのフォームスタイルを使用する。
  • [フォーム上部] セクションでカスタムコードを適用する。
  • 拡張ランディングページビルダーのフォームコンポーネントで [スタイル] タブを使用する。

ユーザーが拡張ランディングページビルダーでフォームのスタイルを編集できるようにするには、フォームレコードの [スタイル] タブですべての項目に [デフォルト] が表示されていることを確認します (1)。[クリア] をクリックして、デフォルトのフォントの色に戻します (2)。

拡張ランディングページのブランド設定されたフォームで元のスタイルを保持するには、Account Engagement フォームレコードでカスタムスタイルを変更して、特定のスタイルの変更からフォームを保護します。

メモ フォームコンポーネントでスタイルを編集しようとしても変更が有効にならない場合は、既存のスタイルを確認してください。フォームレコードの [デザイン] セクションと [フォーム上部] ソースコードを開いて、変更を上書きしているスタイルがあるかどうかを確認します。

ボタン
ボタンのプロパティは、フォームの送信ボタンにのみ適用されます。
[角の半径] は、ボタンの角の丸みを制御します。

Lightning レコードページをカスタマイズする 「アプリケーションのカスタマイズ」
  1. 拡張ランディングページから、[設定] タブに移動します。
  2. [ヘッダーコード] または [フッターコード] ブロックで、[追加] をクリックします。
    これらのブロックの既存のコードを変更するには、[編集] をクリックします。
  3. 追加するコードを入力して保存します。
    ヘッダーおよびフッターのコードブロックでは、script、style、link、noscript、および comment タグ (<!-–hidden text--> など) がサポートされます。
  4. エラーがあれば確認して解決します。
  5. ランディングページを公開するには、[公開] をクリックします。
メモ [設定] タブが見つからない場合、管理者が Lightning アプリケーションビルダーを使用して [ヘッダーコード] 項目と [フッターコード] 項目を追加できます。項目を追加するには、ランディングページ Lightning レコードページを開き、タブを作成して「設定」という名前を付けます。次に、[ランディングページ - ヘッダー & フッター] コンポーネントをドラッグします。ページを保存して、ユーザーに対して有効化します。
