Salesforce から Oracle CPQ Cloud への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Oracle CPQ Cloud (旧 BigMachines) にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Oracle CPQ Cloud は統合 SSO で SAML プロトコルをサポートしています。Oracle CPQ Cloud をサービスプロバイダーとして設定し、接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Oracle CPQ Cloud にアクセスできます。SSO を有効にして ACS URL を取得するには、Oracle CPQ Cloud の担当者にお問い合わせください。

Salesforce から Oracle CPQ Cloud への SSO を設定するには、次の概要手順に従います。この手順を完了するには、SAML が有効化された Oracle CPQ Cloud の管理アカウントが必要です。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Oracle CPQ Cloud での SAML の設定

  1. Oracle CPQ Cloud アカウントに管理者としてログインします。
  2. [User and Company Administration (ユーザーと会社の管理)] で [Admin (管理)] を選択します。[Single Sign-On Setup (シングルサインオンの設定)] に移動します。
  3. SAML SSO 設定を定義します。
    • [Single Sign-On Method (シングルサインオンメソッド)] で [Federated Authentication (統合認証)] を選択します。
    • [Issuer URL (発行者 URL)] に「https://customername.bigmachines.com」と入力します。customername は、Oracle CPQ Cloud での一意の名前です。
    • [Identity Provider Certificate (ID プロバイダー証明書)] に、先ほどダウンロードした Salesforce 証明書をアップロードします。
    • [Requested Name Identifier Format (要求される名前 ID 形式)] 項目は空のままにします。
    • SAML ID プロバイダー URL として、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。
    • [User ID (ユーザー ID)] と [User ID type (ユーザー ID 種別)] はデフォルトを受け入れます。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Oracle CPQ Cloud 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Oracle CPQ Cloud アプリケーションを表すロゴとアイコンをアップロードまたは指定します。
  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、Oracle CPQ Cloud で設定した発行者 URL を入力します。たとえば、「https://customername.bigmachines.com」のように入力します。
    3. [ACS URL] に、Oracle CPQ Cloud の担当者から提供された値を入力します。
    4. [件名種別] で、ID プロバイダーでユーザーを識別する方法 ([統合 ID] または [カスタム属性] など) を選択します。いずれの場合も、SAML の件名種別が Oracle CPQ Cloud ユーザーの ID と一致する必要があります。
    5. [名前 ID 形式] で、[urn:oasis:names:tc:SAML:1.1:nameid-format:unspecified] を選択します。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト値 (デフォルトの IdP 証明書) のままにします。
  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Oracle CPQ Cloud の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから [Oracle CPQ Cloud] アプリケーションを見つけて開きます。接続アプリケーションに Oracle CPQ Cloud のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。

SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

Salesforce から QlikView への SSO の設定

使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

QlikView は、ID プロバイダーによる SSO とサービスプロバイダーによる SSO の両方で、SAML プロトコルをサポートしています。QlikView をサービスプロバイダーとして設定し、接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して QlikView にアクセスできます。

Salesforce から QlikView への SSO を設定するには、次の概要手順に従います。

QlikView に連絡して SAML 設定を行う

アカウントで SAML を有効にし、設定を行うには、QlikView の担当者に連絡します。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

  2. [証明書のダウンロード] をクリックします。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. QlikView 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで QlikView アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、QlikView の担当者から提供された QlikView ドメインの URL を入力します (例: 「https://partners.qlikview.com/sfdc/shibboleth」)。
    3. [ACS URL] に、QlikView の担当者から提供された URL を入力します。
    4. [件名種別] で、QlikView のユーザー名を Salesforce ユーザー ID に対応付ける属性を選択します ([統合 ID] など)。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。
  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. QlikView の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を入力します。
    4. 設定を保存します。

接続アプリケーションのテスト

  1. Salesforce で、アプリケーションランチャーから [QuipView] アプリケーションを見つけて開きます。接続アプリケーションに QlikView のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。
  2. サービスプロバイダーによる SSO をテストするには、QlikView 担当者から提供された URL が必要です。サービスプロバイダーによる SSO 用の URL を入力します。Salesforce ログインページにリダイレクトされたら、ログイン情報を入力します。SSO が適切に設定されていれば、Salesforce によって QlikView アプリケーションセッションが作成されます。

Salesforce から Samanage への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Samanage にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Samanage をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Samanage にアクセスできます。Samanage は、ID プロバイダーによる SSO とサービスプロバイダーによる SSO の両方で、SAML プロトコルをサポートしています。

  2. [証明書のダウンロード] をクリックします。

Samanage での SAML の設定

  1. Samanage アカウントに管理者としてログインします。
  2. [Setup (設定)] で、[Single Sign-On (シングルサインオン)] に移動します。
  3. [Login using SAML (SAML を使用したログイン)] で、[Enable Single Sign-On with SAML (SAML を使用したシングルサインオンの有効化)] を選択します。

  4. [SAML IdP Settings (SAML IdP 設定)] で、ID プロバイダー URL を入力します (例: 「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」)。

  5. Samanage に表示されたログイン URL をコピーして保存します。この URL は、後でサービスプロバイダーによるログインをテストするために使用します。

  6. ログアウト URL を入力します (例: https://MyDomainName.my.salesforce.com/secur/logout.jsp)。

  7. 必要に応じ、SAML ログイン中にエラーが発生した場合にユーザーをリダイレクトするにはエラー URL を入力します。
  8. [Identity Provider x.509 Certificate (ID プロバイダーの x.509 証明書)] に、ダウンロードした Salesforce 証明書の内容を入力します。

  9. ユーザーを自動的にプロビジョニングするには、[Create users if they do not exist in Samanage (Samanage にユーザーが存在しない場合はユーザーを作成する)] を選択します。

  10. 設定を保存するには、[Update (更新)] をクリックします。

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Samanage 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「samanage.com」と入力します。
    3. [ACS URL] に「https://yourdomain.samanage.com/saml/yourdomain」と入力します。たとえば、「https://acme.samanage.com/saml/acme」のように入力します。
    4. [件名種別] で、ID プロバイダーでユーザーを識別する方法 ([統合 ID] など) を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Samanage の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

  1. Salesforce で、アプリケーションランチャーから [Samanage] アプリケーションを見つけて開きます。接続アプリケーションに Samanage のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

  2. サービスプロバイダーによる SSO をテストするには、サービスプロバイダーによるログイン URL を入力します (例: 「https://yourdomain.samanage.com/saml_login/yourdomain」)。yourdomain はサブドメインです。たとえば、「https://identitydemo.samanage.com/saml_login/identitydemo」のように入力します。SSO が適切に設定されていれば、Salesforce 組織にログインするように促されます。ログイン情報を入力すると、Salesforce によって最初の要求 URL へリダイレクトされます。これで、Samanage アカウントにログインした状態になります。

Salesforce から SAP HANA への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して SAP HANA にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

SAP HANA をサービスプロバイダーとして設定し、接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して SAP HANA にアクセスできます。Salesforce から SAP HANA への SSO を設定するには、次の概要手順に従います。

この手順を完了するには、SAML が有効化された SAP HANA 管理者アカウントと SAP HANA クラウドにリリースされたアプリケーションが必要です。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 組織の証明書およびその他の情報を SAP HANA に提供する手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [メタデータのダウンロード] をクリックします。

SAP HANA での SAML の設定

  1. SAP HANA クラウドアカウントに管理者としてログインします。
  2. [TRUST (信頼)] で、[Local Service Provider (ローカルサービスプロバイダー)] を選択し、[Edit (編集)] をクリックします。
  3. [Configuration Type (設定種別)] で、[Custom (カスタム)] を選択します。
  4. [Local Provider Name (ローカルプロバイダー名)] にある URL をコピーして保存します。後で Salesforce で接続アプリケーションを設定するときに、この URL が必要になります。
  5. Salesforce を ID プロバイダーとして信頼を確立するために、SAP HANA で使用される自己署名証明書を作成するには、[Generate Key Pair (鍵ペアを生成)] をクリックします。

  6. アプリケーション間の SSO を有効にするには、[Principal Propagation (プリンシパルの伝達)] を有効にします。
  7. SSO を使用するには、[Force Authentication (認証を強制)] を無効にします。ユーザーに SAP HANA への再認証を強制する場合は、この設定を有効にします。設定を保存します。

  8. [Trusted Identity Provider (信頼できる ID プロバイダー)] タブで、[Add Trusted Identity Provider (信頼できる ID プロバイダーを追加)] をクリックします。

  9. [IdP Settings (IdP 設定)] で、先にダウンロードしておいた Salesforce メタデータファイルをアップロードします。メタデータファイルをアップロードすると、多数の項目が自動的に入力されます。設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. SAP HANA 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで SAP HANA アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、先ほど保存したローカルプロバイダー名を入力します。
    3. [ACS URL] に SAP HANA クラウドプラットフォームの値を入力します (例: https://authn.hanatrial.ondemand.com/saml2/sp/acs/p179870387/p179870387)。
    4. [件名種別] で、[統合 ID] を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト値 (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. SAP HANA の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. SAP HANA クラウドアカウントで、[APPLICATIONS (アプリケーション)] を選択します。このタブには、SAP HANA クラウドにリリース済みのアプリケーションが表示されます。
    2. SAP HANA アプリケーションに移動し、[URLs] の上にマウスポインターを置きます。アプリケーションの URL をコピーします。

    3. Salesforce の接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    4. [開始 URL] に、HANA アプリケーションからコピーした URL を入力します。
    5. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから SAP HANA アプリケーションを選択します。接続アプリケーションに SAP HANA のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。

SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

Salesforce から ServiceNow への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して ServiceNow にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

ServiceNow をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して ServiceNow にアクセスできます。ServiceNow は、SAML 2.0 SSO プロトコルおよび統合 SSO をサポートしています。

SSO で SAML 2.0 を使用するには、まず ServiceNow 管理者が Integration - Multiple Provider Single Sign-On Installer (統合 - 複数プロバイダーシングルサインオンインストーラー) プラグインを有効化する必要があります。このプラグインを有効にする方法やその他の設定要件については、ServiceNow のドキュメントで SAML 2.0 設定手順を参照してください。

プラグインを有効にした後、次の概要手順に従って Salesforce から ServiceNow への SSO を設定します。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 組織に関する情報を ServiceNow に提供するには、ID プロバイダーメタデータをダウンロードします。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [メタデータのダウンロード] をクリックします。メタデータには、後の手順で使用できる URL と自己署名証明書が含まれています。

ServiceNow での SAML の設定

  1. ServiceNow で Salesforce 組織の ID プロバイダープロパティを設定します。
    1. ServiceNow アカウントに管理者としてログインします。
    2. [SAML 2.0 Single Sign-on (SAML 2.0 シングルサインオン)] の ID プロバイダープロパティに移動します。
    3. 外部認証を有効にするために [Yes (はい)] を選択します。
      メモ 外部認証を有効にすると、Salesforce からの SSO を介してのみ ServiceNow にログインできるようになります。ロックアウトされた場合でも、https://ServiceNowdomain.service-now.com/side_door.do を使用すれば ServiceNow にアクセスできます。ServiceNowdomain は ServiceNow インスタンスのドメインです。

    4. ダウンロードした Salesforce メタデータを確認します。
      • バインド属性として HTTP リダイレクトを指定する SingleSignOnService 要素を見つけます。この要素の location 属性には AuthnRequest サービスの設定に使用する URL がリストされています。
      • バインド属性として HTTP リダイレクトを指定する SingleLogoutService 要素を見つけます。この要素の location 属性には SingleLogoutRequest サービスの設定に使用する URL がリストされています。
      • 自己署名証明書をメタデータからコピーする場合は、その場所を書き留めておきます。後の手順で、証明書を ServiceNow 設定にコピーします。
      メモ ServiceNow SAML 2.0 統合は、HTTP リダイレクトによる ID プロバイダー (IdP) サービスへのバインドのみをサポートしています。
    5. プロパティを入力します。
      • ID プロバイダーの AuthnRequest サービスのベース URL を入力します。SingleSignOnService メタデータ要素の location 属性を使用します。たとえば、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」のように入力します。
      • ID プロバイダーの SingleLogoutRequest サービスのベース URL を入力します。SingleLogoutRequest メタデータ要素の location 属性を使用します。たとえば、「https://MyDomainName.my.salesforce.com/secur/logout.jsp」のようになります。
      • 初めてログインする場合、または SSO 認証が失敗した場合にセッションをリダイレクトするために使用する URL を入力します。たとえば、「https://MyDomainName.my.salesforce.com/」のようになります。
      • ログアウト後にユーザーをリダイレクトする URL を入力します。たとえば、「https://MyDomainName.my.salesforce.com/logout」のようになります。
  2. サービスプロバイダーのプロパティを設定します。以降のサービスプロバイダー URL 例で、ServiceNowdomain は ServiceNow インスタンスの名前です。
    1. ServiceNow インスタンスのホームページの URL を入力します。たとえば、「https://ServiceNowdomain.service-now.com/navpage.do」のように入力します。
    2. IdP が認証するインスタンスのベース URL (ログインページを含まない) を入力します。たとえば、「https://ServiceNowdomain.service-now.com」のように入力します。
  3. SAML 2.0 設定の下の証明書設定に移動します。[PEM Certificate (PEM 証明書)] に、Salesforce ID プロバイダー証明書の内容を貼り付け、[Update (更新)] をクリックします。

  4. SAML 2.0 設定の下のログインスクリプト設定に移動します。スクリプトの sessionIndex セクション (54 ～ 65 行目あたり) をコメントアウトし、[Update (更新)] をクリックします。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. ServiceNow アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで ServiceNow アプリケーションを表すロゴとアイコンをアップロードまたは指定します。
  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、ServiceNow ドメインの URL を入力します。たとえば、「https://ServiceNowdomain.service-now.com」のように入力します。
    3. [ACS URL] に、ServiceNow ドメインの URL を入力します。たとえば、「https://ServiceNowdomain.service-now.com」のように入力します。
    4. [件名種別] で、[ユーザー名] を選択します。
    5. [名前 ID 形式] で、[urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress] を選択します。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. 設定を保存します。
  4. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. ServiceNow の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  5. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    2. [開始 URL] に、ServiceNow の URL を入力します。たとえば、「https://ServiceNowdomain.service-now.com/navpage.do」のように入力します。
    3. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから [ServiceNow] アプリケーションを見つけて開きます。接続アプリケーションに ServiceNow のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。

WS-Federation を使用した Salesforce から SharePoint への SSO の設定

Salesforce 組織から Web Services Federation とシングルサインオン (SSO) を使用して SharePoint にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Salesforce を WS-Federation (Web Services Federation) ID プロバイダーとして設定すると、ユーザーは SSO を使用して Salesforce から SharePoint にアクセスできます。

SharePoint で SSO を確立する最も簡単な方法は、Microsoft Active Directory フェデレーションサービス (AD FS) を SharePoint ファームのフロントエンドとして使用することです。AD FS を ID プロバイダーとして使用する代わりに、Apex 実装を使用して Salesforce を WS-Federation ID プロバイダーとして設定することもできます。

メモ これらの手順を実行するには、Salesforce Apex に精通し、PowerShell および Web サービス信頼設定の経験がある必要があります。

Apex と WS-Federation を使用して SharePoint への SSO を設定するには、次の概要手順に従います。

WS-Federation ID プロバイダーとしての組織の設定

  1. Salesforce 組織に WS-Federation 機能を追加するには、リンク https://login.salesforce.com/packaging/installPackage.apexp?p0=04ti00000008ezm を使用して apex-wsfederation パッケージをインストールします。

    パッケージをインストールした後に、ソースを表示できます。または、GitHub の https://github.com/salesforceidentity/ws-federation でも参照できます。

  2. 必要な主要情報を生成するには、Keys ディレクトリ (https://github.com/salesforceidentity/ws-federation/tree/master/Keys) にある cryptocommands.txt ファイル内のコマンドを実行します。コマンドでパスワードを要求されたら、毎回同じパスワードを入力します。このスクリプトを実行すると、次のファイルが生成されます。
    • key.pem - encodedPrivateKey (この鍵は慎重に保護し、配布を制限してください)
    • wsfed.crt - 公開証明書
    • modulus
    • exponent
      メモ modulus と exponent を取得するには、classes ディレクトリに Java クラスが必要です。
  3. 証明書ファイルと鍵ファイルを編集します。すべての改行を削除して、base64 エンコードデータのみを残します。データ形式の例については、WSFederationControllerTest クラスを参照してください。
  4. /apex/WSFederationManagement に移動し、次の設定を使用して領域を作成します。
    • Name—SharePoint.
    • Realm — urn:sharepoint:salesforce、またはその他の値。
    • Audience — urn:sharepoint:salesforce、またはその他の値。
    • Issuer—https://MyDomainName.my.salesforce.com/apex/WSFederation。
    • Action — https://yoursharepointserver/_trust/。
    • EncodedPrivateKey — 非公開鍵を使用して生成した PEM エンコード PKCS8 ファイル。
    • Certificate — 生成した PEM エンコード証明書。
    • Modulus — base64 エンコード modulus。
    • Exponent — base64 エンコード exponent。

Salesforce から SpringCM への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して SpringCM にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

SpringCM をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して SpringCM にアクセスできます。SpringCM は、ID プロバイダーによる SSO とサービスプロバイダーによる SSO の両方で、SAML プロトコルをサポートしています。

Salesforce から SpringCM への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

SpringCM での SAML の設定

  1. SAML が有効化された管理者として、SpringCM アカウントにログインします。
  2. Salesforce ID プロバイダー証明書をアップロードするために、[Upload (アップロード)] をクリックします。
  3. [Preferences (個人設定)]、[Account Preferences (アカウント設定)]、[SAML SSO] で、[Identity Provider Configuration (ID プロバイダー設定)] をクリックします。
  4. アップロードした Salesforce 証明書を選択します。
  5. [Issuer (発行者)] に、SAML IdP 発行者を https://MyDomainName.my.salesforce.com の形式で入力します。たとえば、「https://identitydemo.my.salesforce.com」のように入力します。
  6. [Service Provider (SP) Initiated Endpoint (サービスプロバイダー (SP) が開始するエンドポイント)] に「https://MyDomainName.my.salesforce.com/idp/endoint/HttpPost」と入力します。
  7. [SAML Enabled (SAML の有効化)] で [Enable (有効化)] を選択します。
  8. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. SpringCM 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで SpringCM アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「https://www.springcm.com/atlas/sso/Prod」と入力します。
    3. [ACS URL] に「https://www.springcm.com/atlas/sso/SSOEndpoint.ashx」と入力します。
    4. [件名種別] で、SpringCM のユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性を選択します。たとえば、[ユーザー名] を選択します。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. SpringCM の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. 接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

  1. Salesforce で、アプリケーションランチャーから [SpringCM] アプリケーションを見つけて開きます。接続アプリケーションに SpringCM のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

  2. サービスプロバイダーによる SSO をテストするには、ブラウザーで ACS URL にアカウント ID を追加します。たとえば、「https://www.springcm.com/atlas/sso/SSOEndpoint.ashx?aid=12062」のように入力します。SSO が適切に設定されていれば、Salesforce 組織にログインするように促されます。ログイン情報の入力に成功すると、SpringCM アカウントにログインした状態になります。

    4. 設定を保存します。

Salesforce から Syncplicity への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Syncplicity にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Syncplicity をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Syncplicity にアクセスできます。Syncplicity は、サービスプロバイダーによる SSO でのみ SAML プロトコルをサポートしています。

Salesforce から Syncplicity への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Syncplicity での SAML の設定

  1. SAML が有効化された管理者として、Syncplicity アカウントにログインします。
  2. [admin (管理)] で [Configure Authentication Settings (認証設定)] をクリックします。
  3. ユーザーのログイン先となるカスタムブランドドメインを作成するには、ドメイン名を入力します (例: 「sales」)。

  4. SSO 設定を定義します。
    1. [Single Sign-On Status (シングルサインオンの状況)] で [Enabled (有効)] を選択します。
    2. [Entity Id (エンティティ ID)] に、[私のドメイン] ログイン URL を入力します (例: 「https://MyDomainName.my.salesforce.com」)。
    3. [Sign-in page URL (サインインページ URL)] に、ユーザーが認証のためにリダイレクトされるエンドポイントを入力します (例: 「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」)。
    4. [Logout page URL (ログアウトページ URL)] に、Syncplicity からログアウトした後にユーザーがリダイレクトされるページを入力します (例: 「https://my.syncplicity.com/」)。
    5. .CER 形式または .PEM 形式の Salesforce 証明書を選択してアップロードします。
    6. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Syncplicity 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Syncplicity アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、Syncplicity エンティティの URL を入力します (例: 「https://SyncplicityOrgName.syncplicity.com/sp」)。
    3. [ACS URL] に、https://SyncplicityOrgName.syncplicity.com/Auth/AssertionConsumerService.aspx の形式でアサーションコンシューマーサービスの URL を入力します。たとえば、「https://sales.syncplicity.com/Auth/AssertionConsumerService.aspx」のように入力します。
    4. [件名種別] で、ユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性を選択します ([統合 ID] など)。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] で、[urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress] を選択します。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Syncplicity の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. 接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    2. [開始 URL] に、https://SyncplicityDomain.syncplicity.com の形式でサービスプロバイダーによる SSO の URL を入力します。たとえば、「https://sales.syncplicity.com/」のように入力します。
    3. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから [Syncplicity] アプリケーションを見つけて開きます。接続アプリケーションに Syncplicity のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

Tableau Online への Salesforce メタデータの入力

  1. Tableau Online サイトにサイト管理者としてサインインします。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。

  2. 接続アプリケーションの [基本情報] を設定します。
    1. WebEx 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。

    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。
  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。

    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。

WebEx での SAML の設定

  1. WebEx アカウントに管理者としてログインします。

    1. [Federation Protocol (フェデレーションプロトコル)] で [SAML 2.0] を選択します。
    2. [IDP Initiated (IDP 開始)] を選択します。
    3. [Target page URL Parameter (ターゲットページ URL パラメーター)] に「RelayState」と入力します。
    4. [WebEx SAML Issuer (SP ID) (WebEx SAML 発行者 (SP ID))] に「http://www.webex.com」と入力します。
    5. [Issuer For SAML (IdP ID) (SAML の発行者 (IdP ID))] に、[私のドメイン] ログイン URL を入力します。
    6. [Customer SSO Service Login URL (顧客 SSO サービスログイン URL)] に、Salesforce で表示された Idp-init のログイン URL を入力します。
    7. [NameID Format (名前 ID 形式)] で [Unspecified (指定なし)] を選択します。
    8. [AuthnContextClassRef] に「urn:oasis:names:tc:saml:2.0:ac:classes:unspecified」と入力します。
    9. 設定を保存します。

  4. [Security Settings (セキュリティ設定)] で、[Organization Certificate Management (組織の証明書管理)] をクリックします。
    1. [Import New Certificate (新規証明書のインポート)] をクリックします。

    2. Salesforce 組織の証明書の別名を入力し、証明書をインポートします。

    3. [Organization Certificate Management (組織の証明書管理)] ウィンドウで、インポートした証明書を有効にするために、証明書を選択します。
    4. 設定を保存します。

メモ Wikispaces アカウントの SSO 設定を有効にするには、Wikispaces の担当者にお問い合わせください。

Wikispaces に連絡してアカウントを設定

    11. 認証要求メソッドには [SHA1] を選択します。
    12. [Enable Signature Keyinfo Validation (署名の Keyinfo 検証の有効化)] を選択します。

    13. 設定を保存します。

Salesforce から Zendesk への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Zendesk にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Zendesk をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Zendesk にアクセスできます。Zendesk は、ID プロバイダーによる SSO とサービスプロバイダーによる SSO の両方で、SAML プロトコルをサポートしています。

Salesforce から Zendesk への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、または変更する正当な理由がある場合は、名前を変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Zendesk での SAML の設定

  1. Zendesk アカウントに管理者としてログインします。
  2. [Settings (設定)] で、[Security (セキュリティ)] に移動します。
  3. シングルサインオンを有効にするために、[Enabled (有効)] を選択します。SSO 認証モードとして [SAML] を選択します。

  4. [SAML SSO URL] に、ID プロバイダーエンドポイントを入力します (例: 「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」)。
    メモ Zendesk に ACS URL が表示されます。後ほど Zendesk の Salesforce 接続アプリケーションを設定するときに、この URL を入力します。

  5. 必要に応じて、ログアウト後にユーザーをリダイレクトするためにリモートログアウト URL を入力します (例: 「https://MyDomainName.my.salesforce.com/secur/logout.jsp」)。たとえば、「https://identitydemo.my.salesforce.com/secur/logout.jsp」のように入力します。
  6. Salesforce ID プロバイダー証明書の SHA1 フィンガープリントを入力します。

  7. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Zendesk 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Zendesk アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「yourdomain.zendesk.com」と入力します。たとえば、「https://acme.zendesk.com」のように入力します。
    3. [ACS URL] に「https://yourdomain.zendesk.com/access/saml/」と入力します。たとえば、「https://acme.zendesk.com/access/saml/」のように入力します。
    4. [件名種別] で、ID プロバイダーでユーザーを識別する方法 ([統合 ID] など) を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Zendesk の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

  1. Salesforce で、アプリケーションランチャーから [Zendesk] アプリケーションを見つけて開きます。接続アプリケーションに Zendesk のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

  2. サービスプロバイダーによる SSO をテストするには、サービスプロバイダーによるログイン URL を入力します (例: 「https://yourdomain.zendesk.com/」)。yourdomain はサブドメインです。たとえば、「https://acme.zendesk.com/」のように入力します。SSO が適切に設定されていれば、Salesforce 組織にログインするように促されます。ログイン情報を入力すると、Salesforce によって最初の要求 URL へリダイレクトされます。これで、Zendesk アカウントにログインした状態になります。

ID 検証の 3 つの形式を確認します。

  • 多要素認証 (MFA)

    直接ログインまたはシングルサインオン (SSO) のどちらを使用して Salesforce 製品にアクセスする場合でも、MFA は契約上必要です。顧客がこの要件を満たすことができるように、本番組織への直接ログインでは MFA が自動的に有効になります。MFA では、ユーザーは Salesforce ユーザー名とパスワードに加えて検証方法を指定する必要があります。

  • デバイスの有効化

    ユーザーは不明なデバイスから Salesforce にログインするときに検証方法を提供します。MFA が有効になっている場合、デバイスが認識されるかどうかに関係なく、ユーザーは ID を検証する必要があるため、デバイスの有効化は適用されなくなります。

  • ステップアップ認証

    ユーザーは、セッションセキュリティレベルを引き上げる必要があるアクションを実行するときに検証方法を提供します。たとえば、標準セッションセキュリティレベルを持つユーザーは、高保証セッションセキュリティレベルを必要とするリソースにアクセスする前に ID を検証する必要があります。MFA では、ユーザーがログインするたびに高保証セッションが提供されるため、MFA が有効になっている場合、ステップアップ認証は適用されなくなります。高保証セッションセキュリティの要求についての詳細を参照してください。

トリガー基準

ID 検証のセキュリティポリシーまたは設定。

  • Apex メソッド — 検証 Apex メソッドによって行われる ID 検証。
  • デバイスの有効化 — 不明なデバイスまたは新しい IP アドレスからログインするユーザーに必要な ID 検証。この検証は、Salesforce のリスクベースの認証の一部です。
  • Lightning Login 登録 — Lightning Login でのユーザー登録に ID 検証が必要です。この検証はユーザーが登録を試行したときにトリガーされます。ユーザーに「Lightning Login ユーザー」ユーザー権限があり、[セッションの設定] の [Lightning Login の許可] が組織で有効になっている場合は、登録が可能です。
  • 高保証セッションが必要です — リソースへのアクセスに高保証セッションが必要です。高保証セッションレベルを必要とする接続アプリケーション、レポート、ダッシュボードなどのリソースをユーザーが使用しようとするとこの検証が起動します。
  • Lightning Login ログイン — Lightning Login での内部ユーザーログインに ID 検証が必要です。この検証は登録済みユーザーがログインを試行したときにトリガーされます。ユーザーに「Lightning Login ユーザー」ユーザー権限があり、Lightning Login での登録が成功している場合は、ログインが可能です。また、[設定] の [セッションの設定] で、[Lightning Login を許可] を有効にする必要があります。
  • プロファイルセッションレベルポリシー — ログイン時にセッションセキュリティレベルが必要です。この検証は、ユーザーのプロファイルの [ログインに必要なセッションセキュリティレベル] 設定によってトリガーされます。
  • 多要素認証が必要です — ログイン時に多要素認証 (旧称「2 要素認証」) が必要です。この検証は、カスタムプロファイルに割り当てられた「ユーザーインターフェースログインの多要素認証」ユーザー権限によってトリガーされます。または、この権限がユーザーに割り当てられた権限セットに含まれている場合もトリガーされます。

  • メールメッセージ — Salesforce によって、確認コードを含むメールがユーザーのアカウントに関連付けられたアドレスに送信されました。
  • Lightning Login 登録 — Lightning Login で登録するために、Salesforce Authenticator によって、ユーザーのモバイルデバイスに通知が送信されました。
  • ワンタイムパスワード — ユーザーのモバイルデバイスの認証アプリケーションによって、時間ベースのワンタイムパスワード (TOTP) が生成されました。
  • Lightning Login ログイン — Lightning Login でログインを承認するために、Salesforce Authenticator によって、ユーザーのモバイルデバイスに通知が送信されました。
  • Salesforce Authenticator — Salesforce Authenticator によって、ユーザーのモバイルデバイスにアカウントアクティビティを検証する通知が送信されました。
  • 仮の確認コード — 「ユーザーインターフェースでの多要素認証の管理」権限を持つ Salesforce システム管理者またはユーザーがユーザーの仮の確認コードを生成しました。
  • テキストメッセージ — Salesforce によって、確認コードを含むテキストメッセージがユーザーのモバイルデバイスに送信されました。SMS メッセージングには、ID 検証クレジットに対する Salesforce アドオンライセンスが必要です。
  • U2F セキュリティキー — U2F セキュリティキーによって、ユーザーに必要なログイン情報が生成されました。
状況

ID 検証試行の状況。

  • アクセスが拒否されました — Salesforce Authenticator などの認証アプリケーションの承認申請をユーザーが拒否しました。
  • アクセスが拒否されました: ユーザーによってフラグが付けられました — Salesforce Authenticator などの認証アプリケーションの承認申請をユーザーが拒否し、さらに承認申請をシステム管理者に報告するようにフラグを付けました。
  • 失敗: 一般的なエラー — 確認コードが無効、試行回数が多すぎる、または認証アプリケーションの接続以外の問題が原因でエラーが発生しました。
  • 失敗: 確認コードが無効です — ユーザーが無効な確認コードを入力しました。
  • 失敗: 復旧できるエラー — Salesforce が ID を検証する認証アプリケーションに接続できませんでしたが、再試行を続けます。
  • 失敗: 試行回数が多すぎます — ユーザーが ID の検証を試行した回数が多すぎます。たとえば、ユーザーが無効な確認コードを繰り返し入力した場合などです。
  • Succeeded — ユーザーの ID が検証されました。
  • 成功: 自動応答 — 信頼できる場所から要求が行われたため、Salesforce Authenticator がアクセス要求を承認しました。ユーザーが Salesforce Authenticator のロケーションサービスを有効にすると、信頼できる場所を指定できます。認識されるデバイスからのログインなど、特定のアクティビティに対してユーザーが場所を信頼すると、その場所が信頼される限り、信頼できる場所からのアクティビティは承認されます。
  • ユーザーによる確認コードの入力を待機中 — Salesforce がユーザーに ID の検証を求め、ユーザーによる応答または Salesforce Authenticator による自動応答の送信を待機しています。

ユーザーアクティビティ

ユーザーが試行した ID 検証が必要なアクション。

  • 接続アプリケーションへのアクセス — ユーザーが接続アプリケーションへのアクセスを試行しました。
  • レポートへのアクセス — ユーザーがレポートまたはダッシュボードへのアクセスを試行しました。
  • Apex で定義されたアクティビティ — ユーザーが検証 Apex メソッドで Salesforce リソースへのアクセスを試行しました。
  • レポートをエクスポートおよび印刷 — ユーザーがレポートまたはダッシュボードのエクスポートか印刷を試行しました。
  • Salesforce へのログイン — ユーザーがログインを試行しました。
