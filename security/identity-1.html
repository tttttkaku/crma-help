ユーザーのアカウントからの Salesforce Authenticator の切断（Salesforce 組織）

ユーザーのアカウントには、一度に 1 つの Salesforce Authenticator モバイルアプリケーションしか接続できません。ユーザーがSalesforce Authenticatorがインストールされたモバイルデバイスを紛失または交換した場合、そのユーザーのアカウントからアプリケーションを切断できます。ユーザーのアプリケーションが動作しなくなった場合は、アプリケーションを切断してリセットし、再登録してアカウントへのアプリケーションの接続を復元するようにユーザーに要求します。また、ユーザーが退職した場合はユーザーの検証方法をすべて切断することをお勧めします。

パスキーを使用したパスワードなしのログイン

従業員向けの高速で簡単でフィッシング詐欺に強いログインプロセスを設定します。パスキーによるパスワードなしのログインでは、内部ユーザーは組み込み Authenticator (Touch ID や Windows Hello など) またはセキュリティキーを使用してログインします。

必要なエディション

使用可能なエディション: すべてのエディション

パスキーとは?

パスキーは、組み込み Authenticator などの生体認証方法と U2F キーなどのセキュリティキーを使用してログインできるようにする一連のログイン情報です。ユーザーがこれらの方法を使用してログインすると、パスキーが使用されます。パスキーは、バックグラウンドで公開鍵暗号化を使用して安全にユーザーを認証します。パスキーは Fast IDentity Online (FIDO) 標準に基づいています。パスキーのしくみについての詳細は、FIDO ドキュメントを参照してください。

パスキーの利点

  • セキュリティの向上 — パスキーには、フィッシングへの耐性など、いくつかのセキュリティ上の利点があります。パスキーのセキュリティについての詳細は、FIDO ドキュメントを参照してください。
  • 利便性 — パスキーは自分とユーザーにとってより便利です。パスキーを使用すると、ユーザーは長く複雑なパスワードを追跡する必要がなくなります。ユーザーは、デバイスの Touch ID など、簡単に使用できる方法を使用してログインできます。ほとんどの場合、パスワードを入力するよりもパスキーを使用する方が簡単です。パスキーを有効にすると、パスワードのリセットやログインの問題が減り、会社の時間とリソースを節約できます。

Passkey Login Experience (パスキーログイン環境)

パスキーのログイン環境は、ログイン方法によって若干異なります。

組み込み Authenticator では次のように動作します。

  • (1) ユーザーが Salesforce ログインページに移動し、保存したユーザー名をクリックします。
  • (2) ユーザーのブラウザーで組み込み Authenticator を使用するように促されます。たとえば、指紋を使用して Touch ID を入力するように促されます。
  • (3) 組み込み Authenticator を使用すると、ユーザーは Salesforce にログインします。

セキュリティキーのログイン環境を次に示します。

  • (1) ユーザーが Salesforce ログインページに移動し、保存したユーザー名をクリックします。
  • (2) ユーザーのブラウザーでセキュリティキーを使用するように促されます。
    • セキュリティキーには、ユーザーが携帯している YubiKey などの小さな物理デバイスを使用できます。
    • ユーザーは携帯電話などの別のデバイスをセキュリティキーとして使用することもできます。この方法では、ユーザーはもう一方のデバイスを使用して QR コードをスキャンし、認証を完了するように求めます。たとえば、携帯電話で QR コードをスキャンし、携帯電話で Face ID を使用して認証を完了します。
  • (3) セキュリティキーを使用すると、ユーザーは Salesforce にログインします。

パスキーの要件と考慮事項

  • パスキーは本質的に複数の要素を使用してユーザーの ID を検証するため、Salesforce MFA (多要素認証) 要件を満たします。ユーザーが組み込み Authenticator またはセキュリティキーを使用してログインする場合、認証に別の要素を指定するように要求されることはありません。パスキーと MFA についての詳細は、FIDO ドキュメントを参照してください。
  • Salesforce システム管理者は、パスキーを使用したパスワードなしログインを有効にする必要があります。
  • ユーザーがパスキーを使用してログインするには、登録済みの Built-In Authenticator for MFA または Security Keys for MFA が必要です。
  • ユーザーのユーザー名を保存する必要があります。ユーザーが以前にログインしていて、ログインページで [記憶する] チェックボックスをオンにしている場合、Salesforce はユーザー名を保存します。
  • Experience Cloud サイトでは、パスキーを使用したパスワードなしのログインはサポートされていません。
  • パスキーを使用したパスワードなしのログインを有効にすると、保存されたユーザー名と登録済みの組み込み Authenticator またはセキュリティキーの要件を満たす限り、すべての内部ユーザーに対して有効になります。特定のユーザーに対して無効にすることはできません。
  • パスキーを使用したパスワードなしのログインの有効化
    パスワードなしのログインにパスキーを設定して、登録済みの組み込み Authenticator またはセキュリティキーを使用して従業員がログインできるようにします。

SAML シングルサインオンフロー

Security Assertion Markup Language (SAML) を使用してシングルサインオン (SSO) を設定すると、サービスプロバイダーまたは ID プロバイダーからログインを開始できます。サービスプロバイダーの起動によるログインと ID プロバイダーの起動によるログインでは、それぞれ異なるフローを使用しますが、どちらもユーザーはサービスプロバイダーにログインします。

必要なエディション

使用可能なインターフェース: Salesforce Classic および Lightning Experience の両方
使用可能なエディション: Developer Edition、Enterprise Edition、Performance Edition、Unlimited Edition、および Database.com Edition
必要なユーザー権限
ID プロバイダーとサービスプロバイダーの定義と変更 「アプリケーションのカスタマイズ」

SAML セキュリティ

これらの SSO フローのしくみを理解するには、プロバイダーが SAML を使用してセキュリティ情報をやりとりする方法を理解することが重要です。

ヒント SSO の語彙を磨くには、Salesforce ヘルプの「シングルサインオン用語」を参照してください。

どちらの SAML SSO フローバリエーションでも、ID プロバイダーがユーザーを認証し、ユーザーが本人であることを確認します。ID プロバイダーは、ユーザーを認証した後、SAML 応答を使用して、ユーザーが誰であり、何を許可されているかをサービスプロバイダーに通知します。ユーザーの ID に関する情報は、応答の特定の部分 (SAML アサーション) に保存します。

サービスプロバイダーが SAML 応答を Trust できることを示すために、ID プロバイダーは応答ボディ、アサーション、またはその両方に署名します。レスポンスボディとアサーションのどちらに署名するかは、ID プロバイダーによって異なります。

  • Salesforce を ID プロバイダーとして使用している場合、Salesforce は SAML レスポンスボディとアサーションに署名します。
  • サードパーティ ID プロバイダーを使用している場合は、ID プロバイダーが SAML 応答に署名する方法を確認してください。

サービスプロバイダーは SAML 応答を受信すると、この署名を検証します。署名の検証方法は、サービスプロバイダーによって異なります。

  • Salesforce を ID プロバイダーとして使用している場合は、サービスプロバイダーに署名の検証方法を確認してください。Salesforce はレスポンスボディとアサーションに署名するため、さまざまなサービスプロバイダーと互換性があります。
  • Salesforce をサービスプロバイダーとして使用している場合、Salesforce はレスポンスボディまたはアサーションのいずれかで署名を検証できます。Salesforce は最初にレスポンスボディの署名を検索します。応答署名が欠落しているか無効である場合、Salesforce は SAML アサーションで署名を検証します。攻撃者がユーザーのブラウザーから SAML 応答を取得して応答本文を改ざんしたとしても、アサーション署名が無傷である限り、SSO ログインが危険にさらされることはありません。

    セキュリティを強化するために ID プロバイダーで暗号化された SAML アサーションがサポートされている場合は、SAML アサーションを暗号化するための外部 ID プロバイダーの設定もできます。

サービスプロバイダーの起動による SAML フロー

サービスプロバイダーの起動によるフローでは、サービスプロバイダーが ID プロバイダーに対する SAML 要求によってログインプロセスを開始します。このフローは次のように機能します。

  1. ユーザーは、サービスプロバイダーで保護されているリソースにアクセスするための安全なセッションを要求します。たとえば、サービスプロバイダーでフォームに記入するためのリンクをクリックします。しかし、フォームは保護されているリソースであるため、ログインしなければアクセスできません。
  2. サービスプロバイダーは、ID プロバイダーに SAML 要求を送信してユーザーの認証を依頼することでログインを開始します。
  3. ID プロバイダーはユーザーをログインページに転送します。
  4. ユーザーは ID プロバイダーのログイン情報を入力し、ID プロバイダーはユーザーを認証します。
  5. ID プロバイダーは、ユーザーの身元を確認し、暗号で署名された SAML 応答をサービスプロバイダーに送信します。SAML 応答には、サービスプロバイダーにユーザーの身元を通知する SAML アサーションが含まれます。
  6. サービスプロバイダーは、SAML 応答に含まれる署名を検証して、ユーザーを識別します。
  7. ユーザーは、サービスプロバイダーにログインして、保護されているリソースにアクセスできます。

ID プロバイダーの起動による SAML フロー

ID プロバイダーの起動によるログインフローでは、ID プロバイダーが SAML 応答でフローを開始するため、SAML 要求は不要です。ID プロバイダーの起動によるフローは、サービスプロバイダーの起動によるフローの短いバージョンです。このフローは次のように機能します。

  1. ユーザーは、ID プロバイダーにログインします。
  2. ユーザーは、サービスプロバイダーにアクセスするためのボタンまたはリンクをクリックします。たとえば、ユーザーは Salesforce 組織の [アプリケーションランチャー] ページでアプリケーションをクリックします。
  3. ID プロバイダーは、暗号で署名された SAML 応答をサービスプロバイダーに送信することでログインを開始します。SAML 応答には、サービスプロバイダーにユーザーの身元を通知する SAML アサーションが含まれます。
  4. サービスプロバイダーは、SAML 応答に含まれる署名を検証して、ユーザーを識別します。
  5. ユーザーは、Service プロバイダーにログインします。

SAML ID プロバイダーとしての Salesforce の有効化

Salesforce を外部サービスプロバイダーに対するシングルサインオン (SSO) SAML ID プロバイダーとして設定できます。組織が SAML ID プロバイダーとして機能することで、ユーザーは 1 回のログインで複数のアプリケーションにアクセスできます。この設定を開始するには、Salesforce を ID プロバイダーとして有効化し、設定情報をサービスプロバイダーと共有します。

必要なエディション

使用可能なインターフェース: Salesforce Classic および Lightning Experience の両方
使用可能なエディション: Developer Edition、Enterprise Edition、Performance Edition、Unlimited Edition、および Database.com Edition
必要なユーザー権限
ID プロバイダーとサービスプロバイダーの定義と変更 「アプリケーションのカスタマイズ」

組織がサービスプロバイダーと通信できるようにするために使用する証明書を決定します。デフォルトの証明書を使用するか、独自の証明書を作成できます。「証明書とキーの管理」を参照してください。

  • デフォルトでは、Salesforce ID プロバイダーは、SHA-256 署名アルゴリズムによって生成される自己署名証明書を使用します。デフォルトの証明書を使用する場合は、ステップ 1 に進みます。
  • 自己署名証明書を作成するには、「自己署名証明書の生成」の手順に従ってから、ステップ 1 に進みます。
  • CA 署名証明書を作成するには、「認証機関によって署名された証明書の生成」の手順に従ってから、ステップ 1 に進みます。
  1. [設定] の [クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [ID プロバイダーを有効化] をクリックします。
  3. ドロップダウンメニューから証明書を選択します。
  4. 変更内容を保存します。

ID プロバイダー情報を確認するには、[設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。

このページから、次のアクションを実行できます。

  • ID プロバイダー証明書を変更するには、[編集] をクリックします。
    警告 証明書を変更すると、外部アプリケーションへのアクセスが無効化される場合があります。新しい証明書情報を確認するには、すべての外部アプリケーションを更新します。
  • ID プロバイダーとしての組織を無効化するには、[無効化] をクリックします。
    警告 ID プロバイダーとしての組織を無効化すると、ユーザーは SSO で外部アプリケーションにアクセスできなくなります。
  • ID プロバイダー証明書をダウンロードするには、[証明書のダウンロード] をクリックします。サービスプロバイダーは、この情報を使用して Salesforce に接続できます。
  • ID プロバイダーに関するメタデータの XML ファイルをダウンロードするには、[メタデータのダウンロード] をクリックします。サービスプロバイダーは、このメタデータを使用して Salesforce に接続できます。
  • [詳細] セクションの [発行者] で、Salesforce ID プロバイダーの一意の識別子を確認します。
  • [SAML のメタデータ検出エンドポイント] セクションでは、カスタムドメインおよび任意の Experience Cloud サイトの ID プロバイダーのメタデータにアクセスできます。一部のサービスプロバイダーは、この URL を使用して Salesforce に接続するためのシングルサインオンを設定します。たとえば、Amazon Web Services (AWS) をサービスプロバイダーとして設定する場合は、Salesforce ID プロバイダーのメタデータを AWS にアップロードします。

    カスタムドメインやサイトの ID プロバイダーのメタデータは次の項目に入っています。

    • Salesforce ID — カスタムドメインの ID プロバイダーメタデータの URL。
    • コミュニティ ID — 特定の Experience Cloud サイトの ID プロバイダーメタデータの URL。たとえば、XYZ という名前のサイトを設定してある場合は、[XYZ Community Identity] と表示されます。

Salesforce では、サービスプロバイダーに送信される SAML アサーションの存続期間も定義します。Salesforce ID プロバイダーによって送信された SAML アサーションは、発行から 5 分間有効であり、クロックスキューに対応する 30 秒のバッファがあります。たとえば、アサーションが 12:00:00 GMT に発行された場合、11:59:30 GMT から 12:05:00 GMT の間有効になります。通常、サービスプロバイダーは、この期間以外に SAML 応答を受信してもアサーションを拒否します。

Salesforce を ID プロバイダーとして有効化したら、次の手順を実行します。

  • サービスプロバイダーを統合するための前提条件を完了します。
  • サービスプロバイダーを SAML 対応アプリケーションとして統合します。
  • Salesforce ユーザーをサービスプロバイダーに対応付けます。

  • 自己署名証明書の生成
  • 接続アプリケーションの作成

Microsoft AD FS を ID プロバイダーとして使用した Salesforce への SSO の設定

Microsoft Active Directory フェデレーションサービス (AD FS) 2.0 を使用してユーザーが Microsoft 環境から Salesforce 組織にログインできるようにします。 Microsoft AD FS は、シングルサインオン認証の ID プロバイダーとして機能します。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Microsoft AD FS 2.0 は SAML 2.0 プロトコルをサポートしています。AD FS 2.0 が Salesforce ID プロバイダーとして設定されている場合、ユーザーはシングルサインオン (SSO) を使用して Salesforce にログインできます。

メモ

AD FS UserInfo エンドポイントは、OpenID 標準に指定された対象ユーザークレームのみを返します。UserInfo エンドポイント経由で要求された追加の要求は提供されません。ID トークンで追加の要求が必要な場合は、カスタム ID トークンを使用します。

Salesforce で使用するために AD FS 2.0 を設定するときには、Salesforce のシングルサインオン設定の [サービスプロバイダーの起動要求バインド] で [HTTP リダイレクト] を選択することをお勧めします。この設定により、iOS ベースのデバイスとの相互運用性が向上します。

前提条件

AD FS 2.0 を Salesforce ID プロバイダーとして設定するには、以下が必要です。

  • Microsoft Windows Server 2008 R2 Enterprise または Datacenter エディション。評価目的で環境を設定する場合は、Microsoft ダウンロードセンターからトライアルバージョンをダウンロードできます。
  • Microsoft Active Directory フェデレーションサービス 2.0。
    メモ Windows Server 2008 R2 に含まれる AD FS 1.0 は SAML 2.0 をサポートしていません。 そのため、AD FS 2.0 RTW (Release To Web) パッケージをダウンロードします。
  • Salesforce 組織。Developer Edition 環境で試すことができます。

概要

SAML 2.0 では、SSO への参加者のロールが定義されています。ユーザーは ID プロバイダー (IdP) (この場合は AD FS 2.0) に対して認証します。 ユーザーは 1 つ以上のサービスプロバイダー (SP) のリソースに、各サービスプロバイダーにログインすることなくアクセスできるようになります。この場合の SP (「証明書利用者」とも呼ばれる) は Salesforce 組織です。

次の図は、IdP が開始する Salesforce へのログインプロセスを示します。

  • ユーザーが統合 Windows 認証 (HTTP 経由の Kerberos トークン) を使用して AD FS サーバーに対する認証を行い、Salesforce へのログインを要求します。(1)。
  • AD FS が SAML アサーションをユーザーのブラウザーに返します。(2)
  • ブラウザーがアサーションを Salesforce に送信し、Salesforce がユーザーをログインします。(3)

以下はテストリリースを作成するための概要手順です。

  1. Microsoft AD FS 2.0 をインストールする。
  2. AD FS と Salesforce 環境を設定する。
  3. 設定をテストする。
  4. 必要に応じて実装の問題をトラブルシューティングする。

ソフトウェアのインストール

  1. まず Windows Server 2008 R2 をインストールします。
    メモ AD FS サーバーは Active Directory ドメインのメンバーである必要があります。評価目的でラボ設定を構築する場合、AD FS サーバーをドメインコントローラーにすることができます。ただし、この設定は本番設定にはお勧めしません。
  2. AD FS にわかりやすい DNS 名を作成し (例: adfs.testzone.local)、AD FS 2.0 サーバーを参照するように指定します。
  3. AD FS 2.0 をダウンロードしてインストールします。 このステップでは、前提となる他の Windows コンポーネント (IIS など) をインストールします。
  4. IIS マネージャーで、わかりやすい DNS 名に対する SSL 証明書を作成します。IIS 6.0 リソースキットがある場合は、SelfSSL を使用して自己署名証明書を作成できます。
  5. AD FS サーバー設定ウィザードを実行します。
    1. フェデレーションサービスを作成します。
    2. [Stand-alone Server (スタンドアロンサーバー)] を選択します。
    3. わかりやすい DNS 名に対して作成した証明書を選択します。
  6. インストーラーがサービスプリンシパル名 (SPN) を登録するときにエラーが発生したら、その DNS 名に対して手動で Kerberos SPN を作成します。この SPN により、統合 Windows 認証はブラウザーと AD FS IIS インスタンス間で適切に機能できます。
1  setspn -a HOST/adfs.testzone.local testzone\ADFSSVR01
2  setspn -a HOST/adfs testzone\ADFSSVR01

Kerberos SPN についての詳細は、「Active Directory and Kerberos SPNs Made Easy」 (Active Directory と Kerberos SPN についての簡単な説明) を参照してください。

Salesforce の設定

2 者間にフェデレーションを構築するには、メタデータを交換して信頼関係を確立する必要があります。AD FS 2.0 インスタンスのメタデータは Salesforce の設定に入力されます。Salesforce のメタデータは AD FS 2.0 で使用可能な XML ファイルとしてダウンロードされます。

SAML 2.0 の設定

AD FS 2.0 MMC Snap-in で、証明書ノードを選択し、トークン署名証明書をダブルクリックして表示します。[詳細] タブをクリックし、[ファイルにコピー] を選択します。証明書を DER 形式で保存します。

AD FS サーバーで、AD FS MMC の [Service (サービス)] | [Endpoints (エンドポイント)] | [Metadata (メタデータ)] | [Type:Federation Metadata (Type:Federation メタデータ)] にある統合メタデータ URL を参照します。この例では、URL は https://adfs.testzone.local/FederationMetadata/2007-06/FederationMetadata.xml です。

entityID 属性の値をコピーします。この例では、値は http://adfs.testzone.local です。

Salesforce で、[設定] から [クイック検索] ボックスに「シングルサインオン」と入力し、[シングルサインオン設定] を選択します。[SAML を有効化] を選択し、SAML SSO 設定を作成するオプションをクリックします。

メモ [統合 ID を大文字と小文字を区別しない] 設定は、SAML を初めて有効にするときにデフォルトで有効になっています。この設定により、csmith や CSmith など、類似する統合 ID を持つ一意のユーザーを作成できなくなります。この設定は有効にしておくことをお勧めします。

設定を定義します。

  • 名前 — SAML SSO 設定の名前を入力します。
  • SAML のバージョン — 2.0 に設定されています。
  • 発行者 — 上記の entityID をここに貼り付けます。
  • ID プロバイダーの証明書 — 前にエクスポートしたトークン署名証明書を参照して選択します。
  • 証明書の署名要求 — 前に作成した自己署名証明書を選択します。(自己署名証明書の生成手順を参照してください)。
  • 署名要求メソッド — [RSA-SHA-1] に設定します。
  • SAML ID 種別 — ユーザーをログインするために、Salesforce ユーザー名または統合 ID のいずれかと照合できます。 統合 ID と照合する場合、統合 ID がすべてのユーザーのプロファイルに入力されている必要があります。テストでは、統合 ID を選択します。 ユーザーが Salesforce ユーザー名としてメールアドレスを使用する場合は、本番リリースでユーザー名との照合に切り替えることができます。
  • SAML ID の場所 — ユーザーをログインするために、SAML アサーションの NameID か、別の属性を使用できます。AD FS では SAML アサーションに NameID が入力されるため、NameID を使用できます。
  • サービスプロバイダーの起動要求バインド — [HTTP リダイレクト] を選択することをお勧めします。
  • ID プロバイダーのログイン URL — AD FS SAML エンドポイントの URL を入力します。この URL に Salesforce から SP で開始されるログインへの SAML 要求が送信されます。
    メモ URL の末尾にスラッシュを追加してください。

    この URL は、AD FS MMC の [Endpoints (エンドポイント)] | [Token Issuance (トークンの発行)] | [Type:SAML 2.0/WS-Federation] にあります。この例では、URL は https://adfs.testzone.local/adfs/ls/ です。

  • カスタムログアウト URL — ログアウト後にユーザーがリダイレクトされる URL (例: http://intranet.mycompany.com/) を設定できます。
  • エンティティ ID — AD FS IdP が Salesforce SP を識別する方法を指定します。SP が開始する SSO を有効にするには、設定済みの [私のドメイン] からエンティティ ID を入力します。

設定を保存し、メタデータ XML ファイルをダウンロードします。

AD FS 2.0 設定

Salesforce のメタデータを入手できたので、AD FS 側の信頼関係を作成します。AD FS 2.0 MMC Snap-in を開き、新しい「証明書利用者信頼」を追加します。

  • Select Data Source (データソースを選択) — ファイルから証明書利用者に関するデータをインポートします。Salesforce からダウンロードした XML ファイルを参照します。
  • Specify Display Name (表示名) — 信頼の表示名を指定します (例: Salesforce Test)。
  • Choose Issuance Authorization Rules (発行承認ルールの選択) — すべてのユーザーにこの証明書利用者へのアクセスを許可します。
  • Open Edit Claim Rules Dialog (要求ルールの編集ダイアログを開く) — 選択します。

要求ルールエディターで、[Issuance Transform Rules (発行変換ルール)] タブをクリックします。[Send LDAP Attributes as Claims (LDAP 属性を要求として送信)] に設定した [Claim Rule Template (要求ルールテンプレート)] を使用してルールを追加します。

  • Claim Rule Name (要求ルール名) — テストでは、属性 User-Principal-Name に NameID が設定されるため、ルール名として「Send UPN as NameID」 (NameID として UPN を送信) を指定します。本番環境では、一般にユーザーのメールアドレスまたは従業員 ID を送信します。 属性の値が変わるとそのユーザーの SSO が無効になるため、将来的に値が変更される可能性が少ない属性を使用することが重要です。
  • LDAP Attribute (LDAP 属性) — [User Principal Name (ユーザープリンシパル名)] を選択します。
  • Outgoing Claim Type (送信要求種別) — [Name ID (名前 ID)] を選択します。

SP が開始するログイン

IdP が開始するログインプロセスでは、通常、会社のイントラネット上にリンクを設定し、ユーザーがそのリンクをクリックして Salesforce にアクセスできるようにします。SP が開始するログインプロセスは、ユーザーが Salesforce への直接リンクをクリックすると発生します。

Salesforce の SAML 設定に [私のドメイン] のエンティティ ID を設定すると (例: https://testinfo-developer-edition.my.salesforce.com)、ユーザーはそのドメインの URL に移動できます。その後、ユーザーは AD FS にリダイレクトされて認証されます。

Salesforce の SAML 設定に [私のドメイン] のエンティティ ID が設定されていると (例: https://testinfo-developer-edition.my.salesforce.com)、ユーザーはそのドメインの URL に移動できます。その後、ユーザーは AD FS にリダイレクトされて認証されます。

SP が開始するログインが機能するためには、AD FS のセキュアハッシュアルゴリズムパラメーターを SHA-1 に設定します。 Salesforce では SAML 要求への署名時に SHA-1 を使用しますが、AD FS のデフォルトは SHA-256 です。

SHA パラメーターは、AD FS で証明書利用者である Salesforce の信頼プロパティの [Advanced (詳細設定)] タブに設定します。

このパラメーターを設定しないと、AD FS イベントログにメッセージが表示されます。

Event ID: 378
SAML request is not signed with expected signature algorithm. SAML request is signed with signature algorithm http://www.w3.org/2001/04/xmldsig-more#rsa-sha256 . Expected signature algorithm is http://www.w3.org/2000/09/xmldsig#rsa-sha1

テスト

これで、Salesforce ユーザーの統合 ID に AD ユーザーアカウントの UPN を設定して、ログインプロセスをテストできます。

SP が開始するログインの場合、[私のドメイン] にエンティティ ID が設定されているという前提で、その URL を直接参照します (例: https://testinfo-developer-edition.my.salesforce.com)。

IdP が開始するログインの場合、AD FS ログイン URL を使用し、loginToRp パラメーターを Salesforce SAML エンティティ ID として指定します (例: https://adfs.testzone.local/adfs/ls/idpinitiatedsignon.aspx?loginToRp=https://saml.salesforce.com)。

どちらの場合でも、ブラウザーは一連のリダイレクトを行ってから、最終的に Salesforce 上のアプリケーションにログインします。Salesforce ログインエラーになった場合、Salesforce の SSO 設定ページの SAML アサーション検証ツールを使用します。ツールでは、最後に失敗した SAML ログインの結果が表示されます。

AD FS からエラーが返された場合、Server Manager\Diagnostics\Applications and Services Logs\AD FS 2.0\Admin にある AD FS ログを確認します。AD FS 2.0 の診断に関する MSDN のブログ記事も参考になります。

[私のドメイン] のエンティティ ID を設定している場合、SP が開始するログインはディープリンクに対応しています。Salesforce 内の深い階層からのリンクをブックマークして、ログアウトしてください。ブラウザーを再読み込みして、そのブックマークを選択します。IdP にリダイレクトされ、認証されて、ブックマークしたリンクに再度リダイレクトされます。

よくある問題とトラブルシューティング

  • 統合 ID の大文字と小文字が正しくない。

    統合 ID が組織のメールアドレスである場合、AD FS が送信するとおりに入力してください。そうしないと、Salesforce は一致するユーザーを検出できません。

    要求の言語では、基本的な正規表現の置換しか行われないため、LDAP 属性を送信する前に大文字と小文字を正規化するカスタム要求ルールを記述することはできません。

  • アサーションの期限が切れた。

    タイムスタンプから 5 分を経過したアサーションは拒否されます。

    メモ Salesforce では 3 分間のクロックスキューが許容されます。そのため、アサーションの有効期間は、タイムスタンプの 3 分前から 8 分後まで許容されます。また、アサーションは、有効期間 (5 分未満に設定可能) で指定されたとおりに期限切れになります。

    Network Time Protocol (NTP) を使用して、AD FS サーバーのシステムクロックが正しいインターネット時刻ソースと同期するようにしてください。

  • Salesforce にログインできない。

    エラーにより、SSO を介して Salesforce にログインできない場合でも、ユーザー名とパスワードを使用してログインできます。ログイン URL に「?login」を付加します (例: https://login.salesforce.com/?login)。ログイン後、この問題のトラブルシューティング中は必要に応じて SSO を無効にできます。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能には、証明書と鍵のペアも含まれます。証明書によって、Salesforce 組織と Accellion 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Accellion での SAML の設定

  1. Accellion の管理アカウントにログインします。
  2. メニューの [Administration (管理)] で [SSO] を選択します。
  3. ID プロバイダーの SAML 設定を編集します。
    • [email Attribute (メール属性)] に「Email」と入力します。
    • [Entity ID (エンティティ ID)] に「https://MyDomainName.my.salesforce.com」と入力します。
    • [Single Sign-On Service URL (シングルサインオンサービス URL)] に、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。
    • [Single Logout Service URL (シングルログアウトサービス URL)] に「https://MyDomainName.my.salesforce.com/secur/logout.jsp」と入力します。
    • [RSA Public Key Certificate (RSA 公開鍵証明書)] で、ダウンロードした Salesforce 証明書を選択します。
  4. 設定を保存します。
  5. Salesforce 接続アプリケーションの設定時に必要なサービスプロバイダー情報が表示されます。次の URL を保存します。
    • エンティティ ID。形式は https://domain_name/simplesaml/module.php/saml/sp/metadata.php/default-sp/3356 です。domain_name は各自の Accellion ドメインの名前です。たとえば、https://cloud-eval-hc2b.accellion.net/simplesaml/module.php/saml/sp/metadata.php/default-sp/3356 となります。
    • SAML アサーションコンシューマーサービスエンドポイント。形式は https://domain_name/simplesaml/module.php/saml/sp/saml2-acs.php/default-sp/3356 です。domain_name は各自の Accellion ドメインの名前です。たとえば、https://cloud-eval-hc2b.accellion.net/simplesaml/module.php/saml/sp/saml2-acs.php/default-sp/3356 となります。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

AgileApps Cloud での SAML の設定

  1. AgileApps Cloud アカウントに管理者としてログインします。
  2. [Settings (設定)]、[Administration (管理)]、[Account Management (アカウント管理)] の下で、[Single Sign-On Settings (シングルサインオン設定)] に移動します。
  3. [Single Sign-On Using (シングルサインオンに使用)] で [SAML] を選択します。
  4. ID プロバイダーの SAML 設定を指定します。
    1. [SAML version (SAML バージョン)] で 2.0 を選択します。
    2. [Issuer (発行者)] に「https://MyDomainName.my.salesforce.com」と入力します。たとえば、「https://identitydemo.my.salesforce.com」のように入力します。
    3. [User Id Type (ユーザー ID 種別)] で、ID の種別を選択します。たとえば、[Federated Id (統合 ID)] を選択します。
    4. [User Id Location (ユーザー ID の場所)] に、ユーザー ID の場所を定義する属性タグを入力します。たとえば、[件名] を選択します。
    5. [SAML Third Party authentication URL (SAML サードパーティ認証 URL)] に、ID プロバイダーエンドポイントを入力します (例: 「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」)。
    6. [Issuer Certificate (発行者証明書)] で、以前にダウンロードした Salesforce 証明書を参照して選択します。[アップロード] をクリックします。
    7. 設定を保存します。

    後ほど Salesforce で接続アプリケーションを設定するために使用する URL が表示されます。

    • Assertion Consumer Service EndPoint (アサーションコンシューマーサービスエンドポイント) — 接続アプリケーションを設定するときに、この URL を ACS URL として使用します。
    • Platform Authentication Service URL (プラットフォーム認証サービス URL) — 接続アプリケーションの開始 URL を設定するときに、この URL を開始 URL の最初の部分として使用します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. AgileApps Cloud 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで AgileApps Cloud アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「yourdomain.agileappscloud.com」と入力します。たとえば、「https://acme.agileappscloud.com」のように入力します。
    3. [ACS URL] に「https://yourdomain.agileappscloud.com/saml/ssoResponse」と入力します。たとえば、「https://acme.agileapps.com/access/saml」のように入力します。
    4. [件名種別] で、ID プロバイダーでユーザーを識別する方法 ([統合 ID] など) を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. AgileApps Cloud の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. 接続アプリケーションの開始 URL を作成します。
    1. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    2. 開始 URL の最初の部分には、AgileApps Cloud で SAML 設定を行ったときに表示されたプラットフォーム認証サービス URL を貼り付けます。
    3. プラットフォーム認証サービス URL に、パラメーター done= を追加します。たとえば、「https://acme.agileappscloud.com/networking/saml/ssoRequest?ticket=cfcflmhgbdh?done=」のように入力します。
    4. ユーザーが SSO 認証に成功した後に表示されるランディングページに移動します。
    5. ブラウザーのアドレスバーの URL の networking/ より後の部分をコピーします。
    6. この部分を done= パラメーターの引数として貼り付けます。たとえば、URL が https://acme.agileappscloud.com/networking/dashboard/1555611998oxd1878317529 の場合、dashboard/1555611998oxd1878317529 をコピーします。この例では、開始 URL 全体は、「https://acme.agileappscloud.com/networking/saml/ssoRequest?ticket=cfcflmhgbdh?done=dashboard/1555611998oxd1878317529」となります。
    7. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから [AgileApps Cloud] アプリケーションを見つけて開きます。接続アプリケーションに AgileApps Cloud のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

Salesforce から Amazon Web Services への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Amazon Web Services (AWS) にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Salesforce を AWS の ID プロバイダーとして設定するには、次の概要手順に従います。

  • SAML IdP 証明書の取得。
  • メタデータドキュメントのダウンロード
  • AWS での SAML プロバイダーの作成
  • Salesforce での接続アプリケーションの作成と設定

関連項目:

  • 接続アプリケーション

SAML IdP 証明書の取得

サービスプロバイダーの設定に使用するため、自己署名証明書または認証機関によって発行された証明書を取得します。証明書をローカルドライブに保存します。

メタデータドキュメントのダウンロード

  1. [設定] から、[クイック検索] ボックスに「ID」と入力し、[ID プロバイダー] を選択します。
  2. [メタデータのダウンロード] をクリックします。

同じページの [SAML のメタデータ検出エンドポイント] の下にある Salesforce ID (例: https://MyDomainName.my.salesforce.com/.well-known/samlidp.xml) を書き留めておきます。

AWS での SAML プロバイダーの作成

AWS の手順に従って、SAML ID プロバイダーを作成します。システム管理者として AWS コンソールにログインし、[Identity Providers] に移動してから、手順に従って SAML プロバイダーを作成します。AWS は、プロバイダーの Amazon リソースネーム (ARN) を生成します。後のステップで ARN が必要です。

  1. ローカルドライブからメタデータドキュメントをアップロードします。AWS が ID プロバイダーの ARN (例: arn:aws:iam::365652557137:saml-provider/salesforce) を生成します。ARN をローカルドライブに保存します。
  2. ユーザーに適したポリシーを持つ 1 つ以上のロールを作成します。各ロールについて、次の手順を実行します。
    1. ID プロバイダーアクセス用のロールを作成します。
    2. SAML プロバイダーに Web シングルサインオン (WebSSO) アクセス権を付与します。
    3. 目的の権限を設定します。
    4. ロールの ARN (例: arn:aws:iam::365652557137:role/SSOUserRole) を保存します。

Salesforce での接続アプリケーションの作成と設定

  1. [設定] から、[クイック検索] ボックスに「外部クライアントアプリケーション」と入力し、[外部クライアントアプリケーション] セクションの [設定] を選択します。
  2. [Allow create of connected apps (接続アプリケーションの作成を許可)] をオンにします (オフの場合)。
  3. [新規接続アプリケーション] をクリックします。
  4. 接続アプリケーションの設定を行います。[基本情報] で、アプリケーションに「Amazon Web Services」という名前を付け、独自のメールアドレスを入力します。
  5. [Web アプリケーション設定] で、次のように設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「https://signin.aws.amazon.com/saml」と入力します。
    3. [ACS URL] に「https://signin.aws.amazon.com/saml」と入力します。
    4. [件名種別] で、[永続 ID] を選択します。
    5. [名前 ID 形式] で、[urn:oasis:names:tc:SAML:2.0:nameid-format:persistent] を選択します。
    6. [発行者] は、デフォルト値であるサブドメインのままにします。
    7. [ID プロバイダーの証明書] 項目はデフォルト (選択されていない状態) のままにします。
    8. [要求署名を確認] はデフォルト (選択されていない状態) のままにします。
    9. [保存] をクリックします。
    メモ 接続アプリケーションが作成されるまでに数分かかることがあります。
  6. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
  7. [Amazon Web Services] をクリックします。接続アプリケーションの詳細ページが表示されます。
  8. [カスタム属性] で、[新規] をクリックしてカスタム属性を作成します。
    1. 属性キーに「https://aws.amazon.com/SAML/Attributes/RoleSessionName」と入力します。属性値に「$User.Email」と入力します。
    2. 次の属性キーに「https://aws.amazon.com/SAML/Attributes/Role」と入力します。属性値に「'arn:aws:iam::365652557137:role/SSOUserRole,arn:aws:iam::365652557137:saml-provider/salesforce'」と入力します。
      属性値は、ロールの保存済みの AWS ARN 値と IdP プロバイダーの ARN 値で、カンマで区切り、一重引用符で囲みます。
      ヒント Amazon ロールを使用してカスタムユーザー属性を選択リストとして作成すると、ユーザーのロールを動的に選択できます。
  9. 接続アプリケーションの開始 URL を設定します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] の下にある [Idp-init のログイン URL] をコピーします。
    2. [ポリシーを編集] をクリックします。
    3. [基本情報] の下にある [開始 URL] に Idp-init のログイン URL を貼り付けて [保存] をクリックします。
  10. [プロファイル] または [権限セット] の下で、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  11. アクセス権をテストするには、エンドユーザーとして接続アプリケーションを実行します。

Salesforce から BIME への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して BIME にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

BIME をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して BIME にアクセスできます。BIME は、ID プロバイダーによる SSO とサービスプロバイダーによる SSO の両方で、SAML プロトコルをサポートしています。

Salesforce から BIME への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

BIME での SAML の設定

  1. BIME アカウントに管理者としてログインします。
  2. [Admin (管理)] で [Account (アカウント)] を選択します。
  3. [Enable SAML authentication (SAML 認証の有効化)] を選択します。

  4. BIME で SAML の設定を行います。
    1. [Remote Login URL (リモートログイン URL)] に、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。
    2. [certificate fingerprint (証明書のフィンガープリント)] に、Salesforce 証明書の SHA1 フィンガープリント (またはサムネイル) を入力します。この値を取得するには、証明書ビューアーを使用して Salesforce 証明書を開きます。
  5. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. BIME 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで BIME アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「MyDomainName.bimeapp.com」と入力します。たとえば、「identitydemo.bimeapp.com」のように入力します。
    3. [ACS URL] に「https://MyDomainName.bimeapp.com/saml/consume」と入力します。たとえば、「https://identitydemo.bimeapp.com/saml/consume」のように入力します。
    4. 件名種別を選択します (例: [統合 ID])。件名種別は、BIME のユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性です。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. BIME の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付け、それに RelayState 属性を使用して SP のログイン URL の URL エンコードを追加します。たとえば、「https://MyDomainName.my.salesforce.com/idp/login?app=0spi00000008OJX&RelayState=https%3A%2F%2Fconnect5.acmegizmo.com%2Fsfidentity」のように入力します。
    4. 設定を保存します。

SSO 設定のテスト

  1. Salesforce で、アプリケーションランチャーから [BIME] アプリケーションを見つけて開きます。接続アプリケーションに BIME のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

  2. サービスプロバイダーによる SSO をテストするには、BIME アカウントにログインする URL を入力します。たとえば、「https://identitydemo.bimeapp.com」と入力します。SSO が適切に設定されていれば、SAML を使用してサインインするように促されます。SAML リンクをクリックすると、Salesforce にリダイレクトされ、そこでログイン情報を入力します。SSO 認証に成功すると、BIME アカウントにログインした状態になります。

Salesforce から Brainshark への SSO の設定

      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Brainshark の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。

    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

    1. [Enable SAML (SAML を有効化)] をクリックします。

    5. [Login URL (ログイン URL)] に、HttpRedirect エンドポイントを入力します (例: https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect)。
    6. [Logout URL (ログアウト URL)] に、ログアウト後にユーザーがリダイレクトされる URL を入力します (例: 「https://MyDomainName.my.salesforce.com/secur/logout.jsp」)。

      メモ この設定は省略可能ですが、セキュリティ上の理由からお勧めします。
    3. [SP-Initiated Auth Context (SP が開始する認証コンテキスト)] で、[Password Protected Transport (パスワードで保護された転送)] および [Minimum (最小)] を選択します。これらの設定では、認証コンテキストの方法と比較レベルを指定します。

Clarizen をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Clarizen にアクセスできます。Clarizen は、ID プロバイダーによる SSO で SAML プロトコルをサポートしています。

Salesforce から Clarizen への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Clarizen での SAML の設定

  1. SAML が有効化された管理者として、Clarizen アカウントにログインします。
  2. [Settings (設定)]、[Global Settings (グローバル設定)]、[Federated Authentication (統合認証)] で、SSO を有効にするために [Enable Federated Authentication (統合認証の有効化)] を選択します。
  3. Salesforce 証明書を選択してアップロードします。
  4. [Sign-in URL (サインイン URL)] に、ユーザーが認証のためにリダイレクトされるエンドポイントを入力します (例: 「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpPost」)。
  5. [Enable Password authentication (パスワード認証の有効化)] で、[Everyone (internal and external) (すべてのユーザー (内部および外部))] を選択します。
  6. ユーザーが Clarizen の API でアプリケーションにアクセスできるようにするには [Enable API access (API アクセスの有効化)] を選択します。
  7. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Clarizen 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Clarizen アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「Clarizen」と入力します。
    3. [ACS URL] に「https://app.clarizen.com/Clarizen/Pages/Integrations/SAML/SamlResponse.aspx」と入力します。
    4. [件名種別] で、ユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性を選択します ([統合 ID] など)。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Clarizen の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. [ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから [Clarizen] アプリケーションを見つけて開きます。接続アプリケーションに Clarizen のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

メモ Clarizen は、ID プロバイダーによる SSO のみをサポートしています。サービスプロバイダーによる SSO はサポートしていません。そのため、Clarizen ログインページに直接アクセスすると、認証のために Salesforce にリダイレクトされません。

    2. Dropbox の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。

Salesforce から Google Apps への SSO の設定

ID プロバイダーとして設定された Salesforce 組織で、ユーザーがシングルサインオン (SSO) を使用して Google Apps にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Salesforce を Google Apps の ID プロバイダーとして設定するには、次の概要手順に従います。

SAML IdP 証明書の取得

サービスプロバイダーの設定に使用するため、自己署名証明書または認証機関によって発行された証明書を取得します。

メタデータドキュメントのダウンロード

  1. [設定] から、[クイック検索] ボックスに「ID」と入力し、[ID プロバイダー] を選択します。
  2. [メタデータのダウンロード] をクリックします。

同じページの [SAML のメタデータ検出エンドポイント] の下にある Salesforce ID (例: https://MyDomainName.my.salesforce.com/.well-known/samlidp.xml) を書き留めておきます。

Google Apps での SAML プロバイダーの設定

  1. https://admin.google.com を使用して管理者として Google Apps アカウントにサインインします。
  2. シングルサインオンを設定する Google Apps ページに移動します。
  3. サインインページ URL として、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。
  4. サインアウトページ URL として、「https://MyDomainName.my.salesforce.com/」と入力します。
  5. パスワード変更 URL として、「https://MyDomainName.my.salesforce.com/_ui/system/security/ChangePassword」と入力します。
  6. 検証証明書として、先ほど取得した SAML IdP 証明書をアップロードします。
  7. [ドメイン固有の発行元を使用] を選択します。
  8. [変更を保存] をクリックします。

Salesforce での接続アプリケーションの作成と設定

  1. 接続アプリケーションを定義します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションを設定します。

    [基本情報] で、次のように設定します。

    1. アプリケーションに名前を付けます (たとえば Gmail など)。
    2. 自分のメールアドレスを入力します。

    [Web アプリケーション設定] で、次のように設定します。

    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「https://google.com」と入力します。
    3. [ACS URL] に、Google Apps アカウントの URL を入力します。
    4. [件名種別] で、Google Apps のユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性を設定します。たとえば、統合認証を使用する場合は、[統合 ID] を選択します。詳細は、「シングルサインオン実装のベストプラクティス」を参照してください。
    5. [保存] をクリックします。
    メモ 接続アプリケーションが作成されるまでに数分かかることがあります。
  3. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。

  4. [Gmail] をクリックします。
  5. [SAML ログイン情報] で、Idp-init のログイン URL をコピーします。

    1. [ポリシーを編集] をクリックします。
    2. [基本情報] の下にある [開始 URL] に Idp-init のログイン URL を貼り付けて、&RelayState=https%3A%2F%2Fmail.google.com%2Fa%2FyourGoogleAppDomainName という RelayState 文字列を追加します。

      次の例に示すように、yourGoogleAppDomainName を各自の Google ドメインに置き換えます。

      https://identitydemo.my.salesforce.com/idp/login?app=0sp30000000000k
&RelayState=https%3A%2F%2Fmail.google.com%2Fa%2Fidentitydemo.com
    3. [保存] をクリックします。
  6. [プロファイル] または [権限セット] の下で、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。

接続アプリケーションのテスト

Salesforce 組織が SSO を使用して接続アプリケーションにアクセスできることを確認します。

  1. Google Apps と Salesforce からログアウトします。
  2. http://mail.google.com/a/respond.info/ など、Google Apps ページへのアクセスを試みます。
  3. Salesforce サインオンページにリダイレクトされます。ログイン後は、指定した Google Apps ページに移動しています。

それ以外のテストとして、Salesforce 組織の Web タブに Google Apps を追加する方法があります。

  1. Salesforce にログインします。
  2. [設定] から、[クイック検索] ボックスに「タブ」と入力し、[タブ] を選択します。
  3. [Web タブ] の下で、[新規] をクリックします。
  4. タブレイアウトを選択し、[次へ] をクリックします。
  5. タブの表示ラベルを入力します。デフォルトの名前を使用します。これは表示ラベルと同じです。
  6. [タブスタイルの選択] を表示するには、[タブスタイル] ルックアップアイコンをクリックします。アイコンを選択します。その他はすべてデフォルトのままにします。
  7. [次へ] をクリックします。
  8. [ボタンまたはリンクの URL] テキストボックスに、Google Apps ページ (mail.google.com/a/respond.info/ など) を入力し、[次へ] をクリックします。
    メモ https:// で始まる絶対 URL を入力してください。
  9. [Next (次へ)] をクリックし、さらに [Save (保存)] をクリックします。
  10. 設定をテストするには、ページ上部の新しいタブをクリックします。Google Apps ページに自動的にログインします。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Intacct での SAML の設定

  1. Intacct アカウントに管理者としてログインします。
  2. [Company and Company Info (会社および会社情報)] で、[Single Sign On (シングルサインオン)] を選択します。
  3. [編集] をクリックします。
  4. [Single Sign On (シングルサインオン)] タブで [Single Sign On Enabled (シングルサインオンが有効)] を選択します。
  5. [SSO Identity Provider Type (SSO ID プロバイダー種別)] で、[SAML 2.0] を選択します。
  6. [SSO Issuer URL (SSO 発行者 URL)] に、このサービスプロバイダーの一意の ID を入力します。Salesforce 接続アプリケーションを設定するときには、この URL をエンティティ ID として入力します。
  7. [SSO Login URL (SSO ログイン URL)] に、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。
  8. Salesforce 証明書の [Begin Certificate (証明書開始)] 表示ラベルから [End Certificate (証明書終了)] 表示ラベルまでの内容をコピーして、[SSO Certificate (SSO 証明書)] に貼り付けます。
  9. 変更内容を保存します。

  10. [Company (会社)] タブで、[Users (ユーザー)] をクリックします。

  11. ユーザーの SSO を設定します。
    1. リストからユーザーを選択し、[Edit (編集)] をクリックします。

    2. ユーザー情報ページで [Single Sign On (シングルサインオン)] タブをクリックします。

    3. [Enable Single Sign On (シングルサインオンを有効化)] を選択します。

    4. [Federated SSO user id (統合 SSO ユーザー ID)] に、ユーザーを識別する値を入力します。この値は、Salesforce 接続アプリケーションで定義する件名種別に対応します。
    5. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Intacct 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Intacct アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの Web アプリケーション設定を行います。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、Intacct の SAML 設定で指定した SSO 発行者 URL を入力します (例: 「https://saml.intacct.com」)。
    3. [ACS URL] に、アサーションコンシューマーサービス URL を入力します (例: 「https://trial.intacct.com/ia/acct/sso_response.phtml」)。
    4. 件名種別を選択します (例: [ユーザー名])。件名種別は、Intacct の統合 SSO ユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Intacct の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

  1. Salesforce で、アプリケーションランチャーから [Intacct] アプリケーションを見つけて開きます。接続アプリケーションに Intacct のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。
  2. サービスプロバイダーによる SSO をテストするには、Intacct アカウントにログインする URL を入力します (例: 「https://trial.intacct.com/ia/acct/login.phtml?.sample=1&_company=Company_Id」)。Company_Id は Intacct の会社です。たとえば、「https://trial.intacct.com/ia/acct/login.phtml?.sample=1&_company=Sample+wwwzpcl」と入力します。SSO が適切に設定されていれば、SSO を使用するように促されます。[Use single sign on (シングルサインオンを使用)]、[Sign in (サインイン)] の順にクリックします。このアクションにより、Salesforce にリダイレクトされ、そこでログイン情報を入力します。SSO 認証に成功すると、Intacct アカウントにログインした状態になります。

Salesforce から Juniper Networks Instant Virtual Extranet への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Juniper Networks IVE にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Juniper をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Juniper にアクセスできます。Juniper は、ID プロバイダーによる SSO とサービスプロバイダーによる SSO の両方で、SAML プロトコルをサポートしています。

Salesforce から Juniper への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Juniper での SAML の設定

  1. SAML が有効化された管理者として、Juniper アカウントにログインします。
  2. [Authentication and Signing In (認証とサインイン)] で、サインイン SAML ページに移動します。
  3. Juniper で、Salesforce を ID プロバイダーとする SAML を設定するには、[Identity Provider (ID プロバイダー)] を選択します。
  4. Salesforce を SAML ピアとして追加するには、[Peer Service Provider Configuration (ピアサービスプロバイダー設定)] で [Add SP (SP を追加)] をクリックします。
  5. ピアサービスプロバイダーの設定を行います。
    1. [Entity ID (エンティティ ID)] に「https://saml.salesforce.com」と入力します。
    2. [Customize IdP Behavior (IdP 動作をカスタマイズ)] を選択します。
    • [Override Default Configuration (デフォルト設定を上書き)] を選択します。
    • [Accept unsigned AuthnRequest (未署名の AuthnRequest を受け入れる)] を選択します。
    • [Session Lifetime (セッションの有効期限)] で、[Role Based (ロールベース)] を選択します。
    • Salesforce が認証に使用するサインインポリシーを入力します。
    • [Subject Name Format (件名形式)] で、[Email Address (メールアドレス)] を選択します。
    • [Subject Name (件名)] で、ドメイン内のユーザーへのアクセスを制限するには、名前テンプレートの一部としてドメイン名を入力します。
  6. [Authentication and Signing In (認証とサインイン)] で、SAML ページに移動し、[New Metadata Provider (新規メタデータプロバイダー)] をクリックします。
  7. 認証サーバーの設定を行います。
    • [SAML Version (SAML バージョン)] で 2.0 を選択します。
    • [SA Entity Id (SA エンティティ ID)] に、Juniper エンティティの URL を入力します。
    • [Configuration Mode (設定モード)] で、[Metadata (メタデータ)] を選択します。
    • [ID プロバイダー Entity Id (ID プロバイダーのエンティティ ID)] に、https://MyDomainName.my.salesforce.com など、Salesforce Identity プロバイダーの URL を入力します。たとえば、「https://identitydemo.my.salesforce.com」のように入力します。
    • [ID Identity Provider Single SignOn Service URL (ID プロバイダーシングルサインオンサービス URL)] に、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。
    • [SSO Method (SSO メソッド)] で、[Post] を選択します。
    • 先にダウンロードしておいた Salesforce ID プロバイダーの証明書を選択します。
  8. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Juniper 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Juniper アプリケーションを表すロゴとアイコンをアップロードまたは指定します。
  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、Juniper エンティティの URL を入力します。たとえば、「https://connect5.acmegizmo.com/dana-na/auth/saml-endpoint.cgi?p=sp1」のように入力します。
    3. [ACS URL] に、Juniper アサーションカスタマーサービスの URL を入力します。たとえば、「https://connect5.acmegizmo.com/dana-na/auth/saml-consumer.cgi」のように入力します。
    4. [件名種別] で、[統合 ID] を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] は、デフォルト値のままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。
  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。

      Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。

      Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。

    2. Juniper の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を入力し、それに RelayState 属性を使用する SP のログイン URL の URL エンコードを追加します。たとえば、「https://MyDomainName.my.salesforce.com/idp/login?app=0spi00000008OJX&RelayState=https%3A%2F%2Fconnect5.acmegizmo.com%2Fsfidentity」のように入力します。
    4. 設定を保存します。

接続アプリケーションのテスト

  1. Salesforce で、アプリケーションランチャーから [Juniper] アプリケーションを見つけて開きます。接続アプリケーションに Juniper のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。
  2. サービスプロバイダーによる SSO をテストするには、Juniper Networks IVE ドメインにログインする URL を入力します。SSO が適切に設定されていれば、Salesforce 組織にログインするように促されます。Salesforce ログイン情報を使用してログインした後、Salesforce によって最初の要求 URL へリダイレクトされます。これで、Juniper アカウントにログインした状態になります。

Salesforce から LogMeIn GoToMeeting、GoToWebinar、GoToTraining への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して LogMeIn GoToMeeting、GoToWebinar、または GoToTraining にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

LogMeIn GoTo アプリケーションをサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用してそのアプリケーションにアクセスできます。GoToMeeting、GoToWebinar、および GoToTraining は、ID プロバイダーによる SSO で SAML プロトコルをサポートしています。

Salesforce からこれらの GoTo アプリケーションへの SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

組織の証明書およびその他の情報を LogMeIn に提供する手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [メタデータのダウンロード] をクリックします。
  3. Salesforce 自己署名証明書をファイルにダウンロードする場合は、[証明書のダウンロード] をクリックします。

LogMeIn での SAML の設定

  1. https://authentication.logmeininc.com/saml/settings.html にアクセスし、管理者としてログインします。
  2. SAML 設定ページで、メタデータをアップロードするか、手動で設定を行うことができます。
    1. メタデータを使用して設定を行うには、メタデータ URL を指定します。
    2. 手動で設定を行う手順は、次のとおりです。
      • サインアウトページ URL として、「https://MyDomainName.my.salesforce.com/secur/logout.jsp」と入力します。たとえば、「https://identitydemo.my.salesforce.com/secur/logout.jsp」のように入力します。
      • サインインページ URL として、「https://MyDomainName.my.salesforce.com/idp/endpoint/HttpRedirect」と入力します。たとえば、「https://identitydemo.my.salesforce.com/idp/endpoint/HttpRedirect」のように入力します。
      • Salesforce 証明書をアップロードするには、アップロードするファイルを参照して選択します。
  3. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. GoTo 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡できるようにメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで GoTo アプリケーションを表すロゴとアイコンをアップロードまたは指定します。
  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「https://authentication.logmeininc.com/saml/sp」と入力します。
    3. [ACS URL] を入力します。
      • GoToMeeting の場合、「https://authentication.logmeininc.com/saml/acs」と入力します。
      • GoToWebinar の場合、「https://authentication.logmeininc.com/saml/acs」と入力します。
      • GoToTraining の場合、「https://authentication.logmeininc.com/saml/acs」と入力します。

      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。

    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。

Salesforce から Marketo への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Marketo にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Marketo をサービスプロバイダーとして設定し、Salesforce で接続アプリケーションを作成すると、ユーザーは Salesforce ログイン情報を使用して Marketo にアクセスできます。Marketo は、ID プロバイダーによる SSO で SAML プロトコルをサポートしています。

Salesforce から Marketo への SSO を設定するには、次の概要手順に従います。

ID プロバイダーとしての Salesforce 組織の設定

[私のドメイン] 機能を使用すると、Salesforce 組織が ID プロバイダーとして有効になります。[私のドメイン] はすべての組織で必須です。組織の [私のドメイン] の名前が気に入らない場合、変更できます。

[私のドメイン] 機能では、証明書と鍵のペアも作成されます。証明書によって、Salesforce 組織と ADP 間の信頼が確立されます。必要に応じて、別の自己署名証明書を使用するか、CA 署名証明書をインポートすることができます。

Salesforce 自己署名証明書をダウンロードする手順は、次のとおりです。

  1. [設定] から、[クイック検索] ボックスに「ID プロバイダー」と入力し、[ID プロバイダー] を選択します。
  2. [証明書のダウンロード] をクリックします。

Marketo での SAML の設定

  1. Marketo アカウントに管理者としてログインします。
  2. [Admin and Integration (管理と統合)] で [Munchkin] をクリックします。
  3. Munchkin アカウント ID をコピーします。 この ID は、Salesforce で接続アプリケーションを設定するときに使用します。

  4. [Admin and Integration (管理と統合)] で [Single Sign-On (シングルサインオン)] をクリックします。
  5. [SAML Settings (SAML 設定)] で [Edit (編集)] をクリックします。
  6. [SAML Single Sign-On (SAML シングルサインオン)] で [Enabled (有効)] を選択します。
  7. [発行者 ID] に、[私のドメイン] のログイン URL を https://MyDomainName.my.salesforce.com 形式で入力します。
  8. [エンティティ ID] に、[私のドメイン] のログイン URL を https://MyDomainName.my.salesforce.com 形式で入力します。
  9. [User ID Location (ユーザー ID の場所)] で、[In Name identifier element of Subject (件名の名前 ID 要素)] を選択します。
  10. [Identity Provider Certificate (ID プロバイダー証明書)] に、Salesforce 証明書をアップロードします。

  11. 設定を保存します。
  12. [Redirect Pages (リダイレクトページ)] で、[Edit (編集)] をクリックします。
  13. [Logout URL (ログアウト URL)] を入力します (例: https://MyDomainName.salesforce.com)。ユーザーが Marketo からログアウトすると、この URL にリダイレクトされます。
  14. [Error URL (エラー URL)] を入力します (例: 「https://www.marketo.com/404」)。Marketo へのユーザーログインが失敗した場合、ユーザーはこの URL にリダイレクトされます。

  15. 設定を保存します。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. Marketo 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで Marketo アプリケーションを表すロゴとアイコンをアップロードまたは指定します。

  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「http://saml.marketo.com/sp」と入力します。
    3. [ACS URL] に、https://login.marketo.com/saml/assertion/Munchkin-Account-ID の形式で URL を入力します。Munchkin-Account-ID は先ほどコピーした値です。たとえば、「https://login.marketo.com/saml/assertion/903-GVU-861」のように入力します。
    4. [件名種別] で、ID プロバイダーでユーザーを識別する方法 ([統合 ID] など) を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] で、[urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress] を選択します。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。
      • Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
    2. Marketo の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. 接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

Salesforce で、アプリケーションランチャーから [Marketo] アプリケーションを見つけて開きます。接続アプリケーションに Marketo のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。

Mimeo に連絡して SAML 設定を取得

  • companyId

  1. Salesforce で接続アプリケーションを作成します。

    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に、SAML オーディエンス URL を入力します (例: 「Mimeo-Salepublications」)。
    3. [ACS URL] に、Mimeo の担当者から提供された URL を入力します。たとえば、「https://my.sandbox.mimeo.com/sso/authenticate.ashx」のように入力します。
    4. [件名種別] で、Mimeo のユーザー名を一意の Salesforce ユーザー ID に対応付けるメソッド属性を選択します。たとえば、[統合 ID] を選択します。
    5. [名前 ID 形式] は、デフォルトのままにします。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。

  4. 設定を保存します。
  5. Mimeo で Salesforce を ID プロバイダーとして使用するには、カスタム属性を設定する必要があります。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。
      • Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。

      • lastName、$User.LastName
      • IDPemail、$User.Email
      • companyName (Mimeo ドメイン名を入力します)

      • organizationId (Mimeo チームから提供された値を入力します)

  8. 接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、ID プロバイダーの起動によるログイン URL を貼り付けます (例: 「https://MyDomainName.my.salesforce.com/idp/login?app=0spR000000000Dg」)。
    4. 設定を保存します。

  8. SAML 接続をテストするには、[Test SAML Login (SAML ログインのテスト)] をクリックします。
  9. SAML が正しく設定されている場合は、アカウントで SAML SSO を有効にします。
  10. SAML SSO を有効にすると、SAML ログイン URL が生成されます (例: https://rpm.newrelic.com/accounts/224357/sso/saml/login)。この URL は、テストで使用できる、サービスプロバイダーによるログイン URL です。

Salesforce での接続アプリケーションの作成

  1. Salesforce で接続アプリケーションを作成します。
    • Lightning Experience では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーションマネージャー] を選択します。[新規接続アプリケーション] をクリックします。
    • Salesforce Classic では、[設定] から、[クイック検索] ボックスに「アプリケーション」と入力し、[アプリケーション] を選択します。[接続アプリケーション] で、[新規] をクリックします。
  2. 接続アプリケーションの [基本情報] を設定します。
    1. New Relic 接続アプリケーションの名前を入力します。Salesforce はこの名前を使用して API 参照名を入力します。
    2. Salesforce がアプリケーション提供者またはそのサポートチームに連絡が必要な場合に使用するメールアドレスを入力します。
    3. 必要に応じて、Salesforce アプリケーションランチャーで New Relic アプリケーションを表すロゴとアイコンをアップロードまたは指定します。
  3. 接続アプリケーションの [Web アプリケーション設定] を設定します。
    1. [SAML の有効化] を選択します。
    2. [エンティティ ID] に「http://rpm.newrelic.com」と入力します。
    3. [ACS URL] に New Relic SAML 設定で表示された URL を入力します (例: 「https://rpm.newrelic.com/accounts/yourAccountID/sso/saml/finalize」)。yourAccountID は New Relic アカウントです。たとえば、「https://rpm.newrelic.com/accounts/223456/sso/saml/finalize」のように入力します。
    4. [件名種別] で、ID プロバイダーでユーザーを識別する方法 ([統合 ID] など) を選択します。統合 ID は、複数の Web サービスおよび Salesforce 組織のユーザーに割り当てられる一意の値です。
    5. [名前 ID 形式] で、[urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress] を選択します。
    6. [発行者] は、デフォルト値である [私のドメイン] ログイン URL のままにします。
    7. [IdP 証明書] は、デフォルト (デフォルトの IdP 証明書) のままにします。
  4. 設定を保存します。
  5. 接続アプリケーションのプロファイルと権限セットを設定します。
    1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。

      Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。

      Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。

    2. New Relic の接続アプリケーションの名前をクリックします。接続アプリケーションの詳細ページが表示されます。
    3. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルまたは権限セットを追加します。
  6. Salesforce で、接続アプリケーションの開始 URL を入力します。
    1. 接続アプリケーションの詳細ページで、[SAML ログイン情報] にある Idp-init のログイン URL をコピーします。
    2. 接続アプリケーションの詳細ページで、[ポリシーを編集] をクリックします。
    3. [開始 URL] に、Idp-init のログイン URL を貼り付けます。
    4. 設定を保存します。

SSO 設定のテスト

  1. Salesforce で、アプリケーションランチャーから [New Relic] アプリケーションを見つけて開きます。接続アプリケーションに New Relic のロゴとアイコンを設定してある場合は、アプリケーションランチャーに表示されます。ID プロバイダーの SSO が適切に設定されていれば、Salesforce でアプリケーションセッションが作成されます。
  2. サービスプロバイダーによる SSO をテストするには、サービスプロバイダーによるログイン URL を入力します (例: 「https://rpm.newrelic.com/accounts/yourAccountID/sso/saml/login」)。yourAccountID は New Relic アカウントです。たとえば、「https://rpm.newrelic.com/accounts/224357/sso/saml/login」のように入力します。SSO が適切に設定されていれば、Salesforce 組織にログインするように促されます。ログイン情報を入力すると、Salesforce によって最初の要求 URL へリダイレクトされます。これで、New Relic アカウントにログインした状態になります。

Salesforce から Office 365 への SSO の設定

ID プロバイダーとして設定された Salesforce 組織からシングルサインオン (SSO) を使用して Office 365 にログインできるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience および Salesforce Classic
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

Salesforce を Office 365 の ID プロバイダーとして設定するには、次の概要手順に従います。

  • Salesforce で、SSL 証明書を取得します。
  • Office 365 で、ドメインの Salesforce ID 情報を設定します。
  • Salesforce で、Office 365 を Salesforce 内で実行する接続アプリケーションを作成および設定します。

手順を完了するには次が必要です。

  • Office 365 の管理者アカウント
  • Azure Active Directory 用の Windows PowerShell

関連項目:

  • 接続アプリケーション

SAML IdP 証明書の取得

サービスプロバイダーの設定に使用するため、自己署名証明書または認証機関によって発行された証明書を取得します。証明書をローカルドライブに保存します。

メタデータドキュメントのダウンロード

  1. [設定] から、[クイック検索] ボックスに「ID」と入力し、[ID プロバイダー] を選択します。
  2. [メタデータのダウンロード] をクリックします。

同じページの [SAML のメタデータ検出エンドポイント] の下にある Salesforce ID (例: https://MyDomainName.my.salesforce.com/.well-known/samlidp.xml) を書き留めておきます。

ドメインの Salesforce ID 情報の設定

  1. Windows PowerShell 用 Windows Azure Active Directory モジュールを起動します。
  2. $cred=Get-Credential cmdlet を実行し、管理者アカウントの Windows Azure AD ログイン情報を入力します。 
    PS C:\Windows\system32> $cred=Get-Credential
Cmdlet Get-Credential at command pipeline position 1
Supply values for the following parameters:
Credential
  3. Connect-MsolService –Credential $cred を実行します。 
    PS C:\Windows\system32> Connect-MsolService –Credential $cred
  4. 必須のパラメーター値を入力します。
    • ドメインの例: $dom = salesidentity.info
    • Salesforce IdP のエンドポイント URL の例: $url = https://MyDomainName.my.salesforce.com/idp/endpoint/HttpPost
    • IdP 発行者の例: $uri = https://MyDomainName.my.salesforce.com
    • IdP ログアウト URL の例: $logouturl = https://MyDomainName.my.salesforce.com
    • IdP 証明書の例: $cert = <your certificate content>
    メモ 証明書は、改行せずに 1 行に入力します。
    PS C:\Windows\system32> $dom = salesidentity.info
PS C:\Windows\system32> $url = https://MyDomainName.my.salesforce.com/idp/endpoint/HttpPost
PS C:\Windows\system32> $uri = https://MyDomainName.my.salesforce.com
PS C:\Windows\system32> $logouturl = https://MyDomainName.my.salesforce.com
PS C:\Windows\system32> $cert = <your certificate content>
  5. Set-MsolDomainAuthentication –DomainName $dom -FederationBrandName $dom -Authentication Federated -PassiveLogOnUri $url -SigningCertificate $cert -IssuerUri $uri -LogOffUri $logouturl -PreferredAuthenticationProtocol SAMLP cmdlet を実行して信頼を確立します。 
    PS C:\Windows\system32> Set-MsolDomainAuthentication 
–DomainName $dom -FederationBrandName $dom -Authentication 
Federated -PassiveLogOnUri $url -SigningCertificate $cert 
-IssuerUri $uri -LogOffUri $logouturl 
-PreferredAuthenticationProtocol SAMLP
  6. Get-MsolDomain cmdlet を実行して、フェデレーションの取得が有効かどうかを確認します。 
    Name							Status	Authentication
----							------	--------------
salesforceidentity.info			Verified	Federated
sfidentity.mail.onmicrosoft.com		Verified	Managed
sfidentity.onmicrosoft.com			Verified	Managed
  7. Get-MsolDomainFederationSettings cmdlet を実行して設定を確認します。

Salesforce での接続アプリケーションの作成と設定

  1. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
  2. [基本情報] で、次のように設定します。
    1. アプリケーションに「Office 365」と名前を付けます。
    2. 自分のメールアドレスを入力します。
  3. [Web アプリケーション設定] で、次のように設定します。
    1. [開始 URL] に、URL を入力し、ドメイン名の URL を含めます。 
      https://login.microsoftonline.com/PostToIDP.srf?msg=AuthnReq&realm=
MyDomainName.my.salesforce.com&wa=wsignin1.0&wtrealm=urn:federation:MicrosoftOnline&
wctx=bk%3D1367916313%26LoginOptions%3D3
    2. [SAML の有効化] を選択します。
    3. [エンティティ ID] に「urn:federation:MicrosoftOnline」と入力します。
    4. [ACS URL] に「https://login.microsoftonline.com/login.srf」と入力します。
    5. [件名種別] で、[FederationID] または [カスタム] 属性を選択します。
      メモ 件名種別には、UPN の ObjectGUID が使用されます。
    6. [名前 ID 形式] は、デフォルトの選択 (未指定) のままにします。
    7. [発行者] は、デフォルト値 (サブドメイン) のままにします。
    8. [要求署名を確認] はデフォルト (選択されていない状態) のままにします。
    9. [ID プロバイダーの証明書] は、デフォルト (選択されていない状態) のままにします。
    10. [保存] をクリックします。
    メモ 接続アプリケーションが作成されるまでに数分かかることがあります。
  4. [設定] から、[クイック検索] ボックスに「アプリケーション」と入力します。Lightning Experience を使用している場合は、[接続アプリケーションを管理する] を選択します。Salesforce Classic を使用している場合は、[アプリケーションを管理する] で [接続アプリケーション] を選択します。
  5. [Office 365] 接続アプリケーションを選択します。
  6. [プロファイルを管理する] または [権限セットの管理] をクリックし、このアプリケーションにアクセスできるユーザーのプロファイルおよび権限セットを追加します。
  7. [カスタム属性] で、[新規] をクリックします。
    1. 属性キーに「IDPEmail」、属性値に「$User.Email」と入力します。
    2. [保存] をクリックします。
  8. アクセス権をテストするには、ユーザーとして接続アプリケーションを実行します。
