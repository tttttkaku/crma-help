メッセージ画面コンポーネントを使用したユーザーの最新情報の入手

画面フローを使用して取引先責任者と会社の情報を収集し、自動起動フローをコールして取引先レコードと取引先責任者レコードを作成します。メッセージ画面コンポーネントを使用して、新しいレコードに関するメッセージを実行ユーザーに表示します。次に、取引先責任者にメールを送信します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
メモ 「フローの管理」権限を持つ管理者である必要はありません。プロファイルまたは権限セットに追加するようにシステム管理者に依頼してください。
重要 Salesforce からメールを送信するには、Salesforce フローの [メールを送信] アクションでドメインレベルとユーザーレベルのメール検証が必要です。ユーザーのメールアドレスまたはメール送信ドメインが検証されていない場合、メールの送信は失敗します。「Requirements to Send Email from Salesforce」を参照してください。

取引先と取引先責任者を作成する自動起動フローの作成

取引先責任者と会社情報を入力として受け入れ、取引先レコードを作成してから、関連する取引先責任者レコードを作成する自動起動フローを作成します。

  1. [フロー] リストビューを開きます。
    • Automation アプリケーションから、[フロー] タブを選択します。
    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。
    [オートメーションアプリケーション] および [フロー] タブのオプションには、[設定] アクセス権は必要ありません。
  2. 自動起動フローを作成します。
    • 自動化アプリケーションから、[New | Autolaunch Automations | Autolaunch Flow (No Trigger) (新規自動起動オートメーション自動起動フロー (トリガーなし))] をクリックします。
    • [設定] から、[New Flow | Autolaunch Automations | Autolaunch Flow (No Trigger)] をクリックします。
    Flow Builder で新しい自動起動フローが開きます。
  3. 画面フローから収集した取引先責任者および会社情報を保存する入力変数を作成します。
    1. ツールボックスを開くには、[] をクリックします。
    2. [新規リソース] をクリックし、[変数] を選択します。
    3. [API 参照名] に「firstName」と入力します。
    4. [データ型] で [テキスト] を選択します。
    5. [入力で使用可能] を選択します。
    6. [完了] をクリックします。
    7. ステップ 3 ～ 6 を繰り返して、データ型テキストで次の追加の入力変数を作成します: lastName、email、phone、company。
  4. 画面フローに送信する新しい取引先責任者の ID を保存する出力変数を作成します。
    1. ツールボックスを開くには、[] をクリックします。
    2. [新規リソース] をクリックし、[変数] を選択します。
    3. [API 参照名] に「contactId」と入力します。
    4. [データ型] で [テキスト] を選択します。
    5. [出力で使用可能] を選択します。
    6. [完了] をクリックします。
  5. [レコードを作成] 要素を使用して取引先レコードを作成します。
    1. キャンバスで、[] をクリックし、[レコードを作成] を選択します。
      [レコードを作成] パネルが開きます。
    2. [表示ラベル] に「Create Account」 (アカウントの作成) と入力します。
      API 参照名を自動入力します。
    3. [説明] に「Creates a new account record using the Company input variable」 (会社の入力変数を使用して新規取引先レコードを作成します) と入力します。
    4. [レコードフィールド値の設定方法] で、[手動] を選択します。
    5. [オブジェクト] で [取引先] を選択します。
      [取引先名] 項目が [取引先の項目値を設定] に追加されます。
    6. [値] で、会社変数を選択します。
  6. [レコードを作成] 要素を使用して取引先責任者レコードを作成します。
    1. [] をクリックし、[レコードを作成] を選択します。
      [レコードを作成] パネルが開きます。
    2. [表示ラベル] に「Create Contact」 (取引先責任者の作成) と入力します。
      API 参照名を自動入力します。
    3. [説明] に「Creates a new contact record associated with the newly created account」と入力します。
    4. [レコードフィールド値の設定方法] で、[手動] を選択します。
    5. [オブジェクト] で [取引先責任者] を選択します。
      [姓] 項目が [取引先責任者の項目値を設定] に追加されます。
    6. [値] で、lastName 変数を選択します。
    7. ［+ Add Field］ をクリックします。
    8. [項目] で、[名] を選択します。
    9. [値] で、firstName 変数を選択します。
    10. ［+ Add Field］ をクリックします。
    11. [項目] で、[メール] を選択します。
    12. [値] で、email 変数を選択します。
    13. ［+ Add Field］ をクリックします。
    14. [項目] で、[携帯電話] を選択します。
    15. [値] で、電話変数を選択します。
    16. ［+ Add Field］ をクリックします。
    17. 項目で 取引先 ID を選択します。
    18. [値] で、accountId 変数を選択します。
    19. [Manually assign variables (advanced) (変数の手動割り当て (詳細))] を選択します。
    20. [変数に取引先責任者 ID を保存] セクションで、[変数] に [contactId] を選択します。
      これにより、新しい取引先責任者の ID が contactId 変数に保存されます。
  7. 自動起動フローを保存します。
    1. [保存] をクリックします。
    2. [フローの表示ラベル] に「Create Account and Contact」と入力します。
      フロー API 参照名は自動入力されます。
    3. [説明] に「Creates an account and a associated contact from input variables」 (入力変数から取引先および関連付けられた取引先責任者を作成する) と入力します。
    4. [保存] をクリックします。
  8. フローをテストします。
    1. [デバッグ] をクリックします。
    2. 会社、メール、名、姓のテストデータを入力します。
    3. [実行] をクリックします。
    4. 各要素の詳細を展開し、フローが期待どおりに動作することを確認します。
  9. フローを有効化します。
    1. [有効化] をクリックします。

自動起動フローをコールするアクションボタンを含む画面フローの作成

参照コンポーネント、入力項目、および [取引先と取引先責任者を作成] 自動起動フローをコールする画面アクションをトリガーするアクションボタンを使用して、画面フローを作成します。ユーザーは既存の取引先責任者を検索し、見つからない場合は、取引先責任者および関連付けられた取引先を作成できます。

  1. [フロー] リストビューを開きます。
    • Automation アプリケーションから、[フロー] タブを選択します。
    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。
    [オートメーションアプリケーション] および [フロー] タブのオプションには、[設定] アクセス権は必要ありません。
  2. 画面フローを作成します。
    • 自動化アプリケーションで、[新規 | 画面の自動化 | 画面フロー] の順にクリックします。
    • [設定] から、[新規フロー | 画面の自動化 | 画面フロー] をクリックします。
    Flow Builder で新しい画面フローが開きます。
  3. 画面要素を追加します。
    1. キャンバスで、[] をクリックし、[画面] を選択します。
      [画面] パネルが開きます。
    2. [表示ラベル] に「Collect Contact and Company Information」と入力します。
      API 参照名を自動入力します。
    3. [フッターを設定] セクションを開きます。
    4. [次へ] または [完了ボタン] で、[カスタム表示ラベルを使用] を選択します。
    5. [次へ] または [完了] ボタンの表示ラベルに「完了」と入力します。
    6. [完了] をクリックします。
  4. ルックアップコンポーネントを画面に追加します。
    1. [Components (コンポーネント)] リストで、[Lookup (参照)] をクリックします。
      ルックアップコンポーネントが画面に追加されます。
    2. [Field API Name (項目 API 参照名)] に「ContactId」と入力します。
    3. [API 参照名] に「ContactLookup」と入力します。
    4. [表示ラベル] に「Select Existing Contact」と入力します。
    5. [オブジェクト API 参照名] に「Case」と入力します。
      参照コンポーネントは、指定したオブジェクトの参照項目を模倣します。このフローの組織にはケースオブジェクトの取引先責任者オブジェクトへの参照項目があるため、ここではケースオブジェクトを使用します。
  5. 画面にチェックボックスコンポーネントを追加します。
    1. [コンポーネント] リストで、[チェックボックス] をクリックします。
    2. [表示ラベル] に「Create new contact？」 (新規取引先責任者の作成?) と入力します。
      API 参照名を自動入力します。
  6. [名前] コンポーネントを画面に追加します。
    1. [Components (コンポーネント)] リストで、[Name (名前)] をクリックします。
    2. [API 参照名] に「Name」と入力します。
    3. [コンポーネントの表示を設定] セクションを開きます。
    4. [コンポーネントを表示するタイミング] で、[すべての条件に一致 (AND)] を選択します。
      条件ウィンドウが開きます。
    5. [Resource (リソース)] で、[Collect Contact and Company Information | Create new contact (取引先責任者と会社情報を収集する)] をクリックします。
    6. [演算子] で [次の文字列と一致する] を選択します。
    7. [値] で、[True] を選択します。
      これにより、[新規取引先責任者を作成しますか?] チェックボックスがオンの場合にのみコンポーネントが表示されるように設定されます。
  7. 取引先責任者の会社を収集する画面にテキストコンポーネントを追加します。
    1. [Components (コンポーネント)] メニューで、[Text (テキスト)] をクリックします。
    2. [表示ラベル] に「Company」と入力します。
      API 参照名は自動入力されます。
    3. [コンポーネントの表示を設定] セクションを開きます。
    4. [コンポーネントを表示するタイミング] で、[すべての条件に一致 (AND)] を選択します。
      条件ウィンドウが開きます。
    5. [Resource (リソース)] で、[Collect Contact and Company Information | Create new contact (取引先責任者と会社情報を収集する)] をクリックします。
    6. [演算子] で [次の文字列と一致する] を選択します。
    7. [値] で、[True] を選択します。
  8. メールコンポーネントを画面に追加します。
    1. [Components (コンポーネント)] リストで、[Email (メール)] をクリックします。
    2. [API 参照名] に Email と入力します。
    3. [コンポーネントの表示を設定] セクションを開きます。
    4. [コンポーネントを表示するタイミング] で、[すべての条件に一致 (AND)] を選択します。
      条件ウィンドウが開きます。
    5. [Resource (リソース)] で、[Collect Contact and Company Information | Create new contact (取引先責任者と会社情報を収集する)] をクリックします。
    6. [演算子] で [次の文字列と一致する] を選択します。
    7. [値] で、[True] を選択します。
  9. 電話コンポーネントを画面に追加します。
    1. [Components (コンポーネント)] リストで、[電話(Phone)] をクリックします。
    2. [API 参照名] に「Phone」と入力します。
    3. [コンポーネントの表示を設定] セクションを開きます。
    4. [コンポーネントを表示するタイミング] で、[すべての条件に一致 (AND)] を選択します。
      条件ウィンドウが開きます。
    5. [Resource (リソース)] で、[Collect Contact and Company Information | Create new contact (取引先責任者と会社情報を収集する)] をクリックします。
    6. [演算子] で [次の文字列と一致する] を選択します。
    7. [値] で、[True] を選択します。
  10. [アクションボタン] コンポーネントを画面に追加します。ユーザーはこのコンポーネントをクリックして、新しい取引先と取引先責任者を作成する自動起動フローをコールする画面アクションを実行できます。
    1. [コンポーネント] リストで、[アクションボタン] をクリックします。
    2. [表示ラベル] に「Create」と入力します。
    3. [API 参照名] に「CreateNewAccountContact」と入力します。
    4. [フロー] で、[Create Account and Contact (取引先と取引先責任者の作成)] を選択します。
      このフローは、作成した自動起動フローです。
      [画面アクションを設定] パネルが開きます。
    5. [API 参照名] が自動入力されない場合、[API 参照名] に「Create_Account_and_Contact」と入力します。
  11. 画面コンポーネントの値を自動起動フローに渡すように画面アクションの入力を設定します。
    1. [入力値を設定] セクションで、ボタンをクリックしてすべての入力を含めます。
    2. company の場合、Collect Contact and Company Information | Company をクリックします。
    3. メールの場合は、[Collect Contact and Company Information | Email | Value (取引先責任者および会社情報のメール値を収集する)] をクリックします。
    4. firstName で、Collect Contact and Company Information | Name | First Name をクリックします。
    5. lastName で、Collect Contact and Company Information | Name | Last Name をクリックします。
    6. phone の場合は、Collect Contact and Company Information | Phone | Value をクリックします。
    7. [コンポーネントの表示を設定] セクションを開きます。
    8. [コンポーネントを表示するタイミング] で、[すべての条件に一致 (AND)] を選択します。
      条件ウィンドウが開きます。
    9. [リソース] で [Collect Contact and Company Information (取引先責任者および会社情報を収集)] をクリックし、[Create new contact? (新規取引先責任者を作成しますか?)] をクリックします。
    10. [演算子] で [次の文字列と一致する] を選択します。
    11. [値] で、[True] を選択します。
      これにより、ユーザーが取引先責任者の作成を希望していることを示した場合にのみアクションボタンが表示されるように設定されます。
    アクションボタンは、クリックしたときに自動起動フローをコールし、画面入力コンポーネントから値を渡するように設定されました。
  12. メッセージコンポーネントを画面に追加して、新規取引先責任者に加えて取引先も作成されることをユーザーに通知します。
    1. [Components (コンポーネント)] リストで、[Message (メッセージ)] をクリックします。
    2. [メッセージ] コンポーネントを画面の上部にドラッグします。
    3. [API 参照名] に「InfoMessage」と入力します。
    4. [メッセージ種別] で、[情報] を選択します。
    5. [メッセージコンテンツ] に「A new account will be created for the contact using the Company field」と入力します。
    6. [コンポーネントの表示を設定] セクションを開きます。
    7. [コンポーネントを表示するタイミング] で、[すべての条件に一致 (AND)] を選択します。
      条件ウィンドウが開きます。
    8. [リソース] で、[Collect Contact and Company Information | Create new contact (取引先責任者と会社情報を収集する)] をクリックします。
    9. [演算子] で [次の文字列と一致する] を選択します。
    10. [値] で、[True] を選択します。
      これにより、[新規取引先責任者を作成しますか?] チェックボックスがオンの場合にのみ表示されるメッセージコンポーネントが設定されます。
    11. [+ 条件を追加] をクリックします。
    12. [リソース] で、 [ Collect Contact and Company Information | Create Account and Contact (画面アクション) | Results | contactId(取引先責任者 ID)] をクリックします。
    13. [演算子] で [null] を選択します。
    14. [値] で、[True] を選択します。
      これにより、画面アクションが実行されておらず、結果がない場合にのみメッセージコンポーネントも表示されます。
    15. [+ 条件を追加] をクリックします。
    16. [Resource (リソース)] で、[Collect Contact and Company Information | Create Account and Contact ( | In Progress (取引先責任者および会社情報の取得と取引先責任者の作成 (処理中))] をクリックします。
    17. [演算子] で [次の文字列と一致する] を選択します。
    18. [値] で、[False] を選択します。
      これにより、画面アクションが現在実行されていない場合にのみメッセージコンポーネントも表示されます。
  13. レコードが作成されたことをユーザーに通知するために、別のメッセージコンポーネントを画面に追加します。
    1. [Components (コンポーネント)] リストで、[Message (メッセージ)] をクリックします。
    2. [メッセージ] コンポーネントを画面の上部にドラッグします。
    3. [API 参照名] に「SuccessMessage」と入力します。
    4. [メッセージ種別] で、[成功] を選択します。

HTTP コールアウトアクションを使用した外部在庫の管理の例

この例では、ストアの在庫レベルを確認し、在庫が少なくなったときにサプライヤーの API に HTTP コールアウトして注文を実行します。

必要なエディション

使用可能なインターフェース: Lightning Experience
サポートされているエディションを表示する。
必要なユーザー権限
Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
外部ログイン情報、指定ログイン情報、HTTP コールアウトアクションを作成する 「アプリケーションのカスタマイズ」

サプライヤーの注文システムと統合してリアルタイムで注文できるようにすることで、ペットショップの在庫管理を容易にするとします。在庫レベルを確認し、在庫レベルが少なくなったらサプライヤーの API へのコールをトリガーするフローを作成します。[Submit Order (注文を送信)] をクリックすると、注文を自動的に実行するリアルタイム API コールが表示されます。

HTTP コールアウトアクションを設定する前に、次の手順を実行します。

  • 外部サービスが API に接続できるように外部ログイン情報と指定ログイン情報を作成します。「Guidelines for Authenticating HTTP Callout Actions (HTTP コールアウトアクションの認証に関するガイドライン)」を参照してください。この例では、外部ログイン情報は PetStore、指定ログイン情報は Acme Pet Supplies です。
  • JSON 形式で API 応答のサンプルを準備します。API のドキュメントにサンプルが存在しない場合は、サードパーティ API プラットフォームを使用して応答を取得できます。この例では、使用されるサンプル API 応答を次に示します。
    {
  "id": 0,
  "petId": 0,
  "quantity": 0,
  "shipDate": "2024-10-09T08:49:33.605Z",
  "status": "placed",
  "complete": true
}
  • まず、十分に文書化されている API を使用します。項目の要件や定義などの詳細が不正確であるか、または古い場合は、デバッグに時間がかかることがあります。
  1. [フロー] リストビューを開きます。
    • Automation アプリケーションから、[フロー] タブを選択します。
    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。

自動レイアウトとは?

自動レイアウトモードは、キャンバスをすっきりと整理したフローを作成するための合理化された環境です。キャンバス上の任意の場所に要素をドラッグ & ドロップする自由形式の構築とは異なり、自動レイアウトでは構造化された線形パスに要素が自動的に配置されます。これにより、フローロジックに従いやすくなり、整理されたクリーンなキャンバスを維持できます。自動レイアウトは、Flow Builder のデフォルトモードです。

メモ 自動レイアウトモードでは、変更が自動的にドラフトフローに保存されます。変更を永続的にするには、Flow Builder でフローのウィンドウを閉じる前にフローを保存します。

自動レイアウトには、フローを効率的に作成するための次の要素管理機能が用意されています。

  • 要素の追加 - 新しい要素をフローに挿入して自動化ロジックを構築します。
  • 要素を編集 - 既存の要素設定を変更して、フローの動作を調整します。
  • 要素をコピー - 要素を複製して設定を再利用し、時間を節約
  • 要素を移動 - フロー内の要素を再配置してロジックを再編成
  • 要素の削除 - フローで不要になった要素を削除します。
  • 自動レイアウトでの要素の追加
    自動レイアウトモードで要素をフローに追加して、自動化を構築します。
  • 自動レイアウトの要素の編集
    フローの既存の要素を変更して、設定または動作を更新します。
  • 自動レイアウトの要素のコピー
    フロー内の要素を複製して、オートメーションの他の部分で再利用します。
  • 自動レイアウトでの要素の移動
    フロー内の要素を再配置して、フローロジックを再編成し、読みやすくします。
  • 自動レイアウトの要素の削除
    オートメーションで不要になった要素をフローから削除します。
  • 自動レイアウトでのフロー要素のグループ化
    関連するフロー要素を名前付き折りたたみ可能なセクションに整理して、複雑なフローのナビゲーションと管理を容易にします。

HTTP コールアウトを使用するときは、次の考慮事項と制限に留意してください。

必要なエディション

考慮事項

  • 同じデータ型の項目のリストが含まれる JSON 応答がサポートされます。たとえば、[1, 2, 3, 4] は同じデータ型の数値のリストです。一方、[“one”, 2, “three”, “four”] では、2 は数値で他は文字列であるため、同じデータ型ではありません。
  • HTTP コールアウトからの空の応答を適切に処理するには、空の文字列{}ではなく、空の JSON オブジェクトまたは空の JSON 配列[]""を使用します。
  • 列挙データ型はサポートされません。たとえば、[承諾済み] と [却下済み] の有限の値を持つ [状況] 項目が API に含まれている場合、Flow Builder ではそれらの値は複数選択リストとして表示されません。その代わりに、[状況] 項目が文字列データ型として推定され、コールアウト応答には 1 つの値が含まれます。「列挙」を参照してください。
  • float 型と long データ型はサポートされません。設定中に提供された API 応答に float 型と long データ型の項目が含まれている場合は、データ型を integer 型または double 型に設定できます。
  • グローバル差し込み項目をサポートする認証を設定する場合は、指定ログイン情報にヘッダーを含めます。呼び出し可能なアクションではなく、コールアウトの URL エンドポイントでヘッダーを設定します。
  • 要求ヘッダーはサポートされません。代わりに、ヘッダーをログイン情報の一部として設定するか、外部サービスで OpenAPI 仕様を手動で更新できます。これにより、HTTP コールアウトが標準外部サービスに変換されます。
  • 外部サービスアクションをコールアウトすると、300 以上の応答状況コードがエラーとして返されます。障害パスを使用して、アクションからのエラーを処理します。たとえば、障害パスからエラーメッセージを取得してユーザーに表示できます。
  • API のプロパティ名が Apex の予約キーワードと競合する場合、外部サービスはその名前をエンコードして Apex と互換性があるようにします。エンコードされた名前は、元の名前ではなく、Flow Builder に表示される可能性があります。コールアウト時に、外部サービスは元の名前を使用します。詳細は、「Apex 予約キーワード」を参照してください。

制限

  • Flow Builder 内で HTTP コールアウトアクションを作成するたびに、外部サービス登録が自動生成されます。詳細は、「コールアウトとコールバック: 制限と使用法」を参照してください。
  • JSON 階層には、最大 15 ネストレベルの項目とオブジェクトを含めることができます。

HTTP コールアウトアクションの認証に関するガイドライン

Flow Builder で HTTP コールアウトアクションを設定する前に、外部システムへの要求を認証するための指定ログイン情報を設定します。[設定] で、次のガイドラインに従って、権限セット、認証プロバイダー、外部ログイン情報、および指定ログイン情報を、この順序で作成し、ユーザーにユーザーログイン情報オブジェクトへのアクセス権を付与します。

必要なエディション

使用可能なインターフェース: Lightning Experience
サポートされているエディションを表示する。

権限セット

必須。コールアウトを実行するためのアクセス権をユーザーに付与します。

権限セットが存在しない場合は作成します。権限セットに外部ログイン情報を追加します。そして、コールアウトを実行できる各ユーザーに権限セットを割り当てます。また、従来の指定ログイン情報では権限セットが不要であり、時間を節約できますので、そちらの作成も検討してください。詳細は、「外部ログイン情報プリンシパルアクセス用の権限セットの作成」を参照してください。

認証プロバイダー

OAuth プロトコルの使用事例でのみ必要です。認証プロバイダーは ID プロバイダーとやりとりしてトークンを取得します。

外部ログイン情報

必須。認証プロトコルとログイン情報を定義します。

[指定ログイン情報] 設定ページの [外部ログイン情報] タブで外部ログイン情報を作成します。

API の認証要件に応じて適切なプロトコルを選択します。

  • カスタム。次の場合に選択します。
    • 基本認証 (ユーザー名とパスワード)
    • キーまたはトークン
    • 認証なし
  • OAuth 2.0
  • AWS 署名バージョン 4

外部ログイン情報に権限セットの対応付けを追加し、関連する権限セットを選択します。

ヘッダーにキーまたはトークンが必要な API の場合:

  • 権限セットの対応付けに認証パラメーターを追加します。一意の名前を入力し、[値] 項目にキーを入力します。
  • カスタムヘッダーを追加します。API で想定されている名前を正確に入力してください。[値] で、認証パラメーター名を参照します。次に例を示します。 
    $Credential.namedCredApiName.authParameterName

基本認証 (ユーザー名およびパスワード) が必要な API の場合:

  • 権限セットの対応付けに認証パラメーターを追加して、ユーザー名の値を定義して保存します。
  • パスワードの値を定義して保存するには、別の認証パラメーターを追加します。
  • カスタムヘッダーを追加します。名前として「Authorization」 (承認) と入力します。[値] に、ユーザー名とパスワードの認証パラメーターへの参照を入力します。次に例を示します。 
    {!'Basic ' & BASE64ENCODE(BLOB($Credential.BasicAuth.Username & ':' & $Credential.BasicAuth.Password))}

外部ログイン情報を作成したら、そのプリンシパルを作成します。これらのプリンシパルは権限セットおよびプロファイルに対応付けられます。プリンシパルの作成についての詳細は、「外部ログイン情報の作成または編集」を参照してください。

指定ログイン情報

必須。エンドポイントの名前と URL を定義します。Flow Builder でアクションを作成すると、指定ログイン情報が HTTP コールアウトアクションに関連付けられます。

多くの API では複数のエンドポイントで同じ認証情報が共有されているため (例: calendar.google.com/api と drive.google.com/api)、外部ログイン情報と指定ログイン情報は別々に定義されます。

接続先のエンドポイントを説明する表示ラベルを入力し、[URL] 項目にベース URL を入力して、前のステップで作成した外部ログイン情報を選択します。

[認証ヘッダーを生成] 項目は、認証なしまたは OAuth の使用事例ではこのオプションを選択します。キー/トークンと基本認証 (ユーザー名とパスワード) の使用事例では、選択を解除します。

[HTTP ヘッダーの数式を許可] 項目では、基本認証の使用事例に適用される数式がヘッダーに含まれている場合にこのオプションを選択します。

ヘッダーにキーまたはトークンが必要な API の場合、カスタムヘッダーを追加します。API で想定されている名前を正確に入力してください。[値] で、認証パラメーター名を参照します。ユーザーが複数のプリンシパルにまたがる複数の権限セットに属している場合は、連番を設定します。詳細は、「ログイン情報でのカスタムヘッダーの使用」を参照してください。

認証を必要としない Open API を除くすべての使用事例で必須です。指定ログイン情報サブシステムは、秘密トークンまたは値をユーザーのログイン情報オブジェクトに保存します。

権限セットまたはプロファイルを使用して、必要なアクセス権 (参照、作成、編集、削除) をユーザーログイン情報オブジェクトに付与します。
