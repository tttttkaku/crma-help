進行中の承認申請のキャンセル

[承認申請] リストビューから承認申請をキャンセルします。キャンセルできるのは進行中の承認申請のみです。

必要なエディション

フロー承認プロセスでサポートされるエディションを表示します。
必要なユーザー権限
進行中の承認申請をキャンセルする 承認管理者

Approvals アプリケーションを開く

Approvals アプリケーションを使用して、承認申請をキャンセルします。

  1. ナビゲーションバーで、[] をクリックします。
  2. 検索ボックスに approvals と入力し、Approvals を選択します。
    Approvals アプリケーションが開きます。
  3. [ホーム] タブで、[Manage All Pending Approval Submissions (待機中の承認申請をすべて管理)] を選択します。
  4. 承認申請待機中を表示するには、ドロップダウンリストから [承認申請待機中] を選択します。

承認申請リストビューを開く

[承認申請] リストビューを使用して、承認申請をキャンセルします。

  1. ナビゲーションバーで、[] をクリックします。
  2. 検索ボックスに「承認」と入力し、[承認申請] を選択します。[承認申請] をクリックします。
  3. 承認申請待機中を表示するには、ドロップダウンリストから [承認申請待機中] を選択します。

承認申請のキャンセル

進行中の承認申請をキャンセルします。

  1. [承認申請の待機中] ページで、関連する承認申請のドロップダウンから [キャンセル] を選択します。
  2. 誤って承認申請をキャンセルしようとした場合は、[X] をクリックしてウィンドウを閉じます。それ以外の場合は、確認ウィンドウで [次へ] をクリックします。

フロー承認プロセス

フロー承認プロセスには、複雑な承認シーケンスを整理するためのフェーズ、ステップ、決定が含まれます。[新規自動化] ウィンドウの [フロー承認プロセス] タイルを使用して、フロー承認プロセスを作成します。Approval アプリケーションで自動起動フロー承認プロセスを作成します。Flow Builder でフロー承認プロセスを作成します。

必要なエディション

フロー承認プロセスでサポートされるエディションを表示します。

外部システム変更トリガーフロー承認プロセスには、MuleSoft for Flow アドオンが必要です。

フロー承認プロセス種別

フロー承認プロセスのタイルは、[自動起動フロー承認プロセス (トリガーなし)]、[外部システム変更トリガーフロー承認プロセス]、[レコードトリガーフロー承認プロセス] です。

自動起動フロー承認プロセスは、承認申請コンポーネント、Apex、REST API、カスタム ボタン、またはカスタム リンクによって呼び出されると起動します。自動起動フロー承認プロセスは、フローがフロー承認プロセス固有のバージョンの動的 [承認申請] アクションをコールするときに、自動起動フローから呼び出すこともできます。

レコードが作成または更新されたときにレコードトリガーフロー承認プロセスが起動されますが、これはレコードが保存された後にのみ実行されます。

フロー承認プロセスの取り消しパス

取り消しパスを追加するようにフロー承認プロセスの開始要素を設定します。このパスは、そのフロー承認プロセスに基づく承認申請が取り消された場合に実行されます。取り消しパスには、バックグラウンドステップのみを含む 1 つのフェーズを含めることができます。

承認申請が取り消されると、実行されていたフェーズとその子ステップがキャンセルされます。承認申請に関連付けられているすべての未承認の承認作業項目もキャンセルされます。その後、取り消しパスのフェーズが実行されます。取り消しパスフェーズが完了すると、承認申請が取り消されます。

フロー承認プロセスのレコード更新

フロー承認プロセスでレコード変数またはレコードコレクション変数を参照する場合、これらの変数は、そのフロー承認プロセスに基づく親承認申請に関連付けられたオーケストレーションの実行が再開されるたびに、最新のレコード値で更新されます。自動起動フロー承認プロセスに基づく承認申請の場合、参照されるすべてのレコードが更新されます。レコードトリガーフロー承認プロセスに基づく承認申請の場合、$Record_Prior を除くすべての参照レコードが更新されます。

フロー承認プロセスでのレコードのロック

レコードのロックは、進行中の承認申請に関連付けられたレコードを変更できるユーザーを制御します。レコードロックの実装方法は、フロー承認プロセスステージの承認ステップが連続して実行されるか、同時に実行されるかによって異なります。

必要なエディション

フロー承認プロセスでサポートされるエディションを表示します。

承認ステップを連続して実行するためのレコードのロック

ステージの承認ステップが順次実行される場合、[承認ステップ] プロパティパネルの [アクションを完了する場所を選択] セクションで [レコードをロック] 設定を使用します。また、フロー承認プロセスに一連のフェーズが含まれ、各フェーズに 1 つの承認ステップのみが含まれている場合にもこの設定を使用します。

同時実行承認ステップのレコードのロック

一度に設定できるレコードのロックは 1 つのみです。ロックされたレコードを再度ロックしようとすると、フロー承認プロセスでエラーが発生します。この制限により、フロー承認プロセスに同時に実行される承認ステップが含まれる場合、[レコードをロック] 設定を使用できません。この設定を選択解除し、代わりにフロー承認プロセスまたはステージレベルでレコードのロックを管理します。複数の承認ステップを同時に実行するフロー承認プロセスステージがある場合、バックグラウンドステップを使用してレコードのロックを管理します。

フロー承認プロセスレベルまたはステージレベルでレコードのロックを管理するには、Lock Record アクションを参照するアクション要素を含む自動起動フローが必要です。このフローには、2 つの必須入力と 1 つのオプションの入力があります。最初の必須入力アクションは、レコードをロックするかロック解除するかを指定します。もう 1 つの必須入力 [レコード ID] は、確認中のレコードの ID です。省略可能な入力 [許可 ID] は、ロック中のレコードを編集できるユーザーを表すユーザー、グループ、キュー、またはユーザーロールレコードの ID です。

フロー承認プロセスレベルのロック。フロー承認プロセスレベルでレコードのロックを管理するには、フロー承認プロセスに 2 つのステージを追加します。各ステージには、レコードのロックを管理するバックグラウンドステップが含まれます。

承認ステップが含まれるフェーズの前に最初のフェーズを追加します。このステージのステップでは、承認されるレコードをロックする自動起動フローを呼び出し、[アクション] 入力を [ロック] に設定し、[レコード ID] 入力をレビュー中のレコードの ID に設定します。

承認ステップが含まれる最後のステージの後に 2 番目のステージを追加します。このステージのこのステップでは、承認されるレコードのロックを解除し、[アクション] 入力を [ロック解除]、[レコード ID] 入力をレビュー中のレコードの ID に設定します。このステージは、最終承認時のアクションと最終却下時のアクションを処理するステージに追加することもできます。

ステージレベルのロック。レコードのロックをステージレベルで管理するには、同時に実行される承認ステップを含むステージに 2 つのバックグラウンドステップを追加します。

最初のバックグラウンドステップを追加して、ステージの開始時に実行されるように設定します。このステップでは、承認されるレコードをロックする自動起動フローを呼び出し、アクション入力を Lock に、レコード ID 入力をレビュー中のレコードの ID に設定します。

各承認ステップを開始する前に、レコードをロックするバックグラウンドステップが完了としてマークされていることを必須とするように、ステージの各承認ステップを設定します。

2 番目のバックグラウンドステップを同じステージに追加します。このステップでは、承認されるレコードのロックを解除する自動起動フローを呼び出し、アクション入力を Unlock に、レコード ID 入力をレビュー中のレコードの ID に設定します。このステップで選択するエントリ条件は、ステージ内の同時承認ステップの数によって異なります。

承認ステップが 10 個以下の場合は、When the specified requirements are met entry requirement, the step starts を選択します。次に、ステージの各承認ステップの状況が [完了] の場合にのみステップが開始されるように要件を追加します。

承認ステップが 10 個を超える場合、フェーズの各承認ステップの状況の入力変数を含む評価フローを作成します。評価フローで、isOrchestrationConditionMet 出力変数を True に設定します。それ以外の場合は、出力変数を False に設定します。次に、2 番目のバックグラウンドステップのエントリ条件を設定します。When the specified evaluation flow returns True, the step starts を選択し、評価フローの名前を指定します。入力ごとに、各承認ステップの状況の自動出力を渡します。

ロックされたレコードの編集を許可するケース

フロー承認プロセス中にレコードをロックすると、レビュー中のレコードが変更されなくなります。ただし、Salesforce システム管理者は承認プロセスでロックされたレコードを編集できます。

通常、承認者は処理中の承認申請に関連付けられたレコードを変更しません。承認者またはその代理人は、承認申請者から提供されたレコードのみに基づいて承認作業項目を承認または却下します。

ただし、変更を伴う承認シナリオをフロー承認プロセスに導入することはできます。上位の承認者は、処理中の承認申請に関連付けられたレコードを変更できます。承認者がレビュー中のレコードを変更した場合の欠点は、承認申請に「変更を伴う承認済み」の状態が存在しないことです。承認者によって変更が行われたことを確認するには、承認者が行った変更の詳細を承認コメントに追加します。

すべてのレコードロック方法で、ロックされたレコードの編集を許可できます。方法に関係なく、ロックされたレコードを編集できるのは、代理承認者ではなく、割り当てられた承認者のみです。

承認ステップが連続して実行される場合、[承認ステップ] プロパティパネルの [アクションを完了する場所を選択] セクションで [承認者にロックされたレコードの編集を許可] 設定を使用します。この設定が選択されている場合、ステップが割り当てられたすべての承認者がレコードを編集できます。

承認ステップが同時に実行される場合、レビュー中のレコードをロックするバックグラウンドステップを更新します。このバックグラウンドステップの [許可 ID] 入力を、ロック中にレコードを編集できるユーザー、グループ、キュー、またはユーザーロールの ID に設定します。レコードのロックを解除するバックグラウンドステップでは、変更は不要です。

レコードのロックと承認申請コンポーネント

[承認申請] コンポーネントで複数のフロー承認プロセスを設定する場合、レコードのロックが同時申請にどのように影響する可能性があるかを考慮します。フロー承認プロセスでレコードがロックされている場合、同じレコードで別のフロー承認プロセスを開始すると、そのレコードもロックされます。これを回避するには、同じ [承認申請] コンポーネント内で設定するフロー承認プロセスでレコードロックを実装する方法を検討してください。また、ユーザーが同じレコードで同時に複数のフロー承認プロセスを開始する可能性も考慮します。

フロー承認プロセスの概念

フロー承認プロセスの構成と、オーケストレーション実行、フロー、承認申請、承認作業項目との関連について説明します。

  • フロー承認プロセス
    フロー承認プロセスには、複雑な承認シーケンスを整理するためのフェーズ、ステップ、決定が含まれます。[新規自動化] ウィンドウの [フロー承認プロセス] タイルを使用して、フロー承認プロセスを作成します。Approval アプリケーションで自動起動フロー承認プロセスを作成します。Flow Builder でフロー承認プロセスを作成します。
  • フロー承認プロセス種別
    フロー承認プロセスの種類によって、トリガー方法と開始できるユーザーが決まります。承認プロセスを開始する内容と、承認プロセスを実行するときにどの程度制御する必要があるかに基づいて、使用する種別を決定します。
  • フロー承認プロセスのトリガー
    レコードを作成または更新すると、レコードトリガーフロー承認プロセスを開始できます。レコードトリガーフロー承認プロセスの開始要素で、トリガーの条件を設定します。Flow Trigger Explorer を使用して、レコードトリガーフロー承認プロセス、オーケストレーション、フローの順序を並び替えます。
  • フロー承認プロセスのビルディングブロック
    フェーズ、ステップ、フローは、フロー承認プロセスのビルディングブロックです。
  • フロー承認プロセスでの自動出力
    フロー承認プロセスでは、フェーズとステップのステータスを参照し、自動出力を使用して参照されるフローの出力を取得します。
  • フロー承認プロセスでのレコードのロック
    レコードのロックは、進行中の承認申請に関連付けられたレコードを変更できるユーザーを制御します。レコードロックの実装方法は、フロー承認プロセスステージの承認ステップが連続して実行されるか、同時に実行されるかによって異なります。
  • フロー承認プロセス通知メール
    デフォルトでは、フロー承認プロセスで承認申請者、割り当てられた承認者、承認者の代理にメール通知が送信されます。
  • フロー承認プロセスのエラー処理
    エラー処理は、フロー承認プロセスの実行時に発生する可能性のある予期しない問題の管理方法に対応します。フェーズの障害パスを設定して、問題が発生した場合に実行するアクションを定義し、承認申請が失敗するのではなく承認または却下されるようにします。
  • フロー承認プロセスの実行コンテキスト
    実行コンテキストによって、フロー承認プロセスが Salesforce データに対して持つアクセスや、一時停止中のフロー承認プロセスが再開する際に使用するコンテキストが決まります。デフォルトでは、自動起動フローまたはレコードトリガーのフロー承認プロセスの実行コンテキストは、システムコンテキストの [自動化プロセスユーザー] です。
  • フロー承認プロセスのバージョン管理
    フロー承認プロセスには、フロー承認プロセスのバージョンとフロー承認プロセスでコールされるフローのバージョンの 2 つのバージョン設定があります。
  • 承認申請とオーケストレーションの実行
    Salesforce は、フロー承認プロセスを使用してレコードが承認申請されると、承認申請を作成します。各承認申請には、オーケストレーションの実行が関連付けられています。
  • 承認作業項目とオーケストレーション作業項目
    承認ステップでは、ユーザー、グループ、またはキューに割り当てられた作業項目が作成されます。承認ステップでは、メール通知も自動的に承認者に送信されます。承認者は、オーケストレーション作業ガイドコンポーネント、メール返信、または [承認作業項目] リストビューを使用して承認作業項目を完了します。各承認作業項目はオーケストレーション作業項目にリンクされています。

バックグラウンドステップの処理

各バックグラウンドステップは、有効な自動起動フローを参照します。親承認申請に関連付けられたオーケストレーションの実行が実行されると、ステップのフローが同期または非同期のどちらで実行されるかが自動的に判断されます。

実行中のフロー承認プロセスでは、ステップの基礎となるフローに 1 つ以上のサブフローまたは待機要素が含まれている場合、バックグラウンドステップを非同期で処理します。1 つ以上のアクション要素を含むバックグラウンドステップの実行方法は、関連付けられたフロー承認プロセスの API バージョンによって異なります。

API バージョン 68.0 以降で実行されているフロー承認プロセスの場合、同期アクションを含むフローのバックグラウンドステップは同期して実行されます。非同期アクションを含むフローのバックグラウンドステップは非同期で実行されます。

API バージョン 67.0 以前で実行されているフロー承認プロセスの場合、アクション要素を含むフローのバックグラウンドステップは非同期で実行されます。

バックグラウンドステップのフローが同期実行されると、親承認申請に関連付けられたオーケストレーションの実行がフローの完了時にすぐに再開されます。

バックグラウンドステップのフローが非同期的に実行される場合、プラットフォームイベントのフローオーケストレーションイベントが公開されます。実行中のフロー承認プロセスはイベントを受信すると、現在のフェーズとその [未開始] または [進行中] の各ステップを評価します。

フロー承認プロセスのビルディングブロック

フェーズ、ステップ、フローは、フロー承認プロセスのビルディングブロックです。

  • フロー承認プロセスのステージ
    フェーズでは、関連するステップがグループ化され、論理フェーズに整理されます。ステージは順次実行され、フロー承認プロセスでは一度に 1 つのステージのみが処理中となります。フェーズが完了したとみなされるために満たす必要がある条件を設定します。
  • フロー承認プロセスの手順
    ステップは段階的にグループ化されており、順次、同時、または指定された要件を満たしたときに実行できます。承認ステップでは、有効な画面フローの完了をユーザー、グループ、またはキューに割り当て、ユーザーの介入が必要になります。バックグラウンドステップでは、有効な自動起動フローが同期または非同期で実行され、ユーザー操作はありません。
  • フロー承認プロセスのフロー
    フロー承認プロセスの各バックグラウンドおよび承認ステップで、関連付けられたフローが実行されます。フェーズとステップの実行を制御するロジックで 10 個を超える要件が必要な場合、評価フローを使用してより複雑な条件を作成します。

フロー承認プロセスの各バックグラウンドおよび承認ステップで、関連付けられたフローが実行されます。フェーズとステップの実行を制御するロジックで 10 個を超える要件が必要な場合、評価フローを使用してより複雑な条件を作成します。

  • 自動起動フロー
  • 画面フロー
  • 評価フロー
出力 ユーザー定義変数は [出力で使用可能] とマークされます。出力変数は、関連付けられたステップの自動出力としてアクセスでき、設計時にフロー承認プロセス全体で使用できます。

評価フローの変数

[New Automation (新規自動化)] ウィンドウで [Evaluation Flow (評価フロー)] タイルを選択すると、isOrchestrationConditionMet という名前の定義済み Boolean 出力変数を含む評価フローが作成されます。

評価フローは、isOrchestrationConditionMet の値のみを返します。他の出力変数の値は破棄されます。

評価フローの実行

現在のフェーズ内の承認ステップまたは非同期バックグラウンドステップが完了するたびに、親承認申請に関連付けられたオーケストレーションの実行でそのフェーズの条件とそのステップが評価されます。現在のフェーズとそのステップの条件の評価をトリガーするには、親承認申請に関連付けられたオーケストレーション実行の$Orchestration.Instanceを含むオーケストレーション イベントを公開します。

各フェーズまたはステップの状況によって、親承認申請に関連付けられたオーケストレーション実行でチェックされる条件が決まります。チェックされる条件が評価フローに依存している場合、評価フローが実行されます。

  • フェーズが進行中の場合、親承認申請に関連付けられたオーケストレーションの実行によって、フェーズを完了できるかどうかが決まります。
  • 現在のステージ内で開始されていないステップごとに、親承認申請に関連付けられたオーケストレーションの実行によって、ステップを開始する準備が整っているかどうかが決まります。
  • 現在のステージ内の処理中の承認ステップごとに、親承認申請に関連付けられたオーケストレーションの実行によって、ステップを完了できるかどうかが決まります。

内部グループまたはキューに割り当てられた作業

承認ステップが実行されると、関連付けられたオーケストレーションの実行によって承認作業項目が作成され、指定されたグループまたはキューに割り当てられます。割り当てられたグループまたはキュー内のすべてのユーザーとその代理人に、内部関連レコードページへのリンクが記載されたメール通知が送信されます。承認者がメールリンクをクリックすると、内部関連レコードページの [作業ガイド] で画面フローを完了できます。

割り当てられた承認作業項目を承認または却下した最初のユーザーは、承認作業項目の完了をトリガーします。2 人のユーザーが同時に承認作業項目を確認すると、2 番目のフロー承認項目を承認または却下したユーザーにエラーが表示されます。承認作業項目が完了すると、作業ガイドを参照している他のグループまたはキューメンバーには、期限切れのバッジが付けられて項目が無効になります。ページを離れるか、ページを更新するか、別の作業項目を完了するまで、リストから削除されません。作業ガイドを積極的に表示していない場合、次にページにアクセスするときに関連作業が表示されなくなります。

全員の承認が必要な内部グループに割り当てられた作業

すべてのグループメンバーまたはその代理人が子作業項目を承認すると、オーケストレーションの実行で親作業項目の状況が [承認済み] に設定されます。グループメンバーまたはその代理人が作業項目を却下すると、オーケストレーションの実行で待機中の子作業項目の状況が [割り当て済み] から [取り下げ済み] に変更されます。次に、承認ステップの状況を [却下済み] に設定します。

全会一致の承認が必要なログイン情報のある Experience Cloud サイト訪問者のグループに割り当てられた作業

割り当てられた承認者と代理承認者が承認作業項目を完了する方法

割り当てられた承認者とその代理者は、指定されたレコードページのオーケストレーション作業ガイドコンポーネントで割り当てられた承認作業項目を完了できます。[承認作業項目] リストビューから承認作業項目を完了することもできます。

デフォルトでは、承認者と代理承認者は、承認作業項目が割り当てられたときにメール通知を受信します。[設定] で [プロセスの自動化設定からメール応答を有効化] が選択されている場合、割り当てられた承認者とその代理者もメールで承認または却下できます。割り当てられた承認者とその代理承認者がメールを使用してフロー承認プロセスの承認作業項目を完了できるかどうかに影響を与えるには、フロー承認プロセスの承認作業項目のメール完了の制御を参照してください。

特定のフロー承認プロセスで、割り当てられた承認者とその代理者へのメールを停止することもできます。フロー承認プロセスでメール通知が送信されない場合、割り当てられた承認者と代理承認者はメールを使用して承認作業項目を完了できません。特定のフロー承認プロセスにおける承認メールの停止に関する詳細は、フロー承認プロセスの承認者メールの制御を参照してください。

フロー承認プロセスに関する考慮事項

フロー承認プロセスを設計および使用するときは、エントリおよび終了条件の要件、レコードの変更によってトリガーされるイベント、入力値、メール通知を考慮します。

必要なエディション

フロー承認プロセスでサポートされるエディションを表示します。

エントリ条件と終了条件の要件

ステップ開始条件の要件、フェーズまたはステップ終了条件の要件で選択されたリソースには、フロー承認プロセスリソースまたはグローバル変数を含めることができます。要件に含めることができる内容には制限があります。

  • [リソース] 項目または [値] 項目のレコードを使用するには、そのレコードの項目を選択する必要があります。
  • 参照されるレコードでは、関連レコードの項目ではなく、そのオブジェクトの項目を使用する必要があります。

フェーズとステップの要件

最大 10 個の要件を使用して、ステップを開始するタイミング、またはフェーズまたは承認ステップを完了としてマークするタイミングを決定できます。これらの要件のいずれかで参照されるレコードを変更すると、承認申請に関連付けられたオーケストレーションの実行がトリガーされ、現在のフェーズの状況とその中の未完了のステップが評価される場合があります。ただし、一部の要件リソースでは条件評価がトリガーされません。

これらの要件リソースは条件評価をトリガーしません。

  • リソースが null レコードです。
  • リソースが無効な ID のレコードです。
  • リソースは自動起動承認オーケストレーションのグローバル変数です。
  • リソースが、レコードトリガー承認オーケストレーションの $Record 以外のグローバル変数である。
  • リソースが変更イベントをサポートしないオブジェクトのレコードである。

レコード変更トリガーフロー承認プロセスのイベント

ステップのエントリ条件やフェーズまたはステップの終了条件の要件には、レコードへの参照を含めることができます。そのレコードを変更すると、フロー承認プロセスがトリガーされ、現在のフェーズの状況とその中の未完了のステップが評価される場合があります。レコードで条件の評価をトリガーできるタイミングには制限があります。

  • 参照されるレコードの親オブジェクトで変更イベントがサポートされている必要がある。
  • 参照されるレコードフィールドは、IsDeleted、SystemModeStamp、または関連レコードや数式から派生したフィールドではありません。
  • 参照されるレコードを null にしたり、無効な ID にしたりすることはできません。
  • 参照されるレコードは、フロー承認プロセスのグローバル変数にすることができます。

フローの入力値

承認ステップまたはバックグラウンドステップでコールされたフローの合計入力値が 32,768 文字を超えると、フロー承認プロセスは失敗します。このエラーは、ステップでコールされたフローに 1 つ以上のレコードを渡したことが原因である可能性があります。このエラーを回避するには、参照されるフローにレコード ID を渡し、渡された ID を持つフローで [レコードを取得] 要素を使用します。 [レコードを取得] 要素で渡された ID を使用すると、常に最新バージョンのレコードを使用できます。

メール通知

ステップでコールされたフローが失敗し、親承認申請に関連付けられたオーケストレーションの実行が失敗すると、2 つのメール通知が送信されます。

  • フローエラー通知
  • フロー承認プロセスのエラー通知

    • レコードが追加または変更された後に自動的に実行されるフロー承認プロセスを作成するには、[レコードトリガーフロー承認プロセス] を検索して選択します。

新しいレコードトリガーフロー承認プロセスを開くと、開始要素が選択され、[開始を設定] パネルが開きます。

  2. [トリガーを設定] で、オプションを選択します。
    • レコードの作成時にのみフロー承認プロセスをトリガーするには、[レコードが作成されました] を選択します。
    • レコードの更新時にのみフロー承認プロセスをトリガーするには、[レコードが更新されました] を選択します。
    • レコードが作成または更新されたときにフロー承認プロセスをトリガーするには、[レコードが作成または更新されたとき] を選択します。

    条件の要件 フロー承認プロセスの実行時
    なし 常に
    すべての条件に一致 (AND) すべての条件が true です。
    いずれかの条件に一致 (OR) 少なくとも 1 つの条件を満たしている。
    カスタム条件ロジックに一致

フロー承認プロセスの作成

フロー承認プロセスは、フェーズ要素と決定要素で構成されます。フェーズには 1 つ以上のステップが含まれます。承認ステップとバックグラウンドステップのコールフロー。各フェーズには、そのフェーズまたはフェーズ内のステップで発生したエラーを処理する接続された障害パスを含めることができます。各フロー承認プロセスには、バックグラウンドステップを含む 1 つのフェーズを含む取り消しパスを含めることもできます。

すべてのフロー承認プロセスで 1 つ以上の承認ステップが必要です。フロー承認プロセスに承認ステップがない場合、その承認ステップに基づく承認申請は常に承認されます。「フロー承認プロセス」を参照してください。

フロー承認プロセスの構造は、その承認ステップが連続して実行されるか、同時に実行されるかによって異なります。「フロー承認プロセスでのレコードのロック」を参照してください。

承認申請が失敗しないように、フロー承認プロセスのエラー処理を設定します。フロー承認プロセスのエラー処理に使用する戦略についての詳細は、「フロー承認プロセスのエラー処理」を参照してください。

  1. 要素をフロー承認プロセスに追加するには、[] をクリックして要素を選択し、表示ラベル、API 参照名、説明を入力します。
    • フロー承認プロセスのステップを保存する要素を追加するには、[フェーズ] を選択します。
    • フロー承認プロセスの転送先パスを決定する要素を追加するには、[決定] を選択します。決定要素の設定についての詳細は、「Decision Flow Approval Processes Resource (決定フロー承認プロセスリソース)」を参照してください。
  2. ステップをフェーズに追加するには、[ステップを追加] をクリックし、ステップ種別を選択して、表示ラベル、API 参照名、説明を入力します。
    • 承認者とその代理人とやりとりするステップを追加するには、[承認ステップ] を選択します。
    • ユーザー操作のないステップを追加するには、[バックグラウンドステップ] を選択します。
  3. フロー承認プロセスの要素は、次の要素に自動的に接続されます。フロー承認プロセスには決定要素とフェーズ要素を含めることができますが、フローの場合のようなループ要素はありません。フロー承認プロセスで 1 つ以上の要素のシーケンスを繰り返す場合や、次に実行する要素を変更する場合は、移動コネクタを使用します。
    1. 別の要素に接続するには、決定要素またはフェーズ要素の後で [] をクリックし、[要素に接続] をクリックします。
    2. 移動する要素の をクリックします。
  4. (省略可能) 進行中のフロー承認プロセスが取り消されたときにステップを実行するには、取り消しパスを追加します。
    1. [開始] 要素を選択し、[Add Recall Path (Optional) (リコールパスを追加 (省略可能))] をクリックします。
    2. [Configure Start (開始を設定)] パネルで、[Add Recall Path (リコールパスを追加)] をクリックします。
  5. (省略可能) 承認申請の失敗を最小限に抑えるには、障害パスを使用してエラー処理をフロー承認プロセスに追加します。
    1. 障害パスをフェーズに追加するには、フェーズカードで [] をクリックし、[障害パスを追加] を選択します。
    2. フェーズ要素と決定要素を障害パスに追加します。フロー承認プロセスの障害パスのフェーズ要素には、承認ステップとバックグラウンドステップを含めることができます。
    3. (省略可能) デフォルトでは、障害パスは終了要素で終了します。障害パスまたは障害パス内の決定結果をメインフロー承認プロセスのフェーズまたは決定に接続するには、Go To コネクタを使用します。[] をクリックし、[要素に接続] をクリックして、移動先の要素の [] をクリックします。
  6. 作業を保存します。

フロー承認プロセスを作成したら、テストして期待どおりに動作することを確認します。

フロー承認プロセスで管理される承認があるオブジェクトのレコードページレイアウトにオーケストレーション作業ガイドコンポーネントを追加します。

承認者へのメールのカスタマイズ

デフォルトでは、承認申請に関連付けられたオーケストレーションの実行で承認作業項目が作成されるたびに、割り当てられた承認者と代理承認者に通知が送信されます。承認者と代理承認者の両方に送信するメール通知を変更するには、関連付けられた承認ステップをカスタマイズします。

必要なエディション

フロー承認プロセスでサポートされるエディションを表示します。
必要なユーザー権限
Flow Builder でフロー承認プロセスを開く、編集する、または作成する 「フローの管理」
[すべてのフロー承認プロセスを管理] タイルを表示する 承認デザイナー
割り当てられた承認作業項目を完了する 「フローの実行」

承認ステップを含むフロー承認プロセスが必要です。カスタムメール通知を承認者とその代理承認者に送信する承認ステップを作成するには、「承認者とやりとりするステップの作成」を参照してください。

すべてのメール通知を承認者および代理者に送信するには、[承認設定で承認作業項目の割り当てメールを送信] を選択する必要があります。「承認メール通知の管理」を参照してください。

承認ステップごとに最初の承認者通知メールの内容をカスタマイズできますが、送信者をカスタマイズすることはできません。フロー承認プロセスでは、[プロセスの自動化設定] で指定した [自動化プロセスユーザーのメールアドレス] からメール通知が送信されます。この設定を指定しない場合、Salesforce は [デフォルトの No-Reply アドレス] が目的の組織のメールアドレスを検索します。存在しない場合、Salesforce は検証済みの組織のメールアドレスを使用します。組織のメールアドレスが存在しない場合、Salesforce はフロー承認プロセスを実行しているユーザーのメールアドレスを使用します。フロー承認プロセスに関連付けられたオーケストレーション実行がユーザーのいないシステムコンテキストで実行された場合、Salesforce はメールを送信しません。

テキストテンプレートリソースを使用して、カスタムメールのユニークでパーソナル化された件名と本文を生成します。承認ステップごとに異なるテキストテンプレートのセットを使用できます。

  1. カスタマイズするフロー承認プロセスを開きます。
  2. 省略可能。カスタムメールの件名に使用するテキストを含むテキストテンプレートリソースを作成します。
  3. 省略可能。カスタムメールに使用する本文を含むテキストテンプレートリソースを作成します。
  4. 承認ステップを編集します。
    承認ステップの [プロパティ] パネルが開きます。
  5. [承認者を選択] で、[通知メールをカスタマイズ] を選択します。
    1. [件名] で、カスタムメールの件名が含まれるテキストテンプレートを選択します。または、件名の文字列を入力します。
    2. [本文] で、カスタムメールの本文が含まれるテキストテンプレートを選択します。
  6. 作業内容を保存します。

自動起動フロー承認プロセスをユーザーが使用できるようにする

有効なレコードトリガーフロー承認プロセスに基づく承認は、レコードが追加または更新されたときに自動的に実行され、フロー承認プロセスの入力条件を満たしています。ただし、有効な自動起動フロー承認プロセスに基づく承認は自動的に実行されません。ユーザーが手動で承認を申請する前に、有効な自動起動フロー承認プロセスをコールするボタンを作成し、そのボタンを関連するレコードページに追加します。

  • レコードページの複数のフロー承認プロセスの設定
    Lightning アプリケーションビルダーで [承認申請] コンポーネントをレコードページレイアウトに追加します。申請者が申請するプロセスを選択できるように、コンポーネントで最大 10 個のフロー承認プロセスを設定します。申請者が承認者を選択して申請コメントを追加できるように、各フロー承認プロセスを設定できます。

    Lightning アプリケーションビルダーで承認申請コンポーネントをレコードページレイアウトに追加します。申請者はコンポーネントを使用してレコードの承認を申請できます。申請者が承認者を選択して申請コメントを追加できるようにコンポーネントを設定します。[承認申請] コンポーネントで設定できるフロー承認プロセスは 1 つのみです。
  • Experience Cloud サイトの単一フロー承認プロセスの設定
    エクスペリエンスビルダーでオブジェクトの詳細ページレイアウトに [承認申請] コンポーネントを追加します。ログイン情報のある Experience Cloud サイト訪問者は、このコンポーネントを使用してレコードの承認を申請できます。申請者が承認者を選択して申請コメントを追加できるようにコンポーネントを設定します。[承認申請] コンポーネントで設定できるフロー承認プロセスは 1 つのみです。

自動起動フロー承認プロセスを実行するボタンの作成

ユーザーが自動起動フロー承認プロセスを使用して手動でレコードを承認申請できるように、承認申請用のボタンを作成します。

必要なエディション

フロー承認プロセスでサポートされているエディションを確認します。
必要なユーザー権限
カスタムボタンを作成または変更する 「アプリケーションのカスタマイズ」

オブジェクトのカスタムボタンを作成するには、アクティブな自動起動型フロー承認プロセスが必要です。

  1. ボタンを作成するオブジェクトの管理設定から、[ボタン、リンク、およびアクション] に移動します。
  2. [新規ボタンまたはリンク] をクリックします。
  3. ボタンの表示ラベルに「Submit for Approval」 (承認申請) と入力します。
  4. [表示の種類] で、[詳細ページボタン] を選択します。
  5. [動作] で、[Display in new window (新しいウィンドウで表示)] を選択します。
  6. ボタンの属性を入力します。
    1. 属性パネルに /flow/ を入力します。
    2. この承認で実行されるアクティブな自動起動型フロー承認プロセスの API 参照名を入力します。
      たとえば、契約オブジェクトのボタンを追加するとします。アクティブな自動起動型フロー承認プロセスの API 名は Contract_Approval なので、Contract_Approval と入力します。
    3. 属性パネルに ?recordId= を入力します。
    4. [項目を挿入] から、ボタンを作成するオブジェクトの ID を選択します。
      この例では、[Select Field Type (項目種別)] が [Contract (契約)] で、[Insert Field (項目を挿入)] に [Contract ID (契約 ID)] を選択します。
      選択した差し込み項目が属性パネルに追加されます。
    5. 属性パネルに &submitter= を入力します。
    6. [項目種別を選択] から [$User] を選択し、[項目を挿入] から [ユーザー ID] を選択します。
      $User.Id 差し込み項目が属性パネルに追加されます。
    7. 属性パネルに &retURL= を入力します。
    8. [項目種別を選択] から、ボタンを作成するオブジェクトの名前を選択し、[項目を挿入] からオブジェクトの ID を選択します。
      この例では、[Select Field Type (項目種別)] が [Contract (契約)] で、[Insert Field (項目を挿入)] に [Contract ID (契約 ID)] を選択します。
      選択した差し込み項目が属性パネルに追加されます。
    この例では、/flow/Contract＿Approval？recordId＝{!Contract.Id}&submitter＝{!$User.Id}&retURL＝{!Contract.Id} が属性パネルに表示されるようになりました。
  7. [構文を確認] をクリックします。エラーが表示された場合は、属性パネルの内容を削除して、ステップ 6 を繰り返します。
  8. 作業内容を保存します。

オブジェクトのレコードのページレイアウトにボタンを追加します。

フロー承認プロセスに関連付けられたオーケストレーションの実行でエラーが発生すると、失敗します。この失敗により、関連付けられた親承認申請のステータスが [エラー] に設定されます。他のオーケストレーション実行とは異なり、フロー承認プロセスに関連付けられたオーケストレーション実行は再開できません。

フロー承認プロセスに関連付けられたオーケストレーションの実行が失敗すると、Salesforce は、フロー承認プロセスを最後に変更した管理者または Apex 例外メールの受信者にエラー メールを送信します。エラーメールには、実行された要素とそのステップで参照されるすべてのフローなど、フロー承認プロセスに関する詳細が表示されます。有効なフロー承認プロセスの場合、メールには Flow Builder で失敗したオーケストレーション実行の詳細を表示するためのリンクも記載されます。オーケストレーションの実行によってコールされたフローが失敗の原因である場合、受信者は 2 つのエラーメールを受信します。1 つはフロー承認プロセスの失敗、もう 1 つはコールされたフローの失敗です。

エラーを管理するには、フロー承認プロセスのフェーズの障害パスを設定します。これらのパスでは、フェーズまたはそのステップでエラーが発生したときに実行する代替アクションを定義します。これにより、プロセスの失敗を最小限に抑えることができます。

失敗した承認申請は以前のすべてのレコード変更をロールバックするとは限らないため、本番にリリースする前にサンドボックス環境でフロー承認プロセスを設計およびデバッグします。

フロー承認プロセスのエラー処理戦略

フロー承認プロセスのエラー処理の主な目的は、関連付けられたオーケストレーションの実行の失敗を最小限に抑えて、親承認申請が承認または却下されるようにすることです。障害パスを使用して、フェーズやステップからエラーを管理します。フロー承認プロセスでは、個々の障害パスまたは一元化された障害パスを使用できます。

障害パスには、決定要素とフェーズ要素を含めることができます。障害パスのフェーズ要素には、バックグラウンドステップと承認ステップを含めることができます。障害パスでは Go To コネクタも使用できます。障害パスの Go To コネクタは、障害パスの別の要素、別の障害パスの要素、またはフロー承認プロセスのメインパスの要素に接続できます。

個々の障害パス。フロー承認プロセスのフェーズごとに個別の障害パスを設定します。これらの個々のパスには、各フェーズに固有のエラーを管理するステップを含む要素とフェーズが含まれます。このアプローチでは、高度にローカライズされたエラー解決が提供されます。たとえば、フェーズに 1 つの承認ステップのみが含まれている場合、障害パスによって承認ステップが承認されるか却下されるかが決まります。承認ステップが承認され、追加の承認が必要ない場合は、最終承認アクションを実行するフェーズに決定結果を接続します。承認ステップが承認されたが、さらに承認が必要な場合は、承認ステップが含まれる次のフロー承認プロセスフェーズに決定結果を接続します。承認ステップが却下された場合、最終却下アクションを実行するフェーズに決定結果を接続します。

一元化された障害パス。統合されたエラー処理メカニズムとして機能する 1 つの中央障害パスを設定します。通常、このアプローチは、オーケストレーション実行に関連する変数と自動出力を評価して、エラーが発生した特定のフェーズと、エラーに対処する方法を特定する決定要素から始めます。他のフェーズの障害パスを中央の障害パスの最初の決定要素に接続します。このアプローチでは、包括的なエラー解決が提供されます。たとえば、複数フェーズの承認プロセスでは、一元化された障害パスは決定要素から始まります。[初期レビューを実行] フェーズの状況が完了していない場合、決定結果のパスには、申請者に問題を自動的に通知するバックグラウンドステップがあるフェーズが含まれます。反対に、[財務承認を処理] フェーズの [最初の財務承認を取得] ステップが失敗した場合、決定結果のパスにはバックグラウンドステップと承認ステップの 2 つのステップを含むフェーズが含まれます。バックグラウンドステップで、失敗が財務部門に通知されます。承認ステップでは、代替承認が財務グループに割り当てられます。財務承認は、この承認プロセスで最後に必要な承認であるため、この結果パスは、最終承認アクションを実行するか最終却下アクションを実行するかを決定する決定要素に接続されます。

障害パスの自動承認の回避

障害パスのないフェーズまたはそのステップのいずれかが失敗すると、オーケストレーションの実行が失敗し、関連付けられた承認申請の状況がエラーに設定されます。もし障害パスが設定されたフェーズ、またはそのステップのいずれかが失敗し、かつその障害パスがエラーなく実行された場合、関連付けられた承認申請の状況は承認済みまたは却下済みになります。承認申請の最終状況はシナリオによって異なります。

承認申請結果
エラーのシナリオ 最終承認申請状況
エラーが発生したフェーズに障害パスが設定されていない。 エラー
エラーが発生したフェーズには、エラーなしで実行される障害パスが設定されています。完了したすべての承認作業項目が承認されます。 承認済み
エラーが発生したフェーズには、エラーなしで実行される障害パスが設定されています。1 つ以上の完了した承認作業項目が却下された。 却下済み
エラーが発生したフェーズには、エラーなしで実行される障害パスが設定されています。完了した承認作業項目はありません。 承認済み

完了した承認作業項目のない承認申請を自動的に承認しないようにするには、次のガイドラインに従ってください。

  • フェーズの障害パスは、前のフェーズに 1 つ以上の承認ステップが含まれている場合にのみ設定します。たとえば、フロー承認プロセスは、レコードを承認対象としてロックするバックグラウンドステップのみを含むフェーズで開始されます。このフェーズの障害パスは設定しないでください。このフェーズが失敗する可能性が最も高い理由は、レコードがすでにロックされていることです。
  • 承認作業項目が完了したかどうかを判断する承認ステップが含まれる最初のフェーズの障害パスを設定します。承認作業項目が完了していない決定結果パスに、承認ステップを含むフェーズを追加します。

エラー処理の制限事項

  • フロー承認プロセスに関連付けられたオーケストレーション実行で未対応のエラーが発生すると、オーケストレーション実行を再開できません。
  • 障害パスがエラーなしで完了し、承認作業項目が完了していない場合、承認申請を却下する方法はありません。
  • オーケストレーション実行レベルのエラーにはエラー処理を追加できません。
  • 失敗したオーケストレーション実行のデバッグの詳細は、失敗から 14 日以内にのみ表示できます。
  • 承認申請が失敗した場合、関連付けられたオーケストレーションの実行が失敗する前に発生したレコードの追加、変更、削除がロールバックされるとは限りません。

    割り当てられた承認作業項目は、オーケストレーション作業ガイドコンポーネントのレコードページに直接表示されます。日付による項目の並び替え、ToDo の優先順位付け、完了状況の追跡を行います。

    承認申請リストビューを使用して、承認申請のリストと詳細を確認します。

    割り当てられた承認作業項目を別のユーザー、グループ、またはキューに再割り当てします。まだ進行中の承認オーケストレーションに割り当てられた作業項目を再割り当てできます。

    デフォルトでは、フロー承認プロセスによって、割り当てられた承認者、代理承認者、承認申請者にメール通知が送信されます。承認メール設定を使用して、これらのグループに送信されるメールを管理します。
  • フロー承認プロセスの承認者メールの制御
    特定のフロー承認プロセスに基づく承認申請の承認者およびその代理者へのメール通知の送信を停止するには、上級設定の「承認者通知を送信しない」を使用します。
  • フロー承認プロセスの承認作業項目のメール完了を制御
    デフォルトでは、承認作業項目が作成または再割り当てされると、割り当てられた承認者と代理承認者にメール通知が送信されます。承認者と代理承認者がメール通知を受信したら、メール通知に返信して、フロー承認プロセスの承認申請に関連付けられた承認作業項目を完了できるようにすることができます。
  • 進行中の承認申請の取り消し
    [承認申請] リストビューから承認申請を取り消します。取り消すことができるのは、進行中の承認申請のみです。
  • 進行中の承認申請のキャンセル
    [承認申請] リストビューから承認申請をキャンセルします。キャンセルできるのは進行中の承認申請のみです。

  • Approvals アプリケーションでのフロー承認プロセスの連動関係の表示
    フロー承認プロセスでは、フローを使用してステップを実行し、複雑な条件を評価します。フローでは、アクション要素を使用してフロー承認プロセスをコールすることもできます。フロー承認プロセスと、フロー承認プロセスがコールするフローおよびフロー承認プロセスをコールするフローとの関係を理解するには、Approvals Lightning アプリケーションの [オーケストレーションバージョン] ページまたは [オーケストレーション] ページの [利用状況] タブを表示します。

申請者に送信されるフロー承認プロセスのメール通知の制御

フロー承認プロセスでは、承認申請者にメール通知が送信されます。このメールは、項目の承認申請後、および項目の承認または却下後に申請者に通知されます。[申請者に承認申請状況メール通知を送信] 設定を使用して、これらのメールを制御します。

  1. [承認設定] には、[承認] アプリケーションまたは [設定] からアクセスします。
    1. Approvals アプリケーションで、[設定] をクリックします。
    2. [設定] の [クイック検索] ボックスで、[承認設定] を検索して選択します。
  2. 承認申請者にメール通知を送信するかどうかを決定します。
    • 承認申請者へのメール通知の送信を停止するには、申請者に承認申請状況メール通知を送信の選択を解除します。
    • 承認申請者にメール通知を送信するには、申請者に承認申請状況メール通知を送信します。

承認者に送信する承認作業項目メール通知の制御

承認ステップでは、割り当てられた承認者と代理承認者にメール通知が送信されます。[承認者への承認作業項目割り当てメールの送信] 設定を使用して、これらのメールを制御します。

重要 [承認者への承認作業項目割り当てメールの送信] と [メール承認の有効化] が選択されている場合のみ、承認者とその代理者がメールから承認作業項目を完了できます。「フロー承認プロセスの承認作業項目のメール完了の制御」を参照してください。
  1. [承認設定] には、[承認] アプリケーションまたは [設定] からアクセスします。
    1. Approvals アプリケーションで、[設定] をクリックします。
    2. [設定] の [クイック検索] ボックスで、[承認設定] を検索して選択します。
  2. メール通知を割り当てられた承認者とその指定された代理人に送信するかどうかを決定します。
    • 割り当てられた承認者とその指定された代理承認者へのメール通知の送信を停止するには、承認作業項目割り当てメールを承認者に送信の選択を解除します。
    • 割り当てられた承認者とその指定された代理承認者へのメール通知を送信するには、承認作業項目割り当てメールを承認者に送信します。

キューメンバーの承認作業項目メール通知の制御

承認ステップがキューに割り当てられたときに承認作業項目メール通知を送信するユーザーを制御します。

メモ [承認作業項目のメールをキューメンバーにのみ送信] 設定は、ロール階層が有効になっていない場合は無効です。また、[承認者への承認作業項目割り当てメールの送信] 設定がオフになっている場合も無効です。
  1. [承認設定] には、[承認] アプリケーションまたは [設定] からアクセスします。
    1. Approvals アプリケーションで、[設定] をクリックします。
    2. [設定] の [クイック検索] ボックスで、[承認設定] を検索して選択します。
  2. キューが承認ステップの割り当て先である場合に作業項目メール通知を受信するユーザーを制御します。
    • 承認作業項目のメール通知をキュー メンバーとその代理人のみに制限するには、[Send approval work item emails only to queue members (承認作業項目のメールをキュー メンバーにのみ送信)] を選択します。
    • 承認作業項目メール通知をキューメンバー、キューメンバーの代理、およびロール階層でキューメンバーより上位の個人に送信するには、[承認作業項目メールをキューメンバーにのみ送信] をオフにします。

フロー承認プロセスの承認作業項目のメール完了を制御

デフォルトでは、承認作業項目が作成または再割り当てされると、割り当てられた承認者と代理承認者にメール通知が送信されます。承認者と代理承認者がメール通知を受信したら、メール通知に返信して、フロー承認プロセスの承認申請に関連付けられた承認作業項目を完了できるようにすることができます。

必要なエディション

フロー承認プロセスでサポートされるエディションを表示します。
必要なユーザー権限
プロセスの自動化設定を編集する 「アプリケーションのカスタマイズ」

[承認設定で承認者に承認作業項目割り当てメールを送信] がオフになっている場合、承認者とその代理者はメールを使用して承認作業項目を完了できません。「承認メール通知の管理」を参照してください。

特定のフロー承認プロセスのメール通知を停止することもできます。上級設定で [特定のフロー承認プロセスの承認者通知を送信しない] を選択した場合、承認者とその代理承認者もメールを使用して承認作業項目を完了できません。「フロー承認プロセスの承認者メールの制御」を参照してください。

重要 [メール承認の有効化] 設定は、Classic 承認プロセスと共有されます。この設定を選択または選択解除すると、割り当てられた承認者と代理承認者がフロー承認プロセスおよび従来の承認プロセスの両方の承認作業項目を完了できるかどうかに影響します。
  1. [設定] の [クイック検索] ボックスに「プロセスの自動化」と入力し、[プロセスの自動化設定] を選択します。
  2. 割り当てられた承認者とその代理人がフロー承認プロセスの承認作業項目をメールで承認するか却下するかに応じて、[メール承認の有効化] を設定します。
    • 割り当てられた承認者とその代理人がフロー承認プロセスの承認作業項目をメールで承認または却下できるようにするには、[Enable email approval response (メール承認の有効化)] を選択します。
    • 割り当てられた承認者とその代理人がフロー承認プロセスの承認作業項目をメールで承認または却下しないようにするには、[メール承認応答を有効化] をオフにします。

  1. [承認申請] リストビューを開きます。

    • 承認申請名をクリックし、承認申請レコードから [削除] をクリックします。
    承認申請レコードとその子レコードが削除されます。
