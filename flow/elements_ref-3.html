チェックボックスグループ画面入力コンポーネント

ユーザーがチェックボックス形式で複数のオプションを選択できるようにします。

必要なエディション

サポートされているエディションを表示する。

チェックボックスグループコンポーネントの設定

属性 説明
API 参照名

コンポーネントの API 参照名。

API 参照名には、スペースを含まないアンダースコアと英数字を使用できます。文字で始まる必要があり、末尾をアンダースコアにすることはできません。アンダースコアを 2 つ続けて使用することもできません。
選択肢

このコンポーネントに少なくとも 1 つの選択肢、レコード選択肢セット、または選択リスト選択肢セットを追加します。選択肢コンポーネントを画面コンポーネントに追加するときにのみ使用できます。表示テキストコンポーネントを除くすべての画面コンポーネントでは、実行時に選択肢の値が使用されます。

コレクション選択肢セットやレコード選択肢セットなどの動的選択肢リソースを選択する場合、選択肢リソースの各値が一意であることを確認します。そうでない場合、ユーザーが重複値を選択すると、Salesforce でその値が正しく設定されません。
コンポーネントの種類

選択肢コンポーネントの種類を変更します。

ユーザーが 1 つのオプションのみを選択できる場合、次のコンポーネントの種類が使用可能になります。

  • 選択リスト
  • ラジオボタン

ユーザーが複数のオプションを選択できる場合、次のコンポーネントの種類が使用可能になります。

  • チェックボックスグループ
  • 複数選択リスト
データ型 このコンポーネントでは、テキスト選択肢のみがサポートされています。
デフォルト値 コンポーネントに事前選択された選択肢。関連付けられた画面が実行されていないか、コンポーネントの表示条件が満たされていない場合、コンポーネントの保存値は null です。
無効

true に設定されている場合、ユーザーは値を変更できません。デフォルト値は false です。

この属性は、Boolean 値を持つリソースを受け入れます。
表示ラベル 実行ユーザーに使用方法を指示する画面コンポーネントと共に表示されるテキスト。
ユーザーが複数のオプションを選択できるようにする ユーザーが選択できるオプションが 1 つのみであるのか、それとも複数であるのかを指定します。[ユーザーが複数のオプションを選択できるようにする] で [はい] を選択すると、[データ型] が自動的に [テキスト] に設定され、テキスト以外の選択肢リソースはコンポーネント設定からクリアされます。
ヘルプを提供 ユーザーにこの画面コンポーネントの詳細なコンテキストを提供します。入力したテキストは、コンポーネントの横の情報バブルに表示されます。
必須 次の画面に進む前に、ユーザーが値を選択する必要があります。

コンポーネントの表示の設定

フローでコンポーネントを表示するタイミングを決定するロジックを指定します。

オプション 説明
コンポーネントを表示するタイミング

条件付きロジックを使用して、コンポーネントを表示するタイミングを設定します。

コンポーネントを次のように設定できます。

Always
コンポーネントは常に表示されます。
すべての条件に一致する場合 (AND)
定義したすべての条件が成立したときにコンポーネントが表示されます。少なくとも 1 つ条件を指定してください。
いずれかの条件に一致する場合 (OR)
定義した 1 つ以上の条件に一致したときにコンポーネントを表示します。少なくとも 1 つ条件を指定してください。
カスタム条件ロジックに一致する場合
定義したすべての条件ロジックが成立したときにコンポーネントが表示されます。少なくとも 1 つの条件を指定し、条件ロジックを指定します。

再アクセス画面での値の処理の指定

ユーザーが値を入力し、前の画面に移動して、このコンポーネントが含まれる画面に戻ったときのコンポーネントの実行内容を指定します。

オプション 説明
ユーザーがこの画面に最後にアクセスしたときの値を使用 コンポーネントにはユーザーが指定した値が保持されます。前の画面での変更を反映して値が更新されることはありません。
入力を更新してフローの他の場所での変更を組み込む

コンポーネントでは、ユーザーが指定した値が更新され、前の画面での変更が反映されます。

フローを一時停止して再開した場合、フローでユーザー指定の値が保持されるのは、チェックボックス、チェックボックスグループ、通貨、ロングテキストエリア、複数選択リスト、数値、パスワード、選択リスト、ラジオボタン、およびテキストコンポーネントのみです。

考慮事項

ユーザーがチェックボックスグループコンポーネントの情報バブルをクリックすると、別のウィンドウにヘルプテキストが表示されます。その他の種類の Salesforce 提供のコンポーネントでは、ヘルプテキストがポップオーバーで表示されます。

選択肢

このコンポーネントに少なくとも 1 つの選択肢リソース (レコード選択肢セットまたは選択リスト選択肢セットなど) を追加します。選択肢コンポーネントを画面コンポーネントに追加するときにのみ使用できます。

属性 説明

ユーザーが複数のオプションを選択できる場合、フローを実行しているユーザーが選択したすべての選択肢オプションの表示ラベルがセミコロンで区切られます。

ユーザーが複数のオプションを選択できる場合、フローを実行しているユーザーが選択したすべての選択肢オプションの値がセミコロンで区切られます。

考慮事項

  • 選択肢ルックアップフロー画面コンポーネントは、モバイルデバイスまたはスタンドアロン Aura アプリケーションと互換性がありません。
  • コンポーネントは、指定された選択肢リソースの [選択肢表示ラベル] 項目のみで一致を検索します。
  • 他の選択肢項目と同様に、選択肢ルックアップコンポーネントでは [選択済み] 演算子がサポートされています。
  • 検索では、大文字と小文字は区別されません。
  • 最初に 20 個の選択肢オプションが表示されます。スクロールすると、さらに 100 個の選択肢オプションがグループごとに読み込まれ、最大 1,020 個まで読み込まれます。
  • 最初の選択の読み込み後に検索条件を適用すると、表示がリセットされ、新しい 20 個の選択肢が表示されます。
  • 選択肢ルックアップコンポーネントでは、選択肢リソースに対して [テキスト入力を表示] 項目がサポートされていません。たとえば、選択肢リソースの設定時に [テキスト入力を表示] チェックボックスをオンにして、そのリソースを選択肢ルックアップコンポーネントに追加した場合、ユーザーが実行時に対応する選択肢を選択したときにコンポーネントにテキスト入力項目は表示されません。

考慮事項

  • データテーブルフロー画面コンポーネントは、モバイルデバイスと互換性がありません。
  • [レコードを取得] フロー要素を使用して、データテーブルに表示するレコードを取得する場合は、[項目を選択] を選択して、残りの項目を Salesforce に実行させ、最適なパフォーマンスを実現します。
  • データテーブルの高さの最大値は 400 ピクセルになります。
  • データテーブルでテキストをラップする場合は、フローをテストするときにテキストがオーバーフローしていないことを確認してください。データテーブルが画面上で縮小されている場合 (データテーブルが複数の列のいずれかに含まれている場合など)、折り返されたテキストがはみ出す可能性があります。
  • データテーブルには、最大 1,500 件のレコードを表示できます。ただし、検索はデータセット全体で実行されます。
  • 1 つのデータテーブルで最大 200 件のレコードを表示できます。
  • 初期のレコードの読み込み後に検索条件を適用した場合、新しい結果のみが表示されます。初期のレコードは表示されなくなります。
  • データベースにコミットされていない数式項目とレコードまたはレコードへの更新がデータベースに含まれている場合、その数式は適切に評価されません。

    レコードがデータベースに存在しない場合は、静的値または数式リソースを使用して、割り当てによって数式項目の値を更新します。フローで後続の作成や更新の操作は影響を受けません。

    既存のレコードが更新された場合は、呼び出し可能なアクションを使用して数式を再評価するか、IN 演算子を使用してレコードと数式項目の値を更新します。

  • 時間項目は削除できません。
  • ToDo および行動レコードの [件名] 項目はサポートされていません。
  • 日時は International Components for Unicode (ICU) の日時形式で表示されます。
  • マルチ通貨組織の場合、データテーブルコンポーネントではユーザーの個人設定の通貨と異なる通貨のレコードがサポートされません。
  • データテーブルコンポーネントでマルチ言語の列ヘッダー表示ラベルを表示するには、$Label グローバル変数を使用してカスタム表示ラベルを指定します。カスタム表示ラベルの作成と翻訳についての詳細は、「カスタム表示ラベル」を参照してください。
  • 実行時のデータテーブルの選択は、『Lightning Aura コンポーネント開発者ガイド』に記載されているクライアントのペイロードデータ制限の対象になります。この制限数を超えると、一般的なエラーメッセージがフローから返されます。たとえば、制限を超えるファイルデータを含めると、フローでエラーが発生します。ソースコレクションの ContentVersion レコードの VersionData 項目などの項目は避けることをお勧めします。
  • データテーブルコンポーネントがあるフローを開いていて、別のページでユーザー設定のタイムゾーンを更新する場合、フローページを更新して、更新された日時項目をデータテーブルコンポーネントに表示します。
  • 行選択を設定するときに、別のデータテーブルコンポーネントの行選択を使用する場合は注意が必要です。Salesforce では、レコード ID のない重複レコード変数がある行選択は使用できません。
  • 行選択モードを単一に設定して必須にした場合、または行選択の最小値と最大値を 1 に設定した場合、Salesforce では実行時にラジオボタンが使用されます。それ以外の場合は、実行時にチェックボックスが使用されます。
  • データテーブルコンポーネントが含まれるフローをパッケージ化した場合、データテーブルで使用される項目は自動的にパッケージに追加されません。データテーブルコンポーネントで項目を使用する場合は、手動でパッケージに追加する必要があります。
  • API バージョン 65.0 以降、データテーブルコンポーネントでは項目名の変更が自動的に更新されます。65.0 より前の API バージョンで実行されているフローの場合、オブジェクトマネージャーでデータテーブルの列に対応付けられている項目の名前を変更しても、Salesforce では列名が更新されません。データテーブルで新しい名前を表示するには、列を削除して、再度追加します。
  • API バージョン 65.0 以降、データテーブルコンポーネントで参照されている項目は削除できなくなりました。65.0 より前の API バージョンで実行されているフローの場合、データテーブルコンポーネントで使用するカスタム項目を削除できます。そのため、データテーブルコンポーネントからも項目を削除する必要があります。
  • API バージョン 65.0 以降、データテーブルコンポーネントでは名前空間が自動的に更新されます。65.0 より前の API バージョンで実行されているフローの場合、名前空間のない組織でカスタムオブジェクトまたはカスタム項目を使用するデータテーブルコンポーネントを使用し、後で組織に名前空間を追加する場合、その名前空間をデータテーブルの関連付けられた列項目にも手動で追加する必要があります。
  • 列の並び替えでは、最初に選択した行と選択した行に並び替えの影響はありません。
  • [レコード名を表示] を選択した場合、並び替えオプションと検索オプションは使用できません。
  • ユーザーが関連レコードオブジェクトにアクセスできる場合にのみ、[レコード名を表示] を選択すると、実行時に関連レコード名が表示されます。

  • ユーザーレコードへのカスタム参照項目はサポートされていません。
    ヒント フローユーザーがユーザーレコードのリストから選択できるようにするには、CreatedById や LastModifiedById などの標準ユーザー参照項目を使用します。OwnerId はサポートされていません。
  • 実行時にフローユーザーが項目に 2 文字を入力すると、[名前] 項目がクエリに一致する最近のレコードが 5 件表示されます。
  • 外部レコードへのルックアップはサポートされていません。
  • 実行中、割り当てられたページレイアウトに [項目 API 参照名] で定義された参照項目がない場合、ルックアップコンポーネントに [Search undefined...] と表示されます。正しいテキストを表示するには、実行ユーザーに割り当てられているすべての取得元オブジェクトのページレイアウトに定義済みの参照項目を追加します。
  • 無効なレコード ID は無視されます。レコード ID が有効な Salesforce レコード ID ではない場合、またはレコードのキープレフィックスが項目の API 参照名オブジェクトと一致しない場合、そのレコード ID は無効です。
  • [最大選択数] の値が 1 で、レコード ID コレクションとレコード ID の両方が変更された場合は、レコード ID が優先されます。レコード ID コレクションは無視されます。

  • 複数のオブジェクトに関連付けられているリレーション項目 (多態的な項目とも呼ばれます) はサポートされません。たとえば、タスクレコードの WhoId 項目は取引先責任者またはリードに関連付けることができるため、このコンポーネントではサポートされていません。
  • Field API Name および Object API Name では、大文字と小文字が区別されます。
  • ルックアップフロー画面コンポーネントでは、ソースオブジェクトレコードタイプによる絞り込みはサポートされていません。

フローでの電話コンポーネントの値の保存

フローは値を自動的に保存します。手動で値を保存する場合は、属性の出力値を変数に保存してください。

値を手動で保存するには、[手動割り当て変数 (詳細)] を選択します。

すべての属性をフロー変数に保存できますが、最も保存する必要があると考えられるのは [値] 属性です。

ユーザーが入力した電話番号を保存するには、[値] 属性をフロー変数に対応付けます。

ヒント デフォルトでは、Lightning ランタイム バージョン 58 以前で実行される画面コンポーネントにはメモリがありません。ユーザーが値を入力して次のいずれかの操作を行うと、値が失われます。
  • 別の画面に移動して、コンポーネントの画面に戻る。
  • フローを一時停止してから再開する。
  • 次の画面に移動して、入力規則エラーをトリガーする。

属性を設定すると、フローで値を記憶できるようになります。フローは値を自動的に保存します。手動で値を保存する場合は、属性の出力値を変数に保存してください。

利用状況

繰り返しコンポーネントを設定したら、繰り返し内で 1 つ以上の子コンポーネントを追加して設定します。フローでは、繰り返しコンポーネントのユーザー入力がコンポーネントの AllItems 属性に保存されます。このコレクションの項目をループ処理して、フローの後半で使用するコレクション変数を作成できます。

AllItems 属性に関する考慮事項

  • 次の場合、AllItems 属性は空です。
    • 繰り返しコンポーネントには、表示テキストコンポーネントなど、ユーザー入力を受け付けない子コンポーネントのみが含まれます。
    • ユーザーが画面に繰り返しインスタンスを追加していない。
  • 条件付き項目の表示によってすべての子コンポーネントが非表示になっている場合、AllItems 属性は null です。
  • AllItems 属性とその値は参照のみです。
  • AllItems 属性は割り当て要素ではサポートされていません。

一般的な考慮事項

  • 繰り返しにアクションボタンコンポーネントまたはレコード項目を含めることはできません。
  • 繰り返しコンポーネントの出力は、変換要素、コレクション検索条件要素、またはコレクション並び替え要素ではサポートされていません。
  • 繰り返し子コンポーネントで別の繰り返しコンポーネントの出力を参照することはできません。
  • [選択肢] 項目でコレクション選択肢セットリソースを参照する選択肢コンポーネントは、繰り返しコンポーネント内では反応しません。
  • 画面を作成または更新するときに、同じ画面のコンポーネントを繰り返しコンポーネントに移動できます。繰り返しコンポーネント内から画面上の別の場所にコンポーネントを移動することもできます。ただし、移動したコンポーネントへの参照は壊れます。
  • [手動で変数を割り当て] チェックボックスがオンになっているコンポーネントを繰り返しコンポーネントに移動すると、手動割り当ては削除され、チェックボックスはオフになります。ただし、変数はフローにまだ存在します。移動後にコンポーネントを確認して、破損した参照が含まれていないことを確認することをお勧めします。
  • ユーザーは、実行時に繰り返しコンポーネントのインスタンスを 30 個まで画面に追加できます。
  • コンポーネント自体内の繰り返しコンポーネントへの参照の形式は {!repeaterAPIName.fieldName} です。検証メッセージとフローメタデータパッケージでは、同じ参照の形式は {!repeaterAPIName.AllItems[$Items].fieldName} です。

使用方法

セクションを使用して画面コンポーネントと項目を整理することで、ユーザーにコンテキストを提供し、ナビゲーションを容易にします。[セクション] コンポーネントには、省略可能なヘッダーと最大 4 つの横並びの列が含まれます。各列には、複数のコンポーネントと項目を表示できます。画面に複数のセクションを配置し、各セクションに独自のヘッダーと列数を設定できます。

ヒント 条件付き表示ルールをセクションに適用すると、そのセクションのすべてのコンポーネントと項目に適用されます。列が 1 つしかない場合でも、この方法を使用して多数のコンポーネントに対して表示ルールを 1 回だけ設定します。

  • ヘッダー (1) — セクションヘッダーを使用して視覚的階層を作成し、画面の最も重要な項目にユーザーを誘導します。ヘッダーを含むすべてのセクションは折りたたみ可能で、ユーザーが画面にアクセスするたびにデフォルトで開いて表示されます。セクションヘッダーの表示ラベルの翻訳も可能です。
  • 列 (2) — 列を使用して画面を整理することで、ユーザーが無駄にスクロールしなくても済むようにします。
  • 列幅 (3) — 新しい列を追加または削除すると、そのセクションのすべての列の幅が等しくなるように設定されます。列の幅を変更するには、ドロップダウンから幅を選択します。
  • 列を列の順序 (4) — 削除すると、その列のすべてのコンポーネントと項目が削除されます。
ヒント コンポーネントと項目の中央揃えやインデント、またはパディングの追加は、画面に空の列を追加することで行います。
