Flow Builder に関する考慮事項

Flow Builder でフローを作成するときは、その制限と動作についてよく理解してください。たとえば、Flow Builder では、わずかな数のロケールのみがサポートされます。知的財産の保護のため、管理パッケージからインストールされたフローは、フローがテンプレートでない限り、開くことはできません。

必要なエディション

サポートされているエディションを表示する。

Salesforce データへのアクセス

  • Flow Builder では、現在のユーザーに割り当てられている権限とロケールが使用されます。
  • Flow Builder では、Flow Builder を開いたときに存在する情報にアクセスできます。組織のデータまたはメタデータを変更し、フローで参照する必要がある場合は、Flow Builder を閉じて再度開きます。たとえば、Flow Builder が開いているときにカスタム項目を追加するか Apex クラスを変更した場合は、Flow Builder を閉じてからもう一度開きます。

Cloud Flow Designer で保存されたフローを開く

クラウドフローデザイナーで作成したフローバージョンを Flow Builder で開くと、[保存] ボタンが無効になっています。このバージョンを Flow Builder で編集するには、Flow Builder で新しいバージョンとして保存します。

テキストの書式設定

表示テキスト画面コンポーネント、選択肢リソースの表示ラベル、ヘルプテキスト、一時停止確認画面、または入力規則を開くと、Flow Builder は、既存の HTML をリッチテキストに変換します。サポートされない HTML は削除されます。HTML タグの <a>、<b>、<br>、<font>、<i>、<li>、<p>、<span>、<u>、および <div> は、リッチテキストに変換されます。リッチテキストエディターに貼り付けられた HTML は、サポートされません。

リッチテキスト

  • リッチテキストエディターでアップロードされた画像は [ファイル] タブに保存され、組織内の全員が表示できます。
  • リッチテキストエディターでアップロードされた画像は Experience Cloud サイトには表示されません。
  • テキストテンプレートを [Chatter に投稿] アクション、[メールを送信] アクション、またはプレーンテキストが必要なカスタムアクションで使用する場合はプレーンテキストに切り替えてください。をクリックして、[テキスト形式] を選択します。

  • リッチテキストに < などの不完全な HTML 記号を含めると、Flow Builder によって記号と隣接する文字列が削除されます。たとえば、Flow Builder では 2<3 は 2 として表示されます。HTML 記号を表示するには、記号をスペースで囲みます。たとえば、2 < 3 です。

日付/時間の値

実行時に、日付/時間値のタイムゾーンが、Flow Builder に表示される値と異なる場合があります。実行中の日付/時間値は、フローを実行しているユーザーのタイムゾーン設定を反映します。Flow Builder の日付/時間値は、フローを設定するシステム管理者のタイムゾーン設定を反映します。

制限

  • フロー要素 [レコードを取得] または [レコードを更新] を実行する各フローインタビューでは、この要素で SOQL クエリが使用されるため、最大文字数に SOQL クエリ制限が適用されます。フローインタビューあたりの各要素の SOQL クエリ制限は 100,000 文字です。たとえば、フローインタビューで、取引先 ID のコレクションに対して In 演算子を使用するレコードを取得要素を実行するとします。要素に 4,700 件を超える ID の取引先 ID のコレクションが含まれていて、他の条件を指定して 100,000 文字の制限を超えた場合、フローインタビューが失敗する可能性があります。

権限

  • Salesforce データベースを操作するフローの場合、関連するレコードと項目を作成、参照、編集、および削除する権限がユーザーにあることを確認します。権限がない場合、ユーザーがフローを起動しようとすると権限が不十分であるというエラーが表示されます。たとえば、フローがケースレコードの状況を検索して更新するとします。このフローユーザーは、ケースオブジェクトの [状況] 項目に対する「参照」権限と「編集」権限が必要です。

変数

  • レコード変数またはレコードコレクション変数を削除すると、削除された変数を使用する変数割り当ては null に設定されます。
  • プロセスまたはフローで別のフローを起動する場合、起動時にそのフローの入力変数に値を割り当てることができます。ただし、コレクションでないテキスト変数、選択リスト変数、複数選択リスト変数では、null の値が空の文字列に変換されます。
  • 画面フローと自動起動フローの場合のみ、レコードを取得要素で項目値を自動的に保存できます。

テキスト値

  • Flow Builder ではユーザー入力項目のテキストで UTF-8 エンコードがサポートされません。

  • Flow Builder にはサポートしているすべてのロケールの埋め込みフォントが含まれています。サポートしているロケールは次のとおりです。

    • 中国語 (繁体字)
    • 中国語 (簡体字)
    • 英語 (米国)
    • フランス語 (フランス)
    • ドイツ語 (ドイツ)
    • 日本語 (日本)
    • スペイン語 (スペイン)

    サポートされるロケールでサポートされていない文字を入力すると、埋め込みフォントではなくシステムフォントを使用して表示されます。

    サポートされていないロケールでは、システムフォント設定は、Flow Builder ですべての文字を表示するために使用されます。

  • Flow Builder のテキストフィールドの値として文字列 null を入力しないでください。

出力値

同じ出力値を複数の変数に保存するには、値を 1 つの変数に割り当てます。次に、割り当て要素をアクションの後に追加し、他の変数を最初の変数の値に設定します。

管理パッケージ

管理パッケージからインストールされたフローがテンプレートでも上書き可能でもない場合、Flow Builder は、そのフローを開くことはできません。

フロー要素

  • ステップ要素: Flow Builder では、ステップ要素をフローに追加または更新できません。また、ステップを画面に変換することもできません。クラウドフローデザイナーでステップが追加された場合、ステップは引き続きキャンバスに表示されます。フローからすべてのステップを削除することをお勧めします。
  • アクション要素: 従来の Apex アクションは、プラグインコードのタグで整理されません。
  • メールアクション要素: メールアクション要素の受信者リストに内部アドレスと外部アドレスの両方が含まれている場合、フローは 2 つの別々のメールを作成して送信します。この分離により、内部メールアドレスが誤って外部閲覧者に表示されることを防ぎます。

Winter '12 以前からアップグレードされたフロー

最後に開いたフローを Winter '12 以前で開くと、各 Boolean 決定は、次の条件の複数結果形式の決定要素に変換されます。

  • 古い決定と同じ表示ラベルを使用する。
  • 古い決定の API 参照名を取得して「_switch」が追加される。
  • 「True」という結果ラベルが付いている。この結果の API 参照名は、古い決定の API 参照名に一致し、その条件は、古い決定の True 結果から移行されます。
  • 「False」というデフォルトの結果ラベルが付いている。

用語

Flow Builder またはクラウドフローデザイナーの一部の警告、エラーメッセージ、およびデバッグの詳細内の用語は更新されていません。

フローの数式に関する考慮事項

数式リソースを作成するか、画面入力コンポーネントに入力規則を追加する場合は、フローでの数式の動作を理解しておく必要があります。

数式関数

  • フロー数式では、次の関数はサポートされません。
    • GETRECORDIDS
    • IMAGE
    • INCLUDES
    • PARENTGROUPVAL
    • PREVGROUPVAL
    • PRIORVALUE
    • REQUIRE SCRIPT
    • VLOOKUP

    Salesforce で数式を作成するための演算子と関数の完全なリストについては、「コンテキスト別の数式の演算子と関数」を参照してください。

  • フローでは、括弧内のすべての文字が CONTAINS 関数でチェックされます。クロスオブジェクト項目の参照では、CONTAINS は Salesforce の他の部分と同様に動作します。参照の最初の 250 文字のみがチェックされます。

    例を示します。varContract は、契約レコードの値が含まれるレコード変数です。次の数式は、最初の 250 文字のみをチェックします。 

    CONTAINS({!varContract.Account.Description}, "description")

    次の数式は、項目内のすべての文字をチェックします。 

    CONTAINS({!varContract.Description}, "description")

数式でのフローデータ

  • 数式でのグローバル変数への参照は検証されません。
  • 数式でプラットフォームイベントを参照するには、イベントデータを待機要素のレコード変数に渡します。次に、そのレコード変数内の該当の項目を参照します。
  • null 項目値を 0 値として評価するには、BLANKVALUE 関数を使用します。たとえば、NumberOfEmployees 項目の null 値を 0 値として評価するには、BLANKVALUE(NumberOfEmployees, 0) を使用します。

同じ画面でリソースを参照する数式

  • 数式がユーザー入力の検証に使用され、数式と同じ画面要素のリソースを参照している場合、一部の数式関数はサポートされていません。例: REGEX。サポートされる数式関数のリストについては、Reactive Screen Flow Formula Operatorsを参照してください。
  • 数式が同じ画面要素のリソースを数式で参照している場合、その数式はパーセントに従います。たとえば、値が 100 の場合、1.00 と評価されます。 それ以外の場合、パーセントは考慮されません。たとえば、値が 100 の場合、100 として評価されます。

注意点

  • フローの数式に含めることができる文字数は最大 3,900 文字です。
  • 数式を貼り付ける場合、アポストロフィーと引用符がストレート (") であり、カーリー (‘’) ではないことを確認してください。ストレートでない場合、フローを保存するときに構文エラーが発生します。
  • レコード数式項目は、Salesforce Classic での評価とまったく同様にフローで評価されます。レコード数式項目が NOT(null/blank) をチェックすると、FALSE と評価されます。

エラー

式の評価時に次のようなエラーが発生した場合、数式は null を返します。

  • 数式から返される値がそのデータ型と一致しない。
  • サポートされない関数が数式に含まれている。

    たとえば、数式リソースのデータ型が数値である場合、出力は数値である必要があります。

フローに無効な数式リソースが含まれていると、フローを有効化できません。[表示テキスト] 画面コンポーネントに無効な数式リソースが含まれていると、実行時にフローに空の文字列が表示されます。

2 列フローに関する考慮事項

組織で Lightning ランタイムを有効にしている場合は、そのフローを 1 列で表示するか、2 列で表示するかを制御できます。この機能を使用する前に、フローレイアウトの現在の動作方法を把握してください。

必要なエディション

サポートされているエディションを表示する。
メモ Winter ’23 以降では、2 列フローレイアウトは無視されます。レイアウトオプションを改善するには、[セクション] コンポーネントをフロー画面に追加します。各 [セクション] コンポーネントでは、レコード項目と画面コンポーネントを幅が調整可能な最大 4 列に整理できます。

次の考慮事項は、フロー画面の [セクション] コンポーネントには適用されません。

細分性

レイアウト設定はフローレベルで適用されます。画面レベルまたは項目レベルでレイアウトを制御することはできません。2 列を使用するようにフローを設定すると、そのフローのすべての画面は 2 列で表示されます。

項目の順序

どの項目をどの列に表示するかを手動で制御することはできません。2 列を表示するようにフローを設定すると、項目は各列に交互に表示されます。奇数番目の項目 (第 1、第 3、第 5 など) は左列に配置されます。偶数番目の項目 (第 2、第 4、第 6 など) は右列に配置されます。

ユーザーが Tab キーで画面を移動すると、左列のすべての項目にタブで移動してから、右列のすべての項目に移動します。左から右にタブで移動するように項目を設定することはできません。

応答性

フローレイアウトはユーザーの画面のサイズに対応しません。ユーザーの画面が幅 1 インチでも、幅 20 インチでも、同じレイアウトが使用されます。

ヒント ユーザーが携帯電話または小型タブレットからフローを実行する場合、2 列レイアウトをフローに適用しないでください。

[セクション] コンポーネントとの互換性

エクスペリエンスビルダー、Lightning アプリケーションビルダー、またはユーティリティバーを使用して配布されたフローの場合、[セクション] コンポーネントを含む各フロー画面では [レイアウト] プロパティが無視されます。

URL によって配布されるフローの場合、[セクション] コンポーネントが含まれる各フロー画面では flowLayout URL パラメーターが無視されます。

フローの複数選択リソースおよび画面項目に関する考慮事項

チェックボックスグループ、複数選択リスト、選択肢ルックアップ画面コンポーネントを使用すると、フローユーザーは複数の選択肢を選択できます。これらの画面コンポーネントの使用を開始する前に、フローを設計するときおよびユーザーがフローを実行するときにフローでこれらのコンポーネントがどのように機能するかを理解しておきます。

必要なエディション

サポートされているエディションを表示する。

チェックボックスグループ、複数選択リスト、または選択肢ルックアップ画面コンポーネントの設定

  • これらの画面コンポーネントでは 1 つのデフォルト値のみがサポートされます。複数のデフォルト値を個々に選択することはできません。ただし、デフォルト値項目に手動で値を追加し、それぞれの値をセミコロンで区切ることができます。
  • レコード選択肢セットリソースを設定して、ユーザーが選択したレコードの項目値をフローの変数に割り当てることができます。チェックボックスグループ、複数選択リスト、または選択肢参照画面コンポーネントでレコード選択肢セットを使用する場合、ユーザーが選択した最後のレコードの値のみがフロー変数に保存されます。1 つの画面上の複数のチェックボックスグループコンポーネント、複数選択リストコンポーネント、または選択肢ルックアップコンポーネントで同じレコード選択肢セットを使用する場合、それらのすべてのコンポーネントから選択された最後のレコードに従って変数が割り当てられます。

チェックボックスグループ、複数選択リスト、または選択肢ルックアップ画面コンポーネントの値の使用

  • 実行時に、チェックボックスグループ、複数選択リスト、または選択肢ルックアップ画面コンポーネントの値は、ユーザーが選択した選択肢の値をセミコロンで区切った連結値になります。選択した選択肢の値にセミコロンが含まれる場合、そのセミコロンは削除されます。
  • チェックボックスグループ、複数選択リスト、または選択肢ルックアップ画面コンポーネントをフロー条件内で参照する場合、次の点に注意してください。
    • 画面コンポーネント内の各選択肢の選択肢値が設定されていることを確認します。
    • 同一画面上の複数のチェックボックスグループ画面コンポーネント、複数選択リスト画面コンポーネント、または選択肢参照画面コンポーネントで同じ選択肢を使用することはできません。
  • [チェックボックスグループ]、[複数選択リスト]、または [選択肢ルックアップ] にデフォルト値が 1 つ以上ある場合、選択肢の値とデフォルト値が一致すれば、実行時に選択肢が事前に選択されます。

一時停止中のフローインタビューに関する考慮事項

待機要素を含むフローを設計する場合は、その動作とガイドラインを理解しておく必要があります。

必要なエディション

使用可能なインターフェース: Salesforce Classic (使用できない組織もあります) および Lightning Experience の両方

時間ベースの再開イベントを使用可能なエディション: Essentials Edition、Professional Edition、Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

プラットフォームイベントベースの再開イベントを使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition

一般的な考慮事項

  • フローバージョンを無効にした後も、その一時停止中のインタビューは、設定された再開イベントを引き続き待機します。フローバージョンがインタビューを一時停止している場合、そのフローバージョンを削除することはできません。
  • インタビューは、待機要素ごとに 1 つのコネクタのみを実行できます。その再開イベントの 1 つが処理されると、残りの再開イベントがキューから削除されます。
  • Salesforce が待機コネクタを実行しようとしたときにインタビューを開始したユーザーが無効化されている場合、インタビューの再開に失敗します。
  • フローが一時停止しており、フローインタビューが 1 MB を超えた場合、インタビューは保存に失敗し、再開できなくなります。
  • 待機要素 を含むフローをコールすることはできません。
  • 画面アクションの自動起動フローの待機要素は、画面フローの実行時に機能しません。

トランザクションおよび一時停止中のインタビュー

フローインタビューが 1 つまたは複数の再開イベントを待機するために一時停止した時点で、トランザクションは終了します。フローインタビューが再開すると、新しいトランザクションが開始します。待機要素の後にあるものはすべて、再開された他のインタビューを含む一括処理トランザクションの一部として実行されます。

インタビューは個別に再開されません。インタビューは 1 つのバッチにグループ化され、そのバッチは最初のアクションがバッチに入ってから 1 時間以内に再開されます。グループインタビューの結果として実行されるアクションも、トランザクションで実行されます。バッチには、同時に再開され、同じフロー バージョン ID を持ち、同じユーザ ID で実行される他のインタビューを含めることができます。再開されたインタビューが DML 操作または SOQL クエリを実行する場合、この動作によって Apex ガバナ制限を超える可能性があります。詳細は、「トランザクション単位のフローの制限」を参照してください。

  • フロー要素 (レコードの作成、Apex アクション (従来) など)
  • Apex トリガー
  • ルール適用時のアクション

DML 操作または SOQL クエリを実行するフロー要素の前に待機要素がある場合:

  • 待機要素間で制限を超える可能性のある DML 操作または SOQL クエリを 1 人のユーザーがフローを使用して実行できないことを確認します。
  • DML 操作や SOQL クエリが複数のトランザクションで実行されるように複数の待機要素を使用することを考慮します。
  • これらの要素に障害パスを追加して、障害メッセージに「Too many SOQL queries (SOQL クエリが多すぎます)」または「Too many DML operations (DML 操作が多すぎます)」が含まれている場合にフローが待機要素に戻るようにします。

再開後のインタビューが失敗した場合

  • そのバッチのトランザクションの以前のインタビューは正常に実行されています。
  • インタビューが一時停止する前に実行した操作は成功しています。
  • 失敗が障害パスによって処理されたときは、インタビューが再開されてから失敗するまでに行われた操作は正常に実行されています。インタビューの失敗の原因になった操作は正常に実行されていません。
  • 障害パスで障害が処理されない場合、インタビューが再開されてから失敗するまでの間に実行された操作はロールバックされます。インタビューの失敗の原因になった操作は正常に実行されていません。
  • このバッチの残りのインタビューは試行されます。

プラットフォームイベント

ヒント プラットフォームイベントの考慮事項と割り当てについても確認してください。
  • サポートされるプラットフォームイベント

    フローでカスタムプラットフォームイベントと以下の標準プラットフォームイベントを登録できるようになりました。

    • AIPredictionEvent
    • BatchApexErrorEvent
    • FlowExecutionErrorEvent
    • FOStatusChangedEvent
    • OrderSummaryCreatedEvent
    • OrderSumStatusChangedEvent
    • PlatformStatusAlertEvent
  • 数式 — 数式でプラットフォームイベントを参照するには、イベントデータを待機要素のレコード変数に渡します。次に、そのレコード変数内の該当の項目を参照します。
  • 値の切り捨て — プラットフォームイベントメッセージを絞り込む場合、条件の値が 765 文字を超えることはできません。
  • [登録] 関連リスト — プラットフォームイベントの詳細ページの [登録] 関連リストには、そのプラットフォームイベントのメッセージの受信を待機しているエンティティが表示されます。関連リストには、各登録済みプロセスへのリンクが含まれます。フローインタビューがそのプラットフォームイベントのメッセージを待機している場合、1 人の「プロセス」登録者が [登録] 関連リストに表示されます。
  • イベントのアンインストール — プラットフォームイベントを含むパッケージをアンインストールする前に、プラットフォームイベントのメッセージを待機しているインタビューを削除します。
  • Einstein 予測 — Einstein 予測結果ごとに予測イベントが送信されます。このため、特定のオブジェクトの予測でのみフローをトリガーする場合は、イベントの条件絞り込みを使用します。たとえば、フローが使用する待機要素が、リードレコードに書き込まれた予測に基づいてのみ動作する場合は、再開イベントを追加して、AIPredictionEvent.TargetId 項目が現在のレコードに等しいことを確認します。

    Einstein 予測で使用される項目をフローが更新した場合、Einstein は、予測を再実行して、新しい結果を再び書き込みます。この新しい結果により、フローを再びトリガーできる新しい予測イベントが生成され、ループが作成されます。ループが作成されないようにするには、Einstein 予測で使用されない項目のみを更新します。

プラットフォームキャッシュ

フローに待機要素が含まれる場合は、フロー内のそれ以降の要素が、セッションキャッシュ値を保存または取得する Apex コードを呼び出さないことを確認します。Apex アクションと、Apex トリガーを起動させるデータベースに対してフローが行った変更には、セッションキャッシュの制限が適用されます。

時間ベースの再開イベント

  • 時間ベースの再開イベントは、分および秒をサポートしていません。
  • インタビューが過去の時間を待機している場合、Salesforce はできるだけ早くインタビューを再開します。Salesforce がその時点で処理しているアクションの数に応じて、アクションは 1 時間以内に実行されます。

    たとえば、完了予定日の 7 日前に商談所有者にメールを送信するフローが設定されているとします。完了予定日が今日に設定された商談についてインタビューが開始されます。Salesforce は 1 時間以内にインタビューを再開します。

  • 組織は、時間ベースの再開イベントを 1 時間につき最大 1,000 件処理できます。再開イベントが処理されると、それに関連付けられているインタビューが再開され、そのインタビューの他の再開イベントがキューから削除されます。組織がこの制限を超えると、Salesforce は残りの再開イベントを次の 1 時間に処理するように延期します。

    たとえば、午後 4 時から 5 時の間に組織に 1,200 の再開イベントの処理がスケジュールされているとします。Salesforce は、午後 4 時から午後 5 時の間に 1,000 の再開イベントを処理し、残りの 200 の再開イベントは午後 5 時から午後 6 時の間に処理します。

  • 一時停止中のインタビューの時間ベースの再開イベントで参照されている商品または価格表はアーカイブできません。

フローベースの時間

特定の時間に基づく再開イベントの場合、再開時間は、フローを作成したユーザーのタイムゾーンに基づいて評価されます。

レコードベースの時間

  • レコードの項目値に基づく再開イベントの場合、再開時間は、組織のタイムゾーンに基づいて評価されます。
  • 再開イベントで次の項目は参照できません。
    • TODAY や NOW など、自動的に派生する関数を含む DATE または DATETIME 項目。
    • 関連オブジェクトの差し込み項目が含まれる数式項目。
  • 再開イベントによって参照され、一時停止中のインタビュー内でまだ実行されていない日付項目を変更すると、Salesforce はインタビューに関連付けられた再開イベントを再計算します。

    たとえば、完了予定日の 7 日前に商談所有者にメールを送信するフローが設定され、完了予定日が 2014 年 2 月 20 日に設定されているとします。 この場合、次の動作が発生する可能性があります。

    • インタビューが再開される前に完了予定日が更新されない。結果: Salesforce は 2014 年 2 月 13 日にインタビューを再開し、メールを送信します。
    • インタビューが再開される前に完了予定日が 2014 年 2 月 10 日に更新される。結果: Salesforce は再開イベントを再スケジュールし、2014 年 2 月 3 日にインタビューを再開します。
    • 完了予定日が過去の日付に更新される。結果: Salesforce は再開イベントを再計算し、レコードが保存された直後にインタビューを再開します。
  • インタビューが待機要素を実行したときに再開イベントで null の日付項目が参照された場合、Salesforce はできるだけ早くインタビューを再開します。Salesforce がその時点で処理しているアクションの数に応じて、アクションは 1 時間以内に実行されます。
  • フローインタビューが待機要素を実行したときに再開イベントで null 以外の値の日付項目が参照され、再開イベントが処理される前に日付項目が null に更新された場合、Salesforce は日付項目の更新後 1 時間以内にインタビューを再開します。
  • 再開イベントで参照されているレコードまたはオブジェクトが削除された場合、最回イベントはキューから削除されます。インタビューに待機する再開イベントが他にない場合は、そのインタビューが削除されます。
  • リードの取引開始の制限
    • 一時停止中のインタビューの再開イベントで参照されているリードの取引を開始することはできません。
    • [リード変換からの検証とトリガー] が有効になっている場合は、リードの取引開始時に、待機要素後のリードに対する既存の操作が実行されません。
    • リードに基づくキャンペーンメンバーの取引が、そのレコードに関連付けられている一時停止中のインタビューが終了する前に開始されても、Salesforce はインタビューを実行します。

フローステージと標準の進行状況インジケーターに関する考慮事項

フローにフェーズを追加して標準の進行状況インジケーターを使用する前に、次の考慮事項に留意してください。

必要なエディション

サポートされているエディションを表示する。
メモ

標準の進行状況インジケーターには Lightning ランタイムが必要です。

フェーズの参照

  • 表示テキストコンポーネント値で、またはチェックボックス、チェックボックスグループ、選択肢ルックアップ、通貨、日付、日時、ロングテキストエリア、複数選択リスト、数値、パスワード、選択リスト、ラジオボタン、テキスト画面コンポーネントのいずれかのラベルでステージの差し込み項目が使用されている場合、ステージの差し込み項目はステージのラベルに解決されます。その他の場所では、フェーズの差し込み項目はフェーズの完全修飾名 (namespace.flowName:stageName または flowName:stageName) に解決されます。
  • できる限り、{!myStage} などのフェーズの差し込み項目を使用してフェーズを参照してください。
  • サブフローのフェーズを参照する場合は、完全修飾名を使用します。
  • フローのデバッグ時に、表示テキストコンポーネント値で、またはチェックボックス、チェックボックスグループ、選択肢ルックアップ、通貨、日付、日時、ロングテキストエリア、複数選択リスト、数値、パスワード、選択リスト、ラジオボタン、テキスト画面コンポーネントのいずれかのラベルでステージの差し込み項目を使用する場合、デバッガーで差し込み項目値は更新されません。

デフォルトで有効なフェーズ

ステージリソースを[デフォルトでアクティブ]としてマークすると、フローでグローバル変数の値が自動的に設定されます。この設定は、ステージがフローのすべてのパスに適用される場合に使用してください。

実行時に、デフォルトで有効なフェーズが昇順で並び替えられます。フローでデフォルトのアクティブなステージを使用して $Flow.ActiveStages および $Flow.CurrentStage を更新する方法は、フローが上位フローか参照されるフローかによって異なります。

上位フローのステージ

デフォルトのアクティブなステージは昇順で$Flow.ActiveStagesに追加されます。$Flow.CurrentStage は、順序が最も小さいデフォルトのアクティブなステージに設定されます。

フローがステージのあるフローとステージのないフローの 2 つを参照する場合、フローの最後に $Flow.ActiveStage の値が null に設定されるようにステージのあるフローを設定します。次に、フローの開始時に $Flow.CurrentStage の値をステージ 1 に設定します。

参照されるフローのステージ

デフォルトのアクティブなステージは昇順で$Flow.ActiveStagesに挿入されます。$Flow.CurrentStageは自動的に更新されません。

  • $Flow.CurrentStage が $Flow.ActiveStages に含まれる場合、デフォルトのアクティブなステージは、$Flow.ActiveStages で $Flow.CurrentStage の後に挿入されます。

    たとえば、Flow1 は $Flow.ActiveStages を「1、2、3、4」、$Flow.CurrentStage を「3」に設定します。次に、サブフロー要素を使用して Flow2 をコールします。Flow2 のデフォルトのアクティブなステージは「A、B、C」です。Flow2 が開始されると、$Flow.ActiveStages は「1、2、3、A、B、C、4」になります。$Flow.CurrentStage は「3」のままです。

  • $Flow.CurrentStage が $Flow.ActiveStages に含まれない場合、デフォルトのアクティブなステージは $Flow.ActiveStages の最後に追加されます。

    たとえば、Flow1 で $Flow.ActiveStages を「1、2、3、4」に設定し、$Flow.CurrentStage は設定しないとします。サブフロー要素を使用して、フロー 2 をコールします。 フロー 2 のデフォルトで有効なフェーズは「A、B、C」です。フロー 2 が開始されると、$Flow.ActiveStages は「1、2、3、4、A、B、C」になります。$Flow.CurrentStage は未設定のままです。

  • $Flow.ActiveStages で $Flow.CurrentStage が重複している場合、デフォルトのアクティブなステージは最初の出現の後に付加されます。

    たとえば、Flow1 は $Flow.ActiveStages を「1、2、2、3、4」、$Flow.CurrentStage を「2」に設定します。次に、サブフロー要素を使用して Flow2 を /call します。Flow2 のデフォルトのアクティブなステージは「A、B、C」です。フロー2 が開始されると、$Flow.ActiveStages は「1、2、A、B、C、2、3、4」になります。$Flow.CurrentStage は「2」のままです。

その他のステージに関する考慮事項

  • 画面要素が読み込まれるときに、ステージが関連付けられている場合、フローは $Flow.ActiveStages グローバル変数をチェックして、関連付けられたステージが存在するかどうかを確認します。含まれていない場合、フローは関連付けられたステージを $Flow.ActiveStages グローバル変数の最後に追加します。
  • フローエラーメールでは、インタビューの開始時に $Flow.ActiveStages と $Flow.CurrentStage の値は指定されません。初期値を確認するには、一時的な要素を追加して、表示テキスト画面コンポーネントを含む画面要素などに初期値を表示します。

標準の進行状況インジケーターに関する考慮事項

  • 新しいフローでは、標準の進行状況インジケーターがデフォルトで有効になっています。既存のフローの場合、標準の進行状況インジケーターを有効にします。
  • 標準の進行状況インジケーターが有効になっていてもフローにフェーズがない場合、進行状況インジケーターは実行時に画面に表示されません。
  • 画面要素の編集ウィンドウで、進行状況インジケーターのプレビューに表示されるフェーズはサンプルフェーズであり、フローの実際のフェーズではありません。
  • 標準の進行状況インジケーターは Field Service Mobile フローまたは Salesforce Scheduler フローではサポートされません。
  • フローがアクション & レコメンデーション Lightning ページコンポーネントに実装されている場合は、標準の進行状況インジケーターはサポートされません。
  • フッターの進行状況インジケーターは、624 ピクセル未満の画面ではサポートされません。モバイルデバイスなどの小さい画面で進行状況インジケーターを使用するには、進行状況インジケーターを画面の上部に追加します。
  • パススタイルの進行状況インジケーターは、小さい画面または Lightning ページの小さい列にシンプルなスタイルとして表示されます。
  • 標準の進行状況インジケーターには、最大 20 個のステージを表示できます。最適なユーザーエクスペリエンスを得るには、7 個以下のステージにすることをお勧めします。

フロー変数に関する考慮事項

変数リソースを作成する前に、フローでの変数の動作を理解しておく必要があります。

必要なエディション

サポートされているエディションを表示する。

この動画では、変数とは何か、およびフローで変数を使用してデータを保持する方法について説明します。

この動画は別のタブでご覧ください。

このビデオでは、一般的な型、Boolean型、Apexで定義された変数、コレクション変数などの変数の型について説明します。

この動画は別のタブでご覧ください。

空白の項目またはリソースの参照

  • 項目またはリソースの値を空白のままにすると、実行時にその値は null になります。テキスト値を null ではなく空の文字列として処理するには、その値を {!$GlobalConstant.EmptyString} に設定します。

Boolean 変数

  • Boolean 型では null の処理が false とは異なります。
  • フローでは、null を false とは異なる値として扱います。たとえば、チェックボックス項目が null に設定されているレコードを見つけようとすると、返されるレコードはありません。この場合は、チェックボックス項目が false に設定されているレコードを探します。変数 (myCheckbox = {!varBoolean} など) を使用している場合、変数をレコード検索条件または条件で参照する前に、その変数が null に設定されていないことを確認します。

数値変数

  • 数値変数はデフォルトで整数として処理されます。

パーセント変数

  • フローでレコード変数を使用してパーセント値を操作する場合、フローを慎重にテストしてください。レコード変数のパーセント項目に値を挿入し、数式内でその項目を参照すると、その値は 100 で割った値になります。

    たとえば、商談の [確度] 項目が 100 に設定されているとします。 その値を{!Opportunity.Probability}レコード変数に割り当てても、値は 100 のままです。 ただし、式が {!Opportunity.Probability} の数式を作成すると、値は 1 になります。

レコード変数

  • レコードおよびレコードコレクション変数では、Salesforce オブジェクトのみがサポートされます。

入力/出力で使用可能

  • 既存の変数の入力または出力アクセスを無効にすると、フローをコールして変数にアクセスするアプリケーションやページの機能が停止する可能性があります。たとえば、URL パラメーター、サブフロー、プロセスから変数にアクセスできます。
  • 新しい入力変数または出力変数をフロー上書きに追加することはできません。既存の変数を削除できますが、Lightning コンポーネントなどのコール元コンポーネントが削除済みの入力変数を使用しようとすると、入力変数を削除すると実行時エラーが発生します。

入力変数の設定

  • プロセスビルダー: プロセスまたはフローで別のフローを起動する場合、起動時にそのフローの入力変数に値を割り当てることができます。ただし、コレクションでないテキスト変数、選択リスト変数、複数選択リスト変数では、null の値が空の文字列に変換されます。
    重要 プロセスビルダーのサポートと更新は、2025 年 12 月 31 日に終了する予定です。「Workflow Rules & Process Builder End of Support (ワークフロールールとプロセスビルダーのサポート終了)」を参照してください。

    2025 年 12 月 31 日以降は、既存のプロセスを引き続き有効化、無効化、編集できます。既存のプロセスを移行するには、Flow Builder への切り替えを計画し、Migrate to Flow ツールを使用します。新しい自動化の場合は、Flow Builder でフローを作成します。

  • アクション: フローアクションでは、レコードの ID 項目の値をフローに渡すことができますが、それだけです。フローに recordId というテキスト入力変数があれば、アクションの実行時にレコードの ID がその変数に渡されます。ない場合は、レコード ID は渡されず、フローはそのまま実行されます。
  • Lightning アプリケーションビルダー: コレクション変数、レコード変数、レコードコレクション変数はサポートされません。フローコンポーネントの入力変数には、手動で入力された値のみがサポートされます。テキスト入力変数に使用できるのは最大 4,000 文字です。
  • サブフロー要素: サブフロー入力に変数を渡す場合、変数の API 参照名は最大 40 文字です。

フローの配布

  • フローを配布するとき、URL パラメーターを使用して Salesforce レコードから通貨項目値をフローの通貨変数に渡さないでください。通貨項目が差し込み項目 ({!Account.AnnualRevenue} など) を介して参照される場合、値には通貨単位の記号 ($ など) が含まれます。フローの通貨変数で受け入れられるのは数値のみであるため、フローは実行時にエラーになります。代わりに、URL パラメーターを使用してレコードの ID をテキスト変数に渡します。フローでは、その ID を使用して該当するレコードの通貨項目の値を検索してください。

フロー Lightning ランタイムに関する考慮事項

フローを実行するときは、次の点を考慮してください。

必要なエディション

サポートされているエディションを表示する。
メモ Lightning ランタイムでは、フローユーザーは常にアクティブなフローバージョンを実行します。「フローの管理」権限を持つフロー管理者は最新のフローを実行するため、フローユーザー向けに有効化しなくても最新のフローバージョンをテストできます。フロー管理者は、サブフロー要素経由で参照される最新のフローも実行します。

フローインタビュー

フローインタビューはフローのインスタンスです。これはレコードがオブジェクトのインスタンスであることとよく似ています。フローインタビューでは、Salesforce データの検索と処理など、多くのことを行うことができます。インタビューで、データを変数や他のリソースに渡すことができます。データは、さまざまなソース (フローで照会した Salesforce レコード、ユーザーが画面の入力項目に入力する情報、手動で入力する情報など) から取得します。

インタビューは、関連付けられているトランザクションが完了するまで、アクション (メールの送信、レコードの作成、編集、削除など) を実行しません。インタビューが完了または実行されたときに、画面、ローカルアクション、または待機要素がトランザクションに反映されます。データ要素の他に、Chatter に投稿、承認申請、およびクイックアクションの各コアアクション要素でもレコードが作成または更新されます。

処理中のインタビューのデータは Salesforce データベースに保存されません。フローでレコードを作成または更新する要素 ([レコードを更新] や [Chatter に投稿] など) を実行すると、その要素で設定された情報のみが Salesforce データベースに保存されます。

インタビューが待機要素を実行したり、ユーザーがインタビューを一時停止したりすると、すべてのインタビューデータが逐次化され、一時停止中のフローインタビューレコードとしてデータベースに保存されます。インタビューが再開されると、一時停止中のフローインタビューレコードが削除されます。

フローの Lightning ランタイムの制限

Salesforce 組織で Lightning ランタイムを有効にしているとき、Lightning Experience のフローは次のものに読み込まれません。

  • Web タブ
  • サイドバー付きまたはサイドバーなしで現在のウィンドウを表示するように設定されているリストボタン

組織で Lightning ランタイムを有効にしている場合、サイドバー付きまたはサイドバーなしの既存のウィンドウに表示されるように設定されているカスタムボタンまたはカスタムリンクに Salesforce Classic のフローは読み込まれません。

数値入力項目には、小数点以上と小数点以下の桁も含めて 17 桁までの数値を入力できます。

実行時、ユーザーがエラーを修正しても、検証エラーメッセージは画面フローコンポーネントで表示されたままになります。ユーザーはメッセージがあってもフローインタビューを完了できます。

フローランタイムのアクセシビリティに関する考慮事項

Salesforce では、画面フロー実行時の環境をリハビリテーション法セクション 508 および Web Content Accessibility Guidelines (WCAG) 2.0 レベル AA で定められているベストプラクティスに準拠させるように努めています。ただし、いくつかの例外があります。

必要なエディション

  • [次へ] または [前へ] をクリックしても画面のタイトルは変わらないため、異なるページに切り替えたことが明白ではない場合もあります。
  • 表示ラベルが定義されていないフロー画面コンポーネントは、支援技術で適切に読み取ることができません。
  • 支援技術でエラーを識別するために ARIA アラートロールや他の方法を使用していない限り、これらのカスタムエラーメッセージは支援技術では検出できません。
    • 条件付き表示が設定されたテキストコンポーネントのエラーメッセージ
    • 関連付けられた [入力を検証] 数式が false に評価されたときにコンポーネントに表示されるエラーメッセージ

    • URL
    • カスタムボタンとカスタムリンク
    • Web タブ
  • Salesforce で用意されているコンポーネントの一部のエラーメッセージは、対応する入力項目には関連付けられていません。この制限により、関連付けられているエラーメッセージをスクリーンリーダーが読み上げることができません。影響を受ける Salesforce 提供のコンポーネント:
    • 連動選択リスト
    • メール
    • 参照
    • 電話
    • 切り替え
    • URL

  • 画面が最初に表示された後に画面のコンポーネントやその一部が表示された場合は、それらにフォーカスを設定することはできません。たとえば、コンポーネントが非同期で ToDo リストを取得して表示した場合は、フォーカスをどの ToDo にも設定できません。画面コンポーネントで条件付き表示が使用されていて、ユーザー入力の後でなければ表示されない場合、その画面コンポーネントのどの部分にもフォーカスを設定することはできません。

フローの管理に関する考慮事項

フローを管理する場合、管理および有効化の制限を考慮します。

必要なエディション

サポートされているエディションを表示する。

フローの表示

Lightning Experience では、ユーザが ［すべてのフロー］ リスト ビューの ［共有設定］ を ［このリスト ビューを表示できるのは私のみです］ に設定した場合、［設定］ の ［フロー］ ページにフローは表示されません。

フローの有効化

フローの新バージョンを有効化すると、以前に有効化されたバージョン (存在する場合) は自動的に無効になります。実行中のフローインタビューは、起動されたときのバージョンを使用して実行を続行します。

フローを有効化したユーザーが無効化されると、フローは機能しなくなります。これは、フォームトリガーフローやセグメントトリガーフローなど、すべてのフロー種別に適用されます。

フローの削除

有効なフローバージョンを削除するには、まず無効化する必要があります。フローに一時停止中のインタビューがある場合は、これらのインタビューが終了または削除されるまで削除できません。どの時点でも有効化されなかったフローは削除できます。

フロー種別

フローに異なる種別のバージョンがある場合、そのフロー種別は、有効な (または最新の) バージョンによって決定されます。

フローのリリース

本番組織では、変更セットまたはメタデータ API を使用して、プロセスまたはフローの新しい有効なバージョンをリリースする設定を有効にできます。スクラッチ組織、Sandbox 組織、開発者組織などの非本番組織では、新しい有効なバージョンを常にデプロイできるため、この設定は表示されません。

パッケージからインストールされたフローの考慮事項

パッケージからインストールしたフローを配布、アップグレード、または削除する場合は、次の制限を考慮してください。

必要なエディション

サポートされているエディションを表示する。
  • 管理パッケージからインストールされたフローがテンプレートでも上書き可能でもない場合、Flow Builder は、そのフローを開くことはできません。
  • 新規の対象組織に複数のバージョンのフローを含む管理パッケージをインストールすると、最新バージョンのフローのみがリリースされます。
  • 非テンプレートフローを管理パッケージからインストールした場合は、そのフローのインタビューのエラーメールに個別のフロー要素に関する詳細が記載されません。メールはフローをインストールしたユーザーまたは Apex 例外メールの受信者に送信されます。
  • 組織に存在するフローと同じ名前で、異なるバージョン番号を持つ未管理のパッケージからフローをインストールする場合、新たにインストールされたフローは、既存のフローの最新バージョンになります。ただし、パッケージ化されたフローの名前とバージョン番号が組織のフローのものと同じである場合、パッケージのインストールは失敗します。フローを上書きすることはできません。
  • 組織に存在するフローと同じ名前のロック解除済みパッケージからフローをインストールすると、新たにインストールされたフローで既存のフローが上書きされます。

状況

パッケージの有効なフローは、インストール後は有効です。新しくインストールされたバージョンが優先され、対象組織のフローの以前の有効なバージョンは無効になります。現在無効になっているバージョンに基づく進行中のフローがある場合は、引き続き無停止で実行できますが、前のバージョンのフローが反映されます。

インストールされたフローの配布

  • 管理パッケージからインストールされたフローにカスタムボタン、リンク、Web タブを作成する場合は、URL に名前空間を含めます。URL の形式は /flow/namespace/flowuniquename です。
  • Visualforceページに管理パッケージからインストールされたフローを埋め込む場合は、name属性をこの形式 namespace.flowuniquename に設定します。

インストールされたフローのアップグレード

組織で管理パッケージのアップグレードを行うと、開発者からより新しいフローバージョンがリリースされている場合に限り、新しいフローバージョンがインストールされます。複数回アップグレードを行うと、フローバージョンが複数になることがあります。

インストールされたフローの削除

  • インストール済みのパッケージからフローを削除することはできません。パッケージ化されたフローを組織から削除するには、無効にしてからパッケージをアンインストールします。
  • パッケージング組織では、リリース済みまたはベータ版の第一世代管理パッケージにアップロードしたフローを削除することはできません。リリース済みまたはベータ版の第一世代管理パッケージにアップロードしたフローバージョンをパッケージング組織から削除できるのは、次の条件をすべて満たしている場合です。
    • Salesforce カスタマーサポートが管理コンポーネントの削除権限を有効化した。
    • フローバージョンが、フローの最新のパッケージバージョンではない。
    • フローバージョンが有効ではない。
    • フローバージョンは唯一のバージョンではありません。
  • 複数の未管理パッケージからインストールされた複数のバージョンのあるフローがある場合は、そのパッケージをアンインストールすると 1 つのバージョンのみを削除できます。フローの単一のバージョンを含むパッケージ (管理または未管理) のアンインストールを行うと、すべてのバージョンを含むフロー全体が削除されます。
  • ロック解除済みパッケージからはフローを手動で削除します。ロック解除済みパッケージから削除することでそれらを削除することはできません。

フローをパッケージ化する際の考慮事項

フローは、管理パッケージまたは未管理パッケージでパッケージ化できます。フローを含むパッケージを作成、更新、またはリリースする前に、パッケージの制限と動作を理解しておく必要があります。

必要なエディション

サポートされているエディションを表示する。

パッケージの作成

  • 変更セットを使用してフローをリリースする場合、変更セットにはフローが参照するすべてのコンポーネントが含まれている必要があります。
  • フローをパッケージ化する場合は、フローが参照するすべてのコンポーネントと項目が同じパッケージまたは連動パッケージで使用可能である必要があります。
  • 次の要素をフロー内で使用する場合、要素が参照するパッケージ化可能なコンポーネントは自動的にはパッケージに追加されません。パッケージを正常にリリースするには、参照するこれらのコンポーネントをパッケージに手動で追加します。
    • Chatter に投稿
    • メールを送信
    • 承認申請
    たとえば、特定の Chatter グループに投稿するフローをリリースする場合、参照される Chatter グループをパッケージに手動で追加します。
  • フローで CSP 信頼済みサイトに依存する Lightning コンポーネントを参照している場合、その信頼済みサイトはパッケージに自動的に含まれません。
  • パッケージまたはパッケージバージョンをアップロードすると、有効なフローバージョンが含まれます。フローに有効なバージョンがない場合は、最新バージョンがパッケージ化されます。

パッケージの更新

  • 異なるバージョンのフローで管理パッケージを更新するには、そのバージョンを有効化して、そのパッケージをアップロードします。または、フローのすべてのバージョンを無効化して、フローの最新バージョンが配布するバージョンであることを確認し、パッケージをアップロードします。誤ってフローバージョンを有効化し、パッケージをアップロードすると、そのフローバージョンが全ユーザーに配布されます。
  • 同じ API 参照名のフローをロック解除済みパッケージからインストールした場合、新しいフローで対象組織の既存のフローが上書きされます。
  • フローをパッケージパッチに含めることはできません。

その他の考慮事項

  • 関連付けられたメソッドが global としてマークされている場合にのみ、Flow Builder で管理パッケージからの Apex アクションが表示されます。

私のレコード変数に参照のみの項目が含まれるときの対処法

レコード変数に保存されている参照のみの項目ごとに、次のように対処します。

  • フローでその項目を使用しているかどうかを判断します。使用していない場合は、その項目の値を保存しないようにフローを更新します。この提案事項が当てはまるのは、[レコードを取得] などのフロー内の要素によって変数が入力される場合のみです。

  • 参照のみの項目がフローで参照されている場合は、フローでその操作を実行するために必要となる権限を実行ユーザーに与えます。
  • その項目で必要となる権限を実行ユーザーに与えられない場合は、その項目を更新しないようにフローを更新します。

次に例を示します。フローでは、レコード更新要素を使用して取引先のいくつかの項目が更新されます。ユーザーは [説明] および [取引先 評価] を編集できますが、[所有者 ID] または LastModifiedDate を編集できません。フローが実行時にエラーになることを防止するには、次のように操作します。

  • ユーザーに [所有者 ID] の「編集」権限を与えます。
  • 元のレコード変数から新しいレコード変数に、書き込み可能な項目値 ([説明]、[取引先 評価]、[所有者 ID]) のみをコピーします。レコードを更新要素で新しいレコード変数を参照します。

    書き込み可能な項目値のみをコピーすると、フローは実行時に LastModifiedDate の値を設定しようとしなくなります。

フローのセキュリティに関する考慮事項

フローインタビュー

ユーザーセッションの期限が切れると、Salesforce によって進行中のフローインタビューが中断され、ユーザーは再開できなくなります。フローでアクション ([レコードを作成] 要素や [Chatter に投稿] 要素など) が実行された場合、Salesforce はそれらのアクションをロールバックしません。ただし、ユーザーが画面で入力した内容など、他の進行状況は失われます。

ヒント
  • 適切な期間後にユーザーをログアウトするようにセッションタイムアウト設定を行う。
  • インタビュー中に、セッションがまもなく期限切れになるというアラートに注意を払うようにユーザーに促す。
  • リリースアップグレード中にフローを実行しないようにユーザーに促す。通常、アップグレードにかかる時間は約 5 分です。

期限切れのユーザーセッションは、一時停止中または待機中のフローインタビューには影響しません。

画面フロー入力

セキュリティ強化のために、画面フローで公開されている入力項目からすべての HTML を削除します。たとえば、公開されている画面フローの入力項目を Salesforce のリッチテキスト項目に対応付けます。不正な URL によってリッチテキスト項目にアクセスされるのを防ぐには、オブジェクトに個別のフローを作成して HTML を削除します。項目を迅速に更新するために新しいフローを最適化して、入力項目が空白でないときは実行するように設定します。公開されている入力項目にはいくつかのソースから書き込むことができるため、画面レベルではなく項目レベルで HTML を確認してください。

重要 画面フローで取得する公開カスタムメタデータ型またはカスタム設定に機密情報を保存しないでください。

レコードトリガーフローに関する考慮事項

レコードトリガー自動起動フローでは、追加の更新をトリガーレコードに加える前または加えた後に、トリガーレコードをデータベースに保存します。保存前および保存後の更新を実行するフローに関する考慮事項とその特定の動作を把握します。

必要なエディション

サポートされているエディションを表示する。

一般的な考慮事項

次の考慮事項は、すべてのレコードトリガーフローに適用されます。

  • レコードトリガーフローでカスタム入力規則を実行します。
  • 自動起動フローから画面フローを参照することはできません。
  • 実行順序の位置により、レコードトリガーフローの動作は同様のワークフロールールとは異なる場合があります。
  • Case.AccountId 項目が実行ユーザーの参照のみの場合、フローはユーザーがその取引先からケースを作成するときにその取引先を検索できません。たとえば、ユーザーが取引先詳細ページからケースを作成すると、Case.AccountId 項目は null のままになります。ケースは取引先に自動的にリンクされないため、フローで未入力の Case.AccountId 項目を使用して取引先レコードを検索することはできません。
  • 同期実行パス中に Data Cloud オブジェクトなどの外部データにアクセスしようとすると、レコードトリガーフローは失敗します。レコードの保存中は外部サービスへのコールアウトを実行できないため、失敗します。外部データソースを照会するフローロジックを実行するには、非同期パスを使用します。フローの開始要素で、[アクションと関連レコード] の [非 同期パスを追加] 切り替えをオンにして、このパスを作成します。非同期パスは、元のレコードの保存が正常に確定された後、バックグラウンドで実行され、外部コールアウトが有効になります。
  • 非同期パスでは、決定要素などで ISCHANGED 演算子はサポートされません。

  • 特定のオブジェクトで実行するように設定されているフローは、そのオブジェクトに別のオブジェクトを参照する数式項目があり、その項目が別のオブジェクトで更新されている場合は実行されません。

    たとえば、更新された取引先に対して実行されるレコードトリガーフローについて考えてみます。Account オブジェクトには、次の 2 つのカスタム数式項目が含まれます。

    • パートナー住所: 別の取引先レコードの [住所] 項目を参照する数式項目。
    • 取引先責任者電話: 取引先責任者レコードの [電話] 項目を参照する数式項目。
    シナリオ 結果
    2 番目の取引先レコードの [住所] 項目が更新されます。 フローは、2 番目の取引先レコードと [住所] 項目を参照する取引先レコードの両方でトリガーされます。
    取引先責任者レコードの [電話] 項目が更新されます。 [電話] 項目を参照する取引先レコードに更新されたデータが表示されても、フローはトリガーされません。

高速項目更新に関する考慮事項

項目をすばやく (保存前) 更新できるように最適化されたレコードトリガーフローに関する考慮事項は次のとおりです。

  • フローでは、トリガーレコードの項目値の更新以外のアクションを実行できません。
  • フローでは、トリガーレコードに関連するレコードの値を更新できません。

スケジュールトリガーフローの制限および考慮事項

スケジュールトリガーフローは、指定された時間に開始し、指定された頻度で実行され、レコードのバッチを処理します。スケジュールトリガーフローを作成または有効化する前に、次の考慮事項、制限、および特殊な動作を確認してください。

必要なエディション

サポートされているエディションを表示する。
メモ スケジュールトリガーフローはスケジュールに従って実行され、多くのレコードを処理できるため、作成する前に制限、セキュリティ、コールアウト、再試行の処理方法を確認することが重要です。

スケジュールトリガーフローに関する次の考慮事項を確認してください。

権限とセキュリティ:

  • 「データエクスポートの管理」権限が [セッションセキュリティレベルポリシー] で [セッションを高保証に上げる] に設定されている場合、Flow Builder でスケジュールトリガーフローを有効化または無効化することはできません。
    • スケジュールトリガーフローでは、フローでスケジュール済みデータエクスポートが使用されているかどうかに関係なく、有効化または無効化されたときに「データエクスポート」権限が確認されます。
    • この権限が高保証セッションを必要とする場合、高保証要件を満たさない限り、フローを有効化または無効化できません。

    フローを有効化または無効化するには、次のいずれかを実行します。

    • [セッションセキュリティレベルポリシー] で [データエクスポートを管理] を [なし] に設定します。
    • ユーザーのプロファイルで [Session Security Level Required at Login (ログイン時に必要なセッションセキュリティレベル)] を [High Assurance (高保証)] に設定します。
  • トリガーを持つ自動起動フローを有効化するには、「すべてのデータの参照」権限が必要です。
  • $Record グローバル変数の ID とすべての項目値を使用するようにレコードの更新要素を設定する場合、組織のプロセスの自動化設定で [Filter inaccessible fields from flow requests (フロー要求からのアクセスできない項目の絞り込み)] を有効にします。有効にしない場合、システム項目と他の参照のみの項目の値がレコードを更新要素により設定されるため、フローは失敗します。

フロー実行ユーザー:

[プロセスの自動化設定] で設定された [デフォルトのワークフローユーザー] は、スケジュールトリガーフローの実行ユーザーです。

開始動作:

  • スケジュールトリガーフローには、指定された時間と頻度で開始されます。スケジュールトリガーフローを他の方法で開始することはできません。
  • [開始時刻] 項目値は、Salesforce 組織のデフォルトのタイムゾーンに基づきます。
  • フローを 1 回実行するようにスケジュールされた日時がすでに経過している場合、フローは実行されません。

Sandbox:

  • Sandbox の更新が完了すると、Sandbox で有効だったスケジュール済みフローを、更新された Sandbox ですぐに実行できます。

制限とバッチ処理:

1 つのフローのスケジュールトリガーフローインタビューの最大数は 25 万件です。 24 時間あたりのスケジュールトリガーフローインタビューの最大数は 25 万件か、組織のユーザーライセンス数に 200 を掛けた数のいずれか大きい方です。スケジュールトリガーフローのクエリで取得されたレコードごとに 1 つのインタビューが作成されます。

  • フローがレコードのバッチに対して実行されるようにオブジェクトを指定する場合、制限に達しないように時間、頻度、レコード条件を設定します。デフォルトでは、スケジュールトリガーフローのクエリは 200 件のバッチでレコードを取得しますが、バッチサイズは 1 ～ 200 の範囲で設定できます。 最大バッチサイズを低く設定すると、バッチサイズと実行するレコードの合計数に応じて処理時間が長くなる可能性があります。
  • スケジュールトリガーフローで実行されるレコード数を確認するには、デバッグログを使用して、SCHEDULED_FLOW_DETAIL イベントがあるレコード数を追跡します。
  • 組織が制限に達した場合、フローエラーメールが送信されます。

スケジュールトリガーフローの削除:

[設定] の [スケジュール済みジョブ] ページからスケジュールトリガーフローを削除すると、そのフローの今後の繰り返しもすべてキャンセルされます。今後の実行を有効化するには、フローを無効化して再度有効化します。

コールアウトと Apex:

  • Apex コードを実行するスケジュール トリガー フローが必要な場合は、[フローで呼び出される Apex クラスへのユーザー アクセスが必要] 更新を有効にしないでください。リリース更新を有効にすると、スケジュール トリガー フローは Apex の実行時に失敗します。
  • スケジュールトリガーフローが次の条件を満たす場合、待機要素なしのコールアウトがサポートされます。
    • レコードのバッチを処理する
    • API バージョン 63.0 以降で実行
  • 条件を満たしていない場合、スケジュールトリガーフローは待機要素を実行した後にのみコールアウトを実行できます。たとえば、待機要素がない場合、フローは外部オブジェクトにアクセスしたり、コールアウトを実行する Apex アクションを実行したり、外部サービスの登録から生成されたアクションを実行したりできません。
    ヒント 少しの間だけフローを一時停止する待機要素を挿入できます。時間取得元として特定の時間を使用して、指定の時間まで一時停止するように再開イベントを設定します。基準時刻には、$Flow.CurrentDateTime グローバル変数を指定します。次に、オフセットを 0 時間に設定します。実行時に、このように設定された待機要素により、フローが一時停止します (通常は 1 分未満)。
  • 非同期フローから呼び出される同期 Apex トランザクションは、トランザクションあたりの同期 Apex の制限に影響します。非同期フローには、スケジュール済みフローと、スケジュール済みパスまたは非同期パスを持つフローがあります。

エラー処理:

  • 実行時に、スケジュールトリガーフローに複数のレコードを処理する [レコードを作成]、[レコードを削除]、[レコードを取得]、または [レコードを更新] 要素があり、一部のレコードが失敗した場合、すべてのレコードがロールバックされます。成功したレコードが再試行されます。フローの後半で同じ失敗レコードを処理する別のレコード作成要素、レコード削除要素、レコード取得要素、またはレコード更新要素がある場合、すべての変更がロールバックされ、フロートランザクションは失敗します。

[履歴を編集] では、フローバージョンごとに過去 5 回以上、最大 100 回の保存が保持されます。

有効なフローバージョン

フローインタビュー

フローインタビューは、フローの実行中のインスタンスです。フローは、システム管理者が作成するアプリケーションです。ユーザーに入力を求め、その入力に基づいて Salesforce で処理を行います。

必要なエディション

サポートされているエディションを表示する。

たとえば、フローではカスタマーサポートコールの通話スクリプトを提供したり、ユーザーが指定した情報を使用してケースを作成したりできます。入力した情報に基づいてフローが実行する処理は、システム管理者が決定します。

リンク、ボタン、タブのいずれからフローインタビューを実行しても、実行されるのはフローの 1 つのインスタンスです。用語がわかりづらい場合は、レコードとオブジェクトの違いを考えてみてください。取引先レコードを作成する場合、そのレコードはシステム管理者がカスタマイズした取引先オブジェクトの 1 つのインスタンスです。

メモ フローを実行するときには、次のヒントに留意してください。
  • フローを移動するときに、ブラウザーの [戻る] ボタンや [進む] ボタンを使用しないでください。これを行うと、フローと Salesforce の間でデータの矛盾が生じる場合があります。
  • 1 つのフローには、最大 50 個のバージョンを作成できます。フローを実行すると、有効なバージョンが表示されますが、さらに新しいバージョンが存在する可能性があります。
  • フローインタビューの削除
    フローインタビューを一時停止した後、再開しない場合は削除します。不要なフローインタビューを削除することで、保留リストにまだ対応する予定があるフローインタビューのみが含まれるようにすることができます。
  • フローインタビューの一時停止
    システム管理者がフローに設定していれば、そのインタビューを一時停止できます。一時停止は、顧客との電話が意図せず切れた場合や、顧客が取引先番号を見つけられず、折り返し電話をかけてくる予定がある場合などに便利です。
  • フローインタビューの再開
    フローインタビューを一時停止した場合は、必要なすべての情報が揃った後に再開します。フローインタビューを一時停止し、関連付けられたフローが再開前に更新された場合、再開したフローインタビューでは更新されたフローは使用されません。代わりに、一時停止したときに有効だったバージョンのフローが使用されます。

フローインタビューを一時停止した場合は、必要なすべての情報が揃った後に再開します。フローインタビューを一時停止し、関連付けられたフローが再開前に更新された場合、再開したフローインタビューでは更新されたフローは使用されません。代わりに、一時停止したときに有効だったバージョンのフローが使用されます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
フローインタビューを再開する

「フローの実行」

または

[フローユーザー] 項目がユーザーの詳細ページで選択されている

一時停止する前に値を入力した場合、再開すると、有効な値はすべて該当する項目に復元されます。一時停止する前に入力した値が表示されない場合、その値は無効であったためフローで保存されていません。たとえば、数値のみを受け入れる項目に「Acme, Inc.」と入力して一時停止した場合、フローインタビューを再開するとその項目は空白になります。

警告 フローインタビューを再開すると、そのフローインタビューは [一時停止中のフローインタビュー] リストから削除されます。フローインタビューを再開した後、再開を取りやめるには [一時停止] をクリックします。一時停止する前にフローインタビューを閉じた場合、そのフローインタビューを後で再開することはできません。
  1. 一時停止中のフローインタビューを見つけます。見つける場所は、システム管理者の設定によって決まります。
    1. エクスペリエンスビルダーサイトページで一時停止中のフローインタビューを見つけるには、コンポーネントパネルから一時停止中のフロー コンポーネントをページにドラッグします。
    2. Salesforce Classic で一時停止中のフローインタビューを見つけるには、ホームタブで一時停止中のフローインタビューリストに移動します。
    3. Salesforce モバイルアプリで一時停止中のフローインタビューを見つけるには、メニューアイコンから 一時停止中のフロー を見つけて選択します。
    4. 自動化アプリケーションで一時停止中のフローインタビューを検索するには、アプリケーションランチャーから、[自動化] を見つけて選択し、[監視] タブに移動します。
  2. 一時停止中のフローインタビューを再開します。
