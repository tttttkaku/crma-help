オートメーションアプリケーションの [オーケストレーション] タブ

[オーケストレーション] タブには、多数の標準オーケストレーションリストビューと作成したリストビューが含まれます。オーケストレーションの表示ラベルまたは説明でキーワードを検索します。トリガー種別、状況、最終更新日などの項目でオーケストレーションを絞り込んだり並び替えたりします。選択したオーケストレーションに関連するオーケストレーションの実行を表示および管理します。

必要なエディション

使用可能なインターフェース: Lightning Experience
サポートされているエディションを表示する。
メモ この機能は、Government Cloud および Government Cloud Plus でサポートされています。

各オーケストレーションの状況は関連付けられています。

オーケストレーション状況 説明
有効 オーケストレーションの現在のバージョンが有効化されました。
ドラフト オーケストレーションの現在のバージョンが有効になっておらず、エラーが含まれています。
無効 オーケストレーションの現在のバージョンが有効化されていないか、無効化されています。

    オーケストレーションのバージョンに関する詳細を表示します。
  • オーケストレーションに関連するオーケストレーション実行の表示
    オーケストレーションに関連するオーケストレーション実行レコードを表示します。選択したオーケストレーション実行に関連するオーケストレーションフェーズ実行、オーケストレーションステップ実行、オーケストレーション実行ログレコードを表示することもできます。

オーケストレーションの構造

  • フローオーケストレーションエンタイトルメント
    フローオーケストレーションは、使用量ベースの制限のない特定のエディションに含まれています。オーケストレーション実行は、オーケストレーションの実行インスタンスです。オーケストレーションは、フェーズ、ステップ、決定を使用して複雑なビジネスプロセスを整理する、システム管理者が作成したアプリケーションです。

オーケストレーションでのフェーズエラーの処理

オーケストレーションのフェーズエラーを管理するための障害パスを設定します。フェーズまたはそのステップでエラーが発生したときに実行される要素と移動コネクタを追加します。これらのパスは、オーケストレーションが失敗するのではなく正常に完了するのに役立ちます。

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限
Flow Builder でオーケストレーションを開く、編集または作成する 「フローの管理」

オーケストレーションでのエラー処理の値と戦略については、「オーケストレーションでのエラー処理」を参照してください。

障害パスの追加

オーケストレーションでフェーズの障害パスを定義します。

このタスクには、1 つ以上のフェーズを含むオーケストレーションが必要です。

  1. オーケストレーションのフェーズにマウスポインターを置きます。
  2. [] をクリックし、[障害パスを追加] を選択します。
  3. 作業内容を保存します。

障害パスに少なくとも 1 つの要素を追加します。

障害パスへの決定要素の追加

決定要素を使用して、障害パスで実行する要素を制御する条件を作成します。

このタスクには、障害パスが定義された 1 つ以上のフェーズを含むオーケストレーションが必要です。

決定要素を使用して、エラーが発生したステップを判断し、オーケストレーションを適切な回復アクションに転送します。決定要素では、オーケストレーション実行変数と自動出力を評価してエラーの原因を特定し、最適な復旧パスを決定します。

一元化された障害パス戦略を実装する場合、決定要素はエントリポイントとして機能します。エラーの原因となったフェーズを特定し、適切な結果パスに転送して解決します。

  1. [障害パス] で、[] をクリックし、[決定] を選択します。
  2. 表示ラベル、API 参照名、説明を入力します。
  3. 決定要素に使用する決定ロジックの種別を選択します。
    • 従来のロジック式とオーケストレーションから明示的に定義されたデータに基づいて実行される結果を決定するには、[Define Manually (Default)] を選択します。
    • オーケストレーションからのデータを評価しているAIに基づいて実行される結果を動的に判別するには、[Define with AI (Advanced)]を選択します。
  4. [手動で定義 (デフォルト)] を選択した場合は、要素の条件と結果を定義します。手動条件が含まれる決定要素の結果は、リストの順序で評価されます。そのため、結果を定義する順序が、オーケストレーションの実行の結果に影響する可能性があります。
    1. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名はオーケストレーション内で一意である必要があります
    2. 最初の結果に使用する条件の要件を定義します。
      オプション 決定結果の動作
      すべての条件に一致 いずれかの条件が false の場合、オーケストレーションで次の結果の条件が評価されます。
      いずれかの条件に一致 いずれかの条件が true の場合、オーケストレーションでこの結果のパスがすぐに使用されます。
      カスタム条件ロジックに一致

      このオプションを選択する場合は、最大 1,000 文字を入力して条件ロジックを指定します。以下を使用します。

      • 各条件を参照する数値
      • どのような条件の組み合わせが true となる必要があるのかを識別する AND、OR、NOT
      • 文字列の一部をグループ化するための括弧

      AND を入力した場合は、[すべての条件に一致] を選択した場合と同じです。OR を入力した場合は、[いずれかの条件に一致] を選択した場合と同じです。その他のロジックを入力する場合は、各条件の番号を含めるようにします。

      たとえば、1 AND NOT(2 OR 3) の場合、フローは最初の条件が true であることと、2 番目および 3 番目の条件の両方が true でないことを評価します。
    3. 最初の結果のロジック条件を定義します。
      列ヘッダー 説明
      リソース

      オプション:

      • フェーズまたはステップから入力変数または自動出力を選択する
      • 決定要素を選択する
      • グローバル変数を選択する
      演算子 使用可能な演算子は、[リソース] に選択されたデータ型によって異なります。「決定要素のフローオーケストレーション演算子」を参照してください。
      値

      同じ行の [リソース] と [値] のデータ型は、互換性がある必要があります。

      オプション:

      • オーケストレーションリソース (入力変数や、フェーズまたはステップからの自動出力など) を選択する
      • グローバル変数を選択する
      • リテラル値を入力する。

      日付値から数値を加算または減算すると、日付は時間単位ではなく日単位で調整されます。
  5. [AI で定義 (詳細)] を選択した場合は、要素の指示と結果を定義します。
    1. [決定手順] に、要素による決定を説明するテキストを入力します。オーケストレーションのリソースを含めて、AI の精度を向上させます。
    2. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名はオーケストレーション内で一意である必要があります。
    3. [結果の手順] に、AI に結果を取得するタイミングを指示するテキストを入力します。オーケストレーションのリソースを含めて、AI の精度を向上させます。AI 条件が含まれる決定要素の結果は同時に評価されます。そのため、結果を定義する順序は、オーケストレーションの実行の結果に影響しません。
  6. (省略可能) 決定結果を決定要素に追加するには、[] をクリックします。この手順を繰り返して、表示ラベルと結果の API 参照名を追加し、条件を設定して、条件間のロジックを特定します。手動条件については、ステップ 4b を参照してください。AI 条件については、ステップ 5b を参照してください。
  7. (省略可能) [決定] 要素の決定結果を並び替えるには、[] をクリックし、項目を新しい場所にドラッグします。デフォルトの結果は常に最後であるため、条件を含む決定結果をリストの最後の位置に移動することはできません。
  8. (省略可能) 決定要素の読みやすさを向上させるには、デフォルトの結果の名前を変更します。
    1. [結果の順序] で、[デフォルトの結果] を選択します。
    2. 表示ラベルを入力します。
  9. 作業内容を保存します。

オーケストレーションの作成

フローオーケストレーションを使用して、フローを組み合わせて調整することで高度なビジネスプロセスを作成します。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限
Flow Builder でオーケストレーションを開く、編集または作成する 「フローの管理」

各要素の組み合わせを理解していると、ビジネスプロセスを簡単に自動化できます。オーケストレーションを作成する前に、関係者と話して要件を理解しておきます。必要な情報をすべて知らなくても、ドラフトオーケストレーションを保存できます。オーケストレーションを有効化して実行する前に、すべてのフローと詳細を指定します。

オーケストレーションには、フェーズ要素と決定要素が含まれます。フェーズには少なくとも 1 つのステップが含まれ、各ステップで実行するアクションをコールします。バックグラウンドステップと対話型ステップでフローをコールします。MuleSoft ステップでは、MuleSoft API からインポートされた MuleSoft アクションをコールします。可能な場合は、オーケストレーションを作成する前に、フローを作成して必要な MuleSoft アクションをインポートします。

  • オーケストレーションでの決定要素の使用
    オーケストレーションで特定の決定結果を取得するタイミングを制御します。
  • オーケストレーションのフェーズとステップの要件の定義
    要件を使用して、レコードが変更されたときにオーケストレーションを再開します。最大 10 個の要件を定義して、ステップを開始するタイミングや、対話型のステップまたはフェーズを完了とマークするタイミングを決定します。
  • ユーザーとやりとりするステップの作成
    オーケストレーションのステップを個人、グループ、またはキューに割り当てるには、対話型ステップを作成します。オーケストレーションの実行では、実行する対話型ステップごとに作業項目が作成されます。
  • 割り当て先へのメールをカスタマイズ
    デフォルトでは、オーケストレーションの実行でオーケストレーション作業項目が作成されるたびに、割り当て先に通知が送信されます。オーケストレーション作業項目の作成時に送信されるメール通知を変更するには、関連付けられた承認ステップをカスタマイズします。
  • オムニチャネルによるオーケストレーション作業項目の転送
    サービスでオムニチャネルルーティングをオーケストレーション作業項目で使用するには、少なくとも 1 つのキューをオーケストレーション作業項目に関連付ける必要があります。そのキューに対話型ステップを割り当てると、ルーティングロジックに基づいてキューのメンバーにオムニチャネルウィジェット経由で通知が送信されます。作業項目のデフォルトのメール通知を無効にしない限り、キューメンバーにはメール通知も送信されます。
  • オーケストレーションパスをリダイレクトする
    フローオーケストレーションでは、Flow Builder の自動レイアウトが使用されます。自動レイアウトでは、キャンバスの要素が自動的に間隔を空けて配置され、接続されます。通常の連続する自動レイアウトパスに従わない要素がある場合、Go To コネクタを使用します。
  • オーケストレーションパスへの終了要素の追加
    オーケストレーションのすべての要素は自動的に接続されるか、手動で追加した Go To コネクタによって接続されます。オーケストレーションのパスを終了するには、終了要素を追加します。
  • オーケストレーションでの自動出力の使用
    オーケストレーションには、そのフェーズ、ステップ、決定の出力へのアクセス権があります。オーケストレーションのフェーズまたはステップの状況を照会します。ステップに関連付けられたフローの出力パラメーターを使用します。API バージョン 58.0 以降で実行するように設定されたオーケストレーションでは、参照される自動出力にレコードまたはレコードコレクションが含まれる場合、オーケストレーションの実行が再開されるたびに自動出力が最新の値で更新されます。
  • オーケストレーションでのフェーズエラーの処理
    オーケストレーションのフェーズエラーを管理するための障害パスを設定します。フェーズまたはそのステップでエラーが発生したときに実行される要素と移動コネクタを追加します。これらのパスは、オーケストレーションが失敗するのではなく正常に完了するのに役立ちます。
  • オーケストレーションステージおよびステップの条件評価をトリガーする
    現在のフェーズ内のステップが完了するたびに、オーケストレーションではそのフェーズとそのフェーズのステップの条件を評価します。フローからオーケストレーションイベントを公開して、オーケストレーションステージおよびステップの条件評価をトリガーすることもできます。
  • 外部システムとのオーケストレーションの統合
    MuleSoft ステップをオーケストレーションに追加して、インポートした MuleSoft アクションをコールします。また、$Orchestration.Instance システム変数を使用して、外部システムをオーケストレーションと統合することもできます。
  • オーケストレーションテンプレートの作成と使用
    オーケストレーションをテンプレートとして保存し、新しいオーケストレーションの開始点として再利用します。登録者がテンプレートに基づいてオーケストレーションを作成できるように、管理パッケージを介してテンプレートを配布します。
  • 割り当てられたユーザーが作業にアクセスできるようにする
    オーケストレーションで対話型ステップが実行されると、割り当てられたユーザー、ユーザーグループ、またはキューにメールで通知されます。認証済みの Experience Cloud サイト訪問者は、[オーケストレーション作業項目リスト] オブジェクトページで割り当てられたフローオーケストレーション作業項目を表示およびアクセスできます。内部ユーザーと認証済みの Experience Cloud サイト訪問者は、[作業ガイド] で割り当てられた仕事を完了します。

レコードトリガーオーケストレーションのトリガーの設定

レコードトリガーオーケストレーションを実行するタイミングを制御するように開始要素を設定します。

  1. [オブジェクトを選択] で、オーケストレーションをトリガーするレコードが含まれるオブジェクトを選択します。
  2. [トリガーを設定] で、オプションを選択します。
    • レコードの作成時にのみオーケストレーションをトリガーするには、[A record is created] を選択します。
    • レコードの更新時にのみオーケストレーションをトリガーするには、[A record is updated] を選択します。
    • レコードが作成または更新されたときにオーケストレーションをトリガーするには、[A record is created or updated] を選択します。
  3. オーケストレーションを実行するタイミングを制限する条件要件を設定します。
    条件の要件 オーケストレーション実行のタイミング
    なし Always
    すべての条件に一致 (AND) すべての条件が true です。
    いずれかの条件に一致 (OR) 少なくとも 1 つの条件を満たしている。
    カスタム条件ロジックに一致

    カスタム条件は true です。

    このオプションを選択する場合は、最大 1,000 文字を入力して条件ロジックを指定します。以下を使用します。

    • 各条件を参照する数値
    • どのような条件の組み合わせが true となる必要があるのかを識別する AND、OR、NOT
    • 文字列の一部をグループ化するための括弧

    AND を入力した場合は、[すべての条件に一致] を選択した場合と同じです。OR を入力した場合は、[いずれかの条件に一致] を選択した場合と同じです。その他のロジックを入力する場合は、各条件の番号を含めるようにします。

    たとえば、1 AND NOT(2 OR 3) の場合、フローは最初の条件が true かどうかと、2 番目と 3 番目の条件の両方が false かどうかを評価します。
    数式の評価が True になる

    数式の評価が true になる。

    このオプションを選択した場合、リソース、関数、演算子を使用して数式を作成します。「 Flow Formula Builder を使用したフロー数式の作成」の「 Flow Start Element Formula Builder での数式の作成」を参照して ください。

オーケストレーションの作成

オーケストレーションは、フェーズ要素と決定要素で構成されます。フェーズには 1 つ以上のステップが含まれます。バックグラウンドステップと対話型ステップでフローをコールします。MuleSoft ステップは MuleSoft アクションをコールします。各フェーズには、そのフェーズまたはフェーズ内のステップで発生したエラーを処理する接続された障害パスを含めることができます。

    • オーケストレーションのルーティング先パスを決定する要素を追加するには、[決定] を選択します。決定要素の設定についての詳細は、「Use Decision Elements in an Orchestration (オーケストレーションでの決定要素の使用)」を参照してください。
  2. ステップをフェーズに追加するには、[ステップを追加] をクリックし、ステップ種別を選択して、表示ラベル、API 参照名、説明を入力します。ステップの設定についての詳細は、「ステップフローオーケストレーションリソース」を参照してください。
    • ユーザー操作のないステップを追加するには、[バックグラウンドステップ] を選択します。
    • ユーザーとやりとりするステップを追加するには、[Interactive Step (対話型ステップ)] を選択します。
    • MuleSoft アクションをコールするステップを追加するには、[MuleSoft Step] を選択します。
  3. オーケストレーションで要素を追加すると、パス上のその前後の要素に自動的に接続されます。オーケストレーションには決定要素とフェーズ要素を含めることができますが、フローのようにループ要素はありません。オーケストレーションで 1 つ以上の要素のシーケンスを繰り返すか、次に実行する要素を変更するには、Go To コネクタを使用します。
    1. 別の要素に接続するには、決定要素またはフェーズ要素の後で [] をクリックし、[要素に接続] をクリックします。
    2. 移動する要素の をクリックします。

    1. 障害パスをフェーズに追加するには、フェーズカードで [] をクリックし、[障害パスを追加] を選択します。
    2. フェーズ要素と決定要素を障害パスに追加します。オーケストレーションの障害パスのフェーズ要素には、バックグラウンドステップ、対話型ステップ、MuleSoft ステップを含めることができます。
    3. (省略可能) デフォルトでは、障害パスは終了要素で終了します。移動コネクタを使用して、障害パス内の要素をメインオーケストレーション内の要素に接続します。[] をクリックして [要素に接続] をクリックし、要素の [] をクリックして移動します。
    エラー処理戦略と障害パス設定についての詳細は、「オーケストレーションでのエラー処理」を参照してください。

ユーザーとやりとりするステップの作成

オーケストレーションのステップを個人、グループ、またはキューに割り当てるには、対話型ステップを作成します。オーケストレーションの実行では、実行する対話型ステップごとに作業項目が作成されます。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限

対話型ステップの割り当て済みユーザーの [ユーザー] 項目には、内部ユーザーとログイン情報のある Experience Cloud サイト訪問者が含まれます。対話型ステップをユーザーまたはログイン情報のあるサイト訪問者に割り当てるときは、必ず関連レコードへの必要なアクセス権をユーザーに付与してください。

内部ユーザーが対話型ステップを完了するには、関連付けられた内部 Salesforce Lightning レコードページへのアクセス権が必要です。ログイン情報のある Experience Cloud サイト訪問者が対話型ステップを完了するには、Aura サイトまたは LWR サイトの関連付けられた関連レコードページへのアクセス権が必要です。

フローオーケストレーションでオムニチャネルルーティングを使用するには、オムニチャネルを設定し、少なくとも 1 つのキューをオーケストレーション作業項目オブジェクトに関連付けます。次に、定義したルーティングロジックに基づいてオムニチャネルウィジェットを使用して割り当て済みユーザーに通知するには、オーケストレーション作業項目オブジェクトに関連付けられたキューに対話型ステップを割り当てます。

対話型ステップでコールする画面フローを作成、テスト、有効化します。評価フローを使用して対話型ステップを開始または完了できるかどうかを決定する場合は、評価フローの作成、テスト、有効化も行います。

オーケストレーションが実行され、対話型ステップが開始されると、作業項目が作成されます。作業項目が作成されると、割り当て先にデフォルトのメール通知が送信されます。関連付けられたインタラクティブステップを設定するときに、メール通知をカスタマイズできます。割り当て先へのオーケストレーションによる通知メールの送信を停止するには、[オーケストレーション作業項目メール通知の送信を停止] を選択します。「作業項目割り当てのすべてのメール通知の無効化」を参照してください。

  1. インタラクティブステップを追加するフェーズを決定します。
  2. stage 要素で、[+ Add Step] をクリックし、[Interactive Step] を選択します。
  3. 表示ラベル、API 参照名、説明を入力します。
  4. (省略可能) [ステップを開始するタイミングを選択] で、条件を選択します。
    • フェーズの開始時にステップを自動的に開始するには、[フェーズの開始時にステップを開始します] を選択します。
    • 別のステップが完了した後にステップを開始するには、[別のステップが [完了] とマークされたら、ステップが開始します] を選択します。次に、最初に完了するステップの名前を入力します。
    • ステップを開始する前に満たすべき要件を最大 10 個指定するには、[指定された要件が満たされたら、ステップを開始します] を選択します。次に、要件を設定します。
    • 複雑な要件を使用してステップの開始時期を決定するには、[指定された評価フローが True を返した場合、ステップが開始します] を選択します。次に、有効な評価フローを選択します。
  5. [実行するアクションを選択] で、ステップで実行する有効な画面フローを選択します。選択したフローの必須入力の値またはリソースの API 参照名を指定します。
  6. [アクションを完了するユーザーを選択] で、割り当て種別を選択します。
    • ユーザーを指定するには、[ユーザー] を選択します。
    • 通常の公開グループを指定するには、[グループ] を選択します。
    • キューであるグループを指定するには、[キュー] を選択します。
    • オーケストレーションの実行時にユーザーのユーザー名、グループの API 参照名、またはキューの API 参照名を含むリソースを指定するには、[リソース] を選択します。

    • [キュー] を選択した場合は、キューの表示ラベルを検索してリストから選択します。

  8. (省略可能) このステップの承認作業項目が作成されたときにカスタムメール通知を割り当て先に送信するには、[通知メールのカスタマイズ] を選択します。パーソナライズされたメールの件名と本文のテキストテンプレートを作成し、件名と本文の API 参照名を入力します。または、メールの件名と本文のテキストを入力します。

オーケストレーションでの自動出力の使用

オーケストレーションには、そのフェーズ、ステップ、決定の出力へのアクセス権があります。オーケストレーションのフェーズまたはステップの状況を照会します。ステップに関連付けられたフローの出力パラメーターを使用します。API バージョン 58.0 以降で実行するように設定されたオーケストレーションでは、参照される自動出力にレコードまたはレコードコレクションが含まれる場合、オーケストレーションの実行が再開されるたびに自動出力が最新の値で更新されます。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限
Flow Builder でオーケストレーションを開く、編集または作成する 「フローの管理」

要素またはリソースをオーケストレーションに追加します。

オーケストレーションを作成すると、そのオーケストレーションの各フェーズとステップの自動出力を全体で使用できます。このように全体で使用できることにより、オーケストレーションの実行で自動出力が生成される前に、設計したオーケストレーションでその自動出力を使用できます。そのため、自動出力を使用する場合は、オーケストレーションで要素とリソースを実行する順序を考慮してください。

バックグラウンドステップが同期して実行され、レコードが更新されても、オーケストレーションの実行が再開されるまで $Record は更新されません。フェーズでは、ステップの完了後に更新された項目値にアクセスできません。また、フェーズまたはステップの終了条件で使用することはできません。ステップで更新された項目値にアクセスするには、$Record を直接参照するのではなく、ステップの自動出力を使用します。

  1. リソース、値、または入力パラメーター項目で、ドロップダウンリストからフェーズまたはステップを選択します。
  2. ドロップダウンリストから自動出力項目を選択します。
  3. 作業内容を保存します。

オーケストレーションでの決定要素の使用

オーケストレーションで特定の決定結果を取得するタイミングを制御します。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限
Flow Builder でオーケストレーションを開いたり、編集または作成する フローの管理

開始する前に、決定要素をオーケストレーションに追加します。

  1. 表示ラベル、API 参照名、説明を入力します。
  2. 決定要素に使用する決定ロジックの種別を選択します。
    • 従来のロジック式とオーケストレーションから明示的に定義されたデータに基づいて実行される結果を決定するには、[Define Manually (Default)] を選択します。
    • オーケストレーションからのデータを評価しているAIに基づいて実行される結果を動的に判別するには、[Define with AI (Advanced)]を選択します。
  3. [手動で定義 (デフォルト)] を選択した場合は、要素の条件と結果を定義します。手動条件が含まれる決定要素の結果は、リストの順序で評価されます。そのため、結果を定義する順序が、オーケストレーションの実行の結果に影響する可能性があります。
    1. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名はオーケストレーション内で一意である必要があります
    2. 最初の結果に使用する条件の要件を定義します。
      オプション 決定結果の動作
      すべての条件に一致 いずれかの条件が false の場合、オーケストレーションは次の結果の条件を評価します。
      いずれかの条件に一致 いずれかの条件が true の場合、オーケストレーションでこの結果のパスがすぐに使用されます。
      カスタム条件ロジックに一致

      このオプションを選択する場合は、最大 1,000 文字を入力して条件ロジックを指定します。使用:

      • 各条件を参照する数値
      • AND、OR、または NOT を使用して、どの条件の組み合わせが true になる必要があるかを指定します。
      • 文字列の一部をグループ化する括弧

      AND を入力した場合、[すべての条件に一致] を選択した場合と同じです。OR を入力した場合、[いずれかの条件に一致] を選択した場合と同じです。他のロジックを入力する場合は、必ず各条件の数値を含めてください。

      たとえば、1 AND NOT(2 OR 3) の場合、フローは最初の条件が true であるかどうかを評価し、2 番目と 3 番目の条件が true であるかどうかを評価します。
    3. 最初の結果のロジック条件を定義します。
      列ヘッダー 説明
      リソース

      オプション:

      • フェーズまたはステップから入力変数または自動出力を選択します。
      • 決定要素を選択します。
      • グローバル変数を選択します。
      オペレータ 使用可能な演算子は、[リソース] で選択したデータ型によって異なります。「決定要素のフローオーケストレーション演算子」を参照してください。
      値

      同じ行のリソースと値には互換性のあるデータ型が必要です。

      オプション:

      • オーケストレーションリソース (フェーズまたはステップからの入力変数や自動出力など) を選択します。
      • グローバル変数を選択します。
      • リテラル値を入力します。

      日付値に数値を加算または減算すると、日付は時間単位ではなく日単位で調整されます。
  4. [AI で定義 (詳細)] を選択した場合は、要素の指示と結果を定義します。
    1. [決定手順] に、要素による決定を説明するテキストを入力します。オーケストレーションのリソースを含めて、AI の精度を向上させます。
    2. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名はオーケストレーション内で一意である必要があります。
    3. [結果の手順] に、AI に結果を取得するタイミングを指示するテキストを入力します。オーケストレーションのリソースを含めて、AI の精度を向上させます。AI 条件が含まれる決定要素の結果は同時に評価されます。そのため、結果を定義する順序は、オーケストレーションの実行の結果に影響しません。
  5. (省略可能) 決定結果を決定要素に追加するには、[] をクリックします。この手順を繰り返して、表示ラベルと結果の API 参照名を追加し、条件を設定して、条件間のロジックを特定します。手動条件については、ステップ 4b を参照してください。AI 条件については、ステップ 5b を参照してください。
  6. (省略可能) [決定] 要素の決定結果を並び替えるには、[] をクリックし、項目を新しい場所にドラッグします。デフォルトの結果は常に最後であるため、条件を含む決定結果をリストの最後の位置に移動することはできません。
  7. (省略可能) 決定要素の読みやすさを向上させるには、デフォルトの結果の名前を変更します。
    1. [結果の順序] で、[デフォルトの結果] を選択します。
    2. 表示ラベルを入力します。
  8. 作業を保存します。

  1. コネクタを変更する要素の直後で、 をクリックします。
  2. [要素に接続] をクリックします。
  3. 接続先の要素の をクリックします。

レコードトリガーフローの作成

レコードのカスタムオーケストレーション実行 ID 項目に保存されている値が変更されたときにオーケストレーションイベントを公開するレコードトリガーフローを作成します。複数のオブジェクトのレコードが外部システムから影響を受ける場合は、オブジェクトごとにレコードトリガーフローを作成します。

外部システムアクションが完了したときにレコードのカスタムオーケストレーション実行 ID 項目の値を更新する、オーケストレーションのバックグラウンドステップが必要です。

  1. レコードのカスタムオーケストレーター実行 ID 項目が更新されたときに実行する、レコードトリガーフローを作成します。
  2. [レコードを作成] 要素をレコードトリガーフローに追加します。
  3. 要素の表示ラベル、API 参照名、および説明を入力します。
  4. [レコードフィールド値の設定方法] で、[手動] を選択します。
  5. オーケストレーションイベントを作成します。
    1. [オブジェクト] で、[オーケストレーションイベント] を検索して選択します。[項目] で [オーケストレーション実行 ID] が自動的に選択されます。
    2. [値] で、「Triggering」を検索し、トリガーレコードを選択します。次に、トリガーレコードのカスタムオーケストレーション実行 ID 項目の名前を検索して選択します。

  6. 新しいレコードトリガーフローを保存して有効化します。

オーケストレーションのフェーズとステップの要件の定義

要件を使用して、レコードが変更されたときにオーケストレーションを再開します。最大 10 個の要件を定義して、ステップを開始するタイミングや、対話型のステップまたはフェーズを完了とマークするタイミングを決定します。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。

  1. [プロパティ] パネルで、ステップを開始したり、フェーズまたは対話型ステップを完了したりするための要件を 10 個まで作成できる条件を選択します。

    ステップの完了 指定された要件が満たされたら、ステップを [完了] とマークする
    フェーズの完了 指定された要件を満たしたら、フェーズは完了とマークされます
  2. 要件のロジックを設定します。
    オプション 要件の動作
    すべての要件が満たされている いずれかの要件が false の場合、要件は満たされています。
    いずれかの要件が満たされている いずれかの要件が true の場合、要件は満たされています。
    カスタム要件ロジックが満たされている

    このオプションを選択した場合は、最大 1000 文字を入力して、要件ロジックを指定します。以下を使用します。

    • 各要件を参照する数値
    • どのような要件の組み合わせが true となる必要があるのかを識別するための AND、OR、NOT
    • 文字列の一部をグループ化するための括弧

    AND を入力した場合は、[すべての要件に一致] を選択した場合と同じです。OR を入力した場合は、[いずれかの条件に一致] を選択した場合と同じです。その他のロジックを入力する場合は、各要件の番号を必ず含めます。

    • ステップリソースの状況を選択します。
    • レコードトリガーオーケストレーションの場合は、$Record グローバル変数を選択する
    • グローバル変数を選択する
    演算子 使用可能な演算子は、リソースで選択されたデータ型によって異なり、決定要素で使用される演算子と同じように動作します。「決定要素のフローオーケストレーション演算子」を参照してください。
    値

    同じ行の [リソース] と [値] のデータ型は、互換性がある必要があります。

    オプション:

オーケストレーションでのレコードの更新

API バージョン 58.0 以降で実行するように設定されたオーケストレーションでレコード変数またはレコードコレクションを参照すると、オーケストレーションの実行が再開されるたびにレコードが最新の値で更新されます。自動起動オーケストレーションの実行では、参照されるすべてのレコードが更新されます。レコードトリガーオーケストレーションでは、$Record__Prior 以外の参照されるすべてのレコードが更新されます。

バックグラウンドステップが同期して実行され、レコードが更新されても、オーケストレーションの実行が再開されるまで $Record は更新されません。フェーズでは、ステップの完了後に更新された項目値にアクセスできません。また、フェーズまたはステップの終了条件で使用することはできません。ステップで更新された項目値にアクセスするには、$Record を直接参照するのではなく、ステップの自動出力を使用します。

オーケストレーションのビルディングブロック

フェーズとステップはオーケストレーションのビルディングブロックです。

  • オーケストレーションのステージ
    フェーズでは、関連するステップがグループ化され、論理フェーズに整理されます。フェーズは順次実行され、オーケストレーションでは一度に 1 つのフェーズのみを処理できます。フェーズを完了する前に、フェーズに必要な条件を設定します。
  • オーケストレーションステップ
    ステップはステージでグループ化され、順次または同時に実行できます。対話型ステップでは、有効な画面フローの完了がユーザー、グループ、またはキューに割り当てられるため、ユーザーの操作が必要になります。バックグラウンドステップでは、有効な自動起動フローが同期または非同期で実行され、ユーザー操作はありません。MuleSoft ステップは、MuleSoft 操作からインポートされたアクションを実行し、ユーザー操作はありません。
  • オーケストレーションのフロー
    オーケストレーションの各バックグラウンドステップと対話型ステップで、関連付けられたフローが実行されます。フェーズとステップの実行を制御するロジックで 3 個を超える要件が必要な場合、評価フローを使用してより複雑な条件を作成します。
  • フローオーケストレーション作業項目
    オーケストレーションの対話型ステップが実行されると、作業項目が作成され、ユーザー、グループ、またはキューに割り当てられます。その後、オーケストレーション実行によって、指定されたレコードページへのリンクが記載されたメールが、割り当てられたすべてのユーザーに送信されます。指定されたレコードページのオーケストレーション作業ガイドコンポーネントで作業を完了します。

オーケストレーションでのエラー処理

エラー処理では、オーケストレーションの実行中に段階的に発生する予期しない問題を管理します。フェーズの障害パスを設定して、フェーズエラーが発生したときの復旧アクションを定義し、オーケストレーションが失敗するのではなく正常に完了するようにします。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。

全般

オーケストレーションの実行でエラーが発生すると、その状況は [エラー] に設定されます。フェーズ内で発生したエラーの多くは回復可能です。これらのエラーの場合、エラーを修正してオーケストレーションの実行を再開するまで最大 14 日の猶予があります。フェーズ外でエラーが発生すると、オーケストレーションの実行は失敗し、再開できません。「オーケストレーション実行での失敗したオーケストレーションの再開」を参照してください。

再開するには、基盤となるフローまたはエラーを修正し、オーケストレーションの実行を再開する必要があります。このアプローチは、オーケストレーションデザイナーが設計時に設定する障害パスとは異なります。障害パスはエラーを適切に処理し、エンドユーザーに復旧メカニズムまたは手動介入ステップを提供します。

オーケストレーションの実行が失敗すると、Salesforceはオーケストレーションを最後に変更した管理者またはApex例外メールの受信者にエラー メールを送信します。エラーメールには、実行された要素や参照されたステップなど、オーケストレーション実行に関する詳細が表示されます。有効なオーケストレーションの場合、メールには失敗したオーケストレーション実行の詳細を Flow Builder で表示するためのリンクも記載されます。オーケストレーションによってコールされたフローが失敗の原因である場合、受信者はオーケストレーション用とコールされたフロー用の 2 つのエラーメールを受信します。

障害パスでエラーが処理され、正常に完了しても、オーケストレーションからエラー通知は送信されません。ただし、障害発生時に関係者に通知するバックグラウンドステップを障害パスに追加できます。

エラーを管理するには、オーケストレーションのフェーズの障害パスを設定します。フェーズまたはそのステップでエラーが発生した場合は、これらのパスでプロセスの失敗を最小限に抑える代替アクションを定義します。

失敗したオーケストレーションは以前のすべてのレコード変更をロールバックするとは限らないため、本番にリリースする前に Sandbox 環境でオーケストレーションを設計およびデバッグします。

未対応のエラーと状況の変更

オーケストレーションの実行中に問題が発生し、回復メカニズムが存在しない場合、未対応のエラーが発生します。オーケストレーションの場合、フェーズまたはステップでエラーが発生し、そのフェーズに障害パスが設定されていないと、未対応のエラーが発生します。

オーケストレーションのエラー処理戦略

オーケストレーションのエラー処理では、ビジネスプロセスが正常に完了または正常に回復するように失敗を管理します。障害パスを使用して、フェーズやステップからエラーを管理します。個別の障害パスを使用して対象を絞ったリカバリを行ったり、一元化された障害パスを使用して包括的なエラー管理を行ったりできます。

障害パスは、オーケストレーションの実行でエラーが発生したときにエンドユーザーが手動で介入できるシナリオで役立ちます。たとえば、エンドポイントが停止しているため、外部インテグレーションまたは API コールが失敗するとします。障害パスには、割り当て先が必要なデータを手動で入力する対話型のステップを含めることができます。

障害パスには、空にすることも、決定要素とステージ要素を含めることもできます。障害パスの各フェーズには少なくとも 1 つのステップが必要であり、複数のステップを含めることができます。これらのステップには、バックグラウンドステップ、対話型ステップ、またはその両方の組み合わせが含まれます。障害パスでは Go To コネクタもサポートされています。移動コネクタは、同じ障害パス、別の障害パス、またはオーケストレーションのメインパスの別の要素にリンクします。

個々の障害パス。オーケストレーションの各フェーズに個別の障害パスを設定します。これらの個々のパスには、各フェーズに固有のエラーを管理するステップを含む要素とフェーズが含まれます。このアプローチでは、高度にローカライズされたエラー解決が提供されます。たとえば、注文処理オーケストレーションで、在庫検証フェーズで接続タイムアウトによるエラーが発生したとします。障害パスでは、検証ステップを再実行したり、業務に通知を送信したり、手動レビューフェーズに転送したりできます。

一元化された障害パス。統合されたエラー処理メカニズムとして機能する 1 つの中央障害パスを設定します。通常、このアプローチは、オーケストレーションの実行に関連する変数と自動出力を評価する決定要素から開始します。この決定により、エラーが発生した特定のフェーズが特定されます。関連付けられた結果パスの要素は失敗に対応します。各フェーズの障害パスを中央の障害パスの最初の決定要素に接続します。このアプローチでは、包括的なエラー解決が提供されます。

例

たとえば、顧客のオンボーディングオーケストレーションでは、一元化された障害パスは決定要素から始まります。この決定では、エラーが発生したフェーズを評価し、適切な復旧アクションを決定します。

[Create Customer Account (顧客取引先を作成)] フェーズの状況が [Completed] でない場合、決定結果のパスにはバックグラウンドステップがあるフェーズが含まれます。このステップでは、取引先マネージャーにこの問題を通知します。[プロビジョニングシステム] フェーズの [サービスアクセスを設定] ステップが失敗した場合、決定結果のパスには 2 つのステップを含むフェーズが含まれます。バックグラウンドステップでサポートチケットが作成されます。対話型ステップでは、システム設定を IT チームに割り当てます。IT 部門が設定を完了すると、オーケストレーションはサービスの有効化フェーズに進みます。

エラー処理の制限事項

  • オーケストレーション実行レベルのエラー処理を追加することはできません。
  • 失敗したオーケストレーション実行のデバッグの詳細は、失敗から 14 日以内にのみ表示できます。
  • 終了要素のみが含まれる障害パスでは、オーケストレーションの実行状況を [Completed] に変更してエラーを処理します。この方法では、エラーを解決せずに抑制します。オーケストレーションの実行状況が [完了] の場合、Salesforce はエラー通知メールを送信しません。ただし、最初にエラーが発生したステップとフェーズは、オーケストレーションの実行状況が [完了] であっても [エラー] 状況のままです。

オーケストレーションの評価フロー

ステージとステップの実行を制御するために 3 個を超える要件が必要な場合は、評価フローを使用します。[新規フロー] ウィンドウで [評価フロー] タイルを選択して、評価フローを作成します。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。

評価フローの変数

[新規フロー] ウィンドウで [評価フロー] タイルを選択すると、isOrchestrationConditionMet という名前の定義済み Boolean 出力変数を含む評価フローが作成されます。

isOrchestrationConditionMet を false に初期化し、カスタム条件が満たされたことを示すために、isOrchestrationConditionMet を true に設定します。

評価フローでは、isOrchestrationConditionMet の値のみが返されます。他の出力変数の値は破棄されます。

評価フローの実行

現在のステージ内の非同期バックグラウンドステップ、対話型ステップ、または MuleSoft ステップが完了するたびに、オーケストレーションでそのステージとそのステップの条件が評価されます。現在のフェーズとそのステップの条件の評価をトリガーするには、$Orchestration.Instance を使用してオーケストレーションイベントを公開します。

各フェーズまたはステップの状況によって、オーケストレーションでチェックされる条件が決まります。チェックされる条件が評価フローに依存している場合、評価フローが実行されます。

  • ステージが処理中の場合、オーケストレーションによって完了できるかどうかが判断されます。
  • 現在のステージ内の開始されていないステップごとに、オーケストレーションによってステップを開始する準備が整っているかどうかが判断されます。
  • 現在のフェーズ内の進行中のインタラクティブステップごとに、オーケストレーションによってステップを完了としてマークできるかどうかが決まります。

評価フローの実行コンテキスト

API バージョン 58.0 および 59.0 では、評価フローは常にシステムコンテキストで実行されます。

API バージョン 57.0 以前では、評価フローはフローの [フローの実行方法] 上級オプションで指定されたとおりに実行されます。

障害パス

オーケストレーションのフェーズまたはフェーズ内のステップでエラーが発生した場合の動作を定義するには、障害パスを使用します。オーケストレーションの各フェーズには、障害パス内にあるフェーズを含め、独自の障害パスを設定できます。

バックグラウンドステップの処理サイクル

バックグラウンドステップの処理

各バックグラウンドステップは、有効な自動起動フローを参照します。オーケストレーションが実行されると、ステップのフローが同期または非同期のどちらで実行されるかが自動的に判断されます。

オーケストレーション実行では、ステップのフローに 1 つ以上のサブフロー要素または待機要素が含まれている場合、バックグラウンドステップを非同期で処理します。1 つ以上のアクション要素を含むバックグラウンドステップの実行方法は、オーケストレーション実行の API バージョンによって異なります。

API バージョン 68.0 以降で実行されているオーケストレーションの場合、同期アクションを含むフローを含むバックグラウンドステップは同期して実行されます。非同期アクションを含むフローのバックグラウンドステップは非同期で実行されます。

API バージョン 67.0 以前で実行されているオーケストレーションの場合、アクション要素を含むフローがあるバックグラウンドステップは非同期で実行されます。

バックグラウンドステップのフローが同期的に実行される場合は、フローが完了したときにオーケストレーションが再開されます。

バックグラウンドステップのフローが非同期的に実行される場合、プラットフォームイベントのフローオーケストレーションイベントが公開されます。オーケストレーション実行はイベントを受信すると、現在のフェーズとその [未開始] または [進行中] の各ステップを評価します。
