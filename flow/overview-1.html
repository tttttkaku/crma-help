Slack チャンネルアクションのアーカイブ

Slack でチャンネルをアーカイブします。Slack のアーカイブ済みチャンネルは新しい活動に対して閉じられますが、メッセージ履歴は保持されます。

必要なエディション

サポートされているエディションを表示する。

Flow Builder で、[アクション] 要素をフローに追加します。[新規アクション] ウィンドウで、[Slack] を選択してから [Slack チャンネルをアーカイブ] を選択します。

利用状況

このアクションを使用するには、まず Salesforce と Slack を接続して、Slack の [Archive Slack Channel Workflow Builder] ステップを [全員] に設定します。キャンバスの所有者として設定したユーザーは、Slack でアクセス権限を管理して他のユーザーと共有できます。

Slack の接続値の設定

入力パラメーター 説明
Slack チャンネル ID アーカイブ中の Slack チャンネルの ID。

  • Slack ヘルプセンター: Salesforce と Slack の接続
  • Slack ヘルプセンター: チャンネルのアーカイブまたは削除

Salesforce フローを使用した自動化について

Flow Builder、フローオーケストレーション、MuleSoft for Flow などの Salesforce フローツールを使用すると、ビジネスニーズに合わせて自動化ソリューションをすばやく設定および変更できます。これらのツールは ToDo とプロセスの自動化を簡単なインテグレーションソリューションと組み合わせることで、コードを記述することなく、あらゆるシステムのデータ変更をまとめてアクションを実行できます。

必要なエディション

サポートされているエディションを表示する。
  • ブラウザー要件
    自動化ツールでは、次の Web ブラウザーがサポートされています。
  • プロセスの自動化設定
    Salesforce には、ビジネスプロセスのカスタマイズと合理化に役立つプラットフォーム自動化のさまざまな設定が用意されています。
  • リリースおよび API バージョンごとの実行時の変更
    これらのバージョン管理された更新は、特定の API バージョンで実行するように設定されたフローにのみ影響します。バージョン管理された更新により、必要に応じて個々のフローの実行時の動作の変更をテストし、採用できます。

  • オートメーションアプリケーションの [オーケストレーション] タブ
    [オーケストレーション] タブには、多数の標準オーケストレーションリストビューと作成したリストビューが含まれます。オーケストレーションの表示ラベルまたは説明でキーワードを検索します。トリガー種別、状況、最終更新日などの項目でオーケストレーションを絞り込んだり並び替えたりします。選択したオーケストレーションに関連するオーケストレーションの実行を表示および管理します。
  • 一時停止中のフローインタビューと失敗したフローインタビューのモニタリングと管理
    オートメーション Lightning アプリケーションで、失敗したフローインタビューと一時停止中のフローインタビューを簡単に追跡して管理できます。[監視] タブには、すべての失敗したフローインタビューと一時停止中のフローインタビュー、および失敗したか一時停止した理由が表示されます。
  • オートメーションアプリケーションの [インテグレーション] タブ
    インテグレーションタブには、組織のすべての接続が表示されます。
  • 呼び出し可能なアクションの表示と検索 (ベータ)
    Flow Builder で使用される標準およびカスタムの呼び出し可能なアクションをすばやく見つけることができます。Agentforce Builder およびプロンプトビルダー。Automation Lightning アプリケーションの [アクションハブ] タブを使用します。アクションのリストを検索するか、アクション種別で絞り込み、アクションを選択して詳細を確認し、使用場所を特定します。
  • フローログを使用したフローのパフォーマンスの監視
    Automation Lightning アプリケーションの [フローログ] タブを使用して、Data 360 を設定し、フローログを設定します。次に、有効化されたフローのパフォーマンス総計値を追跡します。

接続は、コネクタおよび関連付けられたユーザーまたはシステムのログイン情報を使用して外部システムに接続する設定です。フローのさまざまなステップで接続を使用して、システムへの接続、トリガーの確認、データの戻りまたは操作を行います。

接続により、外部システムに接続できます。接続では、接続された外部システムからの API またはオブジェクトのメタデータ (入力項目や出力項目など) へのアクセスと取得を設定します。接続と自動化のニーズに応じて、これらの項目をフローで使用および参照できます。同じフローまたは作成する異なるフローで同じ接続を複数回使用できます。

接続を作成すると、必要な指定ログイン情報と外部ログイン情報がバックグラウンドで自動的に生成され、[設定] で作成する必要がなくなります。

Flow Builder では、さまざまな認証種別を使用して接続が作成されます。接続の認証に必要な項目は標準ですが、外部システムによって異なる場合があります。認証種別は次のとおりです。

ApiKey

ApiKey 認証は、ユーザーを明示的に定義せずにアプリケーションに接続します。この鍵をすべての要求に追加すると、クラウドアプリケーションが要求の発生源を識別し、認証を完了します。

基本

基本認証では、ユーザーは外部システムにログインするときにユーザー名とパスワードを入力できます。

ベアラー

ベアラー認証では、要求ごとに [Bearer (ベアラー)] の値とトークンを含む Authorization という名前のヘッダーが送信されます。

OAuth2BrowserFlow

OAuth2BrowserFlow 認証には、OAuth 2.0 プロトコルの機能とセキュリティを拡張する機能が含まれています。

OAuth2ClientCredentials

OAuth2ClientCredentials 認証では、ユーザー定義のパスからアクセストークンを取得します。

トークンベースの認証

トークンベースの認証では、外部システムへの暗号化されたアクセストークンが生成されます。独自の外部システム生成トークン ID 項目とトークンの秘密項目を使用して、Flow Builder を外部システムに接続します。

指定ログイン情報認証

指定ログイン情報認証では、[設定] の外部ログイン情報と既存の指定ログイン情報を使用して外部システムに接続します。

特定の外部システムへの接続に必要な項目の詳細については、関連する『MuleSoft for Flow: Integration Connectors Reference』ページを参照してください。

MuleSoft for Flow: Integration の設定方法とシステム間の自動接続の作成方法の概要については、「Get Started with MuleSoft for Flow: Integration (フロー用 MuleSoft: Integration の使用開始)」を参照してください。

標準認証方法を使用した外部システムへの接続の作成

    • [コネクタの使用開始] セクションからサードパーティコネクタを選択し、[接続を作成] をクリックします。使用しているコネクタが セクションで使用できない場合は、[View All Connectors (すべてのコネクタを表示)] をクリックし、[Browse Connectors (コネクタを参照)] ウィンドウからコネクタを選択して、[次へ] をクリックします。
    • [新規接続] をクリックし、使用可能なサードパーティコネクタを選択して、[次へ] をクリックします。
  3. [認証プロトコル] で、標準認証方法を選択します。
  4. そのコネクタの接続情報と認証の詳細を入力します。
    重要

    [URL] フィールドに、必ず http://<domain> の形式で値を入力します。たとえば、https://thirdpartyconnector.com のようになります。

  5. [作成] をクリックします。

指定ログイン情報を使用した外部システムへの接続

[設定] から、外部システム接続に使用する指定ログイン情報を選択します。

前提条件

指定ログイン情報を使用して外部システムに接続する前に、既存の認証済み指定ログイン情報と、ユーザーに対して有効になっている外部ログイン情報を作成または使用します

フローで使用するために接続を成功させるには、指定ログイン情報ごとに 1 つのプリンシパルのみを使用します。

  • 指定ログイン情報とその関連オブジェクト (外部ログイン情報や外部認証 ID プロバイダーなど) には同じ名前を使用します。これらのオブジェクトの表示ラベルは異なる場合があります。
  • 接続を作成するユーザーにプリンシパルに必要なユーザー権限を割り当てます。この権限がないと、接続テストは失敗し、接続は無効のままになります。
重要

既存の指定ログイン情報との接続を作成する場合、次の点に注意してください。

  • [インテグレーション] タブではなく、[設定] で指定ログイン情報の参照のみの詳細を管理します。[インテグレーション] タブでは、接続の [接続名] と説明のみを編集できます。
  • [設定] で指定ログイン情報の再接続を実行します。[再接続] ボタンは [詳細] ページに表示されません。
  • [設定] で、関連付けられた指定ログイン情報を削除します。接続を削除しても、ログイン情報は削除されません。

OAuth 2.0 接続の更新

OAuth 2.0 認証を介した外部システムへの接続が期限切れのリフレッシュトークンによって中断した場合は、再接続できます。

  1. 更新する接続を選択します。
  2. 再接続 をクリックします。
  3. サードパーティシステムに接続するために必要な手順を実行します。
  4. 作業内容を保存します。

    接続を更新すると、OAuth ダンスによって新しい更新トークンが生成され、接続が再接続されます。

接続の編集

  1. 自動化アプリケーションの [インテグレーション] タブで、編集する接続を選択します。

    接続を使用するフローは、[関連] タブの [接続を使用するフロー] テーブルに表示されます。次の表に、各フローの名前、バージョン、状況、所有者を示します。フローを表示するには、その名前をクリックします。接続と認証の詳細は、[詳細] タブを参照してください。

  2. [編集] をクリックします。
    重要

    フローで使用されている接続を編集すると、接続に失敗したときにエラーが発生する可能性があります。接続の編集は永続的で、すぐに有効になり、関連付けられたすべてのフローに影響します。

  3. ウィンドウを読み、[編集] をクリックします。
  4. フィールドを編集します。
    重要 [接続 API 種別] や [認証種別] などの無効な項目は編集できません。[認証の詳細] セクションで項目を編集すると、[パスワード] 項目がクリアされます。値をもう一度入力します。
  5. 作業内容を保存します。

    保存後にエラーが表示された場合、変更は保存されません。エラーを解決して、もう一度保存します。接続テストが成功したか失敗したかを示すメッセージが表示されます。[インテグレーション] セクションで、[接続を使用するフロー] テーブルの [最終テスト日] 項目と [進行状況] 項目が更新され、最新のテスト結果が表示されます。

  • 接続を作成するとき
  • アクションまたはトリガーとして使用する外部システムへの既存の接続を選択する場合
  • 外部システムへの接続を含む既存のフローを再度開くとき

手動で接続を再テストすることもできます。

  1. テストする接続を選択します。
  2. [テスト] をクリックします。

    テスト結果を示すメッセージが表示されます。[インテグレーション] セクションの [接続を使用するフロー] テーブルで、[最終テスト日] 項目と [進行状況] 項目が最新のテスト結果で更新されます。

API を使用しないシステムへの接続

外部システムに使用可能な API またはコネクタがない場合、MuleSoft RPA プロセスを作成できます。これらのプロセスは、デスクトップおよび Web アプリケーションとやりとりし、フローからこれらのプロセスを呼び出します。MuleSoft RPA を使用すると、フローで次のことができます。

  • Web ブラウザーおよび Web ベースアプリケーションの起動と操作
  • デスクトップアプリケーションを開いて制御する
  • API アクセス権がないアプリケーションからデータを抽出する
  • 複数のシステムでフォーム入力とデータ入力を自動化

MuleSoft for Flow: API を使用するインテグレーションコネクタとは異なり、MuleSoft RPA プロセスはアプリケーションとの人間のインタラクションを模倣します。このプロセスにより、最新のインテグレーション機能がない古いシステムやアプリケーションからデータを取得するのに役立ちます。

MuleSoft for Flow を使用したドキュメントの処理: IDP

従来の API を使用できない場合や、データがドキュメント内にある場合は、ドキュメント処理に MuleSoft for Flow: IDP を使用します。ドキュメント処理設定をカスタマイズし、PDF、画像、フォームなどの非構造化ドキュメントから構造化データを抽出するには、Flow Builder のドキュメント処理機能を使用します。

  • 設定: オートメーションアプリケーションでドキュメント処理設定を作成し、処理するドキュメントの種類ごとに抽出ルールと出力構造を定義します。これらの設定では、抽出するフィールド、そのデータ型、および Einstein がドキュメント構造を理解するのに役立つ省略可能な命令を指定します。
  • 処理: フローで [ドキュメントからデータを抽出] アクションを使用して、分析用のドキュメントを送信します。このアクションでは、指定されたドキュメント処理設定を使用してデータを抽出し、後続のフロー要素で使用できる構造化情報として結果を返します。このアクションは、抽出されたすべてのデータを含む動的 Apex クラスを返します。このデータを後続のフロー要素で使用したり、人間による確認のために送信したりできます。
  • レビュー: [ドキュメントからデータを抽出] アクションで [ヒューマンレビュー設定] を設定することで、抽出されたデータを人間が直接レビューすることを要求します。フローが一時停止し、レビュー担当者がオートメーションアプリケーションの [ヒューマンレビュー] タブでデータを検証または修正して、フローが再開されます。

ドキュメント処理設定

ドキュメント処理設定では、ドキュメントから抽出する特定の項目、テーブル、列を定義します。また、Einstein がドキュメント構造をより深く理解できるように、人間による指示を提供することもできます。

たとえば、[請求書番号] などの項目を定義して、[ドキュメントのベンダー名の横にある項目から請求書番号を抽出] などの指示を含めることができます。

信頼性スコアとデータ品質

Einstein は、抽出された各フィールドの精度を示す信頼性スコアを割り当てます。信頼性スコアが高いほど、信頼性の高い抽出が可能です。スコアが低いほど、手動レビューが可能です。

信頼性の低い抽出のみをレビューに転送するには、[ドキュメントからデータを抽出] アクションの [ヒューマンレビュー設定] を [必要な場合のみ] に設定します。

レビューウィンドウで、各項目の信頼度がパーセントで表示されます。このアクションでは、後のフロー要素で使用できる [要手動確認] 出力と、相関関係 ID、抽出されたデータ、抽出されたデータ (JSON) も返されます。

人間によるレビューが必要なケース

レビューワークフローを使用すると、抽出されたデータをビジネスプロセスで使用する前に検証できます。次の場合に使用します。

  • 抽出されたデータの信頼性スコアが低い
  • ビジネスルールの手動承認が必要
  • 意思決定を行う前にデータの正確性を検証する
  • コンプライアンス要件による人の監視

人間によるレビューを追加するには、[ドキュメントからデータを抽出] アクションで [人間によるレビューの設定] を有効にします。「Extract Data from Document Action (ドキュメントアクションからのデータの抽出)」を参照してください。

ヒューマンレビュー設定のしくみ

[ドキュメントからデータを抽出] アクションの [ヒューマンレビュー設定] セクションで、レビューが必要なタイミングと完了者を選択します。

  • なし: レビューは作成されません。抽出されたデータは、フローの次の要素に直接移動します。
  • Only when needed: レビューは、抽出された 1 つ以上のフィールドまたはテーブルの行の信頼性スコアが信頼性しきい値を下回っている場合にのみ作成されます。すべての値がしきい値以上である場合、フローはレビューなしで続行されます。
  • 常に: 信頼性スコアに関係なく、アクションで処理されるドキュメントごとにレビューが作成されます。

[割り当て先] で、レビューを所有するユーザーを選択できます。[割り当て先] を空白のままにすると、レビューは割り当てられたレビュー担当者なしで作成されます。

レビューが作成されると、フローはアクションで一時停止し、レビューが送信されるまですべての下流要素が保持されます。レビュー担当者は、オートメーションアプリケーションの [ヒューマンレビュー] タブの [すべてのヒューマンレビュー] リストからレビューを開きます。[ドキュメントレビュー] ウィンドウでは、抽出されたデータを元のドキュメントと比較し、値を編集してレビューを送信します。「抽出済みドキュメントデータの確認」を参照してください。

レビュー担当者が送信すると、フローが再開され、レビュー済みの値が [完了] パスに渡されます。レビューが却下またはタイムアウトした場合、フローは [完了] パスで続行されません。時間内にレビューを完了できなかった場合にアクションを実行するには、アクションのタイムアウト (時間) を設定し、[タイムアウトパスを含める] を有効にします。それ以外の場合、タイムアウトの期限が切れたときにフローがエラーで失敗します。

サポートされるドキュメント種別

この機能では、次のようなさまざまな種類のビジネスドキュメントを処理できます。

バリューマップとは?

値の対応付けは、ソース値をターゲット値に対応付けるルックアップテーブルです。数式または決定分岐で同じ翻訳ロジックを再構築するのではなく、マッピングを 1 回定義して複数のインテグレーションフローで再利用します。

たとえば、あるシステムの優先度値を別のシステムの優先度ラベルに対応付けることができます (P1 から High など)。

バリューマップのしくみ

  • 各エントリには、ソース値と対応付けられた目標値が含まれます。
  • ソース値は一意である必要があります。
  • 目標値は複数のソース値で繰り返すことができます。
  • ルックアップは、ソース値からターゲット値までの順方向にのみ実行されます。

マッピングされていない値の動作の設定

値マップでソース値が見つからない場合は、デフォルトの動作を選択します。

  • フローの失敗: 実行を停止してエラーを返します。
  • マッピングされていない値としてパススルー: ソース値を出力として使用します。
  • デフォルト値の定義: 特定のデフォルトの目標値を返します。

グローバルリソースとしてのバリューマップの管理

グローバルフローリソースから値マップを管理します。ここでは、値マップを作成、表示、および開くことができます。各値対応付けレコードで、対応付けエントリを更新したり、対応付けを参照するフローを確認したり、連動関係が存在しない場合に対応付けを削除したりできます。

  • 外部システムでは、1 つのログイン情報セットで OAuth 接続数が制限される場合があります。たとえば、Salesforce 開発者アカウントにはデフォルトで 5 つの接続があり、他の種別の組織では制限が高くなります。
  • 接続では 1 回の操作で合計 10,000 件のレコードを取得できます。コールあたりの最大ペイロードサイズは 6 MB です。最良の結果を得るには、1 つの操作のレコード数を 5,000 以下に制限します。

フローでの接続アクセスとフローでの使用の管理

指定ログイン情報は、Salesforce Power Connection によって作成および管理されます。「インテグレーション接続の管理」権限または「アプリケーションのカスタマイズ」権限を持つ組織のユーザーは、実行時にコールアウトを実行できます。より厳格なアクセス制御を適用するには、フローを実行できるユーザーを制限します。

接続は複数のフローで機能します。ログイン情報を更新すると、変更は次のフローの実行で有効になります。この更新機能は、パスワードを循環したり、Sandbox から本番に切り替えたりする場合に便利です。フローが使用している接続は削除できません。外部システムへのアクセスをブロックするには、接続を編集し、無効なログイン情報を入力して無効にします。

Agentforce 機能: 動的アクションの制限事項

MuleSoft for Flow の Agentforce 機能: インテグレーションでは、サードパーティコネクタでの動的アクションはサポートされません。NetSuite、Salesforce、および Zendesk コネクタからの動的メタデータに依存するフローでは Agentforce を使用できません。

プロファイルや権限セットの制限によるフローアクセスの制御

[プロファイルおよび権限セットの制限] では、フローへのアクセス、編集、または実行ができるユーザーを管理できます。Salesforce では、フローがサブフローとしてコールされた場合を含め、すべてのエントリポイントにこれらの制限が適用されます。このシナリオでは、デフォルト動作を上書きし、個々のフローに詳細なセキュリティを適用できます。このセキュリティにより、必要な権限を持つユーザーのみがアクセスして実行できます。

パイロットリリース中に作成された接続の管理

組織が MuleSoft for Flow: Integration パイロットに参加している場合、そのリリースの接続を再使用するとエラーが発生する可能性があります。たとえば、コールアウトを行うフローアクションは、認証トークンがないために失敗する可能性があります。既存の接続が機能するように、Salesforce システム管理者は UserExternalCredential オブジェクトへのアクセス権をユーザーに付与する必要があります。

ポーリングベースのフロー自動化で見逃されたトリガー

フローをポーリングするときに、フローオートメーションでトリガーが見逃されることがあります。

外部システム変更トリガーポーリング失敗の処理

重要

外部システム変更トリガーフローでは、ポーリング機能を使用して、選択したスケジュールでレコードを取得します。

ポーリング動作と無効化

  • 再試行: ポーリングが失敗すると、フローは最大 3 回連続して再試行します。
  • 自動無効化: ポーラーが 3 回連続して失敗した後に実行されます。この動作は、ポーラーレベルの失敗 (認証や接続など) に適用されますが、個々のレコードレベルの失敗には適用されません。
  • 再有効化: ポーラーの失敗によってフローが無効化された場合は、原因となっている問題を解決して、フローを手動で再有効化します。

ポーラーの制限と例外

  • Pre-execution Failures: 実行の開始前にポーラーが失敗した場合、開始要素で障害パスを使用できなくなります。
  • ペイロード制限: 128,000 文字を超えるポーリング応答 (データとメタデータを含む) がペイロード制限を超えている。
例

Salesforce で商談の状況が商談成立に変更された場合、フローによって外部システムに販売注文が作成されます。

  • フローは 5 分ごとにポーリングします。

  • 午後 1 時 00 分、複数の商談が商談成立としてマークされます。フローは午後 1 時 00 分にポーリングされ、条件に一致して lastModifiedDateTime値が午後 12 時 55 分より後のレコードを返します。Salesforce は 5 個の商談を返します。

    フローは、この 5 個の商談を取得し、5 個のフローインタビューを実行して外部システムで処理します。

  • インタビューのタイムスタンプは午後 1 時 00 分、フローは午後 1 時 05 分に再度ポーリングされます。午後 1 時 5 分に、フローは条件に一致して lastModifiedDateTime 値が午後 1 時より後のレコードをポーリングします。

Salesforce はバックグラウンドでデータを処理します。午後 1:00:00 に完了した商談が午後 1:00:05 にデータベースにコミットされ、タイムスタンプが午後 1:00:00 になっている可能性があります。レコードが更新されて遅延が発生した場合、トリガーが実行されない可能性があります。

値マップの考慮事項と制限事項

インテグレーションフローをリリースする前に、実行時の動作、パッケージ化要件、サポート対象外のシナリオを確認してください。

実行時の動作

  • 値マップのルックアップは、ソース値から目標値への前方参照のみです。
  • ソース値には、各値マップの一意の値が必要です。
  • 目標値は行間で繰り返すことができます。
  • マッピングされていないソース値は、値マッピングのデフォルトの動作設定をトリガーします。

マッピングされていない値のデフォルトの動作

  • Fail the flow: フローはエラーを返し、停止します。
  • マッピングされていない値としてパススルー: マッピングされていないソース値が出力として返されます。
  • デフォルト値の定義: ユーザー定義のデフォルトの目標値が返されます。

グローバルリソース管理

  • グローバルフローリソースから値の対応付けを管理します。
  • リストビューでは一括削除がサポートされていないため、値の対応付けを個別に削除します。
  • 値マップを削除する前に、値マップへのすべてのフロー参照を削除します。

入力モードとフローのサポートの制限

  • 外部トリガーの開始要素では、[値の対応付け] 入力モードを使用しないでください。開始要素ではサポートされていません。
  • 値マップでは定数リソースがサポートされないため、ソースの変数または項目を参照します。

管理パッケージ

  • 第 2 世代管理パッケージ (2GP) をバリューマップの主要なパッケージ化方法として使用する。
  • 第一世代管理パッケージ (1GP) では、参照値マップは自動的に含まれないため、手動で追加します。

設定手順については、「Create and Manage Value Maps」を参照してください。変換で値の対応付けを適用するには、「Use a Value Map in Transform (変換での値の対応付けの使用)」を参照してください。

1. フローのビルディングブロック すべてのフローを構成する 3 つのコアコンポーネント (要素 (フローが実行するアクション)、コネクタ (フローがたどるパス)、リソース (フローが参照する値)) を理解します。これは、その後のすべての基盤です。
2. フロー種別 使用事例に適したフロー種別を選択します。フローの種別は、使用可能な要素とリソース、およびフローの配布方法を制御します。たとえば、画面フローはユーザー入力を収集しますが、自動起動フローはバックグラウンドでサイレントに実行されます。
3. トリガーフロー フローを開始する内容を決定します。トリガーには、レコードの変更、タイムスケジュール、外部システムイベント、Data Cloud データの変更、オートメーションイベント、利用者またはセグメントメンバーシップが含まれます。このトピックでは、各トリガー種別を対応する概念トピックに対応付けることで、適用されるトリガー種別を詳しく調べることができます。
4. テンプレートトリガープロンプトフロー 特殊なフロー種別を使用して、動的データをプロンプトビルダープロンプトテンプレートに提供します。フローは、プロンプトテンプレートが解決され、生成されたコンテンツ (近隣のイベントのリストなど) がテンプレートの出力に挿入されたときに実行されます。
5. 外部システムインテグレーションの設計 コードなしでフローを Salesforce 外のシステムに接続します。MuleSoft for Flow: Integration コネクタ、直接 API コール用の HTTP コールアウトアクション、従来のデスクトップシステム用の MuleSoft RPA、または MuleSoft for Flow: IDP から選択して PDF やその他のドキュメントからデータを抽出します。

このセクション

  • フローのビルディングブロック
    フローは、要素、コネクタ、リソースの 3 つのコアコンポーネントから構築されます。要素は、Salesforce データの読み取りや書き込みなど、フローで実行されるアクションを表します。コネクタは、実行時にフローがたどるパスを定義します。リソースは、フロー全体で参照できる値を表します。
  • フロー種別
    フローの種別によって、フローに追加できる要素とリソース、およびフローの配布方法が決まります。たとえば、訪問者から情報を収集するためにページに画面フローを埋め込んだり、バックグラウンドでフローを実行するためにユーザーがクリックするカスタムボタンを使用して自動起動フローを配布したりします。同様に、カスタムエラー要素はレコードトリガーフローでのみ追加できますが、選択肢リソース種別は画面フローでのみ追加できます。
  • トリガーフロー
    トリガーされたフローの開始要素で、フローを開始する内容を指定できます。たとえば、フロートリガーはスケジュールや、指定されたオブジェクトの新規および変更されたレコードにすることができます。トリガーを使用しない場合、カスタム ボタン、プロセス、Apex クラス、さらには Einstein ボットなど、フローを起動する他のものを設定する必要があります。
  • テンプレートトリガープロンプトフロー
    テンプレートトリガープロンプトフローを使用して、プロンプトビルダーでプロンプトテンプレートにデータを提供します。
  • 外部システムインテグレーションの設計
    コーディングなしでフローを外部システムに接続するには、フローで MuleSoft for Flow: Integration コネクタを使用します。コネクタが存在しない場合は、HTTP コールアウトアクションを使用して、コーディングなしで外部システムに直接 API コールを実行できます。[外部システムの変更トリガー] フロー種別を選択して、外部システムの変更が発生したときにフローを実行します。API を使用しない従来のシステムでは、Anypoint Platform で公開されている MuleSoft RPA プロセスをフローの外部サービスとして使用できます。ドキュメントと非構造化データの場合、MuleSoft for Flow: IDP を使用して PDF、画像、フォームから情報を抽出します。

フローの要素エラー率

いくつかの種類のフローでバックグラウンドで ToDo が自動化されます。そのため、エラーが発生しても、ビジネスプロセスに問題があることに気付くまでしばらくかかることがあります。[要素エラー率] 項目を使用して、注意が必要なフローを一目で確認できます。この項目には、正常なフローの場合は緑の成功アイコン、正常なフローの場合は黄色の警告アイコンが表示されます。Salesforce でエラー率を計算する方法と、計算で使用する総計値について説明します。

要素エラー率は、最後に発生したフローでエラーが発生したフロー要素の割合です。エラー率が 0% のフローにはエラーがなく、緑のアイコンが表示されます。エラー率が 1 ～ 100% のフローには、調査が必要であることを示す黄色いアイコンが表示されます。この項目は、標準フローリストビューおよび個々のフローレコードページに表示されます。

フロー出現数

フローが実行されるたびに、フロー発生が作成されます。フローに応じて、フローの発生は複数のフローインタビューで構成される場合があります。毎週 50 件のレコードに対して実行されるフローには、毎週 1 件のフロー発生と 50 件のフローインタビューがあります。

要素エラー率の計算方法の例

このフローには、考えられる 3 つの方法を分割する決定要素があります。

このフローが [30 日超] パスに沿っている場合、[決定]、[アクション]、[レコードを更新] 要素の合計 3 つの要素が実行されます。[15 日以上] パスでは 2 つの要素を実行し、[デフォルトの結果] パスでは 1 つの要素のみを実行します。

このフローで [30 日以上] のパスが実行されたが、[レコードを更新] 要素中にエラーが発生したとします。フローで 1 つの要素エラーと 3 つの要素が実行されたため、要素エラー率は 1/3 または 33% になります。

フローは毎週、まだ有効なレコードで実行され、特定の実行で 100 件の対象レコードが検出されます。これらのレコードに対して作成されたフローインタビューのうち、

  • 15 件は [30 日超] パスを実行し、そのうち 5 件は [レコードを更新] 要素でエラーが発生し、合計 45 件の要素の実行と 5 件のエラー。
  • 45 は [15 日間以上] のパスを実行し、そのうち 10 はアクション要素でエラーが発生します。合計で 30 個の要素の実行と 10 個のエラーになります。
  • 40 はデフォルトの結果パスを実行しますが、決定要素でエラーが発生した要素は 5 つあり、合計で 40 要素の実行と 5 つのエラーがあります。

この例では、フロー全体の要素エラー率は 115 要素の実行で 20 件のエラー (17%) です。このパーセントは、[要素エラー率] 項目に表示される数値です。

使用する自動化機能の決定

  2. 事前作成済みコネクタがなく、API があるシステムと通信するには、[設定] で接続を作成し、HTTP コールアウトを作成します。または、HTTP プロトコルを使用する単純な接続の場合は、HTTP コールアウトアクションを使用します。詳細は、「HTTP コールアウトを使用したコネクタなしの API への接続」を参照してください。
  3. API のないシステムでは、MuleSoft RPA を使用して、グラフィカルユーザーインターフェースを介してデスクトップまたは Web アプリケーションを操作します。詳細は、「フローでの既存の MuleSoft RPA プロセスの使用」を参照してください。

完了するフローのアクションの特定

フローを開始するタイミングを決定したら、次のステップは、フローがトリガーされた後に何を実行するかをフローに指示することです。フローで実行する必要のある特定のアクションを判断するには、特定したソリューションを使用します。

  • ユーザーが何かを忘れた場合、ToDo レコードを作成してユーザーに通知します。
  • ユーザーが ToDo を完了する時間がない場合は、別のレコードの項目値を使用してレコードを自動的に更新または作成します。
  • データ入力が多すぎたり、入力ミスがあった場合は、顧客にオンラインフォームに自分の情報を入力してもらいます。
  • 顧客を把握できなくなった場合は、レコード所有者がフォローアップする ToDo レコードを作成します。または、一定時間後に優先度の高いケースレコードを作成します。

次の手順を示されている順序で実行して自動化システムを構築し、必要に応じて特定のビジネスニーズに合わせて変更します。

  1. データモデルの作成
    コース情報、コースの提供、コース参加者を保存するカスタムオブジェクトを作成して、コース管理システムの基盤を構築します。適切に設計されたデータモデルにより、オートメーションで作業するデータ構造が適切になります。
  2. データ品質を改善するための保存前フローの作成
    コースの被招集者レコードを作成する前にデータ品質を検証してビジネスルールを適用する保存前レコードトリガーフローを作成します。このフローは、コース被招集者の作成方法に関係なく、無効なレコードをブロックし、ビジネスロジックに基づいて適切な状況を設定することで、重複登録を防止し、コース業務量を検証し、データの整合性を確保します。
  3. 保存後レコードトリガーフローの作成
    コースの被招集者レコードが保存された後に実行されるフローを作成します。これらのフローは、通知を処理し、関連レコードを更新し、レコードの作成または更新の成功に依存するビジネスプロセスを管理します。
  4. コースの被招集者を登録する画面フローの作成
    画面フローを使用して登録プロセスを合理化します。営業担当は画面フローを使用して、コース被招集者とコース提供に関するすべての関連情報を取得し、被招集者にサインアップすることができます。
  5. すべてのコース管理フローのテストと有効化
    コース管理システムの各フローをテストして、正しく動作することを確認します。フローを有効化します。
  6. 画面フローを起動するボタンの作成
    取引先オブジェクトにアクションボタンを作成します。営業担当は取引先レコードページのボタンをクリックして画面フローを開始し、その取引先から科目の被招集者を登録します。

新しいコース被招集者レコードが保存された後に実行されるレコードトリガーフローを作成します。コースの提供がフルになった場合は、コースの提供状況をフルに設定し、講師にメールを送信します。新しいコース被招集者にメール通知を送信します。

必要なエディション

データ品質を改善するための保存前フローの作成

コースの被招集者レコードを作成する前にデータ品質を検証してビジネスルールを適用する保存前レコードトリガーフローを作成します。このフローは、コース被招集者の作成方法に関係なく、無効なレコードをブロックし、ビジネスロジックに基づいて適切な状況を設定することで、重複登録を防止し、コース業務量を検証し、データの整合性を確保します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
メモ 「フローの管理」権限を持つ管理者である必要はありません。プロファイルまたは権限セットに追加するようにシステム管理者に依頼してください。

このサンプルフローは、「コース管理プロセスプロジェクトの自動化」の他のサンプルフローと連動します。

この保存前フローは、レコードの作成プロセス中に実行され、その後でコースの被招集者レコードがデータベースに保存されます。項目の迅速な更新のために最適化することで、フローは保存操作を代行受信し、作成時のデータを検証します。まず、取引先責任者とコース提供が同じレコードを照会して、同じコース被招集者レコードがすでに存在するかどうかを確認します。重複が見つかった場合、フローはカスタムエラーメッセージで保存をすぐにブロックし、不正なデータがシステムに入力されないようにします。レコードが一意の場合、フローは既存の出席者を数えて最大許容人数と比較することで、コースの提供業務量を確認します。この件数に基づいて、フローは新しい出席者の状況を自動的に [登録済み] または [待機リスト] に設定し、登録済みの出席者の確認コードを生成します。このアプローチにより、レコードの作成方法 (UI、API、データインポート、または画面フロー) に関係なくデータ検証が一貫して行われるようになり、無効なデータがデータベースに到達する前にビジネスルールが適用されます。

カスタムオブジェクトを作成および編集する 「アプリケーションのカスタマイズ」

このカスタムオブジェクトは、Automate a Course Management Process Project と連動します。

  1. オブジェクトマネージャを開く
    • [Setup (設定)] で [Object Manager (オブジェクトマネージャー)] をクリックします。
    • レコードまたはホームページで、[] をクリックして [設定] を選択し、[オブジェクトマネージャー] を選択します。
  2. 「コース」という名前のカスタムオブジェクトを作成します。
    1. [作成] をクリックし、[カスタムオブジェクト] をクリックします。
    2. [表示ラベル] に「コース」と入力し、[表示ラベル (複数形)] に「コース」と入力します。
    3. カスタムオブジェクトを保存する前に、 [オブジェクト作成オプション] で [カスタムオブジェクトの保存後に新規カスタムタブウィザードを起動] を選択します。
    4. [保存] をクリックします。
      [タブ] 画面が開きます。
    5. [タブのスタイル] で、虫眼鏡をクリックし、スタイルを選択します。
    6. デフォルト設定を使用し、新しいオブジェクトを保存できるようになるまで [次へ] をクリックします。
    7. [保存] をクリックします。
      オブジェクトマネージャーでオブジェクトが開きます。
  3. 「コース番号」という名前のコースオブジェクトに自動採番項目を追加します。
    1. [Fields and Relationships (フィールドとリレーション)] を選択し、[新規] をクリックします。
    2. [自動採番] を選択し、[次へ] をクリックします。
    3. [項目の表示ラベル] に「Course Number」 (コース番号) と入力します。
    4. [表示形式] に「CC-{000000」と入力します。
    5. [開始番号] に「1001」と入力します。
    6. デフォルト設定を使用し、フィールドを保存できるようになるまで [次へ] をクリックします。
    7. [保存 & 新規] をクリックします。
      新しいカスタム項目ウィンドウが開きます。
  4. [説明] という名前のテキスト項目をコースオブジェクトに追加します。
    1. [テキストエリア (ロング)] を選択し、[次へ] をクリックします。
    2. [項目の表示ラベル] に「説明」と入力します。
    3. デフォルト設定を使用し、フィールドを保存できるようになるまで [次へ] をクリックします。
    4. [保存 & 新規] をクリックします。
      新しいカスタム項目ウィンドウが開きます。
  5. [期間] という名前の数値項目をコースオブジェクトに追加します。
    1. [数値] を選択し、[次へ] をクリックします。
    2. [項目の表示ラベル] に「Duration」(期間) と入力します。
    3. [長さ] に「2」と入力します。
    4. デフォルト設定を使用し、フィールドを保存できるようになるまで [次へ] をクリックします。
    5. [保存 & 新規] をクリックします。
      新しいカスタム項目ウィンドウが開きます。
  6. [期間単位] という選択リスト項目をコースオブジェクトに追加します。
    1. [選択リスト] を選択し、[次へ] をクリックします。
    2. [項目の表示ラベル] に「Duration Unit」 (期間単位) と入力します。
    3. [値] で、[Enter values, with each value separated by a new line (各値を改行で区切って値を入力)] を選択します。
    4. テキスト ボックスに、時間と日の値を別々の行に入力します。
      会社の状況が異なる場合は、このステップで名前を変更し、期間を追加または削除します。
    5. デフォルト設定を使用し、フィールドを保存できるようになるまで [次へ] をクリックします。
    6. [保存 & 新規] をクリックします。
      新しいカスタム項目ウィンドウが開きます。
  7. [開始日] という名前の日付項目をコースオブジェクトに追加します。
    1. [日付] を選択し、[次へ] をクリックします。
    2. [項目の表示ラベル] に「開始日」と入力します。
    3. デフォルト設定を使用し、フィールドを保存できるようになるまで [次へ] をクリックします。
    4. [保存 & 新規] をクリックします。
      新しいカスタム項目ウィンドウが開きます。
  8. [状況] という名前の別の選択リスト項目をコースオブジェクトに追加します。
    1. [選択リスト] を選択し、[次へ] をクリックします。
    2. [項目ラベル] に「Status」と入力します。
    3. [値] で、[Enter values, with each value separated by a new line (各値を改行で区切って値を入力)] を選択します。
    4. テキスト ボックスに、[新規]、[ドラフト]、[待機中]、[スケジュール準備完了] の値を個別の行に入力します。
      会社で状況が異なる場合は、このステップで名前を変更し、状況を追加または削除します。
    5. デフォルト設定を使用し、フィールドを保存できるようになるまで [次へ] をクリックします。
    6. [保存] をクリックします。

保存後レコードトリガーフローの作成

コースの被招集者レコードが保存された後に実行されるフローを作成します。これらのフローは、通知を処理し、関連レコードを更新し、レコードの作成または更新の成功に依存するビジネスプロセスを管理します。

必要なエディション

サポートされているエディションを表示する。

これらのサンプルフローは、「コース管理プロセスプロジェクトの自動化」の他のサンプルフローと連動します。

保存後フローは、レコードがデータベースに正常に保存された後に実行されます。つまり、メールの送信、関連レコードの更新、外部プロセスのトリガーなど、既存のレコードに依存するアクションを安全に実行できます。データ検証に焦点を絞った保存前フローとは異なり、保存後フローはレコードの作成または変更の結果を処理します。このコース管理システムでは、2 つの保存後フローを作成します。1 つは確認メールの送信とコースの配信状況の更新のために新しいコース被招集者が作成されたときに実行するフローで、もう 1 つは待機リストの管理と関係者への通知のためにコース被招集者の状況が [キャンセル] に変更されたときに実行します。これらのフローはアクションと関連レコード用に最適化されており、トリガーレコードのデータがすでに検証され、データベースにコミットされていることを確認しながら、他のオブジェクトに対する DML 操作の実行、メールの送信、コールアウトの実行を行うことができます。

データモデルの作成

コース情報、コースの提供、コース参加者を保存するカスタムオブジェクトを作成して、コース管理システムの基盤を構築します。適切に設計されたデータモデルにより、オートメーションで作業するデータ構造が適切になります。

必要なエディション

サポートされているエディションを表示する。

これらのカスタムオブジェクトは、Automate a Course Management Process Project と連動します。

このデータモデルは階層構造を使用しており、コースオブジェクトには変更されない一般的なコース情報が保存され、コース配信オブジェクトは日付や場所などの詳細と共にコースの特定のスケジュール済みインスタンスを表し、コース被招集者オブジェクトは取引先責任者を特定のコース配信に接続します。この設計により、フローをインテリジェントに機能させることができます。たとえば、レコードトリガーフローでは、新しいコース被招集者が作成されたときにコース配信がいっぱいかどうかを自動的に確認し、コース配信状況を更新し、確認メールを適切な担当者に送信し、待機リストを管理できます。静的なコース情報をスケジュール済み配信と出席者登録から分離することで、自動化で同じコースの複数のセッションを処理し、各セッションの業務量を追跡し、出席者の登録方法に関係なくビジネスルールを一貫して適用できます。
