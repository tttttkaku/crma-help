Salesforce アプリケーションアクションへの Slack ダイレクトメッセージの送信

Slack 内のユーザーの Salesforce アプリケーションに、設定されたメッセージを送信します。

必要なエディション

サポートされているエディションを表示する。

Flow Builder で、[アクション] 要素をフローに追加します。[新規アクション] ウィンドウで、[Slack] を選択し、[Slack ダイレクトメッセージを Salesforce アプリケーションに送信] を選択します。

利用状況

このアクションを使用するには、まず Salesforce と Slack を接続し、[Slack to Everyone (Slack から全員にメッセージを送信)] の [Send a message to a person Workflow Builder (個人にメッセージを送信)] ステップを設定します。複数のメッセージを同時に送信することはできませんが、複数のメッセージをループすることはできます。

Slack チャンネル詳細の設定

入力パラメーター 説明
Slack ユーザー ID メッセージを送信する Slack ユーザー ID。[Look Up a Slack User Action (Slack ユーザー検索アクション)] を使用して ID を検索するか、ユーザープロファイルを開いて [Copy member ID (メンバー ID をコピー)] を選択します。
メッセージテキスト プレーンで書式設定されたテキスト。

出力値の保存

入力パラメーター 説明
メッセージ URL 送信された Slack メッセージへの一意のリンク
メッセージのタイムスタンプ 配信されたメッセージの日時

音声をテキストに変換アクション

音声ファイルをテキストに変換するには、[スピーチをテキストに変換] アクションをフローに追加します。

必要なエディション

サポートされているエディションを表示する。

Flow Builder で、[アクション] 要素をフローに追加します。[アクション] フィールドで、「スピーチをテキストに変換」を検索し、[スピーチをテキストに変換] を選択します。(Convert speech to text)

入力値の設定

項目 説明
コンテンツドキュメント ID 必須。Salesforce Files に保存されている音声ファイルの ID。この値は、文字起こしするファイルを表す ContentDocument オブジェクトの ContentDocumentId です。
トランスクリプトモデル 省略可能。音声をテキストに変換するために使用される文字起こしモデル。[Whisper V3 Turbo] または [ElevenLabs Scribe V2] を選択します。モデルを選択しない場合、Whisper V3 Turbo が使用されます。

出力値の保存

項目 説明
変換済みテキスト 音声入力から生成されるテキストトランスクリプト。

フローでこのアクションを使用して、Salesforce に保存されている音声ファイルをテキストに変換し、後続のフロー要素でトランスクリプトを使用します。

考慮事項

  • このアクションには 1 分あたりの呼び出し制限が適用されます。制限を超える要求は失敗します。
  • サポートされるオーディオファイルの最大サイズは 5 MB です。
  • このアクションでは、トランスクリプトが出力として返され、自動的に保存されません。
  • 処理時間は、音声の長さ、ファイルサイズ、音質、システム負荷、および選択した文字起こしモデルによって異なります。一般に、Whisper V3 Turbo は高速ですが、ElevenLabs Scribe V2 は予測可能な処理時間が少ない可能性があります。
  • 文字起こしの品質は言語によって異なる場合があります。サポートされる言語については、「生成 AI サポート言語」を参照してください。

アンケートセンチメント分析アクションの実行

アンケートの回答の基盤となるセンチメントに関するインサイトを取得します。

必要なエディション

サポートされているエディションを表示する。

Flow Builder で、[アクション] 要素をフローに追加します。[アクション] 項目に「センチメント」と入力し、[アンケートセンチメント分析を実行] を選択します。または、左側のナビゲーションで [アンケート] をクリックし、[アクション] 項目に「センチメント」と入力して [アンケートセンチメント分析を実行] を選択します。アクションの名前とアンケート受信者を定義します。

API からこのアクションにアクセスするには、performSurveySentimentAnalysis という名前を使用します。

入力値の設定

項目 説明
終了日 必須。参加者の回答が処理されてセンチメントに関するインサイトが取得される最終日付。
操作

必須。AI センチメント結果レコードに対して実行されるアクション。

  • 作成: アンケートの回答のセンチメント分析がまだ完了していなくて関連付けられた AI センチメント結果レコードがない場合、またはセンチメントを再度分析するには、作成操作を使用します。処理が完了すると、アンケートへの回答のセンチメントと [送信済み] 状況を使用して AI センチメント結果レコードが作成されます。
  • 更新: 更新操作を使用して、[ドラフト] 状況の AI センチメント結果レコードが関連付けられたアンケート回答を一括処理します。処理が完了すると、アンケートへの回答のセンチメントを使用して AI センチメント結果レコードが更新され、状況が [送信済み] に変更されます。
質問 ID 必須。センチメントに関するインサイトを取得する回答の質問の ID。
開始日 必須。参加者の回答が処理されてセンチメントに関するインサイトが取得される開始日付。
アンケート ID 必須。センチメントに関するインサイトを取得する回答の質問が含まれるアンケートの ID。

使用方法

実行時、インタビューのトランザクションが完了するまで、AI センチメント結果レコードは作成されません。トランザクションが完了すると、[完了] 状況の AI センチメント結果レコードが作成されます。

テキストを音声に変換アクション (ベータ)

[テキストを音声に変換] アクションをフローに追加して、テキストを音声に変換します。

必要なエディション

サポートされているエディションを表示する。

Flow Builder で、[アクション] 要素をフローに追加します。[アクション] フィールドで、「Convert Text to Speech」 (テキストを音声に変換) を検索し、[Convert Text to Speech] を選択します。

入力値の設定

項目 説明
入力テキスト 必須。音声に変換するテキスト。
音声速度 省略可能。生成された音声の再生速度。
音声の安定性 省略可能。生成された音声の安定度と一貫性。値が低いほど表情豊かな音声を生成でき、値が高いほど安定した音声出力を生成できます。
音声 ID 省略可能。音声の生成に使用される音声の識別子。
ファイル出力 省略可能。応答で音声を Base64 エンコードされた音声ではなくファイル出力として返すかどうかを指定します。デフォルトは false です。

出力値の保存

項目 説明
Converted Audio (変換済みオーディオ) 入力テキストから生成された音声で、Base64 エンコードされた出力として返されます。

フローでこのアクションを使用して、テキストを音声に変換します。デフォルトでは、出力は Base64 エンコード形式で返されます。必要に応じて、[ファイル出力] を true に設定して音声をファイル出力として返し、生成された音声を後続のフロー要素またはカスタム再生コンポーネントで使用できます。

考慮事項

  • このアクションでは、適用可能なレート カードに基づいて Digital Wallet を介して Flex Credits を消費します。
  • このアクションには 1 分あたりの呼び出し制限が適用されます。制限を超える要求は失敗します。
  • 呼び出し制限は 1 分あたり 100 要求です。
  • このアクションでは、Base64 でエンコードされた音声文字列が返され、生成された音声は自動的に再生または保存されません。
  • ファイル出力が true に設定されている場合、下流要素でファイル出力が適切に処理されるようにします。
  • 処理時間は、入力サイズとシステム負荷によって異なります。

Digital Walletアクション

Digital Walletで追跡されている製品と機能の使用状況を監視してアラートを出すアクションを実行します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition および Unlimited Edition

必要なユーザー権限については、Salesforce ヘルプの「Digital Wallet Permissions」を参照してください。

  • 消費を計算
    すべての消費カードの使用量を計算します。
  • 消費アラートの作成
    カードの消費が指定したしきい値以上になったときに、指定したユーザーに通知を送信します。
  • ライセンス利用アラートの作成
    ライセンス使用率が指定したしきい値以上になったときに、指定したユーザーに通知を送信します。
  • 商品制限アラートの作成
    商品制限稼働率が、設定されたしきい値のパーセント以上になったときにアラートを作成します。このアクションでは、指定されたしきい値に対して現在の使用状況を評価し、しきい値を超えた場合に使用状況アラートレコードを作成します。

消費を計算

すべての消費カードの使用量を計算します。

出力値を設定

項目 説明
カード アクションで計算された Digital Wallet 消費カードのリスト。各項目は、1 つの消費カードの利用状況、エンタイトルメント、関連するアラート データを含むsfdw__ConsumptionCardレコードです。このアクションでは、多数のカードに 0 が返されます。

利用状況

[Compute Consumption]を使用して、入力を渡すことなく、組織のすべてのDigital Wallet消費カードの現在の使用量を1つのステップで取得します。たとえば、フローで使用量を表示したり、使用量をしきい値と比較したり、値を別のアクションに渡したりできます。[消費アラートを作成] と組み合わせて消費を計算し、カードがしきい値を超えた場合にアラートを生成します。

関連項目:

  • オブジェクトリファレンス: TenantConsumptionAlert
  • Salesforce ヘルプ: 消費しきい値のアラートと通知の管理

消費アラートの作成

カードの消費が指定したしきい値以上になったときに、指定したユーザーに通知を送信します。

入力値の設定

項目 説明
アラートトリガー種別

必須。アラートをトリガーするしきい値の種別。

有効な値は ThresholdPercent または ThresholdUnits です。
アラートトリガー値 必須。超えたしきい値 (アラートトリガー種別に応じてパーセントまたは単位数)。
ビジネス環境種別

必須。使用をトリガーした組織の環境種別。

有効な値は Production または Sandbox です。
カード定義開発者名 必須。アラートを発生させる Digital Wallet 消費カードの開発者名。この名前は多くの場合、表示名とは異なります。カード定義開発者名を表示名に対応付ける方法については、Salesforce ヘルプの「特定のカードの消費しきい値の変更」を参照してください。
受信者 ID 通知される受信者のユーザー ID のリスト。最大 1000 件を渡すことができます。 [通知を送信] がtrueの場合は必須です。
通知の送信 省略可能。trueの場合、アラートの作成時に受信者に通知します。falseの場合、通知を送信せずにアラートを作成します。デフォルトは true です。
使用モデル

必須。契約の購入モデル。

有効な値は、 PrePurchased 、 PayGo 、 PreCommitted 、または Unlimited です。

出力値を設定

項目 説明
作成済み アラートが作成されたかどうか (true) を示します (false)。
メッセージ アラートが作成されなかった理由の説明。アラートが作成されると、この項目は空になります。

利用状況

[消費アラートを作成] を使用して、消費がしきい値以上になったときに消費カードの使用量アラートを記録し、必要に応じてユーザーに通知します。通常、[消費を計算] アクションの後には、各カードの利用状況を確認する決定要素が続き、しきい値を超えた場合に [消費アラートを作成] がコールされます。[Send Notification] を [true] に設定してユーザーに通知するRecipient IDsを指定するか、[false] に設定して通知を送信せずにアラートを記録します。アクションの実行後、アラートが記録されたことを確認するチェックIs Created。Message を使用して、その理由を処理または記録します。指定された消費カードでしきい値を超えていない場合、Is Created は false になります。たとえば、消費カードの使用量が 12% で、80% の消費アラートをトリガーしようとしたとします。

関連項目:

  • オブジェクトリファレンス: TenantConsumptionAlert
  • Salesforce ヘルプ: 消費しきい値のアラートと通知の管理

ライセンス利用アラートの作成

ライセンス使用率が指定したしきい値以上になったときに、指定したユーザーに通知を送信します。

入力値の設定

項目 説明
ライセンス名

必須。ライセンス名のリスト。これらの名前は、［Digital Wallet License Utilization］ タブに表示される名前と同じです。要求あたり最大 50 ライセンスを処理できます。
ライセンスの種類 必須。サポートされるライセンスの種類を示します。有効な値: UserLicense、PermissionSetLicense。
アラートトリガー種別 必須。トリガーされるアラートのタイプ: ThresholdPercent。
アラートトリガー値 必須。アラートをトリガーするThresholdPercent。

出力値を設定

項目 説明
メッセージ アラートが作成されなかった理由の説明、または作成されたアラートの数を示す成功メッセージ。
作成されたアラート ID 作成されたアラートのレコード ID のリスト。要求ごとに最大 50 件のアラートを処理できます。

利用状況

[Create License Utilization Alert (ライセンス利用アラートを作成)] を使用して、Salesforce 組織でのライセンス消費を積極的に監視します。このアクションにより、次のことができます。

  • ユーザーライセンスと権限セットライセンスの両方を監視します。
  • 使用量が指定したしきい値に達したときに自動アラートを設定します。
  • ライセンスがなくなる前に通知をトリガーすることで、ライセンス不足を回避します。
  • 1 つの要求で最大 50 個のライセンスを処理します。

関連項目:

  • オブジェクトリファレンス: TenantConsumptionAlert
  • Salesforce ヘルプ: ライセンス使用状況のしきい値のアラートと通知の管理

商品制限アラートの作成

商品制限稼働率が、設定されたしきい値のパーセント以上になったときにアラートを作成します。このアクションでは、指定されたしきい値に対して現在の使用状況を評価し、しきい値を超えた場合に使用状況アラートレコードを作成します。

入力値の設定

項目 説明
商品制限

必須。監視する商品制限開発者名のカンマ区切りリスト。1 つのアクションコールで複数の制限を監視できます。
利用しきい値 (%) 必須。アラートを作成するしきい値の割合のカンマ区切りリスト (0～100)。使用率がしきい値以上になると、アラートが作成されます。複数のしきい値を設定できます。デフォルトのしきい値は 80 と 100 です。

出力値を設定

項目 説明
作成されたアラート ID 作成された利用アラート (TenantConsumptionAlert) レコード ID のリスト。新しいアラートが作成されていない場合 (すべてのしきい値を下回る使用率、または超えたしきい値のアラートがすでに存在する)、配列は空です。
isSuccess アラートが作成されたかどうか (true) を示します (false)。
エラー アクションが失敗した場合のエラーオブジェクトの配列。各エラーには、エラーコードとメッセージが含まれます。

利用状況

このアクションは、Salesforce フローで使用するように設計されており、商品制限を自動的に監視し、しきい値を超えた場合にアラートを作成します。

アラートの動作:

  • アラートのトリガー値には、実際の使用状況値ではなく、超えたしきい値が含まれます。
  • 1 つの評価で使用状況が複数のしきい値を超えた場合、超えたしきい値ごとに 1 つのアラートが作成されます。
  • 重複防止: 特定の制限としきい値の組み合わせに対して有効なアラートがすでに存在する場合、重複アラートは作成されません。
  • 自動クリア: 使用状況がしきい値を下回ると、対応する [有効] アラートが自動的に [クリア済み] とマークされ、今後しきい値を超えた場合にアラートを再度トリガーできます。
  • 各アラートは、アラート種別が PRODUCT_LIMIT、トリガー種別が THRESHOLD_PERCENT の使用状況アラート (TenantConsumptionAlert) レコードです。

関連項目:

  • オブジェクトリファレンス: TenantConsumptionAlert
  • Salesforce ヘルプ: 商品制限のアラートと通知の管理

注文アクションの有効化

B2B Commerce Checkout フローで、Salesforce 標準ドラフト注文を有効化します。

必要なエディション

使用可能なインターフェース: Lightning Experience

スコアリング設定

エンゲージメント モデルとして Einstein エンゲージメント スコアリングを選択した場合は、フローで各ユーザーのパスを決定するために使用される評価指標を選択します。

  • Open Likelihood (オープンの可能性): 顧客がメッセージを開く可能性に基づいてパスを選択します。
  • Click Likelihood (可能性をクリック): 顧客がメッセージのリンクをクリックする可能性に基づいてパスを選択します。
  • Unsubscribe Likelihood (購読取り消しの可能性): 顧客がリストから購読取り消しする可能性に基づいてパスを選択します。

次に、最大 4 つのパスを追加します。少なくとも 1 つのパスを追加する必要があります。

  • 可能性が最も高い: ユーザーがエンゲージする可能性が最も高い。たとえば、ユーザーがメール内のリンクをクリックする可能性が最も高いとします。
  • 可能性が高い: ユーザーがエンゲージする可能性は平均以上です。
  • 可能性が低い: ユーザーがエンゲージする可能性は平均以下です。
  • 可能性が最も低い: ユーザーがエンゲージする可能性が最も低い。

頻度設定

エンゲージメント モデルとして [Einstein Engagement Frequency (Einstein エンゲージメント頻度)] を選択した場合、最大 4 つのパスを追加できます。少なくとも 1 つのパスを追加する必要があります。

  • 過飽和: ユーザーが受信したメッセージが多すぎます。
  • ほぼ飽和：ユーザーが受信したメッセージが多すぎます。
  • On Target (対象): ユーザーが適切な数のメッセージを受信しました。
  • Overlooked (見逃された): ユーザーが受信したメッセージが少なすぎます。

パーソナライズ用のデータエクステンション。

トリガーされたメール送信に関連するデータの保存と管理に使用されるデータエクステンション。

利用状況

メールは [開始] 要素で設定されたスケジュールに基づいて送信されます。待機要素で区切られた複数の [Marketing Cloud Engagement メールを送信] 要素がある場合、待機条件が満たされるまでフローはメールを送信しません。

[モバイルアプリケーションメッセージを送信] マーケティングフロー要素

[モバイルアプリケーションメッセージを送信] アクション要素は、Salesforce CMS からアプリケーションのユーザーにプッシュ通知を送信します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Marketing Cloud Growth Edition または Advanced Edition が付属する Enterprise Edition および Unlimited Edition
使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition」を参照してください。

入力値の設定

セグメントは、キャンペーンレコード、またはフローの開始要素から選択します。プッシュ通知メッセージのコンテンツは、マーケティングコンテンツワークスペースでカスタマイズできます。
