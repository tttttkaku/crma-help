Winter '27 (API バージョン 68.0)

これらの更新は、API バージョン 68.0 以降で実行するように設定されているフローにのみ影響します。

必要なエディション

サポートされているエディションを表示する。

フローの実行方法に関係なくユーザー権限を適用

Flow Builder の新しい実行コンテキストオプションにより、フローの実行内容に関係なく、フローは常に実行ユーザーのアクセスレベルで実行されます。[ユーザーコンテキスト – ユーザー権限を適用] オプションは、画面フローと自動起動フローで使用できます。

以前は、ユーザーコンテキストで実行するように設定されたフローは、別のフロー、Apex、または別の自動化に関係なく、通話者から高度なシステムレベルの権限を継承していました。システムコンテキストで実行している通話者がユーザーコンテキストで設定されたフローを実行すると、ユーザーコンテキストで設定されたフローは通話者の高度な権限を継承し、システムコンテキストでも実行されます。

[ユーザーコンテキスト – ユーザー権限を適用] オプションを使用すると、このオプションを使用して設定されたフローは常にユーザーレベルのアクセス権で実行されるため、予測可能なセキュリティ境界とフローのアクセスレベルを完全に制御できます。

有効化前のフローのテスト

有効化する前にフローをテストして、エラーを検出し、すべてのパスを検証し、データの問題を回避します。フロー種別に応じて、テストモードまたは Flow Builder デバッガーを使用して、サンプルデータでさまざまなシナリオをテストします。

必要なエディション

サポートされているエディションを表示する。

デバッガでのフローのテスト

レコードトリガーフローと自動起動フローを除くすべてのフロー種別で、Flow Builder のデバッグ機能を使用してフローを有効化する前にテストします。デバッガーには、フローの実行方法がステップバイステップで表示されます。デバッガーでは、フローが辿るパスと、フロー内でリソース値がどのように変化するかを確認できます。フローで問題が発生した場合、問題の場所を正確に確認できるため、問題を修正できます。生成 AI を使用してエラーを診断し、自動的に修正を適用するには、「Troubleshoot Flow Errors with Agentforce (Beta)」を参照してください。詳細は、「Flow Builder デバッガを使用したフローのテストまたはトラブルシューティング」および「テンプレートトリガープロンプトフローのデバッグ」を参照してください。

テストモードでのフローのテスト

自動起動フローとレコードトリガーフローの場合、テストモードを使用してフローをテストします。テストモードでは、トリガーレコードまたは入力値を使用してテストシナリオを設定し、シナリオを保存して再利用できます。テストモードについての詳細は、「テストモードでのフローのテスト (ベータ)」を参照してください。

必要に応じて、自動テストを使用して、期待される結果を自動的に評価できます。テストモードで自動テストを使用するには、[シナリオテストの自動化] を有効にしてアサーションを追加します。シナリオテストの自動化が有効になっている場合、分離されたテストデータを使用することもできます。詳細は、「自動フローテスト」を参照してください。

Data Cloud トリガーフローの自動テスト

Data Cloud トリガーフローの場合、フローを有効化する前に、自動フローテストを使用して予期される結果を確認し、ランタイムエラーを特定します。詳細は、「自動フローテスト」を参照してください。

別のユーザーとしてのフローのデバッグとテスト

組織全体の設定を有効にして、システム管理者が Flow Builder デバッガーを使用してフローをデバッグしたり、テストシナリオを自分自身ではなく特定のユーザーとして実行したりできるようにします。詳細は、「別のユーザーとしてのフローのデバッグおよびテストの有効化」を参照してください。

サンプルデータの使用

誤ってレコードを変更したり、実際の顧客にテストメールを送信したりしないように、初期テスト時に実際のデータを使用しないようにします。ライブデータに影響を与えることなく、実際のシナリオを模倣したテストレコードを作成します。

たとえば、フローで取引先責任者レコードを更新する場合、フローをテストする前にいくつかのサンプル取引先責任者レコードを作成し、それらのレコードを使用してフローをテストします。リードレコードの作成時にフローを実行する場合、テストするときは、実際のリードではなくテストリードを作成していることを確認してください。

フローでメールを送信する場合は、テストメールが組織の実在するユーザーではなく、いずれかのメールアドレスに送信されることを確認します。

さまざまなシナリオのテスト

さまざまな入力と条件に基づいてフローがたどる可能性のあるすべてのパスを考慮します。シナリオごとにさまざまな入力と潜在的なエッジケースを検討します。たとえば、フローで特定の条件に基づいてレコードを更新する場合、その条件を満たすテストケースと満たさないテストケースを作成します。テストする最も重要な事項を次に示します。

  • Path Coverage (パスカバー率): 考えられるすべてのパスをテストします。たとえば、フローに [決定] 要素がある場合、デフォルトパスも含めて各結果をテストします。
  • 境界条件: 最小値、最大値、および予期しない値を使用してテストします。
  • エラー処理: 障害パスとエラーメッセージが意図したとおりに動作することを確認します。
  • 権限とアクセス: 異なるユーザーとしてテストし、すべてのユーザーにフローを正常に実行するための権限とデータアクセス権があることを確認します。

Sandbox の使用

データを誤って変更することなく、必要なだけテストできるように Sandbox でテストすることをお勧めします。Sandbox の作成方法については、「Sandbox の作成」を参照してください。

自動フローテストの制限

Flow Builder のテストモードでテストするか、Data Cloud トリガーフローを使用してテストするかに関係なく、自動的に評価されるフローテストシナリオの制限と制約を理解します。

必要なエディション

サポートされているエディションを表示する。

制限

フローあたりのテストの最大数は 200 です。

制限事項

  • フローテストは、レコードトリガーフロー、自動起動フロー、および Data Cloud トリガーフローで使用できます。
  • 分離されたテストデータは、レコードトリガーフローと自動起動フローで使用できます。
  • 自動起動フローの自動フローテストシナリオでは、待機要素はサポートされていません。疑似出力を使用して、ライブ実行をシミュレートするアクション要素とサブフロー要素をテストします。
  • テストモードでは、レコードの削除時にトリガーされるレコードトリガーフローのシナリオテストの自動化が無効になっています。これらのフローでは、手動で評価したテストシナリオのみがサポートされます。
  • 自動フローテストシナリオでは、非同期で実行されるフローパスはサポートされません。
  • 自動化されたフローテストシナリオは、フローテストカバー率の要件に含まれます。手動テストシナリオにはありません。
  • Apex テストは、フロー テスト カバレッジの計算に含まれません。
  • テストモード: Apex で定義された変数は、自動起動フローの入力値ではサポートされません。
  • テストデータの設定では数式はサポートされていません。固定値を使用します。たとえば、日付フィールドが相対日付Todayと等しいことを確認するには、固定値を入力します。2022 年 8 月 3 日にテストシナリオを作成して実行すると、日付項目の値は 2022 年 8 月 3 日に設定されます。 それ以降に同じテストシナリオを実行すると、値は 2022 年 8 月 3 日のままになります。

Flow Builder デバッガの考慮事項

Flow Builder でフローをデバッグするときは、次の考慮事項に従ってください。

必要なエディション

サポートされているエディションを表示する。
警告 [レコードを削除] 要素を含むフローをデバッグすると、フローが無効な場合でも削除操作がトリガーされます。

フローのデバッグ

  • ロールバック モードを選択せずにフローをデバッグすると、データ操作言語 （DML） 操作や Apex コード実行などのアクションが実行されます。実行中のフローを閉じても再起動しても、フローがすでにデータベースにコミットしているアクション、コールアウト、変更はロールバックされません。
  • コレクション、レコード、またはレコードコレクション種別の入力変数の値を指定することはできません。
  • [一時停止] を選択するか、待機要素を実行すると、フローが閉じてデバッグが終了します。
  • 別のユーザーとしてフローをデバッグすると、フローはレコードを変更し、そのユーザーとしてアクションを実行します。ユーザーのプロファイルと権限セットによって、フローのオブジェクト権限と項目レベルのアクセス権が決まります。常にシステムコンテキストで実行されるフローでは、ユーザーのオブジェクト権限と項目レベルのアクセス権は無視されます。
  • フローで [完了] を選択すると、デバッグの詳細に「選択されたナビゲーションボタン: 次へ」と誤って表示されます。
  • スケジュールトリガーフローをデバッグする場合、フローは 1 つのレコードに対してのみ開始されます。
  • レコードトリガーフローは常にロールバックモードで実行されます。デバッグでは、フロー内のもののみがテストされます。その他のトリガーされたフローおよびプロセスでは、デバッグ中にフローが意図したとおりに実行される可能性がありますが、実行時には実行されません。実際のシナリオでレコードトリガーフローがどのように動作するかを確認するには、Sandbox で debug の外部でフローを実行し、デバッグログを使用して問題をトラブルシューティングします。
  • [レコードを作成]、[レコードを更新]、または [レコードを削除] 要素を含むセグメントフローをデバッグする場合は、[ロールバックモードで自動化を実行] を選択します。メッセージングアクション以外の呼び出し可能なアクション (メール、SMS、WhatsApp メッセージを送信するアクションなど) がフローに含まれる場合、ロールバックモードを選択します。ロールバックモードをクリアすると、Flow Builder でフローをデバッグできなくなります。デバッグでサポートされていない要素がフローに含まれているというエラーが表示されます。詳細は、「セグメントフロー」を参照してください。
  • 画面アクションの自動起動フローの実行中に新しいフロートランザクションが開始されると、自動起動フローは失敗します。
  • レコードトリガーフローをデバッグする場合、レコード詳細コンポーネントによって編集可能な項目が決まります。

フローの配布

フローの設計とテストが完了したら、フローを実行しましょう!フローは、フローの設計対象に応じていくつかの方法で実行できます。内部ユーザー、外部ユーザー、またはシステムがフローを実行できます。また、フローを別の組織にリリースすることもできます。

フローの配布には 3 つのフェーズがあります。

  1. 概念を確認します。配布する前に、ユーザーアクセス、セキュリティ、データコンテキスト、ランタイム環境がフローの動作にどのように影響するかを理解します。「フロー配布の概念」を参照してください。
  2. フローを有効化します。ユーザーは有効なフローバージョンのみを実行できます。「フローの有効化または無効化」を参照してください。
  3. 配信方法を選択します。フローを使用可能にする方法は、誰がどこからフローを実行するかによって異なります。
    フローの実行者は? 目的
    組織の内部ユーザー カスタム アクション、Lightningページ、ユーティリティ バー、URLボタン、Auraコンポーネント、またはVisualforceページにフローを追加します。「組織内のユーザーへのフローの配布」を参照してください。
    組織外の外部ユーザー フローをエクスペリエンスビルダーサイト、組み込みサービスリリース、または Visualforce ページに追加します。「組織外のユーザーへのフローの配布」を参照してください。
    自動化システム ApexまたはREST APIを使用して、ユーザー操作なしでフローをトリガーします。「Distribute Flows to Automated Systems (自動化システムへのフローの配布)」を参照してください。
    別の組織のユーザー Lightning Bolt Solution、変更セット、または管理パッケージにフローをパッケージ化します。「Distribute Flows to Other Orgs (他の組織へのフローの配布)」を参照してください。

フローの実行ユーザー

フローの実行ユーザーは、フローを起動したユーザーです。実行ユーザーによって、ユーザーコンテキストで実行されるフローが Salesforce データを使用してできることが決まります。

ユーザーコンテキストで実行されるフローの場合、実行ユーザーのプロファイルおよび権限セットによって、フローのオブジェクト権限および項目レベルのアクセス権が決まります。フローで Salesforce データを作成、参照、編集、または削除しようとすると、実行ユーザーの権限と項目レベルのアクセス権が適用されます。たとえば、実行ユーザーに取引先オブジェクトの編集権限がない場合、フローが取引先レコードを更新しようとすると、エラーが発生します。

組織の共有設定、ロール階層、共有ルール、共有の直接設定、チーム、テリトリーも、ユーザーコンテキストで実行されるフローがアクセスできるデータに影響します。商談オブジェクトの組織の共有設定が非公開で、商談レコードが実行ユーザーと共有されていない場合、フローはどの商談レコードも参照および編集できません。

デフォルトでは、ユーザ コンテキストのフローは、別のフローや Apex などのシステム コンテキストのコール元から昇格した権限を継承できます。システムコンテキストで実行されている通話者がユーザーコンテキストフローを呼び出すと、フローもシステムコンテキストで実行されます。呼び出し元に関係なく、常に実行ユーザーのアクセスレベルでフローが実行されるようにするには、フローバージョンのプロパティで [ユーザーコンテキスト – ユーザー権限を適用] を選択します。このオプションは、API バージョン 68.0 以降の画面フローおよび自動起動フローで使用できます。「フロー実行コンテキストの設定」を参照してください。

制限事項

  • 画面コンポーネントやローカルアクションなどの Lightning コンポーネントは、常にユーザーコンテキストで実行されます。
  • コンテキストがコードに依存する場合、Apex では with sharing および without sharing キーワードを使用して、組織のデフォルト設定、ロール階層、共有ルール、共有の直接設定、チーム、テリトリーを適用するかどうかを指定します。
  • Apex によってコールされるフローは、常にオブジェクトおよび項目レベルのアクセス権を無視します。
  • レコードトリガーフロー、スケジュールトリガーフロー、またはプロセスで、継承された共有が含まれるクラスから Apex 呼び出し可能メソッドを呼び出すと、呼び出し可能メソッドが共有ありのシステムコンテキストで実行されます。フローおよびプロセスは共有なしのシステムコンテキストで実行されます。
  • プロセスがフローの起動をトリガーする場合、プロセスをトリガーしたユーザーに他の権限が必要な場合があります。たとえば、権限セットライセンスの割り当てを保存しようとするフローがプロセスで起動され、実行ユーザーに「権限セットの割り当て」権限がない場合、エラーが発生します。
  • フローは、[Chatter に投稿] アクションを実行するときに常にユーザ コンテキストで実行されます。
  • 標準ユーザーコンテキストオプションによって、フローが別のフローや Apex などのシステムコンテキストコール元から昇格した権限を継承することは妨げられません。通話者に関係なくユーザーレベルのアクセス権を適用するには、[ユーザーコンテキスト – ユーザー権限を適用] オプションを使用します。このオプションには API バージョン 68.0 以降が必要で、画面フローと自動起動フローでのみ使用できます。

  • システムコンテキストでの画面および自動起動フロー実行時のデータの安全性

画面フローでのデータへのユーザーアクセスの制限

データへのユーザーアクセスを制限する権限が適用されるため、可能な限りユーザーコンテキストで画面フローを実行します。システムコンテキスト (特に共有のないシステムコンテキスト) で画面フローを実行すると、ユーザーに権限が適用されないため、意図しないデータ共有が発生する可能性が高くなります。システムコンテキストでフローを実行するよりも、ユーザーにアクセス権を付与する安全な方法があります。

画面フロー全体をシステムコンテキストで実行するように設定する代わりに、サブフロー要素を使用して、実行ユーザーが持っている権限以外の権限を必要とするアクションを実行するフローを起動します。

画面フローまたは自動起動フローで、システムコンテキストコール元から昇格した権限を継承しないようにするには、フローバージョンのプロパティで [ユーザーコンテキスト – ユーザー権限を適用] を選択します。このオプションにより、フローを呼び出す内容に関係なく、フローを常に実行ユーザーのアクセスレベルで実行できます。フローを再構築する必要はありません。API バージョン 68.0 以降の画面フローおよび自動起動フローで使用できます。

例 実行ユーザーが持っていない権限を必要とする画面フローの一部として、権限セットをユーザーに割り当てます。システムコンテキストで実行され、権限セットをユーザーに割り当てるトリガーのない自動起動フローを作成します。次に、ユーザーコンテキストで実行されている画面フローを作成し、自動起動フローを起動するサブフロー要素を追加します。

[レコードを取得] 要素の特定の項目の保存

自動起動フロー（トリガーなし）または画面フローをシステムコンテキストで実行するように上書きし、[レコードを取得] 要素を使用してレコードを画面コンポーネント、アクション、または別のフローに渡す場合は、[項目を選択して後は Salesforce に任せる] を選択して保存する項目を指定し、[すべての項目を自動的に保存] を選択しないでください。[レコードを取得] 要素から画面コンポーネント、アクション、または別のフローにレコード変数またはレコードコレクション全体を渡す場合、フローではどの項目が必要かがわからないため、ユーザーがアクセスできるすべての項目が取得されます。[項目を選択して後は Salesforce に任せる] を選択して項目を指定すると、Salesforce は必要な項目のみを保存するため、ユーザーに表示される項目数が減ります。

例 画面フローでは、データテーブルコンポーネントで使用されるレコードコレクションのレコードを取得します。関連付けられた [レコードを取得] 要素では、データテーブルコンポーネントに表示する項目、または画面の別の場所で参照する項目のみを保存します。

カスタムメタデータ型およびカスタム設定での機密データの保護

フローは、実行ユーザーの権限に関係なく、公開カスタムメタデータ型とカスタム設定を参照できます。API バージョン 64.0 以降で実行されるフローでは、[レコードを取得] 要素で取得されるカスタムメタデータ型レコードおよびカスタム設定レコードの項目が画面に表示されることがあります。実行ユーザーがこれらの項目へのアクセス権を持っていない場合でも、画面にはこれらの項目が表示されます。

重要 画面フローで取得する公開カスタムメタデータ型またはカスタム設定に機密情報を保存しないでください。

Experience Cloud サイトのフローでの項目とレコードの指定

Experience Cloud サイトの画面フローでシステムコンテキストで実行し、[レコードを作成]、[レコードを更新]、または [レコードを削除] 要素を使用する場合は、項目とレコードの数をユーザーによる編集が意図されるもののみに制限します。

  • [レコードを作成] 要素では、[レコード項目値の設定方法] で [手動] を選択し、レコードの作成時に使用する各項目を指定します。
  • [レコードを更新] 要素では、[更新するレコードを検索してその値を設定する方法] で [レコードを識別する条件を指定し、項目を個別に設定] を選択します。検索条件を使用して更新するレコードを検索し、更新するフィールドを指定します。
  • [レコードを削除] 要素では、[削除するレコードを検索する方法] で [条件を指定] を選択し、検索条件を使用して削除するレコードを検索します。

[レコードを作成]、[レコードを更新]、または [レコードを削除] 要素でレコード変数またはレコードコレクションを使用する場合は、最初に [変換] 要素を使用して、編集しない項目を除外します。「フローのデータの変換」を参照してください。次に、[レコードを作成]、[レコードを更新]、または [レコードを削除] 要素で、[変換] 要素で生成するレコード変数またはレコードコレクションを選択します。

画面アクションの実行に関する考慮事項

アクションボタンコンポーネントを使用して画面アクションをトリガーする場合、または入力値の変更に基づいて画面アクションを自動的にトリガーする場合は、次の考慮事項に留意してください。

  • 画面アクションによってコールされる自動起動フローのフロー実行コンテキストを確認します。自動起動フローは、画面フローとは異なるコンテキストで実行される可能性があり、必要以上のデータが公開される可能性があります。自動起動フローをユーザーコンテキストで実行し続けることを検討してください。自動起動フローをシステムコンテキストで実行する必要がある場合は、「Restrict User Access to Data in Screen Flows (画面フローのデータへのユーザーアクセスの制限)」、「Store Specific Fields in Get Records Elements (レコード取得要素の特定の項目の保存)」、「Specify Fields and Records in Flows on Experience Cloud Sites (Experience Cloud サイトのフローでの項目とレコードの指定)」セクションの提案を使用してフローを変更し、データを保護します。
  • 画面アクションによってコールされる自動起動フローは、データの検索または計算の実行にのみ使用します。レコードを作成、更新、または削除するには、画面フローで [レコードを作成]、[レコードを更新]、または [レコードを削除] 要素を使用するか、サブフロー要素によって起動される別のフローを使用します。
  • 画面アクションが設定されている画面要素でのみ画面アクションを参照します。画面アクションの出力をフローの別の場所で参照するには、サブフロー要素で画面アクションの自動起動フローを再度実行し、代わりにサブフロー要素の出力を参照します。

システムコンテキストで実行されているサブフロー要素によって起動されるフローの入力と出力の確認

システムコンテキストで実行されているサブフロー要素によって起動されるフローを設定する場合は、次のガイドラインに従ってください。

  • 参照されるフローを起動するフローで変数を使用する場合にのみ、変数を入力および出力で使用できるようにします。未使用の入力変数と出力変数は、ユーザーに不要なデータを示す可能性があります。
  • 推測しやすい入力を参照先のフローに渡さないでください。たとえば、レコードの会社のメールアドレスを渡す場合、会社のメールアドレスが firstname.lastname@company.com のパターンに従うと、別のレコードのメールアドレスを推測してその別のレコードにアクセスすることが簡単にできます。
  • 参照されるフローには、起動したフローで直接使用される出力値のみが含まれていることを確認します。たとえば、連絡先レコードの誕生日のコレクションのみが必要な場合は、連絡先や連絡先のアカウントに関するすべての情報を返すことはしないでください。

外部ユーザー用の Visualforce ページへのフローの埋め込み

フローを Visualforce ページに追加し、そのページを外部に配布して、外部ユーザーがフローを実行できるようにします。たとえば、コミュニティを介して配布します。

必要なエディション

必要なユーザー権限
Visualforce ページを作成、編集、および設定する 「アプリケーションのカスタマイズ」

たとえば、訪問者がカスタム売上見積を生成できるように公開 Salesforce サイト用のセルフサービスツールを設定できます。フローは Visualforce ページに埋め込まれるため、会社のブランドとスタイルを使用するようにフローの外観をカスタマイズできます。

メモ サイトまたはポータルユーザーがフローを使用できるようにするには、フロー自体ではなく、埋め込みフローを含む Visualforce ページを参照するようにします。サイトおよびポータルユーザーがフローを直接実行することはできません。

フローを Visualforce ページに追加するには、<flow:interview> コンポーネントを使用してフローを埋め込みます。

  1. フローの API 参照名を検索します。
    1. [設定] から、[クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
    2. フローの名前をクリックします。
    3. フローの API 参照名をコピーします。
  2. [設定] から、[クイック検索] ボックスに「Visualforce ページ」と入力し、[Visualforce ページ] を選択します。
  3. 新しい Visualforce ページを定義するか、既存の Visualforce ページを開きます。
  4. <flow:interview> コンポーネントを <apex:page> タグ間の任意の場所に追加します。
  5. name 属性をフローの API 参照名に設定します。

    次に例を示します。

    <apex:page>
<flow:interview name="flowAPIName"/>
</apex:page>
    管理パッケージのフローである場合、name 属性は namespace.flowuniquename の形式で指定する必要があります。
  6. [保存] をクリックします。
  7. Visualforce アプリケーションにアクセスできるユーザーを制限します。
    Visualforce ページへのアクセス権を持つすべての外部ユーザーが埋め込みフローを実行できます。
    1. [Visualforce ページ] をクリックします。
    2. Visualforce ページの横にある [セキュリティ] をクリックします。
    3. 追加または削除ボタンを使用して、すべての適切なプロファイルを [選択可能なプロファイル] から [有効にされたプロファイル] に移動します。
    4. [保存] をクリックします。
  8. Visualforce ページを配布するには、Visualforce ページを Salesforce サイトに追加します。または、Visualforce ページを使用してカスタム Visualforce タブを定義し、そのタブをポータルまたはコミュニティに追加します。

必要なエディション

サポートされているエディションを表示する。
  • ボタンを使用したフローの開始
    ボタンからフローを開始する方法はいくつかあります。ボタンの種類によって、開始できるフローの種類、ユーザーに表示されるボタンの場所、フローに送信できる変数値が決まります。

    Lightning Experience または Salesforce アプリケーションユーザーに画面フローを簡単に配布するには、Lightning ページに埋め込みます。
  • レコードページへのフローリンクの追加
    有効な画面フローまたは自動起動フローを開始するカスタムリンクをレコードページに追加します。フローの Web アドレス (URL) を使用してリンクを設定します。
  • アクション & おすすめコンポーネントへのフローの追加
    Lightning コンソールアプリケーションまたは標準のナビゲーションアプリケーションでユーザーがフローに従って複雑なビジネスプロセスを実行できるようにしますか?RecordAction オブジェクトを作成するプロセスを使用するか、アクション & おすすめリリースを作成して、フローをレコードに関連付けます。次に、Lightning アプリケーションビルダーを使用して、アクション & おすすめコンポーネントを Lightning ページに追加します。
  • 組織のナビゲーションタブへの画面フローの埋め込み
    フローの Web アドレス (URL) を使用して、有効な画面フローを組織のナビゲーションタブに追加します。ユーザーはタブを開き、そこから画面フローを実行できます。
  • ユーティリティバーへのフローの追加
    アプリケーションのどのページからもフローにアクセスできるようにしますか?Lightning アプリケーションのユーティリティバーにフローを追加してください。ユーティリティバーでは、ユーザーがよく使用するツールにすばやくアクセスできます。
  • URL の共有によるフローの配布
    Web アドレス (URL) を共有して、画面フローまたは自動起動フローを配布します。
  • URL を使用してフローを起動するための追加オプション
    フローの Web アドレス (URL) を使用してフローを共有している場合、フローの終了時の動作をカスタマイズしたり、URL で変数値をフローに送信したりできます。
  • カスタム Aura コンポーネントへのフローの埋め込み
    フローでデータを取得および受信する方法をカスタマイズするには、フローをカスタム Aura コンポーネントに追加します。次にそのコンポーネントをカスタムアクション、Lightning タブ、または Lightning ページを介して配布します。
  • Visualforce ページへのフローの埋め込み
    内部ユーザー用にフローのデザインをカスタマイズするには、フローを Visualforce ページに追加します。次にそのページを Visualforce タブ、カスタムボタン、またはカスタムリンクを介して配布します。
  • 組織での一時停止中のフローインタビューの準備
    フローインタビューは、フローの実行中のインスタンスです。すべてのフローインタビューが 1 回で完了するわけではありません。フローに [一時停止] ボタンを追加して、ユーザーがフローインタビューを一時停止して後で再開できるようにします。また、フローインタビューの共有モデルを更新して、他のユーザーが一時停止中のインタビューを再開できるようにします。さらに、コンポーネントを [ホーム] ページに追加して、ユーザーがインタビューを簡単に再開できるようにします。

画面フローの作成

ユーザーから情報を収集する画面フローを作成します。

  1. [フロー] リストビューを開きます。

    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。

  2. 画面フローを作成します。
    • 自動化アプリケーションで、[新規 | 画面の自動化 | 画面フロー] の順にクリックします。
    • [設定] から、 [ 新規フロ | ー画面] [オートメーション | 画面フロー]をクリックします。
  3. 必要に応じて、ユーザーがボタンをクリックしたレコードページのレコード ID またはレコード全体を保持する変数を作成します。
    フローに recordId という名前の変数がある場合、クイックアクションによってレコード ID またはレコード全体がフローに自動的に送信されます。フロー内でユーザーがボタンをクリックしたレコードを参照する場合は、recordId 変数を作成します。たとえば、クイックアクションボタンが取引先責任者レコードページにあり、フローで取引先責任者にメールを送信する場合、フローで誰にメールを送信すべきかわかるように取引先責任者のレコードをフローに提供する必要があります。
    1. をクリックしてツールボックスを開きます。
    2. [新規リソース] をクリックします。
    3. [リソース種別] で、[変数] を選択します。
    4. [API 参照名] に「recordId」と入力します。
      変数 API 参照名は、レコードページからフローに送信されるレコード ID またはレコード全体で、この名前と完全に一致する必要があります。
    5. データ型とオブジェクトを設定します。

      レコード全体をフローに送信するには、[データ型] で [レコード] を選択し、[オブジェクト] でレコードのオブジェクトを選択します。

Lightning または非 Lightning フロー URL 形式の選択

URL から画面フローを実行する場合、Lightning を使用するか、Lightning Out を使用する非 Lightning URL 形式を選択できます。より高速で一貫性のある環境を実現するには、Lightningを使用することをお勧めします。ただし、Lightning 以外の形式を使用する必要がある場合があります。

必要なエディション

サポートされているエディションを表示する。

ボタンやリンクなどの URL を使用して画面フローを配信する場合、フローの実行方法には 2 つのオプションがあります。

  • フロー URL の先頭に/lightningを追加します。たとえば、/lightning/flow/My_Flow です。フローは Lightning Experience 内で実行されます。
  • /lightningなしでフロー URL を使用します。たとえば、/flow/My_Flow です。フローは Lightning Out を使用して実行されます。

Lightning でフローを実行するといくつかのメリットがあるため、フロー URL に/lightningを追加することをお勧めします。

パフォーマンスの向上

Lightning でフローを実行すると、必要なコンポーネントのほとんどはすでにブラウザに読み込まれています。この設定により、ページ全体を読み込む必要がなくなるため、フロー画面の読み込み時間が短縮されます。

ユーザーを現在の状況に保つ

Lightning でフローを実行すると、ユーザーは Salesforce 内での位置を維持できます。たとえば、Lightning コンソールで作業しているユーザーは、フローの実行中に既存のタブを開いたままにできます。ユーザーは、フローの実行中にLightningコンソールの他のタブに切り替えることもできます。これは、ケースまたはチケットで作業していて、他の詳細を参照する必要がある場合に役立ちます。

Lightning を使用しない場合、ユーザーが現在のページから移動すると、ワークフローが中断される可能性があります。

ブラウザーナビゲーションの問題の回避

フローが Lightning で実行されている場合、ブラウザの履歴状態が破壊されるリスクはありません。ユーザーは期待どおりに [戻る] ボタンと [進む] ボタンを使用できます。現在の Lightning アプリケーション以外のページに移動すると、ブラウザのナビゲーションで予期しない動作が発生する可能性があります。

Lightning Experience での一貫した動作

Lightning でフローを実行すると、フローの動作が Lightning Experience および Lightning コンソールの他の部分と一貫性が維持されます。フローは、組織のスタイル設定のデザインとも一致します。トースト通知を表示したり、同じウィンドウでレコードを開いたりするなど、画面フローでローカルアクションを使用することもできます。

Lightning Out の制限の回避

画面フローで標準画面コンポーネントを使用しており、Lightning で実行している場合は、フローの動作に影響する可能性がある Lightning Out の制限の影響を受ける可能性があります。Lighting Out の制限についての詳細は、『Lightning Web Components Developer Guide (Lightning Web コンポーネント開発者ガイド)』を参照してください。

Lightning を使用しないケース

URL に/lightningを追加できない場合があります。どちらの場合も、URL に /lightning または flow__ プレフィックスを含めないでください。

  • リストビューから ids というコレクション変数に ID のリストを送信する以外に、コレクション変数の項目の値を設定する。Lightning では、リスト ビューから ids コレクション変数への ID の送信がサポートされています。詳細は、「フローの URL を使用したフローへの変数値の送信」を参照してください。
  • ナビゲーションタブ (Web タブ) からフローを実行します。詳細は、「Embed a Screen Flow in a Navigation Tab in Your Org (組織のナビゲーションタブへの画面フローの埋め込み)」を参照してください。

完了動作を制御するようにフロー URL をカスタマイズ

デフォルトでは、ユーザーが画面フローを完了すると、画面フローによってユーザーは最初の画面にリダイレクトされます。ユーザーが [完了] をクリックしたら Salesforce 内の別のページにリダイレクトされるように設定するには、フロー URL に retURL パラメーターを使用します。

必要なエディション

サポートされているエディションを表示する。

形式

[完了] をクリックした後に画面フローのユーザーを Salesforce の特定のページにリダイレクトするには、次の形式を使用します。

/lightning/flow/flowName?retURL=url

URL は相対 URL です(https://MyDomainName.my.salesforce.com/ または https://MyDomainName.Lightning.Force.com/ の後の部分)。

メモ Lightning Experience を使用し、フロー URL の先頭に /Lightning を追加することをお勧めします。ただし、フロー URL に /Lightning を追加しない場合、フロー URL は引き続き機能しますが、Lightning で実行する新しい利点を得ることはできません。詳細は、「Choosing Between Lightning and Non-Lightning Flow URL Formats」を参照してください。

次に例を示します。

  1. カスタマイズする画面フローを作成または識別します。
  2. 最後の画面で [完了] をクリックした後のフローでのユーザーのリダイレクト先 URL を決定します。
  3. フロー URL に?retURL=urlを追加します。ここで、 url はリンク先ページの相対 URL です。
  4. 入力変数もフローに渡す場合は、変数パラメータの後に retURL パラメータを&で区切って追加します。例: /lightning/flow/MyFlow?flow__varCaseId=500xx000000abc&retURL=lightning/page/home
  5. 完全な URL をボタン、リンク、またはコンポーネントで retURL パラメーターと共に使用します。

  • URL でレコード ID (flow__varCaseId=500xx000000abc など) を渡す場合、動作はフローのフロー変数の型によって異なります。
    • テキスト変数の場合、Salesforce はレコード ID をテキスト文字列として渡します。フローは ID 値 (500xx000000abc など) を受け取ります。
    • レコード変数の場合、Salesforce はレコードオブジェクト全体を渡そうとします。ただし、URL でレコード ID を渡しても、自動的に完全なレコードが読み込まれるわけではありません。フローは ID を受け取りますが、フローで [レコードを取得] 要素を使用して、その ID に基づいて完全なレコードデータを取得します。
    • ID のみを渡すレコード変数で、指定されていないレコード項目が想定される場合、フローが失敗する可能性があります。レコード ID を受信したら、必ず [レコードを取得] 要素を使用して、レコード変数に必要な項目を入力します。

制限事項

  • Salesforce 組織の外部 URL にフローユーザーをリダイレクトすることはできません。
  • retURL パラメーターの値としてフロー変数を使用することはできません。フロー変数を使用して特定のレコードなどにユーザーをリダイレクトするには、Visualforce を使用してフローを配布します。
  • retURL を使用すると、ネストされた上部と横のナビゲーションバーが宛先ページに表示される可能性があります。
  • フロー URL の先頭に/lightningを追加しない場合、retURL では大文字と小文字が区別されます。retUrl を使用した場合、その URL でユーザーはリダイレクトされません。
  • アクションボタン画面コンポーネントでは、retURL パラメーターはサポートされません。

例

ケースオブジェクトのボタン URL をカスタマイズする前に、ボタンでフローが起動します。ユーザーがフローを終了すると、フローの最初の画面にリダイレクトされます。

/lightning/flow/Case_Update_Flow

次に、ユーザーがフローを終了した後にケースリストビューにリダイレクトするようにボタン URL をカスタマイズします。

/lightning/flow/Case_Update_Flow?retURL=500/o

ボタンをカスタマイズする

  1. [設定] で [オブジェクトマネージャー] をクリックします。
  2. [ケース] をクリックして、[ボタン、リンク、およびアクション] をクリックします。
  3. カスタムボタンを見つけて、[編集] をクリックします。
  4. URL フィールドで、フロー URL の最後に ？retURL＝500/o を追加します。
    メモ

    500 はケースのオブジェクトコードです。

  5. [保存] をクリックします。

次のフロー URL により、ユーザーは取引先ホームにリダイレクトされます。これは、Lightning Experience と Salesforce Classic の両方に存在します。

/lightning/flow/myFlow?retURL=001/o

Lightning Experience ユーザーがフローインタビューを完了すると、Salesforce によって http://MyDomainName.lightning.force.com/lightning/o/Account/home にリダイレクトされます。Salesforce Classic ユーザーがフローインタビューを完了すると、Salesforce によって http://MyDomainName.my.salesforce.com/001/o にリダイレクトされます。どちらの場合でも、ユーザーはそれぞれの環境の取引先ホームにリダイレクトされます。

次のフロー URL では、ユーザーは Salesforce Classic にのみ存在する Visualforce ページにリダイレクトされます。

/flow/myFlow?retURL=apex/myPage

ユーザーがフローインタビューを完了すると、Salesforce Classic の http://MyDomainName.my.salesforce.com/apex/myPage にリダイレクトされます。ユーザーが Visualforce ページから離れると、Salesforce は元の環境に戻ります。

たとえば、Visualforce ページを表示した後、ユーザーはホームページに移動します。Lightning Experience ユーザーの場合は、Lightning Experience のホームページ (http://MyDomainName.lightning.force.com/lightning) が表示されます。Salesforce Classic ユーザーの場合は、Salesforce Classic のホームページ (http://MyDomainName.my.salesforce.com/home/home.jsp) が表示されます。

次のフロー URL により、varUserFirst および varUserLast 変数 (どちらもテキスト型) が実行ユーザーの FirstName および LastName 項目値に設定されます。フローインタビューが完了すると、ユーザーは有効化された Salesforce 環境のホームページにリダイレクトされます。

/lightning/flow/User_Info?flow__varUserFirst={!$User.FirstName}
   &flow__varUserLast={!$User.LastName}&retURL=home/home.jsp

URL を使用してフローを配信する場合、URL のパラメーターを使用してそのフロー内の変数値を設定できます。

必要なエディション

必要なユーザー権限

開始する前に、設定しているフロー変数を入力できることを確認します。

  1. [設定] から、[クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
  2. カスタマイズするフローの [] をクリックし、[詳細とバージョンの表示] を選択します。
  3. フローの URL をコピーして、URL の先頭/lightning に追加します。
    メモ Lightning Experience を使用し、フロー URL の先頭に /Lightning を追加することをお勧めします。ただし、フロー URL に /Lightning を追加しなくても機能します。Lightning で実行する新しい利点は得られません。詳細は、「Choosing Between Lightning and Non-Lightning Flow URL Formats」を参照してください。
  4. 1 つの変数値を設定するには、フロー URL の末尾に ?flow__name=value を追加します。 name は設定するフロー内の変数またはコレクション変数の一意の名前、 value は設定する値です。
  5. 複数の変数値を設定するには、フロー URL の最後に ?flow__name1=value1&flow__name2=value2 を追加します。
  6. ID のリストをリストビューからフローに送信するには、ids という名前のコレクション変数を作成し、入力できるようにします。URL に値を設定せずに自動的に機能します。詳細は、「カスタムリストビューボタンからのフローの実行」を参照してください。
  7. ID 以外の同じコレクション変数の複数の項目の値を設定するには、変数名の前にflow__を追加したり、フロー URL の先頭に/lightningを追加したりしないでください。代わりに、フロー URL の最後に ?name=value1&name=value2 を追加します。
メモ コレクション:Lightning でサポートされているコレクション値設定は、リストビューから ids という名前のコレクション変数への ID の送信のみです。詳細は、「カスタムリストビューボタンからのフローの実行」を参照してください。

例 1: 単一変数値。ケースページレイアウトのカスタムボタンで使用されるフロー URL。ユーザーがボタンをクリックすると、ケースレコードの CaseNumber 項目の値に設定された varID 変数 (Text 型) を使用してフローが起動されます。

フローの完了動作を制御するように Visualforce コンポーネントをカスタマイズ

デフォルトでは、ユーザーが [完了] をクリックすると、新しいインタビューが開始され、フローの最初の画面が表示されます。Visualforce ページにフローを埋め込んだら、ユーザーを Salesforce の別のページに転送するように finishLocation 属性を設定します。

finishLocation 関数を使用した URLFOR の設定

メモ
  • Salesforce 組織の外部 URL にフローユーザーをリダイレクトすることはできません。
  • 同じフロー内で Auth.SessionManagement.finishLoginFlow メソッドと finishLocation 属性をコールしないでください。Auth.SessionManagement.finishLoginFlow は、Visualforce ページのログイン フローの終了を示します。finishLocation が同じフロー内にある場合、フローの開始時に finishLocation が実行され、ユーザーにセッションへのフルアクセス権が付与されます。

ID を使用して、相対 URL、特定のレコードまたは詳細ページにユーザーの経路を設定するには、URLFOR 関数を使用します。

この例では、Salesforce ホームページにユーザーの経路を設定します。

<apex:page>
          <flow:interview name="MyUniqueFlow" finishLocation="{!URLFOR('/home/home.jsp')}"/>
          </apex:page>

この例では、ID が 001D000000IpE9X である詳細ページにユーザーの経路を設定します。

<apex:page>
          <flow:interview name="MyUniqueFlow" finishLocation="{!URLFOR('/001D000000IpE9X')}"/>
          </apex:page>

URLFOR の詳細は、『Visualforce 開発者ガイド』の「関数」を参照してください。

finishLocation 変数を使用した $Page の設定

URLFOR を使用せずに別の Visualforce ページにユーザーをルーティングするには、{!$Page.pageName} の形式で finishLocation をデスティネーションページの名前に設定します。

<apex:page>
          <flow:interview name="MyUniqueFlow" finishLocation="{!$Page.MyUniquePage}"/>
          </apex:page>

$Page の詳細は、『Visualforce 開発者ガイド』の「グローバル変数」を参照してください。

finishLocation コントローラーを使用した の設定

カスタムコントローラーを使用したいくつかの方法で finishLocation を設定できます。

このサンプルコントローラーは、3 つの異なる方法でフローの完了動作を設定します。

public class myFlowController {
    
    public PageReference getPageA() {
        return new PageReference('/300');
    }
    
    public String getPageB() {
        return '/300';
    }
    
    public String getPageC() {
        return '/apex/my_finish_page';
    }
}
  • getPageA は、場所を定義する文字列を渡して新しいページ参照をインスタンス化します。
  • getPageB は、PageReference のように処理される文字列を返します。
  • getPageC は、PageReference に変換される文字列を返します。

次の Visualforce ページのサンプルは、コントローラーを参照し、フローの完了動作を最初のオプションに設定します。

<apex:page controller="myFlowController">
          <h1>Congratulations!</h1> This is your new page.
          <flow:interview name="flowname" finishLocation="{!pageA}"/>
          </apex:page>

標準コントローラーを使用して同じページにフローとしてレコードを表示する場合、ユーザーが [完了] をクリックすると、新しいフローインタビューが開始され、レコードのないフローの最初の画面が表示されます。レコードが表示されずフローの最初の画面が現れるのは、id クエリ文字列パラメーターがページ URL に保持されないためです。必要な場合は、ユーザーをレコードに戻すように finishLocation を設定します。
