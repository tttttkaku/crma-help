フローマーケティングフロー要素への送信

[フローに送信] アクション要素は、個人を特定の Marketing Cloud オンデマンドフローに送信します。たとえば、セグメントトリガーフローでは、個人のロイヤルティプログラムの状況に応じて顧客を特定のフローに転送できます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Marketing Cloud Growth Edition または Advanced Edition が付属する Enterprise Edition および Unlimited Edition
使用可能なエディション: Data 360 でサポートされるすべてのエディション。 「Data 360 Edition」を参照してください。

考慮事項

要素で対象フローがコールされた後、対象フローと対象フローが並列で実行されます。個人を宛先フローに送信した後も、元のフローは引き続き実行されます。この要素の後も、オリジンフローでアクションとロジックを引き続き実行できます。

サポートされるフロー種別

  • セグメントトリガーフロー
  • リストトリガーフロー
  • キャンペーンメンバートリガーフロー
  • レコード条件トリガーフロー
  • オートメーションイベントトリガーフロー
  • 有効化トリガーフロー
  • オンデマンドフロー

コレクション並び替え要素

コレクション内の項目を並び替え、必要に応じて並び替え後にコレクションに残す項目数を制限します。

必要なエディション

サポートされているエディションを表示する。
項目 説明
コレクション変数 並び替えられたコレクション変数。この項目は、同じフロー内の任意のコレクション変数を受け入れます。
並び替え基準 コレクションの並び替えの基準となる項目。この項目は、コレクション変数に複数の項目が含まれる場合にのみ表示されます。
並び替え順 コレクションを昇順または降順に並び替えます。
空の文字列と null 値を先頭に配置 この要素が選択されている場合は、[並び替え基準] 項目に空の値または null 値があるレコードがコレクションの先頭に並び替えられます。選択されていない場合は、コレクションの最後に配置されます。
並び替え後に保持する項目数 [項目の最大数を設定] を選択して、並び替え後にコレクションに残す項目の最大数を設定します。

使用方法

[コレクション並び替え] 要素が値を削除したり、その順序を変更したりする場合、これらの変更は選択されたコレクション変数内で直接行われます。

コレクション変数に複数の項目が含まれている場合は、[並び替えオプションを追加] をクリックして、追加の項目で優先度の大きい順または小さい順に並び替えます。一度に最大 3 件の項目で並び替えることができます。

開始要素

実行時に最初に実行するフロー要素に開始要素を接続します。自動起動フローでは、開始要素を開いて、フローを起動するトリガーを追加できます。トリガーを使用しない場合は、カスタムボタン、プロセス、Apex クラス、Einstein ボットなど、自動起動フローを呼び出すための他のものを設定する必要があります。

必要なエディション

サブフロー要素

組織で使用可能な別の有効なフローを起動します。別のフローによって起動されるフローは、参照されるフローと呼ばれます。

必要なエディション

サポートされているエディションを表示する。

サブフロー要素をフローに追加し、フローの表示ラベルまたは API 参照名を使用して、設定するフローを検索します。選択したフローが参照されるフローです。参照されるフローを新しいウィンドウで開くには、アクションメニューをクリックします。自動起動フローから画面またはテンプレートトリガープロンプトフローを参照することはできません。テンプレートトリガープロンプトまたは自動起動フローは、テンプレートトリガープロンプトフローから参照できます。各フローのリストには、有効なバージョンの表示ラベルと API 参照名が表示されます。フローに有効なバージョンがない場合、リストには最新バージョンの表示ラベルと API 参照名が表示されます。待機要素を含むフローをコールすることはできません。

ヒント 一般的なタスクを実行する小規模なフローを作成します。たとえば、住所とクレジットカード情報を取得したり、クレジットカードの購入金額を承認したりするユーティリティフローを構築します。次に、複数の商品注文フローから必要に応じてこれらのフローをコールします。
メモ フロー管理者のみが無効なフローを実行できます。他のユーザーの場合、サブフロー要素が有効なバージョンのないフローをコールすると、フローは実行時に失敗します。

入力値の設定

参照されるフローの入力変数を設定するには、フローの前半の値を使用します。[入力値を設定] タブで、サブフロー要素には参照されるフローの有効バージョンと最新バージョンの入力変数のみが表示されます。

[入力値を設定] で変数を渡す場合は、40 文字以内の変数 API 参照名を使用します。変数 API 参照名を長くすると、Target Variable Name: data value too large: [Variable Name] (max length=40) などのコールフローで保存エラーが発生します。

この値は、実行時にフローが、参照されるフローをコールするときに割り当てられます。ただし、コレクションでないテキスト変数、選択リスト変数、複数選択リスト変数では、null の値が空の文字列に変換されます。空の文字列に変換されます。

プロンプトフロー以外のフロー種別での出力値の保存

参照されるフローの出力をフローの後の方で使用するには、出力を変数に保存します。この値は、参照されるフローの実行が終了すると割り当てられます。[出力値を保存] タブで、サブフロー要素には参照されるフローの有効バージョンと最新バージョンの出力変数のみが表示されます。

プロンプトフローでの出力値の保存

後で参照されるフローの出力を使用するには、サブフロー要素の出力を参照するか、手動で割り当てられた変数として保存します。

使用方法

  • API バージョン 61.0 以降では、画面フローとレコードトリガーフローはデフォルトで参照されるフローの有効なバージョンをコールします。参照されているフローに有効なバージョンがない場合、フローは最新のバージョンの参照フローをコールします。以前の API バージョンでは、画面フローはデフォルトで参照されるフローの最新バージョンをコールしていました。参照される各フローの最新バージョンのみを実行するには、次の 2 つの選択肢があります。
    • Flow Builder で [デバッグ] をクリックし、[サブフロー要素によってコールされた各フローの最新バージョンを実行します] を選択して [実行] をクリックする。Flow Builder キャンバスでフローをデバッグする場合、このオプションは使用できません。

  • API バージョン 63.0 以降では、プロンプトフロー種別で自動起動フローがサブフロー要素の参照フローとしてサポートされます。

プロンプトフローでのサブフローを使用したイベント招待の作成の例

参照されるフローを使用して、セールスメールテンプレートトリガープロンプトフローで生成された各マーケティングイベントのミーティングへの招待を作成します。

必要なエディション

使用可能なインターフェース: Lightning Experience
サポートされているエディションを表示する。
この機能には、Einstein for Sales、Einstein for Service、または Einstein Platform アドオンが必要です。購入するには、Salesforce 取引先担当者にお問い合わせください。
必要なユーザー権限
Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
プロンプトビルダーでプロンプトテンプレートを作成および管理する 「プロンプトテンプレートマネージャー」権限セット

テンプレートトリガープロンプトフローは、Winter '24 で作成されたプロンプトテンプレートと互換性がありません。

あなたが Salesforce システム管理者であるとします。プロンプトテンプレートに指示を送信して、取引先責任者が住んでいる同じ市区郡と都道府県でマーケティングイベントを取得するフローを作成します。これで、プロンプトフローを参照フローとして親フローに追加できます。この新しいフローでは、マーケティングイベントごとに取引先責任者のミーティングへの招待が作成されます。

親フローを作成する前に、マーケティングイベントのリストを取得するフローを作成します。「セールスメールテンプレートトリガープロンプトフローの例」を参照してください。

  1. [フロー] リストビューを開きます。
    • Automation アプリケーションから、[フロー] タブを選択します。
    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。
    [オートメーションアプリケーション] および [フロー] タブのオプションには、[設定] アクセス権は必要ありません。
  2. フローを作成します。
    • 自動化アプリケーションで、[New | Autolaunch | Template-Triggered Prompt Flow (新規自動起動テンプレートトリガープロンプトフロー)] をクリックします。
    • [設定] から、新規フロー | 自動起動 | テンプレートトリガープロンプトフローをクリックします。
  3. フローを設定します。
    1. [自動入力] を選択します。
    2. [プロンプトテンプレート種別] で、[セールスメールテンプレート] を選択します。
      各プロンプトテンプレート種別は、プロンプトビルダーでそのプロンプトテンプレート種別に関連付けられます。
    3. [受信者] で、[取引先責任者] を選択します。
  4. サブフロー要素を追加して設定します。
    1. [] をクリックし、[サブフロー] 要素をクリックします。
    2. [表示ラベル] に「Event Details」と入力し、デフォルトの API 参照名 Event_Details を使用します。
    3. [受信者] で、[Prompt Template Input]> [Contact] を選択します。
    4. [送信者] で、[Prompt Template Input]> [User] を選択します。
  5. [プロンプト手順を追加] 要素を追加して設定します。
    1. [] をクリックし、[プロンプト指示を追加(Add Prompt Instructions)] 要素をクリックします。
    2. [表示ラベル] に「Meeting Invite」と入力し、デフォルトの API 参照名 Meeting_Invite を使用します。
    3. [プロンプトの手順] に「Send a meeting invite to {!$Input.Recipient.Name} with {!Event_Details.Prompt}」と入力します。
  6. フローを保存します。
    1. [フローの表示ラベル] に「Send Marketing Events Invite」と入力し、デフォルトの API 参照名 Send_Marketing_Events_Invite を使用します。
    2. 作業内容を保存します。
  7. フローを有効化する前に、［Debug］ をクリックしてフローエラーのトラブルシューティングを行います。
  8. デバッグオプションと入力変数を設定します。
    別のユーザーとしてフローを実行する場合は、[Process Automation Settings (プロセスの自動化設定)] で [Allow admins debug flows as other users (システム管理者が他のユーザーとしてフローをデバッグできるようにする)] が有効になっていることを確認します。
  9. [実行] をクリックします。
    右側のパネルに実行のデバッグの詳細が表示されます。
  10. 結果を確認するには、デバッグの詳細を確認します。フローが失敗した場合は、フローエラーをトラブルシューティングします。
  11. フローを有効化します。

フローが完了したので、プロンプトビルダーでセールスメールプロンプトテンプレートを作成します。親フローをプロンプトテンプレートに追加します。プロンプトビルダーでプロンプトテンプレートをプレビューすると、親フローがトリガーされ、参照されるフローが実行されます。親フローがプロンプト指示をプロンプトテンプレートに送信します。

変換要素

変換元データを変換先データに対応付けて変換するためのフローリソースを選択します。[変換] 要素は、画面フロー、トリガーのない自動起動フロー、およびレコードトリガーフローで使用できます。

必要なエディション

サポートされているエディションを表示する。
項目 説明
ソースデータ

変換するデータ。

  • リソース — フローで使用できるフローリソース。複数のリソースを追加できます。
変換先データ

変換された後のデータ

  • 複数の値を許可 (コレクション) — 変換先データがコレクションである場合に選択します。ソースデータには 1 つ以上のコレクションが含まれている必要があります。
  • Apex クラス — 変換先データ構造に使用する Apex クラス。
  • データ型 — 対象データのフローリソースのデータ型。
  • オブジェクト — 変換先データ構造に使用するオブジェクト。
数式

データを変換する数式。数式は、次のことができます。

  • 対象データ項目に固定値を設定します。
  • ネストされている 2 つのソースコレクションまで参照できます。たとえば、変換元データ項目にコレクション A が含まれ、コレクション B が含まれているとします。この場合に数式が変換元データとして参照できるのは、コレクションを参照していないフローリソースのみです。

数式の結果は、対象項目のデータ型と互換性がある必要があります。数式の [$EachItem] 差し込み項目構文は、コレクションの各項目を表します。たとえば、差し込み項目は注文のコレクションを参照し、各注文品目には [顧客] 項目があります。各 [顧客] 項目には [名前] 項目があります: {!Orders[$EachItem].Customers[$EachItem].Name}

利用状況

[変換] 要素を使用する場合は、次の一般的な制限事項を理解しておく必要があります。

  • コレクションを変換する場合、変換にデータの並び替えや絞り込みを含めることはできません。コレクションの絞り込みまたは並び替えを行うには、代わりに [コレクション検索条件] 要素または [コレクション並び替え要素] をフローで使用します。
  • リッチで対話型の形式でソースデータと対象データのデバッグの詳細を表示することは、自動起動フローとレコードトリガーフローでのみサポートされます。
  • 対象データのリソースが外部サービス登録の Apex クラスの場合、Flow Builder のデバッグの詳細には変更された項目名が表示されます。
    メモ 外部サービスが登録されると、Salesforce はサービスの入出力を保存する Apex クラスを作成します。
    • 項目名に予約名が使用されている場合、項目名の先頭に z0 が付けられます (例: z0type)。フローが外部サービスをコールアウトした場合は、元の項目名 (この例では type) が使用されます。「Apex の予約キーワード」を参照してください。
    • 末尾に _set が付けられている (例: name_set) 名前の項目は、動的 Apex クラスに自動的に追加されます。項目は、動的 Apex クラスの検査したときにフローのデバッグ詳細にのみ表示されます。「Apex での外部サービス登録」を参照してください。
  • 標準オブジェクト、カスタムオブジェクト、外部オブジェクトの参照項目を介した関連レコードへのアクセスはサポートされていません。
  • データグラフは、セグメントトリガーフローおよびデータグラフトリガーを使用したオートメーションイベントトリガーフローでサポートされます。
  • データグラフのコレクションはサポートされていません。たとえば、[変換] 要素では、データグラフでコレクションを集計できません。

次の画面コンポーネントとデータ型を使用する場合は、それぞれの制限を理解しておく必要があります。

  • ソースデータまたは対象データのフローリソースでは、チェックボックスグループ、選択リスト、選択肢ルックアップ画面コンポーネントはサポートされません。
  • ソースデータのフローリソースでは、Boolean、通貨、データ、日時、数値、文字列、時間などのプリミティブデータ型の画面フローコンポーネントはサポートされません。たとえば、ソースデータではチェックボックス、日付、日時、ロングテキストエリア、表示テキスト、ラジオボタン、テキスト画面コンポーネントはサポートされません。

コレクション内のデータ構造の整合性を保つための以下のルールについて理解しておいてください。

  • 変換元コレクションの項目を変換先コレクションの項目に対応付けるには、両方のコレクションがそれぞれのリソース内で同じ階層レベルにある必要があります。たとえば、ソースデータのコレクション A と対象データのコレクション A が他のコレクション内にない場合などです。これらのコレクションはどちらもそれぞれのリソースで最上位に位置するため、これらのコレクションの間では項目を対応付けることができます。
  • 別のコレクション内にあるコレクションの項目を対応付けるには、その前に親コレクションで項目を対応付けます。たとえば、変換元データと変換先データのフローリソースの両方に、同じデータ構造を持つコレクション A が含まれているとします。コレクション A にはコレクション B が含まれているとします。この場合にコレクション B の項目を対応付けるには、その前にコレクション A の項目を対応付けてから、コレクション B の項目を対応付けておく必要があります。

変換先データ項目が対応付けられていないか null の場合、この項目は実行時に [変換] 要素で生成されたフローリソースから削除されます。

結合変換に関する次の制限事項を確認してください。

  • 別のコレクション内にあるコレクションは結合できません。
  • ソース項目を対象項目に対応付けるには、両方の項目のデータ型が同じである必要があります。たとえば、ソース項目が Apex で定義されたデータ型の場合、対象項目も同じ Apex で定義されたデータ型である必要があります。
  • 結合するために選択された項目はそれぞれ、対象コレクションの 1 つの対象項目にのみ対応付けることができます。
  • 結合変換ですでに選択または対応付けられているソースコレクションやソース項目を削除または変更すると、結合変換は無効になります。
  • 結合変換には 1 つの対象コレクションのみが含まれます。複数の結合変換がある場合、それぞれに独自の対象コレクションが含まれます。
  • 結合変換で対象コレクションを対応付けると、その対象コレクションを結合変換外の他の対応付けに使用することはできません。
  • データグラフはサポートされていません。

結合変換で Apex CPU の制限を超えないようにするために、次のガイドラインを確認してください。デバッグログで、変換要素ごとに、どの程度の CPU 時間がかかっているかを確認できます。

  • すぐに実行されるフローパスの場合、各ソースコレクションに含まれるレコード数が 700 未満になるように制限します。
  • スケジュールに従って実行されるフローパスまたは非同期で実行されるフローパスの場合、各ソースコレクションに含まれるレコード数が 1,500 件未満になるように制限します。
  • 各ソースコレクションに含まれるレコード数が 600 未満の場合、200 件以下のソース項目を対象項目に対応付けます。

制限

  • 変換要素では、ネストされたコレクションを 1 つまで対応付けることができます。
  • Apex で定義されたフローリソースの項目は、Apex で定義された項目を項目内で 10 レベルまで参照できます。たとえば、CollectionA の [名前] 項目は第 1 レベルです。CollectionB の項目は第 2 レベルです (以下同様)。
  • デバッグの詳細には、コレクションのレコードが最大 20 件まで表示されます。
  • [変換] 要素では、数式を最長 255 文字で定義できます。255 文字を超えた部分は切り捨てられます。フローで数式リソースを作成することで、数式に 255 文字を超える文字を入力できます。数式リソースでは、255 文字を超えて数式を定義できます。[変換] 要素では、数式を使用してデータを変換するときに数式リソースを選択できます。

イベント待機後のリマインダーの送信の例

契約が終了する 2 週間前や 1 週間前など、いくつかの時間ベースのイベントを待機した後に複数のリマインダーを送信するフローを作成します。

必要なエディション

サポートされているエディションを表示する。

契約が終了する前に顧客をフォローアップするよう契約所有者に伝えるフローを設計しています。リマインダーは、一度だけでなく、フローで定期的に送信します。この例では、1 つの待機要素を使用して、契約が終了する 2 週間前にリマインダーを送信し、1 週間前にもう一度送信する方法を示します。このフローは簡単に拡張でき、リマインダーを送信する間隔 (3 日ごとや契約が終了する 1 日前など) を増やすことができます。

例

このフローには、すでに次の入力済みの変数が含まれています。フローは待機要素を実行する前に、契約の EndDate と OwnerId を検索して保存します。

  • {!contract} は、契約の EndDate と OwnerId を含むレコード変数です。
  • {!contractId} は、契約の Id が含まれるテキスト変数です。
  • {!oneWeekVisited} は、デフォルト値が {!$GlobalConstant.False} の Boolean 変数です。
  • {!twoWeeksVisited}は、デフォルト値が {!$GlobalConstant.False} の Boolean 変数です。

このフローは契約終了日の 2 週間前と 1 週間前の両方にメールのリマインダーを送信するため、待機要素にレコードベースの時間を使用する 2 つの時間ベースの再開イベントが定義されます。

ヒント どの時間ベースの再開イベントも基準時刻とオフセットで構成されます。レコードベースの時間の場合は、フローが基準時刻を判断するために、オブジェクト、日付/時間項目、特定のレコードの 3 つの情報が必要です。レコードベースの時間の場合も、オフセットはフローベースの時間の場合と同じように機能します。フローが、単位 (日または時間のいずれか) とこれらの単位の時間数を識別する必要があります。レコード項目の数日前または数時間前まで待機する場合は、[オフセット数] に負の整数を設定します。

どちらのイベントでも、オフセットは日単位で宣言されます。これは、週単位が許容されないためです。

最初のイベント (「2 週間」) の基準時刻は、ID が {!contractId} (2) に保存されているレコードの Contract.EndDate (1) の値です。この値から -14 日 (3) をオフセットして 2 週間を表します。

すべてのリマインダーに同じ待機要素を使用する場合は、フローインタビューが 1 つのメールのリマインダーを送信した後に待機要素に戻ります。ただし、インタビューが同じメールを何度も送信しないようにするには、まず待機条件を使用します。インタビューは待機要素を実行するときに、まず各待機設定の条件をチェックして、そのイベントを待機するかどうかを判断します。待機設定に条件が設定され、その条件を満たしていない場合は、インタビューは関連する再開イベントを待機しません。

最初の再開イベントについては、インタビューが Boolean 変数 {!twoWeekVisited} が false に設定されているかどうかをチェックします。変数のデフォルト値は {!$GlobalConstant.False} に設定されているため、フローは変数の値が変更されるまでイベントを待機します。

「2 週間」イベントが発生したときにフローが何を行うかを示すために、待機要素を他の要素に結び付けます。次に、フローパスを待機要素に戻す前に、{!twoWeeksVisited} の値を {!$GlobalConstant.True} に変更します。この変更には割り当て要素を使用できます。待機要素の実行時に {!twoWeeksVisited} の値が false でない場合、フローは「2 週間」イベントの発生を待機しません。基本的に、この変数は関連付けられた待機設定のパスでしか true に変更されていないため、インタビューは最初の再開イベントが発生しているかどうかをチェックします。この再開イベントが発生している場合 (および変数が false に設定されていない場合)、インタビューはこのイベントを待機しないことを認識します。

2 つ目のイベント (「1 週間」) の基準時刻は最初のイベントと同じです。オフセットは、1 週間を表す -7 日です。

2 つ目のイベントについては、boolean 変数 {!oneWeekVisited} が false に設定されているかどうかをフローがチェックします。false に設定されていない場合、フローはこのイベントを待機しません。

最初の待機設定と同様に、フローパスを待機要素に戻す前に、割り当て要素を使用して、{!oneWeekVisited} の値を {!$GlobalConstant.True} に変更します。{!oneWeekVisited} が false でない限り、フローは「1 週間」イベントの発生を待機しません。

ヒント フローで待機要素を実行し、すべての待機設定の条件が満たされない場合、フローはデフォルト パスを実行します。最後のリマインダーを送信した後にこのフローは終了するため、デフォルトパスを別の要素につなげることはありません。

何らかの問題が発生した場合に備えて、障害パスを設定します。この例では、障害パスが、故障メッセージを表示するメールをフローを作成したユーザーに送信します。

プラットフォームイベントを待機した後の ToDo の作成の例

プラットフォームイベントで出荷が確認されるまでフローを一時停止して、サプライ注文を自動化するフローを作成し、翌日用のフォローアップインストールタスクを作成します。

必要なエディション

サポートされているエディションを表示する。

用品を購入するベンダーには、登録するプラットフォームイベントがあります。Vendor Response というプラットフォームイベントには、注文番号、注文状況、配送予定日が含まれます。

メモ このフローは大きなサンプルの一部です。[Printer Status (プリンターの状況)] プラットフォームイベントメッセージを受信したときに開始されるプロセスによって起動されます。プロセスの詳細は、「サンプルプロセス: プリンター管理」を参照してください。

[Order Printer Supplies (プリンター用品の注文)] フローは、プリンター管理プロセスが起動すると開始されます。このプロセスでは、次の変数がフローに入力されます。

  • {!assetId} — 納入商品の ID
  • {!assetOwner} — 資産の所有者
  • {!inkManufacturer} — プリンタのインクの製造元
  • {!inkNeeded} — プリンターに追加のインクが必要かどうか
  • {!inkType} — プリンターで使用される特定のインクの種類
  • {!paperNeeded} — プリンターに追加の用紙が必要かどうか
  • {!paperSize} — プリンターで使用される用紙サイズ
  • {!serialNumber} — 納入商品のシリアル番号

フローでは最初にインクまたは用紙を注文する必要があるかどうかが判断されます。その決定に基づき、Apex アクションを使用してインクまたは用紙をベンダーに注文します。次に、注文が発送されたことを示すプラットフォームイベントメッセージがベンダーから送信されるまで一時停止します。Salesforce が指定されたイベントメッセージを受信すると、フローが再開され、納入商品の所有者が新しい用品を取り付けるための ToDo が作成されます。

決定要素

決定には、[Ink (インク)] と [Paper (用紙)] の 2 つの結果が含まれます。変数 {!inkNeeded} が true の場合、[Ink (インク)] の結果が true になります。変数 {!paperNeeded} が true の場合、[Paper (用紙)] の結果が true になります。

Apex アクション要素

フローには、用品注文をベンダーに送信する 2 つの Apex アクションが含まれますが、これらの Apex アクションは、フローが [Ink (インク)] の結果または [Paper (用紙)] の結果のどちらを実行したかに基づいて、異なる情報を提供します。入力値として使用するすべての変数 ({!serialNumber}、{!paperSize} など) は、プロセスがフローを起動するときに設定されます。

最初の Apex アクションは、注文するインクに関する情報を提供します。

2 番目の Apex アクションは、注文する用紙に関する情報を提供します。

この両方の Apex アクションの各アクションで注文番号が返されます。この値は {!orderNumber} 変数に保存され、待機要素で参照されます。

待機要素

Apex アクションが用品注文を送信した後、フローは、注文の発送確認を待機します。確認は、[Vendor Response (ベンダー応答)] プラットフォームイベントを介して受信されます。

フローは、特定の値が含まれる [Vendor Request (ベンダー要求)] イベントメッセージを Salesforce が受信するまで一時停止します。注文番号は、Apex アクションが提供した注文番号と同じである必要があります。また、注文状況は [Shipped (発送済み)] である必要があります。

正しいイベントメッセージが受信され、フローが再開されると、イベントメッセージのデータがレコード変数に保存されます。これにより、ユーザーは配送予定日を参照して、用品の取り付けスケジュールを計算できます。

レコードの作成要素

フローが再開されると、新しい用品を取り付けるための、納入商品所有者の ToDo が作成されます。

ToDo の項目値の場合、フローは次のリソースを使用します。

  • {!installDate} — イベントの配送予定日の翌日を計算する数式。
  • {!taskDescription} — 取り付けに関する詳細を提供するテキストテンプレート。
  • {!assetOwner} — フローを起動するプロセスによって指定される
  • {!assetId} — フローを起動するプロセスによって指定される

    2 番目のイベントは、契約終了日の 14 日前に発生します。待機条件は、契約している取引先の評価が「見込み有り」ではないかどうかをチェックします。取引先が「見込み有り」の場合、インタビューは 2 つ目のイベントを待機しません。

    待機条件を満たす場合に待機するイベントを定義します。イベントが発生すると、フローはこの待機設定に関連付けられたパスを再開して辿ります。

デフォルトでは、フローを作成すると、最新の API バージョンで実行されます。既存のフローを新しいフローまたはフローバージョンとして保存すると、新しいフローまたはフローバージョンで既存のフローの実行時 API バージョンが使用されます。

実行時 API バージョンは、今後 Salesforce リリースがロールアウトされても変更されません。各フローバージョンを実行するための API バージョンを変更するタイミングは各自で決定します。この項目により、各自のペースでフローを 1 つずつテストしてアップグレードできます。1 つまたはすべてのフローでバージョン管理された更新を採用しないこともできます。

返される値はコンテキストユーザーの言語設定によって異なります。 Salesforce は次の優先順位に基づいて値を返します。

  • ローカル翻訳のテキスト
  • パッケージ翻訳のテキスト
  • 主表示ラベルのテキスト
$Organization Running Org (実行組織) フローが実行されている Salesforce 組織。この変数により、組織の名前や住所などの情報にアクセスできます。
$Permission Running User’s Permission (実行ユーザーの権限) フローを実行しているユーザーのカスタム権限アクセス。
$Output $Output フローの内部または外部で使用できるフローからデータを出力します。フローは出力を参照してロジックとアクションを実行できます。たとえば、プロンプトビルダーのプロンプトテンプレートに関連付けられたフローでは、$Output > Prompt を参照して、レコードの項目にテキストを割り当てることができます。フローの外部では、統合アプリケーションは $Output が参照する値をマージできます。たとえば、プロンプトテンプレートでは、$Output の値がプロンプトテンプレートの解像度にマージされます。[プロンプトフロー] プロセス種別でのみ使用できます。
$Profile Running User Profile (実行ユーザープロファイル)

フローを実行しているユーザーのプロファイル。この変数により、ライセンスの種類や名前などの情報にアクセスできます。

  • プロファイル名を使用して、$Profile マージフィールドで標準プロファイルを参照します。
  • ユーザーは、これらの差し込み項目を参照するフローを実行するときにプロファイル情報にアクセスする必要はありません。
$Record トリガー オブジェクト, 例えば、トリガーアカウント

フローをトリガーしたレコード。トリガーを使用した自動起動フローでのみ使用できます。

レコードトリガーフロー内の $Record グローバル変数には、トリガーされたレコードの値が含まれます。$Record の値をフロー全体で参照および変更できます。

  • レコードがデータベースに保存される前にフローが実行されると、変更された $Record 値が Salesforce によって自動的にデータベースのレコードに適用されます。
  • レコードがデータベースに保存された後にフローを実行する場合、[レコードを更新] 要素を使用して、変更した $Record 値をデータベースのレコードに適用します。

スケジュールトリガーフローは、レコードのバッチに対して、指定された時間と頻度で開始されます。バッチ内のレコードごとにフローインタビューが実行され、レコードのすべての項目値が $Record グローバル変数に保存されます。この値をフロー全体で参照および変更できます。レコードを更新要素では、$Record グローバル変数の ID とすべての項目値を使用できます。その場合、組織のプロセスの自動化設定で [Filter inaccessible fields from flow requests (フロー要求のアクセスできない項目を絞り込む)] を選択します。有効にしない場合、システム項目と他の参照のみの項目の値がレコードを更新要素により設定されるため、フローは失敗します。
$Record__Prior Prior Values of Triggering オブジェクト, 例えば、Prior Values of Triggering アカウント

変更によってフローがトリガーされる前のトリガーレコード。レコードが更新されたとき、またはレコードが作成または更新されたときに実行するように設定されているレコードトリガーフローでのみ使用できます。

$Record__Prior グローバル変数には、フロー開始の直前のトリガーレコードの値が含まれます。フロー内でこの値を変更することはできません。

新規作成されたレコードがフローをトリガーすると、すべての$Record__Prior値が null になります。

トリガーレコードが同じトランザクションで作成および更新された場合、$Record__Prior には $Record と同じ値が含まれます。この動作は、更新が行われたときにコミットされた以前の状態が存在しないために発生します。更新前の項目値を$Record__Priorに取り込むには、フローをトリガーする自動化で作成操作と更新操作を別々のトランザクションに分割します。
$Setup Custom Hierarchy Settings (カスタム階層設定)

hierarchy 型のカスタム設定。このグローバル変数は、組織にカスタム階層設定がある場合にのみ表示されます。list 型のカスタム設定には、Apex でのみアクセスできます。

階層カスタム設定では、次のレベルで値を定義できます。Salesforce では、実行中のユーザーの現在のコンテキストに基づいて、このカスタム設定に適した値が判別されます。

  • 組織 — すべてのユーザーのデフォルト値
  • プロファイル — 組織の値を上書き
  • ユーザー — 組織およびプロファイルの値を上書き
$System System (システム) システムの OriginDateTime ($System.OriginDateTime)。1900-01-01 00:00:00 のリテラル値を表します。この差し込み項目を使用して、日付/時間オフセット計算を実行します。
$User Running User (実行ユーザー)

フローインタビューを実行しているユーザー。たとえば、ユーザーの ID または役職を参照します。

  • 実行ユーザーは、フローを開始したユーザーです。
  • Web-to-ケースまたは Web-to-リードプロセスによってレコードが変更されたためにフローが開始された場合、実行ユーザーは Default Lead Owner または Default Case Owner です。

$User.UITheme および $User.UIThemeDisplayed は、Salesforce ページ上で実行ユーザーに表示される外観と操作性を識別します。この 2 つの変数の違いは、$User.UITheme がユーザーの設定済みのデザインを返すことです。$User.UIThemeDisplayed は、ユーザーの実際のデザインを返します。

たとえば、あるユーザーに Lightning Experience のデザインを表示するための設定と権限があるとします。ただし、Internet Explorer の古いバージョンなど、そのデザインをサポートしていないブラウザーを使用しています。この例では、$User.UITheme と $User.UIThemeDisplayed は異なる値を返します。

  • Theme1 — 古い Salesforce テーマ
  • Theme2 — Salesforce Classic 2005 ユーザーインターフェースのテーマ
  • Theme3 — Salesforce Classic 2010 ユーザーインターフェースのテーマ
  • Theme4d — 最新の「Lightning Experience」 Salesforce のテーマ
  • Theme4t — Salesforce モバイルアプリのテーマ
  • Theme4u — Lightning コンソールのテーマ
  • PortalDefault — Salesforce カスタマーポータルのテーマ
  • Webstore―AppExchange のテーマ
$UserRole Running User Role (実行ユーザーロール)

フローを実行しているユーザーのロール。たとえば、ロール名または ID を参照します。

  • 実行ユーザーは、フローを開始したユーザーです。
  • Web-to-ケースまたは Web-to-リードプロセスによってレコードが変更されたためにフローが開始された場合、実行ユーザーは Default Lead Owner または Default Case Owner です。

フローのグローバル変数に関する考慮事項

  • $Flow は、画面コンポーネントの表示条件で入手可能な唯一のグローバル変数です。
  • レコードトリガーフロー内の $Record グローバル変数には、他のレコードから派生した値を持つフィールドについて、トリガーとなったレコードの値が含まれません。派生フィールドの例としては、Contact.Name や User.MediumPhotoUrl があります。
  • 複数選択リスト、時間、および場所のグローバル変数は数式でのみ使用できます。
  • データベースの項目が空の場合、対応する差し込み項目は空白値を返します。たとえば、組織の [国] 項目に値がない場合、{!$Organization.Country} は値を返しません。
  • フローリソース選択リストでは、$Label グローバル変数の読み込みに時間がかかります。$Label グローバル変数を選択した際、もしフローリソース選択リストに $Label オプションが表示されない場合は、ウィンドウを閉じ、数分後に再試行してください。

null と空の文字列

実行時に、空白値 (空文字列) と null は個別の値として処理されます。

  • 空白値 (空文字列) は、0 文字のテキスト値を示します。項目または変数が空白かどうかを判断するために使用します。
  • null は、値が存在しないことを示します。項目または変数値が存在するかどうかを判断するために使用します。
  • 項目または変数にデータが入力されているかどうかを確認するには、演算子に [次の文字列と一致する] を使用し、値に を使用します。
  • 項目または変数の値を使用できないかどうかを確認するには、条件で演算子に Is Null、値に True を使用します。
例 [レコードを取得] 要素でレコードが見つかったかどうかを確認するには、条件を手動で設定した [決定] 要素を追加します。次に、最初の決定結果のリソースに [レコードを取得] レコードコレクション、演算子に Null、値に False を使用します。

考慮事項

  • テキスト項目または変数に開始値を指定しない場合、実行時に値が null になります。値を空の文字列として処理する場合は、[空白値 (空の文字列)] に設定します。
  • 画面要素に配置したテキスト項目またはコンポーネントの場合、[null] 演算子は常に false に評価されます。項目またはコンポーネントに値がないかどうかを判断するには、演算子に [次の文字列と 一致 する]、値に [ 空白の値 (空の文字列)] を使用します。
  • 2 つのテキスト変数を比較する条件の場合は、デフォルト値が Blank Value (Empty String) に設定されていること、あるいは空白のまま (null) であることを確認します。
  • null値と空白値 (空文字列) の両方を同時にチェックするには、ISBLANK 数式関数を使用します。

例

取引先を作成するプロセスを簡略化するフローで、ユーザーは会社の業種を特定します。

業種ごとに 1 つの選択肢を作成するのではなく、選択リスト選択肢セットをフローに追加して選択リスト画面コンポーネントにその選択肢を入力します。ユーザーがフローを実行すると、選択リスト選択肢セットによって取引先オブジェクト (2) の [業種] 項目 (1) のデータベース内のすべての値が検出されます。

選択リスト選択肢セットは、スタンドアロンの選択肢リソースより設定が簡単なうえ、メンテナンスも軽減されます。他のユーザーが [取引先業種] 項目にオプションを追加すると、フローにその変更が自動的に反映されます。フローを手動で更新する必要はありません。

考慮事項

選択リスト選択肢セットを使用している場合、次の操作は実行できません。

  • データベースから戻され値を除外する。フローには常に項目のすべての選択リスト値が表示されます。レコードタイプを使用して、ページレイアウトの選択リスト選択肢を絞り込んでいる場合も同じです。
  • 各オプションの表示ラベルをカスタマイズする。フローには常に各選択リスト値の表示ラベルが表示されます。
  • 各オプションの保存値をカスタマイズする。フローは常に各選択リスト値の API 値を保存します。

ナレッジの記事の選択リストはサポートされません。

選択リスト選択肢セットに標準選択リスト項目が見つかりませんか?多くの場合、その項目のデータ型は技術的には選択リストではありません。項目の実際のデータ型を確認するには、『Object Reference for the Saleforce Platform』を参照してください。たとえば、選択リスト選択肢セットを作成する場合、オブジェクトマネージャーで選択リストとしてリストされていても、行動オブジェクトの [件名] 項目は表示されません。これらの値をフローに表示するには、レコード選択肢セットを使用して、項目の値でレコードを検索して選択します。または、[メール]、[ミーティング]、[選択肢リソースとの通話] などのオプションを手動で作成することもできます。

翻訳した項目の表示ラベルと値

選択リスト項目を翻訳すると、次のようになります。

  • 各選択肢の表示ラベルでは、実行ユーザーの言語になっているバージョンの選択リスト値が使用されます。
  • 各選択肢の保存値では、組織のデフォルト言語になっているバージョンの選択リスト値が使用されます。

追加オブジェクト項目値の保存

選択肢が選択されているときに、後から参照できるフロー変数に関連レコードの項目値を保存します。

メモ チェックボックスグループ、複数選択リスト、または選択肢ルックアップ画面コンポーネントでレコード選択肢セットを使用する場合、ユーザーが選択した最後のレコードの値のみがフロー変数に保存されます。1 つの画面上の複数のチェックボックスグループコンポーネントまたは複数選択リストコンポーネントで同じレコード選択肢セットを使用する場合、それらのすべてのコンポーネントから選択された最後のレコードに従って変数が割り当てられます。
例

コンピューターハードウェア製造業者のサポートフローで、ユーザーが商品を特定して最新の更新を検索します。この場合、商品 ID が特定の文字列で始まるすべての商品設定を表示する、レコード選択肢セットを作成します。ただし、フローユーザーは商品 ID よりも商品名を知っている可能性があります。 そのため、[選択肢表示ラベル] には商品名を含む項目を選択し、[選択肢の値] には ID 項目を選択します。フローの他の場所で、関連する説明を表示します。このために、ユーザーが選択したレコードの説明項目の値を変数に保存します。

必要なエディション

サポートされているエディションを表示する。

選択したレコードリソースでは、ネストされた 1 対多のデータ構造 (データグラフの注文や注文品目など) をトラバースし、並び替えや検索条件ロジックを使用して、明確に定義された 1 つのレコードを取得できます。その後、リソース種別がサポートされているすべてのフロー要素でそのレコードを参照できます。

Flow Builder の [リソース] タブまたはサポートされているフロー要素項目のリソース選択から、選択したレコードリソースを作成します。

選択したレコードリソースは、セグメントフローと有効化トリガーフローでサポートされます。

Data Source (データソース)

レコードの取得元のコレクション。データグラフパスなど、サポートされているコレクションを検索して選択します。たとえば、$UnifiedIndividual > Individual > Orders です。

並び替え条件

データソースの複数のレコードが検索条件に一致する場合に返されるレコードを決定します。少なくとも 1 つの並び替え条件が必要です。

項目 説明
項目 並び替えの基準となるデータソースの項目。複数の並び替え条件では、データソースの同じレベルの項目を使用する必要があります。
順序 並び替え方向 (昇順または降順)。

検索条件

省略可能。並び替えが適用される前にコレクションを絞り込みます。検索条件を使用しない場合、データソースのすべてのレコードが評価され、並び替えによって返されるレコードが決まります。

項目 説明
条件ロジック 1 つのデータソースレベル内の複数の条件を評価する方法を制御します。[すべての条件に一致 (AND)] または [いずれかの条件に一致 (OR)] を選択します。すべてのレベルの条件では、常に AND ロジックが使用されます。
