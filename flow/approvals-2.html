Classic 承認プロセスからの承認申請用 Chatter 投稿テンプレート

Chatter の承認投稿テンプレートにより、Chatter フィードに表示される承認申請投稿に含まれる情報をカスタマイズできます。

必要なエディション

使用可能なインターフェース: Salesforce Classic および Lightning Experience の両方
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition
重要 従来の承認プロセスに代わる最新のフロー承認プロセスをお試しください。この新しい機能は、より柔軟でユーザーフレンドリーなフローベースのインターフェースを提供し、レコードの変更時にトリガーできます。また、Apex の拡張性とコンプライアンス、そして監査履歴の詳細なログ記録をサポートしています。特定のオブジェクトに関連付けられており、条件を使用してプロセスのサポートが制限されている従来の承認プロセスとは異なり、データとビジネスルールに基づく動的ルーティングがサポートされます。フロー承認プロセスを使用すると、申請済みレコードを監視してボトルネックをすばやく特定できるため、承認ワークフローをこれまでにないほど可視化できます。また、従来の承認プロセスと同様に、フロー承認プロセスでは自動化クレジットやオーケストレーションの実行は消費されません。

制限事項

  • 関連付けられたオブジェクトの承認およびフィード追跡を有効にする必要があります。
  • 承認投稿テンプレートが従来の承認プロセスで使用されている場合、削除できません。
  • 承認申請の Chatter 投稿は Salesforce Classic にのみ表示されます。Lightning Experience で承認申請に返答するには、[承認申請] タブに移動します。

連動関係

  • カスタム項目を削除すると、その項目が参照するすべての承認投稿テンプレートから削除されます。既存の投稿は影響を受けません。カスタム項目を復元すると、[選択可能な項目] リストには復元されますが、以前にその項目が含まれていた承認投稿テンプレートには復元されません。
  • カスタムオブジェクトを削除 (または復元) すると、関連付けられている承認投稿テンプレートと、Chatter フィードにすでに存在する、そのオブジェクトの承認申請投稿も削除 (または復元) されます。
  • カスタムオブジェクトの名前を変更すると、そのオブジェクトに関連付けられている承認投稿テンプレートもそれに応じて更新されます。

  1. [設定] から、[クイック検索] ボックスに「投稿テンプレート」と入力し、[投稿テンプレート] を選択します。

Classic 承認プロセスからの承認申請へのメール返信のトラブルシューティング

メールでの返答が正常に機能しない場合、次の一般的な問題を確認します。

必要なエディション

使用可能なインターフェース: Salesforce Classic および Lightning Experience の両方
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition
重要 従来の承認プロセスに代わる最新のフロー承認プロセスをお試しください。この新しい機能は、より柔軟でユーザーフレンドリーなフローベースのインターフェースを提供し、レコードの変更時にトリガーできます。また、Apex の拡張性とコンプライアンス、そして監査履歴の詳細なログ記録をサポートしています。特定のオブジェクトに関連付けられており、条件を使用してプロセスのサポートが制限されている従来の承認プロセスとは異なり、データとビジネスルールに基づく動的ルーティングがサポートされます。フロー承認プロセスを使用すると、申請済みレコードを監視してボトルネックをすばやく特定できるため、承認ワークフローをこれまでにないほど可視化できます。また、Classic 承認プロセスと同様に、フロー承認プロセスではオートメーションクレジットやオーケストレーションの実行は消費されません。

承認申請のメール通知を受信できない。

考えられる原因は次のとおりです。

  • 承認設定で承認申請メールを受信しないようにしている。
  • メールサーバーにより承認申請メールがスパムとみなされている。すべての受信メールのログを確認できるメール管理者に問い合わせて、メールが配信されているか、受信拒否されていないか、またはスパムのフラグが付いていないかを確認します。
  • メール管理者が承認申請の送信元の Salesforce メールアドレスをメールサーバーで許可されるメールアドレスに追加する必要がある。
  • メールの配信時間が ISP または接続によって異なる。

返答が配信されなかった。

  • メール承認申請は、一度しか処理されません。自分が返答する前に他のユーザーが承認申請に返答すると、エラーになります。
  • 承認申請にメールで返答するには「API の有効化」ユーザー権限が必要です。

「The word used to approve or reject the item was not understood.」という内容のメールを受信した。

Salesforce はエラーメールへの返信を処理しません。元のメール通知に再度返信します。ただし、今回はサポートされている返答の単語のいずれかを使用します。

「You are not authorized to update the referenced object.」という内容のメールを受信した。

承認申請メールはメールアドレスに関連付けられています。申請を他のメールアドレスに転送するか、メールクライアントで複数のメールアドレスに返答できるようになっていると、このエラーを受信します。元のメール通知に再度返信します。ただし今回はメール承認申請を受信したメールアドレスから返信します。

代理承認者

従来の承認プロセスの代理承認者とは、割り当てられた承認者が承認申請の代行者として指名したユーザーです。

メモ 内部 Salesforce ユーザーは、[代理承認者] 参照項目を使用してリストされます。また、この項目を使用して追加することもできます。データローダーとカンマ区切り (CSV) ファイルを使用して、コミュニティライセンスのあるユーザーを代理承認者として追加します。CSV では、DelegatedApproverId の UserId ではなく CommunityUserId が使用されます。コミュニティライセンスは Experience Cloud サイトと従来のポータルで使用されます。

メール承認

メール承認により、ユーザーはメール通知に返信して承認申請に返答できます。

申請時のアクション

従来の承認プロセスの最初の送信アクションは、ユーザーが従来の承認プロセスを使用してレコードの承認を申請したときに実行されます。デフォルトでは、レコードはロックされます。

最終承認時のアクション

従来の承認プロセスの最終承認アクションは、必要なすべての承認が取得されたときに実行されます。

最終却下時のアクション

従来の承認プロセスの最終却下時のアクションは、承認者が申請を却下し、最終却下状態に移行したときに実行されます。

送信メッセージ

従来の承認プロセスの送信メッセージでは、外部サービスなどの指定されたエンドポイントに情報が送信されます。送信メッセージは、[設定] から設定できます。外部エンドポイントを設定し、SOAP API を使用してメッセージのリスナーを作成します。

プロセスインスタンス

プロセスインスタンスは、従来の承認プロセスの 1 つのインスタンスを表します。従来の承認プロセスを使用してレコードが承認申請されるたびに、新しいプロセスインスタンスが作成されます。

プロセスインスタンスノード

プロセスインスタンスノードは、従来の承認プロセスの承認ステップのインスタンスを表します。従来の承認プロセスでレコードがステップに入るたびに、プロセスインスタンスノードが作成されます。レコードがステップ条件を満たしていない場合、または従来の承認プロセスインスタンスがステップに進まずに完了した場合、プロセスインスタンスノードは作成されません。

取り消し時のアクション

取り下げアクションは、従来の承認プロセスの承認要求が取り下げられたときに実行されます。デフォルトでは、レコードはロック解除されます。

レコードのロック

レコードのロックでは、項目レベルのセキュリティや共有設定に関係なく、ユーザーがレコードを編集できないようにします。デフォルトでは、Salesforce は従来の承認プロセスを使用して承認待機中のレコードをロックします。システム管理者のみが、ロックされたレコードを編集できます。

フロー承認プロセスを使用した承認の自動化

会社の成長に伴い、承認の複雑さも増し、多くの場合、異なるタイムゾーンの異なる部門の複数の担当者からの入力が必要になります。この複雑さにより、各ユーザーが適切な順序でレビューを完了するまでの待ち時間が長くなります。フロー承認プロセスは、ユーザー、システム、条件付きパスを含む複数ステップのレビューを調整するのに役立ちます。

フロー承認プロセス

フロー承認プロセスを使用して、レコードの複数ステップのレビュープロセスを作成します。フロー承認プロセスは、承認申請されたレコードを確認できる 1 つ以上のステップを含む一連のフェーズです。フェーズには、承認ステップまたはバックグラウンドステップを含めることができます。フロー承認プロセスの決定要素を使用して、条件に基づいて実行するパスを決定します。

フロー承認プロセスの各承認ステップでは、承認作業項目をユーザー、グループ、またはキューに割り当てます。バックグラウンドステップでは、承認申請に関連するアクションを完了しますが、ユーザー操作は必要ありません。Salesforce システム管理者は、オブジェクトのフロー承認プロセスを有効化する前に、確認するレコードタイプのページレイアウトにオーケストレーション作業ガイド Lightning アプリケーションビルダーコンポーネントを配置します。

誰かがレコードの承認を申請したとき、または対象レコードが作成または更新されたときに、関連付けられたフロー承認プロセスが実行されます。承認者と代理人は、レコードへのリンクが記載されたメール通知を受信します。レコードへの編集アクセス権を持つ承認者または代理人は、オーケストレーション作業ガイドでレコードを開いて、割り当てられたアクションを完了できます。または、承認者または代理者は、指定されたキーワードを使用して通知に返信することで、作業項目を承認または却下できます。通知に十分な情報に基づいて意思決定を行うのに十分な詳細が含まれていない場合、承認者と代理者は返信する前にレコードを参照できます。

  • フロー承認プロセスのリファレンス

障害パスへの決定要素の追加

決定要素を使用して、障害パスで実行されるフェーズを制御する条件を作成します。

障害パスが定義されたフェーズを含むフロー承認プロセスが必要です。

決定要素を使用して、誰も承認作業項目を完了せずに承認申請を承認しないようにします。「フロー承認プロセスのエラー処理での障害パス自動承認の回避」を参照してください。

複数のステップを含むフェーズで障害パスが設定されている場合、決定要素を使用してエラーが発生したステップを判断します。

  1. [障害パス] で、[] をクリックし、[決定] を選択します。
  2. 表示ラベル、API 参照名、説明を入力します。
  3. 決定要素に使用する決定ロジックの種別を選択します。
    • 従来のロジック式とフロー承認プロセスで明示的に定義されたデータに基づいて実行される結果を決定するには、[手動定義 (デフォルト)] を選択します。
    • フロー承認プロセスのデータを評価している AI に基づいて実行される結果を動的に判別するには、[Define with AI (Advanced) (AI で定義 (詳細))] を選択します。
  4. [手動で定義 (デフォルト)] を選択した場合は、要素の条件と結果を定義します。手動条件が含まれる決定要素の結果は、リストの順序で評価されます。そのため、結果を定義する順序は、親承認申請に関連付けられたオーケストレーションの実行の結果に影響する可能性があります。
    1. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名は、フロー承認プロセス内で一意である必要があります。
    2. 最初の結果に使用する条件の要件を定義します。
      オプション 決定結果の動作
      すべての条件に一致 いずれかの条件が false の場合、フロー承認プロセスで次の結果の条件が評価されます。
      いずれかの条件に一致 いずれかの条件が true の場合、フロー承認プロセスは直ちにこの結果のパスを使用します。
      カスタム条件ロジックに一致

      このオプションを選択する場合は、最大 1,000 文字を入力して条件ロジックを指定します。以下を使用します。

      • 各条件を参照する数値
      • どのような条件の組み合わせが true となる必要があるのかを識別する AND、OR、NOT
      • 文字列の一部をグループ化するための括弧

      AND を入力した場合は、[すべての条件に一致] を選択した場合と同じです。OR を入力した場合は、[いずれかの条件に一致] を選択した場合と同じです。その他のロジックを入力する場合は、各条件の番号を含めるようにします。

      たとえば、1 AND NOT(2 OR 3) の場合、フローは最初の条件が true であることと、2 番目および 3 番目の条件の両方が true でないことを評価します。
    3. 最初の結果のロジック条件を定義します。
      列ヘッダー 説明
      リソース

      オプション:

      • フェーズまたはステップから入力変数または自動出力を選択する
      • 決定要素を選択する
      • グローバル変数を選択する
      演算子 使用可能な演算子は、[リソース] に選択されたデータ型によって異なります。「決定要素のフロー承認プロセス演算子」を参照してください。
      値

      同じ行の [リソース] と [値] のデータ型は、互換性がある必要があります。

      オプション:

      • フェーズまたはステップからの入力変数や自動出力などのフロー承認プロセスリソースを選択します。
      • グローバル変数を選択する
      • リテラル値を入力する。

      日付値から数値を加算または減算すると、日付は時間単位ではなく日単位で調整されます。
  5. [AI で定義 (詳細)] を選択した場合は、要素の指示と結果を定義します。
    1. [決定手順] に、要素による決定を説明するテキストを入力します。AI の精度を高めるために、フロー承認プロセスのリソースを含めます。
    2. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名は、フロー承認プロセス内で一意である必要があります。
    3. [結果の手順] に、AI に結果を取得するタイミングを指示するテキストを入力します。AI の精度を高めるために、フロー承認プロセスのリソースを含めます。AI 条件が含まれる決定要素の結果は同時に評価されます。そのため、結果を定義する順序は、親承認申請に関連付けられたオーケストレーションの実行の結果には影響しません。
  6. (省略可能) 決定結果を決定要素に追加するには、[] をクリックします。決定要素種別に適した手順を繰り返して、結果を設定します。手動条件については、ステップ 3b を参照してください。AI 条件については、ステップ 4b を参照してください。
  7. (省略可能) [決定] 要素の決定結果を並び替えるには、[] をクリックし、項目を新しい場所にドラッグします。デフォルトの結果は常に最後であるため、条件を含む決定結果をリストの最後の位置に移動することはできません。
  8. (省略可能) 決定要素の読みやすさを向上させるには、デフォルトの結果の名前を変更します。
    1. [結果の順序] で、[デフォルトの結果] を選択します。
    2. 表示ラベルを入力します。
  9. 作業内容を保存します。

フェーズへの承認ステップの追加

フロー承認プロセスフェーズに障害パスが設定されていて、関連付けられたオーケストレーション実行のフェーズでエラーが発生した場合、完了した承認作業項目なしで、関連付けられた承認申請を自動的に承認できます。障害パスのフェーズに承認ステップを追加して、承認作業項目をレビュー担当者に割り当てます。

フロー承認プロセスに関連付けられた承認申請の最終処理にエラーがどのように影響するかについては、「フロー承認プロセスのフェーズの障害パス」を参照してください。

承認ステップは、関連付けられているフローを実行せずに完了できます。承認作業項目に直接関連するアクションのみが含まれる承認ステップの画面フローを参照します。関連レコードの更新や関係者へのエラー通知の送信などの追加アクションを実行するには、バックグラウンドステップを使用します。

  1. ステージ要素で、[+ ステップを追加] をクリックし、[承認ステップ] を選択します。
  2. 表示ラベル、API 参照名、説明を入力します。
  3. (省略可能) [ステップを開始するタイミングを選択] で、条件を選択します。
    • フェーズの開始時にステップを自動的に開始するには、[フェーズの開始時にステップを開始します] を選択します。
    • 別のステップが完了した後にステップを開始するには、[別のステップが [完了] とマークされたら、ステップが開始します] を選択します。次に、最初に完了するステップの名前を入力します。
    • ステップを開始する前に満たすべき要件を最大 10 個指定するには、[指定された要件が満たされたら、ステップを開始します] を選択します。次に、要件を設定します。
    • 複雑な要件を使用してステップの開始時期を決定するには、[指定された評価フローが True を返した場合、ステップが開始します] を選択します。次に、有効な評価フローを選択します。
  4. [実行するアクションを選択] で、ステップで実行する approvalDecision という名前のテキスト出力変数を含む有効な画面フローを選択します。選択したフローの必須入力の値またはリソースの API 参照名を指定します。「承認ステップで実行するアクションの選択」を参照してください。
    ヒント 承認者は、関連付けられた画面フローを実行せずに承認作業項目を承認または却下できます。画面フローが実行されない可能性があるため、承認の決定に必要な情報のみを含めます。他のアクションを実行するには、承認ステップの後にバックグラウンドステップを使用します。
  5. [承認者を選択] で、割り当て種別を選択します。
    • ユーザーを指定するには、[ユーザー] を選択します。
    • 通常の公開グループを指定するには、[グループ] を選択します。
    • キューであるグループを指定するには、[キュー] を選択します。
    • 承認申請に関連付けられたオーケストレーションの実行時にユーザーのユーザー名、グループの API 参照名、またはキューの API 参照名を含むリソースを指定するには、[リソース] を選択します。
  6. 割り当てられたユーザー、グループ、またはキューを指定します。
    • [ユーザー] を選択した場合は、内部ユーザーまたはログイン情報のある Experience Cloud サイト訪問者の名前を検索し、リストから選択します。
    • [グループ] を選択した場合は、グループの表示ラベルを検索してリストから選択します。
    • [キュー] を選択した場合は、キューの表示ラベルを検索してリストから選択します。
    • [リソース] を選択した場合は、承認申請に関連付けられたオーケストレーションの実行時に、割り当て先のユーザー名、グループの API 参照名、またはキューの API 参照名が含まれる変数の API 参照名を選択します。
    重要 [リソース] で [$User] を選択しないでください。$User グローバル変数は、フロー承認プロセスがシステムコンテキストで実行されているときにシステムユーザーに評価されます。承認ステップをシステムユーザーに割り当てることはできません。
  7. (省略可能) このステップの承認作業項目が作成されたときに承認者とその代理人にカスタムメール通知を送信するには、[通知メールのカスタマイズ] を選択します。パーソナライズされたメールの件名と本文のテキストテンプレートを作成し、件名と本文の API 参照名を入力します。または、メールの件名と本文のテキストを入力します。
  8. [アクションを完了する場所を選択] で、承認するレコードの ID が含まれる変数の API 参照名を選択します。
    1. 承認申請に関連付けられたオーケストレーションの実行が実行され、承認ステップが開始されたときにレビュー中のレコードをロックするには、[レコードをロック] を選択します。承認者またはその代理人が承認ステップを完了すると、レコードは自動的にロック解除されます。
    2. ロックされているときに承認者がレビュー中のレコードを編集できるようにするには、承認者がロックされたレコードを編集できるようにする を選択します。
  9. (省略可能) [ステップを完了するタイミングを選択] で、条件を選択します。
    • 承認者またはその代理人が関連付けられた作業項目を完了したときにステップを完了するには、割り当てられたユーザーが画面フローを完了したら、ステップは完了とマークされます を選択します。
    • ステップを完了する前に満たすべき要件を最大10個指定するには、指定された要件が満たされたら、ステップは完了とマークされます を選択します。次に、要件を設定します。
    • 複雑な要件を使用してステップを完了する前に満たすには、[指定された評価フローが True を返すと、ステップは完了とマークされます] を選択します。次に、作成、テスト、有効化した評価フローを選択します。

障害パスの実行後の処理の続行

デフォルトでは、障害パスは終了要素を含むフロー承認プロセスに追加されます。障害パスをフロー承認プロセスに戻すには、Go To コネクタを使用します。

フロー承認プロセスに最終アクションが含まれる場合、Go To コネクタを使用して、これらのアクションを管理する決定要素に障害パスを転送します。この方法により、フェーズエラーによって障害パスがトリガーされた場合でも、フロー承認プロセスに関連付けられたオーケストレーションの実行が意図したとおりに進行します。

  1. 障害パスで、コネクタを変更する終了要素の直前にある [] をクリックします。
  2. [要素に接続] をクリックします。
  3. 接続先の要素の をクリックします。

終了要素ではなく、障害パスに、指定された要素への点線接続が追加されました。

フロー承認プロセスへの取り消しアクションの追加

進行中のフロー承認プロセスが取り消されたときにステップを実行するには、取り消しパスを追加します。取り消しパスには、バックグラウンドステップを含む 1 つのフェーズを含めることができます。申請が取り消されると、進行中のフェーズとその完了していないすべてのステップがキャンセルされます。未承認の作業項目もキャンセルされます。次に、取り消しパスのフェーズが実行されます。取り消しパスのフェーズが完了すると、承認申請が取り消されます。

Salesforce は、フロー承認プロセスを使用してレコードが承認申請されると、承認申請を作成します。各承認申請には、オーケストレーションの実行が関連付けられています。

フロー承認プロセスの作成

承認プロセスの自動化は、承認部分がどのように組み合わされるかを理解しておくと簡単です。フロー承認プロセスを作成する前に、関係者と話して要件を理解します。必要な情報をすべて把握していなくても、ドラフトのフロー承認プロセスは保存できますが、フロー承認プロセスを有効化して実行する前に、関連付けられたすべてのフローと設定の詳細を指定する必要があります。

  • フロー承認プロセスの作成
    Approvals アプリケーションで自動起動フロー承認プロセスを作成します。[設定] で、自動起動またはレコードトリガーフロー承認プロセスを作成します。
  • フロー承認プロセスでの決定
    決定要素を使用して、フロー承認プロセスで実行されるフェーズを制御する条件を作成します。
  • 承認者とやりとりするステップの作成
    承認ステップを作成して、フロー承認プロセスを特定のユーザー、グループ、キューに割り当てます。承認ステップでは、割り当てられた承認者が関連付けられたフローを実行するかどうかに関係なく承認または却下できる作業項目が生成されます。[プロセスの自動化設定] でメール承認応答を有効にすると、承認者はメールで承認作業項目を完了できます。
  • 承認者へのメールのカスタマイズ
    デフォルトでは、承認申請に関連付けられたオーケストレーションの実行で承認作業項目が作成されるたびに、割り当てられた承認者と代理承認者に通知が送信されます。承認者と代理承認者の両方に送信するメール通知を変更するには、関連付けられた承認ステップをカスタマイズします。
  • フロー承認プロセスのフェーズとステップの要件の定義
    要件を使用して、レコードが変更されたときにオーケストレーションの実行を再開します。最大 10 個の要件を定義して、ステップを開始するタイミングや、フェーズまたは承認ステップを完了としてマークするタイミングを決定します。
  • オムニチャネルを使用して承認作業項目をルーティングする
    承認作業項目でサービスでオムニチャネルルーティングを使用するには、1 つ以上のキューを承認作業項目オブジェクトに関連付ける必要があります。そのキューに承認ステップを割り当てると、キューのメンバーはルーティングロジックに基づいてオムニチャネルウィジェット経由で通知を受信します。承認作業項目のデフォルトのメール通知を無効にしない限り、キューのメンバーにもメール通知が送信されます。
  • フロー承認プロセスで次に実行される要素の制御
    フロー承認プロセスでは、Flow Builder で自動レイアウトが使用されます。自動レイアウトでは、キャンバスの要素が自動的に間隔を空けて配置され、接続されます。通常の連続する自動レイアウトパスに従わない要素がある場合、Go To コネクタを使用します。
  • フロー承認プロセスパスへの終了要素の追加
    フロー承認プロセスのすべての要素は自動的に接続されるか、手動で追加した Go To コネクタで接続されます。フロー承認プロセスのパスを完了するには、End 要素を追加します。
  • フロー承認プロセスでの自動出力の使用
    フロー承認プロセスには、そのフェーズ、ステップ、決定の出力へのアクセス権があります。フロー承認プロセスのフェーズまたはステップの状況を照会します。ステップに関連付けられたフローの出力パラメーターを使用します。フロー承認プロセスでは、レコードまたはレコードコレクションを含む参照される自動出力は、承認申請に関連付けられたオーケストレーションの実行が再開されるたびに最新の値で更新されます。
  • フロー承認プロセスへの取り消しアクションの追加
    進行中のフロー承認プロセスが取り消されたときにステップを実行するには、取り消しパスを追加します。取り消しパスには、バックグラウンドステップを含む 1 つのフェーズを含めることができます。申請が取り消されると、進行中のフェーズとその完了していないすべてのステップがキャンセルされます。未承認の作業項目もキャンセルされます。次に、取り消しパスのフェーズが実行されます。取り消しパスのフェーズが完了すると、承認申請が取り消されます。
  • フロー承認プロセスのフェーズエラーの処理
    フロー承認プロセスのエラーを処理するように障害パスを設定します。各フェーズの障害パスを作成し、そのフェーズまたはそのステップでエラーが発生したときにトリガーする要素を追加します。このアプローチにより、フェーズエラーが原因で承認申請が失敗する可能性を最小限に抑えます。
  • フロー承認プロセステンプレートの使用
    既存のフロー承認プロセスに基づいてテンプレートを作成するか、既存のフロー承認プロセスをテンプレートに変換します。次に、Flow Builder で他のフロー承認プロセスを作成するための開始点としてテンプレートを使用します。購読者がテンプレートに基づいてフロー承認プロセスを作成できるように、管理パッケージを介してテンプレートを配布することもできます。
  • 割り当てられた承認者が承認作業項目にアクセスできるようにする
    承認申請に関連付けられたオーケストレーションの実行で承認ステップが実行されると、デフォルトで、割り当てられた承認者、グループ、またはキューとその代理者に通知がメールで送信されます。内部ユーザーとログイン情報のある Experience Cloud サイト訪問者は、割り当てられた作業を複数の方法で完了できます。

決定要素で 2 つの可能な結果が提供される場合、最初の結果の条件が満たされない場合にのみデフォルトの結果が適用されます。

決定要素に 3 つ以上の結果候補がある場合、リストの順序で評価されます。各結果について:

  • その条件がチェックされます。
  • 条件が true の場合、その結果に関連付けられたパスが実行されます。
  • 条件が false の場合、リスト内の次の結果の条件が評価されます。

実行時に、指定した順序で条件が評価されます。

  1. フロー承認プロセスで、要素を挿入する場所をクリックし、[決定] を選択します。
  2. 表示ラベル、API 参照名、説明を入力します。
  3. 決定要素に使用する決定ロジックの種別を選択します。
    • 従来のロジック式とフロー承認プロセスで明示的に定義されたデータに基づいて実行される結果を決定するには、[手動定義 (デフォルト)] を選択します。
    • フロー承認プロセスのデータを評価している AI に基づいて実行される結果を動的に判別するには、[Define with AI (Advanced) (AI で定義 (詳細))] を選択します。
  4. [手動で定義 (デフォルト)] を選択した場合は、要素の条件と結果を定義します。手動条件が含まれる決定要素の結果は、リストの順序で評価されます。そのため、結果を定義する順序は、親承認申請に関連付けられたオーケストレーションの実行の結果に影響する可能性があります。
    1. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名は、フロー承認プロセス内で一意である必要があります。
    2. 最初の結果に使用する条件の要件を定義します。
      オプション 決定結果の動作
      すべての条件に一致 いずれかの条件が false の場合、フロー承認プロセスで次の結果の条件が評価されます。
      いずれかの条件に一致 いずれかの条件が true の場合、フロー承認プロセスは直ちにこの結果のパスを使用します。
      カスタム条件ロジックに一致

      このオプションを選択する場合は、最大 1,000 文字を入力して条件ロジックを指定します。以下を使用します。

      • 各条件を参照する数値
      • どのような条件の組み合わせが true となる必要があるのかを識別する AND、OR、NOT
      • 文字列の一部をグループ化するための括弧

      AND を入力した場合は、[すべての条件に一致] を選択した場合と同じです。OR を入力した場合は、[いずれかの条件に一致] を選択した場合と同じです。その他のロジックを入力する場合は、各条件の番号を含めるようにします。

      たとえば、1 AND NOT(2 OR 3) の場合、フローは最初の条件が true であることと、2 番目および 3 番目の条件の両方が true でないことを評価します。
    3. 最初の結果のロジック条件を定義します。
      列ヘッダー 説明
      リソース

      オプション:

      • フェーズまたはステップから入力変数または自動出力を選択する
      • 決定要素を選択する
      • グローバル変数を選択する
      演算子 使用可能な演算子は、[リソース] に選択されたデータ型によって異なります。「決定要素のフロー承認プロセス演算子」を参照してください。
      値

      同じ行の [リソース] と [値] のデータ型は、互換性がある必要があります。

      オプション:

      • フェーズまたはステップからの入力変数や自動出力などのフロー承認プロセスリソースを選択します。
      • グローバル変数を選択する
      • リテラル値を入力する。

      日付値から数値を加算または減算すると、日付は時間単位ではなく日単位で調整されます。
  5. [AI で定義 (詳細)] を選択した場合は、要素の指示と結果を定義します。
    1. [決定手順] に、要素による決定を説明するテキストを入力します。AI の精度を高めるために、フロー承認プロセスのリソースを含めます。
    2. 表示ラベルと結果 API 参照名を入力します。結果の API 参照名は、フロー承認プロセス内で一意である必要があります。
    3. [結果の手順] に、AI に結果を取得するタイミングを指示するテキストを入力します。AI の精度を高めるために、フロー承認プロセスのリソースを含めます。AI 条件が含まれる決定要素の結果は同時に評価されます。そのため、結果を定義する順序は、親承認申請に関連付けられたオーケストレーションの実行の結果には影響しません。
  6. (省略可能) 決定結果を決定要素に追加するには、[] をクリックします。決定要素種別に適した手順を繰り返して、結果を設定します。手動条件については、ステップ 3b を参照してください。AI 条件については、ステップ 4b を参照してください。
  7. (省略可能) [決定] 要素の決定結果を並び替えるには、[] をクリックし、項目を新しい場所にドラッグします。デフォルトの結果は常に最後であるため、条件を含む決定結果をリストの最後の位置に移動することはできません。
  8. (省略可能) 決定要素の読みやすさを向上させるには、デフォルトの結果の名前を変更します。
    1. [結果の順序] で、[デフォルトの結果] を選択します。
    2. 表示ラベルを入力します。

  • 割り当てられた承認作業項目をレコードページでアクセス可能にする
    承認ステップで参照されるレコードタイプのレコードページレイアウトにオーケストレーション作業ガイドコンポーネントを追加します。割り当てられたユーザーが承認作業項目にアクセスして完了できるようにコンポーネントを設定します。
  • Experience Cloud サイトでの割り当て済み承認作業項目へのアクセス
    承認ステップで参照されるレコードタイプのオーケストレーション作業ガイドコンポーネントを Aura および LWR サイトの関連レコードページに追加します。
