画面フローでのカスタムエラーメッセージの表示

障害パスを画面フローに追加して、要素で障害が発生した場合に役立つメッセージを表示します。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
メモ 「フローの管理」権限を持つ管理者である必要はありません。プロファイルまたは権限セットに追加するようにシステム管理者に依頼してください。

この方法は、画面を表示可能なフローでのみ使用します。カスタムエラーメッセージにより、フローの実行者は、要素で障害が発生した場合に役立つ指針を得ることができます。

  1. [フロー] リストビューを開きます。
    • Automation アプリケーションから、[フロー] タブを選択します。
    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] の [クイック検索] ボックスに「フロー」と入力し、[フロー] を選択します。
    [オートメーションアプリケーション] および [フロー] タブのオプションには、[設定] アクセス権は必要ありません。
  2. Flow Builder で更新する画面フローを開きます。
  3. 役に立つエラーメッセージを含むテキストテンプレートを作成します。手順については、「テキストテンプレートを使用したフローでのメールの送信」の「テキストテンプレートの作成および設定」セクションを参照してください。 
    <p><b>Something went wrong with this flow.</b></p>
<p>Contact your administrator for help.</p>
  4. 障害が発生する可能性がある要素の場合、3 つの点をクリックし、[障害パスを追加] を選択します。
  5. 画面要素を障害パスに追加します。
    1. 障害パスで、[] をクリックし、[画面] を選択します。
    2. 画面の表示ラベルを入力し、API 参照名の自動入力を受け入れます。
    3. [コンポーネント] で、[表示テキスト] を選択します。
    4. テキスト ボックスの [リソースの挿入] フィールドで、作成したテキスト テンプレートを選択します。
    5. [完了] をクリックします。
  6. フローを実行しているユーザーがエラーを修正できる場合は、エラー画面の原因となった入力を修正できる画面にエラー画面を接続します。
    1. エラー画面の後、[] をクリックし、[要素に接続] を選択します。
    2. ユーザーが入力を修正できる画面を選択します。
  7. 障害パスが必要な要素ごとに、エラー画面を追加して、フローを実行しているユーザーがエラーの原因となった入力を修正できる画面に接続します。
  8. フローを保存します。

フロールートを変更するための要素の移動と接続

キャンバス上の要素を接続して、フローが実行する要素とその順序を特定します。実行順序を変更するには、要素を移動してコネクタを追加または削除します。

Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」

自動レイアウトでのフローの経路設定

自動レイアウトの場合、Flow Builder は、要素が追加されるとコネクタを自動的に作成し、要素が削除されるとコネクタを削除します。必要な順序で要素を配置します。実行順序を変更するには、要素を移動します。

自動レイアウトでの単一の要素の移動

自動レイアウトでは、要素を直接移動できません。そのため、1 つの要素の場所を変更するには、要素を切り取ってから新しい場所に貼り付けます。

  1. 移動する要素をクリックします。
  2. [要素を切り取り] を選択します。
  3. 要素を配置する場所で、 をクリックしてから、 をクリックして貼り付けます。

決定要素または待機要素を切り取るときは、切り取った後にキャンバスで結果または設定のパスからの要素をそのままにできます。キャンバスでパスから要素を保持するには、切り取り要素パネルでパスを選択します。決定要素または待機要素とそのすべてのパスを切り取るには、切り取り要素パネルから [なし、すべてのパスを切り取り] を選択します。

自動レイアウトでの複数の要素の移動

複数の要素を移動するには、移動するすべての要素を選択し、コピーして新しい場所に貼り付けた後、元の要素を削除します。

  1. [要素を選択] をクリックします。
  2. 移動する各要素の をクリックします。
  3. 選択した要素をコピーするには、 をクリックします。
  4. 要素を配置する場所で、[] をクリックします。
  5. [要素を貼り付け] を選択します。
  6. コピーした要素ごとに、要素をクリックして [要素を削除] を選択します。

自動レイアウトでの連続しない要素の接続

自動レイアウトでは、キャンバスの要素が自動的に間隔を空けて配置され、接続されます。自動的に接続されない要素を接続するには、Go To コネクタを使用します。

  1. コネクタを Go To コネクタに変更するには、接続元の要素のすぐ後で、 にを置いて をクリックします。
  2. [要素に接続] をクリックします。
  3. 接続先の要素の をクリックします。

自由形式でのフローの経路設定

自由形式の場合は、キャンバス上の要素の実行順序を決定するコネクタを自分で作成および削除します。

  1. キャンバスで、接続元要素の下のノードを探します。
  2. そのノードを接続先要素にドラッグします。
  3. 促されたら、パスに割り当てる決定結果または待機設定を選択します。

自由形式のフローからのコネクタの削除

自由形式レイアウトでフローの実行パスを変更する必要がある場合は、コネクタを削除してから新しいコネクタを追加します。

  1. フローで、削除するコネクタを選択します。
    コネクタを選択すると、その色が灰色から青に変わります。
  2. Delete キーを押します。

決定要素の特定の結果のコネクタを削除しても、結果はソース要素から削除されません。ただし、決定要素から結果を削除すると、結果のコネクタも削除されます。

[条件を待機] 要素も同様に機能します。条件待機要素の特定のパスのコネクタを削除しても、そのパスはソース要素から削除されません。ただし、[条件を待機] 要素からパスを削除すると、パスのコネクタも削除されます。

フローでのデータの変換

[変換] 要素を使用して、Salesforce と外部システム間でのデータの変換を自動化します。取得元データと取得先データの対応付けを作成したり、取得先データの固定値を設定したりできます。

必要なエディション

サポートされているエディションを表示する。
必要なユーザー権限
Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
メモ 「フローの管理」権限を持つ管理者である必要はありません。プロファイルまたは権限セットに追加するようにシステム管理者に依頼してください。

Flow Builder でのデータ変換のデモ (英語のみ) をご覧ください。

別の表示オプションについては、「Flow Builder を使用したデータの変換」を参照してください (英語のみ)。

開始する前に、変換元データと変換先データの構造 (データに他のコレクション内の複数レベルのコレクションが含まれているかどうかなど) を把握します。コレクションの項目を対応付けるには、データの整合性を維持するためのルールが必要です。「変換要素」を参照してください。

  1. [変換] 要素をフローに追加します。
    1. 必要に応じて、生成された表示ラベルと説明を編集します。Flow Builder で要素の設定に基づいて生成され、API 参照名は表示ラベルに基づいて入力されます。
    2. [ソースデータ] で、[リソースを追加] ボタンをクリックし、データを変換するフローリソースを選択します。
    3. [対象データ] で、[リソースを追加] ボタン をクリックし、データ型を選択します。
    4. 変換先データがコレクションの場合、[複数の値を許可 (コレクション)] を選択します。
    5. データ型がレコードまたは Apex 定義の場合、変換要素で生成する対象データの Apex クラスまたはオブジェクトを選択します。
      たとえば、変換先データがコレクションであり、レコードデータ型が取引先オブジェクトであることを指定した場合、[変換] 要素は取引先コレクションを生成します。コレクションを指定しなかった場合、変換先データは 1 件の取引先になります。
  2. 変換元データと変換先データを対応付けます。
    1. 変換元データ項目にマウスポインターを置き、対応付けボタン をクリックします。
    2. 対象データ項目の横にある対応付けボタン をクリックします。
      変換先項目に [対応付け] ボタン 対応付けがない場合は、その項目に対応付けることはできません。
    3. マッピングできない対象項目またはコレクションの横に対応付けのヒントを表示するには、対象項目またはコレクションにマウスポインターを置き、エラーアイコンにマウスポインターを置きます。
    4. 誤設定エラーの対応付けのヒントを表示するには、対象データ項目またはコレクションの横に表示されるエラーアイコン にマウスポインターを置きます。
    変換要素では、折りたたまれたオブジェクトまたはコレクション内の対応付けを示す破線が追加されます。[変換] 要素は、対応付けられた項目が含まれるコレクションを識別するための点線を自動的に作成します。これにより、両方のリソースデータ構造で識別されるコレクションを簡単に確認できます。コレクションの項目を対応付けるには、変換元項目と変換先項目はそれぞれのリソース内で同じ階層レベルにある必要があります。「フロー要素: 変換」を参照してください。
  3. 数式でデータを変換するには、対応付けられた項目名をクリックして、[]、[数式] の順にクリックします。
  4. 対応付けを削除するには、項目名をクリックして、[削除] ボタン をクリックします。

    データの変換が完了したら、変換先データを Salesforce または外部システムに保存できます。

    変換先データを Salesforce に保存するには、[レコードを更新] 要素を追加して、[変換] 要素と同じ名前のリソースを参照するように設定します。たとえば、[変換] 要素の API 参照名が Return_Order の場合、[レコードを更新] 要素で Return_Order という名前のレコードまたはレコードコレクションを選択します。

    変換先データを外部システムに保存するには、POST などのメソッドを使用する HTTP コールアウトアクションを作成します。

例 営業エージェントが 2 件の注文をストアクレジットで返金する画面フローを実行します。エージェントの顧客には、Salesforce の取引先が割り当てられています。顧客の注文データは Salesforce の外部のシステムに保存されます。Salesforce の注文レコードを更新するには、フローで外部システムから最新の注文データを取得してデータを変換し、変更を Salesforce に保存できるようにします。

[変換] 要素では、amount、customerId、status の変換元データ項目が変換先データ項目に対応付けられます。

変換元データの amount 項目と変換先データの Amount__c 項目間の対応付けでは、数式を使用してデータが変換されます。

数式により、変換元データの amount 項目から補充手数料の固定金額が減算されます。数式の結果は、変換先データの Amount__c 項目の変換された値になります。数式には差し込み項目の構文が表示されます。[$EachItem] は、コレクションの各項目を表しています。この例では、差し込み項目で 2XX のコレクションが参照され、各 2XX 項目には amount 項目があります。各 amount 項目で、数式で 5 が減算されます。

次に、フローの [レコードを更新] 要素で変更をデータベースに保存します。最後に、[アクション] 要素で HTTP コールアウトを実行して、外部システムの注文状況を更新します。

変換要素を使用したコレクションの項目の集計

ソースコレクションのデータを集計して、そのコレクションの項目の合計または数を計算し、結果を対象データ項目に割り当てます。

Einstein for Flow や Agentforce for Flow など、Flow Builder で使用できるすべてのフロー タイプ、要素、機能を使用してフローを開く、編集、作成、有効化、または無効化する 「フローの管理」
メモ 「フローの管理」権限を持つ管理者である必要はありません。プロファイルまたは権限セットに追加するようにシステム管理者に依頼してください。

開始する前に、変換元データと変換先データの構造 (データに他のコレクション内の複数レベルのコレクションが含まれているかどうかなど) を把握します。コレクションの項目を対応付けるには、データの整合性を維持するためのルールが必要です。「フロー要素: 変換」を参照してください。

ソースコレクションの項目数を数えるか、ソースコレクションの各項目の項目値を加算して合計を計算します。

  1. [変換] 要素をフローに追加します。
    1. 必要に応じて、生成された表示ラベルと説明を編集します。Flow Builder で要素の設定に基づいて生成され、API 参照名は表示ラベルに基づいて入力されます。
    2. [ソースデータ] で、[リソースを追加] ボタンをクリックし、データを変換するフローリソースを選択します。
      集計するコレクションを参照するリソースを選択します。
    3. [対象データ] で、[リソースを追加] ボタン をクリックし、データ型を選択します。
    4. 変換先データがコレクションの場合、[複数の値を許可 (コレクション)] を選択します。
    5. レコードまたは Apex 定義のデータ型の場合、変換要素で生成する対象データの Apex クラスまたはオブジェクトを選択します。
      たとえば、変換先データがコレクションであり、レコードデータ型が取引先オブジェクトであることを指定した場合、[変換] 要素は取引先コレクションを生成します。コレクションを指定しなかった場合、変換先データは 1 件の取引先になります。
  2. ソースコレクションを数値データ型の対象データ項目に対応付けます。
    1. ソースコレクションにマウスポインターを置いて、「対応付け」ボタン をクリックします。
    2. 数値データ型の対象データ項目の横にある [対応付け] ボタン をクリックします。
      変換先項目に [対応付け] ボタン 対応付けがない場合は、その項目に対応付けることはできません。コレクションの項目を対応付けるには、変換元項目と変換先項目はそれぞれのリソース内で同じ階層レベルにある必要があります。「フロー要素: 変換」を参照してください。
  3. [Aggregate Type (集計種別)] で、[Count (件数)] または [Sum (合計)] を選択します。
  4. [変換する項目] で、ソースコレクションの各項目の変換元データ項目を選択して、変換後の値を計算します。
    この項目は、合計集計種別でのみ使用できます。
  5. フローを保存します。

会社のロケーション数を数えるように変換要素を設定します。

次に、CompanyDetails ソースコレクションを、変換された値を保存する NumberOfEmployees 対象データ項目に対応付けます。

すべてのロケーションの従業員の合計を計算するように変換要素を設定します。

Reactivity を使用した画面要素の動的化

サポートされているフロー画面コンポーネント、数式、画面アクションを使用して、画面を離れることなく画面コンポーネントをリアルタイムで更新します。このリアクティビティを利用することで、単一ページアプリケーションのような画面を作成できるため、ユーザーが作業を完了するために移動する必要がある画面の数を減らすことができます。このリアクティビティは API バージョン 59.0 以降でサポートされています。

必要なエディション

サポートされているエディションを表示する。

画面で反応型のインタラクションを作成する前に、インタラクションのソースとなる画面コンポーネントと、ソース内の変更に反応するコンポーネントを決定します。たとえば、次のように 3 つのコンポーネントがある画面を考えてみます。

  • ユーザーが値を選択できるスライダーコンポーネントが 2 つ
  • ユーザーがスライダーコンポーネントで選択した値の合計を表示する数値コンポーネント

このシナリオでは、スライダーコンポーネントは反応型インタラクションのソースであり、数値コンポーネントがソースの変更に反応します。反応型インタラクションの 3 つのコンポーネントはすべて、データ型が数値の値を生成します。反応型インタラクションを機能させるには、ソース値と反応型の値が同じである必要があります。

リアクティブな画面を作成するには、標準コンポーネントを使用するのが最も簡単です。カスタムフローコンポーネントを使用する場合は、必ず Lightning Web コンポーネント開発者ガイドでリアクティビティの例を確認してください。

  1. 画面フローを作成し、画面要素を画面フローに追加します。
  2. 画面要素で、反応型インタラクションのソースとなるコンポーネントを追加して設定します。
    たとえば、データテーブルコンポーネントを追加して設定します。このコンポーネントではユーザーが選択する名前のリストが表示されます。
  3. ソースコンポーネントの変更に反応するコンポーネントを追加して設定します。
    たとえば、名前コンポーネントを追加して [名] 項目を DataTableAPIName.firstSelectedRow.FirstName に設定します。名前コンポーネントには、ユーザーがデータテーブルで選択した最初の行の [名] の値が表示されます。
  4. フローを保存して実行します。

画面にリアクティビティを追加するときは、次の動作を考慮してください。

  • 手動のコンポーネント出力では、リアクティビティはサポートされません。コンポーネント出力を手動で設定すると、その変数が他のコンポーネントで参照されても、同じ画面上の変数は変更されません。
  • ヘルプテキストと表示ラベルは、他のコンポーネントの変更には反応しません。この考慮事項は、他のコンポーネントのイベントに応答するように設定されているカスタム Lightning Web コンポーネントの表示ラベルには当てはまりません。
  • リアクティビティをサポートするために出力を別のコンポーネントの入力に対応付ける場合、データ型を一致させる必要があります。
  • カスタムコンポーネントに入力規則が存在する場合、リアクティブな変更では入力規則はトリガーされません。
  • グローバル変数 $Flow はリアクティブです。カスタムラベル、カスタム設定、$Organization、$Profile など、その他のグローバル変数はリアクティブではありません。
  • DateTime 項目を Time に対応付けると、値は GMT に変換され、画面間を移動しても変換されたままになります。DateTime 項目に対応付けられている場合、地域情報は保持されます。たとえば、現在のロケールで午前 8 時であれば、変換された GMT 時刻は、ロケールとは数時間の時差がある可能性があります (例: 午後 4 時)。日付/時間とテキストの変換やタイムゾーンでの日付/時間については、「日付/時間およびタイムゾーンの留意点」の「数式での日付値、日付/時間値、および時間値の使用」を参照してください。
  • 画面アクションを使用した画面要素内のデータの取得または処理
    画面アクションでは、自動起動フローを使用してデータを取得または処理することで、画面要素を動的にします。画面アクションを使用すると、画面間で要素を追加する必要がなくなり、ユーザーが画面を切り替えてデータの更新を確認する必要がなくなります。ユーザーはクリックする画面数が少なくなるため、画面フローをすばやく完了できます。また、ユーザーはインタラクションに反応する画面からメリットを得られ、エンゲージメントが向上します。
  • 反応型画面フローコンポーネント
    すべての画面フローコンポーネントでリアクティビティがサポートされるわけではありません。実行するコンポーネントと適用される制限事項を確認します。
  • 反応型画面フローの数式演算子
    画面フローでサポートされる数式演算子の一部では、リアクティビティがサポートされます。
  • 反応型の画面を作成するための推奨事項
    反応型のコンポーネントと数式を使用して画面フローを作成する場合は、次の推奨事項に留意してください。
  • 1 画面での割引の計算と表示の例
    この例では、反応型の画面コンポーネントを使用して、営業担当が商品割引を即座に計算して表示できる 1 つの画面フローを作成します。
  • 選択した取引先の商談の取得の例
    この例では、ユーザーが取引先を選択し、関連する商談を取得するフローをトリガーして、結果をテーブルにすぐに表示できる画面フローを作成します。これらすべてを 1 つの画面内で行うことができます。

考慮事項

  • クロスオブジェクト数式では、リアクティビティはサポートされていません。クロスオブジェクト数式は、2 つの関連オブジェクトにまたがって、それらのオブジェクトの差し込み項目を参照するものです。たとえば、取引先がデータテーブルで選択されているとします。取引先名 (例: myContactDataTable.FirstSelectedRow.Account.Name) は反応型ではなく、同じ画面で参照されるコンポーネントには表示されません。

  • 反応型の数式が、初期値 null の項目に依存している場合、フローではユーザーが値を指定するまで数式が計算されません。反応型の数式を期待どおりに機能させるために、設定の null 値について検討してください。必要に応じて、BLANKVALUE 数式演算子を使用して null 値をゼロに設定します: BLANKVALUE({!resource},0)。
  • 反応型の数式は 3,900 文字までに制限されます。数式を保存すると、Salesforce によって数式が適切に機能するように文字が追加されます。結果として、指定した文字数が制限を下回っている場合でも、数式が文字制限を超えてしまう場合があります。文字数制限を超えると、リアクティビティがサポートされなくなります。

  • ヘルプテキストと表示ラベルは、他のコンポーネントの変更には反応しません。
  • リアクティビティをサポートするために出力を別のコンポーネントの入力に対応付ける場合、データ型を一致させる必要があります。
  • カスタムコンポーネントに入力規則が存在する場合、リアクティブな変更では入力規則はトリガーされません。
  • グローバル変数 $Flow はリアクティブです。カスタム表示ラベル、カスタム設定、$Organization、$Profile など、他のすべてのグローバル変数はリアクティブではありません。
  • DateTime 項目を Time に対応付けると、値は GMT に変換され、画面間を移動しても変換されたままになります。DateTime 項目に対応付けられている場合、地域情報は保持されます。たとえば、現在のロケールで午前 8 時であれば、変換された GMT 時刻は、ロケールとは数時間の時差がある可能性があります (例: 午後 4 時)。日付/時間とテキストの変換やタイムゾーンでの日付/時間については、「日付/時間およびタイムゾーンの留意点」の「数式での日付値、日付/時間値、および時間値の使用」を参照してください。

反応型の画面を作成するための推奨事項

反応型のコンポーネントと数式を使用して画面フローを作成する場合は、次の推奨事項に留意してください。

必要なエディション

サポートされているエディションを表示する。
  • コンポーネントの入力は別のコンポーネントの出力に直接対応付けてください。入力では「Hello there, {!Screen_Input_1}!」などの差し込み項目の参照を使用しないでください。その代わりに数式リソースを使用してください。
  • データを画面の変更イベントに接続せずに積極的にポーリングまたは照会するコンポーネントを使用しないでください。リアクティビティを使用してデータを照会する場合は、ユーザー権限を考慮して、想定されるパフォーマンスを達成するように結果を制限してください。
  • リアクティブな数式では null 値または空白の値をチェックして、計画的に使用してください。条件付き表示の要件を満たさない null 値または空白の値は、リアクティビティでは機能しません。
  • セルフ参照項目 (自身にテキストを付加する数式を使用している項目など) は、無限再帰を発生させる可能性がありますので注意してください。
  • 評価する数式入力が空白であるフローシナリオに備えて計画するか、対応を実施してください。

  • プリセットされたデフォルト値を使用して画面コンポーネントを追加する場合は、手動でリセットします。そうしないと、実行時にフローで認識されません。たとえば、 スライダーコンポーネントのデフォルト値は 0 です。 デフォルト値をリセットするには、 スライダーコンポーネントのデフォルト値を 1 に変更し、[範囲の最大値] などの別の項目をクリックします。デフォルト値を 0 に戻して、フローを保存します。

可能なフローフェーズの決定

画面フローが 1 つのパスのシンプルなフローである場合、すべてのフェーズを [デフォルトで有効] に設定し、フェーズを順番に並び替えます。たとえば、1、2、3、4、5 のようにします。

画面フローに複数のパスがある場合、特定のフェーズを有効にして進行状況インジケーターに表示するタイミングを計画します。また、進行状況インジケーターから特定のフェーズを削除するタイミングも計画します。フローの開始時に進行状況インジケーターにフェーズを表示しない場合は、フェーズをデフォルトで有効に設定しないでください。

  • スケジュールトリガーフロー
    スケジュールトリガーフローは、レコードのバッチに対して、指定された時間と頻度で開始されます。スケジュールトリガーは、自動起動フローの開始要素で設定します。
  • 保存前レコードトリガーフロー
    レコードを作成または更新すると、レコードがデータベースに保存される前に、そのレコードに追加の更新を行うレコードトリガーフローがトリガーされる場合があります。レコードトリガーフローでは、レコード変更プロセスよりも 10 倍速く Salesforce レコードを更新できます。レコードトリガーは、レコードトリガーフローの開始要素で設定します。
  • スケジュール済みパス
    レコードトリガーフローでスケジュール済みパスを使用して、スケジュールされた時間に別のパスで一部の要素を実行します。スケジュール時間は、レコードトリガーイベント、またはレコードの日付項目または日付/時間項目に基づいて設定できます。
  • 利用者フロー
    利用者フローはスケジュールに従って実行され、指定された利用者にメッセージを送信します。フローの作成時にデータソース (セグメント、リスト、レコード、キャンペーン) を選択します。
  • Segment Flows (セグメントフロー)
    セグメントフローは、スケジュールされた時間にセグメント内のユーザーにメッセージを送信します。フローを有効化すると、その時点でセグメント内のすべてのユーザーにメッセージが送信されます。
  • Data 360 データを使用したフローのトリガー
    Data Cloud トリガーフローは、データモデルオブジェクト (DMO) で条件が満たされたときに開始されます。
  • オンデマンドフロー
    オンデマンドフローは、REST API コールによってトリガーされます。たとえば、ユーザーがメンバーシッププログラムにサインアップした後、またはサイトでボタンをクリックした後にトリガーされる SMS メッセージを顧客に送信する自動化を作成します。
  • オートメーションイベントトリガーフロー
    顧客の注文、SMS サインアップ、サービスレベルの変更などのビジネスイベントに自動的に対応するイベントトリガーフローを作成します。用意されているトリガーから選択したり、Data 360、リアルタイムデータグラフを使用してカスタムトリガーを定義したり、エンゲージメントシグナルを使用してトリガーを作成したりできます。
  • レコードトリガーフローの管理
    フロートリガーエクスプローラーにより、レコードトリガーフローの表示、管理、並び替え、絞り込みを行えます。フロートリガーエクスプローラーには、すべてのフロー (指定されたオブジェクトに関連付けられているフローや、レコードの作成、更新、削除時に実行されるフロー) が表示されます。Flow Builder の特定のフローと、同じ環境下で実行されている他のフローとの間を移動できます。
  • オブジェクトのレコードトリガーフローの実行順序の定義
    トリガー順序値を指定して、同じオブジェクトの保存前フローまたは保存後フローの実行順序を決定します。

POST /services/data/v65.0/actions/custom/flow/FLOW_API_NAME

おそらく、プロセスビルダーに精通したユーザーは、レコード変更プロセスを使用して、プロセスをトリガーする各レコードに追加の更新を加えます。フロー内の保存前更新では、同じ目的をより短時間で達成できます。各レコードがデータベースに再度保存されないためです。この追加の保存手順を回避するには、実行に時間がかかる割り当てルール、自動レスポンスルール、ワークフロールール、その他のカスタマイズをスキップします。

おそらく Apex トリガーには慣れているでしょう。保存前更新を実行するフローは before トリガーに似ています。前述のレコード変更プロセスは after トリガーに似ています。保存手順で、フロー内の保存前更新は Apex beforeの直前に実行されます。

このスピードのため、フロー内で保存前更新を使用して、新規または変更されたレコードの項目を更新することをお勧めします。ただし、レコード変更プロセスまたは Apex afterトリガーを使用して次の操作を実行する必要がある場合があります。

  • 最終更新日項目や新規レコードの ID など、レコードの保存後にのみ設定される項目値にアクセスする。
  • 関連レコードを作成または更新する。
  • フローを起動するレコードの更新以外のアクションを実行する。

通常、保存前更新を実行するフローは、他の種別のフローよりも容易に作成できます。

  • $Record グローバル変数には、フローの実行をトリガーするレコードの値が含まれます。このため、レコードデータを取得するための [レコードを取得] 要素を追加したり、レコードデータを保存するためのフロー変数を作成したりする必要はありません。
  • フローで $Record グローバル変数の値が変更されると、Salesforce はその新しい値をレコードに自動的に適用します。このため、新しい値をデータベースに保存するためのレコードを更新要素を追加する必要はありません。
  • サポートされる要素は、割り当て要素、決定要素、レコードを取得要素、ループ要素のみです。これらの要素を使用して、他の Salesforce レコードからデータを取得し、そのデータを使用してトリガーレコードの項目を更新するかどうかと、どの値に更新するかを決定できます。

自動起動フローを特定の時間に開始するようにスケジュールし、実行する頻度 (1 回、毎日、または毎週) を設定します。レコードのバッチに対してスケジュール済みフローを実行するには、各レコードが満たす必要があるオブジェクトと検索条件を指定します。

フローへのスケジュール済みパスの追加

スケジュール済みパスは、アクションおよび関連レコード用に最適化されたレコードトリガーフローに対して作成できます。スケジュール済み時刻は、レコードの作成日時、更新日時、またはレコードの項目値を基に設定できます。

スケジュール済みパスはシステムコンテキストで実行されるため、すべてのデータにアクセスして変更する権限が与えられます。なお、フローのアクションに関連付けられる実行ユーザーは、レコードを最初に変更したユーザーになります。

スケジュール済みパスを作成する前に、組織のデフォルトワークフローユーザーを定義します。この設定により、フローをトリガーしたユーザーが無効な場合にどのユーザーをデフォルトにするかが Salesforce に指示されます。デフォルトユーザーが本番組織ですでに設定されている可能性もありますが、確認することをお勧めします。[デフォルトのワークフローユーザー] は、[設定] の [プロセスの自動化設定] ページで設定します。

  1. スケジュール済みパスを追加するには、フローの [開始] 要素で [スケジュール済みパスを追加 (省略可能)] をクリックします。フローにすでにスケジュール済みパスが含まれる場合にスケジュール済みパスを追加するか、既存のスケジュール済みパスを編集するには、[編集] をクリックします。

  2. パスの表示ラベルを入力します。API 参照名は自動的に生成されます。
  3. スケジュール済みパスの [時間ソース] を指定します。この時間は、トリガーイベント、またはレコードの指定された日付または日付/時間項目に基づくことができます。
  4. 選択した時間ソースの前後の指定した時間にスケジュール済みフローパスを実行するには、[オフセット番号] を入力し、[オフセットオプション] を選択します。それ以外の場合は、[オフセット番号] に「0」と入力します。
  5. バッチサイズを入力します。デフォルト値と最大値は 200、最小値は 1 です。 バッチサイズは、パスで同時に処理できるレコードの数です。たとえば、バッチサイズを 2 に指定し、同じ期間に 7 件のレコードがスケジュールされている場合、それらは 4 つのバッチで実行されます。Apex ガバナ制限に達しないようにするには、このフィールドを使用します。

[時間ベースのオートメーション] 設定ページでは、待機中のスケジュール済みパスを表示できます。[設定] から、[クイック検索] ボックスに「時間ベースのオートメーション」と入力し、[時間ベースのオートメーション] を選択します。

スケジュール済みパスでのバッチの設定

スケジュール済みパスは、同時に実行するように設定された多数のパスがある場合に一括で実行できます。

条件を満たし、同時に処理されるようにスケジュールされているすべてのレコードは、設定したバッチサイズまでバッチにグループ化されます。パスの実行間隔が 10 分に設定されている場合、パスはバッチ処理されません。

バッチサイズは、パスで同時に処理できるレコードの数です。デフォルト値と最大値は 200、最小値は 1 です。たとえば、同時に処理するレコードが 7 件あり、一括処理サイズを 2 に指定した場合、Flow Builder ではそれらを 4 つの一括処理にグループ化します。高度な機能でバッチサイズ値を設定できます。それ以外の場合は、デフォルトの 200 が使用されます。パスのバッチ・サイズを指定することで、トランザクションあたりのApex制限に達するのを回避できます。

非同期制限はスケジュール済みパスに適用されるため、制限に達することなく複雑な操作を簡単に完了できます。

考慮事項

スケジュール済みパスが [レコードが更新されるたび、条件に一致] で設定されていて、実行時間が項目ベース (たとえば、Opportunity.CloseDate の 1 時間前) の場合、フローはスケジュール済みパスが [レコードが更新されて条件に一致したときのみ] として設定されているかのように動作します。対応するエントリ条件が [レコードが更新されるたび] に設定されているか、[レコードが条件の要件を満たすように更新されるときのみ] に設定されているかは関係ありません。

オブジェクトのレコードトリガーフローの実行順序を定義するためのガイドライン

別のレコードトリガーフローの前または後に実行されるようにレコードトリガーフローを設定するためのガイドラインについて説明します。

  • オブジェクトの保存前または保存後フローでのみトリガー順序値を定義できます。トリガーの順序は、同じトリガー種別の指定オブジェクトのフローのみに影響します。
  • トリガー順序の値は、常に実行ルールの順序に準拠します。たとえば、ある保存後フローを別の保存後フローの前に実行することはできますが、保存後フローのトリガー順序の値が保存前フローまたは Apex トリガーより低い場合でも、これらの前に保存後フローを実行することはできません。
  • オブジェクトとトリガー (保存前または保存後) が同じで、1 ～ 1,000 のトリガー順序値が設定されているフローは、昇順 (1、2、3、以下同様) に実行されます。同じトリガー順序値の複数のフローは、フローの API 参照名に基づいてアルファベット順に実行されます。
  • 次にトリガー順序値のないフローが有効化日順に実行されます。Winter '22 以前に作成されたフローは、トリガー順序値を定義していなければ引き続きこの順序で実行されます。
  • 次に 1,001 ～ 2,000 のトリガー順序値が設定されているフローが昇順に実行されます。同じトリガー順序値の複数のフローは、フローの API 参照名に基づいてアルファベット順に実行されます。
  • 多数のフローを並び替える場合、10、20、30、または 100、200、300 のようにトリガー順序値を均等に分けることをお勧めします。 これにより、後で別のフローをその間 (10 と 20 の間など) に簡単に差し込むことができます。 この方法を使用すれば、既存のフローのトリガー順序値を変更せずに済みます。
  • フローの順序を有効化、無効化、または変更すると、他のフローの順序が自動的に更新される可能性があります。レコードトリガーフローを並び替えても、関連付けられているスケジュール済みパスや非同期パスに直接影響することはありません。
