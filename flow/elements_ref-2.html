一時停止中のフローインタビューの表示

一時停止中のフローインタビューは、ホームページ、Salesforce モバイルアプリケーションのナビゲーションメニュー、またはオートメーションアプリケーションで表示できます。一時停止中のフローインタビューを 1 回のクリックで再開できます。

必要なエディション

サポートされているエディションを表示する。
一時停止中のフローインタビューを表示 このアクションを実行してください。 詳細
Lightning Experience 該当する [ホーム] ページに [一時停止中のフローインタビュー] コンポーネントを追加します。

このコンポーネントは Lightning アプリケーションビルダーの [ホーム] ページでのみ使用できます。ユーザーに読み取りアクセスがある一時停止中のフローインタビューが表示されます。

Lightning アプリケーションビルダーの [コンポーネント] パネルから、[一時停止中のフローインタビュー] コンポーネントを Lightning ページにドラッグします。
エクスペリエンスビルダーサイト サイトページに一時停止中のフローコンポーネントを追加します。

このコンポーネントは、エクスペリエンスビルダーの大部分のページ (ログインページやエラーページなどは除く) で使用できます。コンポーネントには、ユーザーに読み取りアクセスがある一時停止中のフローインタビューが表示されます。

エクスペリエンスビルダーの [コンポーネント] パネルから、[一時停止中のフロー] コンポーネントをエクスペリエンスビルダーサイトページにドラッグします。

「エクスペリエンスビルダーでのページおよびコンポーネントの編集」を参照してください。
Salesforce モバイルアプリケーション [一時停止中のフロー] 項目を Lightning アプリケーションのナビゲーション項目に追加します。 「Salesforce モバイルアプリケーションでの Lightning アプリケーションのナビゲーションメニューのカスタマイズ」を参照してください。
Salesforce Classic 該当するホームページレイアウトに [一時停止中のフローインタビュー] 関連リストを追加します。 このコンポーネントには、ユーザーが一時停止した一時停止中のフローインタビューのみが表示されます。
オートメーションアプリケーション [監視] タブの [フロー] サブタブに移動します。一時停止中のフローの [詳細] タブから一時停止中のインタビューを再開します。 「一時停止中のフローインタビューと失敗したフローインタビューの監視と管理」を参照してください。

関連項目:

  • Lightning Experience ホームページの設定
  • Salesforce Classic の [ホーム] タブのページレイアウト

ユーザーによるレコードの一時停止中のフローインタビューの容易な検索

例 次の例では、Apex コントローラーを使用して、レコードに関連付けられているインタビューのリストを取得します。その後、コンポーネントのテーブルにインタビューが表示されます。コンポーネントには、ユーザーがインタビューを再開または削除できる、各インタビューのアクションメニューが表示されます。

ユーザーが [再開] をクリックすると、ヘルパーによって navigateFlow アクションが起動されてインタビューが再開します。ユーザーが [削除] をクリックすると、Apex コントローラーによってインタビューが削除されます。

Apex コントローラー

public class interviewsByRecordController {

    @AuraEnabled
    public static List<FlowRecordRelation> getInterviews(Id recordId) {
        return [ SELECT 
                    ParentId, Parent.InterviewLabel, Parent.PauseLabel, 
                    Parent.CurrentElement, Parent.CreatedDate, Parent.Owner.Name 
                FROM FlowRecordRelation 
                WHERE RelatedRecordId = :recordId ];
    }

    @AuraEnabled
    public static FlowInterview deleteInterview(Id interviewId) {
        FlowInterview interview = [Select Id from FlowInterview Where Id = :interviewId];
        delete interview;
        return interview;
    }
}

({
    populateTable : function(component, event, helper) {
        var action = component.get("c.getInterviews");
        action.setParams({
            recordId: component.get("v.recordId")
        });
        action.setCallback(this, $A.getCallback(function (response) {
            var state = response.getState();
            if (state === "SUCCESS") {
                // Push interviews fetched by the Apex controller to the component
                var recordRelations = response.getReturnValue();
                var interviews = [];
                for (var i = 0; i < recordRelations.length; i++) {
                    interviews.push(
                        {
                            Id: recordRelations[i].ParentId,
                            InterviewLabel: recordRelations[i].Parent.InterviewLabel,
                            PauseLabel: recordRelations[i].Parent.PauseLabel,
                            CurrentElement: recordRelations[i].Parent.CurrentElement,
                            PausedDate: recordRelations[i].Parent.CreatedDate,
                            PausedBy: recordRelations[i].Parent.Owner.Name
                        });
                }
                component.set('v.Interviews', interviews);
            } else if (state === "ERROR") {
                var errors = response.getError();
                console.error(errors);
            }
        }));
        $A.enqueueAction(action);
    },
    
    handleShowModal: function (component, id) {
        // On resume, render the interview in a modal
        $A.createComponent("lightning:flow", {"onstatuschange": component.get("c.statusChange")},
            function (content, status) {
                if (status === "SUCCESS") {
                    component.find('overlayLib').showCustomModal({
                        body: content,
                        showCloseButton: true,
                        closeCallback: function () {
                            $A.get('e.force:refreshView').fire();
                        }
                    }).then(function(overlay) {
                        // Use to close the modal later
                        component.set("v.overlay", overlay);
                    });
                    content.resumeFlow(id);
                }
            });
    },
    
    handleDelete: function (component, event, helper, id) {
        // On delete, pass the interview ID to the Apex controller        
        var action = component.get("c.deleteInterview");
        action.setParams({
            interviewId: id
        });
        action.setCallback(this, $A.getCallback(function (response) {
            var state = response.getState();
            if (state === "SUCCESS") {
                // Automatically refresh the table
                helper.populateTable(component, event, helper);
            } else if (state === "ERROR") {
                var errors = response.getError();
                console.error(errors);
            }
        }));
        $A.enqueueAction(action);
    }
})

組織での一時停止中のフローインタビューの準備

フローインタビューは、フローの実行中のインスタンスです。すべてのフローインタビューが 1 回で完了するわけではありません。フローに [一時停止] ボタンを追加して、ユーザーがフローインタビューを一時停止して後で再開できるようにします。また、フローインタビューの共有モデルを更新して、他のユーザーが一時停止中のインタビューを再開できるようにします。さらに、コンポーネントを [ホーム] ページに追加して、ユーザーがインタビューを簡単に再開できるようにします。

必要なエディション

サポートされているエディションを表示する。
  • フローインタビューの一時停止をユーザーに許可
    ユーザーがフローインタビューを終了できない場合、組織のプロセスの自動化設定をカスタマイズして、後で再開できるように一時停止オプションを提供します。たとえば、カスタマーサービス担当者は、顧客が必要なすべての情報を揃えていない場合にインタビューを一時停止できます。
  • 一時停止中のフローインタビューの表示
    一時停止中のフローインタビューは、ホームページ、Salesforce モバイルアプリケーションのナビゲーションメニュー、またはオートメーションアプリケーションで表示できます。一時停止中のフローインタビューを 1 回のクリックで再開できます。
  • ユーザーによるレコードの一時停止中のフローインタビューの容易な検索
    このカスタム Aura コンポーネントを使用して、そのレコードに関連付けられているすべての一時停止中のフローインタビューのリストをレコードページに表示します。

フロー要素

要素は、フローで実行できるアクションを表します。たとえば、Salesforce データの読み取りまたは書き込み、情報の表示、フローユーザーからのデータの収集、ビジネスロジックの実行、データの操作などがあります。

必要なエディション

サポートされているエディションを表示する。

Flow Builder では、フローを作成するときに自由形式と自動レイアウトのどちらを使用するのかを選択できます。自由形式の場合は、[要素] タブに、キャンバスでドラッグしてフローに追加できる要素種別が表示されます。自動レイアウトの場合は、 をクリックすると、追加できる要素種別が表示されます。フローにすでに追加されているすべての要素のリストについては、[マネージャー] タブの [要素] セクションを参照してください。

  • アクション要素
    [アクション] 要素をフローに追加して、Salesforce で使用できるアクションを起動します。
  • プロンプト命令要素の追加
    プロンプトビルダーでプロンプトテンプレートにマージされたプロンプト命令の形式でデータを提供します。この要素は、テンプレートトリガープロンプトフローでのみ使用できます。
  • Apex アクション要素
    Apex クラスをコールします。Apex クラスは、そのメソッドのいずれかに @InvocableMethod アノテーションが含まれている場合にのみ Apex アクションとして機能します。
  • Apex アクション (従来) 要素
    従来の Apex インターフェースを使用する Apex クラスをコールします。Apex クラスは、Process.Plugin インターフェースが実装されている場合にのみ従来の Apex アクションとして使用できます。
  • 割り当て要素
    コレクション変数、レコード変数、レコードコレクション変数、グローバル変数などの変数の値を設定します。
  • コレクション検索条件要素
    条件をコレクションに適用し、条件を満たす項目のみを含む新しいコレクションを出力します。
  • コレクション並び替え要素
    コレクション内の項目を並び替え、必要に応じて並び替え後にコレクションに残す項目数を制限します。
  • レコードの作成要素
    レコードコレクション変数を使用して、複数の Salesforce またはマーケティングオブジェクトレコードを作成または更新します。レコード変数またはフローの他の値を使用して、Salesforce またはマーケティングオブジェクトのレコードを 1 つだけ作成または更新します。
  • カスタムエラー要素
    レコードトリガーフローで対象を絞ったエラーメッセージを作成することで、全体のレコードページに表示するか、特定の項目にインラインエラーとして表示できます。エラーが修正されるまで、フローをトリガーした変更はロールバックされます。
  • 決定要素
    一連の条件を評価し、これらの条件の結果に基づいてユーザーが辿るフローの経路を指定します。この要素は、if-then ステートメントと同等に機能します。
  • レコードの削除要素
    レコード変数またはレコードコレクション変数に保存されている ID を使用するか、条件を指定して、削除する Salesforce またはマーケティングオブジェクトのレコードを特定します。
  • メールアラート要素
    メールテンプレートと受信者の静的リストを指定するメールアラートアクションを使用してメールを送信します。[アクション] 要素をフローに追加し、すでに設定されているメールアラートアクションの名前を検索します。
  • レコードを取得要素
    [レコードを取得] 要素では、検索条件と並び替え条件を満たすすべての Salesforce またはマーケティングオブジェクトのレコードを検索し、取得したレコードの値を変数に保存します。[レコードを取得] 要素を使用して、Salesforce 標準およびカスタムオブジェクトレコード、またはマーケティングオブジェクトレコードを取得できます。
  • グループ要素
    関連要素をフローの名前付き折りたたみ可能なセクションに整理します。グループは自動レイアウトモードでのみ使用できます。
  • ループ要素
    コレクション変数内の項目を反復処理するためのループパスを開始します。反復のたびにフローはループ変数内の項目を一時的に保存します。各項目の項目値に対してアクションを実行するには、ループ内の他の要素を使用します。
  • おすすめの割り当て要素
    おすすめオブジェクトのレコード、他のオブジェクトのレコード、コレクションの値、手動で入力した値のデータを組み合わせて、Einstein Next Best Action のおすすめを生成します。
  • エージェント要素を実行
    Agentforce エージェントを使用して、フローで ToDo を動的に処理します。既存のエージェントを選択するか、カスタム手順とアクションを使用してエージェントを作成します。
  • 画面要素
    フローを実行するユーザーから情報を収集したり、そのユーザーに情報を表示したりします。
  • 開始要素
    実行時に最初に実行するフロー要素に開始要素を接続します。自動起動フローでは、開始要素を開いて、フローを起動するトリガーを追加できます。トリガーを使用しない場合は、カスタムボタン、プロセス、Apex クラス、Einstein ボットなど、自動起動フローを呼び出すための他のものを設定する必要があります。
  • サブフロー要素
    組織で使用可能な別の有効なフローを起動します。別のフローによって起動されるフローは、参照されるフローと呼ばれます。
  • 変換要素
    変換元データを変換先データに対応付けて変換するためのフローリソースを選択します。[変換] 要素は、画面フロー、トリガーのない自動起動フロー、およびレコードトリガーフローで使用できます。
  • レコードの更新要素
    更新する Salesforce またはマーケティングオブジェクトのレコードを特定し、それらのレコードの値を変更します。これを行うには、レコード変数またはレコードコレクション変数に保存されている ID と項目値を使用するか、条件を指定してレコードを特定し、項目値を個別に設定します。
  • 待機時間要素
    一定時間だけ待機してからフローインタビューを再開します。
  • 条件要素の待機
    特定の条件が満たされると、フローインタビューを再開します。フローに定義する各待機設定には、省略可能な待機条件があります。実行時に、これらの条件によって、フローが関連付けられた再開イベントを待機するかどうかが決まります。
  • 日付要素まで待機
    特定の日時にフローを再開します。
  • マーケティングフローの Flow Builder 要素
    Flow Builder 要素は、フローで実行できるアクションを表します。たとえば、条件に基づく意思決定や Salesforce データの作成および削除などがあります。[メールメッセージを送信] や [SMS メッセージを送信] など、一部の Flow Builder 要素は Marketing または Data 360 でのみ使用できます。

プロンプトの手順

実行時にフローで評価されるテキストおよびフローリソース。テキスト値とリソース値は $Output グローバル変数に保存されます。

フローでは、最初の [プロンプトの指示を追加] 要素でテキストとフローのリソースを $Output グローバル変数に追加します。後続の [プロンプトの指示を追加] 要素ごとに、テキストとフローのリソースが $Output グローバル変数に追加されます。
例 最初の [Add Prompt Instructions (プロンプトの指示を追加)] 要素では、テキスト Hello! を追加します。次の [プロンプトを追加] 命令要素は、{!contact}レコード変数リソースを追加します。フローが完了すると、$Output グローバル変数に「Hello!Mary。ここで、Mary は {!contact} が参照する値です。同じテキストがプロンプトビルダーの関連付けられたプロンプトテンプレートにマージされます。

プロンプト命令での欠損データの処理

プロンプト命令でデータが返されないロジックまたはアクションを考慮します。次のオプションを考慮してください。

  • 代替値またはデフォルト値を組み込みます。
  • データを使用しない命令を追加します。
  • プロンプトの指示をクリアして、フローの外部に何も渡さないようにします。
  • 欠損データに対処するプロンプトの指示を含めます。

たとえば、プロンプトの指示は検索条件に一致する取引先によって異なりますが、フローで取引先が検出されません。ロジックを使用して欠損データを処理することをお勧めします。[決定] 要素ではデータをチェックでき、[プロンプトの指示を追加] 要素ではデータが使用できないことを示すコンテキスト指示を送信できます。

レコード ID の取得

[レコードを取得] 要素を参照するリソースを [プロンプトの指示を追加] 要素に挿入すると、$Output グローバル変数にはレコード ID のみが保存されます。たとえば、[レコードを取得] 要素で取引先のコレクションを取得します。そのフローリソース{!Get_Accounts}が [プロンプト命令を追加] に挿入されます。$Output グローバル変数には、取引先 ID のみが保存されます。

必要なエディション

サポートされているエディションを表示する。

カスタムエラーメッセージは、レコードトリガーフローの保存前または保存後パスでのみ作成できます。エラーメッセージを非同期で実行することはできません。また、エラーメッセージを別のフロー種別からコールすることはできません。

項目 説明
表示ラベル キャンバス上のエラーメッセージを識別します。

使用方法

カスタムエラー要素を使用して、フローをトリガーした変更をロールバックし、エラーの正確な原因をユーザーに通知します。ユーザーは問題を修正して再試行できます。たとえば、ユーザーがフローをトリガーするレコードを削除すると、フローからユーザーに削除が許可されなかった理由を通知するエラーメッセージが返されることがあります。

考慮事項

  • 実行障害パスにカスタムエラー要素がある場合、フローをトリガーした変更はロールバックされます。
  • カスタムエラーメッセージは、Apex の addError() ID メソッドと同じ機能を使用します。
  • OpportunityTeamMember や CampaignMember などの一部のオブジェクトでは、削除前に実行されたレコードトリガーフローからのカスタムエラーはサポートされません。実行中のフローユーザーには、これらのレコードを削除するときにカスタムエラー要素を使用できないことを説明するエラーメッセージが表示されます。

  • カスタムエラー要素には、1 つのレコードページのエラーメッセージのみを含めることができます。同じフローで別のレコードページのエラーメッセージを作成するには、別のカスタムエラー要素を使用します。
  • 複数のインラインエラーメッセージを表示できますが、項目ごとに 1 つのみ表示できます。

レコードのコレクションを作成する

複数のレコードを作成するには、レコードコレクション変数の値を使用する必要があります。フローの前半で、レコードコレクション変数に新しいレコードの項目値を入力します。ID 項目が空白であることを確認します。

コレクションの一部のレコードを動的に作成して他のレコードを更新するには、[Update Existing Records (既存のレコードを更新)] を有効にします。各レコードを一意に識別するレコードコレクション変数のレコードの項目を選択します。フローはこの項目を使用して、レコードが存在するかどうかを確認します。フローでレコードの作成または更新に失敗した場合の残りのレコードの処理方法を選択します。

レコードコレクション変数を使用して一度に複数のレコードを作成または更新する場合、フローの DML 要求の数を減らします。これにより、組織の制限を超える可能性が低くなります。詳細は、「トランザクションでのフローの一括処理」を参照してください。

1 つのレコードを作成する

レコード変数に新規レコードの項目値を入力している場合、レコード変数のすべての値を使用してレコード項目を設定します。次に、使用するレコード変数を選択します。ID 項目が空白であることを確認します。

レコードを動的に作成または更新するには、[Update Existing Records (既存のレコードを更新)] を有効にします。レコード変数で、レコードを一意に識別するレコードの項目を選択します。フローはこの項目を使用して、レコードが存在するかどうかを確認します。

フローのさまざまなリソースの値を手動で対応付けるには、個別の変数、リソース、リテラル値を使用してレコード項目を設定します。レコードを作成するオブジェクトを選択し、レコードの項目値を設定します。手動でテキスト変数を作成した場合は、必要に応じて、作成したレコードの ID をテキスト変数に保存します。たとえば、子レコードを作成したり、作成したレコードにリンクを提供したりするためにレコードの ID が必要になる場合があります。

更新または作成する重複レコードを動的にチェックするには、[Check for Matching Records (一致するレコードを確認)] を有効にします。

例 ユーザーがフローに名前と住所を入力します。レコードを取得要素を使用して、一致するユーザーが存在するかどうかを確認します。一致する取引先責任者が存在しない場合は、レコードの作成要素を使用して、そのユーザーのレコードを作成します。

使用方法

フローがエラーになることを防止するには、次のことを確認します。

  • すべての必須項目に値が入力されている。[レコードを作成] 要素では、必須項目が入力されます。表示される項目は、マスターレコードタイプで必須です。カスタムオブジェクトの場合、オブジェクト定義の必須項目を確認します。
  • レコード変数の場合、ID 項目値は空白です。レコードが作成されると、フローで ID 項目が入力されます。
メモ インタビューのトランザクションが完了するまで、レコードは作成されません。インタビューが完了または実行されたときに、画面、ローカルアクション、または待機要素がトランザクションに反映されます。

考慮事項

  • [レコードを作成] 要素がレコードコレクションを使用し、障害パスがなく、フローが失敗すると、レコードは作成されず、フローは停止し、エラーが発生します。
  • [レコードを作成] 要素でレコードコレクションが使用され、障害パスがある場合、成功したレコードのみが作成されます。フローのレコードコレクションのレコードでは、成功したレコードの ID は入力されません。ID は組織のレコードに入力されます。
  • [レコードを作成] 要素では、編集がロックされている一致するレコードを更新できません。Flow Builder で一致するレコードが検出され、レコードの項目を更新しようとすると、警告が表示されます。
  • [レコードを作成] 要素では、一致するレコードの参照のみの項目を更新できません。Flow Builder で一致するレコードが検出され、常に参照のみの項目または更新権限のない項目を更新しようとすると、警告が表示されます。
  • [レコードを作成] 要素では、更新機能をサポートしていないオブジェクトの一致するレコードの項目を更新できません。Flow Builder で一致するレコードが検出され、更新機能をサポートしていないオブジェクトの項目を更新しようとすると、エラーが表示され、フローを有効化できません。オブジェクトを更新できるかどうかについては、「Object Reference for the Salesforce Platform (Salesforce Platform のオブジェクトリファレンス)」を参照してください。
  • 組織で [設定] の [レコード作成時の監査項目の設定] ユーザー権限が有効になっている場合、[レコードの作成] 要素を使用してレコードをコピーするフローでは、システム監査項目をソースレコードから新しいレコードにコピーできます。システム項目には、[CreatedDate]、[CreatedById]、[LastModifiedDate]、[LastModifiedById] があります。詳細は、「Enable "Set Audit Fields upon Record Creation" and "Update Records with Inactive Owners" User Permissions (レコード作成時の監査項目の設定と無効な所有者のレコードの更新のユーザー権限の有効化)」を参照してください。
  • 重複レコードのチェック
    レコードの重複を回避するには、一連の条件に一致するレコードを確認し、一致するレコードをフローで見つけた場合の処理を指定します。組織の一部の項目レベルの設定と入力規則は、[レコードを作成] 要素の設定を上書きします。

検索条件の定義に関する考慮事項

取得したレコードの並び替え

選択した項目に基づいて、取得したレコードを昇順または降順に並び替えます。並び替え順は、特定の順序でレコードを処理する場合に便利です。日付項目でレコードを並び替えて昇順を選択すると、最も古い日付が最初に表示されます。降順を選択した場合、最新の日付が最初に表示されます。数値項目でレコードを並び替えて昇順を選択すると、最小値が最初に表示されます。降順を選択した場合、最も高い値が最初に表示されます。

レコードを昇順で並び替える場合、null 値は可能な最小値とみなされるため、null 値はリストの先頭に表示されます。逆に、レコードを降順で並び替えると、null 値がリストの最後に表示されます。

レコードトリガーフローで使用できます。トリガーレコードが条件の要件を満たすように更新されているかどうかに基づいて、この結果のパスを取得するかどうかを決定します。たとえば、フローの実行をトリガーした商談更新で、そのフェーズが [商談成立] 以外の値から [商談成立] に変更された場合です。

このオプションでは、トリガーレコードが以前に条件の要件を満たしていなかったかどうか、$Record 変数が現在条件の要件を満たしているかどうかを確認します。設定された [決定] 要素が実行される前にフローによって $Record 変数の項目が変更されると、[決定] は $Record の新しい項目値が条件の要件を満たすようになったかどうかをチェックします。
例

決定要素を使用して、以下を実行するかどうかを決定します。

  • 品目の欠陥が判明した場合に、お客様に返品先住所を提示するか、それとも問題を解決する手順を示すか。
  • 信用度数式の結果に基づいてお客様に融資するかどうか。
  • 商談のフェーズが [商談成立] に変更されたときに営業リーダーに通知するかどうか。
ヒント 選択リスト画面コンポーネントでユーザーが選択した内容に基づいて異なる操作を行うようにフローを設定します。これを行うには、画面要素の後に決定要素を追加し、選択リストで使用できる選択肢に基づくフローの分岐を作成します。これで、決定要素で各選択肢を表し、それをフローの分岐に接続できるようになります。

フローの実行で実行できるパスごとに、結果を作成します。結果ごとに、結果を取得するタイミングを AI に指示する情報を入力します。AI がどの条件も満たされていないと判断した場合に実行するパスのラベルを変更するには、[デフォルトの結果] をクリックします。結果の詳細を表示するには、パネルのサイズを変更します。

項目 説明

手動条件の利用状況

[決定] 要素で 2 つの可能な結果が提供される場合、最初の結果の条件が満たされない場合にのみデフォルトの結果が適用されます。

決定要素に 3 つ以上の結果がある場合、リストの順序で評価されます。各結果について:

  • その条件がチェックされます。
  • 条件が true の場合、その結果に関連付けられたパスが実行されます。
  • 条件が false の場合、リスト内の次の結果の条件が評価されます。

定義された結果条件がいずれも満たされない場合、デフォルトの結果パスが実行されます。

メモ 下流要素で結果の値を参照する場合、その値は結果が評価され、その条件が満たされた場合にのみ設定されます。結果は順番に評価され、条件が最初に一致した結果で評価が停止するため、それ以降の結果は評価されず、その値は null になります。デフォルトの結果は条件に対して評価されないため、値はありません。他の結果の条件が満たされない場合にのみ実行されます。

AI 条件の利用状況

AI による判断は、Marketing Cloud フローまたはレコードトリガーフローではサポートされていません。

実行時に、決定手順がすべての結果手順と組み合わされ、AI が実行する結果を判断します。AI はすべての条件を同時に評価するため、結果を定義する順序はフローで実行される結果に影響しません。手動条件で説明されている順次評価の動作は、AI による判断には適用されません。

検索条件の定義に関する考慮事項

  • 通常、複数の検索条件を定義する場合、検索条件ロジックはデフォルトの AND になります。ただし、複数の検索条件で同じ項目が選択され、「次の文字列と一致する」演算子が使用されている場合、検索条件は OR で結合されます。

  • 使用可能な検索条件の演算子は、選択した項目のデータ型によって異なります。詳細は、「データ要素とレコード選択肢セットのフロー演算子」を参照してください。

複数のレコードの項目の同時更新の例

この例では、ビジネスルールに基づいて取引先の所有権を再割り当てすることで、複数のレコードの項目を更新するフローを作成します。

必要なエディション

サポートされているエディションを表示する。

まず、collReassignedAccts という取引先ベースのレコードコレクション変数を作成します。

次に、[レコードを取得] 要素を追加して、John Smith が所有するすべての取引先レコードを取得します。

次に、コレクションを反復処理するループを作成します。ループは、コレクションの項目ごとに次の処理を実行します。

  1. コレクション項目をループ変数に割り当てる。
  2. 取引先の従業員数が 10,000 名を超えているかどうかを評価する。
  3. 取引先の従業員数が 10,000 名を超えている場合、Madison のユーザー ID をループ変数の OwnerId 項目に割り当てる。
  4. 取引先の従業員数が 10,000 名を超えていない場合、Amber のユーザー ID をループ変数の OwnerId 項目に割り当てる。
  5. collReassignedAccts コレクションの新しい項目としてループ変数の値を追加する。
  6. 最後に、ループでコレクションの反復処理が終了したら、[レコードを更新] 要素を追加して collReassignedAccts の取引先を新しい OwnerId で更新します。

    フローのこのセクションでは、1 つのクエリを使用して取引先のリストを検索し、1 つの DML ステートメントを使用してこれらの取引先を更新します。項目を個別に設定してレコードを更新した場合、次の操作を実行します。

    1 つのレコード更新要素を使用して、10,000 名を超える従業員がいる John 所有のすべての取引先を検索します (1 つのクエリ)。次に、これらのレコードの OwnerId を Madison の ID に更新します (1 つの DML ステートメント)。

自動パス選択 (推奨)

自動パス選択を使用するには、[自動] を選択し、パフォーマンス指標、テスト設定、フォールバック動作を設定します。自動パス選択時に、システムはパスをテストし、勝者を選択します。システムはベイズ予測を使用して成立経路を選択します。あるパスがテスト後に他のすべてのパスよりも信頼性が 95% 以上高い場合、そのパスが勝者として宣言されます。他のすべてのパスよりも信頼性が 95% 以上高いパスがない場合、選択した代替動作が使用されます。

自動パス選択に関する考慮事項

  • 実験で勝者を選択する前に、選択したパフォーマンス評価指標のすべてのパスに少なくとも 1 つのデータポイントが必要です。各パスで少なくとも 1 つのデータポイントが生成される可能性が高いように、利用者と実験期間が十分に大きいことを確認します。
  • パスあたりのオーディエンスメンバーが 300 人未満の実験は、結果が統計的に有意ではないため、確定的ではありません。確定的ではない実験では、選択したフォールバック動作が使用されます。[Best Performer (最良の実行者)] オプションを使用すると、パスあたりの参加者が 300 人未満であっても最良の実行者が選択されます。
  • Einsteinメトリクス保護では、実験でメールを記録する前にメールからのボットエンゲージメントシグナルを抑制します。エンゲージメントシグナルを抑制すると、パスが最小 1 データポイントに達しない可能性があります。その結果、この実験では勝者は選択されません。詳細については、「Marketing Cloud Engagement Einsteinでのメール クライアント プライバシー評価指標」を参照してください。

パスの割り当てとテストグループの配信

Path Experiment 要素では、ランダム化を使用して個人をパスとテストグループに割り当てます。設定したパーセントは目標であり、保証数ではありません。実際の配分は、特に利用者が少ない場合は、指定した割合と完全に一致するとは限りません。

システムは、一意の ID と実験 ID に基づいて各個人を割り当てます。 この計算では、各個人が特定のバケットに配置され、パスの割り当てとテストグループに属しているかどうかが決まります。合計を均等に分けるのではなく、各個人を個別に割り当てるため、結果は正確な分割ではなく確率のように機能します。

たとえば、2 つのパスを 50% の分布で設定し、6 人の小規模な利用者で実験を実行するとします。実際の分割は、3 人と 3 人のパスではなく、1 つのパスで 4 人、もう 1 つのパスで 2 人のパスになります。 テストグループでも同様です。10 人のテストグループを 80% に設定した場合、8 人ではなく 7 人または 9 人が表示されることがあります。 利用者が多いほど、設定した割合に近い分布結果になります。

この動作は、パスの割合とテストグループの割合の両方に適用されます。

Personalize Paths (パスのパーソナライズ) 要素

各オーディエンスメンバーをコンバージョン目標を達成できる可能性が最も高いパスに誘導します。システムは実際のコンバージョン結果から継続的に学習し、各オーディエンスメンバーにとって最適なパスを予測します。[パスをパーソナライズ] は、オートメーションイベントトリガーフローとセグメントフローで使用できます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Marketing Cloud Advanced Edition が付属する Salesforce Enterprise Edition および Unlimited Edition、および Starter Edition および Pro Suite Edition。使用できるオプションはエディションによって異なります。
メモ Flow Builder では、キャンバス上のこの要素の展開と折りたたみの設定が記憶されます。ビューはブラウザーにローカルに保存され、同じブラウザーのセッション間で保持されます。この設定はユーザーに固有であり、他のユーザーのビューには影響しません。ただし、ブラウザーの Cookie やその他のサイトデータをクリアしたり、別のブラウザーに切り替えたりすると、設定はデフォルトの展開ビューにリセットされます。キャッシュされた画像またはファイルをクリアしても、この設定には影響しません。

前提条件

[パスをパーソナライズ] 要素をフローに追加するには、ユーザーに次の要件があります。

  • 「Marketing Cloud 管理者」または「Marketing Cloud 管理者」権限セット
  • 「フローへのパス要素のパーソナライズの追加」権限

[パスをパーソナライズ] 要素では、パーソナライズ機能を設定する必要もあります。詳細な手順については、「Marketing Cloud Next でのパーソナライズ機能の設定」を参照してください。

考慮事項

  • [パスのパーソナライズ] では、パフォーマンス評価指標がメール評価指標の場合、各パスに [メールメッセージを送信] 要素が必要です。これにより、そのパスのパフォーマンスを評価できます。
  • [パスをパーソナライズ] には、[分析] タブの要素レベルの総計値のみが含まれます。パスの実験で使用できる実行履歴と実験の詳細へのリンクは、パスのパーソナライズでは使用できません。

パーソナライズの設定

[パスをパーソナライズ] では、パーソナライズ設定と使用可能なパスに基づいて各利用者メンバーがパスに移動します。[パスをパーソナライズ] 要素で最大 10 個のパスを使用します。

Performance Metric (パフォーマンス評価指標) と省略可能なエンゲージメントシグナルでコンバージョンの目標を設定します。たとえば、オーディエンスメンバーがメールを開封する可能性が最も高いパスに移動するには、パフォーマンス評価指標として [メール開封] を選択します。特定のリンクのクリックスルーをエンゲージメントシグナルとして追加し、メールを開くだけでなくそのリンクをクリックした利用者に対してパスの選択をさらに絞り込みます。

エンゲージメントシグナル パフォーマンス評価指標と共にパスの選択を通知する、イベントライブラリから選択されたより多くのエンゲージメントシグナル。

おすすめの割り当て要素

おすすめオブジェクトのレコード、他のオブジェクトのレコード、コレクションの値、手動で入力した値のデータを組み合わせて、Einstein Next Best Action のおすすめを生成します。

必要なエディション

サポートされているエディションを表示する。

[おすすめの割り当て] 要素は、[割り当て] 要素と似ており、両方とも変数で値を設定します。ただし、いくつか重要な違いがあります。

  • [おすすめの割り当て] は、新しいおすすめコレクション変数を出力する場合に使用します。これに対し、割り当ては、既存の変数の値を追加または変更する場合に使用します。
  • [おすすめの割り当て] では、既存の変数の値を更新できません。
  • [おすすめの割り当て] では、出力コレクションのすべてのおすすめで項目の値を設定できます。たとえば、AcceptanceLabel を [承諾] に設定した場合、出力コレクションのすべてのレコードの AcceptanceLabel が [承諾] に設定されます。
  • [おすすめの割り当て] では、別のオブジェクトのレコードからおすすめを作成できます。たとえば、ソースコレクションのリードを使用して、それらのリードと同じ名前のおすすめを作成できます。
  • [おすすめの割り当て] は、おすすめ戦略フローでのみ使用できます。

ソースコレクションを設定

おすすめの作成に使用するデータを含むレコードコレクション変数を選択します。[おすすめの割り当て] では、ソースコレクションのレコードごとに 1 つのおすすめが作成されます。

おすすめが含まれるレコードコレクション変数を選択する場合は、対象コレクションの値を設定する項目を選択できます。他のオブジェクトのレコードが含まれるレコードコレクション変数を選択した場合は、要素で特定のおすすめ項目が必要になります。

出力おすすめコレクションのおすすめ項目に値を割り当てます。このセクションで定義された値は、出力コレクションのすべてのレコードで設定されます。ここで設定されていない値がソースコレクション変数にある場合、それらの値は出力おすすめコレクションに渡されます。

特定の項目のソースコレクションレコードの値を使用するには、[値] 列で currentItemFromSourceCollection を選択してから、目的の項目を選択します。

各値は、演算子と値の組み合わせによって変更されます。

フローを実行するユーザーから情報を収集したり、そのユーザーに情報を表示したりします。

画面のプロパティ

選択した画面コンポーネントまたはレコード項目を所有していない場合は、プロパティペインに画面全体が表示されます。

  • Configure Frame (フレームを設定) — この画面にヘッダーとフッターを表示するかどうかを制御します。これらのオプションは Lightning ランタイムでのみサポートされます。フッターを非表示にする場合、カスタム画面コンポーネントを使用して、ユーザーが画面間を移動できるようにします。
  • Control Navigation (ナビゲーションを制御) — この画面で無効にするナビゲーションオプションの選択を解除します。デフォルトでは、ナビゲーションオプションは画面のフッターにボタンとして表示されます。[次へ] アクションは、フロー内で画面の後に要素がある場合にのみ使用できます。[完了] アクションは、画面がフローの最後の要素である場合に使用できます。[前へ] アクションは、この画面の前に画面がある場合に使用できます。[一時停止] アクションは、組織の [プロセスの自動化設定] で [フローの一時停止をユーザーに許可] が有効になっている場合に使用できます。

    たとえば、フローが取引先責任者レコードを取得するために使用する情報を入力するようにユーザーに促すとします。一致する取引先責任者が見つからない場合、フローにより、戻って再試行するようにユーザーに指示する画面が表示されます。

    ヒント
    • フッターは非表示にするが、ユーザーが画面間を移動できるようにする場合、Lightning コンポーネントを使用してアクションを表示します。
    • 画面要素の前にデータ要素 (レコードを更新など) またはアクション ([Chatter に投稿] など) がある場合、[前へ] を選択解除します。
    • 前の入力を修正する場合など、フローユーザーを強制的に前に戻すには、[[次へ] または [完了]] を選択解除します。

    [一時停止] アクションが有効な場合

    • [一時停止確認メッセージ] を使用して、フローがどこで再開されるかをユーザーに知らせます。ユーザーの一時停止中のフローをリストするコンポーネントについては、「Viewing Paused Flow Interviews (一時停止中のフローインタビューの表示)」を参照してください。
    • フローのインタビュー表示ラベルをカスタマイズします。
    • 組織の [プロセス自動化設定] で、[フローの一時停止をユーザーに許可] を有効にします。
  • ヘルプを提供 — ユーザーにこの画面の詳細なコンテキストを提供します。入力したテキストは、画面のヘッダーの情報バブルに表示されます。ヘッダーは非表示にするが、ヘルプテキストは表示する場合、カスタム画面コンポーネントを使用します。

画面コンポーネント

[コンポーネント] タブには、その画面で使用できるすべての標準入力コンポーネント、標準表示コンポーネント、およびカスタムコンポーネントが含まれます。コンポーネントを画面に追加するには、クリックしてドラッグします。

ヒント カスタムコンポーネントが多数ある場合、検索項目にテキストを入力すると、必要なコンポーネントを検索できます。ペインの下部のボタンを使用して、AppExchange にあるサードパーティのカスタムコンポーネントにアクセスできます。

Salesforce オブジェクトから直接項目を追加して、フロー画面をすばやく作成できます。フロー画面にレコード項目を追加すると、その名前、データ型、ヘルプテキスト、必須設定、場合によっては既存の値が自動的に設定されます。レコード項目は、レコード変数を使用して、フロー画面に配置できる項目とその設定を決定します。

フロー画面でのレコード項目の直接配置

レコード項目を画面フローに追加する手順は、次のとおりです。

  1. 画面要素を作成または編集します。
  2. [項目] タブで、レコード変数を選択するか、レコードデータ型と、目的の項目が含まれるオブジェクトを使用して変数を作成します。
    または、[レコードを取得] 要素によって自動的に作成されたレコード変数や、ループ要素を選択します。
  3. 表示された項目のリストから、項目を画面のキャンバスにドラッグします。
  4. レコード項目の既存の値を使用するには、レコード変数の [レコードを取得] 要素を使用します。
メモ 項目にレコード変数の値が含まれている場合、その値は実行時の画面でデフォルト値として設定されます。

フロー画面のレコード項目に関する考慮事項

Salesforce オブジェクトの項目をフロー画面に直接追加する前に、レコード項目の動作を考慮してください。

取引先ティッカー項目

画面の取引先レコードに標準ティッカーシンボル項目を配置すると、フローを保存できなくなります。

レコードの作成と更新

画面の他の項目と同様に、レコード項目のデータは自動的に保存されません。レコード項目データを保存するには、[レコードを作成] 要素または [レコードを更新] 要素で関連付けられたレコード変数を使用します。

デフォルト値

レコード項目では、ソース項目のデフォルト値はサポートされません。レコード項目のソース項目にデフォルト値がある場合、そのレコード項目は空白になります。

項目にレコード変数の値が含まれている場合、その値は実行時の画面でデフォルト値として設定されます。

行動および ToDo レコード項目

実行時、行動レコード項目と ToDo レコード項目の動作は、画面の他のタイプのレコード項目とは異なります。

  • チェックボックス項目の表示ラベルは、チェックボックスに合わせて表示されません。チェックボックスの上または下に表示されます。
  • 編集すると、レコード項目の背景が黄色にならず、[元に戻す] ボタンは表示されません。

参照関係

  • ルックアップからのレコードの作成は、URL から起動されるフロー (リスト ボタンなど)、フロー デバッガ、Lightning Out、デジタル エクスペリエンス (LWR)、組み込みサービス フローの環境ではサポートされません。
  • 参照項目はモバイルデバイスと互換性がありません。
  • 既存のレコードの主従関係の値を表示または変更するには、その項目の [親の変更を許可] 設定を有効にする必要があります。
  • 検索条件が適用された参照項目では、フローを実行しているユーザーがレコードを作成しようとしても、フローランタイムのエラーはすぐに表示されません。エラーは、新規作成されたレコードを参照するレコードを作成または更新するときにのみ表示されます。
  • UI API は、ルックアップが存在するオブジェクトをサポートしている必要があります。

ルックアップ検索条件

ルックアップ検索条件がフローの現在のレコードの項目値に依存している場合、同じ画面でルックアップ検索条件で使用される項目を追加します。フローでユーザーが実行したアクションに基づいてルックアップで使用できるレコードを制限するには、選択肢ルックアップコンポーネントを使用します。

複数選択リスト

割り当てで [項目を追加] 演算子を使用すると、複数選択リスト項目で重複する値を使用できます。

名前項目

実行時に [名前] サブ項目の値が変更されると、新しい値が設定され、サブ項目に新しい値が表示されます。ただし、[氏名] レコードの [氏名] 項目には元の値が表示されます。

権限

システムコンテキストはレコード項目には適用されません。ユーザーがレコード項目へのアクセス権を持っていない場合、そのレコード項目はフローで表示されません。

レコード変数に ID が設定されていない場合、実行ユーザーがレコード項目値を変更するには、Read アクセス権と Create アクセス権の両方が必要です。

ID が設定されている場合、実行ユーザーがレコード項目値を変更するには、Read アクセス権と Edit アクセス権の両方が必要です。

レコード項目の詳細では、[Update Compatible (互換を更新)] および [Create Compatible (互換を作成)] の値に項目のプロパティと権限が反映されます。この値は、フローを実行しているユーザーの権限を反映していません。

画面フローには、オブジェクトレベルで参照のみに設定されたレコード項目は表示されません。

個人取引先

PersonAccount が有効になっていて、取引先レコード項目が画面に追加されている場合:

  • レコードタイプが個人取引先の場合、個人* 項目と共通項目のみが表示されます。
  • レコードタイプが法人取引先の場合、法人取引先項目と共通項目のみが表示されます。

すべての取引先レコード項目が表示され、レコードタイプは無視されます。

Account.Nameは、レコードタイプが個人取引先の場合はPersonName項目として表示され、法人取引先の場合はテキスト項目として表示されます。Account.Name はテキストフィールドとして表示されます。

選択リスト

レコード項目では、連動項目が制御項目と同じ画面にある場合にのみ連動選択リストがサポートされます。

画面に入ったときにレコード項目にレコードタイプ ID が設定されている場合、その値はレコードタイプで絞り込まれます。レコードタイプ ID が設定されていない場合、すべての値が表示されます。

レコード項目の参照

数式、決定、条件付き表示など、フローの他の領域のレコード項目を参照することはできません。代わりに、レコード項目の作成に使用したレコード変数を参照します。

ランタイム環境

レコード フィールドは、Lightning Web Runtime(LWR)を使用する Experience Cloud サイトの画面フローではサポートされません。

サポートされる項目データ型

レコード項目では、住所、チェックボックス、日付、日時、メール、参照、名前、数値、電話、選択リスト、テキスト、テキストエリア、ロングテキストエリアのデータ型がサポートされます。

その他の考慮事項

  • レコード項目では、ユーザーインターフェース (UI) API でサポートされるオブジェクト項目がサポートされます。
  • レコード項目では、ユーザーインターフェース (UI) API から返された表示ラベルが使用されます。これは、レコードページやオブジェクトマネージャーに表示される表示ラベルとは異なる場合があります。名前データ型のレコード項目の場合、ほとんどのオブジェクトで表示ラベルが [名前] ではなく [氏名] として表示されます。
  • 繰り返し画面コンポーネントでは、レコード項目はサポートされていません。
  • ユーザー入力の検証はサポートされていません。

ユーザー入力の検証によるデータ品質の向上

画面フローは手作業によるデータ入力を減らすのに役立ちますが、収集するデータにエラーがないことが重要です。入力を検証して、画面フローユーザーが情報を正しく入力していることを確認します。

必要なエディション

必要なユーザー権限

画面要素と画面コンポーネントには、実行時に画面フローのユーザー入力規則が組み込まれています。標準入力以外の入力規則を確認する場合は、ユーザー入力のカスタム入力規則を作成します。カスタム検証を作成するには、Boolean 数式を使用してユーザー入力を確認し、カスタムエラーメッセージを使用してユーザーをガイドします。

画面要素の標準検証

ユーザーが必須項目を空白のままにすると、その画面コンポーネントでカスタムエラーメッセージを設定しても、フローにデフォルトの標準エラーメッセージが表示されます。

画面コンポーネントの標準入力規則

標準の検証は、画面コンポーネントによって異なります。たとえば、数値画面コンポーネントでは数値のみを使用できます。画面コンポーネントの標準検証を確認します。画面コンポーネントがテーブルにない場合、組み込みの検証はありません。

カスタムユーザー入力検証

標準入力規則が状況で機能しない場合は、カスタムユーザー入力規則を作成できます。カスタム検証では、必要な形式のユーザー入力をチェックする数式を含む数式リソースが使用されます。数式は Boolean 値 (true または false) を返す必要があります。数式が true と評価された場合、ユーザー入力は有効です。数式が false と評価されると、ユーザー入力が無効になり、カスタムエラーメッセージがコンポーネントの下に表示されます。

カスタム検証の作成についての詳細は、「カスタムユーザー入力検証の作成」を参照してください。

カスタム検証エラーメッセージが表示される場合

検証は、ユーザーがボタンをクリックして画面から移動した後や、ユーザーが誤った情報を入力した直後に行われる可能性があります。デフォルトでは、ナビゲーションボタンがクリックされたときに検証されます。

ユーザーが間違った入力を開始した直後に入力内容を確認するには、入力規則の数式で同じ画面の画面コンポーネントを参照できます。

カスタム検証を作成するためのヒント

  • 正規表現では、スラッシュで始まる文字を二重スラッシュを使用してエスケープします。たとえば、\d は \\d になります。
  • [入力を検証] セクションでコンポーネント自体を参照するには、コンポーネントを画面に追加した後にコンポーネント設定ペインから をクリックする必要があります。これにより、参照を試みる前の状態が保存されます。

カスタム検証に関する考慮事項

  • レコード コレクションまたは Apex で定義されたタイプ コレクションの検証はサポートされていません。
  • [空白] 演算子と [Null] 演算子は、入力検証数式ではサポートされません。
  • 実行時に、ユーザーがコンポーネントを空白のままにすると、チェックボックス、チェックボックスグループ、選択肢ルックアップ、通貨、日付、日時、ロングテキストエリア、複数選択リスト、数値、パスワード、選択リスト、ラジオボタン、テキストのコンポーネントの値は検証されません。
  • 入力規則の数式が数式と同じ画面要素のリソースを参照している場合、一部の数式関数はサポートされていません。例: REGEX。サポートされる数式関数のリストについては、「反応画面フローの数式演算子」を参照してください。
  • 入力規則の数式が数式と同じ画面要素のリソースを参照している場合、数式が true を評価して false に戻すまで、一部の入力規則機能は期待どおりに動作しません。

カスタムユーザー入力検証の作成

フロー画面コンポーネントに入力規則を追加する手順は、次のとおりです。

  1. [フロー] リストビューを開きます。
    • Automation アプリケーションから、[フロー] タブを選択します。
    • 任意の Lightning アプリケーションの [フロー] タブで、アクション メニューをクリックし、[フローを開く] を選択します。
    • [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択します。
    [オートメーションアプリケーション] および [フロー] タブのオプションには、[設定] アクセス権は必要ありません。
  2. 画面フローを作成します。
    • 自動化アプリケーションまたは [フロー] タブで、 [ 新 | 規画面の自動 | 画面フロー]を選択します。
    • [設定] から、 [ 新規フロ | ー画面] [オートメーション | 画面フロー]をクリックします。
  3. 画面要素を追加します。
    1. [要素を追加 + アイコン] をクリックし、[画面] を選択します。
    2. [表示ラベル] に、わかりやすい名前を入力します。たとえば、「Collect Contact Details」 (取引先責任者の詳細の収集) とします。
      API 参照名は自動入力されます。
    3. [説明] に、要素の機能に関するわかりやすい説明を入力します。たとえば、作成する取引先責任者に関する情報を収集します。
  4. [入力を検証] セクションで、Boolean 数式を入力してコンポーネントで許可される値を定義します。数式で、コンポーネントの正しい出力を参照します。
    • コンポーネントに 1 つの出力がある場合、コンポーネント自体を参照します。たとえば、「Cancellation Reason」 (キャンセルの理由) という表示ラベルのテキストコンポーネントの場合、{!Cancellation_Reason} を参照します。
    • コンポーネントに複数の出力がある場合、コンポーネントの特定の出力を参照します。たとえば、「Contact Email」 (取引先責任者メール) という表示ラベルのメールコンポーネントの場合、{!Contact_Email.value} を参照します。
例

例 1: この数式は、テキストコンポーネントの郵便番号の形式を検証します。

REGEX({!Zipcode},"\\d{5}(-\\d{4})?")

例 2: この数式は、ユーザーがファイルアップロードコンポーネントで少なくとも 1 つのファイルをアップロードしたことを検証します。

NOT({!fileUpload.contentDocIds} = "[]")

オプション 説明

[処理中] 出力属性を使用した別のコンポーネントの動作の指定

ユーザーがアクションボタンをクリックすると、関連付けられた画面アクションの [処理中] 属性が true に設定されます。アクションが完了すると、[処理中] 属性は false に設定されます。

[処理中] 属性を使用して、別のコンポーネントの動作を指定します。たとえば、アクションの実行中に画面コンポーネントを無効にする場合に使用します。コンポーネントの [無効] 項目の値を [処理中] 属性に設定します。[処理中] が true の場合、[無効] フィールドも true に設定されます。アクションが完了して [処理中] が false に設定されると、[無効] フィールドも False に設定されます。

考慮事項

  • ユーザーが Web ブラウザーでアクションボタンコンポーネントを使用してフローを実行すると、そのコンポーネントに関連付けられたアクションの出力をブラウザーで使用できます。機密情報をアクションボタンコンポーネントの出力として共有しないでください。
  • 待機要素を含む自動起動フローまたは待機要素を含むサブフローは、待機要素の後に再開されないため、アクションボタンアクションとしてはサポートされません。
  • アクションボタンは、繰り返しコンポーネントではサポートされていません。
  • 非同期パスを使用したフローの起動はサポートされていません。
  • アクションボタンから起動されたフローに障害パスがなく、エラーが発生した場合は、アクションボタンの下に一般的なエラーメッセージが表示されます。代わりに役に立つエラーメッセージをユーザーに表示するには、起動されたフローに障害パスを追加します。各障害パスで、出力変数を {!$Flow.FaultMessage} に設定します。次に、アクションボタンを含むフロー画面で、条件付きで非表示になり、役に立つエラーメッセージと障害メッセージ変数が含まれる表示テキストコンポーネントを追加します。
    メモ 表示テキストコンポーネントのコンテンツにエラーメッセージが含まれていても、スクリーンリーダーではエラーメッセージとして読み上げられません。
  • 画面アクションの自動起動フローの入力変数または出力変数がレコード変数で、オブジェクトの項目名を変更した場合、入力と出力を更新しても新しい項目名は反映されません。
  • 画面アクションの自動起動フローの入力変数または出力変数が Apex 変数で、Apex 種別の構造を変更した場合、入力と出力を更新してもその変更は反映されません。
