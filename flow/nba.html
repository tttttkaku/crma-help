Next Best Action について

一意の条件に合わせて調整した、ユーザーへの提案とアクションを作成して表示します。ビジネスロジックを適用する戦略を作成し、おすすめを絞り込みます。戦略により、おすすめが洗練され、修正、割引、またはアドオンサービスのようないくつかの主要な提案に変換されます。最終的なおすすめを Lightning アプリケーションまたは Experience Builder サイトに表示します。

  • Einstein Next Best Action のエンタイトルメント
    Einstein Next Best Action には、使用量ベースのエンタイトルメントがあります。すべての組織は Next Best Action 要求の無料の毎月の許容量を受け取ります。使用量が無料の毎月の許容量、または購入したエンタイトルメントを超えると、契約への追加事項について話し合うために Salesforce から連絡があります。使用量を追跡するには、[設定] から [組織情報] に移動します。

おすすめの表示

戦略を作成したら、戦略を実行しておすすめを表示するページを選択します。おすすめを表示する場所に応じて、Lightning レコードページ、アプリケーションのホームページ、Experience Cloud サイトページ、Visualforce ページ、または外部サイトを使用できます。

戦略の作成

戦略によって、Salesforce Lightning レコードページに Einstein Next Best Action のおすすめを表示するタイミングと方法が決まります。たとえば、一部の顧客に割引を提供する場合、適切な顧客レコードを収集し、提示する割引オプションを特定する戦略を作成します。戦略を作成するには、Flow Builder (推奨) または Strategy Builder を使用できます。

必要なエディション

Next Best Action でサポートされるエディションを表示。
メモ 可能な場合は、[おすすめ戦略] フロー種別を使用して Flow Builder で戦略を作成することをお勧めします。

Strategy Builder ではなく Flow Builder を選択する理由は?

Flow Builder は、ビジネスプロセスの自動化を構築するための機能が統合された充実した Salesforce ツールで、今後すべてのフローオートメーション機能と機能強化のホームとなります。Strategy Builder は従来のツールであり、今後更新される予定はありません。

  • Flow Builder の戦略
    Flow Builder の戦略によりビジネスロジックが指定され、Salesforce Lightning レコードページに Einstein Next Best Action コンポーネントの出力が生成されます。
  • Strategy Builder の戦略
    Strategy Builder または Flow Builder を使用して、Einstein Next Best Action の戦略を作成できます。推奨方法は Flow Builder です。

Flow Builder の戦略

Flow Builder の戦略によりビジネスロジックが指定され、Salesforce Lightning レコードページに Einstein Next Best Action コンポーネントの出力が生成されます。

必要なエディション

Next Best Action でサポートされるエディションを表示します。

Flow Builder の戦略では、次のいずれかの方法でおすすめを生成します。

  • おすすめオブジェクトで作成された定義済みのおすすめを使用する。この方法では、おすすめオブジェクトで個別におすすめを作成し、1 つ以上の Next Best Action コンポーネントで使用します。この方法は、少数のおすすめを作成する場合に適しています。
  • 個別のおすすめレコードを使用せずにその場でおすすめを作成する。この方法では、戦略フローで複数のおすすめを動的に作成できます。この方法は、多数のおすすめを作成する場合に適しています。たとえば、広範な商品リストがある場合、リスト内の商品ごとに異なるアップセルのおすすめを作成できます。

定義済みのおすすめを使用した戦略フローの作成

定義済みのおすすめに基づいて戦略フローを作成します。この方法は、少数のおすすめを複数の Einstein Next Best Action コンポーネントで使用できるようにする場合に適しています。たとえば、顧客に割引を提供するおすすめを作成できます。誕生日割引や新規顧客割引の戦略を作成するときに、同じおすすめを使用できます。

戦略フローを作成する前に、おすすめオブジェクトでおすすめを作成します。

メモ 一度に多数のおすすめを動的に作成する場合、おすすめオブジェクトで個別のレコードを作成せずに、その場でおすすめを使用して戦略フローを作成できます。
  1. [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択し、[新規フロー] をクリックします。
  2. [すべて + テンプレート] タブで、[おすすめ戦略] フロー種別を選択し、[作成] をクリックします。
  3. フローに [レコードを取得] 要素を追加して、おすすめで使用するレコードを読み込みます。
    1. 表示ラベルと API 参照名を入力します。
    2. おすすめで使用するオブジェクト (取引先、ケース、取引先責任者オブジェクトなど) を選択します。
    3. 絞り込みセクションで、戦略で使用するオブジェクトのレコードを制限する条件を追加します。
  4. [レコードを取得] 要素を追加して、定義済みのおすすめを戦略に取り込みます。
    1. 表示ラベルと API 参照名を入力します。
    2. [おすすめ] オブジェクトを選択します。
    3. 絞り込みセクションで、条件を使用して、使用するおすすめを指定します。
  5. 必要に応じて他のフロー要素を追加して戦略を定義します。
  6. おすすめを Einstein Next Best Action コンポーネントで使用できるようにします。
    1. [割り当て] 要素を追加します。
    2. [変数] に [outputRecommendations] を選択します。
    3. [演算子] で [次の文字列と一致する] を選択します。
    4. [値] で、定義済みのおすすめを選択します。
  7. フローを保存します。
  8. フローを有効化します。

You’re now ready to Lightning レコードページに Next Best Action コンポーネントを追加します。

その場でおすすめを使用した戦略の作成

一括で動的に作成する複数のおすすめを使用して、戦略フローを作成します。たとえば、商品リストの商品ごとに異なるアップセルのおすすめを提案する戦略を作成できます。この方法では、個別のおすすめレコードを使用せずに戦略フローで直接おすすめを作成します。

メモ 複数の Einstein Next Best Action コンポーネントでおすすめを再利用する場合は、おすすめオブジェクトで作成された定義済みのおすすめを使用します。
  1. [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択し、[新規フロー] をクリックします。
  2. [すべて + テンプレート] タブで、[おすすめ戦略] フロー種別を選択し、[作成] をクリックします。
  3. フローに [レコードを取得] 要素を追加して、おすすめで使用するレコードを読み込みます。
    • 表示ラベルと API 参照名を入力します。
    • おすすめで使用するオブジェクト (商品オブジェクトなど) を選択します。
    • 絞り込みセクションで、戦略で使用するオブジェクトのレコードを制限する条件を追加します。
  4. [おすすめの割り当て] 要素を追加します。
    • 表示ラベルと API 参照名を入力します。
    • [レコードコレクション変数] で [レコードを取得] で生成した変数を選択します。

      変数を選択すると、対象の項目が自動的に入力されます。

    • 対象の項目で次の値を設定します。
      • AcceptanceLabel — 提案を受け入れるボタンの表示ラベル。
      • RejectionLabel — 提案を却下するボタンの表示ラベル。
      • ActionFlow — 提案が受け入れられた、または却下されたときに、アクションを実行するフローの API 参照名。
      • Description — Next Best Action コンポーネントでボタンの上に表示されるテキスト。
  5. おすすめを Einstein Next Best Action コンポーネントで使用できるようにします。
    • [割り当て] 要素を追加します。
    • [変数] に [outputRecommendations] を選択します。
    • [演算子] で [次の文字列と一致する] を選択します。
    • [値] で、[おすすめの割り当て] ステップからのおすすめを選択します。
  6. フローを保存します。
  7. フローを有効化します。

You’re now ready to Lightning レコードページに Next Best Action コンポーネントを追加.

Einstein Next Best Action の考慮事項

戦略とおすすめを使用するときの考慮事項は、次のとおりです。

必要なエディション

Next Best Action のサポートされているエディションを表示。

Einstein Next Best Action では、フロー、おすすめ、戦略、コンポーネントを使用します。また、レポート用の標準オブジェクトも備わっています。

フロー

  • フローの要件: すべてのおすすめオブジェクトはフローを参照する必要があります。フローがない場合、おすすめを表示できません。
  • 有効なフロー要件: 戦略では、有効なフローがあるおすすめのみが読み込まれます。
  • REST API 実行コンテキスト: REST API を使用してフローを開始すると、認証済みユーザーのコンテキストで実行されます。実行ユーザーのプロファイルと権限セットによって、フローのオブジェクト権限と項目レベルのアクセス権が決まります。フローを実行するユーザーのプロファイルと権限セットを作成します。

おすすめ

  • カスタムカテゴリ項目: おすすめオブジェクトとレイアウトにカスタムカテゴリ項目を追加することを検討してください。カテゴリ項目を使用すると、おすすめの読み込み、並び替え、絞り込みをより詳細に制御でき、フローの作成時により多くのオプションを使用できます。
  • おすすめの表示ラベル: 対象利用者に適した名前、説明、承諾表示ラベル、却下表示ラベルを作成します。
  • 名前が重複する: おすすめ名を再利用すると、既存のおすすめが上書きされるのではなく、おすすめが作成されます。名前が重複していると、戦略で重複したおすすめが顧客に表示される可能性があります。
  • フロー状況の表示: すべてのフロー (無効と有効の両方) が [アクション] ドロップダウンリストに表示されます。おすすめを保存すると、フローが有効かどうかを確認できます。
  • 無効なフロー参照: 無効なフローを参照するおすすめを作成できますが、フローを有効化するまで戦略で読み込まれません。

戦略

  • おすすめの要件: すべての戦略で 1 つ以上のおすすめが必要です。
  • おすすめの読み込み: Flow Builder では、おすすめオブジェクトのレコードを読み込んで絞り込んだり、おすすめの割り当て要素を使用して戦略の最後に任意のオブジェクトのレコードを読み込んで絞り込み、おすすめに変換したりできます。
  • 繰り返しの制限要素: Flow Builder の繰り返しの制限要素を使用して、すべてのユーザーが定義された日数以内に定義された回数以上応答した後におすすめを非表示にします。繰り返しの制限を機能させるには、レコメンデーションにユニークなレコードIDが必要です。
  • サブフローのサポート: おすすめ戦略フローでは、コールサブフローはサポートされません。

反応の追跡とレポート

  • カスタムレポートタイプ: Flow Builder で戦略を作成する場合、おすすめ戦略評価指標とおすすめ応答の主オブジェクトを使用してカスタムレポートタイプを作成します。
  • 一意のレコード ID 要件: [おすすめの反応] 主オブジェクトからレポートを作成する場合、再提案を制限するためにおすすめソース名と ID を正しく表示するには、おすすめに一意のレコード ID が必要です。

Einstein Next Best Action の例

以下の例で、Einstein Next Best Action コンポーネントの作成プロセスについて説明します。

必要なエディション

Next Best Action でサポートされるエディションを表示する。
  • 各取引先へのギフトバスケットの提供
    Lightning の取引先レコードページで Next Best Action コンポーネントを使用して、各取引先にギフトバスケットを提供します。顧客が提供を受け入れると、受取人の名前と配送先住所を収集するためのフォームが開きます。フォームを送信すると、依頼メールが配送部門に送信されます。
  • 顧客満足度を使用したおすすめの促進
    Einstein Next Best Actionを使用して、顧客満足度スコアに基づいておすすめをカスタマイズします。たとえば、満足度の低い顧客にはサービス契約割引を提供し、満足度の高い顧客には新商品プレビューを提供します。対象を絞ったオファーで維持とアップセルを促進します。

顧客満足度を使用したおすすめの促進

Einstein Next Best Actionを使用して、顧客満足度スコアに基づいておすすめをカスタマイズします。たとえば、満足度の低い顧客にはサービス契約割引を提供し、満足度の高い顧客には新商品プレビューを提供します。対象を絞ったオファーで維持とアップセルを促進します。

必要なユーザー権限

準備

顧客満足度スコアを記録し、そのスコアに基づいて表示するおすすめを決定するために、次の例には 2 つのカスタム項目が含まれています。例に従って手順を実行するには、開始前に次の 2 つの項目を設定してください。

取引先責任者オブジェクトのカスタム項目:

  • 項目の表示ラベル: CSAT score
  • API 表示ラベル: CSAT_score
  • 項目のデータ型: 数値 (文字数 2、小数点の位置 0)

おすすめオブジェクトのカスタム項目:

  • 項目の表示ラベル: Category
  • API 表示ラベル: category_c
  • 項目のデータ型: テキスト (文字数 18)

この Next Best Action のおすすめを設定する手順は、次のとおりです。

  1. 高 CSAT と低 CSAT のおすすめのアクションフローを作成します。

  3. カスタマーサービスまたは取引先担当者におすすめがどのように表示されるかを決定する戦略フローを作成します。
  4. 取引先責任者レコードページで、おすすめを表示して戦略を実行する Next Best Strategy コンポーネントを追加します。

おすすめ戦略フローの作成

おすすめ戦略フローでは、おすすめを取引先責任者レコードページに表示するタイミングと方法を指定します。

  1. [設定] で、[クイック検索] ボックスに「フロー」と入力して、[フロー] を選択し、[新規フロー] をクリックします。

  3. フローに [レコードを取得] 要素を追加して、おすすめで使用する取引先責任者レコードを読み込みます。
    1. 表示ラベルと API 参照名を入力します。
    2. [データソース] で、[Salesforce オブジェクト] を選択します。
    3. [取引先責任者] オブジェクトを選択します。
    4. 絞り込みセクションで、[Contact ID equals recordId] という条件を追加します。
    5. すべてのレコードを保存するオプションと、すべての項目を保存するオプションを選択します。
  4. 顧客の CSAT スコアに応じて異なるおすすめに対応するには、[レコードを取得] 要素の後に決定要素を追加します。
    1. 表示ラベル「CSAT Score?」 (CSAT スコア?) とAPI 参照名「CSAT_score」を入力します。
    2. [Select Decision Logic (決定ロジックを選択)] で、[Define Manually (Default) (手動で定義 (デフォルト))] を選択します。
    3. 取引先責任者レコードの [CSAT Score (CSAT スコア)] 項目の値が 3 以下である条件を使用して、「Low CSAT」(低 CSAT) 結果を定義します。
    4. 結果を追加し、取引先責任者レコードの [CSAT Score (CSAT スコア)] 項目の値が 4 以上という条件で High CSAT 結果用に設定します。
    5. CSAT スコアのない顧客のために、[デフォルトの結果] はそのままにします。
    6. [完了] をクリックします。
  5. [レコードを取得] 要素を追加して、低 CSAT 条件と高 CSAT 条件の適切なおすすめを取り込みます。
    1. 表示ラベルと API 参照名を入力します。
    2. [おすすめ] オブジェクトを選択します。
    3. 絞り込みセクションで、おすすめオブジェクトの [Category (カテゴリ)] 項目の API 参照名を選択し、低スコアまたは高スコアの条件を指定して、適切な条件を追加します。
    4. すべてのレコードを保存するオプションと、すべての項目を保存するオプションを選択します。
    5. [完了] をクリックします。
  6. 各取引先レコードのおすすめを 1 回のみ表示し、フロー出力を割り当てるには、低スコアと高スコアのパスに [繰り返しを制限] 要素を追加します。
    1. 表示ラベルと API 参照名を入力します。
    2. [おすすめコレクション] で、低スコアまたは高スコアのおすすめを選択します。
    3. [Look for These Records (これらのレコードを検索)] で [承諾済みまたは却下済み] を選択します。
    4. [Look for This Many Messages (この数のメッセージを検索)] は、デフォルト設定の「1」のままにします。
    5. このパスからの出力を Next Best Action で使用できるようにするには、[詳細] をクリックし、[手動で変数を割り当て] を選択して、[outputRecommendations] を選択します。
    6. [完了] をクリックします。
  7. フローを保存して、「CSAT Strategy Flow」(CSAT 戦略フロー) と名前を付けます。
  8. フローを有効化します。
  9. [フロー] ページに戻るには、[戻る] をクリックします。

必要なエディション

Next Best Action でサポートされるエディションの表示。

Einstein Next Best Action は、フロー、戦略、およびおすすめオブジェクトを使用してアクションをユーザーに推奨するソリューションです。これらのおすすめは、Salesforce 組織の Lightning ページ、Experience Cloud サイト、外部サイトなど、さまざまな種別のページに表示できます。

おすすめは、推奨されたアクションを承諾または却下するオプションと共にユーザーに表示されます。各おすすめには、画像、ボタンテキストや説明などの重要なテキスト値、そしてユーザーが応答したときに実行されるように割り当てられたフローが含まれます。これらは、おすすめ標準オブジェクトに保存して参照するか、または戦略の作成時に手動で組み立てることができます。

戦略では、データとビジネスプロセスに基づいて、ユーザーに表示するおすすめを決定します。ページで Einstein Next Best Action を設定する場合は、表示されるおすすめを定義するための戦略をそのロケーションに割り当てます。

組織に多数のおすすめレコードがある場合でも、状況に応じてどのおすすめが表示されるかを制御できます。戦略では、おすすめ項目、実行ユーザーに関連する項目、現在表示されているレコードに関連する項目など、使用可能なすべての値に基づいておすすめを絞り込むことができます。

重要 Flow Builder では、フローの最後にある outputRecommendations コレクション変数に含めることで、表示するおすすめを定義します。
  1. おすすめの計画と自動化

    おすすめの表示場所、表示対象、および表示される条件を決定します。ユーザーがおすすめを受け入れたときに実行する自動化の計画を作成します。

  2. 「フローの作成」を参照してください。

    Flow Builder では、ユーザーがおすすめを承諾または却下した場合に実行されるフローを設計して作成します。おすすめには画面フローと自動起動フローのみを割り当てることができます。非アクティブまたは無効なフローが割り当てられている場合、おすすめは表示されません。

  3. おすすめの作成

    おすすめは、取引先や取引先責任者と同じような標準 Salesforce レコードです。おすすめを作成するには次の方法があります。

    • おすすめオブジェクトでおすすめレコードを作成します。
    • 戦略の作成時に他のデータからおすすめを作成します。Flow Builder では、[おすすめの割り当て] 要素またはカスタム Apex 呼び出し可能アクションを使用します。
    • Einstein レコメンデーションビルダーの AI を使用して、おすすめを自動的に生成します。
  4. 戦略の作成

    フローを作成し、おすすめレコードの計画を作成したら、Flow Builder を使用して戦略を作成します。

    Flow Builder で戦略を作成するには、次の手順に従います。

    1. [設定] の [フロー] ページに移動して [新規フロー] をクリックします。
    2. [テンプレートを使用] を選択し、[次へ] をクリックします。
    3. おすすめ戦略フロー種別を選択し、[作成] をクリックします。
    4. おすすめオブジェクトや現在表示されているレコードに関連するオブジェクトなどの Salesforce レコードからデータを取得するには、[レコードを取得] 要素を追加します。要素のコレクションに保存されているおすすめは、[レコードを取得] 要素で条件の要件を使用して絞り込めます。または、[おすすめの割り当て] 要素またはカスタム Apex 呼び出し可能アクションを使用して、他のデータからおすすめを作成できます。

おすすめ項目

おすすめは、Einstein Next Best Action 戦略に基づいてユーザーに表示され、ユーザーが応答する推奨アクションです。おすすめを作成するには、次の項目を使用してデザインを定義します。

必要なエディション

Next Best Action でサポートされるエディションを表示します。

次の方法でおすすめを作成できます。

  • Flow Builder または Strategy Builder で必要に応じておすすめを組み立てます。
  • おすすめオブジェクトで、取引先や取引先責任者のような標準 Salesforce レコードとしておすすめを作成します。おすすめレコードは、アプリケーションランチャーの [おすすめ] タブで作成できます。
  • Einstein レコメンデーションビルダーの AI を使用して、おすすめを自動的に生成します。

  • 画像 (1) — おすすめに表示される画像。Einstein Next Best Action Lightning ページコンポーネントにこの画像を表示するには、Lightning ページコンポーネントを設定するときに [画像を表示] を選択します。
  • 名前 (2) — おすすめの上部にあるヘッダーテキスト。Einstein Next Best Action Lightning ページコンポーネントにこのテキストを表示するには、Lightning ページコンポーネントを設定するときに [タイトルを表示] を選択します。
  • 説明 (3) — おすすめに表示される追加の説明テキスト。Einstein Next Best Action Lightning ページコンポーネントにこのテキストを表示するには、Lightning ページコンポーネントを設定するときに [説明を表示] を選択します。
  • 承諾の表示ラベル (4) — おすすめを受け入れるボタンに表示されるテキスト。このオプションは常に表示されます。
  • 却下の表示ラベル (5) — おすすめを却下するボタンに表示されるテキスト。Einstein Next Best Action Lightning ページコンポーネントにこのオプションを表示するには、Lightning ページコンポーネントを設定するときに [却下オプションを表示] を選択します。

アクション

  7. Strategy Builder で、おすすめをどのように表示するかを決定するおすすめ戦略を作成します。
  8. 必要に応じて、おすすめオブジェクトおよびおすすめレイアウトにカスタムカテゴリ項目を追加します。カスタムカテゴリ項目を追加すると、Strategy Builder でのおすすめの読み込み、絞り込み、並び替えを簡略化できます。

    おすすめは、Einstein Next Best Action 戦略に基づいてユーザーに表示され、ユーザーが応答する推奨アクションです。おすすめを作成するには、次の項目を使用してデザインを定義します。
  • おすすめが受け入れられたときのフローの起動
    各おすすめは 1 つのフローに関連付けられます。デフォルトでは、Next Best Action では、おすすめが受け入れられた場合にフローを起動します。次に、フローでケースの更新やメールの送信などのアクションを実行します。
  • おすすめが受け入れられたまたは却下されたときのフローの起動
    各おすすめは 1 つのフローに関連付けられます。デフォルトでは、Next Best Action では、おすすめが受け入れられた場合にフローを起動します。次に、フローでケースの更新やメールの送信などのアクションを実行します。ただし、おすすめがユーザーから却下されたときもフローを起動できるため、柔軟性が高まります。たとえば、おすすめが却下されたときにフローで自動化プロセスを実行したり、別のシステムに書き込んだり、アラームメールを作成したりできます。
  • Next Best Action フローへの [繰り返しの制限] 要素の追加
    おすすめ戦略フローに [繰り返しの制限] 要素を追加すると、同じおすすめや提案を一定の期間に同じレコードや同じユーザーに表示する回数を制限できます。

たとえば、2 つの異なる戦略で A/B テストを実行し、それらの相対的なパフォーマンスを比較します。サービスエージェントが戦略 B から提供されたおすすめをより多く受け入れている場合、総計値を使用して理由を見つけます。

  5. ユーザーが使用できるようにするレポートタイプをリリースします。
  6. ユーザーがこれらのカスタムレポートタイプを使用してレポートを作成できることをユーザーに知らせます。
  7. ユーザーはカスタムレポートタイプからダッシュボードを作成することもできます。

  6. 戦略への変更を保存します。
  7. 期待どおり動作することを確認するために、戦略をテストします。

  • Strategy Builder の拡張要素
    各種サービス (Einstein Discovery、Einstein 予測ビルダーなど) からの AI による予測を取得して、Next Best Action のおすすめを追加の情報 (傾向スコアなど) で拡張できます。拡張要素を使用すると、戦略が実行されるたびに一連のおすすめをその場で変更できます。これらのおすすめは、Salesforce のレコードとして静的およびライブにすることも、動的にして外部データソースから提供することも、他の Salesforce オブジェクトにすることもできます。
  • Strategy Builder の生成要素
    可能性が多数あり、おすすめを手動で作成することが不便な場合、生成要素を使用すると、パーソナライズされたおすすめを動的に生成できます。生成要素により、外部データソースまたはその他の Salesforce オブジェクトからメモリ内のおすすめをその場で作成できます。
  • Strategy Builder の読み込み要素
    [読み込み] は、戦略ブランチの最初の要素です。おすすめオブジェクトのレコードを読み込んで絞り込みます。または、任意のオブジェクトのレコードを読み込み、絞り込んで、戦略の最後で対応付け要素を使用しておすすめに変換します。読み込み要素により、戦略が実行されたときに評価されるおすすめが決定されます。
  • Strategy Builder の条件要素
    コンテキストに応じて、望ましくないおすすめをブロックまたは除外できる式を作成します。式は、ブランチを通過するおすすめごとに評価されます。
  • Strategy Builder の再提案を制限要素
    ユーザーに同じおすすめを表示する頻度を決定します。おすすめを再度表示するまでのおすすめへのユーザーの反応回数や待機日数を決定できます。
  • Strategy Builder の対応付け要素
    対応付け要素では、Apex コードの代わりに数式を使用して、おすすめ項目の作成と既存の項目の変更を行います。これを使用して、1 つの名前のおすすめ項目のデータを別の名前のフロー入力に渡したり、コンテキスト固有のデータを使用して説明、名前、その他の項目をパーソナライズしたりします。
  • Strategy Builder の並び替え要素
    ブランチ内でのおすすめの並び替え方法を選択し、おすすめ項目を使用して並び替えます。
  • Strategy Builder のブランチのマージ要素
    複数のブランチのおすすめを 1 つのブランチに結合します。
  • Strategy Builder のブランチセレクター要素
    ブランチセレクターで複数のブランチを絞り込み、各ブランチに一意の式を作成します。式が true の場合、ブランチのおすすめは通過が許可され、1 つのブランチに結合されます。
  • Strategy Builder の空でない最初のブランチ要素
    空でない最初のブランチ要素では、キャンバスに表示される順序でブランチを絞り込むことができます。おすすめが含まれる最初のブランチは通過が許可され、他のブランチはすべてブロックされます。

global class Enhance_GetAccountDiscount {
    @InvocableMethod(label='Enhance with Discounts Based on Age' description='Returns an enhanced set of recommendations with appropriate discounts')
    global static List<List<Recommendation>> getDiscounts(List<DataContainer> inputData){
        
        List<Recommendation> recommendations = inputData[0].recommendations; 
        List<List<Recommendation>> outputs = new List<List<Recommendation>>();       
        Account[] accounts = [SELECT Name, Description,CreatedDate, id FROM Account WHERE id = :inputData[0].accountId];
           Double ageAccountMonths = accounts[0].CreatedDate.date().monthsBetween(date.today()); 
        Double ageAccount = ageAccountMonths/12;       
        List<Recommendation> returnedRecommendations = new List<Recommendation>(); 
        for (Recommendation r:recommendations){
            if(ageAccount > 1){
                r.Description = r.Description + ' with a 5% discount';
            }
            else if (ageAccount > 2){
                r.Description = r.Description + ' with a 10% discount';
            }
            else if (ageAccount > 5){
                r.Description = r.Description + ' with a 20% discount';
            }

                daysSinceLastContact = account.LastContactDate__c.daysBetween(date.today());

                        Name = account.Name,

                        ActionReference = 'simpleFlow',
                        AcceptanceLabel = 'View'
                    );

                }
            }
        }
        outputs.add(recs);
        return outputs; 
    }
}

戦略は、ケースや取引先責任者などの特定のオブジェクトと連携するように設計されています。Strategy Builder の要素では、戦略の実行時に渡される実際のレコードのプレースホルダーとして $Record を使用します。

  • 戦略に必要な要素として [条件] または [ブランチセレクター] を選択します。
  • 式を入力します。式は、標準および詳細の 2 種類のモードで作成できます。標準モードは宣言型です。検索および選択で数式を作成します。式の複雑さが高い場合、特定の演算子を標準モードで使用できない場合、または連結を使用する場合は、詳細モードを使用します。
  • 標準モードで条件を設定します。実行時に、指定した順に条件が評価されます。
列ヘッダー 説明
リソース 承諾または却下の表示ラベル、アクション、ID、名前などの値を評価するおすすめリソース。たとえば、戦略はケースに関連付けられています。リソースは $Record.Account.Type または $Record.Account.Contact.Name です。
演算子 そのリソースに適した演算子 (Equals、Does Not Equal、Starts With、Contains、Less Than Or Equal To、Is Blank など) を選択します。使用可能な演算子は、そのリソースに関連付けられているデータ型によって決まります。データ型には、テキスト、数値、ブール値、選択リストが含まれます。
値

オプション:

  • おすすめリソースおよび演算子に適した値を選択します。たとえば、リソースとして $Record.Status、演算子として Does Not Equal を入力した場合、使用可能な値は On Hold、Escalated、Closed、New です。
  • リテラル値を手動で入力します。

同じ行の [リソース] と [値] のデータ型は、互換性がある必要があります。

日付値から数値を加算または減算すると、日付は時間単位ではなく日単位で調整されます。
選択肢 決定結果の動作
すべての条件に一致 いずれかの条件が false の場合、おすすめで次の結果の条件が評価されます。
いずれかの条件に一致 いずれかの条件が true の場合、おすすめでこの結果のパスがすぐに使用されます。

たとえば、連絡先レコードにカスタム項目 Has_Mobile_Service__c を作成します。Strategy Builder の式で $Record.Contact.Has_Mobile_Service__c = false を使用する場合、ケースレコードを操作していると、式が解決されるときに要求と一緒に指定された recordID に $Record から置き換えられます。recordID が $Record に置き換えられるのは、ケースレコードに取引先責任者との参照関係があるためです。

  • 数式で $Record 関数を使用して、コンテキストオブジェクトを参照します。

例: ISPICKVAL($Record.Account.Tier__c, 'Premium')

メモ

コンテキストオブジェクトは、おすすめを表示するオブジェクトです。戦略を編集して、[おすすめが表示されるオブジェクト] でオブジェクトを選択することで、コンテキストオブジェクトを選択または変更します。

  • プレーンテキスト表示ラベル名を使用して、おすすめオブジェクトの項目を参照します。このオプションは、ブランチセレクター要素ではなく、条件要素および読み込み要素でのみ使用できます。

例: AcceptanceLabel = =‘Yes, please’

  • $nameOfExternalConnection.dataFromExternalConnection 構文を使用して、外部接続から返された項目にアクセスします。外部接続は、ツールボックスの [管理] タブで管理します。

例: $GetCreditScoreContext.output >= 760

  • $Request を使用して、ユーザーがフォームに入力する情報にアクセスし、その情報を使用して特定のおすすめを要求します。このオプションは、エクスペリエンスビルダーサイトの [検索] ページおよび [【カスタマーサポートへの連絡】] ページでのみ使用できます。

例: CONTAINS($Request.search, 'paperless billing') || CONTAINS($Request.search, 'order checks') || CONTAINS($Request.search, 'new address')

複数選択リスト項目では、Includes ($Record.CarType__c, ‘Audi,’‘BMW’) などの値を入力します。

Strategy Builder のテンプレートの作成、パッケージ化、配布

会社の開発者は、Developer Edition 組織からの複数の Salesforce 組織で使用する戦略と戦略テンプレートを作成してパッケージ化できます。独立系ソフトウェアベンダーは、AppExchange 上でテンプレートを公開し、登録者に配布することもできます。管理パッケージ内のテンプレートとしてマークされていない戦略は、知的財産 (IP) 保護が設定されており、編集することも、複製することもできません。IP 保護により、戦略内の独自情報が保護されます。

戦略テンプレートへの変更は、管理パッケージを通じて配布します。戦略テンプレートをインストールする登録者は、戦略テンプレートを Strategy Builder で開いて複製し、用途に応じてカスタマイズできます。パッケージアップグレードを通じて更新を戦略テンプレートに公開する場合、テンプレート更新によって登録者のコピーに影響が及ぶことはありません。

  1. Strategy Builder で、テンプレートにする戦略を作成します。
  2. 戦略のプロパティを開き、[テンプレート] を選択します。
  3. 必要な場合は、管理パッケージを作成します。
  4. 管理パッケージで戦略テンプレートを配布し、登録者に戦略テンプレートが提供されていることを知らせます。
例

保険会社の戦略を作成してパッケージ化するとします。保険の法律や規制は場所によって異なるため、登録者は必要に応じて戦略を変更したいと考えています。このような場合には、戦略テンプレートを作っておけば、登録者は戦略を変更できます。
