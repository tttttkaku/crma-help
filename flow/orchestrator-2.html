フローオーケストレーションの対話型ステップ

対話型ステップは有効な画面フローを参照し、オーケストレーション作業項目を生成します。割り当てられたユーザーは、関連レコードページの [フローオーケストレーション作業ガイド] で有効な画面フローを完了します。対話型ステップを開始できるタイミング、またはその状況を [完了] に設定するタイミングを制御できます。すべての対話型ステップは非同期で処理されます。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
メモ フローオーケストレーションのステップリソースは、フロー内で廃止されたステップ要素とは関係していません。

対話型ステップ作業サイクル

バージョン 57.0 以前で実行されているフローの場合、対話型ステップが完了としてマークされると、関連付けられた作業項目を完了したユーザーのコンテキストでオーケストレーションの実行が再開されます。作業項目を完了したユーザーに「フローを実行」権限がなく、特定のフローへの詳細なアクセス権がある場合、オーケストレーションの実行を再開することはできません。オーケストレーションを再開するには、「フローを実行」権限を持つユーザーが別の作業項目を実行するか、システム管理者が一時停止中のオーケストレーション実行の ID を使用してフローオーケストレーションイベントをトリガーします。

オーケストレーションのバージョン管理

フローオーケストレーションには、オーケストレーションのバージョンと、オーケストレーションによってコールされるフローのバージョンの 2 つのバージョン設定があります。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。

オーケストレーション定義のバージョン設定

オーケストレーション定義は、一度に1つの有効なバージョンを持つことができます。オーケストレーション実行で使用されるオーケストレーション定義バージョンは、実行が開始された時点で有効なバージョンです。

  • オーケストレーション定義に基づくオーケストレーション実行が開始された後に新しいバージョンのオーケストレーション定義を有効化すると、オーケストレーション実行は開始元の定義バージョンを引き続き実行します。
  • 新しいバージョンが有効化された後に開始されたオーケストレーション実行でのみ、新しい有効なバージョンが使用されます。

フロー定義のバージョン設定

対話型ステップとバックグラウンドステップはフローを呼び出します。ステップでは、ステップの開始時に有効なフローの定義バージョンが使用されます。

  • 関連付けられたステップが作成された後に参照されるフローの新しい定義バージョンを有効化すると、フローの以前の有効なバージョンが実行されます。
  • オーケストレーション実行が開始された後、関連付けられたステップ実行が作成される前に参照されるフローの新しい定義バージョンを有効化すると、新しいバージョンのフローが実行されます。

フローオーケストレーション作業項目

オーケストレーションの対話型ステップが実行されると、作業項目が作成され、ユーザー、グループ、またはキューに割り当てられます。その後、オーケストレーション実行によって、指定されたレコードページへのリンクが記載されたメールが、割り当てられたすべてのユーザーに送信されます。指定されたレコードページのオーケストレーション作業ガイドコンポーネントで作業を完了します。

  • エクスペリエンスビルダーで、システム管理者はオーケストレーション作業項目リストオブジェクトページを Aura サイトと LWR サイトに追加します。

対話型ステップが実行されると、オーケストレーションによって作業項目が作成され、指定された内部ユーザーに割り当てられます。割り当てられたユーザーに内部関連レコードページへのリンクが記載されたメールが送信され、完了すべき作業項目があることが通知されます。作業項目は、割り当てられたユーザーの [ToDo] リストにも表示されます。ユーザーが作業項目へのリンクをクリックすると、内部関連レコードページの作業ガイドで対話型ステップに関連付けられた画面フローを完了できます。

ログイン情報が設定された Experience Cloud サイト訪問者に割り当てられた作業

対話型ステップが実行されると、オーケストレーションによって作業項目が作成され、指定されたログイン情報が設定された Experience Cloud サイト訪問者に割り当てられます。割り当て先には、完了すべき作業項目があることを通知するメールが送信されます。このメールには、そのユーザーがメンバーである最も古いライブサイトの関連レコードページへのリンクが含まれています。サイト訪問者はメールリンクをクリックすると関連レコードページにリダイレクトされ、そのページの [作業ガイド] で関連する画面フローを完了します。

内部グループまたはキューに割り当てられた作業

対話型ステップが実行されると、オーケストレーションによって作業項目が作成され、指定されたグループまたはキューに割り当てられます。割り当てられた内部グループまたは内部キュー内のすべてのユーザーに、内部関連レコードページへのリンクが記載されたメールが送信され、完了すべきアクションがあることが通知されます。ユーザーがメール内のリンクをクリックして作業項目を開くと、内部関連レコードページの作業ガイドで画面フローを実行できます。

割り当てられた作業項目は、画面フローを最初に完了したユーザーによって完了されます。2 人のユーザーが画面フローを同時に実行すると、フローを 2 番目に完了したユーザーにはエラーが表示されます。作業項目が完了すると、作業ガイドを参照している他のグループまたはキューメンバーには、期限切れのバッジが付けられた項目が無効になります。ページを離れるか、ページを更新するか、別の作業項目を完了するまで、リストから削除されません。作業ガイドを積極的に表示していない場合、次にページにアクセスするときに関連作業が表示されなくなります。

ログイン情報が設定された Experience Cloud サイト訪問者のグループまたはキューに割り当てられた作業

対話型ステップが実行されると、オーケストレーションによって作業項目が作成され、ログイン情報が設定された Experience Cloud サイト訪問者の指定されたグループまたはキューに割り当てられます。割り当てられたグループまたはキュー内のサイト訪問者は、完了すべきアクションがあることをメールで通知されます。通常、このメールには、訪問者全員がメンバーである最も古いライブ Experience Cloud サイトの関連レコードページへのリンクが含まれます。グループまたはキューのメンバーがリンクをクリックすると、訪問者は、グループまたはキューのすべてのメンバーのログイン情報が設定された最も古いライブ Experience Cloud サイトの関連レコードページに移動します。サイト訪問者は、その関連レコードページから作業ガイドの関連画面フローを完了できます。

Experience Cloud サイト訪問者は、自分に割り当てられた作業項目をオーケストレーション作業項目リストオブジェクトページでも参照できます。[オーケストレーション作業項目リスト] から、割り当てられた作業にアクセスすることもできます。ログイン情報が設定されたサイト訪問者は、自分がメンバーである Aura または LWR サイトの関連レコードページに移動して、作業ガイドの画面フローを実行できます。

割り当てられた作業項目は、最初に画面フローを完了したログイン情報が設定されたサイト訪問者によって完了されます。2 人のログイン情報サイトが設定された訪問者が画面フローを同時に実行すると、2 番目にフローを完了した訪問者にはエラーが表示されます。作業項目が完了すると、作業ガイドを参照している他のグループまたはキューメンバーには、期限切れのバッジが付けられた項目が無効になります。ページを離れるか、ページを更新するか、別の作業項目を完了するまで、リストから削除されません。作業ガイドを積極的に表示していない場合、次にページにアクセスするときに関連作業が表示されなくなります。

エントリ条件と終了条件の要件

ステップのエントリ条件やフェーズまたはステップの終了条件の要件で選択されたリソースには、オーケストレーションリソースまたはグローバル変数を含めることができます。要件に含めることができる内容には制限があります。

  • [リソース] 項目または [値] 項目のレコードを使用するには、そのレコードの項目を選択する必要があります。
  • 参照されるレコードでは、関連レコードの項目ではなく、そのオブジェクトの項目を使用する必要があります。

レコード変更トリガーフローオーケストレーションイベント

ステップのエントリ条件やフェーズまたはステップの終了条件の要件には、レコードへの参照を含めることができます。そのレコードを変更すると、オーケストレーションがトリガーされ、現在のフェーズの状況とフェーズ内の未完了のステップが評価される場合があります。レコードで条件の評価をトリガーできるタイミングには制限があります。

  • 参照されるレコードの親オブジェクトで変更イベントがサポートされている必要がある。
  • 参照されるレコード項目が IsDeleted、SystemModeStamp、または関連レコードや数式から派生した項目ではない。
  • 参照されるレコードが null であるか、無効な ID である。
  • 参照されるレコードが自動起動オーケストレーションのグローバル変数である。
  • レコードトリガーオーケストレーションで参照されるレコードが $Record 以外のグローバル変数である。

フローの入力値

オーケストレーションステップでコールされたフローの合計入力値が 32,768 文字を超えると、オーケストレーションは失敗します。このエラーは、ステップでコールされたフローに 1 つ以上のレコードを渡したことが原因である可能性があります。このエラーを回避するには、参照されるフローにレコード ID を渡し、渡された ID のフローでレコードを取得要素を使用します。レコードを取得要素で渡された ID を使用すると、常に最新バージョンのレコードを使用できます。

フロー承認プロセスステップによってコールされたフローの合計入力値が 32,768 文字を超える場合、フロー承認プロセスは失敗します。このエラーは、ステップでコールされたフローに 1 つ以上のレコードを渡したことが原因である可能性があります。このエラーを回避するには、参照されるフローにレコード ID を渡し、渡された ID のフローでレコードを取得要素を使用します。レコードを取得要素で渡された ID を使用すると、常に最新バージョンのレコードを使用できます。

メール通知

ステップでコールされたフローが失敗し、オーケストレーションが失敗すると、2 つのメール通知が送信されます。

  • フローエラー通知
  • オーケストレーションエラー通知

ガバナ制限とオーケストレーションステップの同時実行

フローオーケストレーションでステップを一括で実行すると、同時インタビューがユーザーコンテキストとフローバージョンでバッチにグループ化されます。ユーザーコンテキストまたはフローバージョンが異なるインタビューは、別々のグループで実行されます。グループは順序どおりに実行されますが、同じトランザクション内で実行されます。

フローオーケストレーションは、次のような状況でステップの実行を一括処理します。

  • 複数のユーザーが同時に作業項目を完了
  • 一括レコード更新によって複数のオーケストレーションの実行がトリガーされる
  • レコード変更イベントで複数のオーケストレーションの実行を再開する

一括処理のすべてのグループは 1 つのトランザクションで実行され、ガバナ制限を共有します。SOQL クエリ、DML ステートメント、および Apex CPU 時間は、すべてのグループで累積されます。ステップでコールされるフローがレコードを作成、更新、または削除したときに実行されるレコードトリガーフローと Apex トリガーは、同じ制限に含まれます。

フローオーケストレーションでは、ユーザーがいつ開始したかではなく、実行時点で処理キューにあるインタビューに基づいてインタビューがグループ化されます。実行時間をずらすことは、バッチサイズを確実には削減しません。

SOQL 101 および Apex CPU 制限エラーの最も一般的な原因は、次の 1 つです。

  • ステップがコールするフロー内の SOQL クエリ、DML、またはループ内のコールアウト
  • 同じトランザクションのカスケード自動化 (レコードトリガーフローや、ステップでコールされるフローがレコードを作成、更新、削除したときに実行される Apex トリガーなど)
  • ガバナ制限をリセットするために、ステップが多数の連続操作を含みトランザクション境界のないフローをコールする

ガバナ制限に近づかないようにするには、次の設計方法に従ってください。

  • SOQL クエリ、DML、コールアウトをループから除外して、フローで自動的に一括処理されるようにします。
  • ステップがコールする呼び出し可能な Apex アクションの場合、コレクション パラメータ (List<RequestType>、List<ResponseType>) を使用し、ループ内ではなくコレクション全体に対して DML を実行します。
  • コールアウトと DML 操作は別々のステップに配置し、それぞれガバナ制限をリセットする独自のトランザクションで実行されます。
  • 待機要素をバックグラウンドステップの自動起動フローに追加します。待機要素では、ステップを個別のトランザクションで非同期に実行します。

フローオーケストレーションの設計

オーケストレーションの構成とフローとの関連について説明します。

  • オーケストレーション
    オーケストレーションでは、フェーズ、ステップ、決定を使用して複雑なビジネスプロセスを整理します。
  • オーケストレーションタイプ
    オーケストレーションの種別によって、オーケストレーションの配布方法が決まります。
  • オーケストレーションのトリガー
    レコードトリガーオーケストレーションを作成して、ユーザー入力や追加のレコード更新が必要なレコードの変更に対応します。[開始] 要素で、特定のオブジェクトの新規および変更されたレコードに基づいてオーケストレーションをトリガーするかどうかを指定します。フロートリガーエクスプローラーを使用して、レコードトリガーオートメーションの順序を管理します。
  • オーケストレーションのビルディングブロック
    フェーズとステップはオーケストレーションのビルディングブロックです。
  • オーケストレーションでのエラー処理
    エラー処理では、オーケストレーションの実行中に段階的に発生する予期しない問題を管理します。フェーズの障害パスを設定して、フェーズエラーが発生したときの復旧アクションを定義し、オーケストレーションが失敗するのではなく正常に完了するようにします。
  • オーケストレーションの実行コンテキスト
    実行コンテキストによって、Salesforce データに対するオーケストレーションのアクセス権と、一時停止中のオーケストレーションの再開に使用されるコンテキストが決まります。デフォルトでは、オーケストレーションの実行コンテキストはシステムコンテキストの自動化プロセス本ユーザです。
  • オーケストレーションのバージョン管理
    フローオーケストレーションには、オーケストレーションのバージョンと、オーケストレーションによってコールされるフローのバージョンの 2 つのバージョン設定があります。
  • オーケストレーション実行
    オーケストレーション実行は、実行中のオーケストレーションのインスタンスを表します。

オーケストレーションを使用した複雑なプロセスの自動化

会社の成長に伴い、ワークフローの複雑さも増します。プロセスでは、複数のタイムゾーンにまたがる複数の部門の複数のユーザーからの入力が必要になることがよくあります。この複雑さの増加により、各ユーザーが適切な順序でタスクを完了するまでの待機時間が長くなります。フローオーケストレーションは、オーケストレーション (複数のユーザーやシステムを操作する複数ステップのプロセス) を使用してこのプロセスを合理化するのに役立ちます。

フローオーケストレーションとは?

オーケストレーションは、各フェーズが 1 つ以上のステップで構成される一連のフェーズです。フェーズには、バックグラウンドステップ、対話型ステップ、MuleSoft ステップを含めることができます。

対話型ステップにはユーザーが割り当てられ、指定された画面フローが実行されます。システム管理者は、オーケストレーション作業ガイド Lightning アプリケーションビルダーコンポーネントを、自分に割り当てられた対話型ステップを完了できるレコードタイプのページレイアウトに配置します。オーケストレーションで対話型ステップを実行すると、指定されたユーザーに、割り当てられたアクションへのリンクが記載されたメールが送信されます。割り当てられたユーザーはリンクをクリックすると、作業ガイドのアクションを実行するレコードに移動します。

バックグラウンドステップは、Salesforce が実行する自動起動フローをコールします。同期または非同期で実行でき、ユーザー操作はありません。

MuleSoft ステップは、Salesforce が実行する MuleSoft アクションをコールします。非同期で実行され、ユーザー操作はありません。

オーケストレーションと作業項目の管理

リストビューを使用してオーケストレーションと作業項目を管理します。実行中のオーケストレーションをキャンセルまたは一時停止します。ステップでコールされたアクションまたはフローのエラーが原因で過去 14 日以内に失敗したオーケストレーションの実行を再開します。または、手動で一時停止されたオーケストレーションの実行を再開します。割り当てられているが完了していない作業項目を再割り当てします。

  • すべてのオーケストレーション作業項目の表示
    すべての作業項目を表示するには、[すべての作業項目] リストビューを使用します。All Open Orchestration Work Items リストビューを使用して、割り当てられているが完了していない作業項目をすべて表示します。割り当てられたユーザーは、All Open Orchestration Work Items リストビューで自分の未完了の作業項目のみを表示およびアクセスできます。
  • レコードでのオーケストレーション作業項目の表示
    割り当てられたオーケストレーション作業項目は、オーケストレーション作業ガイドコンポーネントのレコードページに直接表示されます。日付による項目の並び替え、ToDo の優先順位付け、完了状況の追跡を行います。
  • オーケストレーション実行の表示
    [オーケストレーション実行] リストビューを使用して、組織で進行中、キャンセル済み、完了したすべてのオーケストレーション実行を確認します。オーケストレーション実行リストビューからオーケストレーションの詳細と履歴にアクセスします。
  • オーケストレーション作業項目の再割り当て
    割り当て済みの作業項目は、別のユーザー、グループ、またはキューに再割り当てできます。
  • 作業項目割り当てのすべてのメール通知の無効化
    デフォルトでは、オーケストレーション作業項目がユーザー、グループ、またはキューに割り当てられるか、再割り当てされると、オーケストレーションからメール通知が送信されます。内部ユーザーとログイン情報が設定された Experience Cloud サイト訪問者へのメール送信を停止するには、すべての作業項目通知を無効にします。
  • キューメンバーのオーケストレーション作業項目メール通知の制御
    対話型ステップがキューに割り当てられたときにオーケストレーション作業項目のメール通知を送信するユーザーを制御します。
  • 処理中のオーケストレーションの一時停止
    オーケストレーション実行は、続行の準備ができるまで一時停止できます。実行中のオーケストレーションを一時停止すると、現在のフェーズも一時停止されます。処理中のステップは引き続き実行されますが、新しいステップは開始されません。処理中のステップに出力がある場合、オーケストレーションが再開されたときに処理できるように保存されます。
  • 一時停止されたオーケストレーションの再開
    一時停止されたオーケストレーション実行を再開してその処理を続行します。一時停止されたオーケストレーション実行が再開されると、一時停止されたフェーズも再開されます。オーケストレーション実行が再開されると、進行中のステップの状況が評価され、必要に応じてステップの状況が更新されます。オーケストレーション実行が一時停止されたときに進行中であったステップからの保存済み出力が処理されます。
  • 失敗したオーケストレーションの再開
    ステップでコールされたアクションのエラーが原因で過去 14 日以内にオーケストレーションの実行に失敗した場合、エラーを修正してオーケストレーションを再開できます。
  • 実行中のオーケストレーションのキャンセル
    [オーケストレーション実行] リストビューから処理中のオーケストレーションをキャンセルします。
  • オートメーションアプリケーションでのオーケストレーション連動関係の表示
    オーケストレーションでは、フローを使用してステップを実行し、複雑な条件を評価します。オーケストレーションと参照されるフロー間のリレーションを理解するには、オートメーションアプリケーションの [オーケストレーションバージョン] ページの [利用状況] タブを表示します。
  • オーケストレーションレポートの使用
    サンプルフローオーケストレーションレポートを使用して、オーケストレーションの利用状況を追跡します。サンプルレポートには、[オーケストレーション実行]、[オーケストレーションフェーズ実行]、[オーケストレーションステップ実行]、[オーケストレーション作業項目]、[オーケストレーション実行ログ] があります。これらのサンプルレポートは、オーケストレーション実行 Spring '24、オーケストレーションフェーズ実行 Spring '24、オーケストレーションステップ実行 Spring '24、オーケストレーション作業項目 Spring '24、オーケストレーション実行ログ Spring '24 カスタムレポートタイプに基づいています。
  • オーケストレーションの状況とマイルストーン
    オーケストレーションの各部分には、オーケストレーションの実行時に状況が割り当てられます。

オーケストレーション実行ログへのコメント列の追加

オーケストレーションバージョンでのフローの利用状況の判断

オーケストレーションバージョンでは、フローを使用して対話型ステップとバックグラウンドステップを実行します。オーケストレーションバージョンのフェーズとステップでは、フローを使用して複雑な条件を評価できます。これらの条件によって、バックグラウンドステップ、対話型ステップ、または MuleSoft ステップを開始するタイミングと、フェーズまたは対話型ステップを完了としてマークするタイミングを決定できます。オーケストレーションバージョンが参照するフローとオーケストレーションバージョン間のリレーションを理解するためにオーケストレーションバージョンで使用するフローを表示します。

失敗したオーケストレーションの実行を再開する前に、コールされたフローまたはアクションのエラーを修正してください。

  2. オーケストレーション実行のページで、状態がエラーのオーケストレーションのドロップダウンから、再開 を選択します。
  3. 再開 をクリックします。

一時停止されたオーケストレーションの再開

一時停止されたオーケストレーション実行を再開してその処理を続行します。一時停止されたオーケストレーション実行が再開されると、一時停止されたフェーズも再開されます。オーケストレーション実行が再開されると、進行中のステップの状況が評価され、必要に応じてステップの状況が更新されます。オーケストレーション実行が一時停止されたときに進行中であったステップからの保存済み出力が処理されます。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限
実行中のオーケストレーションを一時停止する
  • オーケストレーション実行の管理

    または

  • オーケストレーションの実行と作業項目の管理

一時停止されたオーケストレーションを再開できるほか、ステップによって呼び出されたアクションまたはフローのエラーが原因で過去14日以内に失敗したオーケストレーションも再開できます。

  1. アプリケーションランチャーで、[オーケストレーション実行] を見つけて選択します。
  2. オーケストレーション実行ページで、一時停止されたオーケストレーションのドロップダウンから再開を選択します。
  3. 再開をクリックします。

処理中のオーケストレーションの一時停止

オーケストレーション実行は、続行の準備ができるまで一時停止できます。実行中のオーケストレーションを一時停止すると、現在のフェーズも一時停止されます。処理中のステップは引き続き実行されますが、新しいステップは開始されません。処理中のステップに出力がある場合、オーケストレーションが再開されたときに処理できるように保存されます。

必要なエディション

フローオーケストレーションでサポートされるエディションを表示します。
必要なユーザー権限
実行中のオーケストレーションを一時停止する
  • オーケストレーション実行の管理

    または

  • オーケストレーションの実行と作業項目の管理

一時停止できるのは処理中のオーケストレーションのみです。

  1. アプリケーションランチャーで、[オーケストレーション実行] を見つけて選択します。
  2. [オーケストレーション実行] ページで、進行中のオーケストレーションのドロップダウンから [一時停止] を選択します。
  3. [一時停止] をクリックします。

準備ができたら、オーケストレーションの実行を再開します。
