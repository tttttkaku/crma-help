オーケストレーションレポートの使用

サンプルフローオーケストレーションレポートを使用して、オーケストレーションの利用状況を追跡します。サンプルレポートには、[オーケストレーション実行]、[オーケストレーションフェーズ実行]、[オーケストレーションステップ実行]、[オーケストレーション作業項目]、[オーケストレーション実行ログ] があります。これらのサンプルレポートは、オーケストレーション実行 Spring '24、オーケストレーションフェーズ実行 Spring '24、オーケストレーションステップ実行 Spring '24、オーケストレーション作業項目 Spring '24、オーケストレーション実行ログ Spring '24 カスタムレポートタイプに基づいています。

必要なユーザー権限
公開フォルダーと非公開フォルダーでレポートを作成、編集、および削除する
  • レポートビルダー

    または

  • 「レポートビルダー (Lightning Experience)」
メモ 各自の組織に最大数のカスタムレポートが定義されている場合、オーケストレーションレポートは追加されません。
メモ サンプルレポートが削除された場合、再生成することはできません。

サンプルオーケストレーションレポートは公開レポートです。レポートには、ユーザーに直接割り当てられた作業項目のみが表示されます。ユーザーが属するグループまたはキューの作業割り当てを表示するには、それらに割り当てられたすべての作業項目を表示するように検索条件を変更します。

フローオーケストレーションのカスタムレポートタイプには、拡張 sObject リレーションが含まれます。これらのリレーションを使用して、関連オブジェクトをレポートに追加し、複合レポートを作成できます。強化されたリレーションにより、ダッシュボードでフローオーケストレーションレポートを使用することもできます。

関連オブジェクトを追加して、サンプルレポートをカスタマイズしたり、カスタムレポートタイプから独自のレポートを作成したりできます。たとえば、[オーケストレーション実行] カスタムレポートタイプに基づいてレポートを作成し、オーケストレーションフェーズの実行を関連オブジェクトとして追加します。オーケストレーションフェーズの実行のすべての項目が、オーケストレーション実行項目と共に選択可能な列として使用可能になります。オーケストレーション実行データとオーケストレーションフェーズ実行データを同じレポートにまとめて表示できます。同様に、オーケストレーションステップ実行を追加してステップレベルの詳細にアクセスしたり、オーケストレーション作業項目を追加して作業項目情報を含めたりすることもできます。

  1. [レポート] リストビューで、[公開レポート] をクリックします。
  2. [公開レポートを検索] ボックスに、「オーケストレーション」と入力します。
    5 つのサンプルオーケストレーションレポートがリストされています。
  3. サンプルレポートをカスタマイズするには、関連するレポートを編集します。

オートメーションアプリケーションでのオーケストレーション連動関係の表示

オーケストレーションでは、フローを使用してステップを実行し、複雑な条件を評価します。オーケストレーションと参照されるフロー間のリレーションを理解するには、オートメーションアプリケーションの [オーケストレーションバージョン] ページの [利用状況] タブを表示します。

  • オーケストレーションバージョンでのフローの利用状況の判断
    オーケストレーションバージョンでは、フローを使用して対話型ステップとバックグラウンドステップを実行します。オーケストレーションバージョンのフェーズとステップでは、フローを使用して複雑な条件を評価できます。これらの条件によって、バックグラウンドステップ、対話型ステップ、または MuleSoft ステップを開始するタイミングと、フェーズまたは対話型ステップを完了としてマークするタイミングを決定できます。オーケストレーションバージョンが参照するフローとオーケストレーションバージョン間のリレーションを理解するためにオーケストレーションバージョンで使用するフローを表示します。
  • オーケストレーションレコードバージョンページへのオートメーション利用状況コンポーネントの追加
    オートメーションアプリケーションには、オーケストレーションバージョンで使用するフローが表示されます。[デフォルトのオーケストレーションバージョンレコード] ページをカスタマイズした場合は、[オートメーションの利用状況] コンポーネントをページに追加して、組織のデフォルトとして保存します。

失敗したオーケストレーションの再開

障害パスとエラー処理戦略の設定についての詳細は、「オーケストレーションでのエラー処理」を参照してください。

オーケストレーションの実行では、実行中に発生したすべてのエラーから回復することはできません。失敗したオーケストレーションの実行を再開できるかどうかは、エラーが発生した場所によって異なります。

再開するには、基盤となるフローまたはエラーを修正し、オーケストレーションの実行を再開する必要があります。このアプローチは、オーケストレーションデザイナーが設計時に設定する障害パスとは異なります。障害パスはエラーを適切に処理し、エンドユーザーに復旧メカニズムまたは手動介入ステップを提供します。

復旧可能なエラーは 2 つのシナリオで発生し、最大 14 日以内にエラーを修正してオーケストレーションの実行を再開する必要があります。

  • バックグラウンドステップまたは対話型ステップによってコールされたフローでエラーが発生した。
  • ステップの割り当て先が凍結または無効になっている。

3 つのシナリオで回復不可能なエラーが発生し、エラーが発生したオーケストレーションの実行を再開することはできません。

  • オーケストレーションが要求を準備したり、結果を処理したりする場合など、ステップがコールするフローの外部でエラーが発生します。
  • MuleSoft ステップによってコールされたアクションでエラーが発生します。
  • ステップの割り当て先が正しく設定されていない (有効なユーザー、グループ、キューに解決されないリソース変数など)。

オーケストレーションの実行でエラーが発生すると、影響を受けるオーケストレーションの実行、フェーズの実行、ステップの実行の状況が設定されます。

エラーが回復可能な場合は、フローのエラーを修正してから、失敗したオーケストレーションを再開します。再開すると、エラーになったステップが再起動されます。バックグラウンドステップの場合、システムは固定の自動起動フローを使用してステップを再実行します。対話型ステップの場合、別の作業項目が作成され、割り当て先が固定画面フローを使用してステップを完了します。「失敗したオーケストレーションの再開」を参照してください。

オーケストレーション実行の障害パス

障害パスは、フェーズでエラーが発生したときにエラー処理を行います。フェーズに障害パスが添付されていて、処理中にエラーが発生した場合、オーケストレーションは障害パスに従います。このエラー処理のアプローチでは、[エラー] 状況ですぐに終了する代わりに、

障害パスは、オーケストレーションの実行でエラーが発生したときにエンドユーザーが手動で介入できるシナリオで役立ちます。たとえば、エンドポイントが停止しているため、外部インテグレーションまたは API コールが失敗するとします。障害パスには、割り当て先が必要なデータを手動で入力する対話型のステップを含めることができます。

次に何が起こるかは、障害パス設定によって異なります。要素を含む障害パスでは、それらの要素が実行されます。障害パスが終了要素で終了し、未対応のエラーが発生しない場合、オーケストレーションの実行は [完了] 状況で終了します。障害パスの未対応のエラーにより、オーケストレーションの実行が [エラー] 状況で終了します。

障害パスがオーケストレーションに再び接続されても、オーケストレーションは引き続き実行されます。完了するまで、または未対応のエラーが発生するまで実行されます。この動作は、障害パスに要素が含まれているかどうかに関係なく適用されます。空の障害パスがオーケストレーションに接続すると、次の要素が処理なしで実行されます。

障害パスでエラーが処理されても、オーケストレーションからエラー通知は送信されません。ただし、障害発生時に関係者に通知するバックグラウンドステップを障害パスに追加できます。エラーが発生したフローまたはアクションは、そのエラー処理設定に基づいて独自のエラー通知を処理します。

オーケストレーションの障害パスについての詳細は、「オーケストレーションのエラー処理」を参照してください。

決定要素で 2 つの可能な結果が提供される場合、最初の結果の条件が満たされない場合にのみデフォルトの結果が適用されます。

決定要素に 3 つ以上の結果候補がある場合、リストの順序で評価されます。各結果について:

  • その条件がチェックされます。
  • 条件が true の場合、その結果に関連付けられたパスが実行されます。
  • 条件が false の場合、リスト内の次の結果の条件が評価されます。

オーケストレーションのグローバル変数に関する考慮事項

  • レコードトリガーオーケストレーション内の $Record グローバル変数には、トリガーレコードの値でも、他のレコードから派生した項目の値は格納されません。派生フィールドの例としては、Contact.Name や User.MediumPhotoUrl があります。
  • 複数選択リスト、時間、および場所のグローバル変数は数式でのみ使用できます。
  • データベースの項目が空の場合、対応する差し込み項目は空白値を返します。たとえば、組織の [国] 項目に値がない場合、{!$Organization.Country} は値を返しません。
  • $Flow グローバル変数フローオーケストレーションリソース
    $Flow グローバル変数は、実行中のオーケストレーションに関する情報を提供します。一部の変数には、システムから提供された値が含まれます。変数の出力値を保存して、オーケストレーション全体にわたってこれ以外の変数を更新できます。

レコードトリガーオーケストレーションのトリガーレコードの設定

レコードトリガーオーケストレーションをデバッグするには、トリガーレコードを設定します。この設定は、現在の Flow Builder セッションでも保持されます。レコードが作成された場合のみ、レコードが変更された場合のみ、またはレコードが作成または更新された場合のみ、3 つの方法のいずれかでレコードトリガーオーケストレーションをトリガーします。

Flow Builder では、編集モードとデバッグモードを切り替えるときに、選択したトリガーレコード値と設定オプションが保持されます。ブラウザーを更新するか、Flow Builder を閉じると、これらの選択はクリアされます。

  1. ボタンバーで、[デバッグ] をクリックします。
    [設定] タブが選択された状態で [デバッグ] パネルが開きます。
  2. レコードが作成または更新されたときにトリガーされるオーケストレーションの場合、デバッグするトリガーの種別を選択します。
    • 新しいレコードのトリガーをデバッグするには、[Run the automation As If The Record Is (レコードがあるかのようにオートメーションを実行)] で [作成済み] を選択します。
    • レコード変更のトリガーをデバッグするには、[Run the automation As If The Record Is (レコードがあるかのように自動化を実行)] で [更新済み] を選択します。
  3. テキストボックスで、デバッグ実行のトリガーレコードに使用するレコードを選択します。
  4. [Run automation in rollback mode (ロールバックモードで自動化を実行)] を選択解除します。
  5. デバッグ設定を手動でクリアするには、[Reset Debug Settings (デバッグ設定のリセット)] をクリックします。

自動起動オーケストレーションの入力変数の設定

自動起動オーケストレーションをデバッグするには、そのすべての入力変数の値を設定します。入力変数が欠落しているか無効な場合、デバッグの実行は失敗します。指定した値は、現在の Flow Builder セッションで保持されます。

Flow Builder では、編集モードとデバッグモードを切り替えても入力変数値と設定オプションが保持されます。ブラウザーを更新するか、Flow Builder を閉じると、次のデバッグ設定がクリアされます。

  1. ボタンバーで、[デバッグ] をクリックします。
    [設定] タブが選択された状態で [デバッグ] パネルが開きます。
  2. [設定] タブで、関連する各入力変数の値を入力します。
  3. [Run automation in rollback mode (ロールバックモードで自動化を実行)] を選択解除します。
  4. デバッグ設定を手動でクリアするには、[Reset Debug Settings (デバッグ設定のリセット)] をクリックします。

ステップのモック出力の管理

オーケストレーションの実行をデバッグモードで実行するステップを制御します。ステップの参照されるフローを実行するには、[テスト出力値を定義] を [オフ] に設定します。デバッグ時に実行しないステップの疑似出力を設定します。[テスト出力値を定義] が [オン] に設定されているステップでは、参照されるフローを実行する代わりに、定義された疑似出力が使用されます。疑似出力が定義されたステップでは、Salesforce データベースは変更されません。

オーケストレーションを保存すると、疑似出力も保存されます。[Reset Debug Settings (デバッグ設定をリセット)] をクリックしても、模擬出力には影響しません。

  1. [デバッグ] パネルで、[フェーズ] タブをクリックします。
  2. 実行するオーケストレーションの各ステップで疑似出力を無効にします。
    1. [Debug (デバッグ)] パネルの [Stages (フェーズ)] タブで、ステップの [Edit (編集)] をクリックします。
      [ステップ] プロパティパネルが開き、[テスト出力を設定] タブが開きます。
    2. [ステップ] プロパティパネルの [テスト出力を設定] タブで、[テスト出力値の定義] を [オフ] に設定します。
  3. 実行しないオーケストレーションの各ステップの疑似出力を定義します。
    1. [Debug (デバッグ)] パネルの [Stages (フェーズ)] タブで、ステップの [Edit (編集)] をクリックします。
      [ステップ] プロパティパネルが開き、[テスト出力を設定] タブが開きます。
    2. [ステップ] プロパティパネルの [テスト出力を設定] タブで、[テスト出力値を定義] を [オン] に設定します。
    3. ステップの出力値の値を入力します。
  4. オーケストレーションを保存します。
    メモ 有効化されたオーケストレーションをデバッグする場合、オートメーションは新しいオーケストレーションとしてのみ保存できます。

オーケストレーションの実行の開始

オーケストレーションの実行をデバッグし、[デバッグ] ペインの [詳細] タブでその結果を表示します。[出力値を手動で設定] が [オフ] に設定された非同期ステップごとにオーケストレーションの実行が一時停止します。バックグラウンド非同期ステップの場合、オーケストレーションの実行はバックグラウンドステップが完了した後に再開されます。対話型ステップの場合、オーケストレーションの実行は、関連付けられたオーケストレーション作業項目を完了した後に再開されます。

  1. [Debug (デバッグ)] パネルで、[Setup (設定)] タブをクリックし、[Run (実行)] をクリックします。
    [デバッグ] パネルの [詳細] タブには、オーケストレーション実行の詳細のカードが表示されます。
  2. デバッグの詳細を確認します。カードの詳細を表示するには、カードで [詳細] をクリックします。
  3. オーケストレーションの実行を一時停止する対話型ステップごとに、関連付けられたオーケストレーション作業項目を完了します。
    1. 関連するレコードページを開きます。
    2. 『オーケストレーション作業ガイド』で、作業項目を完了します。
    [デバッグ] パネルの [詳細] タブの情報は自動的に更新されます。
  4. オーケストレーションを変更して保存するには、[Edit Flow (フローを編集)] をクリックします。
    [デバッグ] ペインが閉じます。

Flow Builder でのオーケストレーション作業項目の完了

Flow Builder から離れることなく、デバッグ実行中にオーケストレーション作業項目を完了します。[デバッグ] ペインのインタラクティブステップカードから作業項目を開き、[作業ガイド] タブで作業項目を完了します。作業項目を完了すると、デバッグ実行が再開されます。オーケストレーション作業項目は、レコードページの『オーケストレーション作業ガイド』から引き続き完了できます。

  1. [Debug (デバッグ)] ペインで、[Details (詳細)] タブを選択します。
  2. インタラクティブステップカードで、[Continue in Work Guide (作業ガイドを続行)] をクリックします。
    オーケストレーション作業項目が Flow Builder のキャンバスの [作業ガイド] タブで開きます。
  3. よりインタラクティブなステップでオーケストレーション作業項目を完了するには、ステップ 2 を繰り返します。

  2. レコードが作成または更新されたときにトリガーされるオーケストレーションの場合、デバッグするトリガーの種別を選択します。
    • 新しいレコードのトリガーをデバッグするには、[Run the automation As If The Record Is (レコードがあるかのようにオートメーションを実行)] で [作成済み] を選択します。
    • レコード変更のトリガーをデバッグするには、[Run the automation As If The Record Is (レコードがあるかのように自動化を実行)] で [更新済み] を選択します。
  3. テキストボックスで、デバッグ実行のトリガーレコードに使用するレコードを選択します。
  4. [ ロールバックモードで自動化を実行] を選択します。
  5. デバッグ設定を手動でクリアするには、[Reset Debug Settings (デバッグ設定のリセット)] をクリックします。

自動起動オーケストレーションの入力変数の設定

自動起動オーケストレーションをデバッグするには、そのすべての入力変数の値を設定します。入力変数が欠落しているか無効な場合、デバッグの実行は失敗します。指定した値は、現在の Flow Builder セッションで保持されます。

Flow Builder では、編集モードとデバッグモードを切り替えても入力変数値と設定オプションが保持されます。ブラウザーを更新するか、Flow Builder を閉じると、次のデバッグ設定がクリアされます。

  1. ボタンバーで、[デバッグ] をクリックします。
    [設定] タブが選択された状態で [デバッグ] パネルが開きます。
  2. [設定] タブで、関連する各入力変数の値を入力します。
  3. [ ロールバックモードで自動化を実行] を選択します。
  4. デバッグ設定を手動でクリアするには、[Reset Debug Settings (デバッグ設定のリセット)] をクリックします。

ステップのモック出力の設定

すべての非同期ステップの疑似出力を設定します。同期ステップの場合、疑似出力の定義は省略可能です。疑似出力を使用するように設定されたステップは、その参照されるフローを実行しません。

オーケストレーションの実行では、ステップの基礎となるフローに 1 つ以上のアクション、サブフロー、または待機要素が含まれている場合、バックグラウンドステップを非同期で処理します。オーケストレーションの実行では、すべての対話型ステップが非同期で処理されます。

フロー承認プロセスを保存すると、疑似出力も保存されます。[Reset Debug Settings (デバッグ設定をリセット)] をクリックしても、模擬出力には影響しません。

  1. [デバッグ] パネルで、[フェーズ] タブをクリックします。
  2. オーケストレーションの非同期ステップごとに疑似出力を定義します。必要に応じて、同期ステップの疑似出力を定義します。
    1. [Debug (デバッグ)] パネルの [Stages (フェーズ)] タブで、ステップの [Edit (編集)] をクリックします。
      [ステップ] プロパティパネルが開き、[テスト出力を設定] タブが開きます。
    2. [Configure Test Output (テスト出力を設定)] タブで、[Define Test Output Values (テスト出力値を定義)] を [オン] に設定します。
    3. ステップの出力値の値を入力します。
  3. オーケストレーションを保存します。
    メモ 有効化されたオーケストレーションをデバッグする場合、オートメーションは新しいオーケストレーションとしてのみ保存できます。

オーケストレーションの実行の開始

オーケストレーションの実行をデバッグし、[デバッグ] ペインの [詳細] タブでその結果を表示します。

  1. [Debug (デバッグ)] パネルで、[Setup (設定)] タブをクリックし、[Run (実行)] をクリックします。
    [デバッグ] パネルの [詳細] タブには、オーケストレーション実行の詳細のカードが表示されます。
  2. デバッグの詳細を確認します。カードの詳細を表示するには、カードで [詳細] をクリックします。
  3. オーケストレーションを変更して保存するには、[Edit Flow (フローを編集)] をクリックします。
    [デバッグ] ペインが閉じます。

オーケストレーション実行が失敗すると、Salesforce からエラーメールが送信されます。メールは、関連付けられたオーケストレーションを最後に変更したシステム管理者またはApex 例外メールの受信者に送信されます。

フローとオーケストレーションの比較

フローとオーケストレーションを比較して、ビジネスプロセスに適した自動化ツールを選択します。機能、使用事例、実装方法の主要な違いを理解します。

フロー

フローは、ビジネスプロセスを自動化するアプリケーションです。データを収集し、Salesforce 組織や外部システムで何らかの操作を実行します。フローでは、ビジネスプロセスに沿って案内する画面を表示できます。

フローは 1 つのオブジェクトに関連付けられているわけではありませんが、レコードを中心とした処理を実行します。フローでは、複数のオブジェクトのレコードを検索、作成、更新、削除できます。フローは、ポイント & クリックツールである Flow Builder を使用して作成できます。

オーケストレーション

オーケストレーションは、一連のフローを組み合わせて調整することで高度なビジネスプロセスを構築可能なアプリケーションです。オーケストレーションはユーザー中心に設計されています。1 つのオーケストレーションで、さまざまなユーザーや組織の部門が関連するプロセスを管理できます。フローオーケストレーションを使用することで、業務の進捗を監視して効率を向上できます。
