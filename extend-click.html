本書は、ユーザー（Salesforce 管理者・コンサル）が「カスタマイズの全体像と判断軸」を素早く掴むために、Salesforce 公式ヘルプの構造を保ちつつ重要な概念に絵を添えた "案内図" です。各見出しから公式ページへ直接ジャンプできます。

はじめに：Salesforce を "拡張" するとは

Salesforce では、初期セットアップを終えた後も 1 行のコードも書かずに機能を拡張できます。マウス操作とポイント＆クリックツールで、次のすべてが可能です。

データの拡張

  • カスタムオブジェクト・項目
  • 数式・選択リスト
  • 機密データ分類

画面・体験の拡張

  • ページレイアウト／動的フォーム
  • Lightning ページ・アプリ
  • カスタムタブ・アクション

業務範囲の拡張

  • カスタム通知・Slack
  • 外部サービス／API カタログ
  • カスタムドメイン

2. Salesforce 組織のカスタマイズ

標準オブジェクト・タブ・項目のラベル名・ページレイアウト・項目レベルセキュリティ・コンパクトレイアウト・カスタムタブ・レコードタイプ・カスタムヘルプを「画面で見えるもの」全般としてまとめるセクション。

原文: platform.customize_overview.htm

2.1 ページレイアウト と 項目レベルセキュリティ

ページレイアウト は「画面のどこに何の項目を並べるか」を決める従来仕組み。項目レベルセキュリティ (FLS) は「プロファイル毎に項目を見せる／編集させる」をオンオフします。両者は別物で、画面に出ても FLS で隠せば見えません。

項目へのユーザーアクセスの制御方法
項目アクセスは「ページレイアウト」「項目レベルセキュリティ」「権限セット」の3層で決まる。設計時はこの3点をセットで検討。
ページレイアウトおよび項目レベルセキュリティの設定
レコードタイプ × プロファイル の組合せ毎にどのレイアウトを使うかを割当てる。
ページレイアウト Classic 主体
Salesforce Classic 由来。Lightning でも残っているが、新規は次の動的フォームへ。
コンパクトレイアウト
レコード上部のハイライトパネル / モバイルカードに表示する厳選項目（4〜10件程度）。

★ ページレイアウト vs 動的フォーム

2.2 カスタムタブ

カスタムタブ はナビゲーションバーに項目を追加する仕組み。種類は「カスタムオブジェクトタブ」「Web タブ（外部 URL）」「Visualforce タブ」「Lightning コンポーネントタブ」など。アプリへの組込みは Lightning App Builder で行います。

2.3 レコードタイプ

レコードタイプ は、同じオブジェクトを業務シナリオ別に出し分ける仕組み。1つの「商談」テーブルでも、新規ビジネスとアップセルでは選択リスト・レイアウト・営業プロセスを別にしたい—そのために使います。

レコードタイプ ＝ ページレイアウト × 選択リスト値 × ビジネスプロセス の組合せを切り替えるラベル。新規作成時にユーザーに選ばせる、または条件で自動割当できる。

2.4 そのほかのカスタマイズ

オブジェクト・タブ・項目の表示ラベル名称変更
標準オブジェクトの「取引先」を「顧客」「会員」などに改名できる。多言語対応も可能。
カスタムヘルプコンテンツ
標準項目のヘルプ吹き出しを自社用ガイドに置換、または独自オブジェクト用にオンラインヘルプを掲示。
翻訳の管理
多言語ラベル・選択リスト値の翻訳作業を [翻訳ワークベンチ] で行う。

3. 独自の方法でのデータの設定

「データモデル」をビジネスに合わせて作り込むセクション。カスタムオブジェクト・項目・数式・カスタム設定・スキーマビルダー・機密データ分類が含まれる。

原文: platform.extend_click_custom_data.htm

3.1 スキーマビルダー

スキーマビルダー はオブジェクトとリレーション（参照／主従）を ER 図として可視化＆編集するツール。データモデル設計時の最重要画面。

スキーマビルダーでオブジェクトを作成
図面上で右クリック → オブジェクト追加。属性は通常画面と同じ。
スキーマビルダーで項目を作成
サイドバーから項目をドラッグでオブジェクトに追加。型選択 → 必須/外部ID 等。
スキーマビルダーに関する考慮事項
大規模組織では表示が重くなる、レイアウト・権限の編集は不可、などの制約。

3.2 項目のカスタマイズ — 型の全体像

項目のカスタマイズ では、標準/カスタム項目を追加・編集します。型の選択がデータモデル品質を左右します。

3.3 数式項目

数式を使用した項目値の計算。数式項目は「他の項目の値から都度計算する読取専用項目」。保存はされず、参照される度に再計算されます。

数式に使える関数は IF / CASE / TEXT / DATE / DATEVALUE / VLOOKUP / ISCHANGED / ISBLANK など多数。AND/OR/NOT のブール演算と、親レコードの項目参照 Account.Name も可。

関連: レコードからのメール生成（差し込み項目） — メールテンプレート内に {!Contact.LastName} のように埋め込んで動的化。

3.4 カスタム設定

カスタム設定 は、Apex / フロー / 数式から高速参照できる軽量データセット。アプリ設定値・ホワイトリスト・組織別パラメータの格納先として使われる。リスト型（全ユーザー共通）と階層型（プロファイル/ユーザー別オーバライド）の2種類。

カスタムオブジェクトより読み込みコストが軽く、SOQL クエリ数に算入されない。アプリ動作の設定値置場として優秀。

3.5 機密データの分類

機密データの分類 — 各項目に「PII」「機密性レベル」「コンプライアンス分類」のラベルをメタデータとして付与。GDPR / 個情法 / PCI DSS 対応の出発点となる仕組み。

3.6 顧客のデータプライバシー設定の保存

個人 (Individual) オブジェクト を有効化し、取引先責任者 / リードに紐付けて「ニュースレター不可」「データ削除依頼済」などの同意管理を記録します。GDPR 対応で典型。

4. 独自の Salesforce アプリケーションの構築

「アプリ」は項目のコレクションではなく、複数のタブ・ページ・ブランディング・ユーティリティバーを束ねた業務単位のコンテナ。Classic と Lightning の 2 種類。

原文: platform.apps_overview.htm

4.1 Lightning アプリケーション

Lightning アプリケーション は App Launcher（9点メニュー）から起動する1単位。営業/サービス/分析など業務ごとに分けて、ナビ項目とユーティリティバーをカスタマイズします。

Lightning Experience でのアプリケーション作成のヒント
命名規則・ブランディング・アイコンサイズなど作る前に押さえるべき点。
Lightning アプリケーションの作成
ウィザード形式（アプリ詳細 → オプション → ユーティリティ → ナビ項目 → ユーザー割当）。
Lightning アプリケーションビルダーを使用したカスタマイズ
作成後のページ構成は Lightning App Builder で行う。
ユーティリティバーの追加
画面下に常駐するパネル。電話 (Open CTI)・メモ・カスタム LWC を配置可。

4.2 Salesforce Classic のカスタムアプリケーション

Classic カスタムアプリケーションの作成 Classic 専用
Lightning Experience が標準の今、新規構築では原則 Lightning を採用。Classic は既存環境保守のみ。
Classic のサブタブアプリケーション Classic 専用
1つのタブの中に複数サブタブを持たせる構造。Lightning ではコンソールアプリで代替。

5. Lightning アプリケーションビルダー

ノーコードで Lightning ページ（ホーム / アプリ / レコード / 埋め込み）を作る中核ツール。動的フォーム・動的アクション・動的関連リスト・動的インタラクションといった「動的」機能群がここに集約されている。

原文: platform.lightning_app_builder_overview.htm

5.1 Lightning ページの種類とレコードページ

Lightning ページ は「ホーム」「アプリ」「レコード」「メール下書き」「埋込み」など複数の種類があり、種類ごとに使えるテンプレートが異なる。最も使用頻度の高い「レコードページ」の構造と割当ロジックを図示します。

Lightning Experience レコードページの作成および設定
テンプレ選択 → コンポーネント配置 → 保存＆有効化。

5.2 動的フォーム

動的フォーム はページレイアウトの後継。項目を1つずつページに配置でき、条件式で表示/非表示・必須・読取専用を切り替えられる。

動的フォームに切替えてもページレイアウト定義は残る（モバイル/旧 RT で参照される）。完全に置き換える運用は段階移行が安全。

5.3 動的強調表示パネル・動的アクション・動的関連リスト

動的強調表示パネル
ハイライトパネルの項目を「VIP取引先のときだけ表示」のように条件で切替え可能。
動的アクションの作成
レコード上部のアクションボタン群を条件式で出し分け。たとえば「フェーズが提案中のときだけ "見積発行" ボタン」。
動的関連リストの作成
関連リストを条件絞り込み（例: 完了済タスクのみ）。タイトル・表示列も個別設定可。
条件付き項目の書式設定
Spring '24 以降。数値の閾値超過で背景色変更などを画面上から設定。

5.4 動的インタラクション

動的インタラクション は、同じ Lightning ページ内で「あるコンポーネントの操作 → 別コンポーネントが反応」をクリックで設定する仕組み。

6. 通知ビルダーを使用した通知の管理

「通知タイプ」をクリックで定義し、フロー/Apex から呼び出すと、デスクトップ・モバイル・Slack へ同時配信できる仕組み。

原文: platform.notif_builder.htm

カスタムデスクトップまたはモバイル通知の作成と送信
[設定] → 通知ビルダー → カスタム通知タイプを作成 → フロー「カスタム通知を送信」アクションで呼出。受信者・タイトル・本文・遷移先 ID を渡す。
カスタム Slack 通知
Slack 連携の事前設定後、通知タイプで Slack チャネルを選択可能になる。承認/失注などビジネスクリティカルなイベントを Slack に流す用途。
通知の配信設定の管理
各通知タイプ×チャネルのデフォルトON/OFFと、ユーザー側で上書き可否を制御。
通知に関する考慮事項
1日の送信上限、モバイル登録要件、Apex からの呼出制限（DML/同期）など。
通知ビルダーで作れるのはデスクトップ/モバイル/Slack 通知のみ。メール通知は別機能（メールアラート・Email Studio）。

7. カスタムドメイン

「www.example.com」など自社所有ドメインで Experience Cloud サイト・Salesforce サイトを提供する仕組み。ブランディング統一とSEO・SSL証明書を一元管理する目的。

原文: platform.domain_mgmt.htm

7.1 提供方式の選択

Salesforce のカスタムドメイン
概念と前提。My Domain（組織別 URL）と混同しがちだが別物。カスタムドメインは「外向けサイトに自社ドメインを当てる」機能。
カスタムドメインの提供方法の決定
3方式（Salesforce HTTPS / Salesforce CDN / サードパーティ）の選択ガイド。WAF・キャッシュ要件・運用負荷で判断。
カスタムドメインの前提条件
DNS の管理権限・証明書・CNAME 設定・MyDomain 有効化済みであることなど。

7.2 セットアップ・運用

Sandbox でのカスタムドメインのテスト
本番に出す前に Sandbox でドメイン挙動を確認するベストプラクティス。
HTTPS 証明書を使用したカスタムドメイン 方式A
Salesforce サーバーが証明書を保持して HTTPS 終端。最もシンプル。
Salesforce CDN を使用した Experience Cloud サイトの提供 方式B
Experience Cloud 向け推奨。CDN によるキャッシュで高速化。
サードパーティサービス／CDN を使用したカスタムドメインの提供 方式C
Akamai / Cloudflare / AWS CloudFront 等を前段に置く構成。WAF・複雑なヘッダ要件がある場合。
カスタムドメイン管理
追加・編集・削除・URL リダイレクト・証明書更新の手順。

8. 組織の範囲の拡張

Salesforce 組織外のデータ・サービス・外部システムとの接続全般。アクション/ボタン/リンク、API カタログ、外部サービス、Salesforce Connect、プラットフォームイベントなどが含まれる。

原文: platform.extend_click_reach.htm

8.1 アクション・ボタン・リンク

アクション、ボタン、およびリンクの提供 — 「画面から何かを実行する」3つの仕組み。新規構築では クイックアクション + フロー の組合せが第一選択。

8.2 外部サービス

外部サービス — OpenAPI 仕様 1ファイルから「フローで呼べる Apex 不要のアクション」を自動生成する仕組み。社外 REST API との連携をクリックだけで実現。

8.3 API カタログと MuleSoft

Salesforce の API カタログ 新
組織内の API と MCP（Model Context Protocol）サーバーを一元カタログ化。Agentforce / 自動化からの発見性が向上。
MuleSoft Anypoint Platform 接続の管理
MuleSoft テナントを Salesforce と紐付けてクロスプラットフォーム機能を有効化。

8.4 外部データへのアクセス（Salesforce Connect / Files Connect）

Salesforce Connect は、SAP / SQL Server / Oracle / OData ソースなどに保管されたデータを 外部オブジェクトとして Salesforce 内に "投影" する機能。コピーせず参照のみ。Files Connect は SharePoint・Google Drive のファイルを統合的に検索/参照する機能。

「外部サービス」と「Salesforce Connect」は混同されがち。外部サービス = 呼び出すだけ（操作系API）、Salesforce Connect = データを SObject として参照（マスタデータの仮想化）と覚える。

8.5 ビジネスプロセスとリアルタイムイベント

プラットフォームイベント
Salesforce が「イベントバス」を持ち、発行者と購読者を疎結合で繋ぐ Pub/Sub。Apex/フロー/外部システムが双方向で利用可。
Event Studio
Salesforce イベントバスの公開・購読を可視化・追跡。
Salesforce と Heroku 間のデータ同期
Heroku Connect で Salesforce と Heroku Postgres を双方向に同期。
Lightning Out 2.0
カスタム LWC を Salesforce 以外の Web に埋め込んで配信。

9. 独自の Web サイトの構築（参考）

Site.com と Salesforce サイトは Web サイト作成の従来システム。現在の新規構築では Experience Cloud（旧 Community Cloud）が推奨。

このセクションは互換性維持のためにヘルプに残されているもの。新規プロジェクトでは Experience Builder を使い、必要に応じてセクション7のカスタムドメインと組合せる流れが標準です。

10. DX インスペクター（参考）

Sandbox・スクラッチ組織・Developer Edition でメタデータとデータ変更を追跡・可視化する管理ツール。Salesforce DX の開発ワークフローを補助。

各ビルダー（Lightning App Builder / Flow Builder 等）の上部に表示され、変更履歴・差分・依存関係をその場で確認できる。本番組織では利用不可。
