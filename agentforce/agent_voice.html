テレフォニー接続の追加

エージェントに新しいテレフォニー接続を追加します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Foundations Edition または Agentforce 1 Edition が付属する Enterprise Edition、Unlimited Edition、および Developer Edition、および Salesforce Voice アドオン。
必要なユーザー権限  
サービスエージェントを構築および管理する

「Agentforce サービスエージェントを管理」および「AI エージェントの管理」

または

「アプリケーションのカスタマイズ」

テレフォニー接続では、テレフォニーソリューションを使用して音声通話を処理するようにエージェントを最適化します。

関連項目:

  • 動画: Set Up a Voice-Enabled Agent in Agentforce (Agentforce での音声対応エージェントの設定)

Agentforce Builder でのテレフォニー接続の追加

  1. アプリケーションランチャーから、「Agent」と入力し、Agentforce Studioアプリケーションを選択します。[エージェント] タブで、エージェントの名前をクリックします。
  2. [エクスプローラー] パネルの [接続] で、[接続を追加] をクリックします。
  3. [接続を追加] ウィンドウで、[テレフォニー] を選択し、[エージェントに追加] をクリックします。
  4. [言語設定] で指定されたエージェントのデフォルト言語を音声に使用する言語と照合するように求められます。[OK] をクリックして、接続をエージェントに追加します。
  5. [エクスプローラ(Explorer)] パネルの [エージェント定義設定(Agent Definition Settings)] で、[言語設定(Language Settings)] を選択し、デフォルト言語または許可される言語を音声でサポートされる言語に設定します。音声対応エージェントでサポートされる言語のリストについては、「Agentforce Voice Considerations」を参照してください。
  6. [エクスプローラ(Explorer)] パネルの [エージェント定義設定(Agent Definition Settings)] で、[音声設定(Voice Settings)] を選択し、要件に合わせて音声をカスタマイズします。

従来のビルダーでのテレフォニー接続の追加

  1. Agentforce エージェントの [設定] ページから、Agentforce Builder でエージェントを起動します。
  2. まだ有効になっていない場合は、[接続] タブで新しい [接続] パネル環境を有効にします。
  3. [接続] タブで、[新規] をクリックします。
  4. [テレフォニー] を選択し、[エージェントに追加] をクリックします。
  5. エージェントを音声用に最適化するための推奨事項を確認し、[Yes, Optimize for Voice] をクリックしてテレフォニー接続を追加します。

通信プロトコルの選択

Agentforce Voice は、PSTN または SIP 通信プロトコルを使用して設定できます。手順はプロトコルによって異なります。

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Foundations Edition または Agentforce 1 Edition が付属する Enterprise Edition、Unlimited Edition、および Developer Edition、および Salesforce Voice アドオン。

次のいずれかのプロトコルを使用して、通話をエージェントに転送できます。

Public Switched Telephone Network(PSTN; 公衆電話交換網)電話番号
この従来のプロトコルは、銅線電話回線を介してコールを送信します。

このプロトコルは、インターネット上で通話を送信します。仮想接続により、コールのコスト効率と柔軟性が向上します。

Agentforce サービスエージェントに進行中の会話を渡すときの歓迎メッセージのバイパス

Agentforce サービスエージェントを設定して、システムお知らせメッセージを送信する代わりに中断した進行中の会話をシームレスに選択します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

進行中の会話が Agentforce サービスエージェントに転送されると、エージェントはシステムお知らせメッセージを送信し、顧客の以前のメッセージに応答します。拡張チャットを含むメッセージングチャネルで会話が開始されると、エージェントはシステムお知らせメッセージを送信し、顧客がメッセージを送信するまで待機してから、最新のメッセージと以前の会話のコンテキストに基づいて応答を生成します。

システムお知らせメッセージをスキップし、代わりに顧客の以前のメッセージに直接応答するようにエージェントを設定できます。[Welcome Message (ようこそメッセージ)] フィールドを空白のままにします。

  • お知らせメッセージが指定されておらず、以前の会話履歴があるメッセージングセッションがエージェントに転送されると、エージェントは顧客の最新のメッセージを処理して応答します。

    会話がサービス担当者またはボットからエージェントに転送された場合、エージェントは顧客が新しいメッセージを送信するまで待機してから応答します。次に、エージェントは最新のメッセージと以前の会話のコンテキストに基づいて応答を生成します。

  • 歓迎メッセージが指定されておらず、会話履歴のないメッセージングセッションが開始された場合、エージェントは顧客が最初のメッセージを送信するまで待機し、顧客の最初のメッセージの意図に基づいて応答を生成します。サブエージェントの指示を使用して、エージェントが処理するように設計された使用事例に基づいてエージェントの応答方法を絞り込みます。

システム歓迎メッセージを指定しない場合でも、AI エージェントが会話に参加したことを開示して、顧客が人間とチャットしていないことを知ることが重要です。会話確認など、エージェントの会話の開始時に自動レスポンスを設定することをお勧めします。「Customize Auto-Responses in Service Cloud Messaging Channels (Service Cloud メッセージングチャネルでの自動応答のカスタマイズ)」を参照してください。

音声対応エージェントへの着信通話転送の設定

Salesforce でオムニチャネルフローを作成して、着信通話をエージェントに転送します。必要に応じて、通話を異なるエージェントに転送できます。

ヒント AI エージェントへの転送に失敗した通話は、テレフォニーシステムフローでキューまたはサービス担当者にリダイレクトされるバックアップ計画を設定します。
  1. ルーティング設定を作成します。ルーティング設定によって、通話が Agentforce サービスエージェントにルーティングされる方法が決まります。[ルーティング設定] ウィンドウで、次の値を入力します。他のすべての設定にはデフォルト値を使用します。
    • Routing Priority: 1
    • ルーティングモデル: 外部ルーティング
    • 業務量種別: 継承済み
    • 業務量の割合: 100%
  2. キューを作成します。このキューは、着信通話転送の代替キューとして使用されます。[キューの設定] ウィンドウで次の値を入力します。他のすべての設定にはデフォルト値を使用します。
    • ルーティング設定: ステップ 1 で作成したルーティング設定を選択します。
    • サポートされるオブジェクト: 音声通話
    • キューメンバー: なし
  3. Flow Builder で、[新規フロー] をクリックし、オムニチャネルフローを作成します。
  4. 音声通話レコード ID を保存する入力変数を作成します。 変数に「recordId」という名前を付け、データ型を「Text」に設定し、[Available for input] を選択して、[完了] をクリックします。
    テレフォニーシステムは、音声通話レコード ID をこのオムニチャネルフローへの入力として提供します。詳細は、「Create the recordId」を参照してください。
  5. [作業を転送] アクションをキャンバスにドラッグします。
    ヒント 複数の [作業を転送] アクションを追加して、作業項目を異なる Agentforce エージェントに転送できます。
  6. アクションの表示ラベルと API 参照名、必要に応じて説明を入力します。
  7. [入力値を設定] の [転送する作業レコードの数] フィールドで、[1 つ] を選択します。
  8. [レコード ID 変数] 項目で、recordId 変数を選択します。
  9. [Service Channel (サービスチャネル)] フィールドで、[Phone (電話)] を選択します。
  10. [ルーティング先] フィールドで、Agentforce サービスエージェントを選択します。
  11. Agentforce サービスエージェント フィールドで、音声対応エージェントの名前を選択します。
    エージェントがリストに表示されない場合は、エージェントが有効化されていることを確認してください。「Activate or Deactivate Your Agent」を参照してください。
  12. [代替キュー] フィールドで、[キューを選択] を選択し、VoiceCall オブジェクトをサポートする以前に作成したキューを選択します。
    メモ キューで VoiceCall オブジェクトがサポートされていない場合、ルーティングは失敗します。[代替キュー] 項目は必須ですが、通話の転送には使用されません。
  13. [完了] をクリックします。
  14. フローのすべてのアクションが接続されていることを確認します。
  15. オムニチャネルフローを保存して有効化します。
    着信通話をエージェントに転送するサンプルフローを次に示します。
  16. Agentforce Builder で受信フローが追加されていることを確認するには、Agentfore Studio アプリケーションでエージェントのテレフォニー接続を展開します。[ルーティング] タブで、受信フローが追加されていることを確認します。
  17. 従来のビルダーで受信フローが追加されていることを確認するには、Agentforce Agents の [設定] ページでエージェントを起動します。[接続] タブで、エージェントの接続を開き、受信フローが追加されていることを確認します。

その後、テレフォニーシステムで着信通話転送を設定します。

エスカレーションオムニチャネルフローの作成

エージェントが顧客のサポートを必要とする場合、Agentforceはエスカレーションフローをトリガーします。エージェントを切断して通話を担当者に転送するエスカレーションフローを作成します。Salesforce が通話を切断すると、通話制御はテレフォニーシステムに戻ります。

メモ コールが切断される理由のリストについては、VoiceCall の DisconnectReason フィールドを参照してください。
  1. Flow Builder で、[新規フロー] をクリックし、オムニチャネルフローを作成します。
  2. 音声通話レコード ID を保存する入力変数を作成します。 変数に「recordId」という名前を付け、データ型を「Text」に設定し、[Available for input] を選択して、[完了] をクリックします。
    テレフォニーシステムは、音声通話レコード ID をこのオムニチャネルフローへの入力として提供します。
  3. フローに少なくとも 1 つのアクションを追加します。
    空のフローを保存することはできません。
  4. [完了] をクリックします。
  5. フローのすべてのアクションが接続されていることを確認します。
  6. オムニチャネルフローを保存して有効化します。

エージェントは、送信オムニチャネルフローを使用して、会話をキュー、担当者、または指定した別の宛先に転送できます。詳細は、「オムニチャネルフローを使用したエージェントからの会話の転送」を参照してください。

Agentforce Builder でのエージェントへのエスカレーションフローの追加

エスカレーション中に実行するフローを確認するには、有効化されたエスカレーションフローをエージェントに追加します。

  1. Agentforce Studioアプリケーションの「エージェント」リストから、エスカレーションフローを追加するエージェントを開きます。
  2. [エクスプローラー] パネルの [エクスプローラー] パネルの [エージェント定義設定] で、[接続] を展開します。
  3. [Add a Telephony Connection (テレフォニー接続の追加)] で作成したテレフォニー接続を開きます。
  4. [ルーティング] をクリックします。[エスカレーション] セクションの [エスカレーションフロー] 項目で、作成したエスカレーションフローを選択します。
    フローを選択できない場合は、エージェントが無効になっていることを確認します。確定バージョンを使用している場合は、[新しいバージョン] をクリックします。フローがリストに表示されない場合は、ページを更新してフローを有効化してから、もう一度お試しください。
  5. 必要に応じて、[エスカレーションメッセージ] 項目で、通話が営業担当に転送されたときにエージェントが顧客に話すメッセージを変更します。
  6. 接続を保存し、エージェントを有効化します。

従来のビルダーでのエージェントへのエスカレーションフローの追加

エスカレーション中に実行するフローを確認するには、有効化されたエスカレーションフローをエージェントに追加します。

  1. [設定] から、[クイック検索] ボックスに「Agentforce エージェント」と入力し、[Agentforce エージェント] を選択します。
  2. エージェントを編集するには、エージェント名の右にあるドロップダウンをクリックし、[ビルダーで開く] を選択します。
  3. Agentforce Builder で、[接続] タブをクリックします。
  4. [Add a Telephony Connection (テレフォニー接続の追加)] で作成したテレフォニー接続を開きます。
  5. [エスカレーション] セクションの [エスカレーションフロー] 項目で、作成したエスカレーションフローを選択します。
    フローを選択できない場合は、エージェントが無効になっていることを確認します。フローがリストに表示されない場合は、ページを更新してフローを有効化してから、もう一度お試しください。
  6. 必要に応じて、[エスカレーションメッセージ] 項目で、通話が営業担当に転送されたときにエージェントが顧客に話すメッセージを変更します。
  7. 接続を保存します。
  8. [有効化] をクリックします。

Agentforce Builder でのエージェントの人格のカスタマイズ

音声設定を変更してエージェントの声をカスタマイズします。音声設定はどのフェーズでも更新できますが、最初にテレフォニーなどの音声対応接続をエージェントに追加することをお勧めします。音声設定は、そのエージェントのすべての音声対応接続に適用されます。音声設定を変更するには、まずエージェントが無効になっていることを確認します。

テレフォニープロバイダーを使用した Agentforce Voice および Salesforce Voice の役割

Agentforce Voice は、Agentforce に組み込まれた対話型の AI 機能です。Agentforce Voice は音声インタラクションを処理し、顧客のインテントを理解して音声応答を生成します。

テレフォニープロバイダーを使用する Salesforce Voice は、Amazon Connect、Genesys、CCaaS システムなどのサードパーティテレフォニーシステムを Salesforce と統合します。Agentforce Voice を使用するには、少なくともテレフォニープロバイダーを使用する Voice を有効にする必要があります。完全な設定は必要ありません。たとえば、CCaaS を使用している場合は、Voice with Telephony Providers を有効にする必要があります。ただし、テレフォニープロバイダーを備えた完全な Voice の設定により、Agentforce Voice はコンタクトセンターにシームレスに統合され、エージェントのエスカレーションやコンテキストの受け渡しなどのシナリオを簡単に処理できます。

Agentforce Voice とテレフォニープロバイダーを備えた Voice は連携して、コンタクトセンターを従来の静的テレフォニーからインテリジェントな会話環境に変換します。テレフォニープロバイダーを使用するAgentforce VoiceおよびVoiceでは、組み込みのエージェント転送およびエスカレーション機能を使用して、顧客が必要なときに24時間365日のサポートを提供できます。

    Agentforce エージェントにルーティングされる着信通話の管理に使用するチャネルを作成します。サポートされている場合は、すべての着信通話の VoiceCall レコードを Salesforce に作成するようにテレフォニー システムを設定し、SIP アドレスを使用して各通話を Agentforce エージェントに転送します。必要に応じて、通話を人間のサービス担当者に転送します。
  • 関連する音声通話の接続
    最初のポイントから Agentforce エージェントや人間のサービス担当者への通話転送など、1 つの顧客との会話に通話の転送が含まれる場合、通話のセグメントごとに個別の音声通話レコードを Salesforce で作成できます。これにより、同じ会話に対して複数の音声通話レコードが作成されます。1 つの包括的なビューを提供し、完全な通話コンテキストを維持するには、次の関連する音声通話レコードを接続する必要があります。レコードを接続すると、収集したすべての情報に基づいて通話を適切な担当者にエスカレーションするなど、十分な情報に基づいた意思決定が可能になります。

Agentforce Voice は、複数のモデルを使用して音声インタラクションを処理します。

  • ユーザーの話し言葉は、最初に Deepgram などの音声からテキストへの変換モデルを使用してテキストに変換されます。
  • 文字起こしされたテキストは、Salesforce Atlas 推論エンジンのように機能するフラッシュプランナーで処理されます。OpenAI GPT 大規模言語モデル (LLM) を使用して、ユーザーのクエリへの応答に使用する最も関連性の高いサブエージェントとアクションが特定され、テキスト応答が生成されます。
  • 最後に、生成されたテキストはテキスト読み上げモデルを使用して音声に変換され、ElevenLabs などのテキスト読み上げモデルを使用してユーザーに配信されます。

エージェントの回答が明確でわかりやすく、コンテンツの安全とセキュリティポリシーに準拠するための手順とガードレールが組み込まれています。これらの手順は、インタラクションを管理するためにフラッシュプランナーに統合されています。

組み込み命令とガードレールの機能の例を次に示します。

  • 音声配信の最適化: エージェントが住所などの情報を伝えるときの戦略的な一時停止など、音声返信の形式を設定する手順。たとえば、町名・番地から数字を分離します。
  • 簡潔な応答を提供する: 応答が長くなるのを防ぐために、単語制限でエージェントを誘導します。
  • コンテンツの安全性の確保: エージェントの回答に含まれる有害な表現や攻撃的な表現を防止し、機密情報を保護するガードレール。

Zero Data Retention Policies (ゼロデータ保持ポリシー)

データはサードパーティ LLM によって保持されません。OpenAI などのすべての外部モデルプロバイダーと提携して、ゼロデータ保持ポリシーを適用します。

  • 大規模言語モデル: すべての外部大規模言語モデル (LLM) プロバイダーと提携し、ゼロデータ保持ポリシーを適用します。Trust に関連するその他の問題の詳細については、Trust および Agentforce を参照してください。
  • Deepgram: Deepgram が提供する専用のオプトアウトメカニズムを使用して、データが要求の処理に必要な期間のみ保持され、モデルの改善に使用されないようにします。
  • ElevenLabs: ElevenLabs のゼロ保持モード (要求と応答のデータが要求の完了時にすぐに削除されるように強化されたプライバシー機能) を使用しています。特殊モードでは、機密データポイントのログが制限され、長期保存のためにデータベースに送信されることはありません。また、ElevenLabs はサードパーティの LLM プロバイダーとも契約を結んでおり、顧客データに関するモデルのトレーニングを行うことができません。

テレフォニーを使用した Voice の設定のベストプラクティス

テレフォニー接続の選択は、Agentforce Voice のリリースに関する最も重要な技術的決定の 1 つであり、遅延とメタデータ機能に影響します。

接続戦略

  • SIP (推奨): SIP はカスタム UUI (ユーザー間情報) ヘッダーをサポートするため、優先パスです。これらのヘッダーは、ルーティングデータと通話者コンテキストをネイティブに渡すために 16 進数でエンコードされた JSON ペイロードを伝送します。
  • PSTN の制限事項: PSTN は一般的ですが、ネイティブメタデータパススルーがなく、現在米国とカナダの番号のみをサポートしています。国際フローまたは地域間フローでは、SIP を使用して同じ地域内で要求を維持し、遅延を最小限に抑える必要があります。

技術的な実装:

  • Call Record Linking (通話レコードのリンク): PSTN の場合、[設定] で [コンテキストリンク設定] を有効にします。音声通話は、転送前に IVR で作成され、30 秒以内に完了する必要があります。
  • 通話記録: PSTN とは異なり、SIP 記録は Salesforce では自動ではありません。テレフォニーパートナーで明示的に設定する必要があり、これらの録音はパートナーのシステムにあります。
  • SIP 設定: Salesforce で SIP チャネルを作成し、そのチャネルに接続するようにパートナーシステム内で SIP トランクを有効にして設定します。

音声対応エージェントの計画と実装のベストプラクティス

リリースを成功させるには、技術、データ、法務の各ワークストリームを早期に調整する必要があります。

範囲とデータの準備:

  • 低複雑度の使用事例の優先度付け: FAQ や状況確認などの定期的な大規模コールから開始します。初期フェーズでの臨床トリアージのような高確度のシナリオは避けてください。
  • CRM および Knowledge データの監査: エージェントのパフォーマンスは、基礎となるデータの品質に依存します。重複レコードを解決し、Knowledge記事が適切に構造化され、最新であることを確認します。Knowledge 取得の応答速度を向上させるには、プロンプトテンプレートでより高速な出力生成モデルを使用します。音声の使用事例では、通常、Gemini Flash モデルの方が高速です。
  • 業務量の確認: 予想されるピーク量が、組織あたりの同時音声通話数のデフォルトの制限である 500 件以内に収まることを確認します。

セキュリティ、コンプライアンス、およびエスカレーション

  • Legal Engagement (法的エンゲージメント): すぐに音声記録保持ポリシーを定義します。完全な保持が制限されている場合は、トラブルシューティングのために短い期間 (24 時間など) を交渉します。
  • 処理とマスキング: 機密データルールを使用して、トランスクリプトの PII または PHI をマスキングします。PHIの場合、Salesforce Business Associate Agreement(BAA)が音声パイプライン全体をカバーしていることを確認し、Shield Platform Encryptionを有効にします。BAA は HIPPA に基づく法的契約です。
  • Design Fallbacks (フォールバックの設計): 通話者が行き詰まらないように、フォールバックキューまたはボイスメールを常に設定します。エラーシナリオを処理して、誤って通話が切断されないようにします。

請求可能な使用量種別

Agentforce は、音声アクション使用量種別または音声分数でフレックス クレジットを消費できます。

組織で Agentforce 音声アクションと Agentforce Voice Minutes の両方が有効になっている場合、請求では Voice Minutes が優先されます。組織で Agentforce Voice Minutes を使用できる場合、Agentforce Voice Minutes のみが測定され、Voice Actions の使用量種別は同じアクティビティに適用されません。

請求カテゴリ 説明
標準音声アクション

使用量は、エージェントが音声会話で実行する標準アクションの数によって決まります。

メモ Agentforce for Sales アドオンや Agentforce for Service アドオンへの登録など、一部の標準エージェント アクションを使用するには、これらのアクションにアクセスするユーザごとに登録を購入する必要があります。このような標準アクションに必要な登録を判断するには、『標準アクションリファレンス』の「標準アクションリファレンス」を参照してください。この要件はまだ技術的には適用されていませんが、必要なアドオンライセンスを持たないユーザーは、要件が適用されるとライセンスを持たないアクションにアクセスできなくなります。
カスタム音声アクション

使用量は、エージェントが音声会話でコールしたカスタムアクションの数によって決まります。

カスタムアクションは、ユーザーが作成したアクション、または標準アクションの変更によって発生するアクションです。顧客が作成したアクションの詳細については、「Create a Custom Agent Action (カスタムエージェントアクションの作成)」を参照してください。標準アクションがカスタムアクションになる方法についての詳細は、「標準エージェントアクションの参照アクションの編集」を参照してください。
Agentforce Voice Minutes

使用量は、エンド ユーザと Agentforce Voice 間の音声通話の長さによって決まります。使用量は、次の丸 1 分に切り上げられます。つまり、1 分未満の端数は丸 1 分として処理されます。

たとえば、

  • 60 秒の通話は 1 分として請求されます。
  • 61 秒の通話は 2 分として請求されます。

使用制限

  • サービスの継続性とフェールオーバー戦略: サービスの継続性を維持するために、Agentforce Voice は通常、Deepgram の音声/テキスト変換モデルとテキスト/スピーチモデルをローカルにリリースして、Salesforce Trust 境界内のデータを処理します。地域または可用性ベースのレート制限に達すると、システムはゼロデータ保持ポリシーに基づいてプロバイダーの外部インフラストラクチャにフェイルオーバーします。
  • 同時通話業務量およびルーティング: デフォルトの制限は、組織あたり 500 件の同時通話です。この制限を増やすには、Salesforce カスタマーサポートにお問い合わせください。
  • 音声通話レコードの生成: テレフォニープロバイダーを使用する Salesforce Voice ユーザーでない場合、Salesforce は顧客-エージェント間の会話の音声通話レコードを作成しますが、顧客-担当者間の会話の音声通話レコードは作成しません。テレフォニープロバイダーを使用する Salesforce Voice を設定していない場合、顧客と担当者の会話の音声通話レコードを作成できません。
  • SIP チャネルの有効化遅延: SIP ボイスメッセージングチャネルを無効化してから再度有効化すると、変更が有効になるまで最大 10 分遅れる可能性があります。この遅延の間、着信通話ルーティングの設定方法によっては、通話がサービス担当者に転送される場合があります。

Sandbox ストレージの制限

Sandbox 環境には 200 MB のストレージ制限があり、通話記録はすぐにこの制限に達する可能性があります。ストレージ制限に達すると、オムニチャネルが機能しなくなり、十分な領域が確保されるまで Agentforce Voice のテストがブロックされます。

ストレージの問題を回避するために、Sandbox 環境で通話記録を無効にすることをお勧めします。通話記録を無効にするには、[設定] に移動して Agentforce Voice を検索し、Agentforce Voice 設定ページで [エージェントとの音声通話を録音] オプションをオフにします。

ストレージ制限の問題が発生した場合、ストレージを削減またはクリアするには、一括削除オプションを使用して記録ファイルを削除します。録音ファイルを削除しても、関連付けられたトランスクリプトが必ずしも削除されるとは限りません。「大きなデータセットの操作」の「音声通話顧客データの削除」および「一括削除」セクションを参照してください。

本番に似た環境で Agentforce Voice をテストするには、より大きなストレージを使用する Full Sandbox または Partial Copy Sandbox をお勧めします。

調達した電話番号の考えられる状況を確認します。調達した電話番号を使用して通話をエージェントに転送するには、その電話番号の状況が [ライブ] である必要があります。

次の表に、電話番号のさまざまな状況と、状況が [ライブ] でない場合の対応策を示します。

状況 説明
キャンセル 電話番号の調達に失敗したことを示します。この状況が表示される場合は、新しい電話番号を調達してください。
ライブ 電話番号の調達が完了したことを示します。番号は完全にプロビジョニングされ、チャネルで使用する準備が整っています。
プロビジョニング 外部プロビジョニングプロセスが開始されたことを示します。電話番号の調達が進行中です。少し待ってから状況を更新します。
要求済み 調達要求が開始されたが、外部プロビジョニングプロセスがまだ開始されていないことを示します。少し待ってから状況を更新します。

PSTN のチャネルおよびテレフォニーの設定

Agentforce エージェントにルーティングされる着信通話の管理に使用するチャネルを作成します。サポートされている場合は、すべての着信通話の VoiceCall レコードを Salesforce に作成するようにテレフォニー システムを設定し、調達した電話番号を使用して各通話を Agentforce エージェントに転送します。必要に応じて、通話を人間のサービス担当者に転送します。

  • PSTN を使用して通話を転送する電話番号の調達
    PSTN を使用して通話を Agentforce エージェントに転送するには、最初に電話番号を取得します。後で、この電話番号を通話をエージェントに転送するために使用されるチャネルに関連付けます。
  • PSTN を使用した Agentforce Voice のチャネルの作成
    Agentforce エージェントに転送する必要がある着信通話のメッセージングチャネルを作成します。チャネルで、調達した PSTN 電話番号を着信オムニチャネルフローに対応付けます。着信通話がこの番号を使用して転送されると、オムニチャネルはオムニチャネルフローを使用して、チャネルに割り当てられたエージェントに通話を転送します。
  • PSTN を使用する場合のテレフォニーベンダー設定の定義
    サポートされている場合は、すべての着信通話の VoiceCall レコードを Salesforce に作成するようにテレフォニー システムを設定し、調達した電話番号を使用して各通話を Agentforce エージェントに転送します。
  • PSTN を使用する場合の関連する音声通話の接続
    着信通話が PSTN を使用して Agentforce エージェントに転送されると、通話のその区間に対して別個の音声通話レコードが Salesforce に作成されます。その結果、顧客とのこの会話の 2 つの音声通話レコードが作成されます。テレフォニープロバイダーを使用する Salesforce Voice ユーザーの場合、会話全体を把握するには、初回とエージェントの音声通話レコードを接続します。
  • PSTN 使用時の音声通話記録の有効化
    顧客と Agentforce エージェント間の会話を記録するには、記録を有効にします。デフォルトでは、録音は無効になっています。

    テレフォニープロバイダーを使用する Salesforce Voice ユーザーの場合、Salesforce は同じ会話に対して複数の音声通話レコードを作成できます。たとえば、着信通話が SIP を介して Agentforce エージェントに転送されると、Salesforce はそのコール レッグに対して個別の音声通話レコードを作成します。また、エージェントが通話を担当者に転送すると、Salesforce で 3 番目の音声通話レコードを作成できます。顧客との会話全体を表示するには、次の関連する音声通話レコードを接続します。
  • SIP を使用する場合の音声通話の記録と文字起こし
    SIP を使用する場合、Salesforce では音声通話記録はサポートされません。パートナーテレフォニーシステムで録音が提供されている場合は、参照できます。パートナー テレフォニーで通話記録がサポートされていない場合、その録音は音声通話レコードまたは Agentforce Studio では使用できません。

PSTN を使用する場合の通話のエスカレーションの設定

エージェントの通話がエスカレーションされると、エージェントは切断され、テレフォニーシステムは通話を再開します。サポートされている場合、エスカレーションされた通話を処理するようにテレフォニーシステムを設定します (通話を適切な担当者に転送する場合など)。

メモ PSTN の場合、調達した番号に直接電話をかけると、通話のエスカレーションは機能しません。テレフォニーシステムから通話をエージェントに転送する必要があります。

このページでは、Amazon Connect を使用してこのタスクを実行する方法について説明します。具体的には、元の通話をエージェントに転送した後で、通話が中断した場所から再開するように Amazon 着信フローを設定します。

  1. Amazon Connect で、受信 Amazon Connect フローを編集します。
  2. [テレフォニーシステムでの着信通話転送の設定(Configure Inbound Call Transfers in the Telephony System)] で設定した [電話番号に転送(Transfer to Phone Number)] ブロックを選択します。
  3. Agentforce エージェントが切断された後にこの Amazon Connect フローで通話を再開できるようにするには、[切断後にフローを再開] フィールドで [はい] を選択し、[保存] をクリックします。
  4. 通話を転送するテレフォニーロジックを設定します。たとえば、通話を担当者に転送するオムニチャネルフローに通話を転送するには、Amazon フローに [フローに転送] ブロックを追加します。
  5. Amazon Connect フローを保存して公開します。

String。必須。認証に使用される暗号化鍵。ランタイム認証には JSON Web トークン (JWT) が必要です。このトークンの長さは、他の暗号化アルゴリズムを採用するときに変更される可能性があります。SIP ヘッダーには、最大 1,024 文字を含めることができます。

テレフォニープロバイダーが複数のコールでトークンを再利用する場合、認証がすぐに失敗しないように、JWT トークンの有効期限を最長の 24 時間に変更します。要求の送信前に公開鍵または JWT の有効期限が切れた場合、SIP 転送は失敗します。

JWT の JSON クレームセットを作成するときに、次のパラメーターを使用できます。

  • iat— issued-at time (iat) は、JWT トークンが発行された Unix エポック以降の時間です。1970-01-01T0:0:0Z からの秒数で示します。

  • iss—発行者は、証明書を登録した 15 桁の Salesforce 組織 ID です。

  • sub—件名には、Salesforce Call Center API 参照名が含まれている必要があります。Open CTI ユーザーを含め、テレフォニープロバイダーを使用する Salesforce Voice 以外のユーザーの場合、sub パラメーターを除外します。

  • exp—アサーションの有効期限。UTC で測定された 1970-01-01T0：0：0Z からの秒数として表されます。有効期限は発行から 24 時間以内に設定する必要があります。

(SIP のみ) パートナーテレフォニーシステムでの SIP トランキングの設定

SIP を使用して通話を転送およびエスカレーションするようにテレフォニーシステムを設定する前に、テレフォニーシステムを Salesforce に接続します。テレフォニーシステムを Salesforce に接続するには、トラフィックとルーティングを管理するためのロジックを設定するだけでなく、ユーザー間の情報交換をサポートする暗号化された SIP トランクを作成する必要があります。

SIP トランクに次の属性を設定します。

  • Salesforce SBC FQDN とポートを使用して、Salesforce SBC エンドポイントを設定します。
  • プロトコルを TLS に設定します。
  • メディアコーデックを audio/PCMU および audio/PCMA に設定します。
  • 通話を転送する前に、User to User Information (UUI) ヘッダーを設定します。
  • UUI エンコード形式を 16 進数に設定します。
  • IP アドレスへの SIP アクセス権を付与します。Salesforce に転送される通話の許可リストと拒否リストを設定します。

Genesys での SIP トランキング設定の例

パートナーテレフォニーシステムで SIP トランキングを設定する方法を説明するために、このセクションでは Genesys を使用するタスクについて説明します。

サイトの追加

着信通話をピックアップする SIP トランクを定義するサイトを追加します。言及されていないプロパティについては、デフォルト値のままにします。

  1. Genesys Cloud にログインします。
  2. メニューをクリックし、[デジタルおよびテレフォニー] | [テレフォニー] | [サイト] を選択します。
  3. [サイト] ページで、新しいサイトを追加します。
  4. [名前] 項目に、サイトの名前を入力します。たとえば、「Salesforce」と入力します。
  5. [Location (ロケーション)] フィールドで、[Default PCV Location (デフォルトの PCV ロケーション)] を選択します。
  6. [メディアリージョン] 項目で、サイトに最も近いリージョンを選択します。たとえば、Genesys アカウントが米国西部にある場合は、[Americas (US West) (南北アメリカ (米国西部))] を選択します。
  7. サイトを保存します。

番号プランの作成

SIP トランクを使用して通話を転送するには、まず番号プランを作成し、SIP アドレスを割り当ててから、番号プランで SIP アドレスの分類を選択します。番号プランによって、ルーティング先の SIP トランクが決まります。言及されていないプロパティについては、デフォルト値のままにします。

その後、SIP トランクを設定します。

  1. [サイト] ページで、[番号プラン] タブをクリックします。
  2. [新規番号プラン] をクリックします。
  3. [番号プラン名] 項目に、プランの名前を入力します。
  4. [一致種別] 項目で、オプションを選択します。たとえば、[E.164 Number List] を選択します。
  5. [数値] 項目に、SIP アドレスの範囲の開始番号と終了番号を入力します。SIP アドレスが 1 つしかない場合は、両方に同じ番号を入力します。
    各番号は E.164 形式である必要があります。
  6. 作成する SIP トランクに着信通話を転送するには、[分類] 項目で分類を作成します。作成するには、名前を入力して [+] をクリックします。
  7. 番号プランを保存します。

SIP トランクの作成

SIP トランクを作成します。作成した SIP トランクに着信通話を転送するには、番号プランに割り当てた分類を使用します。言及されていないプロパティについては、デフォルト値のままにします。

  1. [デジタルおよびテレフォニー(Digital and Telephony)] メニューで、[トランク(Trunks)] をクリックします。
  2. [外部トランク(External Trunks)] ページで、[新規作成(Create New)] をクリックします。
  3. [名前] 項目に、トランクの名前を入力します。
  4. [Trunk Type (トランク種別)] フィールドで、[Generic BYOC Carrier (汎用 BYOC キャリア)] を選択します。
  5. ［Protocol］ フィールドで、［TLS］ を選択します。
  6. [終了識別子] 項目に、一意の ID を入力します。
  7. [サイトから] 項目で、前のステップで作成したサイトを選択します。
  8. Genesys が Salesforce をコールできるようにするには、[SIP Servers and Proxies (SIP サーバーとプロキシ)] 項目で Salesforce SBC エンドポイントを追加します。
    1. SIP サーバのホスト名として Salesforce SBC の完全修飾ドメイン名(FQDN)を入力し、ポートとして 5061 を入力して、[+] をクリックします。
      Salesforce SBC FQDN のリストについては、『 Agentforce Voice with SIP Regional Availability Chart 』を参照してください。
    2. テレフォニープロバイダーと地域の SBC FQDN を選択します。
  9. [SIP アクセスコントロール] セクションの [フォローしているアドレスを許可] 項目で、Salesforce SBC からの SIP メッセージを許可する IP アドレスを指定します。IP アドレスを取得するには、Salesforce 完全修飾ドメイン名に対してルックアップを実行します。
    1. Windows の場合は、コマンド プロンプトを開き、「nslookup SBCFQDN」と入力します。
    2. Mac または Linux の場合は、ターミナルを開き、「dig SBCFQDN」と入力します。
  10. [Identity] セクションで、[Address Omit + Prefix] を無効にします。
  11. [Media (メディア)] セクションの [Preferred Codec List (優先コーデックリスト)] フィールドに、サポートされている Salesforce コーデック (audio/PCMU および audio/PCMA) を追加し、Genesys の録音を有効にします。
  12. [プロトコル] セクションで、[会話ヘッダー] を有効にし、[UUI パススルー] を有効にして、[種別] を [ユーザー-to-ユーザー]、[エンコード形式] を [16 進数] に設定します。
  13. トランクを保存します。

アウトバウンドルートの作成

通話の分類に基づいて通話を外部 SIP トランクに転送するには、発信ルートを作成します。発信ルートでは、番号プランを特定のトランクに対応付けます。作成したサイトで、作成した SIP トランクのアウトバウンドルートを追加し、トランクを選択して、該当する分類を選択します。言及されていないプロパティについては、デフォルト値のままにします。

  1. 作成したサイトの [発信ルート] タブで、[新規発信ルート] をクリックします。
  2. アウトバウンドルートの名前を入力します。
  3. [外部トランクを選択] 項目で、作成したトランクを選択します。
  4. [分類] 項目で、既存の分類を番号プラン用に作成した分類に置き換えます。
  5. アウトバウンドルートを保存します。

(省略可能) 通話のテスト

  3. [国とコードを選択] ステップで、国と番号種別を選択します。
  4. [次へ] をクリックします。
  5. [Select Number] ステップで、3 桁の市外局番を入力し、[Search] をクリックします。
  6. 電話番号を選択します。
  7. [次へ] をクリックします。
  8. [Review & Save (確認して保存)] ステップで、電話番号の詳細を確認し、[Finish (完了)] をクリックします。

    ウィンドウが自動的に閉じます。番号はプロビジョニングのためにキューに入れられ、[プロビジョニング] 状況になっています。番号が正常にプロビジョニングされると、確認メールが送信されます。状況が [ライブ] の場合にこの番号を使用できます。

    メモ 2 人のユーザーが同じ番号を同時にプロビジョニングする場合、その番号は要求が最初にあったユーザーに割り当てられます。
  9. [電話番号] タブに電話番号が表示されない場合は、ページを更新します。

    新しく調達した電話番号がこのタブに表示されるまで数分かかる場合があります。

    電話番号を使用するには、その状況が [ライブ] である必要があります。状況が異なる場合の対処方法を判断するには、「調達電話番号の状況」を参照してください。

  10. 電話番号の最新の状況を表示するには、電話番号の右にある下矢印をクリックし、[Refresh Status (状況の更新)] をクリックします。

Agentforce Voice の [設定] ページの [電話番号] タブには、電話番号とその状況が表示されます。

  • 調達済み電話番号の状況
    調達した電話番号の考えられる状況を確認します。調達した電話番号を使用して通話をエージェントに転送するには、その電話番号の状況が [ライブ] である必要があります。

PSTN を使用する場合のテレフォニーベンダー設定の定義

サポートされている場合は、すべての着信通話の VoiceCall レコードを Salesforce に作成するようにテレフォニー システムを設定し、調達した電話番号を使用して各通話を Agentforce エージェントに転送します。

  • PSTN を使用した着信通話転送の設定
    このページでは、PSTN を介して行われる着信通話転送を設定する方法を説明するために、Amazon Connect を使用してこれらのタスクを実行する方法について説明します。
  • PSTN を使用する場合の通話のエスカレーションの設定
    エージェントの通話がエスカレーションされると、エージェントは切断され、テレフォニーシステムは通話を再開します。サポートされている場合、エスカレーションされた通話を処理するようにテレフォニーシステムを設定します (通話を適切な担当者に転送する場合など)。

SIP を使用する場合のテレフォニーベンダー設定の定義

サポートされている場合は、すべての着信通話の VoiceCall レコードを Salesforce に作成するようにテレフォニー システムを設定し、調達した SIP アドレスを使用して各通話を Agentforce エージェントに転送します。

  • (SIP のみ) パートナーテレフォニーシステムでの SIP トランキングの設定
    SIP を使用して通話を転送およびエスカレーションするようにテレフォニーシステムを設定する前に、テレフォニーシステムを Salesforce に接続します。テレフォニーシステムを Salesforce に接続するには、トラフィックとルーティングを管理するためのロジックを設定するだけでなく、ユーザー間の情報交換をサポートする暗号化された SIP トランクを作成する必要があります。
  • SIP を使用する場合の着信通話転送の設定
    このトピックでは、SIP を介して行われる着信通話転送を設定する方法を説明するために、Genesys でこれらのタスクを実行する方法について説明します。
  • SIP を使用する場合の通話のエスカレーションの設定
    エージェントの通話がエスカレーションされると、エージェントは切断され、テレフォニーシステムは通話を再開します。サポートされている場合、エスカレーションされた通話を処理するようにテレフォニーシステムを設定します (通話を適切な担当者に転送する場合など)。このトピックでは、SIP でのこの動作を説明するために、Genesys のパートナーテレフォニーを使用した Salesforce Voice を使用してこのタスクを実行する方法について説明します。具体的には、元の通話をエージェントに転送した後で、通話が中断した場所から通話を再開するように Genesys 着信フローを設定します。
