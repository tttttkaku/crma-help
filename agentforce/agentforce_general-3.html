標準適応型応答形式のリファレンス

標準適応応答形式は標準接続に含まれ、特定のチャネル、インターフェース、またはアプリケーションと連携するように構築されています。

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Foundations が付属する Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition、または Agentforce 1 Edition または Einstein 1 Edition
  • 適応型応答形式: リッチリンク応答

豊富な選択肢の回答は、エンドユーザーに固有のレコードのリストが含まれる質問です。現在、リッチ選択肢応答は Agentforce サービスエージェントだけで使用できます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Foundations が付属する Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition、または Agentforce 1 Edition または Einstein 1 Edition

適応型応答形式の詳細

対応付けられたメッセージングコンポーネント 動的オプションが含まれる質問
サポートされるチャネル

サポートされるチャネルについては、メッセージング接続に関連付けられたチャネルを参照してください。

リッチ選択肢の回答は、オムニスーパーバイザーにリッチコンテンツとして表示されます。

考慮事項

  • メッセージングコンポーネントビルダーでは、対応付けられたメッセージングコンポーネントをカスタマイズできません。
  • リッチ選択肢応答では、次のメッセージングコンポーネント形式がサポートされます。
    • 拡張チャット、拡張 WhatsApp、拡張 Facebook Messenger、拡張 LINE チャネルのボタン
    • 拡張チャット、拡張 Facebook Messenger、拡張 LINE チャネルのカードカルーセル
    • 拡張 WhatsApp チャネルと拡張 Apple Messages for Business チャネルのリストセレクター
    • サポートされているすべてのチャネルのテキスト
  • リッチ選択肢応答に含めることができるオプションの数は、対応付けられるメッセージングコンポーネント形式と、その送信チャネルによって異なります。たとえば、リッチ選択肢応答では、拡張 Facebook Messenger チャネルのカードカルーセル形式で最大 10 個のオプションがサポートされます。詳細は、「メッセージングコンポーネント形式」を参照してください。
  • リッチ選択肢応答では、ケース、商品、納入商品、注文、カスタムレコードがサポートされます。
  • リッチ選択肢応答では、PNG、JPEG、JPG 画像形式がサポートされます。
  • パフォーマンスの中断を回避するには、各画像に MIME タイプを含めるか、ファイル拡張子が .jpg、.jpeg、または .png の画像 URL を含めます。MIME 種別またはサポートされるファイル拡張子の URL を含めない場合、画像の MIME 種別はデフォルトで image/jpeg になります。
  • 拡張チャット REST API を使用するカスタムクライアントリリースでリッチ選択肢応答を使用するには、クライアントがテキスト、カードカルーセル、ボタン、リストセレクターメッセージングコンポーネント形式をサポートしている必要があります。

エージェント応答に画像が含まれるリッチ選択肢応答を使用するには、必要な情報を返すカスタムエージェントアクションを作成します。参照アクションのサンプルについては、Apex クラスの例を参照してください。

名前
リストオプションの名前。
MIME タイプ
省略可能。画像の MIME タイプ。例: image/jpeg。
画像の URL
公開されている画像の URL。画像ファイル拡張子を含めることをお勧めします。例: www.example.com/image.jpg。
説明テキスト
省略可能。リッチ選択肢の直前に送信されるテキスト。例: 「当社は、最も素晴らしい素材で作成されたさまざまな品目を取り揃えています。この項目とその作成方法の詳細を確認してください。'

この Apex クラスは、カテゴリ名に基づいて項目オプションのリストを取得します。項目名、画像の URL、MIME タイプ、説明テキストが含まれるオブジェクトのリストを返します。

例 
public with sharing class ItemOptionService {

    // Defines structure of an item name-image pair
        public class ItemDetail {
        public String itemName;
        public String itemImageUrl;
        public String itemMimeType;
        public String itemDescriptionText;
        public ItemDetail(String itemName, String itemImageUrl, String itemMimeType, String itemDescriptionText) {
            this.itemName = itemName;
            this.itemImageUrl = itemImageUrl;
            this.itemMimeType = itemMimeType;
            this.itemDescriptionText = itemDescriptionText;
        }
    }

    // Represents an object that holds a list of item name-image pairs
    public class ItemOptionWrapper {
        @InvocableVariable(label='Item Options' required=true)
        public List<ItemDetail> itemDetails;
        public ItemOptionWrapper() {
            this.itemDetails = new List<ItemDetail>();
        }
    }

    // Reprents input for getItemOptionsByCategory
    public class ItemOptionInput {
        @InvocableVariable(label='Category Name' required=true)
        public String categoryName;
    }

    @InvocableMethod(label='Get Item Options by Category' description='Returns a list of item options based on the category name')
    public static List<ItemOptionWrapper> getItemOptionsByCategory(List<ItemOptionInput> categoryNames) {
        System.debug('categoryNames: ' + categoryNames);

        // Get the category name from the input list
        String category = categoryNames[0].categoryName.toLowerCase();
        System.debug('Processing category: ' + category);

        ItemOptionWrapper selectedItemWrapper = new ItemOptionWrapper();
        if(category.contains('category1')) {
            selectedItemWrapper.itemDetails.add(new ItemDetail('Item1', 'https://example.com/images/item1.jpg', 'image/jpeg', 'We have items that are great and made with most incredible materials. Learn more about item 1 and how it was created.'));
            selectedItemWrapper.itemDetails.add(new ItemDetail('Item2', 'https://example.com/images/item2.jpg', 'image/jpeg', 'We have items that are great and made with most incredible materials. Learn more about item 2 and how it was created.'));
        } else if(category.contains('category2')) {
            selectedItemWrapper.itemDetails.add(new ItemDetail('Item3', 'https://example.com/images/item3.jpg', 'image/jpeg', 'We have items that are great and made with most incredible materials. Learn more about item 3 and how it was created.));
        } else {
            selectedItemWrapper.itemDetails.add(new ItemDetail('Default Item', 'https://example.com/images/default.jpg', 'image/jpeg', 'We have items that are great and made with most incredible materials. Learn more about this item and how it was created.'));
        }

        System.debug('Returning : ' + selectedItemWrapper);
        return new List<ItemOptionWrapper>{ selectedItemWrapper };
    }
}

Web サイトの URL。
リンクタイトル
URL と共に表示するテキスト。
リンク画像の URL

この Apex クラスは、項目名のリストに基づいて項目の詳細を取得します。項目名、URL、タイトル、画像の URL、MIME 種別が含まれるオブジェクトのリストを返します。

例 
public class GetItemDetailsInvocable {

    // Represents input for getItemDetails.
    public class ItemDetailRequest {
    @InvocableVariable(label='Item Name' description='The name of the item' required=true)
        public String itemName;
    }

    // Defines structure for output of getItemDetails.
    public class ItemDetail { 
        public String linkURL;
        public String linkTitle;
        public String linkImageURL;
        public String linkImageMimeType;
        public String descriptionText;
    }

    // Represents output of getItemDetails
    public class ItemDetailResponse {
    @InvocableVariable(label='Item Details' description='linkURL, linkTitle, Image linkURL, MIME Type, and description for a given item name' required=true)
        public List<ItemDetail> itemDetails;
        public ItemDetailResponse() {
            this.itemDetails = new List<ItemDetail>();
        }
    }

    @InvocableMethod(label='Get Item Details' description='Returns linkURL, linkTitle, image linkURL, MIME Type, and description for a given item name')
    public static List<ItemDetailResponse> getItemDetails(List<ItemDetailRequest> requests) {

        List<ItemDetailResponse> responses = new List<ItemDetailResponse>();

        for (ItemDetailRequest request : requests) {
            ItemDetailResponse response = new ItemDetailResponse();
            ItemDetail itemDetail = new ItemDetail();
            String itemName = request.itemName.toLowerCase();

            // Example item data.
            if (itemName.contains('item1')) {
                itemDetail.linkURL = 'https://www.example.com/item1';
                itemDetail.linkTitle = 'Item 1';
                itemDetail.linkImageURL = 'https://www.example.com/image1.jpg';
                itemDetail.linkImageMimeType = 'image/jpeg';
                itemDetail.descriptionText = 'This is an amazing item!'
            } else if (itemName.contains('item2')) {
                itemDetail.linkURL = 'https://www.example.com/item2';
                itemDetail.linkTitle = 'Item 2';
                itemDetail.linkImageURL = 'https://www.example.com/image2.png';
                itemDetail.linkImageMimeType = 'image/png';
                itemDetail.descriptionText = 'This is a great item!'
            } else if (itemName.contains('item3')) {
                itemDetail.linkURL = 'https://www.example.com/item3';
                itemDetail.linkTitle = 'Item 3';
                itemDetail.linkImageURL = 'https://www.example.com/image3.png';
                itemDetail.linkImageMimeType = 'image/png';
                itemDetail.descriptionText = 'This is a wonderful item!'
            } else {
                itemDetail.linkURL = 'https://www.example.com/default';
                itemDetail.linkTitle = 'Unknown Item';
                itemDetail.linkImageURL = 'https://www.example.com/default.jpg';
                itemDetail.linkImageMimeType = 'image/jpeg';
                itemDetail.descriptionText = 'This is an item!'
            }
            response.itemDetails.add(itemDetail);
            responses.add(response);
        }
        return responses;
    }
}

エージェントスクリプト

Agentforce Builder でエージェントを作成するための言語について説明します。キャンバス ビュー、スクリプト ビュー、または Agentforce とのチャットでエージェントを作成してカスタマイズする場合でも、エージェント スクリプトを記述します。エージェントスクリプトを使用して、LLM による解釈のみに依存しない、予測可能なコンテキスト対応エージェントワークフローを作成します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

エージェントスクリプトとは?

エージェントスクリプトは、Agentforce Builder でエージェントを作成するための言語です。スクリプトは、会話タスクを処理するための自然言語命令の柔軟性と、ビジネスルールを処理するためのプログラム式の信頼性を兼ね備えています。スクリプトでは、式を使用して if/else 条件、トランジション、その他のロジックを定義し、変数を設定、変更、比較し、サブエージェントとアクションを選択します。LLM による解釈のみに依存しない、予測可能なコンテキスト対応エージェントワークフローを作成できます。たとえば、スクリプトを使用して、エージェントがサブエージェント間で遷移するタイミングや、アクションを特定の順序で実行するタイミングを制御できます (アクションチェーンと呼ばれることもあります)。

Agentforce Builder には、エージェントスクリプトを記述するいくつかの方法が用意されています。

  • Agentforce とチャットして、エージェントが実行できる機能(「注文の合計が $100 を超える場合は送料無料を提供する」など)を説明できます。Agentforce は、要求をサブエージェント、アクション、命令、およびその他の式に変換します。
  • キャンバスビューでは、エージェントスクリプトはわかりやすいブロックにまとめられ、展開して基盤となるスクリプトを表示できます。クイックアクションショートカットを使用してエージェントを編集できます。一般的なパターン (if/else 条件など) の式を追加するには「/」と入力し、リソース (サブエージェント、アクション、変数) を追加するには「@」と入力します。
  • 上級ユーザーはスクリプトビューに切り替えて、構文の強調表示、オートコンプリート、検証などの開発者向けの支援機能を使用して、スクリプトを直接作成および編集できます。

開発者は、Agentforce DXを使用して、ローカルのSalesforce DXプロジェクトでスクリプトファイルを生成または取得し、Visual Studio Codeで操作することもできます。Agentforce DX VS Code Extensionは、標準のコード編集機能を使用してエージェントスクリプト言語を完全にサポートします。

エージェントスクリプトで何ができますか?

エージェントスクリプトでは、自然言語プロンプトから派生した会話スキルと複雑な推論能力が保持され、プログラムによる指示の決定性が追加されます。たとえば、エージェントスクリプトでは、次のように定義できます。

  • LLM が自由に推論を判断できる特定の領域。
  • エージェントが確定的に実行する必要がある特定の領域。
  • LLM コンテキストメモリに依存するのではなく、エージェントの現在の状態に関する情報を確実に保存するための変数。
  • エージェントの実行パスまたは LLM の発言を決定する条件式 (if/else)。たとえば、is_member variableの値に基づいて顧客に異なる方法で話すようにエージェントに指示できます。または、appointment_type変数の値に基づいて、実行するアクションを決定的に指定できます。
  • エージェントが新しいサブエージェントに移行する条件。確定的に新しいサブエージェントに移行できます。または、サブエージェントトランジションをアクションとして LLM に公開し、LLM がサブエージェントを切り替えるタイミングとタイミングを決定できるようにすることもできます。

エージェントスクリプトの例

エージェントスクリプトの簡単な例を次に示します。

system:
  instructions: "You are a friendly and empathetic agent that helps customers with their questions."
    messages:
        error: "Sorry, something went wrong."
        welcome: "Hello! How are you feeling today?"

variables:
    isPremiumUser: mutable boolean = False
        description: "Indicates whether the user is a premium user."


config:
    agent_name: "HelloWorldBot"
    default_agent_user: "hello@world.com"
    user_locale: "en_US"

start_agent hello_world:
    description: "Respond to the user."
    reasoning:
        instructions: ->
            if @variables.isPremiumUser:
                | ensure you ask the user if they want to redeem their Premium points
            else:
                | ensure you ask the user if they want to upgrade to Premium service.

エージェントの作成

従来のビルダーから新しいビルダーへのエージェントのアップグレード

[設定] の [Agentforce エージェント] ページで、リストビューのエージェントの横にあるドロップダウンメニューからエージェントをアップグレードします。

  1. アップグレードするエージェントのバージョンを選択します。
  2. [Upgrade to New Builder (新規ビルダーにアップグレード)] をクリックします。

    新しい Agentforce Builder でエージェントのドラフトバージョンが作成されます。

  3. 新しいビルダーでエージェントを開くには、[Let's Go] をクリックします。それ以外の場合は、従来のビルダーでエージェントを続行するか、終了することができます。
  4. 必要に応じて、[エージェントスクリプト] のエージェントの指示を最適化します。
    1. [最適化] をクリックします。

      Agentforce は、自然言語の指示を確認して改善を提案し、エージェントの信頼性とパフォーマンスを改善するための確定的制御を追加します。

    2. Agentforce の提案を受け入れるか却下します。
    3. 変更内容を保存します。

理由や指示が変更されると、エージェントの動作に影響する可能性があります。アップグレード後、新しいビルダーで慎重にエージェントをテストし、期待どおりに動作することを確認します。必要に応じて、指示を調整します。準備ができたら、エージェントを確定して有効化します。

アップグレードされたエージェントは元のエージェントのバージョンであるため、次の考慮事項に留意してください。

  • アップグレードされたバージョンのエージェントは、作成元のエージェントの名前を継承し、次の連番が追加されます (たとえば、従来のビルダーで [私のエージェント - 3] をアップグレードすると、新しいビルダーの新しいバージョンは [私のエージェント - 4] という名前になります)。後続の各バージョンは、新しいビルダーで作成しても従来のビルダーで作成しても、同じパターンに従います。
  • エージェントバージョンを開くと、互換性のあるビルダーで開きます。これは、Agentforce Studio の [エージェント] リスト、[Agentforce Agents 設定] ページのリストビュー、またはいずれかのビルダー内のバージョンドロップダウンからバージョンを開いても当てはまります。Agentforce Studio の [エージェント] リストまたは Agentforce Agents の [設定] ページのリストビューから最上位のエージェントを開くと、最新バージョンのエージェントが互換性のあるビルダーで開きます。
  • エージェントの有効なバージョンは一度に 1 つしか使用できません。従来のビルダーで有効なエージェントのバージョンをアップグレードしても、エージェントは有効なままで、進行中のエージェントの会話は中断されません。ただし、新しいビルダーでアップグレードされたバージョンを含め、他のバージョンのエージェントを有効化すると、最初に有効化されたバージョンは無効になります。
  • エージェントのバージョンを削除しても、他のバージョンのエージェントには影響しません。エージェント全体を削除すると、作成されたビルダーに関係なく、すべてのバージョンのエージェントが削除されます。

  2. エージェントの名前をクリックします。次に、[ビルダーで開く] をクリックします。

    1. エージェントのライブラリを選択するか、ライブラリを作成するには [新規ライブラリ] をクリックします。ライブラリを選択または作成する場合は、データライブラリでインデックス付けするナレッジ項目またはファイルアップロードを設定できます。ライブラリを作成した場合、プレビュー会話が更新されるまで数分かかることがあります。

変更をテストするには、プレビュー会話を再開してからエージェントとチャットします。

シミュレーションモード

シミュレーションモードでは、リスクのないテストスペースが提供されます。データを変更せずにエージェントの設定 (その基盤となるロジックやワークフローなど) を確認するように設計されています。このモードを使用して、エージェントが適切なサブエージェントとアクションを選択し、目的どおりに応答していることを確認します。

ライブテストモードは、本番環境に似た条件でエージェントのパフォーマンスと動作をテストします。このモードでテストする場合、エージェントは有効化されているかのように動作します。テストでは、サブエージェントの実行とアクションの実行の機能をチェックし、Salesforce データを積極的に更新します。このステップは、アクションを完全にチェックし、データが正しく、システムインテグレーションが正常に機能していることを確認するために重要です。

    LLM 審査員とは何ですか?

    LLM 審査員 (または LLM-as-judge) とは、ある大規模言語モデル (LLM) が別の大規模言語モデルの出力を評価してスコアを付けることです。裁判官 LLM は、タスクを定義し、結果の正確性、関連性、一貫性、ソースへの忠実度などのスコアリング条件の概要を説明するプロンプトを受信します。これらのリソースとガイドラインを使用して、LLM 審査員は予想される応答を判断し、エージェントの応答と比較します。この比較に基づいて、審査員はスコア、ランキング、または書面によるフィードバックを生成します。裁判官としての LLM モデルは、スコアリング集計や回答のランク付けなどのタスクの拡張性が高く、自動化された客観的な評価ツールとして機能します。LLM-as-Judge プロンプトは、最も正確で有益なテスト結果を提供するために慎重に設計されています。

Agentforce テストの管理

まず、簡単な説明でテストの焦点を定義し、システムでテストケースを生成させます。テストセンターは、エージェントが使用できるKnowledgeコンテンツに基づいて質問と回答形式のテストケースを生成します。

  1. Knowledge からテストケースを作成するには、［Generate test cases based on Knowledge available to this agent］ を選択します。
    メモ Knowledge 記事および項目またはファイルのアップロードに基づいて、データライブラリに接続されているエージェントに対してのみテストを生成できます。カスタム取得者または Web ソースに基づくデータライブラリに接続されているエージェントはサポートされません。
    メモ テストケースは Agentforce Agent のデフォルト言語でドラフトが作成されます。サポートされる言語については、「Considerations for Testing Center (テストセンターに関する考慮事項)」を参照してください。
  2. 生成するテストケースの数を指定します。一度に最大 200 個のテストケースを生成できます。
  3. テストの目的と範囲に関する AI モデルのガイドに役立つ説明を入力します。[次へ] をクリックします。

    テストの説明はテストにどのように影響しますか?

    テストの説明はプロンプトに含まれ、テストの焦点またはテーマを定義することでテストケースの生成方法をガイドします。説明のキーワードや語句は、テストの作成に関する情報を絞り込むのに役立ちます。これは、エージェントが記事や PDF などの複数のソースにリンクされている場合に特に便利です。

    説明でテストの形式や複雑さをカスタマイズすることはできませんが、関連する用語や語句を使用することでテストの焦点を定義できます。完全な文法は必須ではありませんが、完全な文を使用して説明を記述することで、AI と人間のレビュー担当者の両方が意図を理解し、出力の関連性を高めることができます。

メモ 生成 AI では、取引先、リード、商談、取引先責任者オブジェクトのテストケースを生成できます。説明に具体的な手順を含めることで、カスタム オブジェクトのテスト ケースや [Answer Questions with Knowledge (ナレッジを使用して質問に回答)] アクションを作成することもできます。たとえば、カスタムオブジェクトの場合、「Generate test cases for [custom object name]. ([カスタムオブジェクト名] のテストケースを生成します。)サンプル発言は、[カスタムオブジェクトに関連するサンプル発言]、[カスタムオブジェクトに関連するサンプル発言] です。AI で [Answer Questions with Knowledge (ナレッジを使用して質問に回答)] アクションのテストケースを作成するには、「Generate test cases for the Answer Questions with Knowledge action. (ナレッジを使用して質問に回答するアクションのテストケースを生成する。)」のような説明を使用します。[記事のタイトル]、[記事のタイトル] のKnowledge記事を使用してテストを生成します。

    Agentforce テストセンターは、テストするエージェントがアクセスできるサブエージェントとアクションを識別し、この情報を使用して対象を絞ったテストケースを作成します。その後、テスト発言はサブエージェントとアクション指示に基づいてドラフトが作成され、エージェントが選択するようにトリガーされます。エージェントが発言を受信して処理するときに、エージェントが目的のサブエージェントとアクションを正しく選択したことを確認します。

    エージェントの全体的な効果を評価するには、使用可能なすべてのサブエージェントでテストケースを生成します。この包括的なアプローチにより、エージェントのパフォーマンスを幅広く把握できるため、弱点を特定し、より対象を絞ったテストに優先順位を付けることができます。これらの課題を早期に特定して対処することで、リリース前にエージェントの精度を大幅に向上させることができます。

    または、特定のサブエージェントまたはアクションを変更した場合は、それらのサブエージェントを選択して変更を検証し、正しい動作を確認します。たとえば、[返金要求] サブエージェントを更新した場合、そのサブエージェントのみにテストを分離することで、変更が意図したとおりに機能することを確認でき、時間を節約してエージェントのパフォーマンスの信頼性を高めることができます。

    特定のビジネス領域に関連するサブエージェントのクラスタを選択することもできます。たとえば、[注文状況]、[注文をキャンセル]、[注文を変更] など、注文管理に関連するサブエージェントのグループを選択して、エージェントが顧客のエンドツーエンドの注文関連クエリをどのように処理するかを包括的にテストできます。関連するサブエージェントをクラスター化することで、すべてのタッチポイントでシームレスで正確な環境を実現できます。

AI エージェントの信頼性を高め、徹底的なテストでシームレスで効果的なインタラクションを実現します。カスタム テスト シナリオを簡単に生成し、エキスパートによる評価ツールを活用して、応答の精度、会話の品質、サブエージェントの認識、アクションの実行、Knowledge取得を評価します。問題を早期に特定し、エージェントの動作を正確に微調整します。

テストセンターでは、さまざまな評価を通じて大規模なバッチテストをサポートしています。これには、応答の精度、サブエージェントとアクションの検証、主要な品質評価指標 (完全性、一貫性、簡潔性、遅延、命令遵守など) が含まれます。小規模なテストでは見逃されがちなパターンやエッジケースを明らかにすることで、エージェントのパフォーマンスの全体像を把握できます。これらのインサイトを使用して、パフォーマンスギャップを埋め、サブエージェントの指示を調整し、AI エージェントの応答を継続的に改善できます。

評価の選択

評価では、主要な領域全体で AI エージェントのパフォーマンスを測定します。デフォルトの評価には、応答精度、サブエージェントアサーション、アクションアサーションが含まれます。テスト目標により適合させるために、完全性、一貫性、簡潔性、遅延、命令遵守など、品質重視の評価を追加できます。適切な評価の組み合わせを選択することで、エージェントを戦略的に調整および改善するために必要なインサイトが得られます。

まず、テストするエージェントを選択し、実際の使用事例に合わせて会話履歴やコンテキスト変数などの主要な条件を設定します。次に、テストデータを選択します。エージェントが選択したサブエージェントとアクションを検証するシナリオを生成するか、エージェントが使用できるKnowledgeコンテンツに基づいて質問と回答形式のテストケースを生成するか、完全な制御のために独自のテストケースをCSVファイルにアップロードします。次に、基本的な応答精度から、一貫性、完全性、指示の遵守など、より深い品質評価指標まで、エージェントのパフォーマンスを最適に測定する評価を選択します。すぐにテストを実行することも、実行前にケースをダウンロードして確認および調整することもできます。

  1. テストの作成
    AI で生成されたテストシナリオを使用してテストをすばやく追跡するか、独自のテストシナリオを作成してアップロードします。Agentforceデータライブラリで使用可能なサブエージェントおよびアクションまたはデータに対してエージェントをテストします。
  2. テスト条件の定義
    CSV テンプレートからテストケースをアップロードする場合、会話履歴やコンテキスト変数などのテスト条件を定義すると、追加のコンテキストを提供できます。これらの変数は、より現実的なユーザーインタラクションをシミュレーションするのに役立つため、テストの信頼性が向上し、実際のエージェントの行動が反映されます。
  3. テストデータの追加
    AI でテストケースを生成するか、独自のシナリオをアップロードして、エージェントのパフォーマンスを評価するテストケースを追加します。AI で生成されたテスト ケースには、サブエージェントとアクションに基づいて生成するか、Agentforce データ ライブラリを介してエージェントが使用できる Knowledge から生成するかの 2 つのデータ オプションがあります。
  4. 評価の選択
    評価では、主要な領域全体で AI エージェントのパフォーマンスを測定します。デフォルトの評価には、応答精度、サブエージェントアサーション、アクションアサーションが含まれます。テスト目標により適合させるために、完全性、一貫性、簡潔性、遅延、命令遵守など、品質重視の評価を追加できます。適切な評価の組み合わせを選択することで、エージェントを戦略的に調整および改善するために必要なインサイトが得られます。

サブエージェントおよびアクションからのテストの生成

稼働開始前にエージェントが主要なサブエージェントとアクションをどの程度適切に処理しているかを評価します。サブエージェントとアクションメタデータ、および接続済みデータライブラリからの情報を使用して、テスト可能な関連発言を生成します。テストするサブエージェントを選択し、簡単な説明でテストの焦点を定義し、最大 100 個のテストケースを生成できるようにします。

    テストの説明はテストにどのように影響しますか?

    テストの説明はプロンプトに表示され、テストの焦点やテーマを定義することでテストケースの生成方法をガイドします。説明のキーワードや語句は、テストの作成に関連する情報の領域を絞り込むのに役立ちます。これは、エージェントが記事や PDF などの複数のソースを使用している場合に特に便利です。

    説明でテストの形式や複雑さをカスタマイズすることはできませんが、関連する用語や語句を使用してフォーカスを明確に定義すればするほど、テストケースの対象は絞り込まれます。完全な文法は必須ではありませんが、完全な文で記述することで、AI と人間のレビュー担当者の両方が意図をよりよく理解し、出力の関連性を高めることができます。

  4. テストするサブエージェントを選択します。[次へ] をクリックします。

    どのサブエージェントとアクションを選択すればよいですか?

    Agentforce テストセンターは、テストするエージェントがアクセスできるサブエージェントとアクションを識別し、この情報を使用して対象を絞ったテストケースを作成します。その後、テスト発言はサブエージェントとアクション指示に基づいてドラフトが作成され、エージェントが選択するようにトリガーされます。これらの発言がエージェントに送信されると、エージェントが対象のサブエージェントとアクションを正しく選択したことを確認します。

    エージェントの全体的な効果を評価するには、使用可能なすべてのサブエージェントでテストケースを生成します。この包括的なアプローチにより、エージェントのパフォーマンスを幅広く把握できるため、弱点を特定し、より対象を絞ったテストに優先順位を付けることができます。これらの課題を早期に特定して対処することで、リリース前にエージェントの精度を大幅に向上させることができます。

    または、特定のサブエージェントまたはアクションを変更した場合は、それらのサブエージェントを選択して変更を検証し、正しい動作を確認します。たとえば、[返金要求] サブエージェントを更新した場合、そのサブエージェントのみにテストを分離することで、変更が意図したとおりに機能することを確認でき、時間を節約してエージェントのパフォーマンスの信頼性を高めることができます。

    特定のビジネス領域に関連するサブエージェントのクラスタを選択することもできます。たとえば、[注文状況]、[注文のキャンセル]、[注文の変更] など、注文管理に関連するサブエージェントのグループを選択して、エージェントが顧客のエンドツーエンドの注文関連クエリをどのように処理するかを包括的にテストし、すべてのタッチポイントでシームレスで正確な環境を確保できます。
