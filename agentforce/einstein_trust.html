Trust and Agentforce

Salesforce では、エージェントは生成 AI 技術に関連するリスクを軽減するように設計されているため、安全な AI エージェントを簡単に作成できます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

AgentforceプラットフォームはEinstein Trust Layerと統合されており、機能にはAIガードレールが含まれています。エージェントは標準の Salesforce アクセス制御も尊重します。

Einstein Trust Layer

Agentforceは、Salesforceにネイティブに組み込まれた安全なAIアーキテクチャであるEinstein Trust Layerと統合されています。

エンタープライズ セキュリティ標準向けに設計されたTrust Layerにより、顧客データを損なうことなく生成AIのメリットを享受できます。また、信頼できるデータを使用して生成 AI 応答を改善することもできます。

Einstein Trust Layer サービス 説明
Zero Data Retention Policy (ゼロデータ保持ポリシー) Einstein Trust Layerではゼロ データ保持ポリシーが使用されるため、サード パーティLLMによるモデルのトレーニングにデータが保存または使用されることはありません。エージェントを含む他の機能を顧客が使用すると、データストレージが作成される可能性があります。詳細は、Salesforce のアカウントエグゼクティブにお問い合わせください。
安全なデータ取得を使用した動的グラウンディング 信頼できる会社のデータ、Knowledgeベース、または設定したその他のソースからの関連情報を使用して質問に回答します。
プロンプトの防御 (システムポリシーとプロンプトの挿入検出) システムポリシーは、幻覚を制限し、LLM が意図しない出力や有害な出力を行う可能性を減らすのに役立ちます。
有害検出 潜在的な有害な LLM 応答が検出され、フラグが付けられます。
監査とフィードバック プロンプト、応答、Trustシグナルが記録されてData 360に保存されるため、各ユーザー操作の結果を把握できます。フィードバックは、手順やプロンプトテンプレートの改善などに使用できます。

Einstein Trust Layer を介したデータ マスキングは、エージェントのパフォーマンスと精度を高めるために無効になっています。エージェントがアクセスするすべてのデータ (個人識別情報 (PII) を含む) は、厳格なゼロデータ保持ポリシーの一環として、転送中に保護され、外部の LLM プロバイダーによってトレーニング目的で保存または使用されることはありません。「Agentforce のデータマスキングの制限」を参照してください。

AI ガードレール

Agentforceプラットフォームには、AIの幻覚を最小限に抑えるための倫理的なガードレールと、プロンプト インジェクションなどの脅威や悪意のある攻撃を防止するためのセキュリティ ガードレールが含まれています。

より詳細な制御を行うには、エージェントサブエージェントの指示を使用して境界を作成し、コンテキストを設定して、エージェントの動作を定義します。標準エージェントサブエージェントの手順を変更するか、カスタムサブエージェントを最初から作成できます。指示の遵守を使用して、エージェントがサブエージェントの指示をどの程度適切に解釈し、従っているかを確認します。

さまざまなエージェント種別に、エージェントの動作を定義する独自の設定とガードレールを設定できます。たとえば、Agentforce サービスエージェントテンプレートでは、サブエージェントの指示を使用して、エージェントからサービス担当者に会話をエスカレーションするタイミングを決定します。SDR エージェント種別には、エージェントがリードの作業を開始できる条件とエージェントメールを送信できる方法とタイミングに関する、システム管理者が定義したエンゲージメントルールがあります。

権限とアクセス権

AI エージェントは、ライセンス、権限、項目レベルセキュリティ、共有設定などの標準の Salesforce アクセス制御を尊重するため、エージェントは常に安全に動作します。

  • エージェント タイプ：デフォルトの Agentforce エージェントは、システム管理者および「Agentforce Default」権限セットを持つユーザが使用できます。一部のエージェント種別は、特定のクラウドまたはライセンスで動作するように構築されているため、別のライセンスが必要です。
  • 標準エージェントサブエージェント: 多くの標準サブエージェントは、デフォルトの Agentforce エージェントにアクセスする権限を持つすべてのユーザーが使用できます。
  • 標準エージェントアクション: 多くの標準アクションは、デフォルトの Agentforce エージェントにアクセスする権限を持つすべてのユーザーが使用できます。一部の標準アクションは、特定のクラウドまたは製品と連携するように構築されているため、別のライセンスまたは権限が必要です。
  • カスタムエージェントアクション: カスタムアクションへのアクセスは、アクションが参照する Apex クラス、フロー、またはプロンプトテンプレートによって異なります。たとえば、カスタムアクションがフローを使用して作成されている場合、カスタムアクションはフローで設定された権限、項目レベルセキュリティ、および共有設定に従います。

信頼済み URL

Agentforce は、ビジネスの信頼済み URL 許可リストを適用します。これにより、エージェントが悪意のあるリンクを呼び出したり生成したりすることが防止され、機密データのセキュリティが維持されます。

エージェントが未承認の URL を応答に含めようとすると、未承認の URL は「URL_Redacted」に置き換えられます。また、エージェントが未承認の URL をコールまたは生成しようとすると、プランキャンバスにエラーメッセージが表示されるため、ブロックされた URL を許可リストに追加するか、エージェントの設定から削除するかを評価できます。

エージェントに引用が設定されている場合、ドメインが信頼済み URL に含まれていなくても、エージェント応答の生成に使用されるソース URL がエージェントの会話に表示されます。

エージェントで URL を使用するには、信頼済み URL に追加します。

エージェントコンプライアンス

Agentforce は、Einstein プラットフォームおよび Agentforce SOC 2 および SOC 3 レポートに対象サービスとして含まれています。Agentforce は HIPAA の要件を満たしており、Salesforce Business Associate Addendum の制限の対象です。また、ISO 27001、27017、27018 の認定も取得しています。

  • Agentforce のデータマスキングの制限事項

マスクされたデータの確認

Einstein Trust Layer の [設定] でデータのマスキング先を設定したら、機密データがマスキングされていることを確認し、経時的な監視も行う必要があります。

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。
必要なユーザー権限
プロンプトビルダーでプロンプトテンプレートを作成および管理する 「プロンプトテンプレートマネージャー」権限セット
レポートやダッシュボードを表示およびアクセスする 「Data Cloud ユーザー」

どのデータがマスクされているかを確認するには、2 つの方法があります。

  • プロンプトビルダーを使用して、実行時にマスクされるデータを確認できます。「Get to Know プロンプトビルダー」を参照してください。
  • データのマスキング活動を監視するには、標準 Data 360 レポートを作成して、クレジットカードや電話番号などの機密データが LLM プロンプトで適切にマスキングされていることを確認します。次の手順は、Data 360 レポートを作成する手順を示しています。

Data 360でデータを表示するには、事前にEinstein生成AIデータ収集を有効にする必要があります。

  1. Data Cloud の [レポート] タブで、[レポート] をクリックします。
  2. Data Cloud レポートカテゴリで、GenAIGatewayRequest レポートを選択します。このレポートでは、生成 AI 要求データモデルオブジェクト (DMO) が使用されます。
  3. [Start Report (レポートを開始)] をクリックします。
  4. レポートに列を追加します。

    追加する列のリストを次に示します。

    • タイムスタンプ
    • モデル
    • # promptTokens
    • 応答画面
    • MaskedPrompt
  5. レポートを実行します。レポートには、データと対応するマスクされたテキストを含むすべてのプロンプトが表示されます。

有害性スコアの確認

標準 Data 360 レポートを作成して、大規模言語モデル (LLM) で生成された回答の毒性スコアを確認します。また、事前作成済みダッシュボードとレポートを使用して、有害性のトレンドを確認することもできます。

必要なエディション

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。

Einstein Generative AI Audit and Feedback Data Reportsパッケージがインストールされている必要があります。

  1. Data Cloud の [レポート] タブで、[レポート]、[新規レポート] の順にクリックします。
  2. Data Cloud レポートカテゴリで、[GenAIGatewayResponse with GenAIContentCategory] レポートを選択します。
  3. [Start Report (レポートを開始)] をクリックします。
  4. レポートに列を追加します。追加する列のリストを次に示します。
    • タイムスタンプ
    • ResponseText
    • DetectorType
    • カテゴリ
    • 値
  5. [検索条件] パネルを選択します。フィールドで ［Detector Type］ を選択し、演算子で ［Equals］ を選択し、値で ［toxicity］ を選択します。
  6. レポートを実行します。

レポートには、各回答とその有害性スコアが表示されます。

メモ isToxicityDetected フィールドが true の場合、コンテンツに有害な表現が含まれていることの確度が高くなります。ただし、isToxicityDetected フィールドが false の場合は、必ずしも有害性がないという意味ではなく、モデルによってコンテンツの有害性が検出されなかったという意味です。モデルは 0 ～ 1 のスコアを提供するようにトレーニングされます。
  • 安全カテゴリのスコアの範囲は 0 ～ 1 で、1 が最も安全です。0.5 ～ 1 の安全スコアは安全とみなされます。
  • 他のすべてのカテゴリのスコアは、各カテゴリの有害性を示します。範囲は 0 ～ 1 で、1 が最も有害性が高くなります。0.5 以上の有害性スコアは、そのカテゴリで有害とみなされます。

監査履歴

Salesforce 組織での生成 AI の使用を追跡し、AI の使用がセキュリティ、プライバシー、規制、AI ガバナンスポリシーに準拠していることを確認します。

必要なエディション

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。

生成 AI 監査データ (監査履歴とも呼ばれる) には、データ マスキングや有害性スコアなどの Einstein Trust Layer 機能に関するデータが含まれます。

監査履歴とフィードバックデータはData 360に保存されます。 Data 360レポートを使用して、Einstein Trust Layerが機密データを外部のLLM(大規模言語モデル)に公開されないように保護する方法について説明します。Einstein Trust Layer は、LLM によって生成された応答の安全性と正確性も検証します。たとえば、組織でデータマスキングが有効になっている場合、生成 AI データには、外部 LLM に送信されたマスクされたプロンプトテキストが含まれます。同様に、LLM によって生成された応答と、ユーザーに提供された完全なマスクされていない応答も表示できます。

Data 360に保存されているデータにアクセスするには、Einstein生成AIデータ収集およびストレージを有効にして、レポート パッケージをインストールする必要があります。

AI プロジェクトのリスク評価の実施

AI ソリューションでデータを使用するリスクを特定し、顧客データの安全を確保するためのガードレールを設定します。

プロンプトで顧客データを使用すると、モデルからの応答が向上します。ただし、プロンプトにビジネスデータを含めると、会社がリスクにさらされることになります。データを慎重に扱っていない場合、データ漏洩、規制の問題、評判の低下が発生する可能性があります。

AI プロジェクトで必要なデータを特定したら、その顧客データとビジネスデータのセキュリティを維持するように設計されたリスク軽減戦略を確立できます。

  1. プロジェクト関係者と協力して、プロジェクトデータを使用してこれらの各リスク種別の悪影響の可能性を特定します。Trailhead の [Plan Your Trust Strategy] 単元を使用して、主要な関係者と共有するためのリスク プロファイルと軽減戦略を作成できます。
  2. プロジェクトが法的および倫理的なリスクを軽減するのに役立つガードレールを特定します。これらのガードレールの多くは、Einstein Trust Layer でカバーされます。AI ガードレールには次のものが含まれます。
    1. セキュリティガードレール: 安全なデータ取得とは、エンドユーザーがアクセスできるデータのみがプロンプトで使用されることを意味します。データマスキングでは、機密データがプレースホルダーデータに置き換えられるため、モデルにマスクされたデータが表示されることはありません。データ保持ポリシーがゼロの場合、応答の生成後にデータがモデルに保存されません。
    2. テクニカルガードレール: プロンプト防御は、プロンプトインジェクション攻撃や脱獄からデータを保護します。
    3. 倫理的なガードレール: 有害性とバイアスの検出により、プロンプトと応答で有害な言語が特定されます。
  3. 潜在的なリスク領域と、リスクを軽減するためにシステムで使用される特定のガードレールのリストを作成します。
  4. 最も重要なリスクに最初に取り組むように、リスク軽減戦略に優先順位を付けます。

Einstein Trust Layer: Design for Trust

Einstein Trust Layerは、データ プライバシーを保護し、AIの精度を高め、Salesforceエコシステム全体でAIの責任ある使用を促進するために設計された機能、プロセス、ポリシーのコレクションです。

必要なエディション

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。

Einstein Trust Layerのしくみを理解するために、Trust Layerを介したデータ フローを確認し、ジャーニーの各部分を詳しく見ていきましょう。

  • プロンプト形式のデータは、CRMアプリケーションからEinstein Trust Layerを経由して、プロンプト ジャーニーと呼ばれる大規模言語モデル(LLM)に転送されます。
  • LLM はプロンプトを使用して応答を生成します。これを応答生成と呼びます。
  • 生成された応答は、Einstein Trust Layerを通過してCRMアプリケーションに戻り、応答ジャーニーと呼ばれます。
メモ Einstein Trust Layer機能は、生成AIおよびAgentforce機能にのみ適用されます。

プロンプトジャーニー

LLM から応答を生成するには、応答にプロンプトを指定する必要があります。プロンプトは任意の CRM アプリケーションから取得できます。プロンプトビルダーでプロンプトを作成し、Apex またはフローから呼び出すことができます。

安全なデータ取得とグラウンディング

Trust Layer の最初のステップは、安全なデータの取得です。LLM がより関連性の高いパーソナライズされた応答を生成するには、CRM データから追加のコンテキストが必要です。プロンプトにコンテキストを追加するこのプロセスをグラウンディングと呼びます。プロンプトは、CRM データとの差し込み項目を使用してグラウンディングできます。CRM データには、レコード項目、フロー、Apex、Data 360 DMO、関連リストなどがあります。

安全なデータ取得とは、実行ユーザーがアクセスできるデータのみでプロンプトをグラウンディングすることです。

データ取得プロセスでは、Salesforce の既存のアクセス制御と権限が適用されます。

  • プロンプトをグラウンディングするためのデータ取得は、プロンプトを実行するユーザーの権限に基づきます。
  • プロンプトをグラウンディングするためのデータ取得では、CRM インスタンスからデータをグラウンディングするときに、ユーザー権限と項目レベルセキュリティに関するすべての標準の Salesforce ロールベースの制御が保持されます。

グラウンディングは実行時に行われ、ユーザーのアクセス権によって異なるため、グラウンディングは動的です。

LLM のデータマスキング

Einstein Trust Layer ポリシーには、機密データが検出されてマスキングされるデータ マスキングが含まれます。機密データは、次の 2 つの方法で識別されます。

  • パターンベース: パターンとコンテキストを使用して、プロンプトテキスト内の機密データを識別します。具体的には、正規表現 (正規表現) パターンとコンテキストワードを使用します。また、人名や会社名など、パターンが定義されていないデータを識別するためにトレーニングされた機械学習モデルも使用します。
  • 項目ベース: Shield Platform Encryptionまたはデータ分類を使用して分類された項目のメタデータを使用して、機密項目を識別します。これにより、組織のデータに適用済みの分類が LLM データマスキングに拡張されます。

識別されたデータはプレースホルダーテキストでマスキングされ、外部モデルに公開されないようにします。Einstein Trust Layer は、元のエンティティとそれぞれのプレースホルダー間のリレーションを一時的に保存します。このリレーションは、生成された応答のデータをマスク解除するために後で使用されます。

重要 LLM のデータマスキングはエージェントで無効になっています。「データマスキングとエージェント」を参照してください。Einstein Service Replies などの組み込みの生成 AI 機能では、Einstein 作業概要データ マスキングが使用可能で、Einstein Trust Layer 設定で設定できます。

プロンプトの防御

LLM が意図しないものや有害なものを生成する可能性を減らすために、プロンプトビルダーとプロンプトテンプレート Connect API ではシステムポリシーを使用します。システム ポリシーは、ユーザとの Trust を構築するための特定の動作に関する LLM への指示のセットです。たとえば、LLM にコンテンツに対処したり、情報のない回答を生成したりしないように指示できます。システムポリシーは、脱獄攻撃やプロンプトインジェクション攻撃から防御する 1 つの方法です。

応答の生成

プロンプトが完全にハイドレートされて保護されると、LLM ゲートウェイを介して送信できるようになります。ゲートウェイは、さまざまなモデルプロバイダーとのやりとりを管理し、複数の LLM と通信するための統合された安全な方法を表します。ゲートウェイとモデルプロバイダーは TLS 暗号化を使用して、転送中のデータが保護されるようにします。

Salesforce によって作成または調整されたモデルは、Salesforce Trust 境界でホストされます。OpenAIなどのサード パーティ プロバイダーによって作成および管理される外部モデルは、共有Trust境界内にあります。作成および管理するモデルは、インフラストラクチャでホストされます。

OpenAI や Azure OpenAI などの外部パートナーモデルプロバイダーとゼロデータ保持ポリシーを実施しています。このポリシーでは、Salesforce から LLM に送信されたデータは保持されず、応答が Salesforce に返送された後に削除されます。

対応ジャーニー

毒性検出

回答の毒性検出: 生成された回答が毒性についてスキャンされます。検出プロセスには、有害または不適切なコンテンツを含む応答の確度を反映する毒性信頼性スコアが含まれます。毒性スコアとカテゴリは Data 360 に保存されます。

データのマスク解除

プロンプトジャーニー中にデータをマスキングするために作成したプレースホルダーが実際のデータに置き換えられました。元のエンティティとそれぞれのプレースホルダー間のリレーションは、応答を戻すために使用されます。これにより、応答が返信されたときに便利で有意義なものになります。

重要 LLM のデータマスキングはエージェントで無効になっています。「データマスキングとエージェント」を参照してください。Einstein Service Replies などの組み込みの生成 AI 機能では、Einstein 作業概要データ マスキングが使用可能で、Einstein Trust Layer 設定で設定できます。

引用

関連する場合は、応答に引用を含めることができます。引用では、AI で生成された応答を、応答の生成に使用された元のソースにリンクします。引用を使用して、応答を生成してソースデータの有効性を検証するために大規模言語モデル (LLM) で使用された情報を確認します。引用は、生成された応答に不正確な内容や事実に基づかない情報が含まれる可能性を明らかにするのに役立ち、AI ツールの使用に対する信頼性を高めます。

フィードバックと監査

Salesforce で回答が提示されたら、回答を承諾、変更、または却下できます。明示的なフィードバックを提供することもできます。回答に対する明示的なフィードバックは、監査およびフィードバックデータ (監査履歴) の一部として取得され、Data 360 に保存されます。AI 機能によっては、回答に対する暗黙的なアクションも Data 360 に取得されて保存される可能性があります。

監査履歴には、元のプロンプト、マスクされたプロンプト、有害性検出中に記録されたスコア、LLM からの元の出力、マスク解除された出力も含まれます。

監査およびフィードバックデータは Data 360 のインスタンスに保存されます。データを Data 360 のインスタンスに保存する期間は自分で制御できます。また、監査およびフィードバックデータは、コンプライアンスの目的で 30 日間 Salesforce によって保存されます。

有害なコンテンツ

有害なコンテンツとは、個人やコミュニティに悪影響を及ぼす可能性がある情報を指します。生成 AI モデルのコンテキストでは、有害なコンテンツとは、メンタルヘルス、行動、または健康に悪影響を及ぼすプロンプトまたは応答のデータを指します。有害なコンテンツには、ヘイトや暴力などの有害なコンテンツや、不当または差別的なパターンのコンテンツが含まれる可能性があります。

大規模言語モデル (LLM) では、次のような理由で有害なコンテンツが誤って生成される可能性があります。

  • プロンプトの影響: プロンプトの言語がモデルの出力に直接影響します。たとえば、プロンプトに攻撃的な語句や有害な語句が含まれている場合、モデルの応答に同様の語句が組み込まれる可能性があります。
  • トレーニングデータ: LLM は、バイアスのかかったコンテンツや有害なコンテンツが含まれる可能性がある大量のデータから学習します。トレーニングデータに有害な言語が含まれていると、モデルが意図せずに再現してしまう可能性があります。
  • コンテキストパターン: LLM はデータの統計パターンに基づいて応答を生成します。有害な言語が同様のコンテキストで頻繁に出現する場合、モデルがそれらのパターンを再現する可能性があります。
  • 学習の微調整と移行: 特定のタスクの LLM を微調整すると、バイアスが発生する可能性があります。関連しないドメインからの転移学習もコンテンツの生成に影響する可能性があります。

Einstein Trust Layer は、機械学習モデルを使用して、生成 AI アプリケーションおよび機能に含まれる有害なコンテンツを識別します。

プロンプトの挿入

プロンプトインジェクションは、LLM が意図しない動作をさせようとする試みです。ハッカーは、システムポリシーを上書きしたり、LLM を操作して意図しない動作をさせようとするプロンプトを作成できます。

Salesforce には、悪意のある攻撃によるリスクを軽減するのに役立つ迅速な防御メカニズムが用意されています。

プロンプトインジェクション検出をシステムポリシーと共に使用すると、プロンプト防御の詳細なアプローチが可能になります。プロンプト インジェクション防御は、すべてのユーザー プロンプトに一貫して適用され、Agentforceおよび組み込みAIアプリケーションのセキュリティを強化します。

  • ハルシネーションを制限し、LLM が意図しない出力や有害な出力を行う可能性を減らすのに役立つ組み込みシステムポリシーがあります。
  • プロンプトの挿入検出は、LLM を操作して意図しない操作を試みる悪意のある攻撃を検出するのに役立ちます。

Einstein 生成 AI & 信頼

新しいテクノロジーでイノベーションを起こすときには、データの安全を確保することが重要です。Einstein生成AIはそのNo.1の価値としてTrustを保持し、データのセキュリティを確保すると同時に、正確で安全なエクスペリエンスの構築に努めています。

Einstein生成AIとデータ

Salesforce では、Trust が最大の価値です。データのセキュリティを確保するため、Salesforce は OpenAI などの大規模言語モデル (LLM) プロバイダーと契約しています。これらの契約により、組織は LLM プロバイダーが非公開データを保持することなく生成 AI 機能を使用できます。

信頼できる生成 AI

SalesforceのEinstein生成AIソリューションは、信頼できる生成AIに関する5つの原則に基づいて設計、開発、提供されます。

  • 精度: 可能な限り、説明とソースを使用してモデル応答をバックアップします。ほとんどの使用事例でエンドユーザーと共有する前に、人間がモデルの応答を確認することをお勧めします。
  • 安全性: 業界をリードする検出および緩和技術により、製品に使用されているモデルからのバイアス、毒性、有害な応答を検出して軽減します。
  • 透明性: 当社のモデルと機能は、可能な限りデータの証明を尊重し、お客様のデータに基づきます。
  • エンパワーメント: デルの製品によって従業員の能力が向上し、作業の効率と目的が達成されると考えています。
  • Sustainability (持続可能性): 精度を優先し、カーボンフットプリントを削減する適切なサイズのモデルの構築に努めています。

生成 AI 応答の確認

生成 AI は、より創造的で生産的になり、よりスマートなビジネス上の意思決定を行うのに役立つツールです。この技術は人間の判断に代わるものではありません。LLM で生成された応答を顧客と共有する場合、最終的にその責任はユーザーにあります。テキストが人間によって生成されたものか、LLM によって生成されたものかに関係なく、顧客はテキストを組織のブランドに関連付けて、意思決定に使用します。そのため、LLM で生成された外部利用者向けの回答が正確で役立ち、会社の価値観、姿勢、口調と一致していることを確認することが重要です。

エンドユーザーが外部利用者向けに生成された回答を確認するときは、コンテンツの正確性と安全性に焦点を絞ります。

  • 正確性: 生成 AI は、事実や既存のソースに基づかない応答を「幻覚」で改ざんする可能性があります。回答を公開する前に、主要な詳細が正しいことを確認します。たとえば、カスタマー サービスの提案は既存の最新のKnowledge記事に基づいていますか。
  • バイアスと毒性: AI は人間が作成し、人間が作成したデータに基づいてトレーニングされるため、歴史的に疎外されてきたグループに対するバイアスが含まれることもあります。まれに、一部の応答に有害な表現が含まれることがあります。回答をチェックして、顧客に適切であることを確認します。

回答があなたの標準または会社のビジネスニーズを満たしていない場合は、使用する必要はありません。一部のソリューションでは、エンドユーザーが回答を直接編集できます。編集できない場合は、最初から別の回答を生成することをお勧めします。

    LLM のデータマスキングはエージェントで無効になっています。「データマスキングとエージェント」を参照してください。Einstein Service Replies などの組み込みの生成 AI 機能では、Einstein 作業概要データ マスキングが使用可能で、Einstein Trust Layer 設定で設定できます。

[Answer Questions with Knowledge (ナレッジを使用して質問に回答)] 標準アクションでは現在、応答の最後にソース URL を表示するプロンプトベースの引用がサポートされています。生成された応答に含めるには、エージェントのソースを表示するオプションを有効にする必要があります。

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。
必要なユーザー権限

  「アプリケーションのカスタマイズ」

応答で引用を表示するには、エージェントを有効化する必要があります。

  1. [設定] から、[クイック検索] ボックスに「エージェント」と入力し、[Agentforce Agents] を選択します。
  2. Agentforce Builder でエージェントを起動し、サイドバーから [データ] を選択します
  3. [ソースを表示] チェックボックスをオンにします。外部顧客とやりとりするエージェントに割り当てられるKnowledgeのデータライブラリの場合、Salesforce Knowledgeドメインの URL を入力する必要があります。特定のKnowledgeメイン URL を含めない場合、デフォルトで公開されている URL になります。Knowledgeドメインについての詳細を確認してください。
  4. 作業内容を保存します。

実行時に、回答の末尾に、回答の生成に使用された元のソースの番号付きクリック可能リストとして引用が表示されます。インライン番号は、リスト内のソース番号を参照します。引用に画像が含まれている場合、画像へのクリック可能なリンクが応答に含まれます。

有害検出

Einstein Trust Layer は機械学習 (ML) モデルを使用して、プロンプトと応答内の有害なコンテンツを識別し、フラグを設定します。

必要なエディション

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。

AI アプリケーションからの顧客向け出力は、会社のブランドと話し方を表します。AI によって有害なコンテンツが生成され、会社の評判が損なわれる可能性があります。応答の有害性もプロンプトによって影響を受ける可能性があるため、応答だけでなくプロンプトでも有害性を検出することが重要です。プロンプトの有害性は、公開チャットのやりとりやサードパーティの Web コンテンツなどの信頼できないソースから発生する可能性があります。

メモ 応答内の有害検出はデフォルトで有効になっており、変更できません。プロンプト内の有害検出 (ベータ) はデフォルトで無効になっていますが、Salesforce 組織で有効にできます。

プロンプトまたは応答で有害性が検出されると、実行時に Salesforce AI 機能に通知または警告が表示されます。たとえば、LLM から生成された応答で有害なコンテンツが検出された場合、Copilot またはプロンプトビルダーに有害警告が表示されます。

メモ 免責事項: 毒性警告は、一部の AI 機能では使用できません。

プロンプトビルダーでの有害性警告

重要 有害検出モデルは内部テストで有効であることが示されていますが、どのモデルも 100% の精度を保証することはできないことに注意してください。さらに、地域間および多国籍の使用事例は、特定のデータパターンを検出する機能に影響する可能性があります。Salesforce は信頼を優先事項として、モデルの継続的な評価と調整に取り組んでいます。

有害性カテゴリ

Einstein 有害性検出モデルでは、次のカテゴリが認識されます。

カテゴリ コンテンツのタイプ
暴力 人、動物、財産に物理的危害を加えることを意図した行動を描写、参照、扇動するコンテンツ
性的 合意の上および非合意の性的コンテンツ、違法および合法的な性的行為、性的に挑発的で相手の気を引こうとするコンテンツなど、性的な言語、画像、テーマを含む素材、行動、言語を描写、参照、または要求するコンテンツ
冒涜 扇動的、攻撃的、卑猥、下品、不遜な言葉、仕草、暴言を含むコンテンツ
憎悪 アイデンティティまたはその他の際立った個人的な特性に基づいて、個人またはグループに心理的な損害を与えることを意図した行動や言葉を描写、参照、扇動するコンテンツ
物理 違法な物質、非処方薬、および摂取すると生理的または心理的な影響を影響を及ぼすその他の物質、または身体的な危害、自傷行為、死を意図する行為を描写、参照、奨励したり、使用、取得、配布を可能にしたりするコンテンツ

有害性スコアリング

有害コンテンツの各カテゴリは、テキスト内のそのような有害言語の可能性を示すために評価されます。さらに、Einstein Trust Layer では、検出されたすべてのカテゴリの組み合わせを反映する全体的な有害性スコアが示されます。

スコアの範囲は 0 ～ 1 で、1 が最も有害です。スコアは監査履歴に記録され、Data 360に保存されます。 Trust Layerの事前作成済みレポートとダッシュボードでは、機能と時間の有害性トレンドが視覚化されます。Data 360 でカスタムレポートを作成することもできます。
