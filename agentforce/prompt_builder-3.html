プロンプトビルダーの制限

特定の動作と結果に影響するプロンプトテンプレートの機能制限について説明します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

監査履歴がサポートされていない

プロンプトテンプレートの作成または更新は、[設定] 監査履歴では追跡されません。

新しいカスタムオブジェクトとカスタム項目が作成後にすぐに使用可能にならない

カスタムオブジェクトまたはカスタム項目を作成すると、プロンプトビルダーですぐに使用できなくなります。新しいカスタムオブジェクトまたは項目をすぐに使用するには、ログアウトしてから再度ログインします。

名前のないレコードがレコードセレクターに表示されない

暗号化された名前項目または欠落している名前項目を含むプロンプトテンプレートはプレビューできません。テストレコードセレクターでそのレコードを使用できません。

サポートされるオブジェクト種別

Salesforce では、さまざまなデータ型を表す多くのオブジェクトまたは項目サフィックスがサポートされています。プロンプトビルダーでは、次の種類のオブジェクトと項目のみがリソースとしてサポートされます。

  • UI API でサポートされるオブジェクト。完全なリストについては、「All Supported Objects (サポートされるすべてのオブジェクト)」を参照してください。
    重要 KnowledgeArticleVersion オブジェクトは、Flex Template 種別でのみサポートされます。
  • 標準オブジェクト (サフィックスなし)
  • 標準項目 (サフィックスなし)
  • カスタムオブジェクト (__c)
  • カスタム項目 (__c)
  • 履歴 (__history)
  • 関連リスト (__r)

オブジェクトプレビューの制限事項

[名前] 項目がないオブジェクトや、[名前] 項目が暗号化されているオブジェクトはプレビューできません。

項目生成テンプレートの制限事項

ナレッジエンティティ（__kav）のリッチテキストエリアには項目生成プロンプトテンプレートを使用できません。Knowledgeエンティティのリッチテキストエリアにプロンプトビルダーダーテンプレートを入力するには、Flex プロンプトテンプレート、フロー、または Apex を使用します。

Flex テンプレートの制限事項

Flex テンプレートに関連するメタデータを含め、Flex テンプレートからメタデータをインポートまたはエクスポートすることはできません。次に例を示します。

  • Flex テンプレートを参照する Apex クラス
  • Flex テンプレートを参照するフロー
  • Flex 関連のアーティファクトを組織間で移動するための変更セット

フローまたは Apex クラスを使用する Flex テンプレートを削除するには、まずテンプレートのすべてのバージョンのフローと Apex リソースを削除します。次に、プロンプトテンプレートを参照するフローと Apex クラスを削除します。次に、Flex テンプレートを削除します。

Einstein Search の制限事項

プロンプトで Einstein Search 取得機能を使用している場合、変更セットには取得機能や検索インデックス メタデータは含まれません。取得元をリリースする前に、取得先組織で取得元を手動で作成する必要があります。このルールは、変更セットとメタデータ API のリリースに適用されます。

グローバル言語

Einstein の [設定] で [グローバル言語サポート] をオンにすると、Salesforce サポート言語、エンドユーザー言語、プラットフォーム専用言語を有効にできます。ただし、グローバル言語を使用する場合、データ マスキングや有害性スコアリングなどの Einstein Trust Layer の一部の機能が使用できず、応答がビジネスに適した言い回しでサポート言語よりも最適化されない場合があります。

一般に、LLM では特定の応答言語が正式にサポートされておらず、一部の LLM はすべてのグローバル言語で適切に機能しない可能性があります。適切にローカライズされた応答を提供するために、選択したモデルを応答言語でテストしてください。

オブジェクトベースの型への変更の管理

プロンプトビルダーでオブジェクトベースのカスタム Lightning 種別を作成し、プロンプトテンプレートの出力を構造化します。これらの種別を編集する場合、インテグレーションの中断を避けるために特定の項目プロパティを変更することはできません。項目の名前変更、データ型の変更、項目の削除、省略可能な項目の必須化などの変更を行うと、インテグレーションや参照が失敗する可能性があります。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

変更の中断

スキーマ参照の整合性を保護するために、既存の項目を次のように変更することはできません。

  • データ型。インテグレーションでは特定のデータ形式が使用されるため、たとえばテキストから数値にデータ型を変更することはできません。
  • 削除。インテグレーションで参照されている既存の項目は削除できません。
  • フィールド名。外部参照は特定の API 参照名に依存するため、既存の項目の名前は変更できません。
  • 必須。既存の省略可能な項目を必須にすることはできません。項目を必須にすると、その項目の値を提供しない従来のデータやインテグレーションが壊れる可能性があります。

安全な変更

連動関係を中断することなく、これらの更新を安全に行うことができます。

  • 新しいフィールドを追加します。既存のカスタム Lightning タイプに新しいフィールドを追加できます。下位互換性を確保するため、新しい項目はデフォルトで省略可能になり、[必須] チェックボックスは無効になっています。
  • 必須フィールドを省略可能にします。[必須] を選択解除して、フィールドの制限を緩和できます。
  • 説明を更新します。わかりやすくするために説明を変更できます。

  • プロンプトテンプレートの有効化と無効化
    プロンプトテンプレートの有効化と無効化を使用して、ユーザーがアクセスできるバージョンを細かく制御します。
  • プロンプトテンプレートの複数バージョンの使用
    プロンプトビルダーで複数のバージョンのプロンプトテンプレートを作成して使用し、プロンプトの構造とその応答を比較します。
  • プロンプトテンプレートでの LLM 設定の変更
    プロンプトビルダーで出力を生成するための LLM 設定を選択し、必要に応じて変更します。

上書き可能な標準プロンプトテンプレートは、すべてのプロンプトテンプレートのリストの [カテゴリ] 列に表示されます。プロンプトテンプレートワークスペースの [別名で保存] ボタンを使用して、上書き可能なテンプレートの新しいバージョンを作成できます。標準テンプレートを上書きできない場合は、代わりにコピーしてカスタムテンプレートを作成できます。

標準プロンプトテンプレートのカスタムバージョンを有効化すると、標準テンプレートのリストで使用可能になり、標準バージョンと同じ名前が使用されます。有効なカスタムバージョンを無効化すると、有効化するバージョンを選択するまで有効なバージョンはありません。

  2. バージョンを有効化するには、[バージョン] メニューから選択し、[有効化] をクリックします。

パフォーマンスインサイトを使用したプロンプトの評価

プロンプトビルダーでモデル生成評価指標と関連インサイトを直接分析し、プロンプトテンプレートをテストするときにパフォーマンス、トークンの使用状況、マスクされたデータを把握します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

プロンプトビルダーには、プロンプトの実行方法、トークンの計算方法、バックグラウンドで実行される処理を表示する一元的なパフォーマンスインサイトパネルが含まれます。

このパネルにはプレビュー設定と共にアクセスでき、主要なパフォーマンスデータを 1 か所に統合できます。

パフォーマンスインサイトパネルの概要

このパネルには、プロンプトのプレビューと生成に関連付けられたパフォーマンス総計値が表示されます。[プレビュー] を実行すると、次を表示できます。

  • 応答時間 (遅延)
  • トークン使用量
  • マスクされた値

応答時間 (遅延)

[応答時間] には、生成の完了に必要な合計時間が表示されます。ここでは、次の内容について説明します。

  • プロンプトメタデータの取得
  • 必要なデータ (オブジェクトやフローなど) の取得
  • 実際のデータを使用した差し込み項目のハイドレート
  • 集計 (プロンプトがモデルのコンテキストウィンドウを超える場合)
  • 機密項目のマスキング
  • 応答の生成
  • その他 (上記のステップ以外の軽微な処理時間を考慮する)

トークン使用量

[Token Usage (トークン使用量)] には、生成中に使用されたトークンの合計数が表示されます。トークン使用量は次のカテゴリに分類されます。

  • Total Tokens (合計トークン): 入力トークンと出力トークン
  • 入力トークン: モデルに送信されるすべてのコンテンツ
  • 出力トークン: モデルで生成された応答
重要 個々の入力コンポーネントは近似値として表示されます。合計トークン数は LLM ゲートウェイから取得され、請求で計算された値が反映されます。プロンプトが [プレビュー] 外で実行されると、トークン数は請求に影響します。請求は、入力と出力を含むトークンの使用量の合計に基づいて計算されます。

マスクされた値

マスクされたデータは、[パフォーマンスインサイト] パネル内に表示されます。マスキングされた項目のリストを表示し、マスキングされたデータがモデルに送信されていないことを確認できます。

    フロー、Apex、取得などの新しいアクションをプロンプトテンプレートに追加します。

    別のプロンプトテンプレート内にアクションとしてプロンプトテンプレートを追加して、ロジックを再利用し、応答の生成方法を標準化します。あるプロンプトテンプレートを別のプロンプトテンプレートから呼び出して、より一貫性のあるモジュール化されたプロンプトワークフローを作成します。
  • プロンプトテンプレートでのアクションの設定
    プロンプトビルダーの既存のアクション (フロー、Apex、取得など) を変更して、プロンプトに直接追加します。
  • プロンプトテンプレートの修正
    プロンプトテンプレートの完成は反復プロセスです。プロンプトテンプレートを修正し、解決済みのプロンプトと応答を再生成して、その更新された応答に基づいてさらに修正します。プロンプトビルダーでプロンプトテンプレートを実行するたびに、LLM への一意のコールを作成します。つまり、同じプロンプトを解決すると、異なる応答が生成される可能性があります。テンプレートを以前に実行した場合でも、すべての応答の正確性を確認してください。
  • 解決済みプロンプトのプレビュー
    ワークスペースの [解決済みプロンプト] セクションで、実際の Salesforce レコードデータに基づいてグラウンディングされたプロンプトを確認できます。
  • 生成された応答のプレビュー
    ワークスペースの [応答] セクションでは、実際の Salesforce レコードデータに基づく応答を確認できます。
  • 生成された応答形式の設定
    生成される応答の形式を制御するには、[JSON] または [HTML] を選択します。
  • プロンプトテンプレートを確認する解決の有効化
    解決を有効にすると、プロンプトテンプレートから生成された解決済みプロンプトを確認できます。プロンプトビルダーは、プロンプト解決というプロセスを通じて、プロンプトテンプレートの各差し込み項目を、選択したレコードに関連する実際の CRM データで置き換えます。
  • 回答の品質の評価
    生成された応答をプレビューするときに、応答がプロンプトの目標にどの程度適合しているかを評価します。回答が実際に正確であり、有害なコンテンツやバイアスが含まれていないことを確認します。
  • パフォーマンスインサイトを使用したプロンプトの評価
    プロンプトビルダーでモデル生成評価指標と関連インサイトを直接分析し、プロンプトテンプレートをテストするときにパフォーマンス、トークンの使用状況、マスクされたデータを把握します。
  • プロンプト応答での有害なコンテンツ通知
    プロンプトビルダーで、プロンプトテンプレートの応答に有害なコンテンツが含まれる可能性がある場合に警告する方法について説明します。
  • 大きなプロンプトの操作
    プロンプトが大きすぎてモデルで使用することができない場合、OpenAI モデル を使用して [解決] パネルに概要が自動的に生成されます。サマリープロンプトを使用するか、小さいプロンプトを作成するかを選択できます。

プロンプトテンプレートの言語選択の設定

プロンプトテンプレートで生成できる言語と、言語の選択方法を管理します。ユーザーおよび組織の設定に基づいてシステム管理言語の選択を設定するか、LLM が応答言語をプロンプトの指示から直接解釈する命令駆動型言語の選択を有効にします。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

プロンプトビルダーで、出力を生成するためにテンプレートでサポートされる言語を選択し、応答言語の決定方法を制御します。使用可能な言語を管理して、テンプレートで品質出力のテストを行った言語のみで応答が生成されるようにし、組織でサポートまたは流暢に使用できるようにします。

[テンプレート設定] の [応答] セクションで、[自動] 切り替えを使用して言語選択の動作を制御します。システム管理言語の選択の切り替えを有効にするか、または無効にして、LLM がプロンプトの指示から直接言語を解釈できるようにします。

自動言語モード (デフォルト)

自動モードでは、プラットフォームは定義済みのロジックに基づいて応答言語を自動的に判別します。

テンプレートの実行時に言語を指定しない場合、プロンプトビルダーは次の順序に基づいて応答言語を選択します。

  1. Apex の outputLanguage パラメータで設定された応答言語または REST API (提供され、プロンプト テンプレートでサポートされている場合) を使用します。
  2. テンプレートで提供されている outputLanguage がサポートされていない場合、プロンプトテンプレートでサポートされる場合は実行ユーザーの言語を使用します。
  3. テンプレートでユーザーの言語がサポートされていない場合は、組織のデフォルト言語を使用します (サポートされている場合)。
  4. テンプレートで組織のデフォルト言語がサポートされていない場合、サポートされる場合は英語を使用します。
  5. プロンプトテンプレートでこれらの言語がサポートされていない場合、プロンプトビルダーはエラーを返します。

自動モードを使用する場合:

  • ユーザーと地域全体で一貫性を維持します。
  • 言語コンプライアンスを適用します。
  • 組織でサポートされる言語で回答を調整します。
  • 使用できる言語制限を適用します。

応答言語モードを開く

Open Response Language は、システムで管理されるルールではなく、自然言語の指示を使用して応答言語を決定する設定です。[自動] 切り替えを無効にすると、大規模言語モデル (LLM) が言語命令を直接解釈するように言語選択の制約が削除されます。

仕組み:

  • 言語の選択は強制されなくなりました。
  • LLM は、プロンプトの指示と提供されたコンテキストに基づいて応答言語を決定します。
  • 「スペイン語で応答する」、「イギリス英語を使用する」、「正式な口調でヒンズー語で記述する」など、柔軟で構造化されていない指示を使用できます。
  • モデルでは、厳格なシステム制約なしで、インテントが解釈され、それに応じて応答が生成されます。

Open Response Language モードを使用するケース:

  • 要求ごとの動的な言語制御が必要です。
  • 使用事例には、多言語または世界中の利用者が含まれます。
  • システムの適用ではなく、プロンプト駆動型の動作が必要である。

考慮事項

  • [自動] モードが無効になっている場合、許可されている言語は適用されません。
  • 応答品質は、プロンプトで言語の指示をどの程度明確に記述するかによって異なります。
  • 結果は、LLM の言語または方言の理解度によって異なる場合があります。
  • 言語ガバナンスが必要な厳格なコンプライアンス環境や規制された環境では、自動モードを無効にしないでください。
  • 実行時に Open Response Language を使用してプロンプトに提供された outputLanguage 値は無視されます。

言語サポート

標準および新しいカスタムテンプレートでは、デフォルト言語がサポートされます。他の言語をサポートするには、Einstein 設定で [グローバル言語サポート] を有効にします。ただし、グローバル言語を使用する場合、データ マスキングや有害性スコアリングなどの Einstein Trust Layer の一部の機能が使用できないことがあり、システムが応答をビジネスに適した言い回しに最適化するとは限りません。

    [Answer Questions with Knowledge (ナレッジを使用して質問に回答)] プロンプト テンプレートをテストするには、クエリと取得者 ID が必要です。 クエリは、ユーザーが尋ねた質問です。テスト目的で、データソースに関連する任意のクエリを入力できます。取得者は、AIモデル(旧称Einstein Studio)ですでに作成および有効化されています。取得者の ID または名前を取得するには、[AI モデル] で取得者の設定に移動します。「Manage Retrievers」を参照してください

    メモ 独自の手順をプロンプト テンプレートに追加したり、別の取得者を含めたりする場合、結果は標準の [Answer Questions with Knowledge (ナレッジを使用して質問に回答)] プロンプト テンプレートを使用した場合とは異なります。これは、Agentforceデータ ライブラリを使用するAIエージェントと生成AI機能に適用されます。
  3. テンプレートと Einstein の応答に問題がなければ、［Save & Activate］ をクリックします。有効になると、カスタマイズされたプロンプトテンプレートがユーザーがエージェントに質問するときに使用されます。

標準プロンプトテンプレート

標準プロンプトテンプレートを一般的な使用事例の開始点として使用します。標準プロンプトテンプレートをコピーしてカスタマイズできます。一部の標準プロンプトテンプレートを上書きして、標準バージョンの代わりに機能するバージョンを作成できます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

プロンプトテンプレートは、パイロット、カスタム、標準に分類されます。パイロットテンプレートは、プロンプトビルダーのパイロットプログラムに参加した少数のユーザーのみが使用できます。パイロットテンプレートは使用できませんが、新しいテンプレートではそのテキストを使用できます。カスタムテンプレートは、[新規プロンプトテンプレート] ボタンを使用して最初から作成するテンプレートです。「Create a Prompt Template」を参照してください。

標準テンプレートの動作をカスタマイズするには、2 つの方法があります。

  • [別名で保存] ボタンを使用して、標準テンプレートに基づくカスタムテンプレートを作成できます。
  • 標準プロンプトテンプレートが上書き可能な場合、標準バージョンの代わりに機能する追加バージョンを作成できます。元のテンプレートを含め、常に 1 つのバージョンのみが有効になります。

テンプレートはいつでも無効化および再有効化できます。標準テンプレートの元のバージョンを無効にすると、上書きも無効になります。

重要

標準のセールスメールプロンプトでは、ハードコードされたハイパーパラメーターが使用されます。このハイパーパラメーターは、[別名で保存] ボタンを使用してテンプレートを作成するときにはコピーされません。そのため、この方法で作成された新しいプロンプトテンプレートは、標準のセールスメールプロンプトテンプレートとは異なる結果や予期しない結果になる可能性があります。標準のセールス メール プロンプトに最も匹敵する結果を得るには、AIモデル(旧称Einstein Studio)を使用して、次のパラメーターを使用してモデル設定を作成します。

  • model: gpt-3.5-turbo
  • temperature: 1.0
  • frequencyPenalty: 1.0
  • presencePenalty: 0.5

プロンプトテンプレートの材料

Build Your Own プロンプト テンプレートの作成を開始すると、威圧感を感じることがあります。すべての新しいスキルと同様に、優れたプロンプトを設計するには、いくつかの実験と練習が必要です。プロンプト設計の指針として、まず有効なプロンプトテンプレートの主要なコンポーネントについて説明します。優れたレシピと同様に、これらの「材料」は連携して大規模言語モデル (LLM) が正確かつ一貫した応答を生成するのに役立ちます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

プロンプトはすべて異なります。すべてのプロンプトテンプレートにすべての要素が必要なわけではありません。

参加者

モデルの応答を送受信するユーザーを説明します。関係者を説明するときに、レコード項目、フロー、Apex などを参照する差し込み項目を使用できます。

例 
You’re a <sender.JobTitle_Merge_Field> and your
name is <sender.Name_Merge_Field> and you’re from an
organization called <sender.Company_Merge_Field>. Your
prospect is <recipient.Name_Merge_Field> from the company
<recipient.Company_Merge_Field>.

設定

応答の対象となるコミュニケーションチャネルやコンテンツの種別などのコンテキスト情報をモデルに提供します。プロンプトテンプレートの種類によって設定が決まります。たとえば、[項目生成] テンプレート種別を選択した場合、設定はレコード項目になります。

目標

モデルの応答を使用して達成したいことを説明します。ユーザーのコンテキスト、設定、過去の行動を考慮してください。差し込み項目を使用して、目標に詳細を追加できます。

例 
Encourage your contact to attend the <event.Subject_Merge_Field> event in <event.Location_Merge_Field>.

リレーション

関係者間のリレーションを説明します。また、モデルの応答が参加者にどのように関連しているかについても説明します。

例 
You are a customer service agent interacting with a customer over chat for the first time.

データ

差し込み項目を使用して、モデルに関連する CRM データを指定します。

説明

LLM に、必要なコンテンツの種類とコンテンツに含める必要があるコンテンツを指定します。命令を 3 つの引用符の境界で囲みます。これにより、LLM はプロンプトコンテキストと命令を区別できます。

例 
Instructions:
"""
Generate an introduction email to your prospect. Indirectly encourage the prospect to respond to your email by showing that you are willing to answer any questions they may have.
"""

ガイドライン

幻覚の可能性を減らすために、モデルに従う必要があるガイドラインを示します。

例 
When I ask you to generate an introduction email, you must strictly follow my instructions below.

言語

応答を生成する言語をモデルに指示します。サポートされる言語のリストについては、「プロンプトテンプレート応答でサポートされる言語」を参照してください。

スタイルとトーン

従うべきモデルのスタイルとトーンのガイドラインを示します。

例 
Use clear, concise, and straightforward language using the active voice and strictly avoiding the use of filler words and phrases and redundant language.

効果的なプロンプトの質問

これらの要素を状況に合わせて説明するために、次の質問を使用してプロンプトテンプレートの効果を高めるために必要な詳細を特定します。

  • プロンプトテンプレートの目標は何ですか? — 最初に回答の目標を宣言することで、後続のすべての質問に適切に回答できます。
  • 関係者 — 回答を送受信する参加者、参加者間のリレーション、参加者と回答間のリレーションを説明します。
  • プロンプトテンプレートと応答のコンテキストは? — モデル応答の設定、プロンプトをグラウンディングする CRM データを定義し、モデルに生成内容を指示するコマンドを追加します。
  • このプロンプトテンプレートを成功させるために必要なガードレールは? — 応答のスタイルや口調の指示などの情報を追加できます。

効果的なプロンプトテンプレートはこれらの質問に回答するため、LLM は毎回パーソナライズされた応答を生成できます。優れたプロンプトテンプレートは、さまざまな使用事例で再利用できるように拡張性も備えています。プロンプトビルダーを使用すると、これらの目標を達成するプロンプトテンプレートを簡単に設計できます。

プロンプトテンプレートの複数バージョンの使用

プロンプトビルダーで複数のバージョンのプロンプトテンプレートを作成して使用し、プロンプトの構造とその応答を比較します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition
必要なユーザー権限
プロンプトビルダーでプロンプトテンプレートを作成および管理する

「プロンプトテンプレートマネージャー」権限セット

  • プロンプトテンプレートの管理
  • Execute Prompt Templates (プロンプトテンプレートの実行)

または

「アプリケーションのカスタマイズ」権限セット

プロンプトテンプレートのドラフトをテストする場合、探している正確な応答がすぐに得られるとは限りません。多くの場合、満足のいく応答を得るには、グラウンディングデータ、LLM、テンプレートの本文テキストに微調整や編集が必要です。このため、バージョン管理が重要です。プロンプトビルダーでは、複数のバージョンのテンプレートを作成できるため、さまざまなプロンプト構造とその応答を比較しながら、ニーズに最適なプロンプトを作成できます。

  1. プロンプトビルダーのプロンプトテンプレートワークスペースから開始します。「Create a Prompt Template」を参照してください。
  2. [プロンプト] セクションでプロンプトのドラフトを作成します。作業を保存する準備ができたら、[保存] をクリックします。新しいプロンプトを初めて保存すると、そのプロンプトはプロンプトテンプレートのバージョン 1 になります。バージョン番号も URL の一部になるため、バージョンには常に URL を介して静的にアクセスできます。
  3. [プロンプト] セクションでプロンプトのドラフトを作成し続け、プロンプトの現在のバージョンへの変更をいつでも保存します。
  4. プロンプトテンプレートの別のバージョンを作成するには、[別名で保存] | 新しいバージョンとして保存] を選択します。保存されていない変更は、新しいバージョンの一部になります。プロンプトが同じプロンプトテンプレートのバージョン 2 になりました。
    重要 テンプレートバージョンを有効化すると、テンプレートバージョンは不変になります。無効化された場合でも、有効になっていたバージョンは不変のままです。このようなテンプレートを編集するには、新しいバージョンとして保存します。

    プロンプトテンプレートワークスペースの上部にあるバージョン番号には、現在画面上で編集中のプロンプトテンプレートが反映され、有効かどうかが示されます。プロンプトテンプレートの複数のバージョンが存在する場合、表示されるバージョン番号はドロップダウンメニューになり、すべてのバージョンのリスト、有効なバージョンの作成時刻、および作業する新しいバージョンを選択するオプションが表示されます。

    重要 新しいバージョンのプロンプトテンプレートが作成されても、すべてのユーザーに自動的に使用可能になるわけではありません。「Activate and Deactivate Prompt Templates」を参照してください。
  5. [別名で 保存 | テンプレートとして保存]を選択して、編集したバージョンのプロンプトテンプレートをすべて新しいプロンプトテンプレートに変換します。保存されていない変更は、新しいテンプレートの一部になります。
    重要 Flex プロンプトテンプレートでは、[新規テンプレートとして保存] オプションはサポートされていません。

プロンプトテンプレートアクションとは?

プロンプトテンプレートアクションは、プロンプトテンプレートを別のプロンプトテンプレートからコールします。

アクションとして使用した場合、参照されるプロンプトテンプレートは実行時に実行されます。入力に基づいて応答が生成され、その応答がメインプロンプトに戻ります。プロンプトテンプレートをチェーニングしてプロンプトチェーンを作成できます。各テンプレートは以前のテンプレートに基づいて構築されます。

プロンプトテンプレートをアクションとして使用する理由

プロンプトテンプレートをアクションとして使用すると、プロンプトロジックを複数のテンプレートで再利用できます。一般的な使用事例の出力を標準化し、複雑なプロンプトを小さくて扱いやすい部分に分割します。

プロンプトでのアクション出力の使用

プロンプトでプロンプトテンプレートアクションの出力を参照します。

Summarize the following response: {!Prompt_Template_Action_Output}

プロンプトが実行されると、プロンプトテンプレートアクションが実行され、その応答が最終出力の一部になります。

考慮事項

  • 有効なプロンプトテンプレートのみをアクションとして使用可能
  • プロンプトチェーンに最大 5 個のプロンプトテンプレートアクションを追加する
  • 参照されるテンプレートへの変更は、そのテンプレートを使用するすべてのテンプレートに影響します。
  • プロンプトテンプレートアクションは再利用に役立ちますが、フローや取得者などの他のアクション種別は置き換えないでください。

構造化出力を使用したモデル応答の書式設定

プロンプトビルダーの構造化された出力により、モデルで一貫した JSON または HTML 形式で応答が返されるため、ワークフロー、インテグレーション、UI 表示の信頼性が向上します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

構造化出力では、JSON または HTML を使用してモデル応答の形式を定義します。この機能を使用すると、ワークフロー、インテグレーション、または UI でデータを表示または解析するために一貫した書式設定が必要な場合に構造が提供されます。

構造化出力では、ユーザーが記述したプロンプト命令を使用する代わりに、システムレベルの命令が適用され、テンプレートレベルでメタデータが設定されます。この制御により、フローやエージェントなどのツールを使用するときの信頼性が向上します。

予想される応答形式の選択

[JSON] を選択すると、クリーンで有効な JSON を返すのに役立つ特別な命令と構文チェックが適用されます。[HTML] を選択すると、HTML 書式設定を使用して応答するようにモデルに通知されます。テンプレートごとに 1 回形式を設定します。この選択は、そのテンプレートを使用するすべてのプロンプトに適用され、使用事例全体で一貫性が維持されます。

形式: デフォルト

デフォルトでは、モデルでは太字、斜体、箇条書きなどの簡単な書式設定に Markdown がよく使用されます。以前のバージョンのプロンプトビルダーでは、この書式設定が未加工テキストとして表示されていました。現在のバージョンでは、Markdown がスタイル設定された出力として表示されるため、読みやすさが向上し、応答が解釈しやすくなりました。プロンプトビルダーではエージェントと同じ表示コンポーネントが使用されるため、実際の状況でユーザーに表示される形式と一致します。

形式: JSON

[JSON] を選択すると、クリーンで有効な JSON を返すのに役立つ特別な命令と構文チェックが適用されます。

重要 JSON 応答形式では、1 つの JSON オブジェクトが返されます。JSON 配列を生成するには、デフォルト形式を使用し、プロンプトの指示で配列構造を指定します。

JSON 応答は未加工ビューでのみ表示されます。項目では、Markdown や行頭復帰、\n、\r などの書式設定されたテキストは表示されません。JSON の生成時のモデルのパフォーマンスは異なります。精度と一貫性を高めるには、徹底したテストが重要です。最良の結果を得るには、JSON スキーマを適用する Lightning 種別を選択します。Lightning 種別を選択しない場合は、プロンプトの指示に JSON 構造の例を含めます。

応答形式として JSON を使用する場合、必要に応じて Lightning 種別を選択して、定義済みの出力スキーマを適用できます。Lightning タイプは、モデルで返される正確な項目、データ型、および必須値を定義します。

Lightning タイプを使用しない場合、JSON 応答はプロンプトの指示のみに依存します。システムは有効な JSON を確保するために構文チェックを適用しますが、構造自体は応答によって異なります。Lightning タイプでは、スキーマ定義をプロンプト命令からシステムによって適用されるメタデータに移行することで、この可変性が解消されます。Lightning 種別を選択したら、次のようになります。

  • プロンプトビルダーで、定義済みのスキーマに完全に一致するようにモデルに指示
  • モデルでは、構造を決定する代わりに値が入力されます。
  • フロー、エージェント、インテグレーションで応答の信頼性が向上

次の方法で JSON 出力を使用するときに Lightning タイプを選択します。

  • 自動化ツールまたはオーケストレーションツール
  • 下流インテグレーション
  • 一貫したデータ構造が必要な UI コンポーネント

Lightning タイプは 2 つの方法で使用できます。

  • オブジェクトベースの Lightning タイプ (プロンプトビルダーで Lightning タイプビルダーを使用して直接作成)
  • ApexベースのLightningタイプは、[設定]でApexクラスを使用して作成され、機能間で再利用されます。

プロンプトテンプレートの JSON 出力を設定するときに、Lightning タイプを選択します。

形式: HTML

[HTML] を選択すると、構造化されたスタイル設定されたコンテンツを返し、表示するようにテンプレートが設定されます。プロンプトビルダー:

  • テンプレートに format = rich text のタグを付ける
  • HTML 形式の出力を返すようにモデルに指示します。
  • lightning-formatted-rich-text Lightning Web コンポーネントを使用して応答を表示

プロンプトビルダーは Lightning Web コンポーネントlightning-formatted-rich-textを使用して、モデルから応答を表示します。

  • このコンポーネントは HTML タグのサブセットをサポートし、フルブラウザーのようには動作しません。
  • プロンプトビルダーでは、サポートされていない HTML タグはモデル応答に保持されますが、ビューには表示されません。
  • マスク解除されたすべてのデータが [応答] セクションに表示されます。元の値とマスクされた値の対応付けを表示するには、[応答] セクションで [マスキングの詳細] () ウィンドウを開きます。
  • サポートされるタグの完全なリストについては、Salesforce Component Library ドキュメントを参照してください。リッチテキスト出力は、外部 Web プラットフォームでのフル表示用に最適化または検証されていないため、Salesforce 内でのみ使用します。

プロンプトビルダーでのパフォーマンスインサイトの表示

応答時間、トークンの使用状況、マスクされた値などのキー生成評価指標をプロンプトビルダーで直接評価し、プロンプトの実行方法を把握します。

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition
必要なユーザー権限

  • プロンプトテンプレートの管理
  • Execute Prompt Templates (プロンプトテンプレートの実行)

または

「アプリケーションのカスタマイズ」権限セット

[パフォーマンスインサイト] パネルを使用して、プロンプトテンプレートをテストするときにバックグラウンドで実行される処理を透明にします。

  1. プロンプトビルダーのキャンバスで、プロンプトテンプレートを作成します。
  2. [プレビュー] をクリックします。
  3. 該当する場合は、プロンプトをプレビューするために必要な入力を入力し、[プレビュー] をクリックします。[パフォーマンスインサイト] パネルが開きます。パネルから、生成の応答時間、トークンの使用状況、マスクされた値を表示できます。
  4. 総計値をクリックすると、パネル内に詳細な内訳が表示されます。
