エージェントアクション

アクションとは、エージェントが作業を完了する方法です。エージェントにはアクションのライブラリが含まれます。これは、エージェントが作業を行うために使用できるツールです。たとえば、ユーザーがメールの作成に関してエージェントに支援を求めると、エージェントは最初にサブエージェントを選択し、次にメールのドラフトを作成および修正して関連する Salesforce データにグラウンディングするアクションを起動します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。
  • 標準エージェントアクションの共通ユーザーアクセス
    ユーザーが多くの標準エージェントアクションを実行するために必要な権限について説明します。
  • アセットライブラリからサブエージェントへのアクションの追加
    標準アクションをエージェントに追加して一般的なビジネス使用事例の処理をすばやく開始したり、ビジネスニーズに合わせてカスタムアクションを作成したりできます。これらのアクションをエージェントに追加すると、エージェントは独自の独立したコピーを取得します。アセットライブラリ内のテンプレートアクションへの変更は、エージェント内のサブエージェントおよびアクションに自動的に同期されません。あるエージェントのアクションを変更しても、別のエージェントのサブエージェントやアクションには影響しません。
  • カスタムアクションの作成
    カスタムアクションは、アセットライブラリまたは Agentforce Builder のエージェント内から作成できます。アセットライブラリからアクションを作成すると、複数のエージェントおよびバージョンに追加できます。Agentforce Builder でエージェント内からアクションを作成すると、そのエージェントのみが使用できます。
  • 従来のビルダーのエージェントアクション
    従来の Agentforce Builder でアクションを作成および管理します。
  • 標準エージェントアクションの参照アクションの編集
    基盤となるフローまたはプロンプトテンプレートを編集して、一部の標準エージェントアクションの動作をカスタマイズします。
  • 標準エージェントアクションの探索
    Salesforce が標準で提供するエージェントアクションについての詳細は、包括的なリファレンスライブラリを参照してください。

従来のビルダーでのサブエージェントへのアクションの追加

エージェントでアクションを使用するには、アクションをサブエージェントに追加します。アクションは複数のサブエージェントに追加できます。エージェントにサブエージェントを追加すると、Salesforce によってサブエージェントとそのアクションのコピーが作成されます。各エージェントとエージェントバージョンには、サブエージェントとアクションの独自のコピーがあります。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。
必要なユーザー権限
アクションをサブエージェントに割り当てる AIエージェントの管理とエージェントタイプの必要な権限

最適なパフォーマンスを得るには、15 個以下のアクションをサブエージェントに割り当てることをお勧めします。

カスタムサブエージェントを作成するときにエージェントにアクションを追加することもできます。

  1. Agentforce エージェントの [設定] ページから、Agentforce Builder でエージェントを起動します。
  2. エージェントが有効な場合は、無効化します。
  3. 左側のレールから、[サブエージェント] を選択します。
  4. [サブエージェント] パネルで、アクションを追加するサブエージェントの名前をクリックし、[このサブエージェントのアクション] タブを選択します。
  5. [新規] をクリックします。
  6. アクションライブラリからエージェントに追加するアクションを選択します。または、カスタムエージェントアクションを作成します。
  7. 変更内容を保存するには、[完了] をクリックします。

追加したアクションはエージェントに割り当てられ、Agentforce Builder の ［Subagents］ パネルに表示されます。新しく割り当てられたアクションでサブエージェントをテストするには、プレビュー会話を再開して変更を適用します。

エージェントからアクションを削除するには、Agentforce Builder の ［Subagents］ パネルから、アクションを削除するサブエージェントの名前をクリックし、［This Subagent’s Actions］ タブを選択します。アクションの横にあるドロップダウンメニューから、[サブエージェントから削除] を選択します。

従来のビルダーでのカスタムエージェントアクションの作成

カスタムアクションを使用すると、Salesforce 機能でエージェントを拡張して、ビジネスに固有の ToDo でユーザーをサポートする準備ができます。Apex、フロー、プロンプト・テンプレート、APIインテグレーションを使用してカスタム・アクションを構築します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。
必要なユーザー権限
カスタムエージェントアクションを作成する AIエージェントの管理とエージェントタイプの必要な権限
プロンプトテンプレートを作成または変更する プロンプトテンプレートマネージャー
フローを作成または変更する 「フローの管理」

作業を開始する前に

  • カスタムアクションの考慮事項を確認します。
  • エージェントで使用する基盤となる Salesforce 機能を作成します。カスタムアクションを作成するときに、エージェントで使用する機能を設定します。呼び出し可能なメソッドと REST Apex クラス、外部サービス、自動起動フロー、MuleSoft API、またはプロンプトテンプレートを呼び出すカスタムアクションを作成できます。

カスタムエージェントアクションへのアクセスは、参照する Salesforce 機能の種別によって異なります。たとえば、カスタムアクションがフローを使用して作成されている場合、カスタムアクションはフローで設定された権限、項目レベルセキュリティ、および共有設定に従います。アクションを実行するには、ユーザーまたはエージェントユーザーに「フローを実行」権限と、エージェントの種別に応じて特定のフローへのアクセス権が必要です。

  1. [設定] から、[クイック検索] ボックスに「エージェント」と入力し、[Agentforce アセット] を選択して、Salesforce 組織のすべてのアクションを表示します。
  2. [New Agent Action (新規エージェントアクション)] をクリックします。
  3. [参照アクション種別] ドロップダウンから、エージェントアクションの作成に使用する機能種別 (フローやプロンプトテンプレートなど) を選択します。次に、カテゴリと参照アクションを選択します (要求された場合)。
  4. エージェントアクションの表示ラベルと API 参照名には、参照アクション名と API 参照名が入力されます。これらの項目を確認し、必要に応じてアクションを正確に説明するように値を編集します。次に、[次へ] をクリックします。
  5. カスタムアクションと各入力および出力の命令には、参照アクションの説明が入力されます。次の項目を確認して変更します。「Best Practices for Agent Action Instructions」を参照してください。
    参照アクションから説明をコピーしてわかりやすくしていますが、エージェントアクションの手順は従来の説明とは異なります。エージェントは大規模言語モデル (LLM) と推論エンジンを使用して、会話でサブエージェントとアクションを起動するタイミングを決定します。アクション、入力、および出力の手順で、アクションで実行する内容と、アクションを使用するタイミングおよび方法をエージェントに指示します。効果的な手順は、アクションと使用事例によって異なります。指示のテストと反復を計画し、アクションが期待どおりに実行されることを確認します。
  6. 入力と出力ごとに、該当する設定を指定します。
    設定 詳細
    ユーザーからデータを収集 このパラメーターはユーザーが指定する必要があります。
    エージェントアクションからの絞り込み エージェントアクションを作成すると、参照アクションのすべての入力と出力がエージェントアクションに追加されます。エージェントアクションで参照アクションのパラメータを使用しない場合は、この設定を有効にします。エージェントアクションでは少なくとも 1 つの出力を使用する必要があります。
    入力が必要 アクションを実行するためにこのパラメーターが必要です。その他のすべての入力は省略可能として扱われます。参照アクションで入力が必要な場合、この設定はデフォルトで有効になっており、参照のみです。
    会話に表示

    一部またはすべての出力でこの設定を有効にすると、この設定が有効になっている出力がエージェントの応答に含まれます。一部のチャネルでは、一部の出力が構造化コンテンツに変換されます（Lightning Experience の Agentforce パネルでレコード ページが認識される場合など）。

    この設定がすべての出力で無効になっている場合、エージェントは LLM を使用してエージェントの応答の出力を自然言語で要約します。
    このアクションの読み込み中テキストを表示

    アクションをバックグラウンドで実行中のエージェントの会話に読み込み中のテキストを表示します。

    カスタムアクションの場合、[読み込み中テキスト] 項目でアクションの読み込みテキストを指定できます。句読点を含まない 1 ～ 3 の単語で、アクションの内容をユーザーに知らせます。たとえば、「メールの作成」、「更新の作成」、「活動の詳細の取得」などです。

    この設定が無効になっている場合、またはこの設定が有効になっていても読み込みテキストが指定されていない場合、デフォルトの読み込みテキストが表示されます。たとえば、「Working (作業中)」、「Making progress (進行状況の確認)」、「Checking my notes (メモの確認)」などです。

    拡張メッセージングチャネルの会話で読み込み中のテキストを表示するには、拡張チャットと Bring Your Own チャネルで追加の設定が必要です。
    ヒント アクションでレコードに変更を加える場合、エージェントが変更を実行する前にユーザーに変更の確認を求めるようにエージェントに要求できます。アクションのレコードページで、[ユーザー確認が必要] 設定を有効にします。
  7. [完了] をクリックします。

アクション手順では、アクションで実行する内容とアクションを使用するタイミングをエージェントに指示します。カスタムアクションを作成するときは、慎重に手順を計画してテストし、アクションが期待どおりに実行されることを確認します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

エージェントアクションの名前と手順、およびそれらの入力と出力によって、アクションを使用するタイミングと方法が決まります。AI エージェントは、大規模言語モデル (LLM) と推論エンジンを使用して、エージェントに割り当てられたすべてのサブエージェントとアクションを検索し、ユーザーの質問または要求に基づいて会話で実行する 1 つ以上のアクションを選択します。命令の効果が高いほど、アクションの予測精度が高くなります。

効果的な手順は、アクションと使用事例によって異なります。最良の結果を得るには、Agentforce Builder でアクションをテストし、アクションが要件を満たすまで繰り返します。

アクションの手順

アクション手順は、アクションで実行する内容と、会話で使用するタイミングを説明します。アクション指示の最も重要な要素は、アクションの内容の簡潔な自然言語の説明です。通常、1 ～ 3 文が LLM への指示として記述されます。説明には、アクションの目標または ToDo、アクションの使用事例、アクションで使用または変更するオブジェクトまたはレコードを含めることができます。一般に、関連する詳細を指示に含めるほど、LLM はアクションを区別しやすくなります。

入力と出力の手順

入力と出力の手順では、パラメーターの書式設定と使用方法について説明します。入力の手順で、アクションを完了するために必要な情報を指定します。出力の手順で、アクションの結果とエージェントがユーザーに返す内容を指定します。

LLM は、Salesforce コンテキストを含め、コンテキストを完全には理解していません。つまり、LLM は Salesforce レコード ID の文字数や Salesforce オブジェクトの名前を常に認識しているわけではありません。簡潔で詳細な手順は、エージェントが必要な情報を取得して関連する結果を返すのに役立ちます。適切な詳細レベルを判断する最善の方法は、指示をテストして反復することです。

入力または出力の指示を記述するときは、次の点を考慮してください。

  • 情報のデータ種別: 「18 文字の ID」、「ユーザーの質問に対するリッチテキストの回答」。
  • 特定の項目または値: 「取引先責任者 ID と配送予定日を含む」。
  • 情報の取得または生成方法: 「新規メールの場合、ユーザーの入力から ID を取得します。改訂済みメールの場合は、会話履歴から ID を取得します。」
  • アクションの使用目的に関する特別なルール (「SQL または SOQL を生成しないでください。」、「ユーザーが以前のドラフトを修正する必要がある場合にのみ必要です。」、「API 参照名は、ユーザー要求から Salesforce レコードの項目と値のペアを識別するために使用されます。」)。

考慮事項

このアクションにより、特定の条件を満たしたときに、詳細なコンテキストとリンクされたトランスクリプトを含む拡張サポートケースが作成されます。これらの条件が満たされない場合、アクションは件名と説明のみが含まれる基本的なケース作成に戻ります。1 つのメッセージングセッションで複数のケースが作成された場合、最新のケースにのみ完全なトランスクリプトが含まれます。

  • 拡張ケースの作成には、有効なメッセージングセッション ID が必要です。セッション ID は、チャットトランスクリプトを取得し、構造化された件名項目と説明項目を生成するプロンプトテンプレートのコンテキストを提供するために使用されます。
  • 拡張ケースは、拡張チャットなどのセッション ID をサポートするサポート対象のメッセージングチャネル、または WhatsApp や Facebook Messenger などのサードパーティアプリケーションからアクションがトリガーされたときに作成されます。これらのチャネルでは、ケース作成の強化に必要なメッセージングコンテキストが自動的に生成されます。
  • このアクションは、外部 Web サイトまたは認証されていない Experience Cloud サイトからトリガーされた場合に機能します。Experience Cloud サイトでは、実行時にメッセージングセッションをリンクしてトランスクリプトデータを取得できます。
  • アクションが認証済み Experience Cloud サイト、またはセッション ID を使用できない Agentforce Builder などの環境で実行される場合、アクションは基本的なケース作成に戻ります。代替モードでは、ケースには簡略化された件名と説明のみが含まれ、トランスクリプトは添付されません。
  • メッセージングセッションは Agentforce Builder で自動的に作成されません。拡張ケースの作成をテストするには、ユーザーの発言に有効なセッション ID を含めます (「Create a case for this messaging session 123456 (このメッセージングセッションのケースを作成してください 123456)」など)。 本番環境では、メッセージングセッション ID が自動的に渡されるため、手動で入力する必要はありません。
  • 1 つのメッセージングセッションで複数のケースが作成された場合、最新のケースにのみ完全なトランスクリプトが含まれます。以前のケースには構造化された説明が含まれますが、1 対 1 の対応付けのためトランスクリプトは添付されません。作成したケースのトランスクリプトを表示するには、オブジェクトマネージャーでメッセージングセッションオブジェクトをケースページレイアウトの関連リストとして追加します。
  • 複数の問題を話し合うメッセージングセッションからケースが作成されると、最新の問題のみが集計されます。
  • 作成されたケースは顧客の取引先責任者レコードにリンクされます。会話中に共有されたファイル、スクリーンショット、ログなどの添付ファイルは含まれません。サポート チームが自動ケースを識別できるように、[ケースの発生源] フィールドは [Web]、[作成者] フィールドは Agentforce サービスエージェントに設定されています。
  • このアクションでは、アップロードされた添付ファイルのコンテンツは抽出または集計されません。会話中に添付ファイルが共有されている場合、拡張ケースの説明で添付ファイルが提供されたことが示される場合があります。
  • 生成されたケースの説明では、問題の概要、試行されたトラブルシューティング手順の概要、会話の関連するコンテキストが強調表示されます。このアクションでは 2 つのプロンプトテンプレートを使用してチャットを分析し、ケース項目を生成するため、応答が完了するまでに 10 ～ 12 秒かかることがあります。
  • アクションをコピーして、ワークフローの必要に応じてプロンプト、データマッピング、出力形式をカスタマイズできます。
