プロンプトのプロンプトインジェクション検出の有効化 (ベータ)

Einstein Trust Layer の [設定] でプロンプト インジェクション検出を有効にして、大規模言語モデルが意図しない動作をさせようとするコンテンツを監視します。これらの設定は、Salesforce 組織レベルで適用されます。

必要なエディション

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。
必要なユーザー権限
プロンプトの挿入検出を有効にする 「設定の参照」
  および
  「アプリケーションのカスタマイズ」

Einstein 生成 AI が有効になっている必要があります。

メモ プロンプトの挿入検出はベータ機能です。
  1. [設定] の [クイック検索] 項目に「Einstein」と入力し、[Einstein Trust Layer] を選択します。
    メモ [Einstein 生成 AI 設定] が見つからない場合は、使用する生成 AI 機能の前提条件を組織が満たしていることを確認してください。詳細は、Salesforce アカウントエグゼクティブ (AE) にお問い合わせください。
  2. [安全とセキュリティ] をクリックします。
  3. ベータサービス条件を確認します。プロンプトの挿入検出を有効にします。
  4. プロンプトインジェクションが検出されたかどうかを確認するには、Data 360 のレポートとダッシュボードを使用します。

プロンプトインジェクション検出 (ベータ)

プロンプトの挿入 (「ジェイルブレイク 」とも呼ばれる) は、大規模言語モデル (LLM) の脆弱性です。プロンプトインジェクションは、LLM が意図しない動作をさせようとする試みです。ハッカーは、システムポリシーを上書きしたり、LLM を操作して意図しない動作をさせようとするプロンプトを作成できます。

必要なエディション

使用可能なエディション: Einstein for Sales、Einstein for Platform、Einstein for Service、Einstein 1 Service、または Einstein GPT Service アドオンが付属する Enterprise Edition、Performance Edition、および Unlimited Edition。アドオンを購入するには、Salesforce アカウントエグゼクティブにお問い合わせください。

プロンプトの挿入は、プロンプトテキストに直接導入されたり、プロンプトに含まれるデータソースを介して間接的に導入されたりする場合があります。

Salesforce プロンプトの挿入検出モデルでは、次の種別のプロンプトインジェクション攻撃が認識されます。

種別 説明
偽装 (ロールプレイ) 悪意のある別のシステム人格を採用するように AI に指示し、人を欺くような表現や誤解を招く表現を使用してソーシャルエンジニアリング攻撃で操作するプロンプト
権限のエスカレーションまたはシステムルールの変更の試行 Do Anything Now (DAN) ジェイルブレイク攻撃などのセキュリティ制限に違反する攻撃を含め、システムルールを回避または変更し、言語モデルの安全トレーニングをスキップする有害なコマンドが含まれるプロンプト
プロンプト漏洩の試み 言語モデルから機密情報 (システムポリシーやナレッジドキュメントなど) を収集して未承認の情報を取得するためのプロンプト
符号化攻撃 プロンプトで難読化されたメッセージや非表示のメッセージを使用して言語モデルを作成し、悪意のあるコンテンツ、整合性のないコンテンツ、有害なコンテンツを生成
プライバシー攻撃 個人情報や機密情報を取得してデータに不正アクセスしたり、情報を悪用したりするプロンプト
悪意のあるコードの生成 不正ソフトウェア、ウイルス、または詐欺やその他の悪意のある意図を実行するように設計されたツールやソフトウェアなどの有害なコンピューターコードを生成しようとするプロンプト。

プロンプトインジェクションが検出されると、コンテンツが評価され、スコアが監査履歴に記録されて Data 360 に保存されます。 プロンプトインジェクションスコアは Data 360 DMO で表示できます。

重要 プロンプトの挿入検出モデルは内部テストで有効であることが示されていますが、どのモデルも 100% の精度を保証することはできないことに注意してください。信頼を優先事項として、モデルの継続的な評価と調整に取り組んでいます。

プロンプトビルダー

プロンプトテンプレートを利用した生成 AI モーメントをワークフローに統合することで、ユーザーの日次タスクを簡素化します。レコード項目、フロー、関連リスト、Apex を参照する差し込み項目の CRM データを組み込んだプロンプトテンプレートを作成、テスト、修正、カスタマイズ、管理します。プロンプトビルダーを使用すると、自分とデータを LLM に安全に接続するための効果的なプロンプトを作成できます。

プロンプトビルダーでさまざまな種別のプロンプトテンプレートを作成します。

  • セールスメールプロンプトテンプレートは、営業チームが取引先責任者またはリード向けにパーソナライズされたメールのドラフトを作成するのに役立ちます。
  • Field Generation プロンプト テンプレートでは、生成 AI 支援ワークフローを Lightning レコード ページ内のフィールドに取り込みます。ユーザーが LLM によって作成された概要や説明を項目に入力し、顧客とのより生産的な会話を促進できるようにします。
  • Flex プロンプトテンプレートは、さまざまなオブジェクト種別の可変数の入力を取ります。この柔軟性により、商品やキャンペーンオブジェクトに基づいてニュースレターを生成するなど、さまざまな可能性が広がります。

Salesforce Platform の任意の場所で呼び出し可能なアクションを使用するか、Connect REST API または Connect in Apex を使用してプロンプトテンプレートをコールします。

プロンプトビルダーでプロンプトテンプレートを作成および管理する Salesforce システム管理者に「プロンプトテンプレートマネージャー」権限セットを割り当てます。

プロンプトテンプレートの有効化と無効化

プロンプトテンプレートの有効化と無効化を使用して、ユーザーがアクセスできるバージョンを細かく制御します。

プロンプトテンプレートの作成プロセスでは、通常、いくつかのバージョンを作成して、どのテンプレート本文、グラウンディングデータ、LLM の組み合わせが最も満足のいく応答を生成するかをテストします。この反復的なドラフト作成プロセスのため、デフォルトではプロンプトテンプレートをユーザーが使用できません。最初に有効化する必要があります。

プロンプトテンプレートを有効化すると、特定のバージョンのプロンプトテンプレートをユーザーが使用できるようになります。一度に有効化できるテンプレートのバージョンは 1 つのみです。有効なバージョンがない場合、ユーザーはテンプレートを使用できなくなります。バージョンを有効化および無効化すると、共有するテンプレートのバージョンのみを使用可能にする制御が可能になります。

  1. プロンプトビルダーのプロンプトテンプレートワークスペースから開始します。「Create a Prompt Template」を参照してください。
  2. [プロンプト] セクションでプロンプトのドラフトを作成します。作業を保存する準備ができたら、[保存] をクリックします。このプロンプトは、プロンプトテンプレートワークスペースの上部に表示されるバージョン番号で示されるように、プロンプトテンプレートのバージョン 1 になりました。
  3. テンプレートを有効化してユーザーが使用できるようにする準備ができたら、[有効化] をクリックします。
    重要 テンプレートバージョンを有効化すると、テンプレートバージョンは不変になります。無効化された場合でも、有効になっていたバージョンは不変のままです。このようなテンプレートを編集するには、新しいバージョンとして保存します。「Use Multiple Versions of a Prompt Template (プロンプトテンプレートの複数バージョンの使用)」を参照してください。
  4. 有効なテンプレートバージョンを無効にするには、[無効化] をクリックします。

たとえば、顧客が電話をかける前に、特定の顧客のケースの最新の概要を会社の営業チームに提供します。フローセクションでも同じ使用事例を使用しました。

今回は、LLM で集計するケースデータを取得する Apex クラスを統合する項目生成プロンプトテンプレートを作成します。

プロンプトテンプレートのリソースとしてアクセスする Apex クラスを次に示します。

public class OpenCasesPrompt {
    @InvocableMethod(label='Open Cases'
        description='Find Cases for an Account'
        CapabilityType='PromptTemplateType://einstein_gpt__fieldCompletion')
    public static List<Response> getCasesPrompt(List<Request> requests) {
        // Validate the expected number of requests as an input
        if (requests.size() != 1)
          throw new ListException('The requests list must contain one entry only');
        Account a = requests[0].RelatedEntity;
        ID searchAcctId = a.Id;
        List<Case> cases =
            [SELECT Id, Subject, Description
             FROM Case
             WHERE AccountId = :searchAcctId AND Status != 'Closed'
             WITH USER_MODE];
        string responseData = null;
        if(cases.isEmpty()) {
            responseData = 'There are no open cases.';
        } else {
            for(Case c : cases) {  
                responseData =
                   (responseData != null) ? responseData + '\n' : '';           
                responseData += String.format('Case details: {0}, {1}.',
                    new List<Object>{c.Subject, c.Description});
            }
        }
       
        List<Response> responses = new List<Response>();
        Response res = new Response();
        res.Prompt = responseData;
        responses.add(res);
        return responses;
    }
    
    public class Request {
        @InvocableVariable(required=true)
        public Account RelatedEntity;
    }
    
    public class Response {
        @InvocableVariable
        public String Prompt;
    }
}

Apex クラスの要件については、「 Apex 差し込み項目を使用したグラウンディング 」を参照してください。

テストカバー率は重要であるため、テストクラスを追加しましょう。テストクラスは、プロンプトビルダーから送信されるデータをシミュレートします。2 つのテストケースが用意されています。1 つはイベントが見つかった場合のテストケース、もう 1 つはイベントがない場合のテストケースです。

Apex クラスの準備ができたら、プロンプトビルダーから呼び出してみましょう。これを行うには、まず取引先オブジェクトで「Open Case Summary (オープンケースの概要)」というカスタム項目を作成する必要があります。カスタム項目のデータ型は [テキストエリア (ロング)] である必要があります。「カスタム項目の作成」を参照してください。プロンプトビルダーに新しいカスタム項目が表示されるように、ログアウトしてから再度ログインします。

プロンプトビルダーで、新しいプロンプトテンプレートを作成します。

  1. [プロンプトテンプレート種別] で、[項目生成] を選択します。
  2. [プロンプトテンプレート名] に「Apex: Summarize Open Cases」と入力します。
  3. [オブジェクト] で、[取引先] を選択します。
  4. [オブジェクト項目] で、[Open Case Summary] を選択します。
  5. [説明] 項目を空白のままにします。
  6. [作成] をクリックすると、プロンプトテンプレートワークスペースにリダイレクトされます。
  7. サンプルプロンプトテンプレートライブラリで、項目生成プロンプトテンプレート「Summarize open cases for an account」を見つけます。このテンプレートをコピーしてプロンプトテンプレートワークスペースに貼り付けます。
  8. プロンプトビルダーでこのテンプレートを実行する前に、[プロンプト] セクションで [リソースの挿入] をクリックします。検索項目は、このオプションを初めてクリックしたときに表示されます。
    1. <account.Id__Merge_Field> プレースホルダーを削除します。
    2. [ リソース] 検索バーをクリックし、 [取引先] [ 取引先 | ID] を選択します。

public class ContactEventsPrompt {
    @InvocableMethod(label='Contact Events'
      description='Find Events for a Contact'
      CapabilityType='PromptTemplateType://einstein_gpt__salesEmail')
    public static List<Response> getContactsPrompt(List<Request> requests) {
        // validate the expected number of requests as an input
        if (requests.size() != 1)
            throw new ListException('The requests list must contain one entry only');
        Contact c = requests[0].Recipient;
        // Protect against SOQL Injection
        string searchCity = '%' + c.MailingCity + '%';
        string searchState = '%' + c.MailingState + '%';
        List<Event> events =
          [SELECT Id, Subject, Description, Location, StartDateTime
           FROM Event
           WHERE IsArchived = false AND Location LIKE :searchCity
            AND Location LIKE :searchState WITH USER_MODE]; 
        string responseData = '';

        if(events.isEmpty()) {
            responseData = 'No upcoming Marketing events near you.';
        } else {
            for(Event e : events) {
                responseData += 'Event details: ';
                responseData += e.Subject;
                responseData += ', ';
                responseData += e.Description;
                responseData += ', ';
                responseData += e.Location;
                responseData += '/nStart Time: ';
                responseData += e.StartDateTime.format();
                responseData += '.';
            }
        }

        List<Response> responses = new List<Response>();
        Response res = new Response();
        res.Prompt = responseData;
        responses.add(res);
        return responses;
      }

      public class Request {
          @InvocableVariable(required=true)
          public User Sender;
          @InvocableVariable(required=true)
          public Contact Recipient;
      }

      public class Response {
          @InvocableVariable
          public String Prompt;
      }
}

    1. 名前: Image1
    2. API 参照名: Image1
    3. ソース種別: オブジェクト
    4. オブジェクト: ファイル
  5. [追加] をクリックします。
  6. 2 番目の画像には、次のように入力します。
    1. 名前: Image2
    2. API 参照名: Image2
    3. ソース種別: オブジェクト
    4. オブジェクト: ファイル
  7. [追加] をクリックします。
  8. 商品説明に次のように入力します。
    1. 名前: 説明
    2. API 参照名: 説明
    3. ソース種別: オブジェクト
    4. オブジェクト: Product2

  11. 関連リストをプロンプト テンプレートに追加し、リソース ピッカーから [Product2]、[メモ & 添付ファイル] の順にクリックします。
  12. [テンプレート設定] の [モデル] で、[GPT 4 Omni] を選択します。
  13. [プレビュー設定] で、[入力] をクリックします。[入力] セクションに、作成した 3 つのオブジェクトが表示されます。

    6. [項目] で、アカウント名を表す項目を選択します (例: ssot_Name__c)。

Flex プロンプトテンプレートへの自由テキスト入力の追加

自由テキスト入力を含む Flex プロンプトテンプレートを作成します。

使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

  • プロンプトテンプレートの管理
  • Execute Prompt Templates (プロンプトテンプレートの実行)

または

「アプリケーションのカスタマイズ」権限セット

フリーテキスト入力は、テキストのみで構成される非レコードタイプの入力項目です。Flex プロンプトテンプレートには、リソースピッカーから差し込み項目や他のリソースを含める場合と同じように、自由テキスト入力項目を含めることができます。この機能により、プロンプトテンプレートでフリーテキストを入力として受け取るシナリオを処理できます。たとえば、フォーム項目で質問を送信する顧客、ファイルを参照してプロンプトにコンテンツを送信する顧客、プロンプトビルダーで Flex プロンプトテンプレートに任意のテキストを送信する状況を処理する顧客などです。

自分がプロンプト管理者で、Web サイトの特定の商品に関する顧客の質問に回答するプロンプトを設計したいと考えているとします。自由テキスト入力を処理する Flex プロンプトテンプレートは、このような一般的な状況に適したエレガントなソリューションです。商談を使用して、現在実行中のプロモーションについて顧客に知らせることもできます。

メモ ユーザー入力機能は Flex テンプレートでのみ使用でき、最大 127,000 文字までサポートされます。

使用を開始するには、プロンプトテンプレートを作成します。

  1. [Prompt Template Type (プロンプトテンプレート種別)] ドロップダウンで、[Flex] を選択します。
  2. [プロンプトテンプレート名] に「Product Question Response and Promotion」 (商品質問への回答とプロモーション) と入力します。
  3. [ソースを定義] セクションで、3 つのソースを定義します。
    1. 最初の行で、[名前] フィールドに「Product」と入力します。ソース種別として [オブジェクト] を選択します。[オブジェクト] 項目で、[商品] を選択します。この行は、顧客が質問している商品を表します。
    2. 2 番目の行で、[名前] フィールドに「User Question」 (ユーザーの質問) と入力します。ソース種別として [フリーテキスト] を選択します。この行は、顧客が質問形式で入力するテキストを表します。
    3. 3 行目で、[名前] フィールドに「Promotion」 (プロモーション) と入力します。ソース種別として [オブジェクト] を選択します。[オブジェクト] 項目で、[商品サービスキャンペーン] を選択します。この行は、顧客に伝えるプロモーションを表します。
  4. [次へ] をクリックします。
    プロンプトテンプレートワークスペースにリダイレクトされます。
  5. プロンプトテンプレートを最初から記述するか、サンプルテンプレートをコピーして貼り付けます。
    1. この例で使用されているテンプレートに基づいてプロンプトテンプレートを作成する場合は、ページの下部に表示されているサンプルテンプレートテキストをコピーして貼り付け、編集します。
    2. プロンプトビルダーでテンプレートを実行する前に、[プロンプト] セクションで [リソースの挿入] をクリックし、検索バーを使用してプレースホルダーを実際の差し込み項目に置き換えます。検索項目は、このオプションを初めてクリックしたときに表示されます。
    3. テンプレートがプロンプトに解決されると、差し込み項目が実際のデータに置き換えられ、[解決済みプロンプト] セクションに表示されます。
  6. [プレビュー設定] パネルで、[商品] 項目の商品を選択し、[ユーザー質問] 項目にサンプル質問を入力して、[プロモーション] 項目のプロモーションを選択します。
  7. [保存 & プレビュー(Save & Preview)] をクリックして、LLM で生成された応答を確認します。

    A customer on our site is asking the following question about {!$Input:Product.Name}. Do your best to answer the customer's question.
    '''
    {!$Input:User_Question}
    '''
    In addition to answering their question, be sure to mention {!$Input:Promotion.ProductServiceCampaignName} to the customer.

概要

一括処理では、1 つの要求で多数のプロンプト応答が非同期に生成されます。この方法により、LLM レート制限に達することを回避し、大量のコンテンツの生成を効率的に処理できます。

一括処理ジョブがキューに入れられ、すべての項目が処理され、結果が保存されます。ジョブの進行状況を監視し、準備ができたら完了した応答を取得できます。実際の完了時間はモデルプロバイダーによって異なり、異なる場合があります。

一般的な使用事例を次に示します。

  • 何千もの顧客向けにパーソナライズされたメールキャンペーンを作成する。
  • カタログデータから商品説明を生成する。
  • 大量のケースメモや顧客からのフィードバックの集計。
  • 複数のレコードでコンテンツを翻訳する。
  • スケジュールまたはレコードの変更によって一括コンテンツ生成をトリガーする。

実装オプション

Salesforce では、一括処理を実装するために主に次の 2 つの方法を提供しています。

フロー

このアプローチはほとんどの使用事例で機能し、ノーコードソリューションを構築する Salesforce システム管理者に最適です。スケジュールトリガーフローまたはレコードトリガーフローで [プロンプトテンプレート (一括生成)] アクションを使用して、自動的に実行される一括処理ジョブを作成します。これらのフローには [完了] パスと [タイムアウト] パスが含まれており、正常な完了シナリオとタイムアウトシナリオを異なる方法で処理できます。

制限:

  • 通常、フロー一括処理ジョブは送信から 2 時間以内に処理を開始します。
  • 標準モデルでは 1 日あたり最大 10,000 世代。
  • ネイティブのバッチ処理をサポートするモデルを使用している場合、1 日あたり最大 50,000 世代。
  • WebSearch Retrievers を使用する場合、1 時間あたり最大 1,000 件の項目。

Apex

このアプローチでは、カスタムインテグレーションと自動化の柔軟性を最大限に高めることができます。AiJobRun および AiJobRunItem オブジェクトを使用して、プログラムで一括処理ジョブを作成および管理します。Apex は、次の場合にお勧めします。

  • カスタム UI を作成します。例: ジョブを開始するボタン、一括処理ジョブをリストするダッシュボード。
  • バッチサイズを動的に制御する (件数または時間のしきい値に達するまで項目を累積し、しきい値を超えると開始)。
  • レコードトリガーまたはスケジュールベースではない外部イベントからトリガーします。

制限:

  • AiJobRun ごとに最大 1,000 個の AiJobRunItem。
  • ネイティブ一括処理をサポートするモデルを使用している場合、各 AiJobRun には 10,000 AiJobRunItem の制限があります。
  • WebSearch Retrievers を使用する場合、1 時間あたり最大 1,000 件の項目。
  • 24 時間あたり最大 5 個の AiJobRun オブジェクト。要求が 1 日の制限を超えた場合、制限がリセットされるまでキュー状況になります。

ベストプラクティス

適切なモデルを選択します。

  • プロンプトビルダーで「バッチのサポート: はい」という表示ラベルのモデルを使用して、最も速く処理します。
  • バッチ用のミニモデルは動作が顕著に遅くなるため、避けてください。

バッチのサイズ:

  • 大きい方がいい制限要素はジョブの数であり、それらのジョブの項目数ではありません。200 と 2,000 のバッチはほぼ同じ時間で終了します。
  • 1 つ以上の失敗した項目によって残りのバッチがブロックされることはありません。

適切な実装を選択します: フローと Apex:

  • ジョブ、動的バッチサイズ、またはレコード以外のトリガーとスケジュール以外のトリガーを開始するカスタム UI が必要な場合を除き、フローを使用します。

フローを設計します。

  • フローごとに 1 つの一括処理アクションのみを実行します。チェーン化された一括処理アクションはキューに入れられ、ランタイムが大幅に増加します。
  • 可能な場合は、プロンプトを 1 つのテンプレートにまとめます。
  • タイムアウトを 1 日に設定します。

ジョブの進行状況を監視します。

  • AiJobRun と AiJobRunItem に状況、項目数、エラー、応答を照会します。
  • イベント駆動型ワークフローの AiJobRunStatusEvent に登録します。

制限と考慮事項

前提条件

  • 指定されたプロンプトテンプレートには有効なバージョンが必要です。
  • フローの場合: [プロセスの自動化設定] でデフォルトのワークフローユーザーを設定する必要があります。

処理動作

  • ジョブは作成日に基づいて時系列で処理されます。
  • 数秒以内に作成されたジョブは、厳密な順序に従わない場合があります。
  • 処理が開始されると、入力値と特定の項目は不変になります。
  • ジョブ状況の変更はシステムで管理され、手動で変更することはできません。
  • 完了時間はモデルプロバイダーによって異なり、異なる場合があります。

プラットフォームに関する考慮事項

  • バッチ処理は非同期であり、結果はすぐには返されません。
  • 適切なタイムアウトの長さを設定します。フロー一括処理ジョブでは 1 日をお勧めします。
  • プラットフォームイベントまたはジョブレコードを照会して、ジョブの状況を監視します。
  • 時間的制約のあるワークフローを設計するときは、処理時間を考慮して計画します。
  • バッチ内の失敗した項目のフォールバック処理を考慮します。

プロンプトテンプレートでの LLM 設定の変更

プロンプトビルダーで出力を生成するための LLM 設定を選択し、必要に応じて変更します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

プロンプトビルダーの最も強力な機能の 1 つは、数回クリックするだけで LLM 設定を変更できることです。

標準および顧客の LLM 設定

プロンプトビルダーの LLM 設定は、標準またはカスタムに分類されます。プロンプトビルダーには標準設定が含まれています。カスタム設定は BYO-LLM を介して取り込まれます。また、標準設定を変更すると、変更された設定がカスタム設定として保存されます。

バージョンと LLM 設定

プロンプトテンプレートのバージョンごとに異なるモデル設定を含めることができます。有効化されたバージョンの設定モデルのみが使用されます。

重要 テンプレートバージョンを有効化すると、テンプレートバージョンは不変になります。無効化された場合でも、有効になっていたバージョンは不変のままです。このようなテンプレートを編集するには、新しいバージョンとして保存します。「Use Multiple Versions of a Prompt Template (プロンプトテンプレートの複数バージョンの使用)」を参照してください。

モデルの表示

[テンプレート設定] パネルの [モデル] セクションにある [このモデルを表示] リンクをクリックすると、選択したモデルの AI モデル (旧 Einstein Studio) モデルページが開きます。このページでは、プロンプトビルダーでプロンプトテンプレートのドラフトを作成する前にモデルを変更します。

重要 ユーザーが [テンプレート設定] パネルで [このモデルを表示] リンクを表示および使用するには、Data Cloud 管理者権限が必要です。これらの権限がないと、ユーザーは AI モデル内のモデル設定にアクセスできません。

非表示モデルの置き換え

LLM 設定は AI モデルで非表示にできます。非表示モデルを使用するプロンプトテンプレートは、これまでどおり実行されます。ただし、非表示モデルを使用可能なモデルに置き換えることをお勧めします。使用できないモデルを使用するプロンプト テンプレートを開くと、プロンプトビルダーで [モデル] 項目に別のモデルを選択してから、変更を新しいバージョンとして保存できます。

プロンプトテンプレートの変更セットに関する考慮事項

変更セットを使用してプロンプトテンプレートをリリースする前に、コンポーネントの連動関係とリリースに関連する制限と動作を理解します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

有効化と無効化

  • プロンプトテンプレートを有効にすると、バージョン状況が [ドラフト] から [公開済み] に変更されます。バージョンが公開されたら、ドラフトに変更することはできません。
  • プロンプトテンプレートバージョンは有効化または無効化できます。
  • 対象組織で「プロンプトテンプレートのリリース」権限が有効になっていない限り、バージョンは複数の組織間のリリース中に自動的に有効化されません。この権限は変更セットにのみ適用され、Einstein の [設定] の [設定] にあります。
  • プロンプトテンプレートが使用されている場合、別のバージョンが有効でない限り、そのバージョンを無効にすることはできません。
  • プロンプトテンプレートが使用されている場合、有効なバージョンは削除できません。
  • フローがプロンプトテンプレートで参照され、リリースされている場合、フローは自動的に有効化されません。自動有効化のフローガイドラインに従います。無効なフローでプロンプトテンプレートを実行すると、実行時にエラーが発生します。

その他の考慮事項

  • 公開されたプロンプトテンプレートバージョンは変更できず、リリースされるとスキップされます。
  • テンプレートが上書きされた場合、ユーザーは変更セット、Command-ine Interface (CLI)、または Connect API を使用してテンプレートを再度上書きすることはできません。
  • プロンプトテンプレートは変更セットでは削除できません。
  • カスタム大規模言語モデル (LLM) 設定を使用してテンプレートをリリースする場合、対象組織に同じ名前のモデルがあることを確認します。モデル名が一致しない場合、リリースは失敗します。
  • 変更セットを使用してテンプレートをリリースすると、すべてのバージョン (有効または無効) がリリースに含まれます。
  • 変更セットにすべてのリソースを追加し、連動関係を追加します。
