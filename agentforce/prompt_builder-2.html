プロンプトテンプレートに関する Salesforce CLI の考慮事項

プロンプトテンプレートで Salesforce CLI を使用する場合のメタデータコンポーネントの連動関係とリリースに関連する制限と動作について説明します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

Salesforce CLIとは?

Salesforce CLI は、Salesforce 組織での作業時に開発を簡素化し、自動化を構築するコマンドライン インターフェイスです。これを使用して、組織と、GitHub などのソースリポジトリに保存されているローカル DX プロジェクト間でメタデータを同期できます。

Salesforce CLIをダウンロードするには、ここをクリックします。詳細については、『Salesforce CLI Setup Guide』を参照してください。

プロンプトテンプレートでの Salesforce CLI の使用

プロンプトテンプレートは、組織内で GenAiPromptTemplate メタデータ型で表されます。標準のSalesforce CLIコマンドを使用して、DXプロジェクトと組織間で特定のGenAiPromptTemplateコンポーネントをリリースおよび取得します。

リリース: 

sf project deploy start --metadata GenAiPromptTemplate:TemplateName --target-org myorg@username.com

取得:

sf project retrieve start --metadata GenAiPromptTemplate:TemplateName --target-org myorg@username.com

TemplateName をプロンプトテンプレートの名前に置き換え、 myorg@username.com を組織の一意のユーザー名または別名に置き換えます。

project コマンド、および使用できるその他の CLI コマンドの詳細については、『Salesforce CLI Command Reference』を参照してください。

プロンプトテンプレートの有効化と無効化

  • <activeVersionIdentifier>に <versionIdentifier> を使用してテンプレートを有効化することも、UI でテンプレートを有効化して取得して正しい XML にすることもできます。
  • テンプレートが使用されている場合、別のバージョンが有効化されていない限り、バージョンの無効化をブロックします。
  • プロンプトテンプレートバージョンが公開されていて使用されていない場合は、どのバージョンも有効化または無効化できます。
  • テンプレートが使用されていない場合、別のバージョンを有効化することなく、バージョンの無効化が許可されます。

新規プロンプトテンプレートの作成

  • 新しいテンプレートを追加したら、バージョンの作成後に<versionIdentifier>が自動的に生成されるため、テンプレートを取得します。
  • <versionIdentifier>と<activeVersionIdentifier>を含むテンプレートがある場合、そのテンプレートを別の組織にリリースできます。versionIdentifier を使用すると、CI/CD パイプラインのすべての組織で versionIdentifier をリリースまたは取得する必要がなくなります。

プロンプトテンプレートの削除

  • CLI を使用してプロンプトテンプレートを削除することはできません。
  • プロンプトテンプレートバージョンは CLI で削除できます。削除されると、XML のバージョンから削除されます。
  • テンプレートバージョンは、XML から削除し、CLI を使用してリリースできます。削除したバージョンは、対象組織で有効かつ使用中でない限り削除されます。
  • テンプレートが有効なバージョンで使用されている場合、削除できません。

プロンプトテンプレートのリリース

  • テンプレートをリリースするには、少なくとも 1 つのテンプレートバージョンが必要です。

プロンプトテンプレートの変更

  • プロンプトテンプレートバージョンが公開されていて使用されていない場合は、変更できません。
  • 公開バージョンは変更できません。リリースは成功し、公開済みバージョンはスキップされます。
  • 手動で<versionIdentifier>を設定して複製した場合、新しいバージョンと古いバージョンの状況がドラフトであれば、新しいバージョンと古いバージョンが上書きされます。それ以外の場合、公開バージョンは不変であるため、最初の公開バージョンはそのまま残り、2 番目のバージョンはスキップされます。

その他の考慮事項

  • テンプレートが上書きされた場合、ユーザーは変更セット、CLI、または Connect API を使用して再度上書きすることはできません。

プロンプトテンプレートのリリースに関する考慮事項

プロンプトテンプレートを管理パッケージ、未管理パッケージ、ロック解除済みパッケージに含めます。プロンプトテンプレートを含むパッケージをリリースする前に、変更セットまたは CLI で制限と動作を理解します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

パッケージのリリース

  • テンプレートトリガーフローを作成する場合は、手動入力を使用します。プロンプトとフローを 1 つのリリースにまとめてリリースします。
  • 自動入力を使用するフローでは、テンプレートで自動入力が参照されるとリリースが失敗します。
  • リリースに失敗した場合は、最初にフローをリリースしてから、テンプレートを個別にリリースします。
  • CLI を使用してパッケージをリリースするには、テンプレートをリリースするテンプレートバージョンが少なくとも 1 つ必要です。

プロンプトテンプレートのパッケージ化に関する考慮事項

プロンプトテンプレートを管理パッケージ、未管理パッケージ、ロック解除済みパッケージに含めます。プロンプトテンプレートを含むパッケージを作成、更新、またはリリースする前に、パッケージの制限と動作を理解します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

パッケージの作成

  • カスタムオブジェクト入力を含むフローを含むプロンプトテンプレートでは、カスタムオブジェクトを含むプロンプトフローのパッケージ化がサポートされていないため、パッケージのインストールに失敗する可能性があります。
  • 公開バージョンのみを含めます。ドラフトバージョンはパッケージに追加できますが、管理パッケージのカスタマー組織にはインストールされません。
  • 公開済みバージョンに対する今後の変更は、エラーなしでアップグレード時にスキップされます。
  • 公開済みバージョンが有効で、現在のバージョンと異なる場合、顧客の組織で自動的に有効化されます。
  • バージョンが公開されていない場合、テンプレートをパッケージ化しないでください。公開バージョンのないテンプレートをパッケージ化すると、空のテンプレートが原因でインストールまたはアップグレードが失敗します。
  • カスタムモデルを使用するプロンプトテンプレートはパッケージ化できません。
  • Apex クラスをプロンプトテンプレートに含めてパッケージ化する場合、そのクラスはグローバルである必要があります。
  • 未管理パッケージ、ロック解除済みパッケージ、または管理パッケージの場合、標準 (OOTB) テンプレートを上書きするパッケージテンプレートは避けてください。パッケージ化されたテンプレートは、必要に応じて上書き可能として設定できます。これにより、登録者はテンプレートのローカルバージョンを作成できます。
  • データ検索やデータグラフなどの取得機能はパッケージに含まれていません。代わりに、Data 360 のデータキットに含まれています。 Salesforce 独立系ソフトウェアベンダー (ISV) は、取得者を顧客に提供することをお勧めします。提供しない場合、メタデータがないためインストールに失敗します。
  • 新しいバージョンは既存のテンプレートに追加できますが、以前に公開されたバージョンは変更または削除できません。上書き可能なテンプレートの場合、登録者はパッケージ化されたテンプレートをカスタマイズする追加の上書きバージョンを作成できます。
  • 新しいバージョンは有効化でき、古いバージョンは無効化できます。登録者が上書きバージョンを有効化すると、そのバージョンがパブリッシャーの有効なバージョンよりも優先されます。
  • パッケージ化されたテンプレートを直接編集することはできません。ただし、パブリッシャーで上書き可能なテンプレートが有効になっている場合、パッケージ化されたテンプレートを上書きする新しいバージョンを作成できます。顧客はテンプレートをコピーして、独立したカスタムテンプレートを作成することもできます。
  • 有効なバージョンがないテンプレートは配信できますが、バージョンが有効化されるまでは使用できません。顧客はテンプレートをコピーして独立したカスタムテンプレートを作成するか、テンプレートが上書き可能に設定されている場合はローカル上書きバージョンを作成できます。
  • 第二世代 (2GP) パッケージバージョンの作成時に「ManagePromptTemplates」権限を割り当てる必要があります。このスニペットをsfdx-project.jsonに使用して、組織の作成およびパッケージの構築時にビルドユーザーに割り当てる権限を指定できます。 
    {
                        "packageDirectories": [{
                        "versionName": "ver 0.2",
                        "versionNumber": "0.2.0.NEXT",        
                        "path": "force-app",
                        "default": true,
                        "package": "Prompt Template 2GP Pkg",
                        "versionDescription": "",
                        "definitionFile": "config/project-scratch-def.json",
                        "packageMetadataAccess": {
                        "permissionSets": [
                        "EinsteinGPTPromptTemplateManager"
                        ]
                        }
                        }],
                        "name": "managed",
                        "namespace": "NAMESPACE",
                        "sfdcLoginUrl": "https://login.salesforce.com",
                        "sourceApiVersion": "63.0"
                        }

インストール済みプロンプトテンプレートのインストールとアップグレード

  • Einstein の ［設定］ で、［有効化後に入力を追加または必須にする］ が有効になっていない場合にテンプレートのバージョン間で入力を変更すると、「このアプリケーションをアップグレードできません。」というエラーでパッケージのインストールに失敗します。
  • 本番でパッケージをインストールまたはアップグレードする前に、Sandbox でインストールまたはアップグレードをテストしてテストします。
  • インストールまたはアップグレード後にバージョンを無効化することはできません。
  • 公開済みプロンプトテンプレートバージョンを上書きすることはできません。
  • プロンプトテンプレートモデルが非表示の場合、既存のテンプレートは意図したとおりに動作します。ただし、テンプレートがコピーされると、モデルは使用できません。
  • 有効なバージョンの場合、顧客組織で自動的に有効化します。パッケージをインストールまたはアップグレードする前に、必ず Sandbox で変更をテストしてください。
  • プロンプトテンプレートを使用するパッケージをインストールするには、Einstein 生成 AI を有効化する必要があります。有効化しないと、インストールに失敗します。
  • パッケージのインストール時にフローは自動的に有効化されません。フローは、確立された管理パッケージの標準有効化プロセスに従います。
  • パートナーはテンプレートを無効化できます。ただし、そのテンプレートが顧客で使用されている場合、アップグレードは失敗します。パッケージをアップグレードするには、顧客がそのテンプレートを使用から削除する必要があります。
  • カスタム LLM モデル設定を使用してテンプレートをパッケージ化する場合、顧客組織に同じ名前のモデルがあることを確認します。そうしないと、インストールまたはアップグレードに失敗します。
  • 動的フォーム対応 Lightning ページのカスタム項目は、プロンプトテンプレートを参照できます。動的フォーム対応 Lightning ページのカスタム項目で参照されるプロンプト テンプレートを含む管理パッケージをインストールし、そのプロンプト テンプレートが Lightning ページの名前空間とは異なる名前空間でカスタム項目を参照している場合、パッケージのインストールが失敗する可能性があります。

インストール済みプロンプトテンプレートの削除

  • バージョンは管理テンプレートから削除できません。
  • 管理テンプレートは 2GP パッケージから削除できますが、顧客の組織では削除されません。非推奨のテンプレートが顧客に表示され、削除することもできます。

上書き可能なプロンプトテンプレート

パブリッシャーは、パッケージ化されたプロンプトテンプレートを上書きできるように設定できます。テンプレートが上書き可能な場合、登録者はテンプレートのローカルバージョンを作成し、プロンプトテキストまたは設定をカスタマイズできます。これらのカスタムバージョンはテンプレートにリンクされていますが、個別のままです。公開バージョンを更新しても、カスタムバージョンには影響しません。

登録者の上書きバージョンは、パブリッシャーが管理するバージョンと共にバージョンピッカーに表示されます。登録者が上書きバージョンを有効化すると、そのバージョンが登録者組織の有効なバージョンになります。ただし、上書きを有効化してもパッケージバージョンは無効にならず、パッケージバージョンは自動的に有効化されます。この動作では、フロー (特にパッケージ化されたフロー) が保持されます。このフローは、このテンプレートが有効になっているかどうかに依存する場合があります。

パブリッシャーバージョンはパッケージで引き続き管理され、パッケージのアップグレードを通じて引き続き更新を受信します。

パートナーに関する考慮事項

  • テンプレートを上書きできるようにするには、<overridable>true</overridable> を使用します。
  • テンプレートの上書き設定が true になり、カスタマー組織にインストールされると、設定を元に戻すことはできません。アップグレードはエラーで失敗します。
  • パッケージからパッケージテンプレートを削除すると、カスタマー組織で削除可能としてマークされます。顧客がそのテンプレートを削除し、テンプレートが使用されていない場合、顧客の上書きも削除されます。
  • ユーザは、[新しいバージョンとして保存] オプションを使用してテンプレートを上書きできます。
  • カスタムバージョンが有効で、テンプレートが使用されている場合、削除できません。
  • カスタムバージョンが有効で、テンプレートが使用されているが、有効な管理パッケージバージョンがある場合、カスタムバージョンを無効化すると、そのバージョンに戻ります。
  • カスタムバージョンが有効な場合、テンプレートは使用されていますが、有効な管理パッケージバージョンがない場合、無効化は失敗します。
  • プロンプトビルダーの [テンプレートの上書き] オプションは、名前空間がある組織でのみ表示されます。
  • 上書き可能なテンプレートをコピーする場合、コピーしたテンプレートは上書きできません。新しいテンプレートを明示的に上書き可能に設定します。

Apex ベースの Lightning タイプの作成

Apex でスキーマを定義する場合は、Apex ベースの Lightning タイプを作成します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition
必要なユーザー権限
プロンプトビルダーでプロンプトテンプレートを作成および管理する

「プロンプトテンプレートマネージャー」権限セット

  • プロンプトテンプレートの管理
  • Execute Prompt Templates (プロンプトテンプレートの実行)

または

「アプリケーションのカスタマイズ」権限セット
  1. 出力構造を定義する Apex クラスを作成します。Apex クラスで AICopilot.GenAIPromptTemplateOutput が実装されていることを確認します。
  2. [設定] で、[Lightning 種別] を検索して選択します。
  3. Lightning 種別を作成し、既存の Apex クラスに関連付けます。
  4. [保存] をクリックします。

Apex ベースの Lightning タイプは、[設定] に表示され、プロンプトビルダーで使用されます。

項目生成プロンプトテンプレートの作成

Field Generation プロンプト テンプレートでは、生成 AI 支援ワークフローを Lightning レコード ページ内のフィールドに取り込みます。ユーザーが LLM によって作成された概要や説明を項目に入力し、顧客とのより生産的な会話を促進できるようにします。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition
必要なユーザー権限
プロンプトビルダーでプロンプトテンプレートを作成および管理する

「プロンプトテンプレートマネージャー」権限セット

  • プロンプトテンプレートの管理
  • Execute Prompt Templates (プロンプトテンプレートの実行)

または

「アプリケーションのカスタマイズ」権限セット
  1. [設定] の [クイック検索] ボックスに「プロンプトビルダー」と入力し、[プロンプトビルダー] を選択します。
  2. [新規プロンプトテンプレート(New Prompt Template)] をクリックします。
    1. [Prompt Template Type (プロンプトテンプレート種別)] ドロップダウンで、[Field Generation (フィールド生成)] を選択します。

プロンプトビルダーの概要

プロンプトビルダーは、プロンプトのライフサイクルの各フェーズ (作成からテスト、有効化まで) をガイド付きビジュアルレイアウトで説明します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

プロンプトビルダー UI の操作

プロンプトビルダーは、プロンプトのライフサイクルの各フェーズ (作成からテスト、有効化まで) をガイド付きビジュアルレイアウトで説明します。直感的な設計により、プロンプトがどのように構築され、各ステップでどのように実行されるかを理解しやすくなります。

プロンプトテンプレートの作成 (1)

差し込み項目を使用して、実際の組織データに基づいて応答をパーソナライズし、プロンプトテンプレートを作成します。

  • @ 記号を入力するか、[プロンプト] セクションで [リソースを挿入] を選択して、差し込み項目を検索し、挿入します。リソースを追加すると、プロンプトが組織データにグラウンディングされ、関連する応答が生成されます。
  • [コピー()] を選択すると、プロンプトがクリップボードにすばやくコピーされます。コピーアイコンは、[解決済みプロンプト] セクションと [応答] セクションでも使用でき、コンテンツを簡単に再利用できます。

テンプレートとプレビューの設定 (2)

[テンプレートとプレビューの設定] を使用して、プロンプトの動作を制御します。

テンプレート設定

  • テンプレート種別を表示します (1)。
  • ドラフト後にプロンプトテンプレートの名前と説明を編集します (1)。
  • このプロンプトテンプレートに必要な入力を表示します。たとえば、セールスメールプロンプトテンプレートでは主オブジェクトと関連オブジェクトを使用しますが、Flex テンプレートでは使用事例に基づいて異なる入力を使用します (1)。
  • プロンプトテンプレートを使用して LLM モデルを選択してテストします。受け入れられたファイルの種類とサイズ、およびファイルが制限を超えた場合の除外プロセスにすばやくアクセスできます (2)。
  • テンプレートの呼び出し中に outputLanguage パラメーターが指定されたときに、LLM がプロンプトの応答を生成するために使用できる言語を選択します。「プロンプトテンプレート応答のサポート言語」を参照してください (3)。
 

プレビュー設定

  • サンプルデータを選択して、本番環境でプロンプトの出力がどのように表示されるかをプレビューします (1)。
  • [Generate Response (応答を生成)] がオフの場合、解決済みプロンプトのみが表示されます。プロンプトは LLM に送信されず、応答も生成されません。ステップバイステップレイアウト (2) に表示される内容をカスタマイズします。
    • プロンプトを表示または非表示にします。
    • [解決済みプロンプト] を表示または非表示にします。
    • クリーンなプレビュー出力のために応答のみに焦点を絞ります。

[解決済み] プロンプトの確認 (3)

[解決済みプロンプト] セクションで、テスト入力がプロンプトテンプレートにマージされる方法を確認できます。このバージョンのプロンプトテンプレートは、実際の組織データが適用された LLM に送信される内容を表します。

  • すべての差し込み項目が正しく解決されていることを確認します。
  • プロンプトの構造が明確で完全であることを確認します。
  • [コピー] () を使用して、解決済みプロンプトをクリップボードにすばやく追加します。

プロンプトテンプレートに機密データが含まれている場合、LLM に送信する前に山括弧内のプレースホルダーに自動的に置き換えられます。たとえば、<AccountName> です。Einstein Trust Layer は、機密情報をマスキングして顧客情報を保護します。

応答が返されると、元の値が自動的に再挿入され、[応答] セクションに斜体で表示されます。

メソッドの入力

メソッドの入力パラメータには List<Request> 型が必要です。Request クラスでは、プロンプトテンプレート種別で定義された各入力の InvocableVariable メンバーが定義されます。すべての入力がプロンプトテンプレートから呼び出し可能なメソッドに渡されます。リストの最初の要素にのみデータが含まれます。

プロンプトテンプレート種別の CapabilityType が存在する場合は、Request 入力クラスのインターフェイスとして機能します。各 CapabilityType では、Request クラスで特定の InvocableVariable メンバーを定義する必要があります。たとえば、項目生成の CapabilityType では、Request で RelatedEntity メンバー変数を定義する必要があります。プロンプトテンプレートで定義されている追加のオブジェクトがある場合、スペルと大文字と小文字を正確に区別して、関連付けられた InvocableVariable メンバーを定義する必要があります。この例では、プロンプトテンプレートで [取引先] がテンプレートで更新するオブジェクトとして定義されています。

public class Request {
                @InvocableVariable
                public Account RelatedEntity;
        }
メモ プロンプト テンプレートでリソースとして使用されるフローまたは Apex クラスの入力を変更すると、プロンプト テンプレートは機能しなくなり、新しいバージョンのプロンプト テンプレートを保存できなくなります。この既知の問題を参照してください。

メソッドの出力

メソッド出力には、InvocableVariable でアノテーションが付けられた Prompt という 1 つの文字列メンバーを含む List<Response> 型があります。詳細については、『Apex Developer Guide』を参照してください。

  • オブジェクト入力に関連付けられた DMO は、データグラフのルートであるか、グラフのルートで統合プロファイル DMO に接続されている必要があります。

Data 360 データを参照するには、[レコードを取得] 要素を使用します。[レコードを取得] 要素で、データソースとして [Data Cloud オブジェクト] を選択します。次に、関連するデータスペースまたはオブジェクトを選択し、データを絞り込む検索条件を指定します。その後、フローのレコード変数と同様に Data 360 レコードデータを使用します。

次に、[プロンプト指示を作成] 要素を使用して、フローが関連付けられたプロンプトテンプレートに返すプロンプト指示を記述します。これらのプロンプト命令には、決定要素の結果に基づいて CRM および Data 360 データの差し込み項目を含めることができます。各差し込み項目は、プロンプト命令で値をテキスト文字列として返します。たとえば、[プロンプト手順を作成] 要素の Input.Contact.MailingCity 差し込み項目は、プロンプト手順で「サンフランシスコ」を返します。

プロンプトテンプレートフローは、Flow:FlowName 形式の差し込み項目としてプロンプトテンプレートに追加できます。フローは、ユーザーが関連付けられたプロンプトテンプレートを使用するたびに実行されます。フロー内で、[プロンプト指示を作成] 要素ごとにプロンプト指示が追加されます。フローが完了すると、すべてのプロンプト命令がプロンプトテンプレートに送信され、差し込み項目にテキスト文字列として入力されます。

プロンプトビルダーでフローを使用するには、次を参照してください。

  • セールスメールプロンプトテンプレートへの Data 360 オブジェクトのないフローの差し込み項目の追加
  • 項目生成プロンプトテンプレートへの Data Cloud オブジェクトのないフロー差し込み項目の追加

プロンプトビルダーで Data 360 オブジェクトでフローを使用するには、次を参照してください。

  • セールスメールプロンプトテンプレートへの Data 360 オブジェクトを使用したフローの差し込み項目の追加
  • 項目生成プロンプトテンプレートへの Data 360 オブジェクトを使用したフロー差し込み項目の追加

Flex テンプレートなど、さまざまなテンプレート種別でフローを使用できるようになったため、Flex 機能は不要になり、Spring '25 で廃止されます。 Flex: *種別を使用するフローは移行することをお勧めします。手動入力を使用するように開始ノード種別を変更し、各変数を入力として追加します。フローを保存し、プロンプトテンプレートがフローの差し込み項目で期待どおりに動作することを確認します。

メモ プロンプト テンプレートでリソースとして使用されるフローまたは Apex クラスの入力を変更すると、プロンプト テンプレートは機能しなくなり、新しいバージョンのプロンプト テンプレートを保存できなくなります。この既知の問題を参照してください。

レコード差し込み項目を使用したグラウンディング

レコード差し込み項目は、プロンプトテンプレートを Salesforce オブジェクト項目に接続します。プロンプトテンプレート種別と、プロンプトテンプレートに関連付けたオブジェクトによって、使用可能な差し込み項目が決まります。

必要なエディション

セールスメールプロンプトテンプレートには、次のオブジェクトに対応する差し込み項目を含めることができます。

  • 受信者 (取引先責任者またはリード)
  • 送信者 (ユーザー)
  • 現在の組織 (送信者の組織)

  • 現在のユーザー
  • 現在の組織 (ユーザーの組織)
  • プロンプトテンプレートに関連付けたオブジェクト

Flex プロンプトテンプレートには、次のオブジェクトに対応する差し込み項目を含めることができます。

  • 現在のユーザー
  • 現在の組織 (ユーザーの組織)
  • プロンプトテンプレートに関連付けたオブジェクト

プロンプトテンプレートワークスペースで標準オブジェクト項目またはカスタムオブジェクト項目を選択すると、その項目は Input:RecordName.FieldName としてテンプレートに追加されます。プロンプト解決時に、ユーザーが選択した特定のレコードに基づいて実際の CRM 値が差し込み項目に入力されます。

たとえば、次の文を含むプロンプトテンプレートがあるとします。

You are a support representative and you need to create a short summary of all open cases for the [Account Name] account.

プロンプトビルダーで Astro の Bakery アカウントレコードを選択してテンプレートに関連付け、テンプレートを実行します。

You are a support representative and you need to create a short summary of all open cases for the {!$Input:Account.Name} account.

プロンプトビルダーで Input:Account.Name 差し込み項目をアカウント名「Astro’s Bakery」に置き換えます。解決された応答は次のようになります。

You are a support representative and you need to create a short summary of all open cases for the Astro’s Bakery account.

予測 AI を使用したグラウンディング

予測モデルからの関連するKnowledgeとアクション可能なインテリジェンスでプロンプト テンプレートをグラウンディングします。LLM プロンプトに予測、上位の予測因子、処方箋を追加します。

予測 AI およびプロンプトテンプレート

予測モデルを使用して、LLM 応答の精度とコンテキストの関連性を向上させます。予測モデルでは、現在のビジネス状況のデータを使用して将来のビジネス結果を予測します。機械学習と統計モデリングを使用して過去のデータに基づいてトレーニングされ、トレンドとパターンを検出します。詳細については、「予測AIの重要な概念と予測モデルの出力の使用」を参照してください。

メモ 使用する予測モデルへのアクセス権が必要です。予測モデルをまだ設定していない場合は、「Create Predictive AI Models From Scratch or Bring Your Own Model」を参照してください。

フローを使用した予測インテリジェンスの取得

フローでは、オンデマンドの予測、処方箋、上位の要素を含むプロンプトを提供できます。オンデマンド予測は、作業フロー内で動的に生成されます。

  1. Flow Builder で、フローを作成し、予測モデルからの出力を要求する予測アクションを追加して、出力値を保存します。詳細は、「Get Predictions in Flows (フローでの予測の取得)」を参照してください。
  2. プロンプトテンプレートで、フロー差し込み項目を使用してそのデータをプロンプトに埋め込みます。詳細は、「Ground with Flow Merge Fields (フローの差し込み項目を使用したグラウンディング)」を参照してください。

Apex を使用した予測インテリジェンスの取得

Apex は、オンデマンドの予測、処方箋、上位の要素を含むプロンプトを提供できます。オンデマンド予測は、作業フロー内で動的に生成されます。

  1. Apex で、予測モデルからの出力を要求する呼び出し可能なアクションを作成します。詳細は、「Get Predictions in Apex (Apex での予測の取得)」を参照してください。
  2. プロンプトテンプレートで、Apex 差し込み項目を使用してそのデータをプロンプトに埋め込みます。詳細は、「 Apex 差し込み項目を使用したグラウンディング 」を参照してください。

REST を使用した予測インテリジェンスの取得

REST アプリケーションは、オンデマンドの予測、処方箋、上位の要素を含むプロンプトを提供できます。オンデマンド予測は、作業フロー内で動的に生成されます。REST クライアントの場合:

  1. Salesforce Data Cloud Connect REST API で予測エンドポイントをコールして、予測モデルからの出力を要求します。詳細は、「Get Predictions in REST Applications (REST アプリケーションでの予測の取得)」を参照してください。
  2. Connect REST API で generation エンドポイントをコールするときに、これらの出力を inputParams として提供します。詳細は、『Connect REST API Developer Guide』の「Einstein Prompt Template Generations」を参照してください。

データモデルオブジェクト (DMO) を使用した予測インテリジェンスの取得

Data 360 の DMO は、バッチまたはストリームの予測、処方箋、上位の要素を含むプロンプトを提供できます。

  1. 予測モデルからの出力を DMO に入力します。これは、一括予測 (一括処理データ変換または一括処理予測ジョブを使用) またはストリーミング予測 (予測ジョブを使用) で実行できます。詳細は、「予測ジョブを使用した予測の取得」または「予測を使用したデータの変換」を参照してください。
  2. プロンプトテンプレートで、DMO 差し込み項目を使用してそのデータをプロンプトに埋め込みます。詳細は、「Ground with Data 360 DMO Merge Fields」を参照してください。

Ground with Knowledge Using Retrieval Augmented Generation (取得拡張生成を使用したナレッジのグラウンディング)

Data 360 の取得増強生成 (RAG) により、LLM で生成された応答の品質、精度、関連性が向上します。Einstein Search でレトリーバーを使用してプロンプトテンプレートを強化します。非構造化テキストソースから LLM プロンプトに関連するナレッジを追加します。記事、メール、チャットのトランスクリプト、およびその他のソースからナレッジを取得します。

メモ
  • Einstein Search は最近 Retriever に名前を変更しました。プロンプトテンプレートワークスペースに「@」と入力するか、[Insert Resource (リソースの挿入)] をクリックして [Retrievers (取得者)] をクリックします。
  • リソースピッカーでは、取得者は自動的に表示されません。使用可能な取得者を検索するには、[Configure Retrievers + (取得者の設定 +)] をクリックし、選択して設定し、変更を適用して挿入します。
  • プロンプトテンプレートの取得者について
    プロンプトテンプレートで取得者を使用して、Data 360でインデックス付けされたKnowledgeから関連情報を検索して返します。取得者は、プロンプトに関連する特殊なグラウンディング情報を提供することで、プロンプトテンプレートを補強します。取得者は、AIモデル(旧称Einstein Studio)で作成されます。
  • プロンプトテンプレートへの個人取得者の追加
    プロンプト テンプレートで個々の取得者を使用して、LLM プロンプトを関連する Knowledge でグラウンディングします。個々の取得者には、AIモデル(旧Einstein Studio)で作成された取得者と、Data 360で以前に作成された従来のデフォルト取得者が含まれます。
  • プロンプトテンプレートへのアンサンブル取得者の追加
    プロンプト テンプレートでアンサンブル取得を使用して、LLM プロンプトを関連 Knowledge でグラウンディングします。アンサンブル取得者は、個々の取得者のコレクションです。アンサンブル取得を実行すると、個々の取得者が実行され、検索結果が 1 つのリストに結合され、検索要求との関連性に従ってリストが再ランク付けされ、最も関連性の高い情報のみがプロンプトまたはエージェントに返されます。アンサンブル取得者は複数のソースから検索を並列で実行します。
  • プロンプトテンプレートへの Web 取得者の追加
    プロンプト テンプレートで Web 取得を使用して、LLM プロンプトを Web サイトの関連 Knowledge でグラウンディングします。Web 取得は、Web 検索を使用するデータ ライブラリが Agentforce データ ライブラリで作成されたときに作成されます。
  • 事前検索条件を使用した取得者出力のカスタマイズ
    プロンプトテンプレートで事前検索条件を使用して、より関連性の高い検索結果を取得します。事前検索条件では、最も関連性の高い情報のみが返されるように、取得者の検索範囲を制限する条件を定義します。たとえば、事前検索条件を使用して、特定の国または商品のみに関連付けられたコンテンツを取得できます。国コードや商品 ID などの検索条件値は、実行時にプロンプトテンプレートで指定されます。
  • プロンプトテンプレートの回答への引用の追加
    プロンプトテンプレートに引用を追加して、ユーザーが生成された情報とソース情報を比較および検証できるようにします。ソースには、エージェントアクション、Knowledge 記事、および Web ページで使用されるコンテンツが含まれます。

プロンプトテンプレートの取得者について

プロンプトテンプレートで取得者を使用して、Data 360でインデックス付けされたKnowledgeから関連情報を検索して返します。取得者は、プロンプトに関連する特殊なグラウンディング情報を提供することで、プロンプトテンプレートを補強します。取得者は、AIモデル(旧称Einstein Studio)で作成されます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

リソースとしての取得

プロンプトビルダーで、取得者をリソースとしてプロンプトテンプレートに追加できます。次の種別の取得者から選択できます。

  • AI モデルで作成された個々の取得者
  • AI モデルで作成されたアンサンブル取得者
  • Agentforce データライブラリで作成された Web 取得
メモ 以前に Data 360 で検索インデックスが作成されたときに作成されたデフォルトの個人取得はプロンプト テンプレートでサポートされますが、新しいデフォルトの個人取得は作成されなくなりました。

レトリーバー設定

有効な取得者をプロンプトテンプレートに追加したら、[テンプレート設定] サイドパネルを使用して、次のような取得者設定を微調整できます。

  • 検索テキスト: プロンプトテンプレート入力の差し込み項目またはフリーテキストを使用してインデックス付けされたデータを検索する、完全に動的な項目。レトリーバーへの検索テキストの入力は、255 文字、グローバル、プロンプト入力に制限されます。差し込み項目を挿入するには、検索テキストエリアの上にあるリソースピッカーを使用します。
  • 出力フィールド: 検索結果が含まれる、取得元で返されるフィールド。デフォルトでは、レトリーバーで定義されたすべての項目が LLM プロンプトに追加されます。ただし、レトリーバーで使用可能な出力項目から必要な項目のみを選択できます。
  • 結果の数: 15 個の Knowledge 記事チャンクや 10 個の類似ケースチャンクなど、取得される結果の最大数。

出力項目のリストまたは結果数に値が指定されていない場合、プロンプトビルダーでは Einstein Search レトリーバーの作成時に設定された値が使用されます。レトリーバーとそのデータへのアクセスは、Data Cloud 権限セットによって制御されます

レトリーバーから返されるデータ

取得者から返されたデータは、プロンプトビルダーの [Preview Resolution (解決のプレビュー)] に JSON 形式で表示されます。プロンプトテンプレートの応答は、検索条件に基づいてカスタマイズされます。

考慮事項

レトリーバーの検索テキスト項目は、グローバルとプロンプトの入力に制限されます。関連リスト、フロー、Apex などの他のソースは使用できません。

レコードスナップショットを使用したグラウンディングプロンプト

プロンプトテンプレートをレコードスナップショットでグラウンディングして、より便利で強力なプロンプト作成環境を実現します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Einstein for Platform、Einstein または Agentforce for Sales/Service アドオン、または Agentforce Foundation が付属する Enterprise Edition、Performance Edition、および Unlimited Edition

ほとんどの場合、プロンプトをさまざまな種別の Salesforce データでグラウンディングする基本的なプロセスは同じです。まず、Salesforce データを組み込んだプロンプトを作成します。次に、[プレビュー] セクションのリソース項目のグラウンディングリソースをプロンプトに入力します。次に、プロンプトビルダーは応答の生成時に実際のデータを使用してグラウンディングリソースを解決します。

レコードスナップショットでは、1 人のリソースを持つオブジェクトのユーザーのページレイアウトで使用できるデータが自動的に含まれるため、プロンプトをグラウンディングする新しい方法が提供されます。オブジェクトの複数の項目と関連リストを個別に選択する代わりに、1 回のクリックでグラウンディング用の関連データを含めることができます。

レコードスナップショットでプロンプトをグラウンディングするために使用するデータは、ユーザーのページレイアウトによって異なります。ページレイアウトは設定可能で、この設定はレコードスナップショットで使用されるデータに影響します。つまり、プロンプトがレコードスナップショットと共に実行されると、スナップショット解決で使用されるデータにそのユーザーに表示されるデータが反映されます。オブジェクトのレコードスナップショットに加えて、個々の項目とリソースを選択することもできます。

メモ 取引先レコードのスナップショット出力には、主要な取引先項目、商品、上位の商談、オープンケースの統計、過去の活動など、追加のグラウンディングデータが含まれます。追加のグラウンディングデータは、使用可能な場合はページレイアウトに関係なく常に含まれます。

考慮事項と制限

レコードスナップショットを使用してプロンプトをグラウンディングするときは、次の点を考慮してください。

  • 動的フォームは、レコードスナップショットでは使用されません。ただし、レコードスナップショットで使用されるオブジェクトで動的フォームが有効化されている場合、基盤となるページレイアウトは引き続き使用されます。
  • プロンプトビルダーでは、プロンプトトークンの制限がオーバーフローしないように、各ソースから受信するデータの量が制限されます。
  • 「空の」データ (値のない項目、制限のないセクションなど) は除外されます。
  • プロンプトビルダーでは、レコードスナップショットで使用する各データソースに次の制限が適用されます。
    Data Source (データソース) 制限 条件
    ページレイアウト 返された項目数に対してなし。  
    コンパクトページレイアウト 返された項目数に対してなし。  
    関連リスト ページレイアウトの最初の 6 件の関連リストが使用され、関連リストごとに最大 5 件のレコードが使用されます。  
    ToDo 次の 5 個の今後の ToDo が使用されます。 ToDo は、ActivityDate (昇順)、Priority (降順)、ModifiedDate (降順) に基づいて選択されます。
    行動 次の 5 件の今後の行動が使用されます。 イベントは開始日 (昇順) に基づいて選択されます。
    メール 最新の 5 件のメールが使用されます。

  • 確認、修正、繰り返し: プロンプトテンプレートが有効であることの確認
  • プロファイルまたはレコードタイプへのページレイアウトの割り当て
  • ページレイアウトに関する考慮事項

プロンプトビルダーの関連リストのサポートにより、プロンプトテンプレートに関連リストの差し込み項目を追加して、リッチグラウンディングを実現できます。関連リストを使用してプロンプトテンプレートをグラウンディングする場合、関連リストの項目は現在のユーザーの親オブジェクトのページレイアウトに基づきます。レコードレベルの検索条件は適用されません。取得されたデータは JSON 形式で表示され、解決に表示されます。

考慮事項、ガイドライン、および制限事項

プロンプトビルダーで関連リストを使用してプロンプトテンプレートをグラウンディングするときは、次の点を考慮してください。

  • 取引先やケースなどのオブジェクトの [活動] 関連リストはサポートされません。
  • プロンプトテンプレートで関連リストを設定し、ユーザーが親オブジェクトのページレイアウトの関連リストまたは関連付けられたオブジェクトに対する「参照」権限を持っていない場合、関連リストデータは LLM に送信されません。
  • プロンプトビルダーでグラウンディングに使用できるのは、オブジェクトのページレイアウトで使用できる関連リストのみです。オブジェクトにカスタムレコードタイプがある場合、マスターレコードタイプのレイアウトの関連リストのみを使用できます。コンテキストユーザーのデフォルトのレコードタイプが存在しない場合、代わりに Salesforce のデフォルトレコードタイプが使用されます。
  • [リソース] フィールドでリソースを選択するのではなく式を入力すると、オブジェクトが{!$RelatedList:Account.Contacts.Records}として表示されます。この式を入力すると、プロンプトビルダーによって UI の表示が簡略化され、Related List: Account.Contactsのみが表示されます。
  • 関連リストで結果が 0 件になる場合でも、プロンプト応答は正常に返されますが、関連リストの内容は応答に追加されません。
  • [ユーザー] 関連リストと [組織] 関連リストは、グローバル変数に関する制限のためサポートされていません。

プロンプトテンプレートを使用したユーザーの操作

Salesforce システム管理者は、プロンプトテンプレートを設定して、ユーザーが作業を容易にできるようにします。このセクションでは、ユーザーがこれらのプロンプトテンプレートを適用して、メールの作成、ケースの概要の生成、テキストフォーム項目の入力などを行う方法について説明します。

  • プロンプトテンプレートへのアクセス権をユーザーに付与
    Einstein生成AIの機能を活用できるようにユーザーを準備します。権限セットでプロンプトテンプレートを使用できるユーザーを管理します。Einstein for Sales にセールスメールプロンプトテンプレートを追加し、Lightning アプリケーションビルダーで作成されたページの動的項目に項目生成プロンプトテンプレートを追加します。
  • プロンプトテンプレートの Lightning 種別の作成および管理
    Lightning 種別を使用して、プロンプトテンプレートの構造化された出力スキーマを定義および管理します。Lightning 種別は、応答構造を適用するためにプロンプトビルダーで実行時に参照される再利用可能な定義です。
  • セールスメールプロンプトテンプレートの実際の使用
    Einstein生成AIは、パーソナライズされたメールのドラフトを作成するのに役立ちます。組織のカスタムセールスメールプロンプトテンプレートは、Lightning Experience メールコンポーザーのオプションとして自動的に表示されます。Einsteinセールスメールを送信する前に、メールのドラフトを確認し、必要に応じて編集します。
  • 項目生成プロンプトテンプレートの動作
    生成AI対応フィールドを使用すると、Lightningページを離れることなく、組織全体のリアルタイム データを取得できます。生成 AI 対応項目では、項目生成プロンプトテンプレートを使用して動的な概要や説明などを提供します。
  • Flex Prompt テンプレートの動作
    Flex プロンプトテンプレートは使用事例に固有であるため、組織内の必要な場所でコールします。カスタム UI を作成するか、REST API を使用して呼び出し可能なアクションでコールします。
  • プロンプトテンプレートと Salesforce 機能の統合
    プロンプトテンプレートは、Salesforce Platform の任意の場所の呼び出し可能なアクション、または Connect REST API または Connect in Apex を使用してコールできます。
  • プロンプトビルダーでのプロンプトパフォーマンスメトリクスの設定 (ベータ)
    Data 360 からプロンプトテンプレートのユーザー総計値を表示し、どのプロンプトテンプレートが顧客にとって最もパフォーマンスが高いかを追跡します。
  • 構造化出力を使用したモデル応答の書式設定
    プロンプトビルダーの構造化された出力により、モデルで一貫した JSON または HTML 形式で応答が返されるため、ワークフロー、インテグレーション、UI 表示の信頼性が向上します。

プロンプト

生成言語モデルは汎用性が高く、さまざまな応答種別を作成できます。応答を生成するには、プロンプト形式で LLM に要求を指定します。プロンプトによって LLM の応答の品質と関連性が決まるため、モデルで理解して使用できるプロンプトを作成することが重要です。

プロンプトデザイン

プロンプト設計は、モデルの応答の品質と精度を向上させるプロンプトを作成するプロセスです。多くのモデルは特定のプロンプト構造を想定しているため、使用しているモデルでテストして反復することが重要です。モデルに最適な構造を理解したら、特定の使用事例に合わせてプロンプトを最適化できます。プロンプト設計プロセスを拡張するには、プロンプトテンプレートと呼ばれる再利用可能なプロンプトを作成します。

プロンプトテンプレート

バックグラウンドで、Einstein生成AIはプロンプト テンプレートを使用します。プロンプトテンプレートは、プロンプトビルダーで作成および管理できる再利用可能な詳細なプロンプトです。これらのテンプレートは使用事例駆動型であり、LLM が高品質の応答を生成するのに役立つ目標、制約、ブランドガイドラインなどの情報が含まれます。また、LLM に送信するプロンプトが最新のデータに基づいているように、プロンプトテンプレートには、顧客名、連絡先情報、商品価格など、変更される情報のプレースホルダーが含まれます。

グラウンディング

グラウンディングでは、要求に関連するデータにプロンプトを接続することで応答が改善されます。グラウンディングを使用しない場合、モデルの応答に一般的な詳細や無関係な詳細が含まれる可能性があります。LLM は Salesforce データまたはアップロードされたファイルを使用して、プロンプトにコンテキストとパーソナライズを追加します。プロンプトビルダーでは、レコード項目、フロー、Apex、およびアップロードされたファイルを参照する差し込み項目を使用して、プロンプトをグラウンディングできます。LLM は、グラウンディングデータと、トレーニングされた元の汎用データを使用します。

Einstein Trust レイヤは、代わりにプレースホルダー テキストを送信することで、LLM からの機密データをマスキングします。プレースホルダーテキストを確認するには、[解決済みプロンプト] を確認します。応答では、Salesforce によって再度追加されたマスク解除されたデータを確認できます。[Data Masking Details (データマスキングの詳細)] ダイアログで、応答のすべてのマスキングされたデータの概要を確認できます。

Einstein によるデータのセキュリティ保護方法についての詳細は、「Einstein Trust Layer」を参照してください。

プロンプトテンプレート種別

プロンプトテンプレート種別は、特定の使用事例のプロンプトテンプレートを作成するのに役立ちます。たとえば、セールスメールプロンプトテンプレートを使用すると、営業チームは取引先責任者またはリード向けにパーソナライズされたメールのドラフトを作成できます。

プロンプトの手順

プロンプト命令は、プロンプトテンプレートの自然言語命令です。「説明は 500 文字以内で記述してください」など、LLM の ToDo を記述します。プロンプトテンプレートに命令を追加すると、テンプレートのプレースホルダーが関連する CRM データに置き換えられます。プロンプトテンプレートはグラウンディング済みプロンプトになり、LLM に送信されます。

プロンプトおよびプロンプトテンプレート

大規模言語モデル(LLM)は、Einstein生成AIをバックグラウンドで実行します。LLM は、多くの言語ベースのタスクでユーザーをサポートします。たとえば、顧客へのパーソナライズされたメールを生成したり、顧客のフィードバックを分析して主要なインサイトを抽出したりできます。ただし、LLM は単独で優れたコンテンツを作成することはできません。プロンプト形式でユーザーによるガイダンスが必要です。

プロンプトは、LLM に指定する一連の命令です。正確でパーソナライズされた出力をモデルが生成するのに役立つ特定のコンテキスト情報、データ、命令、制約が提供されます。LLM が生成する出力は応答と呼ばれます。

Case #2 details: Our widgets haven’t been delivered. We can't track our order. According to the last tracking update, the widgets should have arrived on June 5. Now it's June 10, and they still haven't arrived.

Do not attribute any positive or negative traits in the summary.

LLM によって次の概要が生成されました。

In Case #2, the issue is that the widgets haven’t been delivered and the order cannot be tracked. The expected delivery date was June 5, but as of June 10, the widgets have not arrived.

LLM の応答の品質は、プロンプトの特殊性によって異なります。漠然とした指示や不正確な指示があると、LLM は無関係な応答や偏った応答を返す可能性があります。LLM が幻覚を見て誤った情報を生成することもあります。また、プロンプトを実行するたびに LLM に対して新しいコールを実行するため、まったく同じプロンプトを渡す場合でも応答が異なる可能性があります。幻覚を防ぎ、応答間の変動を最小限に抑えるには、できるだけ具体的なデータを含むプロンプトを作成します。高品質で正確な応答を一貫して得られるようになるまで、プロンプトを確認して編集することが重要です。

新しいプロンプトで 1 つの高品質な応答のみを作成して反復するプロセスは時間がかかる可能性があります。データと仕様が異なる多数の元のプロンプトを設計することはさらに困難です。また、異なるユーザーによって作成されたプロンプトは、書き方のバリエーションによって出力が一貫していない可能性があります。プロンプト設計を効率的に拡張するには、再利用可能なプロンプトであるプロンプトテンプレートを使用することをお勧めします。プロンプトテンプレートには、顧客や商品などに関する特定の詳細のプレースホルダーが含まれます。
