アセットライブラリからサブエージェントへのアクションの追加

標準アクションをエージェントに追加して一般的なビジネス使用事例の処理をすばやく開始したり、ビジネスニーズに合わせてカスタムアクションを作成したりできます。これらのアクションをエージェントに追加すると、エージェントは独自の独立したコピーを取得します。アセットライブラリ内のテンプレートアクションへの変更は、エージェント内のサブエージェントおよびアクションに自動的に同期されません。あるエージェントのアクションを変更しても、別のエージェントのサブエージェントやアクションには影響しません。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

エージェントを変更するには、ドラフト状態である必要があります。コミットされたエージェントを変更する場合は、新しいドラフトを作成します。

  1. Agentforce Studio アプリケーションの [エージェント] リストから、アクションを追加するエージェントを開きます。
  2. エージェントのバージョンが複数ある場合は、Agentforce Builder のヘッダーから、編集するエージェントのバージョンを選択します。
  3. [エクスプローラー] パネルで、アクションを追加するサブエージェントを開き、[アクション] にマウスポインターを置いて [] をクリックします。
  4. [アセットライブラリから追加] を選択します。
  5. エージェントに追加する 1 つ以上のアクションを選択します。
  6. [エージェントに追加] をクリックします。

選択した各アクションのコピーがエージェントに追加され、そのコピーを編集できます。基盤となるフロー、プロンプトテンプレート、その他の参照アクションなど、各アクションを確認してカスタマイズします。これらのアクションに加えた変更は、このサブエージェントとエージェントバージョンにのみ適用され、他のサブエージェント、エージェント、アセットライブラリのアクションには影響しません。

アクションをサブエージェントに追加すると、アクションは自動的にサブエージェントの推論アクション ([推論で使用可能なアクション]) に追加され、エージェントは LLM を使用して推論中にアクションを選択できます。推論アクションでは、検索条件やフォローアップアクションなどのロジックをエージェントアクションに追加できます。エージェントが推論を開始する前にアクションを確定的に実行するには、サブエージェントの推論手順でアクションを参照します。

標準エージェントアクションの共通ユーザーアクセス

ユーザーが多くの標準エージェントアクションを実行するために必要な権限について説明します。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

エージェント種別およびテンプレートへのユーザーアクセス

エージェント種別やテンプレートによって、サポートされるチャネルや使用事例に応じてユーザーアクセスの管理方法が異なります。

  • エージェント種別の要件を確認し、ユーザーがエージェントにアクセスするために必要な権限を判断します。
    • 従業員とやりとりするエージェントの多くは Agentforce 従業員エージェントです。個々の従業員エージェントへのアクセス権をユーザーに付与する必要があります。
    • 顧客とやりとりするエージェントの多くは Agentforce サービスエージェントです。ユーザーはサービスエージェントとやりとりするのに特別な権限は必要ありません。
  • 権限をエンドユーザーに割り当てるか、エージェントのユーザーレコードに割り当てるか、またはその両方に割り当てるかを決定します。
    • Lightning Experience など、ログイン ユーザに制限されたチャネルに接続されたエージェントは、ログイン ユーザのコンテキストで動作し、ユーザのアクセス制御が適用されます。Lightning Experience、Salesforce モバイル アプリケーション、Slack、または Experience Cloud サイトの拡張 Web チャットに接続する Agentforce 従業員エージェントを作成する場合は、個々のユーザーまたはユーザー プロファイルに権限を割り当てます。
    • メッセージングチャネルなど、ログインユーザーに制限されていないチャネルに接続されているエージェントは、エージェントユーザーのコンテキストで動作します。エージェントは、エージェントが作業するために必要なすべての権限を持つ Salesforce ユーザーレコードです。拡張チャットまたは別のメッセージング チャネルに接続する Agentforce サービスエージェントを作成する場合は、エージェントのユーザ レコードに権限を割り当てます。
  • エージェントテンプレートのドキュメントと、必要なテンプレートまたは機能固有の権限に関するアクションを確認します。
メモ エージェントを作成または管理する権限をエンドユーザーまたはエージェントユーザーに割り当てないでください。

カスタムアクションの作成

カスタムアクションは、アセットライブラリまたは Agentforce Builder のエージェント内から作成できます。アセットライブラリからアクションを作成すると、複数のエージェントおよびバージョンに追加できます。Agentforce Builder でエージェント内からアクションを作成すると、そのエージェントのみが使用できます。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。
必要なユーザー権限
カスタムエージェントアクションを作成する AIエージェントの管理とエージェントタイプの必要な権限
プロンプトテンプレートを作成または変更する プロンプトテンプレートマネージャー
フローを作成または変更する 「フローの管理」

Agentforce Builder でのカスタムアクションの作成

Agentforce Builder でエージェントからカスタムアクションを作成する場合、そのエージェントのみが使用できます。行った変更は、このエージェントバージョンにのみ適用されます。アクションを他のサブエージェント、エージェント、およびエージェントバージョンに追加できるようにするには、代わりにアセットライブラリで作成します。

作業を開始する前に

  • カスタムアクションの考慮事項を確認します。
  • エージェントで使用する基盤となる Salesforce 機能を作成します。カスタムアクションを作成するときに、エージェントで使用する機能を設定します。呼び出し可能なメソッドと REST Apex クラス、外部サービス、自動起動フロー、MuleSoft API、またはプロンプトテンプレートを呼び出すカスタムアクションを作成できます。

カスタムエージェントアクションへのアクセスは、参照する Salesforce 機能の種別によって異なります。たとえば、カスタムアクションがフローを使用して作成されている場合、カスタムアクションはフローで設定された権限、項目レベルセキュリティ、および共有設定に従います。アクションを実行するには、少なくともユーザーまたはエージェントユーザーに「フローを実行」権限と、フローで使用されるオブジェクトへのアクセス権が必要です。「標準エージェントアクションの共通ユーザーアクセス」を参照してください。

エージェントを変更するには、ドラフト状態である必要があります。コミットされたエージェントを変更するには、新しいドラフトを作成します。

  1. Agentforce Studio アプリケーションの [エージェント] リストから、アクションを追加するエージェントを開きます。
  2. エージェントのバージョンが複数ある場合は、Agentforce Builder のヘッダーから、編集するエージェントのバージョンを選択します。
  3. [エクスプローラー] パネルで、アクションを追加するサブエージェントを開き、[アクション] にマウスポインターを置いて [] をクリックします。
  4. [Create New Action (新規アクションの作成)] を選択します。
  5. アクションに名前を付け、[作成して開く] をクリックします。カスタムアクションがサブエージェントとエージェントに追加されます。
  6. [参照アクション種別] ドロップダウンから、エージェントアクションの作成に使用する機能種別 (フローやプロンプトテンプレートなど) を選択します。次に、カテゴリと参照アクションを選択します (要求された場合)。カスタムアクションの説明と各入力および出力には、参照アクションの説明が入力されます。
  7. アクションを変更します。
    1. アクションの説明を確認します。必要に応じて、アクションの内容とタイミングおよび使用方法をエージェントが理解できるように変更します。
    2. 各入力と出力の説明を確認します。
    3. 入力ごとに、該当する設定を指定します。
      入力設定 詳細
      ユーザーからデータを収集 このパラメーターはユーザーが指定する必要があります。
      入力が必要 アクションを実行するためにこのパラメーターが必要です。この設定を有効にすると、入力がない場合、アクションを実行できなくなります。その他のすべての入力は省略可能として扱われます。参照アクションで入力が必要な場合、この設定はデフォルトで有効になっており、参照のみです。
    4. 出力ごとに、該当する設定を指定します。
      出力設定 詳細
      エージェントコンテキストに含める エージェントアクションを作成すると、参照アクションのすべての入力と出力がエージェントアクションに追加されます。この設定を出力で有効にすると、出力がエージェントの会話履歴に追加され、推論で使用可能になります。エージェントで使用しない、基盤となる参照アクション出力の設定を無効にします。エージェントアクションでは少なくとも 1 つの出力を使用する必要があります。
      会話に表示

      この設定を有効にすると、出力がエージェントの応答に含まれます。一部のチャネルでは、一部の出力が構造化コンテンツに変換されます（Lightning Experience の Agentforce パネルでレコード ページが認識される場合など）。

      この設定がすべての出力で無効になっている場合、エージェントは LLM を使用してエージェントの応答の出力を自然言語で要約します。
    5. アクションの追加設定を指定します。
      追加設定 詳細
      ユーザー確認が必要 アクションでレコードに変更を加える場合、エージェントが変更を実行する前にユーザーに変更の確認を求めるようにエージェントに要求できます。
      このアクションの読み込み中テキストを表示

      アクションをバックグラウンドで実行中のエージェントの会話に読み込み中のテキストを表示します。

      カスタムアクションの場合、[読み込み中テキスト] 項目でアクションの読み込みテキストを指定できます。句読点を含まない 1 ～ 3 の単語で、アクションの内容をユーザーに知らせます。たとえば、「メールの作成」、「更新の作成」、「活動の詳細の取得」などです。

      この設定が無効になっている場合、またはこの設定が有効になっていても読み込みテキストが指定されていない場合、デフォルトの読み込みテキストが表示されます。たとえば、「Working (作業中)」、「Making progress (進行状況の確認)」、「Checking my notes (メモの確認)」などです。

      拡張メッセージングチャネルの会話で読み込み中のテキストを表示するには、拡張チャットの追加設定が必要です。
  8. 変更内容を保存します。

このアクションは、このエージェントサブエージェントとバージョンでのみ使用でき、アセットライブラリでは使用できません。アクションに加えた変更は、このサブエージェントとエージェントバージョンにのみ適用されます。変更は他のサブエージェントやエージェントには影響しません。

アクションはサブエージェントの推論アクション ([推論で使用可能なアクション]) に自動的に追加されるため、エージェントは LLM を使用して推論中にアクションを選択できます。推論アクションでは、検索条件やフォローアップアクションなどのロジックをエージェントアクションに追加できます。エージェントが推論を開始する前にアクションを確定的に実行するには、サブエージェントの推論手順でアクションを参照します。

      この設定がすべての出力で無効になっている場合、エージェントは LLM を使用してエージェントの応答の出力を自然言語で要約します。
  5. [完了] をクリックします。

アクションはアセットライブラリで使用できます。アクションを使用するには、アクションをエージェントに追加します。「アセットライブラリからのトピックへのアクションの追加」を参照してください。

アセットライブラリのアクションに加えた変更は、エージェントに追加したアクションのコピーには同期されません。アセットライブラリのアクションに加えられた変更をエージェントに適用するには、更新されたアクションをエージェントに追加する必要があります。

従来の Agentforce Builder の探索

使用可能なインターフェース: Lightning Experience

Agentforce Builder は、ビジネスルール内で動作し、グラウンディングされた信頼できるデータを使用して安全に応答する ToDo 固有のエージェントの作成を支援することで、生産性を向上させます。ビルダーには次の機能があります。

  • エージェントの動作をプレビュー、テスト、トラブルシューティングするツール

Agentforce Builderツアー

Agentforce Builder の各パネルで、サブエージェントの定義、アクションの接続、設定の定義、テスト結果の確認など、エージェントの設定がどのようにサポートされているかについて説明します。Agentforce Builder では、設定とテストを合理化するための 1 つのワークスペースが提供されます。

  • ナビゲーションサイドバー (1) : エージェントが実行できる作業、アクセスできるデータ、接続先チャネル、安全な操作方法を制御する変数と検索条件を定義するために不可欠な設定領域にアクセスします。
  • プランキャンバス (2): エージェントがプランを作成して入力に応答する方法をプレビューするテスト会話を開始します。キャンバスには、選択したサブエージェント、推論パネル、使用したプロンプト、選択したアクション、入力と出力、エージェント応答などのカードが表示され、エージェントが返信を生成した状況を確認できます。
  • 会話プレビューパネル (3): リアルタイムのユーザーインタラクションをシミュレーションして、エージェントがプロンプトにどのように応答するかを確認します。このパネルは、エージェントをリリースする前にサブエージェントの動作、応答の精度、および全体的な環境を検証するのに役立ちます。
    • プレビュー条件の編集: [] をクリックして、さまざまなユーザーシナリオをシミュレーションし、特定のコンテキスト値に基づいてエージェントがどのように応答するかをテストします。
    • 更新: [] をクリックして会話を更新し、新しいセッションを開始せずに最初から更新をテストします。
  • 一括テスト (4): 複数のサブエージェントで自動テストを起動して、エージェントのパフォーマンスを大規模に検証します。この機能を使用して、問題を特定し、予想されるインタラクション全体で一貫性を確保します。「テストの作成」を参照してください。
  • 有効化 (5):エージェントを有効にして、従業員または顧客が使用できるようにします。変更を行うには、エージェントが無効である必要があります。有効になると、ボタンの表示ラベルが [無効化] に変わります。「Activate or Deactivate Your Agent (エージェントの有効化または無効化)」を参照してください。
  • エージェント名とバージョン (6): 選択したエージェントの名前を表示し、使用可能なバージョンを切り替えます。「エージェントバージョンの管理」を参照してください。
  • 設定 (7): 名前、ロール、説明、その他の設定など、エージェントの詳細を編集します。
  • ヘルプ (8): 包括的なサポートにアクセスするには、Salesforce ヘルプと Trailhead モジュールを新しいタブで参照して詳細を確認してください。

ナビゲーションバー

縦方向ナビゲーションパネルでは、サブエージェント、データソース、接続、コンテキスト変数、言語設定、イベントログなど、エージェント設定の主要な領域にすばやくアクセスできます。このパネルを使用して、各設定ステップ間を移動します。

  • サブエージェント (1): 各サブエージェントで手順を割り当て、関連アクションをグループ化して、エージェントが実行できる操作を定義します。アセットライブラリからサブエージェントを追加して、エージェントの機能をさらに拡張できます。
  • データ (2): エージェントが参照できる構造化データソースを接続します。まずデータライブラリを作成し、次にエージェントに割り当てます。
  • 接続 (3): エージェントが外部システムを操作できるように、Slack や他の API などのチャネルを設定します。「従業員エージェントの Slack への接続」を参照してください。
  • コンテキスト (4): パーソナライズされたインタラクションに対するエージェントの応答方法をカスタマイズする変数を定義し、検索条件を適用して特定のサブエージェントとアクションへのアクセスを制御します。エージェントのカスタム変数を作成し、サブエージェントとアクションへのアクセスを制御するフィルタを作成する方法について説明します。
  • 言語 (5): LLM 応答の言語サポートとシステムメッセージを設定します。言語設定を更新してエージェントのコミュニケーションを調整します。
  • イベント (6): エージェントイベントログを表示して、パフォーマンスとインタラクションを分析します。拡張イベントログを有効にして会話データを含めることで、より深いインサイトを得ることができます。

Atlas 推論エンジンは、グラフベースの推論エンジンです。エージェントが特定の予測可能なパスに従うように、ノード、変数、トランジションを含むフローチャートのように考えることができます。厳密にプロンプトベースの推論エンジンとは異なり、Atlas はエージェントの全体像を把握するワークフローを会話スキルから分離します。Agentforce Builder でエージェントを作成するための言語であるエージェントスクリプトを使用して、プログラム式を自然言語の指示と組み合わせます。その結果、ハイブリッドな推論が可能になり、企業が要求する予測可能性と制御性、および大規模言語モデル (LLM) が可能にする柔軟性と創造性が提供されます。

メモ エージェントの会話での LLM コールの数とサイズは、ToDo の複雑さと、使用されるサブエージェントおよびアクションによって異なります。Agentforce の大規模言語モデルのサポートについて説明します。

ステップ 1: ユーザーがメッセージを送信する

ユーザーが質問または要求を入力すると、プロセスが開始されます。

ステップ 2: エージェントが開始サブエージェントに移動する

エージェントは、開始サブエージェントとして定義されたサブエージェントに移動します。エージェントスクリプトでは、これはサブエージェントが「subagent」プレフィックスの代わりに「start_agent」プレフィックスを使用するものです。デフォルトでは、これは [エージェント ルータ(Agent Router)] です。エージェントは、このルータの指示に従って、最近の会話履歴とエージェントが使用できるサブエージェントを選択します。

ステップ 3: エージェントがサブエージェントの指示を上から下に解決

エージェントがサブエージェントに移動すると、記述された順序でサブエージェントの推論命令の解決が確定的に開始されます。サブエージェントの実行のこの段階では、推論は実行されないため、エージェントはまだ LLM に依存しません。

推論手順のいずれかの時点でエージェントが別のサブエージェントへの移行を実行すると、エージェントは手順が解決して推論が行われる前に会話をリダイレクトします。それ以外の場合、すべての推論指示が解決されると、結果の推論指示 (自然言語の指示を含む) を使用してプロンプトが作成されます。

ステップ 4: エージェントがプロンプトを作成する

エージェントは、推論手順を使用して、LLM に送信するプロンプトを作成し、推論プロセスを開始します。プロンプトには次の内容が含まれます。

  • すべてのエージェント操作に適用されるエージェントレベルの手順
  • ユーザーの最新のメッセージを含む最近の会話履歴
  • 解決済みサブエージェントの推論手順
  • サブエージェントに含まれる推論アクション。エージェントが推論プロセス中に実行できるアクション (エージェントアクションを含む)。

ステップ 5: エージェントがプロンプトを LLM に送信し、推論を開始してアクションを実行する

エージェントは LLM を使用して、プロンプトで使用可能な情報を分析し、次のステップを決定します。

  • アクションまたはユーティリティに定義されたロジックと、説明、入力、出力に基づいてエージェントアクションまたはユーティリティを実行する
  • ユーザーに詳細情報を求める
  • 選択可能なオプションを明確にするための質問をユーザーに行う
  • ユーザーの質問または要求にエージェントがすでにアクセス権を持っている情報で解決できる場合は、ユーザーの質問または要求に直接回答する

エージェントはアクションを実行するときに、推論ループで結果を確認し、ユーザーに応答する前に適切な情報が含まれていることを確認します。エージェントは、会話に関する既存の情報にアクション出力を追加します。次に、別のアクションを実行するか、ユーザーにさらに質問するか、最終応答を送信するかを決定します。このプロセスは最大 7 個の推論ループを続行します。

ステップ 6: エージェントが最終応答検証を実行する (Agentforce サービスエージェントのみ)

Agentforce サービスエージェントは応答を送信する前に、応答がデータソースに基づいているかどうか、サブエージェントの範囲と手順に準拠しているかどうか、幻覚、未検証の情報、または潜在的なプロンプトインジェクションリスクが含まれていないかどうかを確認します。提案された応答がこの検証に失敗した場合、エージェントは新しい応答を生成します。

メモ エージェントは応答を受信すると会話で LLM 応答をストリーミングします。応答検証がエージェントの最終応答に適用されます。応答のストリーミングが開始された後に提案された応答がこの検証に失敗した場合、応答が削除され、新しい応答が生成されます。

エージェントが検証に合格する応答を生成できない場合、質問や要求に対応できないことをユーザーに通知します。

ステップ 7: エージェントがユーザーに応答を送信する

エージェントは、推論ループを完了すると、ユーザーにメッセージを送信します。ユーザーはフォローアップの質問をしたり、件名を変更したりして会話を続行でき、エージェントが適切に応答します。バックグラウンドでは、ユーザーの応答によってジャーニーが再開されますが、ユーザーにとっては会話が順番に行われているように見えます。

Agentforce Studio および新しい Agentforce Builder へのアクセス

Agentforce Studio アプリケーションは、新しい Agentforce Builder のホームであり、エージェントを構築、テスト、および監視するための中央ハブです。デフォルトでは、Agentforce Studio は、Agentforce へのアクセス権を持つ組織のすべてのユーザーがアプリケーションランチャーで使用できます。Agentforce Studio 内の各機能には、独自の権限が必要です。

必要なエディション

使用可能なインターフェース: Lightning Experience
使用可能なエディション: Enterprise Edition、Performance Edition、Unlimited Edition、および Developer Edition。必要なアドオンライセンスはエージェント種別によって異なります。

新しい Agentforce Builder にアクセスするには、アプリケーションランチャーから、[Agentforce Studio] を見つけて選択し、[エージェント] をクリックします。Agentforce Studio へのアクセス権を持つすべてのユーザーに [エージェント] タブが表示されます。エージェントのリストビューを表示して Agentforce Builder にアクセスする

  • 組織で Einstein が有効になっている必要があります。
  • 組織で Agentforce が有効になっている必要があります。
  • ユーザーには「AI エージェントの管理」権限が必要です。

コンテキスト変数は、リンク済み変数とも呼ばれ、オブジェクト項目に対応付けられます。たとえば、Agentforce サービスエージェントには、メッセージングセッションオブジェクト項目 (カスタム項目を含む) から対応付けられたコンテキスト変数が含まれます。

たとえば、次のエージェントスクリプトでは、メッセージングセッションレコード ID を保存するコンテキスト変数を定義します。

RoutableId: linked string
    description: "The messaging session ID”
    label: "RoutableID"
    source: @MessagingSession.Id

カスタム変数は可変変数とも呼ばれ、エージェントに固有であり、会話セッション中にのみ値が保持されます。カスタム変数には、string、number、list、object、boolean のいずれかのデータ型を保存できます。デフォルトでは、これらの変数は内部専用です。つまり、エージェントでのみ設定できます。これらは外部にできます。つまり、エージェント API を使用して設定することもできます。

たとえば、次のエージェントスクリプトでは、ユーザー名を保存するカスタム文字列変数を定義します。

userName: mutable string
    description: "The name of the user"
    label: "Name"
    visibility: "External"

エージェントの推論やインタラクション全体で変数を使用する方法を示すエージェントスクリプトの例を次に示します。

  • 変数をアクションの入力または出力に設定します。このアクションでは、設定変数の値を入力として使用するか、出力値を設定変数に保存します。
    run @action.Get_Order_Details
    with order_number=@variables.orderNumber
    set @variables.order_id=@outputs.order_id
  • 検索条件で変数を使用します。
    get_order_details: @actions.Get_Order_Details
    available when @variables.isVerified == False
  • 論理式では変数を使用します。
    if @variables.order_summary == "":
    run @actions.lookup_current_order
      with member_email=@variables.memberEmail
      set @variables.order_summary=@outputs.order_summary
  • 変数値を設定します。
    set @variables.userName = ”New User”
  • エージェントの応答で変数値を使用します。たとえば、サブエージェントの指示で特定の方法で変数を使用するようにエージェントに指示できます。
    | Refer to the user by the name {!@variables.userName}.

カスタムエージェント呼び出し可能アクション

カスタムエージェント呼び出し可能アクションは、より多くの会話を自動的に処理するため、ほとんどの使用事例で使用することをお勧めします。Salesforce では、組織内の Agentforce サービスエージェント、Agentforce 従業員エージェント、および Agentforce (デフォルト) ごとにエージェント呼び出し可能なカスタムアクションが提供されます。

カスタムエージェント呼び出し可能アクションを使用すると、コードではなくクリックでエージェントの動作を簡単に設定できます。たとえば、Apex クラスまたはフローにカスタムエージェント呼び出し可能アクションを追加する場合、UI を使用してエージェントをトリガーする条件、実行する ToDo、および ToDo を完了するために必要なデータを指定します。ユーザーメッセージを指定して、エージェントが実行する ToDo を定義します。エージェントは、ユーザーがチャットウィンドウで質問や要求を行った場合と同様に、サブエージェントとアクションを選択するためにこの項目を使用します。エージェントが応答するフィールドを定義して、フローまたは Apex クラスでそのフィールド値を使用することもできます。

使用事例に応じて、複数のカスタム エージェント呼び出し可能アクションをフローまたは Apex クラスに追加することを検討してください。たとえば、エージェントに電話してサービスケースを要約し、その要約を使用してメール応答のドラフトを作成するために 2 回目の電話を発信できます。同じフローから同じエージェントを複数回コールして、個別の関連 ToDo を処理できます。または、同じフローから複数のエージェントをコールして、より専門的なタスクを処理できます。

標準エージェント API 呼び出し可能アクション

標準エージェント API 呼び出し可能アクションを使用すると、フローまたは Apex クラスからエージェント API に直接アクセスできます。セッション中のエージェントの動作は、呼び出し可能なカスタムエージェントアクションよりも詳細に制御できますが、追加の設定が必要です。高度な使用事例でのみ使用することをお勧めします。

たとえば、[セッションを終了] アクションを使用して、特定の条件を満たしたときにセッションが終了するようにします。または、[フィードバックを送信] アクションを使用して会話に関するユーザーフィードバックを収集し、Data Cloud に保存します。

Salesforce には、次の標準エージェント API アクションが用意されています。

  • セッションの終了
  • Send Message (メッセージを送信)
  • セッションを開始
  • フィードバックの送信
エージェント API アクションについての詳細は、「エージェント API フローコアアクション」を参照してください。

カスタムエージェント呼び出し可能アクションと標準エージェント API 呼び出し可能アクションは、Experience Cloud サイトユーザーとプラットフォームインテグレーションユーザーではサポートされません。プラットフォームインテグレーションユーザーは、システムユーザーまたはシステムコンテキストとも呼ばれます。

Agentforce サービスエージェントをコールするフローは、エージェントユーザーのコンテキストで実行されます。Agentforce 従業員エージェントまたは Agentforce （デフォルト） をコールするフローは、認証済みエンド ユーザのコンテキストで実行されます。

フローでは、すぐに実行されるパスではなく、非同期パスでのみカスタムエージェント呼び出し可能アクションと標準エージェント API 呼び出し可能アクションをコールできます。

Apex クラスまたはフローからエージェントをコールするための準備

Agentforce サービスエージェント、Agentforce 従業員エージェント、または Agentforce (デフォルト)を作成します。

エージェントのサブエージェントとアクションを準備します。標準サブエージェントとアクションは会話の使用事例に合わせて設計されているため、エージェントが呼び出し可能なアクションでは期待どおりに動作しない可能性があります。エージェントから標準サブエージェントとアクションを削除し、使用事例のカスタムアクションを作成することを検討してください。

カスタムエージェントの呼び出し可能なアクションでは、カスタム変数または $Context.EndUserId、$Context.RoutableId、$Context.EndUserLanguage、$Context.EndUserContactId の標準コンテキスト変数はサポートされません。

Agentforce サービスエージェントを使用している場合は、エージェントアクションで使用されるレコードへの必要なアクセス権がエージェントにあることを確認します。たとえば、エージェントがケースを要約できるようにするには、権限セットを作成し、オブジェクト設定を変更してケースオブジェクトに参照アクセス権を付与します。次に、権限セットをエージェントユーザーに割り当てます。

まだ Apex クラスまたはフローからエージェントをコールしていない場合は、コールの準備をします。

  1. Flow Builder で、[アクション] を選択します。次に、[AI エージェントアクション] カテゴリから、フローからコールするエージェントの呼び出し可能なカスタムアクションを選択します。
    有効なエージェントに関連付けられた呼び出し可能なアクションのみが表示されます。
  2. アクションの名前と説明 (省略可能) を入力します。
  3. [ユーザーメッセージ] 項目に、完了する ToDo を定義するエージェントへのサンプルユーザーメッセージを入力します。エージェントは発言を使用して、割り当てられたトピックとアクションを検索し、タスクに適したアクションを特定します。
    たとえば、「受信したサービスケースの概要を 100 文字未満で生成します。
  4. (省略可能) [リソース] 項目で、メッセージに含める変数を選択します。
    フローでエージェントが呼び出し可能なアクションの前に、ユーザーメッセージで参照する要素を追加します。たとえば、ユーザーメッセージのレコードの ID を取得するには、[レコードを取得] 要素をフローに追加します。
    ユーザーメッセージにコンテキスト変数を含めないでください。代わりに、入力項目を使用します。
  5. (省略可能) エージェントとの会話のセッション ID を指定します。
    同じエージェントに関連付けられた複数の呼び出し可能なアクションをフローに含める場合、セッション ID を入力として後続のアクションで使用できます。セッション ID を指定しない場合、新しいセッションが作成されます。
  6. (省略可能) 呼び出し可能なアクションがバージョン 1.1.0 の場合、[構造化出力を編集] セクションで [設定] をクリックし、少なくとも 1 つの構造化出力フィールドを定義します。
    呼び出し可能なアクションの構造化された出力を編集すると、変更はフローの以前のバージョン (有効なバージョンを含む) に適用されます。
  7. (省略可能) 呼び出し可能なアクションが Agentforce サービスエージェントをコールする場合、エージェントに追加したコンテキスト変数が入力として入力されます。コンテキスト変数を入力として使用するには、変数に対応付けます。コンテキスト変数を使用しない場合は、項目を空白のままにします。Agentforce Builder を使用して、コンテキスト変数を追加または削除します。
  8. (省略可能) 呼び出し可能なアクションがバージョン 1.1.0 の場合、アクションがフローへの出力として返す項目を定義します。アクションが常に特定の項目を返すようにするには、その項目を必須としてマークします。
  9. 変更内容を保存します。
  10. 準備ができたら、ユーザーにアクセス権を付与してフローを有効化します。

エージェントのトピックとアクションの設定をテストするには、Agentforce Builder でプレビュー会話のユーザ メッセージを入力します。エージェントの応答をプレビューするには、Flow Builder のデバッグフロー機能を使用します。Apex テストは、エージェントが呼び出し可能なカスタムアクションではサポートされません。

呼び出し可能なアクションがバージョン 1.1.0 の場合、エージェントは指定したフィールドを含む Apex オブジェクトで応答します。

呼び出し可能なアクションがバージョン 1.0.0 の場合、エージェントはテキスト文字列応答で応答します。フローで Apex クラスを使用してエージェント応答を解析できます。「Apex によるフローの拡張」を参照してください。

{
  sessionId: "uuid",
  message: {
    type: text,
    value: AGENT RESPONSE
  }
}

請求カテゴリ 説明
スタータープロンプト

使用量は、LLM ゲートウェイを介した LLM への直接要求の数と、ゲートウェイで Bring Your Own Large Language Model (BYOLLM) が使用されているかどうかの 2 つの要素に基づいて計算されます。

各スタータープロンプトには、最大 2,000 トークンの処理が含まれます。プロンプト使用量は、切り上げられた 2,000 トークンのチャンクで計数されます。この制限を超えるプロンプトは複数のプロンプトとして測定され、2,000 トークンのチャンクが追加されるたびに新しいプロンプトとして計数されます。たとえば、入力トークンと出力トークンの合計が 6500 のプロンプトは、4 つのプロンプトとして測定されます。

トークンは、AI モデルによって処理されるデータの単位です。
